# エージェントが作業領域に入れたツールで、作業領域の写しや PR が壊れないようにする

- 日付: 2026-11-02（UTC）
- タスク: PBI-278
- PR: #276
- ブランチ: feat/issue-278-workspace-tools
- 関係する ADR: なし

## 目的

実験の S16 で、実装のエージェントがテストのために Chromium（616MB）を `node_modules/.browser` に展開した。その中の権限 0000 のファイルで、ゴールガーディアンの作業領域の写しが `EACCES` で失敗し、再開しても同じエラーで止まった。PR の本文の「テストが成功」も、その環境でしか成り立たなかった。

受け入れ条件の要点（ツールの展開は許し、後始末する）：

- 写しは、読めないファイルがあっても全体を失敗にせず、写さずに作業履歴に残す。止まったタスクは再開で進める。
- 入れたツールとその置き場所は、PR・コミットに混ざらない。
- 自分で入れて検証を通したときは、申告させ、PR の本文・最終レビューに「その環境だけの結果」と書かせる。
- 仕様書・ユーザードキュメント（日英）・作業履歴を直し、権限 0000 を含む写しをテストで確かめる。

## したこと

- `copyWorkingTree`：`cp` の filter で、読めない（読み取り、ディレクトリは読み取りと実行ができない）ファイル・ディレクトリを写さず、総数と最初の20件のパスを返す。リンクは今までどおりたどらずに写す。`runGuardian` が `WorkspaceFilesSkipped`（新しい記録だけのイベント）を作業履歴に残し、実行の指示に「作業領域の写しに入れなかったファイル」を足す（パスは JSON のデータ。バッククォートは ``` にして、コードブロックを閉じさせない）。中止された後で記録できなくても、実行は続ける。
- `stage`（差分・コミット・ベースの取り込み）：`git add --all --ignore-errors` に、パス指定 `:(top,exclude).sacty-tools` を付けて、根の `.sacty-tools/` を外す（初版は `core.excludesFile` で `.sacty-tools/` と `node_modules/` を外したが、レビューで `.gitignore` の否定パターンに戻されると指摘され、パス指定に変えた）。標準エラー出力が「読めないファイルを載せられなかった」だけで、そのファイルがすべて起点で未追跡のときだけ進める。起点で追跡しているファイルを読めないとき、ほかの失敗のときは失敗のまま。
- 実装の工程の指示（5か所）と既定の規則：ツールを入れてよいが `.sacty-tools/` の下にすること、入れたら実装の説明に「## この環境だけの結果」の節を作ることを足した。
- 最終レビューの指示：節（`environmentOnlyReport` で取り出し、データとして渡す）・写しに入れなかったファイル・`.sacty-tools/` のどれかがあれば、通った検証を「その環境だけの結果」として `humanChecks` と所見に書かせる。入れたことだけでは不合格にしない。
- 仕様書（`tasks-and-steps`・`event-log`）・ユーザードキュメント（`tasks`・`troubleshooting`）を日英で直した。

選んだこと：

- 置き場所の約束 `.sacty-tools/` を作った。エージェントが入れる場所は様々で、`.gitignore` に頼ると、無視の無いリポジトリで PR に混ざるため。`node_modules/` は Sacty が強制せず、リポジトリの `.gitignore` に任せる（あえて含めるリポジトリの意図を尊重する。PO の判断）。
- 写さなかったものを、ゴールガーディアンの写しに入れる（`.sacty-tools/` は写す）。入れたツールで通る検証は通し、申告で「その環境だけの結果」にする（止めない）。

## 確かめたこと

- `npx biome check .`・`npm run typecheck`：エラーなし。
- `npx vitest run`（全体を1回）：182 ファイル・3401 テストがすべて成功（終了コード 0）。`tests/docs` も成功。
- 新しいテスト：
  - `repository.test.ts`：権限 0000 のファイルとディレクトリ（S16 の `chromium.png` の形）を含む作業領域を写せる（読めないものは `skipped` に出て、写しに無い）。権限を直すと次の写しですべて入る（再開）。読めないものが 0 件・1 件・上限超えの件数、長いパスの切り詰め。`.sacty-tools/`・`node_modules/` が `.gitignore` なしでも差分・コミットに入らず、追跡している `node_modules` のファイルは入る。読めない未追跡のファイルがあっても差分・コミットが失敗しない。root では読めないファイルを作れないので、読めないファイルのテストは root のときは飛ばす。
  - `daemon.test.ts`：読めないファイルがあっても最終レビューが進み、`WorkspaceFilesSkipped` と指示の知らせが出る。写しの失敗で止まったタスクを再開すると進む。読めるファイルだけなら足さない。
  - `environment-only-result.test.ts`：「この環境だけの結果」の節の取り出し（コードブロックの中の見出し・見出しだけ・長い節）、実装の工程（設計あり・なし・テストの仕組みなし・不具合の修正）と最終レビューの指示、申告のデータとしての受け渡し。
- 修正を戻すと落ちること：写しの filter を常に通す・除外の一覧を空にする・`--ignore-errors` を外す、の3つを同時に戻したら、`repository.test.ts` の新しい4件が落ちた（戻して成功を確認）。
- 確かめなかったこと：実際の Docker で、エージェントが `.sacty-tools/` に入れること（指示で促すだけで、sacty は強制しない）。停止中の実際のタスク（87f6b4af）の再開（読むだけにするよう指示されたため）。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| [要修正] 読めない追跡済みファイルのエラーも許容し、その変更が黙って落ちる | 省略を起点で未追跡のファイルだけにした（`ls-tree` で起点の追跡を確かめ、追跡していれば失敗）。追跡済みの読めないファイル（ほかの読めるファイルがあっても）と、読めないこと以外の `git add` の失敗（コミットの無い入れ子のリポジトリ）を拒否するテストを足した。 |
| [要修正] `core.excludesFile` の除外が `.gitignore` の否定パターンで取り消される | パス指定の除外に変え、`!.sacty-tools/`・`!.sacty-tools/**` があっても入らないことをテストした。起点で追跡している `.sacty-tools/` のファイルは起点のまま。`node_modules/` の強制除外はやめ、`.gitignore` に任せた（PO の判断。docs も直した）。 |
| [提案] 権限エラーと別種のエラーが混在するテストの入力に、読めないファイルが無い | 読めない未追跡のファイルと入れ子のリポジトリ（コミットが無く `git add` が失敗する）を同時に置き、失敗になるテストを足した。読めないファイルだけなら進む前提も同じテストで確かめる。エラー判定が権限以外の行を無視する形にすると、このテストだけが落ちることを確認した。 |
