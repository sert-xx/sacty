# 人間が読む成果物の初版を最小限にし、詳しさは差し戻しで足す

- 日付: 2026-10-25（UTC）
- タスク: なし
- PR: #219
- ブランチ: claude/keen-rubin-3ppdyj
- 関係する ADR: [人間が読む成果物の初版を最小限にし、詳しさは人間の差し戻しで足す](../adr/20261025-0222-minimal-first-drafts.md)

## 目的

sacty が作る要求要件・設計・文書が、人間が読むには情報が多い。
利用者は、sacty の草案を別のエージェントで何度も「見やすく」直してから使っている。
初版を最小限にし、人間が差し戻しで求めたときだけ詳しくするようにする。

## したこと

- 指示（`apps/daemon/src/prompts.ts`）
  - `minimalDraftLines` を足し、要求要件・設計・文書・調査が目的のタスクの調査の結果の指示に入れた。読む人が知っていること・採らなかった案・まとめを書かせず、差し戻しで求められた所だけを詳しくさせる。
  - 要求要件・設計：確認したいことを must（上限なし）と should（最大 5 件）に分け、既定で決めたことを異論を持ちうるものだけ・最大 5 件に、行数の目安（20 行・60 行）を足した。
  - 設計：テスト観点の数を要る分だけにし、1文で書かせる。
  - セルフレビュー（`design-doc`）：記述を足す指摘は `must` だけを直させる。
- 既定のスキル
  - `writing`：決まりの最初に「情報を絞る」を足し、`references/sentences.md` に例を足した。
  - `review-dispatch`（`self-review.md`・`viewpoints.md`）・`review-execution`（`D-10.md`）：足す `should` を直さないこと、D-10 の見るものと NG 例を足した。人間の求めで足した記述は削る指摘にしない。
  - `ears-requirements`：要求の数を最小限にすることを足した。
- 既定の規則（`apps/daemon/default-context/rules.md`）に、人が読む文章は必ず `writing` を使って書くことを足した。
- docs：仕様書（タスクと工程・コンテキスト）とユーザードキュメント（タスク）を日英で直した。前の ADR を置き換え済みにした。

## 確かめたこと

- `npx vitest run apps/daemon/src/prompts.test.ts tests/docs`：通った
- `npx vitest run`：8 件が失敗した（`host-mcp-processes`・`context-mcp`・`agent-sessions`・`question-form.browser`）。変更前のコードでも同じ 8 件が失敗するので、この作業環境（root での実行・ブラウザ）によるもので、今回の変更とは関係しない
- `npm run lint`・`npm run typecheck`：通った

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| D-10 の例5が、規約で決まるものを「既定で決めたこと」に回すよう求めていて、既存のやり方に従うだけの決定を並べない方針と食い違う（sacty のレビュー、提案） | 例5を、規約で決まるものはどこにも書かず、人間が異論を持ちうる判断だけを「既定で決めたこと」に残す説明に直した |

## 残したこと

- 行数の目安（20 行・60 行）は、実際の成果物を見て直す。
