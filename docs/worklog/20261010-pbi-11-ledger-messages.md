# 台帳などに記録する文言を、コードと引数にして画面の言語で表示する

- 日付: 2026-10-10（UTC）
- タスク: PBI-11
- PR: #16
- ブランチ: feat/issue-11-ledger-messages
- 関係する ADR: [台帳などに記録するデーモンの文言を、文かコードと引数のどちらかで持ち、外から来た文は訳さずに引数で渡す](../adr/20261010-1423-ledger-messages-as-codes.md)

## 目的

PBI-11 の後半（PBI-11b）。PBI-11a（#15）で作った仕組みを使い、デーモンが台帳などに記録する文言をコードと引数にする。

- デーモンは利用者向けの文言を、コードと引数で返す・記録する。
- 画面は、コードと引数を画面の言語の文にして出す。古い台帳の日本語の文は、そのまま出す。
- エージェントの成果物や判定理由は訳さない。

## したこと

- core：`DaemonText` と、記録する文言のコード・辞書を足した（`packages/core/src/messages.ts`・`packages/core/src/message-code.ts`・`packages/core/src/events.ts`）。
- デーモン：`MessageError`（`apps/daemon/src/errors.ts`）でエラーにコードと引数を持たせ、台帳の失敗・一時停止・判定・後片付け・コンテキストの注意を
  コードと引数で記録するようにした（`apps/daemon/src/service.ts`・`apps/daemon/src/context.ts`・`apps/daemon/src/github.ts`・`apps/daemon/src/repository.ts` など）。
- テストの注記を `TestsRun.note` として出力と分けて記録し、画面とエージェントへの差し戻しの両方に出す（`apps/daemon/src/agents/test-runner.ts`・`apps/daemon/src/agents/docker.ts`）。
- 台帳の外の文言（中止の確認の説明・Issue の取り込みのエラー・設定ファイルの誤り）もコードにした（`apps/daemon/src/intake.ts`・`apps/daemon/src/config.ts`）。
- 秘密情報を引数の中の文からも取り除く（`redactText`、`apps/daemon/src/agents/redact.ts`）。
- 画面：台帳・一時停止の理由・中止の後片付け・変更の申し出の判定・テストの注記・取り込みのエラー・設定の誤りを、画面の言語の文にした（`apps/web/src/lib/labels.ts` など）。
- レビューの対応で、秘密情報の取り除きを文言の形を見て行うようにし（core の `mapFreeText`）、判定を読み取れないときの説明をコード
  （`guardian.verdictUnreadable`・`review.verdictMissing`・`review.unreadable`）にした。

## 確かめたこと

- `npm test`：201件が通った（7件追加、既存の21件を「日本語の文にしてから確かめる」形に更新）。古い文とコードの文言の両方を台帳から読めること、入れ子の文言を
  日本語・英語にすること、引数の中の秘密情報を取り除くこと、テストの注記（docker を実行できない・時間切れ）、GitHub のエラーのコード、台帳にコードと引数で記録すること
  （コンテキストの取得の失敗・PR の作成の失敗）、画面の台帳の表示（英語・日本語・古い文・エージェントの文）を確かめた。エラーのコードを文に戻すと関係するテストが
  失敗することも確かめた。レビューの対応の後は202件が通った。
- 画面で、存在しないコンテキストリポジトリを設定した確かめ用のプロジェクトでチケットを作った。英語では「Cannot fetch the context repository (…): fatal: repository '…' does not exist」
  （git の文はそのまま）、日本語では「コンテキストリポジトリ（…）を取得できません：…」と出た。
- レビューでは `npm test`・`npm run lint`・`npm run typecheck`・`git diff --check` が通ったことを確かめた。ブラウザの操作と、実際のエージェント・Docker の起動は、レビューでは確かめていない。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| P2：秘密情報の取り除きを `code` や列挙値にもかけるので、秘密情報の値がコードの一部と一致すると、コードが伏せ字になって文にできない（試しの値 `failed` で `pr.failed` → `pr.[REDACTED]`、`hint: "token"` の列挙値も変わる） | コードごとの引数の形から、自由に書ける文字列の引数と入れ子の文だけを対象にし、コードと決まった値（列挙・数値・真偽）は変えないようにした。知らないコードは引数の文字列だけを対象にする。指摘の形の回帰テストを足し、前の処理に戻すと失敗することを確かめた |
| P2：ゴールガーディアンや最終レビューの出力から判定を読み取れないときにデーモンが補う説明が、日本語の固定の文で記録され、英語の画面でも日本語のまま出る | 補う説明をコードにし、最終レビューの理由と所見も台帳でコードを持てるようにした。ゴールガーディアンが書いた理由はそのまま残す。画面は画面の言語で、実装のやり直しの指示と PR の本文には日本語の文で入れる。回帰テストを足し、既存のサービスのテストも記録がコードになることを確かめる形にした |

## 残したこと

- デーモンのログ（console）・CLI の文言・エージェントに渡す指示（プロンプト）・既定のプロジェクト名「デフォルト」（データ）は、対象外にした。
