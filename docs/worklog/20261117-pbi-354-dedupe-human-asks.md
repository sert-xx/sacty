# 「人に確かめてほしいこと」に、同じ確認が重ねて出ないようにする

- 日付: 2026-11-17（UTC）
- タスク: PBI-354
- PR: #397
- ブランチ: feat/pbi-354-dedupe-human-asks
- 関係する ADR: [人に確かめてほしいことを、PR のコメントと承認の画面の目立つ所に出す](../adr/20261103-2302-surface-human-asks.md)

## 目的

作り直しの実行が、同じ確認（たとえば「CI を再実行して結果を確認してください」）を複数の指摘の対応に書くと、承認の画面・タスクの詳細・PR のコメントに、同じ確認が指摘の数だけ並んでいた。
人が同じことを2回読まずに済むようにする。受け入れ条件の要点は次のとおり。

1. 実行への指示で、同じ確認を複数の指摘の対応に重ねて書かないよう伝える。
2. それでも同じ文の確認が複数の指摘に付いたら、1件にまとめ、付いていた指摘を並べる。空白などの表記の違いは除いて比べる。
3. 文の違う確認は、まとめない（意味が同じかを、sacty が推測で決めない）。
4. 画面（承認の画面の上・タスクの詳細）と PR のコメントで同じ扱いにし、件数はまとめた後の数にする。
5. 確認が1件だけのとき・無いときの表示は変えない。
6. 仕様書・ユーザードキュメント（日英）・作業履歴に反映する。

## したこと

- `packages/core/src/projection.ts`（`humanAsks`）：`confirms` の1件を、指摘1つ（`remarkId`）から、付いていた指摘の並び（`remarkIds`）に変えた。
  同じ文の確認は、先に出た1件に指摘の ID を足す。比べるときだけ空白をすべて除く。出す文は、先頭の指摘に書かれていた文（前後の空白だけ除く）。
  - 空白を「1つに詰める」のではなく「すべて除く」にした理由：日本語の文は、文の途中の改行で空白の有無が変わる（`確認し、\n結果を` と `確認し、結果を`）。詰めるだけでは、この2つが別の文になる。
  - 大文字と小文字・全角と半角・句読点の違いは、除かない（同じ文かどうかを広く取ると、推測に近づくため）。
- 画面（`apps/web/src/components/human-ask.tsx`）と PR のコメント（`apps/daemon/src/human-ask-notice.ts`）は、どちらも `humanAsks` の結果をそのまま使うので、同じまとめ方になる。
  画面の文言（`apps/web/src/i18n/messages/task.ts` の `humanAsk.confirm`）には、指摘の ID の並びを渡す。日本語は「・」でつなぎ、英語は複数形（`comments`）と「, 」でつなぐ（1回目のレビューの提案で直した）。1件のときの表示は、これまでと同じ文字列になる。PR のコメント（日本語だけ）は「・」でつなぐ。
- `apps/daemon/src/prompts.ts`（`confirmLines`）：同じ確認を複数の指摘の対応に重ねて書かず、いちばん関係の深い指摘の対応に1回だけ書くよう、指示に足した。
- 仕様書（`docs/spec/approval.md`・`approval.en.md`）と、ユーザードキュメント（`docs/user/tasks.md`・`tasks.en.md`）に反映した。
- ADR は足していない（「人に確かめてほしいこと」を出す方針は変えておらず、出し方の細部の変更のため）。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| 1回目・提案：文の違う確認がまとまらないことのテストが、違いを1種類ずつ確かめていない（大文字小文字・句読点を除く誤った実装でも通る。全角と半角は確かめていない） | 直した。大文字と小文字・全角と半角・句読点の有無・句読点の種類を、1つずつ変えた文の組にして、それぞれ別の確認として残ることを確かめる |
| 1回目・提案：英語の画面で、まとめた確認の指摘の ID が、単数形の `comment` に「・」区切りで出る | 直した。文言の関数に ID の並びを渡し、英語は複数形と「, 」区切りにした。英語の文言のテストを足した |

## 残したこと

- 前の回の指摘にも、提出のたびに対応を書かせていること（同じ確認が重なる遠因）は、変えていない。含めるかは、リポジトリの持ち主が決める。
- 文の違う確認を、意味でまとめることはしない（範囲外）。
