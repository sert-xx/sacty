# タスクの詳細で、オーケストレーターにタスクの状況を質問できるようにする

- 日付: 2026-10-13（UTC）
- タスク: PBI-54
- PR: #63
- ブランチ: feat/issue-54-task-chat
- 関係する ADR: [タスクの詳細から、オーケストレーターにタスクの状況を読み取り専用で質問でき、質問と答えは作業履歴のイベントで残す](../adr/20261013-0951-read-only-task-questions.md)

## 目的

タスクの詳細から、オーケストレーターにタスクの状況を質問できるようにする。受け入れ条件の要点は次のとおり。

- 質問を送ると、オーケストレーターが台帳に基づいて答え、画面に出る。
- 質問しても、タスクの状態・工程・承認済みの内容は変わらない（作業中でも質問でき、作業を止めない）。
- 質問と答えが残り、開き直しても読める。費用がタスクの費用と工程ごとの費用に出る。
- 予算の上限に達したタスクでは質問できず、理由が出る。秘密情報は、答え・画面・作業履歴に出ない。

## したこと

- イベント（`packages/core/src/events.ts`・`packages/core/src/projection.ts`）：`QuestionAsked`・`QuestionAnswered` を足した。答え待ちは 1 件まで。
- デーモン（`apps/daemon/src/service.ts`・`apps/daemon/src/prompts.ts`）：質問を記録したらすぐ返し、答えは工程の実行とは別に動かす。
  用意済みのタスクは、対象リポジトリの起点のコードを使い捨ての写しで読み取り専用で渡す。中止したら答えの実行も止める。起動時に
  答えの無い質問は中断として記録する。答えを記録できないときは、答えられなかったこととして記録する。指示は 4 万字に収める。
- 予算：答えの費用はタスクの費用に入る。上限に達したタスク（ちょうども含む）・中止したタスク・答え待ちの間は質問できない。
- API（`apps/daemon/src/server.ts`）：`POST /api/tasks/:id/questions`（201・入力の誤りは 400・質問できない状態は 409）。
- 画面（`apps/web/src/components/task-chat.tsx`・`apps/web/src/components/question-form.tsx`・`apps/web/src/components/step-costs.tsx` ほか）：
  質問と答えの一覧（答えは Markdown）、答え待ちの間の自動の更新、工程ごとの費用の表の「質問への答え（オーケストレーター）」の行。
  作業履歴には本文を出さず、ID・費用・理由だけ。
- `README.md` に説明を足した。

## 確かめたこと

- `npm run lint`・`npm run typecheck`・`npx vitest run`（571 件）・`npm run build` が通った。
- 境界と競合：質問が 0 件・1 件・3 件、同時の質問、予算ちょうどと手前、工程の実行中の質問、一時停止中、中止（実行中・書き出し中）、
  デーモンの再起動、長すぎる台帳、入力の誤り、答えの記録の失敗。
- 主要な処理を 12 か所わざと壊し、すべてテストが落ちることを確かめた。
- 一時的な環境（スタブのエージェント）で、質問から答え、費用の表までを画面で確かめた。
- 未確認：実際の AI・Docker での答えの生成とブラウザの操作（レビューでも未検証）。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| 答えの記録に失敗したときの代わりの記録に、実行にかかった費用・使用量・換算かどうか（costUsd・usage・estimated）が引き継がれず、費用が 0 として数えられる | 代わりの記録にも、元の記録の費用・使用量・換算かどうかとエージェントの設定を引き継ぎ、答えの本文だけを失敗の理由に置き換えるようにした。Q1 の前後で予算が 0.0015 ドル増えることなどをテストに足し、戻すと落ちることを確かめた |

## 残したこと

- 人が質問の本文に書いた秘密情報は伏せない（伏せられるのは、実行に渡した秘密情報だけ）。
- 予算は質問を受け付ける前に判定するので、1 回の答えで上限を超えることがある（超えたら、次の工程の実行の前に予算で止まる）。
