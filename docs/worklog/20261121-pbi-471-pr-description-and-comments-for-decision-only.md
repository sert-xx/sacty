# Sacty が作る PR の説明とコメントを、人が読んで判断する情報だけにする

- 日付: 2026-11-21（UTC）
- タスク: PBI-471
- PR: なし
- ブランチ: main
- 関係する ADR: [PR の説明とコメントを、Sacty を使っていない人が読んで判断できる情報だけにする](../adr/20261121-2200-pr-description-and-comments-for-decision-only.md)

## 目的

PR を読む人は Sacty を使っていないことがある。PBI-460（PR に投稿するレビュー）と同じ方針を、PR の説明と Sacty が PR・Issue に書くコメントにも当てる。
タスクの ID・指摘の内部の ID・手元の画面の URL・内部の語・レビューの本文の写し・書いた時点で古くなる状態・同じ中身の繰り返しを外し、読み手が判断に要る情報だけにする。
外した情報は、Sacty の画面と `get_task` に今までどおり残す。

## したこと

- 説明（実装・要求要件・設計。テンプレートの有り無し）
  - 冒頭の「Sacty のタスク…の成果物です」の行、「レビューの進め方」、AI のレビューの状況を外した。
  - タスクの ID は、表示されない目印 `<!-- sacty task <タスク ID> -->`（説明の最後）にだけ置く。
  - 末尾を、「この PR は Sacty が作成しました。」と、承認の 2 文にした。
  - 最後の直しを、説明の中で 1 回だけ出す形にした。
  - 確かめ方は、観点が依頼の 1 行だけなら表を出さず、テストは件数とファイルだけにした。
  - 指摘への対応は、要点の 1 行と対応にした（要点が無い古い記録は、対応だけ）。
  - 確かめる所から、件数と出典の数え方を外した（画面は変えない）。
  - 要求要件を省いたときと、固定の文から、内部の語を外した。
- 指摘を示す 1 行（`remarkLine`）と、文の中の指摘の ID を除く処理（`withoutRemarkIds`）を足した。要点は、対応の `gist` に書かせて記録する（`packages/core` の `RemarkResponse`・`TaskRemark`）。
- コメント・Issue・後続のタスク
  - 返信の書き出しを「この指摘への返信です。」、末尾を「Sacty の AI が書きました。」にした（新旧の書き出しの返信を読める）。
  - 人への確認・設計に戻した・レビューが止まった・人の判断を待つ・後続に回す決定のコメントから、画面の URL・タスクの ID・指摘の内部の ID・注釈を外し、「Sacty の画面で〜してください」の案内にした。
  - 後続に回す決定のコメントと Issue は、指摘を要点とリンクで示し、理由は残して ID と秘密の値を除く。
  - 後続のタスクの題を、要点から作る形にし、エージェントへの指示の見出しには題を使わず固定にした。
- 人が直した説明の更新：以前の版の可視のタスク ID の行は残さず、目印を 1 つだけ置く。
- エージェントへの指示：実装の説明は指摘の ID と作業の細部を書かない決まり、後続に回したい理由は内部の語・ID・画面の URL を書かない決まりを足した。
- 文書
  - 仕様書（日英）：`approval`・`tasks-and-steps`・`intake` を直し、要求要件・設計の PR の本文、指摘を示す 1 行、文の中の指摘の ID の節を足した。
  - ユーザー文書（日英）：`tasks`・`intake`・`notifications` を直した。
  - ADR：新しい ADR を足し、PBI-450 の ADR と PBI-460 の ADR を、置き換えた部分を書いて `superseded` にした（`git mv`）。名前の変更で切れた、仕様書・ほかの ADR・作業履歴のリンクを直した。

## レビューの指摘への対応

- 後続のタスクの題を作るとき、GitHub のトークンの値を伏せる対象に渡した（`settleDeferralTasks`）。取り出せなければ、ほかの伏せだけで作る。
- 分割の子タスクのレビューの指示に入る親タスクの題と、親が後続のタスクのときのレビューの子タスクの題を、`instructionTitle` を通した（分割の記録に `parentDeferred` を足した）。
- 返信・人への確認・判断の理由の文にも、`withoutRemarkIds` を通した（`publicText`・返信の組み立て）。
- `withoutRemarkIds` の括弧の規則を、長い空白の並びでも時間がかからない形にした。
- `remarkLine` の URL の除去を広げ（`www.`・`//host`・大文字）、`markdownText` は `<`・`>`・`[`・`]`・`#` を行のどこでも逃がす。
- 目印の除去を本文の全体に当て（複数行・`>` を含むもの・`--!>` で閉じるもの）、空行を詰めるのは目印を除いた位置の前後だけにした。
- マージ承認の知らせ（`merge-approval-notice.ts`）も、画面の URL と注釈を外し、「経過は、Sacty の画面で確かめられます。」にした。
- 仕様書・ユーザー文書の、skip-requirements の文言（コードに合わせた）と、英語版の返信の説明を直した。
- テスト：後続のタスクの題の秘密の値（修正を戻すと落ちる）、監査・分割の子・作り直しの指示、返信・人への確認の ID、目印と空行、URL・記法・長い空白の並びを足し、要点の無い入力と空の括弧の確かめを強くした。
- 直さなかった（好みの整理）：使われなくなった入力・関数の掃除、`markdownText` の置き場、重複した名前など。

## 残したこと

- 実際に作られた PR の説明を GitHub で読み、Sacty を使っていない人が画面なしで判断できるかは、人が確かめる。
- Sacty が足す設計・要求要件の文書にある仮リンク（`[この指摘](URL)`）は、インラインコードで囲む直しが要る。要求要件の文書は凍結されているので、人の確認に回した。
