# 指摘を受けた直しの実行では、セルフレビューを再レビューとして扱う

- 日付: 2026-11-03（UTC）
- タスク: PBI-296
- PR: #297
- ブランチ: feat/issue-296-pbi-296
- 関係する ADR: [指摘を受けた直しの実行では、セルフレビューの最初のレビューを再レビューとして扱う](../adr/20261103-1700-fix-run-first-review-is-rereview.md)

## 目的

実験（F39。S16・S18 の3回目）で、人の差し戻しや AI のレビューの指摘で始まった直しの実行が、セルフレビューの観点を全部また起動していた（9観点 $15.96、8観点 $8.17）。#286 の絞り込みは同じ実行の中でしか効かなかった。
直しの実行の最初のセルフレビューを再レビューとして扱い、指摘に関わる観点と X-1 だけを起動する。最初の実行は変えない。

## したこと

- Sacty の指示（`apps/daemon/src/prompts.ts`）：`fixRunCauses` で、その工程の今回の指摘（人・AI。`submittedIn` が無い最新の回）と、実装なら最終レビューの不合格（`verifyFeedback` が `review`）を原因として集める。前回の提出のセルフレビューが合格のときだけ。`fixRunReviewLines` が、最初のセルフレビューを再レビューとして扱う指示を `selfReviewLines` に足す。要求要件・設計は `reviewRework` が `partial` のときだけ。実装は、標準・不具合の修正・要求要件を省いたタスクの3か所に当てた。
- 既定のスキル `review-dispatch`：`references/self-review.md` に「直しの実行の最初のレビュー」を足した（対象、指摘に関わる観点の決め方、X-2、担当への依頼、起動表）。`SKILL.md` の規則 1・5、起動表の例、入力の確認、親の手順、`references/viewpoints.md` を直した。
- 仕様書（`context.md`・`tasks-and-steps.md`と英語の版）、ユーザードキュメント（`tasks.md` と英語の版）、ADR を直した。

## 判断したこと

- 指摘に関わる観点の決め方は、指示ではなくスキルに置いた（PBI-286 と同じ。指示は直しの実行であることだけを伝える）。
- 前回の提出のセルフレビューが未合格・記録なしのときは絞らない。要求要件・設計で前回の下書きが空のときも同じ。
- 最終レビューの不合格だけを実装の原因に数え、テストが通らなかっただけ・競合の目印だけは数えなかった（受け入れ条件にあるのは最終レビューの不合格）。

## 確かめたこと

作業は、リポジトリの外の worktree（`sacty-wt-pbi-296`）で行った。

- `apps/daemon/src/prompts.test.ts` に 8 件、`apps/daemon/src/default-skills.test.ts` に 8 件を追加した。
- 修正を戻す確認：スキルの変更だけを戻すと default-skills の追加 7 件が落ち（残る 1 件は変えていない規則の確認）、`prompts.ts` だけを HEAD に戻すと prompts の追加 4 件が落ちる。
- 境界：タスクの最初の実行、提出済みの指摘だけの再実行、無効にした指摘、別の工程の指摘、前回が未合格・記録なし・下書きが空のときは、指示を足さない。
- 並行の Dev と共有の `git stash` を使って、変更が一時的に入れ替わった。元に戻して、相手に連絡した（作業の内容には影響しない）。

## レビュー対応（Sacty のレビュー）

- 再レビューとして扱う条件を、作業の指示が「直しの実行の最初のレビューの規則で行う」と明示している場合に限る、とスキル（`self-review.md`・`SKILL.md`）に書いた。「差し戻しの直し」「レビューの範囲を絞る」としか書かれていない指示（前回のセルフレビューが未合格のときの既存の指示を含む）では観点を絞らず、全部起動する。テストを足し、スキルを戻すと落ちることを確かめた。
- ユーザードキュメント（日英）の「実装の差し戻しには当てはまりません」を、範囲の絞り込みだけの話だと分かるようにし、実装の直しの実行も観点を絞ることを書き足した。仕様書（日英）の適用条件も揃えた。

## main の取り込み（#295）

- PBI-295（文書だけの依頼の実装のセルフレビューを user-doc にする）が main に入って競合した。`implementSelfReviewLines` が `fixRunCauses` を渡すようにし、主対象の種類が user-doc でも code でも、直しの実行の指示が付くようにした。文書だけの依頼の直しの実行（標準・直接・最終レビューの不合格・修正）で指示が渡るテストを足した（`fixCauses` を渡さないと落ちることを確かめた）。

## 再レビューの提案への対応

- 仕様書 `context.md` の適用条件に、「直しである」と示すだけでなく、「この実行の最初のセルフレビューを、直しの実行の最初のレビューの規則で行う」と明示する、という条件を足した（英語版と揃えた）。
