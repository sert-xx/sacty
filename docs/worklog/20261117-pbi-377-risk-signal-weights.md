# PR のリスク評価の段階を、合図の重さと、依存の版の更新の上げ幅で決め直す

- 日付: 2026-11-17（UTC）
- タスク: PBI-377
- PR: なし
- ブランチ: feat/pbi-377-risk-signal-weights
- 関係する ADR: [PR のリスク評価の段階を、合図の重さと、依存の版の更新の上げ幅で決める](../adr/20261117-0433-risk-level-by-signal-weight.md)

## 目的

PR のリスク評価は、8 つの合図のどれか 1 つに当たれば「高」だった。PR #394〜#404 のレビューに載った評価 38 回のうち、35 回が高で、段階ではレビューの深さを分けられていなかった。
リポジトリの持ち主が決め直した基準（合図の重い・軽い、「不具合の疑い」を外す、依存の版の更新は上げ幅で決める）のとおりに、段階を決める。

受け入れ条件の要点：

1. 重い合図（セキュリティにかかわる振る舞いの変更・取り消しにくい変更・互換性の変更）は 1 つで高。軽い合図（性能・並行処理、構造・広い範囲の変更、大きな差分、確かめていない振る舞い）だけなら、2 つ以上で高、1 つで中。「不具合の疑い」は合図にしない。PR を作る前の評価と、取り込んだレビューのタスクの評価の両方で同じ。
2. 「セキュリティ」は、セキュリティにかかわる振る舞いを変える変更に付く。脆弱性を直すための依存の更新は、上げ幅で決める。
3. 依存の版の更新だけなら、メジャーは高、マイナー・パッチは低。ほかのコードの変更が混ざれば、高いほう。上げ幅を読み取れないときの扱いを決めて、仕様書に書く。
4. PR #394〜#404 の先頭のコミットを新しい決まりで評価し直し、段階の分かれ方を書く。
5. エージェントへの指示は、あらゆる言語・リポジトリの対象に渡るので、特定の言語・パッケージ管理に寄せない。
6. 仕様書・ユーザードキュメント（日英）・ADR・作業履歴に反映する。3 段階・点数なし・評価でレビューを省かない・読み込まれた RADAR のスキルやコンテキストの優先は、変えない。

## したこと

- `packages/core/src/events.ts`
  - 合図の重さ `RISK_SIGNAL_WEIGHT`（`heavy`・`light`・`retired`）を足した。`defect` は `retired`（以前の記録を読むために `RiskSignal` に残す）。
  - 依存の版の更新の上げ幅 `RiskDependencyUpdate`（`none`・`patch`・`minor`・`major`・`unknown`）を足し、`RiskAssessment` に `dependencyUpdate`（更新があるときだけ持つ）を足した。
- `apps/daemon/src/risk-assessment.ts`
  - `riskLevelFor`：合図の重さから決まる段階と、上げ幅から決まる段階の、高いほうを返す。合図があるときは、エージェントが付けた段階を使わない。
  - `riskCriteriaLines`（PR を作る前の評価と、レビューの工程の評価で共通の指示）：合図を、重い・軽いに分けて並べた。`defect` を外した。`security` の基準を「セキュリティにかかわる振る舞いを変える」にした。依存の版の更新の上げ幅の読み方と、混ざったときの決まりを足した。答えの形に `dependencyUpdate` を足した。
  - `RISK_LOADED_GUIDANCE_LINE`：読み込まれた内容で段階を決めたときは、`signals` を空にし、`dependencyUpdate` を `none` にさせる（sacty が決め直さないように）。
  - `extractRiskAssessment`：段階を `riskLevelFor` で決め直す。`defect` は読み捨てる。`dependencyUpdate` が決めた値でない答えは、読めないものとする（項目が無ければ、更新なし）。
  - `riskAssessmentLines`：合図の名前に重さを添え、依存の版の更新があれば上げ幅の行を出す。
- `apps/web/src/components/risk-assessment.tsx`・`apps/web/src/i18n/messages/parts.ts`：画面の欄でも、合図の名前に重さを添え、上げ幅を出す（日英）。
- docs：仕様書 `docs/spec/risk-assessment`（日英）、ユーザードキュメント `docs/user/tasks`（日英）、新しい ADR。前の ADR は、段階の決め方と合図の種類を置き換えたので、`superseded` にした。

人の決定に無く、実装で、安全な側（段階が高く出る側）に決めたこと：

- 上げ幅を読み取れない依存の更新（版の付け方が分からない・番号の版でないもので指している・前後の版を確かめられない・版を下げている）は、高。
- その依存の版の付け方で、互換性を約束していない上げ幅は、メジャーと同じ扱い。
- 複数の依存を更新するときは、いちばん大きい上げ幅。依存を足す・外すことは、版の更新として扱わない。
- 依存の更新と一緒にほかのコード・設定を変えているときは、その変更を合図と安全な種類で決めて、高いほう。
- sacty が自分で段階を上げるのは、メジャーと、上げ幅を読み取れない更新だけ。マイナー・パッチだけの変更が低になるのは、エージェントが合図を付けず、低と答えることによる（sacty は、差分から確かめない）。
- 合図があるときは、エージェントが付けた段階を使わない（軽い合図が 1 つなら、エージェントが高を付けていても中）。合図が無いときは、エージェントの段階のまま（高も、そのまま）。
- 答えにある `defect` は、読み捨てる（答えを読めないものにはしない）。
- 合図の名前に重さを添える・上げ幅を出す（人が、段階の理由を追えるように）。

### 事例の評価し直し（1）：実物の合図の組に、段階の決まりだけを当てはめる

PR #394〜#404 のレビューのコメントから、評価 38 回分の段階と合図を集め（`gh api repos/<owner>/<repo>/pulls/<番号>/reviews`）、`riskLevelFor` に通した。
「不具合の疑い」だけだった回は、合図を除くと、エージェントの段階（古い基準の高）を使えないので、合図なしの中として数えた。

| 決まり | 高 | 中 | 低 |
| --- | --- | --- | --- |
| 今まで（合図が 1 つでもあれば高） | 35 | 3 | 0 |
| 新しい決まり（合図は、実物のまま） | 32 | 6 | 0 |

- 中に変わったのは、「不具合の疑い」だけだった 3 回（#396 の 2 回、#398 の 1 回）。
- 高のままの 32 回の内訳：重い合図がある 25 回、重い合図が無く軽い合図が 2 つ以上の 7 回（#395 の 2 回、#396 の 1 回、#401 の 2 回、#402 の 1 回、#404 の 1 回）。軽い合図が 1 つだけの回は、無かった。
- 段階の決まりだけを変えても、実物の合図の組では、高ばかりのままになる。合図が、古い基準（1 つでも当たれば高）のもとで、1 回に平均で約 3 つ付いていたため。段階が分かれるかどうかは、新しい指示で、エージェントが合図をどう付けるかによる（次の節）。

### 事例の評価し直し（2）：新しい指示で、先頭のコミットを評価させる

`buildRiskAssessmentPrompt`（PR を作る前の評価の指示。基準の部分は、レビューの工程の評価と同じ）を、PR ごとに作り（題と本文は PR のもの、差分の起点は PR の起点との合流点、出すコミットは PR の先頭）、別のエージェントに 1 回ずつ渡して、評価させた。
答えの段階は、どの PR でも、`riskLevelFor` で決め直した段階と同じだった。

| PR | 変更 | 今まで（先頭のコミットの評価） | 新しい決まり | 合図・上げ幅 |
| --- | --- | --- | --- | --- |
| #394 | 依存のパッチの更新（脆弱性の修正） | 高（セキュリティ） | 低 | 合図なし・パッチ |
| #395 | +229 行 | 高 | 中 | 合図なし |
| #396 | +1,004 行 | 高 | 中 | 合図なし |
| #397 | +307 行 | 中 | 中 | 合図なし |
| #398 | +599 行（表示の文言） | 中 | 中 | 合図なし |
| #399 | +769 行 | 高 | 中 | 合図なし |
| #400 | +1,286 行 | 高 | 高 | 性能・並行処理、大きな差分（軽い 2 つ） |
| #401 | +480 行（レビューの基準の文言） | 高 | 高 | 構造・広い範囲の変更、確かめていない振る舞い（軽い 2 つ） |
| #402 | +1,166 行 | 高 | 中 | 構造・広い範囲の変更（軽い 1 つ） |
| #403 | +690 行 | 高 | 高 | セキュリティ（重い）、性能・並行処理 |
| #404 | +998 行 | 高 | 中 | 性能・並行処理（軽い 1 つ） |

- 段階の分かれ方：低 1・中 7・高 3（今までは、先頭のコミットで、高 9・中 2）。
- #394 は、`security` も `large` も付かず、上げ幅がパッチで、低になった。
- 確かめられなかったこと：
  - 実際のレビューの工程（動いている sacty に PR をレビューさせる形）では、評価し直していない。動いている sacty は止められず、別に起動して PR を取り込ませると、PR にレビューを投稿するため。
  - 1 回ずつの評価で、回ごとの揺れは確かめていない。
  - #396 は、今までの評価では重い合図が付く回が多かった（10 回のうち 7 回）。今回は合図なしの中で、付く合図が大きく減っている。評価の指示が違う（レビューと一緒に出す評価では、見つけた指摘に引かれる）ことの影響か、基準の文面の影響かは、切り分けていない。
  - メジャーの更新・上げ幅を読み取れない更新・依存の更新とコードの変更が混ざる PR は、事例に無い。段階の決まり（`riskLevelFor` と読み取り）は、単体テストで確かめた。エージェントが上げ幅を正しく読むかは、パッチの 1 件でしか確かめていない。
