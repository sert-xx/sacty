# 統合レビューで人の確認だけが残った観点を、人が確かめることとして承認待ちに出す

- 日付: 2026-11-16（UTC）
- タスク: PBI-363
- PR: #396
- ブランチ: feat/pbi-363-integration-human-checks-ci-failure
- 関係する ADR: [統合レビューで人の確認だけが残った観点は、不合格にせず、人が確かめることとして承認待ちに出す](../adr/20261116-2255-integration-review-human-checks.md)

はじめは、「指摘なし」の後の CI の失敗を画面に出す変更（PBI-364）も入れていたが、レビューの途中で外した（下の「レビューの指摘と対応」）。ブランチの名前に `ci-failure` が残っているのは、そのため。

## 目的

複数のリポジトリを指定する機能を sacty 自身に実装させたとき、統合レビューで、作業領域では確かめられず人の確認が要る観点（実際の GitHub とエージェントを使った確認）だけが残った。
統合レビューは不合格になり、修正の子タスクが作られたが、子タスクでは直せない。人が確かめた結果を親タスクに伝える手段も無かった。
人の確認だけが残った観点は、不合格にせず、人が確かめることとして、統合レビューの承認待ちに出す。

## したこと

- `IntegrationReviewed` に `humanChecks`（任意）を足した（`packages/core/src/events.ts`）。以前の版の記録は、そのまま読める。
- 統合レビューの指示に、作業領域では確かめられないことが残る観点の扱いを足した（`INTEGRATION_HUMAN_CHECK_LINES`）。確かめられる範囲で判定し、残ることを `humanChecks` に書く。`findings` には書かない。作業領域で確かめられることを、確かめずに回さない。
- 答えの読み取り（`extractIntegrationReview`）で `humanChecks` を読む。合否には使わない。同じ項目は1件にし、1件の長さを抑える。答えの JSON を直しながら読む形（`INTEGRATION_REVIEW_SHAPE`）にも項目を足した。
- 不合格で人が確かめることもあるときは、修正の子タスクを足す指示に「子タスクにしない」ものとして渡す（`integrationFindingLines`）。
- 画面：統合レビューの欄（タスクの詳細と承認の画面で同じ部品）に「人が確かめること」を出し、承認待ちの案内に件数を出す。
- 人が確かめた結果を伝える手段は、新しく作らず、統合レビューの承認・差し戻しにした（理由は ADR）。
- docs：仕様書（日英。`split-and-integrate`）、ユーザードキュメント（日英。`tasks` の「統合レビューの結果を確かめる」）、ADR。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| （1回目）[提案] `task.ts`：足した案内が日英とも3文以上で、判断・エラーの案内を2文までとする規則に合わない | 直した。統合レビューの案内と、「人が確かめること」の補足を、2文以内にした |
| （1回目）[提案] `docs/user/tasks.md`：子タスクの中止を人が認めた場合も統合レビューへ進むのに、「PR がすべてマージされると」と書いている | 直した（日英）。子タスクがすべて片付く（完了するか、中止を認める）と進むこと、中止した子タスクの変更は入っていないことを書いた |
| （1〜6回目）「指摘なし」の後の CI の失敗の表示（PBI-364）への指摘：CI の読み取りが、ほかの PR の確認を遅らせる／未完了の通信が積み重なる／取り消された CI・空の一覧を通ったと扱う／読み取りの一覧の取得が上限で打ち切られたときに、通ったと扱う／実行中の CI を読み続けると、GitHub の API の利用の上限に達しうる／テストの実時間への依存／エラーレポートの分類／文書の食い違い | 1〜5回目の指摘は、その都度直した。6回目でも、CI を読み続ける仕組みに新しい要修正が出たので、PBI-364 をこの PR から外し、別の PR に分けた（リポジトリの持ち主の代理の決定による。統合レビューの人の確認には指摘が残っておらず、PBI-364 の往復で止まっていたため）。外した時点のコードは、ブランチ `feat/pbi-364-ci-failure-as-reviewed` にある。CI の監視を定期の確認から切り離すこと・通信を中断することは、後続に回すと決まった |

## 残したこと

- 「指摘なし」の後に CI が失敗したことを、人に分かるようにすること（PBI-364）。別の PR で、仕組みを小さくして扱う。
- 人が確かめた結果を、項目ごとに記録すること。
- 実際の統合レビューのエージェントが、足した指示のとおりに、人が確かめることを `humanChecks` に分けるかは、確かめていない（指示の文と、答えの読み取り・合否・画面は、テストで確かめた）。
- 統合レビューの欄の「人が確かめること」の、実際のブラウザでの見え方は、確かめていない（種データに統合レビューのタスクが無い。部品の描画は jsdom のテストで確かめた）。
