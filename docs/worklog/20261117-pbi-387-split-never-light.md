# 子タスクに分けて進めるタスクは、オーケストレーターが軽いと答えても、セルフレビューを通常の深さにする

- 日付: 2026-11-17（UTC）
- タスク: PBI-387
- PR: #423
- ブランチ: feat/pbi-387-split-never-light
- 関係する ADR: [子タスクに分けて進めるタスクは、依頼が軽いと判定しない](../adr/20261117-1255-split-parent-is-never-light.md)

## 目的

依頼が軽いかどうかの判定は、オーケストレーターの答えがそのまま記録される。sacty が軽いとしないのは、セキュリティ対応のタスクだけだった。
リポジトリの持ち主の決定（2026-11-17）で、子タスクに分けて進めるタスク（分割の親）も、軽いと答えても通常の深さにする。

受け入れ条件の要点：

1. 分割の親は、オーケストレーターが軽いと答えても、通常として記録する。
2. 画面の判定の理由の表示（軽いと答えたが、sacty が通常にした、と分かること）・人の上書き・選び直しの扱いは、セキュリティ対応のタスクと同じ形にする。
3. 子タスクは、今までどおり、子ごとに判定する。ほかの組み合わせは変えない。
4. 仕様書・ユーザードキュメント（日英）・ADR・作業履歴を合わせる。

## したこと

- `apps/daemon/src/service.ts`：軽いとしない組み合わせ（`NEVER_LIGHT_PLANS`）に `split` を足し、組み合わせごとに、通常にした理由の文言を持たせた（`selfReviewDepthOf`）。
- `packages/core/src/messages.ts`：文言 `selfReview.depthForcedNormalSplit`（日英）を足した。セキュリティ対応の文言（`selfReview.depthForcedNormal`）は変えていない（すでにある記録は、そのまま表示できる）。
- `apps/daemon/src/prompts.ts`：工程の選択の指示（`SELF_REVIEW_DEPTH_LINES`）の、通常と答えさせる組み合わせに `split` を足した。
- 画面（`SelfReviewDepthNote`）は変えていない。記録した理由を、画面の言語で出す仕組みが、そのまま使える。
- docs：仕様書 `docs/spec/tasks-and-steps`（日英）、ユーザードキュメント `docs/user/tasks`（日英）、ADR。

決めたこと（ADR に書いた）：

- 「分割の親」は、工程を選ぶ時点で、選んだ組み合わせが `split` であることで見分ける。分割の親になるのは、この組み合わせを選んだタスクだけ。子タスクは `split` を選べない（`allowedPlans`）。
- 通常として記録するので、人の上書き（軽いと判定されたタスクだけが対象）は、セキュリティ対応のタスクと同じく、出ない。工程の選択からやり直すと、判定を選び直す。

## 確かめたこと

- 足したテスト
  - `apps/daemon/src/self-review-depth.test.ts`：`split` で軽いと答えると、通常と、sacty の文言（日英。オーケストレーターの理由を含む）を記録する。通常と答えたもの・答えが無いものは、そのまま。子タスクが選べる組み合わせに `split` が無く、子が選べる組み合わせの軽い判定は、答えのまま。サービスを通して、`split` と軽いを答えたタスクが、通常として記録され、要求要件の工程の指示が観点を絞らず、人の上書きを断ること。
  - `apps/web/src/components/self-review-depth.test.ts`：sacty が通常にした理由が、画面の言語（日英）で出て、軽くする操作が出ないこと。
- 修正を戻して（`service.ts` を変更の前に戻して）デーモンのテストを実行し、足した 2 件が落ちることを確かめた。
- `npm run lint`：成功。`npm run typecheck`：成功。`npx vitest run --no-file-parallelism`：261 ファイル・5050 件が成功（1 件はスキップ）。
- 確かめていないこと：実際のオーケストレーターが `split` と軽いを同時に答える実行（テストは、答えを渡して確かめた）。画面は、コンポーネントのテストで確かめ、動いている画面では確かめていない。
