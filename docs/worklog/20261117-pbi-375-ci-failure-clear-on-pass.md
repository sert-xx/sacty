# 指摘なしの後の CI の失敗の表示を、CI を読んでいる間に通ったら消す

- 日付: 2026-11-17（UTC）
- タスク: PBI-375
- PR: #410
- ブランチ: feat/pbi-375-ci-failure-clear-on-pass
- 関係する ADR: [指摘なしの後の CI の失敗の表示を、CI を読んでいる間に通ったら消す](../adr/20261117-0440-clear-ci-failure-when-ci-passes-while-reading.md)

## 目的

人の承認を待つ実装の PR の CI が失敗していたら、タスクの詳細（PBI-364）と、タスクの一覧の行の印（PBI-371）に出している。
回復を記録しなかったので、CI を再実行して通っても、表示は、PR を更新する・マージする・閉じるまで残った。
リポジトリの持ち主が、CI を読んでいる間に通ったら、表示を消すと決めた。

受け入れ条件の要点：

- CI を読む期間・回数は変えない（先頭のコミットごとに、5分おきに、12回まで）。期間が終わった後に通った CI は、拾わない。
- 「通った」は、CI の一覧が空でなく、すべて成功のときだけ。取り消し・空の一覧・読み切れなかった一覧では、消さない。
- 消したことを、作業履歴に残す。タスクの詳細の表示と、一覧の印の両方が消える。
- 仕様書・ユーザードキュメント（日英）・ADR・作業履歴に反映する。

## したこと

- デーモン（`apps/daemon/src/service.ts` の `readPullRequestCi`）：
  - 失敗を記録した先頭を、読むのをやめずに、同じ回数の上限の中で、同じ間隔で読むようにした。失敗を記録した回も、上限に数える。上限・間隔・1回の確認で読む件数は変えていない。
  - 失敗の表示を出している間に読んだ CI が通っていたら、`PullRequestCiRecovered` を記録して、その先頭は読むのをやめる。
  - 同じ先頭の CI が落ちたままなら、記録し直さない。
- 「通った」の判定（`packages/core/src/events.ts` の `ciAllPassed`）：一覧が空でなく、すべて終わっていて、結論が成功か、実行されなかった・中立で、成功が1件以上ある。取り消し・古い結果・実行中・結論の無いものが1件でもあれば、通っていない。
- CI の一覧を読み切れたか（`apps/daemon/src/ci.ts` の `CiSnapshot.truncated`）：一覧の取得をページの上限で打ち切った・続きのページをたどれなかったことを、呼び出し側に伝えるようにした。読み切れなかった一覧では、表示を消さない。
- 記録と投影（`packages/core`）：`PullRequestCiRecovered`（PR の番号・CI を読んだ先頭）を足した。`Task.pullRequestCiFailure` を消す。タスクの詳細の表示と一覧の印は、同じ判定（`pullRequestCiFailure`）を使っているので、両方が消える。
- 画面（`apps/web`。日英）：
  - 作業履歴に「PR #N の CI が通った（コミット）。CI の失敗の表示を消した」を出す。
  - タスクの詳細の案内は、「その後の結果は反映されない」という文を、今の結果を PR で確かめる案内に変えた。消える条件は、案内の補足（ⓘ）に出す（画面の文言の規則で、仕組みと数値は補足に書くため）。
  - 一覧の印の補足に、読み直す間に通れば消えることを足した。
- docs：
  - 仕様書（日英）：`approval` の「指摘なしの後の CI の失敗の表示」（読むのをやめる条件・消す条件・出す場所・しないこと・コードの場所）、`tasks-and-steps`。
  - ユーザードキュメント（日英）：`tasks` の「『指摘なし』の後に CI が失敗したとき」。
  - ADR：回復を記録しない決定（PBI-364・PBI-371 の ADR のその部分）を置き換える ADR を足した。古い ADR は、ファイル名・ステータス・置き換え先だけを直した（PBI-371 の作業履歴からのリンクも、新しい名前に直した）。
- ユーザードキュメントのスクリーンショットは撮り直していない。撮影のデータに CI の失敗の記録が無く、写っている所は変わらない。

自分で決めたこと（人の確認は、まだ）：

- 実行されなかった（skipped）・中立（neutral）の項目は、通ったことの妨げにしない。条件つきのジョブがあるワークフローでは、通った CI にも含まれるため。成功が1件も無い一覧は、通ったと扱わない。
- 人が PR にコミットを足して先頭が変わったときは、新しい先頭の CI が通ったら、前の先頭の失敗の表示も消す。
- 読み直しても、記録した失敗したチェックの一覧は更新しない。
- 消える条件の説明は、案内の本文ではなく、補足に出す。

同じ穴を作らないために確かめたこと（読み続ける最初の版が、レビューで指摘されたもの）：

- 取り消された CI だけの一覧・空の一覧・上限で打ち切った一覧を、通ったと扱わない（どれもテストにした）。
- 読む回数は、先頭のコミットごとの上限のまま（失敗の前後を合わせて12回）。持ち回り・間隔の切り替え・並列の読み取りは足していない。

## 確かめたこと

PR を作る前のコードで実行した結果。

- `npx vitest run --no-file-parallelism`：main（`80c9cf9a`）を取り込んだ後のコードで、256 ファイル・4936 件が通った（1 件は以前からの skip）。取り込む前は、251 ファイル・4857 件。
- `npm run typecheck`：通った。`npx biome check --error-on-warnings apps packages docs tests scripts`：指摘なし。`npm run build`：通った。
- 足した・変えたテスト：
  - `apps/daemon/src/daemon-implement.test.ts`：
    - 同じ先頭の CI がすべて通ったら、表示を消して記録し、その先頭は読むのをやめる。実行も PR の更新も始めない。再起動しても消えたまま。
    - 消さないもの（9 通り）：取り消しだけ・成功と取り消し・空の一覧・読み切れなかった一覧（読めた分はすべて成功）・実行中が残る・実行されなかったものだけ・古い結果・コミットの状態が成功でない・結論の無いもの。どれも、回数の上限（失敗を見つけた回を含めて12回）で読むのをやめ、その後に通っても消さない。
    - 取り消し・空の一覧・読み切れなかった一覧の後でも、上限の前にすべて通れば消す。
    - 上限の最後の読み取りで失敗を見つけたら、その後は読まない。
    - 人がコミットを足した新しい先頭の CI が通ったら、前の先頭の失敗の表示を消す。
    - CI を読んでいる間に PR がマージされたら、通っていても記録しない。
    - 失敗を記録した後も間隔ごとに読み、落ちたままなら記録し直さない（PBI-364 のテストの「その後は読まない」を、今の動きに直した）。
  - `packages/core/src/events.test.ts`：`ciAllPassed` の、通ったとするもの・しないもの（14 通り）と、`PullRequestCiRecovered` の形。
  - `apps/daemon/src/ci.test.ts`：一覧が上限（10 ページ）ちょうどなら読み切れている。11 ページ目が残る・続きのリンクが API の外を指すなら、読み切れなかったと返す。
  - `apps/web`：作業履歴の文言（`labels.test.ts`）、詳細の案内と補足（`live-screens.test.ts`）。エラーレポートで、消した記録を失敗に数えない（`error-report.test.ts`）。
- 判定を壊すとテストが落ちること：
  - 読み切れなかった一覧でも消すようにすると、足したテストの 2 件が落ちた。
  - 「通った」を「失敗が無い」に変えると、足したテストの 11 件が落ちた（取り消し・空の一覧・実行中など）。
  - どちらも戻して、通ることを確かめた。
- 実際の画面での確認（`scripts/docs-screenshots/` の種データと偽の GitHub を使い、別のポート（4796・4797）・一時の `SACTY_HOME`・一時の `HOME` で起動した。動いている sacty には触れていない。終わった後、起動したものは止めた）。日本語と英語の画面を、同時に開いて確かめた。29 項目がすべて合った。
  - 偽の GitHub が、実装の PR のマージ待ちのタスク（PR #128）の先頭のコミットの CI を「失敗」と答える：一覧の行に印（「CI 失敗」・「CI failed」）、詳細に案内と失敗していたチェック（CI・test）が出た。
    - 一覧の印の補足：「…読み直す間に通れば消えます。読み直すのは、最初に読んでから1時間ほどの間だけで、その後の結果は反映されません。…」（英語は「It clears if CI passes while Sacty is still re-reading it. …」）。
    - 詳細の案内：「PR の先頭のコミット 9e1d0c4 の CI が、… に失敗していました。今の結果を PR で確かめ、直すなら差し戻すか PR に指摘を書いてください。」と、補足「sacty が CI を読み直す間に通れば、この表示は消えます。…」（英語も同じ内容）。
  - 答えを「取り消し」に変える：次の読み取り（6分後）の後も、一覧の印と詳細の案内は、日英とも残った。
  - 答えを「成功」（実行されなかったジョブを1件含む）に変える：次の読み取り（5分後）の後、読み込み直さずに、一覧の印と詳細の案内が、日英とも消えた。一覧の状態（「実装の PR のマージ待ち」・「Implement PR awaiting merge」）は変わらない。
  - 作業履歴に「PR #128 の CI が通った（9e1d0c4）。CI の失敗の表示を消した」（英語は「CI passed on PR #128 (9e1d0c4). The CI failure notice was cleared」）が出た。
  - 消した後に、答えを「失敗」に戻す：その後の 2 回の PR の確認では CI を読まず、印は出ない。
  - デーモンが GitHub を変えようとした問い合わせは無かった。
- 確かめていないこと：実際の GitHub の CI での動き（再実行した CI の一覧の返り方を含む）。回数の上限（1時間ほど）まで待つことは、実際の画面では確かめていない（テストで確かめている）。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| 1回目（`811165c8`）：sacty のレビューは「指摘なし」（リスク評価の段階は中）。 | 直すものは無い。 |
| 1回目：PR の CI のコードの検査（CodeQL）が、足したテスト（`apps/daemon/src/ci.test.ts`）の、URL に文字列が含まれるかで宛先を確かめる書き方を指摘した（`js/incomplete-url-substring-sanitization`）。 | 問い合わせた先のホスト名（`new URL(url).hostname`）がすべて `api.github.com` であることを確かめる書き方に直した。テストだけの直しで、実装は変えていない。 |

### 2回目に出し直す前の検証（CodeQL の指摘を直した後のコード）

- `npx vitest run --no-file-parallelism`：256 ファイル・4936 件が通った（1 件は以前からの skip）。
- `npm run typecheck`：通った。`npx biome check --error-on-warnings apps packages docs tests scripts`：指摘なし。
- 1回目の先頭（`811165c8`）の PR の CI：`check`（lint・型検査・テスト）は通り、コードの検査（CodeQL）だけが上の指摘で失敗していた。
- 実装は変えていないので、実際の画面の確認はやり直していない。

## 残したこと

- 読む期間を延ばすこと・読み続けること・CI の失敗を自動で扱うこと（範囲外）。
- 失敗を見つけたのが遅いと、読み直す回数が残らない（最後の読み取りで見つけたときは、読み直さない）。持ち主の決定のとおり、期間は延ばしていない。
- 実際の GitHub の CI での動きは、確かめていない（PBI-364・PBI-371 と同じ）。
