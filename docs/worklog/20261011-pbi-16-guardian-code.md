# ゴールガーディアンにも、対象リポジトリのコードを読み取り専用で渡す

- 日付: 2026-10-11（UTC）
- タスク: PBI-16
- PR: #22
- ブランチ: feat/issue-16-guardian-code
- 関係する ADR: [ゴールガーディアンにも、対象リポジトリのコードを読み取り専用で渡す](../adr/20261011-0107-superseded-guardian-reads-target-code.md)

## 目的

調査やレビューにも実体のリポジトリを探索する必要があるという動作確認のフィードバックに対応する。ゴールガーディアンの変更の申し出の判定には起点のコードを、最終レビューには実装後のコードを、読み取り専用で渡す。渡す情報はコードと従来のものだけにし、指示でコードの中身と読むだけであることを伝える。用意できなければ、従来の失敗と同じく理由を記録して止める。

## したこと

- 変更の申し出の判定：起点のコミットのファイルを実行ごとのディレクトリに書き出し、読み取り専用（`:ro`）でマウントし、実行の後に消す。
- 最終レビュー・PR の指摘の戻し先の判断：実装の作業領域の内容（.git を除く）を写して読み取り専用で渡す（`apps/daemon/src/repository.ts` の `RepositoryWorkspace.copyWorkingTree`）。シンボリックリンクはリンクのまま写す。差分はこれまでどおり指示に入れる。
- 指示（`apps/daemon/src/prompts.ts`）：3つの指示に、作業領域のコードが「起点のコミット（短いハッシュ）のコード」か「実装後のコード」かと、読み取り専用で読むだけであることを足した。
- 失敗の扱い：書き出し・写しに失敗したら実行せず、変更の申し出は判定できない（エスカレーション）、最終レビューは一時停止、戻し先は判断できない（人間の確認）にする。
- ゴールガーディアンの3つの実行を、共通の `runGuardian` にまとめた（`apps/daemon/src/service.ts`）。

## 確かめたこと

- `npm test`：245件が通った（3件追加、既存の2件に確認を追加）。変更の申し出で起点のコードを読み取り専用で渡しコンテキストを渡さないこと、最終レビューと戻し先の判断で実装後の写しを読み取り専用で渡し終わったら消すこと、写せないときに最終レビューを実行せず止まること、実際のファイルで .git を除きシンボリックリンクをリンクのまま写すことを確かめた。読み取り専用で渡すのをやめると関係するテストが失敗することを確かめた。
- レビューで、`npm test`（245件）・`npm run lint`・`npm run typecheck` が通った。
- 読み取り専用のマウントが実際のコンテナで書き込みを拒否することは、PBI-15 で確かめた仕組みと同じとして、このタスクでは確かめていない。実際の Docker・エージェントでコードを読む動作も確かめていない。

## レビューの指摘と対応

指摘は無かった（承認のみ）。

## 残したこと

- 実際の Docker・エージェントでコードを読む動作は確かめていない。
- ゴールガーディアンがコードを読む分だけ、費用が増えることがある。
