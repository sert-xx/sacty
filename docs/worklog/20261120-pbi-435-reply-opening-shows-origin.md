# PR のコメントとして投稿する指摘への返信を、書き出しだけで、どの投稿への返信かが分かるようにする

- 日付: 2026-11-20（UTC）
- タスク: PBI-435
- PR: なし
- ブランチ: なし
- 関係する ADR: なし

## 目的

同じ回に、AI のレビューの本文への返信と人の通常のコメントへの返信が PR のコメントとして並ぶと、違いがリンクの文字と署名の末尾の指摘の ID だけで、同じ内容を2回投稿したように見えた。最初の数行だけで、別々の投稿への別々の返信だと分かるようにする。

投稿の数・宛先、行へのコメントのスレッドへの返信の本文、目印・太字の頭・注記・署名は変えない。

## したこと

- `apps/daemon/src/remark-reply.ts`
  - 書き出しを文にした：「<出どころ><種類>（リンク）への返信です。」。種類はレビューの本文・通常のコメント・行へのコメント、出どころは「sacty の AI が書いた」「人が書いた」。
  - 通常のコメントへの返信には、書き出しの次の行に、元のコメントの冒頭の引用（`remarkQuote`）を足した。
  - 返信の文章と引用で、切り詰め（サロゲートペアを避ける）と `@` の処理を共通の関数にした（振る舞いは変えていない）。
- `apps/daemon/src/service.ts`：`RemarkReplyDue` に `source`・`originText` を足し、差し戻しの指摘から渡す。
- 文書：`docs/spec/approval`・`docs/user/tasks`（日英）の返信の形。

## 決めたこと

- 引用の長さは 100 文字。1通を3行ほどに収め、同じ回の通常のコメントを見分けるのに足りる長さとして決めた。
- 引用は `> 「…」` の1行。「 」で囲むのは、行頭が見出し・リストなどの Markdown にならないようにするため。`<` は `&lt;`、「`」は「'」に置き換える。
- 引き継いだ PR の指摘は、出どころと元の本文を記録していない（`continuedResponses` は対応の文だけ）。記録を足さず、GitHub も読み直さず、出どころを書かず引用を付けない形にした（書き出しは、種類とリンクだけ）。
- レビューの本文には引用を付けない（AI のレビューの本文は、目印・見出し・`@名前` から始まり、冒頭を引用しても見分けの役に立たないため）。
- 新しく書く文の製品名は、署名と同じ小文字の「sacty」にした。
- 書き出しと引用で、再レビューに作者の返答として渡る返信の文字数が増える（1件 2,000 文字の上限の内側。デーモンのレビューまわりは変えていない）。
- ADR は足していない。決定（指摘ごとに返信する・宛先・目印）は変えず、返信の書き出しの形だけを直したため。
