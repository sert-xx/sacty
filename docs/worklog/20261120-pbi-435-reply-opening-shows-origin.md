# PR のコメントとして投稿する指摘への返信を、書き出しだけで、どの投稿への返信かが分かるようにする

- 日付: 2026-11-20（UTC）
- タスク: PBI-435
- PR: なし
- ブランチ: なし
- 関係する ADR: なし

## 目的

同じ回に、AI のレビューの本文への返信と人の通常のコメントへの返信が PR のコメントとして並ぶと、違いがリンクの文字と署名の末尾の指摘の ID だけで、同じ内容を2回投稿したように見えた。最初の数行だけで、別々の投稿への別々の返信だと分かるようにする。

投稿の数・宛先、行へのコメントのスレッドへの返信の本文、目印・太字の頭・注記・署名は変えない。

## したこと

- `apps/daemon/src/remark-reply.ts`
  - 書き出しを文にした：「<出どころ><種類>（リンク）への返信です。」。種類はレビューの本文・通常のコメント・行へのコメント、出どころは「sacty の AI が書いた」「人が書いた」。
  - 通常のコメントへの返信には、書き出しの次の行に、元のコメントの冒頭の引用（`remarkQuote`）を足した。
  - 切り詰め（サロゲートペアを避ける）と `@` の処理は、`human-ask-notice.ts` の `cutAtMax`・`withoutMentions`（`publicText` と共通。振る舞いは変えていない）を使う。
  - 出どころと引用の組み立てを `remarkReplyOrigin` にまとめた。
- `apps/daemon/src/service.ts`：`RemarkReplyDue` に `source`・`originText` を足し、差し戻しの指摘から渡す。人が「この PR で直す」と決めた案の指摘（`fixOf`）は、元の指摘の出どころを引き継ぐ。
- 文書：`docs/spec/approval`・`docs/user/tasks`（日英）の返信の形。

## 決めたこと

- 引用の長さは 100 文字。1通を3行ほどに収め、同じ回の通常のコメントを見分けるのに足りる長さとして決めた。
- 引用は `> 「…」` の1行。「 」で囲むのは、行頭が見出し・リストなどの Markdown にならないようにするため。中の文字は置き換えず、インラインコードに入れる（レビューの指摘：置き換えの列挙だと、参照・画像・リンク・文字参照が残るため）。
- 引き継いだ PR の指摘は、出どころと元の本文を記録していない（`continuedResponses` は対応の文だけ）。記録を足さず、GitHub も読み直さず、出どころを書かず引用を付けない形にした（書き出しは、種類とリンクだけ）。
- レビューの本文には引用を付けない（AI のレビューの本文は、目印・見出し・`@名前` から始まり、冒頭を引用しても見分けの役に立たないため）。
- 新しく書く文の製品名は、署名と同じ小文字の「sacty」にした。
- 書き出しと引用で、再レビューに作者の返答として渡る返信の文字数が増える（1件 2,000 文字の上限の内側。デーモンのレビューまわりは変えていない）。
- ADR は足していない。決定（指摘ごとに返信する・宛先・目印）は変えず、返信の書き出しの形だけを直したため。

## 確かめたこと

- `apps/daemon/src/remark-reply.test.ts`：書き出しの種類・出どころ・リンク、引用（1行・上限・秘密情報が切り口をまたぐ・サロゲートペア・`@`・パス・HTML・Markdown・目印を壊さない）、sacty のレビューの本文と人のコメントの返信で最初の2行が違うこと。
- `apps/daemon/src/daemon-implement.test.ts`（取り込んだ PR の指摘への対応を、PR に返信する）：指摘が1件・複数・sacty のレビューと人のコメントが混ざる・行へのコメントと通常のコメントが混ざる（行への返信を断られた場合を含む）・引き継いだ PR の指摘の、投稿の数・宛先・書き出し。同じ確認・実行で重ねて投稿しないこと（既存のテスト）も通る。
- `npx biome check .`・`npm run typecheck`・`npx vitest run`（全件）。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| 「この PR で直す」と決めた案の返信が「人が書いた」になる | `fixOf` の元の指摘の `source` を引き継ぐ。テストを足した |
| 引用の置き換えの列挙では、参照・画像・リンクなどが残る | 引用をインラインコードに入れる方針に変えた。見た目は等幅になる |
| 返信の頭が長くなり、再レビューに渡す返答の末尾が早く切れる | 変えない。長い対応の文（約 1,700 文字以上）は、まれと判断した。残したことに書く |
| 利用者向け文書の、出どころと引用が付かない範囲 | 日英とも、実装に渡した指摘への返信に絞った |
| 引き継いだ PR の指摘のテストが弱い | 書き出しの行を `toEqual` で比べ、引用が付かないことを確かめる |
| 切る・`@` の処理が `publicText` と重なる | `cutAtMax`・`withoutMentions` を共有した |
| `origin` の組み立てが入れ子 | `remarkReplyOrigin` に出した |
| 作業履歴に「残したこと」が無い | 節を足した |

## 残したこと

- 再レビューに作者の返答として渡る返信は、1件 2,000 文字で切られる（デーモンのレビューまわりで、範囲外）。書き出し（約 100 文字）と引用（約 110 文字）の分、対応の文が約 1,700 文字以上のときだけ、末尾が届かない。長い対応の文はまれと判断し、変えていない。
