# 要求要件・設計の人間が読む量を抑える

- 日付: 2026-10-24（UTC）
- タスク: なし
- PR: #217
- ブランチ: claude/pensive-johnson-bnbhk4
- 関係する ADR: [要求要件・設計の冒頭に人間が判断することを分けて置き、書く量を変更に比例させ、セルフレビューに書きすぎの観点を足す](../adr/20261024-1330-superseded-reader-load-of-requirements-and-design.md)

## 目的

要求要件・設計が過剰になり、承認する人の認知の負荷が高くなる問題を減らす。

## したこと

- 要求要件・設計の工程の指示に、構成と分量の決まり（`readerLoadLines`）を足した。最初に「確認したいこと」（最大 5 件・推奨の答えと理由付き）と「既定で決めたこと」を置かせ、詳細には依頼と今回の変更に要ることだけを書かせる。
- 設計の節を、今回の変更で書くことがあるものだけにさせた。テスト観点の異常系・境界値を、今回の変更で新しく起こりうるものにした。
- EARS の指示とスキル `ears-requirements` で、異常系を今回の変更で起こりうるものに絞り、依頼に無い要求・既存の仕組みの言い直しを要求にしないようにした。
- スキル `review-dispatch` の `design-doc` の必須の観点に D-10（簡潔さ・範囲）を足し、`review-execution/references/D-10.md` を作った。D-3 を、今回の変更で起こりうる欠落に絞り、「対象外」の記載を求めないようにした。
- 自己レビューの `design-doc` で、記述を足す `should` を作者の判断にし、D-10 の `should` は直すようにした。
- 日英の仕様書（タスクと工程・コンテキスト）とユーザードキュメント（タスク）を直し、ADR を足した。

## 確かめたこと

- `npm run build`・`npm run lint`・`npm run typecheck`：成功（lint の整形の誤り 1 件は `biome format` で直した）。
- `npx vitest run tests/docs apps/daemon/src/prompts.test.ts apps/daemon/src/default-skills.test.ts`：230 件成功。
  要求要件・設計の指示に2つの節・件数の上限・書かないことが入り、ほかの工程には入らないことを、足したテストで確かめた。
- `npx vitest run`：2649 件成功、8 件失敗。
  失敗は、プロセスの後始末・読めないファイル・層の写しの失敗・ブラウザーのテストの 4 ファイルで、変更を外した状態でも同じ 8 件が失敗する（環境が原因）。

## レビューの指摘と対応

- 提案 1 件：D-3 のチェックポイントに「対象外」の明示を求める行が残り、「関係しない項目に『対象外』の記載を求めない」と食い違っていた。
  今回の変更が関係する項目を意図して扱わないときだけ、その旨と理由を求める形に直した。
