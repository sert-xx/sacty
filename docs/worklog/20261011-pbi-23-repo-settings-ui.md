# プロジェクトの設定を分かりやすくする（PR作成許可・削除ボタン・コンテキストは任意）

- 日付: 2026-10-11（UTC）
- タスク: PBI-23
- PR: #29
- ブランチ: feat/issue-23-repo-settings-ui
- 関係する ADR: なし

## 目的

動作確認でのフィードバックに対応し、プロジェクトの設定を分かりやすくする。リポジトリの設定の「PRを作る」は説明が足りず、リポジトリを設定したら PR が作られるのかと誤解された。削除ボタンは × のボタンにしたいという要望もあった。追加の要望として、もともと任意のコンテキストリポジトリが、画面では必須に見えていたのを直す。

## したこと

- 「PRを作る」を「PR作成許可」（英語は Allow PRs）にし、オン・オフで何が変わるかを説明に添えた。オンは成果物を PR として出して PR の上で確認する（マージで承認、レビューやコメントで差し戻し）。オフは sacty のブランチへのプッシュまでにして、sacty の画面で承認・差し戻しする。
- 取り込み元・リポジトリの設定の削除ボタンを × のアイコンのボタンにした。スクリーンリーダーには「リポジトリの設定『acme/app』を削除」のように、何を削除するかを伝える（`apps/web/src/components/project-editor.tsx`）。
- リポジトリの設定の説明を、画面で作るタスクがここから対象リポジトリを選ぶ今の動作に合わせた。`README.md` の書き方もそろえた。
- コンテキストリポジトリ（スキーマ・設定画面・デーモンのどれでも、もともと任意）：見出しを「コンテキストリポジトリ（任意）」にし、例の値を「例：git@github.com:acme/sacty-context.git」「例：main」と例とわかる形にした。設定しないときはコンテキストを渡さずに工程を実行することと、外し方を説明に書いた。ブランチ・タグは、リポジトリを設定したときだけ入力できるようにした。
- 見た目：ダークテーマの補足の文字（muted-foreground）を明るくし（カードの背景に対して 7.4:1 → 9.7:1）、入力欄の例は専用の色（`--placeholder`）にして補足の文字より一段控えめにした（`apps/web/src/app/globals.css`）。小さく細い文字が暗い背景に沈んで見えていたため。補足の文字を明るくしても、例が入力済みの値に見えないようにするため。
- 既定のコンテキスト（規則・スキル・MCP の設定）を埋め込み、ルートの層として渡す部分は、別のタスク（PBI-24）にした。

## 確かめたこと

- テスト 291件・リント・型チェック・ビルドが通った。#28 をマージした main を取り込んだ。
- コンテキストを外して保存でき、無ければ何も渡さずに工程を実行することを、テストで確かめた。
- 一時的な環境で、プロジェクトの設定画面を確かめた：説明と「PR作成許可」が出ること、× ボタンの読み上げ名が「取り込み元『（未入力）』を削除」「リポジトリの設定『（未入力）』を削除」になること、押すと行が消えること、コンテキストリポジトリの見出しの「任意」・例の表示・説明、空のときにブランチ・タグが入力できないこと。
- レビューで、全291件のテスト・lint・typecheck が通った。レビューでは、ブラウザでの画面操作とビルドは行っていない。

## 残したこと
