# 人間の出番を Slack に通知する

- 日付: 2026-10-12（UTC）
- タスク: PBI-38
- PR: #44
- ブランチ: feat/issue-38-slack
- 関係する ADR: [人間の出番（承認待ち・エスカレーション・一時停止・完了）を、プロジェクトごとに設定した Slack の通知先に送る](../adr/20261012-1352-superseded-slack-notification.md)

## 目的

自走させるうえで人間の出番を知らせる手段が無かったので、プロジェクトごとに Slack へ通知する（構想の「通知」）。受け入れ条件の要点：
プロジェクトの設定で通知先（Slack API の形か Incoming Webhook）と言語を設定でき、設定しなければ通知しない、承認待ち・エスカレーションで
タスクのタイトル・何の判断か・承認の窓口へのリンクを通知する、一時停止（人間が止めたときを除く）は理由とリンクを通知する、完了はリンクを
通知する、秘密情報を作業履歴・画面・ログに出さない、送れなくてもタスクは止めず、どのプロジェクトの通知が送れなかったかと理由を画面に出す、
設定の画面からテストの通知を送れる、日本語・英語。

## したこと

- core（`packages/core/src/projects.ts`）：プロジェクトの定義に `notification`（`slack-api`：url・channel・token? / `slack-webhook`：webhook。どちらも language）。
  秘密情報は名前か `op://` の参照だけを受け付ける。エクスポートにも含める。
- `apps/daemon/src/notifier.ts`（新規）：状態の変わり方から通知することを決める（承認待ちは、差し戻して出し直したときも）。本文を作り、送る
  （Slack API の `ok:false` も失敗）。送れなかった理由は秘密情報を伏せてプロジェクトごとに持ち、送れたら消す。
- `apps/daemon/src/service.ts`・`apps/daemon/src/server.ts`：作業履歴を書いたときに通知する（送るのは待たない）。テストの通知の API。
  状態の warnings に、送れなかった理由を出す。
- CLI（`packages/cli/src/index.ts`）：画面の URL（`SACTY_WEB_URL`）をデーモンに渡す（通知のリンクに使う）。
- 画面（`apps/web/src/components/project-editor.tsx` など）：プロジェクトの設定に「Slack の通知」（送り方・言語・URL・チャンネル・トークン・Webhook）と
  「テストの通知を送る」（保存した設定で送る）。`README.md` に説明を足した。
- レビューの指摘で、HTTP の失敗の本文を伏せてから切り詰めるようにした。

## 確かめたこと

- `npm test`（417 件）・`npm run lint`・`npm run typecheck` が通った（指摘の修正の後、レビューで全 418 件・lint・typecheck の成功を確かめた）。
- 人間が止めたときは通知しない・Slack の `ok:false` を失敗にする・送れたら理由を消す・出し直したら通知する・作業履歴を書いたときに通知する、
  の修正を1つずつ戻すとテストが失敗することを確かめた。
- ホストに Slack API の偽物（Slack Proxy の代わり）を立て、画面で通知先を設定し、テストの通知と、タスクが要求要件の承認待ちになったときの通知が
  届くこと、通知の「承認の画面」のリンクから sacty の承認の画面が開くことを確かめた（動画あり）。
- 実際の Slack・Slack Proxy への送信と、ブラウザでの操作は、レビューでは確かめていない。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| HTTP の失敗の本文を 300 文字に切り詰めてから秘密情報を伏せるので、境界をまたぐトークン・Webhook の URL の一部が、ログ・画面の警告・テストの通知の例外に残る | 本文は切り詰めずに理由に入れ、トークン・Webhook の URL（値そのもの・JSON の文字列にした形・各行）を伏せてから、理由を 400 文字に切り詰めるようにした。HTTP 500 の本文を `'x'.repeat(N) + 秘密情報` にする回帰テストを N = 0・280・290・380・395・5000 で、トークンと Webhook の URL のそれぞれについて足し、元の順に戻すと失敗することを確かめた |

## 残したこと

- 実際の環境での確認（プロジェクトの設定で Slack API の形を選び、ワークスペースの Proxy の chat.postMessage の URL とチャンネルを書いて
  テストの通知が届くことを確かめる。もう1つのワークスペースのプロジェクトでも同じく確かめる）は、利用者の環境で行う。
