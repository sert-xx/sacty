# タスクの一時停止・再開・中止（作業の片付けつき）をできるようにする

- 日付: 2026-10-10（UTC）
- タスク: PBI-3
- PR: #12
- ブランチ: feat/issue-3-pause-cancel
- 関係する ADR: [タスクの一時停止は作業領域を残して止めたところから再開でき、中止は sacty が作ったものだけを確認の画面に並べてから片付ける](../adr/20261010-1142-superseded-pause-and-cancel-with-cleanup.md)、[台帳にイベントを書く前に状態の復元に通し、受け付けられないイベントは書かない](../adr/20261010-1142-validate-events-before-append.md)

## 目的

- タスク詳細から一時停止・再開ができる。一時停止では作業中のものを残す。
- 中止は、確認のダイアログで片付ける対象を一覧にしてから行う。
- 中止すると子タスクもすべて中止される。人間が作ったブランチや PR には触れない。
- すべての操作を台帳に記録し、中止の後も台帳は残す。

## したこと

- 一時停止・再開・中止の処理：`apps/daemon/src/service.ts`、API は `apps/daemon/src/server.ts`。イベント（`TaskPaused`・`TaskCancelled`・`BranchPushed` など）は
  `packages/core/src/events.ts`、状態の復元は `packages/core/src/projection.ts`。
- PR を閉じる・ブランチを消す：`apps/daemon/src/github.ts`・`apps/daemon/src/repository.ts`。ブランチは `sacty/` で始まるものだけを受け付ける。
- 画面：タスク詳細に一時停止・再開・中止（確認の画面つき）を置いた（`apps/web/src/components/task-controls.tsx`・`apps/web/src/app/tasks/[id]/page.tsx`）。
  片付けの結果と一時停止の理由を、日本語・英語で出す（`apps/web/src/i18n/messages/`）。
- 片付けの結果のエラー文から、トークンを取り除く。
- レビューの対応で、次のことを足した。
  - 台帳に書く前に状態の復元に通し、受け付けられないイベントは書かない。中止したタスクの指摘の無効化を拒否する。
  - PR を作ったリポジトリを `PullRequestPublished.repo` に記録し、中止ではそのリポジトリの PR だけを閉じる。
  - clone や秘密情報の取り出しの間に止められたら、コンテナ（実装・テスト）を起動しない。
  - プッシュしたブランチを、PR の作成の前に `BranchPushed` として記録する。
  - 実行器（`apps/daemon/src/agents/docker.ts` の `RunningContainers`、`DockerExecutor`・`DockerTestRunner` で共用）で、止める要求を `docker run` が終わるまで保持し、
    コンテナが作成中なら `docker run` の子プロセスを止めて `docker kill` を繰り返す。タイムアウトとデーモンの停止も同じ経路にした。
  - 止める要求があった実行は、`docker ps` でコンテナが無いことを確かめるまで完了にしない。確かめられなければ、一時停止に警告を添え、中止では作業領域を消さない。
  - 確かめられなかった実行を `TaskPaused.unstoppedRuns` に記録し、中止・再開で確かめ直す。一時停止の API は、止めたことの確認と記録まで待つ。

## 確かめたこと

- `npm test`：157件が通った（10件追加）。実行待ち・実行中・テスト中の一時停止と再開、人間の判断待ちでは止めないこと、中止の片付け（PR・ブランチ・作業領域）、
  実行中の中止、片付けの失敗の記録、中止したタスクへの操作の拒否を確かめた。レビューの対応を重ねた後は170件が通った。
- 本物の git で、sacty のブランチだけを消し、人間のブランチは消さないことを確かめた。
- 画面とローカルの Docker で、次のことを確かめた。
  - テストの実行中に一時停止すると、コンテナが止まり、作業領域が残る。
  - 中止の確認の画面に対象が並び、中止すると片付けの結果が表示・記録される。
  - ブランチをプッシュ済みのタスクを中止すると、ローカルの origin から `sacty/task-*` が消え、main は残る。
  - 実際の Docker で、コンテナの起動中（50ms後）に止めると、実行が終わってからコンテナが残っていない。
- 回帰テストは、どれも修正を外す・戻すと失敗することを確かめた。
- レビューでは、各回で `npm test`・`npm run lint`・`npm run typecheck` が通ったことを確かめた。レビューでの Docker の検証はモックと偽の Docker のコマンドによるもので、
  実際の Docker とブラウザの操作は、レビューでは確かめていない。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| P1：中止の後に指摘の無効化を送ると、拒否されても台帳に残り、次の起動で状態を復元できずデーモンが起動できなくなる | 台帳に書く前に状態の復元に通し、受け付けられないものは書かないようにした。中止したタスクの指摘の無効化もサービスで拒否する。回帰テストを2件足した |
| P1：閉じる PR を、記録した番号といまの設定のリポジトリで決めるので、設定を変えると別のリポジトリの同じ番号の PR を閉じる | PR を作ったリポジトリを記録し、そのリポジトリと番号の PR だけを閉じるようにした。記録が無い古い PR は閉じずに失敗として残す。回帰テストを足した |
| P2：clone や秘密情報の取り出しの間に止めると、準備の後に新しいコンテナが起動する | コンテナを起動する直前に止める要求を確かめ、要求があれば起動せず人間の一時停止として記録するようにした（テストも同じ）。回帰テストを足した |
| P2：プッシュの後に PR の作成が失敗すると、プッシュ済みのブランチが中止で消されない | PR の作成の前に `BranchPushed` を記録し、確認の画面と中止はその記録から消すブランチを決めるようにした。回帰テストを足した |
| P2：`docker run` の子プロセスを起動した後、コンテナが作られる前に止めると、`docker kill` が失敗したまま、後でできたコンテナが止まらない | 実行器で止める要求を保持し、作成中なら `docker run` を止めて `docker kill` を繰り返すようにした。回帰テスト（`apps/daemon/src/agents/containers.test.ts`）を足した |
| P2：子プロセスが終わっただけで実行を完了にするので、遅れてできたコンテナが残ったまま一時停止・中止が進む | コンテナが無いことを確かめるまで完了にしないようにし、確かめられなければ失敗として伝える。一時停止は警告を添え、中止は作業領域を消さない。回帰テストを足した |
| P2：一時停止の後に中止すると、止めたことを確かめられなかったコンテナがあっても作業領域を消す | 確かめられなかった実行を `TaskPaused.unstoppedRuns` に記録し、中止・再開で確かめ直すようにした。確かめられなければ中止は作業領域を残し、再開は拒否する。回帰テストを足した |
| P2：一時停止の API が、止めたことの最後の確認と記録を待たずに返る | 実行の完了を待つ Promise に、止めたことの確認と一時停止の記録まで含め、その間は登録を残すようにした。回帰テストを足した |

## 残したこと

- 子タスクの中止は、MVP にまだ親子関係が無いため対象外にした。親子関係を入れるときに対応する。
