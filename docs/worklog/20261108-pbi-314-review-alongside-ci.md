# 最終レビューを、実装の PR の CI と並べて進める

- 日付: 2026-11-08（UTC）
- タスク: PBI-314
- PR: #320
- ブランチ: feat/issue-314-review-alongside-ci
- 関係する ADR: [最終レビューを、実装の PR の CI と並べて進める](../adr/20261108-0232-final-review-alongside-pull-request-ci.md)

## 目的

ドラフトの PR の CI が終わるまで（最長 60 分）最終レビューを始めず、CI と最終レビューの時間が足し合わさっていたのを、重ねて縮める。

## したこと

- ドラフトの PR を作ったら、CI を待たずに最終レビューを始める（`awaitingVerification` を、合格後に CI の結果だけを待つ間だけ止めるようにした。`awaitingCiAfterReview`）。
- CI が終わっていない最終レビューには、CI を待たせない・判定に使わせない指示（`PENDING_CI_LINES`）を渡し、`FinalReviewed` に `beforeCi`（待っていた CI のコミット）を記録する。
- 投影：
  - 不合格なら、待っている CI を捨てて実装に戻す。
  - 合格なら `pullRequestCi.reviewedBeforeResult` を付けて CI の結果を待つ。
  - CI が初回で通った・無いなら承認待ちへ進める（`ciConfirmsReview`）。落ちた・時間切れ・再実行で通ったなら最終レビューし直す。
  - 最終レビューの間に CI が終わっていた場合も、同じ規則で決める。
- 最終レビューし直すときは、前の回の検証の記録を「CI の結果の前の最終レビュー」として使い回させる。
- CI を待つ間の最終レビューの前には、ベースブランチを取り込まない。
- 画面の「PR の CI を待っている」は、合格後に CI の結果を待つ間だけにした。
- 仕様書（日英）・ユーザードキュメント（日英）・ADR（前の ADR を一部置き換え）を直した。

## 確かめたこと

- `npm run lint`・`npm run typecheck`・`npx vitest run tests/docs`：通った。
- `npx vitest run --no-file-parallelism`：210 ファイル、4379 件が通った（3 件は既存のスキップ）。
- 修正を一時的に戻して、7 通りすべてで新しいテストが失敗することを確かめた：検証の待ちの条件・再実行で通ったときの扱い・不合格で CI を捨てる・取り込みを飛ばす・前の回の記録の使い回し・`beforeCi` の記録・CI の終わりでの確定。
- 確かめていないこと：実際の GitHub の CI と並べたときの時間の短縮（実際のエージェントとリポジトリで動かしていない）。

- レビュー対応の後：`npx tsc -b packages/core`・`npm run -s lint`・`npm run -s typecheck`・`npx vitest run tests/docs`（93件）・`npx vitest run --no-file-parallelism`（4381件成功・3件スキップ）。予算の修正を外すと、足した2件のテストが落ちることを確かめた。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| sacty（要修正）：CI を待つ間の最終レビューで予算の上限に達すると、合格しても一時停止し、CI が通っても承認待ちへ進めない | 合格した後に CI の結果だけを待つ間は、警告だけ記録して一時停止しないようにした（`verify`）。CI が落ちた後の最終レビューのし直しは、既存の実行前の予算の確認で止まる。両方の経路のテストを足し、修正を外すと落ちることを確かめた。仕様に書いた |
| sacty（提案）：図（`verify`）と仕様の本文に、CI を待ってから最終レビューする古い順序が残っている | 図の定義を、PR の CI が動き出す → 最終レビュー → 合格したら CI の結果を待つ（落ちたら最終レビューし直す）に直して作り直した（日英）。仕様の本文も直した |
| sacty（提案）：`projection.ts` の `pullRequestCi` のコメントが新しい動作と逆 | `pullRequestCi`・`PullRequestPublished` の `verifying`・投影・`draftPullRequests`・`PullRequestBodyStage` のコメントを、CI と並べる順序に直した |
| sacty（提案）：ベースブランチを取り込む条件を、CI の結果を受けて最終レビューを実行する場合と明記する | 仕様（日英）に、CI と並べた最終レビューに合格した後に CI が初回で通った・CI が無いときは取り込まないことを書いた |
| sacty 2回目（提案）：図の「通った・CI 無し」が再実行での成功も含んで見える | 図のラベルを「初回で通った・CI 無し」と「落ちた・時間切れ・再実行で通った」に分け、図の説明も合わせて、日英の SVG を作り直した |
| sacty 2回目（提案）：`service.ts` の `verify` に、CI の完了後に最終レビューへ進む説明が残っている | CI の結果を待たずに最終レビューに進む説明に直した |
| sacty：長い URL の性能テストが 1000ms を超えた | 今回の差分と関係しない、負荷の高いときのテストの時間の揺れ。手元では通った（下の確認） |

## 残したこと

- CI が落ちたときの2回目の最終レビューを、CI の失敗の判断だけに絞ることはしていない（今までどおりの最終レビューで、検証を使い回させる）。
