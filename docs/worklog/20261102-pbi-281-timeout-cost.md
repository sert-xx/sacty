# 時間切れで止めた実行の費用を記録する

- 日付: 2026-11-02（UTC）
- タスク: PBI-281
- PR: なし
- ブランチ: feat/issue-281-timeout-cost
- 関係する ADR: [結果が出る前に止めた実行は、出力から読めた分を費用に入れ、読めなければ 0 ではなく不明と記録する](../adr/20261102-1730-record-cost-of-runs-stopped-before-result.md)

## 目的

フィールドの試行（時間切れの再開）で、時間切れで止めた実行（要求要件 3 回・実装 5 回）の費用がどれも $0.0000 と記録された。
時間切れ・エラーで止めた実行でも、出力から拾える分を費用に記録して予算の判定に入れる。拾えないときは、$0 と見せず、費用が不明であることを
画面と作業履歴に出す。

## したこと

- 実際の出力で確かめた：時間切れの実行の出力には、Claude Code は `assistant` ごとの `message.usage`（内容ごとの出来事が同じ id・同じ使用量を
  繰り返す。出力のトークン数は発言の途中の小さい値）、Codex は番が終わるまで使用量が無い。
- 出力の読み取り（`ClaudeOutcomeReader`・`CodexOutcomeReader`）：`result` / `turn.completed` が出る前に止まった失敗に、読めた使用量と
  不明の印（`costUnknown`）を持たせた。出来事が1つも届かない実行には付けない。
- 実行器（`DockerExecutor`）：時間切れのエラーを `AgentTimeoutError` にし、止めるまでに読めた使用量を添える。投げる流れは変えていない。
- サービス（`executeLogged` ほか）：エラーから使用量を費用にし、`Executed.costUnknown` として、失敗を記録するイベントの各所に渡す。
  代わりのエージェントで判定し直したときは、先の実行が不明なら合計も不明にする。
- イベント・投影：失敗を記録しうる10種類のイベントに任意の `costUnknown`。`chargeBudget` が `budget.unknownRuns` に回数を数える。
- 画面：工程ごとの費用の表（行・合計・各回）で「$…以上」「不明」と出し、表の下に注記。タスクの詳細の費用の欄に回数。作業履歴の行にも出す。
- 仕様書（agent-execution・event-log）・ユーザードキュメント（config・troubleshooting）の日英と、ADR を直した。

## 確かめたこと

- 今回の試行の実際のログ（`~/.sacty/runs/…`、読むだけ）をパーサーに通した。Claude の時間切れ 2 回は、読めた分の合計が約 $1.5 と約 $6.7（list の単価で換算）
  の下限と不明の印になり、Codex の時間切れ 3 回（容量不足の失敗を含む）は、使用量なしで不明の印になった。
- テスト（追加）：パーサー（Claude・Codex の空・1件・複数件・同じ id の繰り返し・id の無い出来事・`result` ありの場合）、実行器の時間切れ（出力あり・なし・
  壊れた途中の行・Codex）、サービス（読めた分の記録と予算の判定・読めない場合・何も使っていない失敗・再開の繰り返しの合計・オーケストレーター・代わりのエージェント）、
  `chargeBudget`・投影、表の集計・作業履歴の文言・表の描画。修正を戻すとパーサー・実行器・サービスのテストが落ちることを確かめた。
- `npm run lint`・`npm run typecheck`・`npx vitest run tests/docs`：通過。

## 残したこと

- 完了したタスクの監査の実行（監査の予算は別）は、時間切れの費用を同じ形で記録していない。
- Claude Code の下限は、サブエージェントの内側の使用量と発言の途中の出力のトークン数を含まない。
- Codex の時間切れは使用量が出ないので、常に不明（推定はしない）。
