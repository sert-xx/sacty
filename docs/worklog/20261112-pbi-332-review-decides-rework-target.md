# PR の指摘の戻し先を、ゴールガーディアンではなくレビューの子タスクが示す

- 日付: 2026-11-12（UTC）
- タスク: PBI-332
- PR: （作成後に記入）
- ブランチ: feat/issue-332-review-decides-rework-target
- 関係する ADR: [PR の指摘の戻し先を、ゴールガーディアンではなく、AI のレビューの指摘はレビューの子タスクが、人の指摘は PR の工程のエージェントが決める](../adr/20261112-0748-review-child-task-decides-rework-target.md)

## 目的

ゴールガーディアンをやめても、PR の指摘が正しい工程で直されるようにする（決定を変えない指摘で、承認済みの要求要件・設計を作り直させない）。

## したこと

- 台帳：判定のブロックの `rework`（指摘ごとの戻し先・理由と原因）を `ReviewRework` として `AgentRunCompleted.reviewRework` に足し、子タスクの判定の記録（`reviewVerdicts`）に持たせた。`ReworkJudged` に `reviewTaskId` を足した。
- コア：指摘ごとの戻し先から差し戻す工程を決める `reviewReworkTarget` を足した（決定を変える指摘があればその工程、複数の工程にまたがれば前の工程、読めない・候補に無ければその PR の工程）。
- デーモン：
  - レビューの子タスクの指示に、戻し先の候補・基準・承認済みの前の工程の成果物・原因の選択肢を渡し、判定のブロックに `rework` を書かせる（`reviewReworkLines`）。
  - AI のレビューの指摘だけなら、子タスクの最後の回の `rework` から戻し先と原因を決める（実行しない。費用 0。actor `sacty`）。人の指摘を含む・子タスクが無いときは、PR の工程のエージェントに新しいセッションで判断させる（actor `agent`）。
  - 戻し先の判断の指示・判断文の渡し方から、ゴールガーディアンの語を外した。
- 画面：子タスクの答えから決めた戻し先は、費用ではなく「PR のレビューの子タスクの答えから」と出す。費用の内訳に「戻し先の判断」の行を足した（古い作業履歴のゴールガーディアンの判断は、今までどおりゴールガーディアンの行）。
- docs：仕様書（承認・タスクと工程・作業履歴）とユーザードキュメント（タスク・取り込み）を日英で直し、ADR を足して、確認なしの差し戻しを決めた ADR を置き換え済みにした。
