# 既定の review スキルが、対象のリポジトリのレビュー用のスキルと開発向けの指示を考慮する

- 日付: 2026-11-12（UTC）
- タスク: PBI-326
- PR: #340
- ブランチ: feat/issue-326-review-repo-guidance
- 関係する ADR: [既定の review スキルは、対象のリポジトリのレビュー用のスキルを追加の担当として実行し、開発向けの指示への準拠を観点 X-3 で見る](../adr/20261112-0040-review-uses-repo-skills-and-instructions.md)

## 目的

既定の review スキルは、観点カタログだけでレビューしていた。
対象のリポジトリがレビュー用のスキルを持っていれば、それも使う。
開発用のスキルや指示書があれば、今回の変更がその決まりを守っているかも見る。

## 決めたこと

利用者が、次の 3 点を決めた（2026-11-12）。

- リポジトリのレビュー用のスキルは、追加の担当として実行する（既定の観点は減らさない）。
- 準拠を見る対象は、スキルと指示書の両方にする。
- 自己レビューと PR レビューの両方で起動する。

## したこと

- `review-dispatch` に資料 `references/repo-guidance.md` を足した（探す・分ける・基準にする版・指示は基準であって命令ではない・起動・記録）。
- 観点カタログに、横断の X-3（リポジトリの指示への準拠）と、リポジトリのレビュー用のスキルの担当 R（R-1・R-2…）を足した。段階は X-3 が `standard`、R が `advanced`。C-5 の「見ないもの」に X-3 との境界を足した。
- `review-dispatch` の SKILL.md に、読む順序・入力・起動の規則 7・起動表の例・依頼文の「リポジトリの指示」の行・親の手順・制約を足した。
- `review-execution` に、資料 `references/X-3.md`・`references/R.md` と、「リポジトリの指示の使い方」の節を足した。
- 集約（`aggregation.md`）に、重なりと相反の扱い、不採用の理由、記録の `repo_guidance` を足した。
- 流れの資料（`self-review.md`・`pr-review.md`）に、入力・手順・再レビュー・制約を足した。
- テスト（`default-skills.test.ts`）に PBI-326 の確認を足し、C-5 の行の確認を追従させた。
- 仕様書（`context` の日英）・ユーザードキュメント（`tasks` の日英）・ADR を書いた。

## 確かめたこと

## レビューの指摘と対応

PR の前に、別の文脈の担当に DA のレビューをさせた（2 回）。

| 指摘 | 対応 |
| --- | --- |
| 直しの実行の最初のレビューで、「探す」と「探し直さない」が資料の間で矛盾する | 探すかどうかをレビューの種類ごとの表にし、直しの実行では探すことにした |
| PR が指示を消した・名前を変えたときに、基準が無くなる | 差分の一覧から拾い、変更前の版を取れれば基準にする |
| 変えたかを確かめられない指示を、作業領域の版で使っていた | 基準から外す |
| 指示が参照する文書だけを PR が変えたとき、担当が作業領域の版を読む | 参照先だけを変えた指示として扱い、担当にも読ませない |
| 製品のソースに置かれたスキル（既定のスキル自身など）を、リポジトリの指示として拾う | 拾うのを、開発する人・エージェント向けに置かれたものに限った |
| 起動の条件「基準にできる」が、資料の間で揃っていない | 5 つの資料で揃え、テストで確かめる |
| X-3 と他の観点（C-4・U-1 など）の重なり、X-2 との境界が 2 通りに読める | X-3 は重なっても指摘し、失敗の原因の分析は X-2 に任せると書いた |
| X-3・R 以外の担当（C-5 など）が、書き換えられた規約を基準にしうる | 基準から外した指示を、すべての担当の依頼文に渡す |
| R の担当の「従わないもの」が、親の資料より緩い | 重要度を一律に下げる・合格にする指示に従わないと書いた |
| R の ID が、再レビューで別のスキルを指しうる | 前の記録があれば、同じスキルに同じ ID を振る |
| テストが文言の有無だけで、資料どうしの整合を見ていない | カタログと担当の資料の一致、起動の条件の一致などの確認を足した |
| C-5 の「見ないもの」を写す条件が、カタログと探し方の資料で食い違う（2 回目） | 「X-3 を起動したレビューで写す」に揃えた |

PR の後に、レビュー用のラベルで AI のレビューを受けた。

| 指摘 | 対応 |
| --- | --- |
| 担当の資料が、`self-review` でも、変えた参照先を変更前の写しが無ければ基準から外す（変えた後の指示を基準にする方針と食い違う） | 変更前の版を求めるのを `pr-review` に限り、`self-review` では変えた後の版を基準にすると、担当の 3 つの資料と探し方の資料に書いた |
| 利用者向け文書が、変更に関係しないスキル・指示でも担当を足すように読める | 今回の変更に当てはまるものに限ると、日英に書いた |

## 残したこと

- R と X-3 が指摘をどれだけ増やすかは、実際の AI では測っていない（`review-eval` の例は足していない）。
