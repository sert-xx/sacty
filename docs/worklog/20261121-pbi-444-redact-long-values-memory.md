# 秘密情報を伏せる処理が、とても長い値を受け取っても、デーモンのメモリを使い切らないようにする

- 日付: 2026-11-21（UTC）
- タスク: PBI-444
- PR: なし
- ブランチ: なし
- 関係する ADR: [20261121-1700-redact-tree-compact-nodes-for-long-values.md](../adr/20261121-1700-redact-tree-compact-nodes-for-long-values.md)

## 目的

JSON でない大きな認証ファイルなど、とても長い値を伏せる値に入れても、伏せる処理のメモリと時間が、値と入力の長さに比例するようにする。

## したこと

- `redact.ts`：木の節を、節ごとの `Map` から型付き配列に変えた（1 文字あたり約 300 バイト → 約 14 バイト）。子が 2 つ以上ある節の 2 つ目以降だけ `Map` に入れる。節の数（`nodes`）を木に持たせた。
- `docker.ts`：`readStagedFile` は、バッファを常に上限 + 1 バイト確保する（読んでいる間に増えたファイルを、途中で切って成功にしない）。認証ファイルの大きさに、1MiB の上限を置いた（取り出す前のファイルの大きさで判定。ホストの認証ファイルは `invocation.ts` で、コンテナから写した分は `docker.ts` で）。超えたら、起動せずに（起動の前）、または出力を返さずに（コンテナの中で大きくされたとき）、認証の失敗にする。書き戻さない。セッションログも、その実行の出力を残さない（`session-logs.ts` の `withholdOutput`）。
- `session-logs.ts`：出力を残さないと決めたら、溜めていた書きかけの行と末尾を捨てる（閉じるときに書かない）。`StreamRedactor` が、値の集合が変わらない間、`push` のたびに値の形・並べ替え・比較を作り直さないようにした。
- 新しいテスト `redact-long.test.ts`、`agents.test.ts` の追加：節あたりの大きさ・節の数の比例、2MB・上限の大きさの値、重なり・境目をまたぐ出力、`push` が値の形を作り直さないこと、上限を超えた認証ファイルが失敗になり、ログに出力が残らないこと。
- 仕様（日英）に、木の大きさ・上限・`push` の時間を足した。
- 前の ADR の「影響」に、例外の一句を足した。PBI-438 の作業履歴の「戻すと落ちる」を、確かめた結果に直した。

## レビューの指摘と対応

- 少しずつ届く出力で、1 回の `push` が値の長さに比例する：値の形・木を作り直さないようにした。前回の木の状態の持ち越しはしていない（`push` は持ち越す分に比例）。
- 上限が無く、実際の経路でメモリが使い切られる：認証ファイルに上限を置き（最初は 256KiB。人の指摘で 1MiB・ホスト側・ログの出力を残さない側へ広げた）、超えたら失敗にした。ADR・仕様の数字に前提（値の形・木の数）を書いた。
- テストの揺れ・メモリのテストの測り方・小さな指摘：時間の assert と 32MB のテストは外し、比例は節の数の比で見る。使った節の数で測るようにし、UTF-8 の文字の途中で切る場合を足した。

- 人の指摘（上限の置き方）：判定を取り出す前の大きさにし、上限を 1MiB に。ホストの認証ファイルにも同じ上限。上限を超えたらセッションログの出力も残さない。文書の数字を、実行 1 つあたりの経路（値の形・木の本数・作る間）で書き直した。

- 人の指摘（2 回目）：上限超えのとき写したファイルも残さず（理由を作業履歴に残す）、停止の確認の失敗・デーモンの停止を優先し、失敗の文言にホストのパスを渡した。32MB のテストと時間の assert を外し、`readStagedFile` の上限ちょうど・+1 バイトのテストを足した。

- 人の指摘・AI のレビュー（5 回目）：コンテナに写すときの hash の計算も上限つきで読み、1MiB を大きく超えるホストの認証ファイルを全体メモリに読まないようにした（超えたら起動前の失敗）。`withholdOutput` を必須にし、出力を残さなかったログに省いた大きさを付けない。書き戻しを止める分岐を、`syncBack: true` のテストで確かめる。ADR の「確かめたこと」の節は外した（ここに残す）。作業履歴の画面の文言（`labels.ts`）は、デーモンの外なので、この PR では直さない。

- AI のレビュー（6 回目）：起動前の経路を、仕様・ADR で実装どおりに書き分けた（判定は `hashOfStaged`）。`readStagedFile` のバッファ・出力を残さない実行の閉じ方を直した。`invocation.ts` の上限（ちょうど・+1）と、時間切れと重なる経路のテストを足した。新しい列挙値で前の版が作業履歴を読めなくなりうることを、ADR の影響とコメントに書いた。

## 残したこと

- `hashOfStaged` が上限つきで読むことを直接確かめるテストは無い（メモリの量を測れず、直後の `collectSecrets` も同じ失敗を返すため）。

- `snapshot`・`close`・`docker.ts` の結果の `redact` が呼ぶたびに木を作る件（PBI-438 の後続）。
- `StreamRedactor` の走査の、前回の木の状態の持ち越し（今は持ち越す分の走査）。
