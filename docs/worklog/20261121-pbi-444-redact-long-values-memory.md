# 秘密情報を伏せる処理が、とても長い値を受け取っても、デーモンのメモリを使い切らないようにする

- 日付: 2026-11-21（UTC）
- タスク: PBI-444
- PR: なし
- ブランチ: なし
- 関係する ADR: [20261121-1300-redact-tree-compact-nodes-for-long-values.md](../adr/20261121-1300-redact-tree-compact-nodes-for-long-values.md)

## 目的

JSON でない大きな認証ファイルなど、とても長い値を伏せる値に入れても、伏せる処理のメモリと時間が、値と入力の長さに比例するようにする。

## したこと

- `redact.ts`：木の節を、節ごとの `Map` から型付き配列に変えた（1 文字あたり約 300 バイト → 約 14 バイト）。子が 2 つ以上ある節の 2 つ目以降だけ `Map` に入れる。
- 値の長さに上限は置かない（伏せる対象から外す値は無い）。
- 新しいテスト `redact-long.test.ts`：木の大きさ（比例・1 文字 30 バイト以下）、2MB・32MB の値、長い値の重なり・境目をまたぐ出力。
- 仕様（日英）に、長い値でも比例することを足した。
- 前の ADR の「影響」に、例外の一句を足した。PBI-438 の作業履歴の「戻すと落ちる」を、確かめた結果に直した。

## 確かめたこと

- `npm run lint`・`npm run typecheck`：通った。`npx vitest run --no-file-parallelism`：303 ファイル・6096 件が通り、14 件はスキップ。
