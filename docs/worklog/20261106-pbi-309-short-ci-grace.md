# CI が無いと確かめられたリポジトリでは、実装の PR の CI を短い猶予で終える

- 日付: 2026-11-06（UTC）
- タスク: PBI-309
- PR: なし
- ブランチ: feat/issue-309-short-ci-grace
- 関係する ADR: [実装の PR の CI の待ちは、リポジトリに CI が無いと確かめられたら短い猶予で終える](../adr/20261106-1041-short-grace-when-repository-has-no-ci.md)

## 目的

最終レビューの前の PR の CI の待ちは、チェックが1つも現れないと5分かかり、やり直しのたびに繰り返す。
手元の実行記録では、CI が無いリポジトリでこの待ちが積み重なっていた。CI が無いと確かめられたときだけ、待ちを短くする。

## したこと

- `packages/core/src/events.ts`：短い猶予の定数 `PULL_REQUEST_NO_CI_GRACE_MS`（1分）を足した。
- `apps/daemon/src/ci.ts`：`CiStatusReader` に `repositoryHasNoCi` を足した。`GitHubCiStatus` は、ワークフローの一覧（全ページ）、ベースブランチの先頭（`git/ref/heads/<ブランチ>`）、そのコミットのチェックと状態を読む。
  成功の応答でも一覧を読めないなら空とせず例外にし、一覧を読み切れない（ページの上限・API の外へのリンク）なら CI が無いとは答えない。
- `apps/daemon/src/service.ts`：`readCi` に任意の `noCi` を足し、`checkVerificationCi` だけが渡す。チェックが無いまま短い猶予を過ぎた確認で確かめ、結果を `noCiChecks` にタスクとコミットごとに覚える。読めなければ覚えない。
- 仕様書（日英）・ユーザードキュメント（日英）・ADR を足した。

## 確かめたこと

- `npm run lint`・`npm run typecheck`：成功。
- `npx vitest run tests/docs`：成功。
- `npm test`：3回実行し、206 ファイル、4198 件のうち、変更に関係するテストはすべて成功した。どの回も1ファイルが失敗した。2回は、所要時間の上限を測るテストが同時実行の負荷で上限を超えたもの（最終レビューの出力の読み取り、長い URL の並びの項目化）で、それらのファイルだけの実行では成功した。今回の変更はそれらの処理に触れていない。残りの1回は、テストの失敗が0件でファイルだけが失敗と数えられ、原因は控えていない（次の実行では再現しなかった）。
- 実装を1か所ずつ壊して、テストが失敗することを確かめた（11 通り）：覚えた結果を使わない、覚えた結果がコミットを見ない、失敗も覚える、短い猶予を待たない、マージの後の監視にも渡す、確かめを渡さない、`active` を見ない、状態を見ない、チェックを見ない、配列でない応答を空とする、読み切れない一覧を続ける。
- `gh api` で、公開リポジトリの `actions/workflows`・`git/ref/heads/<ブランチ>`・`check-runs?per_page=1`・`status?per_page=1` の応答の形が、実装の読み方と同じことを確かめた。
- 確かめられなかったこと：ワークフローが1つも無いリポジトリに対して、実際のデーモンで1分で進むところは動かしていない（テストの偽物と応答の形の確認まで）。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| セルフレビュー：成功の応答で本文を読めないと、一覧が空と読まれ、CI が無いと誤る | 一覧の読み方を別にし、例外にした（読めないときと同じく5分待つ） |
| セルフレビュー：一覧の上限で切れると、有効なワークフローを見逃す | 読み切れないなら CI が無いとは答えないようにした |
| セルフレビュー：`dynamic/` のワークフローも `active` として出るので、CI が無くても短くならないリポジトリがある | 定義どおり数える。ADR の影響に書いた |

## 残したこと

- `dynamic/` のワークフローを数えないかどうかは決めていない。
