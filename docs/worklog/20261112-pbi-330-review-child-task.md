# sacty が作る PR のレビューを、ラベルの別タスクではなく、その工程の子タスクとして回す

- 日付: 2026-11-12（UTC）
- タスク: PBI-330
- PR: #347
- ブランチ: feat/issue-330-review-child-task
- 関係する ADR: [sacty が作る PR のレビューを、ラベルで取り込む別のタスクではなく、PR を作ったタスクの子タスクにし、指摘なしになるまで繰り返す](../adr/20261112-0609-review-sacty-pull-requests-in-child-tasks.md)

## 目的

sacty が作る要求要件・設計・実装の PR を、レビュー用のラベルと取り込みに頼らず、PR を作ったタスクの子タスクでレビューし、指摘と修正を指摘なしになるまで繰り返す。
指摘なしの後は人がマージで承認する。sacty の PR にラベルは付けない。

## したこと

- イベント：`TaskCreated` に `reviewOf`（親と PR を作った工程）、親に記録する `ReviewTaskCreated` を足した。`ReviewRestarted` に `reason: updated` と `commit`、`TaskCancelled` に `reason: parent_cancelled` を足した。
- デーモン：ラベルを付けていた3か所（要求要件・設計の PR の作成、実装の PR のドラフトの解除、公開の後に止まったときの再開）を、子タスクの作成（`ensureReviewTask`）に置き換えた。
  PR の確認で `reconcileReviewTasks` が、作る前に止まった子タスクを作り、親が PR を更新して承認待ちに戻ったら子タスクを再レビューに戻す（同じコミットでは1回）。親が中止されたら、終わっていない子タスクも中止する。
  sacty が作った PR は、ラベル・レビューの依頼のどれでも取り込まないようにした。
  子タスクの作成は、デーモンの依存 `reviewTasks` で有効にする（監査と同じく、main.ts で有効、テストの既定は無効。工程の流れだけを確かめる既存のテストで、子タスクが偽のエージェントの答えを使わないように）。
- 画面：タスクの詳細の「関連するタスク」に、親から子（「PR のレビュー」）と子から親（「レビューする PR の元」）のリンクを出し、作業履歴の文言と、設定のレビュー用のラベルの説明を直した。
- docs：仕様書（承認・取り込み・タスクと工程）・ユーザードキュメント（取り込み・タスク・トラブルシューティング）を日英で直し、ADR を足して、ラベルを付ける決定を持つ ADR の置き換え先に書き足した。

- テストで確かめた境界：子タスクを作る（ラベルの設定・トリアージに関わらず）・PR を更新しても作り直さない・再起動の後の復元・作る前に止まったときの作り直し・子タスクだけ作って親に記録する前に止まったとき・以前の版のレビューのタスクがあるときに二重に作らない・指摘ありの回で親が直して再レビュー・指摘なしで繰り返さない・ほかで push されて先頭がずれても同じコミットで繰り返さない・判定ごとの取り込み（指摘なし・提案あり・要修正・評価なし）・3つの工程の PR・マージで子タスクの中止・親の中止。

## レビューの指摘と対応

### 1回目（sacty のレビュー。判定：修正が必要）

- [要修正] 以前の版でレビューの依頼から取り込んだ sacty の PR に再依頼があると、`restartRerequestedReviews` が子タスクとは別のレビューのタスクを作る。
  - 対応：sacty が作った PR の判定を `sactyMadePullRequests` にまとめ（レビューの子タスクの記録も含める）、取り込みと再依頼の両方で使うようにした。
    再依頼の経路では、PR の今の依頼先を読む前に除く。
  - テスト：依頼から取り込んでレビューを投稿した PR 9 を、sacty のタスクが要求要件の PR として作った状態で再依頼しても、タスクを作らず、GitHub も読まないこと。修正を戻すと落ち、戻すと通ることを確かめた。
- [提案] `docs/spec/tasks-and-steps(.en).md` に、レビューへ進めるときにラベルを付けるという旧記述が残っている。
  - 対応：日英とも、レビューへ進めるときにレビューの子タスクを作る（ラベルは付けない）に直した。取り込みの仕様書の再依頼の対象外の項目も、日英で今の動作に合わせた。
