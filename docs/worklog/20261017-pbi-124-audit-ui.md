# 監査の画面を、裏側のモックで一通り動かす

- 日付: 2026-10-17（UTC）
- タスク: PBI-124
- PR: #134
- ブランチ: feat/issue-124-audit-ui
- 関係する ADR: [監査の画面を、裏側のモックで先に作り、モックは環境変数で切り替える](../adr/20261017-1145-audit-ui-with-mock.md)

## 目的

完了したタスクの監査（sacty の一番重要な機能）の画面と API を、裏側をモックにして先に作り、監査の結果の見え方と、改修の提案を
採用・却下する操作を画面で確かめられるようにする。ロジックは PBI-125 で作る。

## したこと

- core：監査のデータの形（`TaskAudit`・`ProjectAudits`・`AuditDashboard`）と入力の検査（採用・却下・再開）、文言のコード。
- デーモン：`AuditService`、監査の無い実装（既定）とモック（`SACTY_AUDIT_MOCK=1`）、API、config.yaml の `budget.default_per_audit_usd`。
- 画面：タスクの詳細の監査の欄、監査の画面（サイドメニューの「監査」）、ダッシュボードの監査の欄、レポート（Markdown）の出力、
  予算で止まった監査の再開。日本語・英語。
- docs：仕様書（監査）、ユーザードキュメント（監査）、設定の項目、ADR。

## 確かめたこと

- `npx biome check`・`npm run typecheck`・`npx vitest run`・`npm run build` が通った。
- 一時的な SACTY_HOME に完了したタスクを 10 件入れ、モックで起動して画面で確かめた：監査の 6 つの状態、原因の 5 つの状態、
  採用（宛先を上位の層に変えた）、却下（空白だけの理由は断られる）、予算で止まった監査の再開（使った額と同じ上限は断られる）、
  根拠から作業履歴の行・実行のログへの移動、ダッシュボードの欄、レポートの出力（期間の誤りは 400）、英語・ライト・スマホの幅。
