# PR の再レビューを、前回の指摘の確認と前回以降の差分に絞る

- 日付: 2026-11-21（UTC）
- タスク: PBI-432
- PR: #477
- ブランチ: sacty/task-pbi-432
- 関係する ADR: [再レビューは、前回の指摘の確認と前回以降の差分に絞る](../adr/20261121-0400-rereview-narrowed-to-previous-findings-and-changes.md)

## 目的

再レビューは、直しが数行でも、PR 全体を初回と同じ必須観点で見直しており、時間と費用の大きな部分を占めていた。
再レビュー（そのレビューのタスクに前回の自分の投稿の記録がある回）の範囲と観点を、前回の指摘の確認と前回以降の差分に絞る。
初回は絞らない。絞るかどうかは、デーモンが決めて指示で明示し、スキルは明示がある回だけ絞る。

## したこと

- デーモン（`apps/daemon/src/service.ts`）：`rereviewNarrowOf` で、絞れるかを決める。前回の先頭の取得・祖先・起点と向き先・前回の回の判定・担当の起動・差分の大きさ（行数が PR 全体の半分を超える、前回の時点の PR に無かったファイルが多い）・差分を渡せるか・前の工程へ戻った提出を確かめ、当たれば絞らず、理由をログに 1 行残す。前回以降の差分は `since.diff` に全体を置く。
- 指示（`apps/daemon/src/prompts.ts`）：節「--- 再レビューの範囲の絞り ---」（`rereviewNarrowLines`）を足し、範囲・起動する観点・親が絞らない条件・変えないもの・本文の 1 行を書く。絞る回の `rereviewLines` の範囲の行を、絞る節と矛盾しない文にした（絞らない回の文は変えない）。規則 10 の節（`rereviewDocsOnlyLines`）は、検証の絞りだけを言う形にした。
- 既定のスキル（`review-dispatch`）：規則 11 と `pr-review` の「絞った再レビュー」を足し、規則 1・5・9・10 と「初回か再レビューか」を、新しい規則に合わせた。規則 10 は検証だけを絞る。集約の不採用「範囲の外」に、絞った回の差分の外の `should`・`nit` を足した。
- 仕様書（`tasks-and-steps.md`・`approval.md`・`context.md` と英語版）、ユーザードキュメント（`user/intake.md` と英語版）、ADR を 1 件足し、PBI-421 の ADR の置き換え先に加えた。

## 決めたこと

- 前回の回の判定を持たない GitHub の再依頼のタスクは、判定を写さず、絞らない（PBI-421 と同じ。新しい状態を足さない）。
- 差分の大きさの値は、行数が PR 全体の半分を超える、または前回の時点の PR に無かったファイルが 3 つ以上かつ半分を超える。
- 前回の回の「見られなかった観点・止まった検証・打ち切り」は、デーモンの記録（前回の回の `reviewDispatch` の担当の数が 0 件と数えた）で分かる範囲だけ確かめ、残りは親の確かめ（本文を読む）に任せる。
- 前の工程へ戻った提出は、前回の回の指摘の戻し先（`reviewReworkTarget`）が、その PR の工程より前のときとした。
- 同じ先頭の判定し直しは、いまの回を始めた `ReviewRestarted` の `reason`（`Task.reviewRestartReason`。declined・replied）と、先頭の記録の両方で決める。判定し直した後に人が同じ先頭で手動の再レビューを始めた回は、絞らない。

## 確かめたこと

- 自動のテスト：`apps/daemon/src/rereview-narrow.test.ts`（絞る・絞らない条件の表、差分の大きさの境界、同じ先頭の判定のし直し、前の工程へ戻った提出、規則 10 との重なり、実装の前の文書の PR、初回）、`default-skills.test.ts`（スキルの文面）。`rereview-docs-only.test.ts` は、観点の絞りを新しい節に任せた形に直した。
- 実物の再レビューでの確かめ（担当の数・時間・費用が初回よりどれだけ減ったか）は、していない。マージの前に、PR の版を別に動かして依頼した側が確かめる。
- 判定し直した後の手動の再レビューを絞らないテスト、切り詰めた差分の長さ・末尾、`since.diff` の中身、新規ファイルの半分の境界を足した。スキルの旧い文が残らないことも確かめる。
- テストの結果は、全件の実行（`npx vitest run --no-file-parallelism`）・lint・型の検査を、最後の変更の後に実行して得たものを、PR の本文に書く。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| スキルの「再レビュー」に旧い規則 10 の意味が残り、検証の扱いが食い違う | 「前回以降が文書だけの再レビュー（規則 10）は、文書に効く検証だけ」に直し、親の手順 3 に規則 11 の確認を足し、コメントをそろえた |
| 判定し直した後の手動の再レビューが絞られる | `reviewRestartReason` で、判定し直す回だけ絞る |
| 前回以降の差分の場所を、切り詰めない回に書かない | 場所があれば、切り詰めないときも書く |
| C-1 を起動しない | 起動する観点は足さず、ADR の「受け入れた見落としの種類」に書いた（人が決める） |
| 英語版の仕様書の 3 か所、テストの確認の弱さ、実装の整理、作業履歴の節 | 直した |

### 2 回目のレビューへの対応

| 指摘 | 対応 |
| --- | --- |
| 担当の数が数えられなかった（`null`）回を絞る | 絞ると決め（0 件と数えた回だけ絞らない）、利用者向け文書・仕様書・ADR・コメントを「0 件と数えた」にそろえた。表に `null` が絞る行を足した |
| 絞る回にも「範囲は PR の差分で決める」の行が残る | 絞る回は「絞りの節で決める」に差し替えた |
| 節を指す向きが逆 | 「上の」に直した |
| 表が理由の文を確かめない・長い差分の `since.diff` | 理由の文をログで確かめ、長い差分の `since.diff` を足した |
| 定数の名前・不要な export | `HALF_NUM`・`HALF_DEN` に改め、export を外した |
| 利用者向け文書・英語版仕様書・仕様書の `since.diff` | 直した |
| 判定し直す回の定義が 2 つ・`rereviewDocsOnlyOf` との重なり | 後続に回したい案（範囲外のリファクタリング） |

### 3 回目のレビューへの対応

| 指摘 | 対応 |
| --- | --- |
| 名前を変えたファイルを 2 件に数える | 前回以降のファイルの数は、変更先の名前だけで数える。仕様書・ADR に書き、名前の変更のテストを足した |
| `since.diff` の書き出しの失敗で実行が失敗する | 書き出しだけを別の `try/catch` で包み、失敗したらログを残して絞らずに PR 全体を見る。テストを足した |
| 絞る回の文が、差分に入っていない文書の範囲を落とす | 絞る回の指示・スキルの規則 11・pr-review に、`linked-docs.md` の再レビューの規則で決める 1 文を足した |
| 実装の前の文書の PR の節が観点を言い切る | 絞る回は、絞りの節に譲る文に差し替えた。テストで、絞る回・絞らない回の両方を確かめる |
| 同じ先頭の判定し直しで `since.diff` を置かないことの確認 | 判定し直しの回を実行して、置かないこと・指示に載せないことを確かめるテストを足した |
| 真偽値の位置引数が 2 つ並ぶ | `rereviewLines` の末尾を `{ docsOnly, narrowed }` のオブジェクトにした |

### 5 回目のレビューへの対応

| 指摘 | 対応 |
| --- | --- |
| 絞らない回に戻すとき、規則 9 の絞りを残すかが 2 通りに読める | 「親が絞らない条件」の 1 か所に、当てはめない対象（範囲・観点の絞りと、範囲を絞る文）と、残るもの（D-3・D-4・D-6 を起動しない決まりと「指摘にしないもの」）を書き、各行の例外文を消した。実装の前の文書の PR の節は、絞らないときの観点の一覧を直接書く |
| `pr-review.md` の「範囲」に規則 11 の例外が無い | 絞った再レビューの範囲を除く 1 句を足した |
| 「ほかの人のレビューがあっても」のテストが、ほかの人の投稿を用意していない | `FakePulls` にほかの人のレビュー・コメントを持たせ、他のレビュアーの指摘として渡り、絞らないことを確かめる |
| 例外文が 4 か所に直書き | 1 か所にまとめた |

## 残したこと

- 実物の再レビューでの確かめ（担当の数・時間・費用の減り方）は、していない。マージの前に、依頼した側が、PR の版を別に動かして確かめる。
- 前回以降の差分がコードのときに C-1 を起動するかは、人が決める。
