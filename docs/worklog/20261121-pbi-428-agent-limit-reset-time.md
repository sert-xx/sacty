# 利用上限の明ける時刻まで、代わりのエージェントに切り替えたままにする

- 日付: 2026-11-21（UTC）
- タスク: PBI-428
- PR: なし
- ブランチ: なし
- 関係する ADR: [利用上限で失敗したエージェントは、失敗の文から明ける時刻を確かに読み取れたとき、その時刻まで使わない](../adr/20261121-0200-agent-limit-reset-from-failure-message.md)

## 目的

週の上限に達したエージェントを 60 分ごとに試し直して失敗するのをなくす。

## したこと

- 失敗の文から明ける時刻を読む `parseLimitReset` を足した。読むのは、時間帯の名前つきの Claude Code の形と古いエポックの形。
- `markLimited` が、読めた時刻を期限にした（読めなければ `cooldown_minutes`）。`AgentFellBack` の `until` は、この期限から出る。
- 仕様書・利用者向け文書（日英）と設定の雛形のコメントを直し、ADR を足した。

## 確かめたこと

- `npx biome check --error-on-warnings .`：通った（719 ファイル）。
- `npm run typecheck`：エラー 0。
- `npx vitest run --no-file-parallelism`：282 ファイル・5742 件が成功、14 件はスキップ。
- 読み取り（各形・境界・不正・遠すぎる・すぐ前・2000 字・夏時間）、出どころ（`cliText`）、切り替え（長い例・短い例・読めないとき・一時的な混雑・発言の文・期限の上書きの順序）を、テストで確かめた。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| Opus・Sonnet の文は `classifyFailure` が利用上限にしない | 変えない決まりなので、読む形から外し、テストも直した |
| エージェントの発言から読み、最長 8 日使わなくなる | `AgentOutcome.cliText` を足し、CLI 自身の出力だけを読む |
| 読めない失敗が、長い期限を短くする | `markLimited` が遅いほうの期限を残す |
| 文書とコードの食い違い・「コード:」の行 | 直した |
| テストの不安定・境界 | 実時間の測定をやめ、2000 字・30 分・8 日・夏時間の境界のテストを足した |

## 残したこと

- 時間帯の名前の無い形（Claude Code の `resets 3:45pm`、Codex の `try again at …`）は読めない。時間帯を知る手段が要る。
