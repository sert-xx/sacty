# 版を 1.30.0 に上げる

- 日付: 2026-11-22（UTC）
- タスク: なし
- PR: #566
- ブランチ: feat/release-1-30-0
- 関係する ADR: [版は 1.0.0 から semver で付け、タグと GitHub Releases でリリースする](../adr/20261019-2345-semver-releases.md)

## 目的

1.29.0 の後に入った変更（PR #455〜#565 の 69 件）をリリースする。レビューの往復の見直し、PR の説明・投稿の書き方、実装を含まない進め方のブランチ、狭い幅の画面、`sacty mcp` のツールの追加など、機能の追加なので MINOR を上げる。

## 1.29.0 からの主な変更

- 人の差し戻しの回数の上限（3 回でエスカレーション）を無くした（PR #455）。
- PR のレビュー：再レビューを前回の指摘の確認と前回以降の差分に絞る（PR #477）、PR の目的の範囲外・対応済みの指摘を投稿しない（PR #470・#498）、提案に対応するかを直しの前に判断する（PR #483・#490）、観点の担当が失敗したら親が代わりに見る（PR #519）、行へのコメントの指摘を本文に重ねない（PR #562）、既定の観点の段階を1段下げる（PR #515・#516）など。
- リスク評価は、レビューが指摘なしの回だけに出す（PR #474・#500・#518）。
- Sacty が作る PR の説明と投稿するレビューを、人が判断する情報だけにし、製品名を「Sacty」に揃えた（PR #506・#523・#535）。
- 実装を含まない進め方では、タスクブランチを作らず、工程の PR をベースブランチへ直接出す（PR #546・#564）。
- 実装の工程から、承認済みの要求要件・設計の文書の誤りを直せる（PR #499・#565）。
- 一時的な git push の失敗をやり直す（PR #534）。利用上限の明ける時刻まで代わりのエージェントを使う（PR #473・#545）。
- 画面：狭い幅の表示（PR #501・#557）、タスクの一覧の最初の表示と 50 件ずつの表示（PR #491）、「あなたの出番」の組分け（PR #492）、設定の呼び分け（PR #505）、監査の提案の束ね（PR #493）、無いページの案内（PR #479・#559）など。
- `sacty mcp`：`create_task` のリポジトリの指定（PR #551）、確認したいことを問いとして読む（PR #552）、再実行の案内（PR #542）。
- 秘密情報を伏せる処理の直し（PR #484・#494）。
- そのほか、テストの安定化と CI の準備（PR #475・#503・#511・#553・#558）。

## 互換性の判断

- 設定ファイル：`config.ts`・`projects.ts` の差分は、雛形のコメントと整形だけで、形は変わっていない。
- 台帳：新しい種類のイベント（`DesignEdited`・`SuggestionsTriaged`・`StepBranchKept`・`PushRetried`・`ReviewRunStopped` など）と、既存のイベントの省略できる項目・列挙の値を足した。ほかの差分は整形（1 行を折り返した）だけで、形を変えたものは無いので MAJOR にはしない。これらを記録した後に 1.29.0 に戻すと作業履歴を読めないので、リリースの説明の注意に書く。
- API：差し戻しの入力から `continueOverLimit` を外したが、入力は知らない項目を読み飛ばすので、送っても断られない（`daemon-no-change-limit.test.ts` で確かめている）。
- 差し戻しの回数の上限が無くなること、PR の説明・投稿の形が変わること、実装を含まない進め方のブランチの作り方、既定のスキル `review` が変わることを、リリースの説明の注意に書く。
- `packages/cli/docker` の変更は無い。

## したこと

- 5 つのパッケージとワークスペースの依存の版を `1.30.0` にし、`package-lock.json` の版の行を直した。
- 既定のイメージの名前（`DEFAULT_IMAGE`）を `sacty-agent:1.30.0` にした。
  同じ版にしたもの：仕様書（`agent-execution`・`configuration`）とユーザードキュメント（`config`・`images`）の日英、イメージの名前を書いているテスト・コメント、ゲートウェイの MCP クライアントの版の文字列。
  直したファイルは、1.29.0 の版上げ（PR #456）と同じ範囲。置き換えは前後に数字・`.` が無い `1.29.0` だけにし、ADR・作業履歴は対象から外した。
- 元のイメージのダイジェスト：`docker buildx imagetools inspect node:26-bookworm-slim` の `Digest` は、`Dockerfile` に固定したもの（`sha256:5df79989…`）と同じだったので変えていない。
