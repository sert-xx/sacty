# プロジェクトのエクスポートに Slack のメンションの相手を含めない

- 日付: 2026-10-15（UTC）
- タスク: PBI-103
- PR: #114
- ブランチ: feat/issue-103-export-without-mentions
- 関係する ADR: [プロジェクトのエクスポートに Slack のメンション（相手と種類）を含めず、含んでいた版 3 のファイルは理由を示して断る](../adr/20261015-0850-superseded-export-without-mentions.md)

## 目的

メンションする相手は使う人や環境ごとに違うので、エクスポートしたファイルをほかの sacty で共有すると、元の人へのメンションが残る。
エクスポートからメンションの相手を除き、インポートした先で相手を足せるようにする。以前の版のファイルの扱いを決め、画面でわかるようにする。

## したこと

- エクスポートの形式の版を 4 に上げ、通知先から `mention` を丸ごと除いた（`packages/core/src/projects.ts` の `ExportNotification`・
  `withoutMention`）。相手の無い種類（`kinds`）は意味が無く、今の形は相手を 1〜20 件と決めているので、種類も除いた。
- インポートでは、通知先の `mention` を知らない項目として断る。版 3 のファイルは、版 4 からメンションの相手を含めないことと、
  エクスポートし直すことを示す文言（`input.exportVersionWithMentions`、ja・en）で断る。ほかの版は今までどおり。
- 画面の説明を直した：プロジェクトの設定の「エクスポート」の注記（含めないものにメンションの相手を足す）と、インポートの説明
  （インポートの後にプロジェクトの設定で相手を足す）。
- 決めたことを ADR に書き、PBI-69 の ADR の「エクスポート・インポートに含める」部分を置き換えた（ファイル名を `superseded` にし、
  その ADR への作業履歴のリンクを直した）。
- 仕様書（`export.md`・`notifications.md`）と利用者向けの文書（`project-settings.md`・`notifications.md`）を、英語の版も直した。

## 確かめたこと

- 回帰テスト：
  - `packages/core/src/projects.test.ts` の「メンションはエクスポートに含めない（PBI-103）」。相手を `U…`・`W…`・`S…`・`@here`・
    `@channel` を含む上限の20件にして、書き出した JSON のどこにも ID・`@here`・`@channel`・`mention` が無いことと、送り先・トークンの参照・
    言語は残ることを確かめる。`mention` を足したファイル（相手が空・種類だけ・空のオブジェクトも）は知らない項目として断り、版 3 のファイルは
    メンションの有無によらず、最初の誤りが版の誤り（`input.exportVersionWithMentions`）になることを確かめる。版 1・2・5・文字列の版は
    `input.unsupportedVersion`。
  - `apps/daemon/src/daemon.test.ts` の API のテスト（PBI-103）。メンションを持つプロジェクトを `GET /api/projects/:id/export` で書き出し、
    応答の本文に ID が無いこと、`POST /api/projects/import` で作ったプロジェクトにメンションが無いこと、その後に保存の API で相手を足せる
    こと、版 3 と `mention` を足した版 4 のファイルが 400 で断られ何も作らないこと、元のプロジェクトのメンションが変わらないことを確かめる。
  - 修正を戻す（通知先をそのまま書き出し、読む形を元の `ProjectNotification` に戻す）と、上のテストのうち 3 件が落ちる。版 3 の判定を
    外すと 2 件が落ちる。
- `npm run lint`（終了コード 0）・`npm run typecheck`・`npx vitest run`・`npm run build`・`npx vitest run tests/docs` が通る。
- 画面：自分のブランチを別のポートと一時的な `SACTY_HOME` で起動し、メンションを設定したプロジェクトをエクスポート → インポート →
  インポートしたプロジェクトの設定の画面でメンションの相手が空であること、を動画で確かめた（PR に添付）。版 3 のファイルのインポートで
  理由が出ることも確かめた。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| （DA のセルフレビュー）PBI-69 の既存のテストが、エクスポートでメンションを引き継ぐ前提のままだった | 新しい振る舞い（相手も種類も無くなり、元のプロジェクトは変えない）を確かめるように直した |
| （DA のセルフレビュー）動画の、インポートした後の設定の画面で、メンションの欄に相手が残っているように見えた | 保存したデータと入力欄の値を確かめ、灰色の入力例（placeholder）だった。動画に欄の値を示す説明を足して撮り直した |
| （PR #114 のレビュー）インポートの説明が相手だけを足すよう促している。種類も引き継がないので、相手だけを足すと種類が既定に戻り、通知の対象が変わる | インポートの説明とエクスポートの注記（日本語・英語）を「相手と種類の両方を必要に応じて設定し直す」に直し、利用者向けの文書・仕様書・ADR も英語の版を含めてそろえた。動画を撮り直した |
