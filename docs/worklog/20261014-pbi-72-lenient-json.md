# エージェントの JSON の答えを、囲み方が揺らいでも受け取る

- 日付: 2026-10-14（UTC）
- タスク: PBI-72
- PR: #80
- ブランチ: feat/issue-72-lenient-json
- 関係する ADR: [エージェントの答えの JSON は、囲み方を問わずに1か所の読み取りで探し、形の合う最後の候補を使う](../adr/20261014-0424-agent-json-lenient-parsing.md)

## 目的

sacty はエージェントの答えの JSON を「```json」の囲みだけで探していたので、「```」だけ・ほかの言語名で囲む、囲まずに出す、
説明の文の中に書く答えを読めず、オーケストレーターなどが「読み取れませんでした」で失敗していた。囲み方が揺らいでも
同じように読めるようにし、答えの JSON を読むほかの呼び出しも洗い出して、読み取りを1か所にまとめる。
候補が複数あれば形の合うものを選び、合わなければわかるエラーにする。既存の「```json」の答えの動作は変えない。

## したこと

- `apps/daemon/src/agent-json.ts` に読み取りを1か所にまとめた。出力の中の JSON のオブジェクトをすべて候補にする。
  括弧の対応は文字列を考えて数える（文字列の中の `{` `}` や ``` は数えない。改行を含む文字列は JSON ではないものとして扱う）。
  オブジェクトの中のオブジェクトは別の候補にしない。
- 呼び出しごとの読み取り（見出しと形の確かめ）で、後ろの候補から順に読み、形の合う最後のものを使う（今までの「最後のブロックを使う」と同じ）。
  合うものが無ければ今までと同じエラーの文言にする。エラーに出力の一部は新しく入れない。
- 読んだ JSON は表示用の本文から取り除く。囲みがあれば囲みの行ごと取り除く（前のコードの囲みの終わりの ``` と取り違えない）。
- `apps/daemon/src/prompts.ts` の11の関数（工程の選択・チケットのトリアージ・ゴールガーディアンの判定・戻し先の判断・最終レビュー・
  統合レビュー・タスク分割・書き出し・再現のテスト・工程の指摘への対応など・レビューの行へのコメント）で、正規表現と `JSON.parse` を
  使っていた10か所を、`jsonCandidates`・`lastJsonAnswer` に置き換えた。
- 対象にしなかったもの：チャット（答えの文をそのまま使う）、`agents/parse.ts`（CLI のストリームの出力を読むもの）、
  設定・DB・gh・1Password などを読む `JSON.parse`。
- レビューの指摘を受け、JSON の文法を入れ子を再帰せずに自前で確かめるようにした。途中で開いた `{` `[` の結果を覚え、同じ位置からは読み直さない。
  `JSON.parse` は正しいとわかった候補にだけ使う。囲みの行は出力の頭から1回だけ調べ、取り除く範囲は頭から順に組み立てる。

## 確かめたこと

- `apps/daemon/src/agent-json.test.ts`：囲み方の8通り（「```json」「```」「```JSON」「```jsonc」、囲みなし、前後に説明の文、文の途中、
  整形した JSON を「```」で囲む）×呼び出しごと（88件）、壊れた JSON、候補が複数、文字列の中の ``` と波括弧、前のコードの囲みとの取り違え、長い出力の速さ。
- `prompts.ts` を main に戻すと81件が落ちる（「```json」で囲む場合と、もともと読めていた場合だけが通る）。囲みの数の確かめを外すと取り違えのテストが、
  括弧の対応を覚えないようにすると速さのテストが落ちる（約68秒かかる）。
- `npm run lint`（終了コード0）、`npm run typecheck`、`npx vitest run`（965件）、`npm run build` が通った。
- レビューの指摘への対応の後：修正前後の計測（n=16000 → 32000）で、末尾が壊れた深い入れ子は 2644ms → 10209ms が 6ms → 12ms に、
  配列の入れ子は 3799ms → 14830ms が 6ms → 9ms になった。ほかの入力（正しい深い入れ子・文字列の中の括弧・閉じない長い文字列・
  ランダムな断片の繰り返し200通り×200KB など）も 25ms 以下だった。修正前の実装に戻すと20秒かかって速さのテストが落ちる。
  新しい検証器が `JSON.parse` と同じ判断をすることを2万件の比較テストで確かめた。lint・typecheck・vitest（967件）・build が通った。
- レビューでも、隔離した環境でテスト（965件、修正後は967件）・lint・typecheck が通り、修正後は約192KBの入力が約13ミリ秒で読めることが確かめられた。
- 本物の AI での動作は確かめていない（レビューでも未実施）。画面の変更は無い。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| 壊れた JSON の深い入れ子で、`JSON.parse` の失敗のたびに次の `{` から重なる範囲を読み直すので、解析の時間が出力の長さの2乗になる（約192KBで10.31秒。デーモンの同期処理なので、ほかのタスクや停止の要求への応答も滞る） | JSON の文法を自前で確かめ、途中で開いた括弧の結果を覚えて読み直さないようにした。同じ種類の2乗の時間（囲みの判定・取り除き）も併せて直した。末尾が壊れた入れ子などの速さの回帰テストと、壊れた外側の中の正しい答えを読むテストを足した |
