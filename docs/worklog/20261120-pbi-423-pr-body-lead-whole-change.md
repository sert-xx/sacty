# 作り直しの後も、PR の本文の「変更：」を PR 全体の変更の要約にする

- 日付: 2026-11-20（UTC）
- タスク: PBI-423
- PR: なし
- ブランチ: なし
- 関係する ADR: なし

## 目的

作り直しの後の PR（#461・#463・#465・#466）で、結論の「変更：」が、レビューへの対応と検査の実行の報告になった。原因は、エージェントが説明の最初の段落に、今回の対応の件数と検査の結果を書くこと。

## したこと

- `apps/daemon/src/prompts.ts`：`IMPLEMENT_REPORT_LINE`（最初の実行・直しの実行の両方）に、最初の段落が結論の「変更：」に載ること、PR 全体の変更の要約だけにすること、対応の件数・検査の結果を最初の段落に書かないことを足した。`implementReworkLines` に、最初の段落は PR 全体の要約のままにし全体の変更が変われば反映すること、対応の件数・経過は「最後の直し」の節に、検査の結果は全体の説明の「どう確かめたか」に今回の結果で書くことを足した。
- 仕様書 `approval`（日英）を直した。

## 確かめたこと

- `apps/daemon/src/pr-body-rework.test.ts`：最初の実行と直しの実行の指示のそれぞれに決まりが入ること（直しの実行だけに足す文は最初の実行に入らないこと）。入力は、要求要件を経ない・テストなし・要求要件あり・不具合の修正（reproduce）・要求要件と設計を経る（テストあり・なし）の6形で、`IMPLEMENT_REPORT_LINE` を使う5経路すべてを通す。
- `npm test`：281 ファイル・5695 件が通過（14 件スキップ）。`npx vitest run tests/docs`：93 件が通過。`biome check --error-on-warnings .`：通過。`npm run typecheck`：エラー 0 件。

## 残したこと

- 本文の組み立てでの機械的な除去は足していない（言語・ツールに寄せずに報告の文を見分けにくいため）。指示が守られず「変更：」が崩れたら、次の作り直しの PR の本文で気づける。再発したときに、除去を足すかを決める。
