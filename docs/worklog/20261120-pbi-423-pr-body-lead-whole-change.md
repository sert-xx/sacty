# 作り直しの後も、PR の本文の「変更：」を PR 全体の変更の要約にする

- 日付: 2026-11-20（UTC）
- タスク: PBI-423
- PR: なし
- ブランチ: なし
- 関係する ADR: なし

## 目的

作り直しの後の PR（#461・#463・#465・#466）で、結論の「変更：」が、レビューへの対応と検査の実行の報告になった。原因は、エージェントが説明の最初の段落に、今回の対応の件数と検査の結果を書くこと。

## したこと

- `apps/daemon/src/prompts.ts`：`IMPLEMENT_REPORT_LINE`（最初の実行・直しの実行の両方）に、最初の段落が結論の「変更：」に載ること、PR 全体の変更の要約だけにすること、対応の件数・検査の結果を最初の段落に書かないことを足した。`implementReworkLines` に、最初の段落は PR 全体の要約のままにし全体の変更が変われば反映すること、対応と検査の報告は「最後の直し」の節に書くことを足した。
- 仕様書 `approval`（日英）を直した。

## 確かめたこと

- `apps/daemon/src/pr-body-rework.test.ts`：最初の実行と直しの実行の指示のそれぞれに決まりが入ること（直しの実行だけに足す文は最初の実行に入らないこと）。
