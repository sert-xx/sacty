# コンテキストリポジトリの雛形を作る sacty context init

- 日付: 2026-10-13（UTC）
- タスク: PBI-45
- PR: #48
- ブランチ: feat/issue-45-context-init
- 関係する ADR: [コンテキストリポジトリの雛形を sacty context init で作り、既存のファイルは --force が無ければ上書きしない](../adr/20261013-0023-context-init-template.md)

## 目的

コンテキストリポジトリを一から書かずに始められるよう、既定のコンテキストと同じ構成の雛形を作るコマンド
`sacty context init [<dir>] [--force]` を足す。

## したこと

- `apps/daemon/src/context-template.ts`（新規）：既定のコンテキストと同じ構成（README.md・rules.md・skills/・mcp.yaml・sacty-context.yaml・
  agents/codex/config.toml）の雛形を作る。各ファイルには何を書く場所かの説明と、コメントにした例だけを入れた（そのまま指定しても既定のコンテキストを変えない）。
- 同じ名前のファイル（シンボリックリンクを含む）か `rules/` がすでにあれば、上書きせずに理由を示して止める。`--force` で上書きする（リンク先は書き換えない）。
- 作った後に、次にすること（git で管理して push し、プロジェクトの設定でコンテキストリポジトリに指定する）を表示する。
- `packages/cli/src/index.ts` の `sacty --help` と README に使い方を足した。

## 確かめたこと

- 雛形をコンテキストリポジトリに指定して、Claude Code・Codex の両方でコンテキストを用意できること（警告なし・既定の設定が変わらないこと）をテストで確かめた。
- コメントの例を外しても sacty が読める形であることをテストで確かめた。
- 空のディレクトリ・既存のファイルあり・`rules/` あり・`--force`・シンボリックリンクの境界をテストし、実装を戻すとテストが失敗することを確かめた。
- 実際の CLI で、空のディレクトリに作成 → 2回目は理由を示して停止 → `--force` で上書き、を確かめた。
- マージの後のレビューで、#47・#48・#49 を含むマージのコミットで全452テスト・`npm run lint`・`npm run typecheck` が通った。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| マージの後のレビュー：末端のファイルのリンクは外していたが、`skills`・`agents`・`agents/codex` などの途中のディレクトリがリンクだとリンク先をたどり、リポジトリの外に README.md を作り、`--force` では外の既存のファイルを上書きした（「リンク先は書き換えない」を満たさない） | 別の PR（#51）で直した。書き込む前に、すべての出力パスの途中のディレクトリを `lstat` で確かめ、ディレクトリでなければ `--force` でも何も書かずに止める |

## 残したこと

- どのパッケージにも package.json の `files` が無く、npm pack では dist/ が .gitignore のために含まれない。いまはすべて private なので、公開するときに別に対応する。
- 途中のディレクトリのリンクの扱いは #51 で直した。
