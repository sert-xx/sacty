# 環境が原因のテストの失敗と、作業領域では確かめられない確かめ方を、人の確認として最終承認へ回す

- 日付: 2026-10-24（UTC）
- タスク: PBI-155
- PR: #215
- ブランチ: feat/issue-155-human-checks
- 関係する ADR: [環境が原因のテストの失敗と、作業領域では確かめられない確かめ方を、人の確認として最終承認へ回す](../adr/20261024-1124-human-checks-at-final-approval.md)

## 目的

sacty のリポジトリのタスクで、最終レビューが3回続けて不合格になって止まった。
実装は承認済みの要求要件に沿っていると判定されていたが、次の2つは、実装をやり直しても直らない。

- エージェントのコンテナで PID 1 がエージェントの CLI（Node.js）になり、ゾンビのプロセスが回収されない。このため、デーモンのプロセスの後始末のテスト 16 件が時間切れで失敗し、テストのコマンドの終了コードが 1 になっていた。
- 要求要件の受け入れの確かめ方に、実機の入力方式（macOS・Windows）での確認が書かれていて、作業領域では満たせなかった。

コンテナの側で直せるものは直し、直せないものは、最終レビューを不合格にせずに、人がマージの前に確かめる項目として残す。

## したこと

- エージェントのコンテナを `docker run --init` で起動する（`apps/daemon/src/agents/docker.ts` の `dockerRunArgs`）。
- 要求要件の工程の指示に、受け入れの確かめ方を「自動のテストで確かめること」と「人が確かめること」に分けて書くよう足した（`acceptanceCheckLines`）。
- 最終レビュー
  - 指示に「人が確かめること」「環境によるテストの失敗」の節を足した（`humanCheckLines`）。作業領域では確かめられない確かめ方は `humanChecks` に、失敗がすべて環境によるときは失敗したテストと根拠を `tests.environmentFailures` に書かせる。
  - `FinalReviewed` に `humanChecks`、`GuardianTests` に `environmentFailures` を足した（どちらも省略可。それより前の記録はそのまま読める）。
  - 合否は `guardianTestsPassed`（終了コード 0、または 0 以外で環境による失敗の申告がある）で決める。終了コードが 0 のときの `environmentFailures` は記録しない。
- 出し方
  - 実装の PR の本文：最終レビューの下に「人が確かめること」のチェックリスト。テストの行に「環境による失敗だけ」。
  - タスクの詳細：最終レビューの欄に「人が確かめること」、ゴールガーディアンが実行したテストに「環境による失敗だけ」（日英）。
  - 実装のやり直しの指示：環境によると判断した失敗を「実装で直す対象ではありません」として渡す。
  - 質問への答えに渡す判定にも出す。
- 仕様書（`tasks-and-steps`・`agent-execution`・`context`。日英）、ユーザードキュメント（`tasks`。日英）、ADR を直した・足した。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| （セルフレビュー）人が確かめることの一覧の key に項目の文を使うと、同じ文が重なったときに key がぶつかる | 順番を key にした |
| （PR #215 レビュー）人が確かめることが、PR の本文の長さの上限で省かれる部分（最終レビューの記録）にある。要求要件が 66,000 文字だと、通常の本文・テンプレートの本文の両方で消える | 省かれない footer の、承認の案内の前に移した。footer を長くしすぎないよう、1項目 1,000 文字・一覧 6,000 文字までにし、入りきらない項目は残りの件数と確かめる場所を書く。長い要求要件で両方の本文に残ること・上限を超える一覧・長い1項目のテストを足した |
| （PR #215 レビュー）仕様書の「テストの仕組みが無いタスク」に「終了コード 0 の申告が要り」が残っている | 共通の合格条件（`guardianTestsPassed`）に直した（日英） |

## 残したこと

- 統合レビュー・レビューの工程のテストの扱いは変えていない。
- 環境が原因かどうかを sacty が自分で確かめること（起点のコミットでのテストの実行）はしない。ゴールガーディアンの申告と人の確認に任せる。
- 止まっているタスク（質問欄のショートカット）は、この変更を取り込んだ後に、人が最終レビューからやり直す。
