# 文書作成の成果物を1つに決めて指示し、外部に直接書いたページを記録して、差し戻しと書き出しで同じページを直させる

- タスク: なし

- 関係する ADR: [文書作成の成果物を1つに決めて指示し、外部に直接書いたページを記録して、差し戻しと書き出しで同じページを直させる](../adr/20261025-0410-document-deliverable-and-rework.md)

## 目的

文書作成のタスクで、外部 PF の文書を直すよう差し戻すと、最初とは別の文書が外部に作られ、タスクの最終報告も外部に文書として作られた。
何が成果物かを明確にし、差し戻しではその成果物を続けて直し、成果物でないものを sacty の外に出さないようにする。

## したこと

- 原因：文書作成のエージェントは外部 PF・MCP に書き込める。指示は「原稿を外部に直接書かず出力する」だけで、何が成果物か
  （出力の全体が原稿として保存・承認・書き出しされること）を伝えておらず、外部に直接書いたページも記録していなかった。
  そのため、外部に書いたエージェントは出力に作業の報告を書き、差し戻しの実行は前のページを知らずに別のページを作り、
  承認でその報告が書き出された。
- `apps/daemon/src/prompts.ts`：文書作成の指示に「成果物」の節（`documentDeliverableLines`）を置いた。成果物は原稿1つ、
  タスクの説明が直接の作成・編集を指示していれば外部に書いてよく、そのページが成果物、指示が無ければ外部に書かない、
  成果物のほかに外部にページ・コメントを作らない、作業の報告を外部にも原稿にも書かない、差し戻しでは前回の原稿と成果物の
  ページを直す。外部に直接書いたページは `sacty-document-page` で申告させ、`extractDocumentPage` で取り出して原稿から除く。
  紛らわしい「既存文書の直接更新依頼は作業で扱います」を除いた。
- 同じファイルの `buildExportPrompt`：書き出し先に書くのはファイルの内容の1ページだけで、書き出しの報告を別のページやコメントにしない。
- `packages/core/src/events.ts`・`packages/core/src/projection.ts`：`AgentRunCompleted` に `documentPage` を足し、投影の
  `Task.documentPage` に最後に申告されたページを残す。
- `apps/daemon/src/service.ts`：文書作成の実行の出力から申告を取り出して記録する。書き出しは、書き出した URL が無くても
  `documentPage` があれば、そのページを更新させる。
- 仕様書（`docs/spec/tasks-and-steps.md`・`docs/spec/export.md`）とユーザードキュメント（`docs/user/tasks.md`）を、英語の版とともに直した。
- 最初の版では外部への書き込みをすべて禁じる指示にしたが、利用者から「タスクの説明で直接編集の指示があれば従ってよい。
  外部への書き込みを禁じたいのではない」と指摘があり、上のとおり直した。

## 確かめたこと

- `npx vitest run apps/daemon/src/prompts.test.ts`：120 件が通る（足したテスト：直接の書き込みはタスクの説明の指示があるときだけ・
  作業の報告を書かせない・差し戻しで前回の原稿と成果物のページを直させる・申告の取り出し・書き出しで報告を書かせない）。
- `npx vitest run apps/daemon/src/daemon.test.ts -t "非コードの成果"`：32 件が通る（足したテスト：直接書いたページを記録し、
  申告の無い差し戻しの回でも残し、差し戻しの指示と書き出しで同じページを使う）。
- `npx vitest run tests/docs`：93 件が通る。
- `npm run lint`・`npm run typecheck`：通る。
