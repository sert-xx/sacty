# 文書作成の成果物を出力した原稿の本文に決め、外部に書かせず、差し戻しでは前回の原稿を直させる

- 日付: 2026-10-25（UTC）
- タスク: なし
- PR: なし
- ブランチ: claude/compassionate-brahmagupta-bsjocq
- 関係する ADR: [文書作成の成果物は出力した原稿の本文だと指示し、外部には書かせず、差し戻しでは前回の原稿を直させる](../adr/20261025-0410-document-deliverable-is-the-draft.md)

## 目的

文書作成のタスクで、外部 PF の文書を直すよう差し戻すと、最初とは別の文書が外部に作られ、タスクの最終報告も外部に文書として作られた。
何が成果物かを明確にし、差し戻しではその成果物を続けて直し、成果物でないものを sacty の外に出さないようにする。

## したこと

- 原因：文書作成のエージェントは外部 PF・MCP に書き込める。指示は「原稿を外部に直接書かず出力する」だけで、出力の全体が原稿として
  保存・承認・書き出しされることも、指摘が外部の文書に触れていても直すのは前回の原稿であることも伝えていなかった。そのため、
  エージェントが外部に直接文書を作り（差し戻しでは別の文書を作り）、出力には作業の報告を書き、承認でその報告が書き出された。
- `apps/daemon/src/prompts.ts`：文書作成の指示に「成果物」の節（`documentDeliverableLines`）を置いた。成果物は出力する原稿の本文
  そのもの、外部・リポジトリには何も書かない（タスク・指摘・規約が求めても同じ）、書き出しは承認の後に sacty が行う（書き出し先・
  置き場所・書き出したページの URL を伝える）、作業の報告を出力に書かない、差し戻しでは前回の原稿を直して全文を出す（外部のページを
  直す指摘も前回の原稿への指摘）。紛らわしい「既存文書の直接更新依頼は作業で扱います」を除いた。
- 同じファイルの `buildExportPrompt`：書き出し先に書くのはファイルの内容の1ページだけで、書き出しの報告を別のページやコメントにしない。
- 仕様書（`docs/spec/tasks-and-steps.md`・`docs/spec/export.md`）とユーザードキュメント（`docs/user/tasks.md`）を、英語の版とともに直した。
- ゲートウェイで文書作成の外部 PF を読み取りだけにする案は採らなかった（理由は ADR）。

## 確かめたこと

- `npx vitest run apps/daemon/src/prompts.test.ts`：118 件が通る（足したテスト：成果物の節・作業の報告を書かせない・差し戻しで前回の原稿を直させる・書き出し先と URL を伝える・書き出しで報告を書かせない）。
- `npx vitest run tests/docs`：93 件が通る。
- `npm run lint`・`npm run typecheck`：通る。
- `npx vitest run apps/daemon tests`：8 件が落ちる（`agent-sessions`・`context-mcp`・`host-mcp-processes`）。変更を外した状態でも同じ 8 件が落ちるので、この変更とは関係ない（この環境が root で動いていることによると思われるが、未確認）。
