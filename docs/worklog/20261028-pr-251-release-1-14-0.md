# 版を 1.14.0 に上げる

- 日付: 2026-10-28（UTC）
- タスク: なし
- PR: #251
- ブランチ: feat/release-1-14-0
- 関係する ADR: [版は 1.0.0 から semver で付け、タグと GitHub Releases でリリースする](../adr/20261019-2345-semver-releases.md)

## 目的

1.13.0 の後に、タスクの詳細の画面の組み直し（PR #250）が入った。設定ファイルの形・台帳・コマンドの引数に互換性の無い変更は無い
（画面だけの変更）ので MINOR を上げ、1.14.0 をリリースする。

## 1.13.0 からの変更

- タスクの詳細を、上に固定する見出し・タブ（概要・作業履歴・費用・工程の設定・監査）・右のプロパティの列で組み直した（PR #250）。
  - 概要の成果物は工程を選んで1つずつ出し、最初はいまの工程の成果物を出す。
  - 開いたタブは `?tab=` に残す。既存のリンクのハッシュ（`#event-<ID>`・`#audit` など）は、その要素のあるタブを開いてから移る。
- 更新の後にすること：`npm ci` で依存を入れ直し、既定のイメージの名前が `sacty-agent:1.14.0` に変わったので、
  `npx sacty image build` で作り直す。

## したこと

- 4 つのパッケージとワークスペースの依存の版を `1.14.0` にし、`package-lock.json` の版の行も同じにした（これまでと同じく、版の行だけを直した）。
- 既定のイメージの名前（`DEFAULT_IMAGE`）を `sacty-agent:1.14.0` にし、仕様書（`agent-execution`・`configuration`）・ユーザードキュメント
  （`config`・`images`）の日英と、イメージの名前を書いているテスト・コメントを同じ版にした。ゲートウェイの MCP クライアントの版の文字列も
  `1.14.0` にした。

## 確かめたこと

- Node v26.12.1 で、`npm ci`・`npm run lint`・`npm run typecheck`・`npm run build`：通過（`npm ci` の後に `package-lock.json` の差分は版の行だけ）。
- `npx vitest run`（`tests/docs` を含む）：159 ファイルが通過、2 ファイルが失敗。
  - `install-security-tools.test.ts` の 2 件（macOS の作業環境で道具を置けない）は、1.13.0 のときと同じく版を上げる前の状態でも失敗する
    （このテストと、テストが試す `install-security-tools.sh` は 1.13.0 から変わっていない）。
  - `daemon.test.ts` の「ゴールガーディアンの作業領域を消す間も、ほかのタイマーが進み、消し終わってから工程を終える」が 1 度落ちた。
    時間に左右されるテストで、単独で流すと 1.14.0 でも版を上げる前の main でも 3 回とも通り、`daemon.test.ts` をファイルごと流しても
    775 件すべて通った。全件を並べて流したときの負荷によるもので、版の文字列とは関係が無いと判断した。
- `git grep 1.13.0` で、ADR・作業履歴のほかに `1.13.0` が残っていないことを確かめた。
