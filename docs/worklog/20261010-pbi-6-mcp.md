# コンテキストの MCP サーバーの合成・変換と、秘密情報の実行時の注入を行う

- 日付: 2026-10-10（UTC）
- タスク: PBI-6
- PR: #14
- ブランチ: feat/issue-6-mcp
- 関係する ADR: [コンテキストの MCP サーバーを mcp.yaml で書いて合成し、秘密情報は名前で参照して実行時に環境変数でだけ渡す](../adr/20261010-1231-context-mcp-and-secret-injection.md)

## 目的

PBI-6 の後半（PBI-6b）。前半の PBI-6a（#13）に続けて、受け入れ条件2・3の MCP の部分と4を扱う。

- MCP の設定を合成し、Claude Code と Codex の形式に変えてコンテナに置く。
- MCP の設定は名前ごとに下位が上書きし、上書き禁止は下位で外せない。
- 秘密情報は名前で参照し、値は実行時に注入する。

## したこと

- `mcp.yaml` の読み込み・検査・合成と、Claude Code の `mcp.json`・Codex の `config.toml` への変換：`apps/daemon/src/context.ts`。
  上書き禁止・取り除きは、スキルと同じ処理に共通化した。TOML で使えない文字はエスケープする。
- 起動のフラグ（`--mcp-config`・`--strict-mcp-config`・`--allowedTools`）と、秘密情報の環境変数での注入：`apps/daemon/src/agents/invocation.ts`。
  Codex の stdio のサーバーは `sh` で包んで目的の変数名に移す。
- サービス：`apps/daemon/src/service.ts`。
- レビューの対応で、`apps/daemon/src/agents/redact.ts` の長さの下限（8文字）を外し、推測で取り出す値（`secretStringsInJson`）にだけ残した。

## 確かめたこと

- `npm test`：189件が通った（10件追加）。合成（上書き・上書き禁止・取り除き）、`mcp.json` と `config.toml` の出力、誤った設定（`${`・秘密情報の名前・サーバー名・
  stdio と HTTP の混在・file の URL・環境変数名）で止まること、TOML のエスケープ、起動のフラグと環境変数での注入、秘密情報が無いときに止まること、
  サービスで設定に値が無く台帳にも残らないことを確かめた。注入をやめると関係するテストが失敗することも確かめた。レビューの対応の後は190件が通った。
- 実物の CLI で、ローカルのコンテキストリポジトリから `prepareContext` で作った設定を使って確かめた。
  - Claude Code 2.1.296：`--mcp-config` の `${...}` が展開され、stdio のサーバーに `prefix` 付きの値が渡る。
  - Codex 0.160.0：`CODEX_HOME` の `config.toml` を読み、stdio・HTTP の両方の設定を解釈することを `codex mcp list` で確かめた。`sh` の包みで目的の変数名に移ることも確かめた。
- レビューでは `npm test`・`npm run lint`・`npm run typecheck` が通ったことを確かめ、生成した Codex の設定を TOML として解析し、シェルの特殊文字を含む試しの値が包みを通して正しく渡ることを確かめた。
  1・2・6・7文字の秘密情報、`prefix` 付きの出力、空の値、推測で取り出す短い値の扱いも確かめた。
- 確かめていないこと：Codex で `codex exec` から MCP サーバーを実際に起動しての動作（`env_vars` での受け渡しはドキュメントに沿っている）。
  レビューでも、実際の Claude Code・Codex からの MCP の接続と Docker での起動は確かめていない。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| P2：取り除きの処理が8文字未満の値を対象にしないので、短い MCP の秘密情報が出力に含まれると、伏せられずに台帳に残る（試しの値を `pin123` にすると `AgentRunCompleted.payload.output` に残る） | 渡した秘密情報は長さにかかわらず取り除くようにし（空の値だけ無視）、長さの下限は推測で取り出す値の側にだけ残した。サービスの統合テスト（`pin123`）と、`redact` 単体（短い値・重なる値・空の値）の回帰テストを足し、下限を戻すと失敗することを確かめた |

## 残したこと

- Codex で `codex exec` から MCP サーバーを実際に起動しての動作の確認。
