# 版を 1.19.0 に上げる

- 日付: 2026-11-08（UTC）
- タスク: なし
- PR: #327
- ブランチ: feat/release-1-19-0
- 関係する ADR: [版は 1.0.0 から semver で付け、タグと GitHub Releases でリリースする](../adr/20261019-2345-semver-releases.md)

## 目的

1.18.1 の後に入った変更（PR #314〜#326）をリリースする。機能の追加があるので MINOR を上げる。

## 1.18.1 からの変更

- 実装の繰り返しの止め方：やり直しても前回の失敗が直らなければ止める（PR #314）、途中は関係するテストだけ実行する（PR #323）、最終レビューの判定基準を先に渡す（PR #321）。
- CI：CI が無いリポジトリで長く待たない（PR #315）、差分と無関係な不安定な失敗で戻さない（PR #316）、失敗ジョブを1回だけ再実行する（PR #317）、不安定なテストの台帳（PR #318）、最終レビューを CI と並べて進める（PR #320）。
- イメージ：`sacty image build` の後の古い版の片付け（PR #319）、実行のイメージをタスクに1つにする（PR #322）、依存の準備のタスクごとのキャッシュ（PR #325）。
- 依存のある子タスクを、依存先の PR のブランチに重ねて始める（PR #324）。
- Claude Code の実行に権限の確認を求めないモードを明示して渡す（PR #326）。

## 互換性の判断

- 設定ファイルの形・コマンドの引数に、互換性の無い変更は無い。
- 台帳：古い作業履歴はそのまま読める（PR #322 は工程ごとのイメージの古いイベントも読む）。新しいイベント（`TaskImageChanged`・`StackedDependencyMerged`・`PullRequestRetargeted`・`PullRequestCiRerunRequested`）を足したので、これらが記録された後に 1.18.1 に戻すと、1.18.1 は知らない種類のイベントを読めず止まる（`apps/daemon/src/activity.ts` の `EventInput.parse`）。リリースの説明の注意に書く。
- HTTP API：工程ごとの `images` を `image` に変え、`POST /api/tasks/:id/images` を消した（PR #322）。同梱の画面は同じ PR で直してあり、API は利用者向けの公開の面として版の規則に挙げていないので、MINOR のままにし、リリースの説明の注意に書く。

## したこと

- 5 つのパッケージとワークスペースの依存の版を `1.19.0` にし、`package-lock.json` を `npm install --package-lock-only` で作り直した（差分は版の行だけ）。
- 既定のイメージの名前（`DEFAULT_IMAGE`）を `sacty-agent:1.19.0` にした。
  同じ版にしたもの：仕様書（`agent-execution`・`configuration`）とユーザードキュメント（`config`・`images`）の日英、イメージの名前を書いているテスト・コメント、ゲートウェイの MCP クライアントの版の文字列。
  直したファイルは、1.18.1 の版上げ（PR #313）と同じ範囲。
- 元のイメージのダイジェスト：`docker buildx imagetools inspect node:26-bookworm-slim` の `Digest` が `Dockerfile` の値（`sha256:add5c17c…`）と同じだったので、変えていない。
- エージェントの CLI の版（`packages/cli/docker/agent-cli`）は変えていない。

## 確かめたこと

- `npm run lint`・`npm run typecheck`：通過。
- `npx vitest run --no-file-parallelism`（`tests/docs` を含む）：通過（件数は PR の本文に書く）。
- `git grep -F 1.18.1` で、ADR・作業履歴のほかに `1.18.1` が残っていないことを確かめた。
- `Dockerfile`・`agent-cli` は変えていないので、イメージのビルドはやり直していない。
