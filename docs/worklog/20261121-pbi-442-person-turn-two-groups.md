# 「あなたの出番」を 2 つの組に分け、ダッシュボード・ベル・一覧のカード・MCP で同じ並びにした

- 日付: 2026-11-21（UTC）
- タスク: PBI-442
- PR: #492
- ブランチ: sacty/task-b7c3f763
- 関係する ADR: [「あなたの出番」を判断すれば進むものと一時停止の 2 つの組に分け、ベルの組分けをやめて 4 か所を同じ対象・同じ並びにする](../adr/20261121-1300-person-turn-two-groups-one-order.md)

## 目的

判断すれば先へ進むタスク（承認待ち・エスカレーション）が、止まったままのタスク（一時停止）に埋もれないようにする。
ダッシュボード・ヘッダーのベル・一覧の上のカード・MCP の `list_tasks` を、同じ対象・同じ並びにする。

## したこと

- `packages/core/src/person-turn.ts` に、人の出番の判定・組・並び（`personTurnGroup`・`personTurnTasks`）を 1 か所に置いた。画面の `needsPerson`、MCP の `isPersonTurn`、集計の 3 状態の条件はこれに置き換えた。
- ダッシュボードの欄を組ごとの見出し・件数つきにし、ベルは組分けを種類の 2 つに替えて待っている時間を出した。一覧のカードは同じ対象・同じ並びにした。
- `aiReview` を一覧の応答にも、承認待ちで PR が開いているタスクの分だけ載せ（`aiReviewsOfHeads`）、`reviewing` のときだけ状態に「・AI のレビュー中」を添えた。
- MCP の `order` を `personTurnGroup_waitingSince_asc` にし、各タスクに `personTurnGroup` を足した。
- 日英の文書・ADR・スクリーンショット（ダッシュボード・タスクの一覧）を直した。

## 確かめたこと

- 本物のサービス・API につないだ、4 か所が同じ ID の列になるテスト（`packages/cli/src/person-turn-parity.test.ts`）。
- `personTurnTasks` の比べ方を組を見ない形に戻すと、そろいのテストと core の並びのテストが落ちることを確かめた。
- ブラウザで、下の組が 8 件あっても、幅 1440px・375px で上の組の見出しと先頭の行が見えることを確かめた。
- `npm run lint`：通った（755 ファイル）。
- `npm run typecheck`：通った。
- `npx vitest run`（依存の最適化のキャッシュを空にして全件）：305 ファイル・6076 件が通り、14 件はスキップ。
  レビューで、ブラウザのテストに `optimizeDeps.include` が無く、キャッシュが空の全体実行で時間切れになると指摘された。`include` と専用の `cacheDir` を足した後は、キャッシュを空にした全体実行でも時間切れは出なかった。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| ブラウザのテストの `optimizeDeps.include` が無く、全体実行で時間切れ | `include` と専用の `cacheDir` を足した |
| `approval` の仕様書が、一覧の応答の `aiReview` と食い違う | 日英とも、`listView` でも足すことを書いた |
| 仕様書の経路に、ヘッダー・一覧のカードが `GET /api/dashboard` を読むことが無い | 日英とも、データの経路・集計の節・取り直しの表に書いた |
| そろいのテスト・「レビュー中」のテストの入力が弱い | 待ち始めの記録を実際のイベントの畳み込みで作り、記録の順を `updatedAt` と食い違わせた。「レビュー中」は途中に置き、`updatedAt` を別々にした |
| `aiReviewsOfHeads` が判定条件を写している | 対象の条件・レビューのタスクの条件を関数に出して共有した |
| 作業履歴にコマンドと結果が無い | 上に書いた |
| `durationText` の再 export | やめ、テストの import を直した |
