# プロジェクトのコンテキストの合成の結果を、Claude Code・Codex ごとにプレビューする

- 日付: 2026-10-14（UTC）
- タスク: PBI-76
- PR: #85
- ブランチ: feat/issue-76-context-preview
- 関係する ADR: [コンテキストの合成の結果を、実行と同じ組み立てで、Claude Code・Codex ごとに画面・API・CLI からプレビューする](../adr/20261014-0701-context-preview.md)、[CLI は、sacty up が書く接続先のファイルを通して、動いているデーモンの API を呼ぶ](../adr/20261014-0701-cli-daemon-connection-file.md)

## 目的

これまで合成の結果を確かめる手段は、実行の後の作業履歴に出る層と commit・警告だけで、mcp.yaml などの誤りも次の実行で工程の失敗として見つかっていた。
プロジェクトのコンテキストの合成の結果を、Claude Code・Codex それぞれについて、保存した設定でも編集中の設定でもプレビューできるようにする。
置かれるファイル（パスと中身）は実行と同じ処理で作り、層・どの項目がどの層から来たか・locked/remove の効果・警告・使える外部 PF・MCP の置き換えた後の形と
元の接続先を出す。秘密情報の値・ゲートウェイのトークンは出さない。誤りを示し、保存のときにも検査する。画面・API・CLI から見られ、取得したものは後片付けする。

## したこと

- 組み立ての分割（`apps/daemon/src/context.ts`）：`writeContext` を、置くファイルの一覧を返す純粋な `planContext` と、書き込む `writePlanned` に分けた。
  `prepareContext` の中の MCP のゲートウェイへの置き換え・ホストの MCP の追加・書き出しの絞り込み・時間切れの警告を `routeMcp` に分けた。実行（`prepareContext`）と
  プレビュー（`previewContext`）は、どちらも `buildContext`（層の取得 → `composeContext` → `routeMcp` → `planContext`）で作る。ホストの MCP とゲートウェイの起点も、
  実行と同じ `TaskService.mcpRouting` で決める。
- スキルの写し方を、ディレクトリごとの `cpSync` からファイルごとに変えた（空のディレクトリは写らなくなる）。Codex のスキルの一覧は写す元の SKILL.md から読む。
- プレビューは一時ディレクトリに取得し、成功・失敗にかかわらず消す。ファイルの中身はファイルごとに256KB、合計8MBまで（sacty が作るファイルを先に数える。
  大きいファイルは先頭だけ、UTF-8 でないファイルは中身を出さない）。
- 秘密情報は参照の名前だけを出し、ゲートウェイの実行ごとのトークンは見本にする。プレビューは秘密情報の取り出し口を呼ばず、ゲートウェイに実行も登録しない。
  画面と CLI に、literal の値や層の設定の中身は書かれたまま出るという注記を出す。
- 層の MCP サーバーがホストの MCP サーバーと同じ名前のときの警告 `context.hostMcpOverride` を足した（実行の作業履歴にも残る）。
- 保存のとき（PUT・POST `/api/projects`）も同じ検査をし、誤りがあれば保存したうえで `contextError` で知らせる。
- API：`GET /api/projects/:id/context-preview?runtime=codex`（保存した設定）と `POST /api/projects/:id/context-preview`（`{ runtime, definition }`）。
- CLI：`sacty context preview <ID か名前> [--runtime claude-code|codex] [--json] [--no-content]`（`packages/cli/src/context-preview.ts`）。起動中の sacty に API で問い合わせる。
  そのため `sacty up` が `$SACTY_HOME/daemon.json`（接続先とトークン、権限 0600）を書き、終わるときに自分のものだけを消す。
- 画面：プロジェクトの設定の「コンテキストリポジトリ」の下に「コンテキストのプレビュー」を足した（`apps/web/src/components/context-preview.tsx`）。保存した設定・
  編集中の設定の2つのボタン、Claude Code・Codex の切り替え。編集中の設定では GitHub アカウントと対象も編集中のものを使って取得する。
- セルフレビューで、同じ層の項目を上書き禁止にしたときに層の名前が2度並ぶのを直した。#84 の取り込みに追従し、実行ではホストの MCP の準備を待ち、プレビュー・保存の検査では
  待たないことをテストで確かめた。
- レビューの指摘を受けて3点を直した（下の表）。

## 確かめたこと

- 回帰テスト：合成10件・API とサービス8件・CLI 5件。両方の AI について、既定のコンテキストを含むプレビューのファイルが、`prepareContext` の出力ディレクトリと、工程の実行で
  コンテナに渡したディレクトリの両方と一致すること。未保存の設定、誤り（形の誤り・取得の失敗・トークンを伏せる）、秘密情報を出さないこと、保存のときの検査、API の
  400/404/401、大きいファイル・バイナリ・合計の上限、CLI（接続先のファイルの権限・名前での指定・同名・つながらない）。
- 修正を戻す8通りの変更（プレビューだけファイルを減らす・実行だけスキルの参照のファイルを写さない・ホストの MCP と同じ名前の警告を消す・後片付けをしない・
  未保存の設定を無視する・トークンを伏せない・保存のときに確かめない・合計の上限を数えない）で、すべて落ちた。
- lint（終了コード0）・typecheck・テスト（1046件）・build が通った。
- 一時の SACTY_HOME とポート 4880/4890 で `sacty up` を起動し、手で確かめた。コンテキストはローカルの git リポジトリ（上位の層 → 下位の層。誤りのあるブランチ `broken` も用意）。
  キーチェーン・1Password・gh・docker は偽のコマンドを PATH の先頭に置き、本物の秘密情報は取り出していない（起動のログは0/2件）。本物の AI は使っていない。
  - 保存した設定の Claude Code のプレビューで、警告（locked に当たった remove・ホストの MCP と同じ名前）、層と locked・remove の効果、MCP（stdio は直接、HTTP はゲートウェイの URL と中継先、
    ホストの MCP）、環境変数（秘密情報の参照・トークンの見本・MCP_TIMEOUT）、ファイルの中身。
  - Codex に切り替え、AGENTS.md（スキルの一覧）と config.toml。
  - ブランチに `broken` を入れ「編集中の設定でプレビュー」で、層・ファイル・項目（`servers.docs.url`）を示す誤りが出ること。そのまま保存すると、保存したうえで誤りを知らせること。
  - CLI の `--runtime codex --no-content` で同じ内容が出ること、終了すると `daemon.json` が消えること。
  - 動画を PR に添付した。
- レビューの指摘への対応の後：同じ SACTY_HOME・ポートで2回目の `sacty up` を起動し、2回目は終了コード1で止まり、`daemon.json` が変わらず（ハッシュが同じ）、その後も
  プレビューが使えること。`--json --no-content` で "content" が0件（"path" は44件）になること。インポートの流れで動画を撮り直した。レビューでテスト1068件・lint・typecheck が通った。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| 起動済みの sacty がある状態で同じ SACTY_HOME・ポートで `sacty up` をもう一度実行すると、接続先のファイルを新しいトークンで上書きし、後の sacty の終了処理がそれを消すので、最初の sacty が動いていてもプレビューが使えなくなる | `sacty up` は、デーモンが自分のトークンで応答してから `daemon.json` を書き、ほかの sacty が書いたものが応答するなら上書きしない（応答しない残りだけ上書きする）。消すのは接続先とトークンの両方が自分のものと合うときだけにした。テストを足した |
| 新しいプロジェクトを作るときにコンテキストの誤りが起きても、`contextError` が画面に渡らないまま設定の画面へ移る | 作成で誤りがあったときと、コンテキストリポジトリを持つ定義をインポートしたときは、設定の画面へ `?contextCheck=1` を付けて移り、その印があるときだけ確かめ直して誤りを先頭に出す（誤りの文は URL に載せない）。テストを足した |
| `--json --no-content` を同時に指定すると、JSON の出力にファイルの中身が出る | 出力の組み立てを `previewOutput` にまとめ、`--no-content` のときは JSON でも人が読む形でも中身を除くようにした。4通りと誤りの結果のテストを足した |

## 残したこと

- `sacty up` を止めても、ホストの MCP サーバーのプロセスが親を失って残っていた。PBI-77 が host-mcp.ts を触っているので、この PR では扱っていない。
