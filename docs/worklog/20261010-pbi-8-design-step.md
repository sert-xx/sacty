# 設計の工程（テスト観点つき）と承認ゲートを作る

- 日付: 2026-10-10（UTC）
- タスク: PBI-8
- PR: #4
- ブランチ: feat/issue-8-design-step
- 関係する ADR: [承認済みの要求要件から設計とテスト観点を作り、差し戻し先を選べるようにし、承認した成果物は凍結する](../adr/20261010-0749-design-step-and-freeze.md)

## 目的

承認済みの要求要件から、設計とテスト観点（入力と期待結果がわかる粒度）を作り、承認ゲートで止める。設計の差し戻しで、
やり直す工程として設計か要求要件（再承認が必要）を選べること、承認済みの要求要件と設計を凍結し、要求要件の変更には
人間の再承認を必須にすることが受け入れ条件の要点。

## したこと

- 設計の工程（`apps/daemon/src/prompts.ts`・`service.ts`）：凍結した要求要件だけを渡し、テスト観点を JSON のブロック（`sacty-test-viewpoints`）で
  受け取る。項目が欠けた観点は取り込まず、ID は sacty が振る。
- 差し戻し先の選択と、要求要件に戻したときの承認の取り消し、工程ごとの指摘と上限の数え方（`packages/core/src/projection.ts`・`events.ts`）。
- 承認の時の凍結（`approved`）と、承認済みの工程の実行の完了を復元の段階で拒否する処理。
- 画面：テスト観点のカード（`apps/web/src/components/test-viewpoints.tsx`）、成果物チェックでの差し戻し先の選択（`gate-form.tsx`）、0 件の警告、凍結の表示。
- 起動の時に、PBI-7 で承認されて設計で待機していたタスクを実行待ちにする（`apps/daemon/src/main.ts`）。PBI-7 までの台帳はそのまま読める。
- 動作確認用のスタブで、工程ごとに出力を変えられるようにした（`stub.outputs`、`apps/daemon/src/config.ts`）。

## 確かめたこと

- `npm test` が全件通った（70件。9件追加）。凍結のテストは、凍結の判定を外すと失敗することを確かめた。
- スタブのエージェントで、画面から次の流れを通しで確かめた：要求要件を承認する → 設計とテスト観点3件が提出される → 要求要件へ差し戻す →
  要求要件の2回目を再承認する → 設計の2回目を承認し、凍結の表示を確かめる。
- 幅 375px で横スクロールが出ないことを確かめた。
- 再レビューでは `npm test`（70件）・`npm run lint`・`npm run typecheck` が通った。ブラウザでの表示、本物の Docker とエージェントでの実行、
  クリーンな環境での全体のビルドは確かめていない。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| テスト観点は本文から取り除いて別に保存しているので、設計を差し戻して再実行しても、前回のテスト観点がプロンプトに渡らない（TV-n を指した指摘が処理できない） | 設計の再実行のプロンプトに、前回のテスト観点を全件、ID・何を確かめるか・入力・期待結果つきで入れ、直さない観点も含めて全件を出し直すよう指示した。回帰テストを足し、修正前のコードで失敗することを確かめた |
