# 版を 1.11.0 に上げる

- 日付: 2026-10-26（UTC）
- タスク: なし
- PR: #233
- ブランチ: claude/fervent-cori-xrvo95
- 関係する ADR: [版は 1.0.0 から semver で付け、タグと GitHub Releases でリリースする](../adr/20261019-2345-semver-releases.md)

## 目的

1.10.0 の後に、機能の追加（PR #229〜#232）が入った。設定ファイルの形・台帳・コマンドの引数に互換性の無い変更は無い
（設定・台帳には項目を足しただけ）ので MINOR を上げ、1.11.0 をリリースする。

## 1.10.0 からの変更

- セキュリティチェックとセキュリティ対応の進め方（`security-check`・`security-fix`）を足した（PR #232）。
  - 区分ごとの指摘のレポートを作り、承認したレポートの区分ごとに対応のタスクを作れる。
  - 対応は、前段の調査が宣言した範囲と照らし、最小限の変更の PR にする。
  - テンプレート「セキュリティチェック」で、スケジュールタスクから定期的に点検できる。
  - 既定のイメージに osv-scanner・gitleaks を足した。
- ブラウザのデスクトップ通知と、Slack の通知の On/Off を足した（PR #230）。
- タスクの詳細の作業履歴で、差し戻しの指摘の本文を読めるようにした（PR #231）。
- 既定のレビューに、要らないコードを探す観点（C-15）と UX の観点（C-16）・画面の記録を足した（PR #229）。
- 更新の後にすること：`npm ci` で依存を入れ直し、既定のイメージの名前が `sacty-agent:1.11.0` に変わったので、
  `npx sacty image build` で作り直す（作り直すと osv-scanner・gitleaks も入る）。

## したこと

- 4 つのパッケージとワークスペースの依存の版を `1.11.0` にし、`package-lock.json` の版の行も同じにした。手元の npm 10 では
  `npm install --package-lock-only` が版と関係の無い行（`libc` など）まで消したので、1.10.0 のときと同じく版の行だけを直した。
- 既定のイメージの名前（`DEFAULT_IMAGE`）を `sacty-agent:1.11.0` にし、仕様書（`agent-execution`・`configuration`）・ユーザードキュメント
  （`config`・`images`）の日英と、イメージの名前を書いているテスト・コメントを同じ版にした。ゲートウェイの MCP クライアントの版の文字列も
  `1.11.0` にした。
- 版を数で比べる例（仕様書の `daemon-lifecycle` と `update-check.test.ts` の「1.10.0 は 1.9.0 より新しい」）は、版を上げても意味が変わらないので、そのままにした。

## 確かめたこと

- `npm ci`・`npm run lint`・`npm run typecheck`：通過。
- `npx vitest run`：下の環境による失敗のほかは通過。`agent-sessions.test.ts`・`context-mcp.test.ts`・`host-mcp-processes.test.ts` の 8 件と
  `question-form.browser.test.ts` は、1.10.0 のときと同じく、この作業の環境（クラウドのコンテナ）によるもので、版の文字列とは関係が無い。
- `rg 1.10.0` で、ADR・作業履歴と、上の版を比べる例のほかに `1.10.0` が残っていないことを確かめた。
