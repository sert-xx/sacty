# 版を 1.15.0 に上げる

- 日付: 2026-11-02（UTC）
- タスク: なし
- PR: #272
- ブランチ: feat/release-1-15-0
- 関係する ADR: [版は 1.0.0 から semver で付け、タグと GitHub Releases でリリースする](../adr/20261019-2345-semver-releases.md)

## 目的

1.14.0 の後に、機能の追加と修正が入った（PR #252〜#271）。設定ファイルの形・台帳・コマンドの引数に、既存の利用を壊す変更は無い
（台帳のイベントと API は足すだけ）ので MINOR を上げ、1.15.0 をリリースする。

## 1.14.0 からの変更

- エラーレポート（PR #254）：タスクのエラーを Markdown のレポートにまとめてダウンロードでき、人が求めたときだけオーケストレーターに分析させられる。
  タスクの詳細の右の列に「エラーレポート」の欄を足した。
- macOS 向けのデスクトップアプリ（PR #256）：Electron から既存の CLI を起動し、Node.js と標準のイメージを同梱する実装例（試作。署名・公証・自動更新は無い）。
- タスクのテンプレート「ドキュメント構築」（`docs-setup`。PR #257）。
- 最終レビュー・差し戻し・PR の扱いの変更。
  - 差分が文書だけなら、ツールがイメージに無くても止めずに人の確認へ回す。止まったタスクは再開でテストの扱いを決め直せる（PR #258）。
  - ゴールガーディアンが環境による失敗をオブジェクトの配列で申告しても読む（PR #259）。
  - 指摘の取り込みの判断の最中に PR がマージされても、差し戻さずにマージとして記録する（PR #260）。
  - 実装の PR がベースブランチと競合しないよう、ホストでベースブランチの最新を作業領域に取り込み、親が 2 つのマージコミットで出す（PR #261）。
  - 最終レビューの作業領域の写しに、PR に入る要求要件・設計の成果物を入れる（PR #262）。
  - 範囲外の変更を最終レビューで不合格にする（PR #264）。
  - PR の指摘の戻し先を、承認済みの決定を変えるかで決める（PR #265）。
  - 要求要件・設計の差し戻しで、前回の成果物を元に指摘の所だけ直す（PR #266）。
  - 差し戻しの原因を判断し、ゴールガーディアンの見逃しは原因が見逃しのときだけ数える（PR #270）。
  - 承認待ちの間に実装の PR がベースブランチと競合したら画面に出す（自動では取り込まない。PR #271）。
- 成果物・PR の読みやすさ：要求要件・設計から作業のメモを締め出す（PR #263）。実装の PR の本文を結論から読める短い形にする（PR #268）。
- 取り込み：GitHub の時刻がこの機械の時計とずれても、PR の指摘とレビューのラベルの取り込みが遅れない（PR #267）。
- プロジェクトの設定を同時に保存しても、先の変更が消えない（PR #269）。画面のサーバーの `PUT /api/projects/:id` は、読み込んだ版を
  `If-Match` で添えないと保存できなくなった（428/409。画面から使う分には変わらない）。
- 依存：`@hono/node-server` を 2 系（2.1.3）に更新した（PR #252）。デーモンが使うのは `serve` だけで、コードの変更は無い。
- docs：最近の変更に遅れた仕様書・ユーザードキュメント・図・スクリーンショットを直した（PR #253）。
- 更新の後にすること：`npm ci` で依存を入れ直し（`@hono/node-server` の 2 系と、デスクトップ用の `electron`・`@electron/packager` が入る）、
  既定のイメージの名前が `sacty-agent:1.15.0` に変わったので、`npx sacty image build` で作り直す。

## したこと

- 5 つのパッケージ（`@sacty/core`・`@sacty/daemon`・`@sacty/web`・`@sacty/cli`、および 1.14.0 の後に足した `apps/desktop`）とワークスペースの
  依存の版を `1.15.0` にし、`package-lock.json` の版の行も同じにした（これまでと同じく、版の行だけを直した。`npm install --package-lock-only` を
  流しても差分は出ない）。
- 既定のイメージの名前（`DEFAULT_IMAGE`）を `sacty-agent:1.15.0` にし、仕様書（`agent-execution`・`configuration`）・ユーザードキュメント
  （`config`・`images`）の日英と、イメージの名前を書いているテスト・コメントを同じ版にした。ゲートウェイの MCP クライアントの版の文字列も
  `1.15.0` にした。

## 確かめたこと

- Node v26.12.1 で、`npm ci`・`npm run lint`・`npm run typecheck`・`npm run build`：通過（`npm ci` の後の `package-lock.json` の差分は版の行だけ）。
- `npx vitest run`（`tests/docs` を含む）：180 ファイル（3374 件）が通過、1 ファイル（2 件）が失敗。
  - 失敗は `install-security-tools.test.ts` の 2 件（macOS の作業環境で `/usr/local/bin` に道具を置けない）だけで、これまでと同じく版を上げる前の状態でも
    失敗する作業環境によるもの。時間に左右されるテストの失敗は出なかった。
- `git grep -F 1.14.0` で、ADR・作業履歴のほかに `1.14.0` が残っていないことを確かめた。
