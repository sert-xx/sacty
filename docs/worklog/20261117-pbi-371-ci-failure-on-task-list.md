# 指摘なしの後に CI が失敗している実装の PR を、タスクの一覧の行でも分かるようにする

- 日付: 2026-11-17（UTC）
- タスク: PBI-371
- PR: #405
- ブランチ: feat/pbi-371-ci-failure-on-task-list
- 関係する ADR: [指摘なしの後の実装の PR の CI の失敗を、タスクの一覧の行にも印で出す](../adr/20261117-0406-show-ci-failure-on-task-list.md)

## 目的

PBI-364（#404）で、人の承認を待つ実装の PR の CI が失敗していたら、タスクの詳細の承認待ちの案内と作業履歴に出すようにした。
タスクの詳細を開かないと分からないのでは足りないので、リポジトリの持ち主が、タスクの一覧にも出すと決めた（通知は足さない）。

受け入れ条件の要点：

- PBI-364 が記録した CI の失敗があるタスクは、一覧の行に印が出る（日英。色だけに頼らない）。
- 印は、PBI-364 の表示が消える条件で消える。新しい判定・回復の仕組みは足さない。
- タスクの状態（一覧の絞り込み・並び）・「あなたの出番」・通知は変えない。
- 仕様書・ユーザードキュメント（日英）・作業履歴に反映する。

## したこと

- 一覧の行のデータ（`TaskRow`）に、印を出すかどうか（`ciFailed`）を足した。判定は、タスクの詳細の案内と同じ `pullRequestCiFailure` をそのまま使う（`apps/web/src/lib/task-list-data.ts`）。デーモン・イベント・記録は変えていない。
- 一覧の行の状態の列に、状態の表示の下に「CI 失敗」（英語は「CI failed」）の印を添えた（`apps/web/src/components/task-list.tsx`）。
  - 色だけに頼らないよう、アイコン（丸に×。飾りなので読み上げない）と文字で出す。
  - 印は、再実行で CI が通っても、PR を更新する・マージする・閉じるまで残る。そこで、補足（ⓘ）に、Sacty が CI を読んだ時点の結果であること・その後の結果は反映されないこと・失敗していたチェックはタスクの詳細に出ることを出す。
  - 状態の文言と種類（`statusText`・`statusTone`）は変えない。絞り込み・並び・「あなたの出番」のカード・ヘッダーのお知らせ・ダッシュボードには手を入れていない。
- 画面の文言（日英）を、タスクの一覧の辞書に足した（`ciFailed`・`ciFailedHint`）。
- core のコメント（`Task.pullRequestCiFailure`・`pullRequestCiFailure`・`PullRequestCiFailed`）の「タスクの詳細に出す」を、今の出す場所に合わせた（コードの動きは変えていない）。
- docs：
  - 仕様書（日英）：`approval` の「指摘なしの後の CI の失敗の表示」（出す場所・しないこと・コードの場所）、`tasks-and-steps`。
  - ユーザードキュメント（日英）：`tasks` の「タスクの一覧」と「『指摘なし』の後に CI が失敗したとき」。
  - ADR：出す場所をタスクの詳細だけにした決定（PBI-364 の ADR）の、その部分を置き換える ADR を足した。古い ADR は、ファイル名とステータス・置き換え先だけを直した（PBI-364 の作業履歴からのリンクも、新しい名前に直した）。
- ユーザードキュメントのスクリーンショットは撮り直していない。撮影のデータ（`scripts/docs-screenshots/seed.mjs`）に CI の失敗の記録が無く、撮る間の偽の GitHub は CI の失敗を答えないので、写っている所は変わらない。

自分で決めたこと：

- 印を出すのは、プロジェクトのタスクの一覧の「すべてのタスク」の行だけ。ダッシュボードの進行中のタスク・「あなたの出番」のカード・ヘッダーのお知らせには出さない（PBI の「タスクの一覧の、そのタスクの行」のとおり）。
- 印の文言は「CI 失敗」（状態の名詞）。読んだ時点の結果であることは、補足に書いた。
- 一覧を印で絞り込む機能は足していない（絞り込みを変えない、という条件のため）。

## 確かめたこと

PR を作る前のコードで実行した結果。

- `npx vitest run --no-file-parallelism`：251 ファイル・4826 件が通った（1 件は以前からの skip）。
- `npm run typecheck`：通った。`npx biome check --error-on-warnings apps packages docs tests scripts`：指摘なし。`npm run build`：通った。
- 足したテスト：`apps/web/src/components/task-list-ci-failed.test.ts` の 4 件。
  - 日本語・英語で、記録があるタスクの行にだけ、飾りのアイコンと文字（「CI 失敗」「CI failed」）と補足が出る。状態の文言は、印の無いタスクと同じ。
  - 記録があっても無くても、行のほかの値（状態の文言と種類・並び）・「あなたの出番」・絞り込みの結果（状態の種類ごと）が同じ。
  - 印が消える条件：記録が無い、記録が今の提出のものでない（PR の更新・別の PR）、PR がマージされた・閉じられた、承認待ちでない、レビューの子タスクの指摘なしを待っている。
- 修正を戻すとテストが落ちること：一覧のデータに印を足す行を消すと、足したテストの 4 件がすべて落ちた（どのテストも、印が出ることを確かめているため）。戻して 4 件が通ることを確かめた。
- 実際の画面での確認（`scripts/docs-screenshots/` の種データと、偽の GitHub の写しを使い、別のポート（4794・4795）・一時の `SACTY_HOME`・一時の `HOME` で起動した。動いている sacty には触れていない。終わった後、起動したものは止めた）：
  - 偽の GitHub が CI の失敗を答える前：一覧（8 行）のどの行にも印は無い。
  - 偽の GitHub が、実装の PR のマージ待ちのタスク（PR #128）の先頭のコミットの CI を「失敗」と答えるようにした。デーモンが次に CI を読んだ後（5分おきの読み取りなので、361 秒後）、開いたままの一覧に、読み込み直さずに印が出た。
  - 日本語：その行の状態の列に「実装の PR のマージ待ち」と、その下に「CI 失敗」（丸に×のアイコンと文字）。補足の印（読み上げの名前は「補足」）を開くと「Sacty が PR の CI を読んだ時点の結果です。その後の結果は反映されません。失敗していたチェックは、タスクの詳細に出ます。」が出た。
  - 英語：状態は「Implement PR awaiting merge」、印は「CI failed」。補足は「The result when Sacty read the PR's CI. Later results are not reflected. The task details list the checks that were failing.」。
  - 印が出る前と後で、すべての行の状態の文言・行の並び・件数の表示・「あなたの出番」のカードが同じ（日英とも）。印が出たのは、その 1 行だけ。
  - 絞り込み：状態を「あなたの出番」にしても、その行は印つきで残った（8件中 3件）。検索に「CI 失敗」と入れても、掛からない（8件中 0件。検索は題だけ）。
  - タスクの詳細には、同じ記録の案内（読んだコミットと時刻・失敗していたチェック）が出ていた。ダッシュボードには、印は出ない。
  - 偽の GitHub の答えを「PR #128 はマージ済み」に変えると、次の PR の確認の後（54 秒後）、読み込み直さずに印が消え、状態は「マージの後の監視・CI/CD 待ち」になった。
- 確かめていないこと：実際の GitHub の CI での動き。PR の更新（作り直し）・クローズで印が消えることは、実際の画面では確かめていない（テストと、PBI-364 の記録を消す処理のテストで確かめている）。
