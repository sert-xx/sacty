# AI エージェントが書いた元のセッションのファイルを、実行ごとに伏せて残し、ハッシュを作業履歴に記録する

- 日付: 2026-10-13（UTC）
- タスク: PBI-66
- PR: #75
- ブランチ: feat/issue-66-agent-session-files
- 関係する ADR: [AI エージェントが書いた元のセッションのファイルを、実行ごとに秘密情報を伏せて残し、大きさとハッシュを作業履歴に記録する](../adr/20261014-0100-agent-session-archive.md)

## 目的

Claude Code・Codex が書く元のセッションのファイルを、監査のために実行ごとに残す。失敗・止めた・中止した実行も残し、スタブでは何もしない。
認証の情報は写さず、秘密情報は境界をまたいだ値も伏せる。大きさとハッシュを作業履歴に記録し、画面と API で一致を確かめられる（書き換えれば不一致）。
上限を超えたら先頭と末尾を残して間を省き、そのことがわかる。画面から一覧を見てダウンロードできる。実際の Claude Code・Codex の形で残ることを確かめる。

## したこと

- `apps/daemon/src/agent-sessions.ts`（新規）：写すファイルの選び方（実際の Docker で、イメージの Claude Code 2.1.296・Codex 0.160.0 が書く場所を確かめた）、
  伏せながらの写し（1MB ずつ読み、境目をまたぐ値・JSON でエスケープされた形も伏せる。UTF-8 でないファイルも壊さない）、上限 200MB の割り振りと切り詰め。
- `apps/daemon/src/agents/docker.ts`・`invocation.ts`：停止の確認と認証ファイルの書き戻しの後、一時的な場所を消す前に写す。Claude Code はコンテキストの無い実行でも
  一時的な場所をマウントする。`apps/daemon/src/agents/parse.ts`：出力の session_id・thread_id を実行のセッション ID として読む（無ければファイル名から推し量る）。
- 台帳：`packages/core/src/events.ts`・`projection.ts` に `AgentSessionArchived`。
- API：`apps/daemon/src/server.ts` に `GET /api/tasks/:id/runs/:runId/agent-files` と `…/agent-files/raw?path=`。
- 画面：`apps/web/src/app/tasks/[id]/runs/[runId]/page.tsx` に「エージェントの元のファイル」（セッション ID・大きさ・SHA-256・一致の状態・ダウンロード・
  不一致の警告・省いた旨）、作業履歴の表示の行。
- レビューの対応：停止を確かめられない実行は写さず `notArchived` を残す。写すときは O_NOFOLLOW・dev/ino・途中のディレクトリの確かめ。上限は伏せた後の大きさで割り振る。

## 確かめたこと

- `npm run lint`・`npm run typecheck`・`npx vitest run`（763件）・`npm run build`：通った。
- 主要な処理を12か所わざと壊し、すべてテストが落ちることを確かめた。
- 画面は一時的な環境で確かめ、ダウンロードしたファイルのハッシュが記録と一致した。
- Codex と Claude Code の形は、実際の Docker（偽のキーで失敗した実行）で確かめた。
- 本物の Claude Code（2.1.296・サブスクリプション）で、利用者の許可を取って確かめた：一時的な環境でチャットに1回質問し、答え・使用量・費用を読み取れ、
  元のセッションのファイル（92,199 バイト）が `runs/<task>/<run>/agent/` に 0600 で残った。記録のセッション ID・大きさ・SHA-256 が、残ったファイルを shasum で
  計算した値と一致し、画面でも「一致」と出た。ファイルに秘密情報は含まれていなかった。
- レビューの対応の後：`npm run lint`・`npm run typecheck`・`npx vitest run`（783件）・`npm run build` が終了コード 0。修正を戻すと、停止のテスト・差し替えの3件・
  膨らむケースと境界のテストが落ちることを確かめた。
- 確かめなかったこと（レビュー）：実際の Docker・実際の Claude Code・Codex の起動とブラウザの操作。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| [P1] コンテナの停止を確かめられなかった実行でも写すので、動いたままのコンテナが選んだ後のファイルをリンクに差し替えると、ホストの別のファイルの中身が保存される | 停止を確かめられないときは写さず、`AgentSessionArchived` に `notArchived: "container_not_confirmed"` を記録し、デーモンのログ・作業履歴・実行のページに理由を出すようにした。写すときも O_NOFOLLOW・O_NONBLOCK で開き、fstat で通常のファイル・同じ dev/ino を確かめ、途中のディレクトリがリンクでないことを開く前と後に確かめる。回帰テスト（停止を確かめられない偽の docker、ファイル・途中のディレクトリのリンクへの差し替え、ハードリンク）を足した |
| [P2] 上限の割り振りが伏せる前の大きさなので、伏せて膨らんだ中身に上限が効かない | 1回目に伏せた後の大きさを測って割り振り、2回目に写すときのファイルごとの最大を必ず有限にした。目印を含めて合計が上限を超えない。回帰テスト（指摘のケース・ちょうど上限と1バイト超え・どれも膨らむケース・目印より小さい割り当て・秘密情報が残す範囲の境目をまたぐ位置）を足した |

再レビューで、2件の解消が確かめられた（追加の指摘は無し）。

## 残したこと

- ファイルが多い実行では、記録のイベントが大きくなる（件数の上限なし）。
- Linux のネイティブの Docker で、ホストの利用者の ID がイメージの node（1000）と違うと、0700 の一時的な場所にコンテナが書けない恐れがある。
- Codex の `codex exec resume` に rollout だけで足りるかは PBI-67 で確かめる。
