# 実例の評価の固定テストが、全体の実行で時々 EPIPE で落ちるのを直す

## 目的

PBI-282（PR #280）で足した `apps/daemon/src/review-eval.test.ts` の「AI の実行が失敗したときは評価せず失敗する」が、全体の `vitest run` で時々 `spawnSync false EPIPE` で落ちる（単独の再実行では通る）。

## 原因

- テストは、模擬の AI に `false` を使い、指示文を標準入力で渡して「終了コード 1」のメッセージを期待していた。
- `false` は標準入力を読まずに終わる。`spawnSync` が指示文を書き込む前（または途中）にパイプが閉じると、`result.error` に EPIPE が付く。`runAgent` は `result.error` があれば終了コードを書かず、そのメッセージだけで失敗にしていたので、メッセージが `spawnSync false EPIPE` になり、期待と食い違った。
- 入力が大きいと毎回起きる（2MB の入力で、旧い作り方のメッセージが 100 回中 100 回食い違った）。小さい入力では、マシンの負荷によって起きたり起きなかったりした。このとき終了コードも付いている（`status` は 1）。

## したこと

- `runAgent`：`error` と終了コード（シグナル）の両方を、失敗の理由に書くようにした。実行の失敗を確実に失敗として扱う性質（起動失敗・異常終了・時間切れは例外）は変えていない。実際の AI が指示文を読む前に異常終了したときも、EPIPE だけで終了コードが分からないことがなくなる。
- テスト：「終了コード 1」の確認は、指示文を読み切ってから終わる模擬の AI（`cat >/dev/null; exit 1` のスクリプト）にした。指示文を読まずに終わる AI（`false`）は、小さい入力・2MB の入力のどちらでも、`AI の実行に失敗しました：…終了コード 1` の形で失敗するテストを別に足した。

## 確かめたこと

- 旧い `runAgent` に戻すと、足したテストが失敗する。
- 該当のテストを 50 回続けて流して、すべて通った。
- `npm run lint`・`npm run typecheck`・`npx vitest run apps/daemon/src/review-eval.test.ts tests/docs`。
