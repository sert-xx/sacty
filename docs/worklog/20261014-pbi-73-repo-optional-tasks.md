# リポジトリを指定せずにタスクを作れるようにする

- 日付: 2026-10-14（UTC）
- タスク: PBI-73
- PR: #81
- ブランチ: feat/issue-73-repo-optional-tasks
- 関係する ADR: [タスクの対象リポジトリを任意にし、リポジトリの無いタスクはオーケストレーターがプロジェクトの対象とコンテキストから進め方を選ぶ](../adr/20261014-0436-superseded-repo-optional-tasks.md)

## 目的

タスクを作るときの対象リポジトリを任意にする。リポジトリの無いタスクは、オーケストレーターがプロジェクトのコンテキスト
（コンテキストリポジトリ・規約・書き出しの接続先）とプロジェクトの対象（リポジトリの一覧）から進め方を選ぶ。
選べる進め方は、調べもの・全体の設計・分割・リポジトリを選んでのコードの変更。子タスクやオーケストレーターが選ぶリポジトリは、
対象に無ければ使わない。リポジトリを前提にした処理を洗い出して手当てし、一覧・詳細・作業履歴にリポジトリの有無と選んだ理由を出す。

## したこと

- タスクの作成（画面・API）で対象リポジトリを任意にした。画面は空欄なら `repo: null` で送る。API は `repo: null` でリポジトリ無し、
  省略は対象がリポジトリ1つならそれ（今と同じ）、そうでなければリポジトリ無し（以前はエラー）。CLI にはタスクを作るコマンドが無いので変えていない。
  リポジトリ無しのタスクは `TaskCreated.noRepo: true` で明示する。
- リポジトリ無し専用のオーケストレーターの指示（`apps/daemon/src/prompts.ts`）に、対象のリポジトリの一覧・コンテキストリポジトリ・
  規約・書き出しの接続先を渡す。
- 進め方（`apps/daemon/src/service.ts` ほか）：
  - 調査だけ（investigate）か、新しい組み合わせ `design-only`（要求要件 → 設計）を選び、リポジトリ無しのまま進めて画面で承認して完了する。
    PR・ブランチは作らない。書き出し先があれば書き出す。
  - 分割（split）では、分割のエージェントが子タスクごとに対象からリポジトリと理由を付ける。対象に無い・無いときは理由
    （`split.repoMissing`・`split.repoNotCandidate`）を記録して止め、再開で分割をやり直す。統合レビューは、子タスクのリポジトリ・
    ベースブランチごとに最新を作業領域の下に用意して読む。
  - コードの変更が要り分けないとき（standard・skip-design・bugfix）は、オーケストレーターが対象からリポジトリを選び（`RepositoryChosen`）、
    次の実行でそのリポジトリを用意して工程を選び直す。選べない・対象に無いときは止め、タスクの詳細で人が選んで再開できる。
- リポジトリ前提の処理の手当て：開始時の clone を飛ばす。工程は空の作業領域で実行し、実装・再現・レビュー・PR 作成の工程は実行せずに
  理由（`repo.stepNeedsRepository`）を示して止める。テストのコマンド・ベースブランチ・docker compose のサービス・PR でのレビュー・
  プロジェクトの対象で指定したイメージは使わない。レビューだけの組み合わせは選べない。
- 画面（`apps/web`）：作成の画面で対象リポジトリを「任意」にした。一覧に「リポジトリ無し」の印と子タスクのリポジトリを、詳細に
  「リポジトリ無し」か対象リポジトリと選んだ理由（オーケストレーター・人）を出す。再開の画面でリポジトリを任意に選べる。
  作業履歴に選んだリポジトリ・子タスクのリポジトリ・統合レビューで読んだリポジトリを出す。
- イベントと投影（`packages/core/src/events.ts`・`projection.ts`）、README を直した。
- #80（JSON の読み取りの共通化）とは、読み取る項目（`repo`・`repoReason`）の追加だけにとどめ、#80 のマージ後に rebase して追従した。

## 確かめたこと

- `apps/daemon/src/daemon.test.ts` の「リポジトリを指定しないタスク（PBI-73）」ほか：リポジトリ無しで調べものを完了する、全体の設計を画面で承認して
  書き出し完了する（PR でのレビューを使えるプロジェクトでも PR を作らない）、分割して子にそれぞれ別のリポジトリを付ける（統合レビューは両方を読む）、
  分割せずにリポジトリを選ぶ・選べず人が選ぶ・用意できず人が選び直す、対象に無いリポジトリ（オーケストレーター・分割案・人の選択・API）、
  リポジトリのあるタスクの作成・分割・リポジトリの選択の拒否が今と同じ。
- 修正を1つずつ戻すと（リポジトリの用意を飛ばす判定・分割案のリポジトリの検査・子タスクへのリポジトリの付与・リポジトリの選択・`repo: null` の扱い）、
  それぞれのテストが落ちることを確かめた。
- lint（終了コード0）・typecheck・テスト（986件）・build が通った。
- 偽の docker（指示の内容で決まった出力を返す）・一時的な SACTY_HOME・ローカルのリポジトリで、調べもの → 分割 → リポジトリを選べず人が選んで再開、を
  画面で追い、動画（2分15秒）を撮った。本物の AI は使っていない。
- レビューでも、隔離した環境でテスト（986件）・lint・typecheck が通った。本物の AI・本物の Docker・外部のサービスとの結合と、ブラウザでの画面の操作は、
  レビューでは確かめていない。
