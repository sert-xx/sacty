# PR への指摘を取り込み、ゴールガーディアンが戻し先を判断する

- 日付: 2026-10-11（UTC）
- タスク: PBI-14
- PR: #21
- ブランチ: feat/issue-14-pr-review
- 関係する ADR: [PR へのレビューとコメントを指摘として取り込み、戻し先はゴールガーディアンが判断し、設計・要求要件まで戻すときは人間に確認する](../adr/20261011-0059-superseded-pr-feedback-rework-judged-by-guardian.md)

## 目的

PBI-14 の後半（PBI-14b）。#20 の PR の見守りに、PR への指摘の取り込みを足す。取り込んだ指摘は累積し、二重に取り込まない。戻し先はゴールガーディアンが承認済みの要求要件・設計に照らして判断し、設計・要求要件まで戻すときは人間に確認する。取り込んだこと（ID・だれが・いつ）を作業履歴に残す。

## したこと

- フィードバックの読み取り（`apps/daemon/src/github.ts`）：レビュー（Request changes と本文のあるコメント）・行ごとのコメント・PR への通常のコメントを読む。承認・bot は除く。
- 取り込み（`apps/daemon/src/service.ts`）：最後のフィードバックから2分たってから、未取り込みのものをまとめて `PullRequestReviewImported` として記録する。1件ずつの指摘にし、行ごとのコメントにはファイルと行を添える。本文の無い Request changes は「変更を求められた」を1件にする。1件 2,000 文字・50 件まで。
- 戻し先の判断：ゴールガーディアンへの指示を `apps/daemon/src/prompts.ts` に足し、新しいセッションで判断させる（`ReworkJudged`、費用は予算に入れる）。実装だけなら差し戻して見逃しを記録する。設計・要求要件・判断できないときは `TaskEscalated`（`rework_confirmation`）で人間の確認に回し、画面に提案と理由を出す。
- 判断の途中でデーモンが止まっても、次の確認で続きから進める。判断の間に人間が操作していたら記録しない。
- 作業履歴と画面：`packages/core/src/events.ts`・`packages/core/src/projection.ts`、`apps/web/src/components/gate-form.tsx`・`apps/web/src/app/tasks/[id]/page.tsx` ほか。
- 途中のコミットで、Request changes だけでなく、コメントのレビューや PR への通常のコメントも指摘として取り込むようにした。
- レビューの対応：取り込みを 50 件までのバッチにし、取り込み済みにするものと指摘を同じバッチから作る。3つの一覧とも `Link` ヘッダーの `rel="next"` をたどって全ページを読む（API と同じ場所の URL だけ、50 ページまで）。

## 確かめたこと

- `npm test`：240件が通った（10件追加）。3種類のフィードバックを指摘として取り込むこと、実装の判断で差し戻すこと（見逃しの記録を含む）、2分待つこと、二重に取り込まないこと、ゴールガーディアンへの指示に指摘と承認済みの成果物がありタスクの内容が無いこと、人間が選んだ戻し先に指摘を引き継ぐこと、実行の失敗・本文の無い Request changes、読み取り（承認・本文の無いコメントのレビュー・bot の除外、行の元の行、時刻の順）、作業履歴・表示を確かめた。書き終わるのを待たないようにするとテストが失敗することを確かめた。
- 実物の GitHub で、試し用のリポジトリの PR のレビュー・行のコメント・通常のコメントを読めることを確かめた（どれも無いので空。gh の表示と一致）。
- 再レビューで、`npm test`（242件）・`npm run lint`・`npm run typecheck` が通った。
- 実際にコメントを付けて取り込む流れ（実際のゴールガーディアンの判断）と、画面は確かめていない。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| 未取り込みが 51 件以上あると、指摘は先頭 50 件だけなのに全件を取り込み済みにし、51 件目以降を永久に取りこぼす | 取り込みを指摘の上限（50 件、古い順）までのバッチにし、取り込み済みと指摘を同じバッチから作るようにした。51 件で 51 件目が取り込み済みにならない回帰テストを足し、戻すと失敗することを確かめた |
| フィードバックの3つの一覧が1ページ（100件）しか読まず、100 件を超えると以後の指摘を読めない | `Link` の `rel="next"` をたどって全ページを読んでから、絞り込み・重複の除外・50 件ずつの取り込みをするようにした。たどるのは API と同じ場所の URL だけで、ページ数の上限を設けた。2ページ目を読むこと、違う場所の URL をたどらないことの回帰テストを足し、戻すと失敗することを確かめた |

## 残したこと

- 実際にコメントを付けて取り込む流れ、実際のゴールガーディアンでの判断、画面は確かめていない。
