# 実装の工程と、テストの実行・最終レビューを作る（PBI-10 の前半）

- 日付: 2026-10-10（UTC）
- タスク: PBI-10
- PR: #6
- ブランチ: feat/issue-10-implement-verify
- 関係する ADR: [実装の工程は対象リポジトリの clone で行い、sacty が秘密情報の無いコンテナでテストを実行し、合格したらゴールガーディアンが観点ごとに最終レビューする](../adr/20261010-0834-superseded-implement-test-final-review.md)、[差分は、clone の直後にどのコンテナにもマウントしない場所へ退避した git のメタデータで作り、作業領域の git の設定をホストで評価しない](../adr/20261010-0834-diff-from-isolated-git-metadata.md)

## 目的

PBI-10 は大きいので2つに分け、この PR は前半（PBI-10a、受け入れ条件1〜3）を扱う。実装の工程がテスト観点に沿ってテストを書き、
「観点 → テスト → 実行結果」の対応表を成果物として出すこと、sacty が隔離されたコンテナでテストを実行して全件が通ることを
機械的に確かめること、ゴールガーディアンが新しいセッションで、観点ごとにテストが観点を本当に検証しているか、過去の差し戻しの
指摘ごとに再発が無いかをレビューすることが要点。PR の作成と成果物チェックのゲート、見逃しの記録は後半（PBI-10b）に回した。

## したこと

- 対象リポジトリの準備（`apps/daemon/src/repository.ts`）：config.yaml の `repository` で指定したリポジトリを clone し、起点のコミットを `RepositoryPrepared` で記録する。
- 実装の工程のプロンプト（`apps/daemon/src/prompts.ts`）：承認済みの成果物・テスト観点・人間の指摘を渡し、観点ごとのテストの対応を `sacty-test-map` で受け取る。
- テストの実行（`apps/daemon/src/agents/test-runner.ts`）：別のコンテナで秘密情報を渡さずに実行し、`TestsRun` を記録する。
- 最終レビュー（`apps/daemon/src/service.ts`）：空の作業領域・新しいセッションで、観点ごと・指摘ごとに判定し、`FinalReviewed` を記録する。
- やり直し（3回続けて通らなければ一時停止）、最終レビューを実行できないときの停止、一時停止の理由の説明（`pausedMessage`）。
- 起動の時に、設計を承認して待機していたタスクを実行待ちにする。
- 画面：タスクの詳細に対応表・テストの結果・最終レビューを出す（`apps/web/src/components/implementation.tsx`）。
- レビューの対応で、差分を退避した git のメタデータで作るようにし、最終レビューの失敗の費用（`FinalReviewFailed`）と差分の取得の失敗での停止を足した。

## 確かめたこと

- `npm test` が全件通った（97件。13件追加）。本物の git での clone・差分（新しいファイル・日本語を含む）・ブランチが無いときの失敗もテストで確かめた。
- 回帰テストは、修正を外すと失敗することを確かめた。
- 画面で、スタブのエージェントとローカルの対象リポジトリを使い、次の流れを確かめた（テストの実行は本物の Docker）：要求要件・設計を承認する →
  実装する → テストを実行する（合格）→ 最終レビュー（TV-3 が不合格）で3回やり直した後に一時停止する → 再開する → 最終レビューに合格し、実装が完了する。
- 幅 375px で横スクロールが出ないことを確かめた。
- レビューは、一時リポジトリの git のフィルターでホストでの実行を無害なマーカーのファイルで再現し、一時 SQLite と偽の executor で最終レビューの
  失敗の費用の欠落と、差分の取得の失敗での合格を再現した。再レビューでは `npm test`（100件）・`npm run lint`・`npm run typecheck` が通り、
  clean フィルター・textconv・fsmonitor を仕込んでもマーカーが作られないこと、作業領域の `.git` を消しても差分を取得できることが確かめられた。
  本物のコンテナ・外部のエージェント・ブラウザでの動作は確かめていない。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| コンテナはエージェントが `.git/config` と `.gitattributes` を変えられるので、ホストで `git add --all` を実行すると、仕込まれたフィルターなどの外部コマンドがデーモンの権限で実行され、隔離を越える | clone の直後に `.git` をどのコンテナにもマウントしない場所へ退避し、差分はそれを `--git-dir` にして一時インデックスで作るようにした。利用者・システムの git の設定を読まず、外部のコマンドを使う設定を打ち消し、`--no-ext-diff --no-textconv --text` で出す。フィルター・textconv・fsmonitor と `-diff` を仕込んだ回帰テストを足し、修正前の方式ではマーカーが作られることを確かめた |
| 最終レビューの実行に失敗したとき、使用量と費用を捨てて一時停止だけを記録している | `FinalReviewFailed`（記録者はゴールガーディアン）に使用量・費用・換算値かどうかを記録してから一時停止し、費用を予算に足して 80% の通知も判定するようにした。100万出力トークン（$15）の利用上限の失敗で確かめる回帰テストを足し、加算を外すと失敗することを確かめた |
| 差分を取得できないときに、エラーの文を差分の代わりにしてレビューを続けるので、コードを見ずに合格になりうる | 差分を取得できなければ、ゴールガーディアンを呼ばずに一時停止するようにした。状態は「テスト合格・最終レビュー待ち」のままにし、再開するとテストを繰り返さずに差分の取得からやり直す。回帰テストを足し、修正前のコードで失敗することを確かめた |

## 残したこと

- PR の作成と成果物チェックのゲート、見逃しの記録は、後半（PBI-10b）で行う。
- テストのコンテナのネットワークを切る設定は、必要なら PBI-10b 以降で足す。
- テストごとの合否は読んでいない（全体の合否はテストのコマンドの終了コードで判定する）。
- 対象リポジトリの設定（config.yaml の `repository`）は、PBI-5 のプロジェクトの設定で置き換える予定。
