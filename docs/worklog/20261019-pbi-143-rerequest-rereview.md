# レビューの再依頼で、自動で再レビューする

- 日付: 2026-10-19（UTC）
- タスク: PBI-143
- PR: #155
- ブランチ: feat/issue-143-rerequest-rereview
- 関係する ADR: なし

## 目的

「レビューの依頼」で取り込んだ PR は、sacty がレビューを投稿すると完了する。
その後に作者が GitHub で再依頼（Re-request review）しても、同じ PR は二度取り込まないので拾わず、人が「再レビュー」を押す必要があった。
再依頼したら、sacty が自動で再レビューするようにする（ステークホルダーの要望）。

## したこと

- デーモン：`restartRerequestedReviews` を足した。
  - 依頼の検索で、依頼で取り込んだタスクのうち「再レビュー」できるもの（`canRereview`）の PR が見つかったら、PR の今の依頼先（`requested_reviewers`）と、
    そのタスクのアカウントへの最後の依頼の日時（PR のできごとの `review_requested`）を読む。
  - 今も依頼されていて、最後の依頼が前回の投稿より後なら、再依頼として再レビューする（`ReviewRestarted`、`reason: rerequested`、actor は sacty）。
  - 検索の結果は反映が遅れる（投稿の直後に、外れた依頼が残る）ので、それだけでは再レビューしない。
  - 投稿で依頼が外れなかった（取り込みの後にアカウントを変えたなど）ときに、投稿のたびに再レビューを繰り返さない（最後の依頼が投稿より前）。
- 取り込み：PR のレビューの取り込みのあとに確かめる。今の依頼先か依頼の日時を読めなければ、理由を取り込みの結果に残す。その検索の読んだ位置は進めず、次の取り込みで確かめ直す。
- GitHub：PR を読むときに、今の依頼先（個人だけ。チームは含めない）も読む。PR のできごとから、その人への最後の依頼の日時を読む（`lastReviewRequest`）。
  実際の GitHub で、できごと（`review_requested`・`requested_reviewer.login`・`created_at`）と `requested_reviewers` の形を確かめた。
- 画面：作業履歴で、再依頼を受けた再レビューを「PR でレビューが再依頼されたので、再レビューを始めた」と出す。
- docs：仕様書（取り込み、タスクと工程）、利用者向けの説明（取り込み）。いずれも日本語・英語。

## 確かめたこと

- `npm run lint`・`npm run typecheck`・`npx vitest run`・`npm run build` が通った。
- 次をテストにした。
  - 検索に残っていても、今の依頼先に無ければ再レビューしない。
  - 依頼が残っていても、最後の依頼が投稿より前か同じ時刻か、依頼のできごとが無ければ、再レビューしない。投稿より 1 ミリ秒でも後なら再レビューする。
  - 再依頼で 1 回だけ再レビューする。再レビューの間は重ねない。投稿で外れたらしない。2 回目の再依頼でもう一度する。
  - 次のときは再レビューしない：投稿の前、中止したタスク、ラベルで取り込んだタスク、Off、ほかのアカウントへの依頼。
  - 同じ PR は 1 回だけ確かめる。
  - 読めなければ、伏せた理由を返し、取り込みの読んだ位置を進めない。
  - Issue の取り込みでは確かめない。
  - 作業履歴の文言（日本語・英語）。
- 次の 21 個の、どの修正を戻してもテストが落ちることを確かめた。
  1. 今の依頼先を見ない
  2. 大文字・小文字を区別する
  3. 投稿前・作業中も対象にする
  4. ラベルで取り込んだものも対象にする
  5. Off でもする
  6. ほかのアカウントへの依頼でもする
  7. 同じ PR を二度確かめる
  8. 失敗を返さない
  9. 理由を伏せない
  10. 理由を付けずに始める
  11. 取り込みで確かめない
  12. 失敗しても読んだ位置を進める
  13. 失敗を残さない
  14. Issue の取り込みでも確かめる
  15. 依頼先を読まない
  16. 作業履歴で区別しない
  17. 最後の依頼の時刻を見ない
  18. 投稿と同じ時刻も再依頼とみなす
  19. 依頼のできごとで人を見ない
  20. 依頼のできごとの種類を見ない
  21. 最後でなく最初の依頼を返す
