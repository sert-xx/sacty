# r5 で見つかった問題のうち、成果物と PR の本文（C 群）を直す

- 日付: 2026-11-04（UTC）
- タスク: PBI-302
- PR: なし
- ブランチ: feat/issue-302-r5-followups-c
- 関係する ADR: [要求要件・設計の本文の外にある作業の報告は、指示で防ぐだけでなく、sacty が取り除く](../adr/20261104-0354-strip-work-report-from-deliverables.md)

## 目的

PBI-302 のうち C 群（C1〜C4）の分。A・B・D 群は別の担当で、あとで 1 つの PR にまとめる。

実験 r5（sacty 1.16.0）の S2・S14・S16・S18 で、成果物と PR の本文に出た次の問題を直す。

- C1：要求要件・設計に作業の報告が混ざる（F16 の再発）。削除した行が「確かめる所」に並ぶ。
- C2：PR の本文で、最終レビューの総評・最後の直しが複数の節に繰り返される。空の見出しが出る。
- C3：「観点 → テスト」の表で同じテストが2回出る。`%j` が書式のまま出る。
- C4：情報収集が、対象のリポジトリの外の文書を、リポジトリの文書と区別せずに使う。

## 証拠から確かめたこと

- S14：要求要件 v4 の先頭（最初の見出しの前）に「要求要件を直しました。…セルフレビューは 1 回目で must の指摘がなく、通りました。」の段落があり、実装 PR の本文の「要求要件（人間が承認済み）」の要点にそのまま入った。同じ版の削除行 5 件（R-1・R-4・R-5・R-8・R-10）が「確かめる所」に「分類なし」として並んだ。S16 の 3 回目も同じ（指摘 ID を挙げた報告が文書の冒頭）。#263 の指示は r5 まで効いていなかった。
- S14（PR #2 の 3 回目の本文）：結論の「最後の直し」と「## 最後の直し」の節が同じ 2 文。結論の「最終レビュー」が、折りたたみの「最終レビュー（全文）」の頭と同じ。
- S2（PR #1）：「## 変更」の直下に「## 変更内容」が続き、「## 変更」が空の見出しになった（実装の説明が自分で「## 変更内容」から始まっていた）。「最後の直し」の 2 文が結論と節で同じ。最終レビューの総評が結論・折りたたみの全文で重なる。
- S18（PR #2）：観点表の REQ のテスト 10 件のうち、`src/app.test.ts › books API › returns publisher %j …` と `src/app.test.ts › returns publisher %j …`（describe 無し）のように、同じ 5 件が 2 回ずつ出た。`%j` は書式のまま。
- S2：情報収集が、取り込み元の upstream の `CLAUDE.md`・`docs/dev` を `gh api` で読み、まとめの情報源にした。

## したこと

- C1
  - `apps/daemon/src/prompts.ts`：`withoutWorkReport` を足した。最初の見出しより前の段落と、最後の区切り線より後ろで見出しを含まない節の段落のうち、報告の語を含むものだけを取り除く。`apps/daemon/src/service.ts` が、要求要件・設計の提出された出力に使う（承認の画面・PR のファイル・出典の分類の項目に反映される）。
  - 要求要件・設計の指示に「出力の最初は最初の見出しにする」を足した。
  - `provenanceIds` が、「R-n（削除：…）」の行の ID を除く。
- C2（`apps/daemon/src/prompts.ts`）
  - 最終レビューの折りたたみは、結論に載せた頭の続きだけ（`finalReviewMore`）。名前は「続き」「再発の確認」「続きと再発の確認」。
  - 「最後の直し」の節は、結論に載せた最初の段落を除いた残り。収まるなら節を出さない。
  - 観点ごとの所見は、総評にある文（12 文字以上）を繰り返さず、全部が同じなら「総評と同じです」。
  - 実装の説明が自分で `#`・`##` の見出しから始まるときは、「## 変更」を重ねない。
- C3：`packages/core/src/test-names.ts`（`displayTestNames`）を足し、PR の本文と画面（`implementation.tsx`）で使う。同じファイル・同じテスト名で、describe の並びが他方の末尾にあたる名前は長いほうに統合する。`%s`・`%d`・`%i`・`%f`・`%j`・`%o`・`%O`・`%p`・`%#`・`%$` は `‹…›` に置き換える。ゴールガーディアンに渡す対応は申告のまま。
- C4：情報収集の指示（`GATHER_OUTSIDE_LINE`）に、対象のリポジトリの外の情報は出どころと「対象のリポジトリの外」を明記して別の項目にすること、`sources` の題にも添えること、文書の無さを外の文書で補ったように書かないことを足した。まとめを読む側の指示（`gatheredLines`）にも、外の情報を対象のリポジトリの規約や決定にしないことを足した。指示は、特定のリポジトリ・言語・ツールの名前に寄せていない。
- 仕様書（`approval`・`tasks-and-steps`、日英）・ユーザードキュメント（`tasks`、日英）・ADR を直した。

## 確かめたこと

- `npx vitest run apps/daemon/src/r5-followups-c.test.ts`：23 件。C1（S14・S16 の報告、本文の要約を残す、区切り線の後ろ、本文の中・コードブロック・見出しの下線は触らない、見出しなし・空）、削除行（全角・半角の括弧、削除の語を含むだけの行）、C2（長い総評・文の切れ目が無い総評・再発の確認だけ・テンプレート・所見の重なり・短い文・最後の直しが収まる／収まらない・自分の見出しから始まる説明）、C3（S18 の 6 件→3 件、空・1件・同名のテスト・入れ子・空白・vitest の区切り・書式の文字）、C4。
- `apps/daemon/src/daemon.test.ts` に、サービスを通して、報告が取り除かれ、削除行が確かめる項目に出ないことを確かめる 1 件を足した。
- 修正を戻すと落ちることを確かめた（C1 の取り除き・削除行・「変更」の見出し・最後の直しの節・総評の続き・テスト名・C4 の指示・所見の重なり）。
- 実際の記録で確かめた：S14 の `requirements-v4.md` に `withoutWorkReport` をかけると、先頭の報告だけが消えて見出しから始まり、`provenanceIds` が R-1・R-4・R-5・R-8・R-10 を除く。
- 既存のテストのうち、重なりを前提にしていたもの（「最後の直し」の節・折りたたみの「全文」・「## 変更」の直後の見出し）は、重ならない形に直した。

## 残した制限

- 本文の途中に混ざった報告は取り除かない（セルフレビューの D-6・D-10 に任せる）。見出しの前に、報告の語を含む本体の要約を置くと消える。
- テスト名の統合は、ファイル名を含む名前だけ。ファイル名が無い名前と有る名前は別のテストとして残る。書式の文字は展開せず印にする（値は名前だけからは分からない）。
- 観点ごとの所見は、同じ文だけを除く。言い換えた重なりは除けない。
