## 目的

PR #500 のマージ後に、Sacty のレビューが出した提案を直す。評価の JSON・保存・判定・画面のカード、評価だけで上限を超えるときに段階まで省く振る舞いは変えない。

## したこと

- 低の根拠は、各項目の末尾の「。」を除いてからつなぎ、最後に「。」を1つ付ける。
- `urlPathSegment`・`markdownCode` を `apps/daemon/src/markdown-text.ts` に移し、工程の成果物のリンクと確認箇所のリンクの両方から使う。エンコードは、工程の成果物のリンク（`()` だけを符号にする）に揃えた。確認箇所のリンクは、`! ' *` を符号にしなくなる（リンク先として有効な文字）。
- 確認箇所のラベルは、バッククォートを `'` に置き換えず、長いバッククォートで囲んで元の綴りのまま出す。
- `focusLocation` の効かない条件（コミットの前後の空白・`match[0] !== where`・先頭の `/`）を消し、効く理由をコメントにした。拒否の一覧のテストに、path 内の `:`・制御文字・U+2028・U+2029・前後に空白のあるコミットを足した。
- 何も確かめていない否定のアサーションを、直すか消した。
- 評価が収まらないときの案内を、画面へのリンクを出さず、「Sacty のタスク <ID> の画面」と注釈（`TASK_LINK_NOTE`）にした（PBI-450）。`buildReviewBody` の `risk` を `riskLines` にし、コメントを実際の条件に合わせた。
- ADR は、新しい ADR を足して置き換えた（本文は書き換えない決まり）。比べた案は、PR #500 に書かれておらず、「わからない」と書いた。
- 仕様書・利用者文書（日英）を直した。
