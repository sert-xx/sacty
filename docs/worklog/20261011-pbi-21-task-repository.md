# 画面で作るタスクの対象リポジトリを、プロジェクトの設定から選ぶ

- 日付: 2026-10-11（UTC）
- タスク: PBI-21
- PR: #27
- ブランチ: feat/issue-21-task-repository
- 関係する ADR: [画面で作るタスクの対象リポジトリは、プロジェクトに登録したリポジトリの設定から選び、config.yaml の repository は廃止する](../adr/20261011-1035-superseded-task-repository-from-project.md)

## 目的

画面で作るタスクの対象リポジトリだけが、どのプロジェクトでも `config.yaml` の `repository` を使っていた。動作確認でのフィードバックを受け、プロジェクトに登録したリポジトリから選べるようにする。タスクは選んだリポジトリの設定で進む。設定が無ければ作れないようにし、`config.yaml` の `repository` は廃止する。タスクの詳細に対象リポジトリを出す。

## したこと

- 作成のダイアログ（`apps/web/src/components/new-task-dialog.tsx`）に「対象リポジトリ」を出し、プロジェクトのリポジトリの設定から選ぶ。1つだけなら選ばれている。設定が無ければ案内と設定画面へのリンクを出し、作れないようにする。
- デーモン（`apps/daemon/src/service.ts`）：選んだリポジトリの設定で clone・検証・PR 作成を行う。大文字・小文字の違いは設定のリポジトリ名にそろえる。設定が無い・選んでいない（複数あるのに）・設定に無いときは理由を返して作らない。
- `config.yaml` の `repository` を読まず、雛形からも消した（`apps/daemon/src/config.ts`）。`README.md` に「対象リポジトリはプロジェクトの設定で登録する」と書いた。
- タスクの詳細の見出しの下に対象リポジトリを出す。以前の版で作ったタスクには clone した URL を出す。
- 以前のタスク：対象リポジトリを持たず、まだ clone していないものは、理由（「中止して、タスクを作り直してください」）を記録して一時停止する。
- レビューの対応：対象リポジトリを持たない以前のタスクでも、clone 済みなら記録した URL から owner/name を求め、そのリポジトリの設定で検証と PR 作成を続ける（`git@github.com:` の形にも対応）。

## 確かめたこと

- テスト：285件が通った。選んだリポジトリの設定で clone すること（名前のそろえ方）、複数あるのに選んでいない・設定に無いときは作らないこと、以前のタスクが理由を記録して止まること、画面の操作が選んだリポジトリを渡すこと、`config.yaml` の `repository` を読まないことを足した。
- 次の修正を外すと、それぞれテストが失敗することを確かめた：設定のリポジトリ名にそろえる、複数のときは先頭を選ばない、以前のタスクに対象を補わない、画面で選んだリポジトリを渡す。
- リント・型チェック・ビルドが通った。
- 利用者の環境の写しで画面を確かめた：リポジトリが1つ登録されたプロジェクトでは、それが選ばれた状態でダイアログが開いた。設定の無いデフォルトのプロジェクトでは、案内が出て作成できなかった。以前のタスクの詳細に、clone した URL が出た。
- レビューの対応で、`repo` なしの `TaskCreated` と `git@github.com:acme/app.git` の `RepositoryPrepared` から再開すると、プロジェクトのテストのコマンドで検証し、acme/app に PR を作って成果物チェックに進む回帰テストを足し、修正を戻すと失敗することを確かめた。
- 再レビューで、全286件のテスト・lint・typecheck が通った。レビューでは、ブラウザでの画面操作は行っていない。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| 以前の画面作成のタスクは `TaskCreated.repo` を持たないので、clone 済みでも検証（テストのコマンド）と公開で対象リポジトリの設定を解決できず止まる。「clone 済みのタスクは記録した URL のまま進む」を満たしていない | 記録した URL から owner/name を求め、そのリポジトリについてプロジェクトのリポジトリの設定を使うようにした。まだ clone していない以前のタスクは、これまでどおり止まる。回帰テストを足した |

## 残したこと

- 利用者の環境の `config.yaml` の `repository` は使われなくなる（残っていても読み飛ばす）。sacty 自身を調べるときは、どれかのプロジェクトのリポジトリの設定に sacty のリポジトリを登録する必要がある。
