# レビューの担当の結果を起動のツールの結果として受け取らせ、通知の形の文面を親が書いた実行を作業履歴に残す

- 日付: 2026-11-17（UTC）
- タスク: PBI-368
- PR: #399
- ブランチ: claude/pbi-368-review-result-wait-0cb301
- 関係する ADR: [レビューの担当の結果を起動のツールの結果として受け取らせ、通知の形の文面を親が書いた実行を記録する](../adr/20261117-0038-receive-reviewer-results-synchronously.md)

## 目的

工程のエージェント（親）が、レビューの担当（サブエージェント）の結果が届く前に、完了の通知・結果の文面を自分の発言として書き、それをもとに下書きを直した実行が見つかった。次の 4 つを満たす。

- 親が担当の結果として扱うのは、担当が実際に返したものだけ。
- 親が、担当の結果を、待つ間の番なしで受け取る。
- 担当の結果が揃う前に、親が成果物を直さない。
- 起きたときに、人が気づける。

受け入れ条件は、着手のときに次のとおりに固めた。

1. スキル `review-dispatch` が、担当の結果を起動のツールの結果として受け取る起動の仕方（待つ番が生まれない形）と、届いていない結果を書かない決まりを持つ。
2. 親の発言に、担当の完了の通知・システムの知らせの形の文面があったら、sacty が作業履歴に記録し、画面の作業履歴に出す。見つかった 3 件の形を拾う。
3. 直した後に、同じ種類の依頼を実際に複数回実行し、届く前の修正・通知の形の発言が無いこと、待ちの番が無いことを、実行の記録で確かめる。
4. 既定のコンテキストに、sacty や特定の言語に寄せた記述を書かない。
5. 仕様書（日英）・ADR・作業履歴に反映する。

観点の選び方・指摘の重み・費用のための観点の絞り込みは、範囲外。

## したこと

### 調べたこと（実行の記録。読むだけ）

- Claude Code の親のセッションの記録 1,506 件のうち、担当を起動した記録は 108 件。担当を背景で起動した記録は 83 件、起動のツールの結果で受け取った記録は 25 件。
- 担当の起動 1,070 件を、Agent ツールの `run_in_background` の指定ごとに数えた。

  | 指定 | 件数 | 結果の届き方 |
  | --- | --- | --- |
  | 省いた | 528 | すべて背景（完了の通知で届く） |
  | `true` | 371 | すべて背景 |
  | `false` | 171 | すべて起動のツールの結果 |

- 見つかった 3 件は、どれも担当が背景で動いていた。2026-11-03 と 11-04 の 2 件は、親が `run_in_background: true` を指定していた。11-16 の 1 件は、指定を省いていた。
- 3 件の文面の形は、`<system-reminder>` で囲んだ担当ごとの結果（9 件分）、`<system-reminder>` で囲んだ完了の知らせ 1 件、`<task-notification>` の通知の全文 1 件。
- 背景の 83 件では、担当の結果を待つ間の親の発言が合わせて 1,063 回、待つためのコマンド（`sleep`・`echo`・担当の出力のファイルを覗く）が 24 回。起動のツールの結果で受け取った 25 件では、どちらも 0 回。

### 変えたこと

- 既定のスキル `review-dispatch`（`apps/daemon/default-context/skills/review/review-dispatch/SKILL.md`）に、節「担当の起動と結果の受け取り」を足し、親の手順 7 と制約を直した。
- 出力の読み取り（`apps/daemon/src/agents/parse.ts` の `countImitatedNotices`・`ClaudeOutcomeReader`）で、親の発言の中の、`<task-notification>`・`<system-reminder>` で始まる行を数える。コードブロックの中と、文の中での言及は数えない。
- 件数があれば、実行の結果に持たせ（`apps/daemon/src/agents/docker.ts`）、作業履歴に `SubagentNoticeImitated` を記録する（`apps/daemon/src/service.ts` の `recordImitatedNotices`、`packages/core/src/events.ts`、`packages/core/src/projection.ts`）。実行の結果は変えない。
- 画面の作業履歴の行の文言（日英）を足し、行からその実行のログを開けるようにした（`apps/web/src/lib/labels.ts`・`apps/web/src/i18n/messages/labels.ts`・`apps/web/src/lib/session-log.ts`）。
- 仕様書（`docs/spec/context.md`・`agent-execution.md`・`event-log.md` と英語の版）、ユーザードキュメント（`docs/user/troubleshooting.md` と英語の版）、ADR を直した。

### 採らなかった案

- 環境変数 `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1` を実行に付ける案。手元の Claude Code 2.1.322 で、`run_in_background` を省いても担当が同期になることを確かめた（小さな依頼で 1 回）。コマンドの背景の実行も使えなくなり、長い検証を背景で動かした実行（記録で 22 件）への影響を確かめきれないので、採らなかった（ADR）。

## 確かめたこと

### 直した後のスキルで、同じ種類の依頼を実際に実行した

- このブランチをビルドし、一時の `SACTY_HOME`・別のポート（4797・4798）で起動した。動いている sacty には触れていない。
- 文書作成の工程（セルフレビューをさせる工程）のタスクを、同じ依頼（会議室の予約の重複を防ぐ要求要件の文書。リポジトリ無し）で 4 件作った。Claude Code（2.1.318。`claude_advanced`）が 3 件、Codex（`codex_standard`）が 1 件。
- Claude Code の 3 件の結果（セッションログと、親のセッションの記録の両方で数えた）。

  | 実行 | 担当の起動 | `run_in_background: false` | 背景になった起動 | 起動を含む発言の数 | 待つ間の発言・ツール | 通知の形の文面 | 番の数 | 費用 |
  | --- | --- | --- | --- | --- | --- | --- | --- | --- |
  | 1 | 16 | 16 | 0 | 5 | 0 | 0 | 37 | $3.94 |
  | 2 | 12 | 12 | 0 | 3 | 0 | 0 | 29 | $2.75 |
  | 3 | 15 | 15 | 0 | 5 | 0 | 0 | 33 | $3.49 |

  - 3 件とも、初回の担当 9 つを 1 つの発言でまとめて起動し、すべての結果を起動のツールの結果として受け取った。
  - `result` の出来事は、どの実行も 1 回（背景の通知で番が起き直す形にならなかった）。
  - 作業履歴に `SubagentNoticeImitated` は記録されなかった（文面が無いので、正しい）。
- Codex の 1 件の結果（セッションの記録 `rollout-*.jsonl` で数えた）。
  - 親は `spawn_agent` を 9 回続けて呼び、その後 `wait_agent` を 3 回呼んでから、最後の答えを書いた。起動と待ちの間に、ほかのツールの呼び出しは無い。
  - 待つためのツールの名前は `wait_agent` だった。スキルの記述を、これに合わせて直した。
- 確かめられなかったこと。
  - Codex は 1 回だけで、起きないと言える回数ではない。Codex の出力には通知のタグが無いので、sacty の検出は Codex には効かない。
  - 担当が背景になったときの待ち方（スキルの「担当が背景になったとき」）は、実物では 1 回も通っていない（背景にならなかったため）。
  - タグを使わずに「担当は指摘なしだった」と地の文で書く形は、検出できない。
  - 画面の作業履歴の行は、文言のテスト（`labels.test.ts`）で確かめた。実物の画面では出していない（実物の実行で文面が出なかったため）。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| 1 回目（提案）：コードブロックの境界の判定。4 つの空白で字下げした ``` を開始と扱うと後ろの通知を見逃す。ブロックの中の ```xml を終了と扱うと引用の中のタグを拾う。本文の区切りごとに状態を初期化すると、区切りをまたぐ引用を拾う | 直した。開く行は字下げが空白 3 つまで、閉じる行は同じ記号・同じ長さ以上で後ろに空白だけ、とした。1 つの発言の本文は、つないでから数える。それぞれのテストを足した |
| 1 回目（提案）：作業履歴の文言に、括弧書きの注釈と、確かめる理由が本文として入っている | 直した。本文は、起きたことと次にすることだけにし、仕組みと理由は、行を開いて読む詳細（補足のキー）に分けた |
| 2 回目（提案）：リストの中のコードブロックは、開く行が「- ```」の形なので開きを見分けられず、その中の字下げした `<system-reminder>` を数える | 直した。数えるのは、行の先頭（字下げなし）のタグだけにした（届ける文面も、見つかった 3 件の文面も、タグは行の先頭にある）。コードブロックを開く行は、リストの印・引用の印・字下げの後ろでも見分ける。その形のコードブロックは、字下げの無い行で終わる（1 回目の指摘の「開いたままにして後ろを見逃す」を戻さないため） |
| 2 回目（提案）：`TaskService` を使う作業履歴のテストを、決まりの配置先 `daemon-steps.test.ts` に移す | 移した（「工程の実行と費用」）。`imitated-notices.test.ts` には、数え方・出力の読み取り・コンテナの実行のテストを残した |
