# 今の実装の仕様書を docs/spec に書く

- 日付: 2026-10-14（UTC）
- タスク: PBI-82
- PR: #91
- ブランチ: feat/issue-82-spec-docs
- 関係する ADR: [docs を4種類に分け、実装の変更で直すのは仕様書とユーザードキュメントだけにする](../adr/20261014-0816-docs-structure-and-policy.md)

## 目的

PBI-80 で決めた方針（`docs/spec/README.md`）に従い、今の sacty がどう動くかを仕様書として書く。対象は、全体の構成・タスクと工程・
作業履歴・エージェントの実行・コンテキストの合成・ゲートウェイ・秘密情報・サービス・通知・チケットの取り込み・書き出し・デーモンの起動と終了。
書く内容はすべてコードで確かめ、主な節の終わりにコードの場所を付ける。確かめられないことは書かない。

## したこと

- `docs/spec/` に15の仕様書を足し、`docs/spec/README.md` の目次に並べた。
  - `architecture.md`・`daemon-lifecycle.md`・`configuration.md`
  - `tasks-and-steps.md`・`approval.md`・`split-and-integrate.md`
  - `event-log.md`・`agent-execution.md`・`context.md`・`gateway.md`・`secrets.md`
  - `services.md`・`notifications.md`・`intake.md`・`export.md`
- 1つの機能を変える PR で直すファイルがなるべく1つで済むよう、機能の単位で分けた。タスクと工程は量が多いので、承認と差し戻し、
  タスク分割と統合レビューを別のファイルにした。
- 調べ方：テーマごとに読み取り専用のサブエージェントでコードを調べ、その報告をもとに書いた。書いた記述は、定数・関数・分岐をコードで
  読み直して照合した（下の「確かめたこと」）。
- 利用者向けの手順（設定の書き方の例・コマンドの使い方）は書かず、ユーザードキュメントへのリンクにした。経緯は書いていない。

## 確かめたこと

- コードの参照：仕様書の「コード:」の行のファイルのパスがすべて存在し、括弧の中の関数・型・定数の名前がそのファイルにあることを、
  一時のスクリプトで確かめた（619 件、食い違い 0）。
- 記述の照合：定数の値（ポート・間隔・上限・既定値）、`STEP_PLANS`・`allowedPlans`・工程の分類、ロックの方式、`dockerRunArgs` の引数、
  認証方式ごとの環境変数、ゲートウェイのパスとリトライ、セッションログの上限、停止の確認の回数、書き出し・質問の条件などを、コードを
  読み直して照合した。
- 未確認として書かなかったこと：コンテナを compose のネットワークにつながないときのネットワーク（Docker の既定に任せていて、コードでは
  決めていない）、MCP の SDK の既定の時間切れ、外部の API（Slack・JIRA・GitHub）の実際の応え方、画面の細部。
- `npm run lint`（終了コード 0）・`npm run typecheck`（0）・`npm run build`（0）：通った。
- `npx vitest run tests/docs`：59 件通った。
- `npx vitest run`：既定の並列数では、負荷で時間切れになる無関係のテスト（セッションログ・出力の中継の大きな入力のもの、5件）が
  失敗した。`--maxWorkers=2` で実行し直すと、49 ファイル・1163 件すべて通った。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| セルフレビュー：リポジトリの無いタスクになる条件を「対象がリポジトリ1つだけではない」とだけ書いていて、`repo: null` の指定と、対象が無いプロジェクトでは作れないことが抜けていた | `createTask` を読み直して書き直した |
| セルフレビュー：要求要件・設計の PR を作り直す条件を「ベースから進んだら」とだけ書いていて、PR がマージ済み・閉じられたときと、PR を作れないときの扱いが抜けていた | `publishStepPullRequest` を読み直して書き直した |
| セルフレビュー：ゲートウェイのリトライの上限に達した後を「利用上限として扱う」と書いていたが、コードで確かめられなかった | 確かめられたこと（応答を返し、その後のエージェントの失敗は出力の文で分ける）だけにした |

## 残したこと

- コードのコメントと振る舞いの食い違いを見つけた（`chooseSteps`・`extractStepPlan` のコメントは「判断できなければ標準の工程」だが、実際は
  一時停止する。工程ごとの費用の表は `TicketTriaged`・`RepositoryChosen` の費用を集計していないが、タスクの費用には入る）。仕様書には実際の
  振る舞いを書いた。コードの直しはこのタスクではしない。
