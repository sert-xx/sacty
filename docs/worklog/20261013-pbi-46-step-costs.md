# タスクの詳細で、工程ごとのエージェント・設定・費用を見られる

- 日付: 2026-10-13（UTC）
- タスク: PBI-46
- PR: #52
- ブランチ: feat/issue-46-step-costs
- 関係する ADR: [作業履歴に工程ごとの接続先・モデル・リーズニングエフォートを任意で記録し、タスクの詳細に工程ごとの費用を出す](../adr/20261013-0057-step-costs-and-agent-settings.md)

## 目的

タスクの詳細で、どの工程をどのエージェントがどの設定で動かし、いくらかかったのかを見られるようにする。

## したこと

- 画面（`apps/web/src/components/step-costs.tsx`・`apps/web/src/lib/step-costs.ts`・`apps/web/src/app/tasks/[id]/page.tsx`）：タスクの詳細に「工程ごとの費用」の表を足した。
  - 行は、オーケストレーター（工程の選択）→ タスクの工程 → ゴールガーディアン（判定・最終レビュー）。工程の名前の下に、エージェント・接続先・モデル・リーズニングエフォートを小さく出す
    （列を増やさず、詳細の左の列の幅に収める）。
  - 列は、トークンの使用量（入力・出力・キャッシュの読み / 書き）・費用・実行の回数。同じ工程を複数回動かしたときは回数と合計を出し、「各回の内訳」（日時・設定・使用量・費用・結果）を折りたたんで出す。
  - タスクの合計（上部の「費用」と一致）と、子タスクを持つタスクは子タスクの合計（子タスクの一覧と同じ値）を出す。換算した費用（サブスクリプションなど）には「概算」を添え、
    記録の無い項目（以前のタスクのモデル・エフォートなど）は「—」と出す。
  - ゴールガーディアンの行は PBI の記載には無いが、その費用もタスクの予算に入るので、合計を一致させるために足した。
- 作業履歴（`packages/core/src/events.ts`・`apps/daemon/src/service.ts`・`apps/daemon/src/config.ts`）：実行の開始・工程の選択・ゴールガーディアンの記録に、接続先・モデル・リーズニングエフォートを
  任意の項目として足した。以前の作業履歴もそのまま読める。API キーなどの秘密の値は記録しない。モデル・エフォートは、config.yaml のエージェントに書いた場合だけ記録する。
- 表をタスクの詳細の幅に収めた。
- ゴールガーディアンの実行の失敗・中断を、工程ごとの費用で「完了」と出さないようにした（レビューの指摘）。

## 確かめたこと

- build・typecheck・lint・test（460件）が通った。
- 集計のユニットテスト：合計とタスクの費用の一致、複数回の実行と内訳、オーケストレーター・ゴールガーディアンの行、以前の形の作業履歴。
- daemon のテスト：工程・オーケストレーターの AI の設定が記録され、書いていない設定と秘密情報の名前は記録されないこと。
- 追加したテストは、実装を戻すと失敗することを確かめた。
- 画面は動画で確かめた（一時的なデータの環境）。
- 再レビューで、全469テスト・`npm run lint`・`npm run typecheck` が通った。ブラウザ上の描画と実際の AI の実行は、レビューでは未確認。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| ChangeJudged・ReworkJudged は実行の失敗（認証・接続の誤りなど）や中断のときにも記録されるのに、内訳で無条件に「完了」と出していた。判断不能と実行の失敗を区別し、古い記録でも成功と断定しないでほしい | ChangeJudged・ReworkJudged に、ゴールガーディアンの実行の結果 `runResult`（completed：実行できた（判断できなかった場合も含む）、failed：実行に失敗、interrupted：デーモンの停止で中断）を任意の項目として足し、daemon で記録するようにした。集計は `runResult` で完了・失敗・中断に分け、`runResult` の無い以前の記録は sacty が書いた理由の文言（`run.guardianFailed`・`run.guardianInterrupted`）で判別する。集計と daemon の回帰テストを足し、戻すと失敗することを確かめた |
