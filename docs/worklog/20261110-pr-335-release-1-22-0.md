# 版を 1.22.0 に上げる

- 日付: 2026-11-10（UTC）
- タスク: なし
- PR: #335
- ブランチ: feat/release-1-22-0
- 関係する ADR: [版は 1.0.0 から semver で付け、タグと GitHub Releases でリリースする](../adr/20261019-2345-semver-releases.md)

## 目的

1.21.0 の後に入った変更（PR #334）をリリースする。`npm run cli:install` と `sacty --version` は機能の追加なので MINOR を上げる。

## 1.21.0 からの変更

- どのディレクトリでも `sacty` を使えるように、`npm link` で入れる `npm run cli:install` を足した。`sacty --version` も足した（PR #334）。

## 互換性の判断

- 設定ファイルの形・既存のコマンドの引数・作業履歴・HTTP API に、互換性の無い変更は無い。`npx sacty` はこれまでどおりリポジトリの中で使える。
- 新しい種類のイベントは無いので、1.21.0 に戻しても作業履歴は読める。

## したこと

- 5 つのパッケージとワークスペースの依存の版を `1.22.0` にし、`package-lock.json` を `npm install --package-lock-only` で作り直した（差分は版の行だけ。`jiti` の依存の範囲 `>=1.21.0` は外部のパッケージのもので、変えていない）。
- 既定のイメージの名前（`DEFAULT_IMAGE`）を `sacty-agent:1.22.0` にした。
  同じ版にしたもの：仕様書（`agent-execution`・`configuration`）とユーザードキュメント（`config`・`images`）の日英、イメージの名前を書いているテスト・コメント、ゲートウェイの MCP クライアントの版の文字列。
  直したファイルは、1.21.0 の版上げ（PR #333）と同じ範囲。
- 元のイメージのダイジェスト：`docker buildx imagetools inspect node:26-bookworm-slim` の `Digest` が `Dockerfile` の値（`sha256:add5c17c…`）と同じだったので、変えていない。
- エージェントの CLI の版（`packages/cli/docker/agent-cli`）は変えていない。

## 確かめたこと

- `npm run lint`・`npm run typecheck`：通過。
- `npx vitest run --no-file-parallelism`（`tests/docs` を含む）：通過（件数は PR の本文に書く）。
- `git grep -F 1.21.0` で、ADR・作業履歴・外部の依存の範囲のほかに `1.21.0` が残っていないことを確かめた。
- PR #334 で確かめていなかった macOS で、npm のグローバルの場所（`npm_config_prefix`）を一時ディレクトリに向けて `scripts/cli-install.mjs` を実行した（この Mac のグローバルの設定は変えていない）。
  - `PATH` に無いとき：PATH に無い注意を出して終了コード 0。
  - `PATH` にあるとき：`sacty 1.22.0 を入れました` を出して終了コード 0。
  - `PATH` で先に別の `sacty` があるとき：先に見つかる注意を出して入れる。
  - リポジトリの外のディレクトリで、リンクした `sacty --version` が `1.22.0` を出した。作業ツリーに変更は残らなかった。
  - 初めは UUID を含む一時ディレクトリで試し、「このリポジトリを指していません（ありません）」で止まった。npm が出力の中の UUID の形の文字列を `***` に伏せるため、`npm prefix -g` の結果が実在しないパスになっていた。npm のグローバルの場所に UUID が入ることは普通は無いので、この PR では直していない。
- `Dockerfile`・`agent-cli` は変えていないので、イメージのビルドはやり直していない。

## レビューの指摘と対応

- なし。

## 残したこと

- PR をマージした後の、タグ `v1.22.0` と GitHub Release の作成。
- npm のグローバルの場所のパスに UUID の形の文字列が入っていると、`npm run cli:install` が誤って失敗する（`npm prefix -g` の出力が伏せられるため）。
