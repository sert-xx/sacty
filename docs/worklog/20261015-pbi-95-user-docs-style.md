# ユーザードキュメントをです・ます調にし、書き方の規則を docs/user から外す

- 日付: 2026-10-15（UTC）
- タスク: PBI-95
- PR: #104
- ブランチ: feat/issue-95-user-docs-style
- 関係する ADR: [ユーザードキュメントはです・ます調にし、その書き方の規則は docs/README.md に置く](../adr/20261015-0017-user-docs-polite-style-and-rules-location.md)

## 目的

docs/user は利用者がそのまま読むページなので、本文をです・ます調にする。あわせて、ユーザードキュメントの書き方・分け方・
ひな形などの開発者向けの規則を、利用者向けのページ（`docs/user/README.md`）から外す。

## したこと

- `docs/user/` の15ページの本文を、です・ます調にした。見出し・表の短い項目・コードブロック（中のコメントを含む）は変えていない。
  見出しを変えていないので、ページの間のアンカーのリンクはそのまま。手順・設定の名前・既定値・例は変えていない。
  - `tasks.md`：「工程の選択と、コードや仕組みを読んで説明する調査では、開発のセットアップを実行しない」の箇条が、
    テンプレート「Sacty セットアップ」の節の API の段落の後ろに紛れていた（PBI-90 で節を差し込んだときにずれたとみられる）ので、
    元の「タスクを作る」の箇条の最後に戻した。中身は変えていない。
  - `images.md`：`env` の名前の説明を、コード（`apps/daemon/src/config.ts` の `^[A-Z_][A-Z0-9_]*$`）に合わせ、
    「英大文字か `_` で始まる」を足した（数字で始まる名前は受け付けない）。
- `docs/user/README.md` を、利用者向けの概要と目次だけにした（「ファイルの分け方」「書き方の規則」「ひな形」と、方針への案内を外した）。
- 外した規則を、`docs/README.md` の「ユーザードキュメント（user/）」の下の「ユーザードキュメントの書き方」に移し、
  「本文はです・ます調で書く」を足した。冒頭の「規則は各ディレクトリの README.md に書く」に、ユーザードキュメントだけは例外で
  ここに書くことを書き足した。
- docs の方針のスキル（`.claude/skills/sacty-docs/SKILL.md`・`.agents/skills/sacty-docs/SKILL.md`）で、ユーザードキュメントの規則の
  正本を `docs/README.md` の節にし、PR の前に確かめることに、です・ます調と、開発者向けのことを docs/user に書かないことを足した。
  2つの写しは同じ中身のまま。
- ADR を足した。PBI-80 の ADR（docs の構成と方針）の「ファイル名の規則とひな形は各ディレクトリの README.md に書く」のうち、
  ユーザードキュメントの部分を置き換えるので、古い ADR を `20261014-0816-superseded-docs-structure-and-policy.md` に変え、
  ステータスと置き換えの関係を直し、古い名前へのリンク（`docs/README.md`・PBI-80〜82 の作業履歴）を直した。
- `tests/docs/docs.test.ts` に、`docs/README.md` に「ユーザードキュメントの書き方」の節とです・ます調の規則があり、
  `docs/user/README.md` に規則の見出し（ファイルの分け方・書き方の規則・ひな形）が無いことの検査を足した。

## 確かめたこと

- 書き直しの前後の差分を、語の単位（`git diff --word-diff`）で1ページずつ見直し、変わったのが文末の言い方だけであること
  （設定の名前・既定値・数値・例・リンクが変わっていないこと）を確かめた。上の2か所（箇条の移動・`env` の名前）は意図した変更。
- 15ページの記述（設定の項目・既定値・CLI のオプション・制約）をコードと照合した。食い違いは `images.md` の `env` の名前だけ
  （上で直した）。書かれていない制約として、`reasoning_effort` の長さの上限（31文字）・JIRA のキーの長さと数の上限（50）があるが、
  食い違いではないので足していない。
- 本文の「。」の前が、です・ます（〜ます・〜です・〜ください など）で終わっているかを、コードブロック・表・見出しを除いて機械的に
  調べ、残りが括弧の中の補足や名詞の列挙だけであることを見た。
- 足した検査は、`docs/user/README.md` を変更の前に戻すと落ちる（1件）。
- `npm run lint`（終了コード0）・`npm run typecheck`・`npx vitest run`（57ファイル・1372件が通過）・`npm run build`・
  `npx vitest run tests/docs`（67件が通過）。
- 画面とコードの変更は無いので、動作確認の動画は撮っていない。

## わからないこと・確かめていないこと

- 表の中の説明（「確かめること」の列など）は、文になっているものだけをです・ます調にし、短い項目は体言止めのまま残した。
  どこまでを文とみなすかは判断による。
- 括弧の中の補足の一部（「（〜しない）」など）は常体のまま残っている。
