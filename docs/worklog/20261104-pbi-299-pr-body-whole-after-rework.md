# 作り直しの後の PR の本文を PR 全体の説明にし、「人が確かめること」を重複させない

- 日付: 2026-11-04（UTC）
- タスク: PBI-299
- PR: なし

## 目的

実験 S5 r4（F44）で、2回作り直した最後の PR の本文が、最後の直しだけを説明していた（機能全体の説明・観点表のテスト 18 件から 3 件が消えた）。「人が確かめること」は、回ごとに言い換えられた「この環境だけの結果」で5件中3件が実質重複した。

受け入れ条件の要点：作り直しの後の本文は PR 全体の説明にし、最後の直しは分けて読める。「人が確かめること」は回をまたいで同じ趣旨を1件にする（#296 の「根拠なしに落とさない」を弱めない）。作り直しが無いタスクの本文は変えない。テストで確かめ、docs を直す。

## したこと

- `packages/core/src/projection.ts`：`Task.implementHistory`（実装の提出ごとの出力。10 件まで。上流の承認・上流の成果物を変える申し出の適用で空に戻す）を足した。直しの提出の `testMap` は、今回の申告に出てくる観点に、前の提出までのテストを残して足す（`mergeTestMaps`）。
- `packages/core/src/events.ts`：`FinalReviewed` に `mergedHumanChecks` を足した。
- `apps/daemon/src/prompts.ts`
  - 実装の指示（前の説明を添えるとき）に、説明を PR 全体にすること・「## 最後の直し」の節に分けること・テストの対応を全体にすることを足した（`implementReworkLines`）。
  - 本文（`buildPullRequestBodyText`・`buildPullRequestBodyParts`）は、`implementDescription` で説明を全体と最後の直しに分け、結論の1行と「最後の直し」の節を足した。節を書かなかった提出は、前の全体の説明を土台にする。
  - 最終レビューの指示に `updatedHumanChecks` を足し、`extractFinalReview` で、書き直しの置き換え・同じ見出し「この環境だけの結果」の1件化・書き方だけが違う項目の1件化をして、`mergedHumanChecks` に記録する。
- 仕様書（`approval`・`tasks-and-steps`、日英）・ユーザードキュメント（`tasks`、日英）・ADR を直した。

## レビューの指摘と対応（自分で悪魔の代弁者として確かめた）

| 指摘 | 対応 |
| --- | --- |
| 書き方の比べ方で記号まで消すと、版の番号やパスだけが違う別の項目を同じとして落とす（#296 違反） | 全角半角・空白・大文字小文字・文末の句点だけを除く比べ方にした。テストあり |
| 最初の提出に「最後の直し」の節があると、機能全体が節に飲まれる | 前の提出が無いときは、節があっても説明を変えない。テストあり |
| 履歴の最後が現在の説明と食い違う（人が直したなど） | 現在の説明を最後の直しとして扱い、落とさない。テストあり |
| 秘密の値が前の提出の説明に残る | 本文を作る前の置換（`hideSecrets`）が履歴にも掛かる。テストあり |
| 履歴が際限なく大きくなる | 10 件までにした。テストあり |

## 残した制限

- 書き直しが元の趣旨を保つかは確かめない（元の文は `mergedHumanChecks` に残る）。
- 削除・改名したテストの前の名前が、観点とテストの対応に残りうる。
- 節を書かない提出が続くと、途中の直しの説明は本文に出ない。
- `StepCompleted` による履歴の空への戻りは、テストで直接確かめていない。
