# 終わったタスクと、中断された実行の作業領域を片付ける

- 日付: 2026-10-26（UTC）
- タスク: PBI-157
- PR: なし
- ブランチ: claude/zealous-ramanujan-8u53bn
- 関係する ADR: [完了したタスクの作業領域は、もう使わなくなった時点で消し、中断で残った一時領域は起動時に消す](../adr/20261026-0022-retire-finished-task-workspaces.md)

## 目的

`SACTY_HOME/workspaces` が使い続けると十数 GB まで増えていた。残り続けていたのは、次の2種類。

- 中断で残った実行ごとの一時領域（`_guardian`・`_snapshots`・`_review` など）
- 完了したタスクの作業領域と、退避した git のメタデータ

受け入れ条件の要点は次のとおり。

- 起動時に、動いている実行のものでない一時領域を消す。
- 完了したタスクは、もう使わなくなった時点で消す（監査をするタスクは監査の後）。すでに残っているものも、起動時に同じ基準で消す。
- 完了の後に作業領域を使う操作は、作業領域が無くても動く。
- 消すのは ID の形の名前だけにし、リンクはたどらない。コンテナが動いている場所は消さない。
- 作業履歴・`sessions/`・`memory/`・DB は消さない。
- 消せなくても、起動とタスクの進行を止めない。

## したこと

- `apps/daemon/src/workspace-cleanup.ts` を足した。
  - `RUN_SCRATCH_DIRS`：実行ごとの一時領域の名前。PBI に挙がった5つに、同じ作りの `_deployment`・`_export`・`_handoff`・`_question-logs` を足した。
  - `workspaceRetirable`：完了したタスクが、もう作業領域を使わないか。
  - `isSactyId`・`idEntries`：UUID の形の名前だけを選ぶ。根がリンクなら読まない。
  - `removeEntry`：リンクはリンクだけを消す。
  - `overlapsMounts`：マウントされている場所との重なりを見る。
  - `runningContainerMounts`：`docker ps -q` と `docker inspect` で、動いているコンテナのマウントの元を取る。上限は 15 秒で、失敗したら undefined。
- `TaskService` に、次の3つを足した。
  - `retireWorkspace`：完了したタスクの作業領域を消す。
    - 呼ぶのは、使わなくなった追記のとき・`runNext` の終わり・質問への答えの終わり。
    - 実行・質問の答え・中止の途中なら消さない。
    - Docker への問い合わせの後に、条件を確かめ直してから消す。
    - 消している間は `retiring` に Promise を持ち、`prepareRepository` などが待つ。
    - 大きな作業領域でもイベントループを止めないよう、非同期の `rm` で消す。
  - `cleanupWorkspacesAtStartup`：起動時に、一時領域と、もう使わない・どのタスクのものでもない作業領域を消す。
  - `workspaceMissing`：`runGuardian`（質問への答えなど、コードの写しを渡す実行）の前に、消した作業領域を `prepareRepository` で用意し直す。
    作業中のタスクの振る舞いを変えないよう、完了したタスクに限った。
- 中止：完了の後に作業領域を消したタスクは、sacty のブランチを消すために、退避した git のメタデータを用意し直す。
- 作業領域と退避した git のメタデータは、片方がマウントされていれば両方残す（片方だけ残すと、次の準備で両方を作り直すことになるため）。
- `main.ts`：`containerMounts` を渡し、`recoverInterrupted` の後・ワーカーを始める前に `cleanupWorkspacesAtStartup` を待つ。
- 仕様書を直した（日英）。
  - [タスクと工程](../spec/tasks-and-steps.md#終わったタスクの作業領域の片付け)：節を足した。
  - [デーモンの起動と終了](../spec/daemon-lifecycle.md#デーモンの起動の順序)：起動の順序に、手順を足した。
  - [アーキテクチャ](../spec/architecture.md)：`workspaces/` の行を直した。
- ユーザードキュメント：[はじめに](../user/getting-started.md)の「データの置き場所」に、作業領域を自分で消すことを書いた（日英）。

## 確かめたこと

- `npm run lint`：問題なし。
- `npm run typecheck`：問題なし。
- `npx vitest run`：2717 件が通り、8 件が失敗した。
  - 失敗した 8 件は、この変更の前（`git stash` した状態）でも同じに失敗する。
  - 内訳は `host-mcp-processes`（実際のプロセスのシグナル）・`agent-sessions` と `context-mcp`（root で動かしていて、権限で読めないファイルを作れない）・`question-form.browser`（Playwright のブラウザが無い）。
  - この環境の都合で、変更とは関係ない。
- 回帰テスト：`apps/daemon/src/daemon.test.ts` の「終わったタスクと、中断された実行の作業領域の片付け（PBI-157）」に 8 件を足した。
  - 監査しないタスクは、完了で消す。
  - 監査するタスクは、監査が終わるまで残す。
  - 完了していないタスクと、マウントされているものは残す。Docker に問い合わせられなければ残す。
  - 質問への答えで、同じ起点で用意し直してから、また消す。
  - 起動時に一時領域・リンク・どのタスクのものでもないものを消し、ID の形でない名前・`_cache`・`runs/`・完了していないタスクの作業領域は残す。
  - 起動時に、マウントされている実行・停止を確かめられなかった実行の一時領域は残す。
  - このリリースより前に完了したタスクの作業領域を、起動時に消す。
  - 消せなくても続ける。
- `workspace-cleanup.test.ts`（部品）と、`instance-lock.test.ts`（起動の順序）にも足した。
- 修正を戻すとテストが失敗することを確かめた。
  - 消す処理を止めると、5 件が失敗した。
  - 用意し直す処理を止めると、質問の 1 件が失敗した。
- `npx vitest run tests/docs`：通った。

## 残したこと

- 完了したタスクの中止で、退避した git のメタデータを用意し直す処理は、直接のテストを足していない。sacty のブランチを持つ完了したタスクを作る手順が長いため。
- 作業履歴（`runs/`）の保持期間は、範囲外。
