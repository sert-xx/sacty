# エージェントをコンテナで実行し、費用を記録して予算で止める

- 日付: 2026-10-10（UTC）
- タスク: PBI-2
- PR: #2
- ブランチ: feat/issue-2-agent-container
- 関係する ADR: [エージェントはアダプターを介してタスク専用のコンテナで実行し、選んだ認証方式の秘密情報だけを渡して、台帳に書く前に取り除く](../adr/20261010-0705-agent-container-execution.md)、[実行ごとの費用をトークン数と設定の単価で台帳に記録し、予算・利用上限・認証エラーでは失敗にせず一時停止する](../adr/20261010-0705-cost-budget-pause.md)

## 目的

工程をタスク専用のコンテナで実行し、トークン数から費用を計算して台帳に記録する。予算・利用上限・認証エラーでは一時停止し、
画面から再開できるようにする。認証方式を AI の定義ごとに選べること、選んだ方式の変数だけをコンテナに渡すこと、秘密情報を
キーチェーンに置いて台帳・ログ・画面・コマンドラインに出さないことも受け入れ条件。範囲は要求要件の工程の下書きを実行して
記録するところまでで、承認ゲートと設計以降の工程は PBI-7 以降に回した。

## したこと

- アダプターと実行（`apps/daemon/src/agents/`）：Claude Code・Codex・スタブの呼び出しの組み立て（`invocation.ts`）、出力の読み取り（`parse.ts`）、
  コンテナでの実行（`docker.ts`）、秘密情報の除去（`redact.ts`）。
- 設定と秘密情報：`apps/daemon/src/config.ts`、`apps/daemon/src/secrets.ts`。CLI に `sacty config init`・`sacty secret set`・`sacty image build` を足した
  （イメージは `packages/cli/docker/Dockerfile`）。
- 費用と予算：`packages/core/src/cost.ts`、台帳のイベントと復元（`packages/core/src/events.ts`・`projection.ts`）、実行のキュー（`apps/daemon/src/worker.ts`）。
- 画面：費用のメーター、再開のフォーム（`apps/web/src/components/resume-form.tsx`）、実行中の自動更新（`apps/web/src/components/auto-refresh.tsx`）。
- デーモンを止めて中断された実行は、再起動の時に失敗として記録して一時停止にする。

## 確かめたこと

- `npm test`（46件）・`npm run lint`・`npm run typecheck` が通った。
- まっさらな複製で `npm install` → `npm run build` → `sacty config init` → `sacty image build` が通った。
- イメージの中に Claude Code 2.1.296 と Codex 0.160.0 があり、root 以外（node）で動くことを確かめた。
- スタブのエージェントで、画面から次を確かめた。
  - チケットの作成 → コンテナで実行 → 下書きと費用（換算値）と台帳の記録が出る。
  - 予算 $0.01 で上限に達して一時停止 → 使用済み以下の上限はエラー → $1.25 で再開。
  - 利用上限のエラーで一時停止（エラーの文を表示）→ 再開すると工程を実行し直して完了。
- 実行の後にコンテナが残らないこと、キーチェーンに無い秘密情報は認証エラーとして止まることを確かめた。
- 本物の認証情報での実行は、費用や利用枠を使うため確かめていない（PR の本文に、利用者が確かめる手順を書いた）。
- レビューは、一時 DB・ダミーの認証値・偽の docker コマンドで指摘を再現した。最後の再レビューでは `npm test`（55件）・`npm run lint`・
  `npm run typecheck` が通った。本物の Docker と CLI での認証の実行、ブラウザでの表示、クリーンな環境での全体のビルドは確かめていない。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| 実行中に Ctrl+C・SIGTERM を受けると、コンテナを止める命令を出しただけで終了し、認証ファイルの書き戻しと一時ファイルの削除が終わらない | 新しい実行を止め、コンテナを止めたうえで、実行中の処理（書き戻し・一時ファイルの削除・台帳への記録）を待ってから、サーバーと台帳を閉じて終了するようにした（上限 20 秒）。中断した実行は一時停止として記録する。CLI の強制終了までの猶予を 5 秒から 30 秒にした。偽の docker で、中断しても書き戻しと削除が終わるテストを足した |
| エージェントの出力・エラー文を、渡した秘密情報を取り除かずに台帳へ保存している | 実行に渡した秘密情報を控え、成功の出力・失敗の文言・例外の文言のどれも、台帳に書く前に `[REDACTED]` に置き換えるようにした。Codex の認証ファイルのトークン類も対象にし、8文字未満の値は対象外にした。3つの経路のテストを足した |
| 失敗した実行では費用を足した直後に一時停止するので、80% の通知を判定しない | 失敗でも費用を足して一時停止を記録した後に通知を判定するようにした。1回の実行で 80% 未満から上限を超えたときも、通知を記録してから止めるようにした |
| 再レビュー：キューが空のときに処理が同期的に終わり、「実行中」の印が残って、以降の実行がすべて止まる（前の修正で入った回帰） | 処理を変数に受けてから代入し、印を外すのは処理の完了の後で、自分が残っているときだけにした。空のキューの後に作ったチケット・再開したタスクが実行される回帰テストを足し、修正を戻すと失敗することを確かめた。`sacty up` でも確かめた |
| 再レビュー：コンテナの中で更新されたトークンは除去の対象に入っていない | ステージした認証ファイルの値を実行の前と、実行の後（書き戻しの前）に控え、両方を出力・エラー文から取り除くようにした。偽の docker で更新したトークンを出力させるテストを足した |

## 残したこと

- 本物の認証情報での実行（`claude setup-token` → `sacty secret set` → `sacty config init` → `sacty up`）の確認は、利用者の手に回した。
- 承認ゲートと設計以降の工程は、PBI-7 以降。
