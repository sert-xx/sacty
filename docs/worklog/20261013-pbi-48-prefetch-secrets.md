# sacty up の起動時に、使う秘密情報をまとめて取り出す（1Password の認証を1回にする）

- 日付: 2026-10-13（UTC）
- タスク: PBI-48
- PR: #56
- ブランチ: feat/issue-48-prefetch-secrets
- 関係する ADR: [sacty up の起動時に、使う秘密情報をまとめて取り出してから、タスクの実行と取り込みを始める](../adr/20261013-0354-superseded-prefetch-secrets-at-startup.md)

## 目的

タスクを作って動き始めたときに 1Password の認証を求められていた。`sacty up` の起動時に、使う秘密情報をまとめて取り出し、1Password の認証を起動のときの1回だけにする。

## したこと

- `apps/daemon/src/secret-uses.ts`（新規）：設定とプロジェクトで使う秘密情報の参照を集める。
  - 対象：使うエージェント（既定・ゴールガーディアン・工程ごと）の認証、providers の API キー、外部の PF（プラットフォーム）の認証、ホストで動かす MCP サーバーの秘密情報、プロジェクトの通知先（Slack のトークン・Webhook）。
  - 対象外：イメージの作成だけで使う npm のトークン、gh から取る GitHub のトークン、コンテキストリポジトリの mcp.yaml の秘密情報（取得しないとわからないため。使うときに取り出す）。
- `apps/daemon/src/secrets.ts`：1Password の参照は、1回の `op run --no-masking --env-file <参照のファイル> -- node -e …` で取り出す。
  - 参照のファイルには参照だけを書き（本人だけが読める）、終わったら消す。値は子のプロセスの環境変数で受け渡し、コマンドラインにもファイルにも出さない。取り出した値は、これまでどおりデーモンのメモリーだけに持つ。
  - まとめて取り出せなかった（参照の誤り・サインインしていないなど）ときは、参照ごとに取り出し直して、取り出せなかったものを特定する。
  - キーチェーンの秘密情報は、取り出せるかを確かめる（使うたびに取り出すので、`sacty secret set` で変えた値はすぐに使われる）。
- `apps/daemon/src/main.ts`：秘密情報を取り出し終えてから、タスクの実行と取り込み、外部の PF の認証の用意、ホストの MCP サーバーの起動を始める。サーバーは先に起動する。
- 取り出せなかったものは、起動を止めずに、画面の警告と端末に「どの設定か」と理由を出す（値は出さない）。
- 「sacty の設定」に「秘密情報」を足し、「秘密情報を取り出し直す」で、持っている値を捨てて取り出し直せる（`apps/web/src/components/secrets-section.tsx`）。
- 参照が1つも無い設定では、これまでどおり何も聞かずに起動する。起動の後に増えた参照は、使うときに取り出す（これまでどおり）。
- README に説明を足した。

## 確かめたこと

- build・typecheck・lint・全テスト（520件）が通った。
- 追加したテスト：
  - 偽の op（PATH に置いた sh。`op run` で参照を値にして環境変数で渡し、`--` の後のコマンドを動かす）で、1回の `op run` で取り出し、使うときに op を呼ばないこと。参照のファイルが消えること、空白を含む値、アカウントの指定。
  - まとめて取り出せないときに参照ごとに取り出し直し、取り出せなかった参照と理由を返すこと。
  - 取り出し直し（持っている値を捨てる）、キーチェーンの確かめ、参照が無ければ op を呼ばないこと。
  - 集める参照（エージェント・providers・PF・MCP・通知先、npm のトークンとゲートウェイのトークンは含めない、重ねない）。
  - 取り出せなかったものが画面の警告に出て、取り出し直すと消えること（値は出ない）。
- 主な判定を戻すと、テストが失敗することを確かめた（6通り）。
- 画面と端末の警告は動画で確かめた（一時的な設定。存在しないキーチェーンの名前を書いた）。
- 開発した環境には 1Password のアカウントが無いため、偽の op で開発した。実際の 1Password のアカウントで認証が1回になることは未確認。
- 再レビューで、全521テスト・lint・型チェックが通った。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| まとめて取り出す前に、ホストの MCP サーバーの起動と外部の PF の認証の用意を始めていたので、個別の取り出しが先に起き、1回の `op run` にまとまらない。さらに、取り出し中の参照を待たずに成功として戻っていた | ホストの MCP サーバーの起動と外部の PF の認証の用意を、まとめて取り出した後（タスクの実行・取り込みを始めるのと同じところ）に移した。サーバーの待ち受けはこれまでどおり先に起動する。すでに取り出し中・取り出し済みの参照は、その結果を待ってから戻り、失敗なら取り出せなかったものとして返すようにした。回帰テストを足し、待つ処理を外すと失敗することを確かめた |
| `forEach` の式形式のコールバックが値を返すので、リポジトリの lint（`useIterableCallbackReturn`）が失敗する | `for … of` で `cache.set()` を呼ぶ形にした。直す前の版で lint のエラーが出て、直した版で出ないことを確かめた。リポジトリの中にある作業用の worktree の biome.json のために `npm run lint` がそのままでは動かず、範囲を指定した確認で見落としていたので、以後は対象のディレクトリを直接 lint して確かめることにした |

## 残したこと

- 1Password のアカウントのある環境で、次を確かめる（PR で依頼した）：1Password の参照を複数書いた config.yaml で `npx sacty up` を実行し、認証を1回だけ求められること。
  端末に「秘密情報を取り出しました（n/n 件）」と出ること。タスクを作って動かしても認証を求められないこと。
  1Password からサインアウトして起動すると警告が出て起動はし、サインインしてから「秘密情報を取り出し直す」を押すと警告が消えること。
