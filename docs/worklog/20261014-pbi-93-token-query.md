# ゲートウェイのトークンの取得で、キーをクエリのパラメーターで送る PF に対応する

- 日付: 2026-10-14（UTC）
- タスク: PBI-93
- PR: #101
- ブランチ: feat/issue-93-token-query
- 関係する ADR: なし

## 目的

`GET /auth/token?api_token=<キー>` のように、キーを URL のクエリで送ってトークン（JWT）を受け取る PF を、`gateway.platforms`
とコンテキストの `platforms.yaml` に書いて使えるようにする。これまでの `auth.token` は `{{secret}}` をヘッダー・JSON・フォームに
しか入れられなかった。キーの入った URL は、ログ・作業履歴・画面・エラーの文・エージェントへの応答のどこにも出さない。

## したこと

- `apps/daemon/src/platforms.ts`
  - `TokenRequest` に `query`（`名前: 値`。値の `{{secret}}` をキーにする）を足した。
  - 検査を足した：`query` の名前が空・値が文字列でない（`config.platformTokenQuery`）、`url` に `{{secret}}` を書いた
    （`config.platformTokenUrlSecret`。`query` に書くよう案内する）、`method` が `GET`・`HEAD` なのに `json`・`form` を書いた
    （`config.platformTokenBody`。送るたびに失敗する書き方なので、読み込みのときに弾く）。`url` が http・https の検査は保った。
    文言は `packages/core/src/messages.ts` に日本語・英語で足した。
  - `tokenUrl`：`query` を URL エンコードして、`url` に元からあるクエリの後ろに足す（元のクエリは書き換えない。`#` 以降は
    送らない）。エンコードは `encodeURIComponent` に加えて `!'()*` も変える（URL の組み立てで `'` が `%27` に変わるなど、
    送る形と伏せる形が食い違わないようにするため）。`query` が無い・空なら `url` をそのまま使う（今の設定の動作は変わらない）。
  - `hideSecret`：伏せる形に、URL エンコードした形（上のエンコード・`encodeURIComponent`・16進の小文字・フォームの形）を足した。
    トークンの取得の失敗の理由は、これまでどおり伏せてから切り詰める。`hideSecret` はほかの所（ホストの MCP・通知・
    チケット）でも使うので、URL エンコードできない値（対になっていないサロゲート。`encodeURIComponent` が例外を投げる）でも
    失敗しないようにした（DA の検証で見つけた）。
- 仕様書 `docs/spec/gateway.md`（検査・URL の組み立て・伏せる形）、ユーザードキュメント `docs/user/gateway.md`（例・項目の表・
  キーを出さないこと）を直した。

## 確かめたこと

- テストを足した。
  - `apps/daemon/src/platforms.test.ts`：設定の検査（日本語・英語の文。POST ならクエリと本文を一緒に書ける）、
    `config.yaml` の `gateway.platforms` で読めること・誤りの項目の場所、GET でエンコードしたクエリで送り本文と `content-type` を
    付けないこと（送った URL を読み直すと元のキーに戻る）、期限・取り直し・捨てて取り直し、元からあるクエリとの組み合わせ・`#`・
    `?` だけの URL・クエリが無いとき、送信の失敗の文に URL が入る場合・窓口のエラーの本文に URL を写す場合（大文字・小文字の16進・
    フォームの形）と切り詰めの境界（0・560・580・595 文字の前置き）でキーを出さないこと。
  - `apps/daemon/src/gateway.test.ts`：クエリで送る窓口の PF をゲートウェイ経由で呼び、401 で取り直して送り直す。PF への転送の
    URL にキーを付けない。取り直しの送信の失敗（文に URL が入る）でも、エージェントへの 502 の応答にキーを出さない。
  - `apps/daemon/src/context.test.ts`：コンテキストの `platforms.yaml` で `query` を読めること、3つの誤りを層と項目の場所付きで弾くこと。
- 修正を戻すと落ちること：送る URL を `spec.url` に戻す（3件落ちる）、厳しいエンコードを `encodeURIComponent` に戻す（3件）、
  `hideSecret` に足した4つの形を1つずつ外す（それぞれ1件）・まとめて外す（2件）、GET の本文の検査・`url` の `{{secret}}` の
  検査を外す（それぞれ2件）。
- 本物の Node の fetch（ビルドした `dist`）で、閉じたポートと引けないホストの窓口に送ると、理由は `fetch failed` だけで、URL・キーは
  出なかった（`cause` は伝えない）。
- `npm run lint`（終了コード0）・`npm run typecheck`・`npx vitest run`（53ファイル・1244件が通過）・`npm run build`・
  `npx vitest run tests/docs`（66件が通過）。
- 画面の変更は無い（設定と、画面に出す理由の文の中身だけ）ので、動作確認の動画は撮っていない。

## わからないこと・確かめていないこと

- 本物のクエリで送る PF の窓口には繋いでいない（偽の窓口で確かめた）。
- 窓口がリダイレクトを返したときに、リダイレクト先の URL にキーが入る場合（窓口が決めること）。トークンの取得のリダイレクトの扱いは、
  これまでと同じ（fetch の既定でたどる）。

## レビューの指摘と対応

PR #101 のレビュー（2件。どちらも P2）。

1. パーセントエスケープの16進の大文字・小文字が箇所ごとに混ざると（`FAKE%2ba%2Fb`）、列挙した形のどれにも合わず伏せられない。
   - 対応：決まった形を並べるのをやめ、`urlPattern` で、文字ごとに「そのまま」か「UTF-8 のパーセントエスケープ（16進の大文字・小文字を
     問わず、`%25` の二重のエンコードも）」か（空白は `+` も）を受け付ける正規表現にした。エスケープの箇所ごとに違っても伏せる。
     DA の検証で、空白の `+` と `%20` の混在・一部だけエスケープ・二重のエンコード・エンコードしなくてよい文字のエスケープ（`%46`）・
     非 ASCII のバイトごとの混在も見て、テストに入れた。URL の形は各行より先に置き換える（行を先に伏せると、エンコードした形の残りが
     出るため）。
2. 1〜3文字のキーは、長さの絞り込みで伏せる候補からすべて外れる。
   - 対応：クエリの値の全体がキー（上の形）のとき（`?名前=値`・`&名前=値`。後ろが文の終わり・`&`・`#`・空白・引用符など）は、
     長さに関係なく伏せる。ほかの所の短い文字列一般は、これまでどおり置き換えない（値の一部・クエリの外の `abc` は残る）。
     DA の検証で、名前の部分を長さの上限なしで読むと、`?` が並ぶ長い文で遅くなる（20万文字で約40秒）ことを見つけ、名前は
     `?` を含まない256文字までにした（テストは2秒未満を確かめる）。
- 確かめたこと：
  - 修正の前の `platforms.ts` に戻すと、足した2件のテストが落ちる。
  - クエリの値の伏せを外す（1件）、16進の大文字・小文字を区別する（3件）、二重のエンコードを外す（1件）、名前の上限を外す
    （1件。40秒かかって落ちる）と、それぞれ落ちる。
  - main（PR #95・#98 を含む）を取り込んだ。ぶつかりは無かった。
  - `npm run lint`（終了コード0）・`npm run typecheck`・`npx vitest run`・`npm run build`・`npx vitest run tests/docs`。
- 伏せられない形として残るもの：クエリの値の一部だけが短いキーのとき（`pre-abc`）、JSON の文字列にした形の中の URL エンコード、
  キーの文字ごとの大文字・小文字の違い（キーそのものが変わるため）。

PR #101 の再レビュー（1件。P2）：短いキーの漏れが2通り残る。(1) `?api_token=abc: forbidden` のように値の後ろが `:` だと、終わりの
判定の列挙に無いので伏せない。(2) `query: { api_token: "pre-{{secret}}" }` で送った `pre-abc` は、値の全体がキーではなく、4文字未満の
除外にも当たるので伏せない（上の「残るもの」の1つ目）。

- 対応：
  - 値の終わりの判定を、区切りの列挙から「値を続けられる文字（英数字・`-._~`・`%`・`+`）でなければ何でも区切り」に変えた
    （否定の先読み）。
  - トークンの取得の理由では、送ったクエリの値のうちキーを入れたもの（置き換えた後の値）も、キーと同じ規則
    （`hideSecret`。値の全体がクエリの値なら長さに関係なく、4文字以上ならどこでも、URL の書き方の違いも含めて）で、長いものから伏せる
    （`sentQueryValues`）。キーを入れていない値（`v=1` など）は伏せない。
  - これで上の「残るもの」の1つ目（`pre-abc`）は、送った値の丸ごとでは伏せる。ただし、窓口が値の一部だけを写す場合（`pre-` を
    落として `abc` だけ、など）で、それがクエリの値の全体でも4文字以上でもないときは、まだ伏せない。
- 確かめたこと：
  - DA の検証として、区切り `:`・`: forbidden`・`)`・`]`・`,`・`;`・`\n`・`\r\n`・タブ・引用符・`/`・`|`・`!`・`}`・`*`・`&x=1`・`#f`・
    文の終わりを、そのまま・エスケープ・16進の大文字・小文字・二重のエンコード・`+` と `%20` の値と組み合わせた。
  - 値を続ける文字（`d`・`-`・`.`・`_`・`~`・`%41`・`+`）が後ろにあれば、別の値として伏せないことも確かめた。
  - 送った値 `pre-abc` の後ろが `: forbidden`・`)`・改行・`,`・`-more`・文の終わりの場合と、エスケープした形（`pre%2Dabc`・`%70re-abc`）を、
    窓口の 403 の本文から理由と画面の文まで確かめた。
  - 修正の前の版（a100979）に戻すと足した2件が落ちる。送った値を伏せる処理だけを外すと1件落ちる。
  - 長い文の性能のテスト（2秒未満）は保った。
  - main（PR #96 を含む）を取り込んだ。ぶつかりは無かった。
  - `npm run lint`（終了コード0）・`npm run typecheck`・`npx vitest run`・`npm run build`・`npx vitest run tests/docs`。

PR #101 の再々レビュー（1件。P2）：窓口が短いキーを名前付きで本文に返す（403 の本文が `invalid api_token=abc`）と、`?`・`&` の後ろでも
4文字以上でもないので伏せない。同じ種類の指摘が続いたので、形を足していくのをやめ、今回で終わる形にした。

- 決めたこと：`query` の値にキー（`{{secret}}`）を入れた窓口が失敗（2xx 以外）を返したときは、本文を理由に写さず、状態コードだけに
  する（`sendsKeyInQuery`）。送った名前の後ろの値を伏せる案（`=`・`:`・空白・引用符・JSON を問わず）も考えたが、窓口は名前を変えたり
  （`key abc is not valid`）、値だけを返したりもしうるので、形を数えて伏せる限り、また漏れが残る。本文を写さなければ、本文の
  どんな形の写しも出ない。代わりに、利用者は失敗の理由の本文を画面で見られなくなる（状態コードは出る。ユーザードキュメントに書いた）。
  キーを本文・ヘッダーで送る窓口は、これまでどおり本文を伏せて写す。
- 残る形（仕様書に書いた）：送信の失敗の文（fetch の例外の文）で、短いキーや短い送った値が、クエリの値の全体ではない形で現れる
  とき（Node の fetch の失敗の文は `fetch failed` で URL を含まないことを、前に本物の fetch で確かめた）。キーを本文・ヘッダーで送る窓口の
  失敗の本文の、短いキー（これまでどおり）。
- 確かめたこと：
  - 本文が `invalid api_token=abc`・`{"error":"invalid","api_token":"abc"}`・`api_token: abc`・`key abc is not valid`・切り詰めの
    境界をまたぐものの、どれでも、理由は状態コードだけになり、画面の文に `abc` が出ないことを確かめた。`pre-{{secret}}` のときも
    同じになることを確かめた。キーをヘッダーで送る窓口は、これまでどおり本文を伏せて写すことも確かめた。
  - 本文を写さない処理を外すと、足したテストが落ちる。
  - 前の2回の指摘（`pre-abc`・短いキーの値）のテストのうち、窓口の本文で確かめていたものを、送信の失敗の文（URL を含む）で確かめる
    ように変えた（本文はもう写さないため）。
  - main を取り込んだ。ぶつかりは無かった。
  - `npm run lint`（終了コード0）・`npm run typecheck`・`npx vitest run`・`npm run build`・`npx vitest run tests/docs`。
