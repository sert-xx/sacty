# 実時間の経過に上限・下限を置くテストを、時間に頼らない検査に直す

- 日付: 2026-11-22（UTC）
- タスク: PBI-473
- PR: #553
- ブランチ: sacty/task-8da97908
- 関係する ADR: なし

## 目的

テストの中に、かかった実時間に上限・下限を置いて合否を決める検査があり、CI の機械が遅いと本体が正しくても落ちる（2026-11-19 の main の CI では、600ms 未満の検査が 612ms で落ちた）。
こうした検査を、偽の時計・止めた理由・状態・入力の大きさで確かめる形に直し、遅い機械でも落ちないようにする。直した後も、元の検査が確かめていたこと（固まらない・期限で止まる・線形の時間で終わる）は確かめ続ける。
本体（テストでないコード）は変えない（時計・期限の差し込み口も足していない）。

### 検査に数えない一致

洗い出しの検索に当たるが、実時間の経過に上限・下限を置いて合否を決めていないもの。

- `testing/wait.test.ts` の `testTimeLeftMs()`：計算した値への上限で、経過時間を測っていない
- `github.test.ts` の `githubRetryAfterMs`（590,000 より大きいこと）：`Date.now()` から 600 秒後のリセットとの差で、遅くなるほど通りやすい
- 固定の待ち（`setTimeout(r, 20〜300)` で「まだ待っている」ことを見るもの）：経過時間を測っていない
- `vi.waitFor` の期限（既定 1 秒など。14 ファイル）と、`testing/wait.ts` の `waitFor` の `timeoutMs`、`host-mcp.test.ts`・`context-mcp.test.ts` の自前の待ちの期限（`Date.now() + ms`）：条件を待つ期限で、経過時間を測っていない。含めると別の範囲（65 か所と 11 ファイル）になるため含めない
- `Date.now()` を時刻の値として使うもの（`links.test.ts` の `ago`・`dashboard-attention.browser.test.ts`・`daemon-deployment-security.test.ts` と `daemon-implement.test.ts` の `now:`・`github.test.ts` のリセット時刻・`replyPostTimes` の記録）：経過の上限・下限の判定ではない
- `audit-causes.test.ts`・`daemon-audit-bulk.test.ts` の `performance.now()` と `elapsed`：かかった時間を `console.info` に出すだけで、合否に使わない
- `task-mcp-wait.test.ts` の `clock.t`・`daemon-projects-intake.test.ts` の `elapsed`：偽の時計の値
- Vitest のテストの時間切れ（`timeout:`・既定 5 秒）：検査に数えない

`Promise.race` と `setTimeout` の組み合わせは、直した後のテストに残っていない。
