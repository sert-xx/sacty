# タスクの詳細を、上に固定した見出し・タブ・右の列のプロパティで組み直す

- 日付: 2026-10-28（UTC）
- タスク: なし
- PR: #250
- ブランチ: claude/nifty-lamport-oxt41x
- 関係する ADR: [タスクの詳細を、上に固定した見出し・タブ・右の列のプロパティで組む](../adr/20261028-1533-task-detail-tabs-and-properties.md)

## 目的

タスクの詳細は、多くの欄を1列に縦に並べていて（縦 2,200〜3,100px）、承認の判断に要る成果物やよく行う操作がスクロールした先にあった。
証跡・監査を人が確かめやすくするため、表示している情報とできる操作を洗い出し、見る頻度で置き場所を分けて組み直す。
試作を撮って方向を確かめてから、仕上げた。

## したこと

- 洗い出し：題・状態・メタ情報・費用・承認や判断の案内・再開・中止の片付け・工程の欄（理由・ベースブランチ・テスト・書き出し先・イメージ・エージェント）・
  監査・作業の実行設定・内容・集めた情報・工程ごとの成果物・PR・セキュリティ対応・続きのタスク・マージの後の監視・変更の申し出・
  工程ごとの費用・オーケストレーターのセッション・作業履歴と、一時停止・中止・再開・再レビュー・再実行・工程の設定の変更・書き出し直し・
  続きのタスクの作成・質問の操作。
- `apps/web/src/components/task-detail.tsx`
  - 題・状態・工程・操作・タブを上に固定し、承認・判断・再開の案内（`GateNotice`・`ResumeForm`）をタブの下に出す。
  - タブ（概要・作業履歴・費用・工程の設定・監査）。`?tab=` に残し、`#event-<ID>` なら作業履歴を開く。隠したタブも描いておく（`TabPanel`）。
  - 成果物を工程ごとに1つずつ出す（`Deliverables`・`currentStep`）。
  - 右の列のプロパティ（`Properties`）と最近の作業履歴（`ActivityList` の `compact`）。
  - 申し出の無い「変更の申し出と判定」と、まだ始まっていないマージの後の監視は出さない。
- `apps/web/src/components/card-section.tsx`：1つずつ出すときに折りたたまない（`ExpandCards`）。
- `apps/web/src/i18n/messages/task.ts`：タブ・プロパティなどの文言（`layout`。日英）。
- docs：仕様（アーキテクチャの「タスクの詳細の並び」、工程の欄・監査の欄の読み替え）、ユーザードキュメント（「タスクの詳細の見方」、参照先の修正）、ADR。
- スクリーンショット：`task-detail` を足し、`task-costs` は費用のタブで撮る。タスクの詳細の画像を撮り直した（ほかの画面の画像は変えていない）。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| [要修正] 監査の一覧の `#audit` と、判断の案内の `#proposals` でも、要素のあるタブを開く（初めに開いたときと、同じ画面の中の操作の両方） | ハッシュの要素が隠したタブ・成果物の工程にあれば、そのタブ・工程を開いてから移る（`revealHash`。パネルに `data-tab`・`data-step`）。jsdom で `#audit`・`#proposals`・`#event-` を確かめるテストを足した（`task-detail-tabs.test.ts`） |
| [要修正] 工程の無い古いタスクでも、監視の記録（`task.deployment`）があれば監視の結果を出す | まだ始まっていない監視を隠す条件と、記録がある監視を出す条件を分けた。テストを足した |
| [提案] `?tab=` は、出しているタブかで確かめる | 出していないタブの指定は概要にする（表示の時にも、出しているタブに無ければ概要にする） |
| [提案] 表示のタブと成果物の工程のタブを、矢印キーで移れるようにする | 左右の矢印キー・Home・End で移り、フォーカスも移す。選んだタブだけをフォーカスの順に入れる（`moveTab`） |
| [提案] 成果物のタブとパネルを結び付ける | タブに `id`・`aria-controls`、パネルに `role="tabpanel"`・`id`・`aria-labelledby` を付けた |
| [提案] 監査のタブの条件を実装に合わせる（未監査の完了タスクにも出る） | 実装のまま、docs を「完了したタスクだけ。まだ監査していなければ、その旨」に直した（ユーザードキュメント・仕様・ADR。日英） |
| [提案] 「詳細の先頭」に出るとしていた元のレポート・テンプレート・続きの元・修正の元を、プロパティの項目名に合わせる | ユーザードキュメントと仕様（tasks-and-steps・deployment-watch）を、プロパティの項目名で書き直した（日英） |
| [要修正]（2回目）`#100%` のような不正なハッシュで開くと、`decodeURIComponent` が例外を投げて読み込みに失敗する | 復号できないハッシュは無いものとして扱い、ふつうに表示する。テストを足し、実ブラウザーでも確かめた |
| （2回目）前回の `#proposals` が一部未対応：費用のタブから「判断する」を押しても、概要が隠れたまま | 「判断する」は `next/link` で、同じ画面の中の移動は `history.pushState` なので `hashchange` が起きなかった。同じ画面へのハッシュ付きのリンクのクリックも拾い、押したリンクのハッシュで開く（`useRevealHash`）。テストを足し、実ブラウザーで、費用のタブから同じ画面へのリンクを押すとそのタブを開いて要素が画面に入ることを確かめた |
| [提案]（2回目）パネルを開いてから移る順序もテストで確かめる | テストの `requestAnimationFrame` をためて描き直しの後に動かし、`scrollIntoView` を呼んだときに要素を含むパネルが見えていることを確かめる。移る処理を同期にすると落ちることを確かめた |
| [提案]（3回目）隠れた成果物の工程へのリンクもテストで確かめる | 費用のタブから、選んでいない工程（`#deliverable-requirements`）へのリンクを押し、概要と工程の両方が開いて、移るときに要素を含むパネルがすべて見えていることを確かめるテストを足した。成果物の側の `useRevealHash` を外すと落ちることを確かめた |

## 残したこと

- 中止をヘッダーに出したままにするか、メニューにしまうかは決めていない。
- 作業履歴の種類での絞り込み（人の判断だけなど）は足していない。
