# 観点ごとの担当を起動しなかった PR のレビューを、採らずにやり直させる

- 日付: 2026-11-17（UTC）
- タスク: PBI-379
- PR: #420
- ブランチ: feat/pbi-379-review-viewpoints
- 関係する ADR: [観点ごとの担当を 1 件も起動しなかった PR のレビューは、採らずにやり直させ、続いたら止める](../adr/20261117-1015-reject-reviews-that-start-no-reviewers.md)

## 目的

PR のレビューが、既定のスキルの決まり（観点ごとの担当を起動して見る）を守らずに、親が自分で差分を読んで判定を出す実行が続いていた。
担当を起動しなかったレビューは、「修正が必要」を 1 回も出していなかった。

受け入れ条件の要点は、次のとおり（この PR は、PR のレビューの分。工程の中の自己レビューは、別の PR にする）。

- 担当を起動するよう、指示と既定のスキルを直す。既定のスキルに、特定のエージェントの製品に寄せた記述を書かない。
- sacty が、レビューの実行ごとに、起動した担当の数を記録する。数えられないときは、やり直しにしない。
- 担当を 1 件も起動しなかった回は、判定を採らず、PR に投稿せず、やり直させる。やり直しは 3 回まで。それでも起動しなければ、一時停止して人に知らせる。担当を起動する手段が無い環境（逐次モード）は、今までどおり通す。
- 投稿する本文とタスクの画面に、レビューしたエージェント・起動した担当の数・切り替え先で動いたことを出す。

## したこと

### なぜ担当を起動しないのかの見立て

実行の記録（担当を 1 件も起動しなかった回と、十数件起動した回）の、親のセッションの流れを見比べた。

- どちらも、最初にスキル `review-dispatch` を読み込んでいる（`SKILL.md` の全文が渡っている）。
- 担当を起動した回は、その後に流れの資料（`references/pr-review.md`）と観点カタログを開き、検証を実行し、担当を起動している。
- 担当を起動しなかった回は、資料を開かず、差分の周りのコードを数回読んで、本文を書いている。本文には「担当に分けずに自分で見た」「見落としの可能性は、分けたときより高い」と書いている。
- 決まりを知らないのではなく、省いて、そのことを申告している。なぜ省くのかは、記録からは分からなかった（考えた過程が残っていない）。

見立ては 2 つ。指示が、進める順と省けないことを言っていなかったこと（出力の形を詳しく決め、差分をそのまま渡し、「観点をどう見たかを 1 行で書く」が、分けない見方も選べるように読める）。省いても何も起きなかったこと。

### 指示とスキル

- `apps/daemon/src/prompts.ts`：レビューの指示に、進める順と、省けないこと、sacty が担当の数を数えてやり直させることを足した（`REVIEW_DISPATCH_LINES`）。前の実行が担当を起動しなかったときは、指示の先頭にそのことを足す（`reviewUndispatchedLines`）。
- `apps/daemon/default-context/skills/review/review-dispatch/SKILL.md`：役割の表のすぐ後に、次に読む資料を名指しし、親が担当を起動せずに終えるのはスキルに従ったレビューではないと書いた。
- `references/pr-review.md`：担当に分けずに親が自分で見る、という見方は無いこと、再レビューでも、結果が揃う前に本文を書き始めないことを書いた。

### 数え方

- `apps/daemon/src/review-dispatch-count.ts`（`countReviewDispatch`）：実行の後に、写したエージェントのセッションのファイルから、起動した担当の数を数える。
  - Claude Code：親のセッションの `Agent`・`Task` の呼び出し（呼び出しの ID で重複を除く）と、担当ごとのセッションのファイルの数の、多い方。
  - Codex：先頭の `session_meta` の `source` が `exec` の rollout（親）の中の `spawn_agent` の呼び出し。
  - 数えられないとき（ファイルが無い・親が無い・上限で間を省いたファイルで 0 件・知らない種類）は、分からない。
  - 担当を起動する手段があったかは、Claude Code は実行の出力の最初の出来事の `tools`、Codex は親の `turn_context` の `multi_agent_version` で確かめる。

### やり直しと一時停止

- `apps/daemon/src/service.ts`（`runNextInner`）：レビューの実行が完了した後、数を数える。手段があったのに 0 件なら、`AgentRunFailed`（`reviewDispatch` 付き）を記録して、止めずに実行待ちに戻す。やり直し 3 回の後も 0 件なら、`TaskPaused`（`review.notDispatchedPaused`）で止める。
- `packages/core/src/events.ts`：`ReviewDispatch`（`subagents`・`model`・`configuredAgentId`）を、`AgentRunCompleted` と `AgentRunFailed` に任意の項目として足した。これより前の記録には無い（無いまま読める）。
- `packages/core/src/projection.ts`：タスクに `reviewDispatch`（最新のレビューの実行の記録）と `reviewUndispatched`（採らなかった実行の数）を持たせた。人が再開すると、やり直しの回数だけを数え直す。
- 一時停止の理由は、新しい種類を足さず、`error` と文言（`review.notDispatchedPaused`）にした。レビューが止まったときの PR への知らせは、今の仕組みがそのまま働く。

### 表示

- `buildReviewBody`（`reviewDispatchLines`）：投稿する本文の最後に、レビューしたエージェント（モデル）、切り替え先で実行したこと、起動した担当の数を書く。
- `apps/web/src/components/task-detail.tsx`・`apps/web/src/i18n/messages/task.ts`：タスクの詳細のレビューの工程に、同じ内容と、採らなかった実行の数を出す（日英）。

## 確かめたこと

- `npx vitest run apps/daemon/src/review-dispatch-count.test.ts`：数え方（Claude Code・Codex・数えられないとき・手段を確かめられないとき・シンボリックリンク）。10 件が通過。記録の形だけを写した、架空の内容で確かめた。
- `npx vitest run apps/daemon/src/daemon-review-dispatch.test.ts`：0 件の実行を採らずにやり直す・3 回のやり直しの後に止まる・再開でもう一度試す・手段を確かめられない実行は通す・数えられない実行は通す・切り替え先で動いた回の記録と本文。5 件が通過。
  - やり直しの判定を無効にすると、このうち 2 件（やり直す・止まる）が落ちることを確かめてから、戻した。
- `npx vitest run apps/daemon/src/prompts.test.ts apps/daemon/src/default-skills.test.ts`：指示とスキルの文面。通過。
- `npx biome check --error-on-warnings .`：指摘なし。`npm run typecheck`：通過。`npx vitest run --no-file-parallelism`（全件）：260 ファイル・5025 件が通過（1 件は元から飛ばしている）。`npm run build`：通過。
- タスクの画面の表示（レビューしたエージェントと担当の数の行）は、型検査と文言のテストで確かめた。画面を開いての確かめは、していない。
- 実物（別のポート・一時のホームで起動した sacty で、マージ済みの PR を、投稿を偽の応答で受けてレビューさせる）では、確かめられなかった。一時のホームでデーモンを起動する所まで進めたが、そのデーモンの API を呼ぶ操作が、作業した環境の権限の判定で止められた（起動したデーモンは止めた）。このため、直した指示とスキルで、実際に担当が起動されるようになるかは、未確認。やり直しと一時停止（担当を起動しない回を採らないこと）は、テストで確かめた。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| （自分で見直した）上限で間を省いた目印の名前が、指示に入った差分の文字列にあるだけで「間を省いた」と扱い、0 件の実行を「分からない」として通してしまう | 目印の行を JSON として読み、種類が目印のときだけ「間を省いた」と扱うようにした。テストを足した |
| （自分で見直した）再レビューの始まりで、採らなかった実行の数を消す行が、実際には働かない（再レビューは、レビューが採られた後にしか始まらない） | 消した |

## 残したこと

- 工程の中の自己レビュー（要求要件・設計・実装・文書作成など）の、担当の起動の記録とやり直しは、別の PR にする。
- 実物での確かめ（差分の小さい PR・大きい PR・再レビュー）。
- 起動が 1 件だけのレビュー（数だけ合わせたもの）は、見分けない。必須の観点が揃っているかも、判定しない（[ADR](../adr/20261117-1015-reject-reviews-that-start-no-reviewers.md) の理由）。
