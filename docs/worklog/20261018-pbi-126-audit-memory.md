# 監査が教訓をメモリーに登録し、工程のエージェントが必要な分だけ読む

- 日付: 2026-10-18（UTC）
- タスク: PBI-126
- PR: #136
- ブランチ: feat/issue-126-memory
- 関係する ADR: [監査が登録したメモリーを、作業履歴を正本にして、スキルの索引の形で書き出す](../adr/20261018-0130-audit-memory.md)

## 目的

監査で見つかった知見を、改修の PR を待たずに次のタスクのエージェントへ届ける。メモリーはプロジェクトとリポジトリの2階層で持ち、
登録するのは監査だけにする。

## したこと

- core：深掘りの結果の `memories`（`AuditMemoryRecord`）と、削除の `AuditMemoryDeleted`。タスクの監査の状態に `memories` を畳み込む。
  画面の形 `AuditMemory`。
- デーモン
  - `memory.ts`：階層の置き場所（`memory/projects/<ID>/`・`memory/repos/<ホスト>/<オーナー>/<名前>/`）、索引（`SKILL.md`）と中身
    （`references/<ID>.md`）の書き出し、件数の上限、起動のときの書き直し。
  - 深掘りの指示に、既存のメモリーと登録の決まりを入れ、出力の `memories` を読む（重複・宛先・長さの検査）。
  - 工程（統合レビューを除く）・手直し・監査の実行に、タスクのプロジェクトと対象リポジトリの階層を読み取り専用でマウントし、
    工程には読み方を指示する。
  - 人の削除（`POST /api/audits/memories/:id/delete`）。
  - 既定のスキル `memory`。
- 画面：監査の欄に、登録したメモリーと「消す」（確定してから消す）。作業履歴の行の文言。
- docs：仕様書（メモリー・監査・全体の構成・エージェントの実行・コンテキスト）、ユーザードキュメント（監査）、ADR。

## 確かめたこと

- `npx biome check`・`npm run typecheck`・`npx vitest run`・`npm run build` が通った。
- 次の修正を戻すと、テストが落ちることを確かめた：プロジェクトの階層のマウント、統合レビューに渡さない、件数の上限、削除の後の書き出し、
  書き出す場所が無いときに登録しない、監査に読み方の指示を足さない、記録の無い階層の削除、sameAs の重複の除外、対象リポジトリが無い
  ときのリポジトリのメモリーの除外、パスを外れる名前のハッシュ。
