# 調査・要求要件・設計の承認した成果を、オーケストレーターが工程ごとに決めた書き出し先に書き出す

- 日付: 2026-10-13（UTC）
- タスク: PBI-56
- PR: #65
- ブランチ: feat/issue-56-export-outputs
- 関係する ADR: [調査・要求要件・設計の承認した成果は、オーケストレーターが工程ごとに決めた書き出し先に、利用者が用意した接続先だけで書き出す](../adr/20261013-1136-export-approved-outputs.md)

## 目的

調査・要求要件・設計の承認した成果を、Confluence・Notion などに書き出せるようにする。受け入れ条件の要点は次のとおり。

- オーケストレーターが工程ごとに書き出し先（書き出さないことも含む）と理由を決め、作業履歴と画面に出る。
- 承認した成果が書き出され、URL が作業履歴とタスクの詳細に出る。差し戻しの後に承認し直すと、同じ書き出し先が更新される。
- 書き出せないときは理由が残り、いまの仕様にフォールバックする。タスクは止まらず、書き出し直せる。
- ゲートウェイの接続先と MCP サーバーのどちらでも書き出せ、認証はコンテナ・作業履歴・ログ・画面に出ない。

## したこと

- 判断（`apps/daemon/src/prompts.ts`・`apps/daemon/src/context.ts`）：工程を選ぶとき、使える接続先とプロジェクトのコンテキストの規約を
  オーケストレーターに渡し、工程ごとの書き出し先と理由を決めさせる（`StepsChosen.exports`）。
- 書き出し（`apps/daemon/src/service.ts`・`apps/daemon/src/agents/invocation.ts`）：人が承認した後、次の工程や取り込み元へのコメントより先に、
  決めた接続先だけで書き出す。差し戻し後の承認し直しでは前のページを更新する。本文の目印でページを探す。一時停止・中止したら
  中断として費用だけ記録し、再開すると続ける。
- イベント（`packages/core/src/events.ts`・`packages/core/src/projection.ts`）：`ExportStarted`・`OutputExported`。
- 失敗：理由を記録して進める。画面から書き出し直せる（`POST /api/tasks/:id/exports/:step/retry`、`apps/web/src/components/export-retry-button.tsx`）。
- URL を添える先：取り込み元（Issue・JIRA）への調査の結果のコメント、チケットへの PR のコメント、PR の本文。
- 費用：タスクの費用に入れ、工程ごとの費用に「書き出し」として出す。
- 画面（`apps/web/src/app/tasks/[id]/page.tsx` ほか）：工程の欄に工程ごとの書き出し先と理由、成果の欄に書き出した URL・失敗の理由・
  書き出し直すボタン（承認済みで折りたたんだ欄の外にも出す）、作業履歴に決定・開始・結果。
- `README.md` に仕組みと `allow` の例。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| 結果を解析できなかった場合などにも開始の記録を消すので、書き出し直すと既存のページを探さず新しく作る指示になり、同じ成果を二重に作る | 前に書き出した URL が無いときは、始めた記録の有無にかかわらず、必ず置き場所で目印を含むページを探し、あれば更新・無ければ作ると指示するようにした。指摘と同じ流れのテストを足した |
| 書き出しで、選んでいない MCP も渡すので、無関係な接続先の認証の取得に失敗すると選んだ先への書き出しまで失敗し、無関係なツールも見える | MCP サーバーを決めた接続先の 1 つに絞り、生成する MCP の設定・ゲートウェイに中継させる MCP・取り出す認証のどれにもほかの MCP を含めないようにした。テストを足し、絞る処理を外すと落ちることを確かめた |

## 残したこと

- コンテキストがあるプロジェクトでは、工程の選択でもコンテキストを取得するので、少し遅くなる。
- Issue へのコメントの後に書き出し直した場合、Issue のコメントは更新しない。
- 予算の上限で書き出せなかった場合、予算を上げても自動では書き出さない（画面から書き出し直す。文言で案内している）。
