# 最終レビューの判定を読み取れないときに、不合格にしない

- 日付: 2026-11-02（UTC）
- タスク: PBI-277
- PR: なし
- ブランチ: feat/issue-277-unreadable-verdict
- 関係する ADR: なし

## 目的

実験のシナリオ S14 で、最終レビューが「出力から、判定を読み取れませんでした」で不合格になり、過去の指摘 14 件が全件「再発」扱いになった。内容の不合格ではないのに、実装を余分に 1 回走らせて合格した。
判定を読み取れなかったときは、不合格にも再発にも数えず、最終レビューを決まった回数まで出し直させ、それでも読めなければ一時停止して人に知らせる。

## したこと

- 原因の確認：S14 のタスクの実行の記録（最終レビュー 5 回分の出力）を読み直した。読み取れなかったのは 1 回で、出力は `sacty-final-review` の見出しを持つ JSON だったが、`viewpoints` の配列を閉じる `]` が抜けていて JSON として不正だった。囲み方や見出しの読み取りの不備ではなく、エージェントの出力の誤りなので、読み取りは緩めていない（緩めると、別の括弧の誤りを黙って補うことになる）。ほかの最終レビュー 33 回の出力は、すべて読めた。
- `extractFinalReview` が、判定のオブジェクトを読み取れなかったこと（`unreadable`）を返す。読めて判定が足りないだけのときは、これまでどおり不合格にする。
- 読み取れなかったときは、`FinalReviewed` を記録せず、`FinalReviewFailed`（`verdictUnreadable`）に費用と出力の場所（`runs/<タスク ID>/<実行 ID>.jsonl`）を記録し、最終レビューを出し直させる。`lastReview`・`verifyFailures` は変わらず、実装に戻らず、過去の指摘は再発と数えない。
- 続けて 3 回（`MAX_UNREADABLE_REVIEWS`）読み取れなければ、実装に戻さず一時停止する（理由 `error`、出力の場所を示す）。回数は `unreadableReviews` で数え、判定の記録・再開・前の工程からのやり直しで数え直す。
- 仕様書（日英）・ユーザードキュメント（日英）を直した。

## 確かめたこと

- S14 の実際の出力を `extractFinalReview` に通し、修正前は不合格（unreadable）になることを再現した。
- 追加したテスト：`daemon.test.ts`（1 回読めず出し直して合格・空の出力・3 回続けて止まり再開で数え直し・2 回読めず判定の後にまた 2 回でも止まらない・観点が足りないだけなら従来どおり不合格）、`projection.test.ts`（0・1・複数回の回数と、判定・再開での数え直し）、`agents.test.ts`（読めない出力と判定が足りない出力の区別）。`service.ts` の変更を戻すと daemon のテスト 4 件が落ちることを確かめた。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| projection のテストが lastReview 未設定・不合格0回の状態だけで、既存の判定や不合格回数を消す回帰を検出できない（Sacty のレビュー・提案） | 不合格の `FinalReviewed` → 次の実装完了 → 読み取れなかった回、の順に適用し、`lastReview`・`verifyFailures`・`verifyFeedback` が変わらないテストを足した。読み取れなかった回に `lastReview` と `verifyFailures` を消す変更を入れると、足したテストだけが落ちることを確かめた |

## 残したこと

- 統合レビュー（`integrate.unreadable`）・監査など、最終レビュー以外の判定の読み取れなかったときの扱いは変えていない。
- 出し直しの指示に、前回は形式が崩れていたことは伝えていない。
