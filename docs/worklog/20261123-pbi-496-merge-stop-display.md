# マージで止めた作り直しの表示を状態に合わせる

- 日付: 2026-11-23（UTC）
- タスク: PBI-496
- PR: なし
- ブランチ: main
- 関係する ADR: [前の工程へ戻した後も実装 PR のマージを承認にする](../adr/20261123-0038-implementation-merge-after-send-back.md)

## 目的

実装 PR のマージで作り直しを止めたとき、利用者が停止時の工程と状態、再開後の進み方を読み違えないようにする。

## したこと

停止前の状態を記録し、両方マージの追加の停止と再開を通じて最初の値を保持する。
過去の記録で特定できない状態は表示しない。
再開の説明の重複をなくし、工程 PR の番号を昇順にする。
承認にしなかったマージの知らせに失敗したときは、次に試せる時刻を警告に残し、待ち時間を最大 1 時間まで倍にする。

## 確かめたこと

日英の実画面の記録として、[日本語の動画](../sacty/2bd47317/videos/pbi-496-ja.webm)・[英語の動画](../sacty/2bd47317/videos/pbi-496-en.webm)を残した。
`npx vitest run apps/daemon/src/daemon-step-pull-requests.test.ts apps/web/src/components/live-screens.test.ts` は 386 件成功した。
今回の修正後の動画の撮り直しと画面の操作は行っていない。

## レビューの指摘と対応

### 設計のレビュー

過去の記録で工程を特定できない場合の主語を「直し」とし、停止前の状態を追加の停止と再開の後まで保持する。

### この PR の最初の提出

承認したマージの知らせの失敗には再試行時刻を出さず、状態を省く画面のテストを強めた。

## 残したこと

通知の失敗後、待ち時間の間にタスクが進むと再試行されない。進行後の再試行は後続対応の案とする。
