# マージで止めた作り直しの表示を状態に合わせる

- 日付: 2026-11-23（UTC）
- タスク: PBI-496
- PR: なし
- ブランチ: main
- 関係する ADR: [前の工程へ戻した後も実装 PR のマージを承認にする](../adr/20261123-0038-implementation-merge-after-send-back.md)

## 目的

実装 PR のマージで作り直しを止めたとき、利用者が停止時の工程と状態、再開後の進み方を読み違えないようにする。

## したこと

停止前の状態を記録し、両方マージの追加の停止と再開を通じて最初の値を保持する。
過去の記録で特定できない状態は表示しない。
再開の説明の重複をなくし、工程 PR の番号を昇順にする。
PR への知らせに失敗したときは、次回の試行時刻を警告に残し、待ち時間を最大 1 時間まで倍にする。

## 確かめたこと

日英の実画面を、偽の GitHub と保存済みのイベントを使って確認した。
両方マージの停止と、停止した行をそれぞれ [日本語の動画](../sacty/2bd47317/videos/pbi-496-ja.webm)・[英語の動画](../sacty/2bd47317/videos/pbi-496-en.webm) に残した。

| コマンド | 結果 |
| --- | --- |
| `npm run lint` | 成功 |
| `npm run typecheck` | 成功 |
| `npx vitest run tests/docs` | 99 件成功 |
| `npm test` | Git 2.46.4 で 7,270 件成功、実 AI を使う 1 件をスキップ |
| `npm run build` | 成功 |

再開説明、履歴の状態、番号の整列をそれぞれ一時的に戻すと、対応する画面テストが失敗した。
ビルド済みの `sacty up` を認証情報のない隔離環境で起動し、画面の説明とローカルのデータ取得に含まれる停止前の状態を確かめた。
全件テストには公式ソースからビルドした Git 2.46.4 を用い、標準の Git では全件を確かめていない。

## レビューの指摘と対応

### 設計のレビュー

過去の記録で工程を特定できない場合の主語を「直し」とし、停止前の状態を追加の停止と再開の後まで保持する。

まだ無い（最初の提出）。
