# git の時間切れのテストの不安定さを直す

- 日付: 2026-10-17（UTC）
- タスク: PBI-123
- PR: #133
- ブランチ: feat/issue-123-flaky-git-timeout-test
- 関係する ADR: なし

## 目的

テスト「上限の時間を過ぎたら、取得の git の子プロセスを止め、一時ディレクトリも残さない（PR #117 レビュー指摘）」が、全体のテストでときどき落ちる。
止める処理を確かめたまま、負荷にかかわらず通るようにする。

## 落ちる理由

- 全体のテストを2つ同時に流すと、2回とも落ちた（記録されたプロセス番号が0件）。
- 上限の時間のタイマーは、git の認証の準備より前に動き出す。
  負荷が高いと、準備と git（偽の git の sh）の起動だけで上限（1 秒）を使い切り、偽の git が最初の行を実行する前に、プロセスのグループごと止められていた。
- 実装のふるまいは正しく、テストが「1 秒のうちに git が動き出す」ことに頼っていたのが原因。

## したこと

- テスト（`daemon.test.ts`）：上限の時間のタイマーだけを捕まえ、偽の git と子プロセスが動き出したのを見届けてから時間切れにする。
  ほかのタイマー（`vi.waitFor` など）は実時間のまま使う。実装は変えていない。

## 確かめたこと

- `npx biome check`・`npm run typecheck`・`npx vitest run`・`npm run build` が通った。
- 全体のテストを2つ同時に流す負荷で3回（計6回）実行し、すべて通った（直す前は2回とも落ちた）。
- git を止める処理を外すと、このテストが落ちる（止める処理を確かめたまま）。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| テストの中の待ち（起動 10 秒・停止 5 秒）より、テスト全体の既定の時間切れ（5 秒）が短い | 待ちの時間を定数にし、テスト全体の時間切れを、待ちの合計に余裕（10 秒）を足した長さにした。中の待ちをわざと失敗させ、時間切れより先に中の失敗が報告されることを確かめた |
