# 版を 1.26.0 に上げる

- 日付: 2026-11-16（UTC）
- タスク: なし
- PR: #382
- ブランチ: feat/release-1-26-0
- 関係する ADR: [版は 1.0.0 から semver で付け、タグと GitHub Releases でリリースする](../adr/20261019-2345-semver-releases.md)

## 目的

1.25.0 の後に入った変更（PR #369〜#381）をリリースする。PR のレビューの子タスクの引き継ぎ（PR #373・#374・#379）、未完了の実装の扱い（PR #378・#381）、分割の子タスクのテスト観点（PR #380）、既定のレビューの段階（PR #370）、`writing` の文書と図の決まり（PR #372）は機能の追加なので MINOR を上げる。

## 1.25.0 からの変更

- ユーザードキュメントに、sacty の概要を図と画面で伝える紹介のページを足した（PR #369）。
- 既定のレビューの観点ごとの段階を下げ、expert も既定で使わない（PR #370）。
- スクリーンショットのデータを今の実装の流れに直し、ユーザードキュメントを読みやすく直した（PR #371）。
- 既定のスキル `writing` に後から読まれる文書と図・画像の決まりを足し、文書作成の工程でセルフレビューをさせる（PR #372）。
- PR のレビューの子タスクが、親タスクの集めた情報を引き継ぐ（PR #373）。
- PR のレビューの子タスクがレビューする工程では、提出の前のセルフレビューを省く（PR #374）。
- 終わっていない実装を提出にせず、変更の無いやり直しで行き止まりにしない（PR #378）。
- PR のレビューで親が担当に渡す範囲を差分で決め、観点をどう見たかを本文に書かせる（PR #379）。
- 分割の子タスクに、親の設計のテスト観点を割り当てる（PR #380）。
- 未完了で終わった実装の実行を、同じセッションの続きから進め、続きの上限を 10 回にする（PR #381）。

## 互換性の判断

- 設定ファイル：設定の形を決めるコードに差分は無い。
- 台帳：新しい種類のイベント（`GatheredInherited`・`ImplementationIncomplete`・`ImplementationUnchanged`）と、既存のイベントの省略できる項目（完了の申告・続きの理由・テスト観点）を足した。形を変えたものは無いので MAJOR にはしない。ただし、これらのイベントを記録した後に 1.25.0 に戻すと作業履歴を読めないので、リリースの説明の注意に書く。
- 既定のコンテキストのスキル（`review`・`writing`）と工程の指示が変わることを、リリースの説明の注意に書く。

## したこと

- 5 つのパッケージとワークスペースの依存の版を `1.26.0` にし、`package-lock.json` の版の行を直した。
- 既定のイメージの名前（`DEFAULT_IMAGE`）を `sacty-agent:1.26.0` にした。
  同じ版にしたもの：仕様書（`agent-execution`・`configuration`）とユーザードキュメント（`config`・`images`）の日英、イメージの名前を書いているテスト・コメント、ゲートウェイの MCP クライアントの版の文字列。
  直したファイルは、1.25.0 の版上げ（PR #368）と同じ範囲。置き換えは前後に数字・`.` が無い `1.25.0` だけにし、ADR・作業履歴は対象から外した。
- 元のイメージのダイジェスト：`docker buildx imagetools inspect node:26-bookworm-slim` の `Digest` は、`Dockerfile` に固定したもの（`sha256:5df79989…`）と同じだったので変えていない。1.25.0 の後に `packages/cli/docker` の変更は無い。
