## 目的

デーモンのテストの、処理の完了を固定の時間で待つ書き方を、条件を待つ形に置き換える（PBI-376）。背景・受け入れ条件・最初に数えた結果は、[1 つ目の作業履歴](20261117-pbi-376-fixed-waits-daemon-steps.md)にある。2 つ目は、[実装の工程のテスト](20261117-pbi-376-fixed-waits-daemon-implement.md)。

## したこと

5 つのファイルの 34 か所のうち、27 か所を置き換え、何も起きないことを見る 7 か所を、理由を書いて残した。本体のコードは変えていない。テストの期待値は変えていない。

置き換えた 27 か所：

- 後続に回したい案への決定の、PR へのコメントと Issue の作成の終わりを待っていた所（5 ミリ秒の `settled` のうち 18 か所）：待たずに送る処理が、すべて終わるまで待つ（2 つ目の PR で足した `noticesSettled`。この処理も、順に処理する仕組みに、同期で登録される）。
- Issue の作成が終わらない（止めてある）テストの 2 か所：Issue の作成が始まるまで待つ（偽の PR の操作に、始めた回数 `issueStarted` を足した）。
- 中断に応じないドラフトの切り替えの要求を、数えるのをやめる上限（テストでは 200 ミリ秒）が過ぎるのを待っていた 4 か所（上限 + 50 ミリ秒の固定の待ち）：終わっていない要求の数が、無くなるまで待つ（`apps/daemon/src/testing/daemon.ts` に足した `draftRequestsSettled`。`noticesSettled` と同じく、本体に待つ口が無いので、`TaskService` の private の表 `draftRequests` を直接見る）。上限そのものは、本物の時計で過ぎる。
- 届いた要求の続き・通知を送る処理の続きを、0 ミリ秒の待ちで待っていた 3 か所：イベントループを一巡させる（`loopTurn`）。

残した 7 か所（`idleFor`。時間は変えていない）と、その理由：

- `daemon-context.test.ts`（20・50・50・30 ミリ秒）：
  - 時間切れの後に返った取得で、`op` を呼んでいないこと。
  - 同じ内容で保存し直した後に、1Password に問い合わせていないこと。
  - プロジェクトを作った後に、1Password に問い合わせていないこと。
  - 承認を待っている間に、タスクが同じ参照に行き当たるまでの猶予（その間に、別に問い合わせていないことを、後の確認で見る）。
- `daemon-audit-memory.test.ts`（20・20 ミリ秒）：
  - 先の深掘りの間に、後の深掘りが始まっていないこと。
  - 後のタスクが、先の深掘りの後を待つ所まで進むための猶予。
- `daemon-orchestrator-sessions.test.ts`（50 ミリ秒）：1つ目の実行が終わる前に、同じタスクの 2つ目が始まっていないこと。

どれも、何も起きないことを見るための猶予か、処理が待つ所まで進むための猶予で、猶予が環境に対して短くても、テストは誤って落ちない（起きてはいけないことを見逃すか、確かめたい順番にならないまま通るだけ）。条件で待つ形にするには、本体に、待っている所を外から見る口が要る。

自分で決めたこと（人の確認は、まだ）：

- 処理が待つ所まで進むための猶予（`daemon-context.test.ts` の 30 ミリ秒・`daemon-audit-memory.test.ts` の 2 つ目の 20 ミリ秒）も、「短くても誤って落ちない」ので、何も起きないことを見る待ちと同じ扱いで残す。
- 負荷が高いと 5 秒の時間切れに当たるテスト（下の「確かめたこと」）は、固定の待ちの形ではないので、この PR では触っていない。
- `daemon-*.test.ts` のほかのデーモンのテストの 32 か所（1 つ目の作業履歴の数）は、この PBI の 3 つの PR では触っていない。
