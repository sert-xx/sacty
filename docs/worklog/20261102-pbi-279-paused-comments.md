# 一時停止中に届いた PR の指摘を、再開のときに取り込む

- 日付: 2026-11-02（UTC）
- タスク: PBI-279
- PR: #283
- ブランチ: feat/issue-279-paused-comments
- 関係する ADR: [一時停止の間に届いた PR の指摘を、再開のときに取り込む](../adr/20261102-1900-hold-pr-comments-while-paused.md)

## 目的

実験 S16 で、最終レビューがエラーで一時停止している間に人が実装の PR に書いた指摘が、取り込まれなかった。再開しても止まった工程だけが走り直され、実装のやり直しに進めなかった（F23）。
受け入れ条件：一時停止中も指摘を拾って未反映として残し画面に出す／再開したら止まった工程の前にゴールガーディアンに戻し先を判断させる（無ければ従来どおり）／予算で止まったタスクも同じ／docs とテスト。

## したこと

- 残す：PR の確認（`checkPullRequests`）が、一時停止中のタスクの実装の PR（`reworkingPullRequest`）のフィードバックを読み、`PullRequestReviewImported`（`held: true`）で記録する。承認待ちの `pendingReview` に足す（何回かに分けて届いても1つにまとまる）。差し戻し・判断はしない。
- 反映：再開したタスクが次に実行されるとき（`runNextInner` の先頭）、`reworkHeldReview` が、再開の直後に1回フィードバックを読み直し、残した指摘があればゴールガーディアンに戻し先と原因を判断させ（`judgeRework`。PBI-58・265 と同じ）、`ChangesRequested` で差し戻す（`settleHeldReview`）。承認ゲートが無い状態の差し戻しなので、`ChangesRequested` の投影が、判断済みの指摘がある実装の作り直し中（実行待ち・待機）も受け付け、止まった工程の途中経過（検証・PR の更新待ち）を消す。
- PBI-275 との関係：AI のレビューの指摘も同じように残し、人の指摘と区別する（`source`・`aiReview`）。古い head へのレビューは `PullRequestReviewDiscarded` で捨てる（`withoutStaleReviews` を一時停止中にも使う）。AI の指摘だけなら actor は `sacty` で、人の差し戻しの回数に数えない。
- PBI-276 との関係：一時停止中にマージされたら、作り直しの停止が残した指摘を捨て（`ReworkStoppedByMerge.discardedReview`）、マージを承認として進める。再開後・判断の前にマージされていたら、反映せず次の確認に任せる。
- 画面：一時停止中のタスクの詳細に、届いた件数と再開したときの扱いを出す。作業履歴に、一時停止の間に届いて残した旨を出す。再開後の判断中は、状態を「ゴールガーディアンが PR の指摘を判断中」にする。
- docs：仕様書（approval・tasks-and-steps。日英）、ユーザードキュメント（tasks。日英）、ADR。

## 判断したこと（PR にも書く）

- 人の差し戻しの上限：承認ゲートが無く、エスカレーションを置く場所が無いので、上限に達していても止めず、`overLimit: true` で記録する（人の再開を続ける判断とみなす）。
- ゴールガーディアンの見逃し（`GuardianMissed`）は記録しない（止まった工程の実装は最終レビューに合格していない）。
- 判断の実行を一時停止で止めたときは、判断できなかったことを残さず、再開で判断し直す。

## 確かめたこと

テストの結果は PR に書く（全体の vitest run は最後に1回）。

- 足したテスト：`packages/core/src/projection.test.ts`（残す・足す・AI の位置・受け付けない状態・判断後の差し戻し・マージで捨てる・古い head）、`apps/daemon/src/daemon.test.ts`（S16 の再現（最終レビューのエラーで止まって指摘 → 再開）・指摘が無ければ従来どおり・再開の直前の指摘・設計への戻し・判断できない・予算で止まった場合・AI だけ／混ざる／古い head・マージ（一時停止中・再開後の判断前）・上限・再起動・判断中の一時停止・読めないとき）、`apps/web`（作業履歴の文、状態の表示、詳細の案内）。
- 修正を戻すと落ちることを確かめた：反映の呼び出し／残す確認／再開直後の読み直し／AI の actor／上限の記録／マージ時の扱い／判断中の一時停止、をそれぞれ外すと、対応するテストが落ちる。

## 残したこと

- 要求要件・設計をやり直している間に一時停止したタスクは対象外（実装の PR だけ）。
- デーモンを再起動すると、再開直後の読み直し（`heldRecheck`）は消える。それまでに残した指摘は作業履歴から復元する。

## Sacty のレビューの指摘と対応（1回目）

| 指摘 | 対応 |
| --- | --- |
| 判断の間に PR がマージされても、判断前の状態のまま差し戻す。戻し先が設計・要求要件だと作り直しの停止の対象外になる | 判断を記録した後、差し戻す直前に PR の状態を読み直し、マージ済みなら差し戻さず、次の確認の作り直しの停止に任せる |
| 一時停止中に始まった確認が判断中に指摘を足すと、キーの不一致で判断を記録できず費用が履歴に入らない | 一時停止中の確認は、読んでいる間に再開されたら足さない。再開の後に足すのは反映の側だけにして、判断した指摘と記録が食い違わないようにした |
| PR の CI 待ちで止めたタスクは、再開後も検証の待ちから外れ、保持した指摘の判断が始まらない | 反映の対象（`heldReviewDue`）を実行待ちに数える（`queuedTaskIds`） |
| 再開直後の読み取りに失敗しても、印を消して止まった工程を走らせ、復旧後も読み直さない | 読めるまで印を残し、止まった工程を走り直さずに待って、次の周期で読み直す |
| 一時停止中の確認と再開の確認が同じ古い AI のレビューを捨てようとして、重複で例外になり取り込みが中断する | 記録の直前に取り込み済みのものを除き、無ければ記録しない |
| （提案）保持が50件になると、確認も読み直しも追加できる件数が 0 になる旨が書かれていない | 仕様書（日英）に、未反映の指摘の合計が上限であること、超えた分は取り込み済みにせず反映の後の取り込みが足すことを明記 |

テスト（各指摘の競合する順序。修正を戻すと落ちることを確かめた）：判断中のマージ（設計への戻し）、判断中に終わる定期の確認、CI 待ちで止めた再開、再開直後の読み取りの失敗と復旧、同時に走る2つの確認の古い AI のレビューの破棄。
