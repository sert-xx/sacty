# 仕様書とユーザードキュメントを、既定のコンテキストの writing スキルに沿って読みやすく書き直す

- 日付: 2026-10-22（UTC）

- 関係する ADR: なし

## 目的

`docs/spec/` と `docs/user/` の全ページ（日本語の版と英語の版）を、既定のコンテキストの writing スキル（`apps/daemon/default-context/skills/writing/`）の決まりに沿って読みやすくする。
中身（事実・設定の名前・既定値・コマンド・コードの参照）は変えない。

## したこと

- 日本語の版
  - 「。」の後で改行して1行1文にし、文の途中での折り返しをやめた。
    長い文は短い文に分けた。
  - 地の文に埋もれていた条件・列挙を箇条書き（3階層まで）に、同じ観点で比べられる情報を表にした。
  - 文末のコロンを外し、受け身を行為者が主語の文に直した。
- 英語の版
  - 日本語の版と同じ構造にそろえ、行の途中の折り返しをやめて 2〜3 文の段落にした。
  - 能動態で行為者を主語にした。
- 一部のページ（仕様書の approval・context・gateway・secrets・memory、ユーザードキュメントの gateway・compose）に `###` の見出しを足した。
  既存の見出しの文字は、ほかのページからのアンカーリンクが切れないように変えていない。
- 仕様書の event-log で、費用を持つイベントの数が節によって 13 種類と 14 種類に食い違っていた。
  `packages/core/src/cost.ts` の `CHARGED_EVENT_TYPES` は 14 種類なので、14 種類にそろえた（日英とも）。
- `docs/user/gateway.en.md` の先頭の HTML コメントに、日本語の版にある対応するコード（`github-relay.ts`・`gh-shim.cjs`）が抜けていたので足した。
- ADR は足していない（方針・仕様は変えていない）。

## 確かめたこと

- `npx vitest run tests/docs`：89 件すべて通過（ファイル名の規則・リンク切れ・アンカー・日英の版の突き合わせ）。
- 日本語の版で、括弧・かぎ括弧・インラインコード・表・コードブロックの外に、1行に「。」が2つ以上ある行が残っていないかを awk で調べた。
  検出した行は、入れ子の括弧の中の「。」を拾った誤検出だった。
- `config.agentLegacyKey`・`config.providerLegacyName` の誤りの文言が「書き直すよう示す」とおりであることを、`packages/core/src/messages.ts` で確かめた。
- 書き直しの前後で、事実を足したり省いたりしていないかは、ページごとに日英を読み比べて確かめた。
  すべての文をコードと照らし合わせ直してはいない。

## レビューの指摘と対応

| 指摘 | 対応 |

## 残したこと
