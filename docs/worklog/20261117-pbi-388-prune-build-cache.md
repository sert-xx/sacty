# デーモンのコンテキストのイメージの片付けで、3日使っていないビルドキャッシュも消す

- 日付: 2026-11-17（UTC）
- タスク: PBI-388
- PR: なし
- ブランチ: feat/pbi-388-prune-build-cache
- 関係する ADR: [デーモンのコンテキストのイメージの片付けでも、3日使っていないビルドキャッシュを消す](../adr/20261117-1500-prune-build-cache-with-context-images.md)

## 目的

ビルドキャッシュを消すのは `sacty image build` を人が実行したときだけ（7日より長く使っていないもの）で、sacty を動かし続けていると、コンテキストのイメージを作り直すたびにキャッシュが増え、ディスクを圧迫していた。
リポジトリの持ち主の決定（2026-11-17）で、期間を3日にし、デーモンの自動の片付けでも消す。

受け入れ条件の要点：

1. デーモンが、使わなくなったコンテキストのイメージを片付けるとき、3日使っていないビルドキャッシュも消す。
2. `sacty image build` の片付けの期間も3日にそろえる。
3. 消せなくても（docker の失敗・時間切れ）、作成・読み直し・タスクの実行を止めない。片付けの上限の時間の中に収め、デーモンを止めるときは途中でも止まる。
4. 作っている最中・読み直しの最中には消さない。
5. 消したこと・消せなかったことが、デーモンのログで分かる。
6. 仕様書・ユーザードキュメント（日英）・ADR・作業履歴を合わせる。

## したこと

- `apps/daemon/src/image.ts`：期間（`BUILD_CACHE_MAX_UNUSED`）を `168h` から `72h` に変え、docker の引数を `buildCachePruneArgs` にまとめた（`pruneOldImages` とデーモンの片付けが、同じ引数を使う）。
- `apps/daemon/src/context-images.ts`：`pruneContextImagesAndBuildCache` を足した。使わなくなったコンテキストのイメージを消してから、ビルドキャッシュを消し、結果をログに出す。失敗は例外にしない。打ち切られていたら、ビルドキャッシュの docker を動かさない。
- `apps/daemon/src/main.ts`：片付け（`removeStale`）の組み立てを、上の関数を呼ぶ形にした。片付けを呼ぶ条件・上限の時間・停止の扱い（`ContextImageBuilder` の `prune`）は変えていない。
- docs：仕様書 `docs/spec/daemon-lifecycle`・`docs/spec/agent-execution`（日英）、ユーザードキュメント `docs/user/cli`・`docs/user/images`・`docs/user/troubleshooting`（日英）、ADR。
  PBI-313 の ADR は、期間の部分を置き換えたので、名前に `superseded` を付け、PBI-313 の作業履歴からのリンクを直した。

決めたこと（ADR に書いた）：

- イメージの一覧を取れなくても・消すイメージが無くても、ビルドキャッシュは消す。
- 消すものが無かったとき（docker の出力の合計が 0）は、ログを出さない（片付けは、5分ごとの読み直しのたびに動くため）。
- 打ち切り（時間切れ・デーモンの停止）は、1つの文言でログに出す（片付けに渡る signal では、2つを見分けられない）。

## 確かめたこと

- 足したテスト
  - `apps/daemon/src/context-images.test.ts`（docker の実行は差し替えた）
    - イメージを消した後に `builder prune -f --filter until=72h` を呼び、消したことと空いた容量をログに出す（新旧2つの形の出力）。
    - 合計が 0 ならログを出さない。量を読めない出力でも、消したことは出す。
    - docker の失敗（終了コード）・起動できない（例外）で、例外にせず、消せなかったことをログに出す。長い出力は切る。
    - イメージの一覧を取れなくても、ビルドキャッシュは消す。
    - 打ち切られていたら、ビルドキャッシュの docker を動かさない。
    - 実際の `ContextImageBuilder` につないで：上限の時間を過ぎたら止めて、読み直しと次の片付けが進む。デーモンを止めると、消している途中でも止まる。作っている最中・ほかのプロジェクトを読み直している最中には消さない。片付けが重なっても、同時に2つ動かさない。
  - `apps/daemon/src/image.test.ts`：`pruneOldImages` が `until=72h` で呼ぶ。
- 修正を戻して、足したテストが落ちることを確かめた（期間を `168h` に戻す：10 件、デーモンの片付けでキャッシュを消さない：13 件、打ち切りの確かめを外す・0 でもログを出す・例外を投げ直す：それぞれ 1 件）。
- `npm run lint`：成功。`npm run typecheck`：成功。`npx vitest run --no-file-parallelism`：261 ファイル・5065 件が成功（1 件はスキップ）。
- 手元の Docker（クライアント 29.6.2・サーバー 29.5.3）で `docker builder prune --help` を読み、`docker buildx prune` に渡ること・`-f`・`--filter` があることを確かめた。
- 確かめていないこと
  - 実際の `docker builder prune` は実行していない（手元のキャッシュが消えるため）。消した量の出力の形（`Total: …`・`Total reclaimed space: …`）は、実行して確かめたものではない。
  - `apps/daemon/src/main.ts` の組み立ては、テストでは通していない（型の検査だけ）。動いているデーモンのログも見ていない。
  - 2分の上限で打ち切ったときに、それまでに消した分が残るか。

## レビューの指摘と対応

まだ無い。

## 残したこと

- ビルドキャッシュが多いと、最初の片付けが2分の上限に掛かり、その間、読み直し（プロジェクトの設定の保存の後など）が待つことがある。上限は変えていない。
