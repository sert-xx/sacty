# 版を 1.10.0 に上げる

- 日付: 2026-10-26（UTC）
- タスク: なし
- PR: #228
- ブランチ: ccr-0810afb3-4n4c9u
- 関係する ADR: [版は 1.0.0 から semver で付け、タグと GitHub Releases でリリースする](../adr/20261019-2345-semver-releases.md)

## 目的

1.9.1 の後に、機能の追加と修正（PR #210〜#227）が入った。設定ファイルの形・台帳・コマンドの引数に互換性の無い変更は無い
（スケジュールタスクの定義を足しただけ）ので MINOR を上げ、1.10.0 をリリースする。

ただし、次の2つは今までの設定のまま動きが変わるので、リリースの説明に「注意が要る変更」として書く。

- 作業領域の片付け（PR #227）：完了したタスクの作業領域と、中断で残った実行ごとの一時領域を消す。すでに残っているものも、
  起動時に同じ基準で消す。
- エージェントのコンテナ（PR #215）：`--init` で起動し、PID 1 を init にする。

## 1.9.1 からの変更

- スケジュールタスク：決めた内容のタスクを、決めた予定で作る。PC が止まっていた間の予定は、復帰したときに1つだけ作る（PR #221）
- 終わったタスクと、中断された実行の作業領域を片付ける（PR #227）。作業領域の写し・削除の間も、デーモンが画面や API に応答し続ける（PR #226）
- `sacty up` を止めている途中を表示し、2回目の Ctrl+C で待たずに止める（PR #225）
- 情報収集にサービスの起動のルールを伝え、オーケストレーターがサービスを確定させる（PR #211）
- PR のレビューの工程で、依存関係を取得して検証を実行させる（PR #212）
- Claude Code の実行で後で起こす予約を使わせず、結果が何回も出ても本文と使用量を正しく取る（PR #213）
- 環境が原因のテストの失敗と、作業領域では確かめられない確かめ方を、人の確認として最終承認へ回す（PR #215）
- オーケストレーターへの質問を Ctrl + Enter・⌘ + Enter で送れる（PR #216）
- 要求要件・設計・文書の初版を最小限にし、受け入れ条件を文型ごとの表で書く（PR #217・#219・#222）
- 文書作成の成果物を明確にし、外部に直接書いたページを記録して、差し戻しで同じページを直させる（PR #220）
- 既存の PR を直すタスクは PR を引き継ぐ。手動で作ったレビューのタスクの指摘も、元のタスクの PR の指摘として取り込む（PR #223・#224）
- 依存の更新（PR #218）と、docs の図とスクリーンショット（PR #210）
- 更新の後にすること：`npm ci` で依存を入れ直し、既定のイメージの名前が `sacty-agent:1.10.0` に変わったので、
  `npx sacty image build` で作り直す。

## したこと

- 4 つのパッケージとワークスペースの依存の版を `1.10.0` にし、`package-lock.json` の版の行も同じにした。手元の npm 10 では
  `npm install --package-lock-only` が版と関係の無い行（`libc`）まで消したので、1.9.0 のときと同じく版の行だけを直した。
- 既定のイメージの名前（`DEFAULT_IMAGE`）を `sacty-agent:1.10.0` にし、仕様書（`agent-execution`・`configuration`）・ユーザードキュメント
  （`config`・`images`）の日英と、イメージの名前を書いているテスト・コメントを同じ版にした。ゲートウェイの MCP クライアントの版の文字列も
  `1.10.0` にした。

## 確かめたこと

- `npm ci`・`npm run lint`・`npm run typecheck`：通過。
- `npx vitest run`：2738 件が通り、8 件（`agent-sessions.test.ts`・`context-mcp.test.ts`・`host-mcp-processes.test.ts`）が落ちた。
  1.9.0 のときと同じく、この作業の環境（クラウドのコンテナ）によるもの。`question-form.browser.test.ts` も、この環境ではブラウザーのテストを
  始められずに落ちた。どれも版の文字列とは関係が無い。
- `rg 1.9.1` で、ADR・作業履歴と、`package-lock.json` のほかのパッケージの版・`smol-toml` の依存の範囲のほかに、`1.9.1` が残っていないことを確かめた。
