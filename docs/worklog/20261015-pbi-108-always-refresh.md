# タスクの一覧と詳細を、画面をリロードせずに常に最新にする

- 日付: 2026-10-15（UTC）
- タスク: PBI-108
- PR: #119
- ブランチ: feat/issue-108-always-refresh
- 関係する ADR: [タスクの一覧・詳細などの画面は、画面をリロードせず、データだけを常に3秒ごとに取り直す](../adr/20261015-1349-refetch-screen-data.md)

## 目的

画面の自動の更新は、タスクが動いている間だけ `router.refresh()` で画面の全体を描き直していた。承認待ち・一時停止・完了の間は更新
されず、取り込みで増えたタスク・ほかのタブや CLI での承認と再開・デーモンが拾って動き出したタスクが画面に出なかった。新しいタスクを
一覧に出し、状態の変化をすぐに画面に出す。画面はリロードせず（入力や操作の途中の状態を消さないため）、データだけを取り直す。

## したこと

- 取り直しの仕組み：`apps/web/src/lib/live.ts`（`pollWhileVisible`・`fetchLive`）と `useLiveData`。3秒ごと、前の取り直しが
  終わってから次を数える。タブが隠れている間は止め、見えたらすぐに取り直す。前の版（中身のハッシュ）を送り、同じなら中身を送らない。
  デーモンに届かないときは 200 で `unavailable` を返し、画面をそのまま残す。
- 画面のサーバーのルート：`/live/tasks?project=`（一覧の行とカード。表示に要るものだけ）、`/live/tasks/<ID>`（詳細のデータ）、
  `/live/header?current=`（ヘッダーの切り替えとお知らせ）。データを取る処理は `loadTaskList`・`loadTaskDetail`・`loadHeaderData` にまとめ、
  画面を描くときと取り直すときで同じものを使う。
- タスクの詳細を、サーバーのコンポーネントからクライアントのコンポーネント（`components/task-detail.tsx`）に移した。表示の部品
  （task-bits・deployment・implementation・integration・orchestrator-session・proposals・pull-request・reproduction・step-costs・task-chat・
  test-viewpoints）も、文言を `useMessages` で読むクライアントのコンポーネントにし、部品の中のデーモンへの問い合わせ（子タスク・修正の
  タスク・イメージの候補）はデータを取る所に移した。
- タスクの一覧（あなたの出番とすべてのタスク）を `LiveTaskList` に、ヘッダーのメニューを `LiveHeaderMenus` にした。
- `gh` で GitHub に問い合わせる対象リポジトリの候補は、取り直しでは取らない。タスクの作成のダイアログは画面を描いたときのまま。
  詳細で人がリポジトリを選ぶ一時停止の候補は、持っていないときだけ一度求める。
- `AutoRefresh`（作業中だけ `router.refresh()`）・`RefreshOnVisible`・使われなくなった `isWorking` を消した。ほかの画面（レビュー・実行の
  ログ・設定など）は自動で描き直さない（ヘッダーのお知らせは取り直す）。
- DOM のテストのために、開発用の依存に `jsdom` を足した。
- 仕様書（`architecture.md`）と利用者向けの文書（`tasks.md`）を、英語の版も直した。ADR を足した。

## 確かめたこと

- 回帰テスト：
  - `apps/web/src/components/live-screens.test.ts`（jsdom。13件）：操作せずに3秒のうちに出ること（ほかのタブ・CLI での承認、一時停止からの
    再開、実行待ちが拾われて動き出し承認待ちになること、取り込みで増えたタスク、すべてが承認待ち・一時停止・完了の一覧、ヘッダーの
    お知らせ）。タブが隠れている間は問い合わせず、見えたらすぐ取り直すこと。デーモンに届かない間は画面を残し、届いたら更新すること・
    描いたときに届かなくても届いたら出すこと。リポジトリの候補を取り直しのたびに求めないこと。操作の途中の状態が残ること（書きかけの
    質問・選んだ工程のイメージ・開いた欄（details）・開いたチャットのパネル・フォーカスと選択の範囲・再開のフォームの値・作成の
    ダイアログの書きかけ・変わらない所の要素がそのまま＝スクロールの位置が動かない）。`router.refresh` を呼ばないこと。
  - `apps/web/src/lib/live.test.ts`（8件）：間隔が3秒、重ねないこと、隠れている間と見えたとき、失敗しても続けること、返事の形（版が同じなら
    中身を送らない・届かないときも 200）。
  - 修正を戻すと落ちることを確かめた：取り直しを止めると live-screens の13件がすべて落ちる。データが変わるたびに詳細を作り直す形
    （`key` を変える。リロードと同じく状態を失う）にすると、状態を残すテスト2件が落ちる。
- `npm run lint`（終了コード 0）・`npm run typecheck`・`npx vitest run`（1537 件）・`npm run build`・`npx vitest run tests/docs` が通る。
- PO の確かめへの対応の後：`npm run lint`（終了コード 0）・`npm run typecheck`・`npx vitest run`（1544 件）・`npm run build`・`npx vitest run tests/docs` が通る。
- 画面：自分のブランチを別のポート（4820・4830）と一時的な `SACTY_HOME`（スタブの AI。リポジトリ無しの設計だけのタスク）で起動し、
  Playwright で動画に撮った。承認待ちのタスクを開き、チャットの質問を書きかけて少し下に送ったまま、別のタブで承認する → 操作せずに
  「設計の承認待ち」に変わり、書きかけの質問・フォーカス・スクロールの位置（160 → 160）が残る → 一覧を開いておき、別のタブでタスクを
  作る → 一覧に出る。ブラウザのコンソールにエラーは出なかった。
  - 撮る途中で、本番の build だけで起きる誤り（`setTimeout` をオブジェクトのメソッドとして呼ぶと「Illegal invocation」で画面が壊れる。
    jsdom では起きない）を見つけて直した。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| （DA のセルフレビュー）`isWorking` が画面のどこからも使われなくなった | 関数と、それだけを確かめていたテストの行を消した |
| （DA のセルフレビュー）詳細の画面の部品が、別のタスクに移ったときに前のタスクのリポジトリの候補を持ち越しうる | タスクの ID を `key` にして、タスクが変わったら作り直す |
| （DA のセルフレビュー）一時停止でリポジトリの候補が要るかを、前の描画のデータで決めていて、1回遅れていた | 取り直す先を、取り直すときのデータから決めるようにした。回帰テストで、候補を一度だけ求めることを確かめた |
| （PR #119 の PO の確かめ）実行中のタスクの実行のログの画面が、これまでと違って自動で更新しなくなる。今までできていたことができなくなるのは不可。ほかの画面も確かめる | 実行のログは、持っている分の長さと目印を送り、足された分だけを取って後ろに足すようにした（`/live/tasks/<ID>/runs/<実行の ID>`・`appendedText`・`applyChunk`）。ファイルが書き直されていれば全体を置き換える。読んでいる途中は位置を動かさず、一番下を見ているときだけついていく。実行が終わったら止め、エージェントの元のファイルの一覧はそのときに一度だけ取る。ほかの画面を確かめ、これまで作業中に描き直されて中身が変わりえた成果物のレビュー（タスク）とプロジェクトの一覧（取り込みの状況）も、データだけを取り直すようにした（`LiveReview`・`LiveProjectList`）。sacty の設定とプロジェクトの設定は、フォームの値を描いたときの値で持つため描き直しで中身が変わらず、タスクの状態で変わるものも無いので、取り直さない。回帰テスト `live-other-screens.test.ts`（7件）を足し、ログの取り直しを止めると4件、ついていく処理を消すと1件、レビューと一覧の取り直しを止めると2件落ちることを確かめた。実行のログが伸びる様子を動画に撮った（スタブの AI の実行はすぐ終わるので、実行のログのファイルを終わりの記録の無い形にして行を足した。読んでいる途中は 500 → 500 で動かず、一番下ではついていった） |
| （PR #119 の PO の確かめ）撮影の準備で、公開リポジトリに push しようとした件 | 以後、実在の他人のリポジトリを対象にしない（架空の対象と、リポジトリ無しのタスクで確かめる）。gh で、そのリポジトリに sert-xx の PR・Issue・コメントが無く（検索の件数 0）、sacty のブランチも無いことを確かめた |
