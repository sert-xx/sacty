# Next.js を 16.4.5 に上げ、既知の脆弱性（GHSA-mfr8-8qww-v76h ほか）を直す

- 日付: 2026-11-16（UTC）
- タスク: なし
- PR: #394
- ブランチ: claude/nextjs-security-update-33c721
- 関係する ADR: なし

## 目的

- `next build` が、経路の一覧を出した後に `Error [SecurityFatalError]: Your version of Next.js is affected by a known security vulnerability.` を出して
  exit 1 で終わることがあった。当たっている勧告を調べ、直った版に上げる。
- 上げ幅は、勧告を解消する最小（同じメジャー・マイナーの中）にする。Next.js 以外の依存の更新と、コードの整理はしない。

## したこと

- `apps/web/package.json` の `next` を `16.4.2` から `16.4.5` にし、`package-lock.json` を更新した（`next`・`@next/env`・`@next/swc-*` の版・取得元・
  ハッシュだけが変わった）。コードの変更は無い。
- `npm audit` が `next` 16.3.0〜16.4.4 に出していたのは、次の 1 件（moderate）。16.4.5 で直っている。
  - [GHSA-mfr8-8qww-v76h](https://github.com/advisories/GHSA-mfr8-8qww-v76h)（CVE-2026-119790）：`'use cache'` の関数を、描画の中で直接呼ぶのと
    `unstable_cache()` 経由で呼ぶのとを両方していて、その関数がルートパラメータを読むとき、プロセスの起動直後の競合で、あるルートパラメータの値の
    ために作ったキャッシュの中身が、別の値への要求に返ることがある。
- 16.4.5 の[リリースノート](https://github.com/vercel/next.js/releases/tag/v16.4.5)は、上を含む 7 件の勧告（すべて moderate）を直したと書いている。
  残りの 6 件は、GitHub の全体の勧告のデータベースにまだ載っておらず（`gh api /advisories/<ID>` が 404）、`npm audit` には出ない。
- 版は 16.4.5 にした（npm の最新は 16.4.6）。16.4.3・16.4.4 は不具合の修正の取り込み、16.4.5 は勧告の修正だけ、とリリースノートにある。

### ビルドが止まっていた仕組み

- Next.js は、入っている版に既知の勧告が当たると知らせる仕組みを持つ（`experimental.agentUpgrade` の既定が `security`）。
  AI のエージェントから実行したと判定したときは、1 回目のビルドをエラーで止め、5 分以内にやり直すと警告だけ出して続ける
  （`node_modules/next/dist/lib/upgrade/nudge.js` を読んで確かめた）。「やり直すと通ることがある」のはこのため。
- エラーの文面には、エージェントに向けて、アップグレードのコマンドの実行と、人への質問を求める文が含まれる。これには従わず、版を上げた。
- CI では出ていない。CI で出ない理由は、コードを追い切れておらず、分からない。

### sacty への影響（分かる範囲）

`apps/web` のコードと設定を調べて判断した。攻撃を試してはいない。

| 勧告 | sacty の使い方 | 判断 |
| --- | --- | --- |
| GHSA-mfr8-8qww-v76h | `'use cache'`・`unstable_cache()` を使っていない。ルートレイアウト（`src/app/layout.tsx`）は動的なセグメントの下に無く、ルートパラメータが無い | 当たらない |
| [GHSA-vc7v-qv4w-wrv8](https://github.com/vercel/next.js/security/advisories/GHSA-vc7v-qv4w-wrv8)（入れ子の `'use cache'` でルートパラメータをまたいでキャッシュが漏れる） | 同上 | 当たらない |
| [GHSA-rhh4-g77r-r9qj](https://github.com/vercel/next.js/security/advisories/GHSA-rhh4-g77r-r9qj)（バイナリの引数を取る `'use cache'` のキャッシュのキーの衝突） | `'use cache'` を使っていない | 当たらない |
| [GHSA-vvgp-ww4w-46vf](https://github.com/vercel/next.js/security/advisories/GHSA-vvgp-ww4w-46vf)（Cache Components の共有のフォールバックシェルの汚染） | `cacheComponents: true` で `next start` だが、勧告が回避策に挙げる `partialPrefetching: true` を設定済み。`generateStaticParams` も使っていない | 前提を満たさない |
| [GHSA-f3mh-rxg3-f5g2](https://github.com/vercel/next.js/security/advisories/GHSA-f3mh-rxg3-f5g2)（Edge ランタイムの経路で HttpOnly の Cookie が内部のヘッダーに出る） | Edge ランタイムを指定した経路が無い | 当たらない |
| [GHSA-pc58-hwjq-p385](https://github.com/vercel/next.js/security/advisories/GHSA-pc58-hwjq-p385)（取得した応答をそのまま返すルートハンドラーで、応答がクライアントの間でずれる） | デーモンから取得した応答の本文をそのまま返す経路が 2 つある（`tasks/[id]/runs/[runId]/agent`・`tasks/[id]/runs/[runId]/raw/[file]`）。条件は「細工された上流の応答」と「パイプラインを許す HTTP/1.1 のリバースプロキシの後ろ」で、sacty の上流は同じマシンの自分のデーモン、画面は `127.0.0.1` で直接待ち受ける | 形は近いが、ふつうの使い方では条件を満たさないと考える。リバースプロキシの後ろに置いたときにどうなるかは、勧告の説明が短く、分からない |
| [GHSA-7qx7-33qx-rqx2](https://github.com/vercel/next.js/security/advisories/GHSA-7qx7-33qx-rqx2)（画像の最適化が、無効にした SVG を処理させられる） | `next/image` を使っておらず、`images` の設定（外部の画像の許可）も無い。ただし `/_next/image` の経路そのものは残っていて、`src/proxy.ts` の認証の対象からも外れている | 攻撃者が SVG を渡す経路は見当たらないが、勧告に手口の説明が無く、当たらないと言い切れない |

## 確かめたこと

Node.js 26.13.1（`.node-version` の版）で実行した。

- `npm audit`：`found 0 vulnerabilities`（変更前は `next` の moderate 1 件）。
- `npm run build`：exit 0（`▲ Next.js 16.4.5 (Turbopack)`）。出力に `SecurityFatalError` も、脆弱性の警告も出ない。
- 変更前の main（`7e9bad1b`）を別に clone し、同じ環境で `npm run build`：1 回目は `SecurityFatalError` で exit 1、すぐやり直した 2 回目は
  `⚠ Your version of Next.js is affected by a known security vulnerability. This command is continuing after the upgrade reminder.` を出して exit 0。
  上げた後は 1 回目から通るので、通知が消えたのはこの変更による。
- `npm run typecheck`：通った。
- `npm run lint`：まっさらな複製で指摘なし（662 ファイル）。作業していた作業ツリーでは、git 管理していない手元の設定ファイル 1 つの整形だけが指摘された
  （この変更とは関係が無い）。
- `npx vitest run --no-file-parallelism`：244 ファイル・4683 件が通った（1 件はスキップ）。
- まっさらな複製（このブランチを clone → `npm install` → `npm run build`）：`npm install` の後に `package-lock.json` の差分なし、ビルドは exit 0。
- 画面：まっさらな複製のビルドを、架空のデータ（`scripts/docs-screenshots/seed.mjs`）を入れた一時のデータディレクトリと別のポート（画面 4790・
  デーモン 4791）で `sacty up` し、Playwright で開いた。入り口（`/auth`）→ ダッシュボード → タスクの一覧 → 一覧からクリックしてタスクの詳細 →
  別のタスクの詳細を直接開く → プロジェクトの設定、がすべて 200 で表示され、コンソールのエラー・4xx/5xx の応答は無かった。確かめた後に止めた。
- 確かめていないこと：各勧告の攻撃が変更前に実際に成り立ったかどうか（コードの使い方から判断しただけ）。デスクトップ版（`apps/desktop`）の
  パッケージでの動作。
