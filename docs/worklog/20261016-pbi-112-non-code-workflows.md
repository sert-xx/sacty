# 非開発の原稿作成と単発の外部作業の工程を追加する

- 日付: 2026-10-16（UTC）
- タスク: PBI-112
- PR: #123
- ブランチ: feat/issue-112-non-code-workflows
- 関係する ADR: [文書原稿と単発の外部作業を独立した承認工程で扱う](../adr/20261015-2353-superseded-non-code-workflows.md)

## 目的

原稿作成と外部単発更新を、要求要件・設計・実装の形式に当てはめず進められるようにする。関連する PBI-113 の外部操作も同じ変更で扱い、原稿の承認前の外部未更新と、単発作業の実行開始後の再送防止を明確にする。

## したこと

工程定義・選択指示・承認境界・永続化と画面表示を実装した。仕様書と利用者向け文書の日英に、原稿作成と外部作業の使い分け、原稿の外部アクセス制約、開始後の差し戻し禁止・再開時の扱いを記載した。設定できる工程と書き出せる成果物の説明も更新した。

## 確かめたこと

`npx vitest run tests/docs` は 2 ファイル・89 テストで合格。日英の節を読み比べ、DA セルフレビューで再開時の例外と承認境界を確認した。第1回レビュー対応後も同じ文書テストが 89 件合格し、`git diff --check -- docs` に問題なし。原稿の外部読取制約・書き出し選択・旧版復帰・評価ケースの未実施表示を DA ロールで再確認した。第1回DAレビュー後の修正では、`npx tsc -b packages/core apps/daemon packages/cli` が合格。`npx vitest run apps/daemon/src/prompts.test.ts apps/daemon/src/daemon.test.ts -t '単発操作|非コードの成果|成果の書き出し'` は49件合格。Webの関連5テスト・型チェック・対象Biomeも合格した。全体の再検証とDA再レビューは別途記録する。実際の外部サービスは更新しない。実モデルでの分類精度と本番の選択比率は未評価であり、プロンプトと状態遷移のテスト結果とは区別する。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| 既存の再開説明が外部操作の再実行を促す可能性 | 開始済みの作業実行は再実行しない例外を日英で追記 |
| 任意の書き出し失敗と、外部操作失敗の扱いが異なる | 原稿完了を止めない書き出しと、成功根拠が必要な作業実行を区別 |
| 原稿作成時に外部接続を渡すと承認前に変更できる | 接続とプロジェクトコンテキストを渡さない制約、外部原稿を読めず人間が本文を補う手順を日英へ追加 |
| 新工程を保存した DB を旧版で読み込めない | ADR と利用手順に更新前バックアップ、旧版復帰時の新規履歴の損失・外部変更確認を記載 |
| 接続があれば必ず書き出すと読める | オーケストレーターが選んだ場合だけであること、選択結果の確認と書き出し文書への参照を追加 |
| 評価用業務ケースが追跡対象に残らない | この履歴に目的・前提・期待経路・境界を記録。実モデルの評価結果ではないことを明示 |

## 業務分類の評価用ケース

以下は工程選択を評価するための期待値であり、実モデルによる実行結果ではない。入力文の表現を変えた場合の分類精度や本番の選択比率は未評価。プロンプト・制約・状態遷移の回帰テストが通ることと、AI が各入力を正しく分類することを区別する。将来評価するときは、利用可能なリポジトリ・接続先・テスト基盤を入力条件として固定し、選択された工程と理由を期待値に照合する。

| ID | 業務の目的と前提 | 期待する経路 | 評価する境界 |
| --- | --- | --- | --- |
| B01 | 認証処理の説明を求め、変更は依頼しない | investigate | 説明だけで完了し、コード変更へ進まない |
| B02 | 障害原因と影響範囲だけを報告する | investigate の不具合調査 | 原因調査と修正依頼を区別する |
| B03 | 既存リポジトリの文言を局所的に修正する | skip-design | 文書ファイルも PR を伴う変更として扱う |
| B04 | 複数の画面と API に関わる振る舞いを変更する | standard | 要求要件・設計が必要な影響範囲を考慮する |
| B05 | 既存テストで再現でき、期待動作が明確な不具合を直す | bugfix | 再現テストを経て実装する |
| B06 | 不具合の解消に認証方式の設計変更が必要 | standard | 「不具合」という語だけで bugfix に限定しない |
| B07 | 特定の既存 PR のレビューを依頼する | review | 対象 PR とリポジトリが必要 |
| B08 | リポジトリを指定せず、システム全体の方針を設計する | design-only | 設計成果物と利用者向け原稿を区別する |
| B09 | 複数の独立した PR に分ける規模の変更を依頼する | split | 子タスクで再分割せず、統合時に親の目的を確認する |
| B10 | 提供された情報から利用者向けの手引きを作る | document | 要求要件や設計の形式を強制しない |
| B11 | 本文を提供した議事録の整理・翻訳草稿を作る | document | 承認前に外部サービスを更新しない |
| B12 | 外部ページの URL だけから原稿を改訂したい | document で本文の補足を求める | 承認前の原稿作成は外部読取もできない |
| B13 | 提供された原稿をリポジトリの利用者文書へ反映する | 規模に応じて skip-design または standard | 原稿の画面承認だけでは完了にしない |
| B14 | 完成原稿を接続済みの公開先へ書き出す | document と選択済みの export | 接続の存在だけで書き出しを約束しない。失敗は原稿完了を止めない |
| B15 | 外部の既存ページ・予定表・台帳の指定対象を直接更新する | operation | 既存オーケストレーターが対象・前提・変更・確認方法を選定し、事前承認を挟まず依頼に従って1回実行して結果承認を待つ |
| B16 | 予定を読み、候補日を報告するだけ | investigate | 外部変更がないため operation にしない |
| B17 | 外部更新したいが対象 ID または接続先が不明 | operation の実行前で不足を解消 | 推測で変更しない。必要な接続がなければ実行しない |
| B18 | 書込の結果応答を受け取る前に中断・再起動する | 停止し、人間が実際の状態を確認 | 再開・差し戻しで変更を再送しない |
| B19 | 複数システムをまたぐ定期処理を求める | 今回の単発作業の対象外とする | operation を長期・繰り返し業務の自動化と誤認しない |

standard の選択率だけで偏りを判定しない。各ケースの目的に対する適切さ、不要な開発工程への誘導、対象や接続先の不足時の挙動を併せて評価する。

## 残したこと

実モデルによる代表業務の分類評価、本番の選択比率と目的に対する適切さの分析は未実施。外部側の exactly-once 保証、複数接続先の一括操作、定期業務・監視の追加は範囲外。


### 二段階案での第1回DAレビューの実装修正（準備工程は撤去済み）

- 原稿工程にも外部接続を渡さず、承認前の外部変更を防ぐ。書き出し選択の指示には原稿を追加した。
- 操作のJSONは共通抽出器で読み、対象訂正・成功後の失敗訂正・壊れた併記・重複キーを拒否する。
- 停止未確認の操作は実行IDとタスク配下の作業領域を残し、中止時に停止を確認し直す。手動停止・失敗・例外と、後から停止確認できた場合の削除をテストした。
- 承認後にも新工程の成果物・書き出し結果を表示する。実行後には差し戻し操作を表示しない。
- 複数接続の権限制限、承認後の接続削除、中止と成功応答の競合、訂正後の具体案だけの実行を検証した。準備の差し戻し・承認を前提にした検証は、後の単一工程化で対象仕様を撤去したため、最終仕様の検証結果には含めない。

### 二段階案の検証とDA再レビュー（単一工程化前の記録）

- `npx biome check apps packages tests`: 合格（整形・lint）。`npm run lint` 全体は、今回変更していない別 worktree の入れ子設定と衝突するため、変更したソース・テストを含む範囲を指定して検証した。
- `npm run typecheck`: 合格。
- `npx vitest run`: 78ファイル・1,663テストが一括実行で合格。初回に不足していた既存のテスト依存は `npm ci` でロックファイルどおり復元した。
- `npm run build`: 全パッケージで合格。
- 操作結果の成功判定を一時的に旧挙動へ戻すと、成功後の失敗訂正を拒否する回帰テストが失敗することを確認。復元後は合格し、対象ファイルの変更前・復元後のハッシュ一致を確認した。
- DA自己レビューは2回。C-1〜C-7・C-9・C-10・C-12〜C-14・U-1・U-6・X-1・X-2の16観点で再レビューし、全観点が合格。C-8は大量データ・ホットパスの変更がなく、C-11は依存・ビルド定義の変更がないため起動しなかった。残る修正指摘・見られなかった観点はない。
- 利用者の追加指定により、偏りの評価は実装上の推定を対象とした。実モデルの分類精度・運用履歴の選択比率は今回の受け入れ対象外。外部サービスの実更新とブラウザの実操作は行わず、実行境界と表示は自動テストで確認した。


### 利用者の方針変更による単一工程化

準備と実行の二段階は過剰という指定に従い、最終仕様を単一の operation 工程へ変更する。準備成果物・差し戻し・実行前承認は撤去し、既存オーケストレーターの選定後に依頼どおり1回実行して結果承認を待つ。対象・接続の不足時は開始前停止、開始後の結果不明・失敗では再送しない。上記の二段階案のテスト件数・DA合格は変更前の記録であり、単一工程化後の合格を表すものではない。単一工程化後の検証結果は別途追記する。

日英仕様・利用手順・設定の工程名と承認境界、未公開の ADR、業務評価ケースを最終仕様に合わせて更新した。実モデルの分類精度・実ログでの選択比率は引き続き未評価。

単一工程化後の文書について、`npx vitest run tests/docs` は 2 ファイル・89 件で合格、`git diff --check -- docs` も合格した。DA ロールで日英の工程名、事前承認撤去、開始前の不足停止、開始後の再送禁止、旧検証記録との区別をセルフレビューした。実装全体の再検証は別途記録する。
