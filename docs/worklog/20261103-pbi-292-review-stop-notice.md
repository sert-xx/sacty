# Sacty のレビューがエラーで止まったことを、レビューを頼んだ PR で分かるようにする

- 日付: 2026-11-03（UTC）
- タスク: PBI-292
- PR: #293
- ブランチ: feat/issue-292-pbi-292
- 関係する ADR: [Sacty のレビューが止まったら、レビューを頼んだ PR にコメントで知らせ、再開して投稿したら解消済みに書き換える](../adr/20261103-0746-tell-pr-when-review-stops.md)

## 目的

実験 findings F37：sert-xx/sacty#288 のレビュー（ラベルで依頼）が、codex の「Selected model is at capacity」で止まり、PR にはラベルだけが残って約50分レビューが来なかった。依頼した人は PR しか見ていないので気づけない。
止まったこと・理由の要点・再開のしかたを PR に書き、再開して投稿したら古いと分かるようにする。一時的な失敗の自動のやり直しが既にあるかを調べる。

## 調べたこと（自動のやり直し）

証拠：`~/.sacty/sacty.db` の activity 表、タスク 52359c0c-6e66-4842-a4ae-65e73d30a117（読むだけ）。

| seq | 時刻（UTC） | 記録 |
| --- | --- | --- |
| 4781 | 03:18:12 | `AgentRunStarted`（review、`codex_advanced`） |
| 4793 | 03:18:49 | `AgentRunFailed`（reason: error、message: `Selected model is at capacity. Please try a different model.`、`costUnknown`） |
| 4794 | 03:18:49 | `TaskPaused`（reason: error。message なし） |
| 4972 | 04:06:56 | `TaskResumed`（人が再開。約48分後） |
| 4994〜4995 | 04:14 | 2回目の実行が成功し、レビュー（指摘なし）を投稿 |

- 失敗から一時停止まで同じ時刻（49.998）。待つ・やり直す処理は挟まっていない。
- `classifyFailure`（`agents/parse.ts`）は、この文を利用上限（`usage_limit`）にも認証（`auth`）にもせず `error` にする。
- 失敗の処理（`pauseOrFallBack`）は、エージェントに `fallback` を書いていれば代わりで実行し直し、無ければそのまま `TaskPaused` を書く。`~/.sacty/config.yaml` に `fallback` は無かった。
- 同じエージェントで間を置いてやり直す処理、時間が経ったら自動で再開する処理は、どちらも無い。ゲートウェイのリトライ（`gateway.ts`、429・5xx、最大 8 回・合計 10 分）は、ゲートウェイを通す AI の呼び出しだけが対象で、サブスクリプションで動く codex の CLI には効かない。
- 同じ失敗は、実験 S20 試行 2（codex の容量不足で実装が止まった）にも記録されていた（`agents/agents.test.ts` の「容量不足で始まってすぐ失敗した番」）。

判断：自動のやり直しは足さない（理由は ADR）。既にある `fallback` の設定で自動の切り替えは選べるので、ユーザードキュメントに、その設定への案内を書いた。

## したこと

- `apps/daemon/src/review-stop-notice.ts`（新規）：投稿の目印・止まり方の識別・本文・解消済みの本文・理由の要点（`stopSummary`：秘密情報を伏せてから 1 行にして 300 文字で切り詰める）。
- `service.ts`：`append` で、レビューのタスクが人が止めたのではない理由で一時停止に変わったら、`announceReviewStop` で PR にコメントする。同じ止まり方の解消していないコメントが PR にあれば書かない。`postReview` でレビューを投稿したら、`resolveReviewStops` で、そのタスクの解消していないコメントを解消済みに書き換える。書けなかったら警告をログに出すだけ。
- `github.ts`：`listIssueComments`（目印で始まる、指定のアカウントのコメント）・`editIssueComment`（本文の書き換え）を足し、PR の指摘の取り込み（`feedback`）で、止まったことのコメントを除く。`messages.ts` に `editIssueComment` の失敗の文言を足した。
- `main.ts`：タスクの画面へのリンクの元（`SACTY_WEB_URL`）を `webUrl` として渡す。
- docs：仕様書（intake・agent-execution。日英）、ユーザードキュメント（intake・troubleshooting。日英）、ADR。

## レビュー対応

- 1回目（88320ec7）：知らせの投稿と解消の順序を保証（タスクごとの Promise）、`noticeAccounts` の受け渡し、編集失敗のテスト、再開の案内の文言。
- 2回目（a9397e70）：
  - 要修正：投稿の最中の知らせを待つ間に「再レビュー」が始まると、タスクから対象の PR が消えて解消されない。解消の対象のタスクと PR を、待つ前に持って渡すようにした。
  - 要修正：順番の待ちに taskId だけを持っていたので、先の投稿の最中に違う理由で続けて止まると、後の処理がどれも最後の理由を読んだ。停止した時点の理由と説明を、待ちに足すときに持つようにした。
  - どちらも、先の知らせの投稿を遅らせた回帰テストを足し、修正を戻すと落ちることを確かめた。

## 確かめたこと

結果は PR に書く。

- 足したテスト
  - `review-stop-notice.test.ts`（7件）：本文（F37 の止まり方）、止まり方の識別、要点の整形、秘密情報の伏せと切り詰めの順序（切り口にかかる位置を 3 通り。前半が 4 文字以上残らない）、外から来た文のコード化、解消済みへの書き換え、知らせる理由。
  - `github.test.ts`（3件）：`listIssueComments`（自分のアカウント・先頭の目印・解消済み・他人・引用・別のタスクの ID の前方一致）、`editIssueComment`、止まったことのコメントを PR の指摘に取り込まないこと（他人が目印をまねたものは取り込む）。
  - `daemon.test.ts`（7件）：F37 の形で 1 件書く、同じ止まり方は増えない・違う止まり方は別に書く・投稿で全部解消済みになる、解消後に同じ止まり方で止まったらまた書く（再レビュー）、投稿の失敗で止まったときにトークンを載せない、ラベルで取り込んだ PR の対象を決める前の停止、人が止めたとき・PR が分からないタスクは書かない、PR に書けなくてもタスクの状態は変わらない。
- 修正を戻すと落ちること：切り詰めてから伏せる順にすると要点のテスト 2 件、`append` の呼び出しを外すと `daemon.test.ts` の 6 件、解消済みへの書き換えを外すと 2 件、`feedback` の除外を外すと `github.test.ts` の 1 件が落ちた。

## 残したこと

- 書けなかった知らせと、デーモンの再起動をまたいだ知らせは、書き直さない。
- レビューのタスクを中止（PR のマージ・クローズを含む）しても、止まったことのコメントは解消済みにならない。
- 秘密情報の伏せは、sacty が知っている値（使った GitHub のトークン、記録のときに伏せた値）だけ。形から推測して伏せる処理は足していない。
- 一時的な失敗の自動のやり直しは足していない。
