# 役に立ったメモリーの日付を監査が更新し、使われないメモリーを自動で掃除する

- 日付: 2026-10-18（UTC）
- タスク: PBI-127
- PR: #137
- ブランチ: feat/issue-127-memory-cleanup
- 関係する ADR: [メモリーの有効な最終利用日は、開いた記録と監査の判断で決め、残す日数を過ぎたら消す](../adr/20261018-0200-memory-useful-date-and-cleanup.md)

## 目的

PBI-126 で登録するようになったメモリーのうち、役に立っているものは残し、使われなくなったものを自動で消す。

## したこと

- core：`AuditSurveyed` に開いたメモリー・役に立ったメモリー、削除の理由 `expired`、sacty の設定 `memoryRetentionDays`（既定 90 日）。
- デーモン
  - 大まかな監査の前に、タスクの実行のセッションログから、開いたメモリーを数えて指示に入れ、役に立ったものを出させる。
  - 有効な最終利用日を、役に立ったタスクの完了日の最新と登録の時刻から決め、索引と中身のファイルに書く。
  - 残す日数を過ぎたメモリーを、起動のときと1時間ごとに消す。
- 画面：監査の欄に、役に立ったメモリーと有効な最終利用日、期限で消した印。sacty の設定に「メモリーを残す日数」。
- テストのファイル（`daemon.test.ts`）が biome の既定の上限（1 MiB）を超えたので、`files.maxSize` を 2 MiB にした。
- docs：仕様書（メモリー・全体の構成）、ユーザードキュメント（監査・config.yaml の設定）、ADR。

## 確かめたこと

- `npx biome check`・`npm run typecheck`・`npx vitest run`・`npm run build` が通った。
- 次の修正を戻すと、テストが落ちることを確かめた：役に立った日の最新を取る、登録より前に戻さない、ちょうどの日数は残す、索引の相対リンクを
  数えない、開いていないものを役に立ったにしない、役に立った後の書き直し、起動のときの掃除、既定の日数。
- 監査の実行のログを数えない絞り込みは、一度は対象が無いと考えて外したが、レビューで止めた後の再起動で対象が残ることが分かり、戻した（下の表）。

## レビューへの対応

| 指摘 | 対応 |
| --- | --- |
| （要修正）大まかな監査の途中で止めると、次の起動で前の監査のログまで数える | 監査の記録の `runId` と、セッションの記録の役割が `audit`・`audit-dive` の実行を、数える対象から外した。止めてから再起動し、前の監査だけが開いたメモリーを数えないテストを足し、修正を戻すと失敗することを確かめた |
| （提案）監査の一覧で、監査のタスクごとに全タスクを走査し直す | メモリーの集計を、一覧の中で1回だけ作って渡すようにした。集計のために各タスクを読み直さないこと（読んだ回数）を確かめるテストを足し、修正を戻すと失敗することを確かめた |
| （提案）1時間ごとの掃除のタイマーにテストが無い | タイマーを `startMemoryCleanup` に分け、偽のタイマーで、1時間前には動かない・1時間で動く・失敗しても次の回は動く・止めた後は動かないことを確かめた |
| （提案）読めなかったログを追えない | 無いログのほかは、タスク・実行の ID とエラーのコードを警告するようにした。仕様と利用者向けの文書に、数えない場合と確かめ方を書いた |
| （提案）「このタスクの完了日にしました」が、最新の日付を保つ仕様と合わない | 画面の補足と利用者向けの文書を「完了日を基に更新し、すでに新しければ変わらない」にした |
| （提案）ADR の「開いた回数が作業履歴に残る」が実装と合わない | 「開いた ID と判断が残り、監査の欄には役に立ったものが出る」に直した |
