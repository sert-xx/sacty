# 時間切れで止めた実行を、セッションの続きから再開する

- 日付: 2026-11-02（UTC）
- タスク: PBI-280
- PR: #281
- ブランチ: feat/issue-280-timeout-resume-session
- 関係する ADR: [時間切れで止めた実行は、再開のときに同じエージェントのセッションの続きから進める](../adr/20261102-1320-continue-session-of-run-stopped-by-timeout.md)

## 目的

フィールドの試行（時間切れの再開）で、時間切れで止めた実行を再開すると、止まった工程を新しいセッションで最初から実行し直し、短い
`run_timeout` では何度再開しても進まなかった（要求要件は調査とセルフレビューの起動、実装は検証とセルフレビューのやり直し）。再開のときに、
止めた実行のセッションの続きから進めて、最後は完了まで進めるようにする。

## したこと

- 作業履歴に、記録だけのイベントを 2 つ足した。`AgentRunTimedOut`（時間切れで止めた実行）と `AgentRunContinued`（次の実行が、セッションを
  続けたか `resumed`、続けずに最初から実行し直したか `restarted` と理由）。
- `apps/daemon/src/timeout-resume.ts`（新規）：直前の実行が時間切れで止まったものか（`timedOutRunBefore`）、続けられるか（`planTimeoutResume`。
  エージェントが同じ・セッション ID と本体のファイルがある・省いたファイルが無い・ハッシュが一致する）、指示の先頭に足す知らせ（`timeoutResumeLines`）。
- `service.ts`：オーケストレーターと質問への答え以外の実行を `executeResumable` に通した。続けるときは、止めた実行の `runs/…/agent/` を
  設定の場所に戻し、Claude Code は `--resume`、Codex は `resume` で再開する（既存の再開の仕組み）。時間切れで止めた実行と、続けた／続けなかった理由を残す。
- 画面：作業履歴の行（日英）。
- 実装の作業領域：時間切れで止めても、タスクの clone は消えず、次の実行も同じ作業領域で動くことを、コードで確かめた（消すのは完了したタスクと、
  どのタスクのものでもない領域だけ。`workspaceRetirable`・`cleanupWorkspacesAtStartup`）。ベースブランチの取り込み（`mergeBase`）も、未コミットの変更を含む
  作業領域の内容と 3 方向でマージするので、変更は失われない。消える経路が見つからなかったので、退避は足していない。
- 仕様書（agent-execution・event-log）・ユーザードキュメント（troubleshooting・config）の日英と、ADR を直した。

## 確かめたこと

- テスト（追加）：
  - `timeout-resume.test.ts`：直前の実行の判定（空・1件・複数回・続けた後・別の実行を挟む・質問への答えを挟む）、続けない理由（エージェントの ID・AI の種類・記録なし・
    写さなかった・ファイルが空・セッション ID の不正・省いた・本体なし・書き換え・消えた・置き場所なし）、Codex の本体のファイル、指示の知らせ。
  - `daemon.test.ts`：Claude Code の再開（同じセッション・元のファイルを戻す・指示に知らせと元の指示・続けた記録・次の工程は続けない）、3 回続けて止まっても毎回同じセッションで
    積み重なって完了、Codex の `resume`、時間切れ以外の失敗は続けない、記録なし／コンテナ停止の未確認／エージェントを変えた／ファイルが壊れた／別のセッションで始まった／AI が再開を断った場合の
    最初からの実行し直しと理由、実装が時間切れで止まっても同じ作業領域に変更が残り、同じセッションで続く。
  - 修正を戻すと落ちることを確かめた（再開しない・続けた記録で打ち切らない・別の実行で打ち切らない）。
- `npm run lint`・`npm run typecheck`・`npx vitest run tests/docs`・全体の vitest：通過（全体は 185 ファイル・3528 件）。

## 残したこと

- 実機（Docker 上の Claude Code・Codex）で、強制終了したセッションを `--resume` できるか、短い `run_timeout` の実タスクで 2 回以上止まって完了まで進むかは未確認
  （PR の本文に手順を書いた）。
- オーケストレーターは、以前から保存したセッションを再開する（PBI-67）。時間切れで再開したことの知らせは、指示に足していない。
- 再開した実行が時間切れ以外の理由（認証・利用上限）で止まると、その次の再開は最初から実行する。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| 続けた実行（r2）の途中でデーモンが止まると、r2 の写した記録も続けた記録も残らず、次の実行が r1 の進捗を含まない古い会話を続ける | 実行の開始・失敗（`AgentRunStarted`・`AgentRunFailed`）も別の実行として数える（時間切れで止めた実行自身と、いま実行する実行は除く）。デーモンの停止と復旧（`recoverInterrupted`）を通す回帰テストと、判定の単体テストを足した。修正を戻すと落ちる |
| 最終レビュー・ゴールガーディアンなどが、作業履歴の行で内部の ID のまま出る | 工程以外の役割（`guardian`・`final-review`・`rework`・`orchestrator`・`gather`・`chat`・`export`・`audit`・`audit-dive`）に日英の表示名を付けた。知らない役割は役割のまま |
