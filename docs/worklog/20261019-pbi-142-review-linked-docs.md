# PR の本文で示された文書も、レビューの対象かを判断してレビューする

- 日付: 2026-10-19（UTC）
- タスク: PBI-142
- PR: #154
- ブランチ: feat/issue-142-review-linked-docs
- 関係する ADR: なし

## 目的

設計などの成果物を Git の外（Confluence・Google Docs・Notion・wiki など）に書き出し、PR の本文にリンクを貼ることがある。
この場合にレビューすべきなのはリンク先の文書だが、既定のスキル review には「差分が小さくリンク先が主題なら主対象にする」の 1 行しか無かった。
リンク先は根拠として扱われ、範囲の外は指摘しないので、レビューされにくかった。

## したこと

- 既定のスキル：`review-dispatch/references/linked-docs.md` を足した。親が担当を起動する前に、次を行う。
  - 本文で示された文書を拾い、タイトル・説明・差分を総合して「対象」か「根拠」かに分ける。迷ったら対象にする。
  - 対象と根拠の全文を取得し、作業領域の外に写しを置く。認証情報は求めない。
  - 対象の文書を主対象の種類の判断と担当の対象に含める。差分の外でも、範囲から外さない。
  - 文書の置き場はプロジェクトごとに違うので、スキルには特定の PF の名前を書かない（テストで確かめる）。
- 取得できないとき：
  - 主対象の文書が読めなければ、レビューを完了できない。
  - ほかの対象の文書なら、「レビューの範囲」に書いて合格と書かない。
- 指摘と記録：
  - 文書への指摘は、位置を付けられない指摘として、文書と節を添えて書く。
  - 分けた結果は、集約の記録の `linked_docs` に残す。
- 既存のファイルの直し：`SKILL.md`・`pr-review.md`・`self-review.md`・`aggregation.md`・`review-execution/SKILL.md` を、上に合わせた。
- sacty のレビューの工程のプロンプト：次の 2 つに、PR の説明で示された文書を入れた。
  - 判定を付けない条件
  - 差分の外への指摘を本文に回す規則
- docs：仕様書（コンテキスト、タスクと工程）、利用者向けの説明（取り込み）。いずれも日本語・英語。

## 確かめたこと

- `npx biome check`・`npm run typecheck`・`npx vitest run`・`npm run build` が通った。
- スキルの文言とプロンプトの文言をテストにした。
- 次の 11 個の、どの修正を戻してもテストが落ちることを確かめた。
  1. 読む順序から外す
  2. 担当の対象に写しを入れない
  3. 迷ったら根拠にする
  4. 差分の外を範囲から外す
  5. 認証情報を求める
  6. 主対象の文書が読めなくても完了する
  7. 読めない対象の文書があっても合格にする
  8. 記録を残さない
  9. 指摘の位置を写しのパスにする
  10. プロンプトで文書を扱わない
  11. プロンプトの判定の条件に文書を入れない
