# 判定し直しの回に残った提案もすべて対応しないとき、一時停止せずに、ドラフトを外して人の承認待ちにする

- 日付: 2026-11-20（UTC）
- タスク: PBI-440
- PR: なし
- ブランチ: sacty/task-（タスク ID の先頭 8 文字）
- 関係する ADR: [判定し直した回に残った提案もすべて対応しないときは、一時停止せずに、リスク評価だけを 1 回行ってから、ドラフトを外して人の承認を待つ](../adr/20261120-2342-no-pause-when-rejudged-suggestions-all-declined.md)

## 目的

選り分けで始めた同じ先頭の判定し直しの回が、また提案だけを残し、それもすべて対応しないとしたとき、一時停止して人を待たずに、判定は「提案あり」のまま、ドラフトを外して人の承認を待つ（利用者の決定）。
最初の決定は「その先頭にリスク評価が出ないことを受け入れる」だったが、利用者が追加で、再レビューはせず、リスク評価だけの実行を 1 回行ってからドラフトを外すと決めた（人の指摘 implement-1-1）。あわせて、選り分けの指示に載せる今回の提案・要修正の文の上限を 600 から 2,000 文字に上げる。

## したこと

- `PullRequestMarkedReady` に `reason`（`suggestions_declined`）を足した。無い記録は指摘なし（以前の記録は、そのまま読める）。
- PR の確認で、`triageStopDue` が真のとき、`TaskPaused`（`triage.left`）の代わりに `markReady(…, "suggestions_declined")` を呼ぶ。`markReady` の最後の検査は、この場合、子タスクが同じ先頭・同じ回・同じ判定数で、最後の判定が「提案あり」であり、`triageStopDue` が今も真であることを見る。
- 投影：`Task.triageStop` を `TaskPaused` で消さずに、`PullRequestMarkedReady` で消す（以前の版が一時停止させたタスクも、再開でドラフトが外れる）。`pullRequest.suggestionsLeft` を足し、`wantsDraft` と PR の確認の `redraftAwaiting` が、提案が残ったまま外した先頭をドラフトに戻さないようにした。
- 画面：作業履歴の行（`PullRequestMarkedReady` の理由が `suggestions_declined` のとき、別の文言）と、承認の画面・タスクの概要の `AiReviewNotice` に、提案が残っていること・再レビューをしていないこと・直させたいときは PR に要対応とコメントすることを足した。
- 追加の決定（リスク評価だけの実行）：ドラフトを外す前に、`assessDeclinedRisk` が、オーケストレーターのエージェントで評価を 1 回実行する（版を上げる前の PR を出す前の評価の実行を、`assessPullRequestRisk`・`buildRiskAssessmentPrompt` として今のコードに合わせて戻した。残った提案と対応しない理由を材料に渡す）。記録は `PullRequestRiskAssessed`（`via: suggestions_declined`。費用は他の評価と同じに予算へ数える）。PR のコメントは、目印つきで 1 通（`commentDeclinedRisk`。同じ目印があれば書かない）。評価できなくても理由を記録してドラフトを外す。止まったことを確かめられなかった実行があれば一時停止にして外さない。同じ先頭は記録で見つけて繰り返さない。
- 画面：「PR のリスク評価」の欄に、この場面の評価を、評価の出どころ・評価したコミットつきで出す（子タスクの前の先頭の評価より新しいとき）。作業履歴の評価の行にも、この場面の文言を足した。
- 指摘なしの回の評価・PR の作成・更新のときに評価しないこと・要求要件・設計の PR は、変えない。
- 選り分けの指示：今回の提案と要修正の文を 1 件 2,000 文字まで（前の回の指摘・対応しないとした提案・返信・再レビューに渡す分は 600 文字のまま）。件数が多いときの合計の上限は、1 つのレビューの本文の長さで抑えられるので、置かない。
- 仕様書（`approval`・`event-log`・`risk-assessment`）・利用者向けの文書（`tasks`）を日英とも直し、ADR を足して PBI-436 と PBI-429 の ADR を `superseded`（一部の置き換え）にした。

## 確かめたこと

- `daemon-suggestion-triage.test.ts`：一時停止せずにドラフトが外れる（判定し直し・選り分けが増えない）、人の要対応のコメントで直しに入る、先頭が進むと再レビューが始まる、以前の版の一時停止（stop と `triage.left`）を再開するとドラフトが外れる、起動し直し。
- `daemon-suggestion-triage.test.ts`（追加の決定）：評価が成功する（評価 1 回・コメント 1 通・ドラフトが外れる・判定は提案あり・子タスクに評価が付かない・繰り返さない）、評価が失敗する（理由の記録・コメント 1 通・ドラフトが外れる）、評価の後・ドラフトを外す前に起動し直す（評価もコメントも重ならない）、以前の版の一時停止を再開する（評価してからドラフトが外れる）、評価の対象でないデーモンは評価せずに外す。評価の呼び出しを外すと 4 件が落ちることを確かめた。`risk-assessment.test.ts`（web）：この場面の評価の出し方。
- `suggestion-triage.test.ts`：今回の提案・要修正は 2,000 文字まで、前の回の指摘・対応しないとした提案は 600 文字まで。
- 検査：`npm run lint`（警告も失敗）と `npm run typecheck` が通り、`npx vitest run --no-file-parallelism` は 299 ファイル・6,053 件が通った（14 件はスキップ）。`npm run build` は実行していない。
