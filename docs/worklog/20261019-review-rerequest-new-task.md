# GitHub のレビュー再依頼を別タスクとして取り込む

- 日付: 2026-10-19（UTC）
- タスク: なし
- PR: なし
- ブランチ: feat/review-rerequest-new-task
- 関係する ADR: [GitHub のレビュー再依頼は完了タスクを戻さず別タスクにする](../adr/20261019-0503-review-rerequest-new-task.md)

## 目的

完了したレビューの記録を保持し、GitHub から届いた次のレビュー依頼の作業を別のタスクで確認できるようにする。

## したこと

- レビュー再依頼による新タスクの作成、元タスクの保持、前回指摘の引き継ぎと重複排除を実装した。
- 取り込み・レビュー工程の仕様と、利用者向けの取り込み手順を日英で更新した。
- 手動「再レビュー」と初回・ラベル取り込みの動作は維持した。

## 確かめたこと

- `npm run typecheck` と `npx biome check apps packages tests` は成功した。
- `npm test -- --reporter=dot` で2,312件を実行した。ローカル待受・子プロセスの権限制約で94件が失敗したため、対象ファイルを制限外で再実行してすべて成功した。文書テスト89件も全体実行で成功した。
- DA 指摘の修正後、全体を制限外で再実行し、119ファイル・2,315件がすべて成功した。型チェックとソース対象の Biome 検査も再実行して成功した。
- `npm run lint` は既存の入れ子作業ツリーの Biome 設定を検出して終了するため、上記のソース指定で同じ検査を行った。
- 新しい回帰テストを変更前のコードに当て、同じタスク ID が返るため失敗することを確認した。新しい実装では成功した。

## レビューの指摘と対応

- 実装時の確認で、新タスクから古い完了タスクへ戻って追加作成しないようにし、前回レビューから回数を継続するようにした。
- DA レビューで、異なる依頼日時を取得した並行処理が古い完了タスクから追加作成できることを指摘されたため、API の待機後も最新タスクを選び直して元と一致することを確認するようにした。
- 現在の依頼先に対象アカウントが無いときは履歴 API を呼ばないようにし、その回帰テストを追加した。
- 別タスクの実際のレビュー指示に前回の行コメント・本文・コミット・作者返答を引き継ぐテストと、取り込み件数の統合テストを追加した。

- 追加のセルフレビューで保存済みセッションのある元タスクとの分離のテスト不足を指摘されたため、再開可能な保存ファイルを用意し、新タスクがそれを使わず元ファイルも変えないことを検証するテストを追加した。

## 残したこと

画面の手動「再レビュー」の別タスク化は、この変更には含めない。
