# 版を 1.7.1 に上げる

- 日付: 2026-10-21（UTC）
- タスク: なし
- PR: なし
- ブランチ: claude/pr-review-triage-orchestrator-spk66d
- 関係する ADR: [版は 1.0.0 から semver で付け、タグと GitHub Releases でリリースする](../adr/20261019-2345-semver-releases.md)

## 目的

1.7.0 の後に、依存の更新（`@modelcontextprotocol/sdk` を 1.31.0 から 1.32.0 に。PR #181）が入った。機能の追加は無いので PATCH を上げ、
1.7.1 をリリースする。

## したこと

- 4 つのパッケージとワークスペースの依存の版を `1.7.1` にし、`package-lock.json` の版の行も同じにした。
- 既定のイメージの名前（`DEFAULT_IMAGE`）を `sacty-agent:1.7.1` にし、仕様書（`agent-execution`・`configuration`）・ユーザードキュメント
  （`config`・`images`）の日英と、イメージの名前を書いているテスト・コメントを同じ版にした。ゲートウェイの MCP クライアントの版の文字列も
  `1.7.1` にした。
- `package-lock.json` の外部の依存（`use-sync-external-store`・`atomically`・`get-east-asian-width`）の `1.7.0` は変えない。
- 依存の更新（PR #181）は、マージの前に確かめた。`@modelcontextprotocol/sdk` 1.32.0 の互換性の注意（HTTP のクライアントのトランスポートが、
  別のオリジンへのリダイレクトに従わない）は、sacty の本体では HTTP のクライアントのトランスポートを使わない（テストだけ）ので影響しない。
  同じ更新の PR #179 は、古い main を元にしていて競合しており、#181 と同じ内容なので、マージしない。

## 確かめたこと

- PR #181 の内容で `npm ci`・`npm run lint`・`npm run typecheck`・`npx vitest run`：`npx vitest run` は 2414 件が通り、8 件
  （`agent-sessions.test.ts`・`context-mcp.test.ts`・`host-mcp-processes.test.ts`）が落ちた。この 8 件は更新の前の main でも同じく落ちるので、
  この作業の環境（クラウドのコンテナ）によるもの。
- 版を上げた後：`npm run lint`・`npm run typecheck` が通過。`npx vitest run` は上と同じ結果（2414 件が通り、環境による 8 件が落ちた）。
- `npx vitest run tests/docs`：通過。
