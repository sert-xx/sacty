# 文書作成の成果物を指示で明確にし、外部に直接書いたページ（複数可）を記録して、差し戻しで同じページを直させる

- 日付: 2026-10-25（UTC）
- タスク: なし
- PR: #220
- ブランチ: claude/compassionate-brahmagupta-bsjocq
- 関係する ADR: [文書作成の成果物を指示で明確にし、外部に直接書いたページ（複数可）を記録して、差し戻しで同じページを直させ、書き出さない](../adr/20261025-0410-document-deliverable-pages.md)

## 目的

文書作成のタスクで、外部 PF の文書を直すよう差し戻すと、最初とは別の文書が外部に作られ、タスクの最終報告も外部に文書として作られた。
何が成果物かを明確にし、差し戻しではその成果物を続けて直し、成果物でないものを sacty の外に出さないようにする。
タスクの説明が直接の編集を指示していれば外部に書いてよく、成果物が複数のページになる（条件で探したページをまとめて直す）タスクも扱う。

## したこと

- 原因：文書作成のエージェントは外部 PF・MCP に書き込める。指示は「原稿を外部に直接書かず出力する」だけで、何が成果物か
  （出力の全体が原稿として保存・承認・書き出しされること）を伝えておらず、外部に直接書いたページも記録していなかった。
  そのため、外部に書いたエージェントは出力に作業の報告を書き、差し戻しの実行は前のページを知らずに別のページを作り、
  承認でその報告が書き出された。
- `apps/daemon/src/prompts.ts`
  - 文書作成の指示に「成果物」の節（`documentDeliverableLines`）を置いた。ふつうは原稿1つで外部に書かない。タスクの説明が
    直接の作成・編集を指示していれば外部に書いてよく、書いたページ（複数可。条件で探したものを含む）が成果物。成果物のほかに
    外部にページ・コメントを作らない。作業の報告を外部にも出力にも書かない。差し戻しでは前回の成果物を直し、同じページを直す。
  - 外部に直接書いたページは `sacty-document-pages` で申告させ、`extractDocumentPages` で取り出して出力から除く。
  - 書き出しの指示（`buildExportPrompt`）に、書くのはファイルの内容の1ページだけで、報告を別のページやコメントにしないことを足した。
  - オーケストレーターへの組み合わせの説明で、差し戻しで直し続ける外部の文書の直接の作成・編集（複数のページを含む）を `document`、
    一意な対象1つへの決まった変更を1回するものを `operation` にした。文書作成の指示から「既存文書の直接更新依頼は作業で扱います」を除いた。
- `packages/core/src/events.ts`・`packages/core/src/projection.ts`：`AgentRunCompleted` に `documentPages` を足し、投影の
  `Task.documentPages` に回ごとに足して残す。`exportDue` は、`documentPages` があれば文書作成を書き出さない。
- `apps/daemon/src/service.ts`：文書作成の実行の出力から申告を取り出して記録する。
- `apps/web/src/components/task-detail.tsx`・`apps/web/src/i18n/messages/task.ts`：文書作成の成果の欄に、書き出しの結果の代わりに
  「外部に直接書いたページ」の一覧を出す。
- 仕様書（`docs/spec/tasks-and-steps.md`・`docs/spec/export.md`）とユーザードキュメント（`docs/user/tasks.md`・`docs/user/result-export.md`）を、
  英語の版とともに直した。
- 経緯：最初の版では外部への書き込みをすべて禁じる指示にしたが、利用者から「タスクの説明で直接編集の指示があれば従ってよい」と
  指摘があり、外部に直接書いたページ1つを記録する形にした。さらに「成果物が複数のページになるタスクもある（〇〇を含むページを
  探してまとめて直す）」と指摘があり、ページの一覧を記録し、直接書いたなら書き出さない形にした。

## 確かめたこと

- `npx vitest run apps/daemon/src/prompts.test.ts`：121 件が通る（足したテスト：直接の書き込みはタスクの説明の指示があるときだけ・
  複数のページ・作業の報告を書かせない・差し戻しで前回の成果物と同じページを直させる・申告の取り出し・組み合わせの説明・書き出しで報告を書かせない）。
- `npx vitest run apps/daemon/src/daemon.test.ts -t "非コードの成果"`：32 件が通る（足したテスト：直接書いた複数のページを記録し、
  差し戻しの回で申告したページを足し、差し戻しの指示に渡し、承認の後に書き出さない）。
- `npx vitest run tests/docs`：93 件が通る。
- `npm run lint`・`npm run typecheck`：通る。
- `npx vitest run`（全体）：2655 件が通り、8 件と1ファイルが落ちる。落ちるのは `agent-sessions`・`context-mcp`・`host-mcp-processes` の
  8 件と `question-form.browser.test.ts`（この環境に Playwright の Chromium の版が無い）。変更を外した状態でも同じく落ちるので、
  この変更とは関係ない（8 件は、この環境が root で動いていることによると思われるが、未確認）。

## レビューの指摘と対応

- `sacty-document-pages` と `sacty-responses` を同じ JSON のオブジェクトに入れると、先に動く `extractBlocks` がオブジェクトごと除き、
  ページの申告が失われる（[要修正]）。→ `apps/daemon/src/service.ts` で、申告を `extractBlocks` の前の元の出力から読み、原稿からは
  残った申告の JSON だけを除くようにした。`apps/daemon/src/daemon.test.ts` の複数のページのテストで、差し戻しの回の申告を指摘への
  対応と同じオブジェクトに入れ、ページと対応の両方を読むことを確かめた（修正を外すと、このテストが落ちることも確かめた）。
