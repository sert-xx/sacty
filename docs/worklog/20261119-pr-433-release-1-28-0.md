# 版を 1.28.0 に上げる

- 日付: 2026-11-19（UTC）
- タスク: なし
- PR: #433
- ブランチ: feat/release-1-28-0
- 関係する ADR: [版は 1.0.0 から semver で付け、タグと GitHub Releases でリリースする](../adr/20261019-2345-semver-releases.md)

## 目的

1.27.0 の後に入った変更（PR #430〜#432）をリリースする。起動中の sacty を MCP で操作するコマンド `sacty mcp`（PR #431）は機能の追加なので MINOR を上げる。

## 1.27.0 からの変更

- ビルドキャッシュの片付けの後はイメージを最初から作り直すことを、文書とコメントに正しく書いた（PR #430。動きは変えていない）。
- 起動中の sacty を手元の AI から操作する MCP サーバー `sacty mcp` を足した（PR #431）。
- `npm run cli:install` が、入口を mise に登録せず、いつも `~/.local/bin` などに置く（PR #432）。

## 互換性の判断

- 設定ファイル：設定の形を決めるコードに差分は無い。
- 台帳：新しい種類のイベントは無い。`ReviewTargetResolved` に省略できる `headBranch` を足した。1.27.0 のこのイベントの形は知らない項目を読み飛ばすので、1.27.0 に戻しても作業履歴は読める。
- `daemon.json` に画面の URL（`web`）を足した。デーモンが起動のたびに書くファイルなので、戻しても困らない。
- `packages/cli/docker` の差分は `Dockerfile` のコメントだけで、イメージの中身は変わらない。
- `cli:install` の入れ方が変わること（前の版で mise に登録した場合は手で外す）を、リリースの説明の注意に書く。

## したこと

- 5 つのパッケージとワークスペースの依存の版を `1.28.0` にし、`package-lock.json` の版の行を直した。
- 既定のイメージの名前（`DEFAULT_IMAGE`）を `sacty-agent:1.28.0` にした。
  同じ版にしたもの：仕様書（`agent-execution`・`configuration`）とユーザードキュメント（`config`・`images`）の日英、イメージの名前を書いているテスト・コメント、ゲートウェイの MCP クライアントの版の文字列。
  直したファイルは、1.27.0 の版上げ（PR #429）と同じ範囲。置き換えは前後に数字・`.` が無い `1.27.0` だけにし、ADR・作業履歴は対象から外した。
- 元のイメージのダイジェスト：`docker buildx imagetools inspect node:26-bookworm-slim` の `Digest` は、`Dockerfile` に固定したもの（`sha256:5df79989…`）と同じだったので変えていない。
