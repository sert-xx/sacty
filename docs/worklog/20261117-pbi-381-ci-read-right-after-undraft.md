# ドラフトを外した直後の CI の読み取りで、その先頭を「読み終わり」にしない

- 日付: 2026-11-17（UTC）
- タスク: PBI-381
- PR: #418
- ブランチ: feat/pbi-381-ci-after-ready
- 関係する ADR: [実装の PR の CI を、最初に読んだ回と、ドラフトを外した直後には「読み終わり」にしない](../adr/20261117-0820-do-not-settle-ci-right-after-undraft.md)

## 目的

人の承認を待つ実装の PR の CI の読み取りは、失敗が無ければ、その回で、その先頭を読むのをやめていた。
sacty は、レビューの子タスクの「指摘なし」でドラフトを外した確認の中で CI を読む。ドラフトを外したことで CI が走るリポジトリでは、新しい実行が GitHub の一覧に載る前に読んで、読むのをやめてしまい、その後に落ちた CI が出なかった。

受け入れ条件の要点：

- ドラフトを外した後、一定の時間のあいだは、失敗が無くても読むのをやめない。読む期間・回数の上限（先頭のコミットごとに、5分おきに、12回まで）は変えない。
- 読み続ける仕組み・並列の読み取り・間隔の切り替えは足さない。
- 仕様書の「閉じて開き直した PR では、同じ先頭の失敗を出し直さない」が、コードと逆なので、コードを確かめて、仕様書を直す。
- 失敗しても続行する設定のジョブの結論が、GitHub からどう返るかを、公式の文書で調べる（コードは変えない）。

## したこと

- デーモン（`apps/daemon/src/service.ts`）：
  - `readPullRequestCi`：その先頭を「読み終わり」にするのを、その先頭を最初に読んでからと、sacty がドラフトを外してからの、どちらも `PR_CI_SETTLE_MS`（5分）以上たった後の読み取りだけにした。それより前の読み取りでは、間隔の後に読み直す。失敗の表示を出していて通っていたときは、表示は消すが、読み終わりにはしない。
  - 読み終わりを、読んだ回数を上限にする書き方から、印（`settled`）に変えた。読んだ回数を残すため。
  - `notePullRequestUndrafted`：sacty がドラフトを外したとき（指摘なしで外した `markReady`・外し直した `undraftMarkedReady`・重ねた PR の付け替えで外した `retargetPullRequest`）に、外した時刻を覚え、読み終わりにしていた先頭の読み終わりを取り消す。読んだ回数は数え直さない。
  - 外した時刻は、デーモンのメモリーに持つ（`pullRequestCiUndrafted`）。PR が開いていなくなったタスクの分は、読んだ回数と一緒に忘れる。
- 仕様書（日英。`approval` の「指摘なしの後の CI の失敗の表示」）：
  - 読み終わりにする条件と、取り消す条件を足した。
  - 「閉じて開き直した PR では、同じ先頭の失敗を出し直さない」を消し、コードの動き（閉じられたことを記録した PR は、読んだ回数を忘れる。開き直されたら、同じ先頭でも読み直し、落ちていたら記録し直す）を書いた。コードは変えていない。テストを足して確かめた。
  - 拾わないものを、今の動きに合わせた。
- ユーザードキュメント（日英。`tasks` の「『指摘なし』の後に CI が失敗したとき」）：ドラフトを外したときに始まる CI の失敗も出ることと、最初に見た回・ドラフトを外した直後の回では見るのをやめないことを足した。
- ADR：読み終わりにする時期を決めた ADR を足した。PBI-375 の ADR は、ファイル名・ステータス・置き換え先だけを直した（その ADR へのリンクも、新しい名前に直した）。

決めたこと（理由は ADR）：

- 長さは5分（読み直しの間隔と同じ）。読み取りは間隔ごとにしか起きないので、これより短くしても動きは変わらず、長くすると読み取りが1回増える。
- 最初に読んだ時刻からも数える。デーモンを再起動すると、外した時刻を忘れるため。レビューの子タスクを使わない PR でも、同じ決まりになる。どの先頭も、少なくとも2回読む。
- 外した時刻は、記録（イベント）に足さず、メモリーに持つ。
- 先頭が変わったら、新しい先頭を最初に読んだ時刻から数える。

失敗しても続行する設定のジョブについて、GitHub の文書で分かったこと（コードは変えていない）：

- ステップの `continue-on-error`：文書に、失敗したステップの `outcome` は `failure`、`conclusion` は `success` になる、とある（[Contexts reference](https://docs.github.com/en/actions/reference/workflows-and-actions/contexts) の `steps` コンテキスト）。ジョブは通る（[Workflow syntax](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax) の `jobs.<job_id>.steps[*].continue-on-error`）。この設定では、sacty の「CI 失敗」は出ないはず（実物では未確認）。
- ジョブの `continue-on-error`：文書にあるのは、そのジョブが失敗しても、ワークフローの実行は通る、ということだけ（同じページの `jobs.<job_id>.continue-on-error`）。そのジョブの結論が、API で `failure` と返るか、`success` と返るかは、文書からは分からなかった。
  - `failure` と返るなら、sacty は、ワークフローが成功でも「CI 失敗」を出し、ジョブが落ちたままなので、表示は消えない（`readPullRequestCi` は、ワークフローの実行と、その中のジョブの両方を見る）。実物では確かめていない。

## 確かめたこと

- `npx vitest run --no-file-parallelism`：257 ファイル・4987 件が通った（1 件は以前からの skip）。`npm run lint`・`npm run typecheck`：通った。`npx vitest run tests/docs`：通った。
- 足した・変えたテスト（どれも、対応する修正を戻すと落ちることを確かめた）：
  - `apps/daemon/src/daemon-implement.test.ts`：
    - 「すべて終わって失敗が無い先頭は、読むのをやめる」を、最初の読み取りではやめず、間隔の後の読み取りでやめる形に直した。再起動の後も、最初の読み取りではやめないこと。
    - 最初の読み取りで失敗が無くても、間隔の後に読んで落ちていたら、記録すること。
    - 最初の読み取りで失敗の表示を消しても、読み終わりにせず、落ちていたら出し直すこと。
    - 閉じて開き直した PR で、同じ先頭の失敗を出し直すこと（仕様書の食い違いの確認。コードは変えていないので、修正を戻して落とす対象ではない）。
  - `apps/daemon/src/daemon-step-pull-requests.test.ts`：
    - 指摘なしでドラフトを外した確認で読んだ CI に失敗が無くても、読み終わりにせず、間隔の後に読んで、落ちていたら出すこと。通っていたら、間隔の後の読み取りで読み終わりにすること。
    - 人が足したコミットの再レビューの間に読み終わりにした先頭を、外し直した後に読み直して、落ちていたら出すこと。読んだ回数は、上限のまま。
  - `apps/daemon/src/daemon-split.test.ts`：重ねている間に読み終わりにした PR を、付け替えでドラフトを外した後に読み直すこと。
- 修正を部分ごとに戻して、落ちるテストを確かめた：
  - 最初に読んだ時刻を見ない：`daemon-implement.test.ts` の3件が落ちる。
  - ドラフトを外した時刻を見ない・読み終わりを取り消さない：`daemon-step-pull-requests.test.ts` の再レビューの1件が落ちる。
  - 付け替えで外した時刻を覚えない：`daemon-split.test.ts` の1件が落ちる。
  - いつでも読み終わりにする（修正前の動き）：`daemon-implement.test.ts` の3件と、`daemon-step-pull-requests.test.ts` の3件が落ちる。
- テストは、時計を差し替えて書いた（固定の時間を待つ書き方は足していない）。

確かめられなかったこと：

- 実物のリポジトリ（ドラフトを外すと CI が走る設定）で、新しい実行が一覧に載るまでの時間は、測っていない。外部のリポジトリにワークフローと PR を作ることになるため。5分で足りるかは、未確認。
- ジョブの `continue-on-error` の結論が API でどう返るかは、実物で確かめていない。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| `markReady` で外した時刻を覚える呼び出しを、単独で守るテストが無い（消しても、足したテストは通る）。同じ先頭のまま再提出した PR（指摘をすべて断った提出）で、前の提出の間に読み終わりにしていたときに、実害が出る | 指摘の経路を、テストの偽物で組もうとして、組めなかった。レビューの子タスクが指摘なしにした回は、指摘として取り込まない（`sactyReviewsOf`）ので、指摘なしで外した後に、同じ子タスクから AI のレビューの指摘が届くことは無い。届くのは、同じ PR を別の sacty のレビューのタスクがレビューしたときで、その組み立ては足していない。代わりに、指摘なしで外したときに `notePullRequestUndrafted` が呼ばれることを、1件目のテストで確かめる形にした（呼び出しを消すと落ちる）。指摘なしで外す経路だけでは、覚えた時刻が、最初に読んだ時刻と同じになり、読み取りの結果には表れないため |
| 1件目のテストの名前が、確かめている内容より広い | 名前を、確かめている内容（外した時刻を覚えること・その先頭の最初の読み取りでは読み終わりにしないこと）に直した |
| 画面とユーザードキュメントの「最初に読んでから1時間ほどの間だけ」が、読み終わりを取り消した後に合わない | 画面の補足（`apps/web/src/i18n/messages/tasks.ts`・`task.ts` の日英）、ユーザードキュメント（日英）、仕様書（日英）、定数の説明を、「先頭のコミットごとに12回まで（ふつうは、最初に読んでから1時間ほどの間）」に直した。回数の上限は変えていない |
| 同じ先頭での「失敗 → 回復（読み終わりにしない）→ 失敗の出し直し」を通すテストが無い | 足した（`daemon-step-pull-requests.test.ts`）。記録の順序（失敗・回復・失敗）と、読む回数が上限（12回）に収まることを確かめる。ドラフトを外した時刻を見ない・外し直しで時刻を覚えない、のどちらに戻しても落ちる |

## 残したこと

- ジョブの `continue-on-error` で「CI 失敗」が出て消えないか、の確認と、その扱い。
- 人が GitHub でドラフトを外したことで始まる CI は、その先頭を読み終わりにした後に始まると、拾わない。
- 回数の上限に達した先頭は、その後にドラフトを外しても、読まない。
