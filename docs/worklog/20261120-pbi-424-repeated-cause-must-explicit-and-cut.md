# 再レビューで同じ原因の要修正が続いたら、本文に明示し、原因を断つ直しと性質のテストを求める

- 日付: 2026-11-20（UTC）
- タスク: PBI-424
- PR: なし
- ブランチ: なし
- 関係する ADR: [20261121-0000-repeated-cause-must-explicit-and-cut.md](../adr/20261121-0000-repeated-cause-must-explicit-and-cut.md)

## 目的

同じ原因の `must` が再レビューで続いても、本文に書かれず、直し方の案が現れを塞ぐ手当てに戻り、実装も同じ原因の現れを探さないため、往復が続いた。

## したこと

- 既定のスキル（`aggregation.md` に本文を1か所置き、`pr-review.md`・`self-review.md`・`C-17.md` はそれを指す）と、指示の文（`prompts.ts` の再レビュー・セルフレビュー・実装のやり直し）に、明示と原因を断つ直しの決まりを足した。3項目は定数にして、再レビューとセルフレビューで共有した。
- 性質のテストの求めは、テストを書く場面（主対象が code で、文書だけでも、テストなしでもない）にだけ出す。設計書・利用者向け文書・テストなしでは、明示・原因を断つ直し・数え上げまでにした。
- 設計書の観点 D-3 に、取り消せない害を防ぐ処理の境目の数え上げを見る項目と NG 例（例7）を足した。
- 仕様書（日英）と ADR を直した。ADR の日時 `20261121-0000` は、既存の最新の ADR より後に並べるため、書いた日より後にしてある（人が、このままでよいと決めた）。

## 確かめたこと

- `prompts.test.ts`・`default-skills.test.ts`：文が入る場面と、入らない場面（初回・テストなし・文書だけ・取り下げと後続に回す案だけ・設計の工程）を確かめた。
- `npm run lint`・`npm run typecheck`・`npm test` の結果は、PR の本文に書いた。

## 残したこと

- `docs/user/intake.md` の「再レビュー」の節には書いていない（人が、不要と決めた）。
