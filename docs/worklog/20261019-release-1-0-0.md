# 版を 1.0.0 に上げ、GitHub Release を作る

- 日付: 2026-10-19（UTC）
- タスク: なし
- PR: なし
- ブランチ: chore/release-1.0.0
- 関係する ADR: [版は 1.0.0 から semver で付け、タグと GitHub Releases でリリースする](../adr/20261019-2345-semver-releases.md)

## 目的

主要な機能が揃ったので、1.0.0 として最初のリリースを作る。版の付け方とリリースの手順を決め、CONTRIBUTING に残す。

## したこと

- 4 つのパッケージ（`apps/daemon`・`apps/web`・`packages/core`・`packages/cli`）の `version` とワークスペースの依存を `1.0.0` にし、`package-lock.json` を
  `npm install --package-lock-only` で更新した。
- 既定のイメージの名前（`apps/daemon/src/config.ts` の `DEFAULT_IMAGE`）を `sacty-agent:1.0.0` にし、仕様書（`agent-execution`・`configuration`）・
  ユーザードキュメント（`config`・`images`）の日英と、イメージの名前を書いているテスト（`image.test.ts`・`services.test.ts`・`agents.test.ts`）を
  同じ版にした。ゲートウェイの MCP クライアントの版の文字列（`host-mcp.ts`）も `1.0.0` にした。
- `CONTRIBUTING.md` に「リリース」の節（版の上げ方・タグ・GitHub Release の作り方）を足し、ADR を足した。
- ADR・過去の作業履歴の `0.1.0` は、当時の記録なので直していない。

## 確かめたこと

- `npm run lint`：通過（354 ファイル）。`npm run typecheck`：通過。`npm run build`：通過（`apps/daemon/dist/config.js` の `DEFAULT_IMAGE` が `sacty-agent:1.0.0`）。
- `npx vitest run`：119 ファイル・2330 件が通過。
- `package-lock.json` は `npm install --package-lock-only` で作り直し、ワークスペースの 4 パッケージの版だけが変わった（10 行）。
- 実際のイメージの作り直し（`npx sacty image build`）と、更新後のデーモンの起動は手元では確かめていない。運用の環境で、更新の後にイメージを作り直して
  タスクが動くことを確かめる。
