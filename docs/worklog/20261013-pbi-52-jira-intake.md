# JIRA のチケットを取り込み、オーケストレーターがゲートウェイ経由でトリアージする

- 日付: 2026-10-13（UTC）
- タスク: PBI-52
- PR: #62
- ブランチ: feat/issue-52-jira-intake
- 関係する ADR: [JIRA のチケットは、gateway.platforms の接続先をそのまま使い、プロジェクトに書いた取り込み先からラベルで取り込む](../adr/20261013-0819-jira-intake-via-gateway-platforms.md)、[取り込んだチケットは、オーケストレーターがゲートウェイ経由で読んで作業するリポジトリ・題・概要を決め、決められなければ人がリポジトリだけを選ぶ](../adr/20261013-0819-superseded-ticket-triage-by-orchestrator.md)

## 目的

JIRA（Jira Cloud・Jira Server / Data Center）のチケットを、ラベルで取り込んでタスクにする。受け入れ条件の要点は次のとおり。

- プロジェクトに取り込み先を複数書け、接続先は `gateway.platforms` から選ぶ。
- ラベルの付いた終わっていないチケットを二度取り込まずに取り込み、On/Off で止められる。
- オーケストレーターがゲートウェイ経由で読み、リポジトリ・題・概要を決め、理由を作業履歴に残す。選べなければ止まり、画面で選んで再開できる。
- 調査の結果と PR の URL をチケットにコメントする。JIRA の認証は、コンテナ・作業履歴・ログ・画面に出ない。Cloud と Server / DC の両方で動く。

## したこと

- プロジェクトの設定（`packages/core/src/projects.ts`・`apps/web/src/components/project-editor.tsx`）：取り込み先（接続先・種類・キー）を
  複数書ける。同じ接続先の同じキーは 1 つのプロジェクトにだけ。
- 「sacty の設定」（`apps/web/src/components/settings-form.tsx`）：チケットの取り込むラベルと On/Off（PBI-53 の形）。
- 検索（`apps/daemon/src/tickets.ts`・`apps/daemon/src/intake.ts`）：Cloud は `/rest/api/3/search/jql`（nextPageToken）、Server / DC は
  `/rest/api/2/search`（startAt）。1 回に最大 10 ページ読み、続きの位置を次の回に引き継ぐ。
- トリアージ（`apps/daemon/src/service.ts`・`apps/daemon/src/prompts.ts`）：オーケストレーターがチケット（サブタスクなら親とほかの
  サブタスク）を読み、リポジトリ・題・概要を書く。選べなければ止め、タスクの画面（`apps/web/src/components/resume-form.tsx`）で
  リポジトリを選んで再開する。人が選んだら、そのリポジトリに固定して読み直す。概要が空なら止める。
- 結果の書き戻し：調査の結果と PR の URL をチケットにコメントする（状態は変えない）。
- 安全：`allow` に無い API はデーモンも呼ばない。失敗の理由の認証の値は伏せてから切り詰める。コンテナには実行ごとのゲートウェイの
  トークンだけを渡す。
- `README.md`：JIRA の設定の例（Server：Bearer、Cloud：Basic）。不要な表現も直した。
- 対象ごとのイメージ（PBI-41）が、プロジェクトのエクスポートから漏れていたのを直した。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| 検索が毎回先頭から 10 ページで打ち切られ、続きを返さないので、対象が 500 件を超えると残りを取り込めない（Cloud・Server とも 501 件目に届かないことを再現） | 上限で止めたら続きの位置（Server：startAt、Cloud：nextPageToken）を返し、取り込みは検索の条件ごとにその位置を持って次の回に読む。最後まで読んだら先頭に戻り、失敗したら先頭から読み直す。テストを足した |
| リポジトリを決められなかった出力の題・概要が捨てられ、人がリポジトリを選んだ後は要件が定型文のまま工程の選択に進む | 人の選択はリポジトリの曖昧さだけを解消するものにし、選んだリポジトリに固定してチケットを読み直し、題と概要を書く。書けなければ止まって選び直せる。テストを足した |
| 題だけ読めて概要が空でも成功扱いになる経路が残っている（人が選んだ経路・通常の経路の両方） | 概要を必須にし、どちらの経路でも概要が空なら失敗として止める。テストを足し、条件を戻すと落ちることを確かめた |

## 残したこと

- 実際の JIRA（オンプレと Cloud）で、取り込み・チケットの読み取り・コメントができることを、利用者の環境で確かめてもらう。
- `allow` に README の例の API を書いていることを、利用者に確かめてもらう。
