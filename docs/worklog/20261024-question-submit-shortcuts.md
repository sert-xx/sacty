# オーケストレーターへの質問に送信ショートカットを追加する

## 目的

質問欄で Ctrl + Enter と ⌘ + Enter を使い、ボタンと同じ結果で送信できるようにする。

## したこと

質問欄のキーイベントからフォームを送信し、IME と余分な修飾キーを除外した。
描画前の連続入力にも同期的な送信ガードを設けた。
日英の仕様書とユーザードキュメントを更新した。

## 確かめたこと

- `npm run lint`・`npm run typecheck`・`npm run build`：成功。
- 初回の `npx vitest run`：2619 件成功、17 件失敗。
  16 件は変更していないプロセス後始末のテストで、PID 1 が Node.js のコンテナにゾンビが残る環境上の失敗。
  文書のコード参照検査は並行実行時に 5 秒を超え、単独の再実行は成功。
- 修正後の `npx vitest run`：2622 件成功、16 件失敗（同じプロセス後始末の5ファイル）。
  文書検査と Chromium のテストは成功。
- 質問フォームの DOM テスト 28 件は成功。
  ショートカット処理を一時的に除くと 14 件が失敗し、処理を復元した。
- Chromium で実際の質問フォームを描画し、Enter と Shift + Enter で「前後」のカーソル位置に改行が1つ入ることと、上限では改行が入らないことを確認した。
  Playwright と Vite を開発依存に加え、通常の Vitest コマンドから実行する。
- jsdom では変換中のイベントを検証した。
  macOS と Windows の実機 IME はこの Linux 環境では確認できない。

## レビューの指摘と対応

初回：改行操作のテストが標準動作を妨げないことしか検証していないという must 1 件（UI 観点の同内容の should 1 件と統合）。
Chromium 上で実際の質問フォームを操作し、入力値とカーソル位置、未送信、上限での改行抑止を確かめるテストを追加した。
2 回目はコード・テスト・依存・準備手順・文書の 15 観点すべてで指摘なし。
修正後の lint・型検査・ビルドは成功し、質問フォームと文書の 123 件も成功した。

## 残したこと

macOS 標準日本語入力と Windows Microsoft IME の実機検証。

## 再検証で確認した制約

実行環境は `uname -s` が `Linux`、`/proc/1/exe` が `/usr/bin/node` のコンテナ。
利用可能なツールには macOS・Windows の実機を操作する手段がない。
R-6 のイベント単体テストが成功しても、承認済みの実機確認が済んだとは扱わない。
実機確認が終わるまでは、受け入れ確認は未完了。

### 実機 IME の確認手順（未実施）

macOS 標準日本語入力と Windows Microsoft IME のそれぞれで、次を確認する。
OS・ブラウザー・入力方式の版と、確認したキー操作を記録する。

ブラウザーからは Next.js の Server Action を呼び、そのサーバー側でデーモンの質問 API を呼ぶ。
デーモンの `/questions` 通信をブラウザーの Network で直接観測することはできない。
このフォームでは、質問送信の Server Action が呼ばれなければ、デーモンへの質問要求も発生しない。
以下では正常送信で観測対象を特定し、変換中にその要求が発生しないことを確認する。

1. 質問できる確認用タスクのパネルを開き、ブラウザーの開発者ツールで Network の記録を始める。
   種類や URL のフィルターは解除する。
2. 変換を確定した質問をボタンで送り、発生した POST の `Next-Action` ヘッダーを記録する。
   その要求が1件発生し、質問が1件記録されることを確認する。
   この正常送信を観測できなければ、以降は合否を判定しない。
3. 回答待ちでない別の確認用タスクを開き、質問の件数を記録し、Network の記録を消去する。
   同じ画面で、質問欄に日本語を入力し、変換候補が出た未確定の状態で Ctrl + Enter を押す。
4. 手順2で特定した質問送信の Server Action の要求が 0 件で、質問の件数も増えないことを確認する。
   変換の確定や質問欄の内容は合否に含めない。
5. 再び未確定の変換状態を作り、⌘ + Enter（Windows では Meta + Enter）でも同じ確認をする。
   OS が先に受け取りブラウザーに届かない組み合わせは、承認済みの確認方法に従って対象外と記録する。
6. 比較として変換を確定してからショートカットを押し、同じ Server Action の要求と質問の記録が各1件増えることを確認する。
   次の確認には回答待ちでないタスクを使う。

## 全体テストの環境を整えた再検証

PID 1 が Node.js の Linux コンテナでは、終了した孤児プロセスが回収されない。
今回、検証コマンドの親に Linux の child subreaper を設定した Python プロセスを置き、孤児を `waitpid` で回収しながら実行した。
Python の `ctypes.CDLL(None).prctl(36, 1, 0, 0, 0)` で設定し、起動したコマンドの終了コードと、引き取った子孫の終了をそれぞれ回収した。
テスト・期待値・Vitest の設定は変えていない。
この環境調整は検証プロセス内だけで、アプリの起動処理には加えていない。

- `npm ci`：成功。
- `npx playwright install chromium`：成功。
- `npm run lint`：成功。
- `npm run typecheck`：成功。
- `npx vitest run`：137ファイル・2,638件すべて成功、終了コード0。
  前回失敗したプロセス後始末の16件と、質問フォームの30件を含む。
- `npm run build`：成功。

CONTRIBUTING.md に、CI でも `npm ci` 後に `npx playwright install --with-deps chromium` でブラウザーと OS の依存を準備する手順を追記した。
このリポジトリに CI ワークフローは無いため、ワークフローの変更はしていない。

R-6 の macOS 標準日本語入力・Windows Microsoft IME による実機確認は引き続き未完了。
Linux のコンテナと利用可能なツールでは両 OS の実機を操作できず、全体テストの成功を実機確認の代わりには扱わない。

今回の自己レビューは C-1〜C-7・C-10・C-11・C-13・C-14・U-1・U-2・U-6・X-1・X-2 の16観点で実施した。
残った指摘は C-4・C-13・X-2 で共通の、R-6 の実機 IME 確認未完了という must 1件。

## 実行ログの順序テストを安定させる

指定された一連のコマンドを再実行すると、全体テストは2,637件成功・1件失敗した。
失敗した `apps/daemon/src/question-logs.test.ts` を1回再実行しても同じ失敗となり、独立したビルドは成功した。

原因は、実行ログを現在時刻で作り、作成時刻順の結果に `r-req`、`r-design` の順を期待していたこと。
両者が同じミリ秒に作られる場合、その順序は保証されない。
このテストだけで Date を固定し、2件の作成時刻を1秒ずらした。
期待値と製品のログ処理は変更していない。
テスト終了後は実時刻に戻す。
