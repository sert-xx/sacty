# 不安定なテストの台帳を、プロジェクトごとに持つ

- 日付: 2026-11-06（UTC）
- タスク: PBI-312
- PR: #318
- ブランチ: feat/issue-312-flaky-ledger
- 関係する ADR: [不安定なテストの台帳を作業履歴から導き、提案は人が作るタスクにする](../adr/20261106-1105-derive-flaky-test-ledger-from-activity.md)

## 目的

認めた不安定な失敗をプロジェクトごとに集計し、何度も見たテストの実行し直しを省けるようにして、直すタスクを提案する。

## したこと

- `flakySightings`（すべての回の認めた失敗）と、集計の `flakyTests`・`knownFlakyTests` を足した。
- 最終レビューの指示に既知のテストをデータとして渡し、`checkFlakyFailures` に既知のテストの入力を足した。
- `GET /api/projects/:id/flaky-tests` と、監査の画面の「不安定なテスト」の欄を足した。提案はタスクの作成のダイアログを、内容を入れて開く。
- `TaskCreated`・`CreateTaskInput` の `flakyFix` で、直すタスクと台帳をつないだ。
- 撮影の `seed.mjs` に過去のタスクを足し、`capture.mjs` の単価に今の既定のモデルを足した（無いと設定を読めず、認証が OFF にならず撮れなかった）。`audit` を撮り直し、`audit-flaky-tests` を足した。
- 仕様書・ユーザードキュメント（日英）、ADR。

## 確かめたこと

- `npm run lint`・`npm run typecheck`：通った。
- `npx vitest run --no-file-parallelism`：210 ファイル、4251 件が通った（3 件は既存のスキップ）。
- `npx vitest run tests/docs`：通った。
- 修正を一時的に戻して、12 通りすべてでテストが失敗することを確かめた：同じタスクの数え方・プロジェクトの絞り込み・しきい値・リポジトリの絞り込み・マージ後の数え直し・直すタスクの表示・差分の確認・台帳の照合（2 通り）・提案の条件・全回の記録・最終レビューの確認への受け渡し。
- 撮影の仕組みで実際の画面を動かし、提案のボタンで題・内容・対象リポジトリ・直すテストが入ったダイアログが開くこと、作成するとタスクができ、提案が消えることを確かめた。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| 下書きの内容に PR のリンクを入れると、タスクが扱う PR と読まれる | 内容に書かないようにし、テストで確かめた |
| 画面に出す文のうち、題しか伏せていない | 名前・ファイル・根拠も伏せた |

## 残したこと

提案から作らずに直したテストの扱いと、既知のままの期限は決めていない。
