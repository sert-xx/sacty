# 不安定なテストの台帳を、プロジェクトごとに持つ

- 日付: 2026-11-06（UTC）
- タスク: PBI-312
- PR: #318
- ブランチ: feat/issue-312-flaky-ledger
- 関係する ADR: [不安定なテストの台帳を作業履歴から導き、提案は人が作るタスクにする](../adr/20261106-1105-derive-flaky-test-ledger-from-activity.md)

## 目的

認めた不安定な失敗をプロジェクトごとに集計し、何度も見たテストの実行し直しを省けるようにして、直すタスクを提案する。

## したこと

- `flakySightings`（すべての回の認めた失敗）と、集計の `flakyTests`・`knownFlakyTests` を足した。
- 最終レビューの指示に既知のテストをデータとして渡し、`checkFlakyFailures` に既知のテストの入力を足した。
- `GET /api/projects/:id/flaky-tests` と、監査の画面の「不安定なテスト」の欄を足した。提案はタスクの作成のダイアログを、内容を入れて開く。
- `TaskCreated`・`CreateTaskInput` の `flakyFix` で、直すタスクと台帳をつないだ。
- 撮影の `seed.mjs` に過去のタスクを足し、`capture.mjs` の単価に今の既定のモデルを足した（無いと設定を読めず、認証が OFF にならず撮れなかった）。`audit` を撮り直し、`audit-flaky-tests` を足した。
- 仕様書・ユーザードキュメント（日英）、ADR。

## 確かめたこと

- `npm run lint`・`npm run typecheck`：通った。
- `npx vitest run --no-file-parallelism`：210 ファイル、4251 件が通った（3 件は既存のスキップ）。
- `npx vitest run tests/docs`：通った。
- 修正を一時的に戻して、12 通りすべてでテストが失敗することを確かめた：同じタスクの数え方・プロジェクトの絞り込み・しきい値・リポジトリの絞り込み・マージ後の数え直し・直すタスクの表示・差分の確認・台帳の照合（2 通り）・提案の条件・全回の記録・最終レビューの確認への受け渡し。
- レビュー1回目の対応の後：`npm run lint`・`npm run typecheck`・`npx vitest run tests/docs` が通り、`npx vitest run --no-file-parallelism` は 210 ファイル、4367 件が通った（3 件は既存のスキップ）。
  修正を一時的に戻して、6 通りすべてで新しいテストが失敗することを確かめた：やり直しでの引き継ぎ・違うリポジトリでの作成の拒否・子孫のマージ・途中の `..` の解決・回数が不正な申告の拒否・サロゲートペア。識別子の照合は、台帳に無い識別子と別のプロジェクトで見つからないことをテストで確かめた。
- 撮影の仕組みで実際の画面を動かし、提案のボタンで題・内容・対象リポジトリ・直すテストが入ったダイアログが開くこと、作成するとタスクができ、提案が消えることを確かめた。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| 下書きの内容に PR のリンクを入れると、タスクが扱う PR と読まれる | 内容に書かないようにし、テストで確かめた |
| 画面に出す文のうち、題しか伏せていない | 名前・ファイル・根拠も伏せた |
| 既知のテストで、`runs`・`passes` の欠落や整数でない値も、実行し直しを省いたものと認める | 元の値がどちらも 0 のときだけ省くようにし、欠落・`1.5`・文字の申告を拒むテストを足した |
| 直すタスクを分割すると、子の PR のマージを見ず、古い記録が残る | 子孫のタスクの PR のマージも数えるようにし、孫のマージで数え直すテストを足した |
| 画面の名前・ファイルは伏せた値で、`flakyFix` に保存すると元の記録と一致しない | 台帳の各件に識別子（ハッシュ）を持たせ、作成の入力は `flakyFixTest` で識別子だけを送るようにした。sacty が台帳から伏せる前の値を探し、無い識別子・違うリポジトリでは作らない |
| `rerunTask` が `flakyFix` を引き継がない | 同じリポジトリでやり直すときだけ引き継ぐようにし、テストを足した |
| 途中の `.` と `..` をそろえず、同じテストを別に数える | 最終レビューと同じく解決して比べるようにした |
| 実行し直しを省いた失敗にも「実行し直すと結果が変わった」と出る | 合格の注記と画面の文に、既知のテストは省いたことを書いた（日英） |
| 画面にリポジトリが出ず、同じ名前・パスのテストを区別できない | 各件にリポジトリを出した |
| 切り詰めがサロゲートペアの途中で切る | ペアの途中では切らないようにし、テストを足した |
| （2回目）テストのコマンドが無いタスクで CI の結果から認めた `ciFlakyFailures` が台帳に入らない | `reviewFlakyFailures` で両方を `flakySightings` に入れるようにし、テストを足した。修正を戻すとテストが失敗することを確かめた |
| （3回目）テストのコマンドが無く CI だけを見るタスクで、既知のテストの一覧と実行し直しの省き方が指示に入らない | PR の CI を見るときも `knownFlakyLines` を渡すようにし、テストを足した。修正を戻すとテストが失敗することを確かめた |

## 残したこと

提案から作らずに直したテストの扱いは決めていない。既知のままの期限は、今は設けないと人が決めた（2026-11-06）。
