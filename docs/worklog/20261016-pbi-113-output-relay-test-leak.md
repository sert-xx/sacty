# 出力の中継のテストが、失敗・時間切れでも中継とコマンドを残さないようにする

- 日付: 2026-10-16（UTC）
- タスク: PBI-113
- PR: #122
- ブランチ: feat/issue-113-output-relay-test-leak
- 関係する ADR: なし

## 目的

`apps/daemon/src/agents/output-relay.test.ts` の「中継がコンテナの標準出力に書けなくなったら、コマンドを止めて、失敗で終わる」
が起動したコマンド（`setInterval(() => process.stdout.write("x".repeat(1024)), 1)`）が、親を失って35時間動き続け、
消された一時ファイル（`$TMPDIR/sacty-output-*/1`）に書き続けていた。2つで約200GB のディスクを使った。

テストが成功しても、失敗・時間切れでも、テストが起動した中継・コマンド・その子孫を必ず止める。止め忘れても、止まらない
コマンドが自分で終わるようにする。中継の本体が、書けなくなったときにコマンドを止めているかも確かめる。

## したこと

### 原因

- テストは、起動した中継・コマンドを自分では止めず、中継がコマンドを止める（SIGKILL）ことと、テストが最後まで進むことに
  頼っていた。テストが時間切れになると、Promise を待ったまま終わり、中継とコマンドを止めるものが無い。
- 作業の時点で、親が 1 に付け替えられた中継とコマンドが、別に4組（2日以上）残っていた。コマンドは「止めるシグナルは
  コマンドに伝え、…」のテストのもの（`process.on("SIGTERM", ...)` で、`setInterval(() => {}, 1000)` で動き続ける）。
  コマンドの出力のファイルには `ready;` が書かれていたので、中継はそれを流したが、テストがシグナルを送る前に時間切れで
  終わったと見られる。中継は、出力が無いと書かないので、親が消えたことに気づかず、待ち続ける。
- 報告の `setInterval` で書き続けるコマンドが残った経路は、再現できなかった（中継が一時ファイルを消すのは、コマンドに
  SIGKILL を送った後なので、今の中継で、ファイルが消されてコマンドだけが残る経路は見つからなかった）。どの経路でも、
  テストが自分で止めれば残らないので、テストの側で止める。

### 中継の本体（直さなかった）

- 書けなくなったら（EPIPE など）、コマンドに SIGKILL を送ってから一時ファイルを消し、失敗で終わる。親（テストのプロセス）
  を SIGKILL で消して確かめると、読み手が読み続けているとき・止めているときのどちらも、中継とコマンドは消えた。
- コマンドの子孫には SIGKILL を送らないが、本番では中継は `docker run --rm` のコンテナの最初のプロセスなので、中継が終わると
  コンテナごと止まる。そのため本体は直していない。

### 直したこと（テスト）

- `run` は、中継（とテストのコマンド）を自分のプロセスグループで起動し（`detached: true`）、グループを覚える。afterEach と
  afterAll で、PBI-94 の `killSpawned` に覚えたグループを渡し、グループごと SIGKILL で止める。中継が先に終わって親が
  付け替えられたコマンド・その子孫も、グループで止める。
- 止められるまで動き続けるコマンドに、自分で終わるまでの上限（`SELF_EXIT_MS`、60 秒）を付けた。Vitest ごと止められて
  後始末が動かなくても、長くは残らない。テストの時間切れより十分長いので、止めたことを確かめるテストが、自分で終わったのを
  止めたと取り違えない。
  - 「止めるシグナルは…」のコマンド（`setInterval(() => {}, 1000)` を、60 秒で終わる `setTimeout` に）
  - 「中継がコンテナの標準出力に書けなくなったら…」の書き続けるコマンド（60 秒で終わる）
  - 「コマンドが終わったら、後ろで書き続けるプロセスがあっても…」の後ろのプロセス（合図の待ちと書き込みを、回数で数えて
    それぞれおよそ 60 秒で終わる）。後始末をグループで止めるようにしたので、PID のファイルを読んで止める `finally` は
    やめた（ファイルが無いと、本来の失敗を隠して例外を投げていた）。
- 非ブロッキングの状態を作るための後ろのプロセス（`nonBlocking`）は、もともと 30 秒で終わるので、そのまま。

## 確かめたこと

- わざと失敗・時間切れにする変更（「止めるシグナル」のシグナルを送らない・「書けなくなったら」の読み手を閉じない・
  「後ろで書き続ける」の終了コードの期待を変える）をしたテストのファイルを一時的に作り、`npx vitest run` で流した。
  - 直す前のテスト：3つ落ち、「止めるシグナル」の中継とコマンドが、親が 1 に付け替えられて残った（作業の時点で残っていた
    4組と同じ形。確かめた後、手で止めた）。
  - 直した後のテスト：同じ3つが落ちるが、残るプロセスは無い。
  - 直した後のテストを流している途中で、Vitest のプロセスを SIGKILL で止めた（後始末が動かない）。直後は中継とコマンドが
    1組残ったが、60 秒後には自分で終わって消えた。
- 中継の本体の、書けなくなったときの `child.kill("SIGKILL")` を一時的に外すと、「書けなくなったら」のテストは
  「止めたコマンド（PID …）が消えること」を待ちきれずに落ちる（上限やグループでの後始末が、本体の不具合を隠さない）。
  そのとき書き続けていたコマンドも、後始末で止まって残らなかった。戻すと通る。
- 全体の `npx vitest run` を3回続けて流した（77 ファイル・1634 テスト、3回とも通り、終了コード 0）。終わった後に
  `ps -A -o pid=,ppid=,etime=,command= | grep -E "setInterval|sacty-host-mcp-processes|const fs = require|echo late|sleep 30[0-9]"`
  が空だった。
- `npm run lint`（終了コード 0）・`npm run typecheck`・`npm run build`・`npx vitest run tests/docs` が通った。
- 作業ツリーの `node_modules` に `jsdom` が入っておらず、最初の全体の実行は、Web の2つのテストのファイルを始められずに
  終了コード 1 になった（変更とは関係ない）。`npm ci` で入れ直してから流し直した。

### 手で確かめる手順

テストの後に、次が空であることを確かめる。

```bash
ps -A -o pid=,ppid=,command= | grep -E "setInterval|const fs = require|echo late" | grep -v grep
```

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| （DA のセルフレビュー）「後ろで書き続ける」の後ろのプロセスは、合図のファイルを待つ間も止まらない（一時ディレクトリが消えると、ずっと待つ） | 待ちも回数で数えて、およそ 60 秒で終わるようにした |
| （DA のセルフレビュー）上限や後始末が、中継がコマンドを止めない不具合を隠さないか | 本体の SIGKILL を外すと落ちることを確かめた（上限の 60 秒は、テストの時間切れより十分長い） |
| （DA のセルフレビュー）終わったグループの番号が、後始末までに別のプロセスのグループに使い回されると、それを止める | PBI-94 の `killSpawned` と同じ前提。番号がグループの番号になるのは、新しくグループを作ったプロセスだけで、1つのテストの間に使い回される見込みは低いので、受け入れる |
| （DA のセルフレビュー）`finally` で PID のファイルを読むと、ファイルが無いときに本来の失敗を隠す | グループで止めるので `finally` をやめた |

## 残したこと

- 時間切れの後も動き続けたテストの本体が、後始末の後にさらに起動したもの（例：「流した分は、穴を開けて捨てる」の2回目の
  中継）は止められない。どれも自分ですぐ終わるコマンドなので、長くは残らない。
- 中継は、出力が無いあいだは親が消えたことに気づかない。本番ではコンテナの中で動くので、直していない。
