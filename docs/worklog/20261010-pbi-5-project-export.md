## 目的

PBI-5 の後半（PBI-5b、受け入れ条件6）。前半は #8 でマージ済み。プロジェクトの定義をエクスポート・インポートでき、個人の設定と
秘密情報を含めず、インポートの時にも重複を検査することが要点。

## したこと

- 定義の書き出しと読み込み・検査（`packages/core/src/projects.ts`）：名前・取り込み元・リポジトリの設定だけを取り出し、形式・版・各階層の知らない項目を検査する。
- デーモン（`apps/daemon/src/server.ts`・`service.ts`）：エクスポートとインポートの API。インポートは作成と同じ重複の検査を通す。
- 画面：設定画面の「エクスポート」（`apps/web/src/app/projects/[id]/export/route.ts`、日本語のファイル名は `filename*`）と、
  プロジェクトの画面のインポート（`apps/web/src/components/import-project-form.tsx`、1MB まで）。

## 確かめたこと

- `npm test` が全件通った（138件。4件追加）。エクスポートの内容（ID・日時を含まない）、書き出したものをそのまま読めること、形式・版・知らない項目の拒否、
  重複の拒否と重複しない環境へのインポート、API の 200・404・400・409・201 を確かめた。
- 画面で、エクスポートの応答（日本語のファイル名、定義だけの内容）、同じファイルのインポートが重複として拒否されること、Org を変えたファイルなら
  新しいプロジェクトとして作られて設定画面が開くこと、JSON でないファイルを拒否すること、幅 375px で横スクロールが出ないことを確かめた。
- レビューでは `npm test`（138件）・`npm run lint`・`npm run typecheck` が通った。ブラウザでのファイルの選択・ダウンロードの操作は、レビューでは確かめていない。
