# 同じ内容で実行済みの検証の結果を、後の段で使い回す

- 日付: 2026-11-06（UTC）
- タスク: PBI-305
- PR: なし
- ブランチ: claude/determined-hopper-o2zt0g
- 関係する ADR: [同じ内容で実行済みの検証は、記録と CI の結果を使い回し、覆われていない分だけを実行する](../adr/20261106-0005-reuse-verification-results-for-same-content.md)

## 目的

実装の PR を1つ出すまでに、同じ内容（コミット）に対して、実装のセルフレビュー・ドラフトの PR の CI・ゴールガーディアンの最終レビュー・レビュー用のラベルで始まる PR のレビューで、同じ検証が重ねて実行されていた。トークンと時間を減らすため、使い回せる結果はなるべく使い回す。

利用者の条件：

- 一部のテストしか実行していない段の結果で、全体を省かない。
- CI が無いリポジトリもあるので、CI で確かめられるはずだと見なして省かない。
- CI は資源の都合で段階的に実行することがあるので、決まった規則ではなく、エージェントが柔軟に判断する。
- 検証の結果は同じ内容なら決まるので、実装の工程（セルフレビュー）の結果も使い回す。

## したこと

- 台帳：`VerificationRecord`（コマンドごとの種類・コマンド・覆った範囲 `full`/`partial`・結果・抜粋・実行した段）を足し、`AgentRunCompleted`（実装の工程）と `FinalReviewed`（ゴールガーディアン。実装の PR の CI のコミットを付ける）に持たせた。`GuardianTests` に `reusedFrom` を足した。タスクの `implementVerification` は、ベースブランチの取り込み・本文の差し替えで消す（`packages/core/src/events.ts`・`projection.ts`）。
- 指示と読み取り：`apps/daemon/src/verification-reuse.ts` に、記録の申告の指示（実装・ゴールガーディアン）、記録の読み取り、使い回しの指示（`reuseVerificationLines`）をまとめた。
  - 実装：最後の変更の後に実行した検証だけを申告させ、提出の前の検証とセルフレビューの検証を同じ内容で重ねさせない。記録は実装の説明（PR の本文）から取り除く。
  - 最終レビュー：実装の工程の記録と CI の結果を渡し、テストのコマンドの全体が覆われていれば実行せずに使い回させる。記録も読める CI も無ければ、指示を足さない。
  - PR のレビュー：sacty が作った PR で、元のタスクの最終レビューの記録のコミットが PR の先頭と同じときだけ渡す（`TaskService.reviewVerification`）。「CI の結果を自分で実行した結果の代わりにしない」を、全体を覆うと確かめたものは使い回す、に変えた（作者の報告は、これまでどおり使い回さない）。
- 既定のスキル `verification-run` に「1.5 使い回せる結果を探す」を足し、`summary.json` に `coverage`・`reused_from` を足した。再レビューの「前回のログを使い回さない」は、修正で内容が変わるので使い回さない、と理由を書いた。
- 画面と PR の本文：使い回したテストに「実装の工程の結果を使い回し」「PR の CI の結果を使い回し」を出し、PR の本文のテストの行に使い回したことを添えた。
- docs：仕様書（`tasks-and-steps` の「同じ内容の検証の使い回し」・PR のレビューの検証、`context` の既定のレビュー用スキル）、ユーザードキュメント（`tasks` の「実装の PR と CI」）を日英で直した。ADR を足し、PBI-153 の ADR を一部の置き換え（CI の結果の扱い）として `superseded` にした。

## 確かめたこと

- `npm run lint`：通った。
- `npm run typecheck`：通った。
- `npm run build`：通った。
- `npx vitest run`：4144 件が通り、17 件が失敗。失敗は `repository.test.ts`（9）・`host-mcp-processes.test.ts`（6）・`agent-sessions.test.ts`（1）・`context-mcp.test.ts`（1）・`question-form.browser.test.ts`。変更を外した状態でも同じファイル・同じ件数で失敗し、この環境の git の版・プロセスの扱い・ブラウザによるもの。
- 足したテスト：`verification-reuse.test.ts`（記録の読み取り・使い回しの指示・最終レビューと PR のレビューの指示・`reusedFrom`）、`projection.test.ts`（記録の保持と取り込みでの消去）、`daemon.test.ts`（実装の記録を最終レビューに渡し、ゴールガーディアンの記録を PR のコミットに結び付けて残す）、`labels.test.ts`・`final-review-human-checks.test.ts`（画面と PR の本文の表示）。
- 確かめられなかったこと：レビュー用のラベルで作ったレビューのタスクが、元のタスクの記録を受け取ることは、デーモンの通しのテストを書いていない（`reviewVerification` の照合は単純な比較で、指示に載せる部分は単体のテストで確かめた）。実際のエージェントが使い回しを正しく判断するかは、実タスクで確かめていない。
