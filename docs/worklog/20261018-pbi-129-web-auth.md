# 画面を、起動した本人のブラウザだけが使えるようにする

- 日付: 2026-10-18（UTC）
- タスク: PBI-129
- PR: #141
- ブランチ: feat/issue-129-web-auth
- 関係する ADR: [画面は、起動ごとの秘密で入ったブラウザだけが使える](../adr/20261018-0414-web-session-auth.md)

## 目的

工程のコンテナで動くコードが、画面を通して承認・設定の変更・他のプロジェクトの情報の読み取りをできないようにする（Codex Security の指摘）。

## したこと

- CLI：起動ごとに画面の入り口の秘密を作り、画面にだけ渡す（デーモンの環境からは取り除く）。端末に入り口の URL を表示する。
- 画面
  - Proxy（`proxy.ts`）：すべてのリクエストで Host（ループバックだけ）と、今の起動の cookie を確かめる。入り口の URL で cookie を渡す。
    断るときは、画面の部品を使わずに決まった文を画面の言語で返す。
  - デーモンへ中継する所（`daemonFetch`）でも cookie を確かめ直す。
- docs：仕様書（デーモンの起動と終了）、ユーザードキュメント（CLI・はじめに・README）、ADR。

## 確かめたこと

- `npx biome check`・`npm run typecheck`・`npx vitest run`・`npm run build` が通った。
- 次の修正を戻すと、テストが落ちることを確かめた：`daemonFetch` の確かめ直し、Proxy の cookie の確かめ、Host の確かめ、デーモンの環境から
  秘密を取り除くこと、cookie の名前のポート、cookie の `HttpOnly`、入り口の秘密の完全一致。
- デモ用のポートで `sacty up` を起動し、次を確かめた。
  - cookie の無い curl（画面・取り直し・Origin を偽った Server Action・誤った秘密）は 401。
  - 工程のコンテナ（`host.docker.internal` 経由）からは 403、Host・Origin を 127.0.0.1 に偽っても 401。
  - 入り口の URL を開いたブラウザは、127.0.0.1・localhost のどちらでも、画面・取り直し・Server Action（設定の保存）が今までどおり使える。
- 実機で見つけて直したこと：Proxy の転送先を相対パスにすると Next.js が 500 にする。`nextUrl` は 127.0.0.1 を localhost に置き換えるので、
  転送先を Host ヘッダーから作る（cookie を渡したホストから外れないように）。

## レビューへの対応

| 指摘 | 対応 |
| --- | --- |
| （提案）開いたままの画面で sacty を起動し直すと、取り直しの 401 が「デーモンに届きません」と出て、入り直せばよいことが分からない | 取り直しの 401 を、届かないのと分けた。詳細・一覧・ダッシュボード・実行のログなどの画面に「端末に表示された新しい URL を開いてください」、ヘッダーに「入り直してください」と日英で出す。実機で、起動し直した後に出て、入り直すと消えることを確かめた |

- 修正を戻すとテストが落ちることを確かめた（401 の区別・取り直しの理由の受け渡し・実行のログ・案内の文・ヘッダーの文）。
