# 版を 1.31.0 に上げる

- 日付: 2026-11-24（UTC）
- タスク: なし
- PR: #615
- ブランチ: feat/release-1-31-0
- 関係する ADR: [版は 1.0.0 から semver で付け、タグと GitHub Releases でリリースする](../adr/20261019-2345-semver-releases.md)

## 目的

1.30.0 の後に入った変更（PR #570〜#614 の 19 件）をリリースする。共用の compose の対象のリポジトリへのひもづけ（PR #590）、PR のレビューでのサービスの起動（PR #588）、再開の補足で受け入れた変更（PR #596）など、機能の追加なので MINOR を上げる。

## 1.30.0 からの変更

- 共用の compose を対象のリポジトリ・Org にひもづけ、ひもづいたリポジトリでは原則それを使う。複数の compose を同じネットワークで起動する（PR #590）。
- PR のレビューでも、実装で使ったサービスを起動して、DB などが要るテストを流せる（PR #588）。オーケストレーターがテストに要るサービスの compose を見落とさない（PR #584）。工程の担当が、この環境の docker・DB の使い方を先に知る（PR #581）。
- サービスの共通のネットワークとボリュームに持ち主の印を付け、デーモンの起動で残りを回収する（PR #609）。
- 再開の補足で人が方針を変えたとき、それに沿う承認済みの成果物の直しで人の判断待ちにしない（PR #596）。補足で受け入れた申し出の表示を読みやすくする（PR #601）。再開のときに人が決めた範囲を PR のレビューにも渡す（PR #613）。
- レビューの往復を減らす：再レビューで新しく出す要修正の絞り込み（PR #614）、同じ原因の要修正が続いたときの範囲を絞る案（PR #598）、要求要件・設計の PR の「提案あり」の繰り返し（PR #575）、作業履歴の書き漏れ（PR #570）、「判定なし」はレビューがまったくできなかった場合だけ（PR #579）。
- 実装の工程が、ベースの取り込みで入った変更と人がすると決まった確かめを「残り」に数えない（PR #593）。依頼と関係ないファイルを整形しないよう指示する（PR #595）。
- 実装の PR がマージされたタスクが、消えたブランチを取りに行くエラーで止まらない（PR #599）。マージで作り直しを止めたときの表示を直した（PR #604）。
- タスクの PR が、ほかのタスクの過去の作業履歴を書き換えないようにする CI の検査を足した（PR #608）。
- テストの待ちの期限の揺らぎを直し、`npm test` を CI と同じく並列にしない形にした（PR #573）。

## 互換性の判断

- 設定ファイル：共用の compose に、省略できる `forRepos` を足した。形を変えた項目は無い。1.30.0 の共用の compose の定義は知らない項目を読み飛ばすので、1.30.0 に戻しても読める（ひもづけは使われない）。
- 台帳：新しい種類のイベント（`ChangeAcceptedByNote`・`StepSuggestionsHeld`）と、既存のイベントの省略できる項目（サービスの起動の `compose.repo`、`PullRequestClosed` の `merged`）を足した。形を変えたものは無いので MAJOR にはしない。これらを記録した後に 1.30.0 に戻すと作業履歴を読めないので、リリースの説明の注意に書く。
- API：再開の入力に、省略できる `approvedEdits` を足した。
- デーモンの起動で、持ち主の印があり持ち主のプロセスが終わったネットワーク・ボリュームを消すことを、リリースの説明の注意に書く。
- `packages/cli/docker` の変更は無い。

## したこと

- 5 つのパッケージとワークスペースの依存の版を `1.31.0` にし、`package-lock.json` の版の行を直した。
- 既定のイメージの名前（`DEFAULT_IMAGE`）を `sacty-agent:1.31.0` にした。
  同じ版にしたもの：仕様書（`agent-execution`・`configuration`）とユーザードキュメント（`config`・`images`）の日英、イメージの名前を書いているテスト・コメント、ゲートウェイの MCP クライアントの版の文字列。
  直したファイルは、1.30.0 の版上げ（PR #566）と同じ範囲。置き換えは前後に数字・`.` が無い `1.30.0` だけにし、ADR・作業履歴は対象から外した。
- 元のイメージのダイジェスト：`docker buildx imagetools inspect node:26-bookworm-slim` の `Digest` は、`Dockerfile` に固定したもの（`sha256:5df79989…`）と同じだったので変えていない。

## 確かめたこと

- `npm run lint`・`npm run typecheck`：通過。
- `npx vitest run --no-file-parallelism`（`tests/docs` を含む）：349 ファイル・7318 件が通過、2 件が失敗（1 件は元からのスキップ）。
  - 失敗は `tests/scripts/check-worklog-history.test.ts` の 2 件。手元の git の利用者全体の設定が `init.defaultBranch=main` なので、テストが作る一時のリポジトリに初めから `main` があり、`git checkout -qb main` が失敗する。`GIT_CONFIG_GLOBAL=/dev/null` で利用者全体の設定を外すと、このファイルの 27 件がすべて通った。この PR の変更（版の置き換え）とは関係しない。
- 消した行と足した行を比べ、版の違いのほかに差分が無いことを確かめた。
