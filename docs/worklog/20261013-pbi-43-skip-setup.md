# 工程の選択と内容の調査では、開発のセットアップを省く

- 日付: 2026-10-13（UTC）
- タスク: PBI-43
- PR: #49
- ブランチ: feat/issue-43-skip-setup
- 関係する ADR: [工程の選択と内容の調査では開発のセットアップを省き、不具合の調査・再現・実装ではリポジトリの手順に従う](../adr/20261013-0024-skip-setup-for-content-investigation.md)

## 目的

対象リポジトリの AGENTS.md などに「最初に npm run setup を実行すること」とあると、工程の選択やコードを読むだけの調査でも、
エージェントがセットアップを実行していた。時間がかかり、レジストリへの接続など失敗の原因も増えるので、コードを読めば足りる場面ではセットアップを省く。

## したこと

- `apps/daemon/src/prompts.ts`：オーケストレーターのプロンプトに、開発のためのセットアップ（依存のインストール・ビルド・setup のスクリプトなど）を実行しないこと、
  リポジトリの AGENTS.md・CLAUDE.md・README などの指示とぶつかる場合はプロンプトを優先することを書いた。
- オーケストレーターが調査の性質（`content`：内容の調査 / `bug`：不具合の調査）を判断して `StepsChosen` の `investigation` に記録し、調査の工程に渡す
  （`packages/core/src/events.ts`・`packages/core/src/projection.ts`・`apps/daemon/src/service.ts`）。判断が無いとき（以前の作業履歴を含む）は内容の調査として扱う。
- 内容の調査（調査だけ・前段の調査）のプロンプトにも同じ指示を書いた。動かして確かめる必要がある場合に限り、セットアップしてよい（理由を結果に書く）。
- 不具合の調査・再現・実装のプロンプトは、これまでどおりリポジトリの手順に従ってセットアップする。
- README に方針を書き足した。

## 確かめたこと

- build・typecheck・lint・test が通った。
- `prompts.test.ts`：オーケストレーター・内容の調査には指示があり、不具合の調査・再現・実装には無いこと。オーケストレーターの出力から調査の性質を読めること。
- `daemon.test.ts`：オーケストレーターの判断が作業履歴とタスクに記録され、内容の調査だけに指示が出ること。
- 追加したテストは、実装を戻すと失敗することを確かめた（8通り）。
- マージの後のレビューで、#47・#48・#49 を含むマージのコミットで全452テスト・`npm run lint`・`npm run typecheck` が通った。
  実際の AI のエージェントが指示どおりセットアップを省くかの実行は未確認。

## レビューの指摘と対応

指摘は無かった（マージの後のレビューで、修正が必要な指摘は無いとされた）。

## 残したこと

- 利用者の環境で、AGENTS.md に「最初に npm run setup を実行すること」と書いたリポジトリで、内容の調査のタスクがセットアップせずに結果を出し、
  不具合の調査のタスクはセットアップすることを、作業履歴で確かめる（PR で依頼した）。
