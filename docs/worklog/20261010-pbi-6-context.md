# コンテキストリポジトリの継承・合成と、エージェントへの配置を行う

- 日付: 2026-10-10（UTC）
- タスク: PBI-6
- PR: #13
- ブランチ: feat/issue-6-context
- 関係する ADR: [コンテキストリポジトリを中立形式で書き、extends の継承を合成して、実行ごとに空の設定のディレクトリへ Claude Code・Codex の形式で置く](../adr/20261010-1203-superseded-context-repository-composition.md)、[コンテキストリポジトリの読む項目にシンボリックリンクがあれば、リンク先にかかわらず拒否して止める](../adr/20261010-1203-reject-symlinks-in-context.md)

## 目的

PBI-6 は大きいため2つに分け、このタスク（PBI-6a）では受け入れ条件1・2・3・5・6を扱う。MCP の設定と秘密情報の注入（受け入れ条件2・3の MCP の部分と4）は PBI-6b（#14）で扱う。

- `extends` で親を指定でき、sacty が継承を解決する。
- 中立形式の規約・スキルを合成し、Claude Code と Codex の形式に変えてコンテナに置く。
- 規約は上位から連結し、スキルは名前ごとに下位が上書きする。上書き禁止の項目は下位で外せない。
- 使ったコンテキストのリポジトリとコミットを台帳に記録する。
- sacty から起動するときは、Claude Code・Codex の組み込みのメモリーを使わない。

## したこと

- 継承の解決・合成・配置：`apps/daemon/src/context.ts`。浅い clone で層を取得し、循環・10段を超える・取得できない・設定の誤りで止める。
- エージェントへの配置：`apps/daemon/src/agents/invocation.ts`・`apps/daemon/src/agents/docker.ts`。実行ごとに空の `CLAUDE_CONFIG_DIR`・`CODEX_HOME` に置き、コンテナにマウントする。
- サービス：`apps/daemon/src/service.ts` で工程エージェントの実行ごとに合成し、`ContextResolved`（`packages/core/src/events.ts`）を記録する。ゴールガーディアンには渡さない。
- プロジェクトの設定にコンテキストリポジトリ（URL・ref）を足した（`packages/core/src/projects.ts`・`apps/web/src/components/project-editor.tsx`）。エクスポートの対象にした。
- 台帳の表示（`apps/web/src/lib/labels.ts`）に、使ったコンテキストと注意を足した。
- 整形のコミットを足した。
- レビューの対応で、読む項目のシンボリックリンクを拒否するようにした。

## 確かめたこと

- `npm test`：179件が通った（11件追加）。継承の順・規約の連結の順、スキルの上書き・上書き禁止・取り除き、循環・深さ・取得の失敗・設定の誤り、
  Claude Code・Codex それぞれの出力、本物の git での継承の取得、サービスで渡すことと記録すること、偽の docker でマウントするディレクトリに写すことを確かめた。
  レビューの対応の後は181件が通った。
- 画面で、ローカルの2段のコンテキストリポジトリ（上位の層で review スキルを上書き禁止）を決済のプロジェクトに設定し、チケットを作ると、
  台帳に2段のリポジトリ（`#main` とコミット）と、上書き禁止に当たった注意が記録されることを確かめた。
- シンボリックリンクの拒否は、実際の git リポジトリにリンクをコミットして確かめ、修正を戻すと失敗することを確かめた。
- レビューでは `npm test`・`npm run lint`・`npm run typecheck` が通ったことを確かめた。ブラウザの操作と、実際のエージェント・コンテナでの読み込みは、レビューでは確かめていない。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| P1：`rules.md` がシンボリックリンクでもそのまま追うので、コンテキストリポジトリからデーモンのホストの任意のファイルを規約として取り込める | 読む・写す項目（`sacty-context.yaml`・`rules.md`・`rules/`・`skills/`）を lstat でたどり、リンクなど通常のファイル・ディレクトリ以外があれば、読む前に理由を示して止めるようにした。リンク先が中か外かは問わない。回帰テストを足した |
| P2：スキルの中の相対リンクが、写した先でホストの絶対パスに変わり、コンテナからはリンク切れになる | スキルの中のリンクは受け付けず、取得のときに理由を示して止めるようにした。指摘の形（`skills/sample/ref.md` → `guide.md`）をテストに入れた |

## 残したこと

- MCP の設定と秘密情報の注入は、PBI-6b（#14）で行う。
- スキルの中のリンクを実体化して受け付けることは、必要になったら別に検討する。
