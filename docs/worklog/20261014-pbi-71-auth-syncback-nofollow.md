# 認証ファイルの書き戻しで、コンテナの中のリンクを辿らない

- 日付: 2026-10-14（UTC）
- タスク: PBI-71
- PR: #77
- ブランチ: feat/issue-71-auth-syncback-nofollow
- 関係する ADR: [認証ファイルの書き戻しは、コンテナの停止を確かめられたときだけ行い、ステージしたファイルはリンクを辿らずに1度だけ読む](../adr/20261014-0118-auth-syncback-nofollow.md)

## 目的

動いたままのコンテナが staging の認証ファイルをリンクに差し替えても、ホストの別のファイルの中身がホストの認証ファイルに書き戻されないようにする。
停止を確かめられないときは書き戻さず理由をログに残し、リンク・通常のファイル以外は読まない（最後の部分・途中のディレクトリとも）。回帰テストを足し、
修正を戻すと落ちることを確かめる。認証の値は表示・ログ・台帳に出さない。

## したこと

- `apps/daemon/src/agents/docker.ts`：停止を確かめられない実行は書き戻しを飛ばし、`console.warn` で理由を残す。`readStagedFile` で O_NOFOLLOW・O_NONBLOCK で開いて
  通常のファイル・一時ディレクトリ・途中のディレクトリを確かめてから fd から読む。`syncBackIfChanged` は1度だけ読んだ中身のハッシュで比べてそのまま書き、
  リンク・通常のファイル以外は `not-regular` を返す。`collectSecrets` も同じ読み方にした。
- `apps/daemon/src/agent-sessions.ts`：`assertRealParents` と開くときのフラグ（`NOFOLLOW_READ_FLAGS` に改名）を共有するため export した。
- テスト：`apps/daemon/src/agents/agents.test.ts`。

## 確かめたこと

- 偽の docker（`ps` がいつまでもコンテナありと答える）のテストで、ホストの認証ファイルが元のままで、ログに理由とパスが出ることを確かめた。
- 単体テストで、最後の部分がリンク・途中のディレクトリがリンク・一時ディレクトリそのものがリンク・FIFO のそれぞれで `not-regular` になり、
  ホストの認証ファイルが変わらないことを確かめた。
- 修正を戻して確かめた：停止の判定を外すと停止を確かめられないテストが失敗、読み方を `readFileSync` に戻すとリンク・途中のディレクトリ・一時ディレクトリ・
  FIFO・偽 docker のリンク差し替えの5件が失敗（FIFO のテストは書き手を置き、戻したときに止まらず失敗するようにした）、途中のディレクトリ・一時ディレクトリの
  確認だけを外すとその2件が失敗。
- ログはパスとコンテナ名だけで、古い値・更新後の値・別のファイルの中身がログに出ないことをテストで確かめた。テストの値はダミー。
- `npm run lint`・`npm run typecheck`・`npm run build`：終了コード 0。`npx vitest run`：42 files / 790 tests passed。
- 画面の変更は無いので、動作確認の動画は無い。レビューでは、実際の Docker・実際の認証情報での確認と本番のビルドは行っていない。
