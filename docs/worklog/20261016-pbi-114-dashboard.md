# ダッシュボードを作り、タスクの一覧と設定をプロジェクトの URL に移す

- 日付: 2026-10-16（UTC）
- タスク: PBI-114
- PR: #124
- ブランチ: feat/issue-114-dashboard
- 関係する ADR: [画面の入口をダッシュボードにし、タスクの一覧と設定をプロジェクトの URL に置き、ヘッダーの選択を開いている画面で決める](../adr/20261016-0151-dashboard-and-project-urls.md)

## 目的

すべてのプロジェクトの動きを1か所で見られるよう、画面の入口をダッシュボードにする。今の `/`（表示しているプロジェクトの
タスクの一覧）を `/projects/<ID>/tasks` に、`/projects/<ID>`（プロジェクトの設定）を `/projects/<ID>/settings` に移す。
作業の途中で、ヘッダーのプロジェクトの切り替えに「すべてのプロジェクト」を足し、選んだ表示を開いている画面で決めることが
受け入れ条件に足された。

## したこと

- 画面の構成
  - `/` は `/dashboard` へ、`/projects/<ID>` は `/projects/<ID>/tasks` へ移す。
  - タスクの一覧のページを `app/projects/[id]/tasks/` に、プロジェクトの設定のページを `app/projects/[id]/settings/` に移した。
    一覧のプロジェクトは URL の ID で決め（`loadTaskList(projectId)`。無ければ null で 404）、`FollowProject` で cookie を
    URL に合わせる。「タスクを作成」の作成先も URL のプロジェクト。取り直し（`/live/tasks?project=`）も URL のプロジェクトに固定した。
  - 別のプロジェクトの一覧へ移ったときに、作成のダイアログ（作成先を開いた時のプロジェクトに固定している）と取り直しの状態を
    作り直すよう、プロジェクトの ID を key にした（セルフレビューで見つけた）。
  - `/projects/current` を `/projects/current/[[...view]]` にし、`/projects/current`（設定）と `/projects/current/tasks`（タスクの一覧）
    を受ける。ほかは 404。
  - 画面の中のリンクと移動先を `lib/paths.ts` で作るようにした（ロゴ・サイドメニュー・切り替え・`/switch` の既定・パンくず・
    プロジェクトの一覧・作成のダイアログ・タスクの詳細のプロジェクト・作成とインポートの後）。Slack の通知のリンクはタスクの
    URL（`/tasks/<ID>`）だけで、変わらない。
- ダッシュボード
  - 欄（カード）を並べる作り（`DashboardGrid`・`DashboardCard`）。データは `DashboardData`（`loadDashboard`）にまとめ、取り直しは
    `/live/dashboard` の1つ。
  - 「終わっていないタスク」の欄：完了・中止を除くすべて（`statusTone` が `completed`・`cancelled` でないもの）を、最後に動いた順に
    出す。件数の上限は無い。行は 4rem、欄は5件分（20rem）で、あふれたら欄の中でスクロールする。プロジェクトが無いとき・
    終わっていないタスクが無いときの表示がある。
- ヘッダーとサイドメニュー（追記された条件）
  - 切り替えの先頭に「すべてのプロジェクト」（`/dashboard` へ）。個別のプロジェクトは `/switch` を通してそのタスクの一覧へ。
  - 選んだ表示は開いている画面の URL で決める（`pageScope`・`selectedProject`）。プロジェクトの画面（`/projects/<ID>/tasks`・
    `settings` は URL の ID、`/tasks/…` は cookie）ではそのプロジェクト、ほかは「すべてのプロジェクト」。
  - 「すべてのプロジェクト」の間は、サイドメニューの「タスク」を出さず、「設定」はプロジェクトの一覧へ向ける。お知らせは
    プロジェクトで分けずに出す（開くと、そのタスクのプロジェクトに切り替える）。
  - 狭いサイドメニューで「ダッシュボード」が「ダッシュボー／ド」と折り返したので、名称に幅の無い空白を入れ、`word-break: keep-all`
    にした。
- docs：仕様書（architecture の「画面の構成（URL）」「画面のヘッダーとサイドメニュー」・取り直しの表、tasks-and-steps の作成ボタン）、
  利用者向けの文書（はじめにの「画面の構成」・プロジェクトの設定・自動の更新）を、日本語と英語の両方で直した。ADR を足し、
  PBI-4 の ADR の置き換え先に書き足した。

## 確かめたこと

- `npm run lint`（終了コード 0）・`npm run typecheck`・`npx vitest run`（84 ファイル・1728 テスト）・`npm run build`・
  `npx vitest run tests/docs`（89 テスト）が通った。
- 回帰テスト：リダイレクト（`/`・`/projects/<ID>`・`/projects/current…`・`/switch`）、ダッシュボードに出す状態と出さない状態・
  上限が無いこと、自動の更新（状態の変化・増減・スクロールの位置とフォーカスが残ること・デーモンに届かないとき）、新しい URL の
  リンク（サイドメニュー・ロゴ・切り替え・お知らせ・パンくず・作成とインポートの後・ソースに古い URL が残っていないこと）、
  ヘッダーの切り替えと画面ごとの選んだ表示。
- 修正を1つずつ戻す 25 通りの変更（`/` を移さない・`/projects/<ID>` を設定のままにする・完了を出す・一時停止を出さない・上限を付ける・自動で更新しない・欄の高さの
  上限を外す・取り直しで欄を作り直す・切り替えを `/` へ・「すべてのプロジェクト」を出さない／プロジェクトへ向ける・選んだ表示を
  cookie のまま・お知らせを cookie で分ける・サイドメニューを古い URL へ・すべての間もタスクを出す・ロゴを `/` へ・
  `/projects/current/tasks` を設定へ・`/switch` の既定を `/` へ・無いプロジェクトを 404 にしない・一覧のプロジェクトを cookie で
  決める・cookie を URL に合わせない・パンくずを `/` へ・作成の後を `/projects/<ID>` へ・一覧のリンクを `/projects/<ID>` へ・
  作成のダイアログの key を外す）で、どれもテストが落ちることを確かめた。
- 自分のブランチを、別のポート（4800/4810）と一時的な SACTY_HOME（架空のリポジトリを対象にした2つのプロジェクトと7件の
  タスク。AI の設定が無いので、タスクは実行待ちのまま）で起動し、動画に撮った：`/` を開くとダッシュボード → 7件を欄の中で
  スクロール → API で1件を一時停止・1件を中止すると、リロードせずに「一時停止中」と6件に変わる → ヘッダーで「Webサイト」を
  選ぶとそのタスクの一覧、「すべてのプロジェクト」でダッシュボードに戻る（サイドメニューは「タスク」を出さず、お知らせは
  分けずに出る）→「決済」を選び、サイドメニューの「設定」でそのプロジェクトの設定へ。無いプロジェクトの ID の一覧は 404 を出した。
