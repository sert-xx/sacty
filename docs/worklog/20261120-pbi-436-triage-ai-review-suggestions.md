# AI のレビューの提案に対応するかどうかを、直しに入る前に、PR の範囲を考えて AI が判断する

- 日付: 2026-11-20（UTC）
- タスク: PBI-436
- PR: なし
- ブランチ: sacty/task-（タスク ID の先頭 8 文字）
- 関係する ADR: [AI のレビューの提案に対応するかどうかは、直しに入る前に AI が PR の範囲で判断し、対応しない判断は AI で終える](../adr/20261120-2109-triage-ai-review-suggestions-before-rework.md)

## 目的

sacty が作った実装の PR で、AI のレビューの提案だけの往復（直し・push・再レビュー）が続き、時間と費用がかかっていた。
直しに入る前に、AI が PR の範囲を考えて提案ごとに対応するかを決め、対応しない提案のためには往復を起こさないようにする。

受け入れ条件の要点は次のとおり。

- 提案（`[提案]`）だけを選り分ける。要修正と人の指摘は選り分けずに直す。
- 対応しない判断は AI で終え、理由を PR に返信する。人は PR に要対応とコメントして覆せる。
- 判断できなかった提案は、対応する側にして直す。
- 直す指摘が残らなければ直しに入らず、同じ先頭を 1 回だけ判定し直させる。その回も提案がすべて対応しないなら、一時停止して人が選ぶ。
- 再レビューは、対応しないとした提案を未対応に数えず、蒸し返さない。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| 実装が断った後の判定し直し（PBI-357・370）にも選り分けが走り、止め方が変わる（要修正） | `reviewRejudge` があり理由が `triaged` でない回は選り分けず、`stop` も `triaged` のときだけにした。結合テストを足した |
| `triageStop` が一時停止以外で消えず、後の別の回で理由の無い一時停止になる | `triageStop` に PR の番号と先頭のコミットを持たせ、`triageStopDue` で今の先頭と照らす |
| 提案が行へのコメントだけで本文が総評だけの回は、すべて対応しなくても直しに入る | 提案ありの回の、単位が 0 件の本文も、同じ回の提案がすべて対応しないときは外す（`droppedRemarks`） |
| 提案の単位の分け方が書式の慣習に依存する | 「指摘」の節だけを読む許可リストにし、レビューの指示に見出しと頭の付け方を書いた |
| 承認の画面の指摘の一覧・作業履歴・理由の言語・役割の表示名 | 選り分けた指摘の札、`reason: triaged` の文言、理由のコード（日英）、`triage` の表示名を足した |
| テストの不足・重複・小さな整理 | 選り分けない流れ（取り込んだ PR のレビュー・PBI-357）と既定のスキルのテストを足し、純粋な部分を `suggestion-triage.ts` に出し、未使用の引数・別名・文字の切り方を直した |
