# 監査の後に中止したタスクのメモリーを消せず、デーモンが起動しない不具合を直す

- 日付: 2026-11-12（UTC）
- タスク: PBI-335
- PR: #356
- ブランチ: feat/issue-335-memory-delete-on-cancelled
- 関係する ADR: [監査の後に中止したタスクにも、メモリーの削除の記録だけは追記できるようにする](../adr/20261112-2210-delete-memory-of-cancelled-task.md)

## 目的

`sacty up` で、起動のときのメモリーの整理（`syncMemories` の件数の上限）が `task.invalidState` で失敗し、デーモンが止まる不具合を直す。

## 原因

監査でメモリーを登録した後に、レビューのやり直しの失敗で中止になったタスクがあった。
プロジェクトの階層のメモリーが上限（30件）を1件超え、いちばん古いのがそのタスクのメモリーだった。
削除の記録 `AuditMemoryDeleted` を中止したタスクに追記しようとして、投影の「中止したタスクにはイベントを足せない」検査で弾かれた。

## したこと

- 投影：中止したタスクでも `AuditMemoryDeleted` を受け付ける。ほかのイベントはこれまでどおり受け付けない。
- docs：仕様書（作業履歴・メモリー。日英）を直し、ADR を足した。

## 確かめたこと

- 手元の作業履歴の写しで、修正の前は上限超えの削除が `the task is cancelled` で失敗し、修正の後は通ることを確かめた。
- 新しいテスト：
  - 監査の後に中止したタスクでも、登録したメモリーを消せる。同じメモリーは2度消せず、提案の判断など、ほかの監査の記録は足せない。
  - 監査の後に中止したタスクのメモリーを、再起動のときの上限超えで消し、人も消せる。
  - 修正を戻すと、どちらのテストも失敗することを確かめた。
- `npm run lint`・`npm run typecheck`：エラーなし。
- `npx vitest run`：全体が通った。
- `npx vitest run tests/docs`：通った。
