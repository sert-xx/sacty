# ホストの MCP のプロセスのテストが、失敗・時間切れでも子プロセスを残さないようにする

- 日付: 2026-10-14（UTC）
- タスク: PBI-94
- PR: #102
- ブランチ: feat/issue-94-test-process-cleanup
- 関係する ADR: なし

## 目的

`apps/daemon/src/host-mcp-processes.test.ts` が起動した次の2つのプロセスが、テストの後に8時間以上残っていた。

- `sh -c sleep 302 ... while [ ! -e $TMPDIR/sacty-host-mcp-processes-XXXX/go-exit ]; do sleep 0.02; done`
- `node $TMPDIR/sacty-host-mcp-processes-XXXX/wrapper.mjs`

どのテストが残すのかを特定し、テストが失敗・時間切れになっても、作ったプロセスのグループを必ず止めるようにする。

## したこと

### 原因

- 残していたのは、`実際のプロセスの後始末（PBI-78）` の次の2つのテスト。
  - 「MCP サーバーが自分で終わったら、残った子孫を止める」（`sh -c sleep 302 ...`）
  - 「MCP サーバーが自分で終わっても、子孫が標準出力・標準エラーを開いたままなら、子孫を止め、1回だけ知らせる」
    （`wrapper.mjs`）
- どちらも、MCP サーバーを自分のプロセスグループで起動し、合図のファイル（`go-exit`）が置かれるまで待ち続ける。
  afterEach が止めるのは、テストが `recorded()`（記録を読んで子孫を見つける）で見つけて登録したグループだけだった。
  そのため、登録の前（`transport.start()` の後、記録を待っている間など）に失敗・時間切れになると、afterEach は何も
  止めず、外側の afterEach が一時ディレクトリを消すので、合図のファイルが置かれることもなくなり、ずっと残る。
  `host-mcp.test.ts` の実際のプロセス（`node -e ...`）は、自分ですぐ終わるので残らない。

### 直したこと

- `apps/daemon/src/testing/processes.ts`（テスト用。ビルドの対象外）に `killSpawned` を足した。テストのプロセス
  （Vitest のワーカー）の子孫を親をたどって集め、その子孫のグループ・渡したグループごと SIGKILL で止める。親が終わって
  付け替えられた子孫は、グループで見つける。テストのプロセス自身のグループ（Vitest・シェルと同じ）は、グループとしては
  止めない（グループに入っていない子孫は PID で止める）。Vitest のワーカーがスレッドのときは、プロセスがほかのテスト
  ファイルと同じなので、子孫をたどらず、渡したグループだけを止める。
- `host-mcp-processes.test.ts` の実際のプロセスのテストの後始末を、`killSpawned` に替えた。afterEach に加えて afterAll
  でも呼ぶ（時間切れの後も動き続けたテストが、afterEach の後に起動したもの）。テストで作った `HostMcpProcesses` は
  後始末で `endAll()` し、記録し直す処理を止める。

## 確かめたこと

- 修正の前に、2つのテストの `transport.start()` の直後で例外を投げるよう一時的に変えて
  `npx vitest run apps/daemon/src/host-mcp-processes.test.ts` を実行すると、報告と同じ2つのプロセス
  （`sh -c sleep 302 ... go-exit` と `node .../wrapper.mjs`）が、親が 1 に付け替えられて残った（確かめた後、手で止めた）。
  残ったプロセスの子が見えるため、別のテスト（「起動して記録している途中に止めても…」）も巻き込まれて落ちた。
- 修正の後、同じ例外を投げる変更では、2つのテストは落ちるが、残るプロセスは無い
  （`ps -A -o pid=,command= | grep -E "sacty-host-mcp-processes|sleep 30[0-9]"` が空）。
- 修正の後、同じ場所で 60 秒待つよう変えて、テストを時間切れ（20 秒）にしても、残るプロセスは無い。
- 回帰テスト `apps/daemon/src/testing/processes.test.ts`：偽の一覧で、止めるもの（子孫・そのグループ・付け替えられた
  子孫・渡したグループ）と止めないもの（テストのプロセスとそのグループ・ほかのプロセス）を確かめる。実際のプロセスで、
  合図を待ち続ける自分のグループの `sh` とその子孫、付け替えられた子孫を止めることを確かめる。子孫をたどる処理を
  無効にすると 3 つ落ち、戻すと通る。
- まっさらな複製（`git clone` → `npm ci`）で、`npm run lint`・`npm run typecheck`・`npm run build`・`npx vitest run`
  （58 ファイル・1376 テスト）が通り、実行後に残るプロセスは無い。

### 手で確かめる手順

テストの後に、次が空であることを確かめる。

```bash
ps -A -o pid=,ppid=,command= | grep -E "sacty-host-mcp-processes|sleep 30[0-9]" | grep -v grep
```

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| （DA のセルフレビュー）ps が読めないと子孫が見つからない | 登録済みのグループには、一覧によらずシグナルを送る |
| （DA のセルフレビュー）Vitest のワーカーがスレッドだと、ほかのテストファイルの子プロセスまで止める | スレッドのときは子孫をたどらない |

## 残したこと

- テストのファイルが終わった後も動き続けた（時間切れの後の）テストの本体が、さらに起動したものは止められない。
  今のテストでは、時間切れの後に新しく起動する処理は無い。
