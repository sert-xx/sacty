# 未完了で終わった実装の実行を、同じセッションの続きから進める

- 日付: 2026-11-15（UTC）
- タスク: PBI-350
- PR: #381
- ブランチ: feat/issue-350-continue-incomplete-implementation
- 関係する ADR: [未完了で終わった実装の実行を、同じセッションの続きから進め、続きの上限を 10 回にする](../adr/20261115-2254-continue-incomplete-implementation-in-same-session.md)

## 目的

終わっていない実装を提出しない仕組み（PBI-347）を、止めてあった分割の子タスクで確かめたところ、未完了の実装は PR にならなかったが、実装そのものは終わらなかった。

- 実装のエージェント（Codex）が、3 回とも 1〜5 分で実行を終えて、未完了と申告した。
- やり直しは、毎回新しいセッションで、指示の全文を読むところから始まっていた。
- 3 回とも作業領域は進んでいたが、3 回の上限で一時停止した。

受け入れ条件の要点は次のとおり。

- 未完了で終わった実装の次の実行は、同じエージェントのセッションの続きから進める（Claude Code・Codex）。続けたことを作業履歴に残す。
- 続きの実行の指示は、続きであることの知らせの後に、指示の全文を続ける。
  PR を作った時点では、自動の続きでは知らせだけを渡す形だった。1回目のレビューの指摘で改めた（下の「レビューの指摘と対応」）。
- セッションを続けられないときは、最初から実行し直して、理由を残す。
- 続きの実行が 10 回に達しても未完了なら、一時停止する。続けても作業領域が変わらなければ、回数を待たずに止める。
- 完了の申告の指示が、途中で実行を終えないこと・未完了で終えてよい場合・自分で確かめられないことの書き場所を伝える。
- 時間切れで止めた実行の続き（PBI-280）の振る舞いは変えない。

## したこと

- `packages/core/src/events.ts`：続きの実行の上限 `MAX_INCOMPLETE_CONTINUATIONS`（10）。`AgentRunContinued` に、何の続きか（`cause`。`incomplete` は未完了の続き。無ければ時間切れの続き）を足した。
- `apps/daemon/src/timeout-resume.ts`
  - `incompleteRunBefore`：直前の実装の実行が、未完了で終わったものかを決める（時間切れと同じ見方）。
  - `planContinuation`（前の `planTimeoutResume`）：時間切れで止めた実行と、未完了で終わった実装の実行の両方について、セッションを続けられるかを決める。
  - `incompleteResumeLines`：続きの実行の指示の先頭に足す、続きであることの知らせ。
- `apps/daemon/src/service.ts`
  - `executeResumable`：未完了の続きも、セッションの続きから進める。続きであることの知らせの後に、指示の全文を続ける（`continuedPrompt`）。
    AI が再開を断った失敗は、呼び出し側に知らせる（`incompleteResumeRejected`）。
  - 工程の実行の失敗の扱い：未完了の続きで再開を断られた失敗は、失敗を記録して実行待ちに戻す（タスクを止めない・エージェントを変えない）。
  - `implementationCompleted`：止める条件を、未完了が 3 回続いたときから、続きの実行が 10 回に達しても未完了のときに変えた。
- `apps/daemon/src/completion.ts`・`apps/daemon/src/prompts.ts`：完了の申告の指示と、最初から実行し直すときの指示の文言を直した。
- `apps/web`：作業履歴の行に、未完了で終わった実行の続きであることを出す（日本語と英語）。続けられなかった理由の「止めた実行」を「前の実行」にした。
- 仕様書（エージェントの実行・タスクと工程。日本語と英語）、ユーザードキュメント（タスク。日本語と英語）、ADR を直した。前の ADR は、一部を置き換えたので、`superseded` に改名して、リンクを直した。

## レビューの指摘と対応

### 1回目（sacty のレビュー。対象は 9c1c369a。判定は「修正が必要」）

- [要修正] 既存の PR を引き継ぐタスクで、実行の間に足されたレビューやコメントが、自動の続きの短い指示に入らない。その実行が終わると、渡していない指摘も、渡した指摘として記録され、その後の取り込みから外れる。
- [要修正] 短い指示だけの自動の続きで、再開を断られると失敗を返し、別のセッションで始まるとその結果を受け入れる。別のセッションの実行が完了と申告すると、タスクの範囲を知らない実行が、提出に進みうる。

対応：

- 2件とも、自動の続きで指示の全文を送らない設計から来ていた。変わる部分を選んで足す形をやめて、続きの実行にも、続きであることの知らせの後に、指示の全文を渡す形に改めた（時間切れの続きと同じ形）。
  - `continuedPrompt` は、いつも指示の全文を続ける。選んで足すための `ExecuteRun.continuation` と、未完了の後に一時停止があったかの判定（`ContinueCause` の `paused`）を取り除いた。
  - `incompleteResumeLines` は、残っていることと完了の申告の形を持たない（後ろに続く指示の全文にある）。
- 別のセッションで始まった実行は、指示の全文を受け取っているので、結果をそのまま使う（時間切れの続きと同じ）。続けたとは記録せず、理由（`resume_failed`）を残す。
- 再開を断られた失敗は、結果を使わない。失敗を記録して実行待ちに戻し、次の実行で、新しいセッションで、指示の全文から実行し直す（タスクを止めない・エージェントを変えない）。
  - 指摘は、再開の失敗を見つけたら、全文を渡した新しいセッションで実行し直すことを求めていた。その場で新しい実行 ID でやり直す形にはせず、失敗を記録して次の実行に任せた（工程の実行の記録が、1つの実行 ID に結び付いているため）。
  - 時間切れの続きの扱い（失敗して一時停止する）は、変えていない。
- 文書：仕様書（エージェントの実行・タスクと工程。日本語と英語）、ユーザードキュメント（タスク。日本語と英語）、ADR（決定・理由・影響）を直した。

足したテスト（`apps/daemon/src/daemon.test.ts`）：

- 引き継いだ PR で、未完了の実行の後に足された指摘も、続きの指示に入り、渡した指摘として記録される。
- 再開を指定したのに別のセッションで始まっても、指示の全文（タスクの範囲と、前回の実行の状況）が渡っている。続けたとは記録しない。
- AI が再開を断って失敗したら、タスクを止めずに、新しいセッションで指示の全文から実行し直す。失敗した実行は、未完了の回数に数えない。
- AI が再開を断った実行の間に、人が一時停止を求めていたら、一時停止する。再開すると最初から実行し直す。
