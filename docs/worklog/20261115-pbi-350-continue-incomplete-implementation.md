# 未完了で終わった実装の実行を、同じセッションの続きから進める

- 日付: 2026-11-15（UTC）
- タスク: PBI-350
- PR: #381
- ブランチ: feat/issue-350-continue-incomplete-implementation
- 関係する ADR: [未完了で終わった実装の実行を、同じセッションの続きから進め、続きの上限を 18 回にする](../adr/20261115-2254-continue-incomplete-implementation-in-same-session.md)

## 目的

終わっていない実装を提出しない仕組み（PBI-347）を、止めてあった分割の子タスクで確かめたところ、未完了の実装は PR にならなかったが、実装そのものは終わらなかった。

- 実装のエージェント（Codex）が、3 回とも 1〜5 分で実行を終えて、未完了と申告した。
- やり直しは、毎回新しいセッションで、指示の全文を読むところから始まっていた。
- 3 回とも作業領域は進んでいたが、3 回の上限で一時停止した。

受け入れ条件の要点は次のとおり。

- 未完了で終わった実装の次の実行は、同じエージェントのセッションの続きから進める（Claude Code・Codex）。続けたことを作業履歴に残す。
- 自動の続きでは、続きの指示だけを渡す（指示の全文を送り直さない）。人が再開した続きでは、指示の全文を渡す。
- セッションを続けられないときは、最初から実行し直して、理由を残す。
- 続きの実行が 18 回に達しても未完了なら、一時停止する。続けても作業領域が変わらなければ、回数を待たずに止める。
- 完了の申告の指示が、途中で実行を終えないこと・未完了で終えてよい場合・自分で確かめられないことの書き場所を伝える。
- 時間切れで止めた実行の続き（PBI-280）の振る舞いは変えない。

## したこと

- `packages/core/src/events.ts`：続きの実行の上限 `MAX_INCOMPLETE_CONTINUATIONS`（18）。`AgentRunContinued` に、何の続きか（`cause`。`incomplete` は未完了の続き。無ければ時間切れの続き）を足した。
- `apps/daemon/src/timeout-resume.ts`
  - `incompleteRunBefore`：直前の実装の実行が、未完了で終わったものかを決める（時間切れと同じ見方）。未完了の後に一時停止があったかも返す。
  - `planContinuation`（前の `planTimeoutResume`）：時間切れで止めた実行と、未完了で終わった実装の実行の両方について、セッションを続けられるかを決める。
  - `incompleteResumeLines`：続きの実行の指示。
- `apps/daemon/src/service.ts`
  - `executeResumable`：未完了の続きも、セッションの続きから進める。自動の続きは、続きの指示と実行ごとに変わりうる案内だけ、一時停止を挟んだ続きは指示の全文を続ける（`continuedPrompt`）。
  - `implementationCompleted`：止める条件を、未完了が 3 回続いたときから、続きの実行が 18 回に達しても未完了のときに変えた。
- `apps/daemon/src/completion.ts`・`apps/daemon/src/prompts.ts`：完了の申告の指示と、最初から実行し直すときの指示の文言を直した。
- `apps/web`：作業履歴の行に、未完了で終わった実行の続きであることを出す（日本語と英語）。続けられなかった理由の「止めた実行」を「前の実行」にした。
- 仕様書（エージェントの実行・タスクと工程。日本語と英語）、ユーザードキュメント（タスク。日本語と英語）、ADR を直した。前の ADR は、一部を置き換えたので、`superseded` に改名して、リンクを直した。

- 修正を一時的に戻すと、対応するテストが落ちることを確かめた。
  - 未完了の続きを計画しない：4 件
  - 自動の続きでも指示の全文を渡す：3 件
  - 上限を 3 回のままにする：3 件
  - 続きの記録に、未完了の続きであることを残さない：4 件
  - 一時停止を挟んでも、続きの指示だけにする：1 件
  - 続きの指示に、実行ごとに変わりうる案内を足さない：1 件
- PR を作る前の見直しで、次を直した。
  - 自動の続きで指示の全文を送らないと、実行ごとに変わる案内（始める前の取り込みで競合したファイル・人が PR に足したコミット・使える API・起動したサービスの接続先）が、続きの実行に渡らなかった。続きの指示の後ろに、この案内を足した。
  - 続きの指示が、最初の指示に無いことがある出力（セルフレビューの報告）を名指ししていた。名指しをやめた。
- 実際のエージェントで続きの実行を動かすことは、確かめていない。マージの後に、止めてある子タスクで確かめる。
