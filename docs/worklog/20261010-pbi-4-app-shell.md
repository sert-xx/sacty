- PR: #10

- 関係する ADR: [画面に共通の枠（ヘッダー・お知らせ・サイドメニュー）を置き、表示中のプロジェクトを cookie で覚えて一覧と作成をそのプロジェクトに対して行う](../adr/20261010-1030-superseded-app-shell-and-current-project.md)、[ライト・ダークはシステムの設定に従い、ユーザーメニューでブラウザごとに上書きできるようにする](../adr/20261010-1030-theme-follows-system.md)

## 目的

PBI-4 は大きいため2つに分け、このタスク（PBI-4a）では受け入れ条件1〜4を扱う。日本語・英語の切り替え（受け入れ条件5〜6）は PBI-4b（#11）で扱う。

- ヘッダーに、ロゴ・プロジェクトのドロップダウン（対応待ちの件数つき）・お知らせ・ユーザーメニューを置く。
- お知らせに全プロジェクトの人間の対応待ちを、ほかのプロジェクトを先にして並べ、クリックでそのプロジェクトに切り替えてタスクを開く。
- サイドメニューは幅88px程度で、アイコンの下に小さく名称を出す。
- ライト・ダークはシステムの設定に従い、ユーザーメニューで上書きできる。ヘッダーとサイドメニューは本文と境界線で区切る。

## したこと

- ヘッダー・メニュー・サイドメニュー：`apps/web/src/components/shell/`（`header.tsx`・`menus.tsx`・`rail.tsx`）。`apps/web/src/app/layout.tsx` で枠に組み込んだ。
- 表示中のプロジェクト：`apps/web/src/lib/current-project.ts`・`apps/web/src/lib/project-select.ts`。cookie に覚え、無くなったプロジェクトなら既定に戻す。
  タスクの一覧（`apps/web/src/app/page.tsx`）とチケットの作成（`apps/web/src/app/actions.ts`）を、表示中のプロジェクトに対して行う。
- プロジェクトの切り替え：`apps/web/src/app/switch/route.ts`。移動先は `safeLocalPath` で検査し、相対パスでリダイレクトする。
  サイドメニューの「設定」は `apps/web/src/app/projects/current/route.ts` で表示中のプロジェクトの設定に移る。
- テーマ：`apps/web/src/lib/theme.ts`。ブラウザに保存し、`<head>` のスクリプトで最初の描画の前に適用する。
- デーモン：`apps/daemon/src/service.ts` と `packages/core/src/events.ts` を、指定したプロジェクトにチケットを作れるようにした。
- レビューの対応で、ヘッダーに自動更新を置き、チケットの作成先をダイアログを開いたときのプロジェクトに固定し（`apps/web/src/components/new-ticket-dialog.tsx`）、移動先の検査を強めた。

## 確かめたこと

- `npm test`：141件が通った（3件追加）。表示するプロジェクトの決め方（無くなったプロジェクトなら既定に戻す）、移動先の検査（外部の URL や `//` を拒否する）、
  指定したプロジェクトにチケットを作ることを確かめた。レビューの対応の後は143件が通った。
- 画面で次のことを確かめた。
  - ダーク（システムに従う）とライトで表示が崩れず、ライトは再読み込みしても保たれる。
  - プロジェクトを切り替えると一覧が切り替わり、決済のプロジェクトで作ったチケットが決済の対応待ちになる。
  - お知らせが「ほかのプロジェクト」→「このプロジェクト」の順に並び、ほかのプロジェクトのお知らせを開くと、プロジェクトが切り替わってタスクが開く。
  - サイドメニューの「設定」が、表示中のプロジェクトの設定を開く。
  - 幅375pxで横スクロールが出ない（サイドメニューは68px）。
  - `/switch?to=%2F%09%2Fevil.example%2F` や `/switch?project=default&to=%2Fa%2F..%2F%2Fevil.example%2F` を開いても、sacty の `/` に留まる。
  - ダイアログを開いたまま cookie を別のプロジェクトに変えて `router.refresh()` しても、作成先は変わらず、閉じて開き直すと新しいプロジェクトになる。
    テストに DOM の環境が無いため、この確認は自動テストにしていない。
- レビューでは `npm test`・`npm run lint`・`npm run typecheck` が通ったことを確かめた。ブラウザでの複数タブの操作は、レビューでは確かめていない。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| 一覧を表示中のプロジェクトに絞ったため、別のプロジェクトのタスクだけが作業中だと自動更新が止まり、お知らせと対応待ちの件数に反映されない | ヘッダーに自動更新を置き、全プロジェクトのどれかのタスクが作業中なら一定の間隔で最新にするようにした |
| チケットの作成先を送信時の cookie で決めるので、別のタブで切り替えると別のプロジェクトに作られる | 表示中のプロジェクトの ID をフォームに持たせ、action はそれだけを使うようにした。見つからなければ理由を出して作らない。cookie を別にしたまま送るテストを足し、修正前は失敗することを確かめた |
| 移動先の検査が文字列の先頭だけなので、タブ文字を挟んだ値が `//evil.example/` として外部へ移動できる | 制御文字・バックスラッシュを拒否し、固定の基準 URL で解決して同じオリジンのときだけ、正規化したパスを返すようにした。回帰テストを足し、修正前は失敗することを確かめた |
| 正規化した結果が `//evil.example/` になる値（`/a/..//evil.example/`・`/%2e//evil.example/`）が通る | 正規化した結果が `//` で始まるものを拒否し、もう一度解決しても同じオリジン・同じパスになるときだけ返すようにした。回帰テストを足し、検査を外すと失敗することを確かめた |
| 入力中に自動更新で props が変わると、作成先が別のタブで切り替えたプロジェクトに変わる | 作成先を state で持ち、ダイアログを開いたときだけ設定するようにした。画面で確かめた（自動テストにはしていない） |

## 残したこと

- 日本語・英語の切り替えは PBI-4b（#11）で行う。
