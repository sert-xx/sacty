# ゲートウェイが受け取る本文の大きさに上限を設ける

- 日付: 2026-10-18（UTC）
- タスク: PBI-132
- PR: #144
- ブランチ: feat/issue-132-gateway-body-limit
- 関係する ADR: [ゲートウェイが受け取る本文に上限を設ける](../adr/20261018-0450-gateway-body-limit.md)

## 目的

1 つの工程のコンテナが、大きな本文を送り続けてデーモンのメモリーを使い尽くし、他のタスクを止められないようにする（Codex Security の指摘）。

## したこと

- デーモン（ゲートウェイ）
  - 本文を受け取る処理（すべての中継で共通）に、1 つの要求の上限（64 MiB。413）と、同時に受け取っている合計の上限（256 MiB。503）を入れた。
  - 断るときは、理由を返してから接続を切る。
  - 上流に送らないヘッダーに `expect` を足した（確認の中で見つけた不具合）。
- docs：仕様書（ゲートウェイ）、ADR。

## 確かめたこと

- `npx biome check`・`npm run typecheck`・`npx vitest run`・`npm run build` が通った。
- 次の修正を戻すと、テストが落ちることを確かめた：`Content-Length` での事前の確かめ、受け取った量での確かめ、合計の確かめ、応答を返し
  終えたときに空けること、境界（ちょうど・1 バイト多い）、組織内 PF・コンテキストの MCP・ホストの MCP の中継、`expect` を送らないこと。
  断ったときにその場で空ける処理は、戻しても接続が閉じるときに空くので、結果が変わらない（落ちない）。
- 既定の上限のゲートウェイに curl で送った：1 MiB とちょうど 64 MiB は中継し、65 MiB は `Content-Length` の有無にかかわらず 0.1 秒以内に 413。
- 確認の中で、curl の大きな本文（`Expect: 100-continue` が付く）が、上限と関係なく必ず 502 になる不具合を見つけて直した。
