# タスクの詳細で、工程ごとのエージェントを変えられるようにする

- 日付: 2026-10-17（UTC）
- タスク: PBI-121
- PR: #131
- ブランチ: feat/issue-121-step-agent
- 関係する ADR: [タスクの詳細で工程ごとのエージェントを人が変えられるようにし、config.yaml の step_agents より優先する](../adr/20261017-0005-step-agent-override.md)

## 目的

エラーで止まった・差し戻した工程だけ、より強いエージェントで実行し直せるように、タスクの詳細で工程ごとのエージェントを変えられるようにする。
config.yaml を書き換えずに、そのタスクのその工程だけを変える。

## したこと

- core：`StepAgentChanged` イベント・`ChangeStepAgentInput`、投影の `agents`・`agentChanges`、文言のコード（`agent.*`）。
- daemon：`SactyConfig.agents`・`stepAgentFor`（config.ts）、`changeStepAgent`・`pauseForMissingAgent`、工程の実行・マージの後の監視の確認・
  外部作業・書き出しで人が選んだエージェントを優先、状態に `agents`・`stepAgents`、`POST /api/tasks/:id/agents`。
- web：`changeStepAgent`・`changeStepAgentAction`、`StepAgentForm`、タスクの詳細の「工程のエージェント」の欄（`stepAgentRows`・
  `stepAgentOptions`）、作業履歴の行、辞書（日英）。
- docs：仕様書（タスクと工程の「工程のエージェントを人が変える」）、ユーザードキュメント（タスクを進める）、ADR。英語の版も直した。

## 確かめたこと

- `npx biome check`・`npm run typecheck`・`npx vitest run`・`npm run build` が通った。
- 回帰テスト（`daemon.test.ts`）：変えたことを作業履歴に残し、次の実行で使う（config より優先・モデルとエフォートも記録）、断る場合（無い名前・
  同じ名前・無い工程・設定を読めない・中止したタスク）、消えた名前で一時停止してエージェントを動かさない、状態の一覧に秘密を出さない。
  （`step-agents.test.ts`）：欄の行（決めた元・統合レビューを出さない・状態が無いとき）、選択肢（状態が無い・設定を読めない・stub の扱い）。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| 継承の名前（constructor・__proto__・toString）を、agents の名前として受け付け、実行で例外になる | 受け付けと実行の両方で、agents に書いた名前だけを認める（`definedAgent`。`Object.hasOwn`）。断ること・記録済みの継承の名前で例外にせず一時停止することの回帰テストを足した |
| 実行の準備の間の変更が、その後に始まる実行に反映されない | 工程の実行・監視は、準備の後に最新のタスクから読む。外部作業・書き出しは、準備の間に変わったら古いエージェントでは始めず、実行待ちのまま戻す。レビューの対象の確認・外部作業・書き出しの準備の間に変える回帰テストを足した |
| 名前の空白を除き、101 文字以上を断るので、別のエージェントを選んだことになる | 入力の名前を変えずに受け取る。空白を含む別名・長い名前の回帰テストを足した |
| 統合レビューも API では変えられる | `stepAgentChangeable` で、画面と API の両方で外す。API は `agent.stepNotChangeable` で断り、作業履歴に残さない。回帰テストを足した |
| （提案）優先順位のテストが default_agent との比較だけ。監視・外部作業・書き出しのテストが無い | 既定・step_agents・人の選択を別の名前にした。監視・外部作業・書き出しで、選んだエージェントを使うことと、名前が消えたら動かさないことの回帰テストを足した |
| （提案）設定・監視の仕様書が新しい優先順位と食い違う | 設定（configuration）・監視（deployment-watch）の仕様書（日英）に、人の選択を優先することと、この節へのリンクを足した |
| （再レビュー）外部作業で、接続先を調べている間に消えた名前から選び直すと、古い名前で止まる | 接続先を調べた後に、最新のタスクの指定で決め、開始の直前はその名前と比べる。消えた名前から有効な名前へ選び直す回帰テストを足した |
| （再レビュー）config.yaml の空の名前と、入力・作業履歴の制約が食い違う | config.yaml の agents の空の名前を、理由つきで誤りにした（`config.agentNameEmpty`）。default_agent が空の名前の設定を断る回帰テストを足した |
| （再々レビュー）準備の間に config.yaml に足した名前を選ぶと、古い設定で止まる | 準備の間に選び直した名前が、その実行が読んだ設定に無ければ、止めずに実行待ちのまま戻し、次の実行で最新の設定から決め直す（工程の実行・外部作業）。選び直していないのに無ければ、これまでどおり一時停止する。レビューの工程・外部作業で足した名前を選ぶ回帰テストと、戻し続けないことの回帰テストを足した |

## 残したこと

- 実機の AI では確かめていない（スタブの AI で画面を確かめた）。
