## 目的

MVP の土台として、デーモンと Next.js の2プロセス構成と追記専用の台帳を、最小の縦切りで通す。
`npm install` → `npm run build` → `npx sacty up` で起動でき、チケットを作ると台帳に記録され、タスクの一覧と詳細が見られることが
受け入れ条件の要点。再起動の後も同じ状態に戻ること、デーモンが localhost でだけ待ち受けることも求めた。

## したこと

- `packages/core`：台帳のイベントの定義と、イベントからタスクの状態を復元する処理。
- `apps/daemon`：SQLite の台帳（UPDATE・DELETE をトリガーで拒否）と Hono の API。127.0.0.1 でだけ待ち受け、起動ごとのトークンを必須にした。
- `apps/web`：Next.js 16 と shadcn/ui で、チケットの作成、タスクの一覧（タイトル・開始地点・工程・状態）、タスクの詳細（台帳つき）。
- `packages/cli`：`sacty up` でデーモンと画面を起動し、Ctrl+C で両方を止める。入口は `packages/cli/bin/sacty.js`。
- vitest は、当初の版の脆弱性（critical）を避けるため 5 系にした。
- `apps/web/AGENTS.md` は Next.js が生成するファイルで、そのままコミットした。

## 確かめたこと

- `npm test`（11件）・`npm run lint`・`npm run typecheck` が通った。
- `npx sacty up` で起動し、チケットの作成 → 一覧 → 詳細を画面で確かめた。タイトルが空のときの入力エラーの表示も確かめた。
- 停止の後に2つのプロセスが残らないこと、再起動の後も作ったタスクが表示されることを確かめた。
- 不正なポート番号（`abc`、`99999`、画面とデーモンで同じ番号）がエラーになることを確かめた。
- レビューの指摘の対応の後、まっさらな複製で `npm install` の直後に `node_modules/.bin/sacty` が作られ、`npm run build` → `npx --offline sacty up` で
  起動と Ctrl+C での停止ができることを確かめた。画面のポートを別のプロセスで塞いで起動し、終了コードが 1 になりデーモンが残らないことも確かめた。
- 再レビューでは `npm test`（15件）・`npm run lint`・`npm run typecheck` が通った。クリーンな環境での全体のビルドとブラウザでの表示は、再レビューでは確かめていない。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| 初回の `npm install` の時に `dist/index.js` が無いので、npm が `sacty` のコマンドを作らず、受け入れ条件の手順が失敗する | bin をリポジトリに含める小さな入口 `packages/cli/bin/sacty.js` にした（`dist` が無ければ、先にビルドするよう案内して終わる）。ロックファイルに残っていた古い bin も直した |
| 画面のポートが使用中で Next.js が終了コード 1 で止まっても、CLI は 0 で終わる | `process.exitCode` を先に設定し、すべての子プロセスが終わってからその終了コードで抜けるようにした。想定外の終了は、子の終了コードが 0 でも失敗として伝える。デーモンの起動待ちが時間切れになったときも、子を止めてから終わるようにした |
| 内容が 10,001 文字以上のとき、サーバーは拒否するがフォームに理由が出ない | 内容の欄にもエラーの文言と入力エラーの状態（`aria-invalid`・`aria-describedby`）を付け、上限超過の理由を日本語にした。確かめる途中で、内容の欄が際限なく伸びて作成のボタンが画面の外に出ることにも気づき、欄の高さに上限を設けた |
