# レビューの秘密値をデコードの後にも伏せ、書き出しの接続先を選んだものに縛る

- 日付: 2026-10-18（UTC）
- タスク: PBI-131
- PR: #143
- ブランチ: feat/issue-131-redact-and-export-access
- 関係する ADR: [出力の JSON はデコードした形でも伏せ、書き出しのトークンは選んだ接続先に縛る](../adr/20261018-0436-redact-decoded-json-and-export-access.md)

## 目的

実行に渡した秘密値が、JSON のデコードで元に戻って PR に投稿されないようにし、書き出しが選んだ接続先しか使えないようにする（Codex Security の指摘）。

## したこと

- デーモン
  - `redactEscaped`：出力の JSON の文字列のうち、エスケープを戻すと秘密値を含むものを、伏せた文字列に置き換える。
  - 実行の出力を伏せる所（`executeLogged`・Docker の実行）で、生の文字列を伏せた後に `redactEscaped` を通す。
  - 書き出しの実行も、ゲートウェイに許可リストを登録する。
- docs：仕様書（秘密情報・書き出し）、ADR。

## 確かめたこと

- `npx biome check`・`npm run typecheck`・`npx vitest run`・`npm run build` が通った。
- 次の修正を戻すと、テストが落ちることを確かめた：`executeLogged` での伏せ直し、Docker の実行での伏せ直し、書き出しの許可リスト、入れ子の
  JSON の確かめ、どの `"` からでも試すこと、改行のエスケープを含む文字列。
- レビューのタスクで、Unicode エスケープ・引用符と改行のエスケープを混ぜて秘密値を書いた出力が、行のコメント・差分の外の指摘・パスのどれにも
  秘密値を残さず、PR への投稿と作業履歴にも出ないことを確かめた。
