# PR のレビューが、大きな文書を丸ごと照合して判定を出せずに止まるのを直す

- 日付: 2026-11-14（UTC）
- タスク: PBI-343
- PR: #367
- ブランチ: feat/issue-343-review-scope-diff
- 関係する ADR: [PR のレビューでは文書の照合を差分の範囲に絞り、観点を見きれなくても要修正があれば判定を出す](../adr/20261114-0158-review-range-and-partial-verdict.md)

## 目的

PR #365 の再レビューが2回続けて判定「読み取れませんでした」になった。文書の同期の観点（U-1）が、差分に関係しない節まで含めて日英のユーザー
ドキュメントを丸ごと実装と照らし合わせようとして、終えられずに `failed` を返したため。照合の範囲を差分に絞り、観点を見きれなかったときも
要修正があれば判定を出させる。

## したこと

- 既定のレビュー（`apps/daemon/default-context/skills/review`）
  - U-1：検証できる記述・責務の記述を拾うのを依頼文の範囲の中に限った。範囲が変更なら、差分で変えた・足した記述と、差分の変更で正しさが
    変わりうる記述だけ。対象の文書を全体で渡されたときは全体。
  - 担当の規則：範囲の外を見なかったことを `failed` の理由にしない。
  - `pr-review` の「完了できないとき」：起動し直しても `failed` の観点が残ったとき、採用した `must` があれば判定「修正が必要」、無ければ判定を
    書かない。集約の記録の `verdict` の説明も合わせた。
- sacty がレビューに渡すプロンプト（`buildPrompt` のレビューの判定の指示）を同じにした。
- docs：仕様書（既定のコンテキスト・タスクと工程）・ユーザードキュメント（取り込み）を日英で直し、ADR を足した。

## 確かめたこと

- `npm run lint`・`npm run typecheck`：エラーなし。
- `npx vitest run --no-file-parallelism`：219 ファイルのうち、作業履歴の PR の番号の行（PR を作る前で空だった）の1件を除いて通った。番号を書いた後に `npx vitest run --no-file-parallelism tests/docs apps/daemon/src/prompts.test.ts apps/daemon/src/default-skills.test.ts` を実行し直し、5 ファイル・364 件が通った。
- プロンプトのテスト（`prompts.test.ts`）：判定の指示が、読めなかったときは付けない・見られなかった観点があっても要修正があれば `changes_required` を付ける・無ければ付けない、の3つを含むことを確かめた。

## レビューの指摘と対応（1回目）

判定は「修正が必要」（要修正 2 件・提案 1 件）。レビュアーは仕様書とユーザードキュメントの全文の照合を終えられなかったが、要修正があるので
判定を出した（この PR の決まりと同じ形）。

- [要修正] 判定の条件が「見られた観点で新しく採用した must」だけだと、再レビューで前回の must が未対応のまま・既存のレビュアーの must が
  重なりで除かれたまま、別の観点が失敗したときに判定が書かれない：数える must を「先頭のコミットで成り立つ must（新しく採用したもの、
  未対応と確かめた前回・既存のもの）」にした。`pr-review.md`・集約の記録・プロンプト・テスト・仕様書・ユーザードキュメント（日英）・ADR を合わせた。
- [要修正] U-1 が範囲の外の記述を拾う条件が、コード・設定の変更に限られていた（スキルの Markdown のように、文書が振る舞いを定める変更で、
  影響を受ける別の文書が外れる）：振る舞いを定める文書・仕様の変更で正しさが変わる記述（別の文書のものも）を含め、手順 3・5 と合わせた。
  仕様書（日英）・ADR も合わせた。
- [提案] 作業履歴の「下」に、実行し直したコマンドと結果が無い：コマンドと結果を書いた。
- 対応の後：`npm run lint`・`npm run typecheck`：エラーなし。`npx vitest run --no-file-parallelism`：219 ファイル・4265 件が通った（1 件スキップ）。

## レビューの結果（2回目）

判定は「読み取れませんでした」。前回の3件の対応は確認され、新しい指摘は無かった。レビュアーは仕様書とユーザードキュメントの全文の照合を
終えられなかった（動いている sacty の既定のレビューは、この PR で直す前の規則のため）。CI は通っている。指摘が無いことを人が確かめて、
マージすることにした。
