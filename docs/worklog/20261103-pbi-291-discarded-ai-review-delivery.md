# 古い head への AI のレビューを捨てたとき、その指摘を人に届ける

- 日付: 2026-11-03（UTC）
- タスク: PBI-291
- PR: #292
- ブランチ: feat/issue-291-pbi-291
- 関係する ADR: [古い head への AI のレビューを捨てたとき、その指摘を画面で人に届ける](../adr/20261103-0744-deliver-discarded-ai-review-to-person.md)

## 目的

実験 S14 r2 で、AI のレビューが README の API の表の更新を提案していたが、古い head へのレビューとして捨てられ（PBI-275）、人に届かないまま合格条件の一部が未達でマージされた。
捨てた指摘を、人が PR を承認・マージする前に気づける場所に出す。受け入れ条件：理由と要点またはリンクを届ける／人が新しい head に当てはまると判断したら今の仕組みで差し戻せる／自動で取り込まない／費用が増える届け方は実装の前に報告／0・1・複数件のテスト／docs。

## したこと

- 記録：`PullRequestReviewDiscarded` の `items[].summary`（任意）に、指摘の要点を残す。取り込む指摘と同じ文の先頭400文字で、投稿の目印（HTML のコメント）と「sacty のレビュー」の見出しを除き、空白をそろえる（`discardedSummary`）。
- 状態（`packages/core`）：`Task.discardedReviews` に積み、`discardedAiReviews` が、見守っている PR（承認ゲートの PR、または実装の作り直しの間の実装の PR）へのものを古い順に返す。マージされた PR のものは返さない。
- 画面（`apps/web`）：`DiscardedReviewNotice` を、承認の画面とタスクの詳細の上に出す。理由（古い head と、捨てた時点の PR の head）・対象の commit・要点・GitHub へのリンク・差し戻しで伝える案内（日英）。
- 届け方：画面に出すだけにした（理由は ADR）。PR への投稿と、新しい head へのレビューのかけ直しはしない。費用は増えない。
- docs：仕様書（approval。日英）、ユーザードキュメント（intake。日英）、ADR。

## 確かめたこと

- `npx biome check .`・`npm run typecheck`・`npx vitest run tests/docs`：結果は PR に書く。
- 足したテスト：
  - `packages/core`：捨てた指摘が0件・1件・複数件（回をまたぐ）・以前の記録（要点なし）・マージ後・別の PR・一時停止の間の PR。
  - `apps/daemon`：0・1・複数件で、要点（目印と見出しを除く・長い本文を切る・行へのコメントはファイルと行つき）とリンクが残ること、次の確認で重ねて数えないこと、自動では作り直しに取り込まないこと、人が同じ内容を差し戻すと人の指摘（`source` なし・actor `person`）になり差し戻しの回数に数えられ、AI のレビューの節に入らないこと。
  - `apps/web`：タスクの詳細と承認の画面で、0件は出ず、1件・複数件で理由・要点・リンクが出て、マージされたら消えること。
- 修正を戻すと落ちること：要点を記録しない・状態に積まない・画面の部品を外す、のそれぞれで、対応するテストが落ちる。

## 残したこと

- PR のマージまで出し続けるので、人が差し戻して直した後も、直した指摘が消えずに残る。
- PR に直接マージする人（sacty の画面を開かない人）には、PR 側の知らせは出ない（AI のレビュー自体は PR に残っている）。
