# PR の指摘による差し戻しを、人の確認を挟まずゴールガーディアンの判断だけで行う

- 日付: 2026-10-13（UTC）
- タスク: PBI-58
- PR: #64
- ブランチ: feat/issue-58-rework-without-confirmation
- 関係する ADR: [PR の指摘による差し戻しは、人の確認を挟まず、ゴールガーディアンが判断した工程にそのまま行う](../adr/20261013-1000-rework-without-human-confirmation.md)

## 目的

PR の指摘で、ゴールガーディアンが設計・要求要件まで戻すと判断したとき、人の確認（エスカレーション）を待たず、判断どおりに差し戻す。
受け入れ条件の要点は次のとおり。

- 設計・要求要件まで戻す判断のとき、人の確認なしにその工程へ差し戻され、やり直した成果が人の承認に回る。
- 実装だけのときは、これまでどおり実装をやり直して同じ PR を更新する。
- 判断できなかったときは実装のやり直しになり、そのことと理由が台帳に残る。
- 差し戻しの回数の上限を超えたら、これまでどおりエスカレーションになる。過去の `rework_confirmation` を含む作業履歴を読み込める。

## したこと

- 差し戻し（`apps/daemon/src/service.ts`）：ゴールガーディアンが判断した工程に人の確認なしで差し戻す。判断できなかった・候補に無い工程を
  返したときは実装のやり直しにする。上限を超えたときのエスカレーション（`too_many_changes`）は残した。
- 状態（`packages/core/src/events.ts`・`packages/core/src/projection.ts`）：最後に PR の指摘で戻した工程・判断の有無・理由・時刻を持つ。
  判断の後・反映の前に人が別の工程へ差し戻したときは、ゴールガーディアンの判断として残さない。
- ゴールガーディアンへの指示（`apps/daemon/src/prompts.ts`）：「人間の判断が必要」の文言を外し、そのまま差し戻すこと・前の工程を選ぶと
  人がもう一度承認することを書いた。
- 画面（`apps/web/src/components/pull-request.tsx`・`apps/web/src/i18n/messages/review.ts` ほか）：PR の欄に「戻し先」の行を足し、
  成果物チェックの PR の説明を新しい動きに合わせた。
- 過去の作業履歴の `rework_confirmation` のエスカレーションは、これまでどおり読める・画面で扱える。
