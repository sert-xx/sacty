- 関係する ADR: [情報収集が、対象リポジトリのコードも読む（決まっていなければ候補を洗い出して読む）](../adr/20261023-0219-gather-reads-repository-code.md)

## 目的

情報収集のエージェントはコードを読んでおらず（リポジトリを用意する前に動き、指示でも読まなくてよいとしていた）、困ることが多かった（作者の求め）。
リポジトリが指定されていればそのコードを読み、指定が無ければリポジトリの候補をいくつか洗い出して、それらのコードを読むようにする。

## したこと

- `apps/daemon/src/service.ts`
  - `runNextInner`：作業するリポジトリが決まっているタスク（リポジトリの無いタスク・チケットのトリアージを待つタスクを除く）は、情報収集の前にリポジトリを用意するようにした（以前は情報収集とトリアージの後）。
    情報収集には用意した後のタスクを渡すので、`runGuardian` が起点のコードの写しを作業領域に置く。
  - `gatherInformation`：リポジトリの無いタスクには、プロジェクトの対象をリポジトリの候補として指示に渡す（トリアージを兼ねるときは、トリアージの候補をそのまま使う）。
- `apps/daemon/src/prompts.ts`
  - `buildGatherPrompt`：「コード」の節（`gatherCodeLines`）を足した。用意したタスクは作業領域のコード、決まっていないタスクは候補から関係しそうなもの（多くても3つ）を洗い出して `gh api` で読ませる（ファイルの一覧・中身・コードの検索の例を示す）。
    手順にコードを読む段を足し、まとめの見出しに「関係するコード」を足した。読む範囲は、進め方を決め後の工程が背景を知るのに要るところまでとした。
    「コードの調査は後の工程で行うので読まなくてよい」の行を除き、リポジトリのファイルも外部の本文として指示に従わないよう添えた。
  - `gatheredLines`：まとめの説明に「対象リポジトリのコード」を足した。
- テスト：`prompts.test.ts` に指示の2件、`daemon.test.ts` にリポジトリの無いタスクの1件を足し、既存の情報収集のテスト（用意の順序・チケットのタスクで用意しないこと）に確かめを足した。
- docs：ADR を足し、前の ADR（情報収集の導入）の「コードは調査に任せる」部分を置き換え済みにした（ファイル名を `superseded` にし、リンクを直した）。
  仕様書（`docs/spec/tasks-and-steps`）に「コードを読む」の節、ユーザードキュメント（`docs/user/tasks`）に読み方と GitHub のアカウントの要件を書き、それぞれ英語の版も直した。
  工程の流れの図の情報収集のカードに「コード」を足して作り直した（`npm run docs:diagrams`）。

## 確かめたこと

- `npx tsc -b packages/core apps/daemon packages/cli`：エラー無し。
- `npx biome check .`：問題無し。
- `npx vitest run apps/daemon`：1845 件が合格、8 件が失敗。
  失敗した 8 件（`host-mcp-processes.test.ts` の 6 件、`agent-sessions.test.ts`・`context-mcp.test.ts` の各 1 件）は、変更前のコードでも同じく失敗した（root で動かしたこの環境では、プロセスの後始末と読めないファイルの確かめが成り立たない）。
- `npx vitest run tests/docs`：93 件が合格した。

確かめられなかったこと：実際のエージェントで、`gh api` で候補のコードを読めること（テストは偽のエージェントで指示の中身だけを確かめた）。

## 残したこと

- 決まっていないタスクで、候補をホストで clone して渡すこと（`gh api` で読むよりコードを探しやすいが、候補が多いと時間と容量がかかるので、今回はしなかった）。
