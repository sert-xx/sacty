# 予算の上限に達する実行で終えたレビューを、PR に投稿してから止める

- 日付: 2026-11-20（UTC）
- タスク: PBI-418
- PR: なし
- ブランチ: sacty/task-（PR の作成後に決まる）
- 関係する ADR: なし

## 目的

PR のレビューのタスクで、レビューの実行が予算の上限に達して終わると、書き終えたレビューが PR に投稿されないまま予算で一時停止していた。
再開まで投稿が遅れ、その間に PR が進んで、親のタスクが古いコミットへのレビューを捨てることがあった（PR #437 の子タスク）。
投稿は費用がかからないので、上限に達していても投稿し、止めるのは次の再レビューの実行の前にする。

## したこと

- `apps/daemon/src/service.ts`：`checkBudget` が、書いたレビューの投稿待ち（`awaitingReviewPost`）のタスクを止めない。投稿の後は、予算に達していないときと同じく、指摘なしなら完了し、そうでなければ見守る。次の再レビューは、実行の前の予算の確認で止まる。
- `apps/daemon/src/daemon-review-watch.test.ts`：投稿の前に止まる動きを前提にしたテストを、新しい動きに合わせた。指摘なしで完了する場合と、投稿の失敗で止まる場合のテストを足した。
- 文書：仕様書（`tasks-and-steps`）とユーザードキュメント（`intake`）の日本語と英語。

## 確かめたこと

- この版より前に、投稿の前に予算で止まったタスクは、`resume` が `pausedReason: budget` で上限を求めるまま変えていないので、上限を上げて再開すると投稿する。
- ADR は足していない（仕様書の「実行の前に止める」に沿った修正のため）。
