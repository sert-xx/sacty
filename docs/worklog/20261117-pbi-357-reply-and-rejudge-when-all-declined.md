# AI のレビューの指摘をすべて断って何も変えなかったら、断った理由を返信し、同じ先頭を 1 回だけ判定し直させる

- 日付: 2026-11-17（UTC）
- タスク: PBI-357
- PR: #402
- ブランチ: feat/pbi-357-reply-when-all-declined
- 関係する ADR: [AI のレビューの指摘をすべて断って何も変えなかったら、断った理由を返信し、同じ先頭を 1 回だけ判定し直させる](../adr/20261117-0250-reply-and-rejudge-when-all-findings-declined.md)

## 目的

実装が、AI のレビューの指摘をすべて「当たらない」と断り、コードを何も変えなかったとき、これまでは、断った理由が PR に返信されず、タスクが一時停止して人の判断を待っていた（PBI-347）。
人は、作業履歴から理由を探して判断することになり、レビューの子タスクは、断った理由を読まないままだった。

人が決めた形（2026-11-17）：断った理由を PR の指摘の場所に返信し、レビューの子タスクに、同じ先頭のコミットを 1 回だけ判定し直させる。レビューが受け入れれば先へ進み、もう一度指摘が出たら、一時停止して人が判断する。

受け入れ条件の要点（着手のときに固めた）：

1. やり直しの実装が何も変えず、最新の回の指摘のすべてが、AI のレビューの指摘（元のコメントの記録がある）で、すべてに「理由があって対応しなかった」の申告と理由があるとき、止めずに提出し、指摘ごとに理由を PR に返信する（返信の形・条件は、今の返信の仕組みと同じ）。
2. 返信が済んだ後、レビューの子タスクが、同じ先頭を 1 回だけ再レビューする。返信は、作者の返答として渡る。
3. 再レビューが指摘なしなら、ドラフトを外して、人の承認を待つ。
4. 再レビューに指摘が残れば、やり直しを始めずに「やり直しで変更が無いため一時停止」で止まる。同じ先頭の判定のし直しは 1 回だけで、デーモンの再起動・タスクの再開をまたいでも数え直さない。
5. 人の指摘が混ざっている・対応したと申告した指摘がある・申告の無い対応がある・対応の付いていない指摘があるときは、今までどおり、提出にせずに一時停止する（安全な側。着手のときに決めた。人の確認は、まだ）。
6. 元のコメントの記録が無い指摘（この返信の仕組みより前に取り込んだもの）は、返信できないので、今までどおり一時停止する。
7. 画面（一時停止の案内・作業履歴。ja・en）、仕様書・ユーザードキュメント（日英）、ADR、作業履歴に反映する。

範囲外：人のレビューの指摘（レビューの子タスクを待たない PR）、AI のレビューの往復の回数の上限そのもの。指摘への対応の申告の種類は増やしていない（「対応した」「理由があって対応しなかった」のまま）。

## したこと

- `packages/core/src/events.ts`・`projection.ts`
  - `ReviewRejudgeRequested`（PR・先頭のコミット・子タスク）を足した。PR を作ったタスクが、判定し直しを求めた先頭を `Task.reviewRejudge` に持つ。
  - `ReviewRestarted` の `reason` に `declined` を足した。子タスクが、判定し直した先頭を `Task.reviewRejudgeCommit` に持つ。
  - 上限は、この 2 つの記録（作業履歴）から復元する。メモリーには持たない。
- `apps/daemon/src/service.ts`
  - `publish`：変更の無いやり直しで、指摘が残る先頭のとき、`declinedEveryFinding` に当たれば、一時停止せずに、`ReviewRejudgeRequested` を PR の公開・提出と同じ追記で記録して、提出に進む。当たらなければ、今までどおり `ImplementationUnchanged` と一時停止を記録する。
  - 返信は、今の仕組み（承認待ちの提出の、まだ返信していない指摘に返信する）がそのまま行う。返信の処理は変えていない。
  - `reconcileReviewTasks`・`rejudgeDue`：子タスクがレビューした先頭が今の先頭と同じでも、親が判定し直しを求めていて、返信するものが残っておらず、その先頭をまだ判定し直していなければ、`ReviewRestarted`（`reason: declined`）で再レビューを始める。
  - `settleReview`・`rejudgeLeftFindings`・`requestChanges`：判定し直したレビューの指摘（すべてが、その子タスクの最後の回の AI のレビューの指摘）を取り込んだら、差し戻しと同じ追記で、一時停止（理由 `unchanged`、文言 `implement.declinedAgain`）を記録する。
- `apps/daemon/src/prompts.ts`（`rejudgeLines`）：判定し直す回のレビューの指示に、作者が断った理由が成り立つかを先頭のコードで確かめ、成り立つなら取り下げ、成り立たないなら未対応として残すことを足した。
- 画面（`apps/web/src/lib/labels.ts`・`apps/web/src/i18n/messages/labels.ts`）：作業履歴の 2 つの行（判定し直しを求めた・同じコミットを判定し直す再レビューを始めた）と、一時停止の案内の文を、ja・en で足した・直した。
- 文言（`packages/core/src/messages.ts`）：`implement.declinedAgain`（ja・en）。
- 決めたこと
  - 提出にして返信する形にした。提出にしないまま返信するには、返信の条件と、返信を待つ新しい状態を足すことになるため（ADR の理由）。
  - 判定し直しても指摘が残ったときは、差し戻しを記録して、やり直しを始めずに止める形にした。差し戻してやり直させると、AI どうしの往復がもう 1 回続くため。
  - GitHub のアカウントを選んでいないプロジェクトの扱いは、条件に入れていない。アカウントが無ければ、PR の更新そのものができずに止まるので、ここには来ない（テストを書いて、来ないことを確かめた上で、条件から外した）。
  - 断った理由の返信を投稿できなかった（失敗を記録した）ときも、判定し直しは始める（その再レビューには理由が渡らない）。仕様書と ADR に書いた。
