# 要求要件・設計の差し戻しで、成果物を丸ごと作り直さず、指摘の所だけ直す

- 日付: 2026-11-01（UTC）
- タスク: PBI-265
- PR: なし
- ブランチ: feat/issue-265-partial-rework
- 関係する ADR: [要求要件・設計の差し戻しでは、前回の成果物を元に、指摘に関わる所だけを書き換える](../adr/20261101-1355-partial-rework-of-requirements-and-design.md)

## 目的

実務での実証実験で、要求要件・設計が全費用の約 9 割を占め、差し戻すと丸ごと作り直していた（S10 は、確認したいことへの答えを反映するだけの差し戻しで、差し戻し後の実行のほうが高かった）。
人が決めた方針「指摘の所だけ直す」に従う。

受け入れ条件の要点：

- 要求要件・設計の差し戻しは、前回の成果物を元に、指摘に関わる所だけを書き換える。関係の無い節は保つ。
- 指摘が小さいときは、セルフレビューの回数を減らす。判断の基準は仕様書に書く。
- 質の基準（必須の節・ID・確認したいことの扱い）は、作り直しでも保つ。
- 1回あたりの費用が下がることを、テストかログで示す。
- 仕様書・ユーザードキュメント（日英）・ADR・作業履歴を直す。

## したこと

- `apps/daemon/src/prompts.ts`：
  - 要求要件・設計の指示に、指摘（無効にしていないもの）があり、前回の下書きが読めるときの「差し戻しの直し方」（`reworkLines`）を足した。関係の無い所を保つ、複数の節にまたがる指摘・方針を変える指摘の扱い、質の基準を保つこと、確認したいことへの答えの反映、成果物の全体を出し直すこと。今回の指摘は、その工程の最新の差し戻しの回のもの。
  - 前回の下書きが空のときは、元にできないので書き直させる（`reworkMode` が `unreadable`）。セルフレビューは通常どおり。
  - セルフレビューの指示（`selfReviewLines`）に、差し戻しの直しのときだけ、範囲を差分に絞ることと、小さい指摘なら回数を初回を含めて 2 回までにすることを足した（`partialReworkReviewLines`）。判断に迷えば通常の 5 回。どちらで進めたかを `summary` の最初に書かせる。
  - 指摘が無いやり直し（要求要件が変わっただけの設計）、実装・文書作成・調査の指示は変えていない。
- 仕様書（日英）：「要求要件・設計の差し戻しの直し方」の節を足し、「提出の前のセルフレビュー」から参照した。ユーザードキュメント（日英）：「差し戻したときの直し方」の節を足し、セルフレビューの節に回数の違いを足した。ADR を足した。
- 小さい指摘の基準（直す所が 2 か所以内で方針を変えない）と回数（2 回）は、見積り。実際の差し戻しの結果を見て直す。sacty が機械的に判定する案は採らなかった（ADR）。

## 確かめたこと

- `npx vitest run apps/daemon/src/prompts.test.ts`：163 件が通る。追加した 9 件（「差し戻しは前回の成果物を元に、指摘の所だけ直す（PBI-265）」）：
  - 要求要件・設計のやり直しの指示に、前回の下書き・指摘・直し方・全体を出し直すことが入る。初回と、指摘の無い設計のやり直しには入らない。
  - 質の基準の指示（確認したいこと・EARS・ID・分量・指摘ごとの対応の報告）が、やり直しの指示に残る。
  - 差し戻しが 2 回目のとき、今回の指摘と前の回の指摘を分ける。無効にした指摘は数えない。
  - セルフレビューの回数の違い（小さい指摘は初回を含め 2 回、それ以外は 5 回）と、範囲を差分に絞ること。通常の指示と報告の形は変わらない。
  - 前回の下書きが空・空白だけ・無いとき、元にせず書き直させ、セルフレビューは通常のまま。
  - 実装の指示には出ない。
  - `prompts.ts` を元に戻すと、7 件が落ちる（残る 2 件は、出ないことを確かめるもの）。
- `npm run lint`・`npm run typecheck`・`npx vitest run tests/docs`：通る。
- `npx vitest run`（全体）：3221 件が通り、4 件が落ちた。`install-security-tools.test.ts` の 2 件は `/usr/local/bin` に書けない環境のため（既知）。`ci.test.ts`・`prompts.test.ts` の 1 件ずつは、長い文字列の処理時間が 1 秒以内かを見るテストで、全体を並列に実行した負荷で超えた。単独で実行すると通る。
- 確かめられなかったこと：
  - 実際の費用の比較。同じ依頼で差し戻しを入れた実行を、この変更の前後で行わないと取れない。
    参考の前の実績（このリポジトリの試行の記録）：S10 は要求要件 1 回目 $25.23（セルフレビュー 2 回）、差し戻し後 $34.94（3 回）。S8 は 1 回目 $38.24（4 回）、差し戻し後 $47.79（3 回）。
  - エージェント（LLM）が、指示のとおりに関係の無い所を保ち、小さい指摘を正しく判断するか。
