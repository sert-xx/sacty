# PR の本文の作業領域へのリンクの変換の残り（つながる文字・表の縦棒・マージした本文）

- 日付: 2026-11-17（UTC）
- タスク: PBI-385
- PR: #424
- ブランチ: feat/pbi-385-pr-body-links-leftovers
- 関係する ADR: なし

## 目的

sacty が作る PR の本文から、コンテナの作業領域へのリンクを外す変換（PBI-366。#403）に、見直しで3点が残っていた。仕様書が言うことと、コードがすることを合わせる。

1. リンクを外した後の文字が、後ろの文字とつながって、メンション・Issue の参照・自動リンクができる（`ping [@](/workspace)octocat please` が `ping @octocat please` になる）。確かめていたのは、表示の文字の中と、直前の1文字だけ。仕様書とコードのコメントは、外への作用を起こさないと言い切っていた。
2. 表の中で、パスに縦棒があるリンクを外すと、添えたパスの縦棒で行のセルが割れ、隣のセルが表示から消える。
3. すでにある PR の更新で、人の直しとマージした本文・エージェントがまとめた本文は、変換も、その後の伏せ直しも通らない。仕様書の「作成と更新のどちらの本文にも行う」は、言い過ぎだった。

方針は、仕組みを広げず、迷う形は変えずに残す側（開けないリンクが残るだけ）に倒すこと。新しい変換は足さず、変えないリンクの判定だけを足す。

## したこと

- `apps/daemon/src/pr-body-links.ts`
  - 置き換えた後の本文で、置き換えた文字が、周りの文字とつながるかを確かめる（`joinedSpans`・`activeRuns`）。メンション・メールアドレス、Issue・PR の参照、自動リンク、打ち消し線の記号の並びを本文から拾い、置き換えた文字と重なるか隣り合い、かつ、その外へ続く並びがあれば、そのリンクを変えない。当たったリンクを除いて、もう一度置き換え、それでも当たるリンクがあれば、本文を変えずに返す。
  - バックスラッシュによる打ち消し・文字参照は、書いた文字のままでは並びを読めない（`w\@example.com` は `w@example.com` と読まれる）。読まれる文字に直して確かめる仕組みは足さず、それを含む、空白までの文字のかたまりを、並びとして扱う（変えない側に倒す）。
  - 表示の文字の確かめ（`activeOutsideLink`）に、`GH-` に数字が続く形・打ち消し線の記号（`~`）・`@` の後ろの `.`・`_`・`-` を足し、読まれる文字（`readLabel`）でも確かめる。
  - パスに縦棒があるリンクは、変えない。
  - `unlinkedMergedBody` を足した。マージした本文・まとめた本文からリンクを外し、本文が変わったときだけ秘密の値を伏せ直し、伏せた結果が長さの上限を超えるときは、外すのをやめる。
- `apps/daemon/src/service.ts`：`reconcilePullRequestBody` が返す本文（マージの結果・エージェントがまとめた本文）に `unlinkedMergedBody` を通す。呼び出しの3か所（実装の PR・要求要件と設計の PR・重ねた PR の向き先の付け替え）から、その PR の作成で使った秘密の値を渡す。
- 仕様書（日英）：`docs/spec/approval`（「長さ・秘密の値・台帳」「人が直した本文の更新」）。変えないリンクの種類と、確かめない種類を書いた。

## 自分で決めたこと

- 3 は、実装した。外すリンクが無い本文は、そのまま使う（伏せ直しもしない）ので、作業領域へのリンクが無い本文では、これまでと同じ本文で更新する。
- 外して本文が変わったときの伏せ直しは、本文の全体に行う。人が書いた文字も、秘密の値と同じなら伏せる。
- 見つけたうち、次は対応しなかった（仕様書に、確かめない種類として書いた）：コミットの SHA のリンク、絵文字、タスクリストのチェックボックス、表の中で、セルが空になる・行が区切りの行の形になる・添えたパスのバッククォートが、同じセルの組になっていないバッククォートと組になること。どれも、対応には、表の行やバッククォートの組を自前で読む仕組みが要る。
