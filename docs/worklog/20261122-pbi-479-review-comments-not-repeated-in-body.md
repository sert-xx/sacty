# PR のレビューで、行へのコメントにした指摘を、本文に重ねて書かない

- 日付: 2026-11-22（UTC）
- タスク: PBI-479
- PR: なし
- ブランチ: main
- 関係する ADR: [PR のレビューで、行へのコメントにした指摘は、本文に重ねて書かない](../adr/20261122-0254-review-comments-not-repeated-in-body.md)

## 目的

行へのコメントにした指摘と同じ内容が、レビューの本文の「指摘」の節にも書かれ、人が同じ指摘を 2 回読んでいた。重ねないようにする。

## したこと

- レビューの指示（`prompts.ts`）で、行へのコメントにした指摘を本文のどの節にも書かせず、本文の「指摘」の節には行へのコメントにしない指摘だけを書かせるようにした（`HEAD_CHECK_LINES`・本文の指摘の行・`reviewRecordInstructionLines` も同じ形）。総評に件数を書かせない。
- `buildReviewBody` に、判定の行のすぐ下の「行へのコメントに N 件の指摘があります。」を足した（行へのコメントを投稿するときだけ。0 件と、本文に入れて投稿し直すときは足さない）。判定が無い・読めない回の案内を「本文と行へのコメントを確かめてください」にした。
- 再レビューの指示に、前回の行へのコメントを場所と状況だけで挙げることと、前回の件数の行が指摘でないことを足した。直しの側の説明に、件数の行は別の指摘でないことを足した。
- 既定のスキルの `pr-review.md`（依頼した側が投稿するときも重ねない）と `aggregation.md`（他の現れの列挙先）を直した。
- 仕様書（`tasks-and-steps`・`context`、日英）・ユーザー文書（`intake`、日英）・ADR を合わせた。
- 指摘の読み取り（`suggestion-triage.ts`・`github.ts`・`review-comments.ts`）のコードは変えず、本文が減った形で動くことをテストで確かめた（`review-comment-no-overlap.test.ts`）。

## 既定で決めたこと

- 件数は sacty が数えて足す。エージェントには総評に書かせない。

## 確かめたこと

`npm run lint`・`npm run typecheck`・`npx vitest run`・`npm run build` の結果は、実装の説明に書いた。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| （設計のレビューの指摘 6 件・3 件） | 設計に反映済み。実装は承認済みの設計に従った |

## 残したこと

- 件数の行の置き場所（判定の行の下）と、総評に件数を書かせない決めは、利用者の確認（Q-1）に出した。
