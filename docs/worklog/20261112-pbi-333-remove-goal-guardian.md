# ゴールガーディアンを撤去する（変更の申し出は人が判断、統合レビューは統合レビューの工程のエージェント）

- 日付: 2026-11-12（UTC）
- タスク: PBI-333
- PR: #351
- ブランチ: feat/issue-333-remove-guardian
- 関係する ADR: [ゴールガーディアンを撤去し、変更の申し出は人が判断し、統合レビューは統合レビューの工程のエージェントが行う](../adr/20261112-0820-remove-goal-guardian.md)

## 目的

ゴールガーディアンという別の判定役をなくし、変更の申し出は人が決め、それ以外は工程と PR のレビューの中で進むようにする。

## したこと

- デーモン：
  - 変更の申し出は、AI の判定を挟まずに人の判断待ちにする（`TaskEscalated` の `reason: change_proposed`）。以前の版で判定の途中に止まった申し出は、起動のときに人の判断待ちにする。
  - 統合レビューは `step_agents.integrate`、無ければ `default_agent` で行い、作業履歴の actor を `agent` にした。
  - `guardian_agent` を読み捨てて警告にし（`config.guardianAgentIgnored`）、`audit_agent` の既定を `default_agent` にした。
  - 実装後のコードの写しを `workspaces/_code-copy` に作り、残った `_guardian` は起動のときの片付けで消す。
  - 今の流れでエージェントが読む指示（変更の申し出・セキュリティ対応・実装・統合レビュー・PR の本文・オーケストレーター・情報収集など）から、ゴールガーディアンの語を外した。
- 画面：文言（日英）・費用の内訳・作業履歴の表示から、ゴールガーディアンの語を外した。古い作業履歴の実行・判定・費用は、以前の版の記録として出す。変更の申し出の判定中に一時停止できない制限を外した。
- docs：仕様書・ユーザードキュメント（日英）・README・図から、ゴールガーディアン・`guardian_agent`・`_guardian` の記述を今の振る舞いに直し、ユーザードキュメントに変更の申し出の節を足した。ADR を足し、統合レビューをゴールガーディアンが行うと決めた ADR を置き換え済みにした。
- 最終レビューの仕組み（依存 `finalReview` を有効にしたときだけ動く、以前の版のもの）と、その中の文言は残した（別の変更で消す）。

## 確かめたこと

- `npm run lint`・`npm run typecheck`：エラーなし。
- `npx vitest run`：全体が通った。
- `npx vitest run tests/docs`：通った。
- 新しいテスト：
  - 変更の申し出は AI の判定を挟まずに人の判断待ちになり、認める・認めないの後の扱いは今までと同じ。
  - 以前の版で判定の途中に止まった申し出は、再起動のときに人の判断待ちになる。
  - 統合レビューは `step_agents.integrate`、無ければ `default_agent` で動く。
  - `guardian_agent` が書いてあっても起動し、警告を出す。監査は `default_agent` を使う。
  - コードの写しは `_code-copy` に作り、残った `_guardian` は起動のときに消す。
  - 画面の文言（日英）にゴールガーディアンの語が無い。

## レビューの指摘と対応（1回目）

判定は「提案あり（マージは可）」。

- [提案] 変更の申し出の通知が、承認待ちではないので使えない承認の画面へリンクしていた。
  → 判断の欄のあるタスクの詳細の申し出の欄（`/tasks/<ID>#proposals`）へリンクし、申し出であることを文にも書いた。仕様書の通知（日英）も直した。
- [提案] 質問への答えの指示で、役割 `guardian` の実行を「統合レビュー」と名付けていた（以前の版の変更の申し出の判定なども同じ役割で記録されている。今の統合レビューは工程の役割で動く）。
  → 「以前の版の AI の判定（ゴールガーディアン）」にした。
- [提案] ユーザードキュメントのイメージ（日英）が、テストをいつも最終レビューのエージェントが実行するように書いていた。
  → 今は実装の工程のエージェントが実行すると書き、最終レビューの動きは以前の版のものとして分けた。

確かめたこと：

- 新しいテスト：変更の申し出の通知は、タスクの詳細の申し出の欄へリンクする（日英）。修正を戻すと落ちることを確かめた。

## レビューの指摘と対応（2回目）

判定は「提案あり（マージは可）」。

- （前回の提案の未対応）変更の申し出の判断待ちには `task.escalation` が付かないので、通知の申し出の欄へのリンクに分かれていなかった。
  → エスカレーションで、判定の無い申し出（`openProposal`）があるかで見分けるようにした。テストを投影と同じ形（`escalation` が無く、申し出がある）にし、実際の流れのテストでも通知のリンクを確かめた。仕様書の通知（日英）の書き方も合わせた。

## レビューの結果（3回目）

判定は「指摘なし」。前回までの指摘は、いずれも対応を確認された。CI はすべて通った。
