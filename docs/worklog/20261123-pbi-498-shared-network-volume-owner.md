# 共通ネットワークとボリュームの残りを回収する

- 日付: 2026-11-23（UTC）
- タスク: PBI-498
- PR: なし

- 関係する ADR: [共通ネットワークと名前付きボリュームを所有者の印で回収する](../adr/20261123-1625-shared-network-volume-owner.md)

## 目的

異常終了後に残る共通ネットワークと名前付きボリュームを回収する。

## したこと

所有ラベルを付け、起動時に持ち主と資源の種類を確認して回収する。
仕様の日英を合わせた。

## 確かめたこと

| コマンド | 結果 |
| --- | --- |
| `npm run lint` | 通過 |
| `npm run typecheck` | 通過 |
| `npm run build` | 通過 |
| `npx vitest run tests/docs` | 99 件通過 |
| `npx vitest run apps/daemon/src/services.test.ts` | 59 件通過 |
| `npm test` | 348 ファイル、7269 件通過、14 件スキップ（追加テストの前） |

回収を無効にすると終了済み資源のテストが失敗することを確認した。
スキップのうち13件は環境の Git が `merge-tree --merge-base` に対応しないため、1件は実際の AI を使う任意の評価である。
実際の Docker での確認は依頼者がマージ前に行うため、この工程では実行していない。

## レビューの指摘と対応

### 設計のレビュー

プロセス表をプロジェクトの判定前と資源の一覧取得後に読む。
入力の資源に書かれた所有ラベルを除き、回収対象を作り方でも絞る。
別マシン、`hidepid`、新旧版の共存、匿名ボリュームとイメージ取得は依頼者の判断で対象外とした。

### この PR の最初の提出

まだ無い（最初の提出）。

## 残したこと

依頼者がマージ前に Docker のあるホストでデーモンを強制終了し、コンテナを削除して再起動した後、共通ネットワークと名前付きボリュームが消えたことを確認し、手順と出力を記録する。

## 実際の docker での確かめ（マージの前、2026-11-24）

Docker Engine 29.5.3・Docker Compose v5.3.1（macOS）で、PR の先頭（553da9f6）をビルドして確かめた。デーモン役の子プロセスが、ビルドした `DockerComposeServices.startGroup` で2つの compose（名前付きボリューム `dataa`・`datab`）を起動し、持ち主はその子自身にした。起動時の片付けは、一時的な `SACTY_HOME` と別のポートで起動した本物の `sacty up` で走らせた。

- 起動したとき：共通のネットワーク `sacty-svc-<runId>-network` と、名前付きボリューム `sacty-svc-g0<runId>_dataa`・`sacty-svc-g1<runId>_datab` に `io.sacty.owner=<PID> <開始時刻>` が付いた。
- 持ち主が動いている間（コンテナを `docker rm -f` で消し、子は生かしたまま `sacty up`）：共通のネットワーク・2つのボリュームは消えなかった。失敗のログは出なかった。PASS。
- 止めずに終わらせた後（子を `kill -KILL` し、コンテナを消して `sacty up` を起動し直す）：共通のネットワーク・2つのボリュームが消えた。失敗のログは出なかった。PASS（TV-12）。
- おとり（ラベルの無い同じ名前の形のネットワーク、名前の形が違う・プロジェクトのラベルがあるネットワーク、ラベルの無いボリューム、プロジェクトのラベルが無い・`sacty-svc-` でないプロジェクトのボリューム。ラベルのあるものは持ち主の終わった値）：どれも消えなかった。PASS。
- 修正を戻した版（main の `services.ts`）で同じ手順：共通のネットワーク・ボリュームにラベルが付かず、起動し直した後も残った。PASS（修正が効いている）。

確かめられなかったこと：実際のタスクの工程の実行中にデーモンを強制終了する形は取っていない（デーモン役の子で代えた）。コンテナが残ったまま持ち主が動いている形の片付けは試していない。

見つかった残り（範囲の外、後続へ）：compose が各プロジェクトに作る `sacty-svc-g<N><runId>_default` のネットワークは、持ち主のラベルが無くプロジェクトのラベルがあるので、この回収の対象にならない。コンテナを消した後は `compose ls --all` にも出ないので残る（main と同じ振る舞い）。
