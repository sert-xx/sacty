# 取り込みのラベルを sacty 全体の設定にし、対象の Issue と PR を取り込む

- 日付: 2026-10-11（UTC）
- タスク: PBI-26
- PR: #31
- ブランチ: feat/issue-26-intake-label
- 関係する ADR: [取り込みのラベルを sacty 全体の設定にし、すべてのプロジェクトの対象で、そのラベルの付いた開いている Issue と PR をタスクにする](../adr/20261011-1541-global-intake-label.md)

## 目的

ステークホルダーの要望（トリアージはラベルで自動でよいが、ラベルはプロジェクトごとではなく sacty 全体の設定にする）に対応する。sacty 全体の設定でラベルを決め、すべてのプロジェクトの対象で、そのラベルの付いた開いている Issue と PR を取り込む。PR から作ったタスクはその PR をレビューの対象にする。未設定なら取り込まず、そのことを画面に出す。

## したこと

- sacty 全体の設定（`apps/daemon/src/settings.ts`）：`~/.sacty` の SQLite の `settings` テーブル（1行）に取り込むラベルを持つ。設定の API を足した（`apps/daemon/src/server.ts`）。画面はユーザーメニュー →「sacty の設定」（`/settings`、`apps/web/src/components/settings-form.tsx`）。
- 取り込み（`apps/daemon/src/service.ts`・`apps/daemon/src/github.ts`）：検索の条件は `is:open {org|repo}:... label:"..."` で、Issue と PR の両方を探す。PR も Issue と同じ判定で二重に取り込まない。ラベルを変えると先頭から読み直す。
- PR から作ったタスク：取り込み元を `github_pull_request` として記録し、画面からその PR を開ける。本文に PR の URL が無くてもその PR をレビューの対象にし、オーケストレーターにレビューを候補に出す。調査の結果は PR にもコメントで返す。
- 未設定のとき：取り込まない。設定画面とプロジェクトの一覧の取り込みの状態に、そのことと設定画面へのリンクを出す。
- 入力の検査：ラベルの `"` と `\` は受け付けない。空の入力は「設定しない」にする。PBI-25 で固定していた `sacty` は削った。
- 途中のコミットで、プロジェクトの一覧の取り込みの見出しを「GitHub Issue・PR の取り込み」にした（日英2か所の文言）。

## 確かめたこと

- テスト：301件が通った。ラベルの設定（未設定なら取り込まない、空白の除去、変えたら読み直す、不正な文字の拒否）、PR の取り込みとレビューの対象、PR への調査の結果のコメント、状態に出すラベル、設定の API（読み書きと 400）、設定の保存先（SQLite で開き直しても読める）、検索の結果に PR を含めることを足した。
- 次の修正を外すと、それぞれテストが失敗することを確かめた：未設定なら取り込まない、PR として記録、PR をレビューの対象にする、PR にコメント、検索で PR を含める、ラベルの変更で読み直す。
- リント・型チェック・ビルドが通った。
- 一時的な環境で画面を確かめた：未設定のときプロジェクトの一覧に案内が出た。ユーザーメニューから「sacty の設定」を開き、ラベルを保存できた。保存の後、取り込みの状態に「取り込むラベル：sacty」と出た。
- レビューで、全301件のテスト・lint・typecheck が通った。見出しの文言の修正は、レビューで差分だけを確かめ、テストは実行し直していない。レビューでは、ブラウザ操作・実際の GitHub での取り込みと投稿・実際の AI・ビルドは行っていない。

## レビューの指摘と対応

指摘は無かった（承認のみ。マージ後の再確認でも、見出しの文言の修正だけで追加の指摘は無かった）。

## 残したこと

- 取り込むラベルは未設定の状態から始まるので、取り込みを使うには「sacty の設定」でラベルを設定する必要がある。
