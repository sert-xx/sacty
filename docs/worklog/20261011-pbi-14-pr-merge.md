# 成果物チェックを PR のマージで承認する

- 日付: 2026-10-11（UTC）
- タスク: PBI-14
- PR: #20
- ブランチ: feat/issue-14-pr-merge
- 関係する ADR: [PR のあるタスクの成果物チェックは、最新の提出の PR がマージされたことを承認とみなし、画面では承認しない](../adr/20261011-0010-superseded-deliverable-check-by-pr-merge.md)

## 目的

画面で成果物チェックを承認しても PR がマージされないという動作確認のフィードバックに対応する。成果物チェックを PR の上で判断し、マージを承認・完了とする。範囲が広いので PBI-14 を2つに分け、このタスク（PBI-14a）は、マージでの承認・完了、閉じられたときの扱い、画面の案内を受け持つ。PR のレビューを差し戻しとして取り込むのは次の PBI-14b に回した。

## したこと

- PR の見守り：`apps/daemon/src/pr-watcher.ts`（`PullRequestWatcher`）が1分ごとに、成果物チェックで待っているタスクの PR の状態を、プロジェクトの gh のアカウントで読む（`apps/daemon/src/github.ts`）。確かめられないときは何も記録しない。確認は重ならず、失敗しても止まらない。
- 状態ごとの扱い（`apps/daemon/src/service.ts`）：マージされたら `PullRequestMerged`（マージした人）と成果物チェックの承認（`StepApproved`）を人間の操作として記録して完了にする。閉じられたら `PullRequestClosed` を記録して判断を待つ。開き直されたら `PullRequestReopened` を記録してマージを待つ。
- 作業履歴の出来事と状態：`packages/core/src/events.ts`・`packages/core/src/projection.ts`・`packages/core/src/messages.ts`。
- 画面からの承認の拒否：PR のあるタスクは、理由つきで拒否する（`gate.approveOnPullRequest`）。
- 画面：PR のあるタスクの成果物チェックは承認のボタンを出さず、PR で判断する案内とリンクを出す。状態は「PR のマージ待ち」「PR が閉じられた（判断待ち）」と出す（`apps/web/src/components/gate-form.tsx` ほか）。
- レビューの対応：PR の状態に先頭のコミット（`head.sha`）を含め、マージされたコミットが記録済みの提出と一致するときだけ承認する。一致しなければ `PullRequestMerged`（`outdated: true`）を記録して判断を待つ（状態は「古い提出がマージされた（判断待ち）」）。再提出のとき前の PR がマージ済みなら、新しい PR を作る。

## 確かめたこと

- `npm test`：230件が通った（7件追加、既存の1件を「マージで承認」の形に更新）。見守り（アカウントのトークン、失敗でやり直す、閉じられたら待つ、二重に記録しない、開き直し、マージで完了、完了したら確かめない）、画面からの承認の可否、PR の状態の読み分け、確認が重ならないこと、作業履歴の状態・表示を確かめた。マージで承認するのをやめるとテストが失敗することを確かめた。
- 実物の GitHub で、試し用のリポジトリのマージ済みの PR の状態を、プロジェクトの gh のアカウントのトークンで読み、gh の表示どおりに `merged` とマージした人を読めた。
- レビューの対応の後、同じ PR の `head.sha` が、sacty がそのとき記録したコミットと一致することを実物の GitHub で確かめた。
- 再レビューで、`npm test`（232件）・`npm run lint`・`npm run typecheck` が通った。
- 画面は、成果物チェックで待っているタスクが無かったため、ブラウザでは確かめていない（型チェックと文言のテストだけ）。実物の GitHub でのマージ操作も確かめていない。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| 画面から差し戻した後、再提出の前に元の PR がマージされると、PR 番号とマージ済みかだけで判断するので、元の PR に含まれない再提出まで承認してしまう | マージされたコミット（`head.sha`）と記録済みの提出のコミットを照合し、一致するときだけ承認するようにした。一致しなければ `outdated` として一度だけ記録し、人間の判断を待つ。再提出のとき前の PR がマージ済みなら新しい PR を作る。回帰テストを足し、修正を戻すと失敗することを確かめた |

## 残したこと

- PR の Request changes などのレビューを差し戻しとして取り込むこと、作業履歴へのレビューの取り込みの記録は、PBI-14b で行う。
- 画面のブラウザでの確認、実物の GitHub でのマージ操作は確かめていない。
