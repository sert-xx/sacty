# 言語ごとのイメージで、HOME と GOPATH をエージェントを動かす node ユーザーの場所にする

- 日付: 2026-10-13（UTC）
- タスク: PBI-41
- PR: #59
- ブランチ: fix/issue-41-go-home
- 関係する ADR: なし

## 目的

利用者の Go のイメージから作った言語ごとのイメージで、エージェントが `GOPATH` に書き込めず、書き込める一時的なディレクトリを
自分で設定して試行錯誤していた、という報告への対応（PBI-41 の不具合）。CI のイメージは `HOME`・`GOPATH` を root 向けの場所
（`/root`・`/root/go` など）にしていることがあり、エージェントを動かす `node` ユーザーではそこに書けない
（Go のモジュール・ビルドのキャッシュ、`go install`、Maven の設定など）。

## したこと

- `packages/cli/docker/Dockerfile`：言語ごとのイメージで `HOME=/home/node`・`GOPATH=/home/node/go` にし、`/home/node/go/bin` を
  PATH の最後に足した（`go install` で入れたツールを使えるように）。元のイメージの PATH は残す。`GOPATH` は、これまでどおり
  `images` の `env` で上書きできる。Go の入っていないイメージでは使われないだけ。
- エージェントの CLI の導入（root で実行する `npm install -g`）のキャッシュは一時的な場所に置いて消し、root の手順が
  `/home/node` の下に作ったもの（npm のログなど）は `node` ユーザーの持ち物に戻すようにした。
- 既定のイメージ（`image_build`）は変えていない。`README.md` の説明を直した。

## 確かめたこと

- 手元で、`HOME=/root`・`GOPATH=/root/go`・`/root` を 700 にした Go のイメージを元にして、報告と同じ状況を作った。
- 実際にイメージを作って確かめた。
  - 再現用の Go のイメージ：`node` ユーザーで `go build` が通る、`go install` で入れたツール（stringer）が PATH から使える、
    npm のキャッシュに書ける、Claude Code が動く。
  - 既定のイメージ：これまでどおり作れる（`GOPATH` は設定しない。`/home/node` に root の持ち物を残さない）。
- build・typecheck・lint・全テストが通った。レビューでは、525 件のテスト（35 ファイル）・lint・typecheck の成功を確かめた。
- 未確認：最終ステージ全体の再ビルドと、利用者の実際の Go のイメージでの動作（レビューでも未検証）。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| 既存の `node` ユーザーに同名のグループが無いベースイメージでは、`chown -R node:node /home/node` が `invalid group` で失敗する（既定のイメージにも影響する） | 2 か所（言語ごとのイメージの node ユーザーの作成の後と、最終ステージの `USER node` の前）とも、`node:$(id -g node)` で実際のプライマリグループを使うようにした。グループを `agents` に改名したイメージを元に、既定のイメージと言語ごとのイメージの両方が作れ、`/home/node` に書けることを確かめた。直す前の版では同じ条件で失敗することも確かめた |

## 残したこと

- 利用者の Go のイメージで `npx sacty image build <名前>` を作り直し、Go のリポジトリのタスクで、エージェントが GOPATH を
  設定し直さずにビルドできることを、利用者の環境で確かめてもらう。
