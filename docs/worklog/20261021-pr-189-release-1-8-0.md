# 版を 1.8.0 に上げる

- 日付: 2026-10-21（UTC）
- タスク: なし
- PR: #189
- ブランチ: ccr-f98aa812-ifqqb0
- 関係する ADR: [版は 1.0.0 から semver で付け、タグと GitHub Releases でリリースする](../adr/20261019-2345-semver-releases.md)、
  [shadcn の tailwind.css を写して置き、shadcn のパッケージに依存しない](../adr/20261021-2229-vendor-shadcn-tailwind-css.md)

## 目的

1.7.1 の後に、機能の追加（PR #183〜#188、#190）が入った。設定ファイルの形・台帳・コマンドの引数に互換性の無い変更は無い（設定は
`budget.per_plan_usd` を足しただけで、前の作業履歴の `TestsRun`・`TestsSkipped` も読める）ので MINOR を上げ、1.8.0 をリリースする。

## 1.7.1 からの変更

- 工程のエージェントが GitHub をゲートウェイ経由で読み、PR・Issue へのコメントを承認の後に sacty が投稿する（PR #183）
- 起動中に Docker を使える状態かを確かめ、どの画面でも警告を出す。設定のイメージのタグが Sacty の版と違えば知らせる（PR #185）
- 工程が終わるごとにオーケストレーターが要らない工程を飛ばす。要求要件・設計を省く組み合わせ `direct` を足す（PR #184）
- テストのコマンドを検証のコマンド（`kustomize build`・`terraform validate` など）に広げ、ツールがイメージに無ければ
  イメージを直す案内で止める（PR #186）
- 費用を概算だけで出し、工程の組み合わせごとの予算（`budget.per_plan_usd`）を設定できるようにする（PR #187）
- テストを別のコンテナで実行せず、ゴールガーディアンが最終レビューの中で実行する。最終レビュー・再現の上限は既定で
  `agent_minutes` + `test_minutes` になる（PR #188）
- 実行する検証が複数あれば、オーケストレーターに `&&` でつないで1つのテストのコマンドにさせる（PR #190）
- 更新の後にすること：既定のイメージの名前が `sacty-agent:1.8.0` に変わり、イメージの `gh` も変わったので、`npx sacty image build`
  でイメージを作り直す（言語ごとのイメージも `npx sacty image build <名前>` で）。

## したこと

- 4 つのパッケージとワークスペースの依存の版を `1.8.0` にし、`package-lock.json` の版の行も同じにした。手元の npm の版では
  `npm install --package-lock-only` が版と関係の無い行（`libc` など）まで書き換えたので、版の行だけを直した。
- 既定のイメージの名前（`DEFAULT_IMAGE`）を `sacty-agent:1.8.0` にし、仕様書（`agent-execution`・`configuration`）・ユーザードキュメント
  （`config`・`images`）の日英と、イメージの名前を書いているテスト（画面の `docker-notice.test.ts` を含む）・コメントを同じ版にした。
  ゲートウェイの MCP クライアントの版の文字列も `1.8.0` にした。

### 依存の脆弱性への対応

- 版を上げた後の push で、GitHub が main の依存の脆弱性（Dependabot の high が 1 件）を知らせた。`npm audit` で調べると、`braces` 3.0.3 の
  スタックの枯渇によるサービス拒否（GHSA-vfj7-8cjw-p6xm）で、`apps/web` の `shadcn` から `fast-glob` → `micromatch` → `braces` と入っていた。
  `braces` に直った版は無い。
- 画面が使っているのは `shadcn/tailwind.css` だけなので、それを `apps/web/src/app/shadcn.css` に写し（先頭に版と MIT の表示）、`shadcn` を
  依存から消した（ADR）。
- `package-lock.json` は、ほかの行と同じ npm 11 で `npm uninstall -w apps/web shadcn` で直した（npm 10 では `libc` の行まで消えたので
  使わなかった）。消えたのは 161 個のパッケージで、残ったパッケージの版は変わらない（前の lockfile と読み比べた）。ほかの差分は、
  開発用だけになったパッケージの `dev` と、`apps/daemon` の `@modelcontextprotocol/sdk` の指定が package.json の `1.32.0` に揃ったこと。

### PR #190 を含める

- 版を上げた後に PR #190 が main にマージされたので、main をこのブランチにマージして 1.8.0 に含めた。PR #190 には版の文字列の変更は
  無い（`1.7.1` の残りが無いことを確かめた）。

## 確かめたこと

- `npm ci`・`npm run lint`・`npm run typecheck`：通過。
- 脆弱性の対応の後：`npm audit` は 0 件。`npm ls braces` は空。`npm run build` が通過し、写しを Biome で整形する前と後で、
  ビルドした画面の CSS が同じであることを確かめた。
- PR #190 をマージした後：`npm run lint`・`npm run typecheck` が通過。`npx vitest run` は 2477 件が通り、下と同じ環境による 8 件が落ちた。
- `npx vitest run`：2476 件が通り、8 件（`agent-sessions.test.ts`・`context-mcp.test.ts`・`host-mcp-processes.test.ts`）が落ちた。
  1.7.1 のときと同じく、この作業の環境（クラウドのコンテナ）によるもの。
