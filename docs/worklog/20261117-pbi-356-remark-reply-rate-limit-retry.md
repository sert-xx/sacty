# GitHub のレート制限に当たった指摘への返信を、期限が明けてからやり直す

- 日付: 2026-11-17（UTC）
- タスク: PBI-356
- PR: なし
- ブランチ: feat/pbi-356-remark-reply-rate-limit-retry
- 関係する ADR: [レート制限に当たった指摘への返信を、期限が明けてからやり直す](../adr/20261117-0110-retry-remark-replies-after-rate-limit.md)

## 目的

取り込んだ PR の指摘への対応の返信（PBI-352）は、GitHub のレート制限に当たると、残りを失敗として記録して、やり直さなかった。
制限に当たった返信を、失敗のまま残さず、GitHub が示す期限を守って、後で投稿する。制限の間は、同じアカウントで返信を続けない。

着手のときに固めた受け入れ条件の要点：

1. 制限に当たった返信は、GitHub が示す待ち（`retry-after`・`x-ratelimit-reset`。両方あれば遅い方）を満たしてから、やり直す。
2. 待ちは、ホストとアカウントごとに持ち、デーモンを起動し直しても失わない。
3. 制限が続くときは、待ちを延ばす。やり直しの回数に上限を設け、超えたら失敗として作業履歴に残す。
4. 待ちの間、タスクは止めない。実行の枠も取らない。
5. 対象は、指摘への返信だけ（2026-11-17 に、リポジトリの持ち主が決めた。ほかの投稿は、今のまま）。
6. 画面の作業履歴で、待っていること・やり直したこと・あきらめたことが読める（ja・en）。
7. 仕様書・ユーザードキュメント（日英）・ADR・作業履歴に反映する。

## したこと

前に、やり直しの作りへの指摘が続いて方針を戻した経緯があるので、新しく足すものを小さくした。やり直しのための待ち行列や、指摘ごとの状態は足していない。

- 制限に当たった指摘と、その提出の残りは、失敗として記録せずに残す（`apps/daemon/src/service.ts` の `postRemarkRepliesNow`）。
  まだ返信していない指摘を求める今の作り（`awaitingRemarkReplies`）に残るので、期限が明けると、今の返信の処理がもう一度返信する。
  目印で投稿済みの返信を見つける作りも、そのまま使う。
- 待ちの保存（`apps/daemon/src/github-rate-limits.ts` の `GitHubRateLimitStore`）：ホストとアカウントごとに、次に試せる時刻と、連続して制限に当たった回数を、`SACTY_HOME/github-rate-limits.json`（権限 0600）に持つ。
  読めない・壊れたファイルは、待ち無しで始める。保存できなければ、警告を残して、メモリーの上の待ちで続ける。
- 待つ時間（`noteRemarkReplyLimited`）：GitHub が示した待ちと、1 分から倍にしていく待ち（上限 1 時間）の、長い方。
  GitHub が示した待ちは、1 日で頭打ちにした（読み違えた・壊れた値で、そのアカウントの返信を止め続けないため）。
  待ちの間にもう一度制限を見ても、回数は増やさない。投稿が1件できたら、待ちと回数を消す。
- GitHub が示す待ちの読み取り（`apps/daemon/src/github.ts` の `retryAfterOf`）を、`retry-after` を先に採る形から、両方あれば遅い方を採る形に直した。
- 待ちの間：`remarkRepliesReady` が返信を待つ提出を返さないので、タスクは実行待ちに出ない。`remarkReplyPost` は、順番を待っていた投稿も、その後に頼まれた投稿も、投稿しない。
  これまでの、メモリーの上の「制限に当たったことを、順番を待っている投稿に伝える」作り（頼まれた順の番号）は、保存した待ちで置き換えて消した。
- PR のレビューの子タスク（`remarkRepliesSettled`・`reviewWaitsForReplies`）：PR を作ったタスクの返信が制限の待ちに入っているときは、返信を待たずにレビューを始める。
- やり直しの上限（5 回）を超えて制限に当たったら、その提出の残りを、失敗（`github.replyGaveUpAfterRateLimit`）として記録する。
- 作業履歴：待つときに `RemarkRepliesDeferred` を残す（状態は変えない）。待ちの後にやり直した結果の `RemarkRepliesPosted` に `retried` を付ける（`packages/core/src/events.ts`・`projection.ts`）。
  画面のラベル（`apps/web/src/i18n/messages/labels.ts`・`apps/web/src/lib/labels.ts`。ja・en）を足した。
- 仕様書（`docs/spec/approval.md`・`architecture.md` と英語の版）、ユーザードキュメント（`docs/user/tasks.md` と英語の版）、ADR を書いた。

自分で決めたこと（人の確認は、まだ）：

- 待ちの間に、承認された・次の提出に変わった・PR が閉じた返信は、投稿しない（返信する条件を、今のまま使う）。作業履歴には、待っていた記録だけが残る。
- やり直しの回数は、タスクごとでなく、アカウントごとに数える。あきらめた後、投稿が1件できるまでは、同じアカウントで制限に当たった提出も、その場で失敗を記録する。
- 既定の値：最初の待ち 1 分・倍にしていく待ちの上限 1 時間・やり直し 5 回・GitHub が示した待ちの上限 1 日。設定の項目にはしていない。
- 投稿されたかが分からない返信の探し直しが制限に当たったときは、その指摘は、やり直さずに失敗を記録する（重ねて投稿しないため。これまでと同じ）。
- 待ちの後に、PR のレビューの子タスクが返信を待たずに始まる。

## 残したこと

- sacty のほかの投稿（PR のコメントの頼み・レビュー・人に確かめてほしいことのコメント）のやり直しは、対象にしていない（人の決定）。
- GitHub の読み取り（指摘の取り込み・PR の状態の確認）の制限の扱いは、範囲外。
- 待ちの間に対象から外れた返信（マージされた・次の提出に変わった）を、後から投稿することはしていない。
