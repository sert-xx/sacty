# 監査の深掘りの出力が JSON として読めなくても、監査を失敗にしない

- 日付: 2026-11-03（UTC）
- タスク: PBI-293
- PR: #298
- ブランチ: feat/issue-293-pbi-293
- 関係する ADR: [監査の出力の JSON が文字列の中で崩れていても、直して読み、読めなければ何が読めなかったかを残す](../adr/20261103-0900-read-broken-audit-json-leniently.md)

## 目的

実験 findings F41（S16 r3）：深掘りの出力のメモリーの本文に、エスケープしていない二重引用符（`"1,200"` など）が入っていて、監査が「出力を読めない」で失敗し、深掘りの費用が無駄になった。よくある崩れで読めなくならないようにし、それでも読めないときは何が読めなかったかを残し、取れた所を捨てない。

## したこと

- `agent-json.ts`：崩れを直しながら読む読み取り（`lastLenientJsonAnswer`）と、読めなかった理由の診断（`explainUnreadableAnswer`）を足した。既存の厳密な読み取り（`lastJsonAnswer`）は変えない。
- `audit-prompts.ts`：大まかな監査・深掘りの 2 つの出力の読み取りを、`lastLenientJsonAnswer` にした。読めなかった理由を、JSON が無い（`audit.unreadable`）・壊れている（`audit.unreadableAt`）・形が合わない（`audit.unreadableShape`）に分けた。指示に二重引用符のエスケープを足した。
- `messages.ts`：2 つの文言（日英）を足した。
- 方式の選び方：構造化出力は CLI 型のエージェントで使えるとは限らず、AI への再依頼は費用が二重にかかるので、寛容な読み取りにした（ADR）。
- 取れた所を捨てない：失敗の記録（`AuditFailed`）は、それまでの大まかな監査の結果・深掘り・原因・費用を消さない（テストで確かめた）。

## 確かめたこと

- S16 r3 の実際の深掘りの出力（`~/.sacty/runs/` の実行のログ。読むだけ）を `extractAuditDive` に通し、読めることを確かめた。
- テスト：S16 r3 を再現する出力（`audit-prompts.test.ts`）、読み取りの境界（空・入れ子・深さの上限・長い出力・答えが 2 つ。`agent-json.test.ts`）、デーモンの統合（崩れた出力で深掘りが記録される・読めない出力で失敗の理由と大まかな監査の結果が残る。`daemon.test.ts`）。`audit-prompts.ts` を元に戻すと、これらが落ちることを確かめた。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| 前の読める答えが、後ろの崩れた最終の答えより優先される | 後ろに読めない答えがあるときは、直して読み直した後ろを使うようにした |

## 残したこと

- ほかの工程（判定・自己レビューなど）の JSON の読み取りは、今回は直さない。
- 引用符の判定を誤って文字列の切れ目が違う形に読まれる可能性は残る（形の検査に通らなければ読めない扱い）。
