# 「タスク分割」の工程で、大きなタスクを子タスクに分けて進める

- 日付: 2026-10-12（UTC）
- タスク: PBI-27
- PR: #33
- ブランチ: feat/issue-27-task-split
- 関係する ADR: [大きなタスクを「タスク分割」の工程で子タスクに分け、子ごとに PR を作って依存の順に進める](../adr/20261012-0226-superseded-task-split-into-subtasks.md)

## 目的

オーケストレーターが「要求要件 → 設計 → タスク分割」を選べるようにし、設計の承認の後に大きなタスクを子タスクに分けて進める。
受け入れ条件の要点：分割は設計の承認の後だけ、不正な分割案は理由を記録して止める、分割案は承認なしに子タスクにする、
子の工程はオーケストレーターが選ぶ（分割は選べない）、依存のある子は依存先の完了を待つ、子がすべて完了したら親も完了・
子の中止で親は判断待ち・親の中止で子も中止、画面に子の一覧・進み具合・費用の合計と親へのリンク、日本語・英語。

## したこと

- 工程 `split` と工程の組み合わせ `split` を足した。タスク分割のエージェントへの指示（`apps/daemon/src/prompts.ts`）は、承認済みの
  要求要件・設計とコード（読み取り専用）から子タスクの一覧（内容・受け入れ条件・依存）を書かせる。子が2〜10件でない・key の重複・
  存在しない依存・循環は、理由を記録して止める。
- 作業履歴と状態（`packages/core/src/events.ts`・`packages/core/src/projection.ts`）：`TaskSplit`（子タスクの ID もここで決める）・
  `TaskUnblocked`・`SplitCompleted`・`TaskCreated.parent`・一時停止の理由 `child_cancelled`、状態 `blocked`・`waiting_children`。
- 親の進め方（`apps/daemon/src/service.ts`）：子タスクを作る（デーモンが途中で止まっても、再起動の後に同じ ID で作る）→ 依存先が片付いた子を
  実行待ちに → すべて片付いたら親を完了。子の内容に、親の承認済みの要求要件と設計を添える。
- 子が中止されたら親は人間の判断を待つ（再開で中止を認め、依存する子も始める）。親を中止すると終わっていない子も中止する。
  待っている間は一時停止できない。
- 画面（`apps/web/src/app/tasks/[id]/page.tsx`・`apps/web/src/app/page.tsx`・`apps/web/src/lib/subtasks.ts` など）：親に子タスクの一覧
  （状態・依存・PR）・進み具合・費用の合計、子に親へのリンク、一覧では子を親の下に字下げ。日本語・英語の文言。
- レビューの指摘で、親が中止された子をワーカーが中止の対象として拾い、実行せずに中止するようにした（`queuedTaskIds` と `runNext`）。

## 確かめたこと

- `npx vitest run`：317 件すべて成功。lint・typecheck も通った（指摘の修正の後、レビューで全 318 件・lint・typecheck の成功を確かめた）。
- 依存待ちにしない・依存を見ずに始める・親の中止を子に広げない・子にも分割を許す・循環を確かめない・子を作らない、の各変更に戻すと
  テストが失敗することを確かめた。
- ビルドしたアプリ（スタブの AI）で、分割 → 子タスクの作成 → 依存待ち → 依存先の完了で開始、を画面で確かめた（動画あり）。
- レビューでは、画面の操作・実際の AI での実行・ビルドは確かめていない。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| 親の `TaskCancelled` を記録してから各子を中止しているので、その間にデーモンが止まると、再起動の後に中止されていない子が実行される。親をもう一度中止しても伝播をやり直せない | 親が中止された子は、ワーカーが実行ではなく中止の対象として拾い、実行せずに中止するようにした。中止は実行の印（inflight）を付ける前に行う（自分自身を待たないように）。親の `TaskCancelled` までの作業履歴から再起動し、エージェントを呼ばずに子が中止される回帰テストを足し、修正を戻すと失敗することを確かめた |

## 残したこと

- 子タスクの並行の実行は、別の PBI に回した。
