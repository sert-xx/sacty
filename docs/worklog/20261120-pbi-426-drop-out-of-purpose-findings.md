# PR のレビューの集約は、PR の目的の範囲の外の指摘を投稿しない

- 日付: 2026-11-20（UTC）
- タスク: PBI-426
- PR: なし
- ブランチ: なし
- 関係する ADR: [20261121-0100-drop-out-of-purpose-findings-in-pr-review.md](../adr/20261121-0100-drop-out-of-purpose-findings-in-pr-review.md)

## 目的

目的の外の求めが `[提案]` として投稿され、直しと再レビューの往復が増えていた。

## したこと

- 既定のスキルの `aggregation.md` に「PR の目的の範囲の外」の節と不採用の理由を足し、`pr-review.md` の総評に件数の1行と取り下げの書き方を足した。
- 仕様書（日英）・ユーザードキュメント（日英）・ADR を直した。自己レビューには当てない（理由は仕様書）。
- 重みを見直した前回の指摘は、元が `must` なので、この規則で落とさず今の規則で残す、と決めた。

## 確かめたこと

- `npm run lint`・`npm run typecheck`・`npm test -- --no-file-parallelism` を実行した（lint・テスト全件・typecheck とも通った。件数は PR の本文に記す）。
- `default-skills.test.ts` で、4つの決まりが配られることを確かめた。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| 決め直した `should` の読みが割れる・重みを見直した前回の指摘との重なり | 「担当が `must` と出したことを理由に、この理由では落とさない」と言い直し、重みを見直した前回の指摘の節にも目的の範囲の外を足した |
| テストが「迷うとき」「`must` の主文」を確かめない | 該当の文言を `expect` に足した |
| 取り下げの書き方が 3 か所にある・件数の扱いが未決 | 総評の項に寄せ、取り下げた前回の指摘も数えると書いた |
| 作業履歴に結果と節が無い | この節と、確かめたことの結果を足した |
| ユーザードキュメントの「`[要修正]` は落とされない」が理由を限らない | 「目的の範囲を理由には」と限った |

## 残したこと

- 再レビューの指示（`prompts.ts` の `rereviewLines`）は「直っているか・未対応か」の二択のままで、スキルの「取り下げ」と食い違う。デーモンのコードは範囲外のため、後続に回す。
- デーモンの指示（`prompts.ts`）には要点を重ねていない（デーモンのコードの変更は範囲外）。スキルを差し替えたプロジェクトでは、この決まりは効かない。
