# 秘密情報の取得元に 1Password を足す

- 日付: 2026-10-12（UTC）
- タスク: PBI-34
- PR: #41
- ブランチ: feat/issue-34-onepassword
- 関係する ADR: [秘密情報の取得元に 1Password（op:// の参照）を足し、op CLI で取り出した値をデーモンのメモリーだけに持つ](../adr/20261012-1131-onepassword-secret-source.md)

## 目的

利用者の環境では認証情報を 1Password に保存しているので、秘密情報を書くすべての所で、キーチェーンの名前に加えて 1Password の参照を
書けるようにする。受け入れ条件の要点：エージェントの認証・MCP・ゲートウェイのどこでも op:// の参照を書ける、op CLI で取り出し
値を作業履歴・出力・エラー文・画面に出さない、op が無い・サインインしていない・参照先が無いときはどの参照かと理由を記録して止める、
同じ参照は起動中に何度も問い合わせない（メモリーにだけ持ち、ディスクには書かない）。

## したこと

- `apps/daemon/src/secrets.ts`：`SecretRef`（キーチェーンの名前か op:// の参照）、`OnePasswordSecretStore`（`op read --no-newline [--account …]`。
  成功した値だけをメモリーに持ち、同時の問い合わせは1回にまとめる）、`ResolvingSecretStore`（参照の形で取得元を選ぶ）。
- 取り出せないときの理由（op が無い・サインインしていない・取り出せない）を足した（`packages/core/src/messages.ts`）。どれも認証の失敗としてタスクを止める。
- config.yaml の秘密情報（`apps/daemon/src/config.ts`）とコンテキストの MCP の秘密情報（`apps/daemon/src/context.ts`）で op:// を受け付ける。
  `onepassword.account` を足した。
- デーモン（`apps/daemon/src/main.ts`）と `sacty image build`（`packages/cli/src/index.ts`）が上の取り出し口を使う。雛形と `README.md` に例を足した。
- あわせて、オーケストレーターを実行できなかった理由で、理由の文の句点と重なって「。。」になっていたのを直した。
- レビューの指摘で、参照の空白とクエリを受け付け、取り出した値をアカウントと参照の組で持つようにした。

## 確かめたこと

- `npm test`（379 件）・`npm run lint`・`npm run typecheck` が通った。
- 偽物の op を PATH に置いて、実際のコマンドの呼び出し（引数・標準出力・標準エラー・op が無いとき）を確かめた。
- 同じ参照を問い合わせ直さない・失敗した参照は持たない・アカウントを渡す・サインインしていないことの判定・参照の形で取得元を選ぶ・
  op:// を設定で受け付ける・op が無いときの理由、の修正を1つずつ戻すとテストが失敗することを確かめた。
- 開発に使った環境には 1Password のアカウントが無いため、実際の 1Password では確かめていない。op CLI の偽物（同じ引数・出力・終了コード）で確かめた。
- レビューでは、全 379 件のうち 378 件が成功し、既存の Git の操作のテスト1件が5秒で時間切れになった（`repository.test.ts` を単独で実行し直すと
  12 件すべて成功）。lint・typecheck も成功。実際の 1Password のアカウントでの取り出しは確かめていない。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| 参照の各要素で空白を禁止しているが、1Password の仕様は空白を認めている。公式の例（`op://development/aws/Access Keys/access_key_id`）が拒否され、アプリからコピーした参照をそのまま使えない | 仕様に合わせ、英数字・ハイフン・アンダースコア・ピリオド・空白（空白だけの要素は不可）と、`?attribute=otp`・`?ssh-format=openssh` などのクエリを受け付けるようにした。公式の例を受け付けることと、仕様に無い文字（`@` など）を受け付けないことをテストにし、「空白を含む名前を拒否する」期待は受け付けるように直した。元の形に戻すと失敗することを確かめた |
| 取り出した値を参照だけで持ち、持っていればアカウントを見ないので、起動中に `onepassword.account` を変えても前のアカウントの値を返し続ける | アカウントは取り出すときに設定から決め、アカウントと参照の組で持つようにした。A で取り出した後に B に変えると B に問い合わせ、A に戻すと問い合わせずに A の値を返すテストを足し、元の形に戻すと失敗することを確かめた |

## 残したこと

- 実際の 1Password での確認（op CLI をインストールしてサインインし、`op read` で値が出ることを確かめ、config.yaml の `secret` を参照に書き換えて
  タスクを動かす。サインアウトした状態では止まり、サインインして再開すると進むことも確かめる）は、利用者の環境で行う。
