# PR のレビューの子タスクがレビューする工程で、提出の前のセルフレビューを省く

- 日付: 2026-11-15（UTC）
- タスク: PBI-346
- ブランチ: feat/issue-346-skip-self-review-when-pr-reviewed
- 関係する ADR: [PR のレビューの子タスクがレビューする工程では、提出の前のセルフレビューを省く](../adr/20261115-0810-skip-self-review-when-pull-request-is-reviewed.md)

## 目的

要求要件・設計・実装の工程は、提出の前にセルフレビューをしていた。
sacty が PR を作るタスクでは、その PR をレビューの子タスクがレビューするので、同じ成果物を2回レビューしていた。
人から、PR に紐づく工程では機械的な検証（テスト・リンター・フォーマッター）だけにしてセルフレビューを省くこと、PR に紐づかない場合は省かないことを指示された。

受け入れ条件の要点は次のとおり。

- 提出が sacty の作る PR になる要求要件・設計・実装の工程の指示に、セルフレビューが無く、行わないことと理由がある。
- その工程の指示に、提出の前の検証が残っている。
- 対象のリポジトリが無いタスク・文書作成の工程・既存の PR を引き継ぐタスク・要求要件や設計を画面で承認するタスク・レビューの子タスクを作らないデーモンは、今までどおりセルフレビューをする。
- 省いた実行は、セルフレビューの記録を残さず、画面に「記録なし」の警告を出さない。
- 指摘を受けた直しの実行でも、同じ条件で省く。

## したこと

- `apps/daemon/src/service.ts`：`reviewedByPullRequest` を足した。
  工程の実行の前に1回だけ判定し、指示（`buildPrompt` の `pullRequestReview`）と記録に同じ結果を使う。
  省いた実行は、`AgentRunCompleted` に `selfReview` を入れない。
- `apps/daemon/src/prompts.ts`：`pullRequestReview` を受け取ったら、要求要件・設計・実装（標準・要求要件を省いた実装・不具合の修正・文書だけ）の指示で、セルフレビューの指示の代わりに `skippedSelfReviewLines`（行わないことと理由、検証は省かないこと、報告を付けないこと）を出す。
  検証・テストの範囲・本文の読み直し・出典の分類の指示が、行わないセルフレビューに触れないようにした。
  文書作成の工程は、受け取っても省かない。
- `apps/daemon/src/verification-reuse.ts`：検証の記録の指示が、省く工程ではセルフレビューの検証に触れないようにした。
- 仕様書（タスクと工程・承認。日本語と英語）、ユーザードキュメント（タスク。日本語と英語）、ADR を直した。
- `scripts/docs-screenshots/seed.mjs`・`seed-intro.mjs`：スクリーンショットのデータの実行から、セルフレビューの記録を外した（どのタスクも PR で承認する流れなので、今の実装では記録が無い）。
  「セルフレビュー：パス・2回」が写っていた `docs/user/images/task-detail.png`・`task-chat.png` と、その英語の版を撮り直した。
  ほかの画像は、セルフレビューの表示が写っていないので撮り直していない。

実装の「提出の前に確かめる、レビューの基準」と、答えの反映だけの直しの確認、出典の分類は変えていない。
判断の理由は ADR に書いた。
