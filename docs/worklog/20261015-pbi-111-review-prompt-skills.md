# PR のレビューのタスクのプロンプトと既定のスキル（git・review）をそろえ、判定を3つにする

- 日付: 2026-10-15（UTC）
- タスク: PBI-111
- PR: #121
- ブランチ: feat/issue-111-review-prompt-skills
- 関係する ADR: [PR のレビューのタスクは既定のスキルでレビューし、出力の形と投稿は sacty が決める。判定を3つにする](../adr/20261015-1617-review-prompt-follows-default-skills.md)

## 目的

PR のレビューだけのタスクのプロンプトは「sacty が投稿する」前提で、既定のスキルは「エージェントが自分で投稿する」前提だった。
二重の投稿、JSON を出さない、位置の無い指摘で止まる、提案だけのレビューが差し戻しとして届く、というおそれがあった。
投稿は sacty に残し、プロンプトとスキルをそれに合わせ、スキルの決まりを sacty の投稿に取り入れる。

## したこと

- プロンプト（`apps/daemon/src/prompts.ts` の `buildPrompt` の `review`）に、既定のスキルを使う・自分では投稿しない・食い違えばプロンプトの出力の形を優先する、を書いた。
  指摘の頭（`[要修正]`・`[提案]`）、行へのコメントの `severity`、位置の無い指摘は本文に書く、3つの判定も書いた。
- 判定を `reviewVerdict`（`changes_required`・`suggestions`・`no_findings`）にした（`packages/core/src/events.ts`）。
  `[要修正]` の行へのコメントで引き上げ、行へのコメントがあるだけでは修正が必要にしない（`extractReviewComments`）。
  差し戻しに届けるのは修正が必要な回と読めない回だけ（`sactyReviewsOf`）。
- 投稿する本文の先頭に、作者の @login と判定を書く（`buildReviewBody`）。作者は `ReviewTargetResolved` に記録する。
- 再レビューで、前回のレビュー（`previousReview`）と、その後の作者の返答（`reviewReplies`）をプロンプトに渡す。
- 投稿の直前に PR の先頭を確かめ、途中で push されていれば、レビューしたコミットに投稿してその旨を書く（`postReview`）。
- 既定のスキル（`git`・`review-dispatch`）に、依頼した側が出力の形と投稿のしかたを決めていればそれに従う決まりを書き、sacty に限った書き方を除いた。
- 仕様書（tasks-and-steps・approval・intake・context）、利用者向けの intake を、英語の版も直した。

## 確かめたこと

- `npm run lint`（終了コード 0）・`npm run typecheck`・`npx vitest run`（1634 件）・`npm run build`・`npx vitest run tests/docs`（89 件）が通った。
  1回だけ PBI-107 の時間の上限のテストが負荷で落ちたが、再実行（単独・daemon のテスト2回）では通った。
- 修正を戻すとテストが落ちることを、7か所で確かめた（投稿しない指示・判定・@login・再レビュー・先頭の確認・差し戻し・スキルの文言）。
  レビューの対応でも、先頭が無い応答の確認・投稿済みのときの記録し直し・ログ・ログの秘密の値の伏せの4か所で確かめた。
- 前の形の記録（`reviewChangesRequested` のある `AgentRunCompleted`）が、エラーにならずに読める（判定は無いものになる）ことを確かめた。
- 画面のコードは変えていないので、動画は撮っていない。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| （DA のセルフレビュー）頭だけで中身の無い行へのコメントが、空のまま投稿される | 中身が無ければ捨てるようにし、テストを足した |
| （DA のセルフレビュー）GitHub Enterprise の `_` を含む login にメンションできない | login の形に `_` を含めた |
| （DA のセルフレビュー）作者が分からないと、返答が空の一覧として渡り、返答が無いように見える | 読めなかったものとして扱い、テストを足した |
| （DA のセルフレビュー）完了できないレビューで、スキルは判定を書かず、プロンプトは判定を必ず求めていた | 完了できないときは判定を付けさせない、とプロンプトに書いた |
| （PR #121 要修正）`status()` が成功しても、先頭のコミットが無い・空の応答では、確かめずに投稿する | 先頭が英数字 7〜64 文字でなければ `review.headUnknown` で一時停止し、再開で確かめ直すようにした。無い・空・空白だけの3つでテストした |
| （PR #121 提案）投稿の後・記録の前に止まると、やり直しで `latestCommit` が失われる | 先頭を本文に表示されない目印で残し、既にある投稿を使うときは、その本文から記録し直すようにした。やり直しの前にさらに push されても、投稿したときの先頭を記録することをテストした |
| （PR #121 提案）作者の返答を読めない理由が、運用する人に残らない | レビューは続けたまま、タスクと PR と理由（秘密の値を伏せたもの）をデーモンのログに出すようにした |
| （PR #121 提案）利用者向けの文書で、@ メンションがいつも付くように読める | Bot の作者には付かないことを、日英の両方に書いた |

## 残したこと

- 英語など、ほかの言語での sacty の固定の文と頭は、要る人がいれば後で足す。
- 画面での判定の表示は足していない。
