# sacty の PR に人が足したコミットと、人が直した PR の本文を、更新しても残す

- 日付: 2026-11-12（UTC）
- タスク: PBI-334
- PR: #354
- ブランチ: claude/kind-hawking-3yd1ju
- 関係する ADR: [人が sacty の PR に足したコミットを作業領域に取り込み、人が直した PR の本文を3方向でマージして残す](../adr/20261112-1553-keep-human-edits-on-sacty-pull-requests.md)

## 目的

sacty が作った PR をレビューの指摘で直して更新するとき、人が PR に手を入れていても壊さないようにする。

- 人が PR のブランチにコミットを足していても、プッシュに失敗せず、人の変更も消さない。
- 人が PR の本文を補足・整形していても、上書きで消さず、sacty の新しい内容も入れる。

## したこと

- 人が足したコミットの取り込み
  - `apps/daemon/src/repository.ts`：`mergeBase` に `exclude`（両側のツリーから外すパス）を足した。タスクブランチから引き継ぐ
    要求要件・設計のファイルを、取り込みから外すため。
  - `packages/core/src/events.ts`・`projection.ts`：`PullRequestHeadMerged` と `Task.headMerge`・`pendingHeadMerge` を足した。
    PR を出す直前（`publishPending`）に競合したら、PR を出さずに実装をやり直す。
  - `apps/daemon/src/service.ts`：`syncPullRequestHead` を足し、`syncBase`（実装の前・最終レビューの前）・
    `headSyncedBeforePublish`（最終レビューをしない流れの PR を出す前）・`publish`（PR を出す直前）から呼ぶ。`publish` は、
    まだ提出していない取り込みがあれば、その先頭を親にする。タスクブランチの変更の確認の起点も、その先頭にする。
    取り込みは、テスト用の設定 `mergeBase` とは関係なく行う（`mergesBase` から設定を外し、`syncBase` の中でベースブランチの部分だけを止める）。
  - `apps/daemon/src/prompts.ts`：実装の指示に「人が PR に足したコミット」の節（`headMergeLines`）、最終レビューの指示に
    `headMergeReviewLines` を足し、ベースブランチとの競合（`baseConflictLines`）と分けた。
- 人が直した本文
  - `apps/daemon/src/pr-body-merge.ts`（新規）：`git merge-file --diff3` で本文を3方向にマージする `mergePullRequestBody`、
    重なったときにエージェントへ渡す指示 `buildPullRequestBodyMergePrompt`、答えの取り出し `extractMergedPullRequestBody`。
  - `apps/daemon/src/github.ts`：PR の今の本文を読む `pullRequestBody` を足した。
  - `packages/core/src/events.ts`・`projection.ts`・`cost.ts`：`PullRequestBodyWritten`（sacty が組み立てた本文）・
    `PullRequestBodyResolved`（エージェントがまとめた・まとめられなかった。費用を予算に入れる）と `Task.pullRequestBodies`。
  - `apps/daemon/src/service.ts`：`reconcilePullRequestBody`・`recordPullRequestBody` を足し、実装の PR・要求要件・設計の PR の
    更新・重ねた PR の付け替えの3か所で使う。
  - `apps/daemon/src/server.ts`：タスクの一覧の API では `pullRequestBodies` を送らない。
  - `apps/web`：作業履歴の文言（日英）と、工程ごとの費用の表（オーケストレーターの行）。
- docs：仕様書（`tasks-and-steps`・`approval` の日英）、ユーザードキュメント（`tasks` の日英）、ADR。

決めたこと：本文の3方向のマージの共通の祖先は、GitHub に書いた本文ではなく sacty が組み立てた本文にした。GitHub に書いた
本文を祖先にすると、人が前に足した補足が次の更新で消えるため（ADR に書いた）。

## 確かめたこと

- `npx biome check .`：指摘なし。
- `npm run typecheck`：エラーなし。
- `npx vitest run apps packages`：4500 件中 18 件が失敗。変更の前（`git stash` した状態）も 18 件が失敗していて、増えたのは下の
  1 件だけ。どれもこの環境の原因：
  - この環境の git が 2.43 で、`git merge-tree --write-tree` の引数にツリーを渡せない（`unexpected output`）。ベースブランチの
    取り込みの既存の結合テストも同じ理由で失敗する。新しく足した `repository.test.ts` の取り込みの結合テスト1件も同じ理由で、
    ここでは確かめられない（CI で確かめる）。
  - Playwright のブラウザが無い。
- 足したテスト：
  - `apps/daemon/src/daemon.test.ts`：人のコミットを取り込んでその先頭に積む・競合を人の側として渡す・コミットが無ければ
    取り込まない・最終レビューをしない流れで実装の実行中に足されたコミットを PR を出す前に取り込む・その取り込みで競合したら
    数えずにやり直す・本文の重ならない直しを残す（CRLF も）・重なったらエージェントにまとめさせる・まとめられなければ人の本文の
    まま・今の本文を読めなければ上書き。
  - `apps/daemon/src/pr-body-merge.test.ts`：3方向のマージ・目印・答えの取り出し。
  - `packages/core/src/projection.test.ts`：`PullRequestHeadMerged`・`pendingHeadMerge`・`PullRequestBodyWritten`。
  - `apps/web/src/lib/step-costs-totals.test.ts`：無作為の作業履歴に `PullRequestBodyResolved` を足した。
- 既存のテストの直し：イベントの並びを比べるテストに `PullRequestBodyWritten` を足した。タスクブランチに人が積んだ後の
  やり直しのテストは、確かめて止める代わりに、取り込んで積むことを確かめるようにした。
- `npx vitest run tests/docs`：通った。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| ADR の置き換え元が「なし」だが、旧 ADR（タスクブランチの変更を止めて、自動で取り込まない）の一部を変える | 旧 ADR を `superseded` にして置き換え先を書き、新しい ADR の置き換え元と、置き換える範囲（sacty が実装を積んだ後に人が足した変更）を書いた |
| 前回の人のコミットとの競合の目印が残ったまま、実装中に新しいコミットが足されると、競合なしの取り込みで目印の記録が消え、目印のままプッシュできる | `syncPullRequestHead` で、まだ提出していない取り込みの目印が残っていれば、取り込まずに返す。PR を出す前は、数える（`fresh` でない）`BaseConflictsRemained` にした。テストを足し、直す前に失敗することを確かめた |
| 最終レビューをする流れで、最終レビューの後に足されたコミットを PR を出す直前に取り込むと、検証していない内容を出す | PR の作成の待ちで取り込んだら `reverify` を付け、PR を出さずに検証の待ちに戻す。テストを足し、直す前に失敗することを確かめた |
| 付け替えで本文をまとめるエージェントは、タスクの実行として止められない | 付け替えでは、エージェントを実行しない（本文に触れず、次のやり直しの提出でまとめる。`pr.bodyMergeDeferred`） |
| ドラフトの PR をプッシュすると `pendingHeadMerge` が消え、最終レビューに人の変更の扱いが伝わらない | 最終レビューの指示は、`Task.headMerge` があれば出す（差分は起点からなので、ずっと人の変更を含む） |
| まとめる間に人が本文をまた直すと上書きする。まとめられないときも、読んだ時点の古い本文を書き戻す | まとめた後に読み直し、変わっていれば更新しない。まとめられないときは `upsert` に本文を渡さない（本文に触れない）。テストを足した |
| 本文のテストの実行回数の確かめ方が、余分なエージェントの実行を見逃す | 差し戻しの前の回数から、実装と最終レビューの2回だけ増えたこと、まとめる指示が使われていないことを確かめるようにした |
| 利用者向けの文書に、本文が上書きされる例外（この版より前の PR・今の本文を読めないとき）が無い | 日英のユーザードキュメントに書き足した |
| （2回目）最終レビューをする流れで、本文をまとめる間に人がコミットを足すと、検証していない内容でドラフトを外す | 本文を用意した後、PR を更新する前にもう一度取り込み、取り込んだら検証からやり直す。テストを足し、直す前に失敗することを確かめた |
| （2回目）本文をまとめたコンテナが止まったか確かめられなくても、PR の更新を続ける | 確かめられなければ、PR を更新せずに一時停止する（工程の見直しと同じ扱い）。テストを足し、直す前に失敗することを確かめた |
| （2回目）最終レビューの前のドラフトの PR の更新の直前に新しく競合すると、一時停止して、実装のやり直しに戻れない | `BaseConflictsRemained`（数えない）を記録して、実装をやり直す。テストを足し、直す前に失敗することを確かめた |
| （2回目）要求要件・設計の PR の本文をまとめる間に一時停止を求めても、PR を更新して承認待ちになる | まとめた後、PR を更新する前に一時停止・中止の求めを確かめ、あれば更新しない（テストは足していない。実装の PR と同じ確かめ方） |
| （2回目）PR の作成の応答を失い、再試行で既存の PR を見つけたときも、書いていない本文を前回の版として記録する | `upsert` の答えに `existing` を足し、そのときは記録しない。`github.test.ts` にテストを足した |
| （3回目）不具合の修正の流れの実装の指示に、人が足したコミットのことと競合したファイルが渡らない | 不具合の修正の指示にも `mergeConflictLines` を足した（ベースブランチとの競合も、この流れでは渡っていなかった）。テストを足した |
| （3回目）費用を予算に入れるイベントの仕様書の一覧に `PullRequestBodyResolved` が無い | 日英の仕様書（`event-log`）の件数・表・`costUnknown` の一覧を直した |
| （3回目）共通の祖先が、まだ提出していない取り込みの先頭になる条件が仕様書に無い | 日英の仕様書に書き足した |
| （3回目）本文のマージそのものの失敗を、作業履歴に残さない | `PullRequestBodyResolved`（`kept`。`pr.bodyMergeError`）に残すようにした |
| （3回目）前回の指摘のうち5件が未対応とされた | 3回目のレビューは、修正の前のコミット（2b2f2b7）に対するもので、5件は 0cab791 で直してあった |
| （4回目）取り込んだ先頭に積んでプッシュした後のやり直し（最終レビューの不合格など）で、人の変更を守る指示が出ない | 実装の指示も `Task.headMerge` があれば出す（競合したファイルは、まだ提出していない取り込みのものだけ）。テストを足し、直す前に失敗することを確かめた |
| （4回目）PR を更新する前の先頭の読み取りを待つ間の一時停止・中止を確かめない | 読み取りの後、`upsert` の前にも確かめる |
| （4回目）止まったか確かめられなかった本文の実行を、一時停止の記録（`unstoppedRuns`）に残さない | `TaskPaused` の `unstoppedRuns` に残すようにした（再開・中止の前に確かめ直す）。テストで確かめた |
| （4回目）利用者向け文書は git 2.40 以上を案内しているが、git 2.43 で取り込みに失敗する | `merge-tree` にツリーを渡していたため。作業領域の内容（と、外すパスを除いたツリー）を一時的なコミットにして渡すようにした。この環境の git 2.43 で、`repository.test.ts` の取り込みの結合テストがすべて通るようになった（テストの補助の `merge-tree --quiet` も、2.43 に無いので `--name-only` にした） |
| （4回目）`event-log` の投影の節の件数が16種類のまま | 日英とも17種類に直した |
| （5回目）PR を更新する直前の確認で PR のブランチを読めないと、確かめないまま未検証の変更を含む PR を出しうる | その確認だけは、読めなければ PR を更新せずに一時停止する（`strict`）。テストを足し、直す前に失敗することを確かめた |
| （5回目）PR を出す前の先頭の読み取りを待つ間に一時停止・中止を求められても、プッシュする | 読み取りの後、プッシュの前にも一時停止・中止の求めを確かめる |
| （5回目）先頭の読み取りの間の一時停止の回帰テストが無い | 足した。確かめる処理を外すと失敗することを確かめた |
| （5回目）仕様書の「コミットを作らない」が、一時的なコミットの説明と食い違う | 日英とも「ブランチにコミットを積まない（一時的なコミットは作るが、どのブランチにも付けない）」に直した |
| （6回目）先頭の読み取りの後、認証・タスクブランチの取得を待つ間の一時停止・中止を、プッシュの直前に確かめていない | `repos.publish` の直前にも確かめる（テストは足していない。この間だけに一時停止を差し込む偽物が無いため） |
| （6回目の後）PR が `main` と競合し、CI が起動しなくなった | `main` を取り込んだ。`main` で以前の版の最終レビューの仕組みが消えた（PBI-336）ので、それに合わせて、最終レビューからやり直す処理（`reverify`・PR を更新する直前の再確認・`strict`）、最終レビューへの指示（`headMergeReviewLines`）、最終レビューの前のドラフトの PR での競合の処理と、それらのテストを外した。今の流れでは、人が足したコミットは PR のレビューの子タスクが新しい先頭で見直す。一時停止の回帰テストは、PR を出す直前の取り込みの読み取りの間に一時停止を求める形にし、確かめる処理を外すと失敗することを確かめた |
| （7回目）プッシュの直前の確認の後に、コミットの題の用意（`commitSubjectFor`。ファイルを読む）を待つ | 題を先に用意してから確かめ、その後はプッシュまで await しないようにした |
| （8回目）人の先頭に積んでプッシュした後、PR の更新の前に止まって再開すると、親が前の PR のコミットに戻り、早送りでプッシュできない | 同じブランチにプッシュ済みのコミットがあれば、それを親にする（内容が同じなら、そのコミットを使い直す）。テストを足し、直す前に失敗することを確かめた |
| （8回目）仕様書の「今の版は `fresh` を記録しない」が、人のコミットの取り込みと食い違う | ベースブランチの取り込みについての説明だと限定した（日英） |
| （9回目・提案）実装の PR の作成でエージェントを使わない・費用がかからないという説明に、本文が重なったときの例外が無い | 日英の仕様書に書き足した |
| （9回目・提案）依存先のマージの後の付け替えで、本文が重なると本文を据え置くことが利用者向けの文書に無い | 日英のユーザードキュメントに書き足した |
| （9回目・提案）本文を読み直せなかったときも「人がまた直した」と出る | 読み直せなかったときの理由（`pr.bodyRereadFailed`）を分けた（日英） |
| （9回目・提案）上書きする条件の説明が「この版より前の PR」だけで、作成直後に止まって既存の PR を見つけたときが無い | 「前回 sacty が書いた本文の記録が無いとき」として、両方を挙げた（日英） |
| （9回目・提案）仕様書の取り込みの手順の順が、実装（目印の検査が先頭の取得より先）と違う | 日英とも、実装の順に並べ替えた |
| CI（git 2.56）で、`mergeBase` の `exclude` を使う取り込みの結合テストが `read-tree` の「README.md not uptodate」で失敗した。外すパスを除いたツリーを作るために、作業領域の状態を持つ一時インデックスを読み替えていたため | ツリーの加工を別の一時インデックスで行うようにした。この環境の git（2.43）で、`merge-tree` を除いた手順（別インデックスでの加工の後の `read-tree -m -u`）が通ることを確かめた |

## 残したこと

- 要求要件・設計の PR のブランチに人が成果のファイルを直接直したコミットは、sacty が成果のファイルを書き直すので、その直しは
  残らない（これまでどおり。指摘として書くと、工程のエージェントが反映する）。
- この環境の git（2.43）で、ベースブランチの取り込みの結合テストが通らなかった件は、4回目のレビューの対応で `merge-tree` に一時的なコミットを渡すようにして解消した（上の表）。
