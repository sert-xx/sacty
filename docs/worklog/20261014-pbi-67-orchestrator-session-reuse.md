# オーケストレーターのセッションをタスクごとに使い回し、チャットは複製で答える

- 日付: 2026-10-14（UTC）
- タスク: PBI-67
- PR: #79
- ブランチ: feat/issue-67-orchestrator-session-reuse
- 関係する ADR: [オーケストレーターのセッションをタスクごとに保存して再開し、チャットは保存したセッションの複製で答える](../adr/20261014-0216-orchestrator-session-reuse.md)

## 目的

オーケストレーターの2回目以降の実行は、同じタスクの前のセッションを再開する（Claude Code・Codex）。再開か新規かとセッション ID を作業履歴に残す。
エージェントを変えた・壊れた・再開できないときは新しく始めて理由を残し、タスクは止めない。チャットは複製で答えて元のセッションに混ぜない。
ゴールガーディアン・工程のエージェントは毎回新しく、ほかのタスクと混ざらず、同じタスクのオーケストレーターは同時に走らない。

## したこと

- `apps/daemon/src/orchestrator-sessions.ts`（新規）：タスクごとのセッションの保存・読み込み・確かめ（ハッシュ・リンク・パスの外・ID の形）。
- `apps/daemon/src/agents/invocation.ts`・`docker.ts`：再開・複製の引数（`--resume`・`--fork-session`・`codex exec … resume <ID> <指示>`）と、
  保存したファイルの設定の場所への戻し（保存した元は書き換えない）。
- `apps/daemon/src/service.ts`：オーケストレーターの実行で再開か新規かを決め、始め直しの判定・同じタスクの直列化・チャットの複製・中止の片付け。
- 台帳と画面：`packages/core/src/events.ts`・`projection.ts` に `OrchestratorSessionUsed`。`apps/web/src/components/orchestrator-session.tsx`（新規）で
  タスク詳細に「オーケストレーターのセッション」カード、作業履歴の表示。
- レビューの対応：始め直すのを、戻せなかったときと再開を拒んだ文が出たときに限った。本物の Claude Code・Codex が無いセッションの再開を断ったときの出力で、
  判定を確かめるテストを足した。

  Claude Code は haiku・effort low、タスクの予算を小さくし、工程のエージェントは走らせなかった。換算の費用は Claude Code のタスクが $0.034、Codex のタスクが $0.058）。
  - Claude Code：1回目は新規で保存、2回目は再開（init の `session_id` が同じ、セッションのファイルにユーザーの発言が2回分、キャッシュの読みが 10,977 → 18,508）、

    前後で同じ、保存したファイルを書き換えた4回目は新規（壊れていたため）でタスクは止まらなかった。

- 確かめなかったこと（レビュー）：実際の Claude Code・Codex でのセッションの再開、実際の Docker、ブラウザの操作。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| [P1] 使用量が分からない実行のエラー（タイムアウト・`run.containerNotConfirmed`・最終 result の前の異常終了）も再開の拒否とみなし、新しいセッションで始め直すので、前のコンテナが残ったまま次を始めたり、失敗を隠して工程を進めたりする | 一般のエラーは始め直さずにそのまま返すようにした。始め直すのは、何も使わずに失敗し、かつ保存したセッションを戻せなかったか、AI ごとに本体にある拒否の文（Claude Code 3種・Codex 5種）が出たときだけ。再開を指定したのに別のセッションの ID が出たときは新規（`resume_failed`）として記録する。回帰テスト（一般のエラー・ほかの AI の文では始め直さない、本物の拒否の文と戻せなかったときは始め直す、使ってから失敗したときは始め直さない）を足した |

再レビューで、指摘の解消が確かめられた（追加の指摘は無し）。

## 残したこと

- Codex の2回目のオーケストレーターの実行（工程の選択のやり直し）での再開は、本物の Codex では起こせず、チャットの経路で確かめた。
