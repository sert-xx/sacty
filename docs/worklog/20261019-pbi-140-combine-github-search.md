# GitHub の取り込みの検索を、ドメインごとにプロジェクトをまたいでまとめる

- 日付: 2026-10-19（UTC）
- タスク: PBI-140
- PR: #152
- ブランチ: feat/issue-140-combine-github-search
- 関係する ADR: なし

## 目的

GitHub の取り込み（Issue・PR のレビュー）は、プロジェクトの対象（リポジトリ・Org）ごとに、種類ごとに検索を1回ずつ出していた。
対象が増えるほど検索が増え、GitHub の検索 API のレート制限（アカウントごとに 1 分あたり 30 回）に当たりやすい。ステークホルダーから、
プラットフォームへのリクエストを最小にし、プロジェクトへの振り分けは sacty の側で行うよう求められた（ドメインごとにまとめる）。

## したこと

- デーモン：検索を、ドメイン（ホスト）・アカウント・検索の種類ごとにまとめ、すべてのプロジェクトの対象を `repo:`・`org:` として
  1つの検索に並べる（`intakeSources`）。1つの検索に入れる対象は `INTAKE_SCOPES_PER_QUERY`（30）個までで、超えたら分ける。
  担当のプロジェクトの判定・二重の取り込み・依頼の本人の照合は、今までどおり見つかったものごとに `importIssues` で行う。
  アカウントを選んでいないプロジェクトは、まとめずにプロジェクトごとに理由を示す。
- docs：仕様書（取り込み）と利用者向けの説明（取り込み）。

## 確かめたこと

- `npx biome check`・`npm run typecheck`・`npx vitest run`・`npm run build` が通った。
- 実際の GitHub で、複数の `repo:`・`org:` を入れた検索が、それぞれの結果を合わせたものになることを確かめた（151 件と 1,985 件の
  リポジトリで 2,136 件。80 個の `repo:` を並べても答える）。存在しないリポジトリが混じっても、ほかの結果を返す（それだけなら 422）。
- 同じアカウントの 3 つのプロジェクトで取り込むと、GitHub への検索は種類ごとに 1 回（計 2 回。まとめる前は 6 回）になることを、
  実際の GitHub で確かめた。
- まとまること・ドメイン・アカウント・種類が違えば分かれること・アカウントの無いプロジェクトはプロジェクトごとのこと・上限で分かれること・
  1つの検索の結果を担当のプロジェクトに振り分けることをテストにした。それぞれの修正を戻すとテストが落ちることを確かめた。
