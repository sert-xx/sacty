# エージェントの実行ごとのセッションログを残し、画面から見られるようにする

- 日付: 2026-10-13（UTC）
- タスク: PBI-62
- PR: #71
- ブランチ: feat/issue-62-session-logs
- 関係する ADR: [エージェントの実行ごとに、秘密情報を伏せたセッションログを先頭と末尾を残して SACTY_HOME に残し、画面から見られるようにする](../adr/20261013-1533-session-logs-per-run.md)、[Claude Code を stream-json で動かし、最後の答えは標準出力を溜めずに行ごとに読んで取り出す](../adr/20261013-1533-superseded-claude-stream-json-output.md)

## 目的

エージェントの実行ごとに、セッションログ（途中の出来事と標準エラー出力）を残し、タスク詳細の作業履歴から見られるようにする。
エラーで止まったときの原因の調査と、今後の監査（PBI-55）に使う。受け入れ条件の要点は次のとおり。

- 実行ごとにセッションログが残り、失敗・途中で止めた実行も残る。
- 作業履歴の実行の行からログを画面で見られ、生のファイルもダウンロードできる。
- ログに秘密情報が出ない（境界をまたいだ値も伏せる）。大きすぎるログは切り詰められ、そのことが分かる。
- Claude Code・Codex・スタブのどれでも動き、最後の答えの読み取りはこれまでどおり。

## したこと

- 実行の形（`apps/daemon/src/agents/parse.ts`・`apps/daemon/src/agents/docker.ts`）：Claude Code を `--output-format stream-json --verbose` で動かし、
  最後の `result` から値を読む。result が無いときは失敗にする。これまでの json の形も読める。標準出力は溜めずに行ごとに読む読み手に渡し、
  標準エラー出力は先頭と末尾だけを持つ。
- 保存（`apps/daemon/src/session-logs.ts`）：`SACTY_HOME/runs/<taskId>/<runId>.jsonl`・`.stderr.log`・`.meta.json`。execute を通る実行すべて。
  失敗・途中で止めた・コンテナを起動する前に止まった実行も残し、中止の掃除では消さない。`runId` を記録に足した（`packages/core/src/events.ts`）。
- 秘密情報：書く前に伏せ、境目をまたぐ値・JSON でエスケープされた形も伏せる。後から分かった値は閉じるときに伏せ直す。伏せる分の切れ目を
  サロゲートペアの外側に寄せる。
- 切り詰め（PO の判断）：途中の出来事は先頭 15MB・末尾 3MB、標準エラー出力は先頭 1MB・末尾 1MB。伏せてから切り詰め、間に
  `sacty.truncated` の行を入れる。
- API（`apps/daemon/src/server.ts`）：`GET /api/tasks/:id/runs/:runId/log`・`/files/{events|stderr}`。
- 画面（`apps/web/src/app/tasks/[id]/runs/[runId]/page.tsx`・`apps/web/src/lib/session-log.ts` ほか）：作業履歴の実行の行の「ログを見る」から、
  出来事ごとに並べたログ・切り詰めの警告・生のファイルのダウンロード・標準エラー出力。ログの無い古い実行は「ログはありません」と理由を出す。

## 確かめたこと

- `npm run lint`・`npm run typecheck`・`npx vitest run`（711 件）・`npm run build` が通った。レビューの対応の後、レビューでは 721 件・
  lint・typecheck・`diff --check` の成功を確かめた。
- 本物の Claude Code（2.1.296・サブスクリプション）で、一時的な環境のチャットに「ok とだけ答えて」と質問した。答え「ok」・使用量・費用を
  読み取り、ログ（system・assistant・result など）が保存され、秘密情報が含まれず、画面で見られた。
- 実際の Docker（sacty-agent:0.1.0）で、成功・利用上限・標準エラー出力に秘密情報を出して終了・途中で止めた実行のログが残り、秘密情報が
  出ないこと。約 25MB の出力で、先頭と末尾（最後の result の行）が残り、壊れた JSON の行が無いこと。
- 主要な処理を 28 か所わざと壊し、すべてテストが落ちることを確かめた。
- レビューの対応の後、実際の Docker で出力を 4.7〜93.5MB に変えてデーモンのメモリの増えを測った。ヒープの増えは +8.5〜22.7MB で
  出力の大きさに比例せず（全量を持つ旧方式を模したものは 93.5MB で +406.6MB）、どれも最後の答えを読め、ログの最後は result の行だった。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| 秘密情報を伏せるために持っておく分の切れ目がサロゲートペアの途中に来ると、絵文字・補助漢字が 2 つの置換文字に壊れる（`😀1234` が壊れることを再現） | 切れ目がサロゲートペアの前半の直後に来たら 1 つ前に寄せ、届いた分が前半だけで終わるときも持っておくようにした。指摘の再現が標準エラー出力でも JSONL でも元のまま残るテストと、届いた分の境目 × 先頭と末尾の大きさ × 秘密情報の総当たりのテストを足した |
| stream-json に変えたので、途中の全イベントが実行器の標準出力に溜まり、ログを切り詰めてもデーモンのメモリが制限されない | 標準出力は溜めずに、届くたびに行ごとに読む読み手（ClaudeOutcomeReader・CodexOutcomeReader）に渡し、最後の答えと失敗の判定に要るものだけを持つようにした。上限（16MB）より長い行は読み飛ばす。標準エラー出力は先頭 64K 文字・末尾 256K 文字だけを持つ |

## 残したこと

- デーモンが強制終了すると、メモリに持っている末尾（最大 3MB・1MB）と改行の届いていない行は失われる（先頭は書いた分が残る）。
- 先頭を超えた後は、実行が終わるまで末尾がファイルに出ない（実行中にダウンロードすると先頭だけ）。
- 伏せられるのは、そのままの値と JSON でエスケープされた形だけ（base64 など別の符号化は伏せられない）。
