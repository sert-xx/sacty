# 依存のある子タスクを、依存先の PR が最終レビューに合格した時点で、その PR のブランチに重ねて始める

- 日付: 2026-11-08（UTC）
- タスク: PBI-317
- PR: #324
- ブランチ: feat/issue-317-stacked-child-tasks
- 関係する ADR: [依存のある子タスクは、依存先の PR が最終レビューに合格した時点で、その PR のブランチに重ねて始める](../adr/20261108-0615-stack-dependent-subtasks-on-reviewed-pull-requests.md)

## 目的

依存のある子タスクは、依存先がすべて片付く（PR のマージなど）まで始まらず、依存先の PR を人がレビュー・マージする時間がそのまま後の子タスクの待ちになっていた。
人が決めた「依存先のブランチから先に始める（重ねた PR）」を実装する。受け入れ条件の要点は次のとおり。

- 依存先が最終レビューに合格したら、マージを待たずに子が始まる。
- 依存先の更新・マージ・中止で、子の作業領域と PR の起点（base）が正しい。取り込みの衝突は、ベースブランチの取り込みと同じ扱い。
- 依存先が複数あるときの起点の決め方を決めて仕様に書く。決められなければ今と同じく待つ。
- デーモンを再起動しても、起点・取り込みの状態を失わない（イベントで記録する）。
- 依存の無い子・分割しないタスクの振る舞いは変えない。
- PR の本文で、どの PR に重ねたかが分かり、マージの順序を守らせる。

## したこと

- 始める時点と起点（`apps/daemon/src/service.ts` の `blockedStart`・`stackChain`）：依存先を、片付いた・マージ済み・重ねられる（最終レビューに合格して承認待ちの、開いている実装の PR。`packages/core/src/projection.ts` の `reviewedPullRequest`）・それ以外に分ける。
  片付いた・マージ済みでない残りのうち1つに重ねられ、ほかの残りがすべてその依存先の重ねの連なりにあれば、その PR のブランチの合格したコミットに重ねて始める（`TaskUnblocked` の `stackedOn`）。決められなければ待つ。
- 作業領域（`prepareRepositoryNow`）：重ねた子タスクは、初めて用意するとき、依存先の PR のブランチを clone して合格したコミットにする。起点のブランチは依存先の PR のブランチ。オーケストレーターのベースブランチの選択は使わない。
- 取り込み（`syncBase`）：重ねている間は、ベースブランチの代わりに、依存先の PR の合格したコミット（ブランチの先頭ではない）を取り込む。依存先に合格した PR が無い（作り直しの途中・閉じられた）ときは取り込まない。衝突・失敗は今までの取り込みと同じ扱い（`BaseBranchMerged`）。
- PR（`publish`）：重ねた子タスクの PR は、依存先の PR のブランチに向け、検証に通った後もドラフトのまま承認待ちにする。更新でも向き先を送り（`PullRequests.upsert` の `retarget`、`apps/daemon/src/github.ts` で PATCH に `base` を足す）、`PullRequestPublished` の `baseBranch` に記録する。本文の先頭に、重ねた PR とマージの順序を書く（`apps/daemon/src/prompts.ts` の `stackedBodyLines`）。
- 依存先のマージ（`stackAction`・`settleStack`）：子タスクに `StackedDependencyMerged` を記録して、起点のブランチを付け替える（依存先も重ねていたなら、その先に重ね直す）。承認待ちの PR は、PR の確認で GitHub の向き先を付け替え、本文を書き直してドラフトを外す（`retargetDue`・`retargetPullRequest`・`PullRequestRetargeted`）。失敗は次の確認でやり直す。
- 依存先の中止：重ねた先の連なりに中止があれば、子タスクを一時停止し（`stack.dependencyCancelled`）、再開を受け付けない（`resume`）。合格する前の中止は、今までどおり子を始めない。
- 画面の作業履歴の文言（`apps/web/src/lib/labels.ts`・`apps/web/src/i18n/messages/labels.ts`）に、重ねて始めた・付け替えた・PR の向き先を付け替えたを足した。
- docs：仕様書（`docs/spec/split-and-integrate.md` に「依存先の PR に重ねる子タスク」、`docs/spec/tasks-and-steps.md` のベースブランチの取り込み・検証に通った実装の PR から参照。日英）、ユーザードキュメント（`docs/user/tasks.md` に「依存のある子タスクの PR（重ねた PR）」。日英）、ADR。
  図とスクリーンショットに写る振る舞い・画面は変えていない（分割の子タスクの流れの図は無く、スクリーンショットの架空のデータに分割の子タスクは無い）。

## 残したこと

- 承認待ちの間は、依存先の更新・マージの後のベースブランチを取り込まない（今のベースブランチの取り込みと同じ）。依存先が squash でマージされると、付け替えた PR の差分に依存先の変更が重なって見えることがある。差し戻し・指摘でやり直すと解消する。
- 依存先が中止された重ねた子タスクは、作業領域をベースブランチから作り直す仕組みを作らず、止めて人に中止してもらう形にした。
- 実際の GitHub での動作（PR の向き先の付け替え・ドラフトの切り替え）は、フェイクのテストだけで確かめた。
