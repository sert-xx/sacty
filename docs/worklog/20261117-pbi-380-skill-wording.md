# 既定のスキルの再レビューの採用の規則で、重みを見直す前回の要修正の範囲と、差分の外での扱いを一通りに読める文にする

- 日付: 2026-11-17（UTC）
- タスク: PBI-380
- PR: なし
- ブランチ: feat/pbi-380-skill-wording
- 関係する ADR: [レビューの指摘の重みを、影響の大きさと起きやすさで決め、自己レビューは要修正だけを修正に戻す](../adr/20261117-0244-review-finding-weight-by-impact-and-likelihood.md)

## 目的

再レビューの指示文の側は、[前の作業](20261117-pbi-380-rereview-prompt-weight-rule.md)で直した。
そのレビューで残った、既定のスキル（`pr-review` の「採用の規則」）の文の 2 点を直す。

1. 「表では `should` に当たると分かったとき（稀で、影響が中以下）」は、影響：小で稀でない前回の要修正を、見直しの対象にするかどうかで二通りに読めた。表で `should` に当たるものは、すべて対象になる、と一通りに読める文にする。
2. 「`should`・`nit` は、指摘箇所が前回以降の差分に含まれるときだけ採用する」を字義どおりに当てると、重みを見直した前回の指摘（直っていないので、差分の外）が不採用になる。差分の外でも `should` として残し、判定は「提案あり」にする、と書く。

重みの基準（表）と、方針は変えない。文を明確にするだけなので、ADR は足していない（関係する ADR の決定「前回 `must` として出した指摘が、表では `should` に当たると分かったときは、未対応でも `must` に数えない」のとおり）。

## したこと

- `apps/daemon/default-context/skills/review/review-dispatch/references/pr-review.md` の「採用の規則」
  - 括弧書き「（稀で、影響が中以下）」を外し、対象を下の項目に分けて書いた。
    - 表で `should` に当たるものは、すべて対象にする（影響：中で稀なものも、影響：小で稀でないものも）。
    - 影響：小で稀なもの（表では出さない）も、前回すでに出しているので、同じに扱う。
    - 受け入れ条件・要求要件の不適合は、対象にしない（表に依らず `must` のまま）。
  - `should`・`nit` の差分の決まりの次に、重みを見直した前回の指摘は、指摘箇所が前回以降の差分の外でも不採用にせず、`should` として残す、と足した。新しい指摘として繰り返さず、前回の指摘の状況に書く。ほかに `must` が無ければ、判定は「提案あり」。
- 同じ資料群の `aggregation.md` の「不採用」：前回以降の差分の外の `should`・`nit` を不採用にする項目に、重みを見直した前回の指摘は不採用にしない、と足した（同じ決まりを言う箇所。grep で見つけた）。
- `apps/daemon/src/prompts.ts`（`rereviewLines`）：対象を述べる括弧書き「（独立した条件が 2 つ以上重なったときだけ起き、影響が中以下）」を、「（影響が中で、独立した条件が 2 つ以上重なったときだけ起きるもの。影響が小のものは、起きやすさを問わない）」に直した。ほかの行は変えていない。
- 仕様書：`docs/spec/tasks-and-steps.md`（指示文の同じ括弧書き）と `docs/spec/context.md`（既定のレビュー用スキルの節）を、英語の版と合わせて直した。
- テスト：`apps/daemon/src/default-skills.test.ts` に 1 件を足し、括弧書きを確かめていた 1 箇所を直した。`apps/daemon/src/prompts.test.ts` の、スキルと指示文を突き合わせるテストを、新しい文に合わせた。

決めたことと理由：

- 指示文の括弧書きも直した。スキルと同じ形の括弧書きで、「稀なものだけが対象」と読むと、スキル（表で `should` に当たるものすべて）と食い違う。直したのは範囲を述べる括弧書きだけで、指示の中身（数えない・提案として扱う・書き方・判定）は変えていない。
- 影響：小で稀な前回の要修正を、`should` と同じに扱う、と書いた。前の文の括弧書き（稀で、影響が中以下）も、指示文の括弧書きも、これを対象に含めていた。表では「出さない」だが、前回すでに作者に出した指摘なので、黙って消さずに、重みを見直した指摘として残す。人の確認は、まだ。
- 不適合を対象にしないことを書いた。表の升目だけで読むと、影響：小の不適合が `should` に当たると読めるため。不適合は起きやすさを問わず `must`、という決まりのまま。
- ユーザードキュメント（`docs/user/intake.md`）は、「確かめ直して `[提案]` の重さだと分かったとき」と書いていて、今回の文と食い違わないので、変えていない。

## レビューの指摘と対応

自分で、別の読み方を探して確かめた。

| 指摘 | 対応 |
| --- | --- |
| 対象の説明の後ろに「`should` として扱い」を続けると、不適合の文に掛かって読める | 扱いの文を先に置き、対象を下の項目に分けた |
| 表の升目だけで読むと、影響：小の不適合が対象に入る | 不適合は対象にしない、と書いた |
| 表で「出さない」に当たる前回の要修正の扱いが、括弧書きを外すと書かれなくなる | 同じに扱う、と書いた（前の括弧書きと指示文が含めていた範囲のまま） |
| 重みを見直した指摘だけが残るときに、「指摘なし」とも読める | 「修正が必要」にも「指摘なし」にもしない、と書いた |

## 残したこと

- 影響：小で稀な前回の要修正を `should` と同じに扱うこと、指示文の括弧書きを直したことは、人の確認がまだ。
