# 最終レビューのやり直しで、前の回が挙げた「人が確かめること」を引き継ぐ

- 日付: 2026-11-03（UTC）
- タスク: PBI-294
- PR: なし
- ブランチ: feat/issue-294-pbi-294
- 関係する ADR: [最終レビューのやり直しで、前の回が挙げた「人が確かめること」を、理由なしに落とさない](../adr/20261103-1100-carry-human-checks-across-final-reviews.md)

## 目的

実験 S16 r3（findings F42）で、1回目の最終レビューが人が確かめることに挙げた点（`Number()` が `"1e1"` などを受けること、設計に無い直列化のキュー）が、その部分のコードが変わっていない2回目で、理由なく消えた。依頼者は欠陥を見逃して承認した。

受け入れ条件：

- 2回目以降の最終レビューは、前の回の「人が確かめること」と「範囲内か判断できない」とした変更を引き継ぐ。外すのは、解消したとき、または理由を書いたときだけ。
- 引き継いだ点は、PR の本文の「人が確かめること」に今までと同じ形で出る。
- 1回目の振る舞いは変えない。
- 指示の文面と引き継ぎの仕組みのテストを足し、修正を戻すと落ちることを確かめる。指示は特定の言語・ツールに寄せない。

## したこと

- 引き継ぎは sacty が行う。`carriedHumanChecks`（前の回の `humanChecks`。sacty が毎回作る「実行できなかった検証」の項目を除く）を、`extractFinalReview` の `previousHumanChecks` に渡し、外すと申告された項目以外を `humanChecks` の先頭に足す。
- 最終レビューの指示（`carriedHumanCheckLines`）に、前の回の項目を `[P1]` の番号つきで渡す節を足した（前の回がある場合だけ）。外してよい条件と、`droppedHumanChecks` に「<番号>：<外す理由>」を書くことを指示する。判定の形式の例にも、このときだけ `droppedHumanChecks` を足した。
- 理由が空・「なし」・番号が合わない申告は、外さずに引き継ぐ。外した項目と理由は、`FinalReviewed` の `droppedHumanChecks`（任意の項目）に記録する。
- 仕様書（日英）・ユーザードキュメント（日英）・ADR を足した。

## 確かめたこと

- `npx vitest run apps/daemon/src/final-review-carry-human-checks.test.ts`：19 件通る。引き継ぐ対象（前の回が無い・空・1件・複数件、sacty が作る項目の除外）、1回目の指示が変わらないこと、やり直しの指示の文面、外す理由の読み方（理由なし・番号違い・重なり・オブジェクト・全角）、新しい項目との重ね方、3回目以降、PR の本文の出方。
- `npx vitest run apps/daemon/src/daemon.test.ts -t "PBI-294"`：1回目に挙げた2件が、2回目の判定が空でも残り、理由を書いて外した1件だけが外れて記録されること。`service.ts` の引き継ぎの呼び出しを外すと落ち、`prompts.ts` の引き継ぎを外すとテスト 11 件が落ちることを確かめた。

## 残した制限

- 外す理由の真偽は、sacty は確かめない。
- ゴールガーディアンが言い換えて書いた同じ点は、重なって出うる。
