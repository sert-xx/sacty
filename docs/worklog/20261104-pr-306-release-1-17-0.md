# 版を 1.17.0 に上げる

- 日付: 2026-11-04（UTC）
- タスク: なし
- PR: #306
- ブランチ: feat/release-1-17-0
- 関係する ADR: [版は 1.0.0 から semver で付け、タグと GitHub Releases でリリースする](../adr/20261019-2345-semver-releases.md)

## 目的

1.16.0 の後に、機能の追加と修正が入った（PR #304・#305）。設定ファイルの形・台帳・コマンドの引数を壊す変更は無く、機能の追加（段階 expert など）があるので MINOR を上げ、1.17.0 をリリースする。

## 1.16.0 からの変更

- r5 で見つかった問題の修正（PR #304）：作業用のファイルの置き場を作業領域の外にし、内部の名前が差分に入ったら範囲外にする、質問への答えだけの差し戻しを軽い直しにする、
  要求要件・設計の前後の作業の報告を取り除く、PR の本文の重なりを除く、承認の画面に今の head の AI のレビューの状況を出す、など。
- 段階 expert の追加と既定のモデルの見直し（PR #305）：Codex の entry・standard を gpt-6.1-terra、ultimate を gpt-6-astra、Claude の ultimate を claude-fable-5-1 にした。
- 互換性：設定ファイルの形は変わらない。ただし `providers.*.available_models` に新しいモデルの単価が無いと、codex_entry・codex_standard・codex_ultimate・claude_ultimate は使えない扱いになり、
  `step_agents` などで指していると設定の誤りで止まる。既存のイベントに足した項目は任意で、1.16.0 の作業履歴はそのまま読める。
  差し戻しの原因 `question_answer` が記録された後で 1.16.0 に戻すと、作業履歴を読めない。
- 更新の後にすること：`npm ci` で依存を入れ直し、新しいモデルの単価を設定に足し、既定のイメージの名前が `sacty-agent:1.17.0` に変わったので、`npx sacty image build` で作り直す。

## したこと

- 5 つのパッケージ（`@sacty/core`・`@sacty/daemon`・`@sacty/web`・`@sacty/cli`・`apps/desktop`）とワークスペースの依存の版を `1.17.0` にし、
  `package-lock.json` の版の行も同じにした。
- 既定のイメージの名前（`DEFAULT_IMAGE`）を `sacty-agent:1.17.0` にした。
  同じ版にしたもの：仕様書（`agent-execution`・`configuration`）とユーザードキュメント（`config`・`images`）の日英、イメージの名前を書いているテスト・コメント、ゲートウェイの MCP クライアントの版の文字列。
  直したファイルは、1.16.0 の版上げ（PR #303）と同じ範囲。
- 元のイメージのダイジェスト：`docker buildx imagetools inspect node:26-bookworm-slim` の `Digest`（インデックス）が、`packages/cli/docker/Dockerfile` の
  `BASE_IMAGE`・`NODE_IMAGE` のダイジェストと同じだった（`sha256:bc0a2afd…`）ので、更新していない。
- エージェントの CLI の版（`packages/cli/docker/agent-cli`）は上げていない。

## 確かめたこと

- `npm ci`・`npm run lint`・`npm run typecheck`：通過（`npm ci` の後の `package-lock.json` の差分は版の行だけ）。
- `npx vitest run`（`tests/docs` を含む）：通過（件数は PR の本文に書く）。
- `git grep -F 1.16.0` で、ADR・作業履歴のほかに `1.16.0` が残っていないことを確かめた。
