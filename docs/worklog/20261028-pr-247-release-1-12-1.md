# 版を 1.12.1 に上げる

- 日付: 2026-10-28（UTC）
- タスク: なし
- PR: #247
- ブランチ: feat/release-1-12-1
- 関係する ADR: [版は 1.0.0 から semver で付け、タグと GitHub Releases でリリースする](../adr/20261019-2345-semver-releases.md)

## 目的

1.12.0 の後に、依存の更新（PR #245・#246）が入った。機能の追加は無く、画面・API・設定ファイルの形・台帳・コマンドの引数も
変わらないので PATCH を上げ、1.12.1 をリリースする。

Node.js の下限が `>=22.23.4` から `>=26.12.1` に上がるが、依存の更新として扱い、MAJOR は上げないことにした（作者の判断）。
利用者がすることは、リリースの説明の「更新の後にすること」に書く。

## 1.12.0 からの変更

- Node.js を 26.x の LTS（26.12.1）に上げた（PR #245）。
  - `engines.node` を `>=26.12.1` に、`.node-version`・`mise.toml` を `26.12.1` にした。
  - 既定の元のイメージを `node:26-bookworm-slim` にした。
- TypeScript を 7.0.2 に上げた（PR #245 で 6.0.3、PR #246 で 7.0.2）。
- 更新の後にすること：
  - Node.js を 26.12.1 以上にする。
  - `npm ci` で依存を入れ直す。
  - `docker pull node:26-bookworm-slim` で元のイメージを取り直し、既定のイメージの名前が `sacty-agent:1.12.1` に変わったので、
    `npx sacty image build` で作り直す（`sacty image build` は `--pull` を付けないので、取り直さないと古い元のイメージのまま作られる）。

## したこと

- 4 つのパッケージとワークスペースの依存の版を `1.12.1` にし、`package-lock.json` の版の行も同じにした（これまでと同じく、版の行だけを直した）。
- 既定のイメージの名前（`DEFAULT_IMAGE`）を `sacty-agent:1.12.1` にし、仕様書（`agent-execution`・`configuration`）・ユーザードキュメント
  （`config`・`images`）の日英と、イメージの名前を書いているテスト・コメントを同じ版にした。ゲートウェイの MCP クライアントの版の文字列も
  `1.12.1` にした。

## 確かめたこと

- Node v26.12.1 で、`npm ci`・`npm run lint`・`npm run typecheck`・`npm run build`：通過（`npm ci` の後に `package-lock.json` の差分は版の行だけ）。
- `npx vitest run`（`tests/docs` を含む）：157 ファイルが通過、1 ファイルが失敗。失敗は `install-security-tools.test.ts` の 2 件（macOS の作業環境で
  道具を置けない）で、1.12.0 のときと同じく、版を上げる前の状態でも失敗する。版の文字列とは関係が無い。
- `git grep 1.12.0` で、ADR・作業履歴のほかに `1.12.0` が残っていないことを確かめた。
