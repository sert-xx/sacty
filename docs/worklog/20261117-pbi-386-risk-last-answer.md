# PR のリスク評価の最後の答えが読めないとき、前に出た答えにさかのぼらない

- 日付: 2026-11-17（UTC）
- タスク: PBI-386
- PR: #421
- ブランチ: feat/pbi-386-risk-last-answer
- 関係する ADR: [PR のリスク評価は、最後に出た答えだけを読み、読めなければ前の答えにさかのぼらない](../adr/20261117-1245-risk-assessment-reads-only-last-answer.md)

## 目的

リスク評価の答えの読み取りは、後ろの候補から順に読み、読めない候補を飛ばして前の候補へ進んでいた。
評価の答えが 2 つ以上あり、最後の 1 つが読めない形のとき、前に出た答え（下書きの `low` など）が載りえた。
読めない形を決めた目的（合図・上げ幅を読み落として、低い段階を載せない）を、この経路でも果たす。

受け入れ条件の要点：

1. 最後の評価の答えが読めなければ、評価できなかったと記録する（前の答えを使わない）。
2. 答えが 2 つとも読めるときは、今までどおり、最後の答えを使う。
3. ほかの読み取りの振る舞いを変えない。
4. 仕様書（日英）・ADR・作業履歴を合わせる。

## したこと

- `apps/daemon/src/risk-assessment.ts`
  - `extractRiskAssessment`：共通の `lastJsonAnswer`（後ろから順に読み、読めないものを飛ばす）を使うのをやめ、最後に出た評価の答えだけを読む（`lastRiskAnswer`・`readRiskAnswer`）。形の判定（段階・合図・上げ幅・根拠）は、変えていない。
  - `lastRiskAnswer`：評価の見出しをキーに持つ JSON のオブジェクトのうち、最後のものを返す。その後ろに、JSON として読めない評価の答え（見出しを最初のキーに持つ形）があれば、答えなしにする。
- `apps/daemon/src/agent-json.ts` の `lastJsonAnswer` は変えていない（工程の選択などの、ほかの読み取りがそのまま使う）。
- docs：仕様書 `docs/spec/risk-assessment`（日英）、ADR。ユーザードキュメントは、「答えを読めなかった」ときの扱いをすでに書いていて、利用者に見える文言・操作は変わらないので、直していない。

決めたこと（ADR に書いた）：

- 「評価の答え」は、評価の見出しをキーに持つ JSON のオブジェクト。見出しの値がオブジェクトでないものも数える。
- JSON として読めない答えが最後にあるときも、さかのぼらない。数えるのは、見出しを最初のキーに持つ形のものだけ（本文が見出しの名前に触れているだけの箇所で、読めた評価を捨てないため）。

## 確かめたこと

- 足したテスト（`apps/daemon/src/risk-assessment.test.ts`）
  - 答えが 2 つとも読める → 最後を使う（後ろが低い段階でも、最後を使う）。
  - 最後の答えが読めない（知らない合図・配列でない合図・決めた値でない上げ幅・決めた値でない段階・根拠の欠け・オブジェクトでない・末尾のカンマ・途中で切れた）→ 読めないものとする。読めない答えが前にあるだけなら、最後の読める答えを使う。
  - 評価の答えでない JSON・見出しの名前に触れているだけの本文が後ろにあっても、最後の評価の答えを使う。
  - PR を作る前の評価（`assessPullRequestRisk`）が、評価できなかった記録（`pr.riskUnreadable`）になる。
  - レビューの読み取り（`extractReviewComments`）が、評価を載せず、どちらの JSON も本文から取り除く。
- 修正を戻して（`risk-assessment.ts` を変更の前に戻して）テストを実行し、「最後の答えが読めない」の 8 件が落ちることを確かめた。
