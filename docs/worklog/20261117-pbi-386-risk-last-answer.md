# PR のリスク評価の最後の答えが読めないとき、前に出た答えにさかのぼらない

- 日付: 2026-11-17（UTC）
- タスク: PBI-386
- PR: #421
- ブランチ: feat/pbi-386-risk-last-answer
- 関係する ADR: [PR のリスク評価は、最後に出た答えだけを読み、読めなければ前の答えにさかのぼらない](../adr/20261117-1245-risk-assessment-reads-only-last-answer.md)

## 目的

リスク評価の答えの読み取りは、後ろの候補から順に読み、読めない候補を飛ばして前の候補へ進んでいた。
評価の答えが 2 つ以上あり、最後の 1 つが読めない形のとき、前に出た答え（下書きの `low` など）が載りえた。
読めない形を決めた目的（合図・上げ幅を読み落として、低い段階を載せない）を、この経路でも果たす。

受け入れ条件の要点：

1. 最後の評価の答えが読めなければ、評価できなかったと記録する（前の答えを使わない）。
2. 答えが 2 つとも読めるときは、今までどおり、最後の答えを使う。
3. ほかの読み取りの振る舞いを変えない。
4. 仕様書（日英）・ADR・作業履歴を合わせる。

## したこと

レビューの対応の後の、今の形を書く（途中の形と経過は、下の「レビューの指摘と対応」）。

- `apps/daemon/src/risk-assessment.ts`
  - `extractRiskAssessment`：共通の `lastJsonAnswer`（後ろから順に読み、読めないものを飛ばす）を使うのをやめ、最後に出た評価の答えだけを読む。評価（`assessment`）か、評価できなかった理由（`reason`）と、出力の中の評価の答え（`answers`。本文から取り除くのに使う）を返す。
    - 評価の答えは、見出しを最上位のキーに持つ、JSON として読めるオブジェクト。
    - 出力を 1 回走査して、最後に出た見出しのキー（`"sacty-risk-assessment":` の形）を見つける。そのキーが、最後の評価の答えの中にあるときだけ、その答えを読む。無ければ（JSON として読めない答え・入れ子の答え・本文の記述）、読めないものとする。
    - 評価できなかった理由は 3 つに分ける。最後の答えの形が合わず、前に読める答えがある（`pr.riskLastUnreadable`）。最後に出た見出しのキーがどの答えの中にも無く、前に読める答えがある（`pr.riskKeyOutsideAnswer`）。それ以外（`pr.riskUnreadable`。今までの文言）。
  - `readRiskAnswer`：形の判定（段階・合図・上げ幅・根拠）。元のコールバックの中身のままで、変えていない。
  - `assessPullRequestRisk`：読み取りが返した理由を記録する。
- `apps/daemon/src/prompts.ts`（`extractReviewComments`）：評価の読み取りを 1 回だけ呼び、その結果から、本文から取り除く答え・評価・評価できなかった理由（`riskUnreadable`）を取る。
- `apps/daemon/src/service.ts`：レビューの工程の評価できなかった記録に、読み取りが返した理由を使う。
- `packages/core/src/messages.ts`：文言 `pr.riskLastUnreadable`・`pr.riskKeyOutsideAnswer`（日英）を足した。
- `apps/daemon/src/agent-json.ts` の `lastJsonAnswer` などの共通の関数は変えていない（工程の選択などの、ほかの読み取りがそのまま使う）。
- docs：仕様書 `docs/spec/risk-assessment`（日英）、ユーザードキュメント `docs/user/tasks`（日英。評価できなかったときの説明に 1 行）、ADR。

決めたこと（ADR に書いた。持ち主の確認はまだ）：

- 「評価の答え」は、評価の見出しを最上位のキーに持つ、JSON として読めるオブジェクト。見出しの値がオブジェクトでないものも数える。
- 最後に出た見出しのキーが、最後の評価の答えの中に無いときは、さかのぼらない。JSON として読めない答え（見出しが最初のキーでなくても）・入れ子の答え・本文が見出しをキーの形で書いているだけの箇所が当たる（読める評価を捨てるほうへ倒す）。
- 見出しの名前だけに触れている本文と、JSON の文字列の値の中の見出しは、数えない。
- 評価できなかった理由を、上の 3 つに分ける。
