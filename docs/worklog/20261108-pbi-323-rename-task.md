# タスクの題を、タスクの途中で人がタスクの詳細から変えられるようにする

- 日付: 2026-11-08（UTC）
- タスク: PBI-323
- PR: なし
- ブランチ: feat/issue-323-rename-task
- 関係する ADR: [タスクの題を、人がタスクの詳細でいつでも変えられるようにし、すでに作った PR の題は書き換えない](../adr/20261108-1453-rename-task-title.md)

## 目的

利用者から「タスクの名称を途中で変更できるようにしたい」という要望があった。作成済みのタスクの題を、進行中・承認待ち・一時停止中などの
どの状態でも、人がタスクの詳細から変えられるようにする。変更は作業履歴に残し、空・長すぎる題は断る。

## したこと

- 題の使われ方を洗い出した。工程の指示・コミットのメッセージ・通知・PR の本文・書き出し・監査は、使うときのタスクの題を読む。
  PR の題は作るときだけ使い、PR の更新（`upsert` の PATCH）は本文と向き先だけを変える。ブランチ名はタスクの ID から作る（`taskBranchName`）。
  題にある PR のリンクは、レビュー・既存の PR の引き継ぎの対象を決める（`referencedPullRequest`・`continuablePullRequest`）。
- `packages/core`：イベント `TaskRenamed`（`from`・`to`）と入力 `RenameTaskInput` を足した。投影は題を変え、`titleChange` に最後の変更を持つ。
  チケットのトリアージ（`TicketTriaged`）は、人が変えた題を書き換えないようにした。文言のコード `title.unchanged`・`title.pullRequestChanged`（日英）を足した。
- デーモン：`renameTask` と `POST /api/tasks/:id/title`。中止したタスク・今と同じ題・題の PR のリンクが変わる変更は理由を示して断り（409）、
  空・長すぎる題は入力の誤り（400）にする。
- 画面：タスクの詳細の題の横に「題を変える」（鉛筆）を置き、今の題を入れた入力・「変える」「やめる」を出す（`TaskTitle`）。
  断られたら理由を出し、入力した題は消さない。中止したタスクには出さない。作業履歴の行（`TaskRenamed`）の文言を日英で足した。
- すでに作った PR の題を自動で追従させるかは、外部に見える変更なので人に確かめることにし、今回は書き換えない（ADR に記録）。
- 仕様（`docs/spec/tasks-and-steps`）・ユーザードキュメント（`docs/user/tasks`）を日英で直し、ADR を足した。

## 確かめたこと

- `npm run lint`・`npm run typecheck`：通った。
- `npm test`：はじめ、`live-screens.test.ts` の1件が落ちた（題の見出しを要素で包んだため、見出しの親から状態を読むテストが状態を読めなくなった）。
  見出しを包まずに出すよう直して、`apps/web/src/components` のテストが通ることを確かめた。
- 直した後の `npm test`：4492 件が通り、`install-security-tools.test.ts` の1件が5秒の上限で落ちた（全件を並べて動かした負荷のため。
  この変更と関係が無く、そのファイルだけを3回動かして3回とも通った。直す前の全件の実行でも通っていた）。
- `npx vitest run tests/docs`：通った。
- 画面：一時の SACTY_HOME に `scripts/docs-screenshots/seed.mjs` の架空のデータを入れ、別のポート（4801・4810）で `sacty up` を起動して、
  アプリ内のブラウザで確かめた。一時停止中・実装の PR のマージ待ちのタスクで題を変えられ、状態は変わらず、作業履歴に「タスクの題を「…」から
  「…」に変更（人間）」の行が出て、ダッシュボードの一覧も新しい題になった。空白だけの題は「タイトルを入力してください。」で断られ、
  入力は開いたまま。Enter で送れ、Esc・「やめる」で閉じる。中止したタスクには「題を変える」が出ない。
- ユーザードキュメントの `task-detail.png`・`task-detail.en.png` を `scripts/docs-screenshots/capture.mjs` で撮り直した（ほかの画像は変えていない）。
- 足したテスト：投影（題の変更・空や長すぎる記録の拒否・中止したタスク・トリアージが人の題を書き換えない）、デーモン（承認待ち・実行中・
  一時停止中の変更と次の実行の指示の題、再起動の後の題、拒否の理由、題の PR のリンク、API の 200・400・409）、画面（入力の開閉・送る値・
  断られたときの理由と入力の保持・中止したタスク）、作業履歴の文言（日英）。
- 修正を戻すと落ちることを確かめた：投影の題の代入・トリアージの条件・PR のリンクの確かめ・同じ題の確かめ・変えた後に入力を閉じる処理・
  中止したタスクでボタンを隠す条件・作業履歴の文言の分岐を、それぞれ戻して、足したテストが落ちることを確かめた。
