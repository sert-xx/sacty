# コンテキストリポジトリの images.yaml にイメージを定義でき、デーモンが起動の後に裏で作るようにする

- 日付: 2026-11-11（UTC）
- タスク: PBI-325
- PR: #339
- ブランチ: ccr-c948a1e8-xm8eih
- 関係する ADR: [コンテキストリポジトリにイメージを定義できるようにし、デーモンが起動の後に裏で作る](../adr/20261111-0038-context-images-built-by-daemon.md)

## 目的

機能やリポジトリごとに要るイメージ（Playwright のブラウザなど）を、各自の `config.yaml` ではなくプロジェクトのコンテキストリポジトリで定義できるようにする。

- 各自の `config.yaml` の `images` も、これまでどおり使える。
- `sacty image build` は `config.yaml` のイメージだけを作る。
- コンテキストのイメージは、sacty の起動の後にデーモンが裏で非同期に作る。
- 画面には、作成中であることを出す。
  失敗したときは、理由・ログ・作り直しを出す（利用者と決めた）。
- 作成中に、タスクがそのイメージを選ぼうとしたときは、作り終えるまで待つ（利用者と決めた）。

## したこと

- イメージの定義のスキーマを `apps/daemon/src/image-schema.ts` に分けた（`config.ts` → `host-mcp.ts` → `context.ts` → `config.ts` の循環の読み込みを避けるため）。
  `config.yaml` の `images` と `images.yaml` で同じものを使う。
- `context.ts`：層の `images.yaml` を読み（`image` と知らない項目は書けない）、`mergeNamed` で合成し、`locked`・`remove` に `images` を足した。
  デーモンが読むための `contextImages` を足した。
- `context-images.ts`：`ContextImageBuilder`。
  プロジェクトごとにコンテキストを読み、定義の中身のハッシュの名前で、無いものを1つずつ作る。
  状態・ログの末尾・作り直し・待ち・古いものの片付けを持つ。
- `service.ts`：`projectImagesConfig` で、タスクのプロジェクトのイメージを `config.yaml` の `images` に足して、工程の選択・実行・検証・作成時の指定などで使う。
  作成中・失敗のものは、選べるが実行のときに理由で止める（`resolveImage` の `unavailable`）。
  `awaitingContextImages` で、作成中は、イメージを使うかもしれないタスクの実行を始めない（上限60分）。
  状態に `contextImages` を載せ、読めなかった・同じ名前だったことを `warnings` に載せた。
- `server.ts`：作り直しの API と、プロジェクトの保存・削除での読み直し。
- `main.ts`・CLI：デーモンに `SACTY_DOCKER_DIR`（Dockerfile の場所）を渡し、起動の後に作り始める。
- 画面：どの画面にも「イメージの作成」（作成中・順番待ち・失敗・ログ・作り直す）を出し、5秒ごとに取り直す。
  イメージの選択肢に、そのプロジェクトのコンテキストのイメージを足した。
- 文書：ユーザードキュメント（`images.md`・`context.md`・`cli.md`）・仕様書（`daemon-lifecycle.md`・`context.md`・`configuration.md`）を日英で直し、ADR を足した。

## 確かめたこと

- `npx tsc -b packages/core apps/daemon packages/cli`・`npm run typecheck -w @sacty/web`：通った。
- `npx biome check .`：通った。
- `npx vitest run apps/daemon/src/context-images.test.ts`：15件通った（作る・作らない・待つ・順に作る・失敗と作り直し・定義の変更・同じ名前・Docker に接続できない・読めない・片付け）。
- `npx vitest run apps/daemon/src/context.test.ts`：`images.yaml` の合成・上書き禁止・取り除き・書けない項目を足し、通った。
- `npx vitest run apps/daemon/src/daemon.test.ts`：1149件通った（足した5件：作成中は待ち、作り終えたら候補に出してそのイメージで実行する・上限で一時停止・config.yaml のイメージなら待たない・失敗したイメージの工程は止まる・作成時の指定）。
- `npx vitest run tests/docs`：通った。
- 全体の `npx vitest run`：この環境では、変更前から次が失敗する（root で動かしている・git の版・Playwright のブラウザの版の違い）。
  `repository.test.ts`・`host-mcp-processes.test.ts`・`context-mcp.test.ts`・`agent-sessions.test.ts` の 17 件と、ブラウザのテスト 2 ファイル。
  変更前のコードでも同じ 17 件が失敗することを確かめた。
- 実際の Docker でコンテキストのイメージを作ることは、この環境に Docker が無いので確かめていない。
- Node.js は 22（`mise.toml` は 26.12.1）で確かめた。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| 正常時の `/api/status` に `contextImages` が無く、設定の誤りのときに重複している | 直した。正常時に載ることのテストを足した |
| 待っているタスクが、ワーカーの実行の枠を塞ぐ | ワーカーが `runnableTaskIds`（待っているタスクを除いた実行待ち）を使うようにした。テストを足した |
| 片付けの `keep` を決めた後に読み直しが進み、確かめたばかりのイメージを消しうる | 片付けている間は、読み直しが手元にあるかを確かめず、片付け終えてから確かめる。テストを足した |
| `ready` を確かめ直さないので、消えたイメージが作り直されない | 読み直すたびに `ready` も確かめ、無ければ作り直す。テストを足した |
| 別の `SACTY_HOME` のデーモンのイメージを片付けで消す | 名前に `SACTY_HOME` の印を入れ、片付けはその印のものだけにした。テストを足した |
| 名前のハッシュと、作るときの `image_build` がずれうる | 名前を決めたときの `image_build` を持ち、それで作る。テストを足した |
| 作成が応答しないと、後のすべてが作られない | 作成に60分の上限を設け、過ぎたら失敗にして次を作る。テストを足した |
| 失敗の状態がメモリーだけなので、起動し直すと作り直す | 直さず、起動し直すと作り直すことを仕様・ユーザードキュメント・ADR に書いた（起動し直すのは環境を直した後のことが多く、保存の仕組みを増やすほどの得は無いため） |
| Playwright の例は、タスクの実行のときに `XDG_CACHE_HOME` が変わるのでブラウザが見つからない | `PLAYWRIGHT_BROWSERS_PATH` を `env` とインストールのコマンドの両方に書く例にした（日英） |
| 工程の候補のプロジェクトを cookie から決めている | タスクの作成のダイアログは作成先、差し戻しはタスクのプロジェクトを `project` で渡すようにした。テストを足した |
| コンテキストの取得が応答しないと、後のプロジェクトを読まない | 1つのプロジェクトの取得に5分の上限を設け、過ぎたら読めなかったことにして次を読む。テストを足した |
| 止めるときに作成の終わりを待たず、npm の認証を書いた一時ファイルが残りうる | 止めるときに、止めた作成・読み込み・片付けの終わりを、ほかの後処理と一緒に待つようにした。テストを足した |
| （提案）片付けの間に増えた順番待ちを、終えた後に確かめない | 直した。テストを足した |
| （提案）ログを含む欄全体がライブ領域 | 状態の要約だけをライブ領域にした |
| （提案）取得のエラーを日本語の文にしている | 文言のコードのまま返すようにした |
| （2回目）docker が SIGTERM で終わらないと、止めるときの後片付け・作成の時間切れが先に進まない | 止めるときに SIGTERM を送り、10秒で終わらなければ SIGKILL を送るようにした。テストを足した |
| （2回目）設定を読めないまま起動すると、片付けが空の一覧で走る | 設定を読めて、今の定義を読めたプロジェクトだけのときに片付けるようにした。テストを足した |
| （2回目）片付けの docker に上限が無い | 2分の上限を設け、過ぎたら止めて先に進む。テストを足した |
| （2回目）`constructor` などの名前を、config.yaml の同じ名前と取り違える | 自身のプロパティだけを見る `hasImage` にした（`resolveImage`・`imageDefined` も）。テストを足した |
| （2回目）読んでいる途中の保存で、保存後の定義を読み直さない | 読んでいる途中に求められたら、読み終えた後にもう一度読む。テストを足した |
| （2回目・提案）設定の変更のテストが、順番待ちの間の変更を確かめていない | 先の作成で順番を塞ぎ、後のものの名前を決めた後に設定を変える形に直した |
| （3回目）片付けの時間切れで待ちを解くと、消している途中のまま、読み直しの確かめが進む | 時間切れのときも、止めた片付けが終わる（見切りの上限まで）のを待ってから待ちを解く。テストを足した |
| （3回目）npm のトークンの取り出しが応答しないと、作成の時間切れが効かない | 止めてから 15 秒で終わらない作成は見切って失敗にし、次を作る（見切った処理は止めた signal で docker を動かさない）。テストを足した |
| （3回目）人がイメージを default に変えても、作成時の指定のイメージを待つ | 実行のときと同じ順（タスクのイメージを先に）で判定する。テストを足した |
| （3回目・提案）片付けを守るテストが、設定の検査だけで通ってしまう | 設定が戻った後に一部だけ読み直しても片付けないことを確かめるテストを足した |
| （4回目）デプロイの確認で、作成に失敗したコンテキストのイメージの代わりに既定のイメージで確かめる | 作成中・作成に失敗したコンテキストのイメージなら、確認のエージェントを動かさず、理由を記録して止める。テストを足した（直す前のコードで落ちることも確かめた） |
| （提案）`buildImage` の失敗の理由が日本語の文 | 直さない。`sacty image build`（日本語だけの CLI）と同じ文を共有しているため |
