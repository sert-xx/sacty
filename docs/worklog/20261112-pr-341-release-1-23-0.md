# 版を 1.23.0 に上げる

- 日付: 2026-11-12（UTC）
- タスク: なし
- PR: #341
- ブランチ: feat/release-1-23-0
- 関係する ADR: [版は 1.0.0 から semver で付け、タグと GitHub Releases でリリースする](../adr/20261019-2345-semver-releases.md)

## 目的

1.22.1 の後に入った変更（PR #338〜#340）をリリースする。コンテキストリポジトリのイメージの定義（PR #339）と、既定の review スキルの変更（PR #340）は機能の追加なので MINOR を上げる。

## 1.22.1 からの変更

- mise などで Node.js の版が違うディレクトリでも `sacty` を使えるようにし、`sacty launch` の Codex の MCP の名前の衝突を直した（PR #338）。
- コンテキストリポジトリの `images.yaml` にイメージを定義でき、デーモンが起動の後に裏で作る（PR #339）。
- 既定の review スキルが、対象のリポジトリのレビュー用のスキルと開発向けの指示を考慮する（PR #340）。

## 互換性の判断

- 設定ファイルの形・コマンドの引数に、互換性の無い変更は無い。新しい種類のイベントは足していない。
- `npm run cli:install` の入れ方が `npm link` から変わった（PR #338）。前のやり方で入れたこのリポジトリの `sacty` は、`npm run cli:install` をやり直すと外れる。リリースの説明の更新の後にすることに書く。

## したこと

- 5 つのパッケージとワークスペースの依存の版を `1.23.0` にし、`package-lock.json` を `npm install --package-lock-only` で作り直した（差分は版の行だけ）。
- 既定のイメージの名前（`DEFAULT_IMAGE`）を `sacty-agent:1.23.0` にした。
  同じ版にしたもの：仕様書（`agent-execution`・`configuration`）とユーザードキュメント（`config`・`images`）の日英、イメージの名前を書いているテスト・コメント、ゲートウェイの MCP クライアントの版の文字列。
  直したファイルは、1.22.1 の版上げ（PR #337）と同じ範囲。
  機械的な置き換えで、テストの例の値（`Go 1.22.12`、`cli-install` のテストの例の版）まで変わったので、それらは戻した。
- 元のイメージのダイジェスト：`docker buildx imagetools inspect node:26-bookworm-slim` の `Digest` が変わっていたので、`Dockerfile` の `BASE_IMAGE`・`NODE_IMAGE` を `sha256:5df79989…` に更新した。
  新旧のイメージで版を比べると、Node.js が 26.13.0 から 26.13.1 に上がり、npm（11.20.0）と Debian（12.15）は同じだった。
- エージェントの CLI の版（`packages/cli/docker/agent-cli`）は変えていない。

## 確かめたこと

- `npm run lint`・`npm run typecheck`：通過。
- `npx vitest run --no-file-parallelism`（`tests/docs` を含む）：通過（件数は PR の本文に書く）。
- `git grep -F 1.22.1` で、ADR・作業履歴・テストの例の値のほかに `1.22.1` が残っていないことを確かめた。
- 新しいダイジェストで、既定のイメージを `docker build` で作れることを確かめた（結果は PR の本文に書く）。
