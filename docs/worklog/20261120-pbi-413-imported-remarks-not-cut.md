# PR から取り込んだレビュー・コメントの本文を、2000 文字で切らずに実装のやり直しへ渡す

- 日付: 2026-11-20（UTC）
- タスク: PBI-413
- PR: なし
- ブランチ: 提出のときに決まる
- 関係する ADR: なし

## 目的

PR から取り込んだレビュー・コメントの本文が 2000 文字で切られ、後ろの指摘が実装のやり直しに渡らなかった（PR #434 の 2 回目のレビュー）のを直す。

## したこと

- `apps/daemon/src/service.ts`
  - `feedbackRemarks` が、本文を切らずに指摘の文にする（行へのコメントの行の内容の添え書きも、そのまま付く）。
  - `requestChanges` に、取り込んだ指摘だと伝える `imported` を足した。承認待ちの取り込みだけが渡し、人の入力の上限（1 件 2000 文字）の検査を、この指摘には当てはめない。人が差し戻すときの上限・件数の上限（50 件）・1 件を 1 件の指摘にする対応・捨てた指摘の要点（400 文字）は変えていない。
- 仕様書 `approval.md`・`approval.en.md` の上限の記述を合わせた。
- テスト：`daemon-step-pull-requests.test.ts` に、総評（ちょうど 2000 文字・2001 文字・65,536 文字）と行へのコメントで、末尾の目印がやり直しの指示まで入ることを足した。以前の「2000 文字に収める」テストは、この変更で期待が変わるため書き直した。

既定で決めたこと：

- 切らないので、切ったことの記録（受け入れ条件 3）は足さない（切っていないときは何も足さない）。
- 本文を伏せる処理は無かったため、足していない。

## 記録済みの指摘を入れ直す経路（レビューの指摘への対応）

- 取り込んだ指摘は全文のまま記録されるので、記録済みの指摘を差し戻しに入れ直す経路は、どれも 1 件 2000 文字の検査を外す。`packages/core/src/events.ts` に、`RequestChangesInput` から `comments` の文字数の上限だけを外した `RecordedRequestChangesInput` を足し（件数の上限と空の指摘を除くのは同じ）、`requestChanges` は `imported` のとき、これで検査する。切った写しで検査して全文に差し替える書き方と、`as` の型の断定は無くした。
- `imported` を渡す経路は 2 つ：PR の指摘の取り込みと、後続に回したい案を「この PR で直す」と決める `decideDeferrals`（元の文は記録済みの指摘）。人が画面・API で書く差し戻しは、これまでどおり 2000 文字・50 件の上限。
- テスト：2000 文字を超える取り込み指摘を fix に決められること、一時停止の間に届いた長い指摘が再開後のやり直しの指示に末尾まで入ること、人の差し戻しは 2000 文字が通り 2001 文字が断られること。

## 確かめたこと

- `npm run lint`・型検査・`npm test`（全件）を、この変更の後で実行した（結果は PR の本文に書く）。
- 修正を戻すと、足したテスト（総評の 2001 文字・65,536 文字、行へのコメント、fix に決める）が失敗することを確かめた。

## 残したこと

- 取り込んだ指摘の合計の大きさの上限は、この PBI では扱わない（後続）。
- エスカレーションの後、画面の欄から人が長い指摘を書き直して送ると、2000 文字の上限で断られる（欄を空で送れば、残した指摘をそのまま使う）。上限は変えない決まりで、画面の作り替えもしない。
