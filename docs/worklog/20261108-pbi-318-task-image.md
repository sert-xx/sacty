# 実行のイメージを工程ごとからタスクに1つに変え、作成・タスクの詳細・再開・差し戻しの選択もタスクのイメージにする

- 日付: 2026-11-08（UTC）
- タスク: PBI-318
- PR: #322
- ブランチ: feat/issue-318-task-image
- 関係する ADR: [実行のイメージを工程ごとではなくタスクに1つにし、オーケストレーター・作成・タスクの詳細・再開・差し戻しで選ぶのもタスクのイメージにする](../adr/20261108-0334-task-image.md)

## 目的

工程ごとに決めていた実行のイメージを、タスクに1つにする。新しいタスクでは、すべての工程・テスト・最終レビューが同じイメージで動く。
決め方の優先の順（再実行の指定 → 作成時の人の指定 → プロジェクトの対象の指定 → オーケストレーターの選択）は変えない。
作成のダイアログ・API・タスクの詳細・再開・差し戻しの工程ごとのイメージの選択を、タスクのイメージの選択に変える。
古い版の作業履歴（工程ごとの `images` を持つ `TaskCreated`・`StepsChosen` と `StepImageChanged`）は、止まらずに読め、どの工程がどのイメージで動いたかが分かるようにする。
工程ごとのエージェントの選択は変えない。

## したこと

- core（`packages/core`）
  - イベント：`TaskCreated` の `image`、`StepsChosen` の `image`・`defaultImageReason`・`imageUnexplained` と、`imageSource` の `request` を足した。
    新しいイベント `TaskImageChanged`（`from`・`to`）を足した。古い版の項目（`images`・`defaultImageReasons`・`imagesUnexplained`）と `StepImageChanged` は読むために残した。
  - 入力：`CreateTaskInput`・`ResumeTaskInput`・`RequestChangesInput` の `images` を `image` に、`ChangeStepImageInput` を `ChangeTaskImageInput` に変えた。
  - 投影：タスクに `requestedImage`・`image`・`defaultImageReason`・`imageUnexplained`・`imageChange` を持つ。
    工程の実行とテストのイメージは `stepImageOf`・`verificationImageOf`（タスクのイメージ。無ければ古い版の工程ごとのイメージ）で決める。
    工程の選択からやり直すと、タスクのイメージ・変更の記録・既定のイメージの理由を消す。
- デーモン（`apps/daemon`）
  - 優先の順（`pinnedImage`）に作成時の指定（`request`）を入れ、`withImages` がタスクに1つのイメージを決めて `StepsChosen` に記録する。
    候補を見せたのに既定のイメージになったときは、理由を `defaultImageReason` に、理由が無ければ `imageUnexplained` に記録する。
  - オーケストレーターへの指示（`prompts.ts`）を、タスクに1つのイメージ（`image`・`imageReason`・`defaultReason`）を答えさせる形にした。古い工程ごとの答えは読まない。
  - タスクの詳細から変える API を `POST /api/tasks/:id/image`（`changeTaskImage`）にし、工程ごとの `POST /api/tasks/:id/images` を消した。
    再開・差し戻しも同じ確かめ（`taskImageChange`）で `TaskImageChanged` を記録する。
  - 古い版で進め方のすべての工程のイメージを指定したタスクは、タスクのイメージを決めずに工程ごとの指定で動かす（`legacyAllRequested`）。
- 画面（`apps/web`）
  - 作成のダイアログの工程ごとの設定を、上にタスクのイメージの選択1つ、下にエージェントだけの表にした。要約にも指定したイメージを出す。
  - タスクの詳細の「工程のイメージ」を「タスクのイメージ」にした（`TaskImageForm`・`taskImageInfo`）。古い版のタスクは「工程ごと（古い版）」と、どの工程がどのイメージで動いたかを出す。
  - 再開の欄・差し戻しのフォームの選択（`StepChoiceTable`）を、タスクのイメージ1つと工程のエージェントにした。人が変えたものだけを送る扱いは今までどおり。
  - 作業履歴の文に、作成時のイメージ・選んだイメージ・理由が無いこと・`TaskImageChanged` を足した。
- docs
  - 仕様書（工程とタスク・エージェントの実行・承認・設定・マージの後の監視・スケジュール・サービス。日英）、ユーザードキュメント（タスク・イメージ・設定・取り込み・プロジェクトの設定・マージの後の監視・スケジュール・トラブルシューティング。日英）を直した。
  - ADR を足し、工程ごとのイメージを決めた ADR（作成時の指定・再開・差し戻し・PR のレビューだけのイメージ）を `superseded` に変えた。すでに置き換え済みの3件（工程ごとに選ぶ・人が変える・既定のイメージの理由）にも置き換え先を書き足した。
  - スクリーンショットは、写っている所が変わった「工程ごとの設定」と「予算の上限で一時停止したタスク」だけを撮り直した（ほかは日付の表示だけが変わったので戻した）。

## 確かめたこと

- テストを足した・直した。
  - core：タスクのイメージの投影、人の変更、工程が決まる前の変更を誤りにすること、古い版の工程ごとのイメージと `StepImageChanged` を読み、変えた後はタスクのイメージを使うこと、選び直しで消すこと。
  - デーモン：優先の順の4通り（再実行・作成時・プロジェクト・オーケストレーター）、タスクに1つ選ばせて全工程・最終レビューで使うこと、既定のイメージの理由と理由が無いことの記録、人が変える API と再開・差し戻し、古い版の作業履歴を書き込んで再起動しても止まらず工程ごとのイメージで動くこと。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| Sacty のレビュー：古い版の工程ごとのイメージに設定から消えた名前があると、タスクのイメージが無いため警告と欄の自動の展開が出なくなった | 直した。タスクのイメージが無いあいだは、工程ごとの最後の設定にも `images` に無いかを確かめ、その工程に警告を出し、実行すると止まることとタスクのイメージを選べばすべての工程で使うことを案内し、欄を開いて出す。テストを足し、確かめを外すと落ちることを確かめた |
| Sacty のレビュー：古い版の工程ごとの表示は最後に設定した名前で、実行で使った名前ではない（まだ実行していない工程も出る・実行の後に変えた工程は違う） | 直した。実行の記録（`AgentRunStarted`）にはイメージの名前が無いので、作業履歴をたどって、実行を始めたときのタスクのイメージ・工程ごとのイメージから実行で使った名前を求め（`stepRunImages`）、最後に設定した名前と分けて出す（まだ実行していなければその旨）。受け入れ条件の「どのイメージで動いたかが分かる」を、実行で使った名前で満たすため。仕様書・ユーザードキュメント（日英）・ADR も合わせた。テストを足し、求め方を変えると落ちることを確かめた |
| Sacty のレビュー：狭い幅では列の見出しが隠れ、再開・差し戻しの選択がエージェントの設定だと分からない | 直した。狭い幅では、行ごとに「エージェント」の見出しを出す（広い幅では列の見出しを使い、行ごとの見出しは隠す）。テストを足し、見出しを外すと落ちることを確かめた |
| Sacty のレビュー：仕様書の PR のレビューだけのタスクのイメージの選択の条件に、作成時の人の指定が抜けている | 直した。再実行・作成時の人の指定・プロジェクトの対象でイメージを決めていないときだけ選ばせる、と書いた（`pinnedImage`）。英語の版と、取り込みのユーザードキュメント（日英）の同じ条件も直した |
| Sacty の再レビュー：実行で使ったイメージは `AgentRunStarted` だけを数えるので、古い版のタスクで監視の確認をしても deployment の行が「まだ実行していません」のまま | 直した。監視の確認（`DeploymentCheckStarted`）も deployment の工程の実行として数える（`stepRunImages`）。監視の工程の無い古いタスクの確認は、デーモンと同じく実装の工程のイメージにした。テストを足し、数えないように戻すと落ちることを確かめた |
| Sacty の再レビュー：外部作業などで接続先・コンテキストの準備中にイメージを変えると、画面が作業履歴から求めた名前と、実行が使った名前が食い違う | 直した。`AgentRunStarted`・`DeploymentCheckStarted` に任意の `image` を足し、工程・外部作業・統合レビュー・監視の確認で実際に使う名前を記録する。画面は記録の名前を使い、名前の無い古い記録だけ作業履歴から求める。外部作業は準備の後の最新のタスクからイメージを決めて始め、監視の確認は記録を足すときに決めた名前で実行する（記録と実行をそろえるため）。どの実行の記録にも名前があることと、準備中に変えたら変えた後の名前で動いて記録することのテストを足し、修正を戻すと落ちることを確かめた。仕様書（日英）・ADR も直した |

## 残したこと

- 作成時のイメージの指定も、今までどおり進め方を選んだときだけにした（進め方が自動なら、作成のダイアログでは選べない）。
- 古い版で工程ごとの指定を一部の工程だけにしたタスクを、工程の選択からやり直すと、選び直したタスクのイメージが優先する。
- 工程を選び直すと、人のイメージの変更は消える（今までと同じ）。
- スケジュールタスクには、タスクのイメージの指定を足していない（今までも工程ごとの指定が無かった）。
