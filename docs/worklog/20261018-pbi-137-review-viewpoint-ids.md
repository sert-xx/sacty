# 設計を省いたタスクで、最終レビューが判定の ID の食い違いで不合格になる不具合を直す

- 日付: 2026-10-18（UTC）
- タスク: PBI-137
- PR: なし
- ブランチ: feat/issue-137-review-viewpoint-ids
- 関係する ADR: なし

## 目的

設計を省いたタスク（調査・要求要件・実装・マージの後の監視）で、要求要件を満たしているのに、最終レビューが3回とも不合格になった
（ステークホルダーが実際のタスクで発生）。原因は、最終レビューの指示の出力の形式の例が `TV-1` に固定されていたこと。判定する観点は
`REQ` なのに、ゴールガーディアンは例の `TV-1` で「合格」と答え、`REQ` の判定が無いとして不合格になっていた。

## したこと

- 指示：最終レビュー・統合レビューの出力の形式の例を、判定する観点の ID（すべて）にし、その ID のまま答えるよう明示した
  （`verdictFormatLines`）。最終レビューの観点の決め方は `finalReviewViewpointIds` にまとめ、テストの対応の確かめと同じものを使う。
- 判定の読み取り：判定する観点に無い ID だけで答えたときは、読み替えずに不合格のまま、理由を `review.verdictIdMismatch`（観点 REQ の
  判定がありません。答えた ID は TV-1）にした（台帳・画面で原因がわかるように）。
- docs：仕様書（タスクと工程の実装の検証・分割と統合）。

## 確かめたこと

- `npx biome check`・`npm run typecheck`・`npx vitest run`・`npm run build` が通った。
- 設計を省いたタスク（`REQ`）・不具合の修正（`REPRO`）・設計のあるタスク（`TV-…`。すべて）・テストの仕組みが無いタスク・統合レビューで、
  例の ID が判定する観点と一致することをテストにした。
- 次の修正を戻すと、テストが落ちることを確かめた：最終レビュー・統合レビューの例を `TV-1` に戻す、例に最初の観点だけを出す、不具合の修正を
  `REQ` にする、ID の食い違いを理由に出さない、ほかの ID が無いときまで食い違いと出す、サービスの観点を固定する。
- すでに不合格になったタスクは、再開・差し戻しで、直した指示で最終レビューをやり直せる。
