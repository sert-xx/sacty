# sacty の最新版を確かめ、新しい版があれば画面で更新を勧める

- 日付: 2026-10-18（UTC）
- タスク: PBI-135
- PR: なし
- ブランチ: feat/issue-135-update-check
- 関係する ADR: [sacty の最新版を、手元のコミットと GitHub の main で比べて知らせる](../adr/20261018-1213-update-check-against-main.md)

## 目的

PBI-134 でリポジトリに持ったモデルの既定を利用者に届けるため、新しい版が出たことを画面で知らせ、更新を促す（ステークホルダーの要望）。
判断の元は、当面は GitHub の sacty の `main` のコミット（リリースの運用を始めたら GitHub Releases に切り替える）。

## したこと

- デーモン：動いている sacty のコミットと GitHub の `main` を比較の API で比べる `UpdateChecker` を足した。起動のときと1時間ごとに、
  1日たっていれば問い合わせる。確かめられなければ黙る。`GET /api/status` の `update` で返す。
- 設定：`update_check`（既定 `true`）。`false` なら GitHub に問い合わせない。雛形にコメントで書いた。
- 画面：どの画面でも中身の上に、遅れている数・差分のページへのリンク（GitHub の https だけ）・更新のコマンドを出す。
- docs：仕様書（デーモンの起動と終了・設定）、ユーザードキュメント（はじめにの「sacty を更新する」・設定）、ADR。

## 確かめたこと

- `npx biome check`・`npm run typecheck`・`npx vitest run`・`npm run build` が通った。
- 次の修正を戻すと、テストが落ちることを確かめた：同じ・進んでいるときは知らせないこと、1日の間隔の境界、OFF で知らせを消すこと・
  問い合わせないこと、手元のコミットの形を確かめること、問い合わせる前に時刻を記録すること、手元のコミットを1回だけ取ること、失敗したら
  前の知らせを消すこと、設定が誤りでも知らせること、既定を ON にすること、差分のリンクの URL を確かめること、0 件では知らせないこと、
  比較の向き（`ahead_by` を見ること）。
- 同時の問い合わせをまとめる処理を書いていたが、問い合わせる前に時刻を記録するので使われないことが、ミューテーションでわかった。消した。
- 本物の GitHub に問い合わせて確かめたところ、比較の API（`<手元>...main`）の向きを取り違えていた（`main` が進んでいるのは `behind_by` では
  なく `ahead_by`・`status: ahead`）。単体テストも同じ思い込みの応答で作っていたので通っていた。`ahead_by` を見るように直し、本物の応答の形を
  テストに足した。直した後、`main` と同じコミットでは知らせず、#146 の前のコミットでは 4 件遅れていると知らせることを、本物の GitHub で確かめた。
- デモ用のポートで、GitHub の比較の API の応答だけを差し替えて（ステークホルダーの了承のうえ、起動時のスクリプトで）、新しい版があるときに
  画面に表示が出ること、最新のときに出ないことを確かめた。
