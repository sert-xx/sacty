# 差分と無関係な不安定な失敗で、実装に戻さない

- 日付: 2026-11-06（UTC）
- タスク: PBI-310
- PR: #316
- ブランチ: feat/issue-310-flaky-classification
- 関係する ADR: [差分と無関係で実行し直すと結果が変わる失敗を、実装に戻さない](../adr/20261106-1130-accept-flaky-failures-unrelated-to-diff.md)

## 目的

不安定なテストの失敗には、環境による失敗の条件が当てはまらず、実装に戻すしかなかった。差分と無関係と確かめられたものは、人の確認に回して先へ進める。

## したこと

- `tests.flakyFailures`・`rejectedFlakyFailures` を足し、最終レビューの指示に実行し直しの手順を書いた。
- `checkFlakyFailures` で申告を機械的に確かめる。差分のファイルは申告があるときだけ読む。
- 認めた失敗を PR の本文・人が確かめること・画面の説明に出す。認めなかった理由はやり直しの指示に渡す。
- 既定のスキル（`verification-run`・`X-2`）を同じ考えにした。
- 仕様書・ユーザードキュメント（日英）、ADR。

## 確かめたこと

- `npm run lint`・`npm run typecheck`：通った。
- `npx vitest run --no-file-parallelism`：208 ファイル、4207 件が通った（3 件は既存のスキップ）。
- レビュー対応の後：`npm run lint`・`npm run typecheck` が通り、`npx vitest run --no-file-parallelism` は 4248 件が通った（3 件スキップ）。差分の取得の後の確認を外すと、止める経路のテスト2件が失敗する。
- 修正を戻して確かめた：差分のファイルの確認を外すと「テストのファイルが差分に含まれたら認めない」が失敗する。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| 環境の申告を部分一致で照合するので、未説明の失敗が説明済みになる | 「名前：根拠」の名前を取り出して、`failedTests` と完全一致で比べる |
| `tests/./ui.spec.ts` などで、差分のテストを差分外として認める | パスを正規化して比べ、絶対パス・作業領域の外は認めない |
| 申告を認めなくても、ツール不足で合格になる | `guardianTestsPassed` の最初で、認めなかった申告を優先する |
| CI の失敗の申告が、終了コード 0 やテストのコマンドが無いと捨てられる | 同じ条件で確かめて残す。テストのコマンドが無いときは人が確かめることに足し、認めなければ不合格にする |
| 差分の取得中に止めても判定を記録する | 取得の後に止める要求を確かめる |
| 環境と不安定が混ざると「環境による失敗だけ」と出る | 混ざるときのラベルと補足を分けた |
| 認めなかった理由が画面に出ない | テストの結果の詳細に出した |
| 仕様書の空にする条件と、不安定な失敗を引き継がないことの説明 | 日英の仕様書・ユーザードキュメントを直した |
| セルフレビュー：`failedTests` が無いと全件を確かめられないまま認める | テストのコマンドが失敗したのに一覧が無ければ認めない |
| #314 のレビューで、上限を超えた失敗の一覧を記録しないことにした（基のブランチの変更） | 取り込むと失敗の全件を説明できるかの確認が空になるので、記録しない一覧も含めて確かめるようにし、テストを足した |
| `failedTests` の一部を読めないと、残りの一覧だけで全件を説明済みとする | 読めなかった項目を数え、1件でもあれば全申告を認めない |
| 名前に「：」を含む環境の申告を照合できない | 結合する前の名前で比べる。文字列は「：」で区切った先頭からの範囲を候補にする |
| コマンドが無いと認めた失敗が `humanChecks` になり、種別を失って引き継がれる | `ciFlakyFailures`・`rejectedCiFlakyFailures` に分けて持ち、差し戻しの案内と画面に使う |
| 認めなかった理由が英語の画面でも日本語のまま | 理由を文言のコードで持ち、画面の言語で出す |
| 認めなかった理由の長い名前がはみ出す | 一覧に `break-words` を付けた |
| ADR に、CI の申告は全件を照合しない例外が無い | 例外と理由を決定に書いた |
| 環境の申告を空にする出力の説明が、環境と不安定の混在を認める指示と矛盾する | 説明できない失敗があるときだけ空にする条件にそろえた |
| 一覧でない申告を、申告なしとして捨てる | 未指定・空・「なし」と分け、読めない申告は認めず不合格にする |
| コマンドが無いと、申告の項目・除外の条件・JSON の例が指示に無い | CI の節に項目と除外の条件を書き、`tests.flakyFailures` の例を出す |
| 英語の仕様書の区切りの例が半角コロン | 全角の「：」で書き、区切りが全角であることを明記した |

## 残したこと

CI の失敗ジョブの再実行と、不安定なテストの台帳は別の PBI で行う。
