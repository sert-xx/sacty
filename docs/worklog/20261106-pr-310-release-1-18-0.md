# 版を 1.18.0 に上げる

- 日付: 2026-11-06（UTC）
- タスク: なし
- PR: #310
- ブランチ: feat/release-1-18-0
- 関係する ADR: [版は 1.0.0 から semver で付け、タグと GitHub Releases でリリースする](../adr/20261019-2345-semver-releases.md)

## 目的

1.17.1 の後に、同じ内容で実行済みの検証の結果を後の段で使い回す機能が入った（PR #309）。設定ファイルの形・台帳・コマンドの引数を壊す変更は無く、機能の追加があるので MINOR を上げ、1.18.0 をリリースする。

## 1.17.1 からの変更

- 検証の使い回し（PR #309）：実装の工程の検証と PR の CI の結果を、最終レビューとレビュー用のラベルで始まる PR のレビューが、同じ内容なら実行し直さずに使う。
  全体を実行して結果が出ているものだけを使い回し、一部しか実行していないもの・CI で確かめられないものは実行し直す。
- 互換性：イベントに足した項目はすべて任意で、1.17.1 の作業履歴はそのまま読める。イベントの型は知らない項目を捨てるので、足した項目が記録された後で 1.17.1 に戻しても作業履歴を読める。
- 更新の後にすること：`npm ci` で依存を入れ直し、既定のイメージの名前が `sacty-agent:1.18.0` に変わったので、`npx sacty image build` で作り直す。

## したこと

- 5 つのパッケージ（`@sacty/core`・`@sacty/daemon`・`@sacty/web`・`@sacty/cli`・`apps/desktop`）とワークスペースの依存の版を `1.18.0` にし、
  `package-lock.json` の版の行も同じにした。
- 既定のイメージの名前（`DEFAULT_IMAGE`）を `sacty-agent:1.18.0` にした。
  同じ版にしたもの：仕様書（`agent-execution`・`configuration`）とユーザードキュメント（`config`・`images`）の日英、イメージの名前を書いているテスト・コメント、ゲートウェイの MCP クライアントの版の文字列。
  直したファイルは、1.17.1 の版上げ（PR #308）と同じ範囲に、下の `Dockerfile` を足したもの。
- 元のイメージのダイジェスト：`docker buildx imagetools inspect node:26-bookworm-slim` の `Digest`（インデックス）が `sha256:add5c17c…` に変わっていたので、
  `packages/cli/docker/Dockerfile` の `BASE_IMAGE`・`NODE_IMAGE` を更新した。
  新旧のイメージの Node.js（v26.13.0）・npm（11.20.0）・Debian（12.15）は同じだった。
- エージェントの CLI の版（`packages/cli/docker/agent-cli`）は上げていない。

## 確かめたこと

- `npm ci`・`npm run lint`・`npm run typecheck`：通過（`npm ci` の後の `package-lock.json` の差分は版の行だけ）。
- `npx vitest run`（`tests/docs` を含む）：通過（件数は PR の本文に書く）。
- `git grep -F 1.17.1` で、ADR・作業履歴のほかに `1.17.1` が残っていないことを確かめた。
- 更新したダイジェストの `Dockerfile` から、既定のイメージをビルドできることを確かめた。中で `node`（v26.13.0）・`claude`・`codex` が動いた。
  `sacty image build` ではなく、空の secret を渡した `docker build` で確かめた。言語ごとのイメージ（`BASE_KIND=lang`）は確かめていない。
