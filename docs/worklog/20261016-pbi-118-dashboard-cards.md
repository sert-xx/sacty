# ダッシュボードに、人の出番・止まった理由・費用・取り込み・流量・品質・待ち行列の欄を足す

- 日付: 2026-10-16（UTC）
- タスク: PBI-118
- PR: #128
- ブランチ: feat/issue-118-dashboard-cards
- 関係する ADR: [ダッシュボードを工場の管制室にし、人の出番・工場の健康・お金・品質の欄の定義と集計の置き場所を決める](../adr/20261016-1308-dashboard-control-room-cards.md)

## 目的

ダッシュボード（PBI-114）を工場の管制室にする。「終わっていないタスク」だけだった欄に、あなたの出番・止まっているタスクの理由・
費用と予算・工程の待ち行列・取り込みの状況・流量・品質の信号の 7 つを足し、自分が判断すべきもの・止まっているもの・お金・工場の調子を
一目で見られるようにする。受け入れ条件の要点：欄の並びと中身・空のときの表示、リロードせずにデータだけを取り直す、集計のために
タスクの全件や作業履歴を3秒ごとに運ばない、数字の定義を仕様書に書いて画面は本文と補足で出す（PBI-117 の方針）、回帰テスト、docs、
動作確認の動画。

## したこと

- 集計（`packages/core/src/dashboard.ts`）：作業履歴のイベントを 1 つずつ畳み込んで持つ `DashboardStats` を core に置いた。持つのは、
  タスクごとの対応待ちになった最後の記録の時刻、費用を持つイベントの費用と時刻、タスクが終わった時刻（`isFinished` の偽→真）、
  品質の信号のイベント。32 日より古い記録は捨てる。期間の境はデーモンのマシンのローカルの日付（`localDayStart`）。消したプロジェクトの
  記録は数えない。`project` に、イベントを適用するごとに呼ぶ `applied` を足し、デーモンが起動のときの読み込みと `append` で畳み込む。
- デーモン：`service.dashboard()` と `GET /api/dashboard`。待ち行列の「続いている」の始まりはメモリーだけに持つ。設定を読めなければ上限は既定値。
- 画面：`loadDashboard` が既存の `GET /api/tasks?open=1`・`GET /api/status` に加えて `GET /api/dashboard` を取り、あなたの出番・止まっている
  理由・予算に近いタスクはタスクの状態から画面のサーバーで作る。`dashboard.tsx` に 7 つの欄を足し、並びを PBI のとおりにした。
  一覧の欄は 5 件分の高さでスクロール（`ScrollList`・`TaskRow` に共通化）。待っている時間は画面の時計（1 分ごと）で計算し、データに
  「今」を入れない。止まっている理由は `details` で欄の中で広げる。取り込みの状況は、プロジェクトの一覧の表示を `IntakeStatusView`・
  `IntakeRunNow` に切り出して両方で使う。
- 文言：本文は 1 文にし、仕組み・数字の定義・期間の境は補足（`hint`・`*Hint`）に書いた。補足の部品 `Hint`・`WithHint` は PBI-117 の
  ブランチと同じ内容を `components/ui/hint.tsx` に置いた（マージのときに同じ内容になる）。
- docs：仕様書（architecture の画面の構成・新しい「ダッシュボードの集計」の節・API の表・取り直しの表、event-log の投影）、利用者向けの
  新しいページ（`docs/user/dashboard.md`）と目次・はじめに、ADR、作業履歴。英語の版も同じ PR で直した。

## 確かめたこと

- 回帰テスト：

    概算と実請求の混在、費用を持つイベントの種類、消したプロジェクトのタスクを数えない、終わった→終わっていない→また終わった、
    対応待ちの時刻の起点（提出・一時停止・エスカレーションの最後の記録。実行中に戻ったタスクには返さない）、待ち行列の上限との比較と
    「続いている」の始まりの引き継ぎ、古い記録の破棄。

    対応待ちの時刻・費用・品質・流量の変化、再起動（作業履歴から読み直し）で同じ集計になること、消したプロジェクトと設定を読めないとき。
  - 画面（`dashboard-data.test.ts`・`dashboard.test.ts`）：データの形、あなたの出番の並びとリンク先、止まっている理由の並びと件数、
    予算に近いタスク、8 つの欄の並び、空のときの表示、補足の中身、待っている時間が時計で進むこと、止まっている理由を開いた状態が
    取り直しで消えないこと、費用の表と概算の行、待ち行列の 10 分の判定と設定へのリンク、取り込みの表示と「今すぐ取り込む」、流量・
    品質の表、英語、既存の「終わっていないタスク」のテスト。
- `npm run lint`（終了コード 0）・`npm run typecheck`・`npx vitest run`（88 ファイル・1840 テスト）・`npm run build`・
  `npx vitest run tests/docs`（89 テスト）が通った。
- 画面での確認：自分のブランチを、別のポート（4800/4810）と一時的な SACTY_HOME（スタブの AI。架空の 2 つのプロジェクトと、
  作業履歴に直接書いた 14 件のタスク：承認待ち・エスカレーション・利用上限／認証／予算で一時停止・完了・中止）で起動して、動画に
  撮った（PR とは別に共有する。`pbi-118-dashboard.mp4`、約 70 秒）：8 つの欄が出る → 費用の欄の補足（期間の境とタイムゾーン）→
  止まっている理由の利用上限と認証を開く → 下の欄（待ち行列・取り込み・流量・品質）と品質の補足 →「今すぐ取り込む」→ あなたの出番の
  先頭から承認の画面へ移って戻る → 英語・ライトのテーマで同じ画面 → スマホの幅（390px）で縦に積まれる。
- 動画を撮る途中で、スマホの幅で流量の表の見出し（完了・中止・直近7日）が1文字ずつ折れていたので、数字の列と行見出しを折り返さず、
  「作成から完了まで」の見出しだけ折り返すようにした。
- 作業履歴に直接書いた実行待ちのタスクは、デモのデーモンがスタブで実行しようとして「エラーで一時停止」になった（コンテナの実行の
  失敗。デモの環境の都合で、この PBI の対象ではない）。止まっている理由の欄に「エラー 3件」として出ている。

## レビューの指摘と対応（PR #128、sert-xx の DA レビュー）

| 指摘 | 対応 |
| --- | --- |
| 【要修正】PR 経由の差し戻しを二重に数えている（`ReworkJudged` と、その後の `ChangesRequested` の両方） | 実際に差し戻した記録 `ChangesRequested` を 1 回として数え、投影の `prRework.at` がその記録の時刻なら「PR の指摘の差し戻し」、ほかは「人の差し戻し」に分けた。`ReworkJudged` は数えない（判断だけで上限のエスカレーションになったものは数えない）。工程別も 1 回だけ増える |
| 【要修正】待ち行列の件数がワーカーの実行状態と合わない（テスト実行中の idle が実行中に入らない） | 実行中はワーカーが処理しているタスク（`inflight`）、実行待ちは `queuedTaskIds()`（ワーカーと同じ判定）のうち未処理のものにした。集計（core）は ID の集合を受け取って数える |
| 【要修正】混雑の開始と解消が画面の取得（`dashboard()`）だけで更新される | `trackQueue()` を、作業履歴に書くたび・実行の開始と終わり・設定とプロジェクトの保存・起動時に呼び、`queueOverSince`（core の純粋関数）で始まりを更新する。画面を開いていない間の解消と再発、初回取得前の混雑を追う。デーモンのテストで、作成・中止・設定の変更の時刻で確かめた |
| 【要修正】設定を読めない（intake=null）ときに設定へのリンクが無い | 止まっている文に sacty の設定へのリンクを添えた（プロジェクトの一覧の表示にも同じ部品で反映） |
| 【提案】古い記録の破棄が画面の閲覧に依存 | 畳み込み（`add`）の中で、記録の時刻で 1 日に 1 回捨てるようにした（起動時の読み込みでも増え続けない）。集計時の破棄も残す |
| 【提案】展開した停止理由の一覧の高さ | ほかの一覧と同じく 5 件分（20rem）でスクロールし、フォーカスを受けるようにした。取り直しで開閉とスクロールの位置が残ることをテストで確かめた |
| 【提案】暦日の境界を固定 24 時間の減算で作っている（TZ=Australia/Sydney で失敗） | 境界は `localDayStart` の暦日から作り（`day(n)`）、経過時間の検査は 24 時間の単位で別に作った。既定の TZ と Australia/Sydney の両方で通る |
| 【提案】接続失敗時の説明を初回と更新中で分ける | ユーザードキュメント（日英）と仕様書（日英）を、描いたときに届かないときは欄の代わりにエラー、一度出した後は最後の内容を残して更新できないことを出す、に直した |
