## 目的

タスクの作成の画面で、進め方を選んだら、その工程ごとのイメージとエージェントを設定できるようにする。
今のダイアログにそのまま足すと入力が多くなるので、ふだんの作成を妨げない画面の形を検討して決める。

## したこと

- コア：`CreateTaskInput`・`TaskCreated` に `images`・`agents`（`StepSettingMap`）を足した。投影は `requestedImages`・`requestedAgents` を持ち、
  エージェントは作成時から `agents` に、イメージは `StepsChosen` で選んだ工程の分だけ `images` に入れる。工程の選択からやり直したら、作成時の指定に戻す。
- デーモン：作成の入力を確かめる `requestedStepSettings`（進め方が無い・進め方に無い工程・統合レビューのエージェント・無い名前・設定を読めない）。
  `withImages` で指定した工程をオーケストレーター・プロジェクトの対象の決定から除き、すべての工程を指定したらイメージの候補を見せない。
- 画面：
  - 作成のダイアログを、基本の入力と「工程ごとの設定」の2つの画面にした（`task-step-settings.tsx`）。基本の入力には工程の並びと指定の要約・
    指定した工程の印・「工程ごとに設定」だけを置く。ダイアログの幅を `max-w-lg` から `max-w-xl` に広げた。
  - 候補は「工程ごとに設定」を開いたときに `GET /step-options` から読む（`lib/step-options.ts`）。
  - タスクの詳細の「工程のイメージ」「工程のエージェント」の選んだ元に「作成時に人が指定」、作業履歴の「タスクを作成」の行に指定を出す。
- 画面の検討：最初は工程ごとのカード（見出し・選択肢・説明を工程ごとに出す）で作り、スクリーンショットで確かめたところ、4工程でもスクロールが要り、
  エージェントの選択肢（名前・モデル・エフォート）が等幅のフォントで切れた。工程を行・イメージとエージェントを列にした表に直し、列の見出しは1回、
  説明（イメージの説明・モデルとエフォート）は選んだ項目にだけ出すようにした。
- スクリーンショット：撮るときの設定に架空の言語イメージ（`java17`・`playwright`）を足し、`new-task-steps` を撮った。`new-task` も幅が変わったので撮り直した。
- ドキュメント：仕様書（工程とタスク）・ユーザードキュメント（タスク）を日英で直し、ADR を足した。

## 確かめたこと

- `npm run lint`・`npm run typecheck`：通った。
- `npm test`：今回足した・直したテストを含めて通った。8件（`agent-sessions`・`context-mcp`・`host-mcp-processes`・`question-form.browser`）が落ちたが、
  変更を外した状態（`git stash`）でも同じく落ちるので、この環境（root で動かす・プロセス・ブラウザーの版）の都合で、今回の変更とは関係ない。
- `npx vitest run tests/docs`：通った。
- `npm run build` の後、スクリーンショットの仕組み（架空のデータ）で、日英それぞれ、工程ごとの設定・設定後の基本の入力・分割の進め方
  （統合レビューのエージェントを選ばせない）を撮って確かめた。この環境の Playwright のブラウザーの版がリポジトリの指定と違うので、ブラウザーの場所を
  指定した一時的な写しで撮った（写しは残していない）。

## 残したこと

- スケジュールタスクの作成・編集での工程ごとの設定（スケジュールタスクの内容の形を変えるため）。
- 狭い画面（幅 390px）では、工程名を上の行に、イメージとエージェントを2列に並べる。撮って確かめたところ、既定のエージェントの名前
  （「既定：codex_standard」）の末尾が選択肢の幅で切れる（開けば全部見える）。気になるようなら、文言を短くするか、名前を下に出す。
