# 既定のコンテキストに、読みやすく簡潔な文章を書くためのスキルを足す

- 日付: 2026-10-15（UTC）
- タスク: PBI-102
- PR: #112
- ブランチ: feat/issue-102-writing-skill
- 関係する ADR: [既定のコンテキストに文章を書くためのスキルを同梱し、「。」の後の改行は日本語だけにする](../adr/20261015-0844-default-writing-skill.md)

## 目的

エージェントが書く PR の本文・レビューのコメント・報告などが AI の文章とすぐにわかり、読みにくい。
人が書いたように読みやすく簡潔な文章にするため、既定のスキルに書き方の決まりを足す。
「。」の後の改行、改行と段落の使い分け、2〜3 階層の箇条書きと表、簡潔さを、ステークホルダーの要望として優先する。

## したこと

- `apps/daemon/default-context/skills/writing/` を足した。
  - `SKILL.md`：従う順（依頼した人、リポジトリの決まり、このスキル）、決まりの要点、書く手順、見直し、英語の文章の扱い
  - `references/layout.md`：「。」の後の改行、段落、箇条書きの階層、表、地の文、改行で表示が崩れる所
  - `references/sentences.md`：簡潔さ、行為者の主語、比喩の動詞、名詞の連続、否定の対比、装飾、文末のコロン、絵文字
  - 決まりごとに、悪い例と直した例を付けた。
    例は特定の言語・分野に寄らない題材（設定ファイル、ログイン、一覧の画面など）にした。
  - 参考の記事とリポジトリの文章・コードは写していない。
    例はすべて新しく書いた。
- 読み込みの費用を抑えるため、SKILL.md には要点と見直しだけを置き、例は references に分けた。
- 既定の `git`（SKILL.md、PR レビュー投稿、返信、ローカルコミット）と `review-dispatch`・`review-execution`（自己レビュー、PR レビュー、出力の形式）の文章を書く所から、`writing` を参照するようにした。
- 既定のスキルの一覧を確かめるテスト（`apps/daemon/src/context-template.test.ts`）の期待値に `writing` を足した。
- 仕様書（`docs/spec/context.md`）とユーザードキュメント（`docs/user/context.md`）に既定の文章用スキルを書き、英語の版も直した。
- 「。」の後の改行を日本語だけにしたこと、機械的な検査を付けないことを ADR に書いた。

- `npm run build`：終了コード 0
- `npx vitest run`：65 ファイル・1487 件通過
- `npx vitest run tests/docs`：通過
- スキル自身の文章を、コードブロック・かぎ括弧・インラインコードの外で「。」の後に文字が続く行、コロンで終わる行が無いかをスクリプトで調べた。
  該当は front matter の `description`（1行だけの欄）だけだった。
- スキルの中に、特定の製品・言語に寄った語（sacty・Node.js・npm・TypeScript など）が無いことを `grep` で確かめた。
- この PR の本文で、スキルを使う前と後の文章を比べた。
  比べた結果は PR に載せた。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| 仕様書の「関係する ADR」を節の中に置いていて、ページの先頭にまとめる書き方と違った | ページの先頭の行に移した |
| 装飾の決まりに、悪い例と直した例が無かった | `references/sentences.md` に例を足した |
| PR の比較の表に、使う前の下書きに無い「文末のコロン」の行があった | 行を消した |

## 残したこと

- 文章のリンターのような機械的な検査は付けていない（ADR の理由のとおり）。
