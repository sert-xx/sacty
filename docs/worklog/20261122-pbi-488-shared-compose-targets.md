# 共用 compose を対象リポジトリにひもづける

- 日付: 2026-11-22（UTC）
- タスク: PBI-488
- PR: #590
- ブランチ: main
- 関係する ADR: [共用 compose を対象リポジトリにひもづける](../adr/20261122-1700-shared-compose-targets.md)

## 目的

共用 compose を使うリポジトリを明確にし、対象の compose と一緒に利用できるようにする。

## したこと

プロジェクトの設定と画面にひもづけ先を追加し、候補をリポジトリで絞る。
複数の compose を共通のネットワークで起動し、名前の衝突を検査する。

## レビューの指摘と対応

### 設計のレビュー

切り戻しの復旧手順、名前の衝突、単一ネットワークと Org のひもづけを設計に含めた。

### この PR の実装レビュー 1 回目

| 指摘 | 対応 |
| --- | --- |
| 複数 compose のサービス選択 | 名前を各 compose に割り当てる |
| ネットワーク操作と取得の停止 | 作成の中断と操作の期限、取得の中断に対応する |
| ネットワーク作成失敗の詳細 | 秘密情報を伏せて原因を表示する |
| PR 番号の不足 | 番号を記入する |

### この PR の実装レビュー 2 回目

| 指摘 | 対応 |
| --- | --- |
| 取得待ちの中断とプロセス終了 | 待機を中断できるようにし、Git と展開の終了を待つ |
| 作成失敗の詳細のテスト | 原因が残り秘密が伏せられることを確かめる |
| 失敗詳細の表示言語 | 対応しないと判断した |

### この PR の実装レビュー 3 回目

| 指摘 | 対応 |
| --- | --- |
| 複数 compose の停止が応答しない | 各停止に期限を付け、失敗を記録して残りの回収を続ける |
| 回ごとの履歴と後続の判断 | 回ごとに整理し、異常終了後の回収の決定を反映する |

### この PR の実装レビュー 4 回目

| 指摘 | 対応 |
| --- | --- |
| 回収失敗の種類が分からない | 対象名と失敗の種類、終了コードを秘密情報を含めずに記録する |

### この PR の実装レビュー 5 回目

| 指摘 | 対応 |
| --- | --- |
| 複数 compose のレビューでの復元 | 取得元とコミットを記録し、同じ実行の空でない全記録から復元する |
| ネットワークモードを指定したサービスへの接続 | 範囲外とし、接続できない場合があることを日英の文書に記載する |
| PBI-489 の過去の作業履歴 | main の内容に戻す |

## 残したこと

デーモンの異常終了後に残る共通ネットワークの回収は、後続に回す。
ネットワーク作成の時間切れ後の回収も、遅延した作成との競合を防ぐ再試行や状態管理が必要なため、後続に回すか人が判断する。
