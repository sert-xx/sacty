# 共用 compose を対象リポジトリにひもづける

- 日付: 2026-11-22（UTC）
- タスク: PBI-488
- PR: #590
- ブランチ: main
- 関係する ADR: [共用 compose を対象リポジトリにひもづける](../adr/20261122-1700-shared-compose-targets.md)

## 目的

共用 compose を使うリポジトリを明確にし、対象の compose と一緒に利用できるようにする。

## したこと

プロジェクトの設定と画面にひもづけ先を追加し、候補をリポジトリで絞る。
複数の compose を共通のネットワークで起動し、名前の衝突を検査する。

## 確かめたこと

| コマンド・確認 | 結果 |
| --- | --- |
| `npm run lint` | 成功 |
| `npm run typecheck` | 成功 |
| `npx vitest run --no-file-parallelism` | 346 ファイル、7,111 件成功、14 件スキップ。Git の機能に対応しないテスト 13 件と、明示的に有効にした場合だけ動く AI 評価 1 件をスキップ |
| `npm run build` | 成功 |
| ビルドしたデーモンのローカル API | プロジェクトの保存は 201、エクスポートは 200。ひもづけが残ることを確認 |

Docker が無いため、実機での取得・起動・接続は実行していない。
ブラウザーが無いため、画面操作の録画とスクリーンショットの撮り直しは実行していない。

## レビューの指摘と対応

### 設計のレビュー

切り戻しの復旧手順、名前の衝突、単一ネットワークと Org のひもづけを設計に含めた。

### 実装のレビュー

サービス名を各 compose に割り当て、取得とネットワークの作成を停止できるようにした。
ネットワーク操作に期限を付け、作成失敗の詳細を秘密情報を伏せて表示する。

## 残したこと

デーモンの異常終了後に共通ネットワークを回収する提案は、所有情報の保存が必要なため、後続に回すか人が判断する。

Docker のある環境で次をマージ前に確かめる。

1. 対象リポジトリにテスト用の compose を置き、別のリポジトリに Redis などの共用 compose を置く。
2. プロジェクトの共用 compose に取得元とファイルを設定し、使うリポジトリに対象の URL を入力して保存する。設定を開き直して URL が残ることを確かめ、操作の動画を残す。
3. 両方のサービスを使う実装タスクを実行し、作業履歴で共用 compose の選択と取得したコミット、各サービスの起動を確かめる。
4. 担当のコンテナからそれぞれのサービス名とポートで接続し、両方から応答が返ることを確かめる。
