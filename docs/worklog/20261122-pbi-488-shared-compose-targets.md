## 目的

共用 compose を使うリポジトリを明確にし、対象の compose と一緒に利用できるようにする。

## したこと

プロジェクトの設定と画面にひもづけ先を追加し、候補をリポジトリで絞る。
複数の compose を共通のネットワークで起動し、名前の衝突を検査する。

## 残したこと

Docker のある環境で次をマージ前に確かめる。

1. 対象リポジトリにテスト用の compose を置き、別のリポジトリに Redis などの共用 compose を置く。
2. プロジェクトの共用 compose に取得元とファイルを設定し、使うリポジトリに対象の URL を入力して保存する。設定を開き直して URL が残ることを確かめ、操作の動画を残す。
3. 両方のサービスを使う実装タスクを実行し、作業履歴で共用 compose の選択と取得したコミット、各サービスの起動を確かめる。
4. 担当のコンテナからそれぞれのサービス名とポートで接続し、両方から応答が返ることを確かめる。
