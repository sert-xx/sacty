# PR のレビューの子タスクを、タスク一覧で親の下に子タスクとして並べる

- 日付: 2026-11-13（UTC）
- タスク: PBI-341
- PR: #365
- ブランチ: feat/issue-341-review-tasks-under-parent
- 関係する ADR: なし（PBI-330 で決めた「レビューを PR を作ったタスクの子タスクとして回す」の画面の不足を直す）

## 目的

PR のレビューの子タスク（`reviewOf`）が、タスク一覧で親から離れて独立したタスクと同じ位置に出ていて、どのタスクのレビューかを題から
推し量るしかなかった。タスク分割の子タスクと同じく、親のすぐ下に子として並べる。

## したこと

- 画面：タスク一覧の並び（`withSubtasks`）で、レビューの子タスクを、レビューする PR を作ったタスクのすぐ下に、分割の子の後に作った順で
  並べた。分割の子タスクのレビューの子は、その分割の子の下に、もう一段字下げする（行に字下げの段 `depth` を足した）。親が一覧に無い
  ものは、そのままの位置に出す。分割の子の数・費用の合計（`subtaskSummary`）には入れない。
- docs：仕様書（画面の構成）・ユーザードキュメント（タスクの一覧）を日英で直した。

## 確かめたこと

- `npm run lint`・`npm run typecheck`：エラーなし。
- `npx vitest run --no-file-parallelism`：全体が通った。
- 新しいテスト：
  - レビューの子は親のすぐ下に、分割の子の後に並び、分割の子のレビューはもう一段下に並ぶ。親が一覧に無いレビューの子はそのままの位置。
    修正を戻すと落ちることを確かめた。
  - レビューの子は、分割の子の数・費用の合計に入らない。
  - 一覧で、分割の子は1段、分割の子のレビューの子は2段字下げして描く。

## レビューの指摘と対応（1回目）

判定は「提案あり（マージは可）」。提案4件にすべて対応した。

- 絞り込みで親が隠れると、子の字下げが無関係な上の行の子に見える：字下げを、絞り込んだ後の行で決め直すようにした（`indentShown`）。
  行に一覧の親の ID（`parentId`）を足し、表示した行に親があるときだけ字下げする。親が別のプロジェクトにある子も字下げしない。
- 字下げと「↳」（`aria-hidden`）だけでは、読み上げで親子の関係が分からない：字下げした行に、親の題を書いた読み上げ用の文（`sr-only`）を
  添えた（日英の文言を足した）。
- 親が別のプロジェクトにある・絞り込みで隠れたときの見え方がユーザードキュメントに無い：日英のタスクの一覧の節に足した。仕様書も日英で直した。
- コメントの「作った順（一覧の順）」が実装と食い違う：作った日時の昇順と書き直した。

確かめたこと：

- `npm run lint`・`npm run typecheck`：エラーなし。
- `npx vitest run --no-file-parallelism apps/web tests/docs`：95 ファイル・818 件が通った。
- 新しいテスト（`task-rows.test.ts`）：表示した親の下だけ字下げして親の題を添える／親が隠れた子は字下げしない／親が別のプロジェクトの子は
  字下げしない。決め直しを戻す（`depth` をそのまま使う）と2件が落ちることを確かめた。
- 一覧の描画のテスト：読み上げ用の文が親の題を書くこと、親の無い子は字下げも「↳」も読み上げ用の文も出ないこと。
