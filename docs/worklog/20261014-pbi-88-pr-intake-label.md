# sacty が作る PR に取り込むラベルを付け、別のタスクでレビューさせて、その指摘を元のタスクに届ける

- 日付: 2026-10-14（UTC）
- タスク: PBI-88
- PR: #96
- ブランチ: feat/issue-88-pr-intake-label
- 関係する ADR: [sacty が作る PR に取り込むラベルを付け、別のタスクのレビューを元のタスクの PR の指摘として取り込む](../adr/20261014-1445-superseded-label-sacty-pull-requests-for-review.md)

## 目的

sacty が作った PR を、作ったタスクとは別のコンテキストのタスクで敵対的にレビューさせる。そのために、sacty が作る PR すべて
（実装の PR と、要求要件・設計の PR）に取り込むラベル（`intakeLabel`）を付け、次の取り込みでレビューだけのタスクにし、そのレビューを
元のタスクに PR の指摘として届ける。レビューと修正が繰り返し続かないこと、人が外したラベルを付け直さないことも求められた。
当初は実装の PR だけが対象だったが、途中で要求要件・設計の PR も対象に広がった（ステークホルダー）。

## したこと

- PR にラベルを付ける口（`PullRequests.addLabel`）を足した。リポジトリのラベルを読み、404 なら作ってから PR に付ける。作っている間に
  ほかで作られた（422 の `already_exists`）ときはそのまま付ける。失敗は `github.failed`（`getLabel`・`createLabel`・`addLabel`）にする。
- PR を作った直後（`publish`・`publishStepPullRequest`）に `labelPullRequest` で付け、`PullRequestLabeled`・`PullRequestLabelFailed` を
  台帳に残す（失敗の文は使った秘密の値を伏せる）。付けられなくても PR の作成は失敗にしない。取り込むラベルが無い・PR のトリアージが
  Off なら付けない。1つの PR に1回だけ（記録のある PR は、更新しても付け直さない）。projection に `pullRequestLabels` を足した。
- 取り込み（`importIssues`）で、取り込むラベルの付いた PR が sacty の作った PR なら、レビューだけのタスク（`source.review: sacty`）に
  する（オーケストレーターに選ばせない）。レビュー用のラベル・依頼より優先する。リポジトリの URL は書き方の揺れをそろえて比べる。
- PR の指摘の取り込み（`importFeedback`）で、同じ PR の `source.review: sacty` のタスクが投稿したレビュー・行へのコメントを指摘に
  含める（`feedback` の `sactyReviewTasks`。目印のタスク ID が一致するものだけ。再レビューの回の番号つきも。後のレビューの対応で、回とアカウントごとの `sactyReviews` に変えた）。
- 画面：作業履歴に、ラベルを付けた・付けられなかった行を出す。「sacty の設定」の取り込むラベルの説明に、sacty が作る PR にも付けることを
  書いた。
- 決めたこと（Dev の判断）は ADR に書いた。PBI-19 の ADR の「sacty のレビューを PR の指摘から除く」部分を置き換えたので、その ADR を
  `superseded` にした。
- 仕様書（承認と差し戻し・取り込み・タスクと工程）とユーザードキュメント（取り込み・タスク）を直した。

## 確かめたこと

- `npm run lint`（終了コード 0）、`npm run typecheck`、`npx vitest run`、`npm run build`、`npx vitest run tests/docs`。
- テストで確かめたこと：要求要件・設計・実装の PR すべてにラベルを付ける。作り直した PR（新しい番号）には付け、同じ PR の更新では付け直さない。
  設定が無い・PR のトリアージが Off なら付けない。失敗しても承認待ちに進み、理由が残り、トークンが台帳に出ない。ラベルを付けた PR が
  別のレビューだけのタスクになり、レビューを投稿し、元のタスクの指摘の取り込みにそのタスクが渡され、指摘が取り込まれて差し戻しになり、
  同じ PR を更新してもラベルを付け直さず、二度目の取り込みでタスクを作らない。sacty が作っていない PR はこれまでどおり。
  取り込むラベルとレビュー用のラベルが同じでも `sacty` になる。GitHub の口は、ラベルの有無・作成の競合・失敗の種類・指摘の絞り込みを確かめた。
- 修正を1つずつ戻すと、対応するテストが落ちることを確かめた（sacty の PR をレビューだけにしない・レビューのタスクを渡さない・1回だけの判定・
  triageOff・秘密を伏せる・指摘の絞り込み・ラベルの作成・工程の PR への付与）。
- 画面：一時的な SACTY_HOME とポート 4800/4810、偽の gh/docker で起動し、台帳に記録を入れて、作業履歴の行と設定の説明を確かめた（動画あり）。
- 確かめていないこと：本物の GitHub でのラベルの作成・付与と、取り込みからレビューの投稿・指摘の取り込みまでの通しの動き（偽の GitHub で確かめた）。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| 直すべき指摘の無いレビューでも元のタスクに取り込むと、sacty の PR はすべてレビューのタスクになるので、毎回むだな差し戻しと費用が発生する（PO） | レビューのエージェントに、直すべき指摘があるかの評価（`sacty-review-verdict` の `changesRequested`）を付けさせ、`AgentRunCompleted` に残して、回ごとの評価（`reviewVerdicts`）にした。行についての指摘があれば評価に関わらず「あり」。元のタスクの指摘の取り込みには、「あり」か評価を読めなかった回の目印（`<タスク ID>[:<回>]`）だけを渡す。「なし」の回は取り込まず、ゴールガーディアンも動かさない。再レビューは回ごとに判定する。評価のブロックは投稿する本文から取り除く。ADR・仕様書・ユーザードキュメントを直した |
| プロジェクトのアカウントが Bot（GitHub App など）だと、許可したレビューのタスクの投稿も Bot の判定で除かれ、元のタスクに届かない（PR #96 のレビュー、`github.ts`） | 許可したレビューのタスクの目印で始まり、プロジェクトのアカウントが投稿したものは、Bot の判定より先に通すようにした。ほかの Bot の投稿・ほかの Bot が目印を写したものは、これまでどおり除く。回帰テストを足した |
| PR の公開を記録した後、ラベルを付ける前に止まると、再起動しても公開の工程をやり直さないので、その PR はラベルが無いままになる（PR #96 のレビュー、`service.ts`） | 付ける予定を公開の記録（`PullRequestPublished`・`StepPullRequestPublished` の `intakeLabel`）に残し、PR の確認（60秒ごと。再起動の後も）で、予定があり記録の無い開いている PR に付ける（`resumePullRequestLabels`）。いまは付けない設定・中止したタスクなら付けない。付けている途中の PR には重ねて付けない。要求要件の PR と実装の PR で、途中で止めて起動し直すテストを足した |
| 元のタスクとレビューのタスクでアカウントが違う（レビューのタスクが、より具体的なプロジェクトに割り当てられた）と、許可の判定が常に外れる。Bot なら指摘ありの回も除かれ、User なら指摘なしの回まで人の指摘として取り込む（PR #96 の再レビュー、`github.ts`） | `feedback` に、この PR をレビューした sacty のタスクの回ごとに、目印の中身・そのタスクのアカウント・許可するか（`sactyReviews`）を渡すようにした。そのアカウントの投稿は、Bot の判定より先に回で判定し、許可した回だけを取り込み、ほかの回は除く。PR を指すほかのレビューのタスクの投稿も、アカウントが違っても除く。アカウントが違う×Bot・User×許可した回・しない回の回帰テストと、プロジェクトを分けて通しで確かめるテストを足した |

### 指摘への対応で確かめたこと

- 回帰テスト：指摘なし → 取り込まず承認待ちのまま・ゴールガーディアンを実行しない（人の指摘はこれまでどおり取り込む）。評価なし → 取り込む。
  指摘あり → 取り込んで差し戻す。再レビューで1回目なし・2回目ありなら、2回目だけを取り込む。評価の抽出（最後のブロック・真偽値でない・
  行の指摘で「あり」・同じブロックに両方）。
- 修正を1つずつ戻すと落ちることを確かめた（指摘なしでも取り込む・評価を読まない・行の指摘で「あり」にしない・評価を記録しない・回を区別しない・
  目印の回を読まない）。
- Bot：`sacty[bot]` のアカウントで、許可したタスクの目印のレビュー・行へのコメントは取り込み、ほかのタスクの目印・CI の Bot・ほかの Bot の写しは
  除くことを確かめた。判定の順を戻すと落ちる。
- 再開：ラベルを付ける途中で止め（偽の GitHub の応答を返さない）、同じ台帳で起動し直して PR の確認を行うと、要求要件の PR・実装の PR に付けて
  記録する。いまは付けない設定なら付けない。次の確認・付けている途中の確認では重ねて付けない。修正を戻すと落ちる（再開で付けない・
  予定を残さない（工程の PR・実装の PR）・付けている途中を見ない）。
- アカウントが違う場合：元のタスクのアカウントで判定する・許可しない回を除かない・Bot の判定を先にする・レビューのタスクのアカウントを渡さない・
  評価を見ずに許可する、のそれぞれに戻すと落ちることを確かめた。同じアカウントを前提にしたところを探し、レビューの投稿済みの確認（`findReview`）は
  レビューのタスク自身のアカウントで行っていて問題が無いことを確かめた。
- `npm run lint`（終了コード 0）・`npm run typecheck`・`npx vitest run`・`npm run build`・`npx vitest run tests/docs`。

## 残したこと

- レビューのエージェントの評価が誤っている（本文に直すべき指摘を書いたのに false）と、その指摘は元のタスクに届かない（PR には投稿されている）。
