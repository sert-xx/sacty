# 差分が文書だけなら、ツールがイメージに無くても止めずに人の確認へ回し、ツールが無くて止まったタスクは再開でテストの扱いを決め直せるようにする

- 日付: 2026-10-31（UTC）
- タスク: PBI-158
- PR: #258
- ブランチ: feat/issue-158-docs-only-missing-tools
- 関係する ADR: [差分が文書のファイルだけなら、ツールがイメージに無くても止めずに人の確認へ回し、ツールが無くて止まったタスクは再開でテストの扱いを決め直せる](../adr/20261031-1510-docs-only-missing-tools-to-human-checks.md)

## 目的

実務での実証実験（Go の大きなリポジトリに Markdown のドキュメントを書き起こす依頼）で、変更が Markdown だけなのに、イメージに無いツール（go・golangci-lint）の検証のせいで最終レビューで止まった（`verify.commandMissing`）。
ゴールガーディアンは、観点の判定・環境による失敗の申告・人が確かめることまで出していて、止めずに通せば合格になる出力だった。
考察の改善案のうち、案A（A-2：sacty が差分の拡張子で機械的に判断する）と案D（止まった後に、再開で人がテストの扱いを決め直せる）を入れる。案B・C・E は範囲外。

- 差分が文書のファイルだけで、ツールが無くて検証を実行できなかったときは、止めずに判定を記録し、実行できなかった検証を最終承認の「人が確かめること」に回す。
- 差分にコードなど文書でないファイルが1つでもあれば、これまでどおり止める。
- `verify.commandMissing` で止まったタスクも、再開のときにテストのコマンドを指定し直すか、テストなしで進めると決められる。

## したこと

- 文書だけの差分の判定：`isDocumentsOnly`（`apps/daemon/src/test-files.ts`）。文書の拡張子は、テストのファイルを探すときに文書として除く一覧から `txt`（requirements.txt・CMakeLists.txt など、依存やビルドの定義にも使われる）を外したもの（`md`・`markdown`・`rst`・`adoc`・`asciidoc`・`org`）。探索用の一覧は変えていない。差分が空のときは false。
  差分のパスは `diffStats`（名前の変更を変更元と変更先に分ける）から取る。コードを文書の名前に変えても文書だけにならない。取れなければ止める側に倒す（`changesOnlyDocuments`）。
- 最終レビューの読み取り（`extractFinalReview`）に `documentsOnly` を足した。申告されたツール不足があるときだけ、`missingCommands` を空にして止めず、`tests.missingCommands` に記録し、実行できなかった検証を `humanChecks` に1項目足す（`missingToolsCheck`）。
  `guardianTestsPassed` は、`tests.missingCommands` があれば通ったものとする。`GuardianTests` に省略可の `missingCommands` を足した（それより前の記録はそのまま読める）。
- `verify`（`apps/daemon/src/service.ts`）：ツール不足の申告があるときだけ差分を調べ、文書だけなら上の記録をして先へ進む。文書だけでなければ、これまでの一時停止（`verify.commandMissing`）。
- 画面・PR の本文：テストの行に「一部を実行できず」、実装の成果物に「<ツール> が無く実行できず」を出す。やり直しの指示には、直す対象ではないと添える。ゴールガーディアンの指示に「ツールが無くても、実行できる検証と判定は最後まで行う」を1行足した。
- 案D：`testToolsMissing`（一時停止の理由が `verify.commandMissing`・`testCommand` がある・`noTestsReason` が無い）を足し、`canDecideTests` に含めた。`canRechooseSteps` には当てない（止まった所から最終レビューをやり直す）。
  テストなしにしたとき、止まる前の `testCommand` を消す（残すと同じコマンドをまた実行して止まる）。
  再開の欄は、既存の「テストの扱い」の仕組みをそのまま使う（API は `ResumeTaskInput` の `tests`、画面は `ResumeForm`）。ツールが無くて止まったときは、テストのコマンドの入力欄にいまのコマンドを初期値で出す。
  止まったときの文言（日英）に、再開のときにテストの扱いを決め直せることを添えた。`resume.testsNotUndecided` の文言も合わせた。
- 仕様書（`docs/spec/tasks-and-steps.md`・`.en.md`）と、ユーザードキュメント（`docs/user/tasks.md`・`.en.md`・`images.md`・`.en.md`）を直した。ADR を新しく足した（既存の ADR は書き換えていない）。

## 確かめたこと

作業は、リポジトリの外の worktree（`sacty-wt-s2-docs-only`）で、Node.js 26.12.1 を使って行った。

- `npm run lint`：通った。
- `npm run typecheck`：通った。
- `npm run build`：通った。
- `npx vitest run tests/docs`：93 件通った（英語の版との突き合わせを含む）。
- `npx vitest run`（全体）：3106 件通った。失敗は2件と1スイートで、どちらも main でも同じように失敗する、この PC の環境による失敗（Playwright の Chromium が入っていない `question-form.browser.test.ts`、`install-security-tools.test.ts`）。
- 境界を確かめるテスト（`daemon.test.ts`・`prompts.test.ts`・`test-files.test.ts`・`projection.test.ts`・web）：
  - 文書だけ（`README.md`・`docs/guide.md`）：止まらずに実装の承認待ちへ進み、`tests.missingCommands` と `humanChecks` に出る。PR の本文の「人が確かめること」にも出る。
  - コードだけ・文書とコードが混ざる・コードを文書の名前に変えた・文書と画像が混ざる・差分が空・ファイルごとの変更を取れない：いずれも、これまでどおり `verify.commandMissing` で止まり、判定を記録しない。
  - 文書だけでも、ツールが無いという申告が無い失敗（終了コード 1）は不合格のまま。観点が未検証でも不合格のまま（ツール不足で合格にしない）。
  - 案D：ツールが無くて止まったタスクで、テストなしで進めると決めて再開すると、同じコマンドを実行せずに最終レビューが通る。テストのコマンドを指定し直して再開すると、そのコマンドを実行させる。止まったのではないタスクは今までどおり受け付けない。
- 修正を戻すと失敗することも確かめた：①文書だけの分岐を無効にする → 文書だけのテストが落ちる。②常に文書だけとする → コード・混在などの5件と、再開のテストが落ちる。③`canDecideTests` を元に戻す → 再開のテスト（core・daemon）が落ちる。④テストなしにしたとき `testCommand` を消さない → 2件が落ちる。⑤差分が空のとき false にしない → 2件が落ちる。

## レビューの指摘と対応

自分で悪魔の代弁者（DA）として確かめた。

| 指摘 | 対応 |
| --- | --- |
| 終了コードが 127 のときだけ通す案は、`make` 経由（終了コード 2）などで外れて、文書だけなのに実装のやり直しを繰り返す | 終了コードでは見ず、ツール不足の申告がある文書だけの差分は通ったものとした。代わりに、他の失敗が隠れうる点を ADR の影響に書き、実行できなかった検証を人が確かめる項目で補う |
| 名前の変更でコードを `.md` に変えると、文書だけと見なされる | 差分は名前の変更を分けて見るので、変更元のコードが入り、止まる（テストあり） |
| 差分が空・差分を取れないとき、文書だけと見なされて通る | どちらも止める側に倒した（テストあり） |
| テストなしにしても、止まる前の `testCommand` が残り、同じコマンドでまた止まる | 投影で `testCommand` を消した（テストあり） |
| 実装のやり直しの指示に「終了コード 127」だけが載り、直す対象に見える | 直す対象ではないと添えた（テストあり） |

### DA のレビュー後の修正

| 指摘 | 対応 |
| --- | --- |
| 文書だけの差分でツール不足の申告があると、ほかの本物の失敗まで「通った」になり、人の確認の項目にも書かれない | 項目に、終了コードと出力の末尾（`redactLog` で秘密情報を伏せてから 300 文字に切り詰める）と、ツール不足のほかの失敗が混ざっていないか確かめる旨を足した。ゴールガーディアンが `tests.otherFailures` に申告した失敗があるときは、通ったものにせず、ふつうの判定にする（申告に頼る限界と、`&&` の途中で止まった後ろの失敗を見逃しうることは ADR の影響に書いた）。伏せる前に切り詰めると値が残る境界のテストと、`otherFailures` を無視すると落ちるテストを付けた |
| 文書の拡張子の一覧が広すぎる（`.txt` は requirements.txt・CMakeLists.txt などを含む） | 差分の判定用から `txt` を外した（探索用の一覧は変えない）。`.md` がコードに埋め込まれる場合など、残る穴を ADR の影響に書いた |
| 20261021-1431 の扱いが ADR の規則に合っていない | 一部を置き換える ADR として `superseded` を付け（ファイル名・ステータス）、置き換え先に、置き換えた部分を1行で書いた。新しい ADR の置き換え元に、そのリンクを書き、名前の変更で切れたリンク（ADR・仕様書・作業履歴）を直した |
| 出力が末尾 300 文字だけで、`a ; b` や `make docs && go test` の前半の失敗が、後ろのツール不足の行に隠れる | 出力が 300 文字までなら全体、長ければ先頭 120 文字・途中の失敗らしい行（3行まで）・末尾 120 文字を載せるようにした。前半だけの失敗のテストを付けた |
| 伏せ字が URL のユーザー情報を残す。項目に出すコマンドは伏せ字を通っていない | `ci.ts` に `redactUrlCredentials` を足し（スキームの大文字・小文字を問わない。読めない URL は `[REDACTED URL]`。指定すればクエリ・フラグメントも伏せる）、共通の `redactLog` から呼ぶようにした。項目に出すコマンドと出力は、どちらも全文で伏せてから切り詰める。`HTTPS://`・`HtTpS://`・切り詰めの境界をまたぐ値のテストを付けた。既知の秘密の値は、最終レビューの出力には実行後に伏せ済みで、コマンドには渡せる値が無いので渡していない（ADR に書いた） |
| PR の本文が長い | 冒頭に変更の要約を3行で置き、振る舞いの水準の短い説明に書き直した |

## 残したこと

- 案B（オーケストレーターが文書だけの依頼で `testCommand` を絞る）・案C（不足を実装の前に知らせる）・案E（指示の矛盾の整理）は、範囲外。
- 文書の拡張子の一覧は、`.mdx` や `.txt` を含まない。広げるときは新しい ADR で決める。
- ゴールガーディアンが `tests.otherFailures` を書き忘れた失敗は、見逃す。
- 実際のゴールガーディアン（AI）での確かめ（同じ依頼・同じ環境での再試行と、Go のコードを1行変えるだけのタスクで止まること）は、していない。自動のテストは、ゴールガーディアンの出力を差し替えて確かめている。
