# PR のレビューが、長い文書の変えていない本文まで担当に照合させて、判定を出せずに止まるのを直す

- 日付: 2026-11-15（UTC）
- タスク: PBI-349
- PR: （作成後に書く）
- ブランチ: feat/issue-349-review-document-range
- 関係する ADR: [PR のレビューで親が担当に渡す範囲を差分で決め、観点をどう見たかを本文に書く](../adr/20261115-1515-review-range-decided-by-diff-and-viewpoint-line.md)

## 目的

PR #378 のレビューが、4回目から「レビューを完了できませんでした」になり、判定が付かなくなった。
実行のログでは担当（サブエージェント）の起動が見えず、親が1人で見ているように見えたので、原因を調べて直す。

## 調べたこと

実行のログ（`<SACTY_HOME>/runs/<タスク>/<実行>.jsonl`）と、Codex のセッションの記録（同じ場所の `<実行>/agent/sessions/` の下の `rollout-*.jsonl`）を読んだ。

- 担当は起動されていた。Codex（0.167.0）の `codex exec --json` の出力には `spawn_agent` が出ず、`collab_tool_call` の `wait` だけが出る。
  セッションの記録には、親の `spawn_agent` の呼び出しと、担当ごとの記録がある。
  レビューの実行 583 回のうち、Codex の 537 回（1分を超えたもの）で、担当の起動は1回あたり中央値 18 件。
  0 件の 13 回は、どれも検証の途中で実行が失敗したもので、担当を起動する前に終わっていた。親が1人で見てレビューを終えた実行は無かった。
- PR #378 の8回のレビューは、どれも 17〜33 件の担当を起動していた。
  4回目からの5回は、U-1・U-6 の担当が `failed` を返していた。`limitations` は、どれも「変えていない長い既存の本文の全体を照合しきれなかった」。
  2回目は、同じ担当が `limitations` に「変更に関係しない節は照合していない」と書いて `passed`・`changes_required` を返していた。
  3回目に、親が文書の全体を見る担当を足し、その担当が `failed` を返した。
- 本文が「レビューを完了できませんでした」で始まる実行は、全部で 22 回。Codex の上の段階のエージェントの 394 回で 3 回、軽い段階に変えた後の 143 回で 19 回。
  19 回のうち 18 回で、文書の担当（U-1・U-6、または文書の全体を見る担当）が `failed` を返していた。最初は 2026-11-11。
- 2026-11-15 の変更（スキル writing、PBI-345、PBI-346）の前後では、担当の起動の数は変わっていない（中央値 13〜22 件。小さい対象のレビューが多い時間帯は少ない）。
  PBI-343 の後、2026-11-15 の夜までは「完了できませんでした」が無く（14 回）、PR #378 で再び起きた。

## したこと

- 既定のレビュー（`apps/daemon/default-context/skills/review`）
  - `pr-review.md`：「範囲」の節を足した。範囲は差分で決め、差分に入っている文書の変えていない本文の全体を範囲にしない。範囲は途中で広げない。
    担当の `failed` は理由を読んでから扱う。本文の「レビューの範囲」に、観点をどう見たかを必ず1行で書く。
  - `linked-docs.md`：差分に入っているリポジトリ内の文書は、本文で示された文書として拾わず、差分として見る。
  - `aggregation.md`：範囲の外を理由にした `failed` は起動し直さず、見られなかった観点に数えない。範囲を見きれなかった `failed` は、範囲を分けて起動し直す。
  - `review-execution/SKILL.md`・`finding-format.md`：範囲の外を見なかったことを `limitations` に書かず、見た範囲を `checked` に書く。
  - `U-6.md`：範囲が変更なら、変えた箇所と対応する箇所だけを照合する。
  - `review-dispatch/SKILL.md`：入力の確認の「範囲」に、上の決まりへの参照を足した。
- sacty がレビューに渡すプロンプト（`buildPrompt` のレビューの指示と、再レビューの指示）に、範囲の決め方と、観点をどう見たかの1行を足した。
- docs：仕様書（既定のコンテキスト・タスクと工程）・ユーザードキュメント（取り込み）を日英で直し、ADR を足した。
