# これまでの意思決定を ADR に、これまでのタスクを作業履歴に起こす

- 日付: 2026-10-14（UTC）
- タスク: PBI-83
- PR: なし
- ブランチ: feat/issue-83-adr-worklog-backfill
- 関係する ADR: なし

## 目的

#88 で決めた docs の構成に沿って、それより前のマージ済みの PR（#1〜#87）から、仕様・方針の決定を ADR に、PR ごとの作業を
作業履歴に起こす。元にするのは GitHub の公開の記録（PR の本文・コミット・レビューとその返信）だけにする。理由が記録に無いものは
推測せず、記録に無いと書く。後の PR で変わった決定には、規則どおりにステータスと置き換えの関係を付ける。

## したこと

- 元の記録の取得：`gh pr view <番号> --json number,title,body,createdAt,mergedAt,headRefName,reviews,comments,commits,files` と
  `gh api repos/<owner>/<repo>/pulls/<番号>/comments`（行へのレビューコメントと返信）で、#1〜#88 を取得した。
- 日時の決め方：作業履歴の日付は PR の `createdAt`、ADR の日時は PR の `mergedAt`（分まで、UTC）。PBI の番号はブランチの
  `issue-<番号>` から取り、PR のタイトル・本文の PBI と一致することを確かめた。
- 作業履歴：PR ごとに1件、87件（#88 は既にある）。粒度を PR ごとにしたのは、README の規則（別の PR で続きをしたら新しいファイルを足す）に
  合い、日付・レビューが PR の単位で公開の記録に残っているため。同じ PBI に PR が複数ある（PBI-4・5・6・10・11・14・41・42・45）ときは、
  PR ごとに別のファイルにした。
- ADR：仕様・方針の決定ごとに105件。不具合の修正・表示の微修正だけの PR（#29・#34・#47・#51・#59 の5件）は作業履歴だけにした。
- 置き換えの関係：後の PR の本文・コミット・レビューで、前の決定を変えたと確かめられた20件を `superseded` にし、`置き換え先` と
  新しい ADR の `置き換え元` を双方に書いた（どの部分を置き換えたかを添えた）。確かめられなかったもの（後の PR が足しただけのもの、
  前の ADR の決定に書かれていない前提が変わったもの）は、置き換えにせず採用のままにした。
- コンテキストの MCP を扱う #57（PBI-49）の ADR は、command の MCP をホストで動かす PBI-84 の PR がまだマージされていないので、
  採用のままにした。
- PR の作業は、まとまりごとにサブエージェントで読み分けて下書きし、ファイル名・日時・置き換えの関係・文言は自分で確かめた。

## 確かめたこと

- 作業履歴の日付・ブランチ・タスク、ADR の日時・関係する PBI が、PR の記録（`createdAt`・`mergedAt`・`headRefName`）と一致することを、
  取得した JSON と照らすスクリプトで確かめた（不一致0件、作業履歴の無い PR は0件）。
- `git diff origin/main` に、公開リポジトリの文言の規則で書かない語（特定の組織や勤め先の内部を指す語）が0件であることを grep で確かめた。
  元の記録にあったそれらの語や、利用者の環境・勤め先の事情を思わせる言い回し、アカウント名・個人の情報は、言い換えるか書かなかった。
- 理由の節を抜き取りで元の記録と照らし、記録にある理由だけであることを確かめた。
- `npx vitest run tests/docs`：59件が通った。
- `npm run lint`（終了コード 0）・`npm run typecheck`・`npm run build`：通った。
- `npx vitest run`：1件（`apps/daemon/src/session-logs.test.ts` の総当たりのテスト）が負荷で時間切れになった。docs だけの変更で
  関係しないので、`npx vitest run --maxWorkers=2` で確かめ、1163件すべてが通った。
