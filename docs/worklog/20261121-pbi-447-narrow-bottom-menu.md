# 狭い幅（640px 未満）では、メニューを画面の下の横並びにし、左の列を無くす

- 日付: 2026-11-21（UTC）
- タスク: PBI-447
- PR: なし
- ブランチ: sacty/task-pbi-447
- 関係する ADR: なし

## 目的

幅 640px 未満で、メニューが本文の幅を取らず、画面の下から親指で押せるようにする。幅 640px 以上の見え方は変えない。

## したこと

- メニュー（`shell/rail.tsx`）：幅 640px 未満では画面の下に固定した横並びにし、左の列を出さない。項目・順・行き先・`aria-current`・名前は変えない。1 つの `nav` を CSS だけで配置し直すので、支援技術には 1 つだけ読まれる。各項目は縦横 44px 以上。
- 本文（`app/layout.tsx`）：メニューの高さと画面の下の安全な領域の分だけ、本文の下に余白を足した。Tab で移したフォーカスがメニューに隠れないよう、`scroll-padding-bottom` も足した。
- 質問のパネル（`chat-panel.tsx`）：丸いボタンをメニューの上にずらした。パネルは下の安全な領域を空ける。
- 安全な領域：`viewportFit: "cover"` を足した。cover は左右にも効くので、ヘッダー・左の列・本文・丸いボタン・パネルで左右（と下）の安全な領域を空けた。タスクの詳細の固定の見出し（`task-detail.tsx`）も、本文の左右の余白と同じ式にそろえた。安全な領域が 0 のときの見え方は変わらない。
- 文書：`docs/user/getting-started(.en).md` に、狭い幅ではメニューが画面の下に出ることを足した。

## 確かめたこと

- `shell/rail.browser.test.ts`：幅 375px・639px・640px・1280px で、配置・押せる大きさ・丸いボタンの位置・本文の余白・`nav` が 1 つであることを確かめた。
- `app/layout.test.ts`：`viewportFit` が `cover` であることを確かめた（外すと落ちる）。
- `npm run lint`・`npm run typecheck`・`npx vitest run`（全件）を、最後の変更の後に実行した。

## 残したこと

- 実機の iPhone で、下のメニューがホームバーに隠れないこと、横向きで左の列とヘッダーが切り欠きに隠れないことの確認（Chromium では `env()` が 0 になる）。
