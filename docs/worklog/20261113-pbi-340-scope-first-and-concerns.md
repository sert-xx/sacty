# 要求要件・設計はスコープを最初に置き、人への確認に確認しない場合の懸念を添え、writing スキルに書き出し先ごとの改行と語の選び方を足す

- タスク: PBI-340
- PR: #363

- 関係する ADR: [要求要件・設計はスコープを最初に置き、人への確認には確認しない場合の懸念を添える](../adr/20261113-0708-scope-first-and-concerns-in-questions.md)

## 目的

人の要望に合わせて、sacty が書く文章を読みやすくする。
要求要件・設計はスコープから読めるようにし、人への確認には確認しない場合の懸念を添える。
writing スキルに、書き出し先ごとの改行、英語を直訳しないこと、一般的な言い回しを足す。

## したこと

- 既定のスキル `writing`
  - SKILL.md：決まりの要点・書く手順・見直しに、書き出し先ごとの改行、語と言い回し、人への確認の懸念、スコープを先に書くことを足した。
  - layout.md：書き出し先ごとの改行の書き方の表（GitHub のコメント、Markdown のファイル、Confluence のエディタとストレージ形式、チャット）と、要求要件・設計の並べ方を足した。
  - sentences.md：人に確認を求める書き方を足した。
  - wording.md（新規）：英語を単純に置き換えないこと、カタカナ語の扱い、一般的な言い回しの例。
- 既定の規則 `rules.md`：人に確認・判断を求めるときは、確認しない場合の具体的な懸念を添える。
- 工程の指示（`prompts.ts`）
  - 要求要件・設計の冒頭を「スコープ」「確認したいこと」「既定で決めたこと」の順にし、確認したいことに懸念を書かせる。差し戻しの質の基準にもスコープを足した。
  - 人が確かめること（`humanChecks`、受け入れの確かめ方の「人が確かめること」）に懸念を添えさせる。
- 既定のスキル `ears-requirements`：書く手順の最初に、スコープを要求より先に書くことを足した。
- 観点 D-10：スコープが最初にあるかと、確認したいことに懸念があるかを確かめる手順を足した。
- 仕様書（context・tasks-and-steps）とユーザードキュメント（context・tasks）を日英で直し、ADR を足した。

## 確かめたこと

- `npx vitest run apps/daemon/src/prompts.test.ts apps/daemon/src/default-skills.test.ts`：通過。
  足したテスト（スコープが確認したいことより前、懸念の指示）は、`prompts.ts` を main に戻すと失敗することを確かめた。
- `npx vitest run tests/docs`：通過。

## レビューの指摘と対応

- セルフレビュー（DA）：SKILL.md の箇条書きの1項目に、「。」の後の改行が無い所があった。改行して直した。
- セルフレビュー（DA）：`ears-requirements` の書く手順が「何を実現するか」から始まり、スコープを先に書く決まりと食い違っていた。手順の最初にスコープを足した。
