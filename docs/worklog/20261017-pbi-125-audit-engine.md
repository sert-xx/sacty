# 監査を実際に動かす

- 日付: 2026-10-17（UTC）
- タスク: PBI-125
- PR: #135
- ブランチ: feat/issue-125-audit-engine
- 関係する ADR: [完了したタスクを、作業履歴に記録しながら2段で監査する](../adr/20261017-1310-audit-engine.md)

## 目的

PBI-124 でモックで作った監査の画面を、実際の監査で動かす。完了したタスクを自動で監査し、差し戻しや試行錯誤の原因と、それを防ぐ
改修の提案を出す。

## したこと

- core：監査のイベント（10種類）と、タスクの監査の状態（`Task.audit`）の畳み込み。改修のタスクの元の提案（`Task.auditFix`、`start: "audit"`）。
- デーモン
  - 完了した瞬間に監査を待つ記録を足し、ワーカーで大まかな監査 → 懸念のある工程の深掘りを1つずつ進める。
  - 監査の指示と出力の読み方（`audit-prompts.ts`）、根拠の件数（`audit-evidence.ts`）。
  - 監査の予算（80% の記録・上限での一時停止・再開）、採用（改修のタスクの作成）・却下・起動のときの作り直し。
  - 作業履歴から画面の形を組み立てる `LedgerAuditService`（原因のまとめ・再発）。モックは `SACTY_AUDIT_MOCK=1` のときだけ。
  - config.yaml の `audit_agent`、エージェントの役割 `audit`・`audit-dive` とスタブの出力。
- 画面：作業履歴の監査の行の文言・ログへのリンク、sacty 宛ての採用の表示、途中の監査の原因の表示。
- docs：仕様書（監査・作業履歴・設定）、ユーザードキュメント（監査・設定）、ADR。

## 確かめたこと

- `npx biome check`・`npm run typecheck`・`npx vitest run`・`npm run build` が通った。
- 主な処理（止めるときの記録の抑止・根拠の ID の絞り込み・待ち行列の順・予算での一時停止・採用の宛先の検査・完了した瞬間だけの
  開始・sacty 宛てでタスクを作らない・再発の判定・監査の費用をタスクの予算に入れない）は、外すとテストが落ちることを確かめた。
- 一時的な SACTY_HOME と Docker のスタブのエージェントで、画面からタスク（公開リポジトリの調査）を作り、1回差し戻してから承認した。
  完了すると自動で監査を待ち、大まかな監査（人の差し戻し 1 件を sacty が数えた）→ 調査の工程の深掘り → 監査済みになった。
  対象リポジトリ宛ての提案を採用すると改修のタスクができ、監査の画面とダッシュボードに出た。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| （要修正）監査の材料に秘密情報がそのまま入る | 台帳・本文・承認済みの成果物・指摘・却下の理由・既存の原因の題と、監査の出力を、切り詰める前に伏せるようにした（sacty が使う秘密情報の値・GitHub のトークン・よくある秘密情報の形）。境界をまたぐ値・却下の理由・出力のテストを足した |
| （要修正）深掘りで、省いた作業履歴の原文を読めない | 台帳の全文（伏せたもの）を `/sacty-ledger/ledger.jsonl` に読み取り専用でマウントし、指示に場所を書いた。使ったコンテキストの版も指示に入れた |
| （要修正）audit_agent の空文字・継承のプロパティの名前で例外になる | `Object.hasOwn` で確かめ、設定の誤りにした。空文字・constructor・toString のテストを足した |
| （要修正）完了の記録と監査の登録が別の追記 | 完了する追記と同じ追記に `AuditQueued` を入れるようにした。1回の追記で保存するテストを足した |
| （要修正）同じプロジェクトの深掘りを並べると、同じ原因が別の鍵になる | 同じプロジェクトの深掘りを1つずつ実行するようにした。同時に始めても1つの鍵にまとまるテストを足した |
| （要修正）改修のタスクの repo が `.git` 付きで、clone の URL が `.git.git` になる | 宛先の候補を `.git` の無い GitHub の URL にそろえ、GitHub でないものは候補にしないようにした。元と同じ URL で clone するテストを足した |
| サロゲートペアの途中で切る | 切る位置がサロゲートペアの間なら1つ戻すようにした |
| 毎回新しいセッションであることを確かめていない | 再開の指定が無く、実行の ID が別であることを確かめるテストを足した |
| ログの失敗の件数を毎段同期で読み直す | 大まかな監査で数えて記録した件数を深掘りで使い、標準出力のログだけを非同期で読むようにした |
| sacty 宛てでタスクを作らないことを採用の前に説明していない | 採用の補足に、sacty 宛てはタスクを作らないことを書いた |
| ADR の「コードの写しも読み取り専用」 | ログと台帳は読み取り専用でマウント、コードは使い捨ての写しで変更しないよう指示、と直した |
| 旧版へ戻す条件が無い | ADR の影響と、ユーザードキュメント（監査・更新前のバックアップ）に書いた |
| main.ts の古いコメント | 消した |

それぞれ、直した処理を外すと足したテストが落ちることを確かめた。

## 残したこと

- sacty 宛ての改修の提案は、sacty への Issue にしない（セルフヒーリングがまだ無い）。採用の記録と提案の文だけを残す。
