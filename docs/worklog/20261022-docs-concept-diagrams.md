# 仕様書とユーザードキュメントに、Mermaid の概念図を足す

- 日付: 2026-10-22（UTC）
- タスク: なし

- 関係する ADR: [仕様書とユーザードキュメントの概念図を、Mermaid のコードブロックで本文の中に書く](../adr/20261022-1623-docs-diagrams-in-mermaid.md)

## 目的

文章だけではわかりにくい所（ゲートウェイの中継の経路、コンテキストの層と継承など）に、概念図を足す。
装飾の多い画像ではなく、本文と一緒に直せる図にする。

## したこと

- docs/spec と docs/user を読み、構成・流れ・状態の移り方・層の重なりを文章だけで説明している所を選んで、Mermaid の図を足した（日本語の版と英語の版に、同じ図を同じ行の数で 23 ずつ）。
  - 仕様書
    - 全体の構成：プロセスと通信（テキストの木を、待ち受け・トークン・cookie の境目がわかる図に置き換えた）
    - ゲートウェイ：中継の経路の構成図、組織内 PF の中継のシーケンス図
    - コンテキストの合成：層の重なりと extends、合成の規則の流れ、MCP サーバーの置き場所の決まり方
    - タスクと工程：タスクの進み方の全体、実装の検証から承認待ちまで
    - 承認と差し戻し：PR で承認するときのブランチ（gitGraph）
    - マージの後の監視：状態の移り方（stateDiagram）
    - メモリー：登録から読まれるまで、昇格の流れ
    - 監査：2段の監査の流れ
  - ユーザードキュメント
    - 目次：sacty の全体像
    - ゲートウェイ：中継の経路
    - コンテキストリポジトリ：継承の例（モノレポの相対パスとほかのリポジトリ）、上書き禁止と取り除きの効き方、MCP サーバーの動く場所
    - タスクを進める：タスクの進み方、PR で承認するときのブランチと PR
    - マージの後の監視・監査：流れ
    - docker compose のサービス：localhost の転送
- 図の中身は、仕様書の本文（とその「コード:」の参照）に書いてあることだけにした。
- docs/README.md の「共通の規則」に図の書き方を足し、スキル（`sacty-docs`）の2つの写しに、図も直すことを足した。
  方針は ADR に残した。

## 確かめたこと

- `npx vitest run tests/docs`：2 ファイル・89 件がすべて通った（日本語の版と英語の版のコードブロックの数と行の数の突き合わせを含む）。
- docs の中のすべての Mermaid のコードブロック（46 個）を取り出し、`@mermaid-js/mermaid-cli` 11.4.2（Chromium）で描画して、構文の誤りが無いことを確かめた。
  日本語の図は PNG にして目で確かめ、崩れていた図（ゲートウェイの構成図・全体の構成・監視の状態図・PR のブランチの図）は、配置を変えて描き直した。
- GitHub の上での表示は確かめていない（GitHub の Mermaid の版と、描画に使った版は違いうる）。
