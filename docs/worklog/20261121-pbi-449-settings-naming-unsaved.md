# 「設定」を呼び分け、「Sacty の設定」の入口を足し、保存していない変更に気づけるようにする

- 日付: 2026-11-21（UTC）
- タスク: PBI-449
- PR: #505
- ブランチ: sacty/task-pbi-449
- 関係する ADR: [設定の画面は、保存していない変更を送る値の写しで見張り、離れるときに確かめる](../adr/20261121-1800-settings-unsaved-changes-guard.md)

## 目的

初めての人が、全体の設定（Sacty の設定）とプロジェクトの設定を取り違えないこと。変えた設定を、保存しないまま失わないこと。

## したこと

- サイドメニュー（`shell/rail.tsx`）：下の端に「Sacty の設定」（`/settings`）を足した。プロジェクトの画面の「設定」は「プロジェクトの設定」、「すべてのプロジェクト」の画面では「プロジェクト」（`/projects`）と出す。英語も呼び分ける。「Sacty の設定」は `/settings` のときだけ強調する。人のアイコンのメニューの項目は残した。
- 狭い幅（640px 未満）：5 項目が 320px でも収まるよう、項目の間の余白と左右の余白を詰めた。名称は幅の無い空白の所で折り返す。
- 見出し・タイトル：プロジェクトの設定の見出しを「プロジェクト「<名前>」の設定」（英語は `Project "<name>" settings`）にし、`generateMetadata` で同じ文言をタイトルにした。
- 保存していない変更：`lib/unsaved-changes.tsx`（登録・`beforeunload`・Link の確認）、`shell/guarded-link.tsx`、`save-bar.tsx`（画面の下に固定した「保存する」の帯）を足し、`SettingsForm` と `ProjectEditor`（`project` があるとき）に使った。
- 保存の失敗・注意の文（失敗・照合失敗・再読み込み・コンテキストの誤り・GitHub アカウントの要求）は、固定した帯の中に置いた。プロジェクトの作成のフォームは、従来の「作成する」のボタンのままにし、帯を使わない。
- Sacty の設定の Slack の欄は子の部品の状態にあり、親が描き直されない。送る値が変わったら `NotificationSettings` が `onValueChange` で親に知らせ、親が写しを取り直す。
- 文書：`docs/user` の 3 つ（日英）と、`docs/spec/architecture.md`（日英）を直した。ADR を足し、`npm run docs:screenshots` で画像を撮り直した。

## 確かめたこと

- `shell/links.test.ts`：項目・名称・強調（日英）と、人のアイコンのメニュー。
- `shell/rail.browser.test.ts`・`save-bar.browser.test.ts`：実際のブラウザーで、幅 320px・375px の 5 項目（44px 以上・重ならない・はみ出さない）と、「保存する」が下に見えてメニューに隠れないこと。
- `unsaved-changes.test.ts`：2 つの設定の画面で、表示・確認・元に戻す・保存の成功と失敗。対象にしないもの。
- `app/projects/[id]/settings/page.test.ts`：見出しとタイトル。パンくずが `GuardedLink` で描かれること。
- `unsaved-changes.test.ts` には、Slack の欄だけを変える場合、失敗の文が帯の中にあること、作成のフォームが帯を使わず「作成する」のボタンを出すことも含む。`save-bar.browser.test.ts` には、長い結果の文でも帯が画面の 4 割以内で「保存する」が見えるケースを足した。

実行したコマンドと結果（最後の変更の後）：

- `npm run lint`・`npm run typecheck`：通った。
- `npx vitest run --no-file-parallelism`（CI と同じ直列）：323 ファイル、6358 件が通り、14 件はスキップ。失敗なし。
- main（PBI-448 の `rail.browser.test.ts` の事前の読み込みを含む）を取り込み済み。同じファイルの変更は両方の意図を保っている。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| Slack の欄だけを変えると、変更として扱われない | 送る値が変わったときに親が写しを取り直す。Slack の欄だけを変えるテストを足した |
| 失敗・注意の文が固定した帯の外にある | 帯の中に移した |
| 作成のフォームにも固定した帯が付いている | `project` があるときだけ帯を使う |
| パンくずの確認のテストが無い | `GuardedLink` を押すテストを足した |
| 作業履歴・「コード:」が足りない | 書き足した |
| 結果の文が長いと「保存する」が帯の中のスクロールで隠れる | 結果の文だけを別の領域にして画面の 25% までに収め、あふれたらその中だけスクロール。ボタンと「保存していない変更があります」は固定の行に残す。帯に左右の余白を足した |
| 今回の直しを固定するテストが足りない | 失敗の文が帯の中、Slack の保存前の表示、作成のフォーム、パンくず、長い結果の高さのテストを足した |
