# PR で確かめる工程は、「チェックする」から直接 PR を開く

- 日付: 2026-10-18（UTC）
- タスク: PBI-136
- PR: なし
- ブランチ: feat/issue-136-review-opens-pr
- 関係する ADR: なし

## 目的

PR で確かめる工程（要求要件・設計・実装）の承認で、タスク詳細 → sacty のレビュー画面 → PR → マージ → レビュー画面 → タスク詳細、と遷移が
多いのを減らす（ステークホルダーの要望。実装の PR も含めることを確認済み）。

## したこと

- 画面：承認待ちで、今の提出の PR が開いていて、URL が `https://` で始まるとき、「チェックする」の導線を「PR でチェックする ↗」にし、GitHub の
  PR を新しいタブで開く（`reviewPullRequestUrl`・`personAction`）。タスクの詳細・タスクの一覧・ダッシュボードの「あなたの出番」・ヘッダーの
  お知らせ（プロジェクトを切り替えずに開く）で同じにした。外部へ開くリンクは `ActionLink`（↗ と、読み上げの「新しいタブで開く」）。
- エスカレーション（戻し先を人が選ぶなど）・PR が閉じられた・提出と違う内容でマージされた・PR が無いときは、今までどおり sacty のレビュー画面。
- docs：仕様書（承認と差し戻し・全体の構成のダッシュボード）、ユーザードキュメント（タスクを進めるの「PR での承認」）。

## 確かめたこと

- `npx biome check`・`npm run typecheck`・`npx vitest run`・`npm run build` が通った。
- 次の修正を戻すと、テストが落ちることを確かめた：閉じた PR では開かないこと、https の URL だけを開くこと、承認待ちだけで開くこと、PR を開くこと、
  外部なら新しいタブで開くこと、タスクの詳細・一覧・ダッシュボード・お知らせのそれぞれで外部の印を渡すこと（お知らせはプロジェクトを
  切り替えないこと）。
- 「今のゲートの工程の PR か」の確かめは、`gatePullRequest` がもともと今のゲートの工程・提出の PR だけを返すので重複していた（ミューテーションで
  わかった）。消した。
- デモ用のポートで、要求要件の PR で承認待ちのタスク（デーモンのテストの、偽の GitHub で PR を作る流れの作業履歴を写したもの）で、
  「PR でチェックする」が PR を新しいタブで開くこと、PR が閉じられたタスクはレビュー画面に案内することを確かめた。
