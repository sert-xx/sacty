# 実装する組み合わせから前段の調査を外し、情報収集にテストの書き方をまとめさせ、調査だけのタスクの結果の形を依頼に合わせる

## 目的

オーケストレーターの前の情報収集がコードを読むようになり、実装する組み合わせの先頭の前段の調査と同じことを二重にしていた。
前段の調査を外し、前段の調査にしか無かったテストの書き方は、リポジトリが決まっているタスクの情報収集にまとめさせる。
まとめにテストの書き方があっても、テストの要否はオーケストレーターが決める。
調査そのものが目的のタスクは、調査の工程を残し、結果の形を依頼の指定に合わせる。

## したこと

- `packages/core/src/events.ts`：`standard`・`skip-design`・`direct`・`split`・`bugfix` の工程から先頭の `investigate` を外した。
  `security-fix` は、修正の範囲の宣言のために残した。
- `apps/daemon/src/prompts.ts`
  - オーケストレーターへの組み合わせの説明（`planDescriptions`）から「調査 →」を外し、`PLAN_SELECTION_LINES` の前段の調査の説明を、情報収集のまとめを渡すことに直した。
  - 要求要件を経ない設計・実装の拠り所を `basisWithoutRequirements` にした（前段の調査があればその結果、無ければ集めた情報、集めていなければタスクの内容）。
  - 工程の見直しの指示の「調査の結果」を、集めた情報と終わった工程の成果に直した。
  - 調査が目的のタスクの指示で、結果の形を依頼の指定に合わせ、今までの形を指定が無いときの既定にした。
  - 情報収集の指示に、リポジトリが決まっているタスクだけ、テストの書き方を確かめてまとめの見出しに書くこと、テストの要否は書かないことを足した。
  - `gatheredLines` に読み手 `orchestrator` を足し、リポジトリのあるタスクでは、オーケストレーターと工程のエージェントに、まとめのテストの書き方でテストが要るとは限らないことを添えた。
- 仕様書（`docs/spec/tasks-and-steps.md` と英語の版）、ユーザードキュメント（`docs/user/tasks.md` と英語の版）に書いた。
  ADR を足し、置き換えた2つの ADR の名前を変えた。

## 確かめたこと

- `npx vitest run packages apps/daemon/src/prompts.test.ts`：通った。
  工程の見直しのテストは、前段の調査を置いていた版の作業履歴（`StepsChosen` に `investigate` がある）で確かめる形にした。
  新しい振る舞い（情報収集のテストの書き方・添える注意・調査の結果の形・前段の調査を置く組み合わせ・集めた情報に従う実装）のテストを `prompts.test.ts` に足した。
- `npx vitest run apps/daemon/src/daemon.test.ts`：前段の調査が無くなったことに合わせて、既存のテストを直した。
- `npm run typecheck`・`npx biome check`・`npx vitest run tests/docs`：通った。
- `npx vitest run`（全体）：8 件が失敗した（`agent-sessions`・`context-mcp`・`host-mcp-processes`・`question-form.browser`）。
  変更前のコミットでも同じ 8 件が失敗するので、作業した環境（コンテナ）によるもので、この変更とは関係ない。

## 残したこと

- オーケストレーターが決められるテストの扱いは、今までどおり `testCommand` か、テストの仕組みが無いときの `noTests` だけ。
  テストの仕組みがあるリポジトリで、このタスクにはテストが要らないとオーケストレーターが決める仕組みは無い（文書だけの変更などは、実装が観点ごとに差分で確かめると申告する）。
