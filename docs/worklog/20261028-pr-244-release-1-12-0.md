# 版を 1.12.0 に上げる

- 日付: 2026-10-28（UTC）
- タスク: なし
- PR: #244
- ブランチ: feat/release-1-12-0
- 関係する ADR: [版は 1.0.0 から semver で付け、タグと GitHub Releases でリリースする](../adr/20261019-2345-semver-releases.md)

## 目的

1.11.1 の後に、機能の追加（PR #237・#239・#241〜#243）と修正（PR #236・#238・#240）が入った。設定ファイルの形・台帳・コマンドの引数に
互換性の無い変更は無い（台帳・投影には項目を足しただけ）ので MINOR を上げ、1.12.0 をリリースする。

## 1.11.1 からの変更

- 完了したタスクから、その記録を引き継いだ続きのタスクを作れるようにした（PR #242）。
- 一時停止したタスクの再開で、補足を足し、まだ終わっていない工程のイメージ・エージェントを一緒に変えられるようにした（PR #243）。
- タスクの作成時に、進め方の工程ごとのイメージとエージェントを指定できるようにした（PR #241）。
- 実装の PR を最終レビューの前にドラフトで作り、PR の CI を待ってからゴールガーディアンが判定するようにした。検証に続けて通らずに
  止まったタスクは、人の判断でレビューへ進められる（PR #239）。
- 要求要件・設計の項目の出典（引用・導出・推論）を別のサブエージェントに分類させ、人が確かめる所を承認の画面と PR に示すようにした（PR #237）。
- 実装する組み合わせから前段の調査を外し、テストの書き方は情報収集にまとめさせるようにした（PR #236）。
- 長いイメージの説明や URL で画面が崩れないようにした（PR #238）。
- セットアップと更新の手順で、依存を `npm ci` で入れるようにした（PR #240）。
- 更新の後にすること：`npm ci` で依存を入れ直し、既定のイメージの名前が `sacty-agent:1.12.0` に変わったので、
  `npx sacty image build` で作り直す。

## したこと

- 4 つのパッケージとワークスペースの依存の版を `1.12.0` にし、`package-lock.json` の版の行も同じにした。手元の npm では
  `npm install --package-lock-only` が版と関係の無い行（`libc`）まで消したので、1.11.0 のときと同じく版の行だけを直した。
- 既定のイメージの名前（`DEFAULT_IMAGE`）を `sacty-agent:1.12.0` にし、仕様書（`agent-execution`・`configuration`）・ユーザードキュメント
  （`config`・`images`）の日英と、イメージの名前を書いているテスト・コメントを同じ版にした。ゲートウェイの MCP クライアントの版の文字列も
  `1.12.0` にした。

## 確かめたこと

- `npm ci`・`npm run lint`・`npm run typecheck`・`npm run build`：通過。
- `npx vitest run`（`tests/docs` を含む）：156 ファイルが通過、2 ファイルが失敗。失敗は `question-form.browser.test.ts`（Playwright に合うブラウザーが無い）と
  `install-security-tools.test.ts` の 2 件（macOS の作業環境で道具を置けない）で、版を上げる前の状態でも同じく失敗する。版の文字列とは関係が無い。
- `git grep 1.11.1` で、ADR・作業履歴と、外部の依存（`@emnapi/*` の `^1.11.1`）のほかに `1.11.1` が残っていないことを確かめた。
