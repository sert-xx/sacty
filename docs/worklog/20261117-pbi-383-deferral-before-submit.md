# 提出に至らなかった実行で申告した「後続に回したい案」を、提出のときに必ず PR に返信する

- 日付: 2026-11-17（UTC）
- タスク: PBI-383
- PR: #419
- ブランチ: feat/pbi-383-deferral-before-submit
- 関係する ADR: [返信していない後続に回したい案は、理由を次の提出に持ち越して返信する](../adr/20261117-0822-carry-unreplied-defer-proposals.md)

## 目的

実装が指摘を「後続に回したい」と申告した実行が、提出に至らずにやり直されると、案の返信が PR に投稿されず、先頭を変えないやり直しが、変更なしの一時停止になる。これを直す。

受け入れ条件の要点（着手のときに固めたもの）：

1. 案を申告した実行が提出に至らなくても（未完了の申告・ベースとの競合の残り・変更なしの一時停止からの再開）、次の提出のときに、「案で、人に確認中」の返信が、1 回だけ投稿される。デーモンを起動し直しても、重ねない。
2. 返信していない案を、実装の指示で、返信済みと伝えない。
3. 持ち越した案は、先頭を変えないやり直しの「すべて断るか案にした」の判定で、案に数える（一時停止にならず、提出になる）。
4. 人がまだ決めていない案が 1 件でもあれば（前の提出の案を含む）、同じ先頭の判定のし直しは、人の決定を待つ。
5. レビューと実装に渡す、後続に回したい案のデータで、長くて先頭だけを載せた文に、切ったことの印が付く。範囲の決め方は変えない。
6. 人が決めた後の決定を変えない・決める前に「対応した」と申告されたら案を取り下げる、という今の決まりを保つ。前の版の作業履歴が読める。
7. 仕様書・ユーザードキュメント（日英）・ADR・作業履歴を合わせる。

## したこと

- 投影（`packages/core/src/projection.ts` の `AgentRunCompleted`）：人がまだ決めておらず、PR にまだ返信していない案は、その実行に対応が無ければ、案の理由を、その提出の対応として持ち越す（`response`・`status` が `deferred`・`respondedIn`）。人に確かめたいこと（`confirm`）は、申告した実行がまだ提出されていないときだけ残す。返信した案・人が決めた案は、今までどおり未回答に戻す。
  - イベントは変えていない。返信の条件（`awaitingRemarkReplies`）と、すべて断るか案にしたかの判定（`declinedEveryFinding`）の条件も変えず、持ち越した対応を、今の条件のまま読む。
- 判定（`apps/daemon/src/service.ts` の `declinedEveryFinding`）：人がまだ決めていない案が、実装の指摘に 1 件でもあれば、待つ印（`awaitsDecision`）を付ける（今までは、最新の回の指摘に、その実行の案があるときだけ）。
- 実装の指示（`apps/daemon/src/prompts.ts` の `remarkLines`・`ownerDeferralLines`）：対応させる指摘がほかに無くても、案にした指摘のデータを渡す。人に確認中の案の行を、「提出のときに sacty が返信する」に変えた（返信してある、と伝えない）。
- 切ったことの印（`prompts.ts` の `cutHead`）：レビューに渡す `deferredByPerson` に `findingTruncated`・`proposalTruncated`、実装に渡す `deferredByPerson`・`awaitingDecision` に `truncated` を付け、印の意味を 1 行で伝える。切っていなければ、印も行も出さない。
- 仕様書（`docs/spec/approval.md`・`docs/spec/tasks-and-steps.md`）・ユーザードキュメント（`docs/user/tasks.md`）と、それぞれの英語の版を合わせた。ADR を 1 件足した。

決めたこと（理由は ADR）：

- 次の実行に指摘を渡し直さず、投影で理由を持ち越す。
- 提出したが返信できないまま作り直した案も、持ち越す（見つかった不具合は、提出に至らなかった実行の案だけ）。
- 判定のし直しを待つ条件（`rejudgeDue`）は変えず、提出のときの印で決める。

確かめられなかったこと：

- 実際の GitHub への返信と、動いているデーモンでの確認はしていない（テストは、GitHub の偽物で確かめた）。
- 競合の残りのやり直しでは、人のコミットを取り込むので先頭が変わる。先頭を変えないやり直しの判定（判定のし直しが人の決定を待つこと）は、未完了のやり直しと、変更なしの一時停止からの再開のテストで確かめた。

## 残したこと

- 人が後続に回すと決めた範囲の決め方（指摘の先頭の 600 文字と、実装が書いた理由の文で決まること。1 件に複数の指摘がまとまっているときの扱い）は、変えていない。人に確かめる。
- 前の版の記録で、待つ印の無い提出（最新の回をすべて断り、前の提出の案が未決定）の、まだ始まっていない判定のし直しは、今までどおり、人の決定を待たずに始まる。
