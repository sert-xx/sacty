# 人に確かめてほしいことの知らせ・差し戻しの判断の要点・承認待ちの一時停止（PBI-301 の C 群：C1・C2・C3）

- 関係する ADR: [人に確かめてほしいことを、PR のコメントと承認の画面の目立つ所に出す](../adr/20261104-0610-surface-human-asks.md)、[承認待ち（PR のマージ待ち）でも一時停止できるようにする](../adr/20261104-0600-pause-while-awaiting-approval.md)

## 目的

実務実証実験（r2〜r4）で残った、画面・人への知らせの問題を直す。

- C1（S14）：指摘への聞き返し・実行が推測で決めたこと（消えた上限の作り直しなど）が、作業履歴や対応欄の隅にしか出ず、PR を見ている人は気づけなかった。
- C2（S7）：差し戻しの判断の文が 600〜1,000 文字になり、画面で読みにくかった。
- C3（S18 r3）：実装の PR のマージ待ちには「中止」しか出ず、一時停止（F19・F23 の直し）を確かめる場面を作れなかった。

## したこと

- C1
  - `RemarkResponse` に任意の `confirm`（人に確かめたいこと）を足し、`Task.remarks[].confirm` に、対応と同じ提出回のものだけ持たせた。作り直しの指示（`remarkLines`）に、書くとき（意図を読み取れず推測した・元の値が無く作り直した・求められていない範囲を変えた・直さなかった）と、無いときは書かないことを足した。読み取りは 1,000 文字で切る。
  - `humanAsks`（core）：承認待ちの今の提出が受けた指摘について、ゴールガーディアンが判断できなかった理由（`prRework.decided` が偽。理由が sacty の文言のときは出さない。指摘の回が進んでいれば古い判断は出さない）と、`confirm` を返す。見つけた不具合：最初は指摘の回を見ておらず、その後の差し戻しの提出でも古い判断が出ていた（テストで見つけて直した）。
  - 画面（`HumanAskNotice`）：承認の画面の上とタスクの詳細の承認の案内の下に出す。
  - PR のコメント：作り直した成果物が承認待ちに戻ったとき（提出が新しくなったときだけ。再開では書き直さない）、そのゲートの PR に1件コメントする（`announceHumanAsks`・`human-ask-notice.ts`）。目印で二重に書かない。外から来た文は、秘密情報を伏せてから 600 文字で切り、`@` で通知が飛ばないようにして引用にする。次の PR の確認で人間の指摘として取り込まない（`isHumanAskNotice`）。投稿できなくても、タスクは変えない。
- C2：`summarizeDecision`（先頭の2文・160 文字）。作業履歴の戻し先の行（行に要点、詳細に全文）・PR の欄の戻し先（折りたたみ）・人に確かめてほしいことで使う。作業履歴の記録と、実行に渡す判断文は全文のまま。
- C3：承認待ちでも一時停止できる（`pause`）。エージェントの実行が無いので、その場で `TaskPaused` を記録する。投影が `resumeTo: awaiting_approval` を持ち、再開で承認待ちに戻る。止めている間の実装の PR は、作り直しの間と同じ見守り（マージは承認として進める・指摘は残して再開後に反映）。要求要件・設計の PR は、止めている間は見守らず、再開後の確認で取り込む。再開して同じゲートに戻っただけなら、承認待ちの通知をし直さない（`notificationFor`）。画面の一時停止のボタンを、承認待ちにも出す（エスカレーションは出さない）。
- 仕様書（`approval`・`tasks-and-steps`、日英）・ユーザードキュメント（`tasks`、日英）・ADR 2件・承認待ちの画面のスクリーンショット（`task-pull-request`、日英。一時停止のボタンが増えた）を直した。

## 確かめたこと

- 画面の確認：自分の worktree でビルドし、別のポート（4793・4794）と一時の `SACTY_HOME` で起動した（4700 番と `~/.sacty` は触っていない）。架空のデータで、(1) 判断できなかった長い理由と実行の確かめたいことのある、作り直した実装の承認待ち、(2) 普通の実装の PR のマージ待ち、を作った。
  - (1)：タスクの詳細と承認の画面の上に「人に確かめてほしいことが2件あります」。理由は先頭の2文と「詳細」、PR の欄の戻し先と作業履歴の戻し先の行も要点と「詳細」になる。
  - (2)：「一時停止」を押すと「一時停止中」になり、「再開する」で「実装の PR のマージ待ち」に戻る。
- `npx vitest run packages/core`・`apps/daemon/src/{prompts,github,notifier,human-ask-notice}.test.ts`・`apps/web` の関係するテスト・`apps/daemon/src/daemon.test.ts` の PBI-301 の節・`tests/docs`：通る。足したテストは、修正を戻すと落ちることを確かめた（PR への知らせの呼び出し・承認待ちでの一時停止の許可・一時停止のボタン・指示の `confirm`・知らせを人の指摘から除く条件・作業履歴の要点）。
- 状態の境界：確かめたいことが 0・1・複数件、判断できなかった理由の有無、判断できた・実行の失敗、無効にした指摘、差し戻した後の次の提出（古い判断・古い確かめたいことが残らない）、承認待ちでない、要点が1文・2文・3文以上・長い1文。承認待ちの一時停止は、実装の PR（指摘・マージ）と要求要件の PR（止めている間のマージを再開後に承認）。

## レビューの指摘と対応（自分で悪魔の代弁者として確かめた）

| 指摘 | 対応 |
| --- | --- |
| 差し戻した後の次の提出でも、前の判断できなかった理由が出る | 判断の回（`prRework.round`）が、その工程の最新の回のときだけ出す。テストあり |
| 承認待ちで一時停止して再開すると、承認待ちの通知（Slack）が重ねて送られる | 同じゲートに戻っただけなら送らない。テストあり |
| `@名前` を含む文を PR に載せると、他人に通知が飛ぶ | `@` の後ろに幅の無い空白を挟み、引用にした。テストあり |
| 自分のコメントを次の確認で人間の指摘として取り込み、差し戻しが続く | 目印で始まるタスクのアカウントのコメントを除く。他人が目印をまねたものは除かない。テストあり |

## 残した制限

- PR のコメントは、承認待ちに戻る遷移の1回だけ書く。デーモンの再起動をまたいでの書き直しはしない（画面には残る）。
- 一時停止中の要求要件・設計の PR は、再開するまで見守らない。止めている間にマージされても、承認は再開のあとになる。
- 承認待ちでの一時停止は、実タスク（実際の GitHub の PR）では確かめていない。
- GitHub のアカウントを選んでいないプロジェクトでは、PR にコメントしない（画面には出る）。
