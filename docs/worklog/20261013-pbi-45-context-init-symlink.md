# sacty context init で、途中のディレクトリがリンクならリンク先に書かずに止める

- 日付: 2026-10-13（UTC）
- タスク: PBI-45
- PR: #51
- ブランチ: feat/issue-45-context-init-symlink
- 関係する ADR: なし

## 目的

#48 のマージの後のレビューの指摘（P1）に対応する。`sacty context init` で、`skills`・`agents`・`agents/codex` などの途中のディレクトリが
シンボリックリンクだと、雛形をリンクの先に書き込み、`--force` ではリンク先の既存のファイルを上書きしていた。

## したこと

- `apps/daemon/src/context-template.ts`：書き込む前に、すべての出力パスの途中のディレクトリを `lstat` で確かめ、ディレクトリでなければ
  （シンボリックリンク・ファイル）、`--force` でも何も書かずに止める。止めるときは、どのパスがディレクトリでないかを示す。
- 指定したディレクトリ自体（`<dir>`）がリンクであることは、利用者が選んだ場所なので、これまでどおり許す。

## 確かめたこと

- `apps/daemon/src/context-template.test.ts`：`skills`・`agents`・`agents/codex` がリポジトリの外へのリンクのとき、`--force` の有無にかかわらず止まり、
  リンク先のファイルが変わらず、ほかの雛形も書かれないこと。途中のディレクトリの場所がファイルのときも止まること。
- 判定を外すと4件のテストが失敗することを確かめた。
- build・typecheck・lint・全テスト（456件）が通った。
- レビューでは、独立した再現で、`--force` の有無にかかわらず拒否され、リンク先の既存のファイルが守られ、ほかの雛形も書かれないこと、
  指定したディレクトリ自体のリンクは許すことを確かめた。
