# 差し戻しの原因を判断し、ゴールガーディアンの見逃しは原因が見逃しのときだけ数える

- 日付: 2026-11-01（UTC）
- タスク: PBI-268
- PR: なし
- ブランチ: feat/issue-268-rework-cause
- 関係する ADR: [差し戻しの原因を判断し、ゴールガーディアンの見逃しは原因が見逃しのときだけ記録する](../adr/20261101-1355-rework-cause.md)

## 目的

合格にした最終レビュー（統合レビュー）の成果物を人が差し戻すと、理由を問わずゴールガーディアンの見逃し（`GuardianMissed`）に数えていた。
実証実験で、見逃しではない差し戻しも見逃しに数えられた（S13：先の PR のマージによるベースブランチとの競合、S9：人が後から足した要望）。

受け入れ条件の要点：

- 確かめられたのに見逃したものだけを見逃しに数える。競合や、新しく足した要望・方針の変更による差し戻しは数えない。
- 画面や集計で、見逃しとそれ以外が区別できる。過去のイベントは読めるままにする。
- 仕様書・ユーザードキュメント（日英）・作業履歴を直し、テストで確かめる。

## したこと

区別の方法は、差し戻すときに原因を判断させることにした（理由と採らなかった案は ADR）。

- イベント（`packages/core/src/events.ts`）：`ReworkCause`（`guardian_missed`・`new_request`・`base_changed`）を足し、`ChangesRequested`・`ReworkJudged` に省略できる `cause` を足した。
  差し戻しの入力 `RequestChangesInput` にも省略できる `cause` を足した。省略でも過去のイベントは読める。
- 見逃しの記録（`apps/daemon/src/service.ts` の `requestChanges`）：`cause` が `guardian_missed` で、合格のレビューがあるときだけ `GuardianMissed` を記録する。
  省略（原因を決めない）・`new_request`・`base_changed` では記録しない。
- PR の指摘（`apps/daemon/src/prompts.ts`）：戻し先の判断の指示に原因の判断を足し、`extractRework` が原因を読む。
  答えが無い・`undecidable`・知らない値は、原因を決めない。判断した原因は `settleReview` が差し戻しに引き継ぎ、`prRework` にも残す。
- 画面：
  - 承認の画面の差し戻しに「差し戻しの原因」（選ばない・見逃し・新しい要望・競合。初めは「選ばない」）を足した。
  - 作業履歴の差し戻しの行に「（原因：…）」を足した。
  - PR の欄の戻し先に原因を足した。
  - ダッシュボードの品質の信号に、原因ごとの差し戻し（新しい要望・方針の変更、ベースの変化による競合、原因を決めていない）を足した。
    集計は `DashboardSummary.quality.reworkByCause`。
- docs：仕様書（承認・アーキテクチャ。日英）、ユーザードキュメント（タスクを進める・ダッシュボード。日英）、ADR（新規。見逃しを記録する古い ADR は一部を置き換えたので `superseded` にし、作業履歴からのリンクを直した）。

## 確かめたこと

- `npx biome check .`：通る。
- `npm run typecheck`：通る。
- 関係するテスト：
  - `npx vitest run packages apps/web/src`（core の events・dashboard・projection、web の gate-form・actions・labels・dashboard・pull-request）：通る。
  - `npx vitest run apps/daemon/src/daemon.test.ts`：通る。
  - 追加したテスト：原因ごとの見逃しの記録（原因を決めない・競合・新しい要望は記録しない、見逃しは記録する、競合の差し戻しの後の新しいレビューの見逃しは数える）、PR の指摘の原因（競合・新しい要望・答えが無い・判断できない・知らない値）、イベントの形（原因が無くても読める、知らない原因は断る）、ダッシュボードの集計、画面（フォーム・作業履歴の行・PR の欄・ダッシュボード）。
  - 見逃しの条件（`input.cause === "guardian_missed"`）を外すと、追加した 9 件が落ちることを確かめた。
- `npx vitest run tests/docs`：通る（日本語の版と英語の版の突き合わせを含む）。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| DA のセルフレビュー：見逃しの記録の条件（原因が見逃し）を外しても、追加したテストが落ちずに通ってしまわないか | 条件を外すと追加した 9 件が落ちることを確かめた。条件を戻した |
| DA のセルフレビュー：原因を省略した API・原因を答えないゴールガーディアン・知らない原因の値が、見逃しに数えられないか | 数えない（テストで確かめた）。省略の既定は見逃しにしない側（ADR の「影響」に書いた） |
| DA のセルフレビュー：上限でエスカレーションになる差し戻しに、選んだ原因が残らない | 仕様どおり（上限を超えて差し戻すときに選び直す）。仕様書に書いた |
| DA のセルフレビュー：ダッシュボードの「見逃し」と、原因ごとの `guardian_missed` の数が合わないことがある | 合格のレビューが無い成果物や過去の記録で起きうるので、仕様書と ADR に書いた |
