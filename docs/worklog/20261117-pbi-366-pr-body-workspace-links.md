# sacty が作る PR の本文から、コンテナの作業領域へのリンクを外す

- 日付: 2026-11-17（UTC）
- タスク: PBI-366
- PR: #403
- ブランチ: feat/pbi-366-pr-body-links
- 関係する ADR: なし

## 目的

sacty が作った PR の本文に、コンテナの作業領域のパスへのリンク（`[README.md](/workspace/README.md)`）が入った。GitHub では開けない。
エージェントの説明（実装の説明・要求要件・設計）に入ったリンクが、そのまま PR の本文に載るため。これを、リンクでない表記にする。

はじめは #395 に入れていたが、レビューで変換の後の構文の指摘が4回続いたので、#395 から外して、この PR に分けた。
#395 のレビューで直したこと（Markdown のパーサーへの置き換え・長くしない置き換え・解釈の後での判定・秘密の値の伏せ直し）は、そのまま引き継いでいる。

## したこと

- `apps/daemon/src/pr-body-links.ts` の `withoutWorkspaceLinks` を足し、PR の本文を組み立てる1か所（`service.ts` の `pullRequestBody`。要求要件・設計の PR と実装の PR の、作成と更新のすべてが通る）で、長さの上限の後に呼ぶ。
- リンク・画像の範囲は、Markdown のパーサー（`mdast-util-from-markdown` 2.1.0。Web の依存として既にロックファイルにある版を、デーモンの依存に足した）で決める。
- 置き換えは、元のリンクより長い文字にしない（長さの上限の後に置き換えるため）。
- #395 の4回目のレビューの指摘（表示の文字が、リンクのほかの構文に変わる。画像の代わりの文字 `<!--` が HTML のコメントの始まりになって後ろの文章を隠す・代わりの文字から参照の定義ができて、ほかのリンクの行き先が変わる）への対応：
  置き換えた後の本文も解析し、その構文木の全体（位置を除いた、種類・値・子）が、元の構文木の「外したリンク・画像を、中身と添えたパスにしたもの」と同じであることを確かめる（`shapeOf`）。同じでなければ、本文を変えずに使う。
  #395 では、リンク・画像の並びだけを比べていた（`linkSignature`）ので、リンクのほかの構文への変化を通していた。安全な文脈を選んで変えるのではなく、変えた結果の全体を確かめて、違えば戻す。
- 置き換えの後に、秘密の値をもう一度伏せる。伏せた結果が長さの上限を超えるときは、置き換えをやめて、上限の中の本文を使う。
- 仕様書（日英）：`docs/spec/approval`（「長さ・秘密の値・台帳」）。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| （#395 の4回目から引き継いだ）[要修正] 表示の文字を Markdown に再結合し、リンクの一覧だけを照合する方針では、ほかの構文への変化を防げない | 構文木の全体の比較に置き換えた（上の「したこと」）。HTML のコメント・タグ、参照の定義、強調・インラインコード、箇条書き・見出し・引用・コードブロックの囲みになる形を、回帰テストに足した |
| （#395 の4回目から引き継いだ）[提案] 変換の後の伏せ直しで本文が上限を超え、変換の前の本文に戻す分岐を、テストが通っていない | テストを足した。上限まで埋まる本文と、伏せ字より短い秘密の値で、PR の本文が上限の中に収まり、値を含まず、置き換える前の本文であることを確かめる |

## 残したこと

- リンクの解析を、デーモンの中で同期に行っていること。別スレッドに分ける件は、後続に回すと決まっている（#395 のレビュー）。
- 置き換えた結果の構文が元と変わる本文には、作業領域へのリンクが残る（変えずに使うため）。
- PR に投稿するレビュー・コメントの本文、参照形式のリンクの定義、HTML のリンク。
