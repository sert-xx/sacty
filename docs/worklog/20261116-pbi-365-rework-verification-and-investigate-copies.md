# 実装の出し直しで検証をやり直させ、調査の工程にも複数のリポジトリの写しを渡す

- 日付: 2026-11-16（UTC）
- タスク: PBI-365
- PR: #395
- ブランチ: feat/pbi-365-rework-verification-links-copies
- 関係する ADR: なし

PBI-367 も、この PR に入れた（どちらも小さく、互いに独立している）。
はじめは、PR の本文のコンテナのパスへのリンクを外す変更（PBI-366）も入れていたが、レビューの途中で外した（下の「レビューの指摘と対応」）。ブランチの名前に `links` が残っているのは、そのため。

## 目的

複数のリポジトリを指定する機能を sacty 自身に実装させたときに、実物で見つかった次の2つを直す。

- 差し戻しを受けて出し直した PR の作業の記録に、直す前のコードでの検証の結果（「前回の実装では…通った」）が、今回の結果のように書かれた（3つの PR で繰り返した）。実装の指示に、出し直しのたびに検証をやり直す決まりが無かった（PBI-365）。
- 進め方が「調査だけ」のタスクでは、複数指定したリポジトリの写しが工程に渡らなかった（PBI-367）。

## したこと

- PBI-365：実装の直しの指示（`implementReworkLines`。前の実装の説明を添える実行）に、`REWORK_VERIFICATION_LINE` を足した（`apps/daemon/src/prompts.ts`）。
  提出の前の検証を直しの後のコードで実行し直すこと、実装の説明とリポジトリの文書に書く検証の結果は今回のものだけにすること、前の回の結果が文書に残っていれば書き換えること、実行しなかった検証はそう書くこと。
  あらゆるリポジトリの対象に渡る指示なので、言語・ツール・文書の名前を挙げていない。最初の実行の指示は変えていない。
- PBI-367：複数指定のタスクに写しを渡す工程の条件（`requirements`・`design`・`split`）が `service.ts` の 11 か所に書かれていたのを、`REPOSITORY_COPY_STEPS` と `copiesRepositories` にまとめ、`investigate` を加えた。
  写しの用意・失敗のときの停止と再開・片付けは、要求要件・設計・分割と同じ仕組みをそのまま通る。
  調査の指示（`buildPrompt` の `investigate`。調査だけと、前段の調査の両方）に、写しの場所・ブランチ・コミットを渡す。リポジトリを選ぶ前（作業領域に写しを並べる）でも、「プロジェクトのコンテキストをもとに」ではなく、コードを読んで調べさせる。
- 仕様書（日英）：`docs/spec/tasks-and-steps`（写しを渡す工程）、`docs/spec/approval`（直しの指示）。利用者に見える設定・画面・コマンドは変えていないので、ユーザードキュメントは直していない。

## 確かめたこと

PBI-366 を外し、main（Next.js の更新 #394 を含む）を取り込んだ後のコードで、すべて実行し直した結果を書く。

- `npx vitest run --no-file-parallelism`：244 ファイル・4691 件が通った（1 件は以前からの skip）。
- `npm run typecheck`：通った。
- `npx biome check apps packages docs tests scripts`：指摘なし。`npm run lint` は、Git 管理外の `.claude/settings.local.json`（この作業用のディレクトリにだけあるファイル）の整形の指摘 1 件で落ちる。リポジトリのファイルの指摘は無い。
- `npm run build`：通った。
- 足したテスト：`pr-body-rework.test.ts`（直しの実行だけに検証の行がある。要求要件を経ない・経る・テストの仕組みが無い・不具合の修正）、`daemon-repoless.test.ts`（調査の工程で、選ぶ前・選んだ後の写し、写しの失敗の停止と再開）、`prompts.test.ts`（調査だけの指示と、後の工程のある調査の指示の、写しの一覧。複数を指定していないタスクは変わらない）。
- 修正を戻すとテストが落ちること：`REPOSITORY_COPY_STEPS` から `investigate` を外すと `daemon-repoless.test.ts` の 4 件が、直しの指示から `REWORK_VERIFICATION_LINE` を外すと `pr-body-rework.test.ts` の 1 件が落ちた。戻して通ることを確かめた。
- 確かめていないこと：実際のエージェントが、足した指示のとおりに検証をやり直して書くか（指示の文があることだけをテストで確かめた）。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| （1回目）[提案] `prompts.test.ts`：複数リポジトリのケースが調査だけのタスクなので、後の工程のある調査（前段の調査）の分岐で写しの一覧が欠けても検出できない | テストを足した（調査 → 実装のタスクで、リポジトリを選ぶ前と後。写しの場所・ブランチ・コミットと、コードを読む指示） |
| （1〜4回目）PR の本文のリンクの変換（PBI-366）への指摘：行ごとの自前の解析が Markdown の構文と食い違う／変換で本文が長さの上限を超えうる／事前の判定が文字参照のリンクを見落とす／変換の後に秘密の値が現れうる／表示の文字を周りの文字とつなぐと、新しいリンクができる・後ろの文章が隠れる（HTML のコメントの開始になる）・参照形式のリンクの行き先が変わる／同期の解析の間、デーモンのほかの処理が待つ | 1〜3回目の指摘は、その都度直した（Markdown のパーサーへの置き換え・長くしない置き換え・解釈の後での判定・伏せ直し・リンクの並びの照合）。4回目でも、変換の後の構文の指摘が残ったので、リンクの変換をこの PR から外し、別の PR に分けた（リポジトリの持ち主の代理の決定の基準による。問題の無い2点が、リンクの変換の往復で止まっていたため）。外した時点のコードは、ブランチ `feat/pbi-366-pr-body-workspace-links` にある。同期の解析の待ちを別スレッドに分ける件は、後続に回すと決まった |
| （4回目）[提案] この記録の「確かめたこと」で、まっさらな複製での確認だけが以前のコードでの結果とあるが、ビルドも以前のコードで実行したと書かれていて、どの版で実行したかが一致しない | 直した。PBI-366 を外した後のコードで、すべての検証を実行し直し、その結果だけを書いた（以前の回の結果は残していない） |

## 残したこと

- PR の本文のコンテナのパスへのリンクを外すこと（PBI-366）。別の PR で扱う。
- PR のレビューが、古い検証の結果の記載を指摘すること（既定のスキルの変更になる）。
- 実際のエージェントが、足した指示のとおりに検証をやり直して書くかは、確かめていない（指示の文があることだけを、テストで確かめた）。
