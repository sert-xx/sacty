# 「PR作成」の工程をなくし、実装の工程の中で PR を作って承認を待つ

- 日付: 2026-10-15（UTC）
- タスク: PBI-110
- PR: なし
- ブランチ: feat/issue-110-implement-gate
- 関係する ADR: [「PR作成」の工程をなくし、実装の工程の中で PR を作って承認を待つ](../adr/20261015-1430-implement-step-opens-pull-request.md)

## 目的

実装も、要求要件・設計と同じ形（その工程の中で PR ができ、PR のマージで承認する）で確かめられるようにする。工程 `pr`（画面では「PR作成」、
仕様書では成果物チェック）をなくし、今の `pr` の工程の振る舞いを、実装の工程で今と同じく動かす。破壊的な変更で、互換の層は作らず、古い記録は捨てる。

## したこと

- core：`StepKey`・`STEP_PLANS`・`MVP_STEPS` から `pr` を外し、`GATED_STEPS` に `implement` を入れた。投影は、最終レビューに通っても実装の
  工程を終えず、PR の作成の待ち（`publishPending`。状態は実行待ち）にする。`PullRequestPublished`・`NoChangesFound`・`BranchPushed` は、
  この待ちのときだけ受け付ける。実装の PR の見守り・マージ・変更なしの判定（`gatePullRequest`・`deliveredWithoutChanges`）は、実装の工程で
  行う。指摘への対応の提出回は、実装の提出回にした。
- daemon：実行の振り分けで、PR の作成の待ちなら（予算の確認の前に）`publish` する。PR を作ったら実装の提出（`StepSubmitted`）を同じ追記で
  記録する（`implementSubmitted`）。承認・差し戻し・PR の確認・戻し先の判断・マージの後の監視・見逃しの記録の `pr` を `implement` にした。
  工程のイメージの「PR作成は変えられない」の例外（`image.noImageStep`）を外した。オーケストレーターへの指示から PR作成を外した。
  実装の PR の本文の最後に、マージが実装の承認になることと指摘の伝え方を書く（要求要件・設計の PR とそろえた）。
- 古い記録：`SqliteActivityStore.purgeLegacyPrStepTasks` で、工程 `pr` を含むタスクと、つながったタスク（分割の親子・修正のタスクと元の
  タスク）を、起動時に作業履歴から消し、件数と ID をログに出す（`main.ts`）。削除を拒むトリガーは、同じトランザクションの中でだけ外す。
- 画面・通知：工程の名前から「PR作成」を外し、承認待ち・作業履歴・承認の画面・通知を「実装の承認」「実装の PR のマージ待ち」にそろえた（日本語・英語）。
  「成果物チェック」は、工程・承認の名前としては使わない（利用者向けの文書で、以前の版を説明するところだけに残した）。
- docs：仕様書（tasks-and-steps・approval・deployment-watch）、利用者向けの文書（tasks・config・images・notifications・deployment-watch）を
  日英で直した。処理中のタスクも消えることを、利用者向けの文書に書いた。ADR を足し、前の判断の ADR を5件置き換えにした。

## 確かめたこと

- `npm run lint`（終了コード 0）・`npm run typecheck`・`npm run build`・`npx vitest run`（72 ファイル・1567 件）・`npx vitest run tests/docs`
  （89 件）がすべて通った（main の #117・#118 を取り込んだ後）。
- 足した回帰テスト：
  - core（`projection.test.ts`）：工程 `pr` を読まない・検証に通っても実装の工程のまま PR を待ち、PR で承認待ち、マージで完了・検証の前の
    PR は受け付けない・一時停止と再開で待ちが残る・変更なしの判定・指摘の提出回。
  - daemon（`daemon.test.ts`）：工程に PR作成が無く、実装の工程の中で PR を作る順序・予算の上限に達しても PR を作る・PR の作成に失敗して
    再開すると実装をやり直さない・再起動の後に PR を作る・古いタスクを捨てれば起動できる。既存の PR作成のテスト（変更なし・テンプレート・
    ラベル・タスクブランチ・監視・戻し先・中止・子タスク）は、実装の工程で動くように直して通した。
  - `activity.test.ts`：消すタスク・一緒に消すタスク・残るタスク・2回目は何もしない・トリガーが戻る。
- 修正を戻すと落ちること：PR の作成の振り分けを外す（5件）、振り分けを予算の確認の後にする（予算のテスト）、つながったタスクをたどらない
  （`activity.test.ts`）、`StepKey` に `pr` を戻す（core のテスト）。
- 動作確認の動画：一時的な SACTY_HOME と、ポート 4890（デーモンの代わり）・4891（画面）・4893（PR の画面の代わり）で、本物の TaskService・
  API・画面に、偽のエージェント・git・GitHub・テストをつないで撮った。不具合の修正のタスクが 調査 → 再現 → 実装 と進み、実装の工程の中で
  PR ができ、「実装の PR のマージ待ち」になり、承認の画面（実装の承認）から PR を開いてマージすると完了する。
- 確かめていないこと：本物の GitHub での PR の作成とマージ（偽物で確かめた）。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| （DA のセルフレビュー）古い記録を捨てる処理で、分割の子だけを消すと親が子を待ち続け、修正のタスクだけを消すと元のタスクの記録から作り直される | つながったタスクを、どちら向きにもたどって一緒に消すようにし、テストを足した |

## 残したこと

- PR の作成の待ちの間の状態は「実行待ち」と出る（PR を作っている最中の専用の表示は足していない）。
