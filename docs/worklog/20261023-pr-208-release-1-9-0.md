# 版を 1.9.0 に上げる

- 日付: 2026-10-23（UTC）
- タスク: なし
- PR: #208
- ブランチ: claude/adoring-turing-l6j0rp
- 関係する ADR: [版は 1.0.0 から semver で付け、タグと GitHub Releases でリリースする](../adr/20261019-2345-semver-releases.md)

## 目的

1.8.0 の後に、機能の追加（PR #191〜#207）が入った。設定ファイルの形・台帳・コマンドの引数に互換性の無い変更は無い
（設定は `reviewMentionSelf`・`step_agents.gather`・`image_build.drawio`・`context.path` を足しただけで、作業履歴は
`InformationGathered` を足し、`TaskCreated` に任意の `plan` を足しただけ）ので MINOR を上げ、1.9.0 をリリースする。

ただし、次の2つは今までの設定のまま動きが変わるので、リリースの説明に「注意が要る変更」として書く。

- コンテキスト（PR #195）：`ref` の無いローカルのパスは、コミットした中身ではなく今の中身を読む。`extends` の `./`・`../` は、
  その層のディレクトリから解決する。git で取得した層の `extends` にローカルのパスを書くと止まる。`context.path` を書いた
  プロジェクトの定義は、それより前の版ではインポートできない。
- Node.js の下限（PR #193）：`engines.node` を `>=22.23.4` に上げた。

## 1.8.0 からの変更

- タスクの開始時に情報収集のエージェントが外部の情報を集め、すべての工程とゴールガーディアンに渡す。チケットのトリアージを兼ねる
  （PR #206・#207）
- 工程の組み合わせを成果物から選ばせ、タスクの作成時に進め方を指定できる（PR #198）
- テストが決まらずに止まったタスクを、人がテストを決めて再開できる（PR #201）
- 文書作成の工程にも、コンテキスト・外部 PF・MCP・GitHub の読み取りを渡す（PR #199）
- コンテキストにローカルのディレクトリとモノレポの中のディレクトリを使える（PR #195）。サブモジュールを取得する（PR #200）
- レビューの投稿のメンションを自分に切り替えられる（`reviewMentionSelf`。PR #197）
- タスクの一覧の絞り込み（PR #196）、gh のアカウントの一覧の読み直し（PR #194）、プロジェクトの削除（PR #204）
- イメージに作業用の CLI と draw.io の CLI を入れ、draw.io の公式のスキルを既定のスキルにする（PR #191）
- Node.js の下限を 22.23.4 に上げ（PR #193）、`.node-version`・`mise.toml` を足し、Next.js を 16.4.2・`ip-address` を 10.7.4 に上げる（PR #205）
- docs の書き直しと図（PR #192・#202・#203）
- 更新の後にすること：Node.js を 22.23.4 以上にし、`npm ci` で依存を入れ直し、既定のイメージの名前が `sacty-agent:1.9.0` に
  変わったので、`docker pull node:22-bookworm-slim` で元のイメージを取り直してから `npx sacty image build` で作り直す。

## したこと

- 4 つのパッケージとワークスペースの依存の版を `1.9.0` にし、`package-lock.json` の版の行も同じにした。手元の npm 10 では
  `npm install --package-lock-only` が版と関係の無い行（`libc`）まで消したので、1.8.0 のときと同じく版の行だけを直した。
- 既定のイメージの名前（`DEFAULT_IMAGE`）を `sacty-agent:1.9.0` にし、仕様書（`agent-execution`・`configuration`）・ユーザードキュメント
  （`config`・`images`）の日英と、イメージの名前を書いているテスト・コメントを同じ版にした。ゲートウェイの MCP クライアントの版の文字列も
  `1.9.0` にした。

### main で落ちていたテストを直す

- `apps/daemon/src/context.test.ts` の「実行全体の上限（30分）以上の時間切れは、警告を残す」が、main でも落ちていた。ユーザードキュメントの
  `context.md` に書いた実行全体の上限が、コードの定数（`AGENT_RUN_TIMEOUT_MS`）と同じかを確かめる部分で、PR #192 で文を書き直したときに
  （「既定は開始から30分の上限」→「既定は開始から30分で」）、テストの期待が追従していなかった。
- テストの期待を今の文（`既定は開始から30分で`・`既定ではどちらかを30分以上`）に合わせた。文書の数を変えると落ちることを確かめた。

## 確かめたこと

- `npm ci`・`npm run lint`・`npm run typecheck`：通過。
- `npx vitest run`：2584 件が通り、8 件（`agent-sessions.test.ts`・`context-mcp.test.ts`・`host-mcp-processes.test.ts`）が落ちた。
  1.8.0 のときと同じく、この作業の環境（クラウドのコンテナ）によるもの。
- `rg 1.8.0` で、ADR・作業履歴と、`package-lock.json` のほかのパッケージの版のほかに、`1.8.0` が残っていないことを確かめた。
