# タスクの作成のダイアログで、書きかけを失わないようにする

- 日付: 2026-11-21（UTC）
- タスク: PBI-427
- PR: #472
- ブランチ: sacty/task-b10b5735
- 関係する ADR: なし

## 目的

「タスクを作成」のダイアログを閉じても、書きかけの題と内容を失わないようにし、内容の欄を広げる。

## したこと

- 書きかけの題・内容を、`NewTaskDialog` の状態に持つ（閉じると欄は外れるが、この部品は残る）。開き直すと、欄の初期値に戻す。確認のダイアログは足していない。
- 部品は、提案から開くものとふつうのものが別で、プロジェクトごとに `key` で作り直すので、書きかけは混ざらない。提案から開くものは、最初に提案の題・内容が入る。
- 作成に成功すると、`redirect` の例外を `unstable_rethrow` で投げ直し、Next.js が画面を移して部品を作り直すので、空に戻る（自前の判定・空にする処理は持たない）。失敗したときは残す。作成の処理が `redirect` 以外の例外で失敗したときは、投げ直さず理由（`createFailed`、日英）を返して残す（エラー画面でこの部品ごと外れ、書きかけを失わないため）。
- 内容の欄は、12 行分の高さ以上で縦に広げられるようにし、ダイアログの幅は広い画面で 768px（`min(48rem, 100% - 2rem)`）にした。スケジュールタスクの欄は変えていない（`bodyClassName` で分けた）。
- 下書きは、ブラウザーのメモリーにだけ持つ。再読み込みの後は残さない（秘密を含みうる依頼文を、保存の場所に置かないため）。
- 仕様書・利用者向け文書（日英）と、スクリーンショット（`new-task`・`new-task-steps` の日英）を直した。

## 確かめたこと

- 4つの閉じ方のそれぞれ、空のとき（4つの閉じ方すべて）、`redirect` の例外が届くこと、失敗の後、action が reject したとき、自動の更新（同じ `key` で props が変わる）、「工程ごとに設定」の往復、提案とふつうの混ざり、プロジェクトごとの分けを、`new-task-draft.test.ts` で確かめた。
- `npm run lint`・`npm run typecheck`・`npm test`（`tests/docs` を含む）を実行し、通った。
- `new-task`・`new-task-steps` の画像は、ブラウザーを一時的に入れて撮り直した（この環境だけの結果。入れた道具は撮影の後に消した）。
- 人が実機で確かめた結果：作成に成功すると詳細へ移り、一覧へ戻って開き直すと空。1440px で幅 768px・内容欄 12 行、700px で左右 16px、375px で収まる。スケジュールのダイアログの内容欄は変更前と同じ。一覧から詳細へ移って戻ると、書きかけは残っていることがある（文書は「確実に消えるのは再読み込みとブラウザーを閉じたとき」と書く）。
- 確かめていないこと：なし（この環境のブラウザーでは見ていない。上は人の確認）。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| 作成が例外で失敗すると書きかけが消える | `redirect` 以外の例外は理由を返して残す。action が reject するテストを足した |
| 成功の検出が 2 経路 | `digest` の 1 経路に絞り、テストの `redirect` を例外を投げるものにした |
| 消える条件の案内が足りない | 利用者向け文書（日英）と仕様書に、画面を離れたときを足した（のち、実機の確認で逆と分かり、下の人の指摘の行で直した） |
| 文言が 3 文・画面の更新を先に勧める・文書の「離れると消える」・英語の仕様書・テストのモック・PR の本文（人の指摘） | 文言を日英とも 2 文にし、「もう一度試し、直らないときは入力を写してから更新する」順にした。文書（日英の利用者向け・日英の仕様書）は、確実に消えるのは再読み込みとブラウザーを閉じたときで、ほかの画面から戻ると残ることがあるが約束しない、に直した。英語の仕様書に書きかけの項目を足した。テストは本物の `redirect`・`unstable_rethrow` を使う形にした。PR の本文は、画像 4 枚を撮り直した旨に合わせた |
| 作業履歴がひな形と違う | PR・ブランチ・節を足した |
| 成功後の空への戻りをテストで確かめられない（2 回目） | 自前の `digest` 判定と空にする処理をやめ、`unstable_rethrow` に任せた。成功のテストは、子を作り直す境界の下で、開き直した欄が空であることを確かめる。投げられる値の種類（`Error`・文字列・`null`・`undefined`・オブジェクト）ごとに、書きかけが残るテストを足した |
| 例外のときの文言が更新を先に勧める（人の指摘） | 日英とも「もう一度試し、直らないときは入力を写してから更新する」順に直した |
| 幅 640〜767px・内容欄の枠線 2px | 幅を `min(48rem, 100% - 2rem)`、最小の高さに `+2px` |
| テスト不足・lint の info | 自動の更新・工程ごとの設定の往復・空の 4 経路を足し、`closers` の参照を直した |
