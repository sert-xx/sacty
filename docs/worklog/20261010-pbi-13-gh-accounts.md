# GitHub へのアクセスを、ホストの gh とプロジェクトごとのアカウントで行う

- 日付: 2026-10-10（UTC）
- タスク: PBI-13
- PR: #18
- ブランチ: feat/issue-13-gh-accounts
- 関係する ADR: [GitHub へのアクセスは、ホストの gh にログイン済みのアカウントからプロジェクトごとに必ず選んだもので行い、config.yaml のトークンの設定は削除する](../adr/20261010-2314-superseded-github-access-via-gh-accounts.md)

## 目的

動作確認のフィードバックへの対応。GitHub のトークンを config.yaml に1つしか持てず、複数のアカウントを切り替えて使うと使いづらかった。
ステークホルダーと決めた方針（ホストの gh のアカウントを使う・プロジェクトごとに必ず選ぶ・トークンの旧設定は削除する）に従う。

- プロジェクトに選んだアカウントの認証で GitHub にアクセスする。
- プロジェクトの設定画面で、ログイン済みのアカウントから必ず選ぶ。
- config.yaml のトークン（`token_secret`）を削除する。
- トークンを台帳・ログ・画面・コンテナに出さない。
- HTTPS の URL で、ホストの git の認証の設定に頼らずにプッシュできる。

## したこと

- gh の呼び出し：`apps/daemon/src/gh.ts`（アカウントの一覧・`--user` を付けたトークンの取り出し、`GH_TOKEN` を渡さない）。
- サービス・リポジトリ：`apps/daemon/src/service.ts`・`apps/daemon/src/repository.ts` で、プロジェクトのアカウントのトークンを使って clone・プッシュ・ブランチの削除・PR の操作をする。
  アカウントを選んでいなければ `github.accountRequired` で止める。
- 取り込み：`apps/daemon/src/intake.ts` で、取り込み元のプロジェクトのアカウントごとに検索する。
- API：`GET /api/github/accounts`（`apps/daemon/src/server.ts`）。
- 画面：プロジェクトの設定（`apps/web/src/components/project-editor.tsx`）にアカウントの選択を足した。ログアウトしていれば「gh にログインしていません」、
  gh が無いなどで読めなければ理由を出す。
- プロジェクトの定義（`packages/core/src/projects.ts`）にアカウントを足し、エクスポートには含めない。
- config.yaml の `token_secret` を設定の形（`apps/daemon/src/config.ts`）・ひな形・`README.md` から削除し、関係する文言のコードを削除した。
- レビューの対応で、コンテキストリポジトリと継承先の取得（`apps/daemon/src/context.ts`）にも、プロジェクトのアカウントの認証を渡すようにした。

## 確かめたこと

- `npm test`：214件が通った。gh の呼び方（アカウントの一覧でトークンを求めない・必ず `--user`・`GH_TOKEN` を渡さない・gh が無い・ログインしていないときの理由）、
  取り込みがアカウントごとに行われること（使うトークン・アカウントの未選択・失敗・レート制限の分け方）、プロジェクトのアカウントで clone を認証すること、
  アカウントを選んでいなければアクティブなアカウントを使わずに止まること、ログインしていなければ止まること、アカウントの一覧の API、エクスポートにアカウントを
  含めないことを確かめた。アクティブなアカウントで代わりにアクセスするようにすると、テストが失敗することも確かめた。レビューの対応の後は216件が通った。
- 実物の gh と GitHub（テスト用のリポジトリ）で確かめた。
  - アクティブでないアカウントのトークンで、HTTPS の clone ができた。
  - `git push --dry-run` が、トークンを渡すと通り、渡さないと認証できずに失敗した（dry-run なので GitHub は変わっていない）。
  - レビューの対応の後、アクティブでないアカウントのトークンで、`GitContextFetcher` が HTTPS の GitHub から取得できた。
- 画面で確かめた。
  - 選択肢はログイン済みの2つのアカウントだけで、「アクティブなアカウント」という選択肢は無い。
  - 未設定の既定のプロジェクトは、最初の選択がアクティブなアカウントになる。
  - テスト用のプロジェクトは、保存したアカウントのまま。そのアカウントで、エラーなく取り込めた。
- レビューでは `npm test`・`npm run lint`・`npm run typecheck`・画面の本番のビルド・`git diff --check` が通ったことを確かめ、偽の git で、`GitContextFetcher` が clone に
  認証の環境変数を渡し、コマンドの引数には含めず、rev-parse には渡さないことを確かめた。実際の GitHub の認証とブラウザの操作は、レビューでは確かめていない。

## レビューの指摘と対応

| 指摘 | 対応 |
| --- | --- |
| P2：選んだアカウントの認証が実装のリポジトリにだけ使われ、コンテキストリポジトリとその継承先の clone はホストの git の認証のままなので、別のアカウントで認証されるか、取得に失敗する | `ContextFetcher.fetch` に git の認証の環境変数を渡せるようにし、継承の各リポジトリごとに認証を求めるようにした（HTTPS の GitHub はプロジェクトのアカウントのトークン、ローカルのパスや SSH はホストの認証）。未選択なら取得せずに `github.accountRequired` で止め、取得の失敗の記録からトークンと認証の値を取り除く。回帰テストを足し、認証を渡すのをやめると失敗することを確かめた |
