# 既定のプロジェクトをやめ、プロジェクトが無ければ作成画面だけを出す

- 日付: 2026-10-11（UTC）
- タスク: PBI-22
- PR: #28
- ブランチ: feat/issue-22-no-default-project
- 関係する ADR: [既定のプロジェクトをやめ、プロジェクトが1つも無いときは最初のプロジェクトを作る画面だけを出す](../adr/20261011-1331-no-default-project.md)

## 目的

既定のプロジェクト（デフォルト）をやめる。デーモンは起動時にプロジェクトを作らず、タスクの作成にはプロジェクトの指定を必須にする。プロジェクトが1つも無いときは作成画面だけを出し、ほかの画面には移れないようにする。作ったらそのプロジェクトの画面に進む。表示するプロジェクトが無い・消えているときは最初のプロジェクトを出す。

## したこと

- デーモン：起動時に既定のプロジェクトを作らない（`apps/daemon/src/service.ts`）。タスクの作成で `CreateTaskInput.projectId` を必須にした。
- 画面の共通の枠（`apps/web/src/app/layout.tsx`）：`ProjectGate`・`RailGate`・`AppHeader` の3か所で、プロジェクトが無いときは「最初のプロジェクトを作る」画面（新規作成とインポート）だけを出し、サイドメニュー・ヘッダーの切り替え・お知らせを出さない（`apps/web/src/components/shell/project-gate.tsx`）。
- 作成とインポートの後に `revalidatePath("/", "layout")` で枠を作り直す。画面を移っても共通の枠は作り直されず、作成画面が残ってしまうため。
- 表示するプロジェクト：cookie が無い・消えているときは最初のプロジェクトにし、「default」の ID を特別扱いしない（`apps/web/src/lib/project-select.ts`）。サイドメニューの「設定」（`/projects/current`）も同じ規則で移り先を決める。

## 確かめたこと

- テスト：290件が通った。プロジェクトが無いときの画面（作成とインポートだけ、サイドメニューとヘッダーの切り替えを出さない、プロジェクトがある・デーモンにつながらないときはそのまま）、既定のプロジェクトを作らないこと、プロジェクトを指定しないとタスクを作らないこと、表示するプロジェクトの選び方を足した。
- 次の修正を外すと、それぞれテストが失敗することを確かめた：ゲート、サイドメニューを隠す、ヘッダー、既定のプロジェクトを作らない、`default` を特別扱いしない。
- リント・型チェック・ビルドが通った。
- 空のデータで起動して画面を確かめた：`/tasks/abc` などを開いても作成画面だけが出た。作成すると、プロジェクトの画面とサイドメニューが出た。タスクの一覧と「設定」が、作ったプロジェクトで出た。
- レビューで、全290件のテスト・lint・typecheck が通った。レビューでは、ブラウザでの画面操作とビルドは行っていない。

## レビューの指摘と対応

指摘は無かった（承認のみ）。

## 残したこと

- すでに作られている「デフォルト」のプロジェクトは、普通のプロジェクトとして残る。
