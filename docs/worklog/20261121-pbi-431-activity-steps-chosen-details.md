# 作業履歴の「工程を決定」「作業するリポジトリを選んだ」を、短い行と「詳細」に分ける

- 日付: 2026-11-21（UTC）
- タスク: PBI-431
- PR: なし
- ブランチ: なし
- 関係する ADR: なし

## 目的

この 2 つの行は、理由をすべて 1 行につないで千数百字になることがあり、流し読みしにくかった。行は選んだ結果の名前だけにし、理由は「詳細」を開いて読めるようにする。

## したこと

- `apps/web/src/lib/labels.ts`：`StepsChosen` の行は、工程の並び・イメージ（と決めた元）・書き出し先・サービス・飛ばす工程の名前だけを出す。理由は見出し付きで 1 件ずつ改行し、`detail` に入れる。`RepositoryChosen` はリポジトリ（人が選んだときは「（人間）」）だけを行に出し、理由を `detail` に入れる。理由が無い記録は `detail` を持たない。費用不明の印は行の末尾に残す。
- `apps/web/src/components/task-detail.tsx`：右の列の「最近の作業履歴」（`compact`）は、どの行も 2 行までで省略し、「詳細」を出さない。
- 文言は `apps/web/src/i18n/messages/labels.ts`（日英）。
- `docs/spec/ui-wording`（日英）・`docs/spec/approval`（日英）・`docs/user/tasks`（日英）に、出し方を足した・直した。
- `sacty mcp`・エラーレポートの文と、作業履歴の記録は変えていない。

## 確かめたこと

- `apps/web/src/lib/labels.test.ts`・`apps/web/src/components/event-text.test.ts`：日英で、千字を超える理由でも行が変わらないこと、理由が無い記録に「詳細」が出ないこと、右の列に「詳細」が出ないこと、費用不明の印、イメージを決めた元が行に残ること。
- 検査（フォーマッター・リンター・型チェック・テスト全件）は、提出の前に実行した（結果は PR の説明）。
- スクリーンショット（`docs/user/images/task-detail*.png`）は、この環境にブラウザが無く、撮り直していない。
- 詳細を開いたまま自動更新されても閉じないこと、375px・暗い配色でのはみ出しは、実画面で確かめていない。
