# 監査を見る

監査は、完了したタスクの過程を、工程の判断から完了まで調べます。差し戻し・指摘・エージェントの試行錯誤の原因を探し、
それを防ぐための改修（コンテキスト・スキル・エージェントのルール・リンター・テストなど）を提案します。提案を採用すると、
改修のタスクを作ります。

> いまの版の監査は、画面だけです。監査のデータはモックで、`SACTY_AUDIT_MOCK=1` を付けて起動したときだけ出ます。
> 付けずに起動したときは、監査の欄と画面に「まだ監査はありません。」と出ます。

```sh
SACTY_AUDIT_MOCK=1 npx sacty up
```

モックでは、プロジェクトの完了したタスクに、監査のいろいろな状態を割り当てます。採用・却下・再開はデーモンのメモリにだけ残り、
sacty を起動し直すと戻ります。

## タスクの詳細の監査の欄

完了したタスクの詳細に「監査」の欄が出ます。

| 項目 | 出すもの |
| --- | --- |
| 状態 | 監査待ち・大まかな監査中・深掘り中・監査済み・監査の失敗・予算で一時停止 |
| 費用 | 監査に使った費用と上限です。監査の予算は、タスクの予算とは別です |
| 大まかな監査 | 経緯の要約と、根拠になった出来事（人の差し戻し・PR の指摘・一時停止・やり直し・ツール呼び出しの失敗・エスカレーション）の件数 |
| 懸念のある工程 | 大まかな監査が挙げた工程と、工程ごとの深掘りの結果 |
| 原因と改修の提案 | 原因・根拠・提案。根拠の「作業履歴」「ログ」から、その行と実行のログへ移れます。改修の後にまた見つかった原因には「再発」が付きます |

予算で一時停止した監査は、欄の中で新しい上限（使った額より大きい額）を入れて再開します。

## 提案を採用・却下する

判断待ちの提案には、宛先の選択と「採用する」「却下する」が出ます。

- 宛先は、対象リポジトリ・コンテキスト（プロジェクトの層、または上位の層）・sacty の既定のコンテキスト（ゴールガーディアンの
  プロンプトと既定のスキル）から選びます。監査が選んだ宛先が初めから選ばれています。
- 「採用する」を押すと、選んだ宛先に対する改修のタスクを作ります（モックでは作らず、作ったことにします）。
- 「却下する」を押すと理由の入力が出ます。理由は必須です。理由は以後の監査に渡し、同じ提案を繰り返さないために使います。
- 一度判断した提案は、変えられません。

## 監査の画面

サイドメニューの「監査」から、表示しているプロジェクトの監査の画面（`/projects/<ID>/audit`）を開きます。

- **原因**：タスクをまたいで同じ原因をまとめたものです。状態（再発・提案あり・採用・改修済み・却下）、見つかった回数、該当する
  タスクを出します。再発を先に、目立たせて出します。
- **改修の提案**：判断待ちを先に出します。どのタスクの監査で出た提案かも出し、ここからも採用・却下できます。
- **監査したタスク**：状態・差し戻しと指摘の件数・費用・監査の完了の時刻です。
- **レポート**：開始日と終了日を選んで「レポートを出力する」を押すと、期間に完了した監査の原因・提案・判断を Markdown のファイルで
  ダウンロードします。見出しは画面の言語で、監査の結果の文は訳しません。日時は UTC です。

監査の結果は、プロジェクトをまたいでまとめません。

## ダッシュボード

ダッシュボードの「監査」の欄に、プロジェクトごとの原因・再発・判断待ちの件数と提案の採用率、週ごとのタスクあたりの差し戻し・指摘の
件数を出します（[ダッシュボード](dashboard.md)）。プロジェクトの名前を押すと、その監査の画面に移ります。

## 予算

1回の監査の予算の既定の上限は、config.yaml の `budget.default_per_audit_usd`（既定 $1）です（[config.yaml の設定](config.md)）。
