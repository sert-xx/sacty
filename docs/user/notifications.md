# 通知（Slack・デスクトップ）

人間の出番（承認待ち・エスカレーション・一時停止）とタスクの完了を、Slack と、ブラウザーのデスクトップ通知で知らせます。
どちらも画面の「Sacty の設定」（ユーザーメニュー）で設定し、それぞれ On/Off を切り替えられます。
デスクトップ通知は [デスクトップ通知](#デスクトップ通知) を見てください。

## Slack の通知

「Sacty の設定」の「Slack の通知」で、送り方と言語（日本語・英語。既定は日本語）を選び、保存します。
設定しなければ通知しません。

通知先は1つです。
すべてのプロジェクトのタスクを、その送り先に通知します。
プロジェクトの設定には、通知の項目はありません。

**設定する前に、その送り先（チャンネル）を見る人が、すべてのプロジェクトの通知を受け取ってよいかを確かめてください。**
通知には、プロジェクトの名前・タスクの題名とリンクが入り、通知の種類によっては工程の名前も入ります。
以前のようにプロジェクトごとに送り先を分けることはできません。
見る人の範囲が違うプロジェクトの通知も、同じチャンネルに流れます。

### 送り方

- Slack API（chat.postMessage・Slack Proxy）
  - 送り先の URL（`https://slack.com/api/chat.postMessage` や、認証の要らない Slack Proxy）とチャンネルを書きます。
  - トークンが要るなら、秘密情報の名前か 1Password の参照を書きます（Proxy なら空にします）。
  - 送り手の名前は `Sacty`、アイコンは [assets/sacty-icon.png](../../assets/sacty-icon.png) です（`icon_url` で、このリポジトリの公開の画像を指します）。
    Slack のアプリのボットのトークンに `chat:write.customize` の権限が無いと、Slack はこの指定を無視し、アプリの名前とアイコンで出します。
- Incoming Webhook
  - Webhook の URL を、秘密情報の名前か 1Password の参照で書きます（URL そのものが秘密のため）。

### メンション（任意）

メンションする相手と、メンションする通知の種類を選びます。
メンションはどちらの送り方でも効き、本文の先頭に付きます（テストの通知にも付きます）。
設定しなければメンションしません。

- 相手は ID で書きます（Slack は @表示名では届きません）。
  カンマか空白で区切って、20件まで書けます。

| 相手 | 書くもの | 本文での形 |
| --- | --- | --- |
| ユーザー | メンバー ID（`U…`・`W…`。Slack のプロフィールの「メンバー ID をコピー」） | `<@U…>` |
| ユーザーグループ | ID（`S…`） | `<!subteam^S…>` |
| here | `@here` | `<!here>` |
| channel | `@channel` | `<!channel>` |

- 種類は、承認待ち・エスカレーション・一時停止・完了から選びます。
  既定は人の出番（承認待ち・エスカレーション・一時停止）だけで、完了はメンションしません。

### 通知の中身と失敗

- 1行目には、`[プロジェクトの名前]` とタスクへのリンクが入ります（どのプロジェクトのタスクかがわかります）。
- 2行目には、どの工程の通知かが入ります。
  - 例：「設計の承認を待っています」「実装で一時停止しました（予算の上限）」「要求要件でエスカレーションしました。判断してください」
  - 完了の通知と、工程を決める前の一時停止（「工程を決める前に一時停止しました」）には、工程の名前は入りません。
- 承認の窓口（PR で承認する工程は PR も）へのリンクも入ります。
- 人間が自分で一時停止したときは通知しません。
- 送れなかったときは、タスクを止めずに、理由を警告として出します。
  次に送れたら消えます。
  警告が出る場所は次のとおりです。
  - ダッシュボード（「Sacty の設定」へのリンクつき）
  - 「Sacty の設定」の「Slack の通知」の区画
  - タスクの一覧の画面（sacty 全体の警告なので、どのプロジェクトの一覧にも出ます）
- 「Sacty の設定」の「テストの通知を送る」で、送れるかを確かめられます（保存してから送れます）。

### Slack の通知を止める

送り方を選ぶと「Slack に通知する」のチェックボックスが出ます（既定は On）。
チェックを外して保存すると、送り先・メンションなどの設定を残したまま、Slack に送らなくなります。
もう一度チェックを付けて保存すると、同じ設定で送り始めます。

- Off の間は、送れなかったときの警告も出ません。
- Off の間も、「テストの通知を送る」で送れるかを確かめられます。
- 設定ごと消したいときは、送り方で「通知しない」を選んで保存します。

### 以前の sacty から使っている場合

以前の sacty では、通知をプロジェクトごとに設定していました。
プロジェクトに設定していた通知は使わなくなり、移しません。
「Sacty の設定」で、通知先を設定し直してください（設定するまで通知しません）。

## デスクトップ通知

Slack と同じ通知（承認待ち・エスカレーション・一時停止・完了）を、ブラウザーのデスクトップ通知でも出せます。
Slack の通知を設定していなくても、Off にしていても使えます。

1. 「Sacty の設定」の「デスクトップ通知（このブラウザー）」で、「このブラウザーでデスクトップ通知を出す」にチェックを付けます。
2. ブラウザーが通知の許可を求めたら、許可します。
3. 「テストの通知を出す」で、通知が出るかを確かめます。

- 設定はブラウザーごとです。
  切り替えるとすぐに効き、保存は要りません。
  ほかのブラウザーやコンピューターでも使うときは、そこでもチェックを付けます。
- 通知が届くのは、Sacty の画面をどれかのタブで開いている間だけです（ほかのタブやアプリを使っていても届きます）。
  画面を閉じていた間の通知は、後から出ません。
- 通知には、タスクの題名と、`[プロジェクトの名前]` と通知の種類が入ります。
  押すと、そのタスクの画面を開きます。
- 同じブラウザーで Sacty の画面を複数のタブで開いていても、通知は1回だけ出ます。
- ブラウザーは、隠れたタブの動きを間引くことがあるので、通知が少し遅れることがあります。
- 次のときは使えません。
  - `https` でも `localhost`（`127.0.0.1`）でもない URL で画面を開いたとき（ブラウザーの制限です）。
  - ブラウザーで通知を拒否したとき。
    ブラウザーのサイトの設定で通知を許可してから、もう一度チェックを付けてください。
  - OS の設定で、ブラウザーの通知を止めているとき。
