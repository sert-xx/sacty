# 秘密情報（キーチェーン・1Password）

トークンや API キーは、設定ファイルには名前（または 1Password の参照）だけを書き、値はキーチェーンか 1Password に置きます。
sacty は値をコマンドライン・作業履歴・ログ・画面に出しません。

## キーチェーンに保存する

秘密情報の値は、名前を付けてキーチェーンに保存し、設定ファイルにはその名前を書きます。

1. 付ける名前を決めて、次のコマンドを実行します（例の名前は `claude-oauth-token`）。

   ```sh
   npx sacty secret set claude-oauth-token
   ```

2. `security` コマンドが値をたずねるので、入力します。
   入力は表示されず、確認のため2回たずねます。
3. 設定ファイルに、その名前を書きます（例 `secret: claude-oauth-token`）。

名前と保存には、次の決まりがあります。

- 名前に使えるのは英数字と `.`・`_`・`-` だけです。
- 同じ名前があれば上書きします。

## 1Password

1Password に保存した秘密情報は、名前の代わりに参照（`op://保管庫/アイテム/フィールド`）を書きます。
sacty は 1Password CLI（`op`）で値を取り出すので、先に `op signin`（または 1Password のアプリとの連携）でサインインしておいてください。

参照は、秘密情報を書くすべての所で使えます。
たとえば次の所です。

- `providers` の認証
- `gateway.platforms`・`gateway.mcp_servers`
- コンテキストリポジトリの `mcp.yaml`・`platforms.yaml`
- 「Sacty の設定」の Slack の通知先
- npm のトークン

次の例は、`providers` の認証に参照を書いています。
複数の 1Password のアカウントにサインインしているときは、例のように、使うアカウントを `onepassword.account` に書きます。

```yaml
providers:
  codex:
    auth: { mode: api-key, secret: "op://Work/OpenAI/api-key" }
    available_models:
      gpt-6.1-terra: { input: 1, cached_input: 0.05, output: 5 }
# 複数の 1Password のアカウントにサインインしているときは、使うアカウントを書く
onepassword:
  account: acme.1password.com
```

取り出した値の扱いと、取り出せなかったときの動きは、次のとおりです。

- 取り出した値は、デーモンが動いている間だけメモリーに持ちます（ディスクには書きません）。
  同じ参照で何度も問い合わせません。
- サインインしていない・参照先が無いときは、sacty は、どの参照かと理由を記録して、タスクを止めます。
  サインインしてから再開すると、取り出し直します。

## 起動のときに取り出すもの

`sacty up` は、起動のときに、使う秘密情報を次の所からまとめて取り出します。

- 使うエージェントの `providers` の認証
- `gateway.platforms` の認証（`auth.secret`・`auth.token.secret`）
- `gateway.mcp_servers` の環境変数
- 「Sacty の設定」の Slack の通知先
- プロジェクトのコンテキストリポジトリの `mcp.yaml`・`platforms.yaml`

取り出し方は、次のとおりです。

- 1Password の参照は1回の `op run` で取り出すので、認証は起動のときの1回だけです。
- キーチェーンの秘密情報は、取り出せるかを確かめます（使うたびに取り出します）。
- コンテキストリポジトリの秘密情報は、プロジェクトごとにコンテキストを取得して集めます（`extends` で継承した上の層も含みます）。
  取得は最長 30 秒まで待ちます。
  取得できなかったプロジェクトは、画面の警告にその理由を出します（その秘密情報は、使うときに取り出します）。

取り出せなかったものがあっても、起動は止めません。

- sacty は、起動のときに取り出せなかったものについて、画面の警告と端末に、どの設定かと理由を出します。
- 用意してから、画面の「Sacty の設定」の「秘密情報を取り出し直す」を押してください。
  - 取り出し直すと、コンテキストも取得し直します。
  - 読めなかったコンテキストがあると、結果に、その中の秘密情報は確かめていないことを出します。

次のものは、起動のときには取り出しません。

- イメージの作成だけで使う npm のトークン（使うときに取り出します）
- GitHub のトークン（使うたびに `gh` から取り出します）

## プロジェクト・Sacty の設定を保存したときに取り出すもの

設定を保存したときも、sacty は、その設定で使う秘密情報を取り出します。

- プロジェクトの設定を保存したとき（新しく作ったとき・インポートしたときも）は、そのプロジェクトのコンテキストの秘密情報をまとめて取り出します。
  まだ取り出していない参照があるときだけ、1Password の認証を求めます。
- 「Sacty の設定」を保存したときは、Slack の通知先の秘密情報（トークン・Webhook の URL）を取り出します。
  まだ取り出していないときだけ、1Password の認証を求めます。

どちらのときも、保存は止めません（取り出すのを待たずに保存を終えます）。
取り出せなかったものは、画面の警告に出します。

## 後からコンテキストに足した秘密情報

起動の後にコンテキストリポジトリに足した秘密情報は、前もって取り出していません。
sacty は、コンテキストリポジトリを使うたびに、最新を取得するためです。

- 足した秘密情報は、使うとき（工程の実行・チケットのトリアージ・外部 PF の呼び出しなど）に取り出します。
  このときに 1Password の認証を求めます。
- 前もって取り出しておくには、コンテキストリポジトリを変えた後に、次のどちらかをしてください。
  - 「秘密情報を取り出し直す」を押す。
  - プロジェクトの設定を保存し直す。
