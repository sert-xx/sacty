# ユーザードキュメント

sacty を使う人が、設定やコマンドをどう使えばよいかを理解するためのもの。
方針は [docs の入口](../README.md) を参照。

## ファイルの分け方

- 利用者の目的の単位で1ファイルにする（例 `getting-started.md`（はじめに）・`project-settings.md`・`context.md`・
  `gateway.md`・`notifications.md`・`cli.md`・`troubleshooting.md`）。
- ファイル名は英小文字・数字・`-` だけ。日時は付けない。
- このファイルの「目次」に、すべてのユーザードキュメントへのリンクを、読む順に並べる。
- リポジトリの [README](../../README.md) からは、この目次（または各ファイル）へリンクする。README に中身を重ねて書かない。

## 書き方の規則

- 利用者がすること（手順）と、その結果を書く。内部の仕組みは書かず、必要なら仕様書へリンクする。
- 設定の項目・既定値・コマンドのオプションは、コードと照合してから書く。名前はコードのまま（`default_agent` など）。
- 例の値は架空のもの（`example.com`・`acme`）にし、秘密の値は書かない。
- 対応するコードの場所は、利用者には見せず、ファイルの先頭の HTML コメントに書く（直すときに照合する場所がわかるように）。

  ```markdown
  <!-- 対応するコード: packages/cli/src/index.ts、apps/daemon/src/<ファイル>.ts -->
  ```

- 利用者に見える変更（設定・コマンド・オプション・画面・既定値・エラーの文言）をする PR では、同じ PR で直す。
