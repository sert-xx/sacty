# マージの後の監視（CI/CD とデプロイ）

sacty のタスクの実装の PR がマージされたら、マージでできたベースブランチのコミットの CI/CD が通ったか、デプロイされたアプリが動いているかを
sacty が見届け、失敗していたら修正のタスクを自動で登録します。

## 使う

1. プロジェクトの設定の「マージの後の監視」で、チェックを付けて保存します（既定は Off。Off のプロジェクトでは何もしません）。
2. デプロイ後のアプリも確かめたいときは、対象のリポジトリにデプロイの確認のスキル `deployment-observer` を置きます（下の「スキル」）。
   置かなければ、CI/CD だけを見ます。

- プロジェクトの GitHub のアカウントに、対象のリポジトリの Actions とチェックを読む権限が要ります。
- 見るのは、sacty のタスクの実装の PR（成果物チェック）のマージだけです（要求要件・設計の PR、人が作った PR は見ません）。

## 何をするか

1. マージのコミットの CI/CD（GitHub Actions のワークフローの実行・ほかのアプリのチェック・コミットの状態）を、1分ごとに確かめます。
   - 5分たっても1つも現れなければ、CI/CD が無いとして監視を飛ばします。
   - 60分たっても終わらなければ、時間切れで終えます（修正のタスクは作りません）。
   - `cancelled`・`skipped`・`neutral` は失敗とみなしません。
2. CI/CD が失敗したら、修正のタスクを登録します。本文には、元のタスク・PR・コミット・失敗したワークフローとジョブ・実行へのリンクと、
   ジョブのログの末尾（秘密情報を伏せたもの）が入ります。
3. CI/CD が通り、スキルがあれば、エージェントがスキルに従ってデプロイの完了とデプロイ後のアプリの状態を確かめます。エラーになっていれば、
   確認の結果と根拠を入れた修正のタスクを登録します。判断できなかったときは、修正のタスクを作らずに飛ばします。

修正のタスクは、ふつうのタスクとして進みます（そのマージでも、同じく監視します）。

## スキル

- 原本を `.agents/skills/deployment-observer/SKILL.md` に置き、Claude Code 用の `.claude/skills/deployment-observer` は原本への
  シンボリックリンクにします（どちらか一方だけでも使います）。
- タスクのテンプレート「Sacty セットアップ」で、このスキルを作る PR をエージェントに作らせることもできます
  （[タスクを進める](tasks.md#テンプレートsacty-セットアップ)）。
- リポジトリの外を指すシンボリックリンクは、安全のため使いません（スキルが無いものとして扱い、理由を画面に出します）。
- 何を「デプロイの完了」とみなすか、アプリにどうつなぐか（プロジェクトのコンテキストの外部 PF・MCP サーバー）は、スキルに書いてください。
  エージェントには、マージのコミットのコードの使い捨ての写しと、プロジェクトのコンテキストが渡ります。
- エージェントには、確かめるだけで何も変えないこと、最後に結果（`healthy`・`unhealthy`・`unknown`）・要点・根拠を答えることを指示します。
- 確認に使う AI は、`config.yaml` の `step_agents.deployment`（書かなければ `default_agent`）です。

```yaml
step_agents:
  deployment: luna-low
```

## 費用と予算

- デプロイの確認の費用は、元のタスクの費用に入ります（工程ごとの費用の表の「デプロイの確認」）。CI/CD の監視は AI を使いません。
- 予算の上限に達していたら、デプロイの確認を実行せずに飛ばします（タスクは止めません）。

## 二重の登録と上限

- 同じ失敗（同じリポジトリで同じワークフロー・ジョブ、デプロイの確認ならリポジトリ）の修正のタスクが終わっていなければ、新しく作りません
  （画面に、そのタスクへのリンクを出します）。
- 修正のタスクのマージでまた失敗すると、次の修正のタスクを作ります。元のタスクから3段（`MAX_FIX_CHAIN`）を超えては作りません。そのときは人が
  確かめてください。

## 画面で見る

- 元のタスクの詳細の「マージの後の監視」に、状態（待っている・通った・失敗・飛ばした・時間切れ）・理由・コミット・CI/CD の実行とチェック・
  失敗したジョブとログ・デプロイの確認の結果・修正のタスクへのリンクが出ます。待っている間は自動で更新します。
- 修正のタスクの詳細の先頭に、元のタスクへのリンクが出ます。
- 作業履歴にも、監視の開始・CI/CD の結果・デプロイの確認・修正のタスクの登録（作らなかった理由）が残ります。

## デーモンを再起動したとき

- CI/CD を待っている監視は、そのまま続きます（60分の上限は監視を始めた時刻から数えます）。
- デプロイの確認の途中で止まったら、確かめられなかったとして飛ばします（やり直しません）。
