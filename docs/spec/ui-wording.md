# 画面の文言と補足

画面の文言は、本文（常に見える文）と補足（印にマウスを乗せると出るツールチップ）に分けて持つ。
本文は「いま何が起きているか」と「次に何をするか」だけにする。
仕組み・理由・頻度や上限の数値・設定ファイルの場所・用語の定義は補足に書く。
文言は日本語と英語の辞書で持ち、辞書の文字列が規則から外れていないことをテストで確かめる。

関係する ADR: [画面の文言を本文と補足に分け、仕組みの説明はツールチップで出す](../adr/20261016-1244-ui-wording-body-and-hints.md)

## 本文の規則

- 画面の製品名は、日本語・英語ともに Sacty と書く。
  ヘッダー・ブラウザーのタイトル・入り口・履歴・エラーにも適用する。
  コマンド・設定キー・Cookie・ラベル名・パスなどの識別子は大文字に変えない。
- 本文に書くのは、いま何が起きているかと、次に何をするかだけ。
  仕組み（どう動くか）・理由・頻度や上限の数値・設定ファイルの場所・用語の定義は、補足に移すか、書かない。
- 1つの文言は1文。
  見出し・ラベル・状態は名詞（体言止め）、ボタンは動詞にする。
  長さの目安は日本語 40 字・英語 80 字。
- 文（案内・エラーなど、「。」や「？」で終わる本文）に、括弧書きの注釈を入れない。
  括弧は、数値と単位（「3 件」）、ID（「PR #12」「PBI-477」）、形式名（`JSONL`）を添えるときだけ使う。
  引数を取る文言では、コマンド・ファイル名・パス・ID・数・名前の識別子そのものを入れる括弧も認める。
  理由・説明を入れる括弧は認めない。
- 見出し・ラベル・選択肢には、短い語を添える括弧を使ってよい。長さは日本語 14 字・英語 30 字未満にする。
- 「〜します」「〜しています」の説明文は、状態の名詞か短い命令文にする。
- 内部の役割（オーケストレーター・工程エージェント）は、人の判断に要るときだけ出す。
- 同じことを2回言わない（見出しと note、本文と補足で重ねない）。
- 本文に残すものは次のとおり。
  エラーと判断の案内は2文まで。
  - 取り消せない操作・費用がかかる操作・他人に見える操作の注意
  - エラーと失敗（何が起きた・次に何をする）
  - 人の判断を求める場面の「何を見て、何を決めるか」
- 日本語と英語を同じ基準で書く。
  英語は直訳にせず、英語として短く書く。

## 補足の規則

- 補足に入れるもの：仕組み、理由、頻度や上限の数値、設定ファイルの項目名と場所、用語の定義、既定値。
- 補足に入れてはいけないもの：操作に要る情報、エラー、警告、入力の必須条件。
  補足が無くても画面を使える。
- 補足も短くする。
  上限は日本語 150 字・英語 320 字。
- 補足が無い項目には印を出さない。

## 補足の部品

- 印は、見出し・ラベル・値の横の小さな i のアイコン。
  本文より目立たない色にする。
- 補足を出す操作と閉じる操作
  - マウスを乗せると出る。
  - キーボードで印に止まる（Tab）と出る。
  - タッチの端末ではタップで出る。
  - Esc か外側のクリック・タップで閉じる。
- 印の押せる大きさは 24×24px 以上にする（印の見た目は 20px のまま、まわりの行の高さ・並びは変えない）。
- 印の名前は、既定は「補足」。見出し・ラベルの横の印（`WithHint`、`CardSection` の見出し。ラベルが文字列のとき）は、「あなたの出番の補足」のように、何の補足かが分かる名前にする。
  じかに置いた印とラベルが文字列でない所は「補足」のまま。
- 乗せただけで出た補足にフォーカスを移さない。
  補足の文は印の中にも隠して置き（`sr-only`）、印の `aria-describedby` で結び付ける。
  このため、開かなくてもスクリーンリーダーで印の名前（「補足」。ラベルが文字列なら「<ラベル>の補足」）と文を読める。
- ダイアログの × と `DialogFooter` の閉じるボタンの名前は、画面の言語の「閉じる」／"Close"（辞書の `common.close`）。
- 長い補足は、高さを 20rem か、印の上下のうち配置した側の空き（Positioner の `--available-height`）に収め、中をスクロールする。
  キーボードでは、印に止まったまま矢印キー・PageUp/PageDown でスクロールできる。
  補足はポータルに出るので、Tab では中に移らない。
  印からフォーカスが外れたら閉じる。
- 作業履歴のコンテキストの用意の行（`ContextResolved`）は、読んだ層と警告だけを出す。
  置いた段階のサブエージェントの定義（段階ごとのエージェント・モデル・リーズニングエフォート。`ContextTiers`）と、使える外部 PF の一覧は、「詳細」を開いて読む（どちらも無ければ「詳細」を出さない）。
- 作業履歴の補足つきの再開の行（`TaskResumed` の `note`）は、再開の文に「・補足あり」を添えて出す。
  人が足した補足の本文は「詳細」を開いて読む（どの再開で足したかを読み返すため）。
- 作業履歴の未完了の実装の行（`ImplementationIncomplete`）は、残っていることの件数だけを出す。
  エージェントが申告した残っていること（1 件ずつ 1 行）は「詳細」を開いて読む（残っていることが無ければ「詳細」を出さない。テストの対応していない観点の行は、観点の ID を行に出す）。
  申告だけを求める実行を足した記録（`declarationOnly`）の行は、その旨を出す（欠けた観点の ID があれば添える）。
- 作業履歴の差し戻しの行（`ChangesRequested`）は、指摘の件数だけを出す。
  人が書いた指摘の本文（指摘の ID と本文、1件ずつ1行）は「詳細」を開いて読む。
  承認の画面は承認待ち・エスカレーションの間しか中身を出さないので、承認の後や完了・中止の後に指摘を読み返すのに使う。
- 作業履歴の工程の決定の行（`StepsChosen`）は、選んだ結果の名前（工程の並び・イメージ・書き出し先・サービス・飛ばす工程）だけを出す（費用不明の印は行の末尾）。
  選んだ理由・イメージの理由（既定のイメージで動かす理由を含む）・書き出し先の理由・サービスの理由・テストの仕組みが無い根拠・マージの後の監視を飛ばした理由は、見出しを付けて 1 件ずつ改行し、「詳細」を開いて読む（理由が無い古い記録は「詳細」を出さない）。
- 作業するリポジトリを選んだ行（`RepositoryChosen`）は、リポジトリ（人が選んだときは「（人間）」）だけを出し、選んだ理由は「詳細」を開いて読む（人が選んだ行と、理由が無い記録は「詳細」を出さない）。
- 右の列の「最近の作業履歴」は、どの種類の行も 2 行までで省略し、「詳細」を出さない。
  全文は「すべて見る」から作業履歴のタブで読む。
  実行のログの画面の「この実行の作業履歴」は、作業履歴のタブと同じ形（「詳細」あり）で出す。
- カードの見出しは、短い事実（件数・状態）を `note` に、仕組みの説明を `hint` に渡す。
- 既存の `title` 属性（費用の「概算」など）で出していた補足は、この部品に置き換えた。

コード: `apps/web/src/components/ui/hint.tsx`（`Hint`・`WithHint`）、`apps/web/src/components/card-section.tsx`（`CardSection`）、`apps/web/src/lib/labels.ts`（`describeEventParts`）、`apps/web/src/components/task-detail.tsx`（`EventText`）

## 辞書と検査

- 文言は領域ごとの辞書に置き、日本語の辞書の型を英語にも当てる。
  片方に無い文言は型の誤りになる。
- 補足のキーは `hint`・`*Hint`。
  判断の案内のキーは `*Help`（本文に残す2文までの案内）で、本文として確かめる。
- テストは、辞書の文字列の葉を日英まとめて確かめる。
  引数を取る文言（関数）は確かめない。
  - 本文は改行を含まず、日本語 60 字・英語 130 字以内。
  - 括弧は、日英の同じキーを組にして確かめる。
    どちらかが文（括弧の外に「。」、後ろに空白か末尾が続く "."、または「？」「！」「…」で終わる）なら、両方の括弧の中身を、数字と単位・ID（前に付ける語は `PR`・`PBI`・`Issue`）・形式名の一覧（`FORMAT_NAMES`）だけにする。長さは問わない。
    語の中の "."（`Node.js`）と略語（`e.g.`・`i.e.`・`etc.`）、括弧の中の「。」は、文と数えない。
    文でないもの（ラベル・見出し・選択肢）は、日本語 14 字・英語 30 字以上の括弧書きを含まない。
  - 補足は日本語 150 字・英語 320 字以内。
  - 改行・長さの例外は `EXCEPTIONS`、括弧の例外は `PAREN_EXCEPTIONS` に、キーのパスと理由を並べる。
    括弧の例外は、括弧が要る理由（見出しやラベルに添える語など）があるキーだけで、括弧の確かめを外す。`EXCEPTIONS` のキーも括弧は確かめる。
- デーモンが作って画面に出す文（一時停止・失敗の理由、取り込みのエラーなど）は、core の辞書のまま出す。
  これらはエラーと理由であり、CLI・Slack の通知と共有するので、画面の規則の対象にしない。
