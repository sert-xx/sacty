# 画面の文言と補足

画面の文言は、本文（常に見える文）と補足（印にマウスを乗せると出るツールチップ）に分けて持つ。本文は「いま何が起きているか」と
「次に何をするか」だけにし、仕組み・理由・頻度や上限の数値・設定ファイルの場所・用語の定義は補足に書く。文言は日本語と英語の辞書で持ち、
辞書の文字列が規則から外れていないことをテストで確かめる。

関係する ADR: [画面の文言を本文と補足に分け、仕組みの説明はツールチップで出す](../adr/20261016-1244-ui-wording-body-and-hints.md)

## 本文の規則

- 本文に書くのは、いま何が起きているかと、次に何をするかだけ。仕組み（どう動くか）・理由・頻度や上限の数値・設定ファイルの場所・用語の
  定義は、補足に移すか、書かない。
- 1つの文言は1文。見出し・ラベル・状態は名詞（体言止め）。ボタンは動詞。目安は日本語 40 字・英語 80 字。
- 括弧書きの注釈を本文に入れない。括弧は、数値や ID を添えるときだけ（例「PR #12」「3 回目」）。
- 「〜します」「〜しています」の説明文は、状態の名詞か短い命令文にする。
- 内部の役割（オーケストレーター・ゴールガーディアン・工程エージェント）は、人の判断に要るときだけ出す。
- 同じことを2回言わない（見出しと note、本文と補足で重ねない）。
- 本文に残すもの：取り消せない操作・費用がかかる操作・他人に見える操作の注意、エラーと失敗（何が起きた・次に何をする）、
  人の判断を求める場面の「何を見て、何を決めるか」。エラーと判断の案内は2文まで。
- 日本語と英語を同じ基準で書く。英語は直訳にせず、英語として短く。

## 補足の規則

- 補足に入れるもの：仕組み、理由、頻度や上限の数値、設定ファイルの項目名と場所、用語の定義、既定値。
- 補足に入れてはいけないもの：操作に要る情報、エラー、警告、入力の必須条件。補足が無くても画面を使える。
- 補足も短くする。上限は日本語 150 字・英語 320 字。
- 補足が無い項目には印を出さない。

## 補足の部品

- 印は、見出し・ラベル・値の横の小さな i のアイコン。本文より目立たない色にする。
- マウスを乗せると出る。キーボードで印に止まる（Tab）と出る。タッチの端末ではタップで出る。Esc か外側のクリック・タップで閉じる。
- 乗せただけで出た補足にフォーカスを移さない。補足の文は閉じていても DOM にあり、印の `aria-describedby` で結び付くので、
  スクリーンリーダーで印の名前（「補足」）と文を読める。
- カードの見出しは、短い事実（件数・状態）を `note` に、仕組みの説明を `hint` に渡す。
- 既存の `title` 属性（費用の「概算」など）で出していた補足は、この部品に置き換えた。

コード: `apps/web/src/components/ui/hint.tsx`（`Hint`・`WithHint`）、`apps/web/src/components/card-section.tsx`（`CardSection`）

## 辞書と検査

- 文言は領域ごとの辞書に置き、日本語の辞書の型を英語にも当てる（片方に無い文言は型の誤りになる）。
- 補足のキーは `hint`・`*Hint`。判断の案内のキーは `*Help`（本文に残す2文までの案内）。
- テストで、辞書の文字列の葉を日英まとめて確かめる：本文は改行を含まず、日本語 60 字・英語 130 字以内で、日本語 14 字・英語 30 字以上の
  括弧書きを含まない。補足は日本語 150 字・英語 320 字以内。例外は、キーのパスと理由を並べた一覧に書く（見出しの括弧、
  2文の案内など）。引数を取る文言（関数）は確かめない。
- デーモンが作って画面に出す文（一時停止・失敗の理由、取り込みのエラーなど）は、core の辞書のまま出す。これらはエラーと理由であり、
  CLI・Slack の通知と共有するので、画面の規則の対象にしない。

コード: `apps/web/src/i18n/index.ts`（`messagesFor`）、`apps/web/src/i18n/wording-policy.test.ts`（`EXCEPTIONS`）、`packages/core/src/messages.ts`（`renderMessage`）
