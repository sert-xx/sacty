# 画面の文言と補足

画面の文言は、本文（常に見える文）と補足（印にマウスを乗せると出るツールチップ）に分けて持つ。
本文は「いま何が起きているか」と「次に何をするか」だけにする。
仕組み・理由・頻度や上限の数値・設定ファイルの場所・用語の定義は補足に書く。
文言は日本語と英語の辞書で持ち、辞書の文字列が規則から外れていないことをテストで確かめる。

関係する ADR: [画面の文言を本文と補足に分け、仕組みの説明はツールチップで出す](../adr/20261016-1244-ui-wording-body-and-hints.md)

## 本文の規則

- 画面の製品名は、日本語・英語ともに Sacty と書く。
  ヘッダー・ブラウザーのタイトル・入り口・履歴・エラーにも適用する。
  コマンド・設定キー・Cookie・ラベル名・パスなどの識別子は大文字に変えない。
- 本文に書くのは、いま何が起きているかと、次に何をするかだけ。
  仕組み（どう動くか）・理由・頻度や上限の数値・設定ファイルの場所・用語の定義は、補足に移すか、書かない。
- 1つの文言は1文。
  見出し・ラベル・状態は名詞（体言止め）、ボタンは動詞にする。
  長さの目安は日本語 40 字・英語 80 字。
- 括弧書きの注釈を本文に入れない。
  括弧は、数値や ID を添えるときだけ使う（例「PR #12」「3 回目」）。
- 「〜します」「〜しています」の説明文は、状態の名詞か短い命令文にする。
- 内部の役割（オーケストレーター・ゴールガーディアン・工程エージェント）は、人の判断に要るときだけ出す。
- 同じことを2回言わない（見出しと note、本文と補足で重ねない）。
- 本文に残すものは次のとおり。
  エラーと判断の案内は2文まで。
  - 取り消せない操作・費用がかかる操作・他人に見える操作の注意
  - エラーと失敗（何が起きた・次に何をする）
  - 人の判断を求める場面の「何を見て、何を決めるか」
- 日本語と英語を同じ基準で書く。
  英語は直訳にせず、英語として短く書く。

## 補足の規則

- 補足に入れるもの：仕組み、理由、頻度や上限の数値、設定ファイルの項目名と場所、用語の定義、既定値。
- 補足に入れてはいけないもの：操作に要る情報、エラー、警告、入力の必須条件。
  補足が無くても画面を使える。
- 補足も短くする。
  上限は日本語 150 字・英語 320 字。
- 補足が無い項目には印を出さない。

## 補足の部品

- 印は、見出し・ラベル・値の横の小さな i のアイコン。
  本文より目立たない色にする。
- 補足を出す操作と閉じる操作
  - マウスを乗せると出る。
  - キーボードで印に止まる（Tab）と出る。
  - タッチの端末ではタップで出る。
  - Esc か外側のクリック・タップで閉じる。
- 乗せただけで出た補足にフォーカスを移さない。
  補足の文は印の中にも隠して置き（`sr-only`）、印の `aria-describedby` で結び付ける。
  このため、開かなくてもスクリーンリーダーで印の名前（「補足」）と文を読める。
- 長い補足は、高さを 20rem か、印の上下のうち配置した側の空き（Positioner の `--available-height`）に収め、中をスクロールする。
  キーボードでは、印に止まったまま矢印キー・PageUp/PageDown でスクロールできる。
  補足はポータルに出るので、Tab では中に移らない。
  印からフォーカスが外れたら閉じる。
- 作業履歴の長い行（コンテキストの用意の使える外部 PF の一覧）は、1行目だけを出す。
  残りは「詳細」を開いて読む。
- カードの見出しは、短い事実（件数・状態）を `note` に、仕組みの説明を `hint` に渡す。
- 既存の `title` 属性（費用の「概算」など）で出していた補足は、この部品に置き換えた。

コード: `apps/web/src/components/ui/hint.tsx`（`Hint`・`WithHint`）、`apps/web/src/components/card-section.tsx`（`CardSection`）、`apps/web/src/lib/labels.ts`（`describeEventParts`）

## 辞書と検査

- 文言は領域ごとの辞書に置き、日本語の辞書の型を英語にも当てる。
  片方に無い文言は型の誤りになる。
- 補足のキーは `hint`・`*Hint`。
  判断の案内のキーは `*Help`（本文に残す2文までの案内）で、本文として確かめる。
- テストは、辞書の文字列の葉を日英まとめて確かめる。
  引数を取る文言（関数）は確かめない。
  - 本文は改行を含まず、日本語 60 字・英語 130 字以内で、日本語 14 字・英語 30 字以上の括弧書きを含まない。
  - 補足は日本語 150 字・英語 320 字以内。
  - 例外は、キーのパスと理由を並べた一覧に書く（見出しの括弧、2文の案内など）。
- デーモンが作って画面に出す文（一時停止・失敗の理由、取り込みのエラーなど）は、core の辞書のまま出す。
  これらはエラーと理由であり、CLI・Slack の通知と共有するので、画面の規則の対象にしない。

コード: `apps/web/src/i18n/index.ts`（`messagesFor`）、`apps/web/src/i18n/wording-policy.test.ts`（`EXCEPTIONS`）、`packages/core/src/messages.ts`（`renderMessage`）
