# git で取得した層の extends を、ネットワークの先のリポジトリに限る

- 日時: 2026-11-06 02:55 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-306
- 置き換え元: なし
- 置き換え先: なし

## 背景

git で取得した層は、ローカルのパスを継承できない決まりだった。取得したコミットの中身で、ホストのディレクトリを読ませないためである。
ただし、止めていたのは絶対パスと `~/` だけで、`file://` の URL と `sibling/repo.git` のような相対パスは `git clone` に渡っていた。
セキュリティチェックがこの経路を指摘した。

## 決定

- git で取得した層の `extends` のうち、別のリポジトリを指すものは、`https://`・`http://`・`ssh://`・`git://` の URL と `user@host:path` の形だけを受け付ける。
- それ以外の別のリポジトリの指定は、ローカルのパスと同じ `context.localExtendsFromRemote` で止める。
- `./`・`../` で始まる、同じリポジトリの中を指す相対パスは、この制限の対象ではなく、これまでどおり継承できる。
- プロジェクトの指定と、今の中身を読む層（`ref` の無いローカルのパスの層）の `extends` は変えない。

## 理由

- 止める形を並べる方法では、`git clone` がホストから読む書き方の漏れを防げない。受け付ける形を決めるほうが確実である。
- `ext::` のように、取得のときにコマンドを動かせる取得方法も、受け付ける形に入れないことで止められる。
- プロジェクトの指定は、利用者が自分で書く値なので、取得した中身による読み取りには当たらない。

## 影響

- 取得した層の `extends` に、`host:path`（ユーザー名の無い形）は書けない。`ssh://` の URL か `user@host:path` で書く。
- `file://` や `sibling/repo.git` のような相対パス（`./`・`../` で始まらないもの）で親を継承していた、git で取得した層は止まる。
- 仕様は [コンテキスト](../spec/context.md)、利用者向けは [コンテキスト](../user/context.md) に書く。
