# docker compose のサービスを起動した工程とテストでは、localhost のポートへの接続をサービスへ転送し、リポジトリの設定を書き換えさせない

- 置き換え先: なし

## 背景

#54 で、docker compose のサービス（DB・モック API など）を工程とテストの実行ごとに起動し、サービス名（例 `db:5432`）でつなぐように
した。リポジトリの開発の設定の接続先は `localhost` のことが多く、そのままでは届かないので、エージェントが設定を書き換えられるかどうかに
左右されていた。

## 決定

- サービスを起動したエージェントの実行とテストの実行だけ、コマンドをくるむ。イメージにある Node.js だけで動く小さな TCP の転送を起動し、
  `127.0.0.1`（と使えれば `[::1]`）で待ち受けてから、元のコマンドを子プロセスとして動かす。標準入出力・終了コードはそのまま
  （シグナルは子に伝える）。コマンドが終わると転送も止まる。サービスの無い工程・テストは、コマンドも含めて何も変えない。
- 転送する番号：
  - コンテナのポート：`localhost:5432` → `db:5432`。
  - compose でホストに別の番号で出しているポート：`ports: ["15432:5432"]` なら `localhost:15432` → `db:5432`（短い書き方・長い書き方・
    アドレス付き・範囲。published の無いもの・UDP など TCP 以外は除く）。
  - 同じサービスの中では、ホストに出すポートの対応（published → target）を優先する（`"8080:80"` と `"18080:8080"` なら
    `localhost:8080` → `app:80`）。
  - 複数のサービスが localhost の同じ番号を使うときは、その番号は転送しない（`ServicesStarted` に `sharedPorts` として残し、指示と
    作業履歴に出す）。使用中のポートは転送せず、理由を出して続ける（失敗にしない）。
- 指示を「`db:5432` または `localhost:5432`・`localhost:15432` で接続できる。リポジトリの設定は書き換えない」に変える。

## 理由

- 接続先が localhost のままでも届くようにし、エージェントが設定を書き換えられるかどうかに左右されないようにするため（PR の本文）。
- 同じサービスの中でホストに出すポートの対応を優先するのは、リポジトリの開発の設定の `localhost:<番号>` はホストから見た番号だから
  （レビューの返信）。レビューで、明示した対応と違うポートへ黙って転送することがわかったのがきっかけ。
- UDP を除くのは、レビューで、UDP の番号が TCP の転送の候補とぶつかりの判定に入り、同じ番号の TCP のサービスの転送まで止めることが
  わかったため（レビューとその返信）。
- 転送をイメージの Node.js で行うこと自体の理由と、比べたほかの案は記録に無い。

## 影響

- MySQL のクライアントなどで `localhost` と書くと UNIX ソケットで接続するので届かない（`127.0.0.1` なら届く）。
- アプリ自身がサービスと同じポート番号で待ち受けると、番号がぶつかって起動できない。
- `ports` も `expose` も無いサービス（イメージの EXPOSE だけ）は、番号が分からないので転送しない。`network_mode: service:X` のサービスには
  届かない。
