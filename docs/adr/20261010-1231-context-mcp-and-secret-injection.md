# コンテキストの MCP サーバーを mcp.yaml で書いて合成し、秘密情報は名前で参照して実行時に環境変数でだけ渡す

- 日時: 2026-10-10 12:31 UTC
- ステータス: 採用
- 関係する PR・タスク: #14、PBI-6
- 置き換え元: なし
- 置き換え先: なし

## 背景

#13 で、コンテキストリポジトリの規約・スキルを合成して工程エージェントに渡すようにした。続けて、MCP サーバーの設定も同じように重ねて渡す必要があった。
MCP サーバーにはトークンなどの秘密情報が要るが、それをコンテキストリポジトリ・設定のファイル・台帳に書くわけにはいかない。

## 決定

- 中立形式：コンテキストリポジトリの `mcp.yaml` の `servers` に、名前ごとに stdio（`command`・`args`・`env`）か HTTP（`url`・`headers`）のサーバーを書く。
  秘密情報は `{ secret: <名前>, prefix: <前に付ける文字> }` で名前だけを参照する。
- `sacty-context.yaml` の `locked`・`remove` に `mcp:` を足し、スキルと同じ規則（名前ごとに下位が上書き、上書き禁止は下位で外せない）で合成する。
- 名前・環境変数名・ヘッダー名・URL（http/https のみ）を検査し、誤りは場所と理由を示して止める。文字列に `${` は書けない。
- Claude Code には、設定のディレクトリに `mcp.json` を置き、`--mcp-config … --strict-mcp-config` で起動して、コンテキストの MCP サーバーだけを使わせる。
  そのツールを `--allowedTools mcp__<名前>` で許可する。
- Codex には、`CODEX_HOME` の `config.toml` に `[mcp_servers.<名前>]` を置く。
- 秘密情報の値は、設定のファイルには書かず、環境変数の名前（`SACTY_MCP_SECRET_<n>`）だけを書く。値はエージェントの起動時にキーチェーンから取り出し
  （`prefix` を付けて）、コンテナの環境変数としてだけ渡す。ディスクにも台帳にも残さない。
  - Claude Code は設定の `${SACTY_MCP_SECRET_n}` を展開する。
  - Codex は、stdio では `env_vars` で渡した変数を `sh` で目的の名前に移してから起動し、HTTP では `env_http_headers` で渡す。
- 取り出した秘密情報は、出力・エラー文から取り除く。名前を指定して取り出した値は、長さにかかわらず取り除く（長さの下限は、認証ファイルから推測で取り出す値にだけ残す）。
  見つからなければ、名前を示して止める（認証の一時停止）。

## 理由

- 文字列に `${` を書けないのは、Claude Code が環境変数として展開するため（PR の本文）。
- Codex で `sh` で包むのは、Codex が値の展開をしないため（PR の本文）。
- 名前を指定して取り出した値を長さにかかわらず取り除くのは、MCP の秘密情報には長さの制限が無く、短い値（例 6文字）が出力に含まれると伏せられずに
  追記専用の台帳に残ることが、レビューで見つかったため（レビュー）。
- 秘密情報を名前で参照して実行時に注入することは受け入れ条件による。それ以上の理由は記録に無い。

## 影響

- MCP サーバーの秘密情報は、`sacty secret set <名前>` でキーチェーンに置いておく必要がある。
- Claude Code では、コンテキストの MCP サーバー以外は使われない。
- Codex で `codex exec` から MCP サーバーを実際に起動しての動作は、この時点では確かめていない。
