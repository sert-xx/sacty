# 不安定なテストの台帳を作業履歴から導き、提案は人が作るタスクにする

- 日時: 2026-11-06 11:05 UTC
- ステータス: 置き換え済み（superseded）
- 関係する PR・タスク: PBI-312、#318
- 置き換え元: なし
- 置き換え先: [実装の最終レビュー（テストの実行）と PR の CI の待ちをやめ、PR のレビューの子タスクの指摘なしでドラフトを外す](20261112-0714-review-child-task-replaces-final-review-and-ci-wait.md)

## 背景

認めた不安定な失敗は、タスクごとの最終レビューに残るだけで、同じテストが何度も不安定でも分からなかった。毎回の実行し直しに時間がかかり、直すきっかけも無かった。

## 決定

- 台帳の新しい保存先は作らず、作業履歴（`FinalReviewed` の `tests.flakyFailures`）からプロジェクトごとに導く。すべての回の記録を、タスクの状態の `flakySightings` に畳み込む。
- テストはリポジトリ・ファイル・名前の組で見分け、見たタスクの数で数える（同じタスクは1）。
- 3 タスク以上で見たテストを既知とし、最終レビューの指示にデータとして渡す。既知のテストは `runs`・`passes` を 0 にして実行し直しを省ける。実行し直しの確認だけを省き、差分に含まれるテストは既知でも認めない。
- 既知のテストの提案は、監査の画面の欄から、題と内容を入れたタスクの作成のダイアログを開く。人が作成を押すまで何も作らない。
- 作ったタスクは `flakyFix` で台帳とつなぐ。終わっていない間は提案を重ねず、PR のマージより前の記録は数えない。
- テストの隔離・無効化は自動で行わない。

- 既知のテストに期限は、今は設けない（人が決めた。2026-11-06）。

## 理由

- 監査の提案（`ProposalView`）の採用には載せなかった。監査の提案は、タスクの監査の結果として記録されたものを判断する仕組みで、台帳の提案には元のタスク・宛先の候補・判断の記録が無い。導いたものを記録に変えると、新しい保存先を作るのと同じになる。
- タスクの作成のダイアログなら、人が内容を確かめて直せて、新しい API の操作も要らない。
- マージより前の記録を数えないのは、直した後のテストが既知のままだと、本当の失敗でも実行し直しを省けてしまうため。
- 内容に PR のリンクを書かないのは、タスクの内容にある PR は、そのタスクが扱う PR と読まれるため。

## 影響

- 実行し直しを省くと、結果が変わるかを確かめない。既知のテストが本当に壊れたときは、差分に含まれない限り通ってしまう。認めた失敗は人が確かめることに残るので、人の目に頼る。省いた申告も認めた失敗として数えるので、壊れたままなら既知のまま続く。
- 提案から作らずに直したテストは、つながらないので、既知のまま残る。
- テストの名前はゴールガーディアンの申告なので、書き方が揺れると別のテストに数える。
- 台帳は読むたびに全タスクをたどる。
