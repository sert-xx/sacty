# 対応を求めていない PR のコメントは、差し戻さない

- 日時: 2026-11-19 14:28 UTC
- ステータス: 採用
- 関係する PR・タスク: なし
- 置き換え元: なし
- 置き換え先: なし

## 背景

sacty は、PR の人のコメントをすべて指摘として取り込み、戻し先を判断して、人の確認を挟まずに差し戻す
（[PR の指摘の戻し先を、ゴールガーディアンではなく、AI のレビューの指摘はレビューの子タスクが、人の指摘は PR の工程のエージェントが決める](20261112-0748-review-child-task-decides-rework-target.md)）。
戻し先の答えは、どこかの工程か「判断できない」だけで、「判断できない」ときはその PR の工程をやり直す。差し戻さないという答えが無かった。

そのため、sacty が指摘に返信した後、人が「承知しました。」と返すと、次のことが起きた（利用者からの報告、2026-11-19）。

- 「承知しました」が指摘として取り込まれ、戻し先の判断が「判断できない」になり、実装をやり直した。
- 何も求められていないのに、コードを直すコミットが PR に入り、PR のレビューの子タスクがもう一度レビューした（費用がかかった）。
- 「承知しました」への返信（対応していません。理由：…）と、「人に確かめてほしいことがあります」のコメントが PR に投稿された。
  後者には、撤去済みの「ゴールガーディアン」の名前が残っていた
  （[ゴールガーディアンを撤去し、変更の申し出は人が判断し、統合レビューは統合レビューの工程のエージェントが行う](20261112-0820-remove-goal-guardian.md)）。

## 決定

- 戻し先を判断する工程のエージェントに、人の指摘のうち、対応を求めていないもの（先の返信や説明を受け入れただけの応答・お礼・同意）を、
  指摘の番号で答えさせる（`no_action`）。変更・確認・質問・反論を少しでも含む指摘、意味を読み取れない指摘、迷う指摘は選ばせない。
- 選ばれた指摘は、取り込み済みのまま、差し戻しから除く（`ReworkJudged` の `noAction`）。指摘にならないので、返信も、
  人に確かめてほしいことのコメントも出ない。
- 取り込んだ指摘がすべてそうなら、差し戻さない（`noRework`）。承認待ちのまま、成果物も PR も変えない。
  一時停止の間に届いた指摘なら、止まった工程をそのまま走り直す。
- AI のレビューの指摘は、対応を求めていない指摘にしない。子タスクの答えから戻し先を決めるとき、判断の実行に失敗した・出力を
  読めなかったときは、どの指摘も除かない。
- 「人に確かめてほしいことがあります」のコメントの文言から「ゴールガーディアン」をなくし、画面と同じ言い方
  （戻し先の判断で、指摘の意図を読み取れませんでした）にする。

## 理由

- 対応を求めていないコメントで作り直すと、費用（作り直しの実行と、その後のレビュー）がかかり、求められていない変更が PR に入る。
  PR を見ている人には、了承しただけなのに sacty が動き出したように見える。
- 見分けるのを、文の一致（「承知しました」などの決まった語）ではなく、戻し先を判断するエージェントに任せるのは、
  同じ語でも「承知しました。ただ、〜も直してください」のように対応を求めることがあるため。人の指摘を含むときは、もともと
  判断の実行をしているので、実行は増えない。
- 迷うときは除かせないのは、求められた対応を落とすほうが、余分に作り直すより重い誤りのため。
- 指摘ごとに除く（まとめて「差し戻さない」だけにしない）のは、人が複数の返信に目を通して、了承のコメントと、対応を求める
  コメントを続けて書くことがあるため。まとめて判断すると、了承のコメントにも「対応していません」の返信が付く。
- 比べた案：取り込む前に、sacty の返信への返事を機械的に除く。行へのコメントの返信は親のコメントを辿れるが、通常のコメントは
  どの投稿への返事かが分からず、返事の中で新しく対応を求めることもあるので、採らなかった。

## 影響

- 対応を求めていないコメントだけのときも、判断の実行の費用はかかる（作り直しとレビューの費用はかからない）。
- エージェントが、対応を求める指摘を誤って除くと、その指摘は取り込み済みになり、作り直されない。作業履歴の戻し先の行に、
  除いた件数（すべて除いたときは、差し戻さなかったこと）と理由が残るので、人はもう一度コメントするか、画面で差し戻す。
- 仕様書は[承認と差し戻し](../spec/approval.md#pr-の指摘の取り込み)、利用者向けは[タスクを進める](../user/tasks.md)に記す。
