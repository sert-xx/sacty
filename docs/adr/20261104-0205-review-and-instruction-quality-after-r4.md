# 受け入れの確かめを縮めさせず、最終レビューの出力の言語を決め、作業領域の内部のパスを人の目に出さない

- 日時: 2026-11-04 02:05 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-301（A1〜A7）
- 置き換え元: なし
- 置き換え先: なし

## 背景

実験 r4 までで、指示とレビューの質に関わる問題が残った。

- 受け入れの確かめが、名前の存在の確認に縮んだ（S2 r4）。オーケストレーターが `noTests` の根拠に確かめ方を書き、それが実装と最終レビューの指示にそのまま入った。
- 最終レビューが、新しく入れた共有の仕組みの失敗後の回帰を見逃した（S16 r4）。
- フォーマッターの検証が漏れた（S18 r4）。
- 最終レビューの所見が英語で出た（r2 の S2、r3 の S18、r4 の S16）。
- 確かめようのない作業領域の内部の物が「人が確かめること」に入った（S18・S5 r4）。
- PR の本文で、結論と変更が同じ文を繰り返し、内部のパス（`/sacty-input/task.md:77`）が出た（S16・S19）。

## 決定

- **`noTests` には、テストの仕組みが無いことの根拠だけを書かせ、受け入れの確かめ方を書かせない**。実装と最終レビューには、根拠は確かめ方を決めるものではなく、受け入れ条件より弱い確かめ方には従わないことを添える。最終レビュー（テストの有無にかかわらず）と統合レビューには、受け入れの確かめを、名前・項目・ファイル・リンクの存在の確認に縮めず、文書が述べる責務・振る舞いはコードを読んで確かめることを求める。セルフレビューの U-1 も、名前と値の照合に加えて、責務・振る舞いの記述を照らす。
- **最終レビューと統合レビューは、共有の仕組みを新しく入れた・変えたときに、異常や失敗の後に後続の処理が続くかを確かめる**。確かめられなかったことは、最終レビューは `humanChecks` に、統合レビューは判定の説明に書かせる。
- **実装・修正の工程は、リポジトリが定める検証を、PR に入る変更すべてに対して提出の前に実行する**。実行しなかった理由は実装の説明に書かせる。最終レビューも、テストのコマンドとは別に、同じ範囲で検証を実行する。
- **セルフレビューの D-10 は、リポジトリの文書や既存の振る舞いに根拠のある記述を、「依頼に無い」だけを理由に消さない**。情報収集は、README・AGENTS.md から参照されていない文書も、文書を置くディレクトリから探す。
- **最終レビューと統合レビューの出力の文は、タスクの題と内容の言語で書かせる**。sacty には出力の言語の設定が無いので、設定は足さない。リポジトリの文章の決まりが言語を定めていればそれに従わせる。
- **sacty の作業領域の内部の物についての確認は、「人が確かめること」に入れない**。人が自分の環境で確かめられることは、これまでどおり入れる。
- **PR の本文の「変更」は、結論に載せた最初の段落を除いた残りにする**。sacty の作業領域の内部のパス（`/sacty-input` など）は、PR の本文・成果物のファイル・コメントで、人が辿れる呼び方（「タスクの依頼」など）に置き換える。

## 理由

- 根拠に確かめ方が混ざる原因は、根拠と確かめ方が同じ欄に書けることだった。欄の役割を狭め、後ろの工程が根拠に縛られないようにすれば、オーケストレーターの書き方に依らず、確かめの深さが保てる。
- 共有の仕組みは、正常な使い方のテストが通っても、失敗後に状態が残る回帰を持ちうる。範囲内の判定とは別に、失敗後の継続を確かめる。
- 出力の言語の設定は今のところ無く、この PBI にも設定を足す要件は無い。足すかどうかは決めていない（足すなら、設定があるときはそれを優先する）。
- 内部のパスは、本文の整形で置き換える。エージェントに書かせない指示だけでは、再発した（F3 の再発）。

## 影響

- 指示の文面での対策で、エージェントが従うかは確率的に変わる。実タスクでは未確認。
- `.sacty-tools/` など、内部の物の確認を「人が確かめること」に入れない対策は、指示だけで、sacty は項目を機械的に消さない。
- 「変更」の節は、結論に載せた最初の段落を除いた残りになる。テンプレートに沿わせる本文の「変更」は、全文のまま。
