# ビルドキャッシュの片付けで、期間の絞り込みをやめ、使っていないものをすべて消す

- 日時: 2026-11-17 22:49 UTC
- ステータス: 置き換え済み（superseded）
- 関係する PR・タスク: PBI-389、#428
- 置き換え元: [デーモンのコンテキストのイメージの片付けでも、3日使っていないビルドキャッシュを消す](20261117-1500-superseded-prune-build-cache-with-context-images.md)（3日より長く使っていないものだけを消す、という期間の決定をやめた。ほかの決定はそのまま）
- 置き換え先: [ビルドキャッシュの片付けの後はイメージを最初から作り直すと分かったうえで、期間の絞り込みの無い片付けを続ける](20261118-0820-keep-ageless-build-cache-prune-with-full-rebuild.md)（「影響」の、片付けの後に作り直すのは共有していない層だけ・共有している層は残る、という見込みを、実測で置き換えた。期間で絞らない決定はそのまま）

## 背景

ビルドキャッシュの片付けは、`sacty image build` の後とデーモンの片付けの両方で、3日より長く使っていないものだけを消していた（`docker builder prune -f --filter until=72h`。置き換え元の ADR）。
この片付けを入れた後の実測（2026-11-17 UTC。Docker 29.5.3、BuildKit v0.30.0）で、キャッシュがほとんど減らなかった。

- デーモンを起動した後の最初の片付けで消えたのは 2.6GB で、約 47GB が残った。同じ引数でもう一度実行すると、消えたのは 0B だった。
- `--all` を足して実行しても、消えたのは約 0.55GB だった。
- 残ったもののうち、最後に使ったのが3日以上前のものは約 43GB あった。そのすべてに、3日以内に使われた子孫の層があった。
- 鎖の端の層の「最後に使った時刻」が、片付けを実行した時刻に揃っていた。

ここから、期間で絞ると、1回の片付けで1本の鎖から端の1層しか消えず、その親の「最後に使った時刻」が片付けの時刻に書き換わって、次の72時間残る、と見ている（時刻の一致からの推定。BuildKit のコードでは確かめていない）。
期間を外した `docker builder prune -f` を実行すると、32.58GB が消え、残ったのは、いまあるイメージと共有している層（95件・14.1GB）だった。

## 決定

- ビルドキャッシュの片付けから、期間の絞り込み（`--filter until=72h`）を外す。引数は `docker builder prune -f` にする。
- `--all` は付けない。
- `sacty image build` の片付けと、デーモンの片付けで、同じ引数を使う（今までどおり）。
- 期間の定数（`BUILD_CACHE_MAX_UNUSED_DAYS`）を消し、ログの文言から「3日」を外す。
- デーモンの片付けの、6時間の間隔・2分の上限・打ち切りの扱い・失敗の警告は変えない。

## 理由

- 「期間をやめて全部消す」ことは、リポジトリの持ち主が、上の実測を見て決めた（2026-11-17 UTC。選択式で確かめた）。
- 期間で絞る形では、片付けを繰り返しても、古い鎖が消えなかった。期間を短くする案は、同じ仕組み（消すたびに親の時刻が書き換わる）で残ると見て、比べていない。
- `--all` を付けないのは、付けても期間で絞る限り消える量がほとんど変わらなかったことと、付けずに期間を外すだけで、いまあるイメージと共有していない分が消えたため。
  `--all` を付けて期間を外したときに何が消えるかは、確かめていない（未確認）。
- 6時間の間隔は、期間をやめた後もそのままにする。この決定の中で、リポジトリの持ち主が決めた（2026-11-17 UTC）。
  置き換え元の ADR は、間隔の理由を「消す対象は3日使っていないもので、毎回走らせても消えるものがほとんど変わらない」としていた。期間をやめたので、この理由は成り立たない（使わなくなった層は、次の片付けですべて対象になる）。
  いまの根拠は、成功のログの量を抑えること（毎回走らせると、5分ごとに1行出る）と、片付けの間に読み直しを待たせる回数を抑えること。
  6時間という値そのものは、置き換え元の ADR（PBI-388）で、リポジトリの持ち主が決めた値で、ここでは選び直していない。

## 影響

- 失うもの
  - 片付けの後の最初のビルドでは、いまあるイメージと共有していない層を作り直す。時間がかかる。
  - [イメージの作成でパッケージの取得をキャッシュする決定](20261112-1526-image-build-cache.md)の cache マウントの中身もビルドキャッシュの一部なので、片付けのたびに消えうる。消えた後のビルドでは、パッケージを取得し直す。
    実測では、キャッシュマウントとローカルソースの分は、消えた 32.58GB のうち約 0.7GB だった。
  - `docker builder prune` は Docker 全体のビルドキャッシュが対象なので、同じ Docker を使う、sacty 以外のビルドのキャッシュも、期間に関わらず消える。
- 残るもの：実測では、いまあるイメージと共有している層は残った。どの版の Docker でも同じかは、確かめていない（未確認）。
- 2分の上限に収まるかは、確かめていない。実測で 32.58GB を消したときの所要時間は、計っていない（未計測）。上限の値は変えていない。
  - 上限を過ぎると、片付けを打ち切る（docker を止める）。前に成功した時刻は進めないので、次の読み直し（遅くとも5分後）で試し直す。
  - 打ち切りが続く間は、読み直しのたびに片付けが走り、そのつど、読み直しが手元にあるかの確かめと作成を、最大で上限の時間だけ待たせる。打ち切りの警告も、そのたびに出る。
  - 打ち切ったときに、それまでに消した分が残るか、打ち切った後も Docker の側で削除が進むかは、確かめていない（未確認）。残るなら、試し直すたびに残りが減って、いずれ上限に収まる。
- デーモンは、起動した後の最初の片付けと、その後は6時間に1回、この片付けを走らせる。コンテキストのイメージを作り直すたびに増えたキャッシュは、遅くとも6時間ほどで消える。
- 消した分だけ Docker の中の使用量は減るが、ホストのディスクの空きが増えるかは、Docker の仮想ディスクの扱いによる（実測の環境では、ホストの空きは変わらなかった。理由は確かめていない）。
- 期間は設定にしていない（今までどおり）。
