# 最終レビューのやり直しで、前の回が挙げた「人が確かめること」を、理由なしに落とさない

- 日時: 2026-11-03 11:00 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-294
- 置き換え元: なし
- 置き換え先: なし

## 背景

実験 S16 r3（findings F42）で、1回目の最終レビューが、率の検査が `Number()` で読むので `"1e1"`・`"0x10"` も整数として受けることと、設計に無い直列化のキューを、人が確かめること（範囲内か判断できない）に挙げた。
最終レビューは別の1件で不合格になり、実装がやり直された。2回目は、その部分のコードが変わっていない（検査の順番と回帰テストだけを直した）のに、人が確かめることが空になり、PR から消えて、依頼者は欠陥を見逃して承認した。
最終レビューの指示には、過去の最終レビューの判定を渡していなかったので、2回目のゴールガーディアンは、1回目に何を挙げたかを知らなかった。

## 決定

- 最終レビューのやり直し（2回目以降）では、前の回の最終レビューの `humanChecks`（「範囲内か判断できない」とした変更を含む）を、次の回へ引き継ぐ。sacty が引き継ぐ：外すと申告された項目以外を、判定の `humanChecks` の先頭に足す。
- 指示には、前の回の項目を `[P1]`・`[P2]` の番号つきで渡す。外してよいのは、今のコードで懸念が解消しているとき、または前の回の判定が誤りだったときだけで、`droppedHumanChecks` に「<番号>：<外す理由>」を書かせる。解消していても、理由が無い・番号が合わない申告は、外さずに引き継ぐ。
- 外した項目と理由は、`FinalReviewed` の `droppedHumanChecks` に記録する。
- 引き継ぐのは最終レビューの `humanChecks` だけ。環境によると判断したテストの失敗（`tests.environmentFailures`）は、その回のテストの結果から判断し直すので引き継がない。sacty が毎回作る「実行できなかった検証」の項目も、引き継がない（同じ条件なら作り直される）。
- 前の回が無い最終レビュー（1回目）の指示・判定は変えない。

## 理由

- 指示だけで「前の回の項目を書き写せ」と頼むと、書き写しを忘れたとき、F42 と同じように項目が黙って消える。引き継ぎを sacty が行い、ゴールガーディアンには外すときだけ理由を書かせれば、消えるのは理由が記録された場合だけになる。
- 前の回の項目を渡さないままでは、2回目のゴールガーディアンは同じ点を見つけ直すしかなく、見つけ直す保証が無い。
- 「その部分のコードが変わったか」は、前の回のコードを渡さないと sacty には判定できない。コードの判断は、ゴールガーディアンが今のコードで懸念が解消しているかを確かめ、理由を書く形にした。理由の中身を sacty は検証しないので、その真偽は人が PR の項目と記録で確かめる。

## 影響

- やり直しの最終レビューの指示に、前の回の項目の節が増える（前の回が人が確かめることを挙げたときだけ）。
- 引き継いだ項目は、これまでと同じ形で実装の PR の本文の「人が確かめること」に出る。やり直しが続くと、人が確かめることが増え続けうる（外す理由を書かない限り減らない）。
- 項目の文面が同じでなければ、ゴールガーディアンが言い換えて書いた同じ点は重なって出うる（指示では、書き写さないよう求めている）。
- 外す理由が実際の解消を伴っているかは、sacty は確かめない。
