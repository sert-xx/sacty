# ADR（Architecture Decision Record）

過去の意思決定を残す。いつ・どのような理由で今の仕様に決まったかがわかるようにする。
方針は [docs の入口](../README.md) を参照。

## ファイル名

```text
<日時>[-<ステータス>]-<スラッグ>.md
```

- 日時：`YYYYMMDD-HHMM`。**UTC** で、決定した日時にする。
  - 新しく書く ADR は、書いた日時（その ADR を足す PR を作る前に決める）。
  - 過去の決定を後から起こすときは、決めた PR のマージの日時（`gh pr view <番号> --json mergedAt`）。
  - 例：`20261014-0816`（2026-10-14 08:16 UTC）
- ステータス：採用中のものには付けない。ほかの ADR で方針が変わった・やめた・採用しなかったときに、日時の後ろに付ける
  （下の表）。
- スラッグ：英小文字・数字・`-` だけ。何の決定かがわかる短い名前（例 `docs-structure-and-policy`）。
  ステータスの語（`superseded`・`deprecated`・`rejected`）で始めない。ステータスを付けてもスラッグは変えない。
- 例：
  - 採用中：`20261014-0816-docs-structure-and-policy.md`
  - 置き換えられた後：`20261014-0816-superseded-docs-structure-and-policy.md`

| ステータス | 意味 | 本文に書き足すこと |
| --- | --- | --- |
| （無し） | 採用中 | — |
| `superseded` | ほかの ADR に置き換えられた | `置き換え先` に、置き換えた ADR へのリンク |
| `deprecated` | 置き換えは無いが、やめた（その決定がもう効いていない） | `廃止` に、やめた日時・理由・やめた PR か ADR |
| `rejected` | 検討したが採用しなかった（記録として残す） | `理由` に、採用しなかった理由 |

すべての ADR を `docs/adr/` の直下に置く（サブディレクトリに分けない。名前の順が決定の順になるように）。

ファイル名の規則は `tests/docs/docs.test.ts` で確かめる。

## 置き換えるときの手順

1. 新しい ADR を足し、`置き換え元` に古い ADR へのリンクを書く。
2. 古い ADR のファイル名を `git mv` で変え、日時の後ろにステータスを付ける。
3. 古い ADR の `ステータス` を変え、`置き換え先` に新しい ADR へのリンクを書き足す。**本文（背景・決定・理由・影響）は書き換えない。**
4. 古い ADR へのリンク（ほかの ADR・仕様書など）を、新しいファイル名に直す。

一部だけ置き換えるときも `superseded` を付け、`置き換え先` にどの部分が置き換わったかを1行で書く。
置き換えの関係（`superseded` の ADR の `置き換え先` と、そのリンク先の `置き換え元`）が揃っていることは、テストで確かめる。

## 本文のひな形

```markdown
# <決定を1文で>

- 日時: YYYY-MM-DD HH:MM UTC
- ステータス: 採用 | 置き換え済み（superseded） | 廃止（deprecated） | 却下（rejected）
- 関係する PR・タスク: #<PR 番号>、PBI-<番号>
- 置き換え元: なし | [<ADR のタイトル>](<ファイル名>)
- 置き換え先: なし | [<ADR のタイトル>](<ファイル名>)（置き換えた部分）

## 背景

何が問題で、何を決める必要があったか。そのときの制約。

## 決定

何をどう決めたか。

## 理由

そう決めた理由。比べたほかの案と、採らなかった理由。理由がわからないものは、わからないと書く（推測で作らない）。

## 影響

この決定で変わること・守ること・後で困りうること。関係する仕様書へのリンク。
```

- `置き換え元`・`置き換え先` の行は消さず、無ければ `なし` と書く。
- `deprecated` にしたときは、`置き換え先` の下に `- 廃止: YYYY-MM-DD HH:MM UTC <理由>（#<PR 番号>）` を書き足す。
