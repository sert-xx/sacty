# PR を参照する sacty のタスクの投稿は、取り込みの経路に関わらず、指摘のある回を元のタスクの PR の指摘として取り込む

## 背景

元のタスクの PR の指摘の取り込みで、その PR をレビューした sacty のタスクの投稿を取り込むのは、レビュー用のラベルで取り込んだ
レビューだけのタスク（`source.review: sacty`）の、指摘のある回だけだった（PBI-88・PBI-145 の決定。引き継いだ人の PR では、依頼・ラベルで
取り込んだタスクも含めていた）。

sacty が作った PR を、人が手動で作ったレビューのタスク（本文に PR の URL を書いたもの）でレビューさせると、そのタスクには `source` が無いので
投稿が取り込まれず、元のタスクが差し戻されずに止まった。依頼（`requested`）で取り込んだタスクのレビューも同じく届かなかった。

## 決定

- この PR を参照する sacty のタスク（取り込んだ PR か、本文の PR の URL）の投稿は、取り込みの経路（レビュー用のラベル・レビューの依頼・
  手動で作ったタスク）に関わらず、判定に指摘のある回（`changes_required`・`suggestions`・判定を読めなかった回）を、元のタスクの PR の指摘として取り込む。
- 指摘の無い回（`no_findings`）と、判定の記録が無い回（レビューの工程を持たない・まだ実行していないタスクの回）は取り込まない。
- ほかの除外（そのタスクのアカウントと違うアカウントの投稿・bot の投稿・この PR を参照していないタスクの目印付きの投稿・二重の取り込み）と、
  取り込んだ後の流れ（ゴールガーディアンが戻し先を判断して差し戻す）は変えない。再レビューも回ごとに判定する。
- 置き換えるのは、PBI-88・PBI-145 の決定のうち「`source.review: sacty` のタスクに限る」部分だけ。

## 理由

- 人が手動でレビューのタスクを作るのも、レビューを依頼するのも、人がそのレビューを求めたことにあたる。PBI-19 で除いた理由
  （人が求めていない AI のレビューを、差し戻しとして扱わない）とは矛盾しない。
- 経路で分けず、「その PR を参照し、判定に指摘のある回」だけで決めれば、規則が1つになり、引き継いだ PR での例外も要らなくなる。
- 実装のタスクが自分の投稿に印を付けて除く案は採らなかった。実装のタスクは自分の PR にレビューもコメントも投稿しないので除くものが無く、
  指摘の無い回のむだな差し戻しや、関係ない sacty のレビューの取り込みも防げないため。
- 手動のタスクに `source` を付けて、ラベル経由のタスクと同じに扱う案は採らなかった（取り込み・工程の選び方まで変わるため）。

## 影響

- 手動・依頼のレビューのタスクが sacty の PR に指摘のあるレビューを投稿すると、元のタスクが差し戻され、やり直しの実行が増える（費用は予算で止める）。
- この変更より前に投稿され、まだ取り込んでいない指摘は、変更後の次の PR の確認で取り込まれる。
- 規則は[承認と差し戻し](../spec/approval.md#pr-の指摘の取り込み)・[タスクと工程](../spec/tasks-and-steps.md#pr-のレビューだけのタスク)・[取り込み](../spec/intake.md)に記す。
