# 人がドラフトを外した PR を、sacty がドラフトへ戻さず、sacty の外しを作業履歴に記録して見分ける

- 日時: 2026-11-21 20:22 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-468
- 置き換え元: なし
- 置き換え先: なし

## 背景

PBI-447 の PR #501 で、sacty のレビューが「提案あり（マージは可）」と判定した後に、人がドラフトを外した。その3秒後に sacty がドラフトへ戻し、直後のマージが「まだドラフト」で失敗した。
sacty は、「指摘なし」を待つ実装の PR を、GitHub の状態にかかわらずドラフトへ戻していた（`settleDraft`・`redraftAwaiting` など）。人が外したことを区別する材料が無かった。
GitHub のタイムラインの切り替えは、actor が PR の作者・sacty・人で同じアカウントになる（PR #501 では 3 つとも同じ）。actor では、人の切り替えと sacty の切り替えを見分けられない。

## 決定

- 人が GitHub でドラフトを外した PR は、一時停止に伴う戻し（`settlePausedDraft`）のほかは、sacty がドラフトへ戻さない。直しの提出・PR の確認・レビューの回の始め・外す間の変化・重ねた PR の付け替えのどれでも、人がコミットを足した後も同じにする。
- 戻す前に、GitHub の最後のドラフトの切り替え（`ReadyForReviewEvent`・`ConvertToDraftEvent`）を読み、切り替えが1件も無い PR と、最後の外しのイベント ID が sacty の記録した外しの ID と合う PR は戻す。それ以外（人が外した・読めない・決められない）は戻さない。
  sacty の外しは、外す要求（`markPullRequestReadyForReview`）の答えの `ReadyForReviewEvent` の ID を、作業履歴（`PullRequestUndraftNoted`）に記録して覚える。再起動で消えない。
- 戻さなかったことは `PullRequestRedraftSkipped`（理由 `person`・`unreadable`・`undetermined`）で作業履歴に残す。重複は作業履歴から決める（外し1回につき1件・読めない間に1件・決められない PR につき1件）。
- 切り替えの履歴を読めない（`unreadable`）・最後の切り替えが sacty のものか決められない（`undetermined`）ときも、戻さない側に倒す。決められないのは、前の版が外した PR（外しの ID の記録が無く、`undraftTracked` の無い `PullRequestMarkedReady` などがある）と、外す要求の答えから今回の外しの ID を決められなかったとき。
- 重ねた PR に直しを提出するときは、判定で戻さない PR を、`pr.stackDraftFailed` で止めずに進める。
- 戻さなかった PR のレビューの回は、今のまま続ける（台帳では「指摘なし」を待つ状態のまま）。マージは今も承認として進む。
- 新しい 2 種類のイベントを記録した後は、前の版のデーモンへ切り戻せなくなる。互換の層は作らない。不具合は前の版へ戻さず、直した版を出して直す。

## 理由

- 人が外した PR を戻すと、マージが「まだドラフト」で失敗する（PR #501）。人の操作を尊重する先例は、すでにある（理由が `unchanged`・`needs_decision` の一時停止）。
- actor で見分けられないので、sacty が自分の外しを覚えて照合するしかない。メモリー上の値は再起動で消え、再起動の後に人の外しと取り違えるため、作業履歴に残す。
- 読めない・決められないときに戻すと、人が外した PR を戻す失敗が再び起きる。戻さないと、レビューしていない先頭がマージできる状態になりうるが、人が外した PR は、人がその状態を選んでいる。
- 採らなかった案：外した時刻で照合する。時計のずれと、外す要求の遅れで取り違える。
- 採らなかった案：互換の層（前の版が読み飛ばす形で記録する）。前の版は、作業履歴の全行を `EventInput` で parse するので、未知の種類を読み飛ばせない。層を作るなら、読める版を先に出す 2 段の公開になる。

## 影響

- 新しいイベントを最初に記録した時点から、前の版のデーモンは作業履歴を読めず、起動できない。切り戻す前の確かめ方：作業履歴の `type` に `PullRequestUndraftNoted`・`PullRequestRedraftSkipped` の行が無いこと。
- この変更より前に sacty が外した PR（外しの ID の記録が無い）は、決められないとして戻さない。デプロイの時点で開いている PR にだけ効く一時的なこと。その PR に人がコミットを足しても、ドラフトに戻らず、レビューしていない先頭がマージできる状態になる。
- sacty と同じアカウントで外したときの GitHub のタイムラインの反映の遅れで、外しの ID を決められないことがある。その PR は、`undetermined` で戻さない。
