# オーケストレーターへの質問の答えで、実行中の実行のログの写しも読ませる

- 日時: 2026-10-20 11:08 UTC
- ステータス: 採用
- 関係する PR・タスク: #171
- 置き換え元: [オーケストレーターへの質問の答えで、タスクの終わった実行のセッションログを、答えの実行ごとに並べて読み取り専用でマウントする](20261014-1445-superseded-question-reads-session-logs.md)
- 置き換え先: なし

## 背景

「オーケストレーターに質問」の答えでは、タスクの終わった実行のセッションログだけを読ませていた
（[前の決定](20261014-1445-superseded-question-reads-session-logs.md)）。実行中の実行は、書き始めた後に分かった秘密情報（コンテナで
更新されたトークンなど）を閉じるときに伏せ直すので、閉じる前のファイルには残っていることがあり、並べていなかった。
しかし質問したいのは、処理が長引いていて、いま何をしているかを確かめたいときが多い。その実行中の工程のログを読めないので、
台帳（工程を始めたことしか分からない）からしか答えられなかった。

## 決定

- デーモンは、開いていてまだ閉じていない実行のセッションログを覚えておき（`SessionLogStore` の中）、求められたら、いまの写しを返す
  （`SessionLog.snapshot`）。
  - 写しは、ファイルに書いた分と、メモリーに持つ分（先頭の書きかけの行・上限を超えた後の末尾・伏せるために持っている分）をつなげ、
    そのときに分かっている秘密情報（後から分かった値も）で伏せ直してから、最後の改行で切る。末尾の前を省いていれば、閉じたときと同じ目印を入れる。
  - ファイルそのものは変えない（伏せ直しは、これまでどおり閉じるとき）。
- 質問への答えでは、終わりが記録されていない実行のうち、このデーモンで開いている実行の写しを、ファイルとして書いて並べる
  （ハードリンクにしない）。一覧の状態は `running` とし、写した時刻を持たせる。開いていない実行（デーモンが止まった）は、これまでどおり並べない。
- 指示には、実行中の実行の行に、いつの時点の写しかを書き、いまの様子を聞かれたら `events.jsonl` の末尾から読み、いつの時点の様子かを
  答えに書くように求める。
- 監査（同じ並べ方を使う）は変えない（実行中の実行は並べない）。

## 理由

- 実行中のファイルを直接（ハードリンクで）渡さず写しを作るのは、閉じる前のファイルに残っているかもしれない、後から分かった秘密情報を
  渡さないため。写すときに、そのときの秘密情報で伏せ直せば、前の決定が避けたかったことは起きない。
- 最後の改行で切るのは、書きかけの JSON の行を渡さないため。伏せた後で切るので、途中までしか届いていない秘密情報の頭も残らない
  （秘密情報は改行を含まない前提。含む値の扱いは、これまでの伏せ方と同じ）。
- メモリーに持つ分もつなげるのは、伏せるために持っている数十文字と、上限を超えた後の末尾が、いまの様子を知るのにいちばん要る部分だから。
- 写しを、このデーモンで開いている実行に限るのは、ほかのデーモンが書いている（ふつうは1つしか動かない）・デーモンが止まって残ったファイルには、
  後から分かった秘密情報を知るすべが無いため。
- 監査を変えないのは、監査は終わったタスクを見るもので、いまの様子を知る必要が無いため。

## 影響

- 処理が長引いているときに質問すると、実行中の工程のログを読んで、いまの様子を答えられる
  （[タスクと工程](../spec/tasks-and-steps.md#オーケストレーターに質問)、[イベントログ](../spec/event-log.md#セッションログ実行ごとのファイル)）。
- 写すときに、実行中のログ（1実行あたり最大 20MB）をメモリーに読み、ファイルに書くので、質問の前の準備に少し時間と場所を使う。
- 実行中の実行のエージェントの元のファイルは、終わるまで読めない（コンテナが終わってから写すため）。
- 写しは質問を受けた時点のもので、答えの実行の間に進んだ分は入らない。
