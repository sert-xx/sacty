# PR の push の一時的な失敗は、15 秒・1 分・3 分の最大 3 回、push だけをやり直す

- 日時: 2026-11-21 18:40 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-467
- 置き換え元: なし
- 置き換え先: なし

## 背景

2026-11-21 に 2 回、PR を作る・直しを積む `git push` が `! [remote rejected] <sha> -> <branch> (failed)` で拒まれ、タスクが止まった。
保護・ルール・名前の衝突は無く、GitHub 側の一時的な失敗と見られた。
人が再開すると、同じコミットで通った。
停止の理由の文には、成功時の案内（`remote: Create a pull request ...`）が混ざり、失敗の行が通知で切り詰められて読みにくかった。

## 決定

- PR の push（実装の PR・引き継いだ PR・要求要件と設計の PR。ブランチの削除は除く）が一時的な失敗で拒まれたら、止めずに、同じコミットを同じブランチへ、15 秒・1 分・3 分の最大 3 回、push し直す（`pushRetryDelaysMs`）。
- 一時的とみなす失敗：`[remote rejected] ... (failed)`・GitHub の内部エラー・HTTP 5xx・レート制限（429、レート制限の 403）・接続の失敗。
  一時的でない失敗を先に判定し（保護・ルール・理由が `(failed)` 以外の `[remote rejected]`（`workflow` の権限が無いことによる拒否を含む）・fast-forward でない・認証の失敗・レート制限を含まない 401・403）、どちらにも当たらない失敗は一時的でないとして止める。
- 判定は git の英語の文言で行うので、PR の push は `LC_ALL=C` で実行する（デーモンの `LANG` に依らない）。
- 作業履歴に `PushRetried`（待った後、push し直す直前）と `PushRetryEnded`（通った・上限まで通らなかった）を記録する。状態は変えない。
- 同じコミットがすでにブランチの先頭にあれば、git の push は通る。通ったとして扱い、その回も回数に数える。
- 待つ間に一時停止・中止・デーモンの停止を求められたら、push も記録もせずにやめる。待つ間も、タスクの実行の枠は手放さない（レビューの `retryTransient` と同じ）。
- 引き継いだ PR は、一時的な失敗が上限まで続いても、人が PR のブランチを進めた（`pr.continuedBranchMoved`）とせず、`pr.failed` で止める。先頭を読み直す再 push は、一時的でない失敗のときだけ残す。
- 停止の理由の文は、`remote:` の案内の行（空・`Create a pull request`・`To create a merge request`・URL だけの行）を除き、`!`・`error:`・`fatal:` の行を先頭に置く。拒否の理由の `remote:` の行は残す。

## 理由

- 一時的な失敗は、待てば通る。人の再開を待つより、数分の自動のやり直しのほうが、人の手間も、止まっている時間も小さい。
- やり直すのは push だけ。コミットは同じ内容・日時で再現できるので、同じコミットの push は何も変えずに通る。
- 回数と間隔は決め打ちにした。レビューの GitHub への問い合わせ（15 秒・1 分・3 分・5 分）より短くしたのは、push の失敗は多くが数十秒で戻り、止まっている間は PR が進まないため。
- 採らなかった案：エージェントの実行の失敗もやり直す。対象外（別の方針）。
- 採らなかった案：既存の `isTransientGitHubFailure` の使い回し。HTTP の GitHub の失敗向けで、git の標準エラーの文は読めない。

## 影響

- 新しい記録（`PushRetried`・`PushRetryEnded`）を残した作業履歴は、この記録を知らない前の版のデーモンが読めず（`EventInput` の検査で落ちる）、起動できない。一度記録したら、前の版に戻せない。
  - 前の版に戻せるのは、どちらかを記録する前まで。
  - 戻す前の確かめ方：作業履歴の `activity` の表に、`type` が `PushRetried` か `PushRetryEnded` の行が無いこと。
  - 戻して起動できなければ、この変更の版へ進め直す。
- 前の版の形（案内の行が残る文）で止まったタスクの記録は、書き直さない。再開して push が通れば消える。
