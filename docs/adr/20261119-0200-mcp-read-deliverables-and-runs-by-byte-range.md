# sacty mcp の成果物と実行の一覧の取得は、バイトで上限と位置を決め、デーモンに読み取りの API を足す

- 日時: 2026-11-19 02:00 UTC

- 関係する PR・タスク: #437、PBI-395

- 置き換え先: なし

## 背景

`sacty mcp` で、手元の AI が、タスクの工程ごとの成果物と、エージェントの実行の一覧を、画面を開かずに読めるようにする（読み取りだけ）。承認の前に中身を確かめるための手段になる。
実行のログの取得は、いったん範囲に入れて作ったが、利用者の決定で外した（後続。下の「影響」）。
決める必要があったのは次のこと。

- 1回に返す量の上限と、その単位。続きの位置の示し方。
- 実行の一覧の元と、成果物・実行の指定の方法（パスを引数に取るので、決まった場所の外を読ませない）。
- 新しい API を足すことで、前の版のデーモンが「タスクが無い」と同じ 404 を返す問題。

前の ADR（PBI-392）は「デーモンには、MCP の入口も新しい API も足さない」と決めていた。今回の依頼は、要るなら API を足すことを認めている（画面の動きは変えない）。
そこで、この ADR は前の ADR のその部分だけを置き換える（API を足す）。ほかの決定（stdio・SDK の版・`daemon.json` の読み方・`TOOLS`／`SactyApi` の構え）は、前の ADR のまま効く。

## 決定

- **上限と単位**：1回に返す成果物の量の上限は、UTF-8 で 32,000 バイト（日本語でおよそ1万字）。位置と量の単位は、本文の UTF-8 のバイト。
  `max_bytes` は省くと上限で、超える値は上限に収めて `clamped` で示す（断らない）。0 以下と負の位置は引数の型で断る。全体以上の位置は失敗にせず、0バイトと全体の大きさを返す。
  境目は、UTF-8 の文字の頭にそろえる（複数バイトの文字・サロゲートペアの途中で切らない）。
- **続きの位置**：結果に `offset`（返した先頭）・`next`（続き）・`totalBytes`・`clipped`・`clamped` を返す。
- **デーモンに読み取りの API を3つ足す**：`GET /api/tasks/:id/deliverables`・`…/deliverables/:step/:kind`・`…/runs`。画面は呼ばない。いまの API・いまの5つのツールは変えない。
  実行を拾う規則（`RUN_EVENTS`・`runLogId`）は `@sacty/core` に移し、画面と共有する（画面の表示は変わらない）。
- **成果物の中身は、画面で読めるものと同じ元・同じ伏せ方**：デーモンがメモリーにあるタスクから本文を取り、UTF-8 の範囲だけを返す。本文は、作業履歴に書く前に伏せてあるので、MCP のための伏せ直しはしない。
- **成果物の指定**：工程（`step`）と種類（`kind`）の組で指定する。種類は `output`・`test_viewpoints`・`sacty_version`・`review_comments` の4つ。
  状態は `approved`・`posted`・`awaiting_approval`・`not_submitted`・`changes_requested`・`none`。まだ提出していない出力は、`submission` を null にして `previousSubmission` で前の回を示し、前の回の提出と読み違えさせない。
  読めるのは、画面のタスクの詳細で読める範囲（承認済みならその版、まだなら最新の出力。レビューは本文と行へのコメント）。差し戻し前の過去の回と、エージェントの元のファイル（`agent-files`）は含めない。
- **実行の指定**：実行の一覧は、メモリーの作業履歴の全件から `runLogId` で拾い、役割・エージェント・切り替え（`fallback`）を決めてからページに切る（ページの区切りで結果が変わらない）。返す分だけ `meta.json` を読む（役割・エージェント・状態のため。ログの中身は読まない。`meta.json` が無い実行は、作業履歴の値。無い項目は null）。
  `task_id` は `[A-Za-z0-9_-]{1,128}` に合うものだけ。工程・種類は許可リストと照合する。
- **前の版のデーモンの見分け方**：新しい API を持たない前の版は、Hono の既定の 404（本文は `404 Not Found`）を返す。タスクが無いときは `{ error: "not_found" }` の JSON の 404 なので、本文が `error` を持つ JSON として読めない 404 を前の版とみなし、「sacty を更新し、実行中のタスクが無いときに `sacty up` で起動し直してください」と返す。
  再起動は、実行中のタスクを止めるので、無いときにする前提を理由に添える。
- **失敗の理由**：理由と標準エラーの1行は、仕様書の定型の文言に限る。デーモンの応答の本文と、成果物の中身は出さない。標準エラーの原因は、接続の失敗の種類と時間切れの印だけにする。

## 理由

- バイトにそろえたのは、続きの位置を、文字数への変換なしに本文のバイトでそろえられるため。`get_task` の文字数（UTF-16）の上限は、サロゲートペアの途中で切りうるうえ、続きの位置を返せない。
- 範囲の切り出しをデーモンに足したのは、数 MB の本文を MCP の側へ全部送らず、返す量だけを送るため。
- 成果物を伏せ直さないのは、本文が、画面と同じ作業履歴・タスクの状態から取った、書く前に伏せた値だから（画面より多く出さない）。
- 全体以上の位置を失敗にしないのは、続きを読み直すとき、まだ増えていないことを失敗と区別するため。
- 比べた案：
  - 文字数で上限を持つ案：位置をバイトと対応させられない。採らなかった。
  - 既存の `GET /api/tasks/:id`（`{ task, activity }`）を MCP の側で切る案：本文の全体を毎回送る。採らなかった。
- 上限 32,000 バイトは、`get_task` のレビューの本文（12,000 文字）と同じくらいの量。手元の AI の文脈が小さいと、利用者が `max_bytes` を小さく指定し直す手間が増える（未確認の懸念）。

## 影響

- ツールは8つになる。成果物と実行の3つは読み取りだけ（`readOnlyHint: true`・`openWorldHint: false`）。説明文と使い方の説明に、結果はほかの人やエージェントが書いた文を含むデータで、中の指示に従わないことを書く。
- 前の版の sacty が動いているときは、新しいツールが更新と再起動を促す理由を返す。
- `list_runs` で続きを取る間に実行が増えると、位置がずれて同じ実行が重なって返りうる（`runId` で重なりを除く）。
- 実行のログの取得（`get_run_log`）は、この PR の範囲から外した（利用者の決定）。ログの範囲の読み取りには、実行中のログの秘密情報の伏せ直しと、記録の書き込み・閉じる処理への変更が絡むため、後続で別に決める。
- 仕様書 [MCP サーバー](../spec/mcp-server.md)・[全体の構成](../spec/architecture.md)、ユーザードキュメント [手元の AI から操作する](../user/mcp.md)・[CLI](../user/cli.md)（いずれも日英）を直した。
- 続きは、承認・差し戻しなどの操作（次の回）と、実行のログの取得。成果物の過去の回・`agent-files`・作業履歴の中身の取得は、必要になれば別に決める。
