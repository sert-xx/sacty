# 認証ファイルの書き戻しは、コンテナの停止を確かめられたときだけ行い、ステージしたファイルはリンクを辿らずに1度だけ読む

## 背景

コンテナの停止を確かめられないときも、認証ファイルの書き戻し（staging → ホスト）が動き、staging のファイルをリンクを辿って読んでいた。
動いたままのコンテナが staging の認証ファイルをホストの別のファイルへのリンクに差し替えると、その中身がホストの認証ファイルに書き戻される
おそれがあった。

## 決定

- コンテナが止まったことを確かめられない実行では、認証ファイルを書き戻さず、理由をデーモンのログに残す（パスとコンテナ名だけ。値は出さない）。
- ステージしたファイルは O_NOFOLLOW・O_NONBLOCK で開き、fstat で通常のファイルであること、一時ディレクトリと途中のディレクトリがリンクでないこと
  （開く前と後）を確かめてから、開いた fd から読む。リンク・通常のファイル以外なら `not-regular` として書き戻さず、ログに残す。
- ステージしたファイルは1度だけ読み、そのハッシュで比べて、その中身をそのまま書く（比べた後に差し替えられても、別の中身を書かない）。
- 出力から伏せる値を集める処理（`collectSecrets`）も同じ読み方にする（リンクの先や FIFO を読まない）。
- 開くときの確かめとフラグは、#75 の元のセッションのファイルの写し（`agent-sessions.ts`）と共有する。

## 理由

- PR の本文にあるのは、上の「背景」のおそれを塞ぐため、#75 の `openSource` と同じ流儀で塞ぐ、ということ。
- ほかの案との比較は記録に無い。

## 影響

- 停止を確かめられない実行では、コンテナの中で更新された認証ファイルがホストに戻らない（理由はデーモンのログに出る）。
- 通常の更新・未変更・ホスト側の更新の優先・ファイルの消失の、これまでの振る舞いは保つ（レビューで確かめた）。
- 実際の Docker・実際の認証情報での確認は、この PR の時点では行っていない。
