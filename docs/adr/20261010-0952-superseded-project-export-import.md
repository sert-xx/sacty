## 背景

#8 でプロジェクトと GitHub Issue の取り込み元を作った（PBI-5 の前半）。後半（PBI-5b）として、プロジェクトの定義をほかの環境へ
持ち出せるようにする必要があった。個人の設定と秘密情報は含めず、インポートの時にも重複を検査することが受け入れ条件。

## 決定

- エクスポートの形式は `{"sacty":"project","version":1,"project":{name, sources, repositories}}` にする。ID・日時は含めない。
  GitHub のトークンなどの個人の設定・秘密情報は、もともと `config.yaml`（個人）とキーチェーンにあり、プロジェクトの定義には含まれない。
- エクスポートは、プロジェクトの設定画面から JSON のファイル（`sacty-project-<名前>.json`、日本語の名前は `filename*`）でダウンロードする。
- インポートは、プロジェクトの画面でファイルを選び、新しいプロジェクトとして作る。ファイルは 1MB まで。
- 形式（`sacty: "project"`）や版の違うファイル、JSON として読めないファイル、知らない項目（`token` など）を含むファイルは、理由を出して拒否する（API では 400）。
- 取り込み元がほかのプロジェクトと重複していれば、作成と同じ検査で拒否する（409）。

## 理由

- 知らない項目を含むファイルを拒否するのは、秘密情報などを気づかずに取り込まないため（PR の本文）。
- 形式を JSON にした理由、版を付けた理由、インポートを常に新しいプロジェクトとして作る理由は、記録に無い。

## 影響

- 形式を変えるときは、版（`version`）で見分ける。今の版と違うファイルは拒否される。
