# sacty のレビューのタスクの投稿は、提案だけの回も元のタスクの PR の指摘として取り込む

## 背景

sacty は、作った PR にレビュー用のラベルを付け、別のタスク（`source.review: sacty`）に別のコンテキストでレビューさせている。
そのレビューの投稿のうち、元のタスクの PR の指摘として取り込むのは、判定が「修正が必要（`changes_required`）」の回と、判定を読めなかった回だけだった。
「提案あり（`suggestions`）」の回は、マージしてよいので差し戻さず、取り込まなかった（レビューと修正の繰り返しで費用が増えるのを避けるため。
[PR のレビューのタスクは既定のスキルでレビューし、出力の形と投稿は sacty が決める。判定を3つにする](20261015-1617-review-prompt-follows-default-skills.md)）。
この ADR は、その決定のうち「元のタスクに届ける回」の規則だけを変える（ほかの部分はそのまま）。

運用すると、sacty のレビューが PR に指摘のコメントを付けても、提案だけの判定だと元のタスクが何もせず、人が指摘を読んで対応することになった。
ステークホルダーの期待は、sacty のレビューの内容を元のタスクが確かめて、対応・修正まで自動で進むこと。繰り返しの費用は、タスクの予算で止めればよい。

## 決定

- `source.review: sacty` のレビューのタスクが投稿したレビューは、指摘のある回（`changes_required`・`suggestions`・判定を読めなかった回）をすべて、
  元のタスクの PR の指摘として取り込む。指摘の無い回（`no_findings`）だけは取り込まない。
- 取り込んだ後の流れは変えない（ゴールガーディアンが戻し先を判断し、人の確認を挟まずに差し戻す。やり直しの上限はエスカレーション、費用は予算で止める）。
- ほかの除外（この PR をレビューしていない sacty のタスク・`requested`・`label` のレビューのタスク・bot・元のタスクのアカウントの目印付きの投稿）は変えない。

## 理由

- 提案だけの回でも、元のタスクが読めば直せる具体的な指摘が多く、人がさばくより自動で対応させた方が、別のタスクにレビューさせる目的に合う。
- 繰り返しの費用の歯止めは、取り込みを絞ることではなく、タスクの予算と差し戻しの上限で持つ（ステークホルダー）。
- 判定を読めなかった回を取り込む扱いと合わせると、「指摘が無いと分かった回だけ取り込まない」という1つの規則になる。

## 影響

- sacty のレビューに提案だけが付いた PR は、元のタスクが差し戻され、やり直しの実行が1回増える（費用が増える）。
- レビューのタスクは PR ごとに1つで、PR を更新しても新しいレビューのタスクは作らないので、取り込みの側からの無限の繰り返しは起きない。
- 規則は[承認と差し戻し](../spec/approval.md#pr-の指摘の取り込み)・[タスクと工程](../spec/tasks-and-steps.md#pr-のレビューだけのタスク)・[取り込み](../spec/intake.md)に記す。
