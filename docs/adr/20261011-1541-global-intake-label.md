# 取り込みのラベルを sacty 全体の設定にし、すべてのプロジェクトの対象で、そのラベルの付いた開いている Issue と PR をタスクにする

## 背景

#8 で、取り込みの条件のラベルはプロジェクトの取り込み元ごとに決め、取り込むのは Issue だけ（PR は除く）だった。#30 で取り込み元を無くし、取り込みのラベルは sacty 全体の設定にするまで、すべての対象で `sacty` に固定していた。ステークホルダーから、Issue や PR のトリアージはラベルで自動でよいが、どのラベルを対象にするかはプロジェクトごとではなく sacty 全体の設定として扱う、という要望があった。

## 決定

- 取り込むラベルは、プロジェクトとは別の sacty 全体の設定にする。画面はユーザーメニューの「sacty の設定」（`/settings`）。`~/.sacty` の SQLite（`settings` テーブル、1行）に保存する。
- すべてのプロジェクトの対象（Org・リポジトリ）について、そのラベルの付いた開いている Issue と PR をタスクにする。二重には取り込まない（PR は Issue と同じ番号の空間なので、同じ判定を使う）。ラベルを変えると、取り込みは先頭から読み直す。
- PR から作ったタスクは、取り込み元を PR（`github_pull_request`）として記録する。本文に PR の URL が無くても、その PR をレビューの対象にして、オーケストレーターに工程を選ばせる。調査の工程を選んだときは、結果を PR にもコメントで返す。
- ラベルが未設定なら取り込まない。設定画面とプロジェクトの一覧に、そのことと設定画面へのリンクを出す。
- ラベルの `"` と `\` は受け付けない。空の入力は「設定しない」として扱う。#30 で固定したラベル（`sacty`）は削除する。

## 理由

- ラベルを sacty 全体の設定にし、Issue と PR を自動で取り込むのは、ステークホルダーの要望による（本文）。
- `"` と `\` を受け付けないのは、検索の条件を壊すため（本文）。

## 影響

- 取り込むラベルは未設定の状態から始まり、設定するまで取り込みは止まる。
- ラベルを付けた PR も取り込まれ、レビューや調査の対象になる。
