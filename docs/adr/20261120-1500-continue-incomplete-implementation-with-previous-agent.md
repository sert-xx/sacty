# 未完了で終わった実装の続きは、直前の実行のエージェントから始める

- 日時: 2026-11-20 15:00 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-417
- 置き換え元: なし
- 置き換え先: なし

## 背景

2026-11-19、既定のエージェントが利用上限だったので、実装の実行は代わりのエージェントで動き、未完了で終わった。
続きの実行は、工程のエージェントを選び直す仕組みのため、利用制限の期限が切れた既定のエージェントで始まり、利用上限で失敗して代わりに切り替わった。
その結果、続きのはずの実行が、セッションの続きにならず、最初からの実行になった。
セッションを続けられるのは、直前の未完了の実行と同じエージェントのときだけである（[未完了の実装を同じセッションで続ける](20261115-2254-continue-incomplete-implementation-in-same-session.md)）。

## 決定

- 未完了で終わった実装の続きの実行は、直前の未完了の実行を動かしたエージェントで始める。工程に選ばれたエージェントと違うときも、利用制限の期限が切れているときも同じ。
- 直前の実行のエージェントは、作業履歴から決める（デーモンのメモリーに頼らない）。
- 未完了で終わった実行の開始より後に、人が実装のエージェントを変えていたら、人が選んだエージェントを優先する。
- 直前の実行のエージェントが使えない（設定から消えた・利用制限中・このタスクで失敗して使わない期限の中）ときは、工程に選ばれたエージェントと、その代わりにする。
- 時間切れで止めた実行の再開と、未完了でない次の実行は、選び方を変えない。
- 直前の実行のエージェントを優先して、工程に選ばれたものと違うときは、`AgentRunStarted` の任意項目 `chosenAgentId` に、元の選び方の結果を残す。

## 理由

- 未完了の続きの価値は、前の会話を引き継げることにある。エージェントが変わると、それを失う。
- 利用制限の期限が切れた既定のエージェントで始めると、続きが失敗して代わりに切り替わり、間に失敗の記録が挟まる。続きと見なされず、最初からの実行になる。
- 人が選んだエージェントは、続きより優先する。人の選択を覆さないためである。

## 影響

- 利用制限の期限が切れても、未完了の続きの間は、代わりのエージェントを使い続ける。既定に戻るのは、続きが終わった後の次の実行からである。
- 人が既定と同じ名前を選んでも `StepAgentChanged` は記録されないので、その場合は直前の実行のエージェントが優先される。
