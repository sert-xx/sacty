# 作業履歴に工程ごとの接続先・モデル・リーズニングエフォートを任意で記録し、タスクの詳細に工程ごとの費用を出す

- 日時: 2026-10-13 00:57 UTC
- ステータス: 採用
- 関係する PR・タスク: #52、PBI-46
- 置き換え元: なし
- 置き換え先: なし

## 背景

#46 で、工程ごとに違うエージェント（接続先・モデル・リーズニングエフォート）を使えるようにした。タスクの詳細では、どの工程をどのエージェントがどの設定で動かし、
いくらかかったのかを見られなかった。

## 決定

- 作業履歴の実行の開始・工程の選択・ゴールガーディアンの記録に、接続先・モデル・リーズニングエフォートを任意の項目として記録する。
  モデル・エフォートは config.yaml のエージェントに書いた場合だけ記録する。API キーなどの秘密の値は記録しない。以前の作業履歴もそのまま読める。
- タスクの詳細に「工程ごとの費用」の表を出す。行は、オーケストレーター（工程の選択）→ タスクの工程 → ゴールガーディアン（判定・最終レビュー）。
  工程ごとに、エージェントと設定・トークンの使用量・費用・実行の回数を出し、各回の内訳は折りたたんで出す。
- 行の合計は、タスクの費用（上部の「費用」）と一致させる。子タスクを持つタスクは、子タスクの合計も出す。換算した費用には「概算」を添え、記録の無い項目は「—」と出す。
- ゴールガーディアンの実行の結果（完了・失敗・中断）を記録し、失敗・中断の実行を「完了」と出さない。結果の無い以前の記録は、sacty が書いた理由の文言で判別し、成功とは断定しない。

## 理由

- ゴールガーディアンの行を足したのは、その費用もタスクの予算に入るので、合計を一致させるため（PR の本文）。
- モデル・エフォートを書いた場合だけ記録するのは、書いていなければエージェントの既定を使うため（PR の本文）。
- ゴールガーディアンの実行の結果を記録するのは、実行の失敗や中断でも判定の記録が残り、内訳で「完了」と出ていたというレビューの指摘による（レビューとその返信）。

## 影響

- 作業履歴の項目が増えるが、任意の項目なので、以前の作業履歴も読める。
- 記録の無い以前のタスクでは、モデル・エフォートが「—」になる。
