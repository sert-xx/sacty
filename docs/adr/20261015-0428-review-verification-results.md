# レビューの検証を親が共有し、結果の分析を独立した観点にする

- 日時: 2026-10-15 04:28 UTC
- ステータス: 採用
- 関係する PR・タスク: #111、PBI-101
- 置き換え元: [既定のコンテキストに、観点ごとのサブエージェントを並列に起動して集約するレビュースキル（親と担当を別のスキル）を同梱する](20261014-0034-superseded-review-skill-subagents.md)
- 置き換え先: なし

## 背景

観点担当が個別に検証コマンドを実行すると、同じ検証が重複し、並列実行によるビルド成果物や一時ファイルの競合が起こりうる。失敗した検証の原因を、レビューのほかの観点と区別して分析する手順も必要だった。

## 決定

- レビューの親は担当の起動前に、対象のプロジェクトで定められた検証コマンドを確認モードで実行し、結果を作業領域の外に保存して全担当へ共有する。自己レビューと PR レビューの両方に適用する。
- 横断の観点 X-1 は常に起動する。検証コマンドまたは CI の結果が1つでもあれば、失敗・警告・未実行の検証を分析する X-2 も起動する。
- 再レビューでは新しい対象で検証を実行し直す。検証が失敗しても観点担当の起動は止めず、今回の変更が原因かを調べる。
- 既定の Codex 設定の `max_threads` を16にする。

## 理由

検証を親がまとめて実行すれば、担当が同じ作業領域で同時に検証して結果を壊すことを避けられる。失敗の分析を X-2 に割り当てれば、各担当が自分の観点に必要なログを使いながら、検証全体の原因を見落とさずに扱える。

## 影響

レビューの前に検証の実行時間がかかる。PR レビューでも対象のプロジェクトの検証コマンドを実行するため、スキルは対象を変更しない確認モードと実行しない操作の範囲を定める。結果が無い場合は X-2 を起動せず、検証を実行していないことを明示する。現在の振る舞いは[コンテキストの仕様](../spec/context.md#既定のレビュー用スキル)に記す。
