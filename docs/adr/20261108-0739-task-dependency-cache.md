# 依存の準備の結果を、タスクごとのキャッシュのディレクトリで工程・実行の間で使い回す

- 日時: 2026-11-08 07:39 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-319
- 置き換え元: なし
- 置き換え先: なし

## 背景

コンテナは実行ごとに作り直し、依存のキャッシュの仕組みが無かった。
エージェントは工程ごとに、リポジトリの手順に従って依存をインストールし直していた。
実装の作業領域の clone には入れたものが残るが、ほかの工程の写し（`_snapshots`・`_guardian`）と最終レビューでは、毎回ダウンロードし直すか、入れずに推測で進めていた。

[実行のイメージをタスクに1つにした](20261108-0334-task-image.md)ので、同じタスクの実行は同じ環境で動く。
その上で、依存の準備の結果を使い回す仕組みを決める必要があった。
sacty が扱う対象のリポジトリの言語・パッケージ管理は決まっていないので、特定のものに寄せられない。

## 決定

- タスクごとのキャッシュのディレクトリを、作業領域の根の下の `_task-cache/<タスク ID>` に作る（持ち主だけが読み書きできる `0700`）。
- 対象のリポジトリをタスクのイメージで扱う実行（工程・最終レビュー・統合レビュー）だけに、コンテナの `/sacty-cache` へマウントし、書けたときだけ `XDG_CACHE_HOME` をそこに向ける（イメージの `ENV`・`env` より優先）。場所は別の変数（`SACTY_TASK_CACHE`）で渡し、`XDG_CACHE_HOME` を `-e` では上書きしない。
  - ゴールガーディアンの判定・オーケストレーター・情報収集・質問への答え・書き出し・外部作業・マージの後の監視には渡さない。
- エージェントの CLI 自身が `XDG_CACHE_HOME` の下に置くもの（Claude Code の `claude-cli-nodejs`：ログなど）は、`--tmpfs` でコンテナの中だけの場所にし、タスクのキャッシュに残さない。前の実行が残したもの（リンクを含む）は実行の前に消す。
- キャッシュを渡す実行の指示に、短い案内を足す（実行の共通の経路で。既定の規則には書かない）。`XDG_CACHE_HOME` を見ないツールは、そのツールのキャッシュの場所の設定で `XDG_CACHE_HOME` の下に向けさせる。認証の設定ファイル・秘密の値はそこに置かせない。キャッシュのせいで失敗するように見えたら、使わずに進めさせる。
- タスクの作業領域と同じときに消す。
  - 完了してもう作業領域を使わないとき（`taskWorkspacePaths` に含める）。
  - 中止の片付けの「作業領域」で（コンテナが止まったことを確かめられなければ消さない）。
  - デーモンの起動のとき、どのタスクのものでもないもの・中止したタスクのもの・もう作業領域を使わない完了したタスクのもの。
  - 進行中のタスクのものは、再起動しても残して使い回す。
- コンテナの実行ユーザーが書けなければ、使わない。コンテナの中で書けるかを確かめてからコマンドを実行し、書けなければ知らせを出し、`XDG_CACHE_HOME` には触れない（イメージの `ENV`・`env` の値も、未設定も、そのまま残る）。場所を渡した変数は、コマンドの実行の前に外す。
  持ち主・権限は作業領域と同じ考え方にする（sacty は持ち主を変えず、`--user` も付けない。持ち主のほかは書けない）。
- 壊れていても止めない。
  - タスクのディレクトリがディレクトリでない（リンク・ファイル）・読み書きできないなら、消して作り直す（リンクはリンクだけを消す）。
  - キャッシュの根がリンク・ファイル、または作り直せないときは、ログに理由を残して、キャッシュを使わずに実行する。

### 秘密の値の扱い

- 向けるのはキャッシュ（`XDG_CACHE_HOME`）だけにする。`HOME`・`XDG_CONFIG_HOME` は向けない。
  `.npmrc`・`pip.conf`・`.netrc`・`~/.docker/config.json`・`gh` の `hosts.yml` など、トークンを書くことが多い認証の設定ファイルは、これまでどおりコンテナを消すと消える。
- エージェントの CLI の認証は、実行ごとの設定の場所（`CLAUDE_CONFIG_DIR`・`CODEX_HOME`）のまま変えない。CLI 自身のキャッシュ（ログ）も残さない（上の `--tmpfs`）。
- キャッシュは作業領域の外に置くので、差分・コミット・PR には入らない。別のタスクのコンテナにはマウントしない。ホストのほかの利用者からは `0700` で読めない。
- ツールがキャッシュに秘密の値を書く（認証付きの URL を含むメタデータなど）ことは、sacty には防げない。そのため、同じタスクの、キャッシュを渡す実行の間だけで共有し、タスクが終われば消す。

## 理由

- `XDG_CACHE_HOME` は多くのツール（pip・uv・Go のビルドのキャッシュ・yarn など。各ツールの文書による）が既定で見る、言語に寄らない変数なので、sacty が個別のツールを知らずに済む。見ないツール（npm・Maven・Gradle・Cargo など）は、エージェントがそのツールの設定で向ければよい。
- 比べたほかの案と、採らなかった理由：
  - `HOME` ごと残す：認証の設定ファイルも残り、ほかの実行に渡ってしまう。
  - ツールごとの環境変数（`npm_config_cache`・`GOMODCACHE`・`CARGO_HOME` など）を sacty が並べる：特定のパッケージ管理に寄せることになり、並べていないツールでは効かない。`CARGO_HOME` などは設定（認証）も同じ場所に置く。
  - 依存のロックファイルのハッシュなどで、タスクをまたいで共有する：別のタスクと共有しない条件に反し、キャッシュの汚染がほかのタスクに広がる。
  - 準備を終えた `node_modules` などの作業領域の中身を写す：言語ごとに場所が違い、作業領域の写しの大きさも増える。
  - 作業領域の中（`<タスク ID>/` の下）に置く：作業領域があるかで用意し直すかを決めている（`workspaceMissing`）ので、キャッシュだけがあると用意し直さなくなる。
  - すべての実行に渡す：判定・情報収集・質問への答えは依存を入れないうえ、外から来た文を読む実行がキャッシュを書き換えると、後の工程に響く。
- 書けるかをホストで確かめないのは、ホストの権限では、コンテナの実行ユーザー（UID）から書けるかが分からないため（Linux のバインドマウントは UID で判定し、Docker Desktop などは持ち主をコンテナの実行ユーザーに見せる）。
  書けない場所に向けたままにすると、キャッシュに書けないと止まるツール（Go のビルドのキャッシュ・Playwright のブラウザなど）が、これまで動いていた実行（作業領域に書かないレビューなど）まで失敗させるので、指示の案内だけに任せない。
  キャッシュを作業領域より緩い権限（`0777` など）にする・`chown` するは、別のホストの利用者に読まれる・デーモンに root が要るので採らない。
- 案内を既定の規則ではなく指示に足すのは、最終レビュー・統合レビューには既定のコンテキストを渡さないため。キャッシュを渡す実行だけに届き、ほかの実行の指示を長くしない。
- 書けなかったときに `XDG_CACHE_HOME` に触れないのは、イメージの `ENV`・`env` で指定した場所には書けても、`HOME` の下の既定の場所を使えない環境で、これまで動いていたコマンドを失敗させないため。
  `-e XDG_CACHE_HOME` で上書きしてから戻す形にしないのは、Dockerfile の `ENV` の値は `-e` で消え、コンテナの外からは分からず戻せないため。書けたときだけ向ける形なら、戻すものが無い。
- 起動のときに、中止したタスクのものも消すのは、中止の片付けの途中でデーモンが止まると、ほかに消す時機が無いため。進行中のタスクのものを残すのは、再起動のたびに準備し直さないため。

## 影響

- 同じタスクの2回目以降の実行で、依存のダウンロードが速くなる（作業履歴に、このリポジトリの `npm ci` で測った時間を書いた）。
- タスクが続く間、キャッシュの分だけディスクを使う。完了・中止で消す。
- 同じタスクの実行が同時に動くと、同じキャッシュを同時に使う。多くのツールのキャッシュは同時に使えるが、使えないツールでは、エージェントが使わずに進めることになる。
- Claude Code が自身のキャッシュの場所の名前を変えると、CLI のログがタスクのキャッシュに残る（タスクが終われば消える）。Codex が `XDG_CACHE_HOME` の下に自身のものを置くかは確かめていない。
