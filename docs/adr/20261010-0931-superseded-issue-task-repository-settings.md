## 背景

#6 で、実装の対象リポジトリを config.yaml の `repository` で1つだけ指定し、プロジェクトの設定で置き換える予定とした。
GitHub Issue からタスクを作れるようになると、タスクごとに対象のリポジトリが変わる。

## 決定

- Issue から作ったタスクは、その Issue のリポジトリに実装する。ベースブランチ・テストのコマンド・PR を作るかは、プロジェクトの「リポジトリの設定」から取る。
- リポジトリの設定が無いとき、または PR を作る設定なのにトークンが無いときは、理由を記録して止める。
- PR の本文に `Closes #<番号>` を入れ、マージで Issue を閉じる。
- 画面で作ったチケットは、これまでどおり `config.yaml` の `repository` を使う。

## 理由

理由は記録に無い。

## 影響

- 対象リポジトリの設定が、Issue のタスクではプロジェクト、画面で作ったチケットでは config.yaml、の2か所に分かれる。
