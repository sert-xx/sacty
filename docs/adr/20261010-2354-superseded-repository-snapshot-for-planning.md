# 対象リポジトリはタスクの開始時に clone して起点のコミットを固定し、要求要件・設計の工程には起点のコードを読み取り専用で渡す

- 関係する PR・タスク: #19、PBI-15
- 置き換え元: なし
- 置き換え先: [調査・要求要件・設計などの工程には、書き込める使い捨ての写しを渡し、コードの変更だけをさせない](20261013-0003-writable-disposable-workspace-for-read-steps.md)（要求要件・設計の工程に読み取り専用で渡す部分）

## 背景

対象リポジトリの clone を作業領域にしていたのは実装の工程だけで、要求要件・設計のエージェントは空の作業領域で動いていた。そのため、
既存のコードを読まずに要求要件・設計を書くことになっていた（動作確認で気づいた）。

## 決定

- 対象リポジトリは、どの工程から始まるタスクでも、タスクの開始時（最初の実行）にベースブランチの最新を clone する。
  `RepositoryPrepared` は、最初の工程の `AgentRunStarted` より前に、タスクの開始時に一度だけ記録する。
- そのとき記録した起点のコミットを、タスクの最後まで使う。途中で取り込み直さない。作業領域を用意し直すときも、記録した起点のコミットに切り替える。
  起点のコミットを取得できなければ、起点を変えずに止める。
- 要求要件・設計の工程には、起点のコミットのファイルを、退避した git のメタデータから一時インデックスで実行ごとのディレクトリに書き出し
  （`RepositoryWorkspace.snapshot`、.git は含めない。利用者やシステムの git の設定は読まない）、読み取り専用（`:ro`）でコンテナにマウントする。実行が終わったら消す。
- 差し戻しや変更の申し出でやり直すときも、起点のコミットから書き出し直す（実装の変更は見えない）。
- 対象リポジトリを用意できない（clone できない・設定が無い・GitHub のアカウントを選んでいない）とき、または起点のコードを書き出せないときは、
  エージェントを実行せず、一時停止の理由として記録して止める。
- 要求要件・設計の指示に、作業領域に起点のコミット（短いハッシュ）のコードがあること、読み取り専用で読むだけであることを書く。

## 理由

- 要求要件・設計のエージェントが既存のコードを読めるようにするため（PR の本文）。
- 開始時に clone するのは、どの工程から始まるタスクでも同じにするためで、今後タスクの種別を増やしても開始時に用意される（ステークホルダーの判断。PR の本文）。
- 起点のコミットを固定するのは、要求要件・設計で読んだコードと実装するコードが食い違わないようにするため（PR の本文）。
- 用意し直すときも記録した起点を使うのは、作業領域が消えた間にベースブランチが進むと、clone し直したときに起点が別のコミットに上書きされることが、
  レビューで見つかったため（レビュー）。
- 対象リポジトリを用意できないときに開始時に止めるのは、エージェントを実行せずに（費用をかけずに）止めるため（PR の本文）。

## 影響

- 対象リポジトリの問題（clone できない・設定やアカウントが無い）は、実装ではなくタスクの開始時にわかり、エージェントの実行の失敗ではなく一時停止の理由として記録される。
- 要求要件・設計の工程では、エージェントはコードを変えられない。
- タスクの途中でベースブランチが進んでも、そのタスクは起点のコミットのまま進む。
