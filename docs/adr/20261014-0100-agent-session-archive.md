# AI エージェントが書いた元のセッションのファイルを、実行ごとに秘密情報を伏せて残し、大きさとハッシュを作業履歴に記録する

- 日時: 2026-10-14 01:00 UTC
- ステータス: 採用
- 関係する PR・タスク: #75、PBI-66
- 置き換え元: なし
- 置き換え先: なし

## 背景

Claude Code・Codex が自分で書くセッションのファイルは、実行ごとの一時的な場所に書かれ、実行が終わると消えていた。
sacty の監査（PBI-55）や、セキュリティの方針による監査のために、実行ごとに残し、改ざんを検知できるようにする必要があった。
オーケストレーターのセッションの使い回し（PBI-67）の前提でもある。

## 決定

- 写すもの：Claude Code は `projects/**`（セッションの本体・サブエージェント・大きなツールの結果）と `history.jsonl`。Codex は `sessions/**`・
  `archived_sessions/**` と `history.jsonl`。通常のファイルだけで、シンボリックリンクは辿らない。認証のファイル（`.credentials*`・`auth.json`・
  `.claude.json*`・`config.toml`）は除く。Codex の `*.sqlite` は伏せられないので写さない。
- いつ・どこへ：コンテナの終了・停止の確認と認証ファイルの書き戻しの後、一時的な場所を消す前に、`SACTY_HOME/runs/<taskId>/<runId>/agent/` に
  相対パスのまま写す（0700・0600）。失敗・止めた・中止した実行も写す。スタブは何もしない。Claude Code は、コンテキストの無い実行
  （オーケストレーター・ゴールガーディアン・チャットなど）でも常に一時的な場所を用意する。
- コンテナの停止を確かめられない実行では写さず、作業履歴に `notArchived`（`container_not_confirmed`）を残し、デーモンのログと画面にも出す。
  写すときは O_NOFOLLOW で開き、開いた後の fstat で通常のファイル・選んだときと同じ dev/ino であること、途中のディレクトリがリンクでないことを確かめる。
- 秘密情報は写す前に伏せる（実行に渡した秘密情報・ゲートウェイのトークン・更新前後の auth.json の値と、JSON でエスケープされた形。読む単位の境目を
  またぐ値も）。伏せてから切り詰める。
- 上限は1実行 200MB。伏せた後の大きさで割り振り、超えたら小さいファイルは丸ごと残し、大きいファイルは先頭8割・末尾2割を残して間を省く（目印を残す）。
  目印を含めて上限を超えない。
- 台帳に新しいイベント `AgentSessionArchived`（runId・role・agent・runtime・sessionId・各ファイルの path・bytes・sha256・元の大きさ・切り詰め）を記録する。
  中止の後も受け付ける（状態は変えない）。
- API（一覧と台帳のハッシュとの照合、台帳に記録したパスの通常のファイルだけのダウンロード）と、セッションログの画面の「エージェントの元のファイル」で、
  一致を確かめてダウンロードできる。
- PBI-67 の再開にも、伏せたものを使う。

## 理由

- 監査のため・改ざんを検知できるようにするため（PR の本文）。
- PBI-67 の再開にも伏せたものを使うのは、再開したエージェントに秘密情報を見せないほうが安全だから（PR の本文の PO の判断）。
- Codex の `*.sqlite` を写さないのは、伏せられないから（PR の本文）。`codex exec resume` に rollout だけで足りるかは PBI-67 で確かめる。
- 停止を確かめられない実行で写さない・写すときもリンクを辿らないのは、動いたままのコンテナが選んだ後のファイルをホストのファイルへのリンクに
  差し替えると、領域の外の中身が保存されるというレビューの指摘（P1）への対応。Node.js には openat が無く、差し替えの競合を完全には塞げないので、
  主な保証は「停止を確かめられないときは写さない」で、開くときの確かめは念のための防御（返信）。
- 伏せた後の大きさで割り振るのは、短い値が `[REDACTED]` への置き換えで膨らみ、上限が効かないというレビューの指摘（P2）への対応。

## 影響

- 実行ごとに元のセッションのファイルが残り、画面と API で記録との一致を確かめられる。過去の作業履歴はそのまま読める。
- 元のファイルを2回読む（大きさを測るときと写すとき）ので、読む量は2倍になる。
- ファイルが多い実行では、記録のイベントが大きくなる（1件あたり約 200 バイト。件数の上限なし）。
- Linux のネイティブの Docker で、ホストの利用者の ID がイメージの node（1000）と違うと、0700 の一時的な場所にコンテナが書けない恐れがある。
  Claude Code を常に一時的な場所にしたので、オーケストレーターなどにも及ぶ。MVP の対象の macOS（Docker Desktop）では起きない。
