# 版は 1.0.0 から semver で付け、タグと GitHub Releases でリリースする

- 日時: 2026-10-19 23:45 UTC
- ステータス: 採用
- 関係する PR・タスク: なし（ステークホルダーの指示）
- 置き換え元: なし
- 置き換え先: なし

## 背景

これまで版の番号はどのパッケージも `0.1.0` のままで、タグも GitHub Releases も運用していなかった
（[sacty の最新版を、手元のコミットと GitHub の main で比べて知らせる](20261018-1213-update-check-against-main.md)）。
主要な機能（取り込み、工程の選択、承認ゲート、PR のレビュー、監査とメモリー、ダッシュボード）が揃ったので、ステークホルダーが
1.0.0 としてリリースすると決めた。

## 決定

- 版は semver（`MAJOR.MINOR.PATCH`）で付け、1.0.0 から始める。4 つのパッケージ（`@sacty/core`・`@sacty/daemon`・`@sacty/web`・`@sacty/cli`）と
  ワークスペースの依存の版は、いつも同じにする。
- 既定のイメージの名前 `sacty-agent:<版>`（`DEFAULT_IMAGE`）と、言語ごとのイメージの既定のタグ `sacty-agent-<名前>:<版>` も、同じ版にする。
  版を上げると利用者はイメージを作り直す（`npx sacty image build`）。
- リリースは、版を上げる PR をマージした main のコミットにタグ `v<版>` を付け、GitHub Release を作る。説明は日本語で、利用者に見える変更・
  互換性の無い変更・更新の後にすることを書く。手順は `CONTRIBUTING.md` の「リリース」に置く。
- npm には公開しない（利用者はリポジトリを clone して使う）。

## 理由

- 版の番号が無いと、利用者がどの状態の sacty を使っているかを伝え合えず、互換性の無い変更（設定の形・台帳の形）を知らせる場所も無い。
- イメージの名前に版を含める決まり（`sacty-agent-<名前>:<版>`）はすでにあるので、版と一緒に上げれば、CLI の版を固定した Dockerfile の変更が
  イメージの作り直しとして利用者に届く。
- 公開先を npm にしないのは、いまの利用の形（clone して `npm run build`）を変えないため。

## 影響

- 更新の知らせは当面 main のコミットで比べたまま。GitHub Releases に切り替えるかは、別に決める（上の ADR の「検討した案」）。
- 既定のイメージの名前が `sacty-agent:1.0.0` に変わるので、1.0.0 に更新した利用者は `npx sacty image build` を実行する。実行しないと、
  イメージが無い（`run.imageMissing`）で実行が止まる。`config.yaml` の `image` に自分の名前を書いている利用者には影響が無い。
