# 分割の子タスクの PR に範囲を明記し、レビューに範囲外を要修正にさせない

- 日時: 2026-11-16 00:36 UTC
- ステータス: 採用
- 関係する PR・タスク: #384、PBI-351
- 置き換え元: なし
- 置き換え先: なし

## 背景

親タスクを子タスク A・B・C に分割し、子タスク A が実装の PR を出した。
その PR をレビューする子タスクは、子タスク C の範囲（画面の候補の絞り込み）が未実装であることを、要修正として指摘し続けた。
実装は範囲外として断ったが、再レビューは同じ指摘を繰り返し、実装は変更なしで一時停止した。

実行のログを読むと、次のことが分かった。

- レビューの指示には、親タスクの全体の要求要件・設計（親が集めた情報の引き継ぎなど）は入っていた。
- 子タスク A の内容（実現すること・受け入れ条件・範囲外）は入っていなかった。
  レビューのエージェントは、PR と親タスクの関係を「分割の子タスクの1つかもしれない」と推測するしかなかった。
- PR の本文にも、子タスクの範囲は書かれていなかった。人が PR を読んでも、何が範囲外かは分からなかった。

## 決定

- 分割の子タスク（統合レビューの指摘を直す修正の子タスクを含む）の実装の PR の本文に、「この PR の範囲（分割の子タスク）」の節を入れる。
  - 親タスクの題と、分割の子タスクの PR であることを書く。
  - 子タスクの内容のうち、タスク分割のエージェントが書いた部分を、要約せずに引用としてそのまま載せる。
    親タスクから添えた要求要件・設計・集めた情報は載せない。
  - 載せる内容は 8,000 文字までにし、超えた分は sacty のタスクの画面で読ませる。
  - 本文を作り直すとき（やり直しの提出）にも入れる。
- PR をレビューする子タスクの指示に、PR を作ったタスクの題・親タスクの題・分割の子タスクであることと、同じ子タスクの内容を渡す。最初のレビューでも再レビューでも渡す。
- レビューの指示で、次のことを伝える。
  - 範囲外と書かれていること・ほかの子タスクが担当することが未実装でも、要修正にしない。
  - 範囲外のことで、その PR だけをマージすると困ることに気づいたら、要修正にせず、人が確かめることとして本文に書く。
  - 範囲の中のことは、今までどおり指摘する。
- 分割していないタスクの PR のレビューと、人が作った PR のレビューは変えない。
- 人の指摘は、範囲外でも人の意思として扱う。戻し先の判断は変えない。

## 理由

- 範囲を決めたのはタスク分割で、その記録は子タスクの内容にある。AI に要約させ直すと、範囲外の項目が落ちたり言い換わったりする。そのまま載せれば、レビューも人も同じ文を読める。
- PR の本文だけに書くと、すでに作られた PR や、人が本文を書き換えた PR では、レビューに範囲が渡らない。レビューの指示にも、台帳の子タスクの内容から直接渡す。
- 範囲外の未実装を要修正にすると、実装は直せない（範囲外なので）ため、やり直しが変更なしで止まる。
  一方で、その PR だけをマージすると困ることは、人がマージの順番を決める材料になる。捨てずに、人が確かめることとして残す。
- 子タスクの内容は長くなることがある。PR の本文の上限（65,000 文字）で、後ろの節（変更の説明・観点の表）が省かれないよう、範囲の節に上限を設ける。
  レビューの指示には上限を設けない（範囲の判断に全文が要るため）。

## 影響

- 分割の子タスクの PR の本文が、範囲の節の分だけ長くなる。
- 子タスクの内容に、親タスクから添えた部分の見出しが無いタスク（以前の版の子タスクなど）は、範囲を見分けられないので、節も指示も足さない。
- 子タスクの間でマージの順番や組み合わせを確かめることは、統合レビューの役割のままで、この決定では扱わない。
