# 指摘なしの後の実装の PR の CI の失敗を、タスクの一覧の行にも印で出す

- 日時: 2026-11-17 04:06 UTC
- ステータス: 置き換え済み（superseded）
- 関係する PR・タスク: #405、PBI-371
- 置き換え元: [指摘なしの後に実装の PR の CI が失敗していたら、タスクの詳細に出す（読み続けず、自動では扱わない）](20261117-0320-superseded-show-ci-failure-after-no-findings.md)
- 置き換え先: [指摘なしの後の CI の失敗の表示を、CI を読んでいる間に通ったら消す](20261117-0440-clear-ci-failure-when-ci-passes-while-reading.md)（回復の仕組みを足さず、再実行で通っても印が残る部分）

## 背景

置き換え元の ADR で、人の承認を待つ実装の PR の CI の失敗を、タスクの詳細と作業履歴に出すことにした。
状態の表示（一覧・「あなたの出番」）と通知には出さなかった。回復を記録しないので、古い結果が人の出番の理由として並ぶことを避けるため。

もとの問題は、「指摘なし」の後に CI が落ちても、人が気づくまで分からなかったこと。タスクの詳細を開かないと分からないのでは、足りない。
リポジトリの持ち主が、タスクの一覧にも出すと決めた（通知は足さない）。

## 決定

- 置き換え元の ADR が記録する CI の失敗があるタスクは、タスクの一覧の、そのタスクの行の状態の列に、「CI 失敗」の印（アイコンと文字）を添える。
- 印を出す条件は、タスクの詳細の表示と同じ判定（`pullRequestCiFailure`）をそのまま使う。新しい判定・回復・読み取りの仕組みは足さない。
- 状態の文言と種類は変えない。一覧の絞り込み・並び・「あなたの出番」・ヘッダーのお知らせ・通知は変えない。
- 置き換え元の ADR のうち、CI の読み方（読み続けない・先頭のコミットごとの回数）と、出すだけで自動では扱わないことは、変えない。

## 理由

- 一覧は、人が最初に見る場所。詳細を開かなくても、CI が失敗しているタスクに気づける。
- 置き換え元の ADR が避けたのは、古い結果が、状態（人の出番の理由）として並ぶこと。印を状態とは別に添え、状態そのものは変えなければ、状態・絞り込み・「あなたの出番」は、今までどおりに読める。
- 印は、再実行で通った後も、PR を更新する・マージする・閉じるまで残る。そこで、印の補足に、Sacty が CI を読んだ時点の結果であることと、その後の結果は反映されないことを出す。読んだ時刻と失敗していたチェックは、タスクの詳細で確かめる。
- 比べた案：状態の文言を「実装の PR の CI が失敗」に変える。回復を記録しないので、通った後も状態が変わったままになり、絞り込みや「あなたの出番」の読み方が変わる。採らなかった。
- 比べた案：通知（Slack・デスクトップ）にも出す。持ち主が、足さないと決めた。

## 影響

- 一覧の印は、再実行で CI が通っても残る（PR を更新する・マージする・閉じると消える）。
- ダッシュボード・「あなたの出番」のカード・ヘッダーのお知らせには、印は出ない。一覧を印で絞り込むこともできない。
- 拾わない失敗（最初に読んでから1時間ほどより後の CI など）は、置き換え元の ADR のまま。
- 仕様は [指摘なしの後の CI の失敗の表示](../spec/approval.md#指摘なしの後の-ci-の失敗の表示) にある。
