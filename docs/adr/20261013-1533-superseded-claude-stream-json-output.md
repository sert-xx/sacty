# Claude Code を stream-json で動かし、最後の答えは標準出力を溜めずに行ごとに読んで取り出す

- 日時: 2026-10-13 15:33 UTC
- ステータス: 置き換え済み（superseded）
- 関係する PR・タスク: #71、PBI-62
- 置き換え元: なし
- 置き換え先: [Claude Code の実行で後で起こす予約を使わせず、結果が何回も出ても本文と使用量を正しく取る](20261024-0700-one-shot-run-results.md)（最後の `result` から出力と使用量を読む部分）

## 背景

実行ごとのセッションログ（途中の出来事）を残すには、Claude Code に途中の出来事を出させる必要があった。これまでは json の形で、
最後の答えだけを受け取っていた。

## 決定

- Claude Code を `--output-format stream-json --verbose` で動かし、最後の `result` の出来事から、これまでと同じ値（出力・使用量・失敗の種類）を
  読む。result が無いときは失敗にする（理由は標準エラー出力 → 最後の発言 → 終了コード）。これまでの json の形も読める。
  Codex・スタブの実行の形は変えない。
- 実行器は標準出力を溜めず、届くたびに行ごとに読む読み手（Claude Code・Codex）に渡す。持つのは最後の result・最後の発言・使用量・
  エラーの文など、最後の答えと失敗の判定に要るものだけ。上限（16MB）より長い行は読み飛ばす。標準エラー出力も、診断に使う先頭と末尾
  だけを持つ。

## 理由

- stream-json にするのは、途中の出来事をセッションログに残すため（PR の本文・コミット）。
- 標準出力を溜めないのは、レビューで、verbose な stream-json の全量をメモリに持ち、大きなツールの出力や長い実行でデーモンのメモリを
  圧迫し、ほかのタスクごと止まりうることがわかったため（レビューとその返信）。対応の後、出力を 4.7〜93.5MB に変えて測り、ヒープの増えが
  出力の大きさに比例しないことを確かめた。

## 影響

- Claude Code の出力の形が変わるので、最後の答えの読み取りは result の出来事に頼る。result が無ければ失敗になる。
- 長い実行・大きなツールの出力でも、デーモンのメモリが出力の大きさに比例して増えない。
