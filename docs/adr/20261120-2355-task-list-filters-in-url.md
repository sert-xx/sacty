# タスクの一覧の絞り込みを URL に残し、最初の表示を「終わっていない」・50 行ずつにする

- 日時: 2026-11-20 23:55 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-441
- 置き換え元: なし
- 置き換え先: なし

## 背景

タスクの一覧は、プロジェクトの全タスクの行を出し、絞り込みを画面の中だけで持っていた（URL・cookie には残さない）。件数が増えると画面が長くなり、リロード・タスクを開いて戻る・リンクで渡すと絞り込みが消えた。

## 決定

- 最初の表示の状態は「終わっていない」。終わっていないタスクが 0 件でタスクがあれば「すべて」。開いたときに 1 回だけ決める。
- 絞り込みの全項目を URL のクエリ（`q`・`from`・`to`・`start`・`repo`・`status`。状態の「すべて」は `status=all`）に、最初の表示と違う項目だけ書く。書き換えは `history.replaceState(null, …)`（App Router の履歴の state を渡すと、ルーターが URL の変更を知らず、あとで描き直したときにクエリが消えるため、state は渡さない）。ページが `searchParams` を読み、サーバーの描画から同じ条件で出す。
- 一度に出すのは 50 行で、「さらに表示」で足す（ページ送りにしない）。足した行数は、Next.js の Activity（`useRouter().bfcacheId` を `key`）で、戻る・進むのときだけ保つ。
- 「条件をクリア」は、最初の表示と違うときだけ出し、最初の表示に戻す。
- 絞り込みと区切りは画面の側で行い、デーモンの API・MCP の `list_tasks` は変えない。

## 理由

- 利用者が「終わっていない」＋件数の区切りを決めた。一覧は新しい順で上から探すので、親子を分けないよう続きを下に足す。
- URL に残せば、リロード・戻る・リンクが同じ仕組みで効く。状態の「すべて」を `status=all` で書き、指定なしと区別する。
- 開始時期はブラウザーのタイムゾーンの日で比べるので、サーバーでは同じ行を選べない。URL に開始時期があるときだけ、表の所を読み込み中にして、ハイドレーションの不一致を避ける。

## 影響

- 以前の「URL・cookie には残さない」は、この決定で置き換わる（仕様書を直した）。
- 一覧からタスク・PR の画面などを 3 画面以上辿って戻ると、Activity が保つ直近の 3 画面を超え、足した行数は 50 行に戻る。絞り込みは URL に残るので、戻れば保たれる（行数を `history.state` には残さない）。
