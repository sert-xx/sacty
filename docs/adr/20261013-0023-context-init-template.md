# コンテキストリポジトリの雛形を sacty context init で作り、既存のファイルは --force が無ければ上書きしない

- 日時: 2026-10-13 00:23 UTC
- ステータス: 採用
- 関係する PR・タスク: #48、PBI-45
- 置き換え元: なし
- 置き換え先: なし

## 背景

コンテキストリポジトリを作るための雛形を、sacty は用意していなかった。

## 決定

- `sacty context init [<dir>] [--force]` を足す。既定のコンテキストと同じ構成（README.md・rules.md・skills/・mcp.yaml・sacty-context.yaml・
  agents/codex/config.toml）の雛形を作る。
- 雛形の各ファイルには、何を書く場所かの説明と、コメントにした例だけを入れる。そのまま指定しても、既定のコンテキストを変えない。
- 同じ名前のファイル（シンボリックリンクを含む）か `rules/` がすでにあれば、上書きせずに理由を示して止める。`--force` で上書きするが、リンク先は書き換えない。
- 作った後に、次にすること（git で管理して push し、プロジェクトの設定でコンテキストリポジトリに指定する）を表示する。

## 理由

- `rules/` があるときに止めるのは、作る rules.md が優先されて `rules/*.md` が読まれなくなるため（PR の本文）。
- コマンドを足すこと・雛形を説明とコメントの例だけにすることの理由は、記録に無い。

## 影響

- 利用者は、雛形を書き換えて push するだけでコンテキストリポジトリを始められる。
- 既存のファイルは、`--force` を付けない限り変わらない。
