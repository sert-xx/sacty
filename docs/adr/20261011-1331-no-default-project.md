## 背景

#8 で、デーモンは起動時に「デフォルト」のプロジェクトを用意し、画面で作るタスクはそのプロジェクトに入るようにしていた。

## 決定

- デーモンは、起動時に既定のプロジェクトを作らない。
- タスクを作るときは、作るプロジェクトの指定を必須にする。省略するとタスクを作らずに理由を返す。
- プロジェクトが1つも無いときは、どの URL を開いても、最初のプロジェクトを作る画面（新規作成と、エクスポートした定義のインポート）だけを出す。サイドメニュー・ヘッダーのプロジェクトの切り替え・お知らせは出さない。判定は画面の共通の枠で行う。デーモンにつながらないときは、これまでどおり各画面がつながらないことを出す。
- 作るかインポートすると、画面の枠を作り直して、そのプロジェクトの画面に進む。
- 表示しているプロジェクト（cookie）が無い・消えているときは、最初のプロジェクトを表示する。「default」という ID は特別扱いしない。

## 理由

理由は記録に無い。

## 影響

- すでに作られている「デフォルト」のプロジェクトは、普通のプロジェクトとして残る。
- 画面を移っても共通の枠は作り直されないので、作成とインポートの後に枠を作り直す必要がある。
