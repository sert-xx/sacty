# フォークからの PR の push では、見守りのレビューが自動で再レビューしない

- 日時: 2026-11-21 22:00 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-461
- 置き換え元: なし
- 置き換え先: なし

## 背景

[レビューのタスクは、判定が指摘なしになるまで完了にせず、PR の変化を見守って自動で再レビューする](20261119-1925-review-task-watches-pr-until-no-findings.md)（PBI-411）は、push の人やフォークかどうかを確かめずに再レビューする。
再レビューの検証では、PR のコードがエージェントのコンテナで動くので、フォークからの PR では、信頼できないコードが人の判断なしに動く。
PBI-411 のときに、人が「フォークの PR の push は、人の操作を待つ」を後続に回すと決めた。

## 決定

- 見守り中のレビューのタスクで、PR がフォークからのもの（head のリポジトリが base と違う。head のリポジトリが読めないものも含む）なら、push・作者の返信で自動では再レビューしない。
- 新しい先頭は `ReviewRestartHeld` に記録し、画面と MCP の `review.heldCommit` に出す。PR には、内部の言葉を使わずに、見送り始めたときに 1 回だけ知らせる。
- 人の再レビュー（画面・`rereview_task`）と GitHub の再依頼、最初のレビュー、マージ・クローズでの見守りの終わり、同じリポジトリの PR の振る舞いは変えない。

## 理由

- 「1回だけ」と画面・MCP の表示を、デーモンを起動し直しても保つため、メモリーではなく作業履歴に記録する。PR のコメントの目印で重複を見分ける案より、画面・MCP の表示と同じ記録で済む。
- フォークかどうかは、見守りが毎回読む PR の状態の答え（head と base のリポジトリ名）から決める。取り込みのときの記録に持たせると、この版より前のタスクが判定できない。

## 影響

- イベント `ReviewRestartHeld` を足した。以前の版に戻すと、この記録がある作業履歴をデーモンが読めず、起動できなくなりうる（PBI-411 の既知の影響と同じ）。
- [PBI-411 の ADR](20261119-1925-review-task-watches-pr-until-no-findings.md) の「影響」の、フォークかどうかを確かめないという記述は、この決定で置き換える。
