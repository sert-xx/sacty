# 返信していない後続に回したい案は、理由を次の提出に持ち越して返信する

- 日時: 2026-11-17 08:22 UTC
- ステータス: 採用
- 関係する PR・タスク: #PR_NUMBER、PBI-383
- 置き換え元: なし
- 置き換え先: なし

## 背景

[後続に回すかどうかは人が決め、実装は案と理由までを出す](20261117-0415-defer-proposals-decided-by-person.md)で、実装は、指摘を後続に回したいと申告でき、sacty は、PR への返信に、案であり人に確認中であることを明記する、と決めた。一度案にした指摘は、後の実行に、対応させる指摘として渡さない、とも決めた。

案は、提出ではなく、実行の完了の記録の時点で付く。その実行が提出に至らずに、実装がやり直されると、次のことが起きた（コードを読んで確かめ、テストで再現した）。

- やり直しになるのは、未完了の申告・ベースとの競合の残り・変更なしの一時停止からの再開。
- 次の実行は、その指摘を渡されないので、対応を書かない。対応の文と申告は消え、案の記録だけが残る。
- 提出の後の返信は、対応の文があることを条件にするので、「案で、人に確認中」の返信が投稿されない。実装の指示は、まだ返信していないのに、返信してあると伝えていた。
- 指摘のすべてを断るか案にしたかの判定は、その指摘を、対応の付いていない指摘として数える。先頭を変えなかったやり直しは、提出にならず、変更なしの一時停止になる。一時停止中は、人は案を決められない。

あわせて、次の 2 つが見つかった。

- 前の提出の案を人がまだ決めていなくても、最新の回の指摘をすべて断ると、人の決定を待たずに、同じ先頭の判定のし直しが始まる（待つ印が、その実行が案を申告したときだけ付くため）。
- 人が後続に回すと決めた指摘を、レビューと実装に渡すとき、指摘の文と理由を、先頭の 600 文字で切る。切ったことが、データから分からない。

## 決定

- 人がまだ決めておらず、PR にまだ返信していない案は、後の実行に対応が無ければ、案の理由を、その提出の対応として持ち越す（申告は、後続に回したい案）。提出のときに、その理由で、PR に返信する。
  - 案を申告した実行が提出に至らなかったときと、提出したが返信できないまま作り直したときの、どちらにも当てはめる。
  - 返信した案と、人が決めた案は、持ち越さない（1 件の指摘には、1 回だけ返信する）。
  - 人に確かめたいことは、申告した実行がまだ提出されていないときだけ残す。
- 一度案にした指摘を、後の実行に対応させないことは、変えない。対応させる指摘がほかに無くても、案にした指摘のデータは渡す。人に確認中の案には、sacty が提出のときに返信することを伝え、返信済みとは伝えない。
- 人がまだ決めていない案が、実装の指摘に 1 件でもあれば（前の提出の案・前の回の指摘の案を含む）、同じ先頭の判定のし直しは、人の決定を待つ。
- レビューと実装に渡すデータで、長くて先頭だけを載せた文には、切ったことの印を付け、先頭だけであることを伝える。

人に確かめていないこと：

- 人が後続に回すと決めた範囲の決め方（指摘の先頭の 600 文字と、実装が書いた理由の文で決まること）は、変えていない。1 件に複数の指摘がまとまっているときの扱いを含めて、人に確かめる。
- 提出したが返信できないまま作り直した案も持ち越すことは、着手のときに決めた（見つかった不具合は、提出に至らなかった実行の案だけ）。

## 理由

- 次の実行に渡し直さず、理由を持ち越す：渡し直すと、続きの実行が、対応を書き直す・書き忘れる、のどちらもありうる。書き忘れると、同じことがもう一度起きる。案にした指摘を後の実行に対応させない、という決まりも変えずに済む。
- 記録の形（イベント）を変えず、投影で持ち越す：対応の文・申告・提出回がそろうので、返信の条件・すべて断るか案にしたかの判定・承認の画面は、今の作りのまま、同じ状態を読む。デーモンと投影で、判定が食い違わない。前の版の作業履歴も、そのまま読める（前の版で、返信されないまま承認待ちになっている案は、読み直すと、返信の対象になる）。
- 提出したが返信できなかった案にも当てはめる：返信が GitHub のレート制限の待ちに入っている間に、次の指摘で作り直すと、案にした指摘は対応させないので、返信する機会が無くなる。提出に至らなかった実行の案と、同じことが起きる。
- 判定のし直しを、前の提出の案でも待つ：決める前に判定し直すと、案にした要修正が未対応のまま残り、1 回だけの判定のし直しを使ってしまう。案を申告した提出がいつかで、扱いを変える理由が無い。
- 切ったことの印だけを足す：範囲の決め方は、人の決定が要る。印が無いと、レビューは、先頭の 600 文字を指摘の全体として読む。

## 影響

- 返信していない案のある指摘は、提出のたびに、対応（後続に回したい案と、その理由）が付く。sacty の画面から書いた指摘（PR に返信しない）の案は、人が決めるまで、毎回の提出に、同じ理由が対応として出る。
- 前の提出の案を決めていないと、最新の回をすべて断った提出の後の判定のし直しは、人が決めるまで始まらない。
- 実装の指示は、対応させる指摘が無くても、案にした指摘を伝える。
