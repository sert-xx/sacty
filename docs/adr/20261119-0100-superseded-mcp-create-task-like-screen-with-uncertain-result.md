# sacty mcp のタスクの作成は、画面の既定（対象リポジトリ空欄・進め方「自動」）と同じ要求を送り、結果を受け取れなかったときは作られた可能性を返す

## 背景

`sacty mcp` は、タスクの一覧・詳細・再レビューだけだった（[前の ADR](20261118-0936-superseded-task-mcp-server-over-stdio.md)）。
手元の AI から、プロジェクトを指定して題と説明でタスクを作れるようにする。機能は1つずつ足す流れの1回目で、承認・成果物の取得などは後で足す。
作るには、次の3つを決める必要があった。

- 画面の「タスクを作成」と同じ結果にするために、何を送るか。
- 作成の要求を送った後に、結果を受け取れなかったときの扱い。作成の API には、二重に作らせないための仕組み（冪等のキーなど）が無い。
- ツールの注釈。

## 決定

- ツールは、`list_projects`（読み取りだけ）と `create_task`（`project_id`・`title`・`body`）の2つを足す。名前は、いまの `動詞_名詞`・`task_id` の付け方にそろえた。
- `create_task` は、`POST /api/tasks` に `{ projectId, title, body, repo: null }` を送る。画面が、テンプレートなし・対象リポジトリ空欄・進め方「自動」のときに送るものと同じ。
  `repo` を省くと、対象がリポジトリ1つだけのプロジェクトで、そのリポジトリが付いてしまい、画面と結果が変わるので、`null` を送る。
  進め方・テンプレート・対象リポジトリ・工程ごとの設定は、引数に足さない（使ってみてから決める。足せる形のまま）。
- 題・説明は、API を呼ぶ前に、画面と同じ検査（`CreateTaskInput`）で断る。デーモンの `invalid_input`（400）も、理由の文にして返す（前の版のデーモンが断ったときのため）。
- 結果を受け取れなかったとき（時間切れ・接続が切れた・本文を読めない・デーモンが 5xx を返した）は、作られている可能性と、`list_tasks` で確かめてから呼び直すことを返す。`rereview_task` と同じ考え方。
  デーモンが 5xx 以外の応答で断ったとき・認証できなかったとき（401）・接続を断られたとき・送る前の失敗は、処理されていないので、理由だけを返す。
- 注釈は `readOnlyHint: false`・`destructiveHint: false`・`idempotentHint: false`・`openWorldHint: true`。作った後に始まる工程が、PR など sacty の外に書くため。
- デーモンに API は足さない（前の ADR のとおり）。

## 理由

- 画面と同じ要求を送れば、記録も工程の始まり方も画面と同じになる。MCP 専用の経路を増やさずに済む。
- 冪等のキーを足すには、デーモンの API を変える必要がある。前の版のデーモンでは通らなくなり、「MCP のための API を足さない」決定とも合わない。
  利用者が確かめてから呼び直す案内なら、前の版のデーモンでも通る。AI が確かめずに呼び直すと二重にできるおそれは残る（説明文と文書で、確かめてから呼び直すことを求める）。

## 影響

- 登録した AI は、利用者に代わってタスクを作れる。作ると工程が始まり、時間と費用がかかる。毎回確かめるかは、AI の CLI の権限の確認に任せる。
- 結果を受け取れなかったときに、タスクが二重にできる可能性は残る。
- 仕様は [MCP サーバー](../spec/mcp-server.md#create_task)、利用者向けは [手元の AI から操作する](../user/mcp.md) に書く。
