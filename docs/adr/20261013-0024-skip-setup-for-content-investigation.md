# 工程の選択と内容の調査では開発のセットアップを省き、不具合の調査・再現・実装ではリポジトリの手順に従う

- 日時: 2026-10-13 00:24 UTC
- ステータス: 採用
- 関係する PR・タスク: #49、PBI-43
- 置き換え元: なし
- 置き換え先: なし

## 背景

対象リポジトリの AGENTS.md などに「最初に npm run setup を実行すること」とあると、工程の選択やコードを読むだけの調査でも、
エージェントがセットアップを実行していた。

## 決定

- オーケストレーター（工程の選択）と内容の調査（調査だけ・前段の調査）のプロンプトに、開発のためのセットアップ（依存のインストール・ビルド・setup のスクリプトなど）を
  実行しないことを書く。リポジトリの AGENTS.md・CLAUDE.md・README などの指示とぶつかる場合は、プロンプトを優先する。
- 内容の調査でも、動かして確かめる必要がある場合に限り、セットアップしてよい（理由を結果に書く）。
- オーケストレーターが調査の性質（`content`：内容の調査 / `bug`：不具合の調査）を判断して `StepsChosen` の `investigation` に記録し、調査の工程に渡す。
  判断が無いとき（以前の作業履歴を含む）は内容の調査として扱う。
- 不具合の調査・再現・実装は、これまでどおりリポジトリの手順に従ってセットアップする。

## 理由

- セットアップは時間がかかり、レジストリへの接続など失敗の原因も増えるので、コードを読めば足りる場面では省く（PR の本文）。
- 判断が無いときを内容の調査として扱う理由は、記録に無い。

## 影響

- 工程の選択と内容の調査は、セットアップを待たずに進む。
- 不具合の調査かどうかの判断はオーケストレーターに任され、その判断が作業履歴とタスクに残る。
