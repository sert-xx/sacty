# 要求要件・設計の本文の外にある作業の報告は、指示で防ぐだけでなく、sacty が取り除く

- 日時: 2026-11-04 03:54 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-302
- 置き換え元: なし
- 置き換え先: なし

## 背景

要求要件・設計は、エージェントの最後のメッセージがそのまま成果物（承認の画面・PR のファイル）になる。成果物の本文に作業の経過・報告を書かせない指示は PBI-263 で入れ、セルフレビューの観点 D-6・D-10 でも確かめさせたが、実験 r5 の S14・S16 で、最初の見出しの前に「要求要件を直しました。…セルフレビューは 1 回目で must の指摘がなく、通りました」のような報告が混ざった（F16 の再発）。指示とセルフレビューは、書いたエージェント自身が守る前提なので、守られなかったときに sacty 側で防ぐものが無かった。あわせて、S14 では差し戻しで消した要求の行（「R-n（削除：…）」）が、PR の本文の「確かめる所」に並んだ。

## 決定

- 要求要件・設計の提出された出力から、文書の本体が置かれない場所にある報告の段落を、sacty が取り除く（`withoutWorkReport`）。場所は、最初の見出しより前と、最後の区切り線より後ろで見出しを含まない節。報告の語（「〜ました」「〜ませんでした」・「セルフレビュー」・「コミット・プッシュ」・指摘の ID）を含む段落だけを取り除く。区切り線の後ろは、すべての段落が報告のときだけ、区切り線ごと取り除く。
- 本文の中の文は取り除かない。コードブロックの中は読まない。見出しが無い出力は変えない。
- 指示にも、出力の最初を成果物の最初の見出しにすることを足す。
- 削除した要求の行の ID は、出典の分類の対象（確かめる項目）から除く。

## 理由

- 指示は、守られなかったときの手当てが無い。取り除く場所を「本体が置かれない場所」に絞れば、本体の文を誤って消すおそれは小さい。
- 本文の途中の報告まで見分けると、本体の説明の文（「〜しました、と利用者に表示する」）を消すおそれがあるので採らない。そこは、これまでどおりセルフレビューで確かめる。
- 報告を取り除くだけで、エージェントにやり直させる案は、費用がもう一度かかり、同じ混ざり方を繰り返しうるので採らない。

## 影響

- 承認の画面・PR のファイル・次の工程への入力から、見出しの前と末尾の報告が消える。報告の語を含む本体の要約を、見出しの前に置くと消えうる（見出しの後に置かせる指示に合わせる）。
