# GitHub のレビュー再依頼は完了タスクを戻さず別タスクにする

- 日時: 2026-10-19 05:03 UTC
- ステータス: 採用
- 関係する PR・タスク: なし
- 置き換え元: なし
- 置き換え先: なし

## 背景

レビューの依頼から取り込んだタスクは、GitHub のレビュー再依頼を検知すると、完了状態を戻して同じタスクで再レビューしていた。
完了した作業の記録と次の依頼の作業を分けて確認できるようにする必要がある。

## 決定

- GitHub の再依頼が前回のレビュー投稿より後に届いたら、同じプロジェクトに新しいレビュー専用タスクを作る。
- 元タスクの完了状態・投稿・履歴・費用・実行セッションは変えない。新タスクでは元の実行セッションを再開しない。
- 再依頼の日時・アカウント・元タスクと前回レビューのスナップショットを新タスクの作成イベントに残し、同じ依頼で複数タスクを作らない。
- 新タスクでも前回の指摘と PR 作者の返答を参照する。新タスクの完了後の次の再依頼は、さらに別タスクにする。
- 画面の手動「再レビュー」は、同じタスクで再実行する動作を維持する。ラベルでの取り込みや初回レビューの重複排除も維持する。

## 理由

- 完了したタスクの記録を維持し、再依頼ごとの作業・費用・実行を分けて確認するため。
- 同じタスクの再開では、完了した作業の状態と次の依頼の作業が混ざるため。
- 前回レビューの内容はデータとして引き継げるため、前回の実行セッションを使わずに指摘への対応を確認できる。

## 影響

- 同じ PR に対して、再依頼ごとのレビュータスクが残る。
- 古いイベントの再生と、画面の手動再レビューは従来の動作を保つ。
- 取り込みの判定・取得失敗時の扱いは[取り込みの仕様](../spec/intake.md)、前回指摘の参照は[タスクと工程の仕様](../spec/tasks-and-steps.md)に記す。
