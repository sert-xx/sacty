# sacty をデーモンと Next.js の画面の2プロセスで構成し、デーモンは 127.0.0.1 でトークンを必須にして待ち受ける

- 日時: 2026-10-10 06:28 UTC
- ステータス: 採用
- 関係する PR・タスク: #1、PBI-1
- 置き換え元: なし
- 置き換え先: なし

## 背景

MVP の最初のタスクとして、sacty の土台になるプロセスの構成を決め、チケットの作成から一覧・詳細の表示までを最小の縦切りで
通す必要があった。

## 決定

- sacty は、デーモン（`apps/daemon`、Hono の API）と画面（`apps/web`、Next.js 16 と shadcn/ui）の2プロセスで動かす。
- 画面は操作をデーモンに依頼する。台帳への書き込みはデーモンだけが行う。
- デーモンは 127.0.0.1 でだけ待ち受け、起動ごとに作るトークンを API の呼び出しに必須にする。
- 共通の型と処理（台帳のイベントの定義、状態の復元）は `packages/core` に置く。
- CLI（`packages/cli`）の `sacty up` で、デーモンと画面を起動して URL を表示し、Ctrl+C で両方を止める。
  子プロセスが想定外に終了したら、その失敗を CLI の終了コードで伝える。
- CLI のコマンドの入口は、リポジトリに含める小さなファイル（`packages/cli/bin/sacty.js`）にする。

## 理由

- 2プロセスに分けた理由、127.0.0.1 とトークンにした理由は、記録に無い。
- CLI の入口をリポジトリに含めるファイルにしたのは、ビルドの成果物（`dist`）を bin にすると、npm が初回の `npm install` の時に
  コマンドのリンクを作らず、`npm install` → `npm run build` → `npx sacty up` の手順が失敗したため（レビューの指摘）。

## 影響

- 画面からの操作は、すべてデーモンの API を通る。画面は台帳に書き込まない。
- `sacty up` を止めるときは、両方のプロセスが終わるのを待ってから終了する。
