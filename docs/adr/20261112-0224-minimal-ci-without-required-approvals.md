# 最小の CI を GitHub Actions で足し、main の承認数は 0 のままにする

- 日時: 2026-11-12 02:24 UTC
- ステータス: 採用
- 関係する PR・タスク: #344、PBI-329
- 置き換え元: なし
- 置き換え先: なし

## 背景

定期のセキュリティチェックが、サプライチェーンの指摘として「CI のワークフローが無い」「main のルールセットの承認数が 0」を繰り返し挙げていた（2026-11-06 の対応から、利用者の判断待ちだった）。
CI が無いので、PR の lint・型検査・テストは、作った人と sacty のレビューの環境でしか確かめられていなかった。

## 決定

利用者が 2026-11-12 に決めた。

- `.github/workflows/ci.yml` を足し、PR と main への push で `npm ci`・`npm run lint`・`npm run typecheck`・`npx vitest run` を実行する。画面のテストのために Chromium を入れ、時間を測るテストが CPU の取り合いで落ちないよう、同時に動かすファイルを2つにする（`--maxWorkers=2`）。
- 権限は `contents: read` だけにし、checkout の認証情報を作業ツリーに残さない（`persist-credentials: false`）。
- 外部の Action（`actions/checkout`・`actions/setup-node`）はコミットの SHA で固定し、タグをコメントに書く。
- Node.js の版は `.node-version` から読む（`engines` の下限と同じ版。下限を上げると CI の版も変わる）。
- main のルールセットの承認数は 0 のままにする（個人で保守していて、承認する人がほかにいないため）。
- Dependabot は今は足さない。

## 理由

- 最小にしたのは、まずは手元と同じ検証を PR ごとに機械で確かめるため。ビルド・デスクトップアプリ・イメージの作成は含めない。
- SHA で固定したのは、タグの付け替えで Action の中身が変わらないようにするため（セキュリティチェックの指摘の直し方の案）。

## 影響

- PR に CI の結果が付く。sacty の実装の工程は、CI のあるリポジトリとして、PR の CI を待って判定する。
- Action の版は自動では上がらない。上げるときは、SHA とタグのコメントを一緒に変える。
- 承認数が 0 なので、CI が落ちていてもマージはできる。マージの前に CI の結果を人が見る。
- テストのうち、時間が入力の長さに比例するかを測るものは、実行する機械が混んでいると落ちることがある。
