# コンテキストリポジトリにイメージを定義できるようにし、デーモンが起動の後に裏で作る

- 日時: 2026-11-11 00:38 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-325
- 置き換え元: なし
- 置き換え先: なし

## 背景

エージェントを動かすイメージ（言語ごとのイメージ）は、各自の `config.yaml` の `images` にだけ書けた。
Playwright のブラウザなど、機能やリポジトリごとに要るツールが違うとき、同じ定義を各自の `config.yaml` に配る必要があり、プロジェクトのリポジトリと一緒にレビュー・管理できなかった。

## 決定

- コンテキストリポジトリに `images.yaml` を足す。
  書き方と検査は `config.yaml` の `images` と同じ（スキーマを共有する）。
  作るイメージの名前（`image`）は書けない。
  ほかの項目と同じく、継承・`locked`・`remove` の対象にする。
- 各自の `config.yaml` の `images` も、これまでどおり使える。
  同じ名前なら `config.yaml` のものを使い、警告を残す。
- `sacty image build` は `config.yaml` のイメージだけを作る。
  コンテキストのイメージは、デーモンが起動の後・プロジェクトの保存のとき・5分ごとにコンテキストを読み、無いものを裏で1つずつ作る。
- イメージの名前は `sacty-ctx-<プロジェクト>-<名前>:<定義の中身のハッシュ>` にする。
- 作るときの npm のレジストリ・認証などは、各自の `config.yaml` の `image_build` を使う。
- 作っている間は、そのイメージを使うかもしれないタスクの実行を始めずに待たせる（上限60分。過ぎたら一時停止）。
- 失敗したイメージは自動では作り直さない。
  画面に理由・ログの末尾・「作り直す」を出し、それを使う工程は理由を示して止める。
- 画面には、どの画面でも、作成中・失敗したイメージを出す。

## 理由

- `images.yaml` の形を `config.yaml` と同じにしたのは、書き方を覚え直さずに、定義をそのまま移せるようにするため。
  `image` を書けなくしたのは、別のプロジェクトのイメージと名前がぶつからないようにするため。
- 名前がぶつかったときに `config.yaml` を優先するのは、`gateway.mcp_servers` と `mcp.yaml` がぶつかったときと同じ扱いにするため。
  各自の環境（プライベートのレジストリなど）に合わせた定義を、コンテキストで上書きさせない。
- 名前に定義の中身のハッシュを入れたのは、push で定義が変われば作り直し、同じなら作り直さないことを、記録を持たずに決められるため。
  `image_build` と sacty の版も含めるのは、どちらが変わっても Dockerfile やミラーが変わるため。
- 作成中のタスクを待たせるのは、作り終える前にオーケストレーターが選ぶと、合うイメージがまだ無いために既定のイメージなどを選び、テストが失敗しうるため。
  待つ代わりに作成済みのものだけを候補にする案もあったが、この事故を防げないので採らなかった。
  上限を60分にしたのは、OS のパッケージやブラウザの導入には時間がかかるため（値の根拠は、ほかに無い）。
  待っている間は実行の印を付けず、ワーカーの見回りで確かめ直す（実行の枠を塞がず、一時停止・中止がすぐ効く）。
- 失敗を自動で作り直さないのは、定義の誤りなど同じ失敗を繰り返さないため。
  定義を直して push すれば名前が変わるので、作り直される。
  Docker に接続できなかったものだけは、読み直すときに確かめ直す（Docker を起動すれば直るため）。
- 1つずつ作るのは、ローカルのマシンの Docker の負荷を抑えるため。
- `run` は root で `docker build` の中で動く。
  コンテキストリポジトリは、すでに `config.yaml` と同じくらい信頼する前提（`mcp.yaml` の `command` はホストで動く）なので、新しい信頼の前提は増えない。

## 影響

- 仕様は [デーモンの起動と終了](../spec/daemon-lifecycle.md#コンテキストのイメージの作成)・[コンテキストの合成](../spec/context.md#コンテキストリポジトリのファイル)、利用者向けは [コンテナイメージ](../user/images.md#コンテキストのイメージ)・[コンテキストリポジトリ](../user/context.md#imagesyaml) に書く。
- デーモンは、`sacty up` が渡す `SACTY_DOCKER_DIR` の Dockerfile でイメージを作る。
- プロジェクトにコンテキストがあると、起動の直後は、コンテキストを読み終えるまで、イメージが決まっていないタスクは始まらない。
