# フォークからの PR の push では、見守りのレビューが自動で再レビューしない

- 日時: 2026-11-21 15:05 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-461
- 置き換え元: [レビューのタスクは、判定が指摘なしになるまで完了にせず、PR の変化を見守って自動で再レビューする](20261119-1925-superseded-review-task-watches-pr-until-no-findings.md)（「影響」の、フォークかどうかを確かめないという部分）
- 置き換え先: なし

## 背景

[レビューのタスクは、判定が指摘なしになるまで完了にせず、PR の変化を見守って自動で再レビューする](20261119-1925-superseded-review-task-watches-pr-until-no-findings.md)（PBI-411）は、push の人やフォークかどうかを確かめずに再レビューする。
再レビューの検証では、PR のコードがエージェントのコンテナで動くので、フォークからの PR では、信頼できないコードが人の判断なしに動く。
PBI-411 のときに、人が「フォークの PR の push は、人の操作を待つ」を後続に回すと決めた。

## 決定

- 見守り中のレビューのタスクで、PR がフォークからのもの（head のリポジトリが base と違う。head のリポジトリが読めないものも含む）なら、push・作者の返信で自動では再レビューしない。
- フォークかどうかは、同じリポジトリと確かめられたときだけ「フォークでない」とする。読めないときは、フォークとして扱う（信頼できないコードを動かさない向きに倒す）。
- 新しい先頭は `ReviewRestartHeld` に記録し、画面と MCP の `review.heldCommit` に出す。先頭がレビューした先頭に戻ったら、待ちを消す。
- PR には、内部の言葉を使わずに、新しいコミットが自動ではレビューされないことを、タスクごとに 1 回だけ知らせる。目印のコメントを探して重複を防ぎ、投稿に失敗したら次の確認でやり直す。
- GitHub の再依頼（レビューの依頼で取り込んだ PR だけ）は、同じリポジトリの PR では新しいタスクの最初のレビューになる。フォークの PR では、頼んだ人が PR の作者でなく、リポジトリへの書き込みの権限（write・maintain・admin）を持つときだけ、人の操作とみなして新しいタスクを作る。
- 頼んだ人・権限を読めないときは、みなさない側（自動では始めない）に倒す。みなさなかった再依頼は、保留と同じに扱う（元のタスクが見守り中なら、新しい先頭を `ReviewRestartHeld` に記録して画面・MCP に出し、PR への知らせは 1 回のまま）。元のタスクが見守っていない（指摘なしで完了した）ときは、待つ先が無いので、何も記録しない。
- 人の再レビュー（画面・`rereview_task`）、最初のレビュー、マージ・クローズでの見守りの終わり、同じリポジトリの PR の振る舞いは変えない。

## 理由

- 画面・MCP の表示は、デーモンを起動し直しても保つため、作業履歴に記録する。PR への知らせは、既存の知らせ（止まったことの知らせなど）と同じく、目印のコメントで重複を見分ける。記録と知らせを分けるので、知らせに失敗しても、次の確認でやり直せる。
- フォークかどうかは、見守りが毎回読む PR の状態の答え（head と base のリポジトリ名）から決める。取り込みのときの記録に持たせると、この版より前のタスクが判定できない。
- 書き込みの権限が無いフォークの作者でも、GitHub では前にレビューした人への再依頼ができる。再依頼を常に人の操作とみなす案は、作者の操作 1 つで、人の判断なしにコードが動く経路を開くので採らない。
- 再依頼の権限は、フォークでなく土台のリポジトリで確かめる（フォークの持ち主は、自分のフォークに書き込めるため）。

## 影響

- イベント `ReviewRestartHeld` を足した。以前の版に戻すと、この記録がある作業履歴をデーモンが読めず、起動できなくなりうる（PBI-411 の既知の影響と同じ）。
- [PBI-411 の ADR](20261119-1925-superseded-review-task-watches-pr-until-no-findings.md) の「影響」の、フォークかどうかを確かめないという記述は、この決定で置き換える。
- 新しいタスクを作ったときは、元のタスクには何も記録しない（[ADR](20261019-0503-review-rerequest-new-task.md) のまま）。
- 仕様書は [intake](../spec/intake.md)（レビューの再依頼）と [tasks-and-steps](../spec/tasks-and-steps.md)（投稿の後の PR の見守り）に書いた。
