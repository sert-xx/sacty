# 承認待ちの間に実装の PR がベースブランチと競合したら、画面に出すだけにして、自動では取り込まない

- 日時: 2026-11-01 14:00 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-269
- 置き換え元: なし
- 置き換え先: なし

## 背景

[実装の PR がベースブランチと競合しないよう、Sacty がホストでベースブランチの最新を作業領域にマージし、親が 2 つのマージコミットで出す](20261101-0340-merge-base-branch-into-workspace.md)で、Sacty は実装を始める前と最終レビューの前に、ベースブランチを取り込むようになった。
ただし、承認待ちの間は取り込まない（人が差し戻すか、PR に指摘を書いたときに、実装のやり直しの前に取り込む）。
そのため、承認待ちの間に先の PR がマージされて競合しても、タスクの画面には何も出なかった。
実務での実証実験（S13）では、人が GitHub で競合に気づき、PR に「解消して」とコメントするまで、Sacty は何も知らせなかった。

## 決定

人が決めた方針「画面に出すだけ」に従う。自動では取り込まない。取り込むかは、今までどおり人が差し戻しや指摘で決める。

1. **判定**：承認待ちの実装の PR について、PR の状態の確認が読む GitHub の `mergeable` が `false` なら競合、`true` なら競合なしとする。GitHub が計算中（`null`）・読めないときは、前の記録のままにする。
2. **記録**：競合が変わったときだけ、イベント（`PullRequestConflicted`・`PullRequestConflictResolved`）を作業履歴に記録する。毎回の確認では書かない。
3. **対象**：承認待ち（`awaiting_approval`）の実装の PR だけ。要求要件・設計の PR はタスクブランチへの PR で、ベースブランチの取り込みの対象でもないので、対象にしない。
4. **表示**：タスクの詳細の案内、承認の画面の PR の欄、状態の表示（「あなたの出番」・ヘッダーのお知らせ・一覧に出る）に競合していることを出し、「あなたの出番」の行には取り込む操作（差し戻す・指摘を書く）を添える。
5. **何もしない**：実行・取り込み・PR の更新・GitHub への書き込みを始めない。

## 理由

- 取り込みを自動にすると、人がまだ読んでいない PR に、費用のかかる実装のやり直しが走る。取り込んで直すかは、競合の中身（意味の衝突があるか）を見た人が決める方が、S13 の経験に合う。
- 既存の 60 秒ごとの PR の状態の確認が読む、GitHub の PR の取得に `mergeable` が含まれるので、GitHub への問い合わせを増やさずに済む。別に問い合わせる案は、承認待ちのタスクの数だけ問い合わせが増えるので採らなかった。
- 表示の状態を作業履歴のイベントにすると、デーモンを再起動しても同じ画面になり、画面側は他の PR の状態（閉じられた・開き直された）と同じように、タスクの状態だけから描ける。イベントを毎回書く案は、作業履歴が肥えるので、変わったときだけにした。
- `mergeable` の `null` は、GitHub が計算を始めたばかりの合図で、競合の解消ではない。前の記録のままにすることで、表示がちらつかない。
- 競合の記録は、PR の番号と提出のコミットに結びつけ、PR の更新・マージ・クローズで消す。古い競合を新しい提出に出さないため。
- 理由がわからないこと：GitHub が `mergeable` を `null` のまま返し続ける長さ（未確認）。この間は競合を出せない。

## 影響

- 承認待ちの間、競合が 1 分ほどで画面に出る（GitHub が計算を終えていれば）。
- 競合を出していても、人がそのままマージしたら通常のマージとして承認する。
- 仕様は [承認と差し戻し](../spec/approval.md#ベースブランチとの競合の表示) に書いた。
