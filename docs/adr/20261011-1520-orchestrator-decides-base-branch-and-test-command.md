# ベースブランチとテストのコマンドは、タスクの開始時にオーケストレーターが決めて記録し、人が直す手段は設けない

- 置き換え先: なし

## 背景

ベースブランチとテストのコマンドは、#8 で決めたプロジェクトの「リポジトリの設定」に人が書いていた。同じ PR で、プロジェクトの設定を「対象」の一覧だけにし、リポジトリの設定を無くすことにした。動作確認で、ベースブランチやテストのコマンドの特定は、タスクの開始時にオーケストレーターが行えるとよい、というフィードバックがあった。

## 決定

- タスクの開始時は、ブランチを指定せずに既定のブランチを clone し、そのブランチ名を記録する。
- オーケストレーターは、工程と一緒に `baseBranch` と `testCommand` を出す。テストのコマンドは、工程の選択の記録（`StepsChosen`）に残す。
- 既定と違うベースブランチなら、その最新で用意し直して記録し直す。用意できなければ既定のブランチで進め、理由に添える。
- テストのコマンドが分からなければ、実装を含むタスクは費用をかける前に止める。調査・レビューだけのタスクは止めない。
- 検証は、オーケストレーターが決めたテストのコマンドで行う。
- ベースブランチとテストのコマンドは、タスクの画面に出すだけにし、人が直す手段は設けない。

## 理由

- ベースブランチやテストのコマンドの特定は、タスクの開始時にオーケストレーターが行えるとよい、という動作確認のフィードバックによる（本文）。
- 人が直す手段を設けない理由は記録に無い。

## 影響

- ベースブランチとテストのコマンドは、プロジェクトの設定に書かなくなる。タスクの画面に、決めた値を出す。
- 実際の AI でオーケストレーターがベースブランチとテストのコマンドを決めるところは、この PR では試していない。
