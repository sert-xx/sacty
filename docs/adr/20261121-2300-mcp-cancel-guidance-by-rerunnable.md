# 中止の案内を、中止の後に再実行できるかで切り替える

- 日時: 2026-11-21 23:00 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-470
- 置き換え元: [sacty mcp の再実行は、画面の既定値のまま補足だけを足す最小の版にし、画面の既定値で送れないものは MCP の層で断る](20261119-1000-superseded-mcp-rerun-minimal-screen-defaults.md)（中止の案内に、やり直す道として再実行を案内する部分）
- 置き換え先: なし

## 背景

[再実行の ADR](20261119-1000-superseded-mcp-rerun-minimal-screen-defaults.md) は、`cancel_task` の説明・`get_cancel_plan` の `irreversible`・使い方の文に、どのタスクにも「やり直すなら再実行」と案内すると決めた。
ところが、PR のレビューのタスク・分割の子・チケット由来でリポジトリが決まっていないタスク・既定値が入力の検査に通らないタスクは、中止の後に `rerun_task` が断る。
AI が「中止してもやり直せる」と伝え、利用者が取り消せない中止を認めてしまうおそれがある。

## 決定

- 中止の後に再実行できるかの判定を、`rerunBlock` の、状態で断る条件（中止していない・完了）を除いた残りを `rerunKindBlock` に分けて、1か所にする。`rerunBlock` と中止の案内が同じ関数を使う。
- 中止できる（`canCancel` が真の）タスクの `get_cancel_plan` の `irreversible`：断らなければ「中止の後に `rerun_task` で再実行できる見込み（デーモンが断ることがある）」、断るなら `rerun_task` を案内せず、「中止すると、MCP からはやり直せません」の前置きと、`rerunBlock` が返す理由と画面で決めることを入れる。中止できないタスクには、やり直しの案内を入れない。
- `resume_task` が中止したタスクを断る理由も、同じ判定で切り替える（再実行済み・分割の子を含む）。
- 固定の文（`cancel_task` の説明・`INSTRUCTIONS` の中止の段落・`gate.invalidTarget` の断り）は、「再実行できる種類のタスクなら」の条件付きにする。
- `canRerun`・`canResume`・`canCancel` の値と、`rerun_task` が断る条件は変えない。

## 理由

- 案内を判定の結果に合わせると、再実行できないタスクを中止する前に、取り消せないことが伝わる。
- 道を `rerunBlock` の理由にそろえると、画面の再実行で済むタスクに、題と説明を書き直す「新しく作る」を案内せずに済む。
- 判定の写しを作らず1か所にすると、`rerun_task` の断りと案内が食い違わない。

## 影響

- デーモンだけが知る断り（リポジトリがプロジェクトの対象でないなど）は判定に入らないので、「再実行できる見込み」と書き、デーモンが断ることがあると添える。
- 仕様書・ユーザー文書（日英）を、条件付きの案内に合わせた。
