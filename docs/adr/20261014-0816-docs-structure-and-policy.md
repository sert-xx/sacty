# docs を仕様書・ユーザードキュメント・ADR・作業履歴の4種類に分け、実装の変更で直すのは仕様書とユーザードキュメントだけにする

- 日時: 2026-10-14 08:16 UTC
- ステータス: 採用
- 関係する PR・タスク: #88、PBI-80
- 置き換え元: なし
- 置き換え先: なし

## 背景

sacty の説明は、リポジトリの README に設定・コマンド・使い方・仕組みが混ざって書かれていた。実装を変えるたびに
どこを直せばよいかが決まっておらず、過去の決定の理由やタスクの記録を残す場所も無かった。開発の多くをエージェント
（Claude Code・Codex）が行うので、エージェントが同じ方針に従えるようにする必要もあった。

## 決定

- `docs/` の下に、目的ごとに4種類のディレクトリを置く：`spec/`（仕様書）・`user/`（ユーザードキュメント）・
  `adr/`（ADR）・`worklog/`（作業履歴）。方針は `docs/README.md`、ファイル名の規則とひな形は各ディレクトリの README.md に書く。
- 実装を変えたときに直すのは、仕様書と（利用者に見える変更なら）ユーザードキュメントだけ。同じ PR で直す。
- ADR は決定ごとに足し、古い ADR の本文は書き換えない。方針が変わったら、古い ADR のファイル名の日時の後ろに
  ステータス（`superseded`・`deprecated`・`rejected`）を付け、置き換えの関係を双方に書く。
- ファイル名の日時・日付は UTC にする（ADR は `YYYYMMDD-HHMM`、作業履歴は `YYYYMMDD`）。
- 作業履歴はタスクごとに足し、マージの後は直さない。却下・置き換えた ADR と作業履歴が実装と矛盾するのは許容する。
- 方針に従うためのスキル `sacty-docs` を、Claude Code 用は `.claude/skills/sacty-docs/SKILL.md`、Codex 用は
  `.agents/skills/sacty-docs/SKILL.md` に、同じ内容で置く。一致はテストで確かめる。

## 理由

- 直す対象を仕様書とユーザードキュメントに絞ると、実装の変更のたびに直すものがはっきりし、ADR と作業履歴を
  書いたときの記録のまま残せる（ステークホルダーの要望）。
- ADR の状態をファイル名に出すと、一覧を見るだけで今も効いている決定がわかる。日時を先頭に置くと、名前の順が
  決定の順になる。
- 日時を UTC にしたのは、過去の決定の日時を GitHub の PR のマージの日時（UTC で返る）から起こすときに、
  換算の誤りを避けるため。
- スキルの置き場所は、手元の CLI で確かめた：
  - Claude Code（2.1.299）は、本体に `.claude/skills/<名前>/SKILL.md` を読み込む記述がある。
  - Codex（0.160.0）は、`codex debug prompt-input`（モデルに渡す入力を API を呼ばずに表示する）で、
    リポジトリの `.agents/skills` と `.codex/skills` の両方がスキルの root として載る（`.claude/skills` は載らない）。
    どちらでも読まれるが、利用者ごとの置き場所（`~/.agents/skills`）と同じ形の `.agents/skills` を選んだ。2つの置き場所の
    扱いの違い（優先の順など）は確かめていない。
- 2つのスキルは形式（`name`・`description` の front matter と本文の SKILL.md）が同じなので、同じファイルを2か所に
  置き、テストでバイト単位の一致を確かめる。シンボリックリンクにしなかったのは、各 CLI がリンクを辿るかを確かめて
  いないため。

## 影響

- 実装を変える PR では、関係する仕様書（と、利用者に見える変更ならユーザードキュメント）を同じ PR で直す。
- README の中身はユーザードキュメントへ移し、README は概要・最小の手順・リンクだけにする（移行は別のタスク）。
- ADR の名前を変えると、そのファイルへのリンクが切れるので、名前の変更と同じ PR でリンクを直す。
  `tests/docs` のテストで、リンク切れ・ファイル名の規則・置き換えの関係・スキルの一致を確かめる。
- スキルを直すときは、2つの写しを同じ内容に保つ。
