# 設定の画面は、保存していない変更を送る値の写しで見張り、離れるときに確かめる

- 日時: 2026-11-21 18:00 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-449
- 置き換え元: なし
- 置き換え先: なし

## 背景

Sacty の設定とプロジェクトの設定は長い 1 ページで、「保存する」は下に 1 つしかない。保存していない変更の表示も、離れるときの確認も無く、変えた値を保存せずに失えた。

## 決定

- 変更の判定：送る値の写しを、基準の写しと比べる。基準は最初に描いたときの値で、保存に成功したら送った時点の写しにする。元の値に戻せば変更なしの扱い。
- 確認の方式：画面の中の移動（Link）は `onNavigate` で `window.confirm` を出し、断れば止める。閉じる・リロード・`<a>` の移動は `beforeunload` で確かめる。画面の確認のダイアログは作らない。
- 対象：Sacty の設定と、プロジェクトの設定（`project` があるとき）だけ。押した時点で効く項目と、プロジェクトの作成のフォームは対象にしない。
- 戻る・進む：確かめない。App Router の戻る・進む（popstate）は `onNavigate` でも `beforeunload` でも止められず、止めるには履歴を書き換える仕組みが要るため。
- 「保存する」は帯にして画面の下に固定し、幅 640px 未満では下のメニューの上に置く。

## 理由

- 送る値の写しで比べると、欄ごとに「変わったか」を持たずに済み、子の部品（Slack の欄）の値も同じ形で含められる。
- 画面を描き直さずに確かめられるよう、変更の有無は ref に持つ。

## 影響

- スマートフォンで戻る操作をすると、確認なしに編集中の値を失う。
