# エージェントの成果物とチケットの本文を、信頼しない前提で Markdown として描画する

- 日時: 2026-10-10 22:21 UTC
- ステータス: 採用
- 関係する PR・タスク: #17、PBI-12
- 置き換え元: なし
- 置き換え先: なし

## 背景

動作確認のフィードバックで、タスク詳細が読みにくいことがわかった。エージェントが書く成果物は Markdown で、画面ではそのまま文字として出ていた。
一方、エージェントの出力や取り込んだ Issue の本文は、sacty が書いたものではない。

## 決定

- 成果物（要求要件・設計）・実装の説明・チケットの内容（GitHub Issue の本文を含む）・成果物チェックの画面・変更の申し出の変更後の全文を、
  `react-markdown` と `remark-gfm`（版を固定）で描画する。表・チェックリスト・取り消し線にも対応する。
- エージェントの出力は信頼しない前提で、生の HTML は描画せず（`skipHtml`）、`javascript:` などの URL は無効にし、画像は読み込まずにリンクとして出し、
  リンクは別のタブで開いて参照元を渡さない。
- 表とコードは、カードの中で横にスクロールさせる。
- あわせて、タスク詳細の表示を次のようにする：承認済みの要求要件・設計と、完了したタスクの実装は折りたたんで見出しだけを出す（承認待ち・作業中は開いたまま）。
  工程をチケットより上に出す。完了したタスク（すべての工程が終わったもの・中止したもの）には「一時停止」「中止」を出さない。

## 理由

- チケットの内容を対象にしたのは、GitHub Issue の本文も Markdown のため（PR の本文）。
- 描画を制限したのは、エージェントの出力を信頼しない前提にしたため（PR の本文）。
- 折りたたみ・工程の順・完了後の操作を隠すことは、動作確認のフィードバックへの対応。それ以上の理由は記録に無い。
- 描画のライブラリに `react-markdown` と `remark-gfm` を選んだ理由は記録に無い。

## 影響

- 画面の依存に `react-markdown` と `remark-gfm` が加わる（`npm audit` で、脆弱性が増えていないことを確かめた）。
- 成果物に HTML や画像を書いても、画面には出ない。
