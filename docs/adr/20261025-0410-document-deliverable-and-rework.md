# 文書作成の成果物を1つに決めて指示し、外部に直接書いたページを記録して、差し戻しと書き出しで同じページを直させる

## 背景

文書作成（`document`）のタスクで、外部の PF（Confluence・Notion など）にある文書の内容を直すよう差し戻したところ、次のことが起きた。

- 最初に作られた文書とは別の文書が、外部に新しく作られた。
- タスクの最終報告（「〜のドキュメントを作成。エージェント ID は〜」のような内容）も、外部に文書として作られた。

文書作成のエージェントには、[ほかの工程と同じく外部 PF・MCP を渡している](20261022-1505-document-step-gets-context.md)。
指示は「原稿そのものは外部やリポジトリに直接書かず出力する」だけで、次のことを伝えていなかった。

- 何が成果物か（出力の全体が原稿として保存され、承認の後にそのまま書き出されること）
- 外部に直接書いたときに、どのページが成果物か（sacty も、エージェントが書いたページを記録していなかった）
- 差し戻しで直す対象は、前回の原稿と、その成果物のページであること

そのため、外部に直接書いたエージェントは、出力に作業の報告を書いた。
差し戻しの実行は前の回が作ったページを知らず、外部に別の文書を作った。
人が承認すると、作業の報告が原稿として書き出された。

利用者からは、何が成果物かを明確にし、修正のときはその成果物を続けて直すべきで、成果物でないものを sacty の外に出してはいけない、という指摘があった。
外部への書き込みそのものを禁じたいのではなく、タスクの説明で直接編集の指示があれば、それに従って外部の文書を直してよい、とのことだった。

## 決定

- 文書作成の指示に「成果物」の節を置き、次のことを伝える（`documentDeliverableLines`）。
  - 成果物は原稿1つ。出力（決まった形式の JSON を除く全体）を原稿の本文として保存し、人間が承認する。外部に直接書いたときも、本文の全文を出力する。
  - タスクの説明（取り込み元のチケットを含む）が外部の文書を直接作る・直すよう指示していれば、そのとおりに書いてよく、書いたページが成果物になる。
    指示が無ければ、外部・リポジトリには書かない。
  - 成果物のほかに外部にページ・コメントを作らない。作業の報告（作成した旨・URL・タスクやエージェントの ID・手順）は、外部にも原稿にも書かない。
  - 差し戻しでは、前回の原稿を直して全文を出力し、別の文書を作らない。外部のページを直すよう求める指摘は、成果物（前回の原稿と成果物のページ）への指摘として扱う。
- 外部に直接書いたエージェントには、そのページの URL を見出し `sacty-document-page` の JSON で出させる。
  sacty はこれを原稿から除いて `AgentRunCompleted` の `documentPage` に記録し、投影は最後に申告されたページを `Task.documentPage` に残す。
- 成果物のページ（`documentPage`、無ければ書き出したページ）があれば、次の回の指示に渡し、外部に書くときはそのページを直させる。
- 書き出しは、書き出した URL が無くても成果物のページがあれば、そのページを更新させる（別のページを作らない）。
  書き出しの指示にも、書くのは書き出すファイルの内容の1ページだけで、書き出しの報告を別のページやコメントにしないことを足す。
- 「既存文書の直接更新依頼は作業で扱います」の一文は、文書作成の指示から除く。
  タスクの説明が直接の編集を指示する文書作成では、外部に直接書いてよいことと食い違うためである（オーケストレーターが、既存の外部文書の単発の更新に `operation` を選ぶ指示は変えない）。

## 理由

- 成果物を1つに決め、外部のページを記録して渡せば、承認する物・書き出す物・差し戻しで直す物が同じになる。差し戻しのたびに別のページができず、報告も外部に出ない。
- 外部への直接の書き込みは、タスクの説明が指示したときに限って認める。利用者は外部の文書を直接直す用途を求めており、禁じると用途を損なう。
  指示が無いときは、承認の前に外部に出さず、承認の後に sacty が書き出す。
- 成果物のページの URL は、エージェントの申告で受け取る。外部の PF・MCP のどれに何を書いたかを、sacty は呼び出しから区別できない。

## 影響

- 外部に直接書かないことも、成果物のページだけを直すことも、指示で伝える（強制はしない）。
- エージェントが URL を申告しなければ、次の回に成果物のページを渡せない（書き出しは目印でページを探す）。
- 仕様は[タスクと工程](../spec/tasks-and-steps.md)・[書き出し](../spec/export.md)、操作は[タスクを進める](../user/tasks.md)に記載する。
