# エージェントとテストのコマンドの出力は、コンテナの中の通常のファイルで受け、小さな中継でコンテナの標準出力に流す

- 日時: 2026-10-13 22:56 UTC
- ステータス: 採用
- 関係する PR・タスク: #73、PBI-64
- 置き換え元: なし
- 置き換え先: なし

## 背景

利用者の環境で、Codex のエージェントの実行が、標準出力への書き込みの `Resource temporarily unavailable (os error 11)` で落ちた
（DB の起動・seed・Web の起動・ブラウザのテストの途中）。コンテナの中で同じ標準出力を受け継いだプロセスが出力を非ブロッキング
（O_NONBLOCK）にし、そこへ Codex が大きな出力を書いて EAGAIN になったと見られる。標準出力の「開いたファイルの記述」はコンテナの
中で共有されるので、どれか1つが非ブロッキングにすると全員に効く。原因のプロセスは特定できていない。

## 決定

- エージェント（`docker.ts`）とテストのコマンド（`test-runner.ts`）の一番外側（PBI-60 で入れた localhost の転送の外側）を、
  `withOutputRelay(command)` で Node.js の中継にくるむ。
- コマンドの標準出力・標準エラー出力は、コンテナの中の一時的な通常のファイル（O_APPEND）に書かせる。中継はそれを 64KB ずつ読み、
  コンテナの標準出力・標準エラー出力に流す。EAGAIN なら待って書き直し、途中までなら残りを書く。標準出力と標準エラー出力は別のまま。
- コマンドが終わったら、その時点までを流し切ってから同じ終了コードで終わる（シグナルなら 128＋番号。後ろで動き続けるプロセスは待たない）。
  SIGTERM・SIGINT・SIGHUP はコマンドに伝える。コマンドが見つからなければ 127。
- 8MB 流すごとに、流した部分を `fallocate --punch-hole` で捨てる（無ければ捨てずに続ける）。一時ファイルを作れなければ、これまでどおり
  直接渡す。コンテナの標準出力に書けなくなったら、コマンドを止めて 1 で終わる。

## 理由

- 通常のファイルへの書き込みは非ブロッキングの影響を受けないので、原因のプロセスを特定できなくても落ちないようにできる（PR の本文）。
- 流した部分を捨てるのは、数十 MB の出力でもディスク・メモリを増やさないため（コミットのメッセージ）。
- 次の制限は、落ちるより影響が小さいので PO の判断で受け入れた（PR の本文）：テストのスクリプトが `/dev/stdout` を開き直すと、まだ流して
  いない直前の出力が画面とログから欠けることがある（テストの合否・終了コードは変わらない。Claude Code・Codex は開き直さない）。

## 影響

- エージェント・テストのコマンドは、実行の途中で標準出力を非ブロッキングにされても EAGAIN で落ちない。
- 読み手が止まっている間は、流す前の出力がディスクに溜まる（fallocate の無いイメージでは、コンテナを消すまで残る）。
- コマンドが見つからないときの文が `<cmd>: spawn <cmd> ENOENT` に変わる（終了コード 127 は同じ）。テストの出力の中の標準出力と
  標準エラー出力の混ざり方が、約20ミリ秒の単位で粗くなることがある。
