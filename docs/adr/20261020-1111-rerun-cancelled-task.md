# 中止したタスクは、元のタスクを引き継いだ新しいタスクを作って最初からやり直す（再実行）

- 日時: 2026-10-20 11:11 UTC
- ステータス: 採用
- 関係する PR・タスク: #173
- 置き換え元: なし
- 置き換え先: なし

## 背景

何かの問題でタスクを中止した後に、情報を補って同じ依頼をやり直したいことがある。チケットから取り込んだタスクは、中止したタスクが
残っていると同じチケットを二重に取り込まないため、もう一度トリアージされず、やり直す手段が無かった。中止では作業領域・ブランチ・PR を
片付けるので、前の試行の成果物は残っていない。作業履歴は追記だけで、中止したタスクにはイベントを受け付けない
（[作業履歴は追記だけ](20261010-0628-append-only-ledger.md)）。

## 決定

- 中止したタスクの詳細に「再実行」を置く。再実行は、中止したタスクを書き換えず、元のタスクを引き継いだ新しいタスクを作る
  （`TaskCreated` の `rerun` に元のタスクの ID）。作業履歴の復元で、元のタスクに再実行のタスクを記録し、再実行は1度だけにする。
- 人が、題・説明・補足・作業するリポジトリ（リポジトリ無しも）・イメージ（すべての工程で使う）を決める。
- 説明には、補足と、中止で消えなかった前の試行の記録（工程の成果・差し戻しの指摘・質問と答え・止まった理由など）を sacty が足す。
  後の工程は説明を読むので、指示を工程ごとに変えずに、前の試行の情報を渡せる。
- チケットのタスクはチケットを引き継ぎ（二重の取り込みの判定と、チケットへのコメントを保つ）、チケットを読み直さずに、人が決めた
  リポジトリで進める。リポジトリ無しなら、リポジトリを指定せずに作ったタスクと同じ進め方にする。
- 分割で作った子タスク（親が進め方を決める）と PR のレビューのタスク（PR で依頼し直す）は再実行できない。

## 理由

- 中止したタスクの状態を初期化するイベントは、投影のほぼすべての項目を戻す必要があり、誤りやすい。新しいタスクなら、追記だけの作業履歴の
  まま、ふつうのタスクと同じ経路で進む。中止したタスクの記録（片付けの結果・費用）もそのまま残る。
- 前の試行の記録を説明に入れると、人が画面で中身を確かめられ、オーケストレーターとすべての工程に同じ形で届く。

## 影響

- 再実行のタスクの説明は長くなる。再実行を重ねても記録が積み重ならないよう、再実行の画面の説明からは sacty が足した記録を除き、
  記録は再実行のたびに作り直す（前の前の試行の記録は引き継がない）。
- GitHub の Issue から取り込んだタスクの再実行は、取り込み元を引き継がない（Issue へのコメントは返さない。記録に Issue の URL を書く）。
- 工程を選んだときのイメージの決め方に、再実行で人が指定したもの（`imageSource: rerun`）が加わる。
