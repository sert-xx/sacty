# sacty image build の元のイメージと npm のレジストリを config.yaml の image_build で変えられ、npm の認証情報はイメージに残さない

- 日時: 2026-10-12 11:07 UTC
- ステータス: 採用
- 関係する PR・タスク: #40、PBI-33
- 置き換え元: なし
- 置き換え先: なし

## 背景

利用者の環境では、プライベートの Docker レジストリに登録されたイメージしか使えない。`sacty image build` は、決まった元のイメージ
（Docker Hub の node）と公開の npm のレジストリからエージェントのイメージを作っていた。

## 決定

- config.yaml の `image_build` に、元のイメージ（`base_image`。Node.js 22 で node ユーザーがあること）・npm のレジストリ（`npm_registry`）・
  npm の認証トークンの秘密情報の名前（`npm_token`）を書ける。書かなければ、これまでどおり。作ったイメージの名前は `image` の設定。
- Dockerfile の FROM を `ARG BASE_IMAGE` で変えられるようにする。git が入っていれば apt を使わない。
- npm の設定（.npmrc。トークンはレジストリのホストとパスに結びつける）は本人だけが読める一時ファイルに書き、BuildKit の secret で
  ビルドのときだけ読ませる。イメージの層・履歴・ビルドの引数には残さず、一時ファイルは終わったら必ず消す。
- トークンがキーチェーンに無ければ、作らずに止める。作れなかったときは、確かめること（Docker・元のイメージ・npm のレジストリ・トークン・
  Debian のミラー）を出して止める。
- 設定ファイルに誤り（形式の誤り・読めない YAML）があれば、理由を出し、docker を呼ばずに終了コード1で止める。既定には戻さない。
  設定ファイルがまだ無いときだけ、既定で作る。
- 作ったイメージは、エージェントの実行とテストの実行の両方で使う（どちらも `image` の設定を使う。変更なし）。

## 理由

- 利用者の環境で、プライベートのレジストリのイメージしか使えないため（PR の本文）。
- git が入っていれば apt を使わないのは、Debian のミラーに届かない環境のため（PR の本文）。
- .npmrc を BuildKit の secret で渡すのは、npm のレジストリの認証が要る場合も、認証情報をイメージに残さないため（PR の本文・コミットのメッセージ）。
- 設定の誤りで既定に戻さないのは、`image_build` の書き誤りで、指定したプライベートのレジストリが丸ごと捨てられ、公開のレジストリと既定の
  イメージ名で作り始めていたため。公開のレジストリを使えない環境のための機能で、誤りを出さずに別の取得先に切り替わるのは問題だった（レビュー）。

## 影響

- プライベートのレジストリに置くには、作ったイメージを利用者が push する。
- CLI が `@sacty/core` を使うようになり、依存関係と TypeScript のプロジェクト参照に足した。
