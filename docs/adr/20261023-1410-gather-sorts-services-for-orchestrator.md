# 情報収集がテストと動作確認に要るサービスを分け、オーケストレーターはそれをもとに依存だけを起動させ、対象のアプリは工程がコンテナの中で起動する

- ステータス: 採用
- 関係する PR・タスク: PBI-152
- 置き換え元: なし
- 置き換え先: なし

## 背景

テストとアプリの起動ができるかを試すタスクで、調査の工程が「Docker が使えないので、アプリの起動は確かめられない」と報告した。
sacty はこの工程のために DB と Redis を起動して、指示にも接続先を書いていたが、エージェントは一度も接続しなかった。

作業履歴とセッションのログで確かめた原因は、次のとおり。

- 情報収集は、既定のイメージのコンテナで、サービスを起動せずに動く。
  そこで確かめた「言語の版が足りない」「docker も DB も無い」を、まとめに「この環境で確かめたこと（事実）」として書いた。
  後の工程のコンテナ（別のイメージで、サービスもある）とは違う環境の話だった。
  情報収集の指示には、実行の環境やサービスのことが書かれていなかった。
- オーケストレーターの指示は「テストを動かすアプリ本体など、要らないサービスは含めない」だけで、アプリをどう起動するかは工程に任されていた。
  工程のサービスの案内には「docker のコマンドは使えない」だけがあり、アプリをコンテナの中で起動すればよいことが書かれていなかった。
- オーケストレーターの指示の「サービス名で接続する（localhost ではない）」は、localhost の転送の前の記述のままだった。

## 決定

- 情報収集の指示（作業するリポジトリがある、またはトリアージで決まるタスク）に、「実行の環境とサービス」の節を足す。
  - 情報収集のコンテナは後の工程の環境ではないので、そこで確かめたツールの有無・版・動いているものを、後の工程の事実として書かせない。
    要る版・ツールは、リポジトリの設定から読ませる。
  - sacty が工程の実行のたびにサービスを起動することと、工程のエージェントは docker を使えないがサービスにはつなげることを伝える。
  - テストと動作確認に要るものを、このリポジトリのコードを動かすアプリ・sacty が起動できる依存（別で管理されている依存アプリと DB・キャッシュ・モック）・
    compose に無い依存（共用の compose に合うものがあればその名前、無ければ起動できない依存）の3つに分けて、まとめに書かせる。
  - プロジェクトの共用の compose（名前・ファイル・説明）を、オーケストレーターと同じく指示に出す。
- オーケストレーターには、このリポジトリのコードを動かすサービスは選ばず、依存アプリと DB などは選ぶよう指示する。
  分け方は compose の build の有無ではなく、何を動かすかによる。情報収集のまとめに分類があれば、それをもとにし、compose ファイルなどで確かめて確定させる。
- 工程（とテストを実行する最終レビュー）のサービスの案内に、このリポジトリのアプリは docker を使わずにコンテナの中で起動して、サービスにつなぐよう足す。
- オーケストレーターの指示の「localhost ではない」を、localhost でも届くことに直す。
- 依存アプリの方から、コンテナの中のアプリを呼ぶ場合（コールバックなど）は扱わない（ステークホルダーの判断）。

## 理由

- 食い違いは、情報収集が sacty の実行の仕組みを知らないまま、自分のコンテナで確かめたことを事実として書いたことから起きた。
  仕組みを伝え、サービスの候補を探させれば、オーケストレーターと工程が同じ前提で動ける（ステークホルダーの案）。
- 対象のアプリを compose で起動させる案は採らなかった（ステークホルダーの判断）。
  対象のアプリのサービスは、イメージのビルドや作業領域のマウントが多く、sacty が起動できない設定に当たりやすい。
  工程で変えたコードを確かめるには、工程のコンテナの中で動かす方が直接でもある。
- 別で管理されている依存アプリは、このリポジトリからはビルドできないので、compose で起動しないとテストできない（ステークホルダーの指摘）。
- build の有無で分けないのは、このリポジトリの Dockerfile でビルドする DB のように、build があっても依存のものがあるため。
- オーケストレーターは、情報収集の見落としに備えて、今までどおりリポジトリを自分でも確かめる。

## 影響

- 情報収集のまとめに「テストと動作確認に要るサービス」の見出しが増え、後の指示に毎回入る分だけ長くなる。
- 指示で求めるだけで、分類や接続を強制はしない。エージェントが従わなければ、同じ食い違いは起こりうる。
- 情報収集の実行の環境（既定のイメージ・サービスなし）は変えない。
