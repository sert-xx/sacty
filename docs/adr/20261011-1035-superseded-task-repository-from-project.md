## 背景

#6 で、実装の対象リポジトリを `config.yaml` の `repository` で指定するようにした。#8 で、Issue から作ったタスクはプロジェクトの「リポジトリの設定」を使うようにしたが、画面で作るタスクは、どのプロジェクトでも `config.yaml` の `repository` を使っていた。プロジェクトの設定は `sacty.db` にあるのに、画面で作るタスクの対象だけが別の場所にあった。

## 決定

- 画面でタスクを作るときに、プロジェクトに登録したリポジトリの設定から対象リポジトリを選ぶ。1つだけなら、それを選んだ状態にする。
- タスクは、選んだリポジトリの設定（ベースブランチ・テストのコマンド・PR を作るか）で進む。URL は `https://github.com/{owner/name}.git` で、プロジェクトの gh のアカウントで clone する。Issue から取り込んだタスクは、これまでどおりその Issue のリポジトリで進む。
- リポジトリの設定が無い・選んでいない・設定に無いリポジトリのときは、タスクを作らずに理由を返す（画面は案内と設定画面へのリンクを出し、作成できないようにする）。
- `config.yaml` の `repository` は廃止する（読まない・雛形からも消す）。移行の手段や旧仕様は残さない。
- 対象リポジトリを持たない以前のタスクは、まだ clone していなければ理由を記録して一時停止する。clone 済みなら記録した URL のリポジトリの設定で、検証と PR 作成まで続ける。

## 理由

- 動作確認でのフィードバックによる（本文）。
- 移行の手段や旧仕様を残さないのは、`config.yaml` の `repository` をまだ誰も使っていないため（本文）。
- clone 済みの以前のタスクを検証と PR 作成まで続けるのは、検証の段階で対象リポジトリの設定を解決できず止まることがレビューで再現されたため（レビュー）。

## 影響

- 画面でタスクを作るには、プロジェクトにリポジトリの設定が要る。
- 残っている `config.yaml` の `repository` は読み飛ばされる（エラーにはならない）。
- タスクの詳細に、対象リポジトリ（以前のタスクは clone した URL）を出す。
