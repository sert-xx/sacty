# PR のレビューの子タスクがレビューする工程では、提出の前のセルフレビューを省く

- 日時: 2026-11-15 08:10 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-346
- 置き換え元: なし
- 置き換え先: なし

## 背景

要求要件・設計・実装・文書作成の工程は、提出の前に、既定のスキル `review-dispatch` の `self-review` の流れでセルフレビューをしていた。
sacty が PR を作るタスクでは、その PR を、PR のレビューの子タスクが別のコンテキストでレビューし、指摘を親タスクに届ける。
同じ成果物を、提出の前と PR で2回レビューしていて、費用と時間が重なっていた。

## 決定

- 提出が sacty の作る PR になり、PR のレビューの子タスクがレビューする工程では、提出の前のセルフレビューをさせない。
  - 要求要件・設計は、PR で承認するタスク。
  - 実装（不具合の修正を含む）は、対象のリポジトリがあるタスク。
  - 人の差し戻し・AI のレビューの指摘を受けた直しの実行も同じ。
- フォーマッター・リンター・テストなどの提出の前の検証は、今までどおり実行させる。
- PR にならない提出は、今までどおりセルフレビューをさせる。
  - 文書作成の工程、対象のリポジトリが無いタスク。
  - 要求要件・設計を画面で承認するタスク。
  - 既存の PR を引き継ぐタスク（引き継いだ PR には、レビューの子タスクを作らない）。
  - レビューの子タスクを作らないデーモン。
- 省いた実行は、セルフレビューの記録を持たない。「記録なし」にもせず、画面には何も出さない。

## 理由

- PR に紐づく工程では機械的な検証だけにしてセルフレビューを省くこと、PR に紐づかない場合は省かないことは、作者が決めた。
- 判定を「PR のレビューの子タスクがレビューするか」にしたのは、セルフレビューを省いてよい根拠が、その後のレビューがあることだから。
  既存の PR を引き継ぐタスクは PR に積むが、子タスクを作らないので、省かない。
- 記録を「記録なし」（`null`）にしなかったのは、「記録なし」が、させたのに報告が無いことを表し、画面で警告になるため。
  させていない実行に警告を出さない。
- 実装の「提出の前に確かめる、レビューの基準」を残したのは、観点の担当を起動するレビューではなく、差分を自分で確かめる短い一覧で、PR のレビューの指摘と直しの往復を減らすため。
- 答えの反映だけの直しの確認と、出典の分類は、セルフレビューとは別の決まりなので、変えていない。

## 影響

- PR で承認する工程は、提出までの費用と時間が減る。
- 提出の前に直っていた問題が、PR のレビューの指摘として出るようになる。
  PR のレビューと直しの往復が増えることがある。
- 要求要件・設計で、実行できなかった検証の理由は、報告が無いので残らない。
  PR の CI と PR のレビューが確かめる。
- 工程の実行の前に PR で承認すると判定し、実行の後に PR を作れなかったとき（アカウントの設定を外したなど）は、その提出はセルフレビューも PR のレビューも受けない。
- 仕様は [タスクと工程](../spec/tasks-and-steps.md#提出の前のセルフレビュー) にある。
