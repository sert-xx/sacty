# 依存の版の更新の上げ幅を読み取れないときは、PR のリスク評価の段階を中にする

- 日時: 2026-11-17 04:55 UTC
- ステータス: 採用
- 関係する PR・タスク: #409、PBI-377
- 置き換え元: [PR のリスク評価の段階を、合図の重さと、依存の版の更新の上げ幅で決める](20261117-0433-superseded-risk-level-by-signal-weight.md)
- 置き換え先: なし

## 背景

依存の版の更新は、上げ幅で段階を決める（メジャーは高、マイナー・パッチは低）。人が決めたのは、ここまでだった。
上げ幅を読み取れない更新（版の付け方が分からない、番号の版ではないもので指している、更新の前か後の版を確かめられない、版を下げている、など）の扱いは、置き換え元の ADR で、実装のときに「高」と決めた。メジャーかもしれない更新を、低として載せないためだった。
この点は、リポジトリの持ち主の確認がまだだった。

## 決定

- 上げ幅を読み取れない依存の版の更新は、「高」ではなく「中」にする（リポジトリの持ち主の決定。2026-11-17）。
- ほかに合図があるときは、合図の決まりで決まる段階と比べて、高いほうにする（軽い合図が 2 つ以上・重い合図が 1 つでもあれば、高）。
- メジャーは「高」、マイナー・パッチは「低」のまま。置き換え元の ADR のほかの決定（互換性を約束していない上げ幅をメジャーと同じに扱う、複数の依存はいちばん大きい上げ幅で決める、など）は、そのまま。

## 理由

- 持ち主が、選択式の問いに「中にする」と答えた。選んだ理由は、聞いていない。
- 中でも、低としては載らない。勧めるレビューの深さは「変えた振る舞いの箇所を読む」になり、人は、上げ幅の行（「上げ幅を読み取れない」）を見て、更新の中身を確かめられる。

## 影響

- sacty が自分で段階を上げるのは、メジャー（高にする）と、上げ幅を読み取れない更新（中以上にする）になる。
- 上げ幅を読み取れない更新が、実際にはメジャーだったとき、段階は中として載る（合図が無ければ）。
- 複数の依存を更新するときの、いちばん大きい上げ幅の決め方（1 つでもメジャーならメジャー。メジャーが無く、1 つでも読み取れなければ、読み取れない）は、変えていない。
