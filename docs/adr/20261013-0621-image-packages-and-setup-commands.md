# 言語ごとのイメージに、作るときに root で入れる OS のパッケージ（packages）と実行するコマンド（run）を書けるようにする

- 日時: 2026-10-13 06:21 UTC
- ステータス: 採用
- 関係する PR・タスク: #60、PBI-50
- 置き換え元: なし
- 置き換え先: なし

## 背景

Playwright のテストが OS のライブラリ（`libnspr4.so` など）が無くて失敗する、外部の PF（プラットフォーム）の CLI を使うテストで
CLI がイメージに無い、という問題があった。エージェントは root ではないので、タスクの中では OS のパッケージを入れられない。

## 決定

- `images.<名前>.packages`：OS のパッケージの一覧。イメージを作るときに root で入れる。dnf・microdnf・yum・apt-get のうち、
  元のイメージにあるものを使う。リポジトリの設定は、元のイメージか `run` で行う。
  - パッケージの名前は、英数字と `. _ + : @ ~ = -` だけを受け付ける（シェルの特別な文字・`-` で始まる名前は拒否する）。
- `images.<名前>.run`：イメージを作るときに root で上から順に実行するコマンド（1 行ずつ）。失敗したら止まる。
  元のイメージに bash があれば `bash -ex -o pipefail`、無ければ `sh -ex` で実行する。
  - コマンドはファイルに書いて BuildKit の secret の仕組みで渡し、ビルドの引数には出さない。パッケージとコマンドの中身の
    ハッシュを引数で渡し、変えたら作り直させる。
  - イメージに残るので、秘密情報は書かない（README に書く）。
- パッケージ → コマンドの順に、エージェントの CLI を入れた後・`node` ユーザーに切り替える前に行う。root が `/home/node` に
  作ったものは、#59 の手順で `node` ユーザーの持ち物に戻す。
- `packages`・`run` を書かないイメージと既定のイメージは、これまでどおり。

## 理由

- エージェントは root ではないので、タスクの中では OS のパッケージを入れられないため（PR の本文）。
- パッケージの名前を限るのは、シェルの特別な文字・`-` で始まる名前を拒否するため（PR の本文）。
- `run` を pipefail で実行するのは、レビューで、`sh -ex` ではパイプの途中の失敗（取得の失敗）を検知できず、CLI が入らないまま
  ビルドが成功することがわかったため（レビューとその返信）。
- コマンドを secret の仕組みで渡す理由は、ビルドの引数に出さないため、と書かれている。それ以上の理由は記録に無い。

## 影響

- 利用者は、言語ごとのイメージに OS のライブラリや CLI を入れられる。`packages`・`run` を変えると、イメージが作り直される。
- bash の無いイメージ（`sh` で実行）では、パイプの最後のコマンドの終了コードしか見ないので、取得と実行はパイプでつながずに
  項目を分ける必要がある（README に書く）。
- `run` の内容はイメージに残るので、秘密情報を書くと漏れうる。
