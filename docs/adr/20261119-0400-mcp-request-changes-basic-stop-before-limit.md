# sacty mcp の差し戻しは、基本の形に限り、上限の手前で止める

- 日時: 2026-11-19 04:00 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-397
- 置き換え元: なし
- 置き換え先: なし

## 背景

`sacty mcp` は、成果物を読み（[前の ADR](20261119-0200-mcp-read-deliverables-and-runs-by-byte-range.md)）、承認できる（[承認の ADR](20261119-0300-mcp-approve-with-screen-api-not-merge.md)）。直してほしいときに差し戻すには、画面を開く必要があった。
機能を1つずつ足す流れの4回目として、差し戻しを足す。
画面の差し戻しには、戻し先・原因・タスクのイメージとエージェントの変更・上限を超えて続ける、という選択がある（[承認](../spec/approval.md)）。
決める必要があったのは、どこまでを MCP から差し戻せるようにするか、上限（同じ工程への人の差し戻しは3回）をどう扱うか。
デーモンの差し戻しは、承認待ちの工程が上限に達していると、断らずにタスクをエスカレーション（`TaskEscalated`）にして指摘を書きかけとして残す。

## 決定

- ツール `request_changes`（`task_id`・`step`・`submission`・`comments`）を足す。デーモンの既存の `POST /api/tasks/:id/request-changes` に `{ step, submission, comments }` だけを送る。デーモンの差し戻しの動き・記録・API は変えない。
- 戻し先（`target`）・原因（`cause`・`answer`）・`image`・`agents`・`continueOverLimit` は、引数にもせず、送らない。戻し先は既定（承認待ちの工程に最も近い、やり直せる工程）に任せ、実際にやり直す工程を結果の `reworkStep` で返す。原因は、画面で選ばないときと同じく、原因を決めない差し戻しになる。
- **上限に達していたら、差し戻さず、何も変えない。** 上限に達した工程にそのまま送ると、API は断らずにエスカレーションにするので、API を呼ぶ前に、MCP の層が `GET /api/tasks/:id` のタスクから確かめて断る（`reworkTargets`・`changeRounds`・`MAX_CHANGE_REQUESTS`。判定の写しであることをコメントに書く）。続けるかどうかは、費用が増えるので、人が画面で決める。
  状態が `escalated` のタスクは、理由を問わず差し戻さない。確かめた後に、API の結果が `escalated` だったら、「差し戻しました」と返さず、エスカレーションになったことを返す。
- 提出（工程と回）は呼ぶ側が指定し、違えば差し戻さない。古い回の理由は、承認の文ではなく、差し戻しの文にする。
- 指摘は `comments` の配列で受け、各文字列を改行で1行1件に分けて、前後の空白と空の行を除く（画面の欄と同じ）。件数・長さの上限（50件・1件 2000 文字）は API と同じ。MCP の引数の形では長さを測らず（API は空白を除いた後で測るため）、分けた後に確かめる。
- PR を作った工程も、画面と同じく差し戻せる（API は断らない）。この指摘は PR に残らず、人の差し戻しとして数える。PR に記録を残したいときは PR のコメントで差し戻す。MCP から PR にコメントを書くことは、入れない。
- 結果を受け取れなかったとき（時間切れ・切断・本文を読めない・5xx）は、差し戻されている可能性を返し、自動でやり直さない（`approve_step` と同じ）。401・接続拒否は、差し戻していないものとして返す。
- 注釈は `readOnlyHint: false`・`destructiveHint: false`・`idempotentHint: false`・`openWorldHint: true`。

## 理由

- 画面と同じ API なら、記録もやり直しの始まり方も画面と同じで、MCP 専用の経路・記録が増えない。
- 上限を超える差し戻しは費用が増えるので、人の判断に残す。API に送ってからでは、エスカレーションという状態の変化が起きてしまうため、送る前に断る。
- 戻し先・原因などは、後から足せる。最初は、頼まれた直しを送るだけの形にして、機能を一度に入れない。

## 影響

- 登録した AI は、利用者に頼まれたときに、画面の基本の差し戻しと同じことができる。差し戻すと工程がやり直され、時間と費用がかかり、取り消せない。毎回確かめるかは、AI の CLI の権限の確認に任せる。
- 上限の確かめは、デーモンの判定の写しなので、判定が変わったら合わせる。確かめと送信の間に状態が変わると、エスカレーションになりうる（その場合は、そのことを返す）。
- 上限を超えた差し戻し・戻し先・原因の指定は、後続で別の決定として足す（この作りは、後から足せる）。
- 仕様は [MCP サーバー](../spec/mcp-server.md#request_changes)、利用者向けは [手元の AI から操作する](../user/mcp.md#差し戻す) に書く。
