# デーモンの API が返す利用者向けの文言を、文言のコードと引数にし、辞書を core に置いて画面の言語で文にする

- 日時: 2026-10-10 13:06 UTC
- ステータス: 採用
- 関係する PR・タスク: #15、PBI-11
- 置き換え元: [画面の言語はブラウザの言語に従って日本語・英語を決め、ユーザーメニューで上書きでき、エージェントの成果物は訳さない](20261010-1048-superseded-ui-language-selection.md)（API が返すデーモンの文言を日本語のままにする部分）
- 置き換え先: なし

## 背景

#11 で画面を日本語・英語で切り替えられるようにしたが、デーモンが作る文言は日本語の文のままだった。これを画面の言語で出すには、
デーモンが文言を文ではなく、コードと引数で返す必要があった。PBI-11 は範囲が広いため2つに分け、この PR（PBI-11a）では仕組みと API が返す文言を、
続く PR（PBI-11b）では台帳などに記録する文言を扱う。

## 決定

- `@sacty/core` に `messages.ts` を置き、文言のコードごとの引数の形（zod のスキーマ。型の `MessageParams` もここから作る）と、日本語・英語の辞書を持つ。
  辞書にコードがすべて揃っていることを型で確かめる。英語の用語は画面の用語集に合わせる。
- `renderMessage(value, locale)` で文にする。コードと引数でない値（古い文・外から来た文）はそのまま返す。知らないコード、引数が無い・一部が欠ける・形が合わないときは、
  例外にせずコードを出す。
- 409（状態に合わない操作）は `{ error: "invalid_operation", messages: [{ code, params }] }` で返す。プロジェクトの重複は、複数をまとめて返す。
- 400（入力の検査）は、すべての誤りを `{ path, message: { code, params } }` で返す。コードを指定した検査はそのコード、指定していない zod の標準の検査は、
  誤りの種類ごとのコード（必須・文字数の上限と下限・件数・数値の範囲・型・形式・値・知らない項目）にする。
- 画面は、デーモンとの通信（`apps/web/src/lib/daemon.ts`）で画面の言語の文にする。古いデーモンが返す日本語の `message` も、そのまま出す。
- エージェントが書いた文や、外から来た文（git・GitHub のエラーなど）は訳さず、引数としてそのまま渡す。

## 理由

- 辞書を core に置いたのは、デーモンのログや CLI、PBI-11b までの台帳の文で日本語の文が要るためで、辞書を1か所にまとめるため（PR の本文）。
- zod の標準の検査もコードにしたのは、コードを指定していない検査の誤り（空のベースブランチなど）が、日本語の画面でも英語のまま出ることが、レビューで見つかったため（レビュー）。
- 引数の形を確かめてからコードに戻すのは、引数が一部欠けると `undefined` が文に埋め込まれることが、レビューで見つかったため（レビュー）。
- 知らないコードを例外にせずコードで出すことの理由は記録に無い。

## 影響

- デーモンで利用者向けの文言を足すときは、core の辞書にコードと日本語・英語の文と引数の形を足す。
- 画面は、新旧どちらのデーモンの応答も表示できる。
