# 一時停止の間に届いた PR の指摘を、再開のときに取り込む

- 日時: 2026-11-02 19:00 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-279
- 置き換え元: なし
- 置き換え先: なし

## 背景

実験（S16）で、最終レビューがエラーで一時停止している間に、人が実装の PR に指摘を書いた。PR の指摘の取り込みは承認待ちのタスクだけが対象なので、指摘は取り込まれなかった。
再開しても、止まった工程（最終レビュー）だけが走り直され、実装をやり直す手段が無かった。

## 決定

- 実装の作り直しを一時停止している間も、実装の PR の指摘（人の指摘と、sacty 自身の AI のレビューの指摘）を読み、未反映として残す。差し戻しにはしない。タスクの詳細に、届いた件数を出す。
- 再開したあと、止まった工程を走り直す前に、未反映の指摘をゴールガーディアンに渡して戻し先を判断させ（承認待ちの PR の指摘と同じ判断）、その工程に差し戻す。指摘が無ければ、今までどおり止まった工程を走り直す。
- 一時停止の理由は問わない（予算の上限・エラー・人が止めた、など）。
- 人の差し戻しの上限は、再開を続ける判断として扱い、止めない。AI のレビューの指摘は、これまでどおり人の回数に数えない。
- 一時停止の間に PR がマージされたら、残した指摘は捨てて、マージを承認として進める。

## 理由

- 指摘の取り込みの方針は人が決めた（再開のときに取り込む）。一時停止の間に判断まで進めると、止めたタスクに費用がかかり、人が止めた意図に反する。残しておいて再開で判断すれば、止めている間は何も動かない。
- 承認ゲートが無い状態で差し戻すので、エスカレーションを置く場所が無い。人の再開が「続ける」という判断にあたるため、上限では止めない。
- 再開の直前に書かれた指摘を落とさないよう、再開した直後にもう一度読む。

## 影響

- `PullRequestReviewImported` に `held`、`ReworkStoppedByMerge` に `discardedReview` が増える（無ければ従来どおり）。
- 要求要件・設計をやり直している間に一時停止したタスクは対象外（その間の指摘は、実装の承認待ちになってから取り込む）。
- 規則は[承認と差し戻し](../spec/approval.md#一時停止の間に届いた指摘)に記す。
