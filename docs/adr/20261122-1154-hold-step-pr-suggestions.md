# 要求要件・設計の PR の提案だけの往復を止める

- 日時: 2026-11-22 11:54 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-481
- 置き換え元: [提案を直しの前に選り分ける](20261120-2109-superseded-triage-ai-review-suggestions-before-rework.md)（要求要件・設計の PR は変えない部分）
- 置き換え先: なし

## 背景

要求要件・設計の PR では提案だけのレビューが続くと、直しと再レビューが繰り返される。

## 決定

提案だけの判定が 2 回続いたら、2 回目は直さず人の承認を待つ。
要修正や人の指摘は直す。

## 理由

最初の提案は取り込みつつ、以降の往復を抑える。
PBI-436 では実装の PR について人を待つ案と回数で止める案を採らず、AI が提案を選り分けることにした。
その仕組みは実装の PR を前提とするため、要求要件・設計の PR には回数による打ち切りを採る。

## 影響

新しい記録を追加するため、その記録後は以前の版のデーモンに戻せない。
仕様は [承認](../spec/approval.md) に記す。
