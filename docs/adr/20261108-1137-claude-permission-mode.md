# Claude Code の実行に、権限の確認を求めないモードを明示して渡す

- 日時: 2026-11-08 11:37 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-320
- 置き換え元: なし
- 置き換え先: なし

## 背景

sacty は Claude Code を `claude -p` で起動し、権限のモードを渡さず CLI の既定に任せていた。
既定のイメージの Claude Code を 2.1.296 から 2.1.318 に上げた（PBI-307）後、実行の初めに報告されるモードが `auto` から `default` に変わった。
`-p` では確認に答える人がいないので、確認の要るツール（Bash の `npm ci`・`npm test` など）は拒まれる。
最終レビューと PR のレビューがテストを実行できず、記録の使い回しで合格を出したり、実行されたコマンドを「実行されていない」と書いたりした。

Codex は、Codex の中のサンドボックスを作れず、隔離は sacty のコンテナが受け持つので、どの設定よりも優先される引数で `--sandbox danger-full-access` を渡している（PBI-40）。

## 決定

- Claude Code の実行に、`--permission-mode bypassPermissions` を引数で渡す（`CLAUDE_PERMISSION_MODE`）。引数は、コンテキストや対象のリポジトリの `.claude/settings.json` の既定のモード（`permissions.defaultMode`）よりも優先される。設定の個別の `ask`・`deny` の規則は、このモードでも効く。
- 使わせないツール（`--disallowedTools`）は、今までどおり渡す。

## 理由

- 実行は一度きりで確認に答える人がいないので、確認を求めるモードでは作業ができない。CLI の既定は版で変わるので、明示しないと版を上げるたびに振る舞いが変わる。
- `auto` は、前の版の振る舞いに近いが、判定の仕組みが使える認証や環境に左右され、使えないときの振る舞いを sacty が決められない。`bypassPermissions` は認証の方式によらず同じに動く。
- 隔離は sacty のコンテナが受け持つ。Codex と同じ考え方にそろえる。
- エージェントは、どのイメージでも root ではない `node` ユーザーで動く（[イメージ](../user/images.md)）ので、root では使えないこのモードを使える。

## 影響

- 工程・ゴールガーディアン・オーケストレーター・情報収集・レビューなど、Claude Code のすべての実行が、確認を求めずにツールを使う。
- 仕様：[エージェントの実行](../spec/agent-execution.md) の起動の引数の表。
