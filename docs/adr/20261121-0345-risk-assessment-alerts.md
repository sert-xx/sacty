# リスクの判断材料と人間への確認依頼を独立した Alert に分ける

- 日時: 2026-11-21 03:45 UTC
- ステータス: 採用
- 関係する PR・タスク: #500
- 置き換え元: なし
- 置き換え先: なし

## 背景

リスクの段階・根拠・レビューの深さ・重点確認箇所・検証情報が同じ箇条書きに並び、人の判断材料と確認依頼を見分けにくい。
投稿の Markdown は固定レンダラーが作るため、生成指示だけでは構造を変えられない。

## 決定

- 共通レンダラーで、低・中・高を NOTE・IMPORTANT・WARNING の GitHub Alert として描画する。1〜3 は区分番号で、点数や確率ではない。
- 根拠は低では1段落、中・高では項目に分け、レビューの深さ・合図・依存更新も同じ枠に置く。
- 人間への重点確認依頼は独立した TIP にし、無ければ省く。生成指示は既存の why に理由と確認してほしいことの両方を求める。過去の記録にない内容は補わない。
- 検証情報は自由文のまま、AI による目安の注記とともに枠外に置く。各 Alert の全行を引用し、枠の間は引用外の空行で分ける。
- 有効な相対パスと行の指定は、対象リポジトリのホストと評価記録のコミットを使ってリンクにする。不明・不正な指定はテキストにする。

## 理由

判断材料と人への作業依頼を分けると、何を根拠にどこを確認するかが読み取れる。評価したコミットへの固定リンクで、後から先頭が変わっても同じ対象を確認できる。
自由文の検証情報を機械的に分割しないことで、記録の意味を変えずに表示できる。

## 影響

指摘なしのレビューコメントと、残った提案をすべて対応しないとした回の専用コメントに適用する。
最新の評価タイミング・PR 本文には載せない仕様・判定・JSON スキーマ・保存イベント・Web カードは維持する。
[仕様書](../spec/risk-assessment.md)に表示とリンクの条件を記載する。
