# スキルをグループのディレクトリ（skills/<グループ>/<名前>/SKILL.md）にまとめて置けるようにし、名前で扱う

- 日時: 2026-10-14 00:34 UTC
- ステータス: 採用
- 関係する PR・タスク: #72、PBI-65
- 置き換え元: なし
- 置き換え先: なし

## 背景

コンテキストのスキルは `skills/<名前>/SKILL.md` の1階層だけを認識していた（#32 で決めた形）。既定のコンテキストに
レビューのスキルを同梱するにあたり、親（観点を起動して集約する役）と観点担当を別のスキルに分け、関係する2つを
まとめて置きたかった。

## 決定

- `SKILL.md` の無いディレクトリはグループとして再帰的に探す（`skills/<グループ>/<名前>/SKILL.md`）。スキルの名前はディレクトリの名前にする。
- worker にはグループを外して `skills/<名前>/` として置く（Codex の AGENTS.md の一覧にも載る）。
- 層の上書き・locked・remove は名前で行い、グループの位置は問わない。下位の層がグループの外に置いても上書きできる。
- 同じ層に同じ名前のスキルが重なれば、先のものを使って警告（`context.duplicateSkill`）を残す。
- 既定のコンテキストと雛形の README に、グループの置き方を書く。

## 理由

PR の本文とコミットのメッセージにあるのは、親と担当を別のスキルにし、グループ `review` の下に2つを置くため、ということだけ。
名前で扱う・重なりを警告にする・worker でグループを外す、をほかの形と比べた理由は記録に無い。

## 影響

- 既定のコンテキスト・コンテキストリポジトリのどちらでも、関係するスキルをグループのディレクトリにまとめて置ける。
- グループが違っても同じ名前のスキルは同じものとして扱われるので、名前は層をまたいで一意である必要がある。
- worker の側から見たスキルの置き場所（`skills/<名前>/`）は変わらない。
