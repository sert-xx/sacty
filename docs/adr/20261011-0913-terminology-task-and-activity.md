# 「チケット」を「タスク」に、「台帳」を「作業履歴」（英語は Activity）に統一し、コードの名前・API・テーブルも合わせる

- 日時: 2026-10-11 09:13 UTC
- ステータス: 採用
- 関係する PR・タスク: #26、PBI-20
- 置き換え元: なし
- 置き換え先: なし

## 背景

画面・文書・コードでは「チケット」「台帳」という語を使っていた。動作確認で、用語を統一するようフィードバックがあった。

## 決定

- 「チケット」は使わず「タスク」にする。タスクの詳細の内容の欄は「内容」（英語は Description）にする。
- 「台帳」は「作業履歴」（英語は Activity）にする。
- 画面・文書・エージェントへの指示だけでなく、コードの名前も変える（`createTicket` → `createTask`、`Ledger*` → `Activity*`、`POST /api/tickets` → `POST /api/tasks`、タスクの API の応答の `ledger` → `activity` など）。
- 作業履歴のテーブルを `ledger` から `activity` に変える。起動時に以前の `ledger` のテーブルがあれば名前を変え、記録済みの行と seq の続きを引き継ぐ（索引とトリガーは作り直す）。
- 画面で作ったタスクの開始地点は `sacty` と記録し、以前の値 `ticket` は `sacty` として読む。
- 記録済みの文（オーケストレーターの理由など）は追記専用なので、その中の「チケット」は残す。

## 理由

- 用語の統一は、動作確認でのフィードバックによる（本文）。コードの名前まで変えるのは決定事項として本文にあるが、理由は記録に無い。
- 記録済みの文を変えないのは、作業履歴が追記専用のため（本文）。

## 影響

- 以前のデータ（`ledger` のテーブル、開始地点の `ticket`）は、起動時の移行と読み替えで引き続き読める。
- API の名前が変わる（`/api/tickets` は `/api/tasks` に）。
- 記録済みの作業履歴の文には、以前の用語が残る。
