# レビューの工程では、PR の差分の全体を切り詰めずに sacty が管理する場所に置き、読み取り専用でマウントして渡す

- 日時: 2026-10-14 00:34 UTC
- ステータス: 採用
- 関係する PR・タスク: #72、PBI-65
- 置き換え元: なし
- 置き換え先: なし

## 背景

レビューの工程で worker に渡す作業領域は `.git` の無い写しで、プロンプトの差分は 10 万文字で切り詰めていた。大きな PR では、
worker が残りの差分を `git diff` で取れなかった。また差分の取得（`diffCommits`）自体も 20 万文字で切り詰めていた。

## 決定

- レビューの工程では、`diffCommits` に `full` の選択肢を足して差分を切り詰めずに取る（既定の振る舞いとプロンプトの切り詰めは変えない）。
- 差分のファイルは、PR 由来の写しの中には書かず、sacty が管理する `workspaceRoot/_review/<runId>/pr.diff` に置く。
  `Invocation.mounts`（追加の読み取り専用マウント）を新設し、コンテナの `/sacty-review` にマウントする。実行の後に消す。
- プロンプトで、その場所と「sacty が置いたもので PR の一部ではない」ことを伝える。スキルの差分の取得の順は
  「差分のファイル → `.git` があれば git → どちらも無ければ省略された範囲があると本文に書く」にする。

## 理由

- 最初は写しの中の `.sacty/pr.diff` に書いたが、レビューで、PR に `.sacty` やそのファイルへのシンボリックリンクがあると、
  コンテナを起動する前のデーモンの権限でホストのファイルを上書きできる（P1）と指摘された。写しの中に書く設計をやめ、
  PR のファイル・リンクとパスが衝突しない管理領域に置くことにした（行へのコメントへの返信）。
- 切り詰めずに取るのは、20 万文字を超えた部分がファイルにも無く、「差分の全体」という案内と一致しない（P2）というレビューの
  指摘への対応。

## 影響

- worker は、大きな PR でも `/sacty-review/pr.diff` から差分の全体を読める。
- 実行ごとに追加の読み取り専用マウントを渡す仕組み（`Invocation.mounts`）ができた。
- 実際の Docker でのマウントは、この PR の時点では確かめていない（レビューの記録）。
