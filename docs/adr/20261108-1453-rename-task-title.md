# タスクの題を、人がタスクの詳細でいつでも変えられるようにし、すでに作った PR の題は書き換えない

- 日時: 2026-11-08 14:53 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-323
- 置き換え元: なし
- 置き換え先: なし

## 背景

タスクの題は、作成のとき（チケットのタスクはトリアージのとき）に決まり、その後は変えられなかった。
利用者から、タスクの途中で題を変えたいという要望があった。

題は、工程の指示・コミットのメッセージ・通知・PR の本文・書き出し・監査などで、使うときのタスクの題を読んでいる。
PR の題は、PR を作るときにだけタスクの題を使い、その後の PR の更新は本文と向き先だけを変える。
ブランチ名はタスクの ID から作り、題を使わない。
題にある PR のリンクは、レビューの対象と既存の PR の引き継ぎの対象を決める（`referencedPullRequest`・`continuablePullRequest`）。

## 決定

- タスクの詳細で、人がタスクの題を変えられるようにする（`POST /api/tasks/:id/title`）。
  中止したタスク（以降の操作は受け付けない）のほかは、状態を問わない。
- 変更は `TaskRenamed`（`from`・`to`。actor は `person`）として作業履歴に足す。作成の記録（`TaskCreated`）は書き換えない。
- 題は作成と同じ規則で確かめる（前後の空白を除き、空・`TASK_TITLE_MAX` を超える題は断る）。今と同じ題も断る。
- 題にある PR のリンクで決まる対象の PR が変わる・無くなる変更は断る。
- 変えた題は、この後に題を使うものから使う。実行中の実行は止めない。PR の題・本文は、使う直前に読み直す。
- コミットのメッセージの題は、コミットの日時（提出ごとに決まる日時）のときの題にする。同じ提出の再試行で、題を変えても同じコミットにするため。
- すでに作った PR の題は、自動では書き換えない。ブランチ名も変えない。
- チケットのトリアージ（`TicketTriaged`）は、人が変えた題を書き換えない。

## 理由

- 作業履歴は追記だけで書き換えないので（[作業履歴は追記だけ](20261010-0628-append-only-ledger.md)）、変更を新しいイベントにする。誰が・いつ・何から何に変えたかも残る。
- 状態を問わないのは、題は進め方に関わらない表示と指示の文で、途中で変えても工程の結果を変えないため。タスクのイメージ・工程のエージェント（[タスクのイメージ](20261108-0334-task-image.md)）と同じく、中止したタスクだけは断る。
- PR の題を自動で書き換えないのは、PR は外部（GitHub）に見え、人がレビューの途中で読んでいるものなので、書き換えるかは人が決めることだと考えたため。今の PR の更新も題を変えていない。自動で追従させるかは、PR で人に確かめる（未決）。
- 題の PR のリンクを変える変更を断るのは、途中からレビュー・引き継ぎの対象の PR が変わると、前の回の記録と食い違うため。
- トリアージが人の題を書き換えないのは、人の指定をオーケストレーターの判断より優先する今までの考え方に合わせるため。
- コミットのメッセージを日時のときの題にするのは、コミットを提出ごとに決まる日時で作って再試行で同じコミットにしている仕組みを保つため。最新の題にすると、PR の作成に失敗した後に題を変えて再開したとき、別のコミットになり、プッシュ済みのブランチに積めない（PR #330 のレビューで実際の git で確かめられた）。比べた案：プッシュ済みのコミットを再試行で使い回す。どの記録が同じ提出の再試行かを見分ける仕組みが新しく要るので採らなかった。
- 比べた案：説明（本文）も一緒に変えられるようにする。説明は工程の要求そのもので、途中で変えると承認した要求要件・設計と食い違うので、今回は題だけにした。

## 影響

- 変更の後に作るコミット・通知・PR の本文の更新・工程の指示は新しい題を使い、変更の前に作った PR の題・コミットのメッセージ・外部のページの題は前の題のまま残る。変更の前に出した成果を、変更の後にコミットし直すとき（再試行）も、メッセージは前の題になる。
- 仕様は [工程とタスク](../spec/tasks-and-steps.md)、利用者向けは [タスク](../user/tasks.md) に書く。
