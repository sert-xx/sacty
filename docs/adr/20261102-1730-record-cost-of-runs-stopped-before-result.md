# 結果が出る前に止めた実行は、出力から読めた分を費用に入れ、読めなければ 0 ではなく不明と記録する

- 日時: 2026-11-02 17:30 UTC
- ステータス: 採用
- 関係する PR・タスク: #277、PBI-281
- 置き換え元: なし
- 置き換え先: なし

## 背景

フィールドの試行（時間切れの再開）で、時間切れで止めた実行の費用がどれも $0.0000 と記録された。エージェントの CLI は、実行の終わりの
結果（`result`・`turn.completed`）で使用量を出すので、その前に止めると使用量を受け取れず、実際には何分も使った実行が 0 になった。
費用の表示にも予算の判定にも入らず、時間切れが続いても予算の保護が働かなかった。

## 決定

- 時間切れで止めた実行は、止めるまでに標準出力へ出た分から使用量を拾って、費用にする。
  - Claude Code：`assistant` の `message.usage` を `message.id` ごとに合計する（下限）。
  - Codex：終わった番（`turn.completed`）の使用量。終わっていない番の分は読めない。
- 拾った分は下限であり、全体は分からないので、イベントに `costUnknown` を付ける。何も読めなければ `costUsd` は 0 のままにして
  `costUnknown` だけを付け、0 を「費用が無かった」と取り違えさせない。出力が1つも届かなかった実行（起動できなかった）には付けない。
- 画面と作業履歴は、読めた分があれば「以上」、読めなければ「不明」と出す。タスクの予算は読めた分を使い、不明の回数を数える（`budget.unknownRuns`）。

## 理由

- 読めた分だけでも予算に入れるほうが、0 のままより予算の保護が効く。
- 下限であることを隠して正確な金額に見せると、予算の判断を誤らせる。不明を 0 と見せないために、イベントで印を持つ。
- 使用量が出ない Codex の時間切れを推定で埋めない（実行の長さや出力の量からの見積もりは、根拠が弱い）。

## 影響

- 失敗を記録しうるイベント（`AgentRunFailed` など10種類）が、任意の `costUnknown` を持つ。古い作業履歴はそのまま読める。
- サブエージェントの内側の使用量は読めないので、Claude Code の下限は、サブエージェントを多く使う実行ほど実際より小さい。
- 完了したタスクの監査の実行（監査の予算は別）は、この PBI の対象にしていない。
