# 指摘なしの後の CI の失敗の表示を、CI を読んでいる間に通ったら消す

- 日時: 2026-11-17 04:40 UTC
- ステータス: 採用
- 関係する PR・タスク: #410、PBI-375
- 置き換え元: [指摘なしの後に実装の PR の CI が失敗していたら、タスクの詳細に出す（読み続けず、自動では扱わない）](20261117-0320-superseded-show-ci-failure-after-no-findings.md)（記録した後の変化を読まない・反映しない部分）、[指摘なしの後の実装の PR の CI の失敗を、タスクの一覧の行にも印で出す](20261117-0406-superseded-show-ci-failure-on-task-list.md)（回復の仕組みを足さず、再実行で通っても印が残る部分）
- 置き換え先: なし

## 背景

人の承認を待つ実装の PR の CI が失敗していたら、タスクの詳細と、タスクの一覧の行の印に出している（置き換え元の2つの ADR）。
仕組みを小さくするため、回復は記録しなかった。CI を再実行して通っても、表示は、PR を更新する・マージする・閉じるまで残った。

一覧に印を出すようになって、古い失敗が残り続けるのが目立つようになった。
リポジトリの持ち主が、CI を読んでいる間に通ったら、表示を消すと決めた。読む期間は延ばさない。

CI を読み続けて回復を判定する最初の版は、レビューで、次の抜けを指摘された（置き換え元の ADR の背景）。

- 取り消された CI だけの一覧を、通ったと扱う。
- 空の一覧を、通ったと扱う。
- 取得を上限で打ち切った一覧の、読めた分だけを見て、通ったと扱う。
- 読み続けるために、GitHub への問い合わせの数が決まらない。

## 決定

- CI を読む期間と回数は変えない。先頭のコミットごとに、5分おきに、12回まで。1回の PR の確認で読むのは1件だけ。
- 失敗を記録した後も、同じ回数の上限の中で、同じ間隔で読む。失敗を記録した回も、上限に数える。
- 失敗の表示を出している間に読んだ CI が通っていたら、表示を消して（`PullRequestCiRecovered`）、作業履歴に残し、その先頭は読むのをやめる。
- 「通った」は、次のすべてを満たすときだけにする。
  - CI の一覧を読み切れている（取得を上限で打ち切っていない・続きのページをたどれなかったことが無い）。
  - 一覧が空でない。
  - すべて終わっていて、結論が成功か、実行されなかった（skipped）・中立（neutral）で、成功が1件以上ある。コミットの状態は、成功だけ。
- 取り消し・空の一覧・読み切れなかった一覧・実行中・古い結果（stale）・結論を読めないものが1件でもあれば、消さない。回数の上限までは、間隔の後に読み直す。
- 人が PR にコミットを足して先頭が変わったときは、新しい先頭の CI が通ったら、前の先頭の失敗の表示も消す。
- 回数の上限の後に通った CI は、拾わない。表示は、PR を更新する・マージする・閉じるまで残る。
- 消すだけにする。実行・差し戻し・再レビュー・CI の再実行・通知は行わない。状態の表示も変えない。

## 理由

- 読む回数の上限を変えないので、GitHub への問い合わせの数・1回の確認で待つ時間・未完了の通信の数は、置き換え元の ADR の上限のまま。変わるのは、失敗を記録した先頭を、上限まで読むようになることだけ。
- 判定に迷うもの（取り消し・空・読み切れない）は、すべて、失敗の表示を残す側に倒す。残った表示は、人が PR で確かめれば済む。誤って消すと、落ちている CI に人が気づけない。
- 実行されなかった（skipped）・中立（neutral）を妨げにしないのは、条件つきのジョブがあるワークフローでは、通った CI にも必ず含まれるため。これらを通っていないと扱うと、そのようなリポジトリでは、表示が消えることが無い。成功が1件も無い一覧（すべて実行されなかった）は、何も確かめていないので、通ったと扱わない。
- 一覧を読み切れたかは、CI を読む口（`CiSnapshot.truncated`）が伝える。読めた分だけでは、読めなかった分の失敗を見落とす。
- 新しい先頭の CI が通ったときに前の先頭の表示も消すのは、表示が PR の今の状態を示すものだから。先頭ごとに消す条件を分けると、人が直して通した PR に、古い先頭の失敗が残る。
- 比べた案：失敗を記録した先頭を、回数の上限とは別に、決まった時間だけ読み直す。問い合わせの数の上限が増え、読む期間を延ばさないという決定に合わない。採らなかった。
- 比べた案：消さずに、「その後に通った」と表示を変える。持ち主が決めたのは、消すこと。採らなかった。

## 影響

- 読み直すのは、その先頭を最初に読んでからの期間（1時間ほど）の残りだけ。失敗を見つけたのが遅いほど、消える機会は少ない。最後の読み取りで失敗を見つけたときは、読み直さない。
- デーモンを再起動すると、回数を数え直すので、表示を出している先頭を、もう一度、上限まで読む。
- 消した後は、その先頭を読まない。消した後に再実行されて落ちた CI は、出し直さない（デーモンを再起動すると、読み直す）。
- 記録した失敗の一覧（失敗していたチェック）は、読み直しても更新しない。
- 取り消された CI が残る PR・CI の項目が上限（1つの一覧につき 1,000 件）を超える PR では、通っても表示は消えない。
