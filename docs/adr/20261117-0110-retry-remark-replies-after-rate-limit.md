# レート制限に当たった指摘への返信を、期限が明けてからやり直す

- 日時: 2026-11-17 01:10 UTC
- ステータス: 採用
- 関係する PR・タスク: #400、PBI-356
- 置き換え元: [取り込んだ PR の指摘への対応を、指摘ごとに PR に返信する](20261116-0045-superseded-reply-to-review-feedback-on-pull-request.md)（レート制限に当たった返信を、失敗として残してやり直さない、という部分）
- 置き換え先: なし

## 背景

[取り込んだ PR の指摘への対応を、指摘ごとに PR に返信する](20261116-0045-superseded-reply-to-review-feedback-on-pull-request.md)（PBI-352）では、返信が GitHub のレート制限に当たったら、そこで投稿を止めて、残りを失敗として作業履歴に残し、やり直さないと決めた。
やり直すには、アカウントごとの待ちの置き場所から設計が要ると分かったので、別に扱うことにしていた。

1回の提出で、多くの指摘への返信を続けて投稿しうる。制限に当たると、残りの返信がすべて失敗になり、指摘した人・AI が、指摘の場所で対応を読めないままになる。

人が決めたこと（2026-11-17）：やり直すのは、指摘への対応の返信だけにする。sacty のほかの投稿（PR のコメントの頼み・レビュー・人に確かめてほしいことのコメント）は、今のままにする。待ちの状態は、ホストとアカウントごとに保存する。

## 決定

上の ADR の決定のうち、「レート制限に当たったら、残りの指摘の返信も、失敗として作業履歴に残す（やり直さない）」を、次のとおりに置き換える。上の ADR のほかの決定（返信の形・1件の指摘に1回だけ返信する・二重の投稿を防ぐ・投稿されたかが分からないときは重ねない、など）は、今も有効で、変えない。

- 制限に当たった指摘と、その提出の残りの指摘は、失敗として記録せずに、まだ返信していないまま残す。期限が明けたら、今の返信の処理（承認待ちの提出の、まだ返信していない指摘に返信する）が、もう一度返信する。
- 待ちは、ホストとアカウントごとに、次に試せる時刻と、連続して制限に当たった回数を持つ。ホームのディレクトリの下のファイル（`github-rate-limits.json`）に保存し、デーモンを起動し直しても失わない。
- 待つ時間は、GitHub が示した待ち（`retry-after` と `x-ratelimit-reset` の遅い方）と、制限が続くたびに倍にする待ち（1 分から。上限は 1 時間）の、長い方。GitHub が示した待ちは、1 日で頭打ちにする。
- 待ちの間は、そのアカウントで、指摘への返信を投稿しない（ほかのタスクの返信も）。返信を待つタスクは、実行待ちに出さない。タスクの状態は変えない。
- PR のレビューの子タスクは、PR を作ったタスクの返信が制限の待ちに入っているときは、返信を待たずにレビューを始める。
- やり直しは 5 回まで。超えて制限に当たったら、その提出の残りを、失敗として記録する。
- 時間切れ（GitHub が時間内に答えない）と制限が重なったときは、時間切れの扱い（残りを失敗として記録し、やり直さない）を優先する。
- 待っていること（`RemarkRepliesDeferred`）・待ちの後にやり直したこと（`RemarkRepliesPosted` の `retried`）・あきらめたこと（失敗の理由）を、作業履歴に残す。

## 理由

- 制限に当たった返信を記録せずに残す：返信を待っている指摘を求める今の作り（承認待ちの提出の、まだ返信していない指摘）と、目印で投稿済みの返信を見つける作りを、そのまま使える。やり直しのための待ち行列や、指摘ごとの状態を足さずに済む。待ちの間に、承認された・次の提出に変わった返信が、対象から外れることも、今の条件のまま決まる。
- 待ちをアカウントごとにファイルに持つ：制限はアカウントに掛かるので、同じアカウントで返信する、どのタスクにも効かせる必要がある。作業履歴はタスクごとなので、アカウントごとの値の置き場所にならない。
- 回数をアカウントごとに数える：制限が続いているかどうかは、アカウントの状態で、タスクごとに数えると、タスクの数だけ制限に当たりに行く。投稿が1件できたら、消す。
- 待ちの間、レビューの子タスクを待たせない：GitHub が示す待ちは、1 時間に及ぶことがある。その間、レビューを止めると、待ちの間もタスクを止めないという要求に反する。返信が渡らないままレビューが始まるのは、これまで（失敗として記録して進める）と同じ。
- 対象を、指摘への返信だけにする：人が決めた。ほかの投稿は、失敗の残し方・二重の投稿の防ぎ方がそれぞれ違い、同じ仕組みに通すには、それぞれの見直しが要る。

## 影響

- 制限に当たった返信は、期限が明けると投稿される。待ちの間に PR がマージされた・次の提出に変わった返信は、投稿されない（作業履歴には、待っていた記録だけが残る）。
- 制限が続くと、同じアカウントの返信は、最長で、やり直しの回数ぶんの待ちの後に、失敗として記録される。
- sacty のほかの投稿と、GitHub の読み取りは、この待ちを見ない（制限の間も、問い合わせる）。それぞれの今の扱い（レビューの対象の確認・レビューの投稿の、一時的な失敗の自動のやり直しなど）は、変わらない。
- ホームのディレクトリに、ファイルが 1 つ増える。
