# 承認ゲートで差し戻すときに、工程のイメージ・エージェントを一緒に変えられる

- 日時: 2026-10-28 14:17 UTC
- ステータス: 採用
- 関係する PR・タスク: #248
- 置き換え元: なし
- 置き換え先: なし

## 背景

タスクの作成のときは、進め方の工程ごとにイメージ・エージェントを選べる。一時停止したタスクの再開でも、まだ終わっていない工程の
イメージ・エージェントを一緒に変えられる（[一時停止したタスクの再開のときに、補足を足し、工程のイメージ・エージェントを一緒に変えられる](20261028-0342-resume-with-notes-and-step-settings.md)）。
一方、承認ゲートでの差し戻しには、この手段が無かった（その ADR の影響に書いたとおり）。

成果物の質が足りずに差し戻すとき、人は「やり直す工程だけ、より強いエージェントで」などと設定を変えてから差し戻したい（利用者の要望）。
タスクの詳細の「工程のイメージ」「工程のエージェント」で変えてから承認の画面に戻って差し戻すことはできたが、画面を行き来する必要があった。

## 決定

- 差し戻しの入力（`RequestChangesInput`）に、工程ごとのイメージ・エージェント（`images`・`agents`）を足す。
- デーモンは、タスクの詳細で変えるときと同じ確かめをして、`StepImageChanged`・`StepAgentChanged` を差し戻し（`ChangesRequested`）の前に、
  同じ書き込みで記録する。今と同じ名前は記録しない。1つでも誤りがあれば、差し戻しも含めて何も記録せずに断る。
  確かめと記録は、再開と共通にする（`stepSettingChanges`）。
- 同じ工程への差し戻しが上限に達してエスカレーションになるときも、工程の設定の変更は記録する。
- 承認では、工程の設定を受け付けない（承認の入力は変えない）。
- 画面の差し戻しのフォームに、工程のイメージ・エージェントの選択（折りたたみ）を置く。出すのは、選んでいるやり直す工程とそれより後の工程
  （飛ばした工程を除く）。候補は、折りたたみを開いたときに読む（タスクの作成のダイアログと同じ `/step-options`）。
  選択の表は再開の欄と共通にし（`StepChoiceTable`）、人が変えた工程だけを送る（`changedStepChoices`）。

## 理由

- 再開と同じ形（同じイベント・同じ書き込み・人が変えた工程だけを送る）にするのは、作業履歴・タスクの詳細の「選んだ元」の表示をそのまま
  使え、変更だけが記録されて差し戻しに失敗する（または逆）中途半端な状態を作らず、触っていない工程の古い名前で、その間の変更を
  黙って戻さないため。
- やり直す工程から後ろだけを出すのは、それより前の工程は差し戻しで実行し直さず、変えても効かないため。
- エスカレーションでも記録するのは、人が選んだ設定を黙って失わないため（設定の変更は、タスクの詳細と同じく、それだけでも意味がある）。
- 承認で受け付けないのは、利用者の要望が差し戻しであり、承認の入力（PR のマージで承認する工程もある）を広げると確かめる経路が増えるため。
  承認の後に変えたいときは、タスクの詳細で変えられる。
- 候補を開いたときに読むのは、承認の画面は一定の間隔でタスクだけを取り直す画面で、普段は設定を変えずに差し戻すので、
  そのたびにデーモンの状態を読まないため。

## 影響

- 承認の画面のフォームで、承認を押したときは、選んだ工程の設定を記録しない（画面のヒントに、差し戻すときだけ記録すると書く）。
- 仕様は [承認](../spec/approval.md) の「差し戻し」に書く。
