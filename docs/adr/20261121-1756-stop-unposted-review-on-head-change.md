# 投稿の前に PR の先頭が変わったレビューは打ち切って始め直し、親に届かなかった回の指摘は次の回で確かめ直す

- 日時: 2026-11-21 17:56 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-465
- 置き換え元: [古い head への AI のレビューを捨てたとき、その指摘を画面で人に届ける](20261103-0744-superseded-deliver-discarded-ai-review-to-person.md)（新しい head への AI のレビューのかけ直しをしない部分を、届かなかった回の指摘を次の回で確かめ直す形に置き換えた）
- 置き換え先: なし

## 背景

PR のレビューの実行中に PR の先頭が変わると、レビューは古い先頭宛てに投稿していた（投稿の記録に `latestCommit` を付ける）。
PR を作ったタスク（親）は、取り込むときに今の先頭と比べて、古い先頭宛ての AI のレビューを捨てる（[PBI-291](20261103-0744-superseded-deliver-discarded-ai-review-to-person.md)）。
そのため、次のことが起きていた。

- 実行の費用を払ったレビューの指摘が、親に届かずに捨てられる。捨てた指摘は画面に出るが、新しい先頭に当てはまるかは、人が判断するしかなかった。
- 次の回の再レビューは、範囲を前回の指摘の確認と前回以降の差分に絞る（[PBI-432](20261121-0400-rereview-narrowed-to-previous-findings-and-changes.md)）。届かなかった回の指摘が前回以降の差分の外にあると、どの回も見直さないまま残る。
- 届かなかった回も、同じ原因の要修正の回数（[PBI-424](20261121-0000-superseded-repeated-cause-must-explicit-and-cut.md)）と、提案だけの回の連続に数えていた。実装の担当は、届いていない指摘を直せないので、同じ原因が続いたように見えた。

## 決定

- 打ち切り：フォークでない PR の、投稿していないレビュー（1 回目を含む）は、PR の先頭が対象の先頭と違うと分かったら、投稿せずにその回を打ち切る。新しいイベント `ReviewRunStopped`（`reason: head_changed`）を記録する。
  - 見つけるのは、60 秒ごとの PR の確認（実行中・対象の確認中）と、投稿の直前の確認（投稿待ち）。一時停止中は打ち切らない。
  - 打ち切った回は、回の番号を進めず、その回の本文・回ごとの記録を消す。同じ先頭を 2 分見続けてから、新しい先頭で始め直す。打ち切りの回数と待つ時間に、上限は設けない。
  - フォークからの PR は、今までどおり古い先頭宛てに `latestCommit` を付けて投稿する（[PBI-461](20261121-1505-fork-pr-push-is-not-re-reviewed-automatically.md) の、PR のコードを人の判断なしに動かさない方針のため）。
- マージ・クローズ：取り込んだ PR のレビューのタスクを、実行中・対象の確認中・投稿待ちに PR のマージ・クローズで中止するときは、`ReviewRunStopped`（`reason: merged`・`closed`）を記録してから `TaskCancelled` を残す。止めた実行を失敗（`AgentRunFailed`・一時停止）に見せない。
- 費用：`ReviewRunStopped` は、`AgentRunCompleted` を記録していない、止めた実行の費用を持つ（費用を持つイベントの一覧に入れる）。
- 届かなかった回の判定：再レビューの対象を決めたときに、作業履歴の記録（親の `discardedReviews`・`importedFeedback`、その回の先頭と `latestCommit`）から決める。作業履歴に欄は足さない。GitHub の再依頼で作ったタスクの前回の回は、判定しない。
- 届かなかった回の数え方：同じ原因の `[要修正]` の回数にも、前回までの現れの一覧にも、提案だけの回の連続にも数えない。
- 届かなかった回の扱い：その回の指摘（提案を含む）は、PBI-432 の範囲の絞りの例外として、絞る回でも範囲の中に入れる。今回の先頭のコードで当てはまるかを確かめさせ、当てはまるものを今回の指摘として出させる。PBI-432 の ADR は置き換えず、絞りの決まりはそのまま残す。
- 変えないもの：親が古い先頭宛ての指摘を直しに取り込まないこと（`PullRequestReviewDiscarded` と画面の知らせは残る）。PBI-424 の、同じ原因の回数に作業履歴の欄・自動の止め方を足さない決定。先頭が変わらない再レビューの振る舞い。

## 理由

- 古い先頭宛ての本文は、投稿しても親に捨てられる。投稿せずに打ち切り、新しい先頭で始め直せば、費用を払ったレビューが親に届く。
- 打ち切った回を次の回に数えると、回の番号だけが進み、同じ原因の回数と前回の指摘の確認がずれる。番号を進めずに同じ回として始め直せば、数え方は変わらない。
- 落ち着くまで待つのは、push が続く間に打ち切りと始め直しを繰り返すと、費用が push の数だけ増えるため。待てば、費用は先頭の変化 1 回につき実行 1 回分までになり、push が止まれば始まるので、回数と時間に上限を設けなかった。
- 届かなかった回を作業履歴の欄で持つ案は採らなかった。親の記録とその回の先頭・`latestCommit` から決められるため。
- 届かなかった回の指摘を範囲に入れるのは、絞った再レビューが前回以降の差分の外を見ないので、入れないとどの回も見直さないため。渡す本文は、PR から読み直さず、そのタスクの作業履歴の `previousReview`・`earlierReviews` から取る。

## 影響

- 新しいイベント `ReviewRunStopped` が増える。前の版のデーモンは、このイベントを持つ作業履歴を読めず、そのタスクだけでなく、デーモンが起動できない。前の版に戻せるのは、最初の `ReviewRunStopped` を記録する前まで。記録した後に戻す手順は用意せず、新しい版で動かし続ける。
- push が続く PR では、レビューが始まるまで待つ。待ちの間は実行待ちのままで、作業履歴の `ReviewRunStopped` で待っていると分かる。
- フォークからの PR は打ち切らないので、古い先頭宛ての投稿が残る。
- 届かなかった回の指摘を確かめ直す分、次の回のレビューが少し重くなる。
