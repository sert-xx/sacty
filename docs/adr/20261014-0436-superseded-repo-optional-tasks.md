## 背景

タスクは作るときに対象リポジトリを1つ選ぶ前提で、API で省略できるのは対象がリポジトリ1つのときだけ（それ以外はエラー）だった。
タスクの開始時の clone・工程の作業領域・テストのコマンド・ベースブランチ・PR でのレビュー・統合レビューなど、多くの処理が
リポジトリを前提にしていた。タスクの対象リポジトリを任意にし、リポジトリの無いタスクの進め方を決める必要があった。

## 決定

- タスクの作成（画面・API）で対象リポジトリを任意にする。API の `repo: null` は常にリポジトリ無し、省略は対象がリポジトリ1つなら
  それ（今と同じ）、そうでなければリポジトリ無し。画面の空欄は `null` で送る。リポジトリ無しのタスクはイベントに明示する（`noRepo: true`）。
- リポジトリの無いタスクは、専用のオーケストレーターの指示に、プロジェクトの対象のリポジトリの一覧・コンテキストリポジトリ・規約・
  書き出しの接続先を渡し、進め方を選ばせる。選べる進め方は次のとおり。
  - 調査だけ、または新しい組み合わせ `design-only`（要求要件 → 設計。リポジトリの無いタスクだけが選べる）。リポジトリ無しのまま進め、
    PR でのレビューを使わずに画面で承認して完了する。PR・ブランチは作らない。
  - 分割。分割のエージェントが子タスクごとに対象からリポジトリと理由を付ける（子ごとに違ってよい）。統合レビューは子タスクのリポジトリごとに
    ベースブランチの最新を読む。
  - コードを変える組み合わせ（standard・skip-design・bugfix）。オーケストレーターが対象からリポジトリを選び、次の実行でそのリポジトリを用意して
    工程を選び直す（2段）。選べないときは止め、人がタスクの詳細で選んで再開できる。
  - レビューだけの組み合わせは選べない。
- オーケストレーター・分割案・人が選ぶリポジトリは、プロジェクトの対象に無ければ使わず、理由を記録して止める。
- 人がリポジトリを選べるのは、工程を決める前・リポジトリを用意する前で、止まっているタスクだけ。
- リポジトリの無いタスクでは、リポジトリを前提にした処理（clone・コードの写し・テストのコマンド・ベースブランチ・compose のサービス・
  PR でのレビュー・対象で指定したイメージ）を使わない。実装・再現・レビュー・PR 作成の工程は実行せずに止める。

## 理由

- 「省略」と「指定しない」を分けたのは、省略のときに今と同じ動作を保つため（PR の本文の「判断した点」）。
- コードを変えるタスクを2段にしたのは、テストのコマンドはコードを読まないと決められないため。チケットの取り込みと同じ流れにした（PR の本文）。
- 人がリポジトリを選べる時点を絞ったのは、オーケストレーターの選択とぶつけないため（PR の本文）。
- リポジトリの無いタスクで PR でのレビューを使わず画面で承認する理由は記録に無い。

## 影響

- タスクにリポジトリが無いことがあるので、リポジトリを前提にする新しい処理は、リポジトリの無いタスクでの扱いを決める必要がある。
- 対象リポジトリを選ぶ前の版で作ったタスク（`noRepo` の無いもの）は、今と同じく理由を示して止める。
- 一覧・詳細・作業履歴に、リポジトリの有無・選んだリポジトリと理由が出る。
