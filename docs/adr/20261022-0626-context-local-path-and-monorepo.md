# コンテキストに、ローカルのディレクトリの今の中身とモノレポの中のディレクトリを使えるようにし、extends に相対パスを足す

- 日時: 2026-10-22 06:26 UTC
- ステータス: 採用
- 関係する PR・タスク: なし（PR を作る前に書いた）
- 置き換え元: なし
- 置き換え先: なし

## 背景

コンテキストリポジトリの指定（`ContextSource`）は、`repo` に git の URL かローカルのパスを書けたが、ローカルのパスも `git clone` で取得していた。
そのため、ローカルのパスは git で管理し、変更をコミットしていなければ使えなかった。
画面の欄の例も SSH の URL だけで、git の URL しか書けないように見えていた。

また、リポジトリの中のディレクトリを指す方法が無く、コンテキストをモノレポの中に置くチームは、コンテキストだけのリポジトリを別に作るしかなかった。
`extends` もリポジトリの単位で、同じモノレポの中の共通のディレクトリを継承できなかった。

## 決定

- `ContextSource` に `path`（リポジトリの中のディレクトリ。根からの相対パスで、`.`・`..` の部分は書けない）を足す。画面のプロジェクトの設定に「ディレクトリ」の欄を足す。
- ローカルのパスは、絶対パスか `~/` で始まるものとする。相対パスは、デーモンのカレントディレクトリで指す先が変わるので、ローカルのパスとして扱わない（これまでどおり git に渡す）。
- ローカルのパスで `ref` が無ければ、git で取得せず、層のディレクトリを `.git` を除いて写して使う（今の中身）。コミットの代わりに、写した中身すべての SHA-256 を記録する。
  `ref` があれば、これまでどおり `git clone` する。
- `extends` に、次の2つの書き方を足す。
  - `./`・`../` で始まる相対パス：同じリポジトリ・同じ `ref` の中の、その層のディレクトリから見たディレクトリ。リポジトリの外は指せない。
  - `{ repo, ref, path }`：ほかのリポジトリの中のディレクトリ。
- 同じ合成の中で、同じ `repo#ref` は1回だけ取得し、中のディレクトリの違う層は同じ取得（同じコミット）を使う。
- git で取得した層は、ローカルのパスを `extends` に書けない（止める）。
- 層のディレクトリの途中にシンボリックリンクがあれば止める。
- 層の表し方を `<repo>//<path>#<ref>` にする（`path`・`ref` はあるときだけ）。作業履歴の層には `path` を足す。

## 理由

- ローカルのディレクトリを写して使うのは、手元で書きかけのコンテキストを、コミットせずにそのまま試せるようにするため。git で管理していない人も使える。
  写すのは、実行のあいだに元のディレクトリが変わっても、使う中身を変えないため。
  中身すべてのハッシュを記録するのは、どの中身で実行したかを作業履歴から区別するため。ホストの MCP サーバーの写しの使い回しも、中身が変われば別の写しになる。
- `ref` を書いたときは `git clone` のままにしたのは、ローカルの git のリポジトリの決まったコミットを使いたい人が、これまでどおり使えるようにするため。
- `path` と相対パスの `extends` を足したのは、モノレポの中に、チームごとのディレクトリと共通のディレクトリを置けるようにするため。
  相対パスは同じ取得の中を指すので、モノレポを何度も clone しない。
- 文字列の `extends` に `path` を書く書き方（`<URL>//<path>` など）にしなかったのは、`https://` などの URL の `//` と見分けにくいため。
  ほかのリポジトリの中のディレクトリは、紛れの無いオブジェクトで書く。
- git で取得した層からローカルのパスを継承させないのは、取得したリポジトリの中身を書き換えられる人が、ホストの任意のディレクトリ（規約・スキル・MCP サーバーの写しになる）を読ませられないようにするため。
  これまでも、git で取得した層からローカルのパスを `git clone` できたが、今回からはディレクトリの中身をそのまま読むので、止めることにした。
- 層のディレクトリの途中のシンボリックリンクを止めるのは、取得したリポジトリのリンクでホストのディレクトリを指させないため（[コンテキストではシンボリックリンクを扱わない](20261010-1203-reject-symlinks-in-context.md) と同じ考え）。

## 影響

- 互換性
  - ref の無いローカルのパスは、これまでの「コミットした中身」から「今の中身」に変わる。コミットの代わりに中身のハッシュを記録する。
  - `extends` に `./`・`../` で始まる値を書いていたコンテキストは、デーモンのカレントディレクトリからではなく、その層のディレクトリから解決するようになる。
  - git で取得した層の `extends` にローカルのパスを書いていたコンテキストは、止まるようになる。
  - 層を表す文字列（誤りの文・警告の `from`・規約の区切りのコメント）から、`ref` の無いときの末尾の `#` が無くなる。
- 書き出したプロジェクトの定義（エクスポート）に `context.path` が入る。`path` を書いた定義は、`path` を知らない版の sacty ではインポートできない。
