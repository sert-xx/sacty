# 取り込むラベルとレビュー用のラベルに同じ名前を許す

- 日時: 2026-10-15 08:50 UTC
- ステータス: 採用
- 関係する PR・タスク: #113、PBI-104
- 置き換え元: [取り込みを「Issue の取り込み」と「PR のレビューの取り込み」に分け、sacty の PR にはレビュー用のラベルを付ける](20261015-0240-superseded-split-issue-and-pr-review-intake.md)
- 置き換え先: なし

## 背景

PBI-99 で、取り込むラベル（`intakeLabel`）とレビュー用のラベル（`reviewLabel`）に同じ名前（大文字・小文字を区別しない）を、
保存のときに拒否するようにした（`input.sameIntakeAndReviewLabel`）。2つの取り込みをラベルで分けるという、設定の意味を単純に保つためだった。

ステークホルダーは、Issue と PR に同じラベル（例 `sacty`）を付けて取り込ませたい（ラベルを1つ覚えるだけで済むように。2026-10-15）。
Issue の取り込みは `is:issue`、PR のレビューの取り込みは `is:pr` で検索するので、検索の条件はもう分かれている。

## 決定

- 2つのラベルに同じ名前（大文字・小文字だけが違う名前も）を保存できるようにする。保存のときの検査と文言
  （`input.sameIntakeAndReviewLabel`。日本語・英語）を消す。保存は、読み込みと同じ `SactySettings` で検査する。
- 取り込みの振る舞いは変えない。同じ名前のとき、Issue は通常のタスク、PR はレビューだけのタスクにする。sacty が作った PR
  （レビュー用のラベル＝取り込むラベルが付く）は、`source.review: sacty` のレビューだけのタスクとして1回だけ取り込み、その指摘は
  元のタスクに PR の指摘として届ける。
- PBI-99 の ADR のほかの決定（取り込みを2つに分けること、sacty の PR にレビュー用のラベルを付けることなど）は、そのまま。

## 理由

- 取り込むラベルは Issue だけを、レビュー用のラベルは PR だけを取り込むので、同じ名前でも Issue と PR が入れ替わらない。検索の条件で
  分かれるうえ、取り込みの判定でも、PR は取り込むラベルで通常のタスクにせず、Issue はレビュー用のラベルでレビューのタスクにしない。
  同じ Issue・PR は二度取り込まない。PBI-99 の ADR の理由にも、同じ名前を許しても動くことは書いてあった。
- PBI-99 で拒否した理由（どちらの設定で取り込まれたかが画面からわかりにくい）は、画面の説明で、同じ名前にできることと、Issue と PR が
  それぞれどちらで取り込まれるかを書くことで補う。
- 拒否を残して、別の名前を使うよう案内する案は、ステークホルダーの要求に合わないので採らなかった。

## 影響

- 同じ名前で保存した設定でも、Issue の取り込み・PR のレビューの取り込み・sacty の PR のレビューは、今までどおりに動く。
- 以前の版で同じ名前を保存していた設定も、そのまま保存し直せる。
