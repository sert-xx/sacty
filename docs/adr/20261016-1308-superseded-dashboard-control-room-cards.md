# ダッシュボードを工場の管制室にし、人の出番・工場の健康・お金・品質の欄の定義と集計の置き場所を決める

- 日時: 2026-10-16 13:08 UTC
- ステータス: 置き換え済み（superseded）
- 関係する PR・タスク: PBI-118
- 置き換え元: なし
- 置き換え先: [費用は概算だけを出し、工程の組み合わせごとに予算を決められるようにする](20261021-1351-estimate-only-costs-and-per-plan-budget.md)（費用の欄で実請求と概算を分けて出す部分）

## 背景

ダッシュボード（PBI-114）は「終わっていないタスク」の欄だけだった。sacty の思想は「人間は承認ゲートでだけ判断し、取り込みから PR・
マージの後の監視まで AI が進める工場」なので、ダッシュボードは工場の管制室として、自分が判断すべきもの・止まっているもの・お金・
工場の調子を一目で見て、個別のタスクを開く前に手を打てる画面にしたい（ステークホルダー、2026-10-16）。載せるのは「人の出番」
「工場の健康」「お金」「品質」の 4 つに絞り、個別タスクの中身や、人を測る指標は載せない。

制約：画面は3秒ごとにデータを取り直す（PBI-108）。完了したタスクを含む全件は成果物の大きさで数十〜数百 MB になるため、集計のために
タスクの全件や作業履歴を3秒ごとに運べない（PBI-114 のレビュー指摘）。画面の文章は本文と補足に分ける（PBI-117）。

## 決定

- 欄は 8 つ（既存の「終わっていないタスク」を含む）で、並びは、あなたの出番 → 止まっているタスクの理由 → 終わっていないタスク →
  費用と予算 → 工程の待ち行列 → 取り込みの状況 → 流量 → 品質の信号。すべての欄がすべてのプロジェクトをまたぎ、消したプロジェクトの
  タスクは出さず、数えない。
- 数字の定義：
  - あなたの出番は、状態の表示が人の出番のタスク（承認待ち・一時停止・エスカレーション。承認待ちでもゴールガーディアンが PR の指摘を
    判断している間は除く）。待ち始めは、その状態になった作業履歴の記録（提出・一時停止・エスカレーション・再現できなかった確認）の最後の時刻。記録が無ければ
    `updatedAt`。
  - 止まっている理由は、一時停止のタスクを `pausedReason` で分け、件数 0 の理由は出さない。利用上限・認証は目立たせる。件数を押すと、
    その理由のタスクを欄の中で広げる（一覧へ移らない）。
  - 費用は、費用を持つイベント（`CHARGED_EVENT_TYPES`）の費用を、その記録の時刻で今日・直近7日に入れる。実請求と概算は分けて出す。
    予算に近いタスクは、終わっていないタスクのうち使用済みが上限の 80% 以上のもの。
  - 流量は、タスクが終わった（`isFinished` が偽から真になった）記録の時刻で、完了・中止を数える。中央値は、その期間に完了した
    タスクの作成から完了までの時間。
  - 品質の信号は、差し戻し（`ChangesRequested` を 1 回として数え、PR の指摘でゴールガーディアンが戻したもの＝`prRework` と、人の
    差し戻しに分ける。判断 `ReworkJudged` だけでは数えない）、`GuardianMissed`、`IntegrationReviewed`（不合格）、`DeploymentFixRegistered`
    の回数。工程ごとの差し戻しは、差し戻された成果物の工程（承認ゲートの工程）で数える。
  - 待ち行列は、ワーカーが処理しているタスク（`inflight`）/ 同時に実行する数の上限と、ワーカーの処理の対象でまだ処理していないタスク
    （`queuedTaskIds`）。実行待ちが上限より多い状態が 10 分続いたら目立たせる。始まりは、状態・実行・設定・プロジェクトが変わるたびに
    デーモンが更新する（画面の取得には依らない）。
  - 期間の境は、画面の言語ではなく、sacty を動かしているマシン（デーモン）のローカルの日付。今日を含む 7 日・30 日。
- 集計の置き場所：作業履歴を要する集計（対応待ちの時刻・費用・流量・品質・待ち行列）は、デーモンが作業履歴を畳み込んで持ち
  （`DashboardStats`。起動のときの読み込みと、書き足すときに 1 イベントずつ）、軽い API（`GET /api/dashboard`）で返す。タスクの状態から
  作れるもの（あなたの出番の行・止まっている理由・予算に近いタスク）は、画面のサーバーが既存の `GET /api/tasks?open=1` から作る。
  既存の経路は重くしない。
- 画面は、本文を「いま何が起きているか・次に何をするか」だけにし、数字の定義・期間の境・仕組みは見出しの横の補足に書く。
  待っている時間は、データに「今」を入れず、画面の時計で計算する。

## 理由

- 集計をデーモンに置いたのは、画面のサーバーがタスクの全件や作業履歴を3秒ごとに読む経路を作らないため。畳み込みにしたのは、
  作業履歴が増えても集計の時間が増えないようにするため（持つのは直近の記録だけ）。
- 期間の境をデーモンのローカルの日付にしたのは、費用や件数の「今日」が、画面を見る人の言語や端末の設定で変わらないようにするため
  （ステークホルダーの指示）。タイムゾーンは補足に出す。
- 止まっている理由をタスクの一覧へ移さず欄の中で広げたのは、一覧に理由の絞り込みが無く、ダッシュボードから離れずに手を打てるため。
- 待っている時間を画面の時計で計算するのは、データに「今」を入れると取り直しのたびに版が変わり、変わっていない欄まで描き直すため。
- 「続いている」を 10 分にしたのは、取り込みで一度に増えた直後の一時的な待ちを、設定の変更の合図にしないため。値は推測で決めた目安。
- グラフは載せない（数字と一覧で足りる。要れば次の PBI。PO）。

## 影響

- デーモンの API に `GET /api/dashboard` が増える。`project` に、イベントを適用するごとに呼ぶ `applied` が増える。
- 取り込みの状況の表示を、プロジェクトの一覧とダッシュボードで共通の部品（`IntakeStatusView`）にした。
- 仕様：[アーキテクチャ](../spec/architecture.md)（画面の構成・ダッシュボードの集計・取り直し）、[作業履歴](../spec/event-log.md)（投影）。
  利用者向け：[ダッシュボード](../user/dashboard.md)。
- 「続いている」の始まりはメモリーだけに持つので、デーモンを再起動すると数え直す。
