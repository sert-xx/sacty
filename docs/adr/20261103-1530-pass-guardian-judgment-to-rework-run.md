# ゴールガーディアンの判断文を、その判断で始まった作り直しの実行に渡す

- 日時: 2026-11-03 15:30 UTC
- ステータス: 採用
- 関係する PR・タスク: #299、PBI-300
- 置き換え元: なし
- 置き換え先: なし

## 背景

人の PR の指摘を取り込むと、ゴールガーディアンが戻し先と、指摘をどう読んだかの判断文を出す。この判断文は作業履歴と PR の欄にだけ残り、作り直しの実行の指示には入っていなかった。
実験（F45。S14 の4回目）で、判断文が戻す行の ID まで挙げていたのに、実行は自力で指摘を読み直し、一部で判断と食い違った。戻し先を判断できなかった回では、実行が理由を知らずに「変更が必要な相違を確認できない」としてコードを変えず、最終レビューが未対応で不合格にして、もう1回やり直した。

## 決定

- 判断で差し戻した回の指摘で始まった作り直しの実行（要求要件・設計・実装のどれでも）の指示に、判断文を渡す。
- 判断文はゴールガーディアンの解釈であり、人の指摘そのものではないと指示に書く。人の指摘の原文は今までどおり渡し、食い違うときは原文（人間の指摘を最優先）に従わせる。
- 戻し先を判断できなかったときも、判断できなかった理由を渡す。読み取れなかった点を推測で大きく変えず、最小限の変更にとどめ、「変更が要らない」と結論するのは満たしていると根拠で示せるときだけにし、読み取れなかった点を指摘への対応に書かせる。
- 判断文は外から来た文字列として、秘密情報を伏せ、長さを切り、指示とは分けた JSON のデータで渡す。
- 判断が無い実行（最初の実行、最終レビューの不合格・上流の変更によるやり直し、人が画面から差し戻した回）の指示は変えない。ゴールガーディアンの実行が失敗した・出力を読めなかったときの sacty の文言は、指摘の読み方ではないので渡さない。

## 理由

- 判断文は、作り直しの実行が持たない情報（承認済みの成果物と指摘を照らした結果、どの行を指すか、何が読み取れなかったか）を含む。渡さないと、実行が同じ読み直しを高い費用で繰り返す。
- 解釈であることを示し、原文を優先させるのは、判断が誤っていたときに、誤った読みが人の意図として固まらないようにするため。
- 判断した回と指摘の ID を投影に残し（`prRework.round`・`remarkIds`）、判断した指摘の集合そのもので始まる実行にだけ渡すのは、最終レビューの不合格などで古い判断を新しい要求として渡さないためと、判断の後に人が無効にした指摘を解釈した判断文が実行に戻らないため。

## 影響

- 判断できなかった回でも、実行は理由を見て最小限の対応をし、読み取れなかった点を対応欄に残す。人が確かめやすくなる一方、判断文が誤っていると実行が引きずられうる（原文を優先させて抑える）。
- 判断文の分だけ指示が長くなる（上限3,000文字）。
- 仕様書は[承認と差し戻し](../spec/approval.md#pr-の指摘の取り込み)に、利用者向けは[タスクを進める](../user/tasks.md)に記す。
