# ブラウザで認証する MCP サーバーは、ゲートウェイがホストで起動して持ち続け、期限の前に起動し直して、HTTP の MCP として中継する

- 日時: 2026-10-12 13:27 UTC
- ステータス: 採用
- 関係する PR・タスク: #43、PBI-36
- 置き換え元: なし
- 置き換え先: なし

## 背景

利用者の環境で使う MCP サーバーの中に、手元で起動するコマンドで、起動時にブラウザで認証するものがある。コンテナの中ではブラウザを
開けない。認証には数時間の有効期限があり、期限が切れたときの MCP サーバーの振る舞いはわからなかった。

## 決定

- config.yaml の `gateway.mcp_servers` に、ホストで動かす MCP サーバー（コマンド・引数・環境変数。秘密情報は名前か 1Password の参照）と、
  起動し直す間隔（`restart_every_min`）・準備を待つ上限（`ready_timeout_sec`）を書く。
- ゲートウェイがホストで起動し（起動時のブラウザの認証はホストのブラウザで行える）、MCP の初期化（認証の完了）を待つ。公式の SDK
  （`@modelcontextprotocol/sdk` 1.30.1）の stdio のクライアントでつなぎ、HTTP 側はリクエストごとに中継のサーバー（ツール・リソース・プロンプト）を
  作って JSON で返す。
- どの振る舞いでも扱えるよう、期限が切れた（切れそうな）ら sacty が自動で起動し直して再認証する。人の操作は待たない。
  - 設定した間隔で、期限の前に起動し直す。新しいプロセスの準備ができてから切り替え、古いプロセスは途中の呼び出しが終わってから（上限5分）止める。
  - プロセスが終わった・ツールが認証エラーらしい結果や例外（401・unauthorized・token expired・login required など）を返したときも起動し直す。
    認証エラーの呼び出しには、再認証しているので少し後にやり直すよう添えて返す。認証が切れた接続は、準備ができるまで新しい呼び出しに使わない。
    起動し直すのはその接続で1回だけ。引数の誤りなどの例外では起動し直さない。
  - 起動の途中で設定が変わったら、終わった後に新しい設定で起動し直す。
- 起動し直しても準備ができないときは、どの MCP サーバーかと理由をタスクの一覧の警告（#42 の warnings）に出し、1分ごとに起動し直す。
  その間の呼び出しには、準備ができていないこと（503）を返す。
- 工程エージェントには、コンテキストの MCP に `<ゲートウェイ>/mcp/<名前>` の HTTP の MCP を加え、認証のヘッダーには実行ごとのトークン
  （実行するときに sacty が入れる）だけを入れる。Claude Code・Codex のどちらにも渡す。
- ツールの呼び出しを待つ上限は、SDK の既定の 60 秒から 10 分にする（進み具合の知らせがあれば数え直す）。
- 起動の失敗の理由は、標準エラーを十分な長さ持っておき、環境変数に入れた秘密情報を伏せてから末尾を添え、長さを切り詰める。

## 理由

- 期限が切れたときの振る舞いがわからないので、どの振る舞いでも扱えるようにし、期限の前に自動で起動し直すことはステークホルダーが決めた。
  ブラウザ側の承認は自動化されているので、人の操作は待たない（PR の本文）。
- 準備ができてから切り替えること・公式の SDK で中継することは PO が決めた（PR の本文）。公式の SDK を選んだ理由は記録に無い
  （版は2週間以上前のものを選んだ）。
- 古いプロセスを途中の呼び出しの後に止めるのは、すぐ止めると使っている途中の呼び出しが切れ、その失敗でもう一度起動し直していたため（コミットのメッセージ）。
- 認証が切れた接続を使わないのは、再認証に失敗しても期限切れの接続に転送し続け、準備ができない間に 503 を返せず、呼び出しのたびに
  1分の間隔を待たずにブラウザの認証を繰り返していたため（レビュー）。
- 例外として返る認証エラーでも起動し直すのは、認証切れを JSON-RPC のエラー（例 `-32001 "401 Unauthorized: token expired"`）で返す
  MCP サーバーで再認証しなくなっていたため（レビュー）。
- 起動の失敗の理由から秘密情報を伏せるのは、MCP サーバーが認証の失敗で秘密情報を標準エラーに出すと、ログ・画面・エージェントへの 503 に
  そのまま出て、ホストだけの認証情報がエージェントにも渡っていたため（レビュー）。

## 影響

- 間隔は、認証の期限より短く書く必要がある。
- MCP サーバーの秘密情報は、ホストのプロセスの環境変数にだけ入り、エージェントのコンテナには渡らない。
