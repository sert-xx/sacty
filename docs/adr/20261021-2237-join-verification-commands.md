# 実行する検証が複数あれば、オーケストレーターに && でつないで1つのテストのコマンドにさせる

- 日時: 2026-10-21 22:37 UTC
- ステータス: 採用
- 関係する PR・タスク: #190
- 置き換え元: なし
- 置き換え先: なし

## 背景

オーケストレーターが決めるテスト（検証）のコマンド（`StepsChosen` の `testCommand`）は、文字列1つ（1〜1000 文字）で、ゴールガーディアンが
最終レビューの中で実行し、終了コード 0 のときだけ合格にする。オーケストレーターへの指示は「テスト（検証）を実行するコマンド
（例：`npm ci && npm test`）」だけで、テストの種類が複数ある・テストのほかに lint やマニフェストの検証もある、といったリポジトリで、
すべてをつなぐのか代表を1つ選ぶのかを決めていなかった。代表だけを選ぶと、CI が実行している検証の一部を確かめないまま合格になりうる。

## 決定

- オーケストレーターへの指示で、実行する検証が複数あるなら、CI・Makefile などが実行しているものをすべて `&&` でつないで1つの
  `testCommand` にさせる。`;` ではつながせず、代表の1つだけを選ばせない。
- `testCommand` の形（文字列1つ・1〜1000 文字）と、ゴールガーディアンの申告（終了コードと抜粋の1組）は変えない。

## 理由

- 指示を足すだけで、イベントの形・最終レビュー・再現・画面を変えずに、検証の漏れを防げる。まずこれで様子を見る、という利用者の判断による。
- `;` でつなぐと、終了コードが最後の検証のものだけになり、前の検証の失敗が合否に効かなくなるため。
- `testCommand` を配列にし、コマンドごとに実行・申告させる案も検討した。どの検証が通りどれが確かめられていないかが分かるが、
  イベントのスキーマ・プロンプトと読み取り・`missingCommands` の照合・画面と PR の本文まで変えることになるので、今は採らなかった。

## 影響

- `&&` は最初の失敗で止まるので、後ろの検証は実行されず、結果から確かめていない検証が分からない（不合格にはなる）。
  やり直しの指示に渡る情報はその分だけ少ない。
- つないだコマンドが 1000 文字を超えると記録できない。
- 仕様は [タスクと工程](../spec/tasks-and-steps.md)。
