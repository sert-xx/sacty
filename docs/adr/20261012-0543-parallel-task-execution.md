# 実行待ちのタスクを、sacty の設定で決めた上限（1〜10、既定 3）まで同時に実行する

- 日時: 2026-10-12 05:43 UTC
- ステータス: 採用
- 関係する PR・タスク: #36、PBI-30
- 置き換え元: [大きなタスクを「タスク分割」の工程で子タスクに分け、子ごとに PR を作って依存の順に進める](20261012-0226-superseded-task-split-into-subtasks.md)（子タスクを1件ずつ実行する部分）
- 置き換え先: なし

## 背景

ワーカーは実行待ちのタスクを1件ずつ実行していた。#33 でタスク分割を足したときも、子タスクは依存の順に1件ずつ実行し、
並行の実行は別のタスクに回していた。

## 決定

- 子タスクに限らず、実行待ちのすべてのタスクを、上限の数まで同時に実行する。巡回ごとに、実行中の数が上限に達するまで、
  実行待ちのタスクを古い順に始める。同じタスクは重ねて始めない（工程を選んでいる間など、状態が実行待ちのままの間も）。
- 上限は「sacty の設定」画面で 1〜10 の整数で決める（`SactySettings.maxParallelTasks`）。空なら 3。次の巡回から効く。
- 実行中のタスクは、処理の流れごと（`AsyncLocalStorage`）に覚える。一時停止・中止はそのタスクのコンテナだけを止める。
  デーモンを止めるときは、実行中のすべての処理を待つ。
- 依存の無い子タスクは同時に、依存のある子タスクは依存先を待つ（これまでどおり）。

## 理由

- 実行中のタスクを1つの変数で持つのをやめ、処理の流れごとにしたのは、コンテナを正しいタスクの実行として覚え、一時停止・中止が
  そのタスクのコンテナだけを止めるようにするため（PR の本文）。
- すべてのタスクを対象にすること、上限の範囲と既定を 3 にしたことの理由は記録に無い。

## 影響

- Codex のサブスクリプション（`auth.json`）で同時に実行すると、トークンの更新が重なるおそれがある（書き戻しは、ホストのファイルが
  変わっていれば上書きしない既存の仕組みのまま）。必要なら上限を 1 にする。
- 上限を下げても、実行中のタスクは続け、新しく始めるのを抑える。
