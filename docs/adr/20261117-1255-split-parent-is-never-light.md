# 子タスクに分けて進めるタスクは、依頼が軽いと判定しない

- 日時: 2026-11-17 12:55 UTC
- ステータス: 採用
- 関係する PR・タスク: #423、PBI-387
- 置き換え元: なし
- 置き換え先: なし

## 背景

[依頼が軽いときは、自己レビューの観点を絞る](20261117-0359-superseded-narrow-self-review-for-light-requests.md)決定では、軽いかどうかを、工程を選ぶ時点でオーケストレーターが判定し、その答えをそのまま記録する。
sacty が、答えにかかわらず軽いとしないのは、セキュリティ対応のタスクだけだった。依頼や差分の中身と照らす確認は無い。

見直しのレビューで、判定がエージェントの答えだけに頼っていることが挙がった。
依頼の文に、判定を誘導する文が入りうる（外から取り込んだ依頼など）。誘導が実際に通るかは、確かめていない。
残っている歯止めは、工程のエージェントが作業中に気づいて通常に戻すこと、画面の判定と理由の表示、人の上書き、観点を絞らない PR のレビュー。

## 決定

リポジトリの持ち主が、2026-11-17 に次のとおりに決めた。

- 子タスクに分けて進めるタスク（分割の親）は、オーケストレーターが軽いと答えても、通常の深さにする。
- ほかは、今のまま（軽いとしない組み合わせを、これ以上は足さない）。

実装で決めたこと（持ち主の確認は、この ADR を書いた時点ではまだ）。

- 「分割の親」は、工程を選ぶ時点で、選んだ組み合わせが `split`（要求要件 → 設計 → タスク分割 → 統合レビュー）であることで見分ける。セキュリティ対応（`security-fix`）と同じ所（工程の選択の答えを記録する所）で、同じ形で通常にする。
- 記録・画面・人の上書き・選び直しの扱いは、セキュリティ対応のタスクと同じにする。
  - 判定は通常として記録し、理由に、sacty が通常にしたことと、オーケストレーターの理由を残す。文言は、セキュリティ対応のものとは別にする（どの決まりで通常にしたかが、画面で分かるように）。
  - 通常として記録するので、人が軽くする操作は出ない（軽いと判定されたタスクだけが、上書きの対象）。
  - 工程の選択からやり直すと、判定を選び直す。選び直した組み合わせが `split` でなければ、答えのとおりに記録する。
- 子タスクは、今までどおり、子ごとに判定する（子タスクは `split` を選べず、子ごとに工程を選ぶ）。
- 工程の選択の指示にも、`split` を選ぶときは通常と答えるように書いた（セキュリティ対応と同じ扱い）。sacty の決まりは、答えにかかわらず効く。

## 理由

- 持ち主が、選択式の問いに「分割するタスクは軽いとしない」と答えた。選んだ理由は、聞いていない。
- 外から取り込んだ依頼を軽いとしない案、提出のときに差分の場所で通常に戻す案もあったが、選ばれなかった。
- `split` の組み合わせで見分けるのは、分割の親になるのが、この組み合わせを選んだタスクだけのため。

## 影響

- 分割の親の、要求要件・設計の工程の自己レビューは、常に通常の観点で動く。費用は、軽いと判定されたときより増える。
- この決定より前に、軽いと記録された分割の親は、記録のまま（軽いまま）。人が「通常の深さで」と上書きできる。
- 判定がエージェントの答えに頼ることは、ほかの組み合わせでは変わらない。
