# 差分と無関係で実行し直すと結果が変わる失敗を、実装に戻さない

- 日時: 2026-11-06 11:30 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-310、#316
- 置き換え元: なし
- 置き換え先: なし

## 背景

環境による失敗は「変更を外した起点でも同じように失敗する」ことを条件にして、不合格にしない。不安定なテストは起点では通るので、この条件を満たせず、「確かめられない失敗」として実装に戻されていた。UI のテストは特に不安定になりやすく、実装で直らない失敗で、実装と最終レビューを繰り返す原因になる。

## 決定

- ゴールガーディアンが失敗したテストだけを実行し直し、結果が変わり、差分と関係が無いと確かめられた失敗を `tests.flakyFailures` に申告する。
- sacty が機械で確かめられること（実行し直しの回数・通った回数・テストのファイルが差分に無いこと・全件を説明できること）を確かめ、1件でも認めなければ、テストは通っていないものとする。
- 認めた失敗は、人が確かめることに必ず出す。
- 認めなかった申告があれば、ほかの理由（ツール不足など）より優先して不合格にする。
- CI で失敗したテストの申告は、作業領域のテストが通っていても同じ条件で確かめて残す。
- 実行し直しは sacty でなくゴールガーディアンが行う。sacty はテストを別のコンテナで実行しない方針を変えない。

## 理由

- 低い確率で落ちる本物のバグは、不安定なテストに見える。差分で変えたテストのファイルは機械で除き、差分で変えたコードを通るテストは指示で除き、認めたものは人の目に残す。
- 1件でも認めなければ全部を認めないのは、本当の失敗が残っている恐れがあるのに、環境の申告や他の不安定な失敗に紛れて通らないようにするため。

## 影響

- 「差分で変えたコードを通るか」は機械で確かめられず、ゴールガーディアンの判断に頼る。見逃すと、変更が持ち込んだレース条件を人の確認に回してしまう。
- テストの実行し直しの分だけ、最終レビューの時間が延びる。
