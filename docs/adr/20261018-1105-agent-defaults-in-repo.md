# エージェントの既定をリポジトリに持ち、config.yaml は接続先と単価だけにする

- 日時: 2026-10-18 11:05 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-134
- 置き換え元: なし
- 置き換え先: なし

## 背景

段階（lite〜ultimate）のエージェントのモデルとリーズニングエフォートは、利用者が `config.yaml` の `agents` に書いていた。設定を見直さない
利用者は古いモデルを使い続け、sacty の評価が下がる。sacty として推奨するモデルの組み合わせを、sacty の更新で利用者に届けたい。

## 決定

- エージェントの既定（10 の段階のエージェントと、既定の工程の AI）を、リポジトリの `config/agents.yaml` に持つ。`config.yaml` の `agents` は
  任意で、書いたときは同じ名前を項目ごとに上書きする（名前を足すこともできる）。
- 接続先は runtime ごとに 1 つ（`providers.codex`・`providers.claude`）。認証・ゲートウェイはここに書き、エージェントには書かない。
- 単価は、契約で変わるのでリポジトリに持たず、接続先の `available_models` にモデルごとに書く。エージェントの単価は、モデルの単価を引く。
- 単価の無いモデル・接続先の無い runtime のエージェントは、使えない扱いにして警告する（誤りにしない）。sacty の更新で既定のモデルが変わっても、
  設定が読めなくならないようにするため。使えないエージェントを工程の AI などに指定したときだけ誤りにする。
- 今までの書き方（エージェントの `auth`・`provider`・`via_gateway`・`price_per_mtok_usd`、名前を付けた接続先）は、読み替えずに誤りにして、
  直し方を示す（ステークホルダーが破壊的変更を了承）。

## 検討した案

- **単価もリポジトリに持つ**：設定がさらに短くなるが、Bedrock・組織の gateway など契約で単価が違い、費用の計算を誤る。
- **単価の無いモデルを誤りにする**：単価の見直しを促せるが、sacty を更新しただけで設定が読めなくなり、工程が止まる。
- **今までの書き方を当面は読み替える**：移行は楽だが、二つの書き方を持ち続けることになる。利用者が少ないうちに切り替える。

## 結果

- `providers` と単価だけを書けば、sacty が推奨する段階のエージェントで動く。sacty を更新すれば、新しいモデルが使われる（単価が無ければ警告）。
- 今の形式の `config.yaml` は読めなくなる。画面の警告に従って書き直す必要がある。
