# GitHub のホストを固定せず、リポジトリ・Org をホストを含めた URL で表し、アカウントをホストごとに選ぶ

- 日時: 2026-10-13 00:03 UTC
- ステータス: 採用
- 関係する PR・タスク: #46、PBI-40
- 置き換え元: なし
- 置き換え先: なし

## 背景

sacty は GitHub のホストを github.com に固定し、対象のリポジトリを `owner/name` の短縮表記で書いていた。利用する環境では、
セルフホストの GitHub Enterprise Server（GHE）2つと github.com を同時に使う。

## 決定

- 対象・リポジトリ・Org は、github.com も含めて、ホストを含めた URL で書く。`owner/name` の短縮表記はやめる。
- gh にログインしているすべてのホストのアカウントを読み、プロジェクトの設定ではホストごとにアカウントを選ぶ（`githubAccounts`：ホスト → アカウント）。
- API・clone・プッシュ・PR の作成・マージの見守り・フィードバックの取り込み・レビューの投稿・Issue へのコメント・中止の片付け・取り込みの検索は、
  リポジトリのホストとそのホストのアカウントで行う。API は、github.com なら `api.github.com`、GHE なら `https://<ホスト>/api/v3`。
- 同じ owner/name が別のホストにあっても、別のリポジトリとして扱う（重複・担当・取り込みの二重の判定にホストを含める）。
  検索の結果は、検索したホストのものだけを受け付ける。
- アカウントを選ぶホストには、対象のホストに加えて、コンテキストリポジトリ（HTTPS）のホストと保存済みのホストも含める。
  対象ではないホストは「選ばない（ホストの git の認証を使う）」も選べる。
- プロジェクトのエクスポートの版を 3 に上げる。`owner/name` で登録したプロジェクト・作業履歴との互換は持たせない。

## 理由

- 利用する環境で、GHE 2つと github.com を同時に使うため（PR の本文）。
- 互換を持たせないのは、まだ本格的に使っていないため（PR の本文）。
- コンテキストリポジトリのホストと保存済みのホストもアカウントの候補に含めたのは、レビューの指摘による。対象のホストだけに絞ると、
  対象が GHE・コンテキストが github.com の構成で github.com のアカウントを選べず、画面で保存すると既存の設定が落ちて、
  コンテキストの clone が選んだアカウントを使えなかった（レビューとその返信）。

## 影響

- これまで `owner/name` で登録したプロジェクト・作業履歴は読めない。エラーになる場合は `~/.sacty` のデータを消して作り直す。
- 画面の対象の入力は URL になり、GitHub アカウントはホストごとに選ぶ。
- リポジトリ名の検査は Org 名と分け、先頭がドット・アンダースコアの名前（`.github` など）も受け付ける（`.` と `..` は除く。レビューの指摘で直した）。
