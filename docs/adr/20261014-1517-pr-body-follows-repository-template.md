# sacty が作る PR の本文を、リポジトリ・Org の PR テンプレートの見出しに沿って決まった規則で埋める

- 日時: 2026-10-14 15:17 UTC
- ステータス: 採用
- 関係する PR・タスク: #99、PBI-87
- 置き換え元: なし
- 置き換え先: なし

## 背景

sacty が作る PR（実装の PR と、要求要件・設計の PR）の本文は sacty の決まった形で、対象のリポジトリや Org が用意した
PR テンプレートに沿っていなかった。チームのレビューの流儀（見出し・チェックリスト）に合わせたい、という要望があった。
決める必要があったのは、テンプレートの探し方（複数のテンプレート・Org の `.github` の扱いを含む）、埋め方（エージェントを使うか）、
sacty が本文に必要とする情報（タスクの ID・`Closes`・承認の仕方）をどう守るか、失敗したときの扱い。

## 決定

- PR を作る・更新するたびに、GitHub と同じ場所（`.github/`・ルート・`docs/` の `pull_request_template.md`。大文字・小文字は
  区別しない）を、対象のリポジトリ → Org（またはユーザー）の公開の `.github` リポジトリの順に探す。1つのファイルが無ければ、
  `PULL_REQUEST_TEMPLATE/` の中の `.md` のうち名前の順で最初のものを使う。
- 埋めるのにエージェントは使わない。見出しの文から種類（目的・変更・テスト・関係する Issue・書けないもの）を決まった規則で決め、
  sacty が持っている内容を入れる。説明・例の文は消し、コメントとチェックボックスは残し、チェックボックスはすべて外す。
  埋められない見出しは「該当なし」にする。
- タスクの ID・成果物チェックの案内・マージが承認になること・`Closes` は、テンプレートに従っても必ず残す（本文の最後に置く・
  見出しに入らなければ最後の部分の前に出す）。見出しに入らない sacty の記録は、末尾の折りたたみに置く。
- テンプレートが無い・使えない（取得の失敗・権限・時間切れ・大きすぎる・空・UTF-8 でない）ときは、今の決まった形の本文で PR を作る。
  どちらにしたか（使ったテンプレートの場所・理由）を PR の記録（`PullRequestPublished`・`StepPullRequestPublished` の `template`）に
  残し、タスクの画面に出す。
- 本文は 65,000 文字までにし、超えるときは最後の部分の前の後ろを省く。使った秘密の値は伏せる。

## 理由

- エージェントで埋める案は、見出しの意図をよりよく汲めるが、PR を作るたびに費用と時間がかかり、出力が揺れ、失敗したときの扱いと
  予算の扱いが要る。PR の本文は人がレビューの入口として見るもので、sacty の内容（要求要件・実装の報告・テストの対応表）はすでに
  決まった形で揃っているので、見出しの種類に振り分ければ足りると判断した。当てはまらない見出しは「該当なし」で人にわかるようにする。
- 複数のテンプレートは、GitHub は既定には使わない（URL の `template` の指定で選ぶ）。何も使わないと、ディレクトリだけを置く
  リポジトリでは要望を満たせないので、決まった順（名前の順）で1つを選び、どれを使ったかを記録して人が確かめられるようにした。
  PR の種類で選ぶ案は、テンプレートの名前の付け方がリポジトリごとに違い、規則を決められないので採らなかった。
- Org の `.github` は、GitHub が既定のテンプレートとして使うのは公開のものだけなので、それに合わせた（GitHub の画面で PR を作ったときと
  同じテンプレートになるように）。
- チェックボックスを外すのは、sacty が確かめていないことにチェックが付いていると、レビューする人が確かめ済みと誤解するため。
- タスクの ID と `Closes` は、作業履歴とマージで Issue を閉じる処理に要るので、テンプレートの形より優先する。

## 影響

- 対象のリポジトリにテンプレートがあると、PR の本文の形が変わる（観点とテストの表は「テスト」の見出しに、最終レビューは折りたたみに入る）。
- PR を作る・更新するたびに、GitHub の contents API を数回呼ぶ（最大で十数回。全体で30秒の時間切れ）。
- 見出しの種類の規則（`CATEGORY_RULES`）に当たらない書き方の見出しは「該当なし」になり、内容は折りたたみに入る。規則を増やすときは
  仕様書を直す。
- 仕様書：[承認と差し戻し](../spec/approval.md#pr-の本文と-pr-テンプレート)
