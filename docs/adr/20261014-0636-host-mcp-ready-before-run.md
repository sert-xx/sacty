# 工程エージェントの実行の前に、使うホストの MCP を設定と突き合わせ、いまの設定での準備を待ってから動かす

- 日時: 2026-10-14 06:36 UTC
- ステータス: 採用
- 関係する PR・タスク: #84、PBI-77
- 置き換え元: なし
- 置き換え先: なし

## 背景

ホストの MCP（`config.yaml` の `gateway.mcp_servers`）は、30秒ごとに設定と突き合わせていた。そのため、設定に足した直後の実行では
`/mcp/<名前>` が 404（unknown MCP server）に、起動中は 503 になり得た。

## 決定

- 工程エージェントの実行の前に、その実行が使うホストの MCP を設定と突き合わせ（足したものを起動し、消したものを止める）、起動・再認証の途中の
  ものは準備ができるまで待ってから動かす。待つ上限は MCP ごとの `ready_timeout_sec`。
- 準備ができたとみなすのは、いまの設定（時間切れを除く）で起動した接続だけ。command・args・env を変えたら、新しいプロセスの準備・失敗・時間切れを待つ。
- 並行する実行は、同じ MCP の起動の待ちを共有する（起動は1度だけ）。
- 起動に失敗して起動し直しを待っているものは、待たずに理由を返す。
- 準備ができないものがあっても実行は進め、どの MCP かがわかる注意（`gateway.mcpUnavailable`・`gateway.mcpReadyTimeout`）を作業履歴に残す。
- ホストの MCP への成果の書き出しは、その MCP だけを待ち、準備ができなければ理由を残して書き出さない（画面から書き出し直せる）。
- 待つ間に人間が一時停止・中止したら、上限まで待たずに戻る。
- 時間切れの値だけの変更では起動し直さない（#82 で決めた動作を保つ）。

## 理由

- 足した直後の実行で 404・503 になり得たため（PR の本文）。
- 起動に失敗したものを待たないのは、実行のたびに起動し直してブラウザの再認証を増やさないため（PR の本文・コミット）。
- いまの設定で起動した接続だけを準備済みとみなすのは、レビューで、設定を変えた途中に古い接続で先に進み、変更前の接続へ送られ、新しい起動の失敗も
  知らされないと指摘されたため。
- 準備ができないときに実行を止めずに注意を残して進める理由は記録に無い。

## 影響

- 実行の開始が、使うホストの MCP の準備（最大 `ready_timeout_sec`）の分だけ遅れることがある。
- 消したホストの MCP は、今までどおり新しい実行に渡さない。
