# オーケストレーターへの質問の答えで、タスクの終わった実行のセッションログを、答えの実行ごとに並べて読み取り専用でマウントする

## 背景

「オーケストレーターに質問」（[読み取り専用の質問](20261013-0951-read-only-task-questions.md)）の答えの材料は、タスクの台帳
（出力・判定・指摘など）と起点のコードだけで、各工程のエージェントが実際に何をしたかは調べられなかった。実行ごとのセッションログ
（[実行ごとのセッションログ](20261013-1533-session-logs-per-run.md)）とエージェントの元のファイル
（[エージェントの元のファイル](20261014-0100-agent-session-archive.md)）は残っているが、大きいので指示に丸ごとは入れられない。
ほかのタスクのログ・ログ以外のファイルに触れさせないこと、秘密の値を答えに出さないことも必要だった。

## 決定

- 答えの実行の前に、このタスクの `SACTY_HOME/runs/<タスク ID>/` から、終わった実行（`meta.json` に `finishedAt` がある）の
  `meta.json`・`events.jsonl`・`stderr.log` と、作業履歴の `AgentSessionArchived` に記録したエージェントのファイルだけを、
  答えの実行ごとの場所（`<workspaces>/_question-logs/<実行 ID>/`）に並べ、コンテナの `/sacty-logs` に読み取り専用でマウントする。
  実行の一覧を `index.json` に書く。答えの実行が終わったら消す。
- 並べるときは、同じファイルシステムならハードリンクにし、できなければ写す。通常のファイルでないもの、記録と大きさが違うエージェントの
  ファイルは並べない。
- 終わりが記録されていない実行（実行中・デーモンが止まった）は並べず、一覧に「読めない」として出す。
- 指示には中身を入れず、置き場所・読み方（探して必要な部分だけ読む）と、実行の一覧（どの工程・何回目・実行 ID・結果・ログの大きさ・
  切り詰め・ログの無い／読めない実行。8000 文字まで、超えたら古い実行を省く）だけを、台帳の前に入れる。
- Claude Code には `--add-dir /sacty-logs` を渡す（作業領域の外を読めるように）。Codex はサンドボックスを使わないので足さない。
- ログの置き場所が無い・並べられないときは、ログを読めないことを指示に書いて、台帳から答えさせる。
- 費用の扱いは変えない（答えの費用はタスクの予算に入る）。

## 理由

- ログの場所（`runs/<タスク ID>/`）を直接マウントせずに並べ直すのは、終わっていない実行のファイルを渡さないため。実行中のログは、
  書き始めた後に分かった秘密情報（コンテナで更新されたトークンなど）を閉じるときに伏せ直すので、閉じる前には残っていることがある。
  答えの実行そのもののログも同じ場所に書かれる（Dev の判断）。
- 並べるものを決まった名前と作業履歴の記録に限るのは、ログ以外のファイルに触れさせないため（受け入れ条件）。タスクごとの場所だけを
  見るので、ほかのタスクのログは並ばない。
- ハードリンクにするのは、エージェントのファイルが1実行 200MB まであり、質問のたびに写すと時間と場所を使うため。読み取り専用で
  マウントするので、コンテナから元のファイルは書き換えられない（Dev の判断）。
- 中身を指示に入れないのは、ログが大きく、指示の長さの上限（40000 文字）に入らないため（受け入れ条件）。
- `--add-dir` を渡すのは、Claude Code が作業領域の外を読めることに頼らないため（Dev の判断。実際の Claude Code での読み取りは未確認）。

## 影響

- 答えの実行で、エージェントがタスクの各実行のログを探して読める（[タスクと工程](../spec/tasks-and-steps.md#オーケストレーターに質問)）。
- 実行中の工程のログは、終わるまで質問の答えで読めない。デーモンが止まって終わりを記録できなかった実行のログは、ずっと読めない。
- 伏せられるのは、これまでどおり実行に渡した秘密情報だけ（ログを書いたときに伏せていない値は、答えに出うる。指示で書かないように求める）。
- ハードリンクにできない（別のファイルシステム）ときは写すので、大きなタスクでは質問の前の準備に時間がかかる。デーモンが答えの途中で
  落ちると、並べた場所が残る。
