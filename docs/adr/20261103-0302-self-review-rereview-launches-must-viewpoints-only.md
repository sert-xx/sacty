# セルフレビューの再レビューは、前回 must を出した観点と X-1 だけを起動する

- 日時: 2026-11-03 03:02 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-286
- 置き換え元: なし
- 置き換え先: なし

## 背景

実験の費用の集計（F31）で、要求要件・設計のセルフレビューが高いことが分かった。要求要件の工程は1回平均で観点の担当を 13.3 個、設計は 17 個起動し、費用は 1 回 $21.11・$31.64 だった。
既定のスキル `review-dispatch` の `self-review` は、再レビュー（2回目以降）でも必須の観点を全部起動し直す（最大 5 回）。
観点ごとの指摘（73 回分）では、くり返しを生む `must` の大半が X-1（10 件）と D-4（8 件）から出ていて、D-6・D-7・D-8・D-9・X-2 は `must` を一度も出していなかった。

## 決定

- 再レビュー（2回目以降）は、前回の回で `must` を出した観点と、横断の X-1 だけを起動する。`must` が無く、`should`・`nit` だけを直して再レビューに進むときは、X-1 だけを起動する。初回は、今までどおり全部の観点で見る。
- 決めるのは前回の回の結果だけ。再レビューでは、必須観点を全部起動する・条件付き観点の起動条件を判定し直す、という初回の規則を使わない。
- 起動した担当には、今までどおり前回の指摘と修正の内容を渡し、直ったかと、修正が新しい問題を持ち込んでいないかを見させる。X-1 には、前回の回で採用した指摘のすべてと修正の内容を渡し、起動しなかった観点の指摘への修正が持ち込んだ問題も見させる。
- 起動しなかった観点は、起動表に「起動しない」と理由（再レビュー：前回の回で must なし）を残し、成果の説明の「起動した観点」でも分かるようにする。
- X-2 も同じ扱いにする。ただし、修正後に実行し直した検証が失敗・警告を出したときは、X-2 も起動する。
- 初回のレビューと、`pr-review` の再レビューの起動の規則は変えない。観点をまとめることはしない。
- Sacty が工程に渡す指示（`selfReviewLines`・`partialReworkReviewLines`）は変えない。回数の上限と範囲だけを決めていて、起動する観点はスキルの規則に任せているため、食い違わない。

## 理由

- 再レビューは「指摘が直ったか」と「修正が新しい問題を持ち込んでいないか」を見る回で、`must` を出さなかった観点まで毎回起動し直す費用に見合う指摘が出ていなかった。
- X-1 は観点にとらわれず対象の全体から欠陥を探すので、起動しなかった観点が見るはずの問題を修正が持ち込んでいても拾える。
- 修正が検証を壊したのに誰も分析しない状態を避けるため、X-2 だけは検証の結果が悪いときに起動する。
- 採らなかった案：観点をまとめて担当の数を減らす案。まとめた分だけ見落とすため、入れない（人の判断）。

## 影響

- 再レビューの観点の担当が減り、要求要件・設計のセルフレビューの費用と時間が下がる。
- 前回 `must` が無かった観点が見るはずの問題を、修正が持ち込んだときは、X-1 が拾えなければ見逃す。初回に全部の観点で見ていること、`must` を出した観点は再レビューで見直すことで、許容する。
