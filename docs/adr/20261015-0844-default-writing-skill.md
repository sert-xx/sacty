# 既定のコンテキストに文章を書くためのスキルを同梱し、「。」の後の改行は日本語だけにする

- 日時: 2026-10-15 08:44 UTC
- ステータス: 採用
- 関係する PR・タスク: #112、PBI-102
- 置き換え元: なし
- 置き換え先: なし

## 背景

工程のエージェントが書く PR の本文・レビューのコメント・報告は、AI が書いたとすぐにわかり、読みにくいという声があった。
既定のコンテキストは、あらゆる言語・分野のリポジトリに渡る。
書き方の決まりも、特定のリポジトリや言語に寄せずに書く必要があった。

## 決定

- 既定のコンテキストに、文章を書くためのスキル `writing` を足す。
  既定の `git`・`review-dispatch`・`review-execution` は、文章を書く所からこのスキルを参照する。
- 従う順は、依頼した人の指示、対象のリポジトリの文章の決まり、このスキルの順にする。
- 日本語では「。」の後で必ず改行する。
  英語ではピリオドの後で改行せず、段落を短くする（リポジトリが1文1行を決めていれば従う）。
- 構造のある情報は箇条書き（2〜3 階層まで）と表にし、理由・経緯・判断は地の文で書く。
- 文章のリンターのような機械的な検査は付けない。

## 理由

「。」の後の改行は、日本語では文の切れ目を見つけやすくする。
英語の文は短く、1文ごとに改行すると、改行をそのまま表示する場所（Issue・PR のコメント）で行が細切れになる。
そのため、英語には持ち込まないことにした。

機械的な検査は、コードブロック・表・引用の中を誤って検出し、文章を壊すおそれがある。
スキルの見直しの手順で、エージェント自身が確かめる形にした。

## 影響

対象のリポジトリに文章の決まりがあれば、そちらが優先される。
決まりの無いリポジトリでは、エージェントの文章の改行と段落の形が変わる。
現在の振る舞いは[コンテキストの仕様](../spec/context.md#既定の文章用スキル)に記す。
