## 背景

画面の入口（`/`）は、表示しているプロジェクト（cookie）のタスクの一覧で、`/projects/<ID>` はプロジェクトの設定だった。
すべてのプロジェクトの動きを見るには、プロジェクトを1つずつ切り替える必要があった。ステークホルダーは、終わっていないタスクを
プロジェクトをまたいで1か所で見たい。その画面には、今後ほかの情報も載せていく。

## 決定

- `/` は `/dashboard` へ移す。ダッシュボードは欄（カード）を並べる作りにし、今回は「すべてのプロジェクトの終わっていないタスク」
  （完了・中止を除くすべて）の欄だけを置く。件数の上限は無く、欄の高さは5件分で、それより多ければ欄の中でスクロールする。
- タスクの一覧を `/projects/<ID>/tasks`、プロジェクトの設定を `/projects/<ID>/settings` に置く。`/projects/<ID>` は
  `/projects/<ID>/tasks` へ移す。プロジェクトの画面のプロジェクトは URL の ID で決め、無い ID は 404 にする。古い URL の互換は、
  この2つのリダイレクトだけにする。
- ヘッダーのプロジェクトの切り替えの先頭に「すべてのプロジェクト」を置き、`/dashboard` へ移す。個別のプロジェクトは、そのタスクの
  一覧へ移す。ヘッダーの選んだ表示は、開いている画面の URL で決める（プロジェクトの画面はそのプロジェクト、ほかは「すべての
  プロジェクト」）。
- 「すべてのプロジェクト」の画面では、サイドメニューの「タスク」を出さず、「設定」をプロジェクトの一覧へ向ける。お知らせは
  プロジェクトで分けずに出す。
- cookie（表示しているプロジェクト）は残す。サイドメニューの「タスク」「設定」（`/projects/current`・`/projects/current/tasks`）と、
  URL にプロジェクトの無いタスクの詳細などの画面で使い、プロジェクトの画面を開いたときに画面のプロジェクトに合わせる。

## 理由

- 入口をダッシュボードにするのは、sacty を開いたら、まずすべてのプロジェクトの終わっていないタスクを見たいという
  ステークホルダーの要求のため（PBI-114）。
- 画面の構成（URL の表）と、互換をリダイレクトだけにすることは、ステークホルダーと合意した（まだ本番で使っていないため）。
- タスクの一覧のプロジェクトを cookie から URL に移したのは、URL でプロジェクトの画面を開けるようにし、ヘッダーの選択と画面の
  プロジェクトがずれないようにするため（PBI-114 の受け入れ条件）。
- 「すべてのプロジェクト」の画面でサイドメニューのプロジェクトの項目を隠す・プロジェクトの一覧へ向けるのは、どのプロジェクトも
  選んでいない間に、押して特定のプロジェクトに飛ばないようにするため（ステークホルダーの追記。隠すかプロジェクトの一覧へ移すかは
  任された）。「タスク」は一覧の行き先が決まらないので隠し、「設定」はプロジェクトの設定が並ぶプロジェクトの一覧へ向けた。
- cookie を残すのは、サイドメニューから開くプロジェクトと、タスクの詳細のヘッダーの表示に、最後に見たプロジェクトが要るため。

## 影響

- 画面の中のリンクと移動先は `apps/web/src/lib/paths.ts` で作る。古い URL を指すリンクが残っていないことを、テストで確かめる。
- ダッシュボードに欄を足すときは、ダッシュボードのデータに欄のデータを足し、欄（カード）を足す（取り直しは画面で1つ）。
- 仕様は [全体の構成](../spec/architecture.md) の「画面の構成（URL）」「画面のヘッダーとサイドメニュー」。
