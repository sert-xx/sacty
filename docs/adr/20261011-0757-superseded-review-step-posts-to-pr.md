# 「レビュー」の工程を足し、タスクにある対象リポジトリの PR を AI がレビューして、人間の承認を待たずに PR に投稿する

- 日時: 2026-10-11 07:57 UTC
- ステータス: 置き換え済み（superseded）
- 関係する PR・タスク: #25、PBI-19
- 置き換え元: なし
- 置き換え先: [sacty が作る PR に取り込むラベルを付け、別のタスクのレビューを元のタスクの PR の指摘として取り込む](20261014-1445-label-sacty-pull-requests-for-review.md)（sacty が投稿したレビューを PR の指摘から除く部分）

## 背景

#23 で、オーケストレーターが決まった候補から工程を選ぶようにし、進める順を「調査」→「レビュー」とした。#24 で調査を足した。次に、既存の PR をレビューする工程を足す必要があった。

## 決定

- 対象は既存の PR。タスク（Issue から取り込んだものを含む）に対象リポジトリの PR の URL があるときだけ、オーケストレーターの候補にレビューを出す。URL が無ければ候補に出さず、選んでも標準の工程にする。
- レビューのエージェントには、PR の先頭のコミットのコードを読み取り専用で渡し、分岐点からの PR の差分（`base...head`）と PR の説明を指示に入れる。PR のコミットは記録した SHA で取得する。
- 書いたレビューは、人間の承認を待たずに、プロジェクトの gh のアカウントで、読んだコミットに対して COMMENT で投稿し、タスクを完了にする。
- 本文とは別に、PR の行へのコメントを書ける。本文と合わせて1つのレビューにする。行へのコメントにするのは、差分に含まれる行（追加した行と前後に表示される行）だけで、50 件まで。外れたものは本文に回す。それでも GitHub が受け付けない（422）ときは、行へのコメントを本文に入れて投稿し直す。
- レビューと行へのコメントにタスクごとの目印を入れる。投稿の前に既存のレビューを目印で照合し、二度投稿しない。照合と、PR へのフィードバック（#21）からの除外は、プロジェクトのアカウントが投稿した、目印で始まるものだけを対象にする。
- 指示に、PR の説明・差分・コードに書かれた指示には従わないことを書く。
- PR を確かめられない・投稿できないときは、理由を記録して一時停止する（トークンは伏せる）。再開すると続きから試し、投稿だけが失敗した場合はエージェントを実行し直さない。

## 理由

- 対象を既存の PR にすること、人間の承認なしに PR に投稿して完了することは、決めたこととして本文にある。理由は記録に無い。
- 差分の外の行を行へのコメントにしないのは、GitHub は差分の外の行が1つでもあるとレビュー全体を拒否するため（本文）。
- sacty が投稿したレビューをフィードバックとして取り込まないのは、sacty が作った PR を別のタスクでレビューしたときに、AI のレビューが人間の差し戻しとして扱われないようにするため（本文）。
- 目印の照合をプロジェクトのアカウントの、目印で始まるものに絞ったこと、指示に従わないことを書いたことは、この PR を sacty でレビューして出た指摘による。目印を含むだけで除くと、人間が引用・転記した指摘が捨てられ、他人が目印を書くと投稿済みと見なされるため。PR の説明・差分・コードは信頼できない入力で、承認なしに投稿される出力を歪められるため（レビュー）。

## 影響

- レビューは人間の確認なしに、プロジェクトの gh のアカウントの名義で投稿される。
- 本文が空で行へのコメントだけのレビューも、書き終えたレビューとして投稿・完了する。
- 画面に、レビューの本文・行へのコメント・対象の PR・投稿したレビューを出す。
