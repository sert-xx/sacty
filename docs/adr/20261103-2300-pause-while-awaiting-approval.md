# 承認待ち（PR のマージ待ち）でも一時停止できるようにする

- 日時: 2026-11-03 23:00 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-301
- 置き換え元: なし
- 置き換え先: なし

## 背景

人の一時停止は、承認待ち・エスカレーション・子タスク待ちでは「人の判断待ちで、止める作業が無い」として断っていた。
実験（r3 の S18）で、実装の PR のマージ待ちに「中止」しか出ず、止めている間のマージと指摘の扱い（一時停止中の PR の見守り・指摘の反映）を確かめる場面を作れなかった。
実際には、マージ待ちの間は PR が動く。人が PR を見ている間だけ取り込みを止めたい（自分で直している間に、AI のレビューの指摘を取り込ませたくないなど）場面がある。

## 決定

- 承認待ち（`awaiting_approval`）のタスクを、人が一時停止できる。実行が無いので、その場で `TaskPaused`（理由 `manual`）を記録する。承認ゲートと PR の記録は残し、再開すると承認待ちに戻る（`resumeTo: awaiting_approval`）。エスカレーションは止められないままにする。
- 止めている間の PR の扱いは、すでにある仕組みに合わせる。
  - 実装の PR は、実装の作り直しの間の PR と同じ扱い。マージされたら承認として進める。届いた指摘は未反映として残す。
  - 要求要件・設計の PR は、止めている間は見守らない。
- 再開したら、承認待ちの PR の確認（60秒ごと）が、止めていた間に起きたこと（マージ・指摘）を取り込む。残した指摘は、承認待ちの取り込みが引き継いで、ゴールガーディアンが戻し先を判断して差し戻す。

## 理由

- 一時停止の間の PR の扱い（マージで承認・指摘は残して再開後に反映）は、PBI-276・PBI-279 で決めて実装済み。承認待ちのタスクの実装の PR は、一時停止の状態にしただけで、同じ経路に乗る。新しい経路を作らない。
- 実装の PR だけ止めている間もマージを見守るのは、マージが人の承認そのものだから。止めていてもマージを取りこぼすと、承認済みの PR が未承認のまま残る。要求要件・設計の PR は、作り直しの間にも見守っていないので、そろえる。
- 再開の先を承認待ちにするので、承認の画面がそのまま使える。

## 影響

- 止めている間は、承認も差し戻しもできない。再開してから行う。
- 要求要件・設計のマージ待ちで止めると、止めている間のマージの承認は再開まで遅れる。
- 人が止めたので、Slack には通知しない。
- 仕様書は[承認と差し戻し](../spec/approval.md#承認待ちでの一時停止)に、利用者向けは[タスクを進める](../user/tasks.md)に記す。
