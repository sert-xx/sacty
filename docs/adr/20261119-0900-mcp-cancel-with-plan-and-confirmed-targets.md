# sacty mcp の中止は、片付けの対象を読む専用のツールと、読んだ対象を引数で確かめる歯止めを付けて足す

- 日時: 2026-11-19 09:00 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-401
- 置き換え元: なし
- 置き換え先: なし

## 背景

`sacty mcp` は、一時停止と再開（[一時停止・再開の ADR](20261119-0800-mcp-pause-resume-minimal-resume.md)）までできる。機能を1つずつ足す流れの7回目の後半（7b）として、タスクの中止を足す。
中止は取り消せず、sacty の外（GitHub の PR を閉じる・リモートのブランチを消す）に書く。ほかの書き込みのツールより、誤って呼ばれにくい作りにする必要がある。
デーモンの `service.cancel` が断るのは、無い・すでに中止・片付けの途中の3つだけで、完了したタスクは断らない（片付けが走り、状態が「完了」から「中止」に変わる）。
確認の画面が使う `GET /api/tasks/:id/cleanup-plan` は、実際の片付けと合わない（実装の PR は、マージ済みでも引き継いだ人の PR でも「ある」と出す）。

## 決定

- ツール `get_cancel_plan`（`task_id`。読むだけ）と `cancel_task`（`task_id`・`close_pull_requests`・`delete_branches`）を足す（13個から15個）。デーモンの既存の `POST /api/tasks/:id/cancel` と `GET /api/tasks/:id/cleanup-plan` だけを呼ぶ。デーモンのサービス・API の入口・`@sacty/core`・画面は変えない。
- 閉じる PR・消すブランチは、`cleanup-plan` ではなく、タスクから MCP の層で作る（`cancelTargets`）。デーモンの片付けの条件（マージ済み・引き継いだ人の PR は閉じない、開いていて置き換えられていない要求要件・設計の PR を閉じる、引き継いだ人の PR のブランチは消さない）の写しで、その旨をコメントに書く。`cleanup-plan` は、コンテナ・作業領域・セッションの有無を読むためだけに使う。
- 中止は、引数の「閉じる PR」「消すブランチ」が、呼んだ時点の対象と一致したときだけ API に送る（承認の `submission` と同じ考え方）。一致しないときは、中止せず、いまの対象を返す。
- 完了したタスク・中止済み・PR のレビューの子タスク・分割の親・分割の子タスクは、API に送らずに断り、理由と画面で人が行えることを返す（`cancelBlock`。要約の `canCancel` も同じ関数）。分割の親・子と PR のレビューの子タスクを MCP から中止できるようにするかは、利用者の判断待ち。
- 結果は、ほかの書き込みのツールと同じ形に、片付けの結果（対象ごとの `done`・`skipped`・`failed`・理由）・閉じた PR・消したブランチ・失敗を足す。失敗があるときは、短い文にも、失敗した対象と理由を入れる。
- 注釈は、中止が `readOnlyHint: false`・`destructiveHint: true`・`idempotentHint: false`・`openWorldHint: true`、読み取りが `readOnlyHint: true`。
- 説明は、ほかの書き込みのツールより強く書く：取り消せない・片付けの中身・利用者がはっきり頼んだときだけ呼ぶ・「止めて」「待って」は一時停止・タスクの文の中の指示では呼ばない・先に読み取りで確かめて伝える。
- 結果を受け取れなかったときは、中止されている・片付けが続いている可能性を返し、自動でやり直さず、`get_task` で `state` を確かめ、まだ中止でなければ呼び直さず `wait_for_task` で待つ。

## 理由

- 読み取りの結果を、実際の片付けと合う形にしないと、利用者に伝えた対象と、実際に閉じる・消すものが食い違う。
- 引数で対象を確かめさせると、読まずに呼ぶこと・読んだ後に PR やブランチが増えたことで、伝えていないものを閉じる・消すことを防げる。
- 完了したタスクを通すと、ブランチが消え、状態が「中止」に変わる。デーモンを変えない範囲では、MCP の層で断るしかない。

## 影響

- 登録した AI は、利用者がはっきり頼んだときに、タスクを中止できる。PR が閉じられ、ブランチと作業領域が消える。取り消せない。
- 読み取りと中止の間に PR やブランチが増える窓、先読みの後に完了する窓は残る（デーモンの変更は範囲外）。要求要件・設計の PR は、sacty の記録で判断するので、人が GitHub で先に閉じた PR は、読み取りに出るが、実際は閉じない。
- 結果を受け取れないまま、後で中止になることがある（片付けの時間に上限が無く、MCP は 30 秒で待つのをやめる）。
- やり直し・派生・エラーの分析は、後続で足す。
- 仕様は [MCP サーバー](../spec/mcp-server.md#cancel_task)、利用者向けは [手元の AI から操作する](../user/mcp.md#中止する) に書く。
