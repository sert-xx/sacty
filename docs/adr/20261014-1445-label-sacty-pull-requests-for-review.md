# sacty が作る PR に取り込むラベルを付け、別のタスクのレビューを元のタスクの PR の指摘として取り込む

- 日時: 2026-10-14 14:45 UTC
- ステータス: 採用
- 関係する PR・タスク: #PR_NUMBER、PBI-88
- 置き換え元: [「レビュー」の工程を足し、タスクにある対象リポジトリの PR を AI がレビューして、人間の承認を待たずに PR に投稿する](20261011-0757-superseded-review-step-posts-to-pr.md)
- 置き換え先: なし

## 背景

sacty が作った PR を、作ったタスクとは別のコンテキストのタスクで敵対的にレビューさせたい（ステークホルダーの要求）。
取り込みには、取り込むラベル（`intakeLabel`）の付いた PR をタスクにする仕組みがすでにある。ただし、次の問題があった。

- 取り込むラベルの PR は、オーケストレーターが工程を選ぶ。sacty の PR の題・本文は実装の内容なので、もう一度実装する組み合わせを
  選ぶと、新しい PR ができ、それにもラベルが付いて、PR とタスクが際限なく増えうる。
- PBI-19 の決定で、プロジェクトのアカウントが投稿した sacty のレビューは、PR の指摘として取り込まない。別のタスクのレビューが、
  元のタスクに届かない。

## 決定

- sacty が作る PR すべて（実装の PR と、要求要件・設計の PR）に、作った直後に取り込むラベルを付ける。リポジトリにラベルが無ければ作る。
  取り込むラベルを設定していない・PR のトリアージを Off にしている（`triageOff` に `pullRequests`）ときは付けない。
- 付けるのは1つの PR につき1回。付けた・付けられなかったことを台帳に残し（`PullRequestLabeled`・`PullRequestLabelFailed`）、記録のある
  PR は、更新しても付け直さない。付けられなくても、PR の作成は失敗にしない。
- 取り込みで、取り込むラベルの付いた PR が、sacty がタスクのために作った PR（台帳にある実装の PR・要求要件・設計の PR）なら、
  オーケストレーターを使わずにレビューだけのタスク（`source.review: sacty`）にする。レビュー用のラベル・レビューの依頼にも当たっても、
  こちらにする（取り込むラベルとレビュー用のラベルを同じにしていても、指摘が元のタスクに届くように）。
- 元のタスクの PR の指摘の取り込みで、そのレビューだけのタスク（同じ PR の `source.review: sacty`）が投稿したレビュー・行へのコメントは、
  PR の指摘として取り込む。ほかの sacty のレビューは、これまでどおり取り込まない（PBI-19 の決定のうち、この部分だけを置き換える）。

## 理由

- 工程をオーケストレーターに選ばせず、レビューだけに決めるのは、もう一度実装させて PR を増やす繰り返しを、仕組みで起こさないため。
  レビューだけのタスクは PR を作らないので、ラベルの付く PR は増えない。同じ PR は二度取り込まない（既存の重複の判定）ので、1つの PR の
  レビューは1回（人が再レビューを選んだときを除く）。
- 1つの PR に1回だけ付けるのは、人がラベルを外したら、それを人の判断として尊重するため。PR の現在のラベルを読んで判断する案もあるが、
  外したのか付け忘れたのかを区別できないので、台帳の記録で決める。
- PR のトリアージを Off にしているときに付けないのは、付けても取り込まれず、後で On にしたときに、古い PR がまとめてレビューの
  タスクになるのを避けるため。
- 取り込む sacty のレビューを、同じ PR のレビューだけのタスク（`source.review: sacty`）のものに絞るのは、PBI-19 で除いた理由
  （AI のレビューを、人が求めていないのに差し戻しとして扱わない）を、それ以外では保つため。このタスクは、人が取り込むラベルを設定して
  求めたレビューなので、指摘として届ける。

## 影響

- 取り込むラベルを設定していると、sacty の PR ごとにレビューのタスクが1つでき、その費用がかかる。
- AI のレビューが指摘として届くと、ゴールガーディアンが戻し先を判断して差し戻す（評価だけで直す点の無いレビューでも、差し戻しになりうる）。
