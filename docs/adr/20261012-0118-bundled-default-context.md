# sacty に既定のコンテキストを同梱し、どのプロジェクトでも工程エージェントに一番上位の層として渡す

- 日時: 2026-10-12 01:18 UTC
- ステータス: 採用
- 関係する PR・タスク: #32、PBI-24
- 置き換え元: なし
- 置き換え先: なし

## 背景

#13 で、コンテキストリポジトリの `extends` をたどって層にし、上位から順に合成して工程エージェントに渡すようにした。コンテキストリポジトリは任意で、無いプロジェクトには何も渡していなかった。#29 で、sacty を円滑に動かすための既定のコンテキスト（規則・スキル・MCP の設定）を埋め込み、ルートの層として渡す部分を、このタスクに回した。

## 決定

- `apps/daemon/default-context/` を既定のコンテキストとして同梱する（形式はコンテキストリポジトリと同じ）。ネットワークなしで使える。
- 既定の規則（`rules.md`）に、秘密情報を読まない・出さない、サブエージェントを起動してよい、作業の範囲などの基本の規則を書く。
- `skills/<名前>/SKILL.md` を置けば、コードを変えずに既定のスキルになる（このときは空）。
- コンテキストリポジトリが無いプロジェクトにも既定のコンテキストを渡す。ある場合は既定の下に重ねる（規則は既定から連結し、同じ名前のスキル・MCP はプロジェクトのものを使う）。
- 作業履歴の「コンテキストを用意」に `sacty-default@<中身のハッシュ>` を記録する。渡さないファイル（README など）の変更では版は変わらない。

## 理由

- #29 の本文で、既定のコンテキストは sacty を円滑に動かすためのものとされている。この PR の記録には、ほかの理由は無い。

## 影響

- どのプロジェクトの工程エージェントにも、既定の規則が渡る。
- 既定の規則の文案は、PR の本文でレビューで直すよう求めていた（レビューでは修正必須の事項は無かった）。
- 既定のスキルを足すときは、`apps/daemon/default-context/skills/` に置く。
