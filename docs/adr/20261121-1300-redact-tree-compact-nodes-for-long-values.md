# 秘密情報を伏せる木は、節を型付き配列で持ち、とても長い値でもメモリを値の長さに比例させる

- 日時: 2026-11-21 13:00 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-444
- 置き換え元: なし
- 置き換え先: なし

## 背景

値の全体の出現を探す木は、値の文字ごとに節を 1 つ持ち、節ごとに `Map` を作っていた。2MB の値 1 つで約 650MB（1 文字あたり約 300 バイト）を使った。
JSON でない認証ファイルは中身の全体が 1 つの値になり、コンテナの中のエージェントは、そのファイルを任意の大きさに書き換えられる。巨大なファイルで、デーモンのメモリを使い切るおそれがあった。

## 決定

- 節を型付き配列（最初の子の文字・最初の子・失敗の遷移・一致する値の長さ）で持つ。1 文字あたり約 14 バイト（値の形が 1 つ・木が 1 本のとき）。
- 子が 2 つ以上ある節の 2 つ目以降の子だけを `Map` に入れる。そうなる節の数は値の数以下なので、長い値の途中の節（子が 1 つ）は `Map` を持たない。
- コンテナから写した認証ファイル（`docker.ts` の `collectSecrets`）は、256KiB を超えるものを読まない。超えたら、伏せる対象から外さずに、実行を失敗にする。
  - 起動の前に超えていれば、コンテナを起動せず、認証の失敗にする。
  - コンテナの中で超えた（エージェントが大きくした）ときは、実行の出力を返さず、認証の失敗にし、使用量は残す。ホストの認証ファイルへの書き戻しもしない。失敗の文言は、読めない認証ファイルの既存の文言を使う。
  - 本物の認証ファイルは数 KB なので、256KiB で正当な利用は止まらない。
- `StreamRedactor` は、値の集合が前回と同じ間は、値の形（JSON のエスケープ）・並べ替え・木を作り直さない。集合の比較は要素の `===` で、長い値でも文字数に比例して比べない。
- 走査・失敗の遷移の作り方は変えない（時間は値と入力の長さに比例する）。

## 理由

- 節を軽くするだけでは、ファイルの大きさに上限が無く、コンテナの中のエージェントが大きくした分だけ、木（値の形ごと・`ByteRedactor` の UTF-8 の長さ・`StreamRedactor` の 2 本、`snapshot` と `close` の `redact` ごと）が増える。実際の経路では、1 文字あたりの量が約 14 バイトの数倍になる。原因は長さに上限が無いことなので、上限を置き、超えたら失敗にする。
- 失敗にする倒し方は、利用者が出力の中身を見られなくなる代わりに、秘密を残す余地が無い。大きすぎる値を伏せる別の方法（`indexOf` の区間の併合など）は、同じ文字が続く入力で二乗になりうるので、採らなかった。
- 上限を 256KiB にすると、値 1 つの木は約 4MB（形が 2 つ・木が数本でも数十 MB）に収まる。

## 影響

- 伏せる結果は、上限以下の値では変わらない。重ならない入力の結果は変わらない。
- 大きすぎる認証ファイルの実行は、認証の失敗になる。コンテナの中で大きくされたときは、出力を返さない。セッションログには、大きくされた値は伏せる対象に入らない（出力を返さないので、それ以前の出力は、起動の前に集めた小さな値で伏せる）。
- `redact`・`compileSecrets` 自体は、長さの上限を持たない。32MB の値でも、木は 1 本あたり約 450MB の配列で、止まらずに作れる（デーモンは認証ファイルからは、この大きさの値を作らない）。ほかの呼び出し元（ホストの認証ファイルを直接読む `invocation.ts` など）の値は、起動のときにステージした写しが上限を超えれば、実行が失敗になる。
- `StreamRedactor` の 1 回の `push` の時間は、持ち越す分（いちばん長い値の長さ）に比例する。上限があるので、1 回あたり 256KiB 程度の走査になる。前回の木の状態は持ち越さない。
- 数字（約 14 バイト・約 4MB）は、値の形が 1 つ・木が 1 本のときのもの。値の形が増える（改行・引用符を含む）と木も増え、`ByteRedactor` は UTF-8 のバイト数で数える。

## 確かめたこと

- `redact-long.test.ts`：使った節 1 つあたりの配列の大きさが 1 文字あたり 30 バイト以下で、使う節の数が長さに比例すること（GC や時間に左右されない数え方）。2MB の値の伏せが 5 秒以内。長い値の重なり・境目（UTF-8 の文字の途中を含む）をまたぐ出力（`StreamRedactor`・`ByteRedactor`）で、1 文字も残らないこと。`StreamRedactor` が `push` のたびに値の形を作り直さないこと。
- `agents.test.ts`：起動の前・コンテナの中で、認証ファイルが上限を超えたとき、失敗になり、ホストの認証ファイルに書き戻さないこと。上限以下の非 JSON の認証ファイルは、今までどおり伏せること。
- 木の持ち方を元の `Map` の版に戻すと、木の配列（`firstCode` など）と節の数（`nodes`）が無くなり、このテストの木の大きさの確かめが `TypeError` で落ちる。上限を外す（大きく変える）と、`agents.test.ts` の 2 件が落ちることを、実際に確かめた。
