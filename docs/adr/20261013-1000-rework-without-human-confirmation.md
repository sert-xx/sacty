# PR の指摘による差し戻しは、人の確認を挟まず、ゴールガーディアンが判断した工程にそのまま行う

- 置き換え先: なし

## 背景

#21 で、PR の指摘を取り込み、ゴールガーディアンが戻し先を判断するようにした。そのとき、設計・要求要件まで戻す判断や、判断できない
ときは、人の確認（`TaskEscalated` の `rework_confirmation`）を待っていた。

## 決定

- ゴールガーディアンが判断した工程（実装・設計・要求要件）に、人の確認なしで差し戻す。差し戻して作り直した成果は、いつもどおり
  人が承認する。
- 判断できなかった・候補に無い工程を返したときは、実装のやり直しにする（判断できなかったことと理由は、判断の記録 `ReworkJudged` に残る）。
- 差し戻しの回数の上限を超えたときのエスカレーション（`too_many_changes`）は、これまでどおり残す。
- タスクに、最後に PR の指摘で戻した工程・判断の有無・理由・時刻を持ち、PR の欄に「戻し先」として出す（ゴールガーディアンの判断
  どおりに戻したときだけ。判断の後・反映の前に人が別の工程へ差し戻したときは、ゴールガーディアンの判断として残さない）。
- ゴールガーディアンへの指示から「人間の判断が必要」の文言を外し、判断した工程にそのまま差し戻すこと・前の工程を選ぶと人が
  もう一度承認することを書く。
- 過去の作業履歴の `rework_confirmation` のエスカレーションは、これまでどおり読み込み、画面で扱える。

## 理由

理由は記録に無い。PR の本文には、差し戻して作り直した成果はいつもどおり人が承認する、とだけ書かれている。比べたほかの案も記録に無い。

## 影響

- 設計・要求要件まで戻す判断のとき、人の確認を待たずに作り直しが始まる。人が関わるのは、作り直した成果の承認から。
- 判断できないときは実装のやり直しになるので、戻し先の誤りは人の承認や次の指摘で正す。
