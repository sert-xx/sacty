# 最終レビューを、実装の PR の CI と並べて進める

- 日時: 2026-11-08 02:32 UTC
- ステータス: 置き換え済み（superseded）
- 関係する PR・タスク: PBI-314
- 置き換え元: [実装の PR を最終レビューの前にドラフトで作り、CI を待ってからゴールガーディアンが判定し、合格したらドラフトを外してレビューへ進める](20261027-2330-superseded-draft-pull-request-before-final-review.md)（CI を待ってから最終レビューに進む部分）
- 置き換え先: [実装の最終レビュー（テストの実行）と PR の CI の待ちをやめ、PR のレビューの子タスクの指摘なしでドラフトを外す](20261112-0714-review-child-task-replaces-final-review-and-ci-wait.md)

## 背景

実装の PR をドラフトで作った後、CI が終わる（最長 60 分）まで最終レビューを始めていなかった。
CI の時間と最終レビューの時間が足し合わさり、PR がレビューできるまでの時間が長くなっていた（利用者の報告、2026-11-08）。

## 決定

- ドラフトの PR を作ったら、CI の終わりを待たずに最終レビューを始める。
  最終レビューには、CI がまだ終わっていないことだけを伝え、CI を待たせない・CI の状態を判定に使わせない。
  記録する `FinalReviewed` に、待っていた CI のコミット（`beforeCi`）を付ける。
- 不合格なら、CI を待たずに実装に戻す。待っていた CI は捨てる（やり直した実装で PR を更新して待ち直す）。
- 合格したら、CI の結果だけを待つ（`pullRequestCi.reviewedBeforeResult`）。
  - CI が初回で通った・CI が無いなら、最終レビューをし直さずに承認待ちへ進める。
  - CI が落ちた・時間内に終わらなかった・失敗したジョブの再実行で通ったなら、CI の結果を見て、今までどおりの最終レビューをし直す。
    前の回の検証の記録を渡し、同じ内容の検証は使い回させる。
  - 最終レビューの間に CI が終わっていたら、記録したときの CI の結果で同じように決める。
- CI を待つ間の最終レビューの前には、ベースブランチを取り込まない（CI を待っているコミットを見るため）。

## 理由

- 最終レビューの多くは作業領域のテストで判定でき、CI の結果を使うのは CI が落ちたとき（変更によるか・環境・不安定か）と再実行したときだけである。
  CI が通るなら、CI を待たずに行った判定と結論は変わらない。
- CI が落ちたときだけ、もう1回の最終レビューの費用が増える。
  CI が通るのが普通なので、待ち時間を縮める効果の方が大きいと判断した。
  前の回の検証を使い回させるので、増える分は CI の失敗の判断が中心になる。
- 再実行で通ったときは、元の失敗を不安定な失敗の候補として確かめる（PBI-311）必要があるので、確定させずに最終レビューし直す。
- 状態は作業履歴（`FinalReviewed` の `beforeCi` と `PullRequestCiFinished`）から導くので、デーモンを起動し直しても、最終レビューを2回せず、取りこぼさない。

## 影響

- CI の待ちと最終レビューが重なり、CI が通る場合は、PR がレビューできるまでの時間が、おおよそ CI と最終レビューの長い方になる。
- 最終レビューは CI の結果を使い回せないので、作業領域で検証を実行する。
- CI が落ちた・時間切れ・再実行で通った場合は、最終レビューが2回になる（作業履歴に2回の `FinalReviewed` と費用が残る）。
- 画面の「PR の CI を待っている」は、最終レビューに合格した後に CI の結果を待つ間だけ出る。CI と並べた最終レビューの間は、検証中と出る。
