# PR のレビューで親が担当に渡す範囲を差分で決め、観点をどう見たかを本文に書く

## 背景

長い仕様書とユーザードキュメントを少し直した PR のレビューが、5回続けて「レビューを完了できませんでした」になり、判定が付かなかった。
実行のログを読むと、次のことが分かった。

- 親は観点ごとの担当（サブエージェント）を起動していた（Codex の 537 回のレビューで、1回あたりの中央値は 18 件）。
  ただし、Codex の `codex exec --json` の出力には担当の起動が出ず、待機だけが出る。sacty の実行のログだけを見ると、起動していないように見えた。
- 判定が付かなかった回は、文書の観点（U-1・U-6）の担当が `failed` を返していた。理由は「変えていない長い既存の本文の全体を照合しきれなかった」。
  同じ形は、レビューのエージェントを軽い段階に変えた後の 19 回のうち 18 回で起きていた。
- [前の決定](20261114-0158-review-range-and-partial-verdict.md)は、担当の側（U-1 が拾う範囲と、`failed` の条件）を直した。
  親が担当に渡す範囲と、親が `failed`・`limitations` をどう扱うかは決めていなかった。
  親は、担当の `limitations` や前回のレビューの「既存の本文の全体は照合していない」を見落としと読み、文書の全体を範囲にした担当を足した。
  その担当は見きれずに `failed` を返し、次の回もその本文を読んで同じことを繰り返した。

## 決定

- `pr-review` で親が担当に渡す範囲は、差分で決める。差分に入っている文書は、PR の本文に挙げられていても、変えていない既存の本文の全体を範囲にしない。
  文書の全体を範囲にするのは、差分に入っていない文書を対象にしたときと、差分がその文書を新しく足した・全面的に書き直したときだけ。
- 親は範囲を途中で広げない。担当の結果や前回のレビューに「変えていない箇所は見ていない」とあっても、その箇所を見る担当を足さない。再レビューでも同じ。
- 担当は、範囲の外を見なかったことを `limitations` に書かず、見た範囲を `checked` に書く。U-6 も、範囲が変更なら、変えた箇所と対応する箇所だけを照合する。
- 親は、`failed` の理由が範囲の外を見ていないことだけなら、起動し直さず、見られなかった観点に数えない。
  範囲を見きれなかったことが理由なら、同じ観点のまま範囲を分けて起動し直す。
- PR のレビューの本文に、観点をどう見たか（担当に分けて見た観点の数、または逐次モードで見たこと）を必ず1行で書く。
- sacty がレビューに渡すプロンプトにも、範囲の決め方と、観点をどう見たかの1行を書く。

## 理由

- 指摘の基準は、もとから `pr-review` では「今回の変更が持ち込んだ問題か、変更した箇所に接していて作者が直せる問題」に限っている。
  変えていない本文の全体を照合しても、出せる指摘はほとんど無い。
- 担当の側だけを直しても、親が範囲に「文書の全体」と書けば、担当はそれに従う。範囲を決めるのは親なので、親の決まりにする。
- 範囲の外を見ていないことが `limitations` に書かれると、親にも人にも、見落としと区別が付かない。見た範囲は `checked` に書けば足りる。
- 担当を起動したかは、エージェントの種類によって実行のログに出ない。本文に書かせれば、どのエージェントでも、人が同じ場所で確かめられる。
  sacty が Codex のセッションの記録から担当の数を数える案は、記録の形が Codex の版で変わるので採らなかった。

## 影響

- 長い文書を少し直した PR でも、文書の観点が差分の範囲で終わり、判定が付く。変えていない節の古い記述は、PR のレビューでは見つからない（前の決定と同じ）。
- 範囲を見きれなかった `failed` は、範囲を分けた担当で見直すので、担当の数が増えることがある。
