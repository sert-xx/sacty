# sacty mcp の待つツールは、デーモンに待つ API を足さず MCP の層で取りに行き、人の出番だけで起こす

- 日時: 2026-11-19 07:00 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-399
- 置き換え元: なし
- 置き換え先: なし

## 背景

手元の AI には、「人の出番」（承認待ち・人の判断待ち・一時停止・完了・中止・PR のレビューの判定）まで待つ手段が無かった。`get_task` を繰り返すか、sacty の外の手段で待っていた。
デーモンには、変化を待たせる API・押し出しが無い。画面は `GET /api/tasks/:id` などを 3 秒おきに取りに行く。
機能を1つずつ足す流れの6回目として、待ち方と、何で起こすかを決める必要があった。

## 決定

- デーモンに待つ API・押し出しは足さない。`sacty mcp` の層で、いまある `GET /api/tasks/:id`（`SactyApi.getTask`）を 5 秒おきに呼んで比べる。
- 起こすのは、人の出番の変化だけ：承認待ち（工程・提出の回の変化を含む）・人の判断待ち・一時停止（理由の変化を含む）・完了・中止・これらから動き出した・人に確かめたいことの件数・PR の状態・PR をレビューする子（`reviewTasks`）が増えたこと・子の状態・回・投稿・判定。工程の進み・実行の開始と終了・費用・作業履歴・`updatedAt` では起こさない。
- 待つ時間は、既定 30 秒・最大 50 秒。ツールは、指定した時間＋5 秒（最大 55 秒）以内に必ず返る。クライアントが 1 回の呼び出しを 60 秒で打ち切ることがあるため。
- 時間切れは失敗にしない。`changed: false` と `cursor` を返し、`cursor` を渡して呼び直すと続けて待てる。`cursor` は、比べる欄の値だけを持つ（文を持たず、sacty を起動し直しても使える）。
- `blocked`・`waiting_children` は人の出番ではないので、動いている側（`active`）に入れ、これらの行き来では起こさない。
- 1回の問い合わせは 10 秒まで。残りが少ないときは、残り（整数のミリ秒）までに縮める。待っている途中の1回の失敗は、締め切りまでの残りがあれば次の周期で1回やり直し、続けて失敗したら、`cursor` を添えた理由で返す。
- 分割の子タスクの変化と、進捗の通知（`notifications/progress`）は、今回は入れない（上限が短いので、進捗は要らない）。
- 取り消し（`notifications/cancelled`）と、相手が標準入力を閉じたときは、すぐ待ちをやめ、タイマーを残さない。そのために、ツールの処理に取り消しの信号を渡す。

## 比べた案

- デーモンに待つ API を足す：待つ間の負荷は減るが、デーモンのサービス・API の入口を変える。依頼の範囲外で、前の版のデーモンでは動かない。後から足せる作りにして、今回は採らない。
- 押し出し（SSE など）：同じ理由で採らない。画面の取りに行く作りも、いまは 3 秒おきの取得のまま。
- 手元の AI が `get_task` を繰り返す：いまの状態。呼び直しの回数・結果の大きさ（題・説明・作業履歴を含む）が増え、子のレビューの判定にも気づけない。人の出番だけを小さな結果で返すツールにした。

## 理由

- デーモンを変えずに作れ、前の版のデーモンでも動く。待つ API は、後から足せる（今回の作りを壊さない）。
- 親が PR のマージ待ちのまま、子のレビューの判定だけが出ることがある。親の状態だけでは気づけないので、子も含める。
- 動いているだけの変化で起こすと、AI が何度も呼び直し、結果の読み取りが増える。人がすることがある変化だけに絞る。
- `GET /api/tasks/:id` は作業履歴を毎回全件返す。間隔を画面（3 秒）より短くせず、引く子の数に上限（5 件）を置く。

## 影響

- 待つ間の負荷：5 秒おきに、待つタスクと子（5 件まで）の `GET /api/tasks/:id` を呼ぶ。この API は作業履歴を毎回全件返す（作業履歴が最も長いタスクで約 0.8MB）。子を `listTasks` で引く・間引くなどの軽くする作りは、今回は変えず、後続で扱う。

- ツールは 11 個になる。待つ間は、5 秒おきに、作業履歴を全件返す API を呼ぶ（待つタスクと子の分）。
- `SactyApi.getTask` に、省ける期限・取り消しの引数を足し、`daemonRequest` に省ける `signal` を足した。ほかの呼び出し元の動きは変わらない。
- 複数のタスク・プロジェクトを待つこと、デーモンの待つ API、作業履歴の差分の取得、費用のしきい値で起こすことは、後続で足す。
- 仕様は [MCP サーバー](../spec/mcp-server.md#wait_for_task)、利用者向けは [手元の AI から操作する](../user/mcp.md#状態が変わるまで待つ) に書く。
