# 工程のイメージを、人がタスクの詳細でいつでも変えられるようにし、その工程を次に実行するときから使う

- 日時: 2026-10-15 11:15 UTC
- ステータス: 採用
- 関係する PR・タスク: #116、PBI-106
- 置き換え元: なし
- 置き換え先: なし

## 背景

工程ごとのイメージは、工程を選ぶときにオーケストレーターが選ぶか、プロジェクトの対象の指定で決まり、その後は変えられなかった。
オーケストレーターが工程に合わないイメージ（Playwright の要るリポジトリで既定のイメージなど）を選ぶとテストが失敗し、人が直す手段が
無いので、タスクを作り直すしかなかった。

## 決定

- タスクの詳細で、工程ごとのイメージを人が変えられる。工程の状態は問わない（実行中・終わった工程も変えられる）。中止したタスクと、
  イメージの無い PR作成の工程は変えられない。
- 選べるのは `images` の名前と `default`。それ以外（config.yaml から消した名前など）は理由を示して断る。
- 変えたことは、新しいイベント `StepImageChanged`（工程・変える前・変えた後。actor は person）で作業履歴に足す。`StepsChosen` は書き換えない。
- 変えたイメージは、その工程を次に実行するときから使う。今の実行は止めない。工程の実行は、実行を始めた（`AgentRunStarted` を足した）
  ときのイメージに決める。テストの実行も、テストを始めるときのイメージで行う。
- プロジェクトの対象でイメージを指定しているタスクも変えられ、人が変えた工程だけ、人の変更を優先する。

## 理由

- 選び違いを直したい場面は、失敗した後（終わった・止まった工程）にも、実行の最中にも、承認や手戻りの前にもあるので、状態で変えられない
  工程を作らない（ステークホルダーの判断）。
- 今の実行を止めて切り替えると、途中の作業が無駄になり、どのイメージで動いた結果かがわからなくなる。実行の開始でイメージを決めれば、
  作業履歴の順（開始・変更・次の開始）と、使ったイメージが一致する。
- プロジェクトの対象の指定は、タスクを作る前の既定の選び方で、選び違いを直す人の判断のほうが新しい。変えられないと、対象の指定が
  合わない工程（モノレポで言語が違うディレクトリなど）を直せない。
- 変える単位は工程ごと（タスクに1つではない。ステークホルダーが確定）。工程ごとに言語が違うリポジトリがあるため。

## 影響

- `images` から名前を消したときに止まった工程は、タスクの詳細で別のイメージに変えてから再開すれば進められる。
- 実装の工程の実行中に実装のイメージを変えると、その実行の後のテストは変えたイメージで動く（エージェントの実行と、テストのイメージが
  違うことがある）。
- 仕様は [工程とタスク](../spec/tasks-and-steps.md) の「工程のイメージを人が変える」に書く。
