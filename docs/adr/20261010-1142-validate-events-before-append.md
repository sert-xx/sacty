# 台帳にイベントを書く前に状態の復元に通し、受け付けられないイベントは書かない

- 日時: 2026-10-10 11:42 UTC
- ステータス: 採用
- 関係する PR・タスク: #12、PBI-3
- 置き換え元: なし
- 置き換え先: なし

## 背景

台帳への追記は、SQLite に書いた後で状態の復元（`applyEvent`）を行っていた。そのため、状態に合わないイベントを拒否するのが書いた後になり、
API が失敗しても、受け付けられないイベントが台帳に残りえた。中止を入れる PR のレビューで、中止の後のイベントという形で、この問題が見つかった。

## 決定

- `TaskService.append` で、台帳に書く前にイベントを状態の復元に通し、受け付けられないものは書かずに拒否する（409・「このタスクの状態では、その操作はできません」）。
- 中止したタスクへの操作（指摘の無効化など）は、サービスでも拒否する。

## 理由

レビューで、中止したタスクに古い画面から指摘の無効化を送ると、拒否されても `RemarkVoided` が `TaskCancelled` の後に台帳に残り、
次にサービスを作るときの状態の復元が失敗して、デーモンが起動できなくなることが見つかったため。中止の後に限らず、受け付けられないイベントが
永続化されることを防ぐために、書く前に検証するようにした（レビューとその返信）。

## 影響

- 台帳には、状態の復元で受け付けられるイベントだけが残る。
- イベントを足すときは、状態の復元で受け付けられる条件が、そのまま書き込みの条件になる。
