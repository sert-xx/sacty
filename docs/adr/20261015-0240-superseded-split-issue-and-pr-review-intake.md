# 取り込みを「Issue の取り込み」と「PR のレビューの取り込み」に分け、sacty の PR にはレビュー用のラベルを付ける

- 日時: 2026-10-15 02:40 UTC
- ステータス: 置き換え済み（superseded）
- 関係する PR・タスク: #108、PBI-99
- 置き換え元: [sacty が作る PR に取り込むラベルを付け、別のタスクのレビューを元のタスクの PR の指摘として取り込む](20261014-1445-superseded-label-sacty-pull-requests-for-review.md)
- 置き換え先: [取り込むラベルとレビュー用のラベルに同じ名前を許す](20261015-0850-allow-same-intake-and-review-label.md)（2つのラベルに同じ名前を拒否する部分）

## 背景

sacty の設定に「Issue・PR の取り込み」（取り込むラベル `intakeLabel`。`triageOff` の `issues`・`pullRequests` で Issue・PR を外せる）と
「PR のレビューの取り込み」（レビュー用のラベル `reviewLabel`・レビューの依頼 `reviewRequested`）があり、PR の取り込みが二重になっていた。
取り込むラベルの PR は、オーケストレーターが工程を選ぶ通常のタスクになり、sacty が作った PR だけが例外としてレビューだけのタスクに
なっていた（PBI-88）。設定の意味がわかりにくく、どちらのラベルで PR が取り込まれるかで振る舞いが変わっていた（ステークホルダーの要求）。

まだ本格運用していないので、互換を保たずに変えてよい（ステークホルダー、2026-10-15）。

## 決定

- 取り込むラベル（`intakeLabel`）は Issue だけを取り込む（検索は `is:issue`。PR は、取り込むラベルが付いていても取り込まない）。
  PR を通常のタスクとして取り込む使い方はなくす。すでに取り込んだタスクは、そのまま進む。
- PR は「PR のレビューの取り込み」（レビュー用のラベル・レビューの依頼）だけで取り込み、レビューだけのタスクにする。
- sacty が作る PR すべて（実装の PR と、要求要件・設計の PR）に付けるラベルを、取り込むラベルからレビュー用のラベルに変える。
  レビュー用のラベルを設定していない・そのトリアージを Off にしている（`triageOff` に `reviewLabel`）ときは付けない。1つの PR に1回だけ
  付けること、付ける予定を PR の公開の記録に残して再開で付けることは、PBI-88 のまま。
- レビュー用のラベルの付いた PR が sacty の作った PR なら、`source.review: sacty` のレビューだけのタスクにし、直すべき指摘のある回の
  レビューを元のタスクの PR の指摘として届ける（PBI-88 のまま）。
- 要らなくなった設定の項目（`triageOff` の `pullRequests`）は、型・画面・API から消す。保存されている設定からは、設定の保存先を開く
  とき（デーモンの起動のとき）に消す。古い値を読み込む互換の処理は作らない（API で `pullRequests` を送ると、知らない種類として拒否する）。
- 取り込むラベルとレビュー用のラベルに同じ名前（大文字・小文字を区別しない）は、保存のときに拒否する（`input.sameIntakeAndReviewLabel`）。
- PR の公開の記録（`PullRequestPublished`・`StepPullRequestPublished`）の、ラベルを付ける予定の項目の名前を `intakeLabel` から `label` に
  変える。台帳はすでに起きた出来事の記録なので書き換えない。これまでの記録の `intakeLabel` は、読み込めるが、付ける予定としては扱わない。

## 理由

- PR の入口を1つにすると、PR がどう扱われるか（レビューだけ）が設定の名前から決まり、二重の取り込みや、sacty の PR だけの例外が要らない。
  PR の実装を任せたいときは、Issue にして取り込むか、画面からタスクを作れば足りる。
- sacty の PR に付けるのをレビュー用のラベルにするのは、PR を取り込むのがレビューの取り込みだけになったため（取り込むラベルを付けても、
  もう取り込まれない）。
- 同じ名前を拒否するのは、2つの取り込みをラベルで分けるという設定の意味を単純に保つため。同じ名前を許しても、Issue は取り込むラベル、
  PR はレビュー用のラベルとして動くが、どちらの設定で取り込まれたかが画面からわかりにくくなる。拒否は保存のときだけにし、読み込みでは
  拒否しない（拒否すると、すでに同じ名前で保存している設定で、デーモンが設定を読めなくなるため）。
- 消した項目を保存先から消すのは、互換の処理を残さず、知らない値として読み込みで失敗しないようにするため。開くたびに確かめ、消すものが
  無ければ書かないので、2回目以降は何もしない。
- 古い版への切り戻しは対象外とする（ステークホルダーの方針：破壊的に変え、互換は保たない）。起動のときに `triageOff` の `pullRequests` を
  消すので、この版で起動した後に古い版に戻すと、取り込むラベルの PR の取り込みが On と解釈される。バックアップと戻し方の手順は作らない。
- 記録の項目の名前を変えるのは、付けるラベルが取り込むラベルではなくなったため。これまでの記録を付ける予定として扱わないことで、
  変更の前に作って、ラベルを付ける前に止まった PR には、再開で付けない（運用前なので影響は小さいと判断した）。台帳の書き換えは、
  監査のための記録を変えることになるので行わない。

## 影響

- 取り込むラベルの付いた PR は、これまで通常のタスクとして取り込めたが、今後は取り込まない。sacty の PR のレビューを続けるには、レビュー用の
  ラベルを設定する。
- sacty の PR に付くラベルが、取り込むラベルからレビュー用のラベルに変わる。変更の前に取り込むラベルを付けた PR は、もうレビューのタスクに
  ならない（すでに作ったレビューのタスクは、そのまま進む）。
- 古い版への切り戻しは扱わない。この版で一度起動した後に古い版に戻すと、PR の取り込みを Off にしていた設定でも、取り込むラベルの PR を
  取り込む。
- すでに同じ名前の2つのラベルを保存している設定は、そのまま動く（Issue は通常のタスク、PR はレビューだけ）。次に保存するときに、別の名前に
  するよう求められる。
