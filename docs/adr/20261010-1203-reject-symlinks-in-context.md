# コンテキストリポジトリの読む項目にシンボリックリンクがあれば、リンク先にかかわらず拒否して止める

- 日時: 2026-10-10 12:03 UTC
- ステータス: 採用
- 関係する PR・タスク: #13、PBI-6
- 置き換え元: なし
- 置き換え先: なし

## 背景

コンテキストリポジトリから、規約・設定・スキルを読み、コンテナに渡す場所へ写す。リポジトリの中のシンボリックリンクを追うと、
デーモンのホストの任意のファイルを取り込めてしまう。また、スキルの中の相対リンクは、写した先ではホストの絶対パスに変わり、コンテナからは解決できない。

## 決定

- 取得した層で sacty が読む・写す項目（`sacty-context.yaml`・`rules.md`・`rules/`・`skills/`）を lstat でたどり、シンボリックリンクなど
  通常のファイル・ディレクトリ以外があれば、読む前に理由（層とパス）を示して止める。止めたときは、タスクを一時停止（エラー）にする。
- リンク先がリポジトリの中か外かは問わず拒否する。スキルの中のリンクも受け付けない。
- 読まない場所（README など）のリンクは、取得を妨げない。

## 理由

- リンクを追うとホストの任意のファイルを取り込めてしまい、写した先ではコンテナから解決できないため（コミットのメッセージ）。
- 範囲の中かを判定するより、すべて拒否するほうが単純で、すり抜けの余地がないため（レビューへの返信）。
- スキルの中のリンクは、無言で壊れたスキルを渡さないよう、取得の時点で理由を示して止めることにした（レビューへの返信）。
  リンクを実体化して受け付ける案は、必要になったら別に検討する（レビューへの返信）。

## 影響

- コンテキストリポジトリの規約・設定・スキルには、シンボリックリンクを使えない。
