# 完了したタスクから、元のタスクを指す続きのタスクを何度でも作れるようにする（派生）

- 日時: 2026-10-28 00:54 UTC
- ステータス: 採用
- 関係する PR・タスク: なし
- 置き換え元: なし
- 置き換え先: なし

## 背景

タスクが完了した後に、その成果から続きの作業をしたいことが多い。例えば、セキュリティチェックのレポートは承認して完了したが、
見つかった指摘を直したい。調査が終わり、わかった問題を直したい。実装がマージされ、追加の改善をしたい。

これまでは、中止したタスクの再実行（1度だけ・やり直し）と、セキュリティチェックの区分ごとの対応のタスク（区分ごとに1つ）しかなく、
ほかの完了したタスクからは、人が成果を写して新しいタスクを作るしかなかった。完了したタスクの作業履歴は、成果を取り込む
ために書き換えたくない（[作業履歴は追記だけ](20261010-0628-append-only-ledger.md)）。

## 決定

- 完了した（工程をすべて終えて止まった、中止していない）タスクの詳細に「続きのタスク」を置く。元のタスクを変えずに、元のタスクを
  指す新しいタスクを作る（`TaskCreated` の `derivedFrom`）。元のタスクには、作業履歴の復元で作ったタスクを記録する（`derivedTasks`）。
- 1つのタスクから、いくつでも作れる（再実行と違い、続きの作業は1つとは限らない）。
- 人が、題・内容（続きで何をするか。必須）・作業するリポジトリ（リポジトリ無しも）・進め方（省略するとオーケストレーターが選ぶ）を決める。
- 説明には、人の内容の後に、元のタスクの記録（工程・工程の成果・PR・最終レビュー・質問と答え）を sacty が足す。
- チケット・取り込み元は引き継がない（`start` は `sacty`）。
- セキュリティの組み合わせのタスクからは、進め方を `security-fix` か `security-check` にした続きだけを作る（指定しなければ `security-fix`）。

## 理由

- 新しいタスクにすれば、追記だけの作業履歴のまま、ふつうのタスクと同じ経路で進む。元のタスクの記録（成果・費用）もそのまま残る。
- 記録を説明に入れるのは再実行と同じ形で、人が画面で中身を確かめられ、オーケストレーターとすべての工程に同じ形で届く。
  再実行と違い、元のタスクの変更（マージした PR など）は残っているので、最初からやり直さず、記録を前提に進めるよう書く。
- 内容を必須にするのは、続きで何をするかが無いと、オーケストレーターが元のタスクの依頼をもう一度行いかねないため。
- チケット・取り込み元を引き継ぐと、元の依頼は終わっているのに、続きの結果がチケットや Issue に返り、二重の取り込みの判定も
  紛らわしくなる。続きは新しい依頼として扱う。
- セキュリティのタスクの記録には、レポートや修正の範囲（攻撃の手がかり）が入る。ほかの組み合わせにすると、PR の本文や
  コメントの頼みで公開の場所に出うるので、公開しない扱いと最小限の変更の決まりのある組み合わせに限る。
  区分をまたぐ対応や一部の指摘だけの対応は、この派生で `security-fix` のタスクとして作れる。
- 比べた案：
  - 完了したタスクを再開して、同じタスクに工程を足す。完了した記録と次の作業が混ざり、承認・費用・監査を分けて確かめられない
    （[GitHub のレビュー再依頼は完了タスクを戻さず別タスクにする](20261019-0503-review-rerequest-new-task.md) と同じ理由）。
  - 再実行を完了したタスクにも広げる。再実行は「中止で消えたものを最初からやり直す」意味で、1度だけ・前の説明を直す形なので、
    続きの作業とは意味と入力が違う。
  - 元のタスクの `securityFix`（指摘の全件）を引き継ぐ。派生では直す指摘を人が選ぶので、全件を渡すと選んでいない指摘まで
    直させてしまう。

## 影響

- 1つのタスクから作った続きのタスクは、元のタスクの詳細に並び、続きのタスクの詳細から元のタスクへたどれる。
- 続きのタスクの説明は、元のタスクの記録の分だけ長くなる（成果は1件 6000 文字まで）。
- 続きのタスクを中止して再実行するときは、人が直す説明から元のタスクの記録を除き、記録は sacty が付け直す（記録を含めた説明は、人の入力の上限を超えうるため）。境目を見出しで探すと、成果の本文の見出しと衝突するので、足した記録の本文を `derivedFrom` に持ち、その本文をそのまま除く。再実行のタスクも `derivedFrom` を引き継ぐ（元のタスクがいま完了していなくても）。
- 仕様は [タスクと工程](../spec/tasks-and-steps.md) の「完了したタスクから続きのタスクを作る（派生）」、利用者向けは [タスクを進める](../user/tasks.md) に書く。
