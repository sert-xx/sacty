# 既定のレビューの観点ごとの段階を下げ、expert も既定で使わない

- 日時: 2026-11-14 13:54 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-344
- 置き換え元: [横断の観点 X-1 を expert で動かし、ultimate は既定で使わない](20261104-2323-superseded-cross-cutting-viewpoint-on-expert-tier.md)（X-1 を expert で動かすとした部分）
- 置き換え先: なし

## 背景

既定の review スキルは、観点 1 つにつき担当（サブエージェント）を 1 つ起動する。
コードの初回のレビューでは、必須観点 8 つと横断の X-1・X-2 の、少なくとも 10 の担当が動く。
そのうち 5 つ（X-1 が `expert`、C-1・C-2・C-3・C-17 が `advanced`）が、上位のモデルで動いていた。
ステークホルダーから、レビューの AI の使用量が大きいという指摘があった。

## 決定

起動の規則（どの観点を起動するか・再レビューでの絞り方）は変えず、観点ごとの段階だけを下げる。ステークホルダーの決定（2026-11-14）。

| 観点 | 変更前 | 変更後 |
| --- | --- | --- |
| X-1 横断（欠陥探索） | `expert` | `advanced` |
| C-2 堅牢性・エラー処理 | `advanced` | `standard` |
| D-3 完全性 | `advanced` | `standard` |
| D-5 セキュリティ・規定 | `advanced` | `standard` |
| C-5 保守性・設計 | `standard` | `entry` |
| C-15 簡潔さ・範囲 | `standard` | `entry` |
| D-4 検証可能性 | `standard` | `entry` |
| X-2 検証結果の分析 | `standard` | `entry` |
| X-3 リポジトリの指示への準拠 | `standard` | `entry` |

- 表に無い観点の段階は変えない。
- `expert` は、既定の観点のどれにも割り当てない。段階と既定のエージェントの `codex_expert`・`claude_expert` は残す（`ultimate` と同じ扱い）。

## 理由

- `advanced` に残すのは、深く読まないと見落とす観点（正しさ・セキュリティ・並行・データ・方針・設計の整合）と、見る範囲の広い X-1・R にした。
- `standard` に下げた観点（C-2・D-3・D-5）は、失敗時の経路や「書かれているか」を確かめる観点で、`advanced` の観点ほどの推論は要らないと判断した。
- `entry` に下げた観点（C-5・C-15・D-4・X-2・X-3）は、規約・決まり・検証の結果との照合や、型の決まった検出が中心と判断した。
- X-1 は、再レビューでも毎回起動するので、下げたときの使用量への効きが大きい。
- 比べた案：
    - X-1 を `expert` のままにする：カタログの漏れを拾う観点なので残す案を出したが、ステークホルダーが `advanced` に下げると決めた。
    - C-17・R を `standard` に、X-2 を `lite` に下げる：方針の誤りの見逃しは直しの往復を増やし、R はスキルの範囲が広いと見落としが増え、X-2 は複雑な失敗で原因を取り違えうるので、採らなかった。
- 下げた段階で見落としが増えないかは、測っていない。使用量がどれだけ減るかも測っていない。

## 影響

- コードの初回のレビューで必ず動く担当は、`advanced` 4（C-1・C-3・C-17・X-1）、`standard` 3（C-2・C-4・C-6）、`entry` 3（C-5・C-15・X-2）になる。
- 既定のままでは、`expert`・`ultimate` のサブエージェントの定義は置かれるが、どの観点からも起動されない。人が `step_agents` やタスクの工程のエージェントで選べば使える。
- 見落としが増えた観点が分かったら、その観点の段階を戻す。
- プロジェクトのコンテキストリポジトリで `review-dispatch` を差し替えているプロジェクトには、効かない。
