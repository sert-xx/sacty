# タスクの作成時に、進め方の工程ごとのイメージとエージェントを指定でき、ダイアログの中の別の画面で選ぶ

- 日時: 2026-10-28 00:49 UTC
- ステータス: 採用
- 関係する PR・タスク: #241
- 置き換え元: なし
- 置き換え先: なし

## 背景

工程ごとのイメージとエージェントは、タスクを作った後にタスクの詳細で変えられる（[工程のイメージ](20261015-1115-superseded-change-step-image.md)・[工程のエージェント](20261017-0005-step-agent-override.md)）。
作るときから決まっている（Java のリポジトリの実装は Java のイメージ、難しい設計だけ強いエージェント、など）ときも、作った後に工程が決まるのを待って
変える必要があり、最初の実行が合わないイメージ・エージェントで動くことがある。
タスクの作成のダイアログには、テンプレート・対象リポジトリ・進め方・題・内容があり、工程ごとの選択肢をそのまま足すと長くなり、ふだんの作成
（既定のまま作る）の妨げになる（ステークホルダーの懸念）。

## 決定

- 進め方を指定したときだけ、その工程ごとにイメージとエージェントを指定できる（`CreateTaskInput`・`TaskCreated` の `images`・`agents`）。
  進め方が自動のときは工程が決まっていないので指定させない。統合レビューのエージェントは、タスクの詳細と同じく指定させない。
- 指定はタスクの詳細で人が変えたときと同じ重みで扱う。イメージはプロジェクトの対象の指定・オーケストレーターの選択より、エージェントは
  `step_agents` より優先する。工程の選択からやり直しても、作成時の指定に戻す。作成の後は、タスクの詳細でいつもどおり変えられる。
- 指定したイメージは `StepsChosen` に入れず（オーケストレーターが決めたものだけを記録する）、投影が選んだ工程の分だけ入れる。
  作業履歴の「タスクを作成」の行と、タスクの詳細の選んだ元（「作成時に人が指定」）で、指定がわかるようにする。
- 画面は、ダイアログの中で「基本の入力」と「工程ごとの設定」の2つの画面を切り替える。
  - 基本の入力には、工程の並びと指定の要約（何工程を指定したか・指定した工程の印）と、「工程ごとに設定」のボタンだけを置く。
  - 工程ごとの設定は、工程を行・イメージとエージェントを列にした表にし、列の見出しは1回だけ、説明は選んだ項目にだけ出す。
  - 選択肢（イメージ・エージェントの候補）は、工程ごとの設定を開いたときにだけ読む。

## 理由

- ふだんは既定のまま作るので、工程ごとの選択肢は基本の入力から外し、必要な人だけが開く形にする（段階的な開示）。要約と工程の印で、
  開かなくても何を指定したかがわかる。
- 別のページや別のダイアログにせず、同じダイアログの中で切り替えると、入力中の題・内容を失わず、作成のボタンも1つのままにできる。
  ダイアログの中に折りたたみで足す案は、工程の数（最大4）×2つの選択肢と説明でダイアログが縦に長くなり、題・内容の入力欄が画面の外に出るので採らない。
- 工程ごとのカードに見出し・説明を繰り返す形は、試作の画面で4工程でもスクロールが要ったので、表の形にした。
- 作成時の指定は、作った後にタスクの詳細で人が変えるのと同じ意図なので、同じ優先の順にそろえる。工程の選択からやり直したときに
  消えると、人の指定が黙って失われる。
- 候補を開いたときにだけ読むのは、リポジトリの候補（PBI-109）と同じく、ふだんの作成で余計な問い合わせをしないため。

## 影響

- 状態を返すデーモンの API はそのまま使い、画面に候補を返す `GET /step-options` を足した。
- スケジュールタスクの作成・編集には、工程ごとの設定を足していない（スケジュールタスクの内容の形を変えるため、別の作業にする）。
- 分割で作った子タスクには、親の指定を引き継がない。
- 仕様は [工程とタスク](../spec/tasks-and-steps.md) の「作成時に指定した工程のイメージ・エージェント」に書く。
