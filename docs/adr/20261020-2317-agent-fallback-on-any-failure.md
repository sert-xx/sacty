# エージェントの実行が失敗したら、理由を問わず、agents の fallback に書いた代わりのエージェントでやり直す

- 日時: 2026-10-20 23:17 UTC
- ステータス: 採用
- 関係する PR・タスク: なし
- 置き換え元: [利用制限に達したエージェントは、agents の fallback に書いた代わりのエージェントに切り替えて、止めずに続ける](20261020-1123-superseded-agent-fallback-on-usage-limit.md)
- 置き換え先: なし

## 背景

代わりのエージェント（`agents.<名前>.fallback`）は、実行が利用制限（`usage_limit`）で失敗したときだけ使っていた。認証の失敗
（`auth`）やそのほかのエラー（`error`）では、代わりを書いていてもタスクが一時停止し、人が直して再開するまで進まなかった。
`fallback` を書いた利用者からは、どのような失敗でも代わりのエージェントで自動的にやり直してほしいという要望があった。

また、失敗の理由はエラーの文から正規表現で分けており（`classifyFailure`）、標準エラー出力には通常のログも出るので、理由の分類は
確実ではない。

## 決定

- `fallback` があれば、実行の失敗の理由を問わず（`usage_limit`・`auth`・`error`）、代わりのエージェントでやり直す。やり直すところ（工程・統合レビュー・工程の選択・チケットの読み取り・最終レビュー・ゴールガーディアンの判定）と、
  止めずに `AgentFellBack` を記録する流れは、前の ADR のまま。
- 利用制限の失敗は、これまでどおり、そのエージェントを `agent_fallback.cooldown_minutes` の間、すべてのタスクで使わない。
- それ以外の失敗は、そのエージェントを同じ時間、そのタスクでだけ使わない（デーモンのメモリーだけに持つ）。
- 切り替えの間に試したエージェントは、タスクごとに期限とは別に覚え、期限が過ぎても戻らない。すべて試し終えたら止める。そのタスクの
  実行が成功したとき・人が再開したときに忘れる。
- コンテナが止まったことを確かめられなかった実行（`run.containerNotConfirmed`）は、切り替えずに止める。
- `AgentFellBack` に失敗の理由（`reason`）を足し、作業履歴に「認証に失敗したので」のように出す。理由の無い前の記録は、利用制限として読む。

## 理由

- 失敗かどうかは、終了コードとエージェントの出力（`is_error`・`turn.failed` など）で決まっていて、標準エラー出力の文では決めていない。
  理由を問わずに切り替えれば、切り替えるかどうかは文の分類に左右されない。
- 利用制限でない失敗をすべてのタスクに広げると、タスクの中身による失敗や、エラーの文の誤った分類（たとえば GitHub の `403` を含む文が
  `auth` になる）で、ほかのタスクまで元のエージェントを使わなくなる。そのタスクだけにすれば、影響はそのタスクに閉じる。
- 認証の失敗もそのタスクだけにしたのは、上の誤った分類と区別できないため。本当に認証が切れているなら、ほかのタスクでも失敗して、
  それぞれ代わりに切り替わるだけで、止まりはしない。
- 試したエージェントを期限だけで覚えると、期限が実行の時間より短いとき、元と代わりを交互に試し続け、止まらずに時間と予算を使う。
  試し終えたことを期限とは別に持てば、どちらの理由でも止まる。成功と人の再開で忘れるのは、その時点で元のエージェントを試し直す意味があるため。
- コンテナが止まったことを確かめられないときは、元のエージェントのコンテナが動いたままかもしれない。同じ作業領域で代わりが始めると、
  変更や外への操作が重なりうるので、人が確かめるまで止める。
- 切り替えの条件を設定で選べるようにする案（`agent_fallback.on` など）は、要望が「単純に、どの失敗でも」だったので採らなかった。
  代わりにしたくないエージェントには、`fallback` を書かなければよい。

## 影響

- 代わりのエージェントも失敗したら、これまでどおり一時停止する。`fallback` の無いエージェントの振る舞いは変わらない。
- タスクの中身による失敗でも代わりでもう一度実行するので、失敗した回の費用が増えうる（失敗した実行の費用は、これまでどおり記録する）。
- 書き出し・マージの後の監視・監査・質問への答えは、これまでどおり、その回の失敗を扱い、利用制限のときだけ次の実行から代わりを使う。
- 仕様は [エージェントの実行](../spec/agent-execution.md#失敗したときの代わりのエージェント)・[設定ファイル](../spec/configuration.md) にある。
