# ブラウザのデスクトップ通知を足し、Slack の通知は設定を残したまま止められるようにする

- 日時: 2026-10-26 13:15 UTC
- ステータス: 採用
- 関係する PR・タスク: なし
- 置き換え元: なし
- 置き換え先: なし

## 背景

人間の出番とタスクの完了は、Slack にだけ通知していた。
Slack を使わない人や、Slack を見ていない間には気づきにくい。
sacty の画面はブラウザで開いて使うので、ブラウザのデスクトップ通知でも知らせてほしいという要望があった。

また、Slack の通知を止めるには、送り方で「通知しない」を選ぶしかなく、そのまま保存すると送り先・メンションの設定が消えた。
一時的に止めて、後で同じ設定で戻すことができなかった。

## 決定

- Slack の通知先（sacty の設定の `notification`）に `off` を足す。
  `true` なら送らず、送り先などの項目は残す。
  送れなかった理由も出さない。
  テストの通知は `off` でも送る。
- デスクトップ通知を足す。
  - 通知する種類と条件は Slack と同じ（`notificationFor`）。
    Slack の送り先・`off` によらない。
  - デーモンは最近の通知（100 件まで）に番号を付け、タスクの題名とプロジェクトと一緒にメモリーに持ち、`GET /api/notifications?after=<番号>` で返す。
  - 画面は、どのページでも、5秒ごとに取り直してデスクトップ通知を出す。
    タブが隠れている間も取り直す。
  - On/Off は、ブラウザごとに `localStorage` に持つ（sacty の設定には保存しない）。
    既定は Off。
    On にするときに通知の許可を求める。

## 理由

- Slack の Off を、送り方の選択肢ではなく別の項目にしたのは、止めても送り先・メンションの入力を残すため。
  ほかの設定（`triageOff`）と同じく、送るとき（既定）は項目を持たないので、これまでの設定はそのまま On として動く。
- デスクトップ通知の On/Off をブラウザごとにしたのは、通知の許可がブラウザごとで、sacty の設定に持っても、許可していないブラウザでは出せないため。
  複数のブラウザで画面を開いていても、出したいブラウザだけで出せる。
- デーモンからブラウザに直接知らせる（SSE・Web Push）案もあった。
  - SSE は、画面のサーバーを通す経路とつなぎ直しの扱いが増える（[画面のデータの取り直し](20261015-1349-refetch-screen-data.md) でポーリングにしたのと同じ理由）。
  - Web Push は、画面を閉じていても届くが、Service Worker と外部の Push サービスが要り、ローカルで動く sacty には重い。
  このため、画面を開いている間だけ届く、ポーリングにした。
- 画面の取り直しは、タブが隠れている間は止めている（[画面のデータの取り直し](20261015-1349-refetch-screen-data.md)）。
  デスクトップ通知は、ほかの作業をしている間に気づくためのものなので、隠れている間も取り直す。
  取り直す内容は小さい（前に受け取った番号より後の通知が無ければ空）。
- 通知を作業履歴から組み立て直さず、メモリーに持つことにしたのは、通知の判断（`notificationFor`）を Slack と同じ1か所にするため。
  デーモンを起動し直すと、それまでの通知は出さない（画面は起動し直したことを `boot` で知り、その後の通知から出す）。
  題名とプロジェクトも一緒に持つのは、画面が通知を出すためにタスクを取り直さないため（タスクの一覧は成果物を含み、大きくなりうる）。
  題名は通知したときのものになる。

## 影響

- デスクトップ通知は、sacty の画面をどれかのタブで開いている間だけ届く。
  閉じていた間の通知は出ない。
- ブラウザは https か localhost の画面でだけ通知を出せる。
  それ以外の URL で開いた画面では使えない。
- 仕様は [通知](../spec/notifications.md)、利用者向けは [通知（Slack・デスクトップ）](../user/notifications.md) に書く。
