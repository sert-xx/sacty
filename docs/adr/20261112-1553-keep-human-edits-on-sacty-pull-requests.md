# 人が sacty の PR に足したコミットを作業領域に取り込み、人が直した PR の本文を3方向でマージして残す

- 日時: 2026-11-12 15:53 UTC
- ステータス: 採用
- 関係する PR・タスク: #354（PBI-334）
- 置き換え元: [タスクブランチに sacty が積んでいない変更があれば、実装を積まずに止め、人の変更を自動では取り込まない](20261013-1318-superseded-stop-on-unexpected-task-branch-changes.md)（sacty が実装を積んだ後に人が足した変更を、止めて取り込まない部分）
- 置き換え先: なし

## 背景

sacty が作った PR を、レビューの指摘で直して更新するとき、その前に人が PR に手を入れていると、次の問題が起きていた。

- 人が PR のブランチにコミットを足していた（レビューの提案の適用・GitHub の画面でのベースブランチの取り込みなど）と、sacty は
  前にプッシュした自分のコミットの上に積むので、早送りでないプッシュになって失敗した（強制プッシュはしない）。タスクブランチに
  積むタスクは、sacty が積んでいない変更を見つけて止まった（`pr.taskBranchChanged`）。どちらも、実装の作業領域に人の変更が
  入っていないので、仮に親だけを人の先頭にしても、人の変更を消すコミットになる。
- 人が PR の本文を補足・整形していても、sacty は更新のたびに組み立て直した本文で丸ごと上書きしていた。

人が、次のように決めた（2026-11-12）。

- 人が足したコミットは、作業領域に取り込む（止めて人に任せるのではなく）。
- PR の本文は、最新の本文を読み、その内容を加味して作り直す。方法は、3方向のマージで重ならない編集を両方残し、同じ箇所が
  重なったときだけ AI にまとめさせる（毎回 AI に書き直させる案・AI を使わずに人の版を残す案ではなく）。

## 決定

- 人が足したコミットの取り込み
  - 実装の実行の前・PR を出す前・PR を出す直前に、sacty が最後にプッシュした
    ブランチの先頭を読み、sacty が最後にプッシュしたコミットと違えば、そのコミットを共通の祖先にして、作業領域の内容と先頭を
    3方向でマージする（ベースブランチの取り込みと同じ `mergeBase`）。タスクブランチから引き継ぐ要求要件・設計のファイルは、
    マージから外す。
  - `PullRequestHeadMerged` に記録し、次の提出は取り込んだ先頭を親にして積む（早送りでプッシュできる）。
  - 競合したら、ベースブランチとの競合と同じく、実装のエージェントに目印を解消させる（人の側を残すよう指示する）。
    エージェントの誤りではないので、検証に通らなかった回数には数えない。
  - 実装の指示に、人の変更を消さないことを伝える。
  - 既存の PR を引き継ぐタスクは、もともと人の PR のブランチに積むので、対象にしない。
- 人が直した本文の扱い
  - PR を作った・更新したら、sacty がその回に組み立てた本文を `PullRequestBodyWritten` に記録する（人の直しを含まない版）。
  - 更新するときは、記録した前回の版を共通の祖先にして、GitHub の今の本文と新しく組み立てた本文を、行の単位で3方向にマージする
    （`git merge-file`）。重ならなければその結果にする。
  - 重なったら、オーケストレーターのエージェントに、4つの本文をデータとして渡してまとめさせる（`PullRequestBodyResolved`。
    費用はタスクの予算に入れる）。まとめられなければ、人の本文のまま変えない（PR の更新は止めない）。
  - 前回の記録が無い（この決定より前に書いた本文）・今の本文を読めないときは、これまでどおり上書きする。

- 置き換える決定：[タスクブランチに sacty が積んでいない変更があれば、実装を積まずに止め、人の変更を自動では取り込まない](20261013-1318-superseded-stop-on-unexpected-task-branch-changes.md)
  のうち、sacty が実装を積んだ後（出し直し）に人が足した変更は、止めずに取り込む。sacty がまだ実装を積んでいない（初めて積む）ときに
  タスクブランチへ人が積んだ変更は、これまでどおり止める（作業領域の起点と、人の変更の関係が分からないため）。
- 旧 ADR が自動で取り込まなかった理由（テストで確かめていないコードが PR に混ざる）は、今は sacty が最終レビューをせず、PR の
  レビューの子タスクが PR の先頭（人の変更を含む）をレビューするので、当てはまらない（[実装の最終レビューと CI の待ちをやめた](20261112-0714-review-child-task-replaces-final-review-and-ci-wait.md)）。

## 理由

- 人が足したコミットは、人がレビューの中で意図して入れた変更である。止めて人に直させると、レビューの提案を適用するたびに
  人の手が要る。sacty はすでにベースブランチを同じ仕組み（作業領域への3方向のマージと、目印の解消をエージェントに任せること）で
  取り込んでいるので、同じ仕組みを使えば、新しい仕組みを足さずに、強制プッシュもせずに済む。
- 共通の祖先を「sacty が最後にプッシュしたコミット」にすると、人の変更だけが「相手の側の変更」になり、実装の変更とベースブランチの
  取り込みを壊さない。
- 本文の3方向のマージの共通の祖先を、GitHub に書いた本文ではなく sacty が組み立てた本文にするのは、GitHub に書いた本文を祖先に
  すると、人が前に足した補足が次の更新で「人の直しなし」と見なされ、消えるため。
- 毎回 AI に書き直させる案は、更新のたびに実行の費用と時間がかかり、結果も毎回ぶれる。AI を使わずに人の版を残す案は、sacty の
  事実の更新（テストの結果・レビューの状況など）が本文に入らなくなる。重なったときだけ AI を使えば、多くの更新は AI を使わず、
  予測しやすいまま、重なったときも両方を生かせる。

## 影響

- 作業履歴に `PullRequestHeadMerged`・`PullRequestBodyWritten`・`PullRequestBodyResolved` が増える。`PullRequestBodyWritten` は
  本文の全文を持つので、タスクの一覧の API では送らない。
- 前回の版の記録がある PR を更新する前に、GitHub から PR の本文を1回読む（記録が無ければ読まない）。エージェントがまとめたときは、
  書き込む前に人がまた直していないか確かめるため、もう一度読む。読めなかったときに上書きしたことは、作業履歴に残す。
- 人のコミットと競合したときは、実装をやり直す（実行の費用がかかる）。PR を出す直前に競合したときも、PR を出さずにやり直す。
- 本文の行の単位のマージは、人の直しと sacty の更新が近い行にあると重なりやすい。重なったときは AI の費用がかかる。AI が
  まとめられないときは、人の本文のまま、その回の sacty の更新が本文に入らない（次の更新で、もう一度取り込む）。
