# MCP サーバーごとに起動とツールの呼び出しの時間切れを秒で書け、各エージェントとゲートウェイにそれぞれの形で効かせる

- 日時: 2026-10-14 04:58 UTC
- ステータス: 採用
- 関係する PR・タスク: #82、PBI-75
- 置き換え元: なし
- 置き換え先: なし

## 背景

MCP サーバーの起動やツールの呼び出しにかかる時間は、エージェントの CLI とゲートウェイの既定の待ち時間で決まっていて、
サーバーごとに延ばす手段が無かった。エージェント（Claude Code・Codex）ごとに設定の形が違い、ゲートウェイの中継にも別の上限があった。
エージェントの実行全体には、開始から30分の上限がある。

## 決定

- `mcp.yaml` の各サーバー（`command`・`url`）とホストの `gateway.mcp_servers` に、`startup_timeout_sec`（1〜3600 秒）・
  `tool_timeout_sec`（1〜86400 秒）を任意で書ける。整数で、範囲の外は場所つきの設定の誤りにする。
- Codex には `config.toml` の `mcp_servers.<名前>` に同じ名前で渡す。
- Claude Code には、ツールの呼び出しをサーバーごとの `timeout`（ミリ秒）で渡す。起動はサーバーごとの設定が無いので、全体の `MCP_TIMEOUT` に、
  書いた値と書いていないサーバーの既定（30秒）の大きい方を渡す。どのサーバーにも書かなければ渡さない。この扱いを README に書く。
- ゲートウェイ経由のコンテキストの MCP は、書いた値が中継の既定（5分）を超えるときだけ、待つ上限を延ばした接続（undici）で中継する。
  ホストの MCP は、中継のツールの呼び出し・一覧を書いた値より先に切らない（既定より短くはしない）。
- 時間切れの値だけを変えたときは、ホストの MCP サーバーを起動し直さない。
- 書いていないときの出力・動作は変えない。
- 実行全体の上限（30分、`AGENT_RUN_TIMEOUT_MS`）は変えない。MCP の時間切れが上限以上なら、設定の誤りにはせず、コンテキストを用意するときに
  警告 `context.mcpTimeoutOverRun` を作業履歴に残す。
- `default_tools_approval_mode` は足さない。

## 理由

- 各エージェントへの渡し方は、手元の CLI の本体で確かめた設定の形に合わせた（Codex の `codex mcp list --json`、Claude Code の設定のスキーマと
  `claude mcp get`・`MCP_TIMEOUT` の処理。PR の本文）。
- Claude Code の `MCP_TIMEOUT` を大きい方にしたのは、書いていないサーバーの待ち時間を既定より短くしないため（PR の本文）。
- 時間切れだけの変更で起動し直さないのは、ブラウザの再認証を起こさないため（PR の本文）。
- undici を依存に足して undici の fetch と組にしたのは、Node 22 の組み込みの fetch に外の Agent を渡すと版の違いで動かないことがあるため（PR の本文）。
- 上限以上の値を誤りにせず警告にしたのは、上限は実行の側の値で後で調整できるようになることもあり得るので、正しく書けている設定を誤りにしないため
  （レビューへの返信）。レビューでは、実行全体の上限を調整できるようにする案も挙がったが、このときは上限を変えず、明記と警告にした。
- `default_tools_approval_mode` を足さないのは、ステークホルダーの判断（PR の本文）。

## 影響

- MCP の時間切れを30分以上にしても、実行全体の上限で止まる（作業履歴に警告が出る）。
- `apps/daemon` が `undici` に依存する。
- Claude Code では起動の時間切れがサーバーごとに効かず、全体の値になる。
