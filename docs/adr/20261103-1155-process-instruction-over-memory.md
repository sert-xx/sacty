# メモリーは参考とし、手順が工程の指示と食い違うときは、工程の指示を優先させる

- 日時: 2026-11-03 11:55 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-297
- 置き換え元: なし
- 置き換え先: なし

## 背景

実験 S14 の3回目で、要求要件の直しの指示は「前回の下書きを元に、指摘に関わる所だけ書き換える」「本文に作業の経過・前の版との違いを書かない」と決めていた。
ところがエージェントは、プロジェクトのメモリーの手順（前の指摘が取り下げられたら、前の版をコミットから取り出して戻す）に従い、1回目の版を丸ごと戻した。
消したはずの期間の上限が復活し、本文に変更のメモが入り、ゴールガーディアンの判断（決定を変えない）とも食い違った（findings F40）。

メモリーを渡す指示には、メモリーは「人の指示・コンテキストの規則とスキル・AGENTS.md などより優先度が低い」とあった。
しかし、その一覧に、そのタスクの工程の指示（直す範囲・本文に書かないこと・判断の結果の扱い）は挙がっていなかったので、エージェントは、メモリーの手順を工程の指示より優先した。

## 決定

- **工程の指示を、メモリーより優先するものとして名指しする**：メモリーを渡す指示、メモリーを読むスキル `memory`、メモリーの索引のいずれにも、メモリーは参考であり、工程の指示（直す範囲・書くこと・書かないこと・判断の結果の扱いなど）と食い違う手順は使わず、工程の指示に従うことを書く。メモリーは、調べる手がかりとしてだけ使う。
- **登録のとき、工程の指示を変える手順を書かせない**：深掘りの登録の決まりに、事実・落とし穴・調べ方・手がかりを書き、工程の指示を変える手順は書かない（書くなら、食い違うなら使わないことを添える）ことを足す。
- 書き方は、特定の言語・ツールに寄せない。メモリーを使わない場面の指示は変えない。

## 理由

- 食い違いを起こしたのは、優先の一覧に工程の指示が無かったこと。一覧に名指しすれば、手順が書かれたメモリーを読んでも、エージェントは、どちらに従うかを指示から決められる。
- 読むときの優先と、登録のときの決まりの両方に入れる。読むときだけだと、手順入りのメモリーが溜まり、エージェントの判断に頼り続ける。登録だけだと、既に登録された手順が残る。

## 影響

- 登録で、手順の中身を機械的に判定する手立ては入れない。「工程の指示を変える手順」かどうかは、タスクごとの工程の指示との関係で決まり、メモリーの文面だけでは判定できない（判定を誤ると、有用な知見を捨てる）。登録の決まりは監査への指示にとどまり、守りの本体は読むときの優先である。
- 既に登録された手順入りのメモリーは、そのまま残る。人は監査のタブから消せる。
