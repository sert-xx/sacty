# 子タスクがすべて片付いた親は、ゴールガーディアンの統合レビューを通り、人間が承認してから完了にする

- 日時: 2026-10-12 07:18 UTC
- ステータス: 採用
- 関係する PR・タスク: #37、PBI-31
- 置き換え元: [大きなタスクを「タスク分割」の工程で子タスクに分け、子ごとに PR を作って依存の順に進める](20261012-0226-superseded-task-split-into-subtasks.md)（子が片付いたら親を完了にする部分）
- 置き換え先: なし

## 背景

#33 で足したタスク分割では、子タスクがすべて片付くと親がそのまま完了していた。子ごとの PR が個々に正しくても、
まとめた結果が親の要求要件を満たすかを確かめる段が無かった。

## 決定

- タスク分割の組み合わせに、統合レビューの工程（`integrate`）を足す（調査 → 要求要件 → 設計 → タスク分割 → 統合レビュー）。
  子タスクがすべて片付く（完了・中止を認めた）と、親は完了にならず統合レビューへ進む。
- 統合レビューはゴールガーディアンが新しいセッションで行う。子の PR がマージされた後のベースブランチの最新のコードを
  読み取り専用で読み、親の承認済みの要求要件・設計・テスト観点、子タスクの一覧（PR・中止を認めたもの）、人間の過去の指摘から判定する。
  読んだコミットを記録する（`IntegrationReviewed`）。
- 合格したら統合レビューの承認待ちにし、人間が承認すると親が完了する。
- 不合格なら、タスク分割の工程をやり直して、指摘をもとに修正の子タスクを追加し（1件から）、片付いたら統合レビューをやり直す。
  続けて3回不合格なら、不合格のまま承認待ちにして人間に上げる。
- 承認待ちで差し戻すと、指摘をもとに修正の子タスクを追加する。合格を差し戻したら見逃しとして記録する。
- 実行できない（ベースブランチを取得できない・利用上限など）ときは、理由を記録して止め、再開でやり直す。費用は親の予算に入れる。
- この変更より前に分割したタスク（工程に統合レビューが無い）は、これまでどおり子の完了で完了する。

## 理由

- 構想の、親の完了条件（すべての子が完了し、かつ親の統合の観点による最終レビューを通ったとき）を実装するため（PR の本文）。
- 不合格のときの続け方・3回の上限・合格の後の人間の承認はステークホルダーが、ゴールガーディアンが新しいセッションで最新のコードを
  読むことは PO が決めた（PR の本文）。それぞれを選んだ理由と、比べたほかの案は記録に無い。

## 影響

- 親の完了には、人間の承認が1回要るようになる。
- 画面に、統合レビューの結果（合否・読んだコミット・観点ごとの判定・足りないこと・所見）と、修正の子タスクの印を出す（日本語・英語）。
- 2回目以降の分割は、子タスクを追加する形になる。
