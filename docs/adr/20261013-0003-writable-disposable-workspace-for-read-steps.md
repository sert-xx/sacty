# 調査・要求要件・設計などの工程には、書き込める使い捨ての写しを渡し、コードの変更だけをさせない

- 日時: 2026-10-13 00:03 UTC
- ステータス: 採用
- 関係する PR・タスク: #46、PBI-40
- 置き換え元: [対象リポジトリはタスクの開始時に clone して起点のコミットを固定し、要求要件・設計の工程には起点のコードを読み取り専用で渡す](20261010-2354-superseded-repository-snapshot-for-planning.md)（要求要件・設計の工程に読み取り専用で渡す部分）
- 置き換え先: なし

## 背景

調査・要求要件・設計・オーケストレーター・ゴールガーディアンには、起点（や実装後）のコミットのコードを実行ごとの写しにして、
読み取り専用で渡していた。対象リポジトリの AGENTS.md に「最初に npm run setup を実行する」などの手順があると、それが失敗して止まっていた（利用者の環境で発生した）。

## 決定

- これらの工程の写しを、書き込める形で渡す。写しはこれまでどおり実行ごとに作って消す。
- 指示は「セットアップやテストなどのコマンドは実行してよいが、コードの変更（実装）はしない」にする。

## 理由

- 写しは実行ごとに作って消すので、書き込める形で渡しても変更は残らず、実装の作業領域にも影響しないため（コミット）。

## 影響

- 調査・要求要件・設計などの工程でも、対象リポジトリの手順（例：最初に `npm run setup`）を実行できる。
- これらの工程でエージェントがファイルを書いても、実行の後に消える。
