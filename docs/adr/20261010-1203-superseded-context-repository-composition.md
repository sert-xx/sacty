# コンテキストリポジトリを中立形式で書き、extends の継承を合成して、実行ごとに空の設定のディレクトリへ Claude Code・Codex の形式で置く

## 背景

工程エージェントに、規約やスキルを渡す手段が無かった。親のリポジトリを継承して規約・スキルを重ねられること、Claude Code と Codex の
どちらにも渡せること、ホストの設定や組み込みのメモリーに影響されないことが必要だった。PBI-6 は大きいため2つに分け、この PR（PBI-6a）では
継承・規約・スキルを、続く PR（PBI-6b）では MCP の設定と秘密情報を扱う。

## 決定

- 中立形式：コンテキストリポジトリには、`sacty-context.yaml`（`extends`・`locked.skills`・`remove.skills`）、規約（`rules.md` か `rules/*.md`）、
  スキル（`skills/<名前>/SKILL.md`）を置く。どれも省略できる。
- プロジェクトの設定に、コンテキストリポジトリ（git の URL かローカルのパスと ref）を持たせ、エクスポートの対象にする。
- 継承：指定したリポジトリから `extends`（`URL#ref`）をたどって浅く clone し、上位から順の層にする。clone はホストの git の認証を使う。
  循環（同じリポジトリと ref が2度出る）・10段を超える・取得できない・設定の誤りのときは、理由を記録して止める。
- 合成：規約は、層ごとの見出し（リポジトリ@コミット）を付けて上位から連結する。スキルは名前ごとに下位が上書きする。
  上位で上書き禁止（`locked`）にしたスキルは、下位で上書きも取り除き（`remove`）もできず、上位のものを使って台帳に注意を残す。
- 配置：工程エージェントの実行ごとに合成し、Claude Code には空の `CLAUDE_CONFIG_DIR` に `CLAUDE.md` と `skills/<名前>/` を、Codex には空の `CODEX_HOME` に
  `AGENTS.md` と `skills/<名前>/` を置く。Codex の `AGENTS.md` には、各スキルの説明と `SKILL.md` の場所を並べる。対象リポジトリの作業領域には置かない。
  設定のディレクトリは、実行が終わったら消す。
- 組み込みのメモリーは使わない（Claude Code は `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`、どちらも設定のディレクトリを実行ごとに空から作る）。
- 実行ごとに、使ったコンテキストの層（リポジトリ・ref・コミット）と合成で気づいたことを `ContextResolved` として台帳に記録する。
- ゴールガーディアン（変更の申し出の判定・最終レビュー）には、コンテキストを渡さない。

## 理由

- 作業領域に置かないのは、コミットに混ざらないようにするため（PR の本文）。
- Codex の `AGENTS.md` にスキルを並べるのは、Codex にスキルの仕組みが無いため（PR の本文）。
- ゴールガーディアンに渡さないのは、決めた情報だけで判定するため（PR の本文）。
- 設定のディレクトリを実行ごとに空から作るのは、ホストの設定やメモリーを読まず、実行をまたいで残らないようにするため（PR の本文）。
- 規約を連結しスキルを下位で上書きする合成の規則、継承の深さの上限（10段）を選んだ理由は記録に無い（受け入れ条件として書かれている）。

## 影響

- プロジェクトごとに、規約・スキルを継承で重ねて工程エージェントに渡せる。
- 台帳から、どの実行がどのコミットのコンテキストを使ったかを追える。
- 実行ごとに継承をたどって clone するので、コンテキストリポジトリの取得に失敗するとタスクが止まる。
