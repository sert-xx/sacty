# 監査が登録したメモリーを、作業履歴を正本にして、スキルの索引の形で書き出す

- 日時: 2026-10-18 01:30 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-126
- 置き換え元: なし
- 置き換え先: なし

## 背景

構想ドキュメントの柱の1つ「メモリー（エージェントが運用の中で学んだこと）」が無かった。監査（PBI-125）は差し戻しや試行錯誤の原因を
見つけるが、その知見は改修の提案にしかならず、次のタスクのエージェントには直接届かない。ステークホルダーと決めた方針は次のとおり。

- メモリーは `~/.sacty` の下に置き、プロジェクトとリポジトリの2階層で持つ。グローバルの階層は持たない（すべてのプロジェクトで読まれ、
  組織をまたいで情報が漏れる経路になるため）。
- リポジトリのメモリーは `~/.sacty/memory/repos/<リポジトリ>` に置く（プロジェクトの下に置くと、プロジェクトの設定次第で変わってしまうため）。
- スキルの索引の形にし、不要なメモリーを展開してコンテキストを汚さない。
- メモリーを登録するのは監査だけ。

## 決定

- **正本**：作業履歴を正本にする。登録は深掘りの結果（`AuditDeepDived` の `memories`）に、削除は `AuditMemoryDeleted` に記録し、
  どちらもメモリーを登録した監査のタスクの作業履歴に追記する。`~/.sacty/memory` のファイルは、デーモンが作業履歴から書き出すもので、
  起動のときにも書き直す。
- **書き出しの形**：階層ごとに `SKILL.md`（各行は題・概要・有効な最終利用日へのリンクだけ）と、`references/<ID>.md`（1件ずつの中身）。
  ディレクトリは置き換えず、中のファイルを一時ファイルから置き換える。
- **書くのは sacty**：監査の AI には構造化した出力で出させ、sacty が検査・秘密情報の伏せ・ID の付与をしてから書く。AI にファイルを
  書かせない。
- **渡す範囲は仕組みで決める**：工程（統合レビューを除く）と手直し、監査の実行に、タスクのプロジェクトと対象リポジトリの階層だけを
  読み取り専用でマウントする。どれを開くかはエージェントが索引から判断するが、ほかのプロジェクト・リポジトリの階層は見えない。
- **ゴールガーディアンには渡さない**：判定・最終レビュー・統合レビューの材料は、承認済みのものに限る（構想の公正さの原則）。
- **件数の上限**：階層ごとに 30 件。超えたら、有効な最終利用日の古いものから消し、消したことを記録する（いつも読まれる索引を大きく
  しない）。
- **人は消すだけ**：監査の欄に、その監査が登録したメモリーを出し、人は誤ったものを消せる。登録はできない。

## 検討した案

- **ファイルだけを正本にする**：作業履歴に残らず、誰がいつ何を登録・削除したかを追えない。登録と書き出しの間で止まったときに直せない。
- **作業履歴に別のイベント（登録）を足す**：深掘りの結果と別の追記になり、間で止まると、深掘りは記録されたのにメモリーが無い状態に
  なる。深掘りの結果に含め、1つの追記にした。
- **上限に達したら新しい登録をやめる**：古くて役立たないメモリーが残り、新しい知見が入らない。古いものから消すことにした。
- **リポジトリのメモリーをプロジェクトの下に置く**：同じリポジトリでも、プロジェクトの設定を変えると知見が引き継がれない。
  プロジェクトの外に置き、プロジェクトに固有のことを書かないよう監査に指示することにした。

## 結果

- 監査で見つかった知見が、改修の PR を待たずに次のタスクに届く。
- 記録が作業履歴にあるので、監査の画面で登録・削除を追える。ファイルが壊れても、起動のときに直る。
- 有効な最終利用日の更新と、期限での掃除は PBI-127、階層の移動とコンテキストへの昇格は PBI-128 で扱う。
