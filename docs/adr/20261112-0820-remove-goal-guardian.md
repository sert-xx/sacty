# ゴールガーディアンを撤去し、変更の申し出は人が判断し、統合レビューは統合レビューの工程のエージェントが行う

- 日時: 2026-11-12 08:20 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-333
- 置き換え元: [子タスクがすべて片付いた親は、ゴールガーディアンの統合レビューを通り、人間が承認してから完了にする](20261012-0718-superseded-parent-integration-review.md)（統合レビューをゴールガーディアンが行う部分）
- 置き換え先: なし

## 背景

[実装の最終レビュー（テストの実行）と PR の CI の待ちをやめた](20261112-0714-review-child-task-replaces-final-review-and-ci-wait.md)・[PR の指摘の戻し先をレビューの子タスクと工程のエージェントが決めるようにした](20261112-0748-review-child-task-decides-rework-target.md)後も、ゴールガーディアンには次の役割が残っていた。

- 承認済みの要求要件・設計の変更の申し出（`CP-<番号>`）の判定
- タスク分割の親の統合レビュー（`step_agents.integrate` が無いとき、`guardian_agent` の AI で行う）

ステークホルダーから、ゴールガーディアンという別の判定役の仕組みそのものをなくしたいという要望があり、人が次のように決めた（2026-11-12）。

- 変更の申し出は、人が判断する。
- 統合レビューは、統合レビューの工程（`integrate`）のエージェントで続ける。

## 決定

- 工程のエージェントが変更の申し出をしたら、AI の判定を挟まずに、タスクを人の判断待ちにする（`TaskEscalated` の
  `reason: change_proposed`、actor `sacty`）。人がタスクの詳細で認める・認めないを選び、その後の扱い（成果物の置き換え・再承認・
  申し出た工程の成果物の提出）は今までと同じ。
- 統合レビューは、`step_agents.integrate` があればその AI、無ければ `default_agent` で、統合レビューの工程のエージェントとして
  行う（作業履歴の actor は `agent`）。判定の仕方・不合格のときの扱いは今までと同じ。
- 設定の `guardian_agent` は使わない。書いてあっても起動に失敗させず、読み捨てて、画面の設定の警告に出す
  （`config.guardianAgentIgnored`）。`audit_agent` を書かなければ、監査は `default_agent` を使う（今までは `guardian_agent`）。
- 実装後のコードの読み取り専用の写しは `workspaces/_code-copy` に作る（今までの `_guardian` は作らない）。残っている `_guardian`
  は、起動のときの片付けで消す。
- 画面・文言（日英）・費用の内訳・作業履歴の表示から「ゴールガーディアン」をなくす。古い作業履歴にあるゴールガーディアンの
  実行・判定・費用（actor `guardian`、`ChangeJudged` など）は、台帳を書き換えずにそのまま読み込み、以前の版の記録として出す。
- 最終レビューの仕組み（依存 `finalReview` を有効にしたときだけ動く、以前の版のもの）は、この決定では消さず、別の変更で消す。

## 理由

- 変更の申し出は、承認済みの決定を変えるかどうかの判断で、もともと承認した人が決めるのが筋である。AI の判定を挟むと、
  判定の誤り（認めるべき申し出の却下・不要な変更の承認）を人が後から見つけて直す手間が増える。
- 統合レビューは工程として残すので、担い手も他の工程と同じく工程のエージェントにそろえると、設定（`step_agents`）と費用の内訳が
  分かりやすい。
- 古い設定ファイルで起動に失敗すると、利用者が版を上げただけで使えなくなるので、読み捨てて警告にとどめる。

## 影響

- 変更の申し出のたびにタスクが止まり、人の判断を待つ（AI が判定して先へ進むことは無くなる）。
- `guardian_agent` で統合レビュー・監査に別の AI を指定していた利用者は、`step_agents.integrate`・`audit_agent` に書き直す必要がある
  （書き直さなければ `default_agent` になる）。
- 以前の版の判定（`ChangeJudged`）を待っていたタスクは、人の判断待ちとして扱う。
