# 入口を足す・変える変更では、差し替えない実行を実装の説明に書かせ、差し替えた道には差し替えないテストを求める

- 日時: 2026-11-21 19:00 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-451
- 置き換え元: なし
- 置き換え先: なし

## 背景

PBI-399 で足した MCP の道具は、時計を差し替えたテスト 28 件がすべて通り、PR のレビューも破綻を見つけなかった。
しかし、本物の時計は小数を返し、期限を整数でしか受けない部品（`AbortSignal.timeout` など）が小数で失敗したので、本物では最初の数回の呼び出しで必ず失敗した。
見つけたのは、人が PR の版をビルドして 1 回呼んだときだった。
C-4 の「モックが実装を置き換えすぎ」「統合の穴」には、差し替えた部品が返す値の形と本物の違い（境目）の名指しも、差し替えない実行の記載を確かめる手順も無かった。

## 決定

- 実装・修正の「提出の前の検証」に、行を 1 つ足す。入口を足す・変える変更だけが対象で、ビルドした成果物（ビルドが無ければ配る形のまま）で、その入口を差し替えずに 1 回以上動かし、動かした入口・動かし方・結果を実装の説明に書かせる。差し替えたテストの実行は数えない。動かせなければ理由を書かせる。
- 安全のため、外部への書き込み・削除・送信・課金を伴う入口と本番の資源に触れる入口は動かさせない。どの入口も、通信の有無の判断に依らず、その 1 回の実行にだけ、入口が使いうる認証の経路のすべて（環境変数・設定ファイル・ホームの下のファイル・認証の代理など）を外して動かさせる。環境変数は子プロセスでだけ外し、設定ファイルとホームの下のファイルは、置き場所・ホームを指す環境変数を空の一時ディレクトリに向けて読ませる。認証情報のファイルの実物は移さない・消さない・読まない。1 つでも外せなければ動かさず理由を書かせる。通信の有無は実装者の判断で、見落とした通信でも本物の認証情報を使わせないため。動かし方と結果に秘密の値を書かせず、作業履歴にも写さない。
- 「入口を変える」は、入口の外から見える契約（呼び方・引数・出力の形・終了コード・既定の振る舞い）を変えること。出力の形を変えずに値の誤りだけを直す変更と、契約を変えない内部の変更は含めない。この範囲で、足さない・変えない変更には手順を増やさない。
- 行はコードの実装・修正のどの経路にも出す。入口を足したかをオーケストレーターが判定できないため、行の頭で「足さない・変えない変更では何もしない」と言い切る。文書だけの依頼には出さない。新しいコマンドを課さない。
- PR のレビューは、新しい観点（C-19 など）を作らず、既存の C-4 の手順 6 に足す。(a) 差し替えたテストだけで確かめた道に、差し替えない道を通る小さなテストを 1 本求める。差し替えない道は手元で結果が決まる本物の部品に絞り、外部のサービスを本物で通すことは求めない。そのテストは、手順 2・手順 4・「壊れやすさ」の対象にしない（逆向きの指摘を出さないため）。(b) PR の本文が渡されたとき、入口を足す・変える変更で記載が無ければ指摘する。NG 例 7 を足し、重要度の目安は `should`。

## 理由

- C-4 は必須の観点なので、担当が増えず、実行の時間も延びない。新しい必須の観点にすると、どのコードの初回のレビューにも担当が 1 つ増える（[C-18 の ADR](20261119-1605-superseded-review-viewpoint-for-harmony-with-existing-code.md)）。条件付きにすると、起動の条件を判定する手間が要る。
- 差し替えたテストは、差し替えた部品が返す値の形が本物と違っても通る。その境目は、差し替えないテストか実行でしか見つからない。
- 重要度を `should` にしたのは、記載やテストが無くても、変更が壊れているとは限らないため（[重みの決め方](20261117-0244-superseded-review-finding-weight-by-impact-and-likelihood.md)）。

## 影響

- 入口を足す・変える実装では、実装の工程で 1 回の実行が増える。ほかの変更では増えない。
- 入口の出力の形を変えずに値だけを直す変更は、差し替えない実行を求めない。入口が本物の環境でだけ壊れる内部の修正は、人が PR の版を動かすまで見つからないことがある。C-4 (a) が、差し替えたテストだけの道を拾う。認証情報が要る外部サービスだけに通信する入口は、実行の記載が「動かせなかった理由」だけになり、(a) も何も求めないので、この型の不具合は C-10 の「モックとの乖離」にしか拾われない。
- 要点を実装の指示にも書いたので、`review-execution` を差し替えたプロジェクトでも、実装側の決まりは効く。レビュー側（C-4）は、差し替えていると効かない。
