## 背景

プロジェクトの設定の Slack の通知は、誰にもメンションしなかった。人の出番の通知に気づけるよう、メンションする相手と、
どの種類の通知でメンションするかを設定できるようにする必要があった。

## 決定

- Slack API・Incoming Webhook のどちらの通知先にも、任意の `mention: { targets, kinds }` を足す。
- `targets`：Slack のメンバー ID（`U…`・`W…`）・ユーザーグループの ID（`S…`）・`@here`・`@channel` だけ。1〜20件。前後の空白は落とし、
  重複は1つにする。`@表示名`・小文字・`<>|&`・`<@U…>` の形のまま・`C…`・空は、理由（位置つき）を示して受け付けない。
- `kinds`：承認待ち・エスカレーション・一時停止・完了。書かなければ完了を除く3つ（人の出番）。
- 選んだ種類の通知の本文の先頭に `<@U…>`・`<!subteam^S…>`・`<!here>`・`<!channel>` を付ける。テストの通知には種類によらず付ける。
- エクスポート・インポートにも含める。設定しなければ、これまでどおりメンションしない（過去の設定・エクスポートもそのまま読める）。
- プロジェクトの設定の画面に、相手（カンマか空白で区切る）と種類（チェックボックス）の欄と ID の調べ方の説明を足す（ja・en）。

## 理由

- 相手の形を限るのは、本文に埋め込むため（コミットのメッセージ）。
- 既定を承認待ち・エスカレーション・一時停止にしたのは、人の出番だから（コミットのメッセージ）。
- ほかの案との比較は記録に無い。

## 影響

- メンションを含むエクスポートを、この PR より前の sacty でインポートすると、メンションは黙って捨てられる。
- ID の調べ方の説明は、実際の Slack の画面では確かめていない。
- この PR は #74（Slack の送り手）の上に重ねた。
