# sacty の最新版を、手元のコミットと GitHub の main で比べて知らせる

- 日時: 2026-10-18 12:13 UTC
- ステータス: 置き換え済み（superseded）
- 関係する PR・タスク: PBI-135
- 置き換え元: なし
- 置き換え先: [sacty の最新版を、動いている版と GitHub Releases の最新のリリースで比べて知らせる](20261020-0008-update-check-against-releases.md)

## 背景

エージェントのモデルの既定をリポジトリに持つようにした（[エージェントの既定をリポジトリに持ち、config.yaml は接続先と単価だけにする](20261018-1105-agent-defaults-in-repo.md)）。
sacty を更新すれば新しいモデルが届くが、利用者が更新に気づかなければ届かない。利用者は sacty のリポジトリを clone して使っており、
版の番号（どれも `0.1.0`）・タグ・GitHub Releases は運用していない。

## 決定

- デーモンが、動いている sacty のコミット（`git rev-parse HEAD`）と、GitHub の sacty のリポジトリの `main` を、GitHub の比較の API で比べる。
  `main` に手元に無いコミットがあれば、画面のどの画面でも、更新を勧める知らせを出す。
- 起動のときと1日ごとに確かめる。確かめられないときは黙る（誤りや警告にしない）。`config.yaml` の `update_check: false` で止められる。
- 当面の判断の元は `main` のコミット。リリースの運用を始めたら、GitHub Releases に切り替える。

## 検討した案

- **GitHub Releases で判断する**：リリースのときだけ知らせられ、変更の内容も示せるが、版の番号を上げてリリースする運用が要る。
  いまは運用していないので、当面は見送った（ステークホルダーが一度選び、当面は main と決め直した）。
- **`git fetch` で比べる**：GitHub の API を使わずに済むが、利用者の作業ツリーの参照を書き換え、認証やプロキシの設定に左右される。
- **画面を開くたびに確かめる**：すぐ気づけるが、GitHub の API の上限（認証なしで1時間に 60 回）に当たりやすい。

## 結果

- `main` に変更がマージされるたびに、利用者の画面に更新を勧める知らせが出る（ドキュメントだけの変更でも出る）。
- インターネットに出られない環境では、何も出ない（`update_check: false` で問い合わせも止められる）。
- fork や手元だけのコミットからは、GitHub が手元のコミットを知らないので、知らせない。
