# sacty とエージェントの作業用のファイルは作業領域の外に置き、リポジトリの検査と人の確認に影響させない

- 日時: 2026-11-04 03:55 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-302（A1・A2・D1・D2）
- 置き換え元: なし
- 置き換え先: なし

## 背景

実務での実証実験の r5（S14・S16・S18）で、検証の記録（`dispatch.md`・`review/summary.json`・起点の写しの `baseline` など）が作業領域の `.sacty-tools/` に書かれ、`prettier --check .` を落とした。最終レビューのテストの終了コードが 1 でも、ゴールガーディアンが「環境による失敗だけ」として合格にし、その説明が「人が確かめること」と PR の本文に入った。S16 では、検証のスクリプトに `.sacty-tools` の名前が入り、人の差し戻しが要った。PBI-301 の A6 は、指示を足しただけで効かなかった。

原因は 3 つ重なっていた。

1. 検証のスキルが「作業領域の外のスクラッチ用の一時ディレクトリ」と書くだけで、具体的な場所を示さなかった。エージェントは、指示に「sacty が PR・コミットに入れない」と書かれた `.sacty-tools/` を、作業用のファイルの安全な置き場と読んだ。
2. 作業領域の中の物は、リポジトリ全体を対象にするフォーマッター・リンター・テストが検査する。`.git/info/exclude` では prettier などが避けない。
3. 最終レビューの指示が、`.sacty-tools/` があるだけで「その環境だけの結果」を人の確認に入れさせていた。

## 決定

1. **置き場所を決める**：作業用のファイル（検証の記録・起点の写し・下書き）は、作業領域の外の `/tmp/agent-scratch/` に置く。既定のスキルの「一時ディレクトリ」をこの場所にし、`.sacty-tools/` は入れた道具の置き場だけと、実装の工程の指示・最終レビューの指示・既定の規則・スキルに書く。
2. **内部の名前の持ち込みを機械的に見つける**：sacty が差分の追加された行から作業領域の内部の名前（`.sacty-tools`・`/tmp/sacty-…`・`/sacty-input` など）を見つけ、依頼・承認済みの要求要件・設計が挙げていないものは、ゴールガーディアンの申告にかかわらず範囲外の変更（観点 `SCOPE`）として不合格にする。
3. **作業用のファイルによる失敗を人の確認に出さない**：最終レビューの結果から、内部の名前を含む人が確かめることの項目（入れたツールの注記「この環境だけの結果」を除く）を外し（記録は残す）、環境による失敗の申告の内部の名前を含むものは、パスも説明も載せない 1 件の文にまとめて人が確かめることに出さない。最終レビューの指示は、`.sacty-tools/` の中の作業用のファイルが検査を落としたときは、写しからそのファイルを消して検査をやり直して判定させる。`.sacty-tools/` があるだけでは「その環境だけの結果」にしない。
4. **終了コードが 0 でないのに合格にした理由を出す**：PR の本文のテストの行と画面（観点ごとの結果とテストの欄）に、環境による失敗だけと判断して合格にしたこと（作業用のファイルによる失敗だけなら、そう）を添える。
5. **今の head の AI のレビューの状況を出す**：承認の画面とタスクの詳細に、承認待ちの PR の今の head に sacty の AI のレビューが付いているか（付いていない・レビュー中・付いた）を出し、PR の本文にも本文を書いた時点の状況を 1 行入れる。承認やマージは止めない。
6. **費用の出どころは、すべての実行で記録する**：CLI が費用を報告しない実行（Codex など）も `RunCostRecorded` に `converted` で記録する。

## 理由

- 指示だけでは、r4 の A6 と同じく効かなかった。具体的な置き場所を決め、持ち込みを機械的に見つけて不合格にし、結果から作業用のファイルの説明を外す仕組みなら、エージェントの読み違いに左右されにくい。
- `.sacty-tools/` 自体を作業領域の外に移すと、実装の工程で入れたツールが、使い捨ての写しで検証するゴールガーディアンに渡らなくなる（PBI-278 の設計を変えることになる）。そのため、道具の置き場はそのままにし、記録の置き場だけを外にした。
- 内部の名前を機械的に見つけるのは、sacty 自身のリポジトリを直すタスクなど、名前が求められている場合があるので、依頼・要求要件・設計が挙げた名前は除く。
- AI のレビューが付く前の承認を止めないのは、AI のレビューを待たずに進めたい場面があり、判断は人のものだから。

## 影響

- 入れたツールに、format や lint が検査するファイル（`.sacty-tools/` の下に `npm install` した `package.json` など）が含まれると、検査はそれで落ちうる。この場合のツールの置き場は、作業領域の外に移す案があるが、今回は変えない。
- AI のレビューの状況は、同じ sacty のデーモンのレビューのタスクだけを見る。GitHub 上のほかの AI のレビューは見ない。
- 本文の AI のレビューの行は、本文を書いた時点の状況で、その後に付いたレビューでは更新されない。
