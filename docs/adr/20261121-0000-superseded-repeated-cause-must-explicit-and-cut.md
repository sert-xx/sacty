# 再レビューで同じ原因の要修正が続いたら、本文に明示し、原因を断つ直しと性質のテストを求める

- 日時: 2026-11-21 00:00 UTC
- ステータス: 置き換え済み（superseded）
- 関係する PR・タスク: PBI-424
- 置き換え元: なし
- 置き換え先: [同じ原因の要修正が続く場合に人の判断を求める](20261123-0007-superseded-repeated-cause-decision.md)（繰り返し時の停止と停止条件）

## 背景

ある実装の PR で、AI のレビューの要修正が6回続けて1件ずつ出た。原因はどれも同じ（値の全体が並んだ所しか処理せず、切れ目で値が割れると一部が残る）で、現れだけが違った。1往復に約 12〜15 ドル・約 25 分かかった。

[レビューの方針と指摘の出し切り](20261113-2328-review-approach-and-all-findings.md)の決まり（同じ原因の現れを1件にまとめる、再レビューで方針の観点に見直させ、方針を変える指摘が出なければふつうの `must` にする）は、この時点でもあったが、次が足りなかった。

- 同じ原因が続いていることを、本文に書く決まりが無かった。
- 方針の観点が方針を変えないと判断すると、直し方の案が現れを塞ぐ手当てに戻った。
- 実装のやり直しの指示に、同じ原因のほかの現れを自分で探すことが無かった。
- 設計のレビューは、漏れが取り消せない処理に、効かなくなりうる境目の数え上げを求めなかった。

## 決定

[レビューの指摘の重みの決め方](20261117-0244-superseded-review-finding-weight-by-impact-and-likelihood.md)と、上の ADR の決まりは変えず、次を足す。

- 再レビューで、今回の `must` が前回までの `must` と同じ原因の別の現れなら、方針の観点の結果に関わらず、本文（PR のレビューは総評か指摘の本文、セルフレビューは記録と返す結果）に、続いていること・原因・何回目か・前回までの現れの一覧を書く。
- 2回目の時点から、直し方の案に、原因を1か所で断つ直し、残りうる現れの軸による数え上げ（確かめた・確かめていないを分ける）、外から見える入口に当てる性質のテストの求めを含める。性質のテストの求めは、テストを書く場面（主対象が code で、文書だけの変更でも、テストなしのタスクでもない）にだけ含め、設計書・利用者向け文書・テストなしでは、本文への明示と、原因を断つ直しと数え上げまでにする。
- 実装のやり直しの指示に、欠陥の指摘は同じ原因のほかの現れを探してまとめて直し、探した範囲を対応の返答に書くこと、「同じ原因が続いている」指摘には、テストを書く場面だけ性質のテストを足すことを入れる。文書だけの指摘と、欠陥でない指摘には、探索も性質のテストも求めない。
- 設計書の観点 D-3 に、取り消せない害を防ぐ処理を足す・変える設計の、効かなくなりうる境目の数え上げを見る項目を足す。重さは今の表で決める。
- 同じ原因が何回続いても、自動の一時停止・通知・判定や作業履歴の新しい欄は足さない。回数で止めるかは、人が決めていない。

## 理由

- 続いていることが本文に出れば、人も実装も気づける。
- 現れを1つずつ塞ぐ直しは、次の回に別の現れを見つける。原因を断つ形と、入口への性質のテストは、数え上げに無かった経路も見つける。

## 影響

- 同じ原因が続く PR では、レビューの本文が少し長くなり、直しの1回が重くなる代わりに、往復が減ると見込む。
- 欠陥の指摘への実装のやり直しは、探した範囲を返答に書く分だけ増える。
