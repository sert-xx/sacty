# 利用上限で失敗したエージェントは、失敗の文から明ける時刻を確かに読み取れたとき、その時刻まで使わない

- 日時: 2026-11-21 02:00 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-428
- 置き換え元: なし
- 置き換え先: なし

## 背景

[理由を問わず代わりのエージェントでやり直す ADR](20261020-2317-agent-fallback-on-any-failure.md) は、利用上限で失敗したエージェントを `agent_fallback.cooldown_minutes`（既定 60 分）の間、すべてのタスクで使わないと決めた。
週の上限に達したエージェントを、60 分ごとに試しては失敗し、そのたびに時間を使っていた。

## 決定

- 利用上限（`usage_limit`）の失敗の文から、上限が明ける時刻を確かに読み取れたときは、その時刻まで、そのエージェントをすべてのタスクで使わない。`cooldown_minutes` より長くても短くても、読み取った時刻を使う。
- 読み取れないときは、`cooldown_minutes`。失敗が続いても期限は延ばさず、人が再開するまで切り替えたままにもしない。
- 対応する形：時間帯の名前つきの Claude Code の `· resets 3:45pm (Asia/Tokyo)`（曜日つきを含む）と、古い形の `Claude AI usage limit reached|<エポックからの秒>`。
- 対応しない形（読み取れない扱い）：時間帯の名前の無い Claude Code の `resets 3:45pm` と、Codex の `try again at …`。CLI が動いた環境の時間帯を、sacty が確かに知る手段が無いため。日付つきの Claude Code の形・費用の上限・一時的な混雑の文も読まない。
- 日付の無い時刻は、失敗の時刻より後の、いちばん近いその時刻（曜日つきはその曜日）と読む。失敗の時刻の 30 分前までに当たる時刻は翌日・翌週とは読まず、読み取れない扱いにする。失敗の時刻より前の時刻と、8 日より先の時刻も読み取れない扱い。
- 失敗の文は先頭の 2000 文字までを、量指定に上限のある正規表現で読む。
- 分類（`classifyFailure`）、利用上限でない失敗の扱い、`cooldown_minutes` の範囲と既定、制限中の一覧をメモリーだけに持つことは変えない。

## 理由

- 時間帯を推測すると、まる半日ずれた時刻で使わなくなったり、上限が明けても使わなかったりする。確かに知れる形だけを読めば、読み違えの害は、今までと同じ `cooldown_minutes` に収まる。
- コンテナに時間帯を渡す案は、イメージの時間帯のデータの有無に左右され、確かに知る手段にならないので採らなかった。
- 期限を延ばす・人が戻すまで切り替えたままにする案は、利用者が入れないと決めた。

## 影響

- 読み取ったときは、`AgentFellBack` の `until` と画面の表示も、その時刻になる。
- Codex の上限は、今のところ `cooldown_minutes` ごとに試し直す。時間帯を知る手段を足せば、読めるようにできる。
- 仕様は [エージェントの実行](../spec/agent-execution.md#失敗したときの代わりのエージェント) にある。

コード: `apps/daemon/src/agents/limit-reset.ts`（`parseLimitReset`）、`apps/daemon/src/service.ts`（`markLimited`）
