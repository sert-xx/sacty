# 差分は、clone の直後にどのコンテナにもマウントしない場所へ退避した git のメタデータで作り、作業領域の git の設定をホストで評価しない

- ステータス: 採用
- 関係する PR・タスク: #6、PBI-10
- 置き換え元: なし
- 置き換え先: なし

## 背景

最終レビューに渡す差分を、ホストのデーモンが作る。実装とテストのコンテナには clone 全体が書き込みできる状態でマウントされるので、
エージェントは `.git/config` や `.gitattributes` も変えられる。最初の実装では、作業領域でホストの `git add --all` を実行して差分を作っていた。

## 決定

- clone の直後（エージェントが触る前）に `.git` を、どのコンテナにもマウントしない場所（`workspaces/_git/<task>.git`）へ退避する。
- 差分は、退避したメタデータを `--git-dir` に使って作る。インデックスは一時ファイルにして、退避したメタデータを書き換えない。作業領域の `.git/config` は読まない。
- 利用者・システムの git の設定も読まない（`GIT_CONFIG_GLOBAL=/dev/null`・`GIT_CONFIG_NOSYSTEM`・`GIT_ATTR_NOSYSTEM`）。`core.fsmonitor`・`hooksPath`・
  `attributesFile`・`diff.external` はコマンドラインで打ち消す。
- 作業領域の `.gitattributes` が指すフィルターや差分ドライバーは、定義が無いので実行されない。属性（`-diff` など）で中身を隠されないよう、
  `--no-ext-diff --no-textconv --text` で出す。

## 理由

作業領域でホストの git を実行すると、エージェントが仕込んだ clean フィルターなどの外部コマンドがデーモンの権限で実行され、コンテナの
隔離を越えるため（レビューの指摘。無害な `touch` で、作業領域の外にホスト側のファイルが作られることが再現された）。
レビューは、差分を隔離された環境で作る案と、信頼できる git のメタデータで外部の処理を実行しない方式で作る案を挙げ、後者を採った。
後者を選んだ理由は記録に無い。

## 影響

- 作業領域の `.git` を消されても、差分を取得できる。
- git の操作をホストで行うときは、退避したメタデータを使い、作業領域の git の設定を評価しないことを守る。
