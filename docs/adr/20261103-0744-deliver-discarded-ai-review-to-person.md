# 古い head への AI のレビューを捨てたとき、その指摘を画面で人に届ける

- 日時: 2026-11-03 07:44 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-291
- 置き換え元: なし
- 置き換え先: なし

## 背景

[PBI-275](20261102-0843-distinguish-ai-review-remarks.md) で、古い head への AI のレビューは作り直しに取り込まずに捨てるようにした。捨てること自体は正しいと実験で確かめている。
ただし、捨てた指摘は作業履歴の1行（件数と commit だけ）にしか残らず、人が気づく形では出ない。
実験 S14 r2 では、AI のレビューが README の API の表に新しい API を足すよう提案していたが、古い head への指摘として捨てられ、要求要件にも README が入らないまま、合格条件の一部が未達でマージされた。

## 決定

- 捨てた指摘の要点（本文の先頭400文字）を `PullRequestReviewDiscarded` の記録に残し、見守っている PR へのものを、承認の画面とタスクの詳細に「取り込んでいない AI のレビューの指摘」として出す。
  捨てた理由（古い head と今の head）・対象の commit・要点・GitHub へのリンクを添え、PR がマージされるまで出す。
- 捨てた指摘は、これまでどおり自動では作り直しに取り込まない。新しい head にも当てはまると人が判断したら、差し戻しの指摘として伝える（人の指摘として扱う）。
- 届け方は画面に出すだけにする。PR への投稿と、新しい head への AI のレビューのかけ直しはしない。

## 理由

- 画面に出すだけなら、費用が増えず、既存の「画面に出すだけ」の方針（[承認待ちの間の PR の競合](20261101-1400-show-pull-request-conflict-while-awaiting-approval.md)）と揃う。人が承認の画面から差し戻すだけで、今の仕組みで人の指摘として扱える。
- PR に sacty が投稿する案は採らなかった。プロジェクトのアカウントは人と同じなので、投稿が人の指摘として取り込まれないよう、取り込みの除外を足す必要がある。また、AI のレビューは PR にすでに投稿されており、足りないのは「作り直しに取り込まれなかった」という知らせなので、sacty の画面が出す先として自然である。
- 新しい head に AI のレビューを自動でかけ直す案は採らなかった。レビューのタスクごとの費用が増える。必要なら、人が「再レビュー」を使う。

## 影響

- `PullRequestReviewDiscarded` の `items[].summary` を足した（任意。以前の記録には無く、その場合は要点なしで出す）。
- 規則は[承認と差し戻し](../spec/approval.md#ai-のレビューの指摘)に記す。
- 残した制限：PR のマージまで出し続けるので、人が差し戻して直した後も、直した指摘が消えずに残る。PR に直接マージする人（sacty の画面を開かない人）には、PR 側の知らせは出ない。
