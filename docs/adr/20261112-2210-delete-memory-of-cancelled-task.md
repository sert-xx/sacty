# 監査の後に中止したタスクにも、メモリーの削除の記録だけは追記できるようにする

- 日時: 2026-11-12 22:10 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-335
- 置き換え元: なし
- 置き換え先: なし

## 背景

監査でメモリーを登録したタスクが、その後にレビューのやり直しの失敗などで中止になることがある。
メモリーの削除（`AuditMemoryDeleted`）は登録したタスクの作業履歴に追記するが、中止したタスクへのイベントは投影が受け付けない。
そのため、件数の上限・残す日数・昇格・人の操作でそのメモリーを消そうとすると例外になり、起動のときの削除ではデーモンが起動できなくなった。

## 決定

中止したタスクでも、`AuditMemoryDeleted` は受け付ける（`AgentSessionArchived`・`OrchestratorSessionUsed` と同じ扱い）。
ほかの監査の記録（提案の判断など）は、これまでどおり中止したタスクに追記できない。

## 理由

- メモリーは監査が終わった時点の知見で、その後にタスクが中止になっても、知見として使い続けてよい。上限や残す日数で消すのも、ほかのメモリーと同じにする。
- `AuditMemoryDeleted` はタスクの状態・工程を変えない記録なので、中止したタスクに足しても中止の意味は変わらない。
- 比べた案：中止したタスクのメモリーを、生きたメモリーから外す。削除の記録を残さずに階層から消えることになり、正本の作業履歴と書き出しが食い違うので採らなかった。

## 影響

- 監査の後に中止したタスクのメモリーも、ほかのメモリーと同じく上限・残す日数・昇格・人の操作で消える。
