# Node.js を 26.x の LTS に上げる

- 日時: 2026-10-28 11:58 UTC
- ステータス: 採用
- 関係する PR・タスク: #245
- 置き換え元: [Node.js の下限（engines）を、脆弱性を直した版の 22.23.4 に上げる](20261022-0351-superseded-node-engines-security-floor.md)
- 置き換え先: なし

## 背景

sacty は Node.js 22.x（下限 22.23.4）を前提にしていた。
Node.js の[リリースの予定](https://github.com/nodejs/Release/blob/main/schedule.json)では、26.x が 2026-10-28 に LTS になる。
24.x は 2026-10-20 に保守（Maintenance）に入り、22.x はそれより前から保守にある。
2026-10-28 の時点の 26.x の最新は v26.12.1（2026-10-21 のセキュリティリリースの修正版）。

## 決定

- ルートの `package.json` の `engines.node` を `>=26.12.1` にする（`package-lock.json` の同じ項目も合わせる）。
- `.node-version` と `mise.toml` の版を `26.12.1` にする（[Node.js の版を、版の管理ツール用の `.node-version` と `mise.toml` にも書く](20261022-2347-node-version-files.md) のとおり、`engines` の下限と揃える）。
- `@types/node` をルートと `apps/web` で `^26.6.5` にする。
- エージェント実行用のイメージの既定の元のイメージ（`packages/cli/docker/Dockerfile` の `BASE_IMAGE`・`NODE_IMAGE`、画面や文言に出す既定の名前）を `node:26-bookworm-slim` にする。
- 利用者向けの「必要なもの」（README・はじめに・CONTRIBUTING）の Node.js の版を 26.12.1 以上にする。
- 元のイメージの条件（Node.js 18 以上）は変えない。

## 理由

- 新しく始める LTS の系列に合わせ、保守に入った系列より長くサポートを受けられるようにするため（26.x の保守の終わりは 2029-04-30）。
- 下限を 26.x の最新の修正版にしたのは、22.23.4 のときと同じく、脆弱性を直していない版を条件から外すため。
- 間の 24.x（LTS）を挟まなかったのは、26.x がこの日に LTS になり、24.x はすでに保守に入っているため。
- イメージの既定のタグは、これまでどおり版を固定しない（2026-10-28 の時点で `node:26-bookworm-slim` と `node:26.12.1-bookworm-slim` は同じ digest）。
  `sacty image build` は `--pull` を付けないので、取り直してから作り直す必要があるのも、これまでと同じ。
- 元のイメージの条件を変えなかったのは、利用者が書いた `image_build.base_image` などのイメージに入っている Node.js は、エージェントの CLI を動かせればよく、sacty のデーモンの `engines` とは別のものだから。

## 影響

- 26.12.1 より古い Node.js（22.x・24.x を含む）では、`engines` の条件を満たさなくなる。`npm ci` は警告（`EBADENGINE`）を出すだけで止まらない。利用者は Node.js を 26.12.1 以上に上げる。
- 既定のイメージは、`docker pull node:26-bookworm-slim` で元のイメージを取ってから `npx sacty image build` で作り直すと、Node.js 26 のものになる。
- 型の取り除きのためにテストで付けている `--experimental-strip-types` は、`engines` より古い Node.js で動かされたときのために残す（Node.js 26.12.1 でも付けたまま動く）。
- 次に Node.js の脆弱性の修正版が出たときに、下限を上げるかは、これまでどおりその都度決める。
