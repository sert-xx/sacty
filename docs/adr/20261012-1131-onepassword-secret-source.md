# 秘密情報の取得元に 1Password（op:// の参照）を足し、op CLI で取り出した値をデーモンのメモリーだけに持つ

- 日時: 2026-10-12 11:31 UTC
- ステータス: 採用
- 関係する PR・タスク: #41、PBI-34
- 置き換え元: なし
- 置き換え先: なし

## 背景

利用者の環境では、認証情報を 1Password に保存して使っている。sacty の秘密情報は、キーチェーンに保存した名前でしか参照できなかった。

## 決定

- 秘密情報を参照するすべての所（config.yaml の `auth.secret`・`image_build.npm_token`、コンテキストの `mcp.yaml` の `{ secret: … }`。
  ゲートウェイの API キーも同じ取り出し口を通る）で、キーチェーンの名前に加えて 1Password の参照
  （`op://保管庫/アイテム/[セクション/]フィールド`）を書ける。参照の形で取得元を選ぶ（`ResolvingSecretStore`）。
- 参照の各要素は、1Password の仕様に合わせて英数字・ハイフン・アンダースコア・ピリオド・空白（空白だけは不可）を受け付け、
  `?attribute=otp` などのクエリも受け付ける。op には引数として渡す（シェルを通さない）。
- 1Password からは op CLI（`op read --no-newline [--account …]`）で取り出す。複数のアカウントにサインインしているときは、
  config.yaml の `onepassword.account` を使う。
- 取り出した値はデーモンが動いている間だけメモリーに持ち、ディスクには書かない。同じ参照（同時の問い合わせも）は1回だけ問い合わせる。
  アカウントは取り出すときに設定から決め、アカウントと参照の組で持つ。取り出せなかった参照は持たない。
- op が無い・サインインしていない・取り出せない（op の理由つき）ときは、どの参照かと理由を記録し、認証の失敗としてタスクを止める。
  サインインして再開すれば取り出し直す。値は作業履歴・出力・エラー文・画面に出さない。
- デーモンと `sacty image build` が、この取り出し口を使う。

## 理由

- 利用者の環境で、認証情報を 1Password に保存して使っているため（PR の本文）。
- 取り出せなかった参照を持たないのは、サインインし直せば次は取り出せるようにするため（コミットのメッセージ）。
- 空白を受け付けるのは、1Password の仕様が空白を認めていて、公式の例の参照やアプリからコピーした参照がそのまま使えなかったため（レビュー）。
- アカウントと参照の組で持つのは、参照だけで持つと、デーモンの起動中に `onepassword.account` を変えても前のアカウントの値を返し続け、
  同じ名前の保管庫・アイテムが複数のアカウントにあると、設定と違う認証情報で接続してしまうため（レビュー）。
- op CLI を使うこと、メモリーだけに持つことの理由と、比べたほかの案は記録に無い。

## 影響

- 実際の 1Password では確かめておらず、op CLI の偽物（同じ引数・出力・終了コード）で確かめた。利用者の環境での確認が要る。
- `@` など仕様に無い文字を含む名前は、参照では ID で書く。
