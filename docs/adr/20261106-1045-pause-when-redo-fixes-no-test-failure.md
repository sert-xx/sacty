# 実装をやり直しても前回のテストの失敗が1つも直らなければ、回数を待たずに止める

- 日時: 2026-11-06 10:45 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-308、#314
- 置き換え元: なし
- 置き換え先: なし

## 背景

最終レビューに通らなければ実装をやり直し、続けて `MAX_VERIFY_ATTEMPTS` 回通らなければ一時停止する。
しかし、差分と無関係な失敗（環境の問題・不安定なテスト）は、実装をやり直しても直らない。上限まで同じ失敗で実装と最終レビューを繰り返し、人が再開すると回数が 0 に戻って、もう一度同じだけ繰り返していた。
手元の実行記録では、1つのタスクが最終レビューを8回繰り返し、そのうち7回の失敗は差分と無関係な後始末のテストだった。

## 決定

- ゴールガーディアンが、失敗したテスト・検査の名前を `tests.failedTests` に申告する。
- 前回の不合格の失敗がすべて今回も失敗していれば、進展なしとして、回数を待たずに一時停止する。
- 失敗の記憶は人の再開では消さない。再開の後に進展が無ければ、1回で止まる。
- 申告が無ければ比べず、これまでどおり回数だけで判断する。
- 上限（`FAILED_TESTS_MAX`）を超えた申告は、切り詰めずに記録しない。欠けた一覧を比べると、切り捨てた分が直っても進展なしに見えて、誤って止めるため。

## 理由

- 名前の完全な一致でなく「前回の失敗がすべて残っている」で比べる。環境の問題は、回によって失敗の数が増減する（実例では 7 件が 16 件になった）。失敗が1つでも直ったなら、実装が効いているので止めない。
- テストが通ったものとして扱う回（環境による失敗だけの回）は覚えない。観点の不合格を直している途中で、通っている扱いの検査を理由に止めないため。
- 再開で記憶を消さないのは、再開だけでは環境もテストも変わらないから。人が環境を直していれば失敗が変わるので、止まらない。

## 影響

- 名前の申告はエージェントの出力に頼る。名前の書き方が回ごとに変わると、進展なしと判定できず、これまでどおり回数で止まる（止まり方が遅くなるだけで、誤って止めることは少ない）。
- 本当に実装の不備で同じテストが落ち続けている場合も、2回目で止まる。人は再開して続けられる。
