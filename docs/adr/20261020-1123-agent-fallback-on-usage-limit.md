# 利用制限に達したエージェントは、agents の fallback に書いた代わりのエージェントに切り替えて、止めずに続ける

- 日時: 2026-10-20 11:23 UTC
- ステータス: 採用
- 関係する PR・タスク: なし
- 置き換え元: なし
- 置き換え先: なし

## 背景

Claude Code をメインに使い、サブスクリプションの利用制限に達したら別のエージェント（Codex など）で続けたいという要望があった。それまでは、
エージェントの実行が利用制限（`usage_limit`）で失敗すると、タスクを一時停止し、人が制限の戻りを待って再開していた。

エージェントの実行には、エージェントの種類（Claude Code・Codex）ごとの形にしたコンテキスト（設定の場所に置くファイル・段階のサブエージェント）を
渡している。また、オーケストレーターはタスクごとに1つのセッションを使い回すが、セッションのファイルは種類ごとの形なので、別の種類の
エージェントでは再開できない。

## 決定

- 代わりのエージェントは、エージェントごとに `agents.<名前>.fallback`（名前1つか並び。上から順に試す）で書く。`default_agent`・
  `step_agents`・`guardian_agent`・`audit_agent`・タスクの詳細で選んだエージェントの、どれにも同じ書き方で効く。
- 実行が `usage_limit` で失敗したら、そのエージェントを `agent_fallback.cooldown_minutes`（既定 60 分）の間、制限中として覚える。
  デーモンのメモリーだけに持ち、作業履歴には持たない（起動し直したら、元のエージェントから試す）。
- エージェントを選ぶところで、選んだエージェントが制限中なら代わりを選ぶ。実行の途中で入れ替えるのではなく、選び直して実行し直す。
  一時停止で止めていた失敗（工程・統合レビュー・工程の選択・チケットの読み取り・最終レビュー）は、一時停止の代わりに `AgentFellBack` を
  記録して実行待ちのままにし、次の処理で代わりのエージェントが実行する。判定（変更の申し出・差し戻しの指摘）は、失敗を判定できなかった
  ことにせず、その場で代わりのエージェントで判定し直す。
- オーケストレーターがエージェントを変えたときは、前のエージェントの保存したセッションから、指示とエージェントの発言の文だけを書き出し、
  読み取り専用で渡して引き継ぐ。正しい状態は、これまでどおり台帳から作る指示に持たせ、引き継いだやり取りは経緯の補いとする。

## 理由

- コンテキストは選んだエージェントの種類で作るので、実行の途中で別の種類のエージェントに入れ替えると、コンテキストを作り直す処理が各所に
  要る。選び直して実行し直せば、いまの「選ぶ → コンテキストを作る → 実行する」の流れのままで、作業履歴の `agentId` も実際に動いたものになる。
  失敗の記録はタスクを実行待ちに戻すので、一時停止を記録しなければ、ワーカーがそのまま拾う。
- 代わりをエージェントごとに書くと、段階ごとに対応する代わり（`claude_advanced` には `codex_advanced`）を選べる。設定の全体に1つだけ書く
  形では、段階の違うエージェントの代わりを表せない。
- 制限が戻る時刻は、エージェントのエラーの文から確実には読めない（形がツールと版で違う）。決まった時間だけ使わないほうが、元に戻る時期が
  分かりやすい。メモリーだけに持つのは、起動し直したときに元のエージェントを試しても、制限中ならまた切り替わるだけで困らないため。
- セッションのファイルを別の種類の形に変換するのは、形が公開の仕様でなく、版で変わるので採らなかった。やり取りの文だけなら、どちらの形からも
  安定して取り出せる。

## 影響

- 代わりのエージェントの秘密情報も、起動のときにまとめて取り出す。
- 書き出し・マージの後の監視・監査・質問への答えは、失敗をこれまでどおり扱い、次の実行から代わりを使う（止めずにやり直すのは、上の処理だけ）。
- 代わりも制限中なら、これまでどおり利用制限で止める。
- 仕様は [エージェントの実行](../spec/agent-execution.md#利用制限のときの代わりのエージェント)・[設定ファイル](../spec/configuration.md) にある。
