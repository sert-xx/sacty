# プロジェクトの削除は定義だけを消し、終わっていないタスクがあれば拒否する

- 日時: 2026-10-22 23:38 UTC
- ステータス: 採用
- 関係する PR・タスク: なし
- 置き換え元: なし
- 置き換え先: なし

## 背景

これまで、プロジェクトは作る・変えることはできても、消すことができなかった。使わなくなったプロジェクトを画面から
片付けるために、プロジェクトの設定から削除できるようにする。削除したときに、そのプロジェクトのタスクと作業履歴を
どう扱うか、実行中のタスクがあるときにどうするかを決める必要があった。

## 決定

- 削除は、プロジェクトの定義（`sacty.db` の `projects` の行）だけを消す。タスクと作業履歴は消さない。
  消したプロジェクトのタスクは、これまでどおり画面に出さず、ダッシュボードでも数えない。
- そのプロジェクトに、終わっていないタスク（完了・中止のほか）、または完了したタスクでも実行中・実行待ちの処理
  （監査・デプロイの確認など）があれば、削除を拒否する（件数を添えて理由を示す）。
- 画面では、プロジェクトの設定の最後に「危険な操作」として分けて置き、確認のダイアログでプロジェクトの名前を入力した
  ときだけ削除できるようにする。

## 理由

- 作業履歴は追記専用（削除を拒むトリガーがある）で、監査や費用の記録の元になるので、プロジェクトの削除のために
  消さない。画面と集計は、すでに「消したプロジェクトのタスクは出さない・数えない」作りになっているので、定義を消すだけで
  画面から片付く。
- 実行中のタスクがあるまま定義を消すと、プロジェクトの設定（GitHub のアカウント・コンテキストなど）が無いまま工程が
  進んでしまう。タスクを自動で中止する案もあったが、削除のついでに作業を止めるのは影響が大きいので、人が先に完了・中止する
  ようにした。
- 元に戻せない操作なので、ほかの設定と分けて置き、名前の入力で打ち間違いを防ぐ。

## 影響

- 消したプロジェクトのタスクと作業履歴は、データとしては残る（画面からは開けない）。
- 仕様は [アーキテクチャ](../spec/architecture.md) の設定の置き場所の節に書く。
