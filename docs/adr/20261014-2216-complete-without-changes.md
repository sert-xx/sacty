# 実装に変更が無ければ PR を作らず、人間が確かめて変更なしで完了にする

- 日時: 2026-10-14 22:16 UTC
- ステータス: 採用
- 関係する PR・タスク: #100、PBI-90
- 置き換え元: なし
- 置き換え先: なし

## 背景

PR作成の工程は、実装の作業領域をコミットしてプッシュし、PR を作る。作業領域が起点から何も変わっていないと、コミットできずに
（`git.nothingToCommit`）エラーで一時停止していた。テンプレート「Sacty セットアップ」では、要求要件・設計・実装を進めた後で
「すでに整っていて変更が要らない」とわかることがあり、検査の結果を残して PR なしで完了できる経路が要った（PR #100 のレビュー）。
一方、ふつうのタスクでは、失敗した実装が何も変えていないこともあり、それが完了に見えてはいけない。

## 決定

- まだ実装の PR を作っていないタスクで、PR作成の工程に変更が無ければ、PR を作らずに `NoChangesFound` を記録し、成果物チェックで
  人間の承認を待つ。すべてのタスクで同じにする（テンプレートのタスクに限らない）。
- 画面では、承認待ちを「変更なしの成果物チェック待ち」、承認の画面に「変更なし（PR は作っていません）」と確かめることを出す。承認すると
  「完了（変更なし）」で完了する。差し戻すと、ふつうと同じく実装からやり直す。
- 実装の工程の指示に、変更が要らないとわかったらファイルを変えずに、理由と根拠を説明に書くよう入れる。
- すでに実装の PR を作ったタスクで、作り直しで変更が無くなったときは、今までどおり止める。

## 理由

- すべてのタスクに広げたのは、テンプレートかどうかで「変更が要らない」ときの扱いが変わる理由が無く、ふつうのタスクでも同じことが
  起きるため。
- 自動で完了にせず人間の承認を挟んだのは、失敗した実装が何も変えなかった場合を完了に見せないため。成果物チェックの前に、テストと
  最終レビュー（観点ごとの検証）も通っている。
- 工程の途中で調査だけの組み合わせへ切り替える経路は採らなかった。承認済みの要求要件・設計を変えずに済み、どの工程から変更が要らないと
  わかっても、PR作成の工程の1か所で扱えるため。
- PR を作った後に変更が無くなったときに止めるのは、開いている PR を閉じるか・残すかを sacty が決めずに人に任せるため。

## 影響

- 成果物チェックは、PR のマージのほかに、画面での承認（変更なし）でも完了する。完了したタスクに PR が無いことがある。
- タスクブランチ（要求要件・設計の PR をマージしたもの）があるタスクでも、ベースブランチへの PR は作らず、タスクブランチは残る。
- マージの後の監視（デプロイの確認）は、PR のマージが無いので行わない。
- 仕様は [承認と差し戻し](../spec/approval.md#実装に変更が無いとき)。
