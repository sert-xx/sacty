# 言語ごとの実行イメージを config.yaml の images に定義し、オーケストレーターが工程ごとに選ぶ

- 日時: 2026-10-13 01:38 UTC
- ステータス: 置き換え済み（superseded）
- 関係する PR・タスク: #53、PBI-41
- 置き換え元: なし
- 置き換え先: [言語ごとのイメージでは、元のイメージに Node.js と npm があればそれを使い、無いときだけ写す](20261013-0432-reuse-base-image-node.md)（Node.js を必ず写す部分）

## 背景

エージェントとテストは、Node.js の既定のイメージ1つで動いていた。Python・Go・Java などのリポジトリや、1つのリポジトリに複数の言語があるリポジトリ（モノレポなど）を扱えなかった。

## 決定

- `config.yaml` に `images` を足す。名前ごとに、説明・元のイメージ・環境変数（`env`）・Maven/Gradle のミラー（`maven_mirror`）を書く。
- 元のイメージは、Node.js の入っていない Debian・Ubuntu 系か RHEL 系でよい。sacty が Node.js（`node_image`、無ければ `image_build.base_image` か `node:22-bookworm-slim` から写す）・
  git・Claude Code・Codex を足し、`node` ユーザーで動かす。
- `env` は、エージェントとテストのコンテナに名前だけを渡す（値をコマンドラインに出さない）。認証の値（`TOKEN`・`PASSWORD` などを含む名前、ユーザー名・パスワードを含む URL）と、
  sacty や docker とぶつかる名前（`PATH`・`HOME`・`DOCKER_*`・`SACTY_*`・`CODEX_*` など）は書けない。
- `sacty image build [<名前>...]` でイメージを作る。名前を省くと、既定のイメージと `images` のすべてを作る。
- オーケストレーターは既定のイメージで動き、イメージの候補（名前と説明）を見て、工程ごとにイメージを選ぶ。テストのコマンドは、実装（不具合の修正では再現）の工程のイメージで実行する。
  統合レビューも、選んだイメージと環境変数で動く。ゴールガーディアンは既定のイメージのまま。
- プロジェクトの対象（リポジトリ・Org）ごとにイメージを指定できる。指定すると、オーケストレーターに選ばせず、すべての工程でそれを使う（リポジトリの指定が Org の指定より優先）。
- 選んだイメージと理由は、作業履歴（工程の決定）に残す。`images` に無い名前を選んだ・指定した・後で消したときは、その工程を実行せずに理由を示して止まる。

## 理由

- Python・Go・Java などのリポジトリを扱い、モノレポのように複数の言語がある場合も工程ごとに違うイメージを使えるようにするため（PR の本文）。
- オーケストレーター・ゴールガーディアンを既定のイメージのままにしたのは、コードを読むだけの判断だから（レビューへの返信）。
- 統合レビューにも選んだイメージを使うのは、レビューの指摘による。既定のイメージのままだと、Java・Maven などを使った検証ができなかった（レビュー）。
- `env` に認証の値と予約された名前を書けなくした理由、元のイメージから Node.js を写す形にした理由は、記録に無い。

## 影響

- 言語ごとのイメージは、利用者が `config.yaml` に定義して `sacty image build` で作る。既定のイメージは、これまでどおり作れる。
- `images` を書いていなければ、画面にイメージの選択は出ず、これまでどおり動く。
