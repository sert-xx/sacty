# Node.js の下限を、2026-11 のセキュリティリリースの修正版 26.13.1 に上げる

- 日時: 2026-11-12 01:54 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-328
- 置き換え元: [Node.js を 26.x の LTS に上げる](20261028-1158-superseded-node-26-lts.md)
- 置き換え先: なし

## 背景

sacty の Node.js の下限は 26.12.1（2026-10-21 のセキュリティリリースの修正版）だった。
Node.js は 2026-11-11 付けでセキュリティリリースを告知し、26.x の修正版 v26.13.1 を 2026-11-10 に公開した
（[告知](https://nodejs.org/en/blog/vulnerability/november-2026-security-releases)）。
直した脆弱性には、TLS・HTTP/2・`https.Agent` の TLS セッションの使い回しなど、sacty のデーモンが使う機能のものが含まれる（重さは最大で High）。

## 決定

- ルートの `package.json` の `engines.node` を `>=26.13.1` にする（`package-lock.json` の同じ項目も合わせる）。
- `.node-version` と `mise.toml` の版を `26.13.1` にする（`engines` の下限と揃える）。
- デスクトップアプリのパッケージを作るスクリプト（`apps/desktop/scripts/package.mjs`）の版の確かめも 26.13.1 にする。
- 利用者向けの「必要なもの」（README・はじめに・CONTRIBUTING）の Node.js の版を 26.13.1 以上にする。
- 置き換え元の ADR のほかの決定（26.x の LTS を使う・`@types/node`・エージェント実行用のイメージの元のイメージ・元のイメージの Node.js の条件）は変えない。

## 理由

- 置き換え元と同じく、脆弱性を直していない版を条件から外すため。
- エージェント実行用のイメージの元のイメージ（`packages/cli/docker/Dockerfile` の `BASE_IMAGE`・`NODE_IMAGE`）は変えない。
  固定しているダイジェストは、2026-11-12 の時点で `node:26.13.1-bookworm-slim` と同じ（`docker buildx imagetools inspect` で確かめた）。

## 影響

- 26.13.1 より古い Node.js（26.12.x を含む）では、`engines` の条件を満たさなくなる。`npm ci` は警告（`EBADENGINE`）を出すだけで止まらない。利用者は Node.js を 26.13.1 以上に上げる。
- mise などの版の管理ツールを使う利用者は、`mise install` などで 26.13.1 を入れる。
- 次に Node.js の脆弱性の修正版が出たときに、下限を上げるかは、これまでどおりその都度決める。
- 関係する仕様書：[エージェントの実行](../spec/agent-execution.md)。
