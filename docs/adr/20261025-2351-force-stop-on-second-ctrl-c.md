# sacty up は、止めている途中でもう一度 Ctrl+C を押されたら、後片付けを待たずに止める

## 背景

`sacty up` を Ctrl+C で止めると、デーモンは実行中の処理（タスクの実行・取り込み・PR の確認・スケジュールタスクの確認）の後片付けを最大20秒待ち、CLI は最大30秒待つ。
その間、端末には何も出ず、もう一度 Ctrl+C を押しても、CLI もデーモンも「もう止めている」として何もしなかった。
利用者からは、何度 Ctrl+C を押しても反応が無く、止まっているのかわからないと報告された。

## 決定

- 1回目の Ctrl+C で、CLI は止めていることと、もう一度押せば待たずに止めることを表示する。
- デーモンは、後片付けが3秒たっても終わらなければ、まだ終わっていないものを表示する。
- 止めている途中で、もう一度 Ctrl+C を押されたら、CLI はデーモンに `FORCE_STOP_SIGNAL`（SIGUSR2）を送り、画面には SIGKILL を送る。
  デーモンは、これを受けたら後片付けを待たずに `process.exit` で終わる。

## 理由

- 後片付けを待つのは、作業履歴への記録や認証ファイルの書き戻しを失わないためなので、1回目は今のまま待つ。待つ理由と抜け方を表示すれば、利用者が選べる。
- デーモンに SIGKILL を送らないのは、`exit` の後処理で、別のプロセスグループで動くホストの MCP サーバーとコンテキストの取得の git を止めさせるため。
  途中だった実行は、次の起動の `recoverInterrupted` で中断として回復する。
- デーモンで SIGINT の回数を数える案は採らなかった。Ctrl+C では端末からの SIGINT がデーモンにも直接届き、CLI からの SIGTERM と重なる。
  端末を通さずに CLI だけにシグナルを送る起動のしかたでは、デーモンに SIGINT が届かない。
  続けて送った同じシグナルは、OS がまとめることがある。そのため、CLI が決めて別のシグナルで伝える。

## 影響

- Windows には SIGUSR2 が無い（Windows での振る舞いは確かめていない）。
- 待たずに止めると、後片付けの途中だった実行は失敗として記録され、タスクは一時停止になる。
- 仕様は [デーモンの起動と終了](../spec/daemon-lifecycle.md) の「sacty up」と「デーモンの終了」。
