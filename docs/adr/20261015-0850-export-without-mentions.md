# プロジェクトのエクスポートに Slack のメンション（相手と種類）を含めず、含んでいた版 3 のファイルは理由を示して断る

- 日時: 2026-10-15 08:50 UTC
- ステータス: 採用
- 関係する PR・タスク: #114、PBI-103
- 置き換え元: [Slack の通知先に、メンションする相手と通知の種類の設定（mention）を足し、既定は人の出番の通知だけにする](20261014-0032-superseded-slack-mentions.md)（エクスポート・インポートに含める部分）
- 置き換え先: なし

## 背景

プロジェクトのエクスポートには、Slack の通知先とメンションの設定（相手の ID と種類）を含めていた。メンションする相手は使う人や
環境ごとに違うので、エクスポートしたファイルをほかの sacty で共有すると、インポートした先にも元の人へのメンションが残る。
まだ本番では使っていないので、以前の版のファイルを読む互換の層は要らない。

## 決定

- エクスポートの形式の版を 4 に上げ、通知先から `mention` を丸ごと（`targets` も `kinds` も）除く。通知先のほかの項目
  （送り先・チャンネル・言語・秘密情報の参照）は今までどおり含める。
- インポートでは、通知先に `mention` があれば知らない項目として断る（`input.unknownKeys`）。
- 版 3 のファイルは、メンションを含むかによらず、理由（版 4 からメンションの相手を含めないこと・エクスポートし直すこと）を示す文言
  （`input.exportVersionWithMentions`、ja・en）で断る。ほかの版は、今までどおり `input.unsupportedVersion`。
- インポートしたプロジェクトにはメンションが無いので、プロジェクトの設定の画面で相手（と種類）を足す。

## 理由

- `kinds` も除くのは、相手の無い種類は意味が無く、今の形（`SlackMention`）は相手を 1〜20 件と決めているため。種類だけを残すには
  相手の無いメンションの形を新しく作る必要があり、相手を足すときに種類も選び直せる（既定は人の出番）ので、残す値打ちが小さい。
- 版 3 のファイルを、相手だけを読まずに取り込む案もあった。互換の層は要らないこと、黙って捨てると利用者が気づかないことから、
  理由を示して断ることにした。
- 版 4 のファイルに `mention` を書き足したものを黙って捨てずに断るのは、エクスポートの項目は知らないものを断るという今までの
  方針（秘密情報などを、気づかずに取り込まないため）に合わせるため。

## 影響

- 版 3 のファイル（この変更の前の sacty でエクスポートしたもの）は、インポートできない。今の sacty でエクスポートし直す。
- 版 4 のファイルを、この変更の前の sacty でインポートすると、版の違いで断られる。
- 仕様は [書き出し](../spec/export.md) と [通知](../spec/notifications.md) に書く。
