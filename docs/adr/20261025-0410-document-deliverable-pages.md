# 文書作成の成果物を指示で明確にし、外部に直接書いたページ（複数可）を記録して、差し戻しで同じページを直させ、書き出さない

## 背景

文書作成（`document`）のタスクで、外部の PF（Confluence・Notion など）にある文書の内容を直すよう差し戻したところ、次のことが起きた。

- 最初に作られた文書とは別の文書が、外部に新しく作られた。
- タスクの最終報告（「〜のドキュメントを作成。エージェント ID は〜」のような内容）も、外部に文書として作られた。

文書作成のエージェントには、[ほかの工程と同じく外部 PF・MCP を渡している](20261022-1505-document-step-gets-context.md)。
指示は「原稿そのものは外部やリポジトリに直接書かず出力する」だけで、次のことを伝えていなかった。

- 何が成果物か（出力の全体が原稿として保存され、承認の後にそのまま書き出されること）
- 外部に直接書いたときに、どのページが成果物か（sacty も、エージェントが書いたページを記録していなかった）
- 差し戻しで直す対象は、前回の成果物であること

そのため、外部に直接書いたエージェントは、出力に作業の報告を書いた。
差し戻しの実行は前の回が作ったページを知らず、外部に別の文書を作った。
人が承認すると、作業の報告が原稿として書き出された。

利用者からは、次の指摘があった。

- 何が成果物かを明確にし、修正のときはその成果物を続けて直すべきで、成果物でないものを sacty の外に出してはいけない。
- 外部への書き込みを禁じたいのではない。タスクの説明で直接編集の指示があれば、それに従って外部の文書を直してよい。
- 成果物が複数のページになるタスクもある（例：「〇〇を含むページを探して、まとめて直して」）。

## 決定

- 文書作成の指示に「成果物」の節を置き、次のことを伝える（`documentDeliverableLines`）。
  - 出力（決まった形式の JSON を除く全体）を工程の成果として sacty に保存し、人間が承認する。
  - ふつうは、成果物は原稿1つ。原稿の全文を出力し、外部・リポジトリには書かない。承認の後に sacty が書き出す。
  - タスクの説明（取り込み元のチケットを含む）が外部の文書を直接作る・直すよう指示していれば、そのとおりに外部に書いてよく、書いたページ（1つでも複数でもよい）が成果物になる。
    条件で探すよう指示されていれば、条件に合うページを探してそれぞれを直す。
    出力には、ページごとに見出し（題と URL）と直した後の内容を書き、人間はこれを読んで承認する。
  - 成果物のほかに外部にページ・コメントを作らない。作業の報告（作成した旨・タスクやエージェントの ID・手順）は、外部にも出力にも書かない。
  - 差し戻しでは、前回の成果物（原稿、または外部に直接書いたページ）を直して成果の全体を出し直し、別の文書を作らない。
    外部のページを直すよう求める指摘は成果物への指摘として扱い、対象のページを足すよう求める指摘なら足してよい。
- 外部に直接書いたエージェントには、その回に作った・直したページの URL を見出し `sacty-document-pages` の JSON で出させる。
  sacty はこれを出力から除いて `AgentRunCompleted` の `documentPages` に記録し、投影は前の回までのページに足して `Task.documentPages` に残す。
- `documentPages` があれば次の回の指示に渡し、それらのページを直すときは同じページを直させる。画面には、外部に直接書いたページを一覧で出す。
- `documentPages` があれば、書き出し先が決まっていても書き出さない。
- 書き出しの指示にも、書くのは書き出すファイルの内容の1ページだけで、書き出しの報告を別のページやコメントにしないことを足す。
- オーケストレーターへの組み合わせの説明で、外部の文書を直接作る・直す依頼のうち、差し戻しで直し続けるもの（複数のページ・条件で探したページをまとめて直すものを含む）を `document` にし、`operation` は一意な対象1つへの決まった変更を1回するものにする。
  文書作成の指示からは「既存文書の直接更新依頼は作業で扱います」の一文を除く。

## 理由

- 成果物を決め、外部に書いたページを記録して渡せば、承認する物と差し戻しで直す物が同じになる。差し戻しのたびに別のページができず、報告も外部に出ない。
- 外部への直接の書き込みは、タスクの説明が指示したときに限って認める。利用者は外部の文書を直接直す用途を求めており、禁じると用途を損なう。
  指示が無いときは、承認の前に外部に出さず、承認の後に sacty が書き出す。
- 成果物のページを1つに限ると、条件で探した複数のページをまとめて直す依頼を扱えない。ページは回ごとに足し、その回に直さなかったページも成果物として残す。
  エージェントが前の回のページを申告し忘れても、成果物から落とさないためである。
- 外部に直接書いたページが成果物なら、sacty の出力（ページごとの内容）は人間が承認するための写しで、外部に出す物ではない。書き出すと、成果物でない物が外部に別のページとして出る。
- `operation` は差し戻しでやり直せず、対象も一意な1つに限る。直しながら進める外部の文書や、複数のページをまとめて直す依頼には合わない。
- 成果物のページの URL は、エージェントの申告で受け取る。外部の PF・MCP のどれに何を書いたかを、sacty は呼び出しから区別できない。

## 影響

- 外部に直接書かないことも、成果物のページだけを直すことも、指示で伝える（強制はしない）。
- エージェントが URL を申告しなければ、そのページは成果物として記録されず、次の回に渡せない。外部に直接書いたのに一度も申告しなければ、承認の後に書き出しが行われる。
- 外部に直接書いた文書は、承認の前に外部に反映される（タスクの説明の指示による）。
