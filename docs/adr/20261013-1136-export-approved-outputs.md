# 調査・要求要件・設計の承認した成果は、オーケストレーターが工程ごとに決めた書き出し先に、利用者が用意した接続先だけで書き出す

- 日時: 2026-10-13 11:36 UTC
- ステータス: 採用
- 関係する PR・タスク: #65、PBI-56
- 置き換え元: なし
- 置き換え先: なし

## 背景

調査・要求要件・設計の成果は、sacty の中と取り込み元へのコメントにしか残らなかった。Confluence・Notion などに書き出したいが、
書き出し先はプロジェクトの規約によって違い、接続の仕方も利用者ごとに違う。

## 決定

- 工程を選ぶとき、オーケストレーターに使える接続先（`gateway.platforms`・ホストの MCP・コンテキストの MCP）とプロジェクトの
  コンテキストの規約を渡し、工程ごとの書き出し先（接続先・置き場所の手がかり）と理由を決めさせる（`StepsChosen.exports`）。
  書き出さない判断もある。存在しない接続先は「書き出さない」として扱う。sacty は Confluence・Notion ごとの専用の設定を持たない。
- 書き出せる工程は、要求要件・設計と、調査だけのタスクの調査（前段の調査は人が承認しないので対象外）。
- 人が承認した後、次の工程や取り込み元へのコメントより先に、書き出しのエージェントが、決めた接続先だけを使って書き出す
  （コンテナには実行ごとのトークンだけ。MCP の設定・ゲートウェイの中継・取り出す認証も、決めた接続先の 1 つに絞る）。
- 差し戻しの後に承認し直したら、前に書き出したページを更新する。ゴールガーディアンが認めた設計の変更も、承認済みの版として同じ
  ページを更新する。本文に目印（`sacty-export:<タスク>:<工程>`）を入れ、前に書き出した URL が無いときは、必ず目印でページを探して
  あれば更新、無ければ作る（二重に作らない）。
- 書き出せないときは理由を記録して、いまの仕様（sacty の中に残す・取り込み元へのコメント）のまま進める（タスクは止めない）。
  画面から書き出し直せる（`POST /api/tasks/:id/exports/:step/retry`）。
- 書き出した URL を、取り込み元（Issue・JIRA）への調査の結果のコメント、チケットへの PR のコメント、PR の本文に添える。
  実装のタスクで要求要件・設計を書き出したら、PR の本文に URL を入れる。
- 書き出しの費用はタスクの費用に入れ、工程ごとの費用に「書き出し」として出す。

## 理由

- 書き出し先の 2 つの扱い（設計の変更も同じページを更新する・実装のタスクでは PR の本文に URL を入れる）は、PO の判断（PR の本文）。
- 決めた接続先だけに絞るのは、レビューで、選んでいない MCP の認証の取得に失敗すると選んだ先への書き出しまで失敗し、無関係な
  MCP のツールも書き出しのエージェントに見えることがわかり、「決めた接続先だけを使う」に合わせたため（レビューとその返信）。
- URL が無ければ必ず目印で探すのは、レビューで、結果の JSON を読めなかった試行の後に書き出し直すと、新しく作る指示になり二重に
  作ることがわかったため（レビューとその返信）。
- 専用の設定を持たずオーケストレーターに決めさせることの理由と、比べたほかの案は記録に無い。

## 影響

- コンテキストがあるプロジェクトでは、工程の選択でもコンテキストを取得するので、少し遅くなる。
- Issue へのコメントの後に書き出し直した場合、Issue のコメントは更新しない（URL は sacty の画面と PR の本文に出る）。
- 予算の上限で書き出せなかった場合、予算を上げても自動では書き出さない（画面から書き出し直す）。
