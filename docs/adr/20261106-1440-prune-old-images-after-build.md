# `sacty image build` の後に、古い版のイメージと使っていないビルドキャッシュを片付ける

- 日時: 2026-11-06 14:40 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-313、#319
- 置き換え元: なし
- 置き換え先: なし

## 背景

既定のイメージの名前は版に連れて変わるので、版を上げて `sacty image build` を実行するたびに、`sacty-agent:<版>`・`sacty-agent-<名前>:<版>` が増える。
古い版は誰も消さず、Docker の仮想ディスクが満杯になって、エージェントがコンテナの中の `/tmp` に書けずに止まった。
そのときはイメージが 99GB、ビルドキャッシュが 58GB で、ビルドキャッシュのうち 52GB はイメージと層を共有していた。

## 決定

- `sacty image build` がすべてのイメージを作れたら、古い版を片付ける。
- 対象は、`sacty-agent`・`sacty-agent-<名前>` の `X.Y.Z` のタグのイメージだけにする。名前ごとに新しい版から2つ残す。
- `image`・`images.*.image` が指すイメージは残す。
- 消すときは強制しない。コンテナが使っていて消せなければ、消せなかったものとして出力する。
- 7日より長く使っていないビルドキャッシュも消す。
- 片付けに失敗しても、`sacty image build` は失敗にしない。

## 理由

- 版を上げた利用者はイメージを作り直すので、この時機なら別の操作を覚えなくても片付く。
- 2つ残すのは、1つ前の版に戻しても作り直さずに済むようにするため。
- 名前とタグを絞るのは、人が付けたタグ・他のプロジェクトのイメージ・`image` に書いた独自の名前を消さないため。
- イメージを消しても層はビルドキャッシュに残り、容量が戻らない。版が変わっても使う層は使われ続けるので、使っていない期間で絞れば、次のビルドが遅くなりにくい。

## 影響

- 3つ以上前の版に戻すときは、イメージを作り直す。
- 作らなくなった `sacty-agent-<名前>` のイメージは、名前ごとに2つ残る。
- 残す数・キャッシュの期間は変えられない。必要になったら設定を足す。
