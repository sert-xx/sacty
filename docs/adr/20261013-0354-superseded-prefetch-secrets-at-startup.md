# sacty up の起動時に、使う秘密情報をまとめて取り出してから、タスクの実行と取り込みを始める

- 日時: 2026-10-13 03:54 UTC
- ステータス: 置き換え済み（superseded）
- 関係する PR・タスク: #56、PBI-48
- 置き換え元: なし
- 置き換え先: [起動時と保存時に、プロジェクトのコンテキストの秘密情報もまとめて取り出す](20261015-1303-prefetch-context-secrets.md)（コンテキストリポジトリの秘密情報を対象外にした部分）

## 背景

秘密情報は使うときに取り出していたので、タスクを作って動き始めたときに 1Password の認証を求められていた。

## 決定

- `sacty up` の起動時に、設定とプロジェクトで使う秘密情報の参照（エージェントの認証・providers の API キー・外部の PF（プラットフォーム）の認証・ホストで動かす MCP サーバーの秘密情報・
  プロジェクトの通知先）を集めて、まとめて取り出す。イメージの作成だけで使う npm のトークン・gh から取る GitHub のトークン・コンテキストリポジトリの mcp.yaml の秘密情報は対象外にし、使うときに取り出す。
- 1Password の参照は、1回の `op run --no-masking --env-file <参照のファイル> -- node -e …` で取り出す。参照のファイルには参照だけを書いて終わったら消し、値は子のプロセスの環境変数で受け渡す
  （コマンドラインにもファイルにも出さない）。取り出した値は、これまでどおりデーモンのメモリーだけに持つ。
- まとめて取り出せなかったときは、参照ごとに取り出し直して、取り出せなかったものを特定する。
- キーチェーンの秘密情報は、取り出せるかだけを確かめ、これまでどおり使うたびに取り出す。
- 秘密情報を取り出し終えてから、タスクの実行と取り込み・外部の PF の認証の用意・ホストの MCP サーバーの起動を始める。サーバーの待ち受けは先に起動する。
- 取り出せなかったものがあっても、起動は止めない。画面の警告と端末に、どの設定かと理由を出す（値は出さない）。「秘密情報を取り出し直す」で、持っている値を捨てて取り出し直せる。

## 理由

- 1Password の認証を、起動のときの1回だけにするため（PR の本文）。
- 取り出し終えてから実行と取り込みを始めるのは、タスクが別に 1Password に問い合わせて、認証を何度も求めないようにするため（PR の本文）。
- 外部の PF とホストの MCP サーバーの用意も後に回したのは、先に始めると個別の取り出しが起き、1回にまとまらないというレビューの指摘による（レビューとその返信）。
- コンテキストリポジトリの mcp.yaml の秘密情報を対象外にしたのは、取得しないとわからないため（PR の本文）。
- キーチェーンを使うたびに取り出すのは、`sacty secret set` で変えた値がすぐに使われるようにするため（PR の本文）。

## 影響

- 1Password の参照がある設定では、起動のときに1回だけ認証を求められる。参照が1つも無い設定では、これまでどおり何も聞かずに起動する。
- 起動の後に増えた参照は、これまでどおり使うときに取り出す。
