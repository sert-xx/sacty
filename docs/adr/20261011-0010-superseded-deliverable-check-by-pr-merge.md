# PR のあるタスクの成果物チェックは、最新の提出の PR がマージされたことを承認とみなし、画面では承認しない

- 日時: 2026-10-11 00:10 UTC
- ステータス: 置き換え済み（superseded）
- 関係する PR・タスク: #20、PBI-14
- 置き換え元: [最終レビューに通ったら sacty が sacty のブランチにプッシュして PR を作り、成果物チェックのゲートで止める](20261010-0858-superseded-pull-request-and-deliverable-gate.md)（成果物チェックを画面で承認して完了にする部分）
- 置き換え先: [人が PR の中で直してからマージしても承認・完了として進め、sacty の成果と人が直した最終の成果の両方を記録する](20261013-1425-accept-human-edited-merge.md)（提出と一致しないマージを承認にせず判断を待つ部分）

## 背景

#7 で、PR を作ったら成果物チェックのゲートで止まり、画面で承認するとタスクが完了する形にした。動作確認で、画面で成果物チェックを承認しても PR はマージされないことが問題になった。成果物チェックをどこで判断するかを決める必要があった。

## 決定

- 成果物チェックは PR の上で判断する。PR のマージを承認とみなし、タスクを完了にする（マージした人を含めて、人間の操作として記録する）。
- デーモンは、成果物チェックで待っているタスクの PR の状態を、1分ごとにプロジェクトの gh のアカウントで確かめる。Issue の取り込みの設定が無くても動く。確かめられないときは何も記録せず、次の確認でやり直す。
- マージせずに閉じられたら記録して、成果物チェックのまま人間の判断を待つ。開き直されたら記録して、マージを待つ。
- 承認するのは、マージされたコミットが最新の提出のコミットと一致するときだけ。一致しなければ記録して、承認にせず人間の判断を待つ。
- 再提出のとき、前の PR がすでにマージ済みなら、その PR を更新せずに新しい PR を作る。
- PR のあるタスクは、画面からの承認を受け付けない（画面は PR への案内とリンクを出す）。PR を作らないリポジトリは、これまでどおり画面で承認・差し戻しする。差し戻しは、PR から取り込めるようになるまで画面でも受け付ける。

## 理由

- 画面で承認しても PR がマージされないという動作確認のフィードバックを受け、ステークホルダーと「成果物チェックは PR 上で判断し、マージを承認とみなす」と決めた（本文）。
- 最新の提出との照合は、レビューの指摘による。差し戻しの後、再提出の前に元の PR がマージされると、元の PR に含まれていない修正まで完了扱いになることが再現されたため（レビュー）。
- 画面からの承認を拒否する理由は記録に無い。

## 影響

- PR のあるタスクの完了は、GitHub での人間のマージに依る。
- 範囲が広いので PBI-14 を2つに分け、PR のレビューを差し戻しとして取り込む部分は次のタスク（PBI-14b）に回した。
- 古い提出がマージされたタスクは、人間が差し戻すか中止するまで止まる。
