## 背景

`create_task` は対象のリポジトリを送らず（`repo: null`）、作った後にオーケストレーターが題と説明から選んでいた。
対象が1つだけのプロジェクトでも選ぶ実行が1回かかり（費用と時間）、複数あるプロジェクトでは、作る側がリポジトリを決められず、選ばれたものも MCP の結果から分からなかった。
利用者は 2026-11-21 に、作成で対象のリポジトリを指定できるようにすると決めた。

## 決定

- `create_task` に、省ける引数 `repo`（リポジトリの URL。1つだけ）を足す。省くと、今までどおり `repo: null`（指定しない）を送る。指定すると、その値をそのまま送る。
  `repos`（複数）・進め方・テンプレート・イメージは足さない（必要になったら別の件）。
- 指定した `repo` の検査は、MCP の層ではしない。プロジェクトの対象に無い値と、URL の形でない値（`owner/repo` の短い形を含む）は、デーモンの `task.repositoryUnknown`（409）の文をそのまま返す。画面と同じ理由になる。
  空・空白だけは、API を呼ぶ前に `CreateTaskInput` で断る（指定したつもりの誤りを、黙って「指定しない」にしない）。
- `list_projects` の結果の形は変えない。説明に、`targets` の URL（`scope` が `repo`）と、Org の対象の下のリポジトリの URL を `repo` に渡せることを書く。
  Org の対象は、GitHub を読んで個々のリポジトリに広げない（読む時間・失敗・トークンの扱いを MCP に持ち込まない）。
- タスクの要約に `repo`（`string | null`。いつも入る）を足す。値は、`rerun_task` の既定値と同じ `source.repo ?? repo ?? repository.url ?? null`。
  `null` は「まだ決まっていない」と「リポジトリ無しで進む・進んだ」を分けず、どちらも表す（文書に、そのように書く）。分けるのは、必要になったときに、`awaitingRepository` に当たる真偽の項目を足す。
  `wait_for_task` の比べる欄には入れない。
- 新しい API はデーモンに足さない。

## 理由

- 指定したタスクは、画面と同じ要求で作られ、デーモンが `repo` を記録し `noRepo` を付けないので、オーケストレーターはリポジトリを選ばない。費用と時間が省ける。
- 検査をデーモンに任せると、画面と同じ理由・同じ条件になり、MCP が重ねて持たずに済む。
- Org の下の URL を AI が指定できる点は、画面（人が選ぶ）と違う。Org を対象に登録した時点で、その下のリポジトリを作業対象にすることをすでに許しているので、画面と同じ受け入れ方にする。
  デーモンは存在を確かめないので、存在しない URL は、作成は通り、タスクの開始時の clone で失敗して一時停止（エラー）になる。エージェントは実行しないので、費用はかからない。
  別のプロジェクトがそのリポジトリを対象にしていれば、そのプロジェクトのものなので断られる。同じ Org を対象にするプロジェクトが複数あり、作成先が先に責任を持つほうでないときも、`responsibleProject` が別のプロジェクトを返すので断られる。
  チケットや PR の本文に誘導された AI が意図しないリポジトリを指定する余地は、`create_task` を利用者に頼まれたときだけ呼ぶ決まり（説明・`INSTRUCTIONS`）と、Org の登録の範囲で抑える。
  候補と照らす案（`GET /api/projects/:id/repositories` を呼ぶ）は、GitHub を読む時間と失敗の扱いが加わるので採らない。
- 要約の項目の追加は、既存の項目の名前・意味を変えないので、互換とみなす（知らない項目を読まないだけ）。

## 影響

- 要約を返すすべてのツール（`list_tasks`・`get_task`・書き込みのツール）の結果が、1項目（`repo`）増える。
- CLI とデーモンの版が揃わないとき：`POST /api/tasks` の `repo` は画面が使う既存の入力なので、前の版のデーモンでも効き、黙って無視されない。要約の元の項目が無いタスクは `repo` が `null` になる。
- 複数のリポジトリにまたがる仕事は、今までどおり画面で作る。後で要れば `repos` を足す（引数・断り・要約を直す）。
- 仕様は [MCP サーバー](../spec/mcp-server.md#create_task)、利用者向けは [手元の AI から操作する](../user/mcp.md) に書く。
