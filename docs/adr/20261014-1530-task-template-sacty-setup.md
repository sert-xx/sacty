# タスクのテンプレート「Sacty セットアップ」で、リポジトリを sacty で扱うためのエージェントの設定を整える

- 日時: 2026-10-14 15:30 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-90
- 置き換え元: なし
- 置き換え先: なし

## 背景

対象のリポジトリが sacty で動かせる状態か（エージェント向けの指示・テストの実行の仕方・テストに要るサービス・マージの後の
デプロイの確認のスキルが整っているか）を検査し、整える PR を作りたい。毎回、題と説明を人が書くのでは手間がかかり、書く内容も
揃わない。デプロイの確認のスキル `deployment-observer` は、マージの後の監視（PBI-89）が決まった置き場所で探し、決まった形の答えを
読むので、作るスキルもそれに合わせる必要があった。

## 決定

- タスクの作成に、テンプレートを足す。テンプレートは `sacty-setup`（Sacty セットアップ）だけ。画面ではテンプレートを選ぶと、
  リポジトリを選ぶだけのフォームになる。API（`POST /api/tasks`）は、本文に `template` があればテンプレートの入力
  （`template`・`projectId`・`repo` だけ。`title`・`body` は受け付けない）として扱う。
- 題と説明（ゴール）は、テンプレートから sacty が決めて `TaskCreated` に書き、`template` も記録する。作った後は、通常のタスクと同じく
  オーケストレーターが進め方を選ぶ（テンプレートで工程を固定しない）。
- 対象リポジトリは必須（プロジェクトの対象がリポジトリ1つだけなら省略できる）。
- ゴールは、特定の言語・ツール・sacty 自身に寄せない文にする。スキルは `.agents/skills/` を原本にし、`.claude/skills/` は原本への相対の
  シンボリックリンクにして二重に管理しない。`deployment-observer` には、PBI-89 が読む見出し `sacty-deployment` の答えの形を書かせる。
- 変更が要らなければ、PR を作らずに調査だけで終えるよう、ゴールに書く（オーケストレーターがコードを読んで `investigate` を選ぶ）。
- CLI にはタスクを作るコマンドが無いので、CLI のコマンドは足さない（入口は画面と API）。

## 理由

- ゴールを作成の時点で説明に書いたのは、オーケストレーター・工程のエージェント・画面が、通常のタスクと同じ説明を読むだけで済むため
  （テンプレートごとの分岐を工程の処理に足さない）。作業履歴にも、そのとき渡したゴールがそのまま残る。
- テンプレートで工程を固定しなかったのは、整っていれば調査だけ、整えるなら PR、という判断はリポジトリを読まないとできず、
  オーケストレーターの選び方（コードを読んで選ぶ）と同じだから。
- テンプレートの入力で `title`・`body` を誤りにしたのは、渡した値が黙って捨てられたと気づけないため。
- CLI のコマンドを足さなかったのは、受け入れ条件が「今のタスクの作成の入口に合わせる」で、今の CLI にタスクを作る入口が無いため。

## 影響

- テンプレートを足すときは、`TaskTemplate` に名前を足し、`templateTask` に題と説明、画面の文言に名前を足す。
- ゴールの文は日本語の固定の文で、画面の言語に合わせて変えない（工程のエージェントへの指示と同じ）。
- `deployment-observer` の置き場所・答えの形（PBI-89 の `DEPLOYMENT_SKILL_PATHS`・`DEPLOYMENT_HEADING`）を変えるときは、
  `apps/daemon/src/task-templates.ts` のゴールも合わせて直す。
- 仕様は [タスクと工程](../spec/tasks-and-steps.md#タスクのテンプレート)。
