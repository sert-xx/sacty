# Sacty のレビューが止まったら、レビューを頼んだ PR にコメントで知らせ、再開して投稿したら解消済みに書き換える

- 日時: 2026-11-03 07:46 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-292
- 置き換え元: なし
- 置き換え先: なし

## 背景

実験で、PR #288 にレビュー用のラベルを付けてレビューを頼んだところ、codex が「Selected model is at capacity」で失敗し、レビューのタスクがエラーで一時停止した（findings F37）。
PR にはラベルだけが残り、約50分レビューが来なかった。画面から再開すると走り直し、指摘なしになった。
レビューを頼んだ人は PR だけを見ているので、止まったことに気づけない。Slack とデスクトップの通知は、sacty を使う人にだけ届く。

## 決定

- **PR に知らせる**：レビューのタスク（PR のレビューの取り込みと、レビューの対象を決めたタスク）が、レビューを投稿する前に、人が止めたのではない理由（`error`・`usage_limit`・`auth`・`budget`）で一時停止したら、その PR に通常のコメント（Issue のコメント）を書く。止まったこと、理由の要点、再開のしかた（タスクの画面へのリンク）を入れる。
- **理由は、秘密情報を伏せてから切り詰め、コードにして載せる**：外から来た文（エージェントの出力・stderr）が入るため。
- **同じ止まり方で何度も書かない**：コメントの先頭に、タスクと「止まり方（理由の種類と要点）」の目印を入れ、解消していない同じ目印の自分のコメントが PR にあれば書かない。違う止まり方は別のコメントにする。
- **古くなったら書き換える**：再開してレビューを投稿したら、そのタスクの解消していないコメントを、目印の末尾を `:resolved` にして「解消済み」に書き換える（消さない。何が起きたかは残し、案内は外す）。
- **PR の指摘に取り込まない**：この投稿は人間の指摘ではない。そのタスクのアカウントと、その PR をレビューした sacty のタスクのアカウントの、この目印のコメントは、PR の指摘の取り込みから除く。
- **一時的な失敗の自動のやり直しは足さない**：同じエージェントで間を置いてやり直す処理は作らない。

## 理由

- タスクの状態は、タスクの一時停止の記録（作業履歴）が正で、PR のコメントは知らせるためだけのもの。コメントの有無を状態として持つと、作業履歴に新しい種類の記録を足し、状態の復元と各画面に影響する。目印を PR のコメントに持てば、デーモンを再起動しても二重に書かず、作業履歴の形を変えない。書けなかった知らせを書き直さないのは、その代わりに受け入れる制限。
- 消すより書き換える方が、後から PR を読む人に「止まって、再開された」ことが残る。
- PR の指摘に取り込まないのは、取り込むと、sacty が作った PR のタスクが、自分の知らせのコメントを人間の指摘として作り直しを始めるため。他人が目印をまねたコメントまで除くと、人間の指摘を隠せてしまうので、sacty のアカウントのものだけを除く。
- 自動のやり直しを足さない理由（調べた結果）
  - 既にある仕組み：エージェントに `fallback`（代わりのエージェント）を書くと、理由を問わず、止めずに代わりで実行し直す（`pauseOrFallBack`）。これは設定で選ぶもので、F37 の環境では `codex_advanced` に書いていなかったので、すぐ止まった。ゲートウェイのリトライ（429・5xx を最大 8 回、合計 10 分まで）は、ゲートウェイを通す AI の呼び出しだけで、サブスクリプションで動く CLI の失敗には効かない。同じエージェントで待ってやり直す処理と、時間が経ったら自動で再開する処理は無い。
  - 「at capacity」は `classifyFailure` で `error` になる（利用上限・認証の語に当たらない）。やり直すには、エージェントごとに変わる文言で一時的な失敗かを判定する必要がある。判定を誤ると、続く本物のエラーを繰り返しやり直す。
  - 失敗した実行は、始まって少し作業した後かもしれず、使った費用を読めない（`costUnknown`）。無条件にやり直すと、費用が二重にかかる。待つ間の状態と回数の上限も要る。
  - 被害は「止まったと分からない」ことだった。知らせれば、人が再開できる（F37 も再開で直った）。代わりのエージェントを書くことで、自動の切り替えは今も選べる。

## 影響

- レビューを頼んだ人は、止まったことと再開のしかたを PR で知る。再開すると、そのコメントは解消済みになる。
- 書けなかったときと、デーモンの再起動をまたいだときは、書き直さない（ログに警告を出すだけ）。レビューのタスクが中止された場合、止まったことのコメントはそのまま残る。
- PR にコメントする権限が、レビューを投稿する権限（PR への書き込み）と同じアカウントで要る。足りなければ、警告を出してコメントしない。
- 一時的な失敗の自動のやり直しは、今回は足さない。足すなら、一時的な失敗の判定、待ち方と回数の上限、費用の扱いを決める別の PBI にする。
