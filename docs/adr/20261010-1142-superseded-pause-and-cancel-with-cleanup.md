# タスクの一時停止は作業領域を残して止めたところから再開でき、中止は sacty が作ったものだけを確認の画面に並べてから片付ける

- ステータス: 置き換え済み（superseded）
- 関係する PR・タスク: #12、PBI-3
- 置き換え元: なし
- 置き換え先: [大きなタスクを「タスク分割」の工程で子タスクに分け、子ごとに PR を作って依存の順に進める](20261012-0226-superseded-task-split-into-subtasks.md)（子タスクを中止の対象にしない部分）

## 背景

タスクを人間が途中で止める手段が無かった。止めたタスクを続けられるようにすることと、やめたタスクが残したもの
（コンテナ・作業領域・ブランチ・PR）を、人間が作ったものに触れずに片付けることが必要だった。

## 決定

- 一時停止
  - タスク詳細に「一時停止」を置き、実行待ち・実行中・検証中（テスト・最終レビュー）のタスクで出す。
  - 実行中なら、そのコンテナ（工程エージェント・テスト・最終レビュー）を止め、処理が終わるのを待ってから `TaskPaused`（理由は `manual`）を記録する。
    中断した実行は失敗として記録し、止めたテストの結果は記録しない。
  - 作業領域（clone）は残す。再開すると止めたところから続け、実行中だった工程は実行し直す。
  - 承認待ち・エスカレーションと、ゴールガーディアンが変更の申し出を判定している間は止めない。
- 中止
  - 「中止…」で確認の画面を開き、対象（実行中のコンテナ・作業領域・セッション・sacty のブランチ・sacty が作った PR）ごとに、片付けるものと名前を並べてから実行する。
  - 順に、コンテナを止める → PR を閉じる（マージしない）→ sacty のブランチをリモートから消す → 作業領域と退避した git のメタデータを消す。
  - ブランチは `sacty/` で始まるものだけを消し、PR は sacty が作って記録したものだけを、記録したリポジトリと番号で閉じる。
    プッシュしたブランチは、PR の作成の前に `BranchPushed` として記録し、PR の作成に失敗しても中止で消す。
  - 片付けの結果を、対象ごと（片付けた・対象なし・失敗と理由）に `TaskCancelled` に記録する。片付けに失敗しても残りは続ける。
  - 中止したタスクの台帳は残し、以降の操作は受け付けない。
- 止めたことの確認
  - コンテナの準備（clone・秘密情報の取り出し）の間に止められたら、コンテナを起動しない。
  - 止める要求があった実行は、コンテナが無いことを確かめるまで完了にしない。確かめられなければ、一時停止は警告を添えて記録し、
    確かめられなかった実行を `TaskPaused.unstoppedRuns` に残す。中止と再開は、それを確かめ直し、確かめられなければ中止は作業領域を消さず、再開は拒否する。
- 子タスクは、まだ親子関係が無いため対象にしない。

## 理由

- 人間の判断待ち（承認待ち・エスカレーション）を止めないのは、すでに人間の判断待ちのため。ゴールガーディアンの判定中（数十秒）を止めないのは、
  止めると「判定できない」扱いになるため（PR の本文）。
- セッションは、sacty が保存しない（実行ごとに空の設定で起動する）ので、常に「対象なし」とした（PR の本文）。
- 子タスクを対象にしないのは、MVP にまだ親子関係が無いため。親子関係を入れるときに対応する（PR の本文）。
- PR を記録したリポジトリで閉じるのは、いまの設定のリポジトリと記録した番号を組み合わせると、設定を変えたときに同じ番号の人間の PR を閉じてしまうことが、
  レビューで見つかったため（レビュー）。
- プッシュしたブランチを PR の作成の前に記録するのは、PR の作成に失敗すると、プッシュ済みのブランチが中止で消されずに残ることが、レビューで見つかったため（レビュー）。
- 止めたことを確かめるまで完了にしないのは、`docker run` の子プロセスが終わっただけではコンテナが止まった確認にならず、残ったコンテナが作業領域に書き込む間に
  再開や中止（作業領域の削除）が進みうることが、レビューで見つかったため（レビュー）。
- ブランチを `sacty/` で始まるものに限ることは、受け入れ条件（人間が作ったブランチや PR には触れない）による。それ以上の理由は記録に無い。

## 影響

- 一時停止・中止は、実行中の処理が終わり、止めたことを確かめるまで返らない。
- 古い PR の記録（リポジトリの記録が無いもの）は、中止で閉じずに失敗として残る。
- 親子関係を入れるときに、中止を子タスクへ広げる対応が要る。
