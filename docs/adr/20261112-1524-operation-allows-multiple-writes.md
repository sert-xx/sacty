# 単発作業（operation）の書き込みに回数の上限を設けず、同じ書き込みの再送だけを禁じる

- 日時: 2026-11-12 15:24 UTC
- ステータス: 採用
- 関係する PR・タスク: #352
- 置き換え元: [文書原稿と単発の外部作業を独立した承認工程で扱う](20261015-2353-superseded-non-code-workflows.md)（外部操作の書き込みを1回にする部分）
- 置き換え先: なし

## 背景

operation 工程の固定の指示は「書込要求は1回だけです」としていた。
Slack に親の投稿をして、そのスレッドに返信するスキルのように、依頼を果たすのに書き込みが2回以上要るタスクでは、この指示と依頼が食い違い、エージェントが投稿せずに失敗として終えていた。
もともとの狙いは、失敗や結果不明の後に同じ書き込みを繰り返して、外部に重複を作らないことだった。

## 決定

- 依頼を果たすのに要る書き込みは、すべて行わせる。書き込みの回数に上限を設けない。
- 同じ書き込みは1回だけにする。エラー・タイムアウト・結果不明の後に、同じ書き込みを再送させない。
- その時点で残りの書き込みもさせず、失敗として、成功を確かめた書き込み・行っていない書き込み・結果が不明な書き込みを分けて報告させる（結果が不明なものは外部で成功しているかもしれず、行っていないものと混ぜると、残りを新しいタスクで行うときに重複しうる）。

## 理由

重複を防ぐのに要るのは、同じ書き込みを繰り返さないことで、書き込みの回数を1に限ることではない。
回数を1に限ると、正当な複数の書き込みが要る依頼を operation で扱えなくなる。
失敗の後に残りの書き込みを続けると、途中までの状態がさらに分かりにくくなるので、そこで止めて人間に外部の状態を確かめさせる（再開を拒む今の扱いと同じ）。

## 影響

- 親の投稿とスレッドへの返信のような、複数の書き込みが要る依頼を operation で実行できる。
- sacty は外部の側での exactly-once を保証しないことは変わらない。再送しないことは、エージェントへの指示である。
