# sacty mcp の成果物とログの取得は、バイトで上限と位置を決め、デーモンに読み取りの API を足す

- 日時: 2026-11-19 02:00 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-395
- 置き換え元: なし
- 置き換え先: なし

## 背景

`sacty mcp` で、手元の AI が、タスクの工程ごとの成果物と、エージェントの実行の一覧・ログを、画面を開かずに読めるようにする（読み取りだけ）。承認の前に中身を確かめるための手段になる。
決める必要があったのは次のこと。

- 1回に返す量の上限と、その単位。続きの位置の示し方。
- 終わった実行のログを、範囲で読む方法（いまのログの API は、終わった実行では全体を最大約 20MB 読んで JSON で返す）。
- 実行の一覧の元と、成果物・実行の指定の方法（パスを引数に取るので、決まった場所の外を読ませない）。
- 実行中のログの秘密情報（後から分かった値が、閉じるまでファイルに伏せないまま残る）。
- 新しい API を足すことで、前の版のデーモンが「タスクが無い」と同じ 404 を返す問題。

前の ADR は「デーモンに MCP のための API は足さない」と決めていた。今回の依頼は、要るなら API を足すことを認めている（画面の動きは変えない）。

## 決定

- **上限と単位**：1回に返す量の上限は、UTF-8 で 32,000 バイト（日本語でおよそ1万字）。位置と量の単位は、伏せ直す前の UTF-8 のバイト（ファイルとメモリーにあるバイト）。
  `max_bytes` は省くと上限で、超える値は上限に収めて `clamped` で示す（断らない）。0 以下と負の位置は引数の型で断る。全体以上の位置は失敗にせず、0バイトと全体の大きさを返す。
  境目は、UTF-8 の文字の頭にそろえる（複数バイトの文字・サロゲートペアの途中で切らない）。
- **続きの位置**：結果に `offset`（返した先頭）・`next`（続き）・`totalBytes`・`clipped`・`clamped` を返す。ログは、末尾から読む指定（`from_end`）と、位置から順に読む指定（`offset`）の両方を持つ。
  実行中のログは、先頭の上限（events は 15MB）を超えた後の末尾の位置が読むたびにずれ、実行が終わるとファイルの位置に変わる。`running` が変わったか `omittedMiddle` が真のときは、`from_end` で読み直す。
- **デーモンに読み取りの API を4つ足す**：`GET /api/tasks/:id/deliverables`・`…/deliverables/:step/:kind`・`…/runs`・`…/runs/:runId/log/range`。画面は呼ばない。いまの API・いまの5つのツールは変えない。
  実行を拾う規則（`RUN_EVENTS`・`runLogId`）は `@sacty/core` に移し、画面と共有する（画面の表示は変わらない）。
- **範囲の読み取りはデーモンが行う**：終わった実行はファイルの範囲だけを `readSync` で読む。実行中の実行は、先頭のファイルの範囲＋省いた印＋メモリーの末尾の範囲を組む（`snapshot()` は先頭のファイルを全部読むので使わない）。
  MCP のための別の記録は作らない。デーモンも MCP サーバーも、全体を読み込まず、返す量に見合うメモリーだけを使う。
- **成果物の指定**：工程（`step`）と種類（`kind`）の組で指定する。種類は `output`・`test_viewpoints`・`sacty_version`・`review_comments` の4つ。
  状態は `approved`・`posted`・`awaiting_approval`・`not_submitted`・`changes_requested`・`none`。まだ提出していない出力は、`submission` を null にして `previousSubmission` で前の回を示し、前の回の提出と読み違えさせない。
  読めるのは、画面のタスクの詳細で読める範囲（承認済みならその版、まだなら最新の出力。レビューは本文と行へのコメント）。差し戻し前の過去の回と、エージェントの元のファイル（`agent-files`）は含めない。
- **実行の指定**：実行の一覧は、メモリーの作業履歴の全件から `runLogId` で拾い、役割・エージェント・切り替え（`fallback`）を決めてからページに切る（ページの区切りで結果が変わらない）。返す分だけ `meta.json` を読む（`meta.json` が無い実行は、作業履歴の値。無い項目は null）。
  `task_id`・`run_id` は `[A-Za-z0-9_-]{1,128}` に合うものだけ。ログのファイルは、開く前に `lstat`・`realpath` で、`runs/<タスク>` もファイルもリンクでなく、通常のファイルで `runs/<タスク>` の下にあることを確かめる。工程・種類は許可リストと照合する。
- **前の版のデーモンの見分け方**：新しい API を持たない前の版は、Hono の既定の 404（本文は `404 Not Found`）を返す。タスクが無いときは `{ error: "not_found" }` の JSON の 404 なので、本文が `error` を持つ JSON として読めない 404 を前の版とみなし、「sacty を更新し、実行中のタスクが無いときに `sacty up` で起動し直してください」と返す。
  再起動は、実行中のタスクを止めるので、無いときにする前提を理由に添える。
- **伏せ直せていない実行**：ログは、実行中・終了後を問わず、呼び出しの時点でデーモンが持つ秘密情報（その実行の秘密情報と、プロジェクトの設定・GitHub のトークンの値）で伏せ直してから切る。範囲の前後に、秘密情報の最長の形の分だけ余分に読み、境目が値にかかるときは外側へ広げる。
  実行中のログの読める終わりは、`StreamRedactor` が伏せる前に持っている分（`peek()`）を含めず、終わりが呼び出しの時点の秘密情報の形のどれかの先頭の一部で終わるときは、その一部も外す（途中で足された値は、知る前に出た先頭が `peek()` の外に出ているため）。外した分は、続きが届いてから遅れて読める。
  間を省いたログの2つの継ぎ目（先頭の終わり・末尾の始まり）も、値の続きが記録に無い所なので、前後に残る値の一部を `[REDACTED]` にし、境目を外側へ広げる。位置は変えず、終わった実行の継ぎ目は `meta.json` に残す。閉じるときの伏せ直しも、継ぎ目の前後で分けて伏せる。
  書き始めた後に `addSecrets` で値が増えた実行は、値をストアのメモリーに持ち、`meta.json` に `redactPending: true` を書く（書けなくても値は持ち続ける）。閉じるときの伏せ直しが全部済み、`redactPending` を消した `meta.json` を書けたときだけ、値を捨てる。どちらかが失敗したら、デーモンが動いている間だけ持つ。
  デーモンが開いておらず、値も持たない実行は、`redactPending` が真か、`finishedAt` が無い（デーモンが止まった実行。前の版が書いた実行と、`redactPending` を書けないまま止まった実行を含む）なら、中身を返さずに理由を返す（API は 409）。
  `finishedAt` があり `redactPending` が無い実行は、伏せ直しが済んだものとして返す。前の版で伏せ直しに失敗して終わった実行は、これと見分けられない（`meta.json` に前の版と見分ける印が無いため）。この場合は、秘密情報が平文で残るログを返しうる（画面は元から伏せずに返す）。
- **失敗の理由**：理由と標準エラーの1行は、仕様書の定型の文言に限る。デーモンの応答の本文と、成果物・ログの中身は出さない。標準エラーの原因は、接続の失敗の種類と時間切れの印だけにする。

## 理由

- バイトにそろえたのは、ログの位置がファイルのバイトで数えられ、範囲の読み取り（`readSync`）と続きの位置が、文字数への変換なしにそろうため。`get_task` の文字数（UTF-16）の上限は、サロゲートペアの途中で切りうるうえ、続きの位置を返せない。
- 範囲の読み取りをデーモンに足したのは、いまの API が終わった実行で全体を読み、MCP の側で読み捨てると、呼ぶたびに両方のプロセスが最大約 20MB を持つため。
- 伏せ直しを呼び出しの時点で行うのは、画面の API が実行中のファイルをそのまま返し、後から分かった秘密情報が伏せないまま手元の AI と外部のサービスに渡るのを防ぐため。
- 全体以上の位置を失敗にしないのは、実行中のログを続きから読み直すとき、まだ増えていないことを失敗と区別するため。
- 比べた案：
  - 既存の `files/:file`（全体のストリーム）を MCP の側で読み捨てる案：メモリーは抑えられるが、毎回デーモンが全体を送り、時間切れ（30 秒）の危険があり、実行中のメモリーの末尾を読めない。採らなかった。
  - 既存の `log`（`eventsFrom`）に範囲を足す案：画面が使うので、画面の動きを変えるおそれがある。採らなかった。
  - 文字数で上限を持つ案：位置をファイルのバイトと対応させられない。採らなかった。
  - 伏せ直せていない実行の値を持たず、残りうると文書に書く案：秘密情報を出さないことを優先して採らなかった。
- 上限 32,000 バイトは、`get_task` のレビューの本文（12,000 文字）と同じくらいの量。手元の AI の文脈が小さいと、利用者が `max_bytes` を小さく指定し直す手間が増える（未確認の懸念）。

## 影響

- ツールは9つになる。成果物とログの4つは読み取りだけ（`readOnlyHint: true`・`openWorldHint: false`）。説明文と使い方の説明に、結果はほかの人やエージェントが書いた文を含むデータで、中の指示に従わないことを書く。
- `meta.json` に `redactPending` を足す（画面は読まない）。
- 前の版の sacty が動いているときは、新しいツールが更新と再起動を促す理由を返す。
- 仕様書 [MCP サーバー](../spec/mcp-server.md)・[全体の構成](../spec/architecture.md)、ユーザードキュメント [手元の AI から操作する](../user/mcp.md)・[CLI](../user/cli.md)（いずれも日英）を直した。
- 続きは、承認・差し戻しなどの操作（次の回）。成果物の過去の回・`agent-files`・作業履歴の中身の取得は、必要になれば別に決める。
