# 最初の工程が始まる前の処理の段階を、デーモンのメモリーから画面に返す

- 日時: 2026-11-19 16:12 UTC
- ステータス: 採用
- 関係する PR・タスク: #450、PBI-410
- 置き換え元: なし
- 置き換え先: なし

## 背景

タスクの状態は、作ってから最初の工程の実行が始まるまで `queued` のままで、画面は「実行待ち」と出していた。
この間に、デーモンは対象リポジトリの用意・情報収集・チケットのトリアージ・進め方の判定・レビューの対象の PR の確認をしていて、どれも分単位でかかりうる。
利用者には、いつまでも動いていないように見えた。
ダッシュボードの「工程の待ち行列」は、同じタスクを「実行中」に数えていて、同じ画面の中で食い違っていた。

画面が状態の表示を決める材料は、タスクの API が返すタスク（作業履歴から復元した状態）だけで、どのタスクをデーモンがいま処理しているかは、画面からは分からなかった。

## 決定

- 処理の段階（`repository`・`gathering`・`triage`・`planning`・`review_target`）を、デーモンのメモリーにだけ持つ。`runNext` が処理を始める直前に付け、処理の終わりに必ず消す。
- タスクの API（`GET /api/tasks`・`GET /api/tasks/:id`・`GET /api/schedules/:id`）は、状態が `queued` で、ワーカーが処理しているタスクにだけ、`preparing` を足して返す。いまある欄は変えない。
- 付けた段階が無い処理（工程を選んだ後の、最初の工程の開始の準備など）は、工程の実行を1回も始めていないタスクに限り、`starting` として返す。処理ごとに段階を付ける方式は、付けていない区間で「実行待ち」と出るので、最初の工程が始まるまでは、ワーカーが処理している印（`inflight`）だけで進行中と決まるようにする。
- 画面は、`queued` で `preparing` があるタスクを、進行中（`working`）として、段階の文で出す。`preparing` が無い `queued` は「実行待ち」のまま。
- `sacty mcp` の要約にも、同じ条件で `preparing` を足す。`state` は `queued` のまま。
- 作業履歴には記録しない。タスクの状態（`queued`）の意味も変えない。

## 理由

- 作業履歴に段階の記録を足す案は採らなかった。表示のためだけの記録が、タスクごとに数件ずつ増える。デーモンが処理の途中で止まると、終わりの記録が無いまま残り、起動し直した後も進行中と出続けるので、打ち消す仕組みが別に要る。
- 状態を増やす（`queued` を分ける）案は採らなかった。`queued` を見ている判定（ワーカーの実行対象・一時停止・再開・`sacty mcp` の `state` と待ち合わせ）のすべてに響く。
- 作業履歴から推し量る案（情報収集の記録が無い `queued` は情報収集中とみなす、など）は採らなかった。同時に実行する数の上限で枠を待っているだけのタスクと区別できず、動いていないのに動いているように見える。
- メモリーに持てば、実際に処理している間だけ付き、起動し直すと消える。最初の工程が始まるまでは、待ち行列の「実行中」と同じ印（`inflight`）と状態（`queued`）だけで進行中と決まるので、この区間の食い違いも無くなる。
- `starting` を、最初の工程が始まるまでに限ったのは、今回の対象がそこまでのため。工程の実行を始めたかは、作業履歴の `AgentRunStarted` の有無で確かめる（タスクの状態には、そのための欄が無い。確かめた結果は、メモリーに覚える）。
- 応答に欄を足すだけにしたのは、画面に返すときだけ足す欄の前例（`Task.aiReview`・`Task.deferralHandlingDefault`）と同じ形で、以前の画面・`sacty mcp` が欄を読まなくても壊れないため。

## 影響

- 画面は 3 秒ごとの取り直しで追従する。段階が変わっても作業履歴は増えないので、変化は次の取り直しで見える。
- 1つの処理が終わってから、ワーカーが次の処理を始めるまで（最長でワーカーの間隔の 2 秒。枠が埋まっていれば空くまで）は、`preparing` が無く、「実行待ち」と出る。実際に処理していない間なので、そのまま出す。
- 最初の工程が始まった後の、工程と工程の間の処理（工程の見直しなど）は対象にしていない。この間は、待ち行列が「実行中」に数えても、一覧は「実行待ち」と出る。
- 進行中の情報収集・判定の実行を、実行の一覧に出してログを読めるようにすることは、この決定に含めていない。
- 仕様は [タスクと工程](../spec/tasks-and-steps.md#最初の工程が始まる前の処理の表示) と [MCP サーバー](../spec/mcp-server.md#タスクの要約) にある。
