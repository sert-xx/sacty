# レビューを依頼された PR とレビュー用のラベルの PR を取り込み、オーケストレーターを使わずにレビューだけを行う

- 日時: 2026-10-13 03:35 UTC
- ステータス: 採用
- 関係する PR・タスク: #55、PBI-44
- 置き換え元: なし
- 置き換え先: なし

## 背景

ほかの利用者に sacty を広めるための最初の使い方として、PR のレビューだけを sacty に任せたい。これまでの取り込みは、取り込むラベルの付いた Issue・PR を
タスクとして取り込むものだけだった。

## 決定

- 「sacty の設定」に「PR のレビューの取り込み」を、Issue の取り込みのラベルとは別の設定として足す。
  - 自分にレビューが依頼された PR を取り込む（切り替え）。自分は、プロジェクトでそのホストに選んだ GitHub のアカウント。個人としての依頼だけで、チームへの依頼は含めない。
    取り込むのは、担当のプロジェクトでそのホストに選んだアカウント本人への依頼だけ。
  - PR のレビュー用のラベルの付いた PR を取り込む（Issue は取り込まない）。
  - github.com と GitHub Enterprise Server の両方で、ホストごとのアカウントで探す。
- この取り込みの PR は、オーケストレーターを使わずに、工程をレビューだけにする。レビューは、PBI-19 のとおり人の承認を挟まずに PR にコメントのレビューとして投稿する。
  依頼・レビュー用のラベル・取り込むラベルのどれに当てはまっても、タスクは1つで、レビューだけ。プロジェクトの対象で指定したイメージは使う。
- PR がマージ・クローズされたら、終わっていないレビューのタスクを sacty が中止する。
- レビューを投稿して完了したタスクで、「再レビュー」で PR の最新のコミットをもう一度レビューして投稿できる。回ごとに別の目印をレビューの本文に入れる。

## 理由

- PR のレビューだけを任せる流れを、ほかの利用者に広める最初の使い方にするため（PR の本文）。
- オーケストレーターを使わないので、工程の選択の費用がかからない（PR の本文）。
- 本人への依頼だけを取り込むのは、Org とリポジトリで別のアカウントを選んだ構成で、別のアカウントへの依頼がそのプロジェクトのタスクとして取り込まれ、
  依頼されていないアカウントで自動で投稿されるというレビューの指摘による（レビューとその返信）。
- 回ごとの目印は、前回のレビューを今回の投稿済みと見なさないため（PR の本文）。
- チームへの依頼を含めない理由は、記録に無い。

## 影響

- レビューの取り込みのタスクは、要求要件・実装などの工程に進まない。
- これまでの Issue・PR の取り込み（取り込むラベル）は、そのまま動く。
