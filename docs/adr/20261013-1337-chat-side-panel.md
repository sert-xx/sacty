# オーケストレーターへの質問は、画面右下の AI のアイコンから開く、モーダルにしないサイドパネルのチャットにする

- 日時: 2026-10-13 13:37 UTC
- ステータス: 採用
- 関係する PR・タスク: #68、PBI-61
- 置き換え元: なし
- 置き換え先: なし

## 背景

#63 で、タスクの詳細の本文の中に「オーケストレーターに質問」の欄を置いた。この欄を、本文を読みながら使える形に変える必要があった。

## 決定

- 本文の中の「オーケストレーターに質問」の欄を無くし、画面の右下に固定した AI のアイコンから開くサイドパネルのチャットにする。
- パネルは既存の Base UI の Dialog をモーダルにしない形で使う（新しいライブラリは足さない）。広い画面ではヘッダーの下の右側に 440px、
  狭い画面では全幅。開いたままでも本文を読めて操作できる。閉じるボタンと Esc で閉じる。開くとフォーカスがパネルへ、閉じるとアイコンへ戻る。
- 答え待ちの間は、パネルを閉じていてもアイコンに印を出し、ボタンの名前でも伝える。
- 開いたとき・答えが来たときは最新まで送る。質問の入力はパネルの下に固定し、閉じても書きかけを残す。入力欄と入力の領域には高さの上限と
  中のスクロールを付ける。
- チャットの中身（質問の一覧・答え・送信・質問できない理由）は、#63 のものをそのまま使う。
- あわせて、タスク詳細の「中止…」のボタンを「中止」にする（英語は「Cancel…」→「Cancel」）。

## 理由

- 入力欄と入力の領域に高さの上限を付けたのは、レビューで、固定の高さのパネルでは長い質問で送信のボタンがパネルの下端からはみ出し、
  送信できなくなることがわかったため（レビューとその返信）。
- サイドパネルにすること・モーダルにしないこと・ボタンの「…」を外すことの理由と、比べたほかの案は記録に無い。

## 影響

- 質問の欄は、どの位置までスクロールしていても右下のアイコンから開ける。
- パネルの開閉・フォーカスの部品のテストは無い（テストの環境が DOM を使わないため。ブラウザでの確認で代えた）。
- 375px でパネルの端までスクロールすると、後ろの本文もスクロールすることがある。
