# オーケストレーターが工程を選べなかったときは、標準の工程で代わりに進めず、理由を記録して止める

- 日時: 2026-10-13 00:03 UTC
- ステータス: 採用
- 関係する PR・タスク: #46、PBI-40
- 置き換え元: [オーケストレーターが認証の失敗・利用上限で実行できなければ、標準の工程で進めずにその理由で一時停止する](20261012-0817-superseded-orchestrator-failure-pauses-task.md)（ほかの理由の失敗では標準の工程で進める部分）
- 置き換え先: なし

## 背景

オーケストレーターが工程を選べなかった（実行の失敗・読み取れない出力）ときは、標準の工程で代わりに進めていた。
テストのコマンドもオーケストレーターが決めるようになって（PBI-25）から、代わりに進めると、実装を含むのにテストのコマンドが無いので、
必ず「テストのコマンドを決められませんでした」で止まっていた。調査のタスクでも、オーケストレーターが接続の失敗などで選べないと、
この誤った理由で止まっていた（利用者の環境で発生した）。

## 決定

- オーケストレーターの実行に失敗した・選んだ工程を読み取れなかったときは、標準の工程で代わりに進めず、その理由を記録して止める。
- 再開すると、工程の選択からやり直す。

## 理由

- 代わりに標準の工程で進めても、テストのコマンドが無いために必ず誤った理由で止まり、本当の失敗の理由がわからなかったため（コミット・PR の本文）。

## 影響

- オーケストレーターの失敗は、その理由でタスクが止まる。利用者は原因を直してから再開する。
