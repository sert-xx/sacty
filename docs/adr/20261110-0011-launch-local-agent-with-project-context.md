# プロジェクトのコンテキストで、ホストの Claude Code・Codex を利用者のログインのまま対話で起動する CLI を足し、作業履歴には記録しない

- ステータス: 採用

## 背景

プロジェクトのコンテキスト（規則・スキル・MCP サーバー・外部 PF・エージェントの設定・段階のサブエージェント）は、工程・情報収集・オーケストレーターなど、sacty が起動するコンテナの中のエージェントにだけ渡していた。
利用者が手元の端末で、同じコンテキストを使って Claude Code・Codex と対話したいという要望があった（タスクの外で、対象リポジトリの手元の clone を触るときなど）。

合成の結果は `sacty context preview` で見られるが、実際に使うには、利用者が置くファイルを手で写し、MCP の宛先と認証を自分で組み替える必要があった。
工程の実行の組み立てはコンテナの中を前提にしていて、そのままではホストで使えない。

- 設定の場所を実行ごとの空の場所（Claude Code は `CLAUDE_CONFIG_DIR=/tmp/sacty-claude-config`、Codex は `CODEX_HOME=/.codex`）にし、認証は sacty の秘密情報から入れる（`apps/daemon/src/agents/invocation.ts` の `buildInvocation`）。
- ゲートウェイ経由の MCP サーバーの宛先は `http://host.docker.internal:<ポート>/ctx-mcp/<名前>` で、実行ごとのトークンを付ける（`routeMcp`・`Gateway.containerOrigin`）。ゲートウェイ自体は 127.0.0.1 で待ち受けるので、ホストのプロセスからは `http://127.0.0.1:<ポート>` で届く。
- 権限の確認は求めないモード（Claude Code は `--permission-mode` の引数、Codex は `--sandbox danger-full-access`）で動かし、隔離はコンテナが受け持つ。
- 渡したコンテキストは、実行ごとに `ContextResolved` として作業履歴に記録する。

## 決定

### コマンド

- CLI に `sacty launch <プロジェクト> [--runtime claude-code|codex] [--cwd <ディレクトリ>] [-- <AI の CLI に渡す引数>...]` を足す。
  - `<プロジェクト>` は ID か名前（`sacty context preview` と同じ）。
  - `--runtime` の既定は `claude-code`。
  - `--cwd` の既定は今のディレクトリ。対象リポジトリを sacty から取得・用意しない（利用者の手元の clone をそのまま使う）。
  - `--` の後の引数は、sacty が組み立てた引数の後に、そのまま渡す。
- 起動中の sacty（`sacty up`）に、`daemon.json` の接続先とトークンで問い合わせる（`sacty context preview` と同じ。起動していなければ止まる）。CLI だけで合成はしない。
- AI の CLI は、端末の標準入出力と利用者の環境変数を引き継いだ子プロセスとして起動し（sacty が渡す環境変数は上に重ねる）、その終了コードで CLI も終わる。Ctrl+C などのシグナルは子プロセスに任せる。

### デーモンの API

- ローカルのセッションを作る API（`POST /api/projects/:id/local-sessions`、runtime を受ける）と、終える API（`DELETE /api/local-sessions/:id`）を足す。
- 合成は、プレビュー・実行と同じ組み立て（`buildContext`：層の取得 → 合成 → MCP の置き換え → 置くファイルの一覧）で作る。ローカル用の別の作り方はしない。
  違うのは、ゲートウェイの起点を `http://127.0.0.1:<ポート>` にすることだけ。
- 作るときに、ゲートウェイにそのセッション用の実行を登録してトークンを発行し、MCP（層のゲートウェイ経由のもの・ホストで起動するコマンド型・ホストの MCP サーバー）と、プロジェクトのコンテキストの外部 PF を、そのトークンで使えるようにする。
  AI の呼び出しの中継と GitHub の読み取りの中継は登録しない（AI は利用者のログインで直接つなぎ、GitHub はホストの gh を使える）。
- 返すのは、置くファイル（パスと中身）・環境変数（MCP の時間切れ・外部 PF の URL・秘密情報の参照を取り出した値）・セッションの ID。
  中身は、プレビューと違い、秘密情報を取り出した値とゲートウェイの本物のトークンを含む。daemon.json のトークンを持つもの（本人の CLI と画面）だけが呼べる。
- 終える API でゲートウェイの登録を閉じ、ホストで起動したコマンド型の MCP サーバーを止める。CLI が終える API を呼べずに終わったとき（強制終了など）は、デーモンが止まるまで残る。
- 作業履歴には何も記録しない（`ContextResolved` も記録しない）。タスク・保存した設定も変えない。

### AI の CLI への渡し方（利用者のログインのまま）

sacty の AI の定義（`agents`）と認証の秘密情報は使わない。モデルも sacty からは指定しない（合成した設定・利用者の設定・`--` の後の引数で決まる）。

- Claude Code
  - 設定の場所（`CLAUDE_CONFIG_DIR`）は変えない。利用者のログイン・利用者の設定（`~/.claude`）・対象リポジトリの `.claude/` もそのまま効く。
  - 合成したものは、CLI が作る一時ディレクトリ（本人だけが読める権限）に置き、引数で渡す。

    | 合成したもの | 渡し方 |
    | --- | --- |
    | `CLAUDE.md`（規則） | `--append-system-prompt-file` |
    | `settings.json` | `--settings` |
    | `mcp.json` | `--mcp-config` と `--strict-mcp-config`（利用者の MCP サーバーは使わず、プロジェクトのコンテキストのものだけにする） |
    | `agents/<段階>.md` | `--agents`（JSON。段階の名前を変えずに渡す） |
    | `skills/` | 一時ディレクトリの `.claude/skills/` に置き、`--add-dir` で渡す |

  - `--permission-mode default` を渡す（合成した設定の `permissions.defaultMode` より優先させる）。
- Codex
  - 設定の場所（`CODEX_HOME`）は変えない。利用者のログイン（`auth.json` でもキーチェーンでも。ChatGPT のアカウントでも API キーでも）・利用者の設定（`config.toml`・`AGENTS.md`）・対象リポジトリの `.codex/` もそのまま効く。ログインとトークンの更新は Codex に任せ、sacty は認証の情報を読まない・渡さない。
  - 合成したものは、CLI が作る一時ディレクトリ（本人だけが読める権限）に置き、`-c`（設定の上書き）で渡す。

    | 合成したもの | 渡し方 |
    | --- | --- |
    | `AGENTS.md`（規則と、スキルの一覧） | `-c developer_instructions=<中身>`。スキルの一覧の場所は、一時ディレクトリの `skills/<名前>/SKILL.md` の絶対パスにする |
    | `skills/` | 一時ディレクトリに置く（上の一覧から場所を示して読ませる。工程の実行と同じ） |
    | `config.toml`（層の設定） | 葉のキーごとに `-c <ドットで区切ったキー>=<TOML の値>`（表ごと置き換えず、利用者の設定の同じ表のほかのキーは残す） |
    | `config.toml` の `[mcp_servers."<名前>"]` | `-c mcp_servers.<名前>=<インラインの表>` |
    | `agents/<段階>.toml` | `-c agents.<段階>.config_file=<一時ディレクトリの絶対パス>` と `-c agents.<段階>.description=<説明>` |

  - 利用者の MCP サーバーは使わず、プロジェクトのコンテキストのものだけにする（Claude Code の `--strict-mcp-config` に合わせる）。Codex には一度に止める引数が無いので、利用者の `config.toml`（`CODEX_HOME`、無ければ `~/.codex`）と、`--cwd` から対象リポジトリの根までの `.codex/config.toml` にある MCP サーバーの名前を読み、コンテキストに無い名前ごとに `-c mcp_servers.<名前>.enabled=false` を渡す。
  - 層の設定の `approvals_reviewer`（既定のコンテキストでは、人のいない実行のための `auto_review`）は渡さない。承認を誰がするかは、利用者の設定のままにする。
  - `--sandbox workspace-write` と `--ask-for-approval on-request` を渡す（合成した設定より優先させる）。

### 安全のための扱い

- ホストで動くので、コンテナの隔離は無い。sacty は権限を広げる引数を渡さない（上の権限のモード・サンドボックス）。利用者が `--` の後の引数で変えるのは止めない。
- 一時ディレクトリは、AI の CLI が終わった後（失敗・シグナルでも）に消す。

## 理由

- CLI にしたのは、対話型の AI の CLI は利用者の端末の子プロセスとして起動するのが自然で、画面（ブラウザー）とデーモンは端末を持たないため。画面・デスクトップ版から使えるようにするときも、中身は同じ CLI を呼べばよい。
- デーモンに問い合わせるのは、合成に要るもの（プロジェクトの設定・gh のトークン・秘密情報の取り出し・ゲートウェイ）がデーモンにあり、CLI で作り直すとプレビュー・実行と食い違うため。
- 利用者のログインのままにしたのは、手元の対話は利用者自身の作業で、sacty の API キーをホストのプロセスの環境変数に出さずに済み、費用も利用者の契約のまま扱えるため。比べた案：工程と同じく sacty の認証で起動する。キーがホストのプロセスに出るので採らなかった。
- Claude Code で設定の場所を変えないのは、変えると利用者のログインが使えなくなるおそれがあり、合成したものはすべて引数で渡せるため（Claude Code 2.1.321 の `--help` で、`--settings`・`--mcp-config`・`--strict-mcp-config`・`--append-system-prompt-file`・`--agents`・`--add-dir`・`--plugin-dir` があることを確かめた）。
- Codex で `CODEX_HOME` を変えないのは、変えるとキーチェーンに置いたログインが使えなくなる（実際に使って確かめた）ためと、合成したものはすべて `-c` で渡せるため。Codex 0.167.0 で、`codex debug prompt-input`（モデルへの入力を出す）で `developer_instructions` が入力に入ること・`agents.<名前>.config_file` の段階が「Available roles」に出ることを、`codex mcp list` で `-c` の MCP サーバーが加わること・`enabled=false` で利用者の MCP サーバーが止まることを確かめた。
- 比べた案と採らなかった理由：
  - `CODEX_HOME` を一時ディレクトリにし、利用者の `auth.json` を写す（工程の実行の `subscription` と同じ扱い）。キーチェーンのログインが使えない。
  - 上に加えて、sacty がキーチェーンからログインの情報を取り出し、環境変数で渡す。API キーなら `OPENAI_API_KEY`・`CODEX_API_KEY` で渡せるが、ChatGPT のアカウントのログインは、短い期限のアクセストークンと、使うたびに新しくなる更新用トークンでできている。一時ディレクトリの Codex が更新すると、新しい更新用トークンが利用者のキーチェーンに戻らず、利用者のログインが切れる。Codex の `CODEX_ACCESS_TOKEN` に ChatGPT のログインのトークンを渡せるかも確かめられない。キーチェーンの項目の名前と形式は Codex の公開された仕様ではなく、版で変わりうる。
- `config.toml` を葉のキーごとに渡すのは、表ごと上書きすると、利用者の設定の同じ表（`[features]` など）のほかのキーが消えるため。
- `approvals_reviewer` を渡さないのは、既定のコンテキストの `auto_review` は人のいない工程の実行のためのもので、手元の対話では利用者が承認するため。
- ゲートウェイを通すのは、MCP と外部 PF の秘密情報をホストのプロセスに出さず、セッションを終えればトークンを無効にできるため。
- MCP を `--strict-mcp-config` でプロジェクトのコンテキストのものだけにしたのは、工程のエージェントと同じ道具で試せるようにし、利用者の個人の MCP サーバーと名前がぶつからないようにするため。
- 権限を広げないのは、コンテナの隔離が無く、層の設定やプロンプトインジェクションでホストを壊せるようにしないため。
- 作業履歴に記録しないのは、ローカルのセッションはタスクの外の利用者自身の作業で、作業履歴（タスクの経過と費用）に入れる実行ではないため。費用も sacty からは分からない（利用者のログインで直接つなぐ）。

## 影響

- 実装のときに、次を実際の CLI で確かめる。確かめられなければ、この ADR を置き換える。
  - Claude Code：`--add-dir` で渡したディレクトリの `.claude/skills/` のスキルが使えるか。使えなければ `--plugin-dir`（スキルの名前に接頭辞が付く）にする。`--agents` の JSON が、対話の起動で引数の長さの上限を超えないか。`--permission-mode default` が設定の `permissions.defaultMode` より優先されるか。
  - Codex：実際にログインした対話の起動で、規則・スキル・段階のサブエージェント・MCP サーバーが使えるか（ここまでの確認は、ログインせずにモデルへの入力と MCP サーバーの一覧を見ただけ）。
- `--` の後の引数で、sacty が渡した引数と同じものを渡したときにどちらが効くかは AI の CLI の決まりによる（確かめてユーザードキュメントに書く）。
- 合成した `settings.json`・`config.toml` のうち sacty が決める項目（`RESERVED_SETTINGS`）は、工程の実行と同じく取り除かれたまま渡る。
- 強制終了などで終える API が呼ばれなかったセッションは、ゲートウェイのトークンとホストで起動した MCP サーバーが、`sacty up` を止めるまで残る。トークンは 127.0.0.1 でだけ使える。
- Codex の規則とスキルの一覧は 1 つの引数で渡すので、引数の長さの上限（Linux は 1 つの引数で 128KiB、macOS は全体で `ARG_MAX`）を超えるときは、起動せずに止めて理由を表示する。
- Codex では、利用者の設定の `developer_instructions` は、合成した規則で上書きされる（利用者の `AGENTS.md` は効く）。
- Codex のスキルは、工程の実行と同じく、規則の一覧から場所を示して読ませる（Codex のスキルの仕組みには載せない）。一時ディレクトリは対象リポジトリの外なので、読めるのは、Codex のサンドボックスがファイルの読み取りを作業領域の外にも許すため。
- `via_gateway: false` の MCP サーバーの秘密情報は、工程の実行でコンテナの環境変数に渡すのと同じく、ホストの AI の CLI のプロセスの環境変数に渡る。
- 利用者のログインで直接つなぐので、sacty の予算・費用の記録・ゲートウェイのリトライは効かない。
- 仕様は実装の PR で [コンテキストの合成](../spec/context.md) に、利用者向けは [CLI](../user/cli.md) に書く。
