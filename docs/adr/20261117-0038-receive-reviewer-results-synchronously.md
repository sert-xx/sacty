# レビューの担当の結果を起動のツールの結果として受け取らせ、通知の形の文面を親が書いた実行を記録する

- 日時: 2026-11-17 00:38 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-368
- 置き換え元: なし
- 置き換え先: なし

## 背景

工程のエージェント（親）は、既定のスキル `review-dispatch` で、レビューの観点ごとの担当（サブエージェント）を起動して結果を集める。
実行の記録を調べると、親が、担当の結果が届く前に、担当の完了の通知・結果の文面を自分の発言として書き、それをもとに下書きを直した実行が 3 件あった（Claude Code の親の記録 1,506 件のうち。2026-11-03・11-04・11-16）。
書かれた結果は、後から届いた本物の結果と違っていた。

3 件とも、担当が背景で動いていた。親は起動の後にすることが無く、通知が届くたびに番が起きる形で待っていた。

- Claude Code（2.1.296・2.1.318）の Agent ツールは、`run_in_background` を省くと背景で起動する。記録では、省いた起動 528 件のすべてと、`true` を指定した 371 件のすべてが背景になり、`false` を指定した 171 件のすべてが、起動のツールの結果として担当の結果を返した。
- 担当を背景で起動した実行 83 件では、待つ間の親の発言が合わせて 1,063 回あり、待つためのコマンド（`sleep`・`echo`・担当の出力のファイルを覗く）が 24 回あった。起動のツールの結果で受け取った実行 25 件では、どちらも 0 回だった。
- スキルは「結果が揃うまで、担当との通信と待機だけを行う」と言うだけで、待ち方を書いていなかった。

## 決定

- スキル `review-dispatch` に、担当の起動と結果の受け取りの決まりを足す。
  - 同じ回の担当は、1 つの発言の中でまとめて起動し、結果を起動のツールの結果として受け取る。
  - 起動のツールに背景で実行するかの指定があるときは、背景にしない指定を担当ごとに明示する（Claude Code は `run_in_background: false`）。起動のツールが結果を返さない環境では、待つためのツールで待つ（Codex は `wait_agent`）。
  - 待つためだけのコマンドを実行しない。
  - 担当の結果として扱うのは、実際に届いたものだけにする。通知の形の文面を自分の発言として書かない。1 つでも届いていなければ、集約・修正に進まない。
  - 担当が背景になったときの待ち方（1 行だけ書いて番を終える）も決める。
- sacty は、Claude Code の親の発言に、実行環境が届けるはずのタグ（`<task-notification>`・`<system-reminder>`）で始まる行があったら、作業履歴に `SubagentNoticeImitated` を記録し、画面の作業履歴に出す。実行の結果は変えず、工程は止めない。
- 観点の選び方・指摘の重み・費用のための観点の絞り込みは変えない。

## 理由

- 起動のツールの結果で受け取る形では、親に「待つ間の番」が無い。届いていない結果を書く機会そのものが無くなり、待ちの番の費用も無くなる。記録でも、この形の実行には通知の形の文面が 1 件も無かった。
- 指示だけでは守られないことがあるので、守られなかった実行を人が見つけられるように、sacty の側で記録する。検出の条件は、見つかった 3 件の形（どれも、実行環境のタグで始まる行を持つ）を拾い、これまでの記録のほかの 1,503 件を 1 件も拾わないものにした。
- 記録だけにして工程を止めないのは、検出が「恐れ」を示すだけで、成果物が誤っているとは限らないため（3 件のうち、最終の成果物に存在しない指摘への対応が残ったものは無かった）。止めるかどうかは、起きる頻度を見てから決められる。
- 比べた案と、採らなかった理由。
  - 環境変数 `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1` を実行に付ける：`run_in_background` を省いても担当が同期になることは確かめた（Claude Code 2.1.322）。ただし、コマンドの背景の実行も使えなくなる。記録では、長い検証のコマンドを背景で動かした実行が 22 件あり、それらが時間の上限で止まる恐れがある。影響を確かめきれないので、採らなかった。
  - 段階のサブエージェントの定義（`agents/<段階>.md`）で同期を強いる：定義に、背景にしない指定があるかを確かめられなかった。
  - 親の発言から通知の形の文面を取り除く・実行を失敗にする：成果物を sacty が書き換えることになり、誤って拾ったときの害が大きい。
- タグを使わずに「担当は指摘なしだった」と地の文で書いたものは、この検出では拾えない。担当の結果と親の発言を突き合わせる仕組み（担当ごとの結果の保存と照合）が要るので、今回は入れていない。

## 影響

- レビューの親は、担当の結果を待つ番を持たない（[既定のコンテキスト](../spec/context.md#既定のレビュー用スキル)）。
- 作業履歴に、新しい記録だけの出来事 `SubagentNoticeImitated` が増える（[エージェントの実行：出力の扱い](../spec/agent-execution.md#出力の扱い)）。
- 担当を同期で起動すると、親の 1 回のツールの呼び出しが、いちばん遅い担当が終わるまで返らない。担当が終わらないときは、実行の時間の上限（`run_timeout`）で止まる。
- Claude Code が Agent ツールの引数の名前・既定を変えると、スキルの記述（`run_in_background: false`）を直す必要がある。
