# タスクの一覧・詳細などの画面は、画面をリロードせず、データだけを常に3秒ごとに取り直す

- 日時: 2026-10-15 13:49 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-108
- 置き換え元: なし
- 置き換え先: なし

## 背景

画面の自動の更新は、sacty やエージェントが作業しているタスクがある間だけ、3秒ごとに `router.refresh()` で画面の全体を描き直していた。
承認待ち・エスカレーション・一時停止・完了の間は更新せず、タブに戻ってきたときだけ一度描き直していた。そのため、更新が止まっている
間に裏で起きた変化（取り込みで増えたタスク・ほかのタブや CLI での承認と再開・デーモンが拾って動き出したタスク）が画面に出なかった。
また、画面の全体を描き直すと、文字の入力や操作の途中の状態が消えるおそれがある。

## 決定

- タスクの一覧・タスクの詳細・ヘッダーのお知らせは、画面をリロード（`router.refresh` を含む、画面の全体の描き直し）しない。
  画面のサーバーのルート（`/live/...`）から JSON のデータだけを取り直し、クライアントのコンポーネントが描き直す（変わった所だけが
  画面に反映される）。タスクの詳細の画面は、サーバーのコンポーネントからクライアントのコンポーネントに移した。
- 取り直しはポーリングにし、間隔は今と同じ3秒とする。タスクの状態によらず取り直す。前の取り直しが終わってから次を数える。
  タブが隠れている間は止め、見えたらすぐに一度取り直す。
- 前に受け取った版（中身のハッシュ）を送り、同じなら中身を送らない。デーモンに届かないときは 200 で `unavailable` を返し、画面は
  いまのまま残す。
- 取り直しでは、`gh` で GitHub に問い合わせる対象リポジトリの候補を取らない（タスクの作成のダイアログは開いたとき、詳細の一時停止は要るときに一度だけ）。
- 成果物のレビュー・プロジェクトの一覧（取り込みの状況）も、同じようにデータだけを取り直す。実行のログは、足された分だけを取って
  後ろに足し、一番下を見ているときだけ新しい行についていく。実行が終わったら止める。
- sacty の設定・プロジェクトの設定は、自動で描き直さない。一定の間隔で `router.refresh()` を呼ぶ仕組み（`AutoRefresh`・
  `RefreshOnVisible`）はやめる。

## 理由

- SSE などでデーモンから知らせを受ける案もあった。デーモンからブラウザまでの経路（画面のサーバーを通す・トークンを渡さない）と、
  つなぎ直しの扱いが増える。ローカルで動く画面で、問い合わせは軽い（デーモンの一覧の取得と、変わらなければ小さな返事）ので、
  間隔と同じ遅さで済むポーリングにした。
- 版を送るのは、変わらない間の通信と、ブラウザでの読み直しを減らすため。一覧は表示に要るものだけを返し、タスクの全体（成果物の
  本文など）を送らない。
- 設定の画面を描き直さないのは、中身が人の編集する設定でタスクの状態では変わらず、入力を描き直しで失うおそれだけがあるため。ヘッダーの
  お知らせは、どの画面でも取り直すので、対応が要るタスクには気づける。
- 表示に使う部品をクライアントに移すと、文言はクライアントの `useMessages` で読む。部品の中でしていたデーモンへの問い合わせ
  （子タスク・修正のタスク・イメージの候補・片付けるもの）は、データを取る所にまとめた。

## 影響

- 実行のログは、ログの全体ではなく足された分だけを送るので、長い実行でも、取り直しの通信が増えない（画面のサーバーとデーモンの間は
  全体を読む）。
- 仕様は [アーキテクチャ](../spec/architecture.md) の「画面のデータの取り直し」、利用者向けは [タスクを進める](../user/tasks.md) の
  「画面の自動の更新」に書く。
