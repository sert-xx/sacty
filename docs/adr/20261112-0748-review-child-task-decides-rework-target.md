# PR の指摘の戻し先を、ゴールガーディアンではなく、AI のレビューの指摘はレビューの子タスクが、人の指摘は PR の工程のエージェントが決める

- 置き換え先: なし

## 背景

PR の指摘を取り込むと、ゴールガーディアンが戻し先（その PR の工程か、承認済みの決定を持つ前の工程か）と、差し戻しの原因・答えの扱いを判断していた。
ゴールガーディアンという仕組みをなくす（ステークホルダーの要望、2026-11-12）ので、この判断を別の担い手に移す。
sacty が作る PR は、PR を作ったタスクのレビューの子タスクが、指摘なしになるまでレビューするようになった（[sacty が作る PR のレビューを、PR を作ったタスクの子タスクにし、指摘なしになるまで繰り返す](20261112-0609-review-sacty-pull-requests-in-child-tasks.md)）。

人が決めたこと（2026-11-12）：戻し先は、レビューの子タスクが指摘ごとに「この PR で直す／前の工程の決定を変える」を示し、それに従う。

## 決定

- PR のレビューの子タスクの指示に、戻し先の候補・基準（承認済みの決定を変えるか）・承認済みの前の工程の成果物・原因の選択肢を渡し、判定のブロック（`sacty-review-verdict`）の `rework` に、指摘ごとの戻し先と理由、原因を書かせる。
- 指摘が AI のレビューの指摘だけで、その PR のレビューの子タスクがあるときは、子タスクが最後の回に示した戻し先から決める。基準は今までと同じ（決定を変える指摘が1つでもあればその工程、複数の工程にまたがれば前の工程）。判断のための実行はしない。
  - 戻し先が読めない・候補に無い・知らない値の指摘は、その PR の工程で直す。`rework` が無ければ、その PR の工程をやり直す。
  - 作業履歴は今までと同じ `ReworkJudged` に、actor `sacty` と、決めた元の子タスク（`reviewTaskId`）を残す。費用は 0（子タスクの費用は子タスクに数える）。
- 人の指摘を含むとき・子タスクが無いとき（ラベル・依頼で取り込んだレビューだけのタスクの投稿だけのときを含む）は、PR の工程のエージェント（人が選んだもの。無ければ `step_agents` か `default_agent`）に、今までと同じ指示で判断させる（actor `agent`）。原因と答えの扱い（`answer`。推奨どおりなら軽い直し）も同じ実行で判断する。
- 費用の内訳では、工程のエージェントの判断を「戻し先の判断」の行に出し、子タスクの答えから決めたものは行にしない。古い作業履歴のゴールガーディアンの判断は、ゴールガーディアンの行のまま読む。
- 判断の実行の仕組み（作業領域の読み取り専用の写しで判断させる）は、ゴールガーディアンの撤去までそのまま使う。

## 理由

- AI のレビューの指摘は、子タスクが PR と承認済みの成果物を読んで書いたもので、どの決定を変えるかを一番よく知っている。同じ指摘を別のエージェントに読み直させると、費用がかかり、読み違いも増える。
- 人の指摘は子タスクが書いたものではないので、子タスクの答えは使えない。人の指摘の意図を読み、PR の成果物を直すのはその工程のエージェントなので、判断もその工程のエージェントに任せる（新しいセッションにして、作った経緯に引きずられないようにする）。
- 読めない・知らない値のときにその PR の工程で直すのは、今の「判断できないとき」と同じで、前の工程に戻す（承認済みの成果物を作り直す）重い誤りを避けるため。

## 影響

- ゴールガーディアンの設定（`guardian_agent`）は、戻し先の判断に使わなくなる（変更の申し出と統合レビューには、撤去まで使う）。
- 子タスクのレビューの指示が長くなる（承認済みの前の工程の成果物を含める）。
- 古い作業履歴の `ReworkJudged`（actor `guardian`）は、そのまま読める。
