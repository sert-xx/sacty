# オーケストレーターが認証の失敗・利用上限で実行できなければ、標準の工程で進めずにその理由で一時停止する

- 日時: 2026-10-12 08:17 UTC

- 関係する PR・タスク: #38、PBI-32
- 置き換え元: なし
- 置き換え先: [オーケストレーターが工程を選べなかったときは、標準の工程で代わりに進めず、理由を記録して止める](20261013-0003-stop-when-orchestrator-fails.md)（ほかの理由の失敗では標準の工程で進める部分）

## 背景

オーケストレーターの実行がどんな理由で失敗しても、タスクは標準の工程で進めていた。認証の失敗・利用上限のときも同じで、
後の工程で「テストのコマンドを決められない」という別の理由で止まり、原因がわからなかった。

## 決定

- オーケストレーターが認証の失敗・利用上限で実行できなければ、標準の工程で進めず、その理由で一時停止する。工程は選ばないままにし、
  再開すると工程の選択からやり直す。
- 止めるときは `OrchestratorFailed`（理由・文言・使用量・費用）を記録し、失敗した実行の費用を予算に入れる（80% の通知も判定する）。
  作業履歴にも費用を出す。
- ほかの理由の失敗は、これまでどおり標準の工程で進める。

## 理由

- 認証の失敗・利用上限では後の工程も同じく失敗するうえ、別の理由で止まって原因がわからなかったため（コミットのメッセージ）。
- 失敗した実行の費用を記録するのは、止めるときに `TaskPaused` だけを記録すると、実行の途中で利用上限などに達して使用量が付いていても
  予算に入らず、再開を繰り返すと費用を少なく数え、予算の判定が実際の消費からずれるため（レビュー）。

## 影響

- この振る舞いは Bedrock に限らず、すべてのエージェントのオーケストレーターに効く。
- 認証の失敗・利用上限のタスクは、人間が原因を直して再開するまで止まる。
