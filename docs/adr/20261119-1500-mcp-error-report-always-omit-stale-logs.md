# sacty mcp のエラーレポートの読み取りは、閉じられなかった実行のログを必ず省き、省いた印と全体の指紋で確かめる

- 日時: 2026-11-19 15:00 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-404
- 置き換え元: なし
- 置き換え先: なし

## 背景

`sacty mcp` で、画面の「エラーレポートをダウンロード」と同じ Markdown を読めるようにする。
デーモンが止まって閉じられなかった実行（`meta.json` に `finishedAt` が無く、いまのデーモンが開いてもいない実行）のログは、閉じるときの伏せ直しを経ていない。画面のダウンロードは、その保存済みのログの末尾をそのまま入れる。
デーモンは、エラーの分析でオーケストレーターに渡すレポートでは、この実行のログを省いている（`omitStaleLogs`）。
前の版のデーモンは、知らないクエリを無視する。省く入力を付けて頼んでも、省いていないレポートが 200 で返る。
レポートは呼ぶたびに組み立て直し、作成時刻（ミリ秒まで）が入るので、本文全体の指紋は毎回変わる。

## 決定

- MCP は、閉じられなかった実行のログを必ず省いたレポートだけを読む。省かない読み方は作らない。常に `stale=omit` を付けて頼む。画面のダウンロード（入力なし）の中身は変えない。
- デーモンは、`GET /api/tasks/:id/error-report` に入力 `stale=omit` と、省いたことを示す応答のヘッダー `x-sacty-stale-logs: omitted` を足すだけにする。入力が無い・`omit` 以外の値は、入力が無いものとして扱い、印も付けない。クエリの値とヘッダーの名前・値は、デーモンの受け口・CLI・テストが同じ定数を使う。伏せる処理・切り詰める処理は、MCP の層にもデーモンにも足さない。
- 印が無い応答（前の版のデーモン）は、本文を読まず、起動し直しを案内して断る。省いていないレポートを MCP のプロセスが受け取った後に持ち回らない。
- 結果は `get_deliverable` と同じ分け方（既にある `readByteRange`）で返し、全体の指紋（SHA-256）を添える。指紋は、作成時刻の行（1行）だけを除いて数える。返す `text` は加工しない。続きを読むときに前の指紋を渡し、いまの全体と違えば、続きを返さず「`fingerprint` を付けずに読み直す」と断る。
- デーモンが指紋を返す形にはしない（デーモンの変更は、入力と印だけ）。

## 理由

- 伏せ直しを経ていないログを、手元の AI に渡さないため。デーモン自身が分析で使う水準に合わせ、既にある仕組みをそのまま使える。
- 印があれば、省いたことをデーモンが応答で示したと分かる。前の版のデーモンが、省いていないレポートを黙って返す場合を、MCP の層が見分けられる。
- 作成時刻の行を含めた指紋では、続きが1度も読めない。行を除くのは指紋を数えるときだけで、返す内容は変えないので、中身を加工する処理にはならない。

## 影響

- 前の版のデーモンでは `get_error_report` は断られる。デーモンを新しい版で起動し直すと読める。
- 実行中のタスクなど、中身が変わり続けるレポートでは、`fingerprint` を渡すと続きが断られて、最後まで読めないことがある。`fingerprint` を付けなければ続きは読めるが、前に読んだ部分とつながらないことがある。確かな全体が要るときは、タスクが止まってから読む。
- 閉じるときの伏せ直しの書き込みに失敗した実行の扱いと、画面のダウンロードの水準をそろえることは、この決定に入れない。
