# 取り込みの間隔を、取り込みの種類ごとに sacty の設定に持つ

- 日時: 2026-10-15 03:10 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-100
- 置き換え元: [GitHub へのアクセスは、ホストの gh にログイン済みのアカウントからプロジェクトごとに必ず選んだもので行い、config.yaml のトークンの設定は削除する](20261010-2314-superseded-github-access-via-gh-accounts.md)（config.yaml の `github:` があれば取り込む部分）
- 置き換え先: なし

## 背景

取り込みの間隔は `config.yaml` の `github.poll_interval_sec`（60 以上、既定 300）だけで、GitHub の Issue・PR と JIRA のチケットの取り込みに
共通だった。`github:` を書かないと、GitHub を使わない JIRA のチケットも取り込まれなかった。画面からは変えられなかった。取り込みには
Issue の取り込み・PR のレビューの取り込み・チケットの取り込みがあり（PBI-99 で Issue と PR のレビューを分けた）、種類ごとに間隔を持ちたい
（ステークホルダーの要求）。

まだ本格運用していないので、互換を保たずに変えてよい（ステークホルダー、2026-10-15）。

## 決定

- 取り込みの種類を `issues`（Issue の取り込み）・`reviews`（PR のレビューの取り込み。レビュー用のラベルと自分へのレビューの依頼）・
  `tickets`（チケットの取り込み）の3つにし、種類ごとの間隔を sacty の設定（`issueIntervalSec`・`reviewIntervalSec`・`ticketIntervalSec`。
  秒）に持つ。下限と既定値はこれまでどおり（60 以上の整数、設定していなければ 300）。画面の「sacty の設定」の、種類ごとの区画で変える。
- 種類ごとに、別々に（並行に）取り込む。最後に取り込みを始めた時刻・どこまで読んだか・取り込みの状況（直近の時刻・作ったタスクの数・
  取り込めなかった取り込み元）は種類ごとに持つ。レート制限で検索を飛ばすのは、その回のその種類の中だけにする。
- `config.yaml` の `github`（`poll_interval_sec`）を消す。書いてあっても、ほかの知らない項目と同じく読まない（誤りにも警告にもしない）。
  取り込みは、`config.yaml` を読めれば動く（`github:` が無くても、JIRA のチケットも GitHub も取り込む）。
- `POST /api/intake/run` は、すべての種類を間隔を待たずに取り込む（種類は選べない）。

## 理由

- 間隔を sacty の設定に置くのは、取り込むラベルや On/Off と同じ画面で、デーモンを止めずに種類ごとに変えられるようにするため。
  `config.yaml` に残すと、画面から変えられず、設定が2か所に分かれる。
- 項目を種類ごとの平らな3つにしたのは、画面の入力と同じ形で、誤りの場所（`issueIntervalSec` など）がそのまま項目を指すため。
- 種類ごとに別々に取り込むのは、1つの種類の失敗・レート制限・遅れ（JIRA の応答が遅いなど）が、ほかの種類を止めないようにするため。
  GitHub のレート制限はアカウントごとなので、同じアカウントの Issue の検索がレート制限に当たれば、PR のレビューの検索も当たりうる。
  それでも種類をまたいで飛ばさないのは、種類ごとに独立させるという要求を単純に保つため（当たった検索は、その種類の失敗として記録する）。
- `github:` を書いてあるときに警告しないのは、ほかの知らない項目の扱いに合わせるため。利用者向けの文書に、読まなくなったことを書いた。
- 保存しているデータで消すものは無い（`poll_interval_sec` は `config.yaml` にだけあり、取り込みの状況はメモリーにだけある）。

## 影響

- `config.yaml` に `github.poll_interval_sec` を書いていた利用者は、間隔が既定の 300 秒に戻る。変えるには、画面の「sacty の設定」で
  種類ごとに設定する。
- `github:` を書いていなかった利用者は、取り込むラベルなどを設定していれば、取り込みが動き始める。
- 状況の API（`GET /api/status` の `intake`）の、直近の取り込み（`lastRunAt`・`imported`・`errors`）は、種類ごとの `runs` に変わる。
  `intake` が `null` になるのは、`config.yaml` を読めないときだけになる。
