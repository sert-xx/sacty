# スケジュールタスクは、逃した予定のうち直前の1回だけを、使えるようになったときに作る

- ステータス: 採用

- 置き換え元: なし

## 背景

決めた内容のタスクを、決めた予定で作るスケジュールタスクを足す。
sacty は利用者の PC で動くので、予定の時刻に PC が動いている・スリープしていない・ネットにつながるとは限らない。
予定の時刻にだけ作る形では、そのときに使えなかった回が抜ける。
逆に、逃した回をすべて作ると、何日も止めていた後に同じ内容のタスクがまとめて作られる。

## 決定

- 予定の時刻を過ぎてから確かめる（起動したとき・その後は1分ごと）。今以前で直前の予定の回をまだ処理していなければ、そのときにタスクを1つ作る。
  逃した回がいくつあっても、作るのは直前の1回だけにする。
- 同じ回を二重に作らない。処理した回をスケジュールタスクに保存し、作ったタスクにも回（`TaskCreated` の `schedule`）を記録して、保存の前に止まったときも作り直さない。
- ネットにつながらない間（`github.com` の名前を引けない間）は作らず、つながってから作る。
- 作ったとき・予定を変えたとき・止めていたのを有効に戻したときより前の予定は、さかのぼって作らない。
- 予定の時刻は、デーモンを動かしている PC のローカルの時刻で数える。
- 作れなかった回（プロジェクトの対象が変わったなど）は理由を残し、同じ回を作り直さない。
- スケジュールタスクは設定として `sacty.db` の `schedules` テーブルに置く（作業履歴には置かない）。作るタスクの内容は、画面の「タスクを作成」と同じ項目・同じ検査にする。

## 理由

- 直前の1回だけを作れば、定期の作業（依存の更新・定期の確認など）は、最新の状態に対して1回すればよく、逃した回の数だけ同じ作業をしても無駄になる。
- 作ったタスクに回を記録すれば、作業履歴が正本になり、保存の順の途中で止まっても二重に作らない。
- ネットにつながらない間に作っても、エージェントの実行や GitHub への問い合わせで失敗するので、つながるまで待つ。
  名前を引けるかだけで確かめるのは、軽く、プロキシの有無に左右されにくいため。
- 内容や予定を編集して変えられるので、スケジュールタスクは作業履歴ではなく、プロジェクトと同じく書き換えられる設定として持つ。

## 影響

- 何日も止めていた PC を起動すると、各スケジュールタスクのタスクが1つずつ作られる。
- 逃した回の記録は残らない（直前の回だけが `lastRun` に残る）。
- `github.com` の名前を引けない環境では、スケジュールタスクのタスクが作られない。
