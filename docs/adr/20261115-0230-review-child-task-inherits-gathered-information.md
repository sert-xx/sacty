# PR のレビューの子タスクは、親タスクが開始時に集めた情報を引き継ぎ、情報収集をし直さない

- 日時: 2026-11-15 02:30 UTC
- ステータス: 採用
- 関係する PR・タスク: #373、PBI-345
- 置き換え元: なし
- 置き換え先: なし

## 背景

タスクの開始時の情報収集は、工程を選ぶ前のタスクのうち、分割の子タスク（`parent` のあるもの）を除くすべてで実行していた。
sacty が作った PR をレビューする子タスク（`reviewOf` のあるもの）は分割の子タスクではないので、開始時に情報収集のエージェントを実行していた。
親タスク（PR を作ったタスク）は、同じ依頼について、すでに情報を集めてまとめている。

## 決定

- PR のレビューの子タスクは、親タスクにまとめがあれば、情報収集のエージェントを実行せず、親のまとめと情報源を引き継ぐ。
- 引き継ぎは、子タスクの作業履歴に `GatheredInherited`（actor は `sacty`。親タスクの ID・まとめ・情報源）として記録する。
  費用は持たない。
- 引き継いだまとめは、自分で集めたまとめと同じ場所（タスクの `gathered`）に持ち、親タスクの ID を添える（`inheritedFrom`）。
  レビューの工程の指示と、タスクの詳細の「集めた情報」には、親タスクから引き継いだものであることを出す。
  指示には、PR を作る前の情報なので、PR の変更の内容は差分とコードで確かめることも添える。
- 親タスクにまとめが無い・親タスクが見つからないときは、今までどおり子タスクが集める。
- 依頼・ラベルで取り込んだレビューだけのタスクと、手動で作ったレビューのタスクは、今までどおり集める。

## 理由

- 子タスクが親のまとめを引き継ぎ、追加で調べないことは、作者が決めた。
- 引き継ぎを、情報収集の記録（`InformationGathered`）ではなく別のイベントにしたのは、`InformationGathered` が情報収集の実行の記録（エージェント・費用・セッションのログ）を持ち、費用の表の「情報収集」の行になるため。
  実行していないものを、実行の記録として残さない。
- 分割の子タスクのように、タスクの内容（`body`）に親のまとめを書き込む形にしなかったのは、親にまとめが無いときに子タスクが集める道を残すため。
  内容に書き込む形では、集めたかどうかをタスクの状態から判断できない。
- 引き継ぎを子タスクを作るときではなく、子タスクの最初の実行のときに行うのは、この変更の前に作られて、まだ集めていない子タスクにも効かせるため。
- 親にまとめが無いときに集めるのは、レビューの工程が背景を何も持たずに進むことを避けるため。

## 影響

- レビューの子タスクは、情報収集の実行が1回減り、その分の費用と時間が減る。
- 親のまとめは、親タスクの開始時（PR を作る前）の情報。
  PR の本文・差分・既存のレビューは、レビューの工程が別に受け取るので、まとめには入らない。
- 親タスクが開始した後に変わった外部の情報（チケットのコメントなど）は、子タスクのまとめに入らない。
- 仕様は [タスクと工程](../spec/tasks-and-steps.md#情報収集) と [承認](../spec/approval.md#pr-のレビューの子タスク) にある。
