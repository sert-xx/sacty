# タスクの詳細を、上に固定した見出し・タブ・右の列のプロパティで組む

- 日時: 2026-10-28 15:33 UTC
- ステータス: 採用
- 関係する PR・タスク: なし
- 置き換え元: なし
- 置き換え先: なし

## 背景

タスクの詳細は、題・メタ情報（1行の文）・費用・操作・工程の欄・監査・内容・成果物・PR・マージの後の監視・
変更の申し出・工程ごとの費用・オーケストレーターのセッションを1列に縦に並べ、右の列に作業履歴の全件を出していた。
縦の長さは 2,200〜3,100px になり、承認の判断に要る成果物は、工程の設定（イメージ・エージェント）や内容を通り過ぎた先にあった。

sacty は証跡と監査を重んじるが、証跡は人が見やすく使いやすいほど確かめられる。
いつも見たいもの（状態・進み具合・操作）、よく確かめるもの（いまの成果物・PR・メタ情報）、
たまに見る証跡（作業履歴の全件・費用の内訳・工程の設定・監査）が、同じ重さで並んでいたことが問題だった。

## 決定

- 題・状態・工程の並び・操作（一時停止・中止・再レビュー）・タブを、画面の上に固定する。
- 承認・判断・再開の案内は、どのタブでもタブの下に出す（人の対応が要ることを見落とさない）。
- タブは、概要・作業履歴・費用・工程の設定・監査（監査したタスクだけ）。開いたタブは `?tab=` に残す。
  隠したタブの中身も描いておき、入力の途中の文字や開いた欄を、タブの切り替えで消さない。
  監査の根拠のリンク（`#event-<ID>`）は、作業履歴のタブを開いてその行へ移る。
- 概要の成果物は、工程を選んで1つずつ出す。最初は、いまの工程（作業中・承認待ち・最後に終えた工程）を出す。
  1つずつ出すので、承認済みの成果物も折りたたまない。
- 右の列に、よく確かめる事実（いまの工程・PR・費用・プロジェクト・リポジトリ・ブランチ・テスト・元のチケット・
  関係するタスク・作成と最終更新）をプロパティとして出し、その下に最近の作業履歴（5件）を出す。
- 中身の無い欄（申し出の無い「変更の申し出と判定」、まだ始まっていないマージの後の監視）は出さない。

## 理由

- 見る頻度で置き場所を分けると、よく行う操作とよく確かめる情報が、スクロールせずに届く。
  試作では、縦の長さが PR のマージ待ちのタスクで 2,472px から 1,446px に、監査済みのタスクで 3,121px から 1,514px になった。
- 証跡（作業履歴・費用・監査）は消さずにタブへ移したので、監査で確かめられることは変わらない。
  タブの URL を共有すれば、同じ証跡を他の人に見せられる。
- 成果物を全部開いて並べる案は、承認済みのものを折りたたんでもページが長くなるので採らなかった。
  成果物だけのタブを別に作る案は、概要に成果物が無いと開くたびにタブを移ることになるので採らなかった。
- 隠したタブを描かない（切り替えのたびに作る）案は、再開の補足や工程の設定の入力の途中の文字が、
  タブの切り替えで消えるので採らなかった。

## 影響

- 仕様は [アーキテクチャ](../spec/architecture.md) の「タスクの詳細の並び」に書く。
- ユーザードキュメントの「工程の欄」「監査の欄」は、「工程の設定」タブ・「監査」タブに読み替えた。
- 作業履歴の行の ID（`event-<ID>`）は、作業履歴のタブの行にだけ付ける（右の列の最近の作業履歴には付けない）。
- タスクの詳細に欄を足すときは、どの頻度で見るものか（固定の見出し・概要・プロパティ・どのタブか）を決めて置く。
