# エージェントの答えの JSON は、囲み方を問わずに1か所の読み取りで探し、形の合う最後の候補を使う

- 日時: 2026-10-14 04:24 UTC
- ステータス: 採用
- 関係する PR・タスク: #80、PBI-72
- 置き換え元: なし
- 置き換え先: なし

## 背景

sacty は、エージェントの答えの JSON（工程の選択・トリアージ・ゴールガーディアンの判定など）を「```json」の囲みで探していた。
AI が「```」だけで囲む・ほかの言語名で囲む・囲まずに出す・説明の文の中に書くと読めず、オーケストレーターなどが
「読み取れませんでした」で失敗していた。読み取りは呼び出しごとに正規表現と `JSON.parse` で書かれていた。

## 決定

- エージェントの答えの JSON の読み取りを `apps/daemon/src/agent-json.ts` の1か所にまとめ、答えの JSON を読むすべての呼び出しで使う。
  CLI のストリームの出力・設定・DB などを読む `JSON.parse` は対象にしない。
- 囲み方を問わず、出力の中の JSON のオブジェクトをすべて候補にする。括弧は文字列の中を数えずに対応を取り、オブジェクトの中の
  オブジェクトは別の候補にしない。
- 呼び出しごとの形（見出しと中身）を後ろの候補から確かめ、形の合う最後のものを使う。合うものが無ければ、今までと同じエラーの文言にする。
  エラーに出力の一部は新しく入れない。
- 読んだ JSON は表示用の本文から取り除く（囲みがあれば囲みの行ごと）。
- 閉じない括弧や壊れた入れ子の多い出力でも、出力の長さに比例する時間で読む（同じ位置からは読み直さない）。

## 理由

- 囲み方の揺らぎで読めず、工程が失敗していたため（PR の本文・コミット）。
- 形の合う最後のものを使うのは、今までの「最後のブロックを使う」と同じ振る舞いにするため（PR の本文）。
- 長さに比例する時間にしたのは、レビューで、壊れた深い入れ子で解析の時間が2乗に増え（約192KBで約10秒）、デーモンの同期処理の間は
  ほかのタスクや停止の要求への応答も滞ると指摘されたため。
- ほかの案（総解析量・入れ子の深さの制限）はレビューで挙がったが、採らなかった理由は記録に無い。

## 影響

- 新しく答えの JSON を読む呼び出しを足すときは、この共通の読み取りを使う。
- 既存の「```json」で囲んだ答えは、今までどおりに読める。
