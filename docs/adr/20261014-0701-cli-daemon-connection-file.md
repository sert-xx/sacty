# CLI は、sacty up が書く接続先のファイルを通して、動いているデーモンの API を呼ぶ

- 日時: 2026-10-14 07:01 UTC
- ステータス: 採用
- 関係する PR・タスク: #85、PBI-76
- 置き換え元: なし
- 置き換え先: なし

## 背景

コンテキストのプレビューを CLI からも見られるようにするにあたり、CLI が動いているデーモンにつなぐ方法が無かった。これまで CLI はデーモンの API を
呼んでおらず、API のトークンは `sacty up` の起動ごとに作るだけだった。

## 決定

- `sacty up` は、デーモンが自分のトークンで応答してから、`$SACTY_HOME/daemon.json`（接続先とトークン、権限 0600）を書く。
- ほかの sacty が書いた `daemon.json` が応答するなら上書きしない。応答しない（止まった後に残った）ものだけを上書きする。
- 終わるときは、接続先とトークンの両方が自分のものと合うときだけ消す。
- CLI（`sacty context preview`）は、このファイルを読んで動いているデーモンの API に問い合わせる。

## 理由

- CLI の中で合成し直す方法もあるが、それではゲートウェイの起点（実際のポート）がわからず、実行と同じ結果にならないため、API を使う（PR の本文）。
- 応答してから書き、ほかのものを上書き・削除しないのは、レビューで、同じ SACTY_HOME・ポートで2回目の `sacty up` を起動すると、動いている sacty の接続先を
  上書きし、2回目の終了処理で消してしまうと指摘されたため。

## 影響

- `daemon.json` にはデーモンの API のトークンが入るので、権限 0600 で書く。
- 同じ SACTY_HOME・同じポートで2つ目の `sacty up` を起動しても、2つ目はポートを使えずに応答の前に止まるので、1つ目の接続先のファイルは変わらない。
