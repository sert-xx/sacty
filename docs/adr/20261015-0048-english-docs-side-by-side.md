# README・仕様書・ユーザードキュメントに、同じディレクトリの `*.en.md` で英語の版を置き、2つの版の形をテストで突き合わせる

- 日時: 2026-10-15 00:48 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-97
- 置き換え元: なし
- 置き換え先: なし

## 背景

OSS として公開するため、英語のドキュメントが要る。日本語のドキュメントは保つ。英語にする範囲は、リポジトリの README・
ユーザードキュメント（docs/user）・仕様書（docs/spec）で、ADR と作業履歴は日本語のまま（ステークホルダーの決定）。
2つの言語の版を並べると、片方だけを直して内容がずれやすい。

## 決定

- 英語の版は、日本語の版と同じディレクトリに、`.md` を `.en.md` に変えた名前で置く（`README.en.md`・`docs/user/cli.en.md`・
  `docs/spec/gateway.en.md` など）。日本語の版の名前と場所は変えない。
- どちらの版も、最初の行（ユーザードキュメントでは先頭の HTML コメントの次）に、もう一方の言語へのリンクを決まった形で置く。
- 英語の版の仕様書のコードの参照は `Code:` で始め、日本語の版の「コード:」と同じ検査の対象にする。英語の版のユーザードキュメントの
  先頭のコメントは `<!-- Code: ... -->`、目次の見出しは `## Contents` にする。
- `tests/docs/docs.test.ts` で、2つの版を機械的に突き合わせる：相手の版があること・最初の行のリンク・見出しの深さの並び・表の行の数・
  コードブロックの数と行の数・インラインコードの数（日本語の版で ASCII だけのものと、両方にあるもの）・リンクの行き先。
- 規則は `docs/README.md` の「英語の版」に置き、docs の方針のスキルから参照する。片方の言語を直す PR では、同じ PR でもう片方も直す。

## 理由

- 置き場所の候補は、`docs/en/` の下に同じ構成を作るか、同じディレクトリに `*.en.md` を置くかだった。`docs/en/` にすると、
  docs の4種類の構成に5つ目のディレクトリが加わり、ADR・作業履歴・docs/README.md へのリンクの深さが日本語の版と変わる。
  同じディレクトリなら、相対リンクの行き先がほぼ同じ形になり、相手の版を名前だけで決められ、どのページに英語の版が無いかも
  テストで挙げやすい。
- 日本語の版の名前を変えないので、名前を変えられない過去の ADR・作業履歴からのリンクが切れない。
- 訳の正しさはテストで確かめられないが、設定の名前・既定値・コマンド・コードの参照はインラインコードやコードブロックに書いてあるので、
  その数と、見出し・表の行・リンクの数をそろえれば、節や表の行の抜けと、片方だけの値の変更の多くを見つけられる。
  インラインコードのうち日本語を含むもの（`<名前>` のような置き換えの例）は訳してよいので、数をそろえる対象から外した。

## 影響

- README・仕様書・ユーザードキュメントを直す PR は、両方の言語を直す。ページを足すときは、両方の版と両方の目次を作る。
- 英語の版にだけ ASCII のインラインコードを足すことは、テストでは見つけられない（日本語の版の置き換えの例を訳したものと
  見分けられないので）。訳の中身はレビューで見る。
- 方針の全体は [docs の入口](../README.md)。
