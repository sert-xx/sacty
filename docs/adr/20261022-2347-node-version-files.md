# Node.js の版を、版の管理ツール用の `.node-version` と `mise.toml` にも書く

- 日時: 2026-10-22 23:47 UTC
- ステータス: 採用
- 関係する PR・タスク: #205
- 置き換え元: なし
- 置き換え先: なし

## 背景

[Node.js の下限（engines）を、脆弱性を直した版の 22.23.4 に上げる](20261022-0351-node-engines-security-floor.md) で、`package.json` の `engines.node` を `>=22.23.4` にした。
`engines` は条件を満たさない版で `npm ci` を実行しても警告（`EBADENGINE`）を出すだけで、使う版を切り替えはしない。
リポジトリには、mise・nodenv・fnm などの版の管理ツールが読むファイルが無く、開発する人がどの版を入れればよいかは、文書を読まないとわからなかった。

## 決定

- リポジトリのルートに `.node-version`（`22.23.4`）と `mise.toml`（`[tools]` の `node = "22.23.4"`）を置く。
- 2つのファイルの版は、`engines.node` の下限と同じ版にする。下限を上げたら、2つのファイルも同じ PR で上げる。
- CONTRIBUTING とはじめにに、2つのファイルに版を書いていることを書く。

## 理由

- `.node-version` は nodenv・fnm・mise など多くのツールが読む。`mise.toml` は mise の設定で、Node.js 以外のツールを足すときにも使える。
- 範囲（`22`）ではなく修正版の番号を書いたのは、ツールが脆弱性を直していない版を選ばないようにするため。
- `engines` の下限と揃えるのは、下限より古い版を版の管理ツールが選ばないようにするため。

## 影響

- 版の管理ツールを使っていれば、リポジトリのルートに移ると 22.23.4 が使われる（入っていなければ、ツールの手順で入れる）。
- 新しい 22.x の修正版が出ても、2つのファイルは自動では上がらない。上げるかは、`engines` の下限と一緒にその都度決める。
- エージェント実行用のイメージ（`node:22-bookworm-slim`）は、2つのファイルを読まない。
