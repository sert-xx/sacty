# PR のレビューの集約は、対応済み・却下済みの指摘と重なる指摘を投稿しない

- 日時: 2026-11-21 16:00 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-445
- 置き換え元: なし
- 置き換え先: なし

## 背景

PR のレビューは、往復を重ねるうちに、直った指摘の言い換えを出し直す・人や AI が「この PR ではやらない」とした指摘を蒸し返す、ことがあり、往復が止まらなかった。
集約には、他のレビュアーの指摘との重なりと PR の目的の範囲の外を落とす決まりはあったが、対応済み・却下済みとの重なりを落とす決まりと、その件数の行は無かった。
デーモンの渡す材料にも、次の欠けがあった。

- 人が書いたコメントか、sacty が投稿した返信かを示す欄が無い（同じ GitHub アカウントを使う構成では、文面でしか見分けられない）。
- 前々回以前の返答が、既存のレビューの最後の 30 件から押し出される。
- 人が画面で無効にした指摘が、レビューの子に渡らない。
- 再レビューの「前回の指摘」に、「取り下げた（理由つき）」を書ける場面が、同じ先頭の判定し直しの回だけで、スキルの決まりと食い違う。

成功の基準は、対応済み・却下済みと重なる指摘が PR に投稿されず、本物の不具合（直っていない指摘・新しい別の問題）は落ちないこと。

## 決定

利用者の決定（2026-11-20・2026-11-21）に従い、集約が、対応済み・却下済みの指摘と重なる指摘を採用せず、PR に投稿しない。

- 落とすもの：対応済み（先頭のコミットで直っていると確かめたもの。返答だけを根拠にしない）と重なる指摘。却下済みと重なる指摘（同じ箇所・同じ問題。言い換えを含む）。
- 人の却下は `must` でも落とす。人の却下は、`by` が `person` の返答、人が後続に回すと決めた指摘、人が画面で無効にした指摘。AI の「対応しない」と重なる `must` は落とさず、確かめ直して `must` の重みなら新しい `must` として出す。
- 落とさないもの：直しが効いていない・確かめられない指摘、直しが持ち込んだ別の問題、却下の後の変更で問題が変わった・影響が大きくなった指摘。
- 理由が重なるときは、人の却下→AI の対応しない→対応済み→既存の指摘→目的の範囲の外の順に当て、1 件を 1 つの行でだけ数える。落とした件数を総評に 1 行で書く。判定は採用した指摘で決める。自己レビューには当てない。
- デーモンは、判断の材料を渡し、決まりの要点を指示にも書く（スキルを差し替えたプロジェクトでも効かせる）。
  - 各件に出どころ `by`（`sacty`・`person`・`unverified`）と、sacty の返信の状態 `reply` を付ける。
  - `existingReviews` を全体で 50 件に上げ、却下・対応しない・後続に回したいの返答と人の投稿を、対応したの返答より優先して残す。載せきれない件数は `omitted` に書く。
  - 人が画面で無効にした指摘を `voidedByPerson` で渡す。
  - 前回の指摘に「取り下げた（理由つき）」を書けるようにし、取り下げた指摘を、PR を作ったタスクの直しの対象から外す。
  - 同じ先頭の判定し直しの回でも、人の却下は確かめずに取り下げる。
- イベントの形・画面・GitHub への投稿の形は変えない。

## 採らなかった案

- 重なりの照合を、デーモンの文字列の一致で行う案：言い換えは、文の一致でなく、箇所と趣旨で比べるため、集約の AI に任せ、デーモンは材料と決まりを渡すだけにした。
- 返信の状態を、返信を作るときに別の欄へ残す案：取り込んだ PR にも効かせ、投稿の形を変えないため、返信の頭の文から読む。読み取りは、返信を作る側と同じ定数を使い、文言の変更で食い違わないようにした。
- 同じ原因が続いたら止める仕組み：利用者の決定で入れない。
- 人の返答を、PR の作者のものだけにする案：別の保守者が断った指摘が蒸し返される。作者と、組織のメンバー・共同作業者（`OWNER`・`MEMBER`・`COLLABORATOR`）の返答を人とした。この関係は書き込み権限までは保証しないため、読み取り権限だけの人の「対象外」でも `must` が落ちうる（権限まで確かめるなら collaborators の権限の API が要り、設計の決定を変える）。

## 理由

- 往復が止まらない原因の多くが、直った指摘の出し直しと却下の蒸し返しである。集約で落とせば、往復が減る。
- 人の却下を `must` でも落とすのは、人の判断を尊重するため。人だと材料から確かめられない返答（権限の無いアカウント、目印の合わない投稿）は人の却下に数えず、`must` を落とさない側に倒す。
- 返答だけを根拠にしないことと、確かめられないときに落とさないことで、直っていない指摘を落とす害を避ける。

## 影響

- 往復が長い PR でも、人の却下・AI の対応しない・対応済みが、レビューの指示に載る。
- 権限を持たないが PR の作業に加わる人の「対象外」では `must` が落ちず、その人の却下した `must` は蒸し返されうる。
- `earlierReviews` の上限（新しい 5 件）は変えない。8 回目以降の往復では、最初の回の指摘が前々回以前のレビューのデータから消える。
