# PR のレビューで、行へのコメントにした指摘は、本文に重ねて書かない

- 日時: 2026-11-22 02:54 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-479
- 置き換え元: なし
- 置き換え先: なし

## 背景

sacty は PR のレビューを、本文と行へのコメントに分けて 1 件の `COMMENT` のレビューとして投稿する。
指示は、行へのコメントに「できる」と書くだけで、本文との書き分けを決めていなかった。そのため、行へのコメントにした指摘と同じ内容が、本文の「指摘」の節にも書かれることがあった。
レビューが長くなり、人が同じ指摘を 2 回読む。どれが新しい指摘かも見分けにくい。

## 決定

- 行へのコメントにした指摘は、本文のどの節にも、同じ内容（言い換えを含む。起きる条件・実害・直し方）を書かせない。本文の「指摘」の節には、行へのコメントにしない指摘（差分の中に付けられる行が無い指摘）だけを書かせる。
- 差分の外の行へのコメントは、今までどおり sacty が本文の「行についての指摘」の節に回す。エージェントは本文の「指摘」の節にも書かない（本文に 1 回だけ出る）。
- 本文だけを読む人が、行へのコメントに気づけるように、sacty が判定の行のすぐ下に「行へのコメントに N 件の指摘があります。」を足す。件数は sacty が数える。エージェントには総評に件数を書かせない。
  - 行へのコメントとして投稿する件が 1 件以上のときだけ足す（判定が無い回も足す）。0 件のときと、422 で本文に入れて投稿し直すときは足さない。
  - 頭（`[要修正]`・`[提案]`）と「<パス>:<行>：」の形を使わない（選り分けが 1 件の指摘として読まない）。
- 判定が無い・読み取れない回の判定の行の案内は、「本文と行へのコメントを確かめてください」にする。
- 再レビューの「前回の指摘」の節は、本文に書く。前回の行へのコメントの指摘も、場所と状況だけを短く挙げ、中身は繰り返さない。前回の本文の件数の行は、前回の指摘でも今回の件数でもない。
- 直しの側への説明に、本文の件数の行は別の指摘ではないと足す。
- 既定のスキルの `pr-review.md` に、依頼した側が投稿するときも重ねないと書く。`aggregation.md` の「他の現れ」の列挙先は、代表の指摘の本文（行へのコメントならそのコメント）にする。
- 判定・重さの数え方、指摘の読み取り（選り分け・取り込み・重なりの照合）のコード、自己レビューは変えない。

## 理由

- 件数は、エージェントが投稿の時点では、どの行へのコメントが差分の外として本文に回るか、422 で全部が本文に入るかを知らないので、エージェントに書かせるとずれる。sacty が投稿する件数を数えて足せば、実際と合う。
- 指摘の読み取りは、本文の「指摘」の節の頭と、行へのコメントの頭を別々に読む。本文が総評と件数の行だけになっても、行へのコメントの指摘は別の 1 件として読まれ、要修正の判定への補いも変わらない。コードを変えずに、テストで確かめる。
- 関係する方針：[PR のレビューの本文に過程の情報を書かない](20261121-1603-superseded-pr-review-without-process-info.md)・[PR の説明とコメントは判断に要る情報だけにする](20261121-2200-pr-description-and-comments-for-decision-only.md)（同じ中身の繰り返しを外す）。

## 影響

- レビューの本文が短くなる。行へのコメントが多い回は、本文が総評と件数の行と検証の結果だけになることがある。
- 本文だけが総評になった要修正の回も、行へのコメントの要修正は別の指摘として直しに渡る。
