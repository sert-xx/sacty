# 指摘を受けた直しの実行では、セルフレビューの最初のレビューを再レビューとして扱う

- 日時: 2026-11-03 17:00 UTC
- ステータス: 採用
- 関係する PR・タスク: #297、PBI-296
- 置き換え元: なし
- 置き換え先: なし

## 背景

[セルフレビューの再レビューは、前回 must を出した観点と X-1 だけを起動する](20261103-0302-self-review-rereview-launches-must-viewpoints-only.md)で、同じ実行の中の再レビュー（2回目以降）は観点を絞った。
実験の3回目（F39）で、人の差し戻しや AI のレビューの指摘で実行が新しく始まると、その実行の最初のレビューが「初回」の扱いになり、観点を全部また起動することが分かった。S16 は人の差し戻しの直しで9観点（$15.96）、S18 は AI の指摘（表の整形だけ）の直しで8観点（$8.17）だった。
原因は、Sacty が直しの実行に渡す指示と、スキルの「初回」の判定が、実行をまたいだ前の回の指摘を見ていないことだった。

## 決定

- 人の差し戻し・AI のレビューの指摘・実装への最終レビューの不合格を受けた直しの実行では、その実行の最初のセルフレビューを再レビューとして扱う。起動するのは、今回の指摘に関わる観点と X-1 だけ。タスクの最初の実行は、今までどおり全部の観点で見る。
- 要求要件・設計・実装のどの工程にも当てる。
- 指摘に関わる観点は、スキルに決め方を書く（指摘が観点の ID を示していればその観点、示していなければ指摘の問題を観点カタログの「見るもの」に当てはめる。決められないときは当てはまりうる観点をすべて起動する）。Sacty の指示は、この実行が直しの実行であることだけを伝え、観点は決めない。
- X-2 は、指摘が検証の失敗に関わるとき、または実行し直した検証が失敗・警告を出したときだけ起動する。
- 起動した担当には指摘と直しの内容を渡し、直ったかと新しい問題を持ち込んでいないかを見させる。起動しなかった観点は、起動表と報告に理由つきで残す。
- 指示を足すのは、その工程の前回の提出のセルフレビューが合格のときだけにする（要求要件・設計は、前回の下書きを元に直すときに限る）。
- 初回のレビューの規則と、`pr-review` の規則は変えない。

## 理由

- 前の実行で合格した成果物に、指摘に応える直しを入れた実行なので、見るべきは指摘が直ったかと、直しが持ち込んだ問題である。全部の観点で見直す費用に見合う指摘は出ていなかった。
- 直しが指摘と無関係な箇所に及んだときの問題は、観点にとらわれない X-1 が拾える。
- 前回の提出が合格していないときは、前回の未解決が今回の指摘の外に残りうるので、絞らない。
- 指示でなくスキルに選び方を置くのは、既定のスキルが言語・リポジトリを問わず使われ、観点の選び方の規則を 1 か所に保つため（PBI-286 と同じ）。
- 最終レビューの不合格だけでなく、テストが通らなかっただけ・競合の目印だけの実装のやり直しには、受け入れ条件にないので足さない。

## 影響

- 差し戻しや AI の指摘への直しのセルフレビューの費用と時間が下がる。
- 指摘に関わらない観点が見るはずの問題を、直しが持ち込んだときは、X-1 が拾えなければ見逃す。前の実行で全部の観点で見ていることで許容する。
- 指摘がどの観点に関わるかの判断は、親のエージェントが行う。外れると、必要な観点を起動しない可能性がある（迷ったら起動する、と書いて抑える）。
- 仕様書は[コンテキスト](../spec/context.md#既定のレビュー用スキル)と[タスクと工程](../spec/tasks-and-steps.md#提出の前のセルフレビュー)に、利用者向けは[タスクを進める](../user/tasks.md#提出の前のセルフレビュー)に記す。
