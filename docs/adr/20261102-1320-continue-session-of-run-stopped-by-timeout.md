# 時間切れで止めた実行は、再開のときに同じエージェントのセッションの続きから進める

- 日時: 2026-11-02 13:20 UTC
- ステータス: 採用
- 関係する PR・タスク: #281、PBI-280
- 置き換え元: なし
- 置き換え先: なし

## 背景

フィールドの試行（時間切れの再開）で、`run_timeout` を短くして流したところ、再開のたびに止まった工程を新しいセッションで最初から
やり直した。要求要件は毎回同じ調査から始めて、セルフレビューの起動で上限が尽き、実装は未コミットの変更を拾ったが、検証とセルフレビューを
毎回通し直して上限に収まらなかった。上限を延ばさずに再開すると、永久に進まないことがあった。

## 決定

- 時間切れ（`run.timeout`）で止めた実行は、`AgentRunTimedOut` を作業履歴に残す。次に同じ役割を実行するとき、直前の実行がその実行で、
  同じエージェントであり、写してあったセッションのファイルが記録どおりなら、そのファイルを設定の場所に戻して、Claude Code は
  `--resume`、Codex は `resume` で、同じセッションの続きから進める。指示の先頭に、時間切れで止めて再開したことを足す。
- 続けられないとき（セッションの記録が無い・エージェントを変えた・ファイルが省かれた／壊れた）は、今までどおり最初から実行し直し、
  続けたか続けなかったかと理由を `AgentRunContinued` に残す。
- 「直前の実行」は、作業履歴を新しいほうから見て、最初に出会う実行の記録で決める。時間切れの後に別の実行（質問への答え以外）があれば続けない。
- 実装の作業領域（タスクの clone）は、止めても消さないことを確かめた。退避は足さない。

## 理由

- 人が決めた方針は、何度か時間切れで止まっても最後はタスクの完了まで進めること。調査・下書き・検証の結果は会話に残るので、
  セッションを続ければ、上限を延ばさなくても進める。
- 写したセッションのファイルは、すでに実行ごとに残している（PBI-66）。新しい保存の仕組みを足さず、作業履歴だけで決められる。
- 判定を作業履歴から導くので、デーモンを再起動しても、再開の前に別の操作（承認・差し戻し）が入っても、古いセッションを誤って続けない。

## 影響

- 作業履歴に、記録だけで状態を変えない `AgentRunTimedOut`・`AgentRunContinued` が増える。
- 続ける実行の使用量は、再開したセッションの使用量の数え方（各 `result` の `usage`）で数える。
- 要求要件・設計などは、実行ごとに写しを用意するので、止める前にコンテナの中・写しに書いたファイルは残らない。会話の記録から作り直すよう指示に書く。
- 再開を断られた場合は、その実行を失敗として返し、次の再開で最初から実行する（実行 ID を変えてやり直さない）。
- Claude Code・Codex が、強制終了したセッションの途中（書きかけの発言・結果の無いツールの呼び出し）を再開できるかは、実機で確かめる必要がある。
