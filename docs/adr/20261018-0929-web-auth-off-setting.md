# 画面の認証を設定で OFF にできるようにする

- 日時: 2026-10-18 09:29 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-133
- 置き換え元: なし
- 置き換え先: なし

## 背景

画面の認証（[画面は、起動ごとの秘密で入ったブラウザだけが使える](20261018-0414-web-session-auth.md)）で、起動のたびに端末の URL を
開く必要ができた。ステークホルダーから、これが邪魔なので設定ファイルで OFF にしたいと要望があった。OFF にすると、工程のコンテナ内のコードが
画面を通して承認・設定の変更をできる状態に戻ることを伝えたうえで、OFF にできるようにすると決めた（起動し直しても入り直さなくてよくする案も
示したが、OFF を選んだ）。

## 決定

- `config.yaml` の `web.auth`（既定 `true`）で OFF にできる。真偽だけを受け付ける。設定ファイルが無い・読めないときは ON（安全側）。
- OFF の指定は、`sacty up` が設定ファイルを読んで画面に渡す。利用者のシェルの環境変数では OFF にならない（取り除く）。
- OFF でも Host の確かめは残す（外部のサイトからの DNS rebinding で、認証の無い画面を操作されないように）。
- OFF のときは、起動のたびに端末に危険を警告する。

## 検討した案

- **起動し直しても入り直さなくてよくする**（秘密を SACTY_HOME に保存し、ブラウザを自動で開く）：認証を保ったまま手間を減らせるが、
  ステークホルダーは OFF を選んだ。後から足すこともできる。
- **環境変数で OFF にする**：シェルの設定に残って、気づかないうちに OFF のままになりやすい。設定ファイルに書き、起動のたびに警告する。

## 結果

- 信頼できるリポジトリだけを扱う環境では、URL を開く手間なく使える。
- OFF にした環境では、工程のコンテナから画面を通して承認・設定の変更をできる（PBI-129 の前と同じ）。Host の確かめだけが残る。
