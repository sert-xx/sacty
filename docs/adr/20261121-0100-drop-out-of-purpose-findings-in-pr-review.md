# PR のレビューの集約は、PR の目的の範囲の外の指摘を投稿しない

- 日時: 2026-11-21 01:00 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-426
- 置き換え元: なし
- 置き換え先: なし

## 背景

集約の「不採用」の「範囲の外」は、変えていない既存の問題と、再レビューで前回以降の差分の外の `should`・`nit` だけを指していた。PR の目的の外の求め（要らない機能の追加、関係の薄い箇所の作り直し、目的の外の文書やテストの拡充）は、指摘箇所が差分の中にあれば採用され、`[提案]` として投稿された。提案が1件でもあれば、PR を作ったタスクが直しに入り、再レビューがもう1回走る（1往復 約20分）。

## 決定

利用者の決定（2026-11-20）に従い、`pr-review` の集約は、重みを表で決めた後に、PR の目的の範囲の外の求めを不採用にし、投稿しない。

- 理由「PR の目的の範囲の外」を `dismissed` に残し、「範囲の外（既存の問題）」と区別する。
- `must` は落とさない。落とすために重みを下げない。目的を読み取れないとき・迷うときは落とさない。変えた・足した箇所そのものへの指摘は範囲の中とする。
- 落とした件数は、総評に1行で書く（内容は書かない。0件なら書かない）。判定は採用した指摘で決める。
- 再レビューでも同じ。前回の指摘を落とすときは、前回の指摘の一覧のその行に、取り下げたことと理由を書く。
- 自己レビューには当てない。自己レビューは `must` だけを修正に戻し、どこにも投稿しないので、落としても往復は減らない。

## 採らなかった案

- 落とした指摘を記録（`dismissed`）だけに残し、総評に件数も書かない案：落としたことが読み手に見えず、判断を確かめられない。
- 落とした指摘の一覧を画面に出す案：利用者が「件数を1行」を選んだ。画面の追加も要る。

## 理由

- 目的の外の求めが往復を増やす。落とせば、提案だけで直しに入る往復が減る。
- `must` と、迷うときを落とさないことで、本物の不具合を落とす害を避ける。

## 影響

- 目的の範囲の外と判断した指摘は、PR に出ない。判断を誤ると、有用な提案が出ない（件数は総評で分かる）。
- デーモンのコードは変えない。
- 規則は、仕様書（[context.md](../spec/context.md) の「PR のレビューと投稿」）に書いた。
