# どれかのプロジェクトのコンテキストを読めない間も、ビルドキャッシュの片付けは走らせる

- 日時: 2026-11-17 22:39 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-389、#428
- 置き換え元: [デーモンのコンテキストのイメージの片付けでも、3日使っていないビルドキャッシュを消す](20261117-1500-superseded-prune-build-cache-with-context-images.md)（コンテキストを読めていないときはビルドキャッシュも消さない、という条件を変えた。ほかの決定はそのまま）
- 置き換え先: なし

## 背景

デーモンの片付け（`ContextImageBuilder` の `prune`）は、使わなくなったコンテキストのイメージを消してから、3日使っていないビルドキャッシュを消す（置き換え元の ADR）。
この片付けは、どれかのプロジェクトのコンテキストを読めない間（認証切れ・リポジトリの削除など）は、何もせずに戻っていた。
イメージの片付けは、残すイメージの一覧（すべてのプロジェクトの今の定義の名前）が揃わないと、作ったイメージを消してしまうので、止める必要がある。
ビルドキャッシュの片付け（`docker builder prune`）は、残す一覧を使わない。それでも同じ条件で止まっていたので、1つのプロジェクトを読めないだけで、ビルドキャッシュが増え続けた。
置き換え元の ADR では、ビルドキャッシュの片付けだけ条件を緩める案を、決めずに残していた。

## 決定

- 設定（`config.yaml`）は読めていて、どれかのプロジェクトのコンテキストを読めない間も、ビルドキャッシュの片付けは走らせる。
  - 間隔（前に成功してから6時間）・上限の時間（2分）・ログの決まりは、置き換え元の ADR のまま（消す対象の期間は、[別の ADR](20261117-2249-prune-build-cache-without-age-filter.md) でやめた）。
- その間、コンテキストのイメージの片付けは走らせない。イメージを1つも消さず、イメージの一覧（`docker image ls`）も取らない。
- 次のときは、今までどおり、イメージもビルドキャッシュも消さない。
  - 作っている最中・読み直しの最中。
  - 設定を読めないとき。
  - 設定を読めないときに読んだままのプロジェクト（設定が戻ってから読み直していないもの）があるとき。
- デーモンの停止・時間切れの扱いは変えない。

## 理由

- 「走らせる」ことは、リポジトリの持ち主が決めた（2026-11-17 UTC）。ビルドキャッシュの片付けは残す一覧を使わないので、止める理由が無い。1つ読めないだけでディスクが増え続けるのを防ぐ。
- イメージの片付けを止めたままにするのは、読めないプロジェクトの今の定義が分からず、残す一覧が揃わないため。
- イメージを消さないことは、片付けに渡す一覧を「無い」（`null`）にして表した。
  読めたプロジェクトの分だけの一覧や、空の一覧を渡す形にすると、渡した先でイメージが消える。一覧が無いことを型で分け、取り違えを型の検査で見つけられるようにした。
- 設定を読めないときに読んだままのプロジェクトがあるときを変えないのは、設定を読めないときの扱いを、この決定の範囲に入れていないため（決めていない）。
  この状態は、設定が戻った後の次の読み直し（遅くとも5分後）で解ける。

## 影響

- コンテキストを読めない状態が続いても、ビルドキャッシュは、6時間に1回、使っていないものが消える。
- その間、使わなくなったコンテキストのイメージは残り続ける。読めるようになると、次の読み直しから消える。
- 設定を読めない間は、今までどおり、ビルドキャッシュも消えない。手での片付け（`sacty image build`・`docker builder prune`）が要る。
- コンテキストを読めない間も、ビルドキャッシュの片付けのログ（成功・失敗・打ち切り）が出る。
