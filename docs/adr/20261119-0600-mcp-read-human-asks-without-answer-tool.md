# sacty mcp の人への問いかけは、読み取り側に出し、答えは既存の承認・差し戻しで行う

- 日時: 2026-11-19 06:00 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-398
- 置き換え元: なし
- 置き換え先: なし

## 背景

sacty が人に問いかけて待っているとき、手元の AI は、何を問われているかを MCP から読めなかった。
sacty が人に問う「質問」には、専用の回答の API が無い。実績のある問いかけは、承認待ちの「人に確かめたいこと」（`humanAsks`）と、人の判断待ち（`escalated`）で、答え方は既存の承認と差し戻し（PR を作った工程は PR のコメント）である。
機能を1つずつ足す流れの5回目として、何をどこまで足すかを決める必要があった。

## 決定

- ツールは足さない（10個のまま）。`get_task` に `humanAsks`（確かめたいことの中身と答え方）と `escalation`（人の判断待ちの理由）を足し、タスクの要約には件数（`asks`）だけを足す。
- 判定は `@sacty/core` の `humanAsks`・`openProposal` を呼ぶ。MCP の層で作り直さない。デーモンの API も新しく呼ばない。
- 答える専用のツールは足さない。答えは、答えが要らなければ承認、答えるなら `request_changes` の `comments`（PR を作った工程は PR のコメント）で行い、欄と説明文で案内する。
- 変更の申し出では、core の投影が `task.escalation` を作らないので、理由は開いている申し出（`openProposal`）から読む。core は変えない。
- 文の長さ（1件 1000 文字）・件数（`confirms` 20 件、指摘の ID 20 件）に上限を置き、省いたことを結果に入れる。

## 理由

- 答える専用の API が無いので、ツールを足すと、MCP 専用の経路・記録が増える。既存の承認・差し戻しなら、記録も動きも画面と同じ。
- 読み取りだけなら、状態を変えず、前の版のデーモンでも（欄が無いだけで）動く。
- 少しずつ足す方針に合わせ、変更の申し出・後続に回したい案への決定は、実績が無いので入れない。

## 影響

- 手元の AI は、承認・差し戻しを頼まれたときに、確かめたいことを読み、利用者に伝えてから進められる。
- 結果にエージェントやほかの人が書いた文が増えるので、説明文と使い方の文に、データとして扱う注意を足した。
- 変更の申し出・後続に回したい案への決定・上限を超えた差し戻しは、MCP からできない（後続で別の決定として足す）。
- 仕様は [MCP サーバー](../spec/mcp-server.md#人に確かめたいこと)、利用者向けは [手元の AI から操作する](../user/mcp.md#確かめたいことを読む答える) に書く。
