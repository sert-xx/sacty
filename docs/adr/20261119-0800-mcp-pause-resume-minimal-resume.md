# sacty mcp の再開は補足だけの最小の版にし、完了したタスクの一時停止は MCP の層で断る

- 日時: 2026-11-19 08:00 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-400
- 置き換え元: なし
- 置き換え先: なし

## 背景

`sacty mcp` は、承認（[承認の ADR](20261119-0300-mcp-approve-with-screen-api-not-merge.md)）・差し戻し（[差し戻しの ADR](20261119-0400-mcp-request-changes-basic-stop-before-limit.md)）・待つツール（[待つツールの ADR](20261119-0700-mcp-wait-for-task-poll-in-mcp-layer.md)）までできる。
機能を1つずつ足す流れの7回目の前半として、タスクの一時停止と再開を足す（中止は取り消せないので、次に分ける）。
画面の再開には、予算の上限の引き上げ・テストの扱いの決定・イメージとエージェントの変更という選択がある。このマシンの作業履歴では、再開の大半は補足だけか、上限の引き上げだった。
デーモンの一時停止（`service.pause`）は、完了したタスク（`idle` で工程がすべて終わった）や、検証中でない `idle` を断らず、`TaskPaused` を記録する。画面は、ボタンを出さないだけである。

## 決定

- ツール `pause_task`（`task_id`）と `resume_task`（`task_id`・`note`）を足す。デーモンの既存の `POST /api/tasks/:id/pause`（`{}`）と `POST /api/tasks/:id/resume`（`{}` か `{ note }`）だけを呼ぶ。デーモンのサービス・API・`@sacty/core`・画面は変えない。
- **再開は、補足だけの最小の版にする。** `capUsd`・`tests`・`image`・`agents` は、引数にもせず、送らない。費用が増える判断（理由が `budget`）・テストの扱いを人が決められる停止（`canDecideTests`）・子タスクの中止を認めることになる停止（`child_cancelled`）は、API に送らず、画面で人が決めることを返す。
- **一時停止できるのは、画面でボタンが出る状態と同じ**（`queued`・`running`・`awaiting_approval`・検証中の `idle`）。完了したタスクと検証中でない `idle` は、デーモンが断らないので、MCP の層が `GET /api/tasks/:id` のタスクから確かめて、API に送らずに断る（`pauseBlock`。画面の判定の写しで、その旨をコメントに書く）。
- 一時停止・再開ができるかの判定（`pauseBlock`・`resumeBlock`）は1か所に置き、ツールの断りと、要約の `canPause`・`canResume`・`get_task` の `resumeBlocked` が同じ関数を使う。
- 結果を受け取れなかったとき（時間切れ・切断・5xx・本文を読めない）は、されている可能性を返し、自動でやり直さない。デーモンの一時停止は、コンテナを止めて処理の終わりを待ってから応答するので、30 秒の時間切れの後で一時停止になる（または承認待ちに達して止まらない）ことがある。待つ時間は変えない。
- 一時停止の結果を受け取れなかったときは、`state` が `running`・`queued` のままなら一時停止が続いている可能性があるので、呼び直さず `wait_for_task` で待つ（二重に送ると、承認待ちに達して止まらなかった後の2回目が、承認待ちの一時停止として記録される）。
- 画面の再開フォームがリポジトリの選択を必須にする場面（チケットから取り込み、作業するリポジトリを決める前に止まった）は、core の `awaitingTicketTriage`・`awaitingRepository` を読んで、`resumeBlock` で断る側に入れる（画面で人が決める）。
- 承認・差し戻しと同じ形の、結果を受け取れなかったときの案内の組み立てと、送る前の失敗・5xx・本文を読めないの振り分けと、「利用者に頼まれたときだけ」の文は、共通の関数・定数にまとめる。既存の2つのツールの文と動きは変えない。
- 注釈は `readOnlyHint: false`・`destructiveHint: false`・`idempotentHint: false`。`openWorldHint` は、再開は `true`（工程が PR などに書く）、一時停止は `false`（ローカルのコンテナを止め、承認待ちなら承認ゲートと PR の見守りを止めるだけで、sacty の外には書かず、再開で戻せる）。

## 理由

- 補足だけの再開で、実績の大半（`budget` 以外）を賄える。費用や取り消せない判断は、人が画面で決める方針（承認・差し戻しと同じ）に揃う。
- 完了したタスクの一時停止を通すと、完了したタスクが一時停止中になり、再開で `idle` に戻る、という意味のない記録が残る。デーモンを変えない範囲では、MCP の層で断るしかない。
- 判定を1か所に置けば、`get_task` の表示とツールの断りが食い違わない。

## 影響

- 登録した AI は、利用者に頼まれたときに、一時停止と補足だけの再開ができる。再開は、止まった工程を実行し直すことがあり、時間と費用がかかる。
- 先読みと送信の間に完了した場合の、わずかな窓は残る（デーモンが完了したタスクを断る変更は、範囲外）。`resume_task` の `canResume` が真でも、デーモンが（外部作業が始まっている・依存先が中止された・止まったと確かめられないコンテナが残っている、などで）断ることがある。
- 中止・やり直し・上限の引き上げ付きの再開・テストの決定・`child_cancelled` の再開は、後続で別の決定として足す（この作りは、後から足せる）。
- 仕様は [MCP サーバー](../spec/mcp-server.md#pause_task)、利用者向けは [手元の AI から操作する](../user/mcp.md#一時停止する) に書く。
