# 起動時と保存時に、プロジェクトのコンテキストの秘密情報もまとめて取り出す

- 日時: 2026-10-15 13:03 UTC
- ステータス: 採用
- 関係する PR・タスク: #117、PBI-107
- 置き換え元: [sacty up の起動時に、使う秘密情報をまとめて取り出してから、タスクの実行と取り込みを始める](20261013-0354-superseded-prefetch-secrets-at-startup.md)
- 置き換え先: なし

## 背景

起動時のまとめての取り出しは、コンテキストリポジトリの `mcp.yaml`・`platforms.yaml` の秘密情報を対象外にしていた（取得しないとわからないため）。
そのため、工程の実行・ゲートウェイでの PF の呼び出し・チケットのトリアージで初めて使うときに、参照ごとに `op read` が走り、
1Password の承認を求めていた。タスクを作った後に出るこの承認は見落としやすく、タスクが止まって見えていた。

## 決定

- 起動時（と「秘密情報を取り出し直す」）は、コンテキストリポジトリを設定したプロジェクトごとにコンテキストを取得して合成し（継承の鎖の上の層を含む）、
  `platforms.yaml` と `mcp.yaml` の秘密情報を、ほかの秘密情報と同じ1回の `op run` で取り出す。ホストの PF・MCP サーバーと同じ名前で、層のものを
  使わない項目は含めない。
- コンテキストは同時に4件ずつ取得し、全体で30秒まで待つ。取得できなかった・時間内に取得できなかったプロジェクトは、理由を画面の警告に出し、
  その秘密情報は使うときに取り出す（今までどおりの最後の手段）。起動は止めない。
- プロジェクトを保存したとき（作成・インポートを含む）は、応答を待たせずに、そのプロジェクトの通知先とコンテキストの秘密情報をまとめて取り出す。
  持っている参照は問い合わせない。取り出せなかったものは画面の警告に出し、そのプロジェクトの前の警告と置き換える。
- 起動の後にコンテキストリポジトリに足された秘密情報は、ほかの時点では前もって取り出さず、使うときに取り出す。前もって取り出すには、
  取り出し直すか、プロジェクトを保存し直す。仕様書と利用者向けの文書にそう書く。
- まとめて取り出している最中に同じ参照が使われたら、別に問い合わせず、その結果を待たせる。まとめて取り出せずに参照ごとに取り出し直すときは、
  1件ずつ順に取り出す。

## 理由

- 1Password の承認を、起動時と、利用者が自分で操作したとき（保存・取り出し直し）だけにするため。タスクを作った後に承認を求めて止まるのを減らす。
- 30秒の上限と同時の数の上限は、プロジェクトが多い・git の取得が応答しないときに、タスクの実行と取り込みの開始を長く止めないため。
  値は実測ではなく、git の浅い clone が通常は数秒で終わることからの見積もり（わからない部分がある）。
- 保存の応答を待たせないのは、1Password の承認を待つ間（最長 120 秒）保存が終わらないのを避けるため。承認が出るのは保存の直後なので、
  利用者には何の承認かがわかる。
- 起動の後に足された秘密情報を、ほかの時点（タスクの作成時・定期的な取得）で前もって取り出すことは採らなかった。タスクの作成時に取り出すと、
  黙って承認を求めることになり、見落としの問題が残る。定期的な取得は、承認が出る時点が利用者にわからない。
- 取り出し中の参照の結果を待たせるのは、保存のときの取り出しがタスクの実行と並ぶので、同じ参照に2回承認を求めないため。

## 影響

- コンテキストリポジトリを設定したプロジェクトがあると、起動のときにそのコンテキストを取得する（git の通信が増える）。
  取得が遅いと、タスクの実行と取り込みの開始が最長30秒遅れる。
- プロジェクトの保存のたびに、コンテキストをもう1回取得する（保存のときの検査と別に）。
- 使っていない秘密情報（合成で残ったが、工程で使わない MCP サーバーなど）も取り出すので、取り出せないと警告が出る。
- 仕様は [秘密情報](../spec/secrets.md) にある。
