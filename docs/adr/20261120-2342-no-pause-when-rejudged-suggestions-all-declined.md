# 判定し直した回に残った提案もすべて対応しないときは、一時停止せずに、ドラフトを外して人の承認を待つ

- 日時: 2026-11-20 23:42 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-440

- 置き換え先: なし

## 背景

選り分けで提案のすべてを対応しないとしたときは、理由を返信し、同じ先頭を 1 回だけ判定し直す。
その回にも提案だけが残り、それもすべて対応しないとなったとき、置き換え元の決定は、返信の後に親タスクを一時停止して、人が選ぶとしていた。
一時停止すると、人は「再開する」を押すだけの手間を負い、押した後の動きも、ドラフトを外して承認を待つだけになる。

## 決定

- 判定し直した回に残った提案もすべて対応しないときは、返信が済んだ後、一時停止せずに、PR のドラフトを外して人の承認を待つ。
  - レビューの判定は「提案あり」のまま（指摘なしに書き換えない）。レビューの子タスクの状態と見守りは変えない。
  - その先頭には、もう 1 回の判定し直しも選り分けも始めない。AI どうしの往復は、そこで止まる。
  - ドラフトを外すのは、その PR の番号・その先頭のときだけ。先頭が進めば、今までどおり再レビューと選り分けが働く。
- 人は、作業履歴・承認の画面・タスクの概要で、提案が残ったこと・AI が対応しないと判断したこと・理由・リスク評価が無いこと・直させたいときは PR に要対応とコメントすることを読める。
- 以前の版が一時停止させたタスクは、再開すると承認待ちに戻り、同じ先頭なら、ドラフトを外す（もう一度止めない）。

## 理由

利用者が「そのままドラフトを外す」と決めた。
判定し直しは 1 回だけなので、それでも残った提案を、人の承認の前にさらに止める理由が薄い。
人はドラフトが外れた PR で、返信された理由を読み、直させたければ要対応とコメントして覆せる。

## 影響

- 良い点：人が再開を押す手間が無くなり、承認の待ちに直接進む。
- 受け入れた代償：その先頭にはリスク評価が出ない（リスク評価は、レビューの子タスクが指摘なしにした回だけに出る。[リスク評価を出す回の決定](20261121-0300-risk-assessment-only-when-review-has-no-findings.md)）。提案ありのままドラフトを外す回のために、再レビューを足さない。
- 作業履歴の `PullRequestMarkedReady` に、外した理由（`reason: suggestions_declined`）を足した。`SuggestionsTriaged.stop` と `triage.left` は、以前の記録を読めるまま残す。
- 仕様は [承認と差し戻し](../spec/approval.md#直しに入る前の提案の選り分け)、[作業履歴](../spec/event-log.md#費用) にある。
