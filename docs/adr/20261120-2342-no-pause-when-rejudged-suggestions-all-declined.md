## 背景

選り分けで提案のすべてを対応しないとしたときは、理由を返信し、同じ先頭を 1 回だけ判定し直す。
その回にも提案だけが残り、それもすべて対応しないとなったとき、置き換え元の決定は、返信の後に親タスクを一時停止して、人が選ぶとしていた。
一時停止すると、人は「再開する」を押すだけの手間を負い、押した後の動きも、ドラフトを外して承認を待つだけになる。

## 決定

- 判定し直した回に残った提案もすべて対応しないときは、返信が済んだ後、一時停止せずに、リスク評価だけを 1 回行ってから、PR のドラフトを外して人の承認を待つ。
  - 評価は、再レビュー（観点の担当の起動・検証）をせず、オーケストレーターのエージェントに、実装後のコードと差分を読ませて行う。材料に、残った提案と、対応しないとした理由を渡す。
  - 結果は、PR のコメント（1 通）と、承認の画面の「PR のリスク評価」の欄（評価したコミットつき）に載せる。記録は `PullRequestRiskAssessed`（`via` は `suggestions_declined`）。費用は、今までの評価と同じに記録し、予算に数える。
  - 評価できなくても（予算の上限・実行の失敗・答えを読めない）、理由を記録し、コメントに書いて、ドラフトを外す。
  - 同じ PR のその先頭に、評価を繰り返さない（デーモンの起動し直しも、評価の後・ドラフトを外す前に止まった場合も。評価は記録で、コメントは目印で見つける）。
  - レビューの判定は「提案あり」のまま（指摘なしに書き換えない）。レビューの子タスクの状態と見守りは変えない。
  - その先頭には、もう 1 回の判定し直しも選り分けも始めない。AI どうしの往復は、そこで止まる。
  - ドラフトを外すのは、その PR の番号・その先頭のときだけ。先頭が進めば、今までどおり再レビューと選り分けが働く。
- 人は、作業履歴・承認の画面・タスクの概要で、提案が残ったこと・AI が対応しないと判断したこと・理由・指摘なしの回ではなく、再レビューをせずに評価したこと・直させたいときは PR に要対応とコメントすることを読める。
- 以前の版が一時停止させたタスクは、再開すると承認待ちに戻り、同じ先頭なら、評価してからドラフトを外す（もう一度止めない）。
- 変えないもの：指摘なしの回の評価（レビューの子タスクが指摘なしと判定した回に出る）、PR の作成・更新のときに評価しないこと、要求要件・設計の PR と既存の PR を引き継いだタスクの PR に評価を付けないこと。

## 理由

利用者が「そのままドラフトを外す」と決めた。
判定し直しは 1 回だけなので、それでも残った提案を、人の承認の前にさらに止める理由が薄い。
人はドラフトが外れた PR で、返信された理由を読み、直させたければ要対応とコメントして覆せる。
その後に、利用者が追加で決めた：人が最終判断をする回なので、リスク評価は付けたい。ただし、再レビューを足すと、AI どうしの往復をまた始めることになる。そのため、評価だけを 1 回行う。
比べた案：再レビューをして、指摘なしの回の評価を出す案は、止めたい往復を増やすので採らなかった。評価を出さない案（最初の決定）は、その先頭の最終判断の目安が無くなるので、改めた。

## 影響

- 良い点：人が再開を押す手間が無くなり、承認の待ちに直接進む。
- 受け入れた代償：評価のための実行（オーケストレーターの 1 回）が、ドラフトを外すまでの待ちに加わる。評価は、レビューの判定ではなく、提案を踏まえた目安で、指摘なしの回の評価（[リスク評価を出す回の決定](20261121-0300-superseded-risk-assessment-only-when-review-has-no-findings.md)）とは出どころが違う。画面は、評価の出どころを添えて見分ける。
- 作業履歴の `PullRequestMarkedReady` に、外した理由（`reason: suggestions_declined`）を足した。`SuggestionsTriaged.stop` と `triage.left` は、以前の記録を読めるまま残す。
- 仕様は [承認と差し戻し](../spec/approval.md#直しに入る前の提案の選り分け)、[作業履歴](../spec/event-log.md#費用) にある。
