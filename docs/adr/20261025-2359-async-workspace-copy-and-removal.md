# 対象リポジトリの大きさに比例する作業領域の写し・削除は、デーモンのイベントループを止めない非同期のファイル操作で行う

- 日時: 2026-10-25 23:59 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-156
- 置き換え元: なし
- 置き換え先: なし

## 背景

ゴールガーディアンの最終レビューの準備で、実装後の作業領域を `_guardian/<実行 ID>` に同期の `cpSync` で写し、終わった後に同期の `rmSync` で
消していた。作業ツリーが数 GB（`node_modules` を含む）になると、写す間・消す間の数分間、デーモンのメインスレッドがファイル操作だけを実行し、
HTTP の要求に応答できなかった（ダッシュボードが読み込み中のままになった）。clone の後の `.git` の退避、`_snapshots`・`_review` の削除、
中止したタスクの作業領域の削除なども、同じく同期で行っていた。

## 決定

- 対象リポジトリの大きさに比例するファイル操作（作業領域の写し・削除、clone の後の `.git` の退避、共用の compose の書き出し先の削除）は、
  `node:fs/promises` の `cp`・`rm` で非同期に行い、終わるまで `await` する。写し方（リンクの先を写さない・作業領域の `.git` を渡さず退避した
  メタデータの写しを `.git` にする・`finally` で片付ける）は変えない。
- 写しの途中で一時停止・中止を求められたら、写し終わった後、コンテナを起動する前に止める（これまでの準備の間の止め方と同じ）。
- デーモンを止め始めた後は、エージェントの実行を新しく起動しない（`run.daemonStopped`）。写している間に止められた実行が、写し終わってから
  起動しないようにするため。
- 大きさが決まっている小さなファイル操作（一時インデックス・セッションログ・認証ファイルの置き場所など）は、同期のまま残す。

## 理由

- 同期の写し・削除の間は、イベントループが止まり、画面・API・タイマーがすべて止まる。非同期のファイル操作なら、1つずつの操作の合間に
  ほかの要求を処理できる。
- ワーカースレッドや子プロセス（`cp -R`・`rm -rf`）に移す案もあったが、`cp` のフィルター（`.git` を除く）・`verbatimSymlinks` をそのまま
  使え、OS ごとのコマンドの違いを持ち込まない `node:fs/promises` を選んだ。
- 写す量を減らす（`node_modules` を写さない）案は、ゴールガーディアンが最終レビューの中でテストを実行するので、影響が大きく、別に検討する。

## 影響

- 写し・削除にかかる時間は変わらないが、その間もデーモンは画面と API に応答する。
- 写し・削除の途中で中止・一時停止を求めると、求めた操作は写し・削除が終わるまで待つ（実行中の処理の終わりを待つのはこれまでと同じ）。
- デーモンの終了で後片付けを待つのは最大20秒なので、大きな作業領域を消している途中で終わると、作業領域が残りうる（同期で消していたときは、
  消し終わるまで終了も止まっていた）。残った作業領域の片付けは PBI-157 で扱う。
