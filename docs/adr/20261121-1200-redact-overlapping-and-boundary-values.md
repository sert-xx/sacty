# 秘密情報を伏せる処理は、重なる出現を1つの目印にし、持ち越しを伏せる前の文字列で照合する

- 日時: 2026-11-21 12:00 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-438
- 置き換え元: なし
- 置き換え先: なし

## 背景

`redact` は値を長い順に1つずつ置き換えていた。繰り返しのある値や、一方の末尾が他方の先頭になる値が重なって現れると、端の文字が残った。
少しずつ届く出力（`StreamRedactor`・`ByteRedactor`）は、伏せた後の文字列を持ち越していたので、短い値が先に伏せられると、それを含む長い値が、残りが届いても一致しなかった。

## 決定

- `redact` は、入力の上で値の全体の出現を1回の走査（Aho-Corasick）で探し、文字を共有する出現を1つのかたまりにして、かたまりごとに1つの `[REDACTED]` に置き換える。隣り合うだけの出現は、今までどおり別々の目印にする。
- 少しずつ届く出力は、持ち越しを伏せる前の文字列にして、次に届いた分とつなげてから照合する。持ち越す量は、いちばん長い値より1文字短い分のまま。目印を出したかたまりが持ち越しの中まで続くときは、その長さだけを覚え、同じかたまりの目印を2回出さない。
- `StreamRedactor.peek()` は、伏せる前の持ち越しから、すでに目印を出した分を除いて返す。呼ぶ `snapshot` は、いまの値で伏せ直してから使う。

## 理由

- 出現を元の文字列の上の区間で扱えば、重なり・含む・目印の中の文字への誤一致が起きない。
- 時間は、値の数と入力の長さに対して二乗にならない（同じ文字が続く入力でも）。

## 影響

- 重ならない入力の結果は、今までと同じ。
- 値の一部だけが現れる場合・base64 などに変えた出力は、今までどおり伏せない。
- 同じ文字が続く入力と、その文字だけの長い値が多数ある場合は、値の木を作る分と走査で、今の手順より時間がかかる（PR に実測を書いた）。
