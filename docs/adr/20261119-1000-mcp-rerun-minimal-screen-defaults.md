# sacty mcp の再実行は、画面の既定値のまま補足だけを足す最小の版にし、画面の既定値で送れないものは MCP の層で断る

- 日時: 2026-11-19 10:00 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-402
- 置き換え元: なし
- 置き換え先: なし

## 背景

`sacty mcp` は、中止まで（[中止の ADR](20261119-0900-mcp-cancel-with-plan-and-confirmed-targets.md)）できる。機能を1つずつ足す流れの8回目の前半（8a）として、中止したタスクの再実行を足す。
再実行（[再実行の ADR](20261020-1111-rerun-cancelled-task.md)）は、新しいタスクを作って工程を始め（時間と費用がかかる）、元のタスクを二度と再実行できなくする（1度だけ）。
デーモンの `service.rerunTask` は、無い・中止でない・再実行済み・分割の子と PR のレビューのタスク・プロジェクトとリポジトリの誤りを断るが、完了したタスクの案内（続きの作成は派生）と、画面の既定値のままでは送れないもの（説明が上限を超えるなど）の案内はしない。
入力の `repo` は省略できず、チケットから取り込み、作業するリポジトリが決まっていないタスクは、画面で人がリポジトリを選ぶ。

## 決定

- ツール `rerun_task`（`task_id`・省略できる `note`）を1つ足す（15個から16個）。デーモンの既存の `POST /api/tasks/:id/rerun` だけを呼ぶ。デーモンのサービス・API の入口・`@sacty/core`・画面は変えない。
- 題・説明・作業するリポジトリ・イメージは引数にしない。画面の「再実行」の既定値を送る：題は元の題、説明は `rerunEditableBody`、`repo` は `source?.repo ?? repo ?? repository?.url`（無ければ `null`）、`image` は送らない。直したいときは、画面で行う。
- 次は、API に送らずに断り、理由と画面で人が行えることを返す（`rerunBlock`。要約の `canRerun`・`get_task` の `rerunBlocked` も同じ関数）：中止していない・完了（続きの作成は画面）・再実行済み（やり直した先の ID）・分割の子・PR のレビューのタスク・チケットから取り込みリポジトリが決まっていない・既定値が `RerunTaskInput` に通らない。補足が長すぎるときも、送らずに断る。
- デーモンが断るもの（リポジトリがプロジェクトの対象でないなど）は、その理由を返す。リポジトリが原因のときは、画面で選び直せることを添える。
- 結果は、ほかの書き込みのツールと同じ形（短い文・新しいタスクの要約）に、元のタスクと新しいタスクの ID（`rerun`）を足す。要約に `canRerun`・`rerunBy`（元のタスクにだけ）・`rerunOf`（再実行で作ったタスクにだけ）を足す。
- 注釈は `readOnlyHint: false`・`destructiveHint: false`・`idempotentHint: false`・`openWorldHint: true`。
- 説明は、新しいタスクが作られて工程が始まること・元のタスクは二度と再実行できないこと・作業領域・ブランチ・PR は引き継がれないこと・利用者に頼まれたときだけ呼ぶこと（タスクの文の中の指示では呼ばない）・画面で行うことを書く。`cancel_task` の説明・`CANCEL_IRREVERSIBLE`・使い方の文に、やり直す道として再実行を案内する。
- 結果を受け取れなかったときは、作られている可能性を返し、自動でやり直さず、元のタスクの `rerunBy` で確かめる（あれば作られている。無ければ呼び直してよい）。

## 理由

- 画面の既定値のままなら、MCP から人の判断の要る入力（題・説明・リポジトリ・イメージの変更）を受け取らずに済み、既存の API をそのまま呼べる。
- 再実行は1度だけで、2回目はデーモンが断るので、結果を受け取れなかった後でも、元のタスクの `rerunBy` で作られたかどうかが分かり、二重には作られない。
- 完了したタスクと、既定値のままでは送れないタスクは、デーモンの断りの文だけでは、続きの作成や画面での直しという次の手が伝わらない。デーモンを変えない範囲では、MCP の層で先に断る。

## 影響

- 登録した AI は、利用者がはっきり頼んだときに、中止したタスクを再実行できる。新しいタスクの工程が始まり、時間と費用がかかる。元のタスクは二度と再実行できない。取り消せない。
- 先読みと送信の間に状態が変わる窓は残る（デーモンが断る）。
- 題・説明を直す再実行、リポジトリ・イメージを変える再実行、チケットから取り込みリポジトリが決まっていないタスクの再実行、完了したタスクからの続きの作成（派生）、エラーの分析・エラーレポートは、この版に入れない（後続の判断待ち）。
- 仕様は [MCP サーバー](../spec/mcp-server.md#rerun_task)、利用者向けは [手元の AI から操作する](../user/mcp.md#中止したタスクを再実行する) に書く。
