# 再レビューで重みを見直した前回の要修正は、影響：小で稀でも提案として 1 回だけ残し、不適合は見直さない

- 日時: 2026-11-17 21:20 UTC
- ステータス: 採用
- 関係する PR・タスク: #426、PBI-380
- 置き換え元: なし
- 置き換え先: なし

## 背景

[レビューの指摘の重みを、影響の大きさと起きやすさで決める ADR](20261117-0244-superseded-review-finding-weight-by-impact-and-likelihood.md) は、`pr-review` の再レビューについて、「前回 `must` として出した指摘が、表では `should` に当たると分かったときは、未対応でも `must` に数えない」と決めた。

この決定を既定のスキルの文にするときに、表と ADR からは決まらないことが 3 つ残った。

- 前回の `must` を確かめ直して、影響：小で稀（表では「出さない」）と分かったときに、どうするか。
- 重みを見直して `should` に下げた指摘を、直らないまま、何回残すか。スキルは、`should` を「指摘箇所が前回以降の差分に含まれるときだけ採用する」と決めていて、直っていない指摘の箇所は、ふつう差分の外にある。
- 前回の `must` が、受け入れ条件・要求要件の不適合のときに、重みを見直すか。表の升目だけで読むと、影響：小の不適合は `should` に当たる。

## 決定

リポジトリの持ち主が、選択肢から選んで決めた。

- 影響：小で稀と分かった前回の `must` は、提案（`should`）として残す。`must` に数えず、判定は「提案あり」にする。
- 重みを見直して提案に下げた前回の指摘は、見直した回に 1 回だけ残す。その回は、指摘箇所が前回以降の差分の外でも残す。次の回からは、ほかの提案と同じに扱う（指摘箇所が前回以降の差分の外なら出さない）。
- 前回の `must` が受け入れ条件・要求要件の不適合のときは、重みを見直さない（`must` のまま）。

実装で決めたこと（持ち主の確認は、この ADR を書いた時点ではまだ）。

- 残す場所は、前回の指摘の一覧のその指摘の行と、総評の 1 行だけにする。新しい指摘（行へのコメント）にせず、親の記録では、採用（`adopted`）に入れずに `reweighted` に残し、前回の指摘の見直しであることを示す項目（`previous`）を付ける。
- 重みを見直した指摘だけが残る回でも、見られなかった観点があるときは、判定を書かない（完了できないときの決まりが先）。
- 「1 回だけ」の境界：すでに見直した指摘かどうかは、前回のレビューの前回の指摘の一覧の、同じ箇所・同じ問題の行で決め、読めなければ今回の見直しとして扱う。次の回に、今回の表で `must` に当たると分かれば、`must` として採用する。前回と同じ先頭のコミットを判定し直す回は、見直した回の続きとして扱う。
- 範囲と扱いは、スキル `pr-review` の「採用の規則」に置く。集約の資料は、範囲を言い直さずにそこを指す。再レビューの指示文と仕様書は、同じ範囲を同じ語で書く。

## 理由

- 影響：小で稀な指摘を残すのは、前回すでに作者に出した指摘を、黙って消さないため。採らなかった案は、表のとおりに出さないこと。作者から見ると、前回の要修正が、説明なしに無くなる。
- 1 回だけ残すことについて、持ち主が選んだ選択肢の説明として示された理由は、「作者は 1 回見ているので、同じ提案が毎回並ばず、指摘なしに届く」。
- 不適合を見直さないのは、もとの ADR が、不適合を起きやすさを問わず `must` と決めているため。
- 残す場所を前回の指摘の一覧と総評だけにしたのは、スキルが、直っていない前回の指摘を「新しい指摘として繰り返さない」と決めているため。採用に入れると、行へのコメントとして繰り返すと読める。

## 影響

- もとの ADR の決定は、そのまま効く。この ADR は、その決定が言っていなかったことを足す（置き換えない）。
- 重みを見直した指摘が直らないまま次の再レビューになると、その指摘は本文に出なくなる。見直した回の本文には、重みを見直したことと根拠が残る。
- 重みを見直した指摘だけが残る回の判定は「提案あり」、その次の回は、ほかに指摘が無ければ「指摘なし」になる。
