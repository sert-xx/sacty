## 背景

画面の文言は日本語だけだった。PBI-4 の後半（PBI-4b）として、画面を日本語と英語で使えるようにする必要があった。
画面には、sacty の文言のほかに、エージェントの成果物やチケットの本文など、利用者やエージェントが書いた文も出る。

## 決定

- 画面の言語は、ブラウザの言語（`Accept-Language`）の優先順で決める。日本語が英語より優先されていれば日本語、それ以外は英語。指定が無ければ日本語。
- ユーザーメニューで「システムに従う・日本語・English」を選べる。選んだ言語は cookie（`sacty-lang`）に保存し、画面をサーバーで描き直す。`<html lang>` も合わせる。
- 画面の文言は、領域ごとの辞書（`apps/web/src/i18n/messages/`）に置く。英語の辞書の型を日本語から取り、片方の文言が欠けると型の誤りになるようにする。
- 英語の用語は、構想ドキュメントの用語集（Requirements・Design・Test viewpoints・Deliverable review・Request changes・Pause・Cancel・Escalation・
  Goal Guardian・Orchestrator・Ledger・Needs you）に従う。用語集に無い語は、モックアプリの英語に合わせる。
- エージェントの成果物（要求要件・設計・実装の説明・テスト観点・判定理由など）とチケットの本文は、画面の言語に関係なく、書かれた言語のまま表示する。
- デーモンが作る文言（409 の理由・一時停止の説明・取り込みのエラー・既定のプロジェクト名・台帳に記録済みのエラー文）は、この時点では日本語のままにし、別の PBI（PBI-11）で扱う。

## 理由

- デーモンの文言を訳さずに残したのは、訳すにはデーモンが文言をコードと引数で返す形に変える必要があるため（PR の本文）。
- ブラウザの言語に従うこと、cookie に保存すること、成果物を訳さないことの理由は記録に無い（受け入れ条件として書かれている）。

## 影響

- 画面に文言を足すときは、日本語と英語の両方の辞書に足す（欠けると型の誤りになる）。
- cookie を読むため、レイアウトで本文・ヘッダー・サイドメニューを Suspense で包む。
- 英語の画面でも、デーモンが作る文言は日本語のまま出る（PBI-11 まで）。
