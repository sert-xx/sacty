# 工程のイメージは images から選ばせ、既定のイメージは最後の手段にして、使う理由（または理由が無いこと）を作業履歴に残す

- 日時: 2026-10-15 11:18 UTC
- ステータス: 置き換え済み（superseded）
- 関係する PR・タスク: #115、PBI-105
- 置き換え元: なし
- 置き換え先: [PR のレビューだけのタスクでも、images があり、イメージを決めていなければ、レビューの工程のイメージだけをオーケストレーターに選ばせる](20261021-0320-review-only-image-by-orchestrator.md)（PR のレビューだけのタスクで既定のイメージの理由を記録しない部分）

## 背景

オーケストレーターへの指示は、イメージの候補の先頭に既定のイメージ（`default`。Node.js・Claude Code・Codex）を並べ、書かない工程は
既定のイメージにすると書いていた。既定のイメージは、オーケストレーター用の最低限のものとして作っている（テストのブラウザ・DB の
クライアントなどは入っていない）。Node.js のリポジトリ（Next.js）のタスクで、`images` に Playwright の入った Node.js のイメージが
あるのに、実装の工程が既定のイメージで動き、テストが失敗した。指示の書き方のために、Node.js のリポジトリでは既定のイメージが
合うように見え、書かなくても既定のイメージになっていたとみられる。

## 決定

- `images` を設定していて、プロジェクトの対象でイメージを指定していないとき、指示で、PR 作成を除く工程それぞれに `images` から
  選ばせる。既定のイメージは候補に並べず、`images` のどれも合わないときの最後の手段として、中身のとおり（Claude Code・Codex を
  動かす Node.js と git だけ）に説明する。使う工程には、`defaultReasons` に合わない理由を書かせる。
- テストを実行するイメージ（実装、不具合の修正では再現）は、テストのコマンドとリポジトリの依存（ブラウザのテスト・DB のクライアント
  など）から選ぶよう指示で求める。
- 既定のイメージで動く工程は、理由を `StepsChosen` の `defaultImageReasons` に、理由が無い工程（イメージを書かなかった・`default` と
  書いて理由が無い）を `imagesUnexplained` に記録し、作業履歴（タスクの画面）に出す。理由が無くても止めずに、既定のイメージで進める。
- `images` が無いとき・プロジェクトの対象でイメージを指定しているとき・リポジトリの無いまま進めるタスク・PR のレビューだけのタスクは、
  これまでどおり（どちらも記録しない）。

## 理由

- 理由が無い工程を、止めて聞き直す案もあった。イメージの書き漏らしだけでタスクが止まると、再開のたびに工程の選択からやり直しになり、
  人の手間が増える。既定のイメージで動くことは今までと同じで、作業履歴に理由が無いことが出れば、テストが失敗したときに原因を
  たどれるので、止めずに記録する形にした。
- PR 作成を対象にしないのは、sacty がコンテナを使わずに PR を作る工程で、イメージを使わないため。
- 実際のオーケストレーターの判断は毎回同じにはならないので、指示の文と、答えの読み取り・記録の処理をテストで確かめる。

## 影響

- `StepsChosen` に省略できる項目（`defaultImageReasons`・`imagesUnexplained`）が増える。これまでの作業履歴は、そのまま読める。
- 仕様は [タスクと工程](../spec/tasks-and-steps.md) の「オーケストレーター」、利用者向けは [言語ごとのイメージ](../user/images.md) に書く。
