# メモリーの有効な最終利用日は、開いた記録と監査の判断で決め、残す日数を過ぎたら消す

- 日時: 2026-10-18 02:00 UTC
- ステータス: 採用
- 関係する PR・タスク: PBI-127
- 置き換え元: なし
- 置き換え先: なし

## 背景

PBI-126 で、監査がメモリーを登録するようになった（[監査が登録したメモリーを、作業履歴を正本にして、スキルの索引の形で書き出す](20261018-0130-audit-memory.md)）。
そのままでは、古くなったものや役に立たないものが残り続ける。ステークホルダーと決めた方針は次のとおり。

- メモリーごとに「有効な最終利用日」を持つ。開いた日ではなく、タスクで役に立った日にする。
- 有効な最終利用日を更新するのは監査だけ。
- 定期的に動く掃除が、一定期間（sacty の設定）を超えたメモリーを消す。

## 決定

- **開いたかは sacty が数える**：タスクの実行のセッションログに、中身のファイルの場所（`/sacty-memory/<階層>/references/<ID>.md`）が
  出てきたかで数える。Claude Code の読み取りのツールの引数も、Codex のコマンドも、場所がそのまま出るので、エージェントの種類を問わない。
  索引の相対リンクは数えない（索引を読んだだけで開いたことにしない）。
- **役に立ったかは監査が判断する**：大まかな監査は完了したタスクごとに必ず動くので、そこで開いたメモリーを渡して判断させる。開いていない
  メモリーは判断させない（読まなかったものを役に立ったとはしない）。
- **日付は記録から決める**：`AuditSurveyed` に開いたもの・役に立ったものを記録し、有効な最終利用日は、役に立ったタスクの完了日の最新と
  登録の時刻の遅い方として、記録から毎回決める（日付の更新のイベントを持たない。古いタスクの監査が後から終わっても前に戻らない）。
- **掃除**：既定で 90 日、sacty の設定（`memoryRetentionDays`）で 1〜3650 日に変えられる。起動のときと1時間ごとに掃除し、消したことを
  `AuditMemoryDeleted`（`expired`）で記録する。

## 検討した案

- **エージェントに、開いたメモリーを出力させる**：書き忘れ・書き誤りがあり、根拠の件数と同じく、sacty が数えたほうが確か。
- **開いた日を最終利用日にする**：開いただけで関係しなかったものも残り続ける。
- **日付の更新を別のイベントにする**：大まかな監査の結果と別の追記になり、間で止まると食い違う。

## 結果

- 役に立ち続けるメモリーは残り、使われなくなったものは自動で消える。
- 開いたメモリーの ID と、役に立ったかの判断が作業履歴に残る。監査の欄には、役に立ったメモリーが出る（開いた回数は指示に入れるだけで、記録しない）。
