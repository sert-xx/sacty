# PR のリスク評価は、レビューが指摘なしになった回だけにする

## 背景

リスク評価は、人が PR をどの深さでレビューするかの目安で、人が読むのは最終判断のときだけである。
それまでは、sacty が PR を作る・更新するたびに、オーケストレーターの実行（中央値 74 秒）で評価し、PR の説明に載せていた。
直しの途中の評価は読まれずに捨てられ、登録からマージまでの時間の長い部分を占めていた。

## 決定

- sacty が PR を作る・更新するときは、評価しない。評価の実行も、記録（引き継ぎを含む）も、評価の実行が止まらないことを理由にした一時停止も、PR の説明の節もなくす。
- 評価は、PR のレビューの工程の中だけで行う。対象は、sacty が自分の実装の PR のために作ったレビューの子タスクと、GitHub から取り込んだ PR のレビューのタスク。要求要件・設計の PR の子タスクと、既存の PR を引き継いだタスクの子タスクは、今までどおり評価しない（子タスクで評価する PR の範囲は、PR を作る前に評価していた範囲と同じ）。
- 評価を出すのは、sacty がその回の判定を指摘なしと読み取った回だけにする。指示は、判定を指摘なしにするときだけ評価を出すよう求め、指摘のある回に評価のための読み込みをさせない。指摘なしでない回は、答えに評価の JSON があっても、記録せず、投稿する本文から取り除く。
- 評価は、その回に投稿するレビューのコメントと、画面から読める。PR を作ったタスクの詳細（承認の待ちを含む）は、子タスクの評価を、どの先頭の評価かを添えて出す。
- 指摘なしの回に評価を読めなかったときは、今までの取り込んだ PR のレビューと同じく、評価できなかったことと理由を記録し、レビューの投稿・承認の待ちは止めない。追加の実行はしない。
- 版を上げる前の記録（`via` が `publish`・`base`・`inheritedFrom` を持つものを含む）の型と読み込みは残す。PR の説明には、`publish` の記録を載せない。「文書だけ」の判定（`documentsOnlySince`）は、再レビューの絞りのために残す。
- 変えないもの：段階と基準、合図の重さ、依存の版の上げ幅、最後の答えだけを読む決まり、読み込まれた基準の優先、秘密の値を伏せてから切る決まり、評価の新しい使い道を足さないこと。既定のコンテキスト（スキル）は、変えない（評価は依頼した側が求めたときだけ返す、という規定のまま。求める回を絞るのは、デーモンの指示）。

## 理由

- 人が評価を読むのは最終判断のときだけなので、その時点（指摘なしの回）に絞れば、直しのたびの待ちがなくなる。
- 評価をレビューの工程の中に置けば、評価のための別のエージェントの実行が要らず、レビューの答えと一緒に出せる。
- 指摘のある回は、人が最終判断をしないので、評価を出さない。指示も出さないことで、評価のためのコードの読み込みを省く。
- PR の説明に載せないのは、説明は PR を更新するたびに書き換わるが、評価は指摘なしの回にだけ付くため（古い先頭の評価を、今の先頭のものとして見せないため）。
- 比べた案：PR を作る時点の評価を残し、引き継ぎを広げる案は、直しのたびの実行を減らせるだけで、待ちはなくならない。採らなかった。

## 影響

- PR を作る・更新するまでの待ちから、評価の実行（中央値 74 秒）がなくなる。
- 指摘なしに一度もならずに人がマージした PR には、評価が載らない。
- 実装の PR の子タスクの評価は、リスク評価を有効にしたデーモンだけが行う。
- PR の説明に評価は載らない。承認する人は、画面の「PR のリスク評価」の欄か、レビューのコメントで読む。
