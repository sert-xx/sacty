# 実行の費用は、CLI が報告した額を使い、無ければモデルごとの使用量をそのモデルの単価で換算する

- 関係する PR・タスク: PBI-301
- 置き換え元: [エージェントを段階で固定し、sacty が接頭辞を外した名前でサブエージェントの定義を置き、スキルは段階の名前で担当を起動する](20261016-1455-superseded-agent-tiers-for-subagents.md)（「理由」の最後の項目の、段階ごとの担当の費用は親の結果の使用量 × 親の単価でしか出せない、という既知の制約の部分）
- 置き換え先: なし

## 背景

実務での実証実験で、Claude Code の費用の見積もりが、CLI の報告額の約 4.5〜5 倍になった（要求要件 3 回で、台帳が $42.7 のところ報告は $9.1。全実行では、報告 $21.85 に対して台帳は約 $98.9）。予算の上限に早く達して、一時停止の原因になった。
sacty は、実行の使用量（トークン数）を、工程のエージェントの単価 1 つで費用に換算していた。原因は 2 つあった。

1. Claude Code の `modelUsage` には、サブエージェント（Sonnet など）のモデルの使用量も入る。sacty はそれを全部足して、工程のエージェント（Opus）の単価で換算していたので、安いモデルの分が高く見積もられた。段階のサブエージェントを置いたとき（ADR 20261016-1455）に、この制約を既知のものとして残していた。
2. 雛形とユーザードキュメントの単価の例が、実勢と合わなかった。雛形の Opus は入力 $15・出力 $75 としていたが、実行のログで確かめた CLI の報告額から求めた単価は、おおよそ入力 $5・出力 $25 で、Sonnet は入力 $2・出力 $10・キャッシュ読み出し $0.1・キャッシュ書き込み $2.5 だった。

実際のログ（916 件の実行の最後の `result`）で確かめた値：

| | CLI の報告額 | 雛形の単価（Opus で全部）で換算 | 比 |
| --- | --- | --- | --- |
| 全実行 | $791.54 | $3,202.60 | 4.05 倍 |
| 複数のモデルを使った実行（72 件） | $341.99 | $1,649.44 | 4.82 倍 |

Sonnet の使用量は、Sonnet の単価（入力 $2・出力 $10・キャッシュ読み出し $0.1・キャッシュ書き込み $2.5）で換算すると、CLI の報告額と完全に一致した（72 件）。
Opus は、報告額から逆算した入力単価が実行ごとにばらつき（$4.2〜$6.1、中央値 $5.3。出力が入力の 5 倍、キャッシュ読み出しが 0.05 倍、キャッシュ書き込みが 1.25 倍という Sonnet と同じ比で逆算した。ばらつきの原因は未確認）、完全には一致しなかった。
決定 4 の単価の例で、モデルごとに換算し直すと、916 件の合計は $818.71 で、報告額（$791.54）の 1.03 倍になった。

## 決定

1. **報告があれば、それを実行の費用にする**：エージェントの CLI が実行の費用を報告するとき（Claude Code の最後の `result` の `total_cost_usd`）は、それを実行の費用にする。
   - 読めない値と、使用量があるのに 0 の報告は、報告として扱わず、換算する。
   - セッションを再開・複製した実行は、報告に前の実行の分も入るので、使わない（これまでと同じく、各 `result` の使用量を換算する）。
   - 最後の `result` の後に始まった番の使用量など、報告に入っていない分は、工程のエージェントの単価で換算して足す。
2. **報告が無いときは、モデルごとに換算する**：`modelUsage` のモデルごとの使用量を、そのモデルの単価（同じ接続先の `available_models`）で換算して足す。単価が設定に無いモデルと、モデルごとの使用量に入っていない分は、これまでどおり工程のエージェントの単価で換算する。`modelUsage` が無い実行（Codex など）は、これまでどおり。
3. **費用の出どころを作業履歴に残す**：CLI の報告を使った実行と、モデルごとに換算した実行について、`RunCostRecorded`（`reported` か `converted`・実行の費用・設定の単価で換算した額・単価が設定に無かったモデル）を記録する。報告と換算の差を、後から確かめられる。
4. **単価と予算の例を、実態に合わせる**：雛形の Claude の例の単価を、Sonnet は入力 $2・キャッシュ読み出し $0.1・キャッシュ書き込み $2.5・出力 $10、Opus は入力 $5・キャッシュ読み出し $0.25・キャッシュ書き込み $6.25・出力 $25 にする。工程の組み合わせごとの予算の例（`per_plan_usd`）は、`standard` を 30、`split` を 100 にする。既定の上限（`budget.default_per_task_usd`）は変えない。

## 理由

- CLI は、使ったモデルごとの正しい単価で費用を出す。sacty が単価の表を持って追いかけるより、報告を使うほうが、モデルの追加や単価の変更に強い。
- 報告が無い CLI（Codex）と、報告を使えない場合のために、換算は残す。換算も、モデルごとの使用量があれば、モデルごとの単価で行うほうが正確。
- 予算の判定は「概算」のままだが、報告額なら実際の請求の見込みに近い。サブスクリプションの実行も、報告された費用を換算値（`estimated`）として扱う点は変えない。
- 報告と換算の両方を残すのは、換算の単価の設定が実勢と離れたときに気づけるようにするため。
- Opus の単価の例は、実行ごとにばらつくため、完全には一致しない。例の値は目安で、契約の単価に合わせて書き換える前提とする（ユーザードキュメントにも書く）。
- 検討したほかの案：換算の単価を、sacty が内蔵する表で持つ。モデルの追加のたびに更新が要り、契約ごとの単価の違いも扱えないので採らない。

## 影響

- Claude Code の実行の費用は、CLI の報告額になる。同じ実行でも、これまでの台帳の値より小さくなる（予算の上限に達しにくくなる）。過去のタスクの記録は変えない。
- `AgentConfig` が、同じ接続先のモデルごとの単価（`modelPrices`）を持つ。
- 作業履歴に `RunCostRecorded` が増える（報告を使った実行と、モデルごとに換算した実行に 1 件。記録だけで、状態も予算も変えない）。使用量を工程のエージェントの単価で換算しただけの実行は、これまでと同じなので記録しない。
- 契約の単価が CLI の価格表と違う場合（Bedrock など）でも、Claude Code の実行は報告額になる。契約の単価は、報告が無い実行と、実行の中の別のモデルの換算にだけ効く（ユーザードキュメントに書く）。
- 段階のサブエージェントを置いた実行の費用は、これまでと同じく推定（`estimated`）として記録する。
