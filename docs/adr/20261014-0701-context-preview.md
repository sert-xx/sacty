# コンテキストの合成の結果を、実行と同じ組み立てで、Claude Code・Codex ごとに画面・API・CLI からプレビューする

- 日時: 2026-10-14 07:01 UTC
- ステータス: 採用
- 関係する PR・タスク: #85、PBI-76
- 置き換え元: なし
- 置き換え先: なし

## 背景

プロジェクトのコンテキストの合成の結果を確かめる手段は、実行の後の作業履歴に出る層と commit・警告だけだった。mcp.yaml などの誤りも、
次の実行で初めて工程の失敗として見つかっていた。

## 決定

- 合成の結果を、Claude Code・Codex ごとにプレビューできるようにする。保存した設定でも、編集中（保存していない）の設定でも作れる。
  画面（プロジェクトの設定）・API（`GET`・`POST /api/projects/:id/context-preview`）・CLI（`sacty context preview`）から見られる。
- プレビューは、実行と同じ組み立て（`buildContext`：層の取得 → 合成 → MCP の置き換え → 置くファイルの一覧）で作る。プレビュー用の別の作り方はしない。
  ホストの MCP とゲートウェイの起点も、実行と同じ決め方にする。
- 出すもの：置かれるファイルのパスと中身、層（repo・ref・commit）と locked・remove の効果、どの項目がどの層から来たか、警告、使える外部 PF、
  MCP のエージェントから見える形と元の接続先。
- 秘密情報は参照の名前だけを出し、ゲートウェイの実行ごとのトークンは見本にする。プレビューは秘密情報を取り出さず、ゲートウェイに実行を登録しない。
  literal の値や層の設定の中身は書かれたまま出ることを、画面と CLI で注記する。
- ファイルの中身は、ファイルごとに256KB・合計8MBまで。UTF-8 でないファイルは中身を出さない。
- プレビューのための取得は一時ディレクトリに行い、成功・失敗にかかわらず消す。タスク・作業履歴・保存した設定は変えない。
- プロジェクトを保存するときも同じ検査をし、誤りがあっても保存は止めずに知らせる。作成・インポートの後に移る設定の画面でも確かめ直して知らせる。
- 層の MCP サーバーがホストの MCP サーバーと同じ名前なら、警告（`context.hostMcpOverride`）を残す（実行の作業履歴にも）。
- スキルはファイルごとに写す（空のディレクトリは写らない）。

## 理由

- 実行と同じ組み立てにしたのは、プレビューと実際に置くファイルを一致させるため（PR の本文。テストで一致を確かめる）。
- 保存を止めずに知らせるのは、既存の流儀（外部 PF の一覧もコンテキストを読めなければ理由を出すだけ）に合わせ、取得の失敗はネットワークや gh のログインのように
  一時的なこともあり、止めるとほかの設定も直せなくなるため（PR の本文）。
- インポートのときに確かめなかったのは、インポートの後は設定の画面に移り、そこでプレビューできるため（PR の本文）。後にレビューの指摘で、作成・インポートの後の
  設定の画面で確かめ直すようにした（同じ PR）。
- スキルをファイルごとに写すのは、プレビューで中身を出すため。空のディレクトリが写らなくても、エージェントが読むのはファイルだけ（PR の本文）。
- 編集中の設定で GitHub アカウントと対象も編集中のものを使うのは、コンテキストリポジトリの認証が変わるため（PR の本文）。
- 同じ名前の MCP の警告を足したのは、MCP の分はこれまで警告なしで置き換えていたため（PR の本文）。
- 中身の上限の値（256KB・8MB）を選んだ理由は記録に無い。

## 影響

- 実行の組み立てを変えると、プレビューにも同じ変更が出る（テストで一致を確かめる）。
- プレビューの出力には、層に literal で書いた値が出うる。
