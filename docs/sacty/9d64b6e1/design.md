# 設計：同じ原因の要修正が続いたときに、範囲を絞る案を添えて人の判断を早める（PBI-492）

## スコープ

同じ原因の `must` が2回目以降なら、レビューは範囲を絞る案を本文に添える。
3回目以降の PR のレビューは、その `must` に `needs_decision` の印を付けて、今ある「直しでは解消できない指摘での一時停止」（PBI-452）で止める。

- 対象
  - 既定のスキル review-dispatch の `aggregation.md`・`pr-review.md`・`self-review.md`
  - `apps/daemon/src/prompts.ts` の再レビュー・セルフレビュー・`needsDecisionLines` の指示
  - 仕様書（日英）・利用者向け文書（日英）・ADR・作業履歴・テスト
- 対象外
  - 止め方・画面・通知・記録の欄の新設（今の `needs_decision` の一時停止をそのまま使う）
  - セルフレビューでの一時停止（本文に書くだけ）
  - 要修正の重さの決め方と、同じ原因の判定の仕方（依頼の範囲の外）

## 確認したいこと

- must
  - Q-1：3回目以降は、今の `needs_decision` の一時停止で止めるか（推奨：止める）。
    理由：人が手で止めていた所を代わりに止められ、画面・PR のコメント・再開の仕組みを足さずに済む。
    懸念：止めずに知らせるだけがよかった場合、承認の代理の人が、3回目のたびに PR のコメントか再開で答えるまでタスクが進まない。
- should
  - Q-2：セルフレビュー（PR の無い工程の中）の3回目以降は、止めずに報告の総評へ「人の判断が要る」と範囲を絞る案を書くだけでよいか（推奨：よい）。
    理由：止める仕組みは PR のレビューの子タスクにしか無く、そのあとの PR のレビューで止まる。
    懸念：セルフレビューの中だけで同じ原因が続いたとき、画面には出ず、PR ができるまで人は気づけない。
  - Q-3：人が一時停止で判断した原因に、後の回で同じ原因が続いたとき、再び印を付けないでよいか（推奨：付けない。今の「人の判断がある指摘には付けない」を同じ原因にも当てる）。
    懸念：人が「直しを続ける」と答えた原因は、その後は何回続いても止まらず、今と同じ往復に戻る。
- 確認しないと決めたこと
  - ADR：PBI-424 の ADR の「自動で止めない・通知しない」を変えるので、`docs/adr/README.md` の一部の置き換えの手順で、新しい ADR を足し、PBI-424 の ADR を `superseded` にする（手順が決まっている）。
  - 範囲を絞る案を人が選んだ後の扱い：今の `deferredByPerson`（後続に回した指摘を出さない）と `decidedPauseLines`（人が受け入れた止めた指摘を要修正に残さない）で足りるので、仕組みを足さない（受け入れ条件に無い）。
  - `user-doc`：方針を見る観点が無く、PBI-424 の規則を当てていないので、範囲を絞る案も当てない（PBI-424 と同じ範囲にそろえる）。

## 既定で決めたこと

- 3回目の数え方は PBI-424・PBI-465 のまま（`delivered` が `false` の回は数えない）。回数が「少なくとも N 回目」で3に届かないときは印を付けない。
- 3回目の印は、`pr-review.md` と `needsDecisionLines` の「直す量が多い・直し方が決まっていないだけなら付けない」の例外として足す。PBI-452 の ADR の決定（印の付いた回で止める）は変えないので、置き換えない。
- 画面の見出し（「直しでは解消できない指摘があるため一時停止」）と文言 `review.needsDecision` は変えない。理由は印の根拠の文（何回目か・範囲を絞る案）で出す。

## 処理の流れ

1. 再レビューで、同じ原因の `must` が2回目：本文に直し方の案（PBI-424）と、範囲を絞る案と照らした結果を書く。判定は変えない。
2. 3回目以降（PR のレビュー）：同じく書き、その `must` に `needs_decision` を付ける。親は直しに入らず、今の仕組みで止まり、PR にコメントし、画面に指摘と根拠を出す。
3. 3回目以降（セルフレビュー）：報告の総評と記録に、人の判断が要ることと範囲を絞る案を書く。止めない。

## テスト観点

- [TV-1] PR の再レビューの指示に、2回目以降の範囲を絞る案の求めが入る
  - 入力：前回のレビューがある PR のレビューの子タスクの指示と、前回のレビューが無い初回の指示を、prompts.test.ts で組み立てる
  - 期待結果：再レビューの指示には、範囲を絞る案（受け入れる・範囲の外にする・後続に回す、と残る影響）を1つ以上、総評かその指摘の本文に書くことと、承認済みの要求要件・受け入れ条件と照らして満たせなくなる条件を書くことが入り、初回の指示には入らない
- [TV-2] PR のレビューの印の条件に、同じ原因の3回目以降が入る
  - 入力：PR のレビューの子タスクの指示（needsDecisionLines を含むもの）を prompts.test.ts で組み立てる
  - 期待結果：同じ原因の must が3回目以降（delivered が false の回を数えず、「少なくとも N 回目」で3に届かないときを除く）なら needs_decision を付け、根拠の文に何回目かと範囲を絞る案を書くことが入る
- [TV-3] セルフレビューの指示に、範囲を絞る案と3回目以降の人の判断の求めが入る
  - 入力：2回目以降のセルフレビューの指示を prompts.test.ts で組み立てる
  - 期待結果：2回目以降は範囲を絞る案と照らした結果を報告の summary と記録に書くこと、3回目以降は人の判断が要ることを summary に書くことが入り、「回数で止める・止めない決まりは足さない」は入らない
- [TV-4] 既定のスキルに、範囲を絞る案と3回目以降の規則が書かれている
  - 入力：default-skills.test.ts で aggregation.md・pr-review.md・self-review.md を読む
  - 期待結果：aggregation.md に2回目以降の範囲を絞る案・受け入れ条件との照合・3回目以降の人の判断の求めが、pr-review.md の印の条件に同じ原因の3回目以降が、self-review.md の記録の項目に範囲を絞る案が書かれ、aggregation.md に「自動で止めたり、通知したり」の文が無い
- [TV-5] 修正を戻すとテストが落ちる
  - 入力：prompts.ts と aggregation.md・pr-review.md の今回の変更を起点のコミットに戻し、prompts.test.ts と default-skills.test.ts を流す
  - 期待結果：上の4つの観点のテストが失敗する
- [TV-6] 既定のスキルに足した文に、sacty に寄せた例が無い
  - 入力：既定のスキルの差分を読む
  - 期待結果：足した例と文が、言語・分野に依らない語（入力の形・範囲・後続など）で書かれ、sacty の工程・画面・PR のレビューの子タスクなどの語を例に使っていない
- [TV-7] 仕様書・利用者向け文書・ADR が日英でそろい、規則と合う
  - 入力：docs/spec/context・approval、docs/user/tasks の日英と docs/adr の差分を読み、npx vitest run tests/docs を流す
  - 期待結果：日英の両方に、2回目以降の範囲を絞る案と3回目以降の印による一時停止が同じ中身で書かれ、「回数による自動の一時停止…は無い」の文が無く、新しい ADR と superseded にした PBI-424 の ADR の置き換えの関係とリンクが tests/docs を通る
