# 設計：狭い幅のタスクの一覧・詳細（PBI-476）

## スコープ

幅 640px 未満では、タスクの一覧をカードの形にし、絞り込みを検索と状態だけにする。
タスクの詳細では、固定の見出しを題（1 行）とタブだけにし、1024px 未満では PR と費用を概要の内容より前に出す。

- 対象
  - `apps/web/src/components/task-list.tsx`（一覧・絞り込み）
  - `apps/web/src/components/task-detail.tsx`・`task-title.tsx`・`apps/web/src/lib/use-sticky-offset.ts`（詳細）
  - `apps/web/src/i18n/messages/tasks.ts`・`task.ts`（足す文言の日英）
  - 375px の画面のテスト（一覧は `task-list.browser.test.ts` に足し、詳細は `task-detail.browser.test.ts` を新しく作る）
  - 文書：`docs/user/tasks.md`・`tasks.en.md`、`docs/spec/architecture.md`・`architecture.en.md`、作業履歴 `docs/worklog/20261122-pbi-476-narrow-task-list-detail.md`
  - 375px で横にずれる原因が、一覧・詳細の中身（成果物・コードブロックなど）にあれば、その要素
- 対象外
  - 640px 以上の見え方（変えないことを、テストと画像の比較で確かめる）
  - 狭い幅の新しいスクリーンショット（今の画像は 1280px で撮るので変わらない。確認したいことの 3）
  - ダッシュボード・プロジェクトの一覧（作業の前に、375px で横にずれていないことだけを確かめる）

## 確認したいこと

- must：なし
- should
  1. 狭い幅で、題をどこに出すか。推奨：流れる側の先頭に、今の `h1`（折り返す。「題を変える」と編集の欄つき）・状態・工程・操作を置く。固定の帯には、1 行に省略した題（読み上げない写し）とタブを置く。
     理由：長い題を全文で読めて、編集の欄を開いても固定の帯は 160px を超えない。
     懸念：ページの先頭では、題が全文と省略の 2 回見える。利用者がこれを嫌うと、写しを「`h1` が画面から出たときだけ出す」作りに直すことになる。
  2. PR と費用を、概要のタブの中に出すか、タブの上に出してどのタブでも見せるか。推奨：概要のタブの中で、内容（`TaskContent`）の直前に出す。
     理由：条件 5 は「概要の本文より前」と求めていて、ほかのタブの先頭は変えずに済む。
     懸念：作業履歴や工程の設定のタブを開いている利用者は、PR へのリンクを見るのに概要へ戻る手間がかかる。
  3. 狭い幅のスクリーンショット（一覧のカード・詳細）を足すか。推奨：足さず、文章だけを直す。
     理由：条件 7 は「変わった所だけ」と求めていて、1280px の画像は変わらない。足すなら `capture.mjs` に幅の切り替えを足すことになる。
     懸念：スマートフォンで使う利用者は、カードと固定の帯の見え方をユーザーガイドの画像で確かめられない。
- 確認しないと決めたこと
  - 「題を変える」と編集の欄は、流れる側の `h1` の横に置く。固定の帯に残すと、編集中に帯が 160px を超えるため。should の 1 と一緒に決まるので、別には確かめない。

## 既定で決めたこと

- 一覧は、表とカードを別々に描かない。1 つの表の要素を、640px 未満では CSS（`max-sm:` の grid・block）でカードに見せる。`data-testid` と、`tbody.rows` を使う「さらに表示」のフォーカス移動をそのまま保つため。
- 閉じた「絞り込み」のボタンに、隠れた項目（開始時期・開始地点・リポジトリ）で使っている条件の数を出す（例：「絞り込み（2）」）。開閉の状態は URL に残さない。
- 1024px 未満では、プロパティの PR と費用の行を隠し、概要に出す方だけを見せる（同じものを 2 か所に出さない）。

## 構成

| 所 | 640px 未満の振る舞い | 640px 以上 |
| --- | --- | --- |
| 一覧の行 | 1 件 1 枚。1 行目に題（2 行まで省略）、その右に状態と CI 失敗の印。2 行目に開始地点・テンプレート・`#番号`・リポジトリを `text-xs` で出し、その下に工程。表の見出しは隠す。子タスクは `↳` と浅い字下げを保つ | 今の表 |
| 絞り込み | 検索・状態・「絞り込み」のボタン（`aria-expanded`）・件数・「条件をクリア」。開くと開始時期（から・まで）・開始地点・リポジトリが出る | 今の 6 項目。ボタンは出さない |
| 詳細の見出し | 外側の固定の箱を `display: contents` にする。題・状態・工程・操作の箱は流れる。`sticky top-16` にするのは、省略の題（`truncate`・`aria-hidden`）とタブの帯だけ。帯は 96px 以下 | 今の固定の箱。省略の題は出さない |
| `useStickyOffset` | 固定になっている方の箱（帯）の高さを測って、`--sticky-offset` に入れる | 今のとおり外側の箱を測る |
| 概要（1024px 未満） | 内容の直前に、PR（`#番号` のリンク。PR があるときだけ）と費用（額・上限・棒・`unknownRuns`）の箱を出す。新しい `data-testid` を付ける | 出さない（`lg:hidden`） |

- 足す文言は、「絞り込み」のボタン（数つき）の日英だけ。省略の題には、今の題をそのまま使う。

## 影響範囲

- `task-detail-layout.test.ts`・`task-detail-tabs.test.ts`：固定の箱の中身の並びを文字列で調べている所を、新しい作りに合わせて直す。
- `task-list.browser.test.ts`：CSS を作る部品のファイルの一覧に、足したファイルを入れる。今ある 375px の「さらに表示」と件数のテストは保つ。
- 文書
  - `docs/user/tasks(.en).md`：640px 未満での違いを足す。対象は「タスクの一覧」の「状態」の列、「タスクを探す・絞り込む」の件数の位置、「タスクの詳細の見方」の固定と右の列の記述。
  - `docs/spec/architecture(.en).md`：「タスクの詳細の並び」と絞り込みの節に、同じことを足す。

## テスト観点

- [TV-1] 一覧のページが 375px で横にずれない
  - 入力：幅 375px の画面のテストで、子タスク・複数のリポジトリ・長い題・CI 失敗を含む 120 件の一覧を描く
  - 期待結果：document.documentElement.scrollWidth が clientWidth（375）と同じになる
- [TV-2] 詳細のページが 375px で横にずれない
  - 入力：幅 375px で、長い題・PR・成果物（長いコードブロックを含む）・操作のボタンがあるタスクの詳細を描き、概要・作業履歴・費用・工程の設定の各タブを開く
  - 期待結果：どのタブでも document.documentElement.scrollWidth が clientWidth（375）と同じになる
- [TV-3] 640px 未満の一覧の 1 件が 1 枚のカードになる
  - 入力：幅 375px と 639px で、3 行以上に折り返す長さの題と開始地点・リポジトリを持つタスクの一覧を描く
  - 期待結果：表の見出しの行は見えず、task-row-<ID> の要素が縦に 1 件ずつ並び、題のリンクの高さは 2 行分以下で、状態のラベルと工程の並びがカードの幅の中に見える
- [TV-4] カードの 2 行目に開始地点とリポジトリが小さく出る
  - 入力：幅 375px で、開始地点・テンプレート・取り込み元の番号・作業するリポジトリ（task-repo-<ID>）を持つタスクのカードを描く
  - 期待結果：開始地点と task-repo-<ID> の要素の上端が題のリンクの下端より下にあり、文字の大きさが 12px になる
- [TV-5] 640px 未満の絞り込みは検索と状態だけが見え、開くと残りが出る
  - 入力：幅 375px で一覧を開き、「絞り込み」のボタンを押す
  - 期待結果：押す前は検索と状態の欄だけが見えて開始時期・開始地点・リポジトリの欄は見えず、押した後はそれらが見えてボタンの aria-expanded が true になる
- [TV-6] 閉じた絞り込みのボタンが、隠れた条件の数を出し、URL の条件で絞り込む
  - 入力：幅 375px で、URL のクエリに start と repo を付けて一覧を開く
  - 期待結果：「絞り込み」のボタンに数 2 が出て、一覧はその条件に合う行だけになり、閉じたまま検索を変えても URL の start と repo が残る
- [TV-7] 640px 未満の詳細で、スクロールしても残るのは省略の題とタブだけ
  - 入力：幅 375px・高さ 800px で、2 行以上になる長さの題を持つタスクの詳細を開き、1500px スクロールする
  - 期待結果：画面の上端から見える要素は、ヘッダー・1 行で省略した題（scrollWidth が clientWidth より大きい）・タブだけで、ヘッダーの高さと固定の帯の高さの和が 160px 以下になる
- [TV-8] 640px 未満の詳細で、状態・工程・操作がページの先頭にあり、スクロールで流れる
  - 入力：幅 375px で、一時停止・中止ができる作業中のタスクの詳細を開き、先頭と 1500px スクロールした後の位置を調べる
  - 期待結果：先頭では状態のラベル・工程の並び・一時停止と中止のボタン・題の h1 と「題を変える」が見え、スクロールした後はどれも画面の上端より上に出て、ページの h1 は 1 つだけになる
- [TV-9] 640px 未満で、移動先が固定の帯の高さの分を空けて止まる
  - 入力：幅 375px で、エラーの記録があるタスクの詳細を #error-report 付きで開く
  - 期待結果：--sticky-offset が 64 + 固定の帯の高さ + 16 の px になり、エラーレポートの見出しの上端が固定の帯の下端より下にある
- [TV-10] 1024px 未満の詳細で、PR と費用が概要の内容より前に出る
  - 入力：幅 375px と 1023px で、PR があり unknownRuns が 1 のタスクの詳細の概要のタブを開く
  - 期待結果：PR の #番号 のリンクと費用（使った額 / 上限・棒・未計上の注記）の箱が内容（TaskContent）より上に見え、プロパティの PR と費用の行は見えない
- [TV-11] 1024px 以上の詳細では、PR と費用はプロパティにだけ出る
  - 入力：幅 1024px で、PR があるタスクの詳細を開く
  - 期待結果：概要の PR と費用の箱は見えず、右の列のプロパティに PR と費用の行が見える
- [TV-12] 640px 以上の一覧と詳細の見え方が変わらない
  - 入力：幅 640px と 1280px で一覧と詳細を描く画面のテストと、変更の前後で npm run docs:screenshots で撮った task-list・task-detail の画像（日英）
  - 期待結果：一覧は表の見出しと 6 項目の絞り込みが見えて「絞り込み」のボタンは見えず、詳細の固定の箱に題・状態・工程・操作・タブが入り、前後の画像の画素が一致する
- [TV-13] ユーザーガイドに 640px 未満の一覧と詳細の違いが書かれている
  - 入力：docs/user/tasks.md と tasks.en.md の「タスクの一覧」「タスクを探す・絞り込む」「タスクの詳細の見方」の節の差分
  - 期待結果：日英の同じ内容で、640px 未満では一覧が 1 件 1 枚のカードになること、絞り込みは検索と状態だけで残りは「絞り込み」を開いて使うこと、固定されるのは題とタブだけで状態・工程・操作は流れること、1024px 未満では PR と費用が概要の先頭に出ることが書かれ、画像は変わっていない
- [TV-14] 仕様書と作業履歴に、狭い幅の並びが書かれている
  - 入力：docs/spec/architecture.md と architecture.en.md の「タスクの詳細の並び」と絞り込みの節、docs/worklog の PBI-476 の作業履歴の差分
  - 期待結果：仕様書の日英に、640px 未満の固定の帯（題とタブ）・一覧のカード・絞り込みの折りたたみと、1024px 未満の PR と費用の位置が書かれ、作業履歴に変えたことと確かめたことが書かれている
- [TV-15] フォーマッター・リンター・型・テストが通る
  - 入力：変更後のリポジトリで npm run lint・npm run typecheck・npx vitest run --no-file-parallelism を実行する
  - 期待結果：どのコマンドも終了コード 0 で終わる
