# 設計：文書だけを直した後の再レビューとリスク評価を軽くする（PBI-421）

## スコープ

前回のレビュー・評価から先頭までの差分が文書だけのとき、PR の再レビューは観点と検証を絞り、PR を更新する前のリスク評価は前回の評価を引き継ぐ。
「文書だけ」は、デーモンの同じ判定で A と B が見分ける。

- 対象
  - デーモンの判定（文書だけか）と、再レビューの指示の分かれ
  - 既定のスキル `review-dispatch` に、絞る規則（規則 10）を足す
  - `assessRisk` での引き継ぎと、`PullRequestRiskAssessed` に足す項目、投影、作業履歴の1行
  - docs/spec（日英）、ADR、worklog
- 対象外
  - 主対象が文書の PR（要求要件・設計の PR など）の再レビュー：いまの規則（`scope: docs`・規則 9）のまま
  - 文書だけでない差分（テストだけの直しなど）の絞り、レビューの投稿の直接の受け渡し、「提案だけ」で人を待つこと（依頼の範囲の外）

## 確認したいこと

- must
  - 拡張子では文書でも、エージェントへの指示（`AGENTS.md`・`CLAUDE.md`・`SKILL.md` とスキルのディレクトリの下、`.` で始まるディレクトリの下）は「文書」に数えない（絞らない・評価し直す）でよいか。
    - 推奨：数えない。振る舞いを変えるファイルで、軽く見ると B-4 の「段階が低いまま残る」に当たるため。
    - 懸念：この見分けは名前とスキルのディレクトリで決めるので、sacty の `apps/daemon/default-context/rules.md` のような指示は文書に数え、直しても再レビューが絞られ、評価も引き継ぐ。
  - 絞りを、主対象が `code` の PR（PR 全体の差分に文書でないものがある）の再レビューに限ってよいか。
    - 推奨：限る。主対象が文書の PR は、すでに `scope: docs` でテストを実行せず、規則 9 を変えない（A-6）ため。
    - 懸念：要求要件・設計の PR の再レビューは、いままでどおり必須の D 観点を全部起動するので、その費用は減らない。
- should：なし
- 確認しないと決めたこと
  - 引き継ぎの記録は、新しいイベントにせず `PullRequestRiskAssessed` に項目を足す。投影の「最後の評価だけを持つ」と PR の説明の読み方を、そのまま使えるため。

## 既定で決めたこと

- 差分が空（木が同じで、コミットだけ違う）は「文書だけ」にしない（`isDocumentsOnly` の「空は false」に合わせる）。
- `base` を持たない過去の評価（この変更の前の記録）は、引き継がずに 1 回評価し直す。
- 前回のレビューの後に PR がベースを取り込んだときは、取り込んだ変更も差分に入るので、ふつうは絞らない。

## 構成

| 場所 | 変更 |
| --- | --- |
| `apps/daemon/src/test-files.ts` | `isChangeDocumentsOnly(paths)`：`isDocumentsOnly` が true で、エージェントへの指示のパスを含まないとき true |
| `apps/daemon/src/repository.ts` | `isAncestor` を `RepositoryWorkspace` の公開のメソッドにする（テストの偽物にも足す） |
| `apps/daemon/src/service.ts` | `documentsOnlySince(gitDir, from, to)`：祖先であること＋`changedPaths`＋上の判定。どこかで失敗すれば false。A と B で使う |
| `apps/daemon/src/prompts.ts` | `rereviewDocsOnlyLines`（明示の指示）。当たる回だけ、`REVIEW_DISPATCH_LINES` の「文書だけでも省かない」と、再レビュー・検証の「実行し直す」の行を差し替える |
| `review-dispatch` の SKILL.md・references | SKILL.md に規則 10 と起動表の例。規則 1・5、viewpoints.md の冒頭、pr-review.md の「再レビュー」「レビューの範囲」、verification-run.md の 0 と「再レビュー」に例外を足す |
| `packages/core` の events・projection | payload と `task.riskAssessment` に `base?`・`inheritedFrom?` を足す |
| `apps/web` の labels・i18n | 引き継いだ評価の作業履歴の1行（`abc1234` の評価を `def5678` に引き継いだ） |

## 処理の流れ

- A（再レビューの準備。`service.ts` 11026 行付近）：次を全部満たすときだけ、`rereviewDocsOnlyLines` を足す
  - `previousReview` があり、先頭が前回と違う
  - 前回の先頭を取得でき、今回の先頭の祖先で、`documentsOnlySince` が true
  - PR 全体の差分は文書だけでない（must の 2 つ目）
  - 前回の行へのコメントに、`[要修正]` で文書でないパスのものが無い
- A（規則 10。明示されたときに限る）
  - 親は、変わったファイルを「主対象の種類」の考え方で見直す。文書でない・迷う・本文の `must` が文書でないものに及ぶなら、絞らずに規則 1〜7 で決める
  - 起動するのは、前回の指摘に関わる観点、変えた文書の種類の正確さの観点（`user-doc` は U-1、`design-doc` は D-2）、X-1（直しと PR のほかの箇所の食い違いを依頼文に書く）。条件付き観点は変えた文書で判定し、X-2・X-3・R はいまの規則で決める
  - ほかの必須観点は、起動表に「起動しない」と理由（前回以降の差分が文書だけ）を残す
  - 検証は `scope: docs`。コードのテストは `summary.json` に `skipped` で、`note` に同じ理由を書く
  - 本文の「レビューの範囲」に、前回の先頭からの差分が文書だけなので絞ったことと、起動しなかった観点を1行で書く
  - 判定・重み・「前回の指摘」の節は変えない
- B（`assessRisk`）
  1. 同じコミットを評価済みなら、いまのとおり何もしない
  2. 前回が `via: publish` で評価があり、`base` が今回と同じで、`documentsOnlySince(前回の commit, 今回)` が true なら、エージェントを実行せず、`PullRequestRiskAssessed` に `{via: publish, commit, base, assessment: 前回の写し, inheritedFrom: 前回の commit, costUsd: 0}` を `sacty` として足す
  3. それ以外は評価し直し、`base` も記録する
  - 引き継いだ記録の `commit` から次を比べるので、何回か引き継いだ後でも、文書でない変更が入れば評価し直す（B-4）

## 影響範囲

- 仕様書（日英）：tasks-and-steps.md「PR のレビューだけのタスク」、context.md「既定のレビュー用スキル」の「`pr-review` の再レビューの規則は変えない」、risk-assessment.md「PR を作る前の評価」「記録と画面」、event-log.md の `PullRequestRiskAssessed` の行
- ADR を 1 件足す（PR の再レビューを、条件を限って絞る。20261117-0359 の「PR のレビューは対象外」を、この条件で変える）。worklog を足す

- [TV-1] 文書だけの判定が文書の拡張子のファイルだけで true になる

  - 期待結果：true を返す
- [TV-2] 文書でないファイル・判定できないファイル・空の差分は文書だけにしない
  - 入力：isChangeDocumentsOnly に ["docs/a.md", "src/x.ts"]、["notes.txt"]、[] をそれぞれ渡す
  - 期待結果：どれも false を返す
- [TV-3] エージェントへの指示のファイルは文書だけにしない

  - 期待結果：どれも false を返す
- [TV-4] 主対象が code の PR で前回以降が文書だけの再レビューに、絞る指示が入る

  - 期待結果：どちらも絞る指示の節が入らず、実装の前の文書の PR の範囲の節（規則 9）の有無もいまと同じになる
