# PBI-479 設計：行へのコメントにした指摘を、レビューの本文に重ねて書かない

## スコープ

デーモンが投稿する PR のレビューでは、行へのコメントにした指摘を本文に書かせないようにします。
本文の判定の行の下には、行へのコメントの件数を sacty が数えて1行で足します。

- 対象
  - レビューの工程の指示（`apps/daemon/src/prompts.ts` のレビューの指示・`rereviewLines`・`AI_REMARK_EXPLANATION_LINE`）
  - 投稿する本文の組み立て（`buildReviewBody`）
  - 既定のスキル（`review-dispatch/references/pr-review.md`・`aggregation.md`）
  - テスト、仕様書（`docs/spec/tasks-and-steps` 日英）、ユーザー文書（`docs/user/intake` 日英）、ADR・作業履歴
- 対象外
  - 指摘の読み取り（`suggestion-triage.ts`・`github.ts`・`review-comments.ts`）のコードの変更。いまの処理のまま、本文が減った形で動くことをテストで確かめる
  - 自己レビュー（`self-review.md` と自己レビューの指示）
  - 行へのコメントの書き方、総評・レビューの範囲・検証の節の長さ

## 確認したいこと

- must：なし
- should
  - Q-1 件数の行は、sacty が数えて、判定の行のすぐ下に「行へのコメントに N 件の指摘があります。」と足す形でよいか（推奨：はい）。
    理由：エージェントは投稿の時点で、どれが差分の外として本文に回るか・422 で全部が本文に入るかを知らないので、数がずれる。
    懸念：エージェントに書かせる形が望みだった場合、本文の組み立ての変更とテストが無駄になり、指示の変更に作り直す手間が増えます。
- 確認しないと決めたこと
  - 件数の行の置き場所：Q-1 の推奨のとおり、sacty が書く判定の行の下に置く。sacty が足す行なので、総評（エージェントが書く）には置けないため。
  - `changes_required` の回に本文が総評だけになり、選り分けで本文の全体が「必ず直す」1 件として渡ること：変えない。いまも総評だけの本文はあり、行へのコメントの指摘は別の 1 件として直しに渡る。直しの側の説明に、件数の行は別の指摘ではないと1文足して、要らない直しを防ぐ。

## 既定で決めたこと

- 件数の行は、行へのコメントとして投稿する件数だけを数える。0 件のときと、422 で本文に入れて投稿し直すとき（`foldComments`）は書かない。
- 件数の行に、`[要修正]`・`[提案]` の頭と `<パス>:<行>：` の形を使わない（選り分けが 1 件の指摘として読まないため）。重さの内訳も書かない。
- エージェントには、総評に件数を書かせない（sacty の行と二重になるため）。
- `aggregation.md` の「他の現れを本文に列挙」は、代表の指摘の本文（行へのコメントならそのコメント）に列挙すると書き直す。

## 構成

| 場所 | 変更 |
| --- | --- |
| レビューの指示（`prompts.ts` 3909 行付近） | 行へのコメントにした指摘は、本文のどの節にも同じ内容（言い換えを含む）を書かない、と足す。差分の外の行へのコメントは sacty が本文に回すので、本文の「指摘」の節にも書かない、と足す。位置を付けられない指摘を本文の「指摘」の節に書く行は残す |
| `rereviewLines` | 「前回の指摘」の節では、前回の行へのコメントの指摘も、場所と状況だけを短く挙げる（中身を繰り返さない）、と足す |
| `AI_REMARK_EXPLANATION_LINE` | 本文の件数の行は、行へのコメントの指摘を数えたもので、別の指摘ではない、と足す |
| `buildReviewBody` | 判定の行の下に件数の行を足す（`foldComments` でなく、`task.reviewComments` が 1 件以上のとき） |
| `pr-review.md` | 「結果の返し方と投稿」に、依頼した側が投稿するときも、行へのコメントにした指摘は本文に重ねない、と書く（自前の投稿の決まりと同じにする） |

## 影響範囲

- 判定の補い方（`extractReviewComments`）・取り込み・選り分け・重なりの照合は、コードを変えない。
- 仕様書の `tasks-and-steps`（日英）の「PR のレビューだけのタスク」の、指示と「投稿する本文」の行に、重ねないことと件数の行を書く。
- ユーザー文書の `intake`（日英）の「投稿されるレビュー」に、件数の行と、行へのコメントにした指摘は本文に出ないことを書く。
- ADR（日本語）と作業履歴（日本語）を足す。

## テスト観点

- [TV-1] レビューの指示が、行へのコメントにした指摘を本文に重ねて書かせない
  - 入力：PR のレビューの工程の指示を buildPrompt で作る
  - 期待結果：指示に、行へのコメントにした指摘は本文のどの節にも同じ内容（言い換えを含む。起きる条件・実害・直し方）を書かないことと、総評に件数を書かないことが含まれる。
- [TV-2] レビューの指示が、行へのコメントにできない指摘を本文の「指摘」の節に書かせ、差分の外の行へのコメントを本文に重ねさせない
  - 入力：PR のレビューの工程の指示を buildPrompt で作る
  - 期待結果：指示に、差分の中に付けられる行が無い指摘は頭を付けて本文の「指摘」の節に書くことと、差分の外の行へのコメントは sacty が本文に回すので本文の「指摘」の節に書かないことが含まれる。
- [TV-3] 差分の外の行へのコメントが、本文に1回だけ出る
  - 入力：本文の「指摘」の節にその指摘が無く、差分の外の行への must の行へのコメントが1件ある答えを extractReviewComments に渡す
  - 期待結果：返る output で、そのコメントの文が「### 行についての指摘」の節に1回だけ現れ、comments は空になる。
- [TV-4] 本文に指摘が無くても、行へのコメントの重さが判定に効く
  - 入力：本文が総評だけで、判定が suggestions、行へのコメントに must が1件ある答え（と、判定が no_findings で should が1件ある答え）を extractReviewComments に渡す
  - 期待結果：判定は前者が changes_required、後者が suggestions になる。
- [TV-5] 行へのコメントがあるとき、判定の行の下に件数の行が付く
  - 入力：reviewComments が2件のタスクを、foldComments なしで buildReviewBody に渡す
  - 期待結果：判定の行のすぐ下に「行へのコメントに 2 件の指摘があります。」の行があり、その行に [要修正]・[提案] の頭と <パス>:<行>： の形が無い。
- [TV-6] 行へのコメントが無いとき・本文に入れて投稿し直すときは、件数の行が付かない
  - 入力：reviewComments が0件のタスクと、2件のタスクを foldComments ありで buildReviewBody に渡す
  - 期待結果：どちらの本文にも件数の行が無く、後者では2件が「### 行についての指摘」の節に1回ずつだけ出る。
- [TV-7] 提案ありの回で、総評と件数の行だけの本文が、行へのコメントの提案に合わせて選り分けられる
  - 入力：件数の行を含む総評だけの本文と、[提案] の行へのコメント2件を、判定 suggestions の同じ回の指摘として splitSuggestions と droppedRemarks に渡し、2件とも decline とする
  - 期待結果：単位は行へのコメントの2件だけで（本文の単位は0件）、droppedRemarks は本文と2件の行へのコメントのすべてを返す。
- [TV-8] 要修正の回で、行へのコメントの要修正が取りこぼされず、本文も直しから外れない
  - 入力：件数の行を含む総評だけの本文と、[要修正] の行へのコメント1件を、判定 changes_required の同じ回の指摘として splitSuggestions と droppedRemarks に渡す
  - 期待結果：単位に kind が must の行へのコメントが1件あり、droppedRemarks はどちらの指摘も返さない。
- [TV-9] 再レビューの指示が、「前回の指摘」の節を本文に書かせ、前回の行へのコメントも短く挙げさせる
  - 入力：previousReview に本文と行へのコメント1件がある再レビューのタスクで、レビューの指示を作る
  - 期待結果：指示に、本文に「前回の指摘」の節を作る行と、前回の行へのコメントの指摘も場所と状況だけを短く挙げて中身を繰り返さないという行があり、データに前回の行へのコメントが含まれる。
- [TV-10] 直しの側への説明に、件数の行が別の指摘ではないことが書かれる
  - 入力：AI のレビューの指摘がある元のタスクの直しの指示を作る
  - 期待結果：AI のレビューの指摘の節の説明に、本文の件数の行は行へのコメントの指摘を数えたもので別の指摘ではないことが含まれる。
- [TV-11] 自己レビューの指示が変わらない
  - 入力：セルフレビューを行う設計の工程の指示を作る
  - 期待結果：指示に、行へのコメントにした指摘を本文に重ねない決まりの文が含まれず、self-review.md は差分に無い。
- [TV-12] 既定のスキルに、依頼した側が投稿するときも重ねない決まりが書かれる
  - 入力：pr-review.md と aggregation.md の差分
  - 期待結果：pr-review.md の「結果の返し方と投稿」に、依頼した側が投稿するときも行へのコメントにした指摘を本文に重ねない（位置を付けられない指摘は本文に書く）と書かれ、aggregation.md の他の現れの列挙先が代表の指摘の本文（行へのコメントならそのコメント）と書かれている。
- [TV-13] 仕様書とユーザー文書（日英）が、重ねないことと件数の行を書いている
  - 入力：docs/spec/tasks-and-steps.md・.en.md と docs/user/intake.md・.en.md の差分
  - 期待結果：仕様書の指示と「投稿する本文」の行に、重ねないことと件数の行（付く条件と付かない条件）が書かれ、ユーザー文書の「投稿されるレビュー」に、行へのコメントにした指摘は本文に出ず判定の下に件数の行があることが、経緯の言い回しなしで書かれている。
