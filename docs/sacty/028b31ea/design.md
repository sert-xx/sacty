# PBI-479 設計：行へのコメントにした指摘を、レビューの本文に重ねて書かない

## スコープ

デーモンが投稿する PR のレビューでは、行へのコメントにした指摘を本文に書かせないようにします。
本文の判定の行の下には、行へのコメントの件数を sacty が数えて1行で足します。

- 対象
  - レビューの工程の指示（`apps/daemon/src/prompts.ts` のレビューの指示・`HEAD_CHECK_LINES`・`reviewRecordInstructionLines`・`rereviewLines`・`AI_REMARK_EXPLANATION_LINE`）
  - 投稿する本文の組み立て（`buildReviewBody`・`VERDICT_ABSENT_LINE`）
  - 既定のスキル（`review-dispatch/references/pr-review.md`・`aggregation.md`）
  - テスト、仕様書（`docs/spec/tasks-and-steps`・`docs/spec/context` 日英）、ユーザー文書（`docs/user/intake` 日英）、ADR・作業履歴
- 対象外
  - 指摘の読み取り（`suggestion-triage.ts`・`github.ts`・`review-comments.ts`）のコードの変更。いまの処理のまま、本文が減った形で動くことをテストで確かめる
  - 自己レビュー（`self-review.md` と自己レビューの指示）
  - 行へのコメントの書き方、総評・レビューの範囲・検証の節の長さ

## 確認したいこと

- must：なし
- should
  - Q-1 件数は sacty が数えて、判定の行のすぐ下に「行へのコメントに N 件の指摘があります。」と足し、エージェントには総評に件数を書かせない形でよいか（推奨：はい）。
    理由：エージェントは投稿の時点で、どれが差分の外として本文に回るか・422 で全部が本文に入るかを知らないので、数がずれる。総評にも書かせると、件数が二重になる。
    懸念：受け入れ条件 4 の例のとおりエージェントに総評で書かせる形が望みだった場合、本文の組み立ての変更とテスト（TV-1・TV-5・TV-6）が無駄になり、指示の変更に作り直す手間が増えます。
- 確認しないと決めたこと
  - 件数の行の置き場所：Q-1 の推奨のとおり、sacty が書く判定の行の下に置く。sacty が足す行なので、総評（エージェントが書く）には置けないため。
  - `changes_required` の回に本文が総評だけになり、選り分けで本文の全体が「必ず直す」1 件として渡ること：変えない。いまも総評だけの本文はあり、行へのコメントの指摘は別の 1 件として直しに渡る。直しの側の説明に、件数の行は別の指摘ではないと1文足して、要らない直しを防ぐ。

## 既定で決めたこと

- 件数の行は、行へのコメントとして投稿する件数だけを数える。0 件のときと、422 で本文に入れて投稿し直すとき（`foldComments`）は書かない。
- 件数の行に、`[要修正]`・`[提案]` の頭と `<パス>:<行>：` の形を使わない（選り分けが 1 件の指摘として読まないため）。重さの内訳も書かない。
- 判定が付かない・読み取れない回の案内は、件数の有無によらず「本文と行へのコメントを確かめてください」にする。
- `aggregation.md` の「他の現れを本文に列挙」は、代表の指摘の本文（行へのコメントならそのコメント）に列挙すると書き直す。

## 構成

| 場所 | 変更 |
| --- | --- |
| レビューの指示（`prompts.ts` 3909 行付近） | 行へのコメントにした指摘は、本文のどの節にも同じ内容（言い換えを含む）を書かない、と足す。差分の外の行へのコメントは sacty が本文に回すので、本文の「指摘」の節にも書かない、と足す。位置を付けられない指摘を本文の「指摘」の節に書く行は残す。総評に件数を書かない、と足す |
| 同じ指示の本文の指摘の行（3890〜3894 行付近）・`HEAD_CHECK_LINES`（463 行）・`reviewRecordInstructionLines`（478 行） | 本文に指摘を書く前提の行を、「行へのコメントにしない指摘だけを本文の『指摘』の節に書く」の形に直す。重さ・場所・起きる条件と実害・直し方を添える決まりは、行へのコメントにも当てる |
| `rereviewLines` | 「前回の指摘」の節では、前回の行へのコメントの指摘も、場所と状況だけを短く挙げる（中身を繰り返さない）、と足す。前回の本文の件数の行は sacty が足した行で、前回の指摘でも今回の件数でもない、と足す |
| `AI_REMARK_EXPLANATION_LINE` | 本文の件数の行は、行へのコメントの指摘を数えたもので、別の指摘ではない、と足す |
| `buildReviewBody` | 判定の行の下に件数の行を足す（`foldComments` でなく、`task.reviewComments` が 1 件以上のとき。判定が付かない・読み取れない回も同じ） |
| `VERDICT_ABSENT_LINE`・判定を読み取れない回の行 | 案内の「本文を確かめてください」「本文の指摘を確かめてください」を「本文と行へのコメントを確かめてください」に直す |
| `pr-review.md` | 「結果の返し方と投稿」に、依頼した側が投稿するときも、行へのコメントにした指摘は本文に重ねない、と書く（自前の投稿の決まりと同じにする）。理由：ユーザーのリポジトリでもこのスキルが使われ、デーモンの指示に無い場面ではスキルの決まりで書くため |

## 影響範囲

- 判定の補い方（`extractReviewComments`）・取り込み・選り分け・重なりの照合は、コードを変えない。
  - 根拠：再レビューは、前回の行へのコメントを `previousReview.comments` で受け取る（sacty の目印つきの元のコメントは、`github.ts` の `human` で既存の指摘から除かれる）。対応しない・対応しましたの返信は、`includeSactyReplies` で既存の指摘（`review_comment`）に sacty の返信として載る（`annotateReviewComments` の `by`・`reply`）。どちらも本文の有無に依らない。
- 仕様書の `tasks-and-steps`（日英）の「PR のレビューだけのタスク」の、指示と「投稿する本文」の行に、重ねないことと件数の行を書き、判定が無い回の案内の引用（「本文の指摘を確かめてください」など）を新しい文言に直す。
- 仕様書の `context`（日英）の「PR のレビューと投稿」の節に、行へのコメントにした指摘は本文に重ねないことを書く。
- ユーザー文書の `intake`（日英）の「投稿されるレビュー」に、件数の行と、行へのコメントにした指摘は本文に出ないことを書く。同じ節の「本文を読んで確かめてください」を本文と行へのコメントを確かめる案内に、「本文は総評から始まり、指摘と…が続きます」を本文の指摘は行へのコメントにしない指摘だけと分かる文に直す。
- ADR（日本語）と作業履歴（日本語）を足す。

## テスト観点

- [TV-1] レビューの指示が、行へのコメントにした指摘を本文に重ねて書かせない
  - 入力：PR のレビューの工程の指示を buildPrompt で作る
  - 期待結果：指示に、行へのコメントにした指摘は本文のどの節にも同じ内容（言い換えを含む。起きる条件・実害・直し方）を書かないことと、総評に件数を書かないことが含まれ、行へのコメントの指摘も含めて無条件に本文の「指摘」の節に書かせる行（HEAD_CHECK_LINES・reviewRecordInstructionLines・本文の指摘の行）が残っていない。
- [TV-2] レビューの指示が、行へのコメントにできない指摘を本文の「指摘」の節に書かせ、差分の外の行へのコメントを本文に重ねさせない
  - 入力：PR のレビューの工程の指示を buildPrompt で作る
  - 期待結果：指示に、差分の中に付けられる行が無い指摘は頭を付けて本文の「指摘」の節に書くことと、差分の外の行へのコメントは sacty が本文に回すので本文の「指摘」の節に書かないことが含まれ、本文の「指摘」の節の行は「行へのコメントにしない指摘だけ」を対象にしている。
- [TV-3] 差分の外の行へのコメントが、本文に1回だけ出る
  - 入力：本文の「指摘」の節にその指摘が無く、差分の外の行への must の行へのコメントが1件ある答えを extractReviewComments に渡す
  - 期待結果：返る output で、そのコメントの文が「### 行についての指摘」の節に1回だけ現れ、comments は空になる。
- [TV-4] 本文に指摘が無くても、行へのコメントの重さが判定に効く
  - 入力：本文が総評だけで、判定が suggestions、行へのコメントに must が1件ある答え（と、判定が no_findings で should が1件ある答え）を extractReviewComments に渡す
  - 期待結果：判定は前者が changes_required、後者が suggestions になる。
- [TV-5] 行へのコメントがあるとき、判定の行の下に件数の行が付き、判定が付かない回の案内が行へのコメントも指す
  - 入力：reviewComments が2件のタスクを、foldComments なしで、判定が suggestions の場合と判定のブロックが無い場合のそれぞれで buildReviewBody に渡す
  - 期待結果：どちらも判定の行のすぐ下に「行へのコメントに 2 件の指摘があります。」の行があり、その行に [要修正]・[提案] の頭と <パス>:<行>： の形が無く、判定が無い場合の判定の行は「本文と行へのコメントを確かめてください」を含む。
- [TV-6] 行へのコメントが無いとき・本文に入れて投稿し直すときは、件数の行が付かない
  - 入力：reviewComments が0件のタスクと、2件のタスクを foldComments ありで buildReviewBody に渡す
  - 期待結果：どちらの本文にも件数の行が無く、後者では2件が「### 行についての指摘」の節に1回ずつだけ出る。
- [TV-7] 提案ありの回で、総評と件数の行だけの本文が、行へのコメントの提案に合わせて選り分けられる
  - 入力：件数の行を含む総評だけの本文と、[提案] の行へのコメント2件を、判定 suggestions の同じ回の指摘として splitSuggestions と droppedRemarks に渡し、2件とも decline とする
  - 期待結果：単位は行へのコメントの2件だけで（本文の単位は0件）、droppedRemarks は本文と2件の行へのコメントのすべてを返す。
- [TV-8] 要修正の回で、行へのコメントの要修正が取りこぼされず、本文も直しから外れない
  - 入力：件数の行を含む総評だけの本文と、[要修正] の行へのコメント1件を、判定 changes_required の同じ回の指摘として splitSuggestions と droppedRemarks に渡す
  - 期待結果：単位に kind が must の行へのコメントが1件あり、droppedRemarks はどちらの指摘も返さない。
- [TV-9] 再レビューの指示が、「前回の指摘」の節を本文に書かせ、前回の行へのコメントも短く挙げさせ、件数の行を指摘として扱わせない
  - 入力：previousReview に件数の行を含む総評だけの本文と行へのコメント1件がある再レビューのタスクで、レビューの指示を作る
  - 期待結果：指示に、本文に「前回の指摘」の節を作る行と、前回の行へのコメントの指摘も場所と状況だけを短く挙げて中身を繰り返さないという行と、前回の本文の件数の行は前回の指摘でも今回の件数でもないという行があり、データに前回の行へのコメントが含まれる。
- [TV-10] 直しの側への説明に、件数の行が別の指摘ではないことが書かれる
  - 入力：AI のレビューの指摘がある元のタスクの直しの指示を作る
  - 期待結果：AI のレビューの指摘の節の説明に、本文の件数の行は行へのコメントの指摘を数えたもので別の指摘ではないことが含まれる。
- [TV-11] 自己レビューの指示が変わらない
  - 入力：セルフレビューを行う設計の工程の指示を作る
  - 期待結果：指示に、行へのコメントにした指摘を本文に重ねない決まりの文が含まれず、self-review.md は差分に無い。
- [TV-12] 既定のスキルに、依頼した側が投稿するときも重ねない決まりが書かれる
  - 入力：pr-review.md と aggregation.md の差分
  - 期待結果：pr-review.md の「結果の返し方と投稿」に、依頼した側が投稿するときも行へのコメントにした指摘を本文に重ねない（位置を付けられない指摘は本文に書く）と書かれ、aggregation.md の他の現れの列挙先が代表の指摘の本文（行へのコメントならそのコメント）と書かれている。
- [TV-13] 仕様書とユーザー文書（日英）が、重ねないことと件数の行と新しい案内を書いている
  - 入力：docs/spec/tasks-and-steps.md・.en.md、docs/spec/context.md・.en.md と docs/user/intake.md・.en.md の差分
  - 期待結果：仕様書の tasks-and-steps の指示と「投稿する本文」の行に、重ねないことと件数の行（付く条件と付かない条件）と、判定が無い回の案内の新しい文言が書かれ、context の「PR のレビューと投稿」の節に行へのコメントにした指摘は本文に重ねないことが書かれ、ユーザー文書の「投稿されるレビュー」に、行へのコメントにした指摘は本文に出ず判定の下に件数の行があることと、判定が無い回は本文と行へのコメントを確かめる案内が、経緯の言い回しなしで書かれ、本文だけを確かめさせる案内が残っていない。
- [TV-14] 前回の指摘が行へのコメントだけにある再レビューで、二度出さない判定と却下・対応済みの照合の材料が渡る
  - 入力：前回の本文が総評と件数の行だけで、前回の sacty の行へのコメント2件に、そのタスクの返信（1件は「対応しない」、1件は「対応しました」）が付いた PR で、reviewFeedback を通して再レビューの指示を作る
  - 期待結果：指示のデータの previousReview.comments に前回の行へのコメント2件が含まれ、既存の指摘には2件の返信が review_comment として by が sacty・返信の状態（対応しない・対応した）つきで含まれ、元の行へのコメントは既存の指摘に含まれない。
