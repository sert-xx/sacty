# 設計：タスクの PR が、ほかのタスクのマージ済みの作業履歴を書き換えないようにする（PBI-497）

## スコープ

PR のときに動く新しいワークフローが、マージベースからの作業履歴の差分を Node のスクリプトで判定し、決まりに反したら落とす。
規則・sacty-docs の写し・正本には、要求要件の M-1・M-3 の答えに沿う文を足す。

- 対象
  - 検査のスクリプト・ワークフロー・テストの新規作成
  - `rules.md`・sacty-docs の2つの写し・`docs/README.md`・`docs/worklog/README.md` の文、`docs/spec/context.md` と英語の版の1文（Q-1）
  - このタスクの作業履歴と ADR
- 対象外
  - 既存の `ci.yml` の手順（lint・テスト）と、その起動の条件
  - `docs/worklog/README.md` の検査（作業履歴ではなく正本なので、変えても落とさない）

## 確認したいこと

### must

なし

### should

- Q-1：既定の規則に足す1項目を、仕様書 `docs/spec/context.md`（と `context.en.md`）の既定の規則の段落にも1文で書くか。
  - 推奨：書く。
    仕様書のこの段落は規則の項目ごとに1文で書いていて（PBI-469・PBI-340 の文）、sacty-docs の 1 は実装の変更と同じ PR で仕様書を直すよう求めるため。
    要求要件の「既定で決めたこと」は CI の検査について書いたもので、規則の文は含まないと読んだ。
  - 懸念：書かないと決めていた場合、実装の PR に仕様書の日英の2行が余分に入り、レビューで消す1周が要る。

## 既定で決めたこと

- 検査は `ci.yml` に足さず、別のワークフローにする。
  題を変えたとき（`edited`）に、lint・全件のテストまでやり直さないため。
- 判定は `scripts/` の Node のスクリプト（依存なし）に置き、テストは `tests/scripts/` に置く（`cli-install.mjs` と同じ形）。
- 出力の行の番号は、変えた・消した行はマージベースの版の番号、足した行は PR の先頭の版の番号とし、どちらの版かを添える。
- 名前の変更は、元のファイルの削除と新しいファイルの追加として判定する（マージ済みのファイルの削除・名前の変更は落とす）。

## 処理の流れ

1. `git merge-base <base.sha> <head.sha>` でマージベースを求め、`git diff --no-renames --unified=0` で `docs/worklog/*.md`（`README.md` を除く）の差分を取る。
2. マージベースに無いファイルは通す（R-6）。
3. 同じタスクかを決める：題の最初の `PBI-<番号>` があれば、日付の後が `pbi-<番号>-` のファイル。無ければ `pr-<PR の番号>-` のファイル。
4. 変わった塊（hunk）ごとに判定する。
   - リンクの直し：消した行と足した行が同じ数で、組ごとにリンクの行き先だけが違い、元の行き先が先頭に無く、直した先が先頭にある。どのファイルでも通す（R-4。R-15 は落ちる）。
   - 足しただけの塊：同じタスクのファイルだけ通す（R-5）。
   - それ以外（ほかのタスクのファイルへの追記、既存の行の変更・削除、ファイルの削除）は違反（R-1・R-13）。
5. 違反があれば、ファイルごとにパス・行の番号と「このファイルの変更を戻してください（`git checkout <マージベース> -- <パス>`）。同じタスクのファイルには、既存の行を変えずに書き足してください」を出し、終了コード 1 で終える。

## エラー時の振る舞い

- 環境変数が無い・SHA を git で解決できない・git が失敗したときは、理由を出して終了コード 2 で落とす（検査せずに通さない）。

## 検証の計画

- 人：GitHub Actions の画面で、次を確かめる。
  - 実際の PR で、R-1 の形の変更が落ち、R-6 の形の変更が通ること。
  - 題を変えると `edited` で検査がやり直され、結果が変えた後の題のものになること。

  - 期待結果：終了コード 1 で、出力に `docs/worklog/20261122-pbi-489-x.md`、マージベースの版の行 3、そのファイルの変更を戻す文（`git checkout <マージベース> -- <パス>` を含む）が出る

  - 期待結果：終了コード 1 で、そのパスと、PR の先頭の版の足した2行の番号が出る
