# 要求要件：notFound() のページのタブの題と、デーモンに届かないときの知らせの文言（PBI-477）

## スコープ

`notFound()` を呼ぶページでも、タブの題を「ページが見つかりません - Sacty」にする。
デーモンに届かないときの知らせと、数値・ID・形式名でない注釈の括弧書きを含むほかの文（エラー・案内など）を直し、文言の検査で見つかるようにする。

- 対象
  - `notFound()` を呼ぶ 8 ページ
    - `/tasks/<ID>`・`runs/<ID>`・`review`
    - `/projects/<ID>` の `tasks`・`settings`・`schedules`・`schedules/<ID>`・`audit`
  - 画面の辞書の文（日英。引数を取る文言を含む）と、文言の検査（`wording-policy.test.ts`）
  - 仕様書（`architecture`・`ui-wording`）とユーザー文書（`tasks`）の日英、作業履歴、ADR
- 対象外
  - 無いタスクの画面から移ったときに出る React の #419 の例外と、`CardSection`・`DashboardCard` の「補足」の名前（依頼の範囲の外）
  - `notFound()` を参照する route.ts（画面ではないため）
  - 補足（`hint`・`*Hint`）の文言と、デーモンが作る文（core の辞書）。どちらも規則の対象外
  - ラベル・見出し・選択肢と、短い語を添える括弧。今の文言と長さの基準のまま残す

## 確認したいこと

### must

なし

### should

- `docs/spec/architecture.md` の「タスクの詳細・成果物のレビュー・実行のログの画面は、URL を直接開いても 404 になる」を、今回は直さずに残すか。
  推奨：残す。応答コードは変えず（R-7）、今の値は実機でしか確かめられないため、人の確かめ（下記）で 200 と分かったときに直す。
  懸念：200 なのに残すと、仕様書を読んだ人が無いタスクの URL の扱いを誤ります。

### 確認しないと決めたこと

- タブの題の直し方と、題が「Sacty」のままになる原因：設計で確かめて決める。要求は題・本文・応答コードで決まり、直し方では変わらないため。
- `notFound()` の道を通すテストの仕組み：設計で決める。要求は受け入れ条件 2（`notFound()` の道を通し、直しを戻すと落ちる）で決まっているため。
- プロジェクトの設定のページ（独自の `generateMetadata` がある）：R-6 に含める。受け入れ条件 1 が「どのページでも」としているため。
- 補足の文言：対象外にする。`docs/spec/ui-wording.md` の括弧の規則は本文に限っているため。

## 既定で決めたこと

- 日本語のユーザー文書（`docs/user/tasks.md`）の知らせの記述は、英語版と同じく括弧を使わない文にそろえる。
- 新しい `live.stale` は、エラーの案内として 2 文までにする（`ui-wording.md` の「エラーと判断の案内は2文まで」）。
- 「文」は、日本語は「。」、英語は "." で終わる本文とする。それ以外の本文をラベル・見出し・選択肢として扱う。
- 文とラベルで括弧の基準を分けた理由を、ADR を 1 件足して残す（`docs/README.md` の、方針を変えたら ADR を足す決まり）。

## 受け入れの確かめ方

### 自動のテストで確かめること

- R-6・R-7：8 ページそれぞれを、`notFound()` を呼ぶ道を通して描く。題・本文・リンクを日英で確かめる。題を直す変更を戻すと落ちる。
- R-9：無い URL の道で、題を日英で確かめる。
- R-1・R-2・R-8・R-10・R-11：文言の検査が通る。直す前の `live.stale` を入れると落ちる。2 文を理由にした例外のキーの文に注釈の括弧書きを入れても落ちる。
- `npm run format`・`npm run lint`・`npm run typecheck`・`npm test`（`tests/docs` の日英の突き合わせを含む）・`npm run build` が通る。

### 人が確かめること

- `sacty up` で、無いタスクの ID の `/tasks/<ID>` をブラウザーで開き、タブの題が「ページが見つかりません - Sacty」になり、応答コードが直す前と同じである。
  懸念：テストは合成の描画で確かめ、応答コードは見えません。ストリーミングの後に題が付かないという実ブラウザーの振る舞いや応答コードの変化を、PBI-434 のときのようにまた見逃すおそれがあります。
