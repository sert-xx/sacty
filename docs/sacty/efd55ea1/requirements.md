# 要求要件：notFound() のページのタブの題と、デーモンに届かないときの知らせの文言（PBI-477）

## スコープ

`notFound()` を呼ぶページでも、タブの題を「ページが見つかりません - Sacty」にする。
デーモンに届かないときの知らせを直す。「括弧は数値や ID を添えるときだけ」の規則から外れるほかの画面の文言も直し、文言の検査で見つかるようにする。

- 対象
  - `notFound()` を呼ぶ 8 ページ
    - `/tasks/<ID>`・`runs/<ID>`・`review`
    - `/projects/<ID>` の `tasks`・`settings`・`schedules`・`schedules/<ID>`・`audit`
  - 画面の辞書の本文（日英）と、文言の検査（`wording-policy.test.ts`）
  - 仕様書（`architecture`・`ui-wording`）とユーザー文書（`tasks`）の日英、作業履歴
- 対象外
  - 無いタスクの画面から移ったときに出る React の #419 の例外と、`CardSection`・`DashboardCard` の「補足」の名前（依頼の範囲の外）
  - `notFound()` を参照する route.ts（画面ではないため）
  - 補足（`hint`・`*Hint`）の文言と、デーモンが作る文（core の辞書）。どちらも規則の対象外

## 確認したいこと

### must

- 「ほかにも規則から外れる文言」は、辞書の本文で括弧の中が数値・ID でないものすべて（目安で 100 件ほど。ラベル・見出し・選択肢を含む）か。
  推奨：すべてを対象にし、検査は括弧の中が数値・ID でなければ長さによらず落とす。文は括弧を使わない形に直し、ラベル・見出し・選択肢で括弧が要るものだけ、理由を添えて例外の一覧に入れる。
  懸念：`live.stale` だけで良かった場合、画面の多くの言葉が変わった差分を利用者がレビューすることになり、戻す手間も出ます。

### should

- 括弧の中の形式名・コード名（「途中の出来事（JSONL）」の `JSONL` など）を、ID と同じに認めるか。
  推奨：認める。利用者が画面とファイルを結び付ける識別子だからです。
  懸念：認めないのが正しかった場合、これらのラベルを後から直し、検査をもう一度変えることになります。
- 引数を取る文言（関数）で規則から外れるものも直すか。
  推奨：直す。検査は今のまま関数を対象にしない（呼ばないと文にならないため）。
  懸念：直さないのが正しかった場合、関数の文言の変更を差分から戻す手間が出ます。
- `notFound()` を呼ぶページの HTTP の応答コードを、今のまま（`<Suspense>` の中で呼ぶものは 200）にするか。
  推奨：今のままにする（受け入れ条件 3 の「応答の振る舞いは変えない」に合わせる）。
  懸念：404 にしたかった場合、設計の直し方とテストを作り直すことになります。

### 確認しないと決めたこと

- タブの題の直し方と、題が「Sacty」のままになる原因：設計で確かめて決める。要求は題・本文・応答コードで決まり、直し方では変わらないため。
- `notFound()` の道を通すテストの仕組み：設計で決める。要求は受け入れ条件 2（`notFound()` の道を通し、直しを戻すと落ちる）で決まっているため。
- プロジェクトの設定のページ（独自の `generateMetadata` がある）：R-6 に含める。受け入れ条件 1 が「どのページでも」としているため。
- 仕様書に書く応答コード：直した後の実際の値を書く。受け入れ条件 5 が「今の振る舞いに合わせる」としているため。
- 補足の文言：対象外にする。`docs/spec/ui-wording.md` の括弧の規則は本文に限っているため。

## 既定で決めたこと

- 日本語のユーザー文書（`docs/user/tasks.md`）の知らせの記述は、英語版と同じく括弧を使わない文にそろえる。
- 新しい `live.stale` は、エラーの案内として 2 文までにする（`ui-wording.md` の「エラーと判断の案内は2文まで」）。

## 受け入れの確かめ方

### 自動のテストで確かめること

- R-6・R-7：8 ページそれぞれを、`notFound()` を呼ぶ道を通して描く。題・本文・リンク・応答コードを日英で確かめる。題を直す変更を戻すと落ちる。
- R-1・R-2・R-8：文言の検査が通る。直す前の `live.stale` を入れると落ちる。
- `npm run format`・`npm run lint`・`npm run typecheck`・`npm test`（`tests/docs` の日英の突き合わせを含む）が通る。

### 人が確かめること

- `sacty up` で、無いタスクの ID の `/tasks/<ID>` をブラウザーで開き、タブの題が「ページが見つかりません - Sacty」になる。
  懸念：テストは合成の描画で確かめます。ストリーミングの後に題が付かないという実ブラウザーの振る舞いを、PBI-434 のときのようにまた見逃すおそれがあります。
