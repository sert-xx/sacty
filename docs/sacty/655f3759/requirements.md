# 要求要件：MCP が、中止の後に再実行できないタスクに「やり直せる」と案内しない

## スコープ

`sacty mcp` の中止の案内を、そのタスクが中止の後に `rerun_task` で再実行できるかで切り替えます。
再実行できないタスクには、中止すると MCP からはやり直せないことを伝えます。

- 対象
  - タスクごとの案内：`get_cancel_plan` の `irreversible`、`resume_task` が中止したタスクを断るときの理由
  - 固定の文：`cancel_task` の説明、`INSTRUCTIONS` の中止の段落、`request_changes` の `gate.invalidTarget` の断りの文
  - 再実行できるかの判定を、`rerun_task` の断り（`rerunBlock`）と1か所にまとめること
  - 仕様書（`docs/spec/mcp-server.md`・`.en.md`）、ユーザー文書（`docs/user/mcp.md`・`.en.md`）、作業履歴、ADR
- 対象外
  - `canRerun`・`canResume`・`canCancel` の値と、`rerun_task` が断る条件そのもの
  - `rerun_task` の説明・`RERUN_ASK_NOTE`・`INSTRUCTIONS` の再実行の段落（`canRerun` を確かめてから呼ぶ前提の文のため）
  - 中止した後の `cancel_task` の結果の文（いまも再実行を案内していない）

## 確認したいこと

### must

1. 再実行できないタスクに示すやり直しの道を、`rerunBlock` の理由にそろえてよいか（R-6・R-7）。
   - 推奨：はい。「MCP からはやり直せない」を前置きにし、道は `rerunBlock` の理由と画面で決めることをそのまま使います（PR のレビューは「PR で依頼し直す」、リポジトリ未定・既定値が通らないは「画面で直して再実行」、分割の子は「親から進める」、再実行済みは「再実行で作ったタスクを確かめる」）。
   - 理由：依頼の文の「画面で新しく作る」で案内すると、画面の再実行で済むタスクでも、利用者が題と説明を書き直すことになります。
   - 懸念：一律の「画面で新しく作る」が望みなら、案内の文とテストの期待を書き直すことになります。

### should

なし

### 確認しないと決めたこと

- 判定の範囲：既定値が `RerunTaskInput` に通らないタスクも「再実行できない」に入れます。受け入れ条件 3 が「`rerun_task` が断る条件と同じ」と決めているためです。
- 中止の前の判定：「いま中止したとすれば `rerun_task` が断るか」で決め、除くのは「中止していない」「完了」で断る条件だけです（R-2）。`get_cancel_plan` は中止の前に呼ぶので、状態で断る条件を除いて判定するしかないためです。
- 中止できないタスク（`canCancel` が false）の `get_cancel_plan`：`irreversible` にやり直しの案内を入れません（R-8）。中止しないので、中止の後の道を示す意味が無いためです。
- デーモンだけが知る断り（リポジトリがプロジェクトの対象でないなど）は判定に入れず、R-5 の案内に「デーモンが断ることがある」と添えます。`rerunBlock` がいまも見ていない条件で、判定を `rerun_task` と同じに保つためです。
- `gate.invalidTarget` の断りの文：固定の文として、条件付きの書き方に直します（R-1）。差し戻しの対象を断る文で、再実行には添え書きで触れるだけなので、受け入れ条件 2 の扱いで足ります。
- 中止した後の `cancel_task` の結果の文：再実行の案内を足しません。依頼に無く、結果の要約の `canRerun` で分かるためです。
- ADR：新しい ADR を足し、既存の ADR（`20261119-1000-mcp-rerun-minimal-screen-defaults`）は `docs/adr/README.md` の一部の置き換えの手順で `superseded` にします（本文は書き換えない）。既存の ADR の「中止の案内に再実行を案内する」を条件付きに変えるので、`CONTRIBUTING.md` の決まり（方針を変えたら ADR を足す）に当たるためです。

## 既定で決めたこと

- 再実行できるタスクの `get_cancel_plan`・`resume_task` の案内は、いまの文の趣旨を保ちます（頼まれたときだけ `rerun_task` を使い、新しいタスクになり、作業領域・ブランチ・PR は戻らない）。

## 受け入れの確かめ方

### 自動のテストで確かめること

- `packages/cli/src` の MCP のテスト（本物のデーモンのサービスにつなぐもの）で、次を確かめる（R-5〜R-8）
  - 再実行できるタスク：`get_cancel_plan` の `irreversible` と `resume_task` の断りに `rerun_task` が入る
  - PR のレビューだけ・リポジトリが決まっていないチケット由来・既定値が通らないタスク：どちらにも `rerun_task` が入らず、MCP からはやり直せないことと `rerunBlock` の理由が入る
  - 再実行済みの中止したタスク：`resume_task` の断りに `rerun_task` の案内が入らず、再実行で作ったタスクの ID が入る
  - 中止できないタスク：`get_cancel_plan` の `irreversible` に、やり直しの案内が入らない
  - `cancel_task` の説明・`INSTRUCTIONS` の中止の段落・`gate.invalidTarget` の断りの文が、条件付きの書き方になっている（R-1）
  - 案内を切り替える直しを戻すと、上のテストが落ちる
- 既存の `mcp-rerun.test.ts` のテストのうち、「resume_task の断り」と、説明・`INSTRUCTIONS` の文を確かめるものを、R-1・R-7 に合わせて直して通す

### 差分で確かめること

- R-1・R-3：固定の文と日英の仕様書・ユーザー文書に、無条件の「やり直すなら再実行」が残っていない
- R-2：判定が `rerunBlock` と別の写しになっていない
- R-4：作業履歴と新しい ADR があり、既存の ADR が `superseded` の名前・ステータス・`置き換え先` になり、新しい ADR の `置き換え元` と揃い、既存の ADR の本文（背景・決定・理由・影響）が変わっていない
