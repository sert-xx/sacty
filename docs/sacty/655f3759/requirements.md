# 要求要件：MCP が、中止の後に再実行できないタスクに「やり直せる」と案内しない

## スコープ

`sacty mcp` の中止の案内を、そのタスクが中止の後に `rerun_task` で再実行できるかで切り替えます。
再実行できないタスクには、中止すると MCP からはやり直せないことを伝えます。

- 対象
  - タスクごとの案内：`get_cancel_plan` の `irreversible`、`resume_task` が中止したタスクを断るときの理由
  - 固定の文：`cancel_task` の説明、`INSTRUCTIONS` の中止の段落、`request_changes` の `gate.invalidTarget` の断りの文
  - 再実行できるかの判定を、`rerun_task` の断り（`rerunBlock`）と1か所にまとめること
  - 仕様書（`docs/spec/mcp-server.md`・`.en.md`）、ユーザー文書（`docs/user/mcp.md`・`.en.md`）、作業履歴、ADR
- 対象外
  - `canRerun`・`canResume`・`canCancel` の値と、`rerun_task` が断る条件そのもの
  - `rerun_task` の説明・`RERUN_ASK_NOTE`・`INSTRUCTIONS` の再実行の段落（`canRerun` を確かめてから呼ぶ前提の文のため）
  - 中止した後の `cancel_task` の結果の文（いまも再実行を案内していない）

## 確認したいこと

### must

1. 再実行できないタスクに、やり直す道をどう案内するか。
   - 推奨：「中止すると MCP からはやり直せない」に、理由ごとの道を添えます。PR のレビューのタスクは「PR で依頼し直す」、リポジトリが決まっていないタスクと既定値が通らないタスクは「画面の再実行で直してやり直す」です。
   - 理由：依頼の文の「画面で新しく作る」で案内すると、画面の再実行で済むタスクでも、利用者が題と説明を書き直すことになります。
   - 懸念：一律の「画面で新しく作る」が望みなら、案内の文とテストの期待を書き直すことになります。

### should

なし

### 確認しないと決めたこと

- 判定の範囲：既定値が `RerunTaskInput` に通らないタスクも「再実行できない」に入れます。受け入れ条件 3 が「`rerun_task` が断る条件と同じ」と決めているためです。
- 中止の前の判定：「いま中止したとすれば `rerun_task` が断るか」で決めます（R-2）。`get_cancel_plan` は中止の前に呼ぶので、状態で断る条件を除いて判定するしかないためです。
- `gate.invalidTarget` の断りの文：固定の文として、条件付きの書き方に直します（R-1）。差し戻しの対象を断る文で、再実行には添え書きで触れるだけなので、受け入れ条件 2 の扱いで足ります。
- 中止した後の `cancel_task` の結果の文：再実行の案内を足しません。依頼に無く、結果の要約の `canRerun` で分かるためです。
- ADR：新しい ADR を足し、既存の ADR（`20261119-1000-mcp-rerun-minimal-screen-defaults`）は書き換えません。既存の ADR の「中止の案内に再実行を案内する」を条件付きに変えるので、`CONTRIBUTING.md` の決まり（方針を変えたら ADR を足す）に当たるためです。

## 既定で決めたこと

- 再実行できるタスクの `get_cancel_plan`・`resume_task` の案内は、いまの文の趣旨を保ちます（頼まれたときだけ `rerun_task` を使い、新しいタスクになり、作業領域・ブランチ・PR は戻らない）。

## 要求

### 常時

| ID | システム | 応答 |
| --- | --- | --- |
| R-1 | `cancel_task` の説明・`INSTRUCTIONS` の中止の段落・`gate.invalidTarget` の断りの文 | 再実行の案内を「再実行できる種類のタスクなら」の条件付きで書き、どのタスクでもやり直せると読める文を含まない |
| R-2 | タスクの MCP | 中止の後に再実行できるかを、`rerun_task` の断りと同じ1か所の判定から得る（中止の前のタスクは、状態で断る条件を除いて判定する） |
| R-3 | 仕様書（日英）・ユーザー文書（日英） | `get_cancel_plan`・`cancel_task`・`resume_task` の断りの案内を R-1・R-5〜R-7 と同じ条件で書き、無条件に「やり直すなら再実行」と書く文を含まない |
| R-4 | リポジトリ | 作業履歴（`docs/worklog/`）と、中止の案内を条件付きにする決定の ADR を足す |

### イベント駆動

| ID | トリガー | システム | 応答 |
| --- | --- | --- | --- |
| R-5 | 中止したとすれば `rerun_task` が断らないタスクに `get_cancel_plan` が呼ばれたとき | タスクの MCP | `irreversible` に、中止の後に `rerun_task` で再実行できること（新しいタスクになり、作業領域・ブランチ・PR は戻らない）を入れる |
| R-6 | 中止したとすれば `rerun_task` が断るタスク（PR のレビュー・リポジトリが決まっていないチケット由来・既定値が通らない）に `get_cancel_plan` が呼ばれたとき | タスクの MCP | `irreversible` に `rerun_task` の案内を入れず、MCP からはやり直せないことと、確認したいことの must 1 の道を入れる |
| R-7 | 中止したタスクに `resume_task` が呼ばれたとき | タスクの MCP | `rerun_task` が断らないタスクだけ理由に `rerun_task` の案内を入れ、断るタスク（再実行済みを含む）には MCP からはやり直せないことと、その道を入れる |

## 受け入れの確かめ方

### 自動のテストで確かめること

- `packages/cli/src` の MCP のテスト（本物のデーモンのサービスにつなぐもの）で、次を確かめる（R-5〜R-7）
  - 再実行できるタスク：`get_cancel_plan` の `irreversible` と `resume_task` の断りに `rerun_task` が入る
  - PR のレビューだけのタスク・リポジトリが決まっていないチケット由来のタスク：どちらにも `rerun_task` が入らず、MCP からはやり直せないことが入る
  - 案内を切り替える直しを戻すと、上のテストが落ちる
- 既存の `mcp-rerun.test.ts` のテストのうち、「resume_task の断り」と、説明・`INSTRUCTIONS` の文を確かめるものを、R-1・R-7 に合わせて直して通す

### 差分で確かめること

- R-1・R-3：固定の文と日英の仕様書・ユーザー文書に、無条件の「やり直すなら再実行」が残っていない
- R-2：判定が `rerunBlock` と別の写しになっていない
- R-4：作業履歴と新しい ADR があり、既存の ADR が書き換わっていない
