# 設計：タスクの一覧の最初の表示・URL の絞り込み・50 行ずつの表示

## スコープ

一覧を「終わっていない」で開き、絞り込みを URL のクエリに残し、行を 50 行ずつ出す。
絞り込みと区切りは画面の側で行う。

- 対象
  - `apps/web`
    - `task-filter.ts`：URL の読み書き・値の検査・最初の状態
    - `task-list.tsx`：一覧の表と絞り込みの欄。「あなたの出番」のカードは除く
    - `projects/[id]/tasks/page.tsx`：`searchParams` を読む
    - 辞書 `tasks.ts` とテスト
  - 文書：`docs/user/tasks.md`・`tasks.en.md`と、写しの `docs/user/images/task-list.png`・`task-list.en.png`
    - 種の payments に完了のタスクがあり、写る行が変わる
  - 仕様と経緯：`docs/spec/architecture.md`・`architecture.en.md` の絞り込みの節、新しい ADR、作業履歴
- 対象外
  - 「あなたの出番」のカードと、`task-list-data.ts` の `needsYou`
  - 狭い幅での表の崩れ（足すボタンと件数の文がはみ出さないことだけ守る）
  - デーモンの API・MCP の `list_tasks`、並べ替え、列の追加

## 確認したいこと

- must：なし
- should
  1. 足した行数は、Next.js の Activity だけで保つ。それでよいか。
     - Activity は `cacheComponents` で、戻る・進むのときに画面の状態を保つ仕組み。保つのは直近の 3 画面まで。
     - 推奨：Activity だけにする。タスクを開いて戻る（受け入れ条件 16）は 1 画面先なので、行数が保たれる。
     - 懸念：一覧からタスク・PR の画面などを 3 画面以上辿って戻ると、50 行に戻り、利用者が開いた行を探し直すことになる。`history.state` に行数を残す作りを足せば防げる。

確認しないと決めたこと
- 「条件をクリア」の行き先：最初の表示（開いたときに決めた状態、ほかは空）に戻し、クエリを消す。
  条件 4 の「最初の表示のままのときは出さない」から決まる。
- `docs/spec/architecture.md` の絞り込みの節：URL に残すこと・50 行ずつ出すこと・最初の表示を書き、ADR を足す。
  リポジトリの決まり（`.claude/skills/sacty-docs/SKILL.md`）に、仕様は同じ PR で直し、方針を変えたら ADR を足すとある。
- デーモンに届かずに開いた（`initial` が null）とき：最初にデータが届いた時点で、最初の表示を 1 回だけ決める。
  条件 3 の「開いたときに 1 回だけ」から決まる。

## 既定で決めたこと

- クエリの名前は `q`・`from`・`to`・`start`・`repo`・`status` にする。
  状態の「すべて」は `status=all` にする。
- クエリに書くのは、最初の表示と違う項目だけにする。
  状態は、開いたときに決めた既定と同じなら書かない。
- 開始時期がクエリにあるときは、サーバーの描画とハイドレーションでは表の所を「読み込み中…」にし、行はブラウザーで描き直してから出す。
  日をブラウザーのタイムゾーンで決めるので、サーバーでは同じ行を選べないため。
- 「さらに表示」を押した後は、足した最初の行の題のリンクへフォーカスを移す。
  残りが無くなるとボタンが消えるため。
- 字下げ（`indentShown`）は、絞り込んだ全部の行に掛けてから 50 行で切る。
  境目の子も、足せば親の下に字下げして続く。

## 構成・データ

| 所 | 変えること |
| --- | --- |
| `task-filter.ts` | `parseTaskFilter(params)`：項目ごとに検査し、指定の無い項目は `undefined`。`resolveStatus(parsed, rows)`：状態の指定が無ければ、終わっていない行があれば `active`、無ければ `""`（すべて）。`filterQuery(filter, base)`：絞り込みを URL のクエリにする。`TaskFilter.status` の `""` は「すべて」のまま |
| `page.tsx` | `searchParams` を読み、`initialFilter` と `defaultStatus` を `LiveTaskList` に渡す |
| `task-list.tsx` | 中身を、`useRouter().bfcacheId` を `key` にした部品に分ける。新しく開いたときは URL から作り直し、戻る・進むでは状態を保つ。状態は `filter`・`limit`（50 から）・`defaultStatus` |
| `tasks.ts` | 区切ったときの件数の文と、残りの件数を出すボタンの文を、日英で足す |

値の検査（合わなければ、その項目は指定なしにする）

- 共通：値が空、または同じ名前が 2 つ以上
- `status`：`all`・`active`・状態の種類のどれでもない
- `from`・`to`：`YYYY-MM-DD` の形の、実在する日でない
- `start`：開始地点の種類のどれでもない
- `repo`・`q`：値は検査しない
  - 一覧に無い `repo`・`start` は、`filterOptions` が選択肢に残す

## 処理の流れ

- 絞り込みを変える：`filter` を変え、`limit` を 50 に戻す。
  `history.replaceState(history.state, "", url)` で、絞り込みのクエリだけを書き換え、ほかのクエリとハッシュは残す。
- 「さらに表示」：`limit` に 50 を足し、足した最初の行へフォーカスを移す。
  合う行が `limit` 以下ならボタンを出さない。
- 件数：全部を出しているときは今の文にする。
  区切っているときは「277件中 120件（50件を表示）」の形にする。
  どちらも今の `role="status"` の中に出す。
- 自動の更新：`filter`・`limit`・`defaultStatus` は変えない。
  行が増減しても `limit` までを出す。
  行の `key` は今のまま。
- 「条件をクリア」：`filter` が最初の表示（状態は `defaultStatus`、ほかは空）と違うときだけ出す。
  押すと最初の表示に戻し、`limit` を 50 にし、絞り込みのクエリを消す。
- 狭い幅：ボタンと件数は `overflow-x-auto` の外に置き、折り返す。

## テスト観点

- [TV-1] URL に指定が無いときの最初の表示は「終わっていない」
  - 入力：完了・中止・進行中・待ちの行がある一覧を、クエリ無しの URL で描く
  - 期待結果：進行中と待ちの行だけが出て、状態の選択欄の値が「終わっていない」になる。
- [TV-2] 終わっていないタスクが 0 件のときの最初の表示
  - 入力：完了と中止の行だけがある一覧を、クエリ無しの URL で描く
  - 期待結果：すべての行が出て、状態の選択欄が「すべて」になり、「条件をクリア」は出ない。
- [TV-3] タスクが 0 件のプロジェクトの表示
  - 入力：行が 0 件の一覧を、クエリ無しの URL で描く
  - 期待結果：`m.empty`（「タスクはまだありません。」）だけが出て、絞り込みの欄と「さらに表示」は出ない。
- [TV-4] 自動の更新で、最初の表示の状態が切り替わらない
  - 入力：終わっていない行が 0 件で開いた（すべて）後に、進行中の行を含むデータへ取り直す。逆に、進行中の行が 1 件で開いた後に、その行が完了になったデータへ取り直す
  - 期待結果：前者は状態が「すべて」のまま、後者は「終わっていない」のままで、URL のクエリも変わらない。
- [TV-5] デーモンに届かずに開いたときの最初の表示
  - 入力：`initial` が null で、URL に状態の指定が無い一覧を描き、その後に終わっていない行を含むデータが届き、さらにその行が完了になったデータへ取り直す
  - 期待結果：最初に届いたデータで状態が「終わっていない」に決まり、次の取り直しの後も「終わっていない」のまま。
- [TV-6] 「すべて」を選ぶと完了・中止も出て、URL に残る
  - 入力：最初の表示（終わっていない）で、状態の選択欄の「すべて」を選ぶ
  - 期待結果：完了と中止の行も出て、URL のクエリが `status=all` になる。
- [TV-7] 「条件をクリア」の出す条件と行き先
  - 入力：最初の表示で欄を見る。次に、検索に文字を入れ、状態を「すべて」にしてから「条件をクリア」を押す
  - 期待結果：最初の表示ではボタンが無く、変えた後は出て、押すと状態が開いたときの既定に、ほかの項目が空に戻り、絞り込みのクエリが URL から消え、ボタンが消える。
- [TV-8] 絞り込みの全項目を URL に書き、履歴を増やさない
  - 入力：検索・開始時期の両端・開始地点・リポジトリ・状態を順に変え、検索には 1 文字ずつ 3 文字を入れる
  - 期待結果：URL のクエリに `q`・`from`・`to`・`start`・`repo`・`status` が今の値で入り、`history.replaceState` だけが呼ばれ `history.pushState` は呼ばれず、`history.length` は変わらない。
- [TV-9] 最初の表示と同じ絞り込みのときはクエリを付けない
  - 入力：状態を「進行中」に変えてから「終わっていない」に戻し、ほかの項目は空のままにする
  - 期待結果：URL に絞り込みのクエリが残らない（`status` も付かない）。
- [TV-10] URL の絞り込みでサーバーが描き、ハイドレーションで食い違わない
  - 入力：`?q=決済&start=sacty&repo=web&status=all` を `searchParams` に渡してページをサーバーで描き、その HTML を jsdom で `hydrateRoot` する
  - 期待結果：サーバーの HTML の時点で条件に合う行だけと各選択欄の値が出ていて、ハイドレーションの後も行と件数の文が同じで、`console.error` にハイドレーションの不一致が出ない。
- [TV-11] 開始時期が URL にあるときは、別の行を先に見せない
  - 入力：`?from=2026-11-01&to=2026-11-10` を渡してページをサーバーで描き、jsdom でハイドレーションする
  - 期待結果：サーバーの HTML では表の所が「読み込み中…」で行が無く、ハイドレーションの後に、ブラウザーのタイムゾーンの日で合う行だけが出て、不一致の警告が出ない。
- [TV-12] 知らない値・形の違う値は、その項目の指定が無いものとして扱う
  - 入力：`status=foo`、`from=2026-13-40`、`to=abc`、`q=`、`status` が 2 つ、`start=unknown` をそれぞれ URL に付けて開く
  - 期待結果：どの場合も画面は例外を出さずに描け、その項目だけが指定なし（状態は最初の表示の規則、ほかは空）になり、ほかの項目の指定は効く。
- [TV-13] 一覧に無いリポジトリ・開始地点の値を URL から復元する
  - 入力：一覧のどの行にも無いリポジトリ名 `gone` と、一覧に無い開始地点の種類を、`repo`・`start` に付けて開く
  - 期待結果：選択欄にその値が選ばれた状態で出て、「条件に合うタスクはありません。」が出る。
- [TV-14] 絞り込みに関係のないクエリとハッシュを消さない
  - 入力：`?foo=1#x` の URL で開き、検索を変えてから「条件をクリア」を押す
  - 期待結果：どの時点でも URL に `foo=1` と `#x` が残る。
- [TV-15] 別のプロジェクトへ移ると、前の絞り込みを持ち込まない
  - 入力：p1 の一覧で状態を「すべて」、検索を入れ、「さらに表示」を押した後に、クエリ無しの p2 の一覧を描く
  - 期待結果：p2 の一覧は最初の表示（状態は p2 の行から決めた既定・ほかは空・50 行）で、URL に絞り込みのクエリが無い。
- [TV-16] 戻る・進むでは絞り込みと足した行数を保ち、新しく開いたときは URL から作り直す
  - 入力：120 行に合う一覧で検索を入れて「さらに表示」を 1 回押し、同じ `bfcacheId` で描き直す。次に、`bfcacheId` を変え、クエリ無しで描き直す
  - 期待結果：同じ `bfcacheId` では絞り込みと 100 行が保たれ、変えたときは最初の表示と 50 行になる。
- [TV-17] 合う行の数ごとの、行の数・ボタン・件数の文
  - 入力：合う行が 0・1・50・51・300 件になる一覧を、全体 320 件で描く
  - 期待結果：0 件は「条件に合うタスクはありません。」でボタン無し、1・50 件は全部の行が出てボタン無しで件数の文は「320件中 1件」「320件中 50件」、51・300 件は 50 行が出て、ボタンに残りの 1 件・250 件が、件数の文に「320件中 51件（50件を表示）」「320件中 300件（50件を表示）」が、`role="status"` の要素に出る（英語の辞書でも同じ数が出る）。
- [TV-18] 「さらに表示」で行を足し、フォーカスを移す
  - 入力：合う行が 120 件の一覧で、ボタンにフォーカスして Enter を押し、もう一度押す
  - 期待結果：1 回目で 100 行になって 51 行目の題のリンクにフォーカスが移り、ボタンの残りが 20 件になり、2 回目で 120 行になって 101 行目のリンクにフォーカスが移り、ボタンが消え、件数の文が「…120件」の形に戻る。
- [TV-19] 絞り込みを変えると、出す行が 50 行に戻る
