# 要求要件：オーケストレーターへの質問をショートカットキーで送る

## 何を実現するか

タスクの詳細の「オーケストレーターに質問」のパネルで、質問を Ctrl + Enter・⌘ + Enter でも送れるようにし、キーボードから手を離さずに質問できるようにする。
ショートカットで送った結果は、「質問する」ボタンで送ったときと同じにする。
修飾キーの無い Enter は、いまどおり改行のままにする。

## 用語

- **質問欄**：「オーケストレーターに質問」のパネルにある、質問を書く複数行の入力欄（ラベル「質問」／「Question」）。この文書の要求の主語にする。R-5 だけは、ユーザードキュメントを主語にする。
- **送信のショートカット**：次の2つ。OS を問わず、どちらも受け付ける（Q-2）。
  - Ctrl + Enter：Ctrl だけを押しながら Enter を押す
  - ⌘ + Enter：⌘（macOS の Command キー。ほかの OS では Windows キーなどの Meta キー）だけを押しながら Enter を押す
- **送信不可の状態**：いま「質問する」ボタンが押せない状態。次のどちらか。
  - 質問がブロックされている（タスクが中止済み・答えを待つ質問がある・予算の上限に達した）
  - 質問を送っている途中（ボタンの表示が「送っています…」）
- **空**：質問欄の文字数が 0 の状態。空白・改行だけの内容は空ではない。
- **変換中**：日本語入力などの入力方式で、文字を変換していて、まだ確定していない状態。
- **質問を送ってはならない（合否の決め方）**：合否は、次の2つで決める。
  - デーモンへの質問の要求が 0 件
  - そのタスクの質問の件数が増えない
  
  質問欄の内容は見ない。Enter・Shift + Enter で改行が入るのは R-3・R-4 のとおり。
- **送信に成功したときの結果**：いまボタンで送れたときと同じ状態。質問が1件、そのタスクの質問として記録され、質問欄が空になる。
- **送信に失敗したときの結果**：いまボタンで送って失敗したときと同じ状態。
  - 質問は記録されない
  - 書いた質問が質問欄に残る
  - ボタンで送って同じ原因で失敗したときと同じ文言の理由がパネルに出る

## 受け入れ条件

ID は追加した順で、番号の順ではない（直しても ID を付け直さないため）。

### 正常系

- **R-1（複合）**：質問欄にフォーカスがあり、質問欄が空でなく、送信不可の状態でない間、Ctrl + Enter を押したとき、質問欄は、質問欄の内容をそのタスクへの質問として1件だけ送らなければならない。
- **R-13（複合）**：質問欄にフォーカスがあり、質問欄が空でなく、送信不可の状態でない間、⌘ + Enter を押したとき、質問欄は、質問欄の内容をそのタスクへの質問として1件だけ送らなければならない。
- **R-2（イベント駆動）**：送信のショートカットで送った質問をデーモンが受け付けたとき、質問欄は、送信に成功したときの結果にしなければならない。
- **R-14（複合）**：質問欄の内容が改行を含まないちょうど 2,000 文字で、R-1 か R-13 の条件で送信のショートカットを押したとき、質問欄は、2,000 文字の質問を1件だけ送らなければならない。
- **R-3（複合）**：質問欄にフォーカスがあり、質問欄の文字数が 2,000 文字未満の間、修飾キーの無い Enter を押したとき、質問欄は、カーソルの位置に改行を1つ入れなければならない。
- **R-4（複合）**：質問欄にフォーカスがあり、質問欄の文字数が 2,000 文字未満の間、Shift + Enter を押したとき、質問欄は、カーソルの位置に改行を1つ入れなければならない。
- **R-5（常時）**：ユーザードキュメント（docs/user/tasks.md の「オーケストレーターに質問する」と、docs/user/tasks.en.md の「Ask the Orchestrator」）は、それぞれ、Ctrl + Enter と ⌘ + Enter の両方を、質問を送る操作として載せなければならない。

### 異常系

- **R-15（望まない振る舞い）**：質問欄にフォーカスがあり、送信のショートカット以外の組み合わせで Enter を押した場合（修飾キー無し・Shift・Alt/Option を押しながら、Ctrl か ⌘ に加えてほかの修飾キーも押しながら）、質問欄は、質問を送ってはならない。
- **R-6（望まない振る舞い）**：変換中に送信のショートカットを押した場合、質問欄は、質問を送ってはならない。
- **R-7（望まない振る舞い）**：質問欄が空のときに送信のショートカットを押した場合、質問欄は、質問を送ってはならない。
- **R-16（望まない振る舞い）**：質問欄が空のときに送信のショートカットを押した場合、質問欄は、空のままボタンを押したときと同じ表示（入力が必要であることの案内）を出さなければならない。
- **R-8（望まない振る舞い）**：質問欄が空白・改行だけのときに送信のショートカットを押した場合、質問欄は、送信に失敗したときの結果にしなければならない。
- **R-9（状態駆動）**：質問がブロックされている間（中止済み・答えを待つ質問がある・予算の上限に達した、の3つの原因のそれぞれで）、質問欄は、送信のショートカットで質問を送ってはならない。
- **R-10（望まない振る舞い）**：R-1 か R-13 の条件で1件目を送り、その送信が終わる前（ボタンの表示が「送っています…」から戻る前）に、送信のショートカットの入力がさらに1回以上届いた場合（続けて押す・キーを押し続けたときの連続入力）、質問欄は、デーモンへの質問の要求を1件だけにしなければならない。
- **R-11（望まない振る舞い）**：送信のショートカットで送った質問が、デーモンにつながらない、またはデーモンが断ったために記録されなかった場合、質問欄は、送信に失敗したときの結果にしなければならない。
- **R-12（望まない振る舞い）**：質問欄と「質問する」ボタンのどちらにもフォーカスが無いとき（パネルの中の閉じるボタン・答えの中のリンク、パネルの外の要素）に送信のショートカットを押した場合、質問欄は、質問を送ってはならない。

## 範囲

**変えないもの**

- 対象は、オーケストレーターへの質問欄だけ。新しいタスク・差し戻しのコメントなど、ほかの複数行の入力欄の Enter・Ctrl + Enter・⌘ + Enter の振る舞いは変えない（Q-4）。
- 質問の規則（2,000 文字の上限・答えを待つ質問は1件まで・ブロックされる条件）と、デーモンの質問の API は変えない。
- 「質問する」ボタンでの送信は、いまどおり使える。ボタンにフォーカスがあるときのキー操作も、いまどおりブラウザの振る舞いに任せる。
- 2,000 文字の上限に達したときは、いまどおり Enter・Shift + Enter でも改行が入らない。
- ブロック中と送っている途中は、いまどおり質問欄とボタンを無効にする。
- ショートカットとボタンを続けて使ったときの二重送信は、いまのボタンの扱い（送っている途中は両方を無効にする）に任せる。
- 送信のショートカット・Enter・Shift + Enter 以外の Enter の組み合わせで質問欄に何が入るかは、ブラウザの振る舞いに任せる。送らないことだけを R-15 で求める。
- 変換中のキー操作で変換を確定するかどうかは、入力方式の振る舞いに任せる。

**受け入れの確かめ方**

- R-9：無効の質問欄にはフォーカスを置けない。このため、ブロック中のパネルで閉じるボタンとパネルの外の要素にフォーカスを置き、3つの原因のそれぞれで確かめる。答えの中のリンクは、答えにリンクがあるときだけ対象にする。
- R-10：デーモンの応答を遅らせて「送っています…」の状態を保つ。そのうえで、質問欄が無効になる前（キーの連続入力）と、無効になった後の両方で、2回目以降の入力を届けて確かめる。
- R-6：少なくとも macOS の標準の日本語入力と、Windows の Microsoft IME で確かめる。
- OS やウィンドウマネージャーが先に受け取り、ブラウザに届かないキーの組み合わせ（Windows の Windows キー + Enter など）は、確かめる対象から外す。

## 確認したいこと

- **Q-1**：Shift + Enter も送信にするか。タスクの候補には挙がっているが、Slack・ChatGPT などの一般的なチャットでは、Shift + Enter は「改行」の意味で使われることが多い。この文書は、Shift + Enter を改行のままにする前提で書いた。送信にするなら、次を直す。
  - 「何を実現するか」と、用語の「送信のショートカット」に Shift + Enter を足す
  - R-4 を、R-1・R-13 と同じ形の送信の要求に差し替える
  - R-15 と、範囲の上限の行から Shift + Enter を外す
  - R-5 に Shift + Enter を足す
  - R-10・R-14 の条件「R-1 か R-13 の条件で」を「R-1・R-13・R-4 のどれかの条件で」にする
  - 用語「質問を送ってはならない（合否の決め方）」の補足から Shift + Enter と R-4 を外す
- **Q-2**：送信のショートカットを OS で分けるか。この文書は、OS を問わず Ctrl + Enter と ⌘ + Enter の両方を受け付ける前提にした。macOS では ⌘ + Enter だけにする案もある。なお Windows では、Windows キー + Enter を OS が先に受け取り、ブラウザに届かないことがある。
- **Q-3**：画面にショートカットを案内するか（入力欄の下の補足文、ボタンにカーソルを合わせたときの説明）。案内するなら、次も決めたい。
  - macOS では「⌘ + Enter」、それ以外では「Ctrl + Enter」と表記を分けるか
  - 画面の文言の規則（docs/spec/ui-wording.md）に沿って、本文と補足（hint）のどちらに置くか
  - なお、日本語・英語の両方の文言と、ユーザードキュメントのスクリーンショット（task-chat.png・task-chat.en.png）の撮り直しも要る
- **Q-4**：ほかの複数行の入力欄（新しいタスク・差し戻しのコメント）にも、同じショートカットを入れるか。この文書は、質問欄だけを対象にした。
- **Q-5**：修飾キーの無い Enter で送る形（Enter で送り、Shift + Enter で改行）に変えたいか。タスクの候補には無い。長い質問やログの貼り付けを想定した欄なので、この文書は Enter を改行のままにした。
- **Q-6**：送った後のフォーカスの位置を決めるか。ショートカットで送ると、送っている間に質問欄が無効になり、フォーカスが質問欄から外れる。送信に失敗して質問が残る場合も、フォーカスは自然には戻らない。
  - 送信に失敗したとき：キーボードだけで直して送り直せるよう、フォーカスを質問欄に戻すか
  - 送信に成功したとき：答えを待つ間は質問欄が無効になる。フォーカスをどこに置くか（いまどおりでよいか）
- **Q-7**：改行を含む 2,000 文字の質問の扱い。送るときに改行が2文字に数えられ、デーモンの上限（2,000 文字）を超えて断られる可能性がある。これは推測で、ボタンで送っても同じため、いまからある問題の候補。この文書は、R-14 を改行を含まない質問に限った。直すなら、別のタスクにするか、この範囲に入れるかを決めたい。
