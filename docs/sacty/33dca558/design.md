# 設計：タスクの作成時に複数のリポジトリを指定する

## スコープ

作成の入力に、リポジトリの一覧 `repos` を足す。
2件以上を指定したタスクは、いまのリポジトリの無いタスク（`noRepo`）として進め、リポジトリの候補を指定したものに絞り、親の要求要件・設計・分割の工程に各リポジトリのコードを渡す。

- 対象
  - packages/core：`CreateTaskInput`・`TaskCreated`・投影の `Task`、メッセージ（ja・en）
  - apps/daemon：作成の検査、候補の絞り込み（オーケストレーター・人の選択・分割・情報収集）、写しの用意、要求要件・設計の指示
  - apps/web：作成のダイアログ・`createTaskAction`、一覧・詳細の表示、再開のフォームの候補
  - docs：spec（tasks-and-steps・split-and-integrate）・user/tasks の ja・en、ADR、worklog
- 対象外
  - 一覧の絞り込みのリポジトリの選択肢（指定したタスクは、いまどおり「リポジトリ無し」に入る）
  - 子タスクと統合レビューの処理（いまのリポジトリの無い親の処理のまま動く）

## 確認したいこと

### must

なし

### should

- S-1：工程ごとに渡すコードを、その実行の時点のベースブランチの最新にするか（読んだコミットを固定しない）。
  - 推奨：最新にする。
    子タスクもベースブランチの最新から始まり、親が読むコードと揃うため。
  - 懸念：要求要件の後にベースブランチが進むと、設計の工程が要求要件と違うコードを読み、人は要求要件がどのコミットに基づくかを作業履歴から辿れない。

## 既定で決めたこと

- `repos` は1件以上の文字列の配列にし、空の配列は入力の誤りとして断る（リポジトリ無しは、いまどおり `repo: null`）。
- 候補は作成時に記録した `repos` を使い、使う時点でこのプロジェクトの対象から外れたリポジトリは除く。
- 一覧と詳細では、指定したタスクに「リポジトリ無し」の印を出さず、指定したリポジトリを並べる。
- 読んだコミットは指示に書くだけにし、作業履歴のイベントには記録しない（S-1 で固定するなら記録を足す）。

## データ

| 場所 | 変更 |
| --- | --- |
| `CreateTaskInput` | `repos?: string[]`（各要素は trim・1文字以上）を足す。件数の上限は重複を除いた後にデーモンが数える |
| `TaskCreated` | `repos?: string[]`（2〜10件、`noRepo: true` と一緒に持つ）を足す。無い作業履歴は、いまの意味のまま読む |
| `Task`（投影） | `repos?: string[]` を足す。`isRepoless` は変えない（`repo` が無いので真になる） |
| メッセージ | 対象に無い（`repo` を示す）・上限（10 を示す）・`repo` と `repos` の両方・指定に無い（オーケストレーター・分割・人の選択）・写しを用意できない（`repo` と理由） |

## 処理の流れ

- 作成（`prepareTask`）
  - `repo` と `repos` の両方があれば断る（R-15）。
  - `repos` の各要素を `projectRepository` で照らし、名前をそろえてから `repoKey` で重複を除く。対象に無い要素は、その名前を示して断る（R-13）。
  - 重複を除いて1件なら `repo` にその値を入れたときと同じ形（`repo` だけ。`repos` は持たない）、11件以上なら断る（R-9・R-14）。
- 候補（R-11）：`projectRepositories` を候補に使う4か所（オーケストレーター・`chooseRepository`・分割・情報収集）を、`repos` があればそれに置き換える関数に通す。
  - 情報収集は、`repos` があるとき「多くても3つ」の文を、指定したリポジトリをすべて読む文に替える。
  - web の再開のフォームの候補（task-detail-data.ts）も `repos` にする。
- 写し（R-10）：`repos` を持つタスクの要求要件・設計・分割の工程は、空の作業領域の代わりに、リポジトリごとに次を行う。
  - `<task>/repos/<dir>` に clone（初回だけ）し、既定のブランチを取得して、作業領域の `<dir>` に書き出す。
  - `<dir>` は統合レビューと同じ `repositoryDirName`（`1-owner__name`）。消すのはタスクの作業領域と同じ時。
  - 指示は、`REPOLESS_LINES` の代わりに、リポジトリ・ディレクトリ・ブランチ・コミットの一覧を渡す。
- 指示（R-12・R-18）：`repos` があるとき、次を足す。
  - 要求要件：各要求に、当たるリポジトリを示させる。
  - 設計：指定したリポジトリごとに「そのリポジトリで実装すること」の節を書かせる。
- 画面（R-2・R-20）
  - リポジトリの欄を配列の状態で持ち、「追加」「削除」のボタンを置く。欄の数の操作は apps/web/src/lib の純粋な関数にする。
  - 10個で追加を無効にし、1個のときは削除を出さない。テンプレートのときは欄を1つに固定する。
  - 欄はすべて `name="repo"` にし、`createTaskAction` が `getAll` で値のある欄を数えて、0件は `repo: null`、1件は `repo`、2件以上は `repos` で送る。

## エラー時の振る舞い

- 作成の断り（R-13〜R-15）：`InvalidOperationError` で返し、タスクを記録しない。
- 指定に無いリポジトリ（R-16）：いまの `repositoryFromPlan`・`splitWithRepositories` の止め方のまま、指定に無いことを示す文言にする。
- 人の選択（R-19）：`chooseRepository` が断り、`RepositoryChosen` を記録しない。
- 写しの失敗（R-17）：エージェントを実行せず、`AgentRunFailed`（リポジトリの名前と理由）と `TaskPaused` を記録する。再開すると用意し直す。

## 影響範囲

- 既存のリポジトリの無いタスクと単数の `repo` のタスクは、`repos` を持たないので、候補・写し・指示が変わらない（R-3・R-4）。
- docs：tasks-and-steps（タスクの作られ方・情報収集・オーケストレーター）、split-and-integrate（分割）、user/tasks（タスクを作る・API の例）の ja・en、ADR、worklog を直す。

## テスト観点

- [TV-1] 2件の指定で、リポジトリの一覧を持つリポジトリの無いタスクになる（R-1・R-7）
  - 入力：対象にリポジトリ A・B・C のあるプロジェクトで、`POST /api/tasks` に `repos: [A, B]` を渡す
  - 期待結果：201 で作られ、`TaskCreated` が `repos: [A, B]`・`noRepo: true` を持ち `repo` を持たず、投影の `isRepoless` が真になる
- [TV-2] 上限の10件まで作れ、重複は1つにまとめて数える（R-1・R-14）
  - 入力：異なる10件を渡す場合と、異なる10件に同じ URL を1つ重ねた11件を渡す場合
  - 期待結果：どちらも作られ、記録される `repos` はどちらも重複の無い10件になる
- [TV-3] 重複を除いて11件以上なら断る（R-14）
  - 入力：対象にある異なる11件を `repos` に渡す
  - 期待結果：400 で断られ、メッセージに上限の 10 があり、タスクが増えない
- [TV-4] 1件だけの指定は、単数の `repo` と同じタスクになる（R-9）
  - 入力：`repos: [A]` を渡す場合と `repo: A` を渡す場合
  - 期待結果：2つの `TaskCreated` の内容が、`repo: A` を持ち `noRepo`・`repos` を持たない同じ形になる
- [TV-5] 対象に無いリポジトリを含めると断る（R-13）
  - 入力：対象に無いリポジトリ X を含む `repos: [A, X]` を渡す
  - 期待結果：400 で断られ、メッセージに X の名前があり、タスクが増えない
- [TV-6] `repo` と `repos` を両方渡すと断る（R-15）
  - 入力：`repo: A` と `repos: [A, B]` を一緒に渡す
  - 期待結果：400 で断られ、メッセージがどちらか一方にするよう示し、タスクが増えない
- [TV-7] 単数の `repo` の入力は変更前と同じ意味になる（R-4）
  - 入力：対象がリポジトリ1つのプロジェクトで `repo` を省略・`null`・値ありで渡す
  - 期待結果：順に、そのリポジトリの `repo`・`noRepo: true`・指定した `repo` で作られ、どれも `repos` を持たない
- [TV-8] 変更前の形の作業履歴を同じ進め方で読む（R-3）
  - 入力：`repos` の無い、`repo` を持つ `TaskCreated` と `noRepo: true` の `TaskCreated` の作業履歴を読み込み、後者でオーケストレーターを動かす
  - 期待結果：前者は同じリポジトリのタスク、後者は `isRepoless` が真で、オーケストレーターの候補がプロジェクトの対象全体になる
- [TV-9] 要求要件・設計・分割の工程に、指定した各リポジトリのコードを渡す（R-10）
  - 入力：`repos: [A, B]` のタスクで、偽のリポジトリの操作で要求要件・設計・分割の工程を実行する
  - 期待結果：各実行の作業領域に A・B の既定のブランチのコミットが別のディレクトリに書き出され、指示に A・B とそのディレクトリ・コミットが載り、「作業領域は空」の文が無い
- [TV-10] コードを用意できなければ、工程を止めてリポジトリの名前を示す（R-17）
  - 入力：`repos: [A, B]` のタスクで、偽のリポジトリの操作が B の clone に失敗する
  - 期待結果：エージェントが実行されず、`AgentRunFailed` のメッセージに B の名前があり、タスクが paused になる
- [TV-11] オーケストレーターと分割の候補を指定したものだけにする（R-11）
  - 入力：対象に A・B・C のあるプロジェクトで `repos: [A, B]` のタスクのオーケストレーターと分割の指示を組み立てる
  - 期待結果：どちらの候補の一覧にも A・B だけが載り、C が載らない
- [TV-12] 情報収集は、指定したリポジトリだけを、すべて読ませる（R-11）
  - 入力：対象に A・B・C・D のあるプロジェクトで `repos: [A, B, C, D]` のタスクの情報収集の指示を組み立てる
  - 期待結果：候補に A〜D だけが載り、すべてを読む指示があって「多くても 3 つ」の文が無い
- [TV-13] オーケストレーターが指定に無いリポジトリを選ぶと止める（R-16）
  - 入力：対象に A・B・C、`repos: [A, B]` のタスクで、偽のオーケストレーターが REPO_PLANS と `repo: C` を答える
  - 期待結果：`RepositoryChosen` が記録されず、タスクが paused になり、メッセージに C の名前がある
- [TV-14] 分割の子のリポジトリが指定に無いと、子を作らずに止める（R-16）
  - 入力：`repos: [A, B]` のタスクで、偽の分割の答えの子の1つが `repo: C`（プロジェクトの対象にある）を持つ
  - 期待結果：子タスクが作られず、タスクが paused になり、メッセージに子の key と C の名前がある
- [TV-15] 分割は、一部のリポジトリだけ・同じリポジトリに複数の子を作れる（要求要件の S-1 の推奨）
  - 入力：`repos: [A, B, C]` のタスクで、偽の分割の答えが2つの子をどちらも `repo: A` にする
  - 期待結果：2つの子タスクが作られ、どちらの `TaskCreated` も `repo: A` を持つ
- [TV-16] 止まったタスクで、人が指定に無いリポジトリを選ぶと断る（R-19）
  - 入力：対象に A・B・C、`repos: [A, B]` の paused のタスクで `chooseRepository` に C を渡す
  - 期待結果：メッセージに C の名前のあるエラーで断られ、`RepositoryChosen` が記録されず、タスクが paused のまま
- [TV-17] 再開のフォームのリポジトリの候補が、指定したものだけになる（R-11）
  - 入力：対象に A・B・C、`repos: [A, B]` の paused のタスクの詳細のデータを組み立てる
  - 期待結果：再開のフォームの候補が A・B だけになる
- [TV-18] 設計の指示が、リポジトリごとに実装することの節を求める（R-12）
  - 入力：`repos: [A, B]` のタスクと、`repos` の無いリポジトリの無いタスクの設計の指示を組み立てる
  - 期待結果：前者には A・B それぞれで実装することの節を書く指示があり、後者には無い
- [TV-19] 要求要件の指示が、各要求のリポジトリを示すよう求める（R-18）
  - 入力：`repos: [A, B]` のタスクと、`repos` の無いリポジトリの無いタスクの要求要件の指示を組み立てる
  - 期待結果：前者には各要求が A・B のどれに当たるかを示す指示があり、後者には無い
- [TV-20] 一覧と詳細に、指定したリポジトリをすべて出す（R-8）
  - 入力：`repos: [A, B]` のタスクの一覧の行と詳細を ja・en で描画する
  - 期待結果：どちらにも A・B の名前が出て、「リポジトリ無し」（en は対応する文言）の印が出ない
- [TV-21] リポジトリの欄を複製・削除でき、10個で複製できない（R-2）
  - 入力：欄の数を扱う関数で1個から追加を繰り返し、途中で削除し、ダイアログを ja・en で描画する
  - 期待結果：追加で欄が1つ増え、削除で1つ減り、10個で追加が無効になり、1個のときは削除が無く、追加・削除のボタンの文言が ja・en で出る
- [TV-22] 値のある欄の数で、作成の入力が決まる（R-20）
  - 入力：空の欄を1つ含め、値のある欄を0・1（A）・2（A・B）件にしたフォームを `createTaskAction` に送る
  - 期待結果：デーモンへの入力が順に `repo: null`・`repo: A`・`repos: [A, B]` になる
- [TV-23] テンプレートで作るときは欄が1つで、空欄なら省略する
  - 入力：対象がリポジトリ1つのプロジェクトで、テンプレートを選んだダイアログを描画し、リポジトリを空欄で送る
  - 期待結果：追加のボタンが無く、デーモンへの入力に `repo` が無く、作られたタスクの `repo` がそのリポジトリになる
- [TV-24] docs に複数を指定したタスクの作り方と進み方がある（R-5）
  - 入力：docs/spec/tasks-and-steps・split-and-integrate と docs/user/tasks の ja・en の差分
  - 期待結果：`repos` の入力と検査（1件・上限 10・重複・両方の指定・対象外）、候補の絞り込み、工程へのコードの渡し方、ダイアログの欄の複製、`repos` を使う API の例が両方の言語にあり、`npx vitest run tests/docs` が通る
- [TV-25] ADR と worklog がある（R-6）
  - 入力：docs/adr と docs/worklog の差分
  - 期待結果：作成時に複数のリポジトリを指定し、リポジトリの無いタスクの進め方で候補を絞る方針の ADR と、このタスクの worklog が、規則どおりの名前と先頭の項目で足されている
