# 要求要件：sacty mcp に成果物とログの取得を足す（PBI-395）

## スコープ

`sacty mcp` に、読み取りだけのツールを足す。
これで、手元の AI が、タスクの工程ごとの成果物と、エージェントの実行の一覧・ログを、画面を開かずに読めるようにする。

- 対象
  - MCP サーバー（`apps/daemon/src/task-mcp.ts`・`packages/cli/src/mcp.ts`）へのツールの追加
  - 成果物は、画面のタスクの詳細で読める範囲（工程ごとに、承認済みならその版、まだなら最新の出力。レビューの工程は本文と行へのコメント）
  - 実行は、画面でログへのリンクがある実行のすべて（工程・オーケストレーター・ガーディアン・書き出し・監査など）
  - 要求を満たすのに要るデーモンの API の追加（画面の動きは変えない）
  - 仕様書・ユーザードキュメント（日英）、CLI の使い方の表示、作業履歴、ADR
- 対象外
  - 承認・差し戻し・中止などの操作、状態の変化を待つこと、対応待ちの一覧
  - 人への問いの取り出し。作業履歴（イベント）の中身・エラーレポート・PR の差分の取得
  - 差し戻し前の過去の回の成果物と、エージェントの元のファイル（agent-files）
  - 画面の表示の変更と、いまの5つのツールの引数・結果の変更

## 確認したいこと

### must

なし

### should

なし

### 確認しないと決めたこと

- 終わった実行のログを範囲で読む方法（API を足すか、MCP の側で読み捨てるか）：設計で決める。
  依頼が、API を足すかどうかを実装に任せているため。
- 前の版のデーモンが返す 404 と「タスクが無い」の区別：R-21 で求め、方法は設計で決める。
  どう振る舞うかは、依頼の条件 7 で決まっているため。
- 上限の単位、続きの位置の示し方、ログを返す形、実行の一覧の元：設計と ADR で決める。
  依頼が、実装の手段として任せているため。
- テスト観点：依頼の条件 9 に挙がった場合をそのまま使う。

## 既定で決めたこと

- 工程の名前が工程の候補に無いときは理由を返す。
  候補にあって成果物がまだ無いときは、空の結果を返す（条件 1 と 4 を両立させるため）。
- 範囲の指定は、負と0の量なら理由を返し、上限を超える量なら上限に収め、全体の大きさ以上の位置なら0の量を返す（R-22・R-26・R-27）。
  全体以上の位置を失敗にしないのは、実行中のログを続きから読み直すときに、まだ増えていないことを失敗と区別するため。

## 要求

主語の「MCP サーバー」は `sacty mcp` を指す。
「新しいツール」は、今回足すツールのすべてを指す。

| ID | トリガー | システム | 応答 |
| --- | --- | --- | --- |

## 受け入れの確かめ方

### 自動のテストで確かめること

- `npm run lint`・`npm run format`・`npm run typecheck`・`npx vitest run --no-file-parallelism` が通る。
- 新しいツールのテストが、依頼の条件 9 の場合を含む。
  空・1件・やり直した工程・上限ちょうどと1超え・大きなログ・複数バイトの境目・無いタスクとほかのタスクの実行・決まった場所の外・伏せる値が境目をまたぐ・デーモンにつながらない・前の版のデーモン。
- 実行の途中で足した秘密情報が、実行中のログの結果に出ない。先頭の上限を超えた実行中のログの末尾を読める。
- 20MB のログで、デーモンが読んだ量と MCP サーバーが受け取った量が、返す量に一定の幅を足した量に収まる。
- レビューの行へのコメント・まだ提出していない出力・工程でない実行・終わりが記録されていない実行・件数の上限を超える一覧を含む。
- 「どのツールも理由を返す」のテストに、新しいツールが入っている。

### 人が確かめること

- Claude Code と Codex から新しいツールを呼び、成果物とログを読める。
  クライアントが結果の型を受け付けないと、依頼した人の手元の AI で今回のツールが使えません。
