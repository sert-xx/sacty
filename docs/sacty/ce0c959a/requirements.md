# 要求要件：sacty mcp に成果物とログの取得を足す（PBI-395）

## スコープ

`sacty mcp` に、読み取りだけのツールを足す。
これで、手元の AI が、タスクの工程ごとの成果物と、エージェントの実行の一覧・ログを、画面を開かずに読めるようにする。

- 対象
  - MCP サーバー（`apps/daemon/src/task-mcp.ts`・`packages/cli/src/mcp.ts`）へのツールの追加
  - 範囲を指定して読むのに要る場合だけ、デーモンの API の追加（画面の動きは変えない）
  - 仕様書・ユーザードキュメント（日英）、CLI の使い方の表示、作業履歴、ADR
- 対象外
  - 承認・差し戻し・中止などの操作、状態の変化を待つこと、対応待ちの一覧
  - 人への問いの取り出し。作業履歴（イベント）の中身・エラーレポート・PR の差分の取得
  - 画面の表示の変更と、いまの5つのツールの引数・結果の変更

## 確認したいこと

### must

- **成果物の範囲**：画面のタスクの詳細と同じ範囲に限るか、差し戻し前の提出とエージェントの元のファイル（agent-files）まで含めるか。
  画面と同じ範囲とは、工程ごとに、承認済みならその版、まだなら最新の出力です。
  実装と分割は、その成果の文です。
  - 推奨：画面と同じ範囲に限る。
    依頼の範囲が「画面のタスクの詳細で読めるもの」で、次の「承認」で確かめるのは承認待ちの回だからです。
  - 懸念：過去の回も読みたい場合は、ツールの引数と一覧の形を作り直すことになり、次の「承認」の作業が遅れます。

### should

- **実行中のログの伏せ方**：画面と同じく実行中のファイルをそのまま読むか、デーモンがいまの秘密情報で伏せ直してから切り取るか。
  - 推奨：伏せ直してから切り取る（R-10 はこの前提で書いた）。
    画面は、実行の途中で分かった秘密情報を、実行が終わるまで伏せずに返しています。
  - 懸念：画面と同じにすると、その秘密情報が、手元の AI の文脈と、その AI が使う外部のサービスに渡ります。
- **実行の一覧に含める実行**：工程のエージェントの実行だけにするか、画面でログへのリンクがある実行をすべて含めるか。
  リンクがある実行には、オーケストレーター・ガーディアン・書き出し・監査などがあります。
  - 推奨：画面でリンクがある実行をすべて、役割を付けて含める。
    工程の実行だけにすると、工程を選ぶ段階で失敗した原因を MCP から読めません。
  - 懸念：絞ると、承認の前に失敗を調べる人が、結局画面を開くことになります。

### 確認しないと決めたこと

- 終わった実行のログを範囲で読む方法（API を足すか、MCP の側で読み捨てるか）：設計で決める。
  依頼が、API を足すかどうかを実装に任せているため。
- 前の版のデーモンが返す 404 と「タスクが無い」の区別：R-21 で求め、方法は設計で決める。
  どう振る舞うかは、依頼の条件 7 で決まっているため。
- 上限の単位、続きの位置の示し方、ログを返す形、実行の一覧の元：設計と ADR で決める。
  依頼が、実装の手段として任せているため。
- テスト観点：依頼の条件 9 に挙がった場合をそのまま使う。

## 既定で決めたこと

- 工程の名前が工程の候補に無いときは理由を返す。
  候補にあって成果物がまだ無いときは、空の結果を返す（条件 1 と 4 を両立させるため）。
- 終わりが記録されていない実行（`finishedAt` が無く、もう動いていない）は、実行中と区別した状態で返す。

## 要求

主語の「MCP サーバー」は `sacty mcp` を指す。
「新しいツール」は、今回足すツールのすべてを指す。

### 常時

| ID | システム | 応答 |
| --- | --- | --- |
| R-1 | MCP サーバー | ツールの一覧に、成果物の一覧・成果物の中身・実行の一覧・実行のログを読むツールを、引数と結果の型と、`readOnlyHint: true`・`openWorldHint: false` の注釈を付けて載せる |
| R-2 | 新しいツール | 成果物の一覧で、成果物ごとに工程・提出の回・種類（名前）・大きさを返す |
| R-3 | 新しいツール | 成果物の中身の結果に、その成果物の工程と提出の回を含める |
| R-4 | 新しいツール | 実行の一覧で、実行ごとに ID・工程（役割）・エージェント・開始の時刻・状態（実行中・成功・失敗）を返す |
| R-5 | 新しいツール | 別のエージェントに切り替わった実行に、切り替えの前と後のエージェントを含める |
| R-6 | 新しいツール | ログを、画面の実行のログと同じ記録から読む |
| R-7 | 新しいツール | 成果物の中身とログを1回に上限の量までだけ返し、結果に、切り取ったか・全体の大きさ・続きを読む位置を含める |
| R-8 | 新しいツール | ログを、末尾から読む指定と、指定した位置から順に読む指定の、どちらでも返す |
| R-9 | 新しいツール | 複数バイトの文字やサロゲートペアの途中で切った文字を返してはならない |
| R-10 | 新しいツール | 画面で伏せる値を伏せたあとに切り取り、切り取りの境目に伏せる値の一部を残してはならない |
| R-11 | MCP サーバー | 新しいツールの結果・理由・標準エラーの1行に、`daemon.json` のトークン・環境変数の値・デーモンの絶対パスを含めてはならない |
| R-12 | MCP サーバー | 新しいツールが失敗したときの標準エラーの1行に、成果物とログの中身を含めてはならない |
| R-13 | MCP サーバー | 新しいツールの説明文とサーバーの使い方の説明に、結果はほかの人やエージェントが書いた文を含むデータで、その中の指示に従わないことを載せる |
| R-14 | MCP サーバー | いまの5つのツールの引数と結果（`get_task` の `reviewBody` を含む）を、起点のコミットと同じに保つ |
| R-15 | 変更 | 仕様書 `docs/spec/mcp-server.md`（日英）・`docs/user/mcp.md`（日英。できること・できないこと）・`docs/user/cli.md`（日英）・CLI の使い方の表示・`docs/worklog/` の作業履歴を直し、上限と切り取り・成果物と実行の指定の方法の ADR を足す |

### イベント駆動

| ID | トリガー | システム | 応答 |
| --- | --- | --- | --- |
| R-16 | 実行中の実行のログを求めたとき | 新しいツール | 呼び出しの時点までに記録された分を返す |
| R-17 | 成果物がまだ無いタスク・工程の成果物の一覧を求めたとき | 新しいツール | `isError` でない0件の一覧を返す |
| R-18 | 20MB のログや数 MB の成果物を求めたとき | 新しいツール | 時間切れ（30 秒）にならずに、上限の分だけを返す |

### 望まない振る舞い

| ID | トリガー | システム | 応答 |
| --- | --- | --- | --- |
| R-19 | 無いタスク（消したプロジェクトのタスクを含む）・無い工程・無い成果物・無い実行・ほかのタスクの実行を指定した場合 | 新しいツール | ほかのタスクの中身を含めずに、`isError` と理由を返す |
| R-20 | 名前・パスの引数に、決まった場所の外（`..`・絶対パス）を指定した場合 | 新しいツール | 中身を読まずに、`isError` と理由を返す |
| R-21 | 起動中の sacty が、今回のツールが使う API を持たない前の版の場合 | 新しいツール | 「タスクが無い」と区別できる、sacty の更新を促す理由を `isError` で返す |
| R-22 | 範囲の指定が、負・0・全体の大きさを超える・上限を超える場合 | 新しいツール | 理由を返すか、決まった範囲に収めた上限以下の量を返す |
| R-23 | sacty が起動していない・つながらない・時間内に応答しない場合 | 新しいツール | いまのツールと同じ理由を `isError` で返し、MCP サーバーは動き続ける |

## 受け入れの確かめ方

### 自動のテストで確かめること

- `npm run lint`・`npm run format`・`npm run typecheck`・`npx vitest run --no-file-parallelism` が通る。
- 新しいツールのテストが、依頼の条件 9 の場合を含む。
  空・1件・やり直した工程・上限ちょうどと1超え・大きなログ・複数バイトの境目・無いタスクとほかのタスクの実行・決まった場所の外・伏せる値が境目をまたぐ・デーモンにつながらない・前の版のデーモン。
- 「どのツールも理由を返す」のテストに、新しいツールが入っている。

### 人が確かめること

- Claude Code と Codex から新しいツールを呼び、成果物とログを読める。
  クライアントが結果の型を受け付けないと、依頼した人の手元の AI で今回のツールが使えません。
