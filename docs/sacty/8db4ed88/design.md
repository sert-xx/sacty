# 設計：整形だけで変わったファイルを PR に入れない（PBI-484）

## スコープ

実装・修正の工程の提出を PR に入れる前に、sacty が起点と構文木を比べ、整形だけで変わったファイルを起点の内容に戻す。
指示でも、リポジトリの設定の外での整形と、依頼の外のファイルの整形を止める。

- 対象
  - 指示：`apps/daemon/src/prompts.ts` の `implementVerificationLines`（実装・修正・直しの回・セキュリティ対応・文書だけの依頼の提出に共通）
  - 検査と書き戻し：`apps/daemon/src/formatting-only.ts`（新規）、`service.ts` の検証待ちの処理と `publish`・`publishContinued`
  - 申告の読み取り：`prompts.ts` の `extractBlocks`
  - 記録・表示：`packages/core` の `FinalReviewSkipped`・投影、PR の本文、Web のタスクの詳細
  - 文書：`docs/spec/tasks-and-steps`・`approval`・`event-log`（日英）、`docs/user/tasks`（日英）、作業履歴
- 対象外
  - JavaScript・TypeScript・JSON 以外の言語のファイル（R-7 で戻さない）
  - 引用符・セミコロン・括弧の付け外しなど、空白・改行・末尾のカンマ以外の整形（R-18 で整形だけとみなさない）

## 確認したいこと

### must

なし

### should

- Q-1：構文の解析に、`@babel/parser` をデーモンの実行時の依存に足してよいか。
  推奨：足す。`typescript` は開発時の依存で、デーモンの実行時に無いため。
  懸念：依存を増やしたくない場合、検査の実装を別の解析器で作り直す手間が増えます。
- Q-2：検査する言語を、JavaScript・TypeScript（JSX を含む）・JSON に限ってよいか（要求要件の S-1 の「解析できる言語」の範囲）。
  推奨：限る。PR #539・#524・#542 の膨らみはどれも TypeScript で、1つの解析器で扱えるため。
  懸念：CSS・Markdown・Python などの整形だけの変更は、検査で戻らず PR に残ります。
- Q-3：引用符（`'a'` と `"a"`）・セミコロン・括弧の付け外しを、整形だけとみなさずに残してよいか。
  推奨：残す。R-18 が除くのは位置と区切りの空白・改行・末尾のカンマだけのため。
  懸念：prettier の既定などで引用符まで変えたファイルは、検査で戻らず PR に残ります。

## 既定で決めたこと

- 検査の候補は、起点にあって内容だけが変わったファイル。追加・削除・名前の変更・モードの変更を含むものは戻さない。
- 申告は、そのタスクの実装の工程のすべての回のものを合わせて使う（直しの回で申告し直さなくても残る）。
- 差分やファイルを読めないときは、止めずに、そのファイルを戻さずに進める（R-7。セキュリティ対応の範囲の検査のように止めない）。
- 戻したファイルと申告の一覧は、PR の本文に載るときも、タスクの詳細に表示する。
- `.jsonc` は、コメント・末尾のカンマを許すかがツールで違うので検査しない（R-7 で戻さない）。

## 構成

| 所 | 変更 |
| --- | --- |
| `formatting-only.ts`（新規） | 起点と提出の内容から、整形だけかを返す（下の「判定」） |
| `service.ts` 検証待ち | `conflictsResolved` の後・`checkSecurityScope` の前に検査する。結果を `FinalReviewSkipped` に記録してから、戻すファイルに起点の内容を書く |
| `service.ts` `publish`・`publishContinued` | PR の先頭の取り込みの後・作業領域を載せる前に、戻すファイルのうち、内容が記録した提出の内容のままのものにだけ起点の内容をもう一度書く（記録の後・書き戻しの前に止まって再開したときの戻し漏れを防ぐ）。内容が変わったもの（取り込んだ人の変更など）は書かずにそのまま載せる |
| `prompts.ts` 指示 | R-1・R-2・R-15 の文と、申告の形 `{"sacty-formatting":{"files":[{"path":"…","reason":"…"}]}}` を足す |
| `prompts.ts` `extractBlocks` | 実装の工程だけ申告を読み、`AgentRunCompleted` に `formatting` として記録する |
| `prompts.ts` PR の本文 | 節「整形だけで戻したファイル」（R-4）と「依頼で求められた整形」（R-13。パスと理由）を足す。引き継いだ PR の本文は今までどおり変えない（R-16） |
| Web のタスクの詳細 | 実装の節に、上の2つの一覧を表示する（R-14・R-16）。文言は日英 |

## データ

- `FinalReviewSkipped.payload.formatting`（任意）：`reverted: {path, submitted}[]`（`submitted` は提出の内容の git の blob の ID）・`declared: {path, reason}[]`。前の版は読まずに捨てる（event-log に書く）。
- 投影 `Task.formattingCheck`：提出ごとに最後の `FinalReviewSkipped` の値で置き換える。
- 申告の理由は伏せの後に 300 文字で切る。パスは `validPath` を通らないもの・差分に無いものを捨てる。

## 判定（R-12・R-17・R-18）

- 拡張子で解析の仕方を決める：`.ts`・`.mts`・`.cts` は typescript、`.tsx` は typescript と jsx、`.js`・`.jsx`・`.mjs`・`.cjs` は jsx で解析する。`.json` は、起点と提出の両方が `JSON.parse` を通るときだけ、式として解析する（末尾のカンマ・コメントを含む JSON は通らないので R-7）。
- 起点と提出の両方を解析し、構文木を比べる。除くのは位置（`start`・`end`・`loc`・`range`）と、括弧・末尾のカンマの位置（`extra.parenStart`・`extra.trailingComma`）だけ。
  - 文字列・テンプレート・正規表現・数値の `extra.raw`、JSX のテキストの値は比べる（引用符・中の空白の違いで別になる）。
  - コメントは、種類と中身を順に比べる。
- どちらかが解析できない・テキストでない（NUL を含むなど）・読めないときは、整形だけとみなさない（R-7）。

## 影響範囲

- 戻したファイルは、作業領域でも起点の内容になる（後の直しの回・PR のレビューも戻した後を見る）。
- 全部戻ると、既存の `NothingToCommitError` の扱いで変更なしになる（R-14）。PR を作った後の直しなら、今までどおり止まる。
- 作業履歴には、原因と再現のコマンド・結果を書く（候補：作業領域の外の写しへの `npx biome format`、依存に無い `npx prettier`）。

## テスト観点

- [TV-1] 整形だけのファイルを戻し、整形以外の変更のファイルは整形ごと残す（R-3・R-4・R-6）
  - 入力：合成の git の作業領域で、依頼の外の a.ts を行幅 80 で折り返しただけにし、b.ts に関数を1つ足しつつ同じファイルの別の行も折り返して、申告なしで提出する
  - 期待結果：PR に入る差分は b.ts だけで、b.ts の折り返しも残り、PR の本文の「整形だけで戻したファイル」に a.ts が載り、検査を外すとこのテストが落ちる
- [TV-2] 整形だけのファイルが無い提出は差分を変えない（R-5）
  - 入力：b.ts にだけ整形以外の変更がある提出
  - 期待結果：PR に入る差分が検査の前と同じで、PR の本文に「整形だけで戻したファイル」の節が無い
- [TV-3] 整形だけか確かめられないファイルは戻さない（R-7）
  - 入力：インデントだけを変えた x.py、構文の誤りがある c.ts、末尾のカンマだけを足した d.json、NUL を含むファイル、読めないファイルを含む提出
  - 期待結果：どのファイルも PR に入り、一覧に載らない
- [TV-4] 申告した整形だけのファイルは戻さない（R-13）
  - 入力：整形だけの a.ts を sacty-formatting で理由を添えて申告した提出
  - 期待結果：a.ts が PR に入り、PR の本文の「依頼で求められた整形」に a.ts のパスと申告の理由が載る
- [TV-5] 前の回の申告は直しの回でも効く
  - 入力：1回目の実装で a.ts を申告し、直しの回では申告を書かずに提出する
  - 期待結果：a.ts が戻らずに PR に残る
- [TV-6] 構文木が変わる空白・改行・カンマの差は戻さない（R-12・R-17）
  - 入力：それぞれ1か所だけを変えた提出：文字列の `New York` を `NewYork`、`return x` の直後に改行、JSX のテキストの空白、テンプレートの中の改行、正規表現の中の空白、`[a, , b]` の空きのカンマを消す、コメントの中身、引用符を `'` から `"` に
  - 期待結果：どのファイルも戻らずに PR に入る
- [TV-7] 区切りの空白・改行と末尾のカンマだけの差は戻す（R-18）
  - 入力：引数の区切りの改行・オブジェクトの複数行化・インデント・末尾のカンマの追加だけを変えた .ts・.tsx・.js のファイルと、改行とインデントだけを変えた .json のファイル
  - 期待結果：どのファイルも起点の内容に戻る
- [TV-8] 全部戻ると変更なしとして扱う（R-14）
  - 入力：整形だけのファイルしか無い、申告の無い、PR をまだ作っていない提出
  - 期待結果：PR を作らずに NoChangesFound が記録され、タスクの詳細に戻したファイルのパスが表示される
- [TV-9] 引き継いだ PR の題・本文を変えない（R-16）
  - 入力：既存の PR を引き継いだタスクで、整形だけのファイルと申告したファイルを含む提出
  - 期待結果：PR の題・本文が提出の前と同じで、タスクの詳細に戻したファイルと申告（パスと理由）が表示される
- [TV-10] 記録の後・書き戻しの前に止まっても戻し漏れが無い
  - 入力：formatting を記録した FinalReviewSkipped の後、作業領域の a.ts が記録した提出の内容のままの状態で publish を実行する
  - 期待結果：PR に入るコミットの a.ts が起点の内容になっている
- [TV-11] 検査の後に取り込んだ人の変更を書き戻しで消さない（R-6）
  - 入力：formatting で a.ts を戻すと記録した後、PR のブランチに人が足した a.ts の変更を publish の先頭の取り込みで作業領域に入れる
  - 期待結果：PR に入るコミットの a.ts が、人の変更を含む取り込み後の内容のままになっている
- [TV-12] 差分を取れないときは止めずに進める
  - 入力：diffStats が失敗する偽の repos で提出する
  - 期待結果：TaskPaused を記録せずに PR の作成へ進み、どのファイルも戻さない
- [TV-13] 実装・修正の工程の指示に整形の決まりがある（R-1・R-2・R-15）
  - 入力：通常の実装・修正・文書だけの依頼・セキュリティ対応のタスクの実装の指示（prompts.test.ts）
  - 期待結果：どの指示にも、整形はリポジトリが定めるコマンドと設定でだけ行い、ほかのツール・依存に無いものを npx で取るもの・ほかの設定・作業領域の外の写しで整形しないこと、依頼で変えたファイルの外が整形だけで変わったら戻してから提出すること、依頼が整形を求めるときは sacty-formatting でパスと理由を申告することが書かれている
- [TV-14] 作業履歴に原因と根拠がある（R-9）
  - 入力：docs/worklog/ に足した PBI-484 の作業履歴の差分
  - 期待結果：原因と、それを再現したコマンドとその結果が書かれている
- [TV-15] 仕様書が指示と検査に一致する（R-10）
  - 入力：docs/spec/tasks-and-steps・approval・event-log（日英）の差分
  - 期待結果：「提出の前の検証」に R-1・R-2・R-15 の指示が、検査の判定・戻す対象・申告の扱い・止めずに進む条件・publish で内容が変わったファイルを書き戻さないことが、PR の本文の形に2つの節と引き継いだ PR では変えないことが、event-log に FinalReviewSkipped の formatting と前の版の扱いが書かれている
- [TV-16] ユーザー文書に戻す動作がある（R-11）
  - 入力：docs/user/tasks（日英）の差分
  - 期待結果：整形だけで変わったファイルを戻すこと、申告した整形は残ること、戻したファイルが PR の本文（引き継いだ PR と PR を作らないときはタスクの詳細）に載ることが書かれている
