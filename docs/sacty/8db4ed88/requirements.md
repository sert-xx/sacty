# 要求要件：実装の担当が、依頼と関係ないファイルを整形して差分を膨らませないようにする（PBI-484）

## スコープ

実装・修正の工程で、整形だけで変わったファイルを PR に入れないようにする。
sacty が提出の差分を検査して、そのようなファイルを戻し、指示でも防ぐ。担当が依頼で求められたと申告した整形と、整形だけと安全に判定できない変更は残す。

- 対象
  - 実装の担当への指示（`apps/daemon/src/prompts.ts` の「提出の前の検証」）
  - 提出の後、PR に入れる前の差分の検査
  - 仕様書 `docs/spec/tasks-and-steps`・`docs/spec/approval`、ユーザー文書 `docs/user/tasks`（日英）、作業履歴
- 対象外
  - リポジトリ全体の整形のやり直し、biome の版・設定の変更（依頼の範囲の外）
  - 依頼で変えたファイルの中の、別の設定での整形を検査で戻すこと（指示だけで防ぐ。M-1）

## 確認したいこと

### must

- M-1：依頼で変えたファイルの中の、リポジトリと違う設定の整形（PR #524 の約 2000 行、#542）も防ぐか。
  推奨：指示（R-1）で防ぎ、検査では戻さない。整形だけの差分の塊を戻すと、受け入れ条件 3 が認める `npm run format` の結果も戻してしまうため。
  懸念：指示が守られないと、#524 のような同じファイルの中の膨らみは PR に残り、レビューの費用は減りません。
- M-2：防ぎ方を、sacty の検査で戻す形にするか（指示だけ・知らせるだけにしないか）。
  推奨：検査で戻し（R-3）、指示（R-1・R-2）も足す。受け入れ条件 4 が提出を入力にしたテストを求め、条件 2 が「提出しない」を求めるため。
  懸念：指示だけを望んでいた場合、検査・テスト・仕様書の作業の大半が無駄になります。
- M-3：整形だけのファイルが依頼で求められたかを、担当の申告で決めるか。
  推奨：申告されたものだけを残し（R-13）、申告の無いものは関連を確かめられないとして戻す（R-3）。差分の形だけでは、依頼された整形と無関係な整形を区別できないため。
  懸念：整形を求める依頼で担当が申告を忘れると、求めた整形が PR から消え、依頼者が差し戻す手間が増えます。

### should

- S-1：検査を、biome 以外のリポジトリにも当てるか。
  推奨：当てる。ツールに依らず、文字列の範囲を確かめられる言語のファイルで、文字列の外の空白・改行・末尾のカンマの違いだけなら整形だけとし、それ以外は戻さない（R-7・R-12）。
  懸念：判定できる言語に限るので、それ以外の言語のファイルの整形は PR に残ります。

### 確認しないと決めたこと

- 「依頼で変えたファイル」：差分に整形以外の変更を含むファイルと、担当が依頼で求められた整形と申告したファイルとする。担当が触ったファイルを記録する仕組みは無いため。
- 直しの回・セキュリティ対応・文書だけの依頼：どれの提出にも当てる。受け入れ条件 2 が実装の担当を限っていないため。
- 原因：実装で確かめ、作業履歴に書く（受け入れ条件 1）。biome の版・設定が原因なら別の件にする（依頼の範囲の外）。

## 既定で決めたこと

- 戻したことは、担当に直させず、PR の本文（引き継いだ PR ではタスクの詳細）に戻したファイルの一覧を載せて知らせる（R-4・R-16）。
- 空白が意味を持つファイル（Python・YAML・Makefile など）は、整形だけかを判定できないものとして戻さない（R-7）。

## 要求

### 常時

| ID | システム | 応答 |
| --- | --- | --- |
| R-1 | 実装・修正の工程の指示 | 整形は、リポジトリが定める整形のコマンドと設定でだけ行い、ほかのツール（依存に無いものを `npx` で取るものを含む）・ほかの設定・作業領域の外の写しで整形しないことを書く |
| R-2 | 実装・修正の工程の指示 | 依頼で変えたファイルの外が整形だけで変わったら、そのファイルを戻してから提出することを書く |
| R-15 | 実装・修正の工程の指示 | 依頼が整形を求めるときは、整形だけで変えたファイルのパスと理由を提出で申告することを書く |
| R-9 | 作業履歴（`docs/worklog/`） | 原因と、その根拠（再現したコマンドと結果）が書かれている |
| R-10 | 仕様書 `docs/spec/tasks-and-steps`・`docs/spec/approval`（日英） | 「提出の前の検証」と PR の本文の記述が、R-1〜R-16 の指示と検査の振る舞いと一致する |
| R-11 | ユーザー文書 `docs/user/tasks`（日英） | 整形だけで変わったファイルを戻すこと、申告した整形は残ること、戻したファイルが PR の本文（引き継いだ PR ではタスクの詳細）に載ることが書かれている |

## 受け入れの確かめ方

- 自動のテストで確かめること
  - 合成の git の作業領域で、整形だけのファイルと整形以外の変更のファイルを含む提出から、PR の差分が後者だけになり、本文に前者のパスが載る（R-3・R-4・R-6）。検査を戻すとテストが落ちる
  - 整形だけのファイルを含まない提出で、差分が変わらない（R-5）。R-7・R-12 の入力と、申告したファイル（R-13）が戻らない
  - 整形だけのファイルしか無い申告の無い提出で、変更なしとして扱われる（R-14）。引き継いだ PR で、PR の題・本文が変わらず、タスクの詳細に一覧が載る（R-16）
  - 指示の文に、R-1・R-2・R-15 の内容がある（`prompts.test.ts`）
  - 仕様書・ユーザー文書・作業履歴の中身を差分で確かめる（R-9〜R-11）
- 人が確かめること：なし
