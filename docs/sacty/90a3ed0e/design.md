# 設計：PR のレビューの「判定なし」を、レビューができなかった場合だけにする

## スコープ

差分を読めない場合、または要求要件・設計の PR で主対象の文書を読めない場合は判定を付けない。
それ以外は、確かめられなかった所があっても判定を付けさせる。
判定なしの回の扱いは変えない。

- 対象
  - sacty のレビューの指示（`apps/daemon/src/prompts.ts` の判定の節・`VERDICT_ABSENT_LINE`）
  - 既定のスキル `review-dispatch` の `SKILL.md`（入力の確認）・`pr-review.md`・`aggregation.md`・`linked-docs.md`
  - 仕様書・ユーザー文書（日英）、ADR の置き換え、作業履歴、テスト
- 対象外
  - 判定なしの回の扱い（直しの対象の決め方・直しに入るか）。要求要件・設計の PR も実装の PR も今のまま、その PR の工程の直しに入る
  - 判定の読み取り（`absent`・`invalid` の読み分け、本文から判定を推し量らない決まり）と、判定なしの回の取り込み（`sactyReviewsOf`）
  - 提出の前の自己レビュー（`self-review.md`）。判定なしの扱いが無いので変えない

## 確認したいこと

- must：なし

### 確認しないと決めたこと

- スキル `pr-review` で「見られなかった観点（親が代わりに見ても見られなかった）」があり、`must` が無いときも、判定を付ける。受け入れ条件 1 と利用者の決定（2026-11-22）がこの場合を含むので、人に確かめない。
- 受け入れ条件 6 の「自己レビュー」は、sacty が自分の PR に付ける PR のレビューの子タスクと読む。判定の指示は `buildPrompt` の1か所にあり、子タスクと、GitHub から取り込んだレビューだけのタスクが共有している。提出の前の自己レビューには判定なしの扱いが無いので、どちらの読み方でも変える所は同じになる。
- 指摘なしの回が増えるので、リスク評価の付く回・見守りが完了する回・再レビューを絞る回も増える。判定なしを減らす依頼の目的どおりの結果なので、人に確かめない。

## 既定で決めたこと

- `VERDICT_ABSENT_LINE` は「判定：付いていません（レビューが判定を付けませんでした。差分も対象の文書も読めなかったレビューには、判定を付けません。本文と行へのコメントを確かめてください）」にする。
- `pr-review.md` の、見られなかった観点がある回は、本文の最初に確かめられなかった所を書く。判定を付ける回なので、「レビューを完了できませんでした」「確かめられた範囲での暫定」は書かない。
- 集約の記録の `verdict` の `incomplete` は、自己レビューのためだけに残す。PR のレビューでは使わず、`must` の有無で `passed`・`changes_required` にする。
- `SKILL.md` の入力の確認は、`pr-review` のときだけ条件表に合わせる。`self-review` の「揃わない」の条件は変えない（判定なしの扱いが無いため）。

## 判定を付けるかの条件

指示（`prompts.ts`）・スキル（`SKILL.md` の入力の確認・`linked-docs.md` の取得できないとき・`pr-review.md`・`aggregation.md`）・テスト観点で、この1つの条件を使う。

| 差分 | 要求要件・設計の PR の主対象文書 | 判定 |
| --- | --- | --- |
| 読めない | 問わない | 付けない |
| 読める | 読めない | 付けない |
| 読める | 読める、または不要 | 付ける |

読めなかった根拠や未確認事項は本文の最初に書く。

## 構成

| 場所 | 変えること |
| --- | --- |
| `prompts.ts` 判定の節 | 付けないのは、「判定を付けるかの条件」の付けない行（差分を読めない、または要求要件・設計の PR で主対象の文書を読めない）のときだけ。確かめられなかった所があっても、`must` が無ければ `suggestions`・`no_findings` を付け、確かめられなかったことを本文の最初に書く。CI の実行中・画面を確かめられない・環境で動かないテストは、判定を付けない理由にしない、と明記する。`changes_required` の行は変えない |
| `prompts.ts` `VERDICT_ABSENT_LINE` | 既定で決めた文に変える |
| `SKILL.md`「入力の確認」の「対象の本体」 | `pr-review` では差分と、要求要件・設計の PR の主対象文書を読む。読めない場合は取得を担当に再試行させる |
| `linked-docs.md`「取得できないとき」 | 要求要件・設計の PR の主対象文書を取得できないときは判定を付けない。「見られなかった文書がある `pr-review` は合格と書かない」を外す |
| `pr-review.md`「範囲」「完了できないとき」「指摘と判定の書き方」 | 差分を読めないときは範囲を推定せず、判定を付けない。読めない入力の取得を担当に再試行させる。判定を書かないのは「判定を付けるかの条件」の付けない行のときだけ。「主対象の文書を取得できない：差分も作業領域も読めないときと同じに扱う」を外す。見られなかった観点があっても、判定は `must` の有無と重さで決め、見られなかった所を本文の最初に書く。例は特定のリポジトリに寄せない |
| `aggregation.md`「判定」と記録の形 | 「見られなかった観点がある初回の PR レビューは合格と書かない」を外し、`incomplete` を自己レビューだけの値にする。「対象にした文書を取得できなかった PR レビューは合格と書かない」を、付けない行のときだけにする。検証失敗の原因を確定できない PR レビューでは、そのことと読む人が確かめることを本文に書き、確認できた指摘の重さで判定する |
| 仕様書 | `tasks-and-steps`・`context`・`risk-assessment`・`intake`（日英） |
| ユーザー文書 | `docs/user/intake.md`・`.en.md` の判定が付かない回の説明（184〜187 行あたり） |
| ADR | 新しい ADR を足し、`20261114-0158-superseded-review-range-and-partial-verdict.md` の判定の部分を置き換える（`git mv` で superseded に改名。この ADR にリンクしている `20261121-1330-…` のリンクも直す） |
| 作業履歴 | `docs/worklog/YYYYMMDD-pbi-485-review-verdict-unless-unreviewable.md`（PR を作った日、UTC） |

## 影響範囲

- 受け入れ条件 5 の「判定なしの回だけを理由に直しと再レビューが回るなら止める」は、判定なしを、差分を読めない、または要求要件・設計の PR で主対象の文書を読めない場合に限ることで足りるとする（利用者の決定。2026-11-22）。止める仕組み（新しいイベント・指摘の有無の判定）は足さない。
- レビューできなかった判定なしの回では、今のまま、要求要件・設計の PR でも直しと再レビューが回る。このことを新しい ADR と仕様書に書く。

## テスト観点

- [TV-1] 確かめられなかった所があっても、要修正が無ければ判定を付けさせる指示になっている
  - 入力：PR のレビューの子タスクと、GitHub から取り込んだレビューだけのタスクのそれぞれで、レビューの工程の指示を作る
  - 期待結果：どちらの指示の判定の節にも、確かめられなかった所があっても要修正が無ければ suggestions か no_findings を付け、確かめられなかったことを本文の最初に中身の言葉で書くとあり、「無ければ付けません」の文が無い
- [TV-2] 判定を付けないのは、差分を読めない、または要求要件・設計の PR で主対象の文書を読めないときだけと指示する
  - 入力：レビューの工程の指示を作る
  - 期待結果：判定の節で、差分または要求要件・設計の PR の主対象文書を読めないときは判定を付けないとあり、付けないときに理由を本文の最初に書かせる文が今のまま残っている
- [TV-3] CI の実行中・画面の見え方・環境で動かないテストを、判定を付けない理由にしないと指示する
  - 入力：レビューの工程の指示を作る
  - 期待結果：判定の節に、CI の実行中・画面の見え方を確かめられない・レビューの環境で動かないテストがあることは判定を付けない理由にせず、本文に書くとある
- [TV-4] 要修正があるときの changes_required の付け方が変わっていない
  - 入力：レビューの工程の指示を作る
  - 期待結果：確かめられなかった所があっても、今回の先頭のコミットで成り立つ要修正の指摘があれば changes_required を付ける文と、changes_required の定義の行が起点のコミットと同じ意味で残っている
- [TV-5] 判定なしの回の本文の判定の行が、読めなかったことを理由として示す
  - 入力：判定のブロックが無い（verdictMissing が absent）レビューの結果から、投稿する本文を作る
  - 期待結果：判定の行が「判定：付いていません（レビューが判定を付けませんでした。差分も対象の文書も読めなかったレビューには、判定を付けません。本文と行へのコメントを確かめてください）」になり、「確かめられなかった所がある」を含まない
- [TV-6] 判定なしの回の取り込みと直しの対象の決め方が、今のまま保たれている
  - 入力：設計の PR の承認待ちで、PR のレビューの子タスクの最後の回が判定なし（missing が absent）で、指摘の無いその回の投稿だけが取り込まれた
  - 期待結果：起点のコミットと同じく、その回の投稿が PullRequestReviewImported で取り込まれ、ReworkJudged（理由 rework.reviewTaskUnreadable）が記録されて設計の工程の直しに入る
- [TV-7] 既定のスキルのレビューの判定の規則
  - 入力：apps/daemon/default-context/skills/review/review-dispatch/ の SKILL.md（入力の確認）・references/linked-docs.md（取得できないとき）・references/pr-review.md・references/aggregation.md
  - 期待結果：pr-review では、差分または必要な主対象文書を読めないときは取得を再試行し、読めなければ判定を書かず、見られなかった観点・文書があっても must の有無と重さで判定して見られなかった所を本文の最初に書くとあり、PR のレビューでは incomplete を使わず、self-review の入力の条件は起点のコミットと同じで、例に特定のリポジトリ・sacty に寄せた語が無い
- [TV-8] 仕様書・ユーザー文書・ADR の記述
  - 入力：docs/spec の tasks-and-steps・context・risk-assessment・intake、docs/user/intake（それぞれ日英）、docs/adr
  - 期待結果：判定なしが差分を読めない、または要求要件・設計の PR で主対象の文書を読めない場合だけであることと、判定なしの回の扱いは今のまま（要求要件・設計の PR でも直しに入る）で、受け入れ条件 5 は判定なしを限ることで足りるとしたことが日英で同じ内容で書かれ、新しい ADR が 20261114-0158 の判定の部分を置き換えている（superseded に改名・置き換え先と置き換え元のリンク）
