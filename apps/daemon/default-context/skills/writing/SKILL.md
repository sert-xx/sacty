# 読みやすく簡潔な文章を書く

人が読む文章を書くときの決まり。
読む人が、確かめる手間をかけずに中身をつかめる文章を目指す。
主な対象は日本語の文章で、英語の扱いは「英語の文章」の節に書く。

## 何より先に従うもの

次の順に従う。
上のものと食い違ったら、このスキルの決まりは使わない。

1. 依頼した人の指示
2. 対象のリポジトリの文章の決まり
   - AGENTS.md・CLAUDE.md、CONTRIBUTING、docs の方針、PR・Issue のテンプレート、文章のリンターの設定
   - 決まりが無ければ、同じ種類の既存の文章（直近の PR の本文、同じディレクトリの文書）の書き方に合わせる
3. このスキル

文体（です・ます調か常体か）も、決まりと既存の文章に合わせる。
1つの文章の中では文体をそろえる。

## 決まりの要点

最初に文章の種類を決め、種類に合った決まりで書く。

- 読む人に合わせて、文章の種類を決める（[文書の組み立て](references/documents.md)）
  - 承認・判断・返信のための文章（PR の本文、レビュー、コメント、要求要件・設計、調査の結果、報告）は、読む人が前提（暗黙知）を持っている。
    情報を絞る
  - 後から読まれる文書（ユーザーガイド、手順書、README、運用の文書）は、読む人が前提を知らない。
    読む人が目的を果たすのに要ることを、省かずに書く
  - 種類は、文章の名前ではなく、読む人が前提を知っているかで決める
- 情報を絞る（[文の組み立て](references/sentences.md)）
  - 読む人が判断と作業に要ることだけを書く。
    読む人がすでに知っていることは書かない
  - 承認・判断・返信のための文章は、最初は最小限にし、読む人が詳しくするよう求めたら、求められた所だけを足す
  - 情報が多いと、読む人は読む気を失い、中身を確かめずに済ませてしまう
- 日本語では「。」の後で必ず改行する
  - 改行の書き方は、書き出し先（GitHub のコメント、リポジトリの Markdown のファイル、Confluence など）の仕様に合わせる（[改行・段落・箇条書き・表](references/layout.md)）
  - 話題が変わるところは、空行で段落を分ける
  - 改行のせいで表示が崩れる所は例外にする
- 構造のある情報は、箇条書きと表にする
  - 並ぶ項目・手順・条件は箇条書きにする。
    項目に細目があれば 2〜3 階層にする
  - 複数のものを同じ観点で比べるときは表にする
  - 理由・経緯・判断は地の文で書く
- 後から読まれる文書は、組み立ててから書く（[文書の組み立て](references/documents.md)）
  - 最初に、何の文書か・誰のためか・先に要るものを書く
  - 節は読む人が進む順に並べ、節の最初に、その節の要点を1〜2文で書く
  - 読む人が順にする操作は番号付きの手順にし、結果と、うまくいったことの確かめ方を書く
  - 読む人が知らない語は、最初に出る所で説明する
  - 今の状態だけを書く。
    経緯（「これまでどおり」「以前は」）は書かない
- 図と画像は、文章より速く伝わる所だけに使う（[図と画像](references/figures.md)）
  - 図にするのは、構成・流れ・状態の移り方のような「関係」だけにする。
    本文に書いたことを並べ直しただけの図は作らない
  - 図の形式は、書き出し先で決める。
    図を表示できない所では、関係を箇条書きか表で書く
  - スクリーンショットは、見る所・押す所が言葉で伝わりにくい所に絞る。
    画面を撮れないとき・画像を置けないときは、撮ったことにしない
- 日本語で一般的に使われる語と言い回しで書く（[語と言い回し](references/wording.md)）
  - 英語を、日本語に単純に置き換えない（entry point を「入口」にしない）
  - カタカナで定着している語（エンドポイント、デプロイなど）は、無理に日本語にしない
  - 直訳の言い回しや、その文章だけの独特な言い回しを使わない
- 人に確認・判断を求めるときは、確認しないで進めた場合の具体的な懸念を添える（[文の組み立て](references/sentences.md)）
  - 何が・誰に・どう困るかを1〜2文で書く。
    一般論（「問題が起きるおそれがあります」）にしない
  - 懸念のために文章を長くしない
- 要求要件・設計は、スコープ（対象と対象外）を最初に書き、要求や設計の中身はそのあとに書く（[改行・段落・箇条書き・表](references/layout.md)）
- 簡潔に書く
  - 結論を先に書く
  - 前置き、同じことの繰り返し、最後のまとめの言い直しを削る
- 文を組み直す（[文の組み立て](references/sentences.md)）
  - 行為者を主語にする
  - 比喩の動詞を、具体的な事実に直す
  - 名詞が続く文を、動詞の述語のある文に戻す
  - 不要な否定の対比（「A ではなく B」）、装飾、文末のコロン、絵文字を外す
  - 避けたい語を見つけたら、同じ意味の別の語に言い換えるのではなく、文を組み直す

## 書く手順

読む人と種類を決めてから書き、書いた後に見直す。

1. 読む人と、読んだ後にしてほしいこと（承認する・直す・判断する・操作する）と、書き出し先（どこに表示されるか）を決める
2. 文章の種類を決める（承認・判断・返信のための文章か、後から読まれる文書か）
3. 読む人がすでに知っていることを決め、それは書かない。
   後から読まれる文書では、読む人が知らない語と前提も決め、それは書く
4. 書くことを決める
   - 承認・判断・返信のための文章：結論と、それを支える事実を書き出す。
     書くか迷ったものは書かない
   - 後から読まれる文書：最初に書くことと、節の並びを決めてから、節ごとに書く
5. 構造のある情報は箇条書きと表に、理由は地の文にする。
   関係は、文章より速く伝わるときだけ図にする
6. 書いたら、「見直し」の節で確かめて直す

例と細かい決まりは、必要なときに資料を読む。

| 知りたいこと | 資料 |
| --- | --- |
| 改行・段落、書き出し先ごとの改行の書き方、箇条書きの階層、表、地の文の使い分け、改行で表示が崩れる所、要求要件・設計の並べ方 | [改行・段落・箇条書き・表](references/layout.md) |
| 情報の絞り方、簡潔さ、行為者の主語、比喩の動詞、名詞の連続、否定の対比、コロン、絵文字、人に確認を求める書き方 | [文の組み立て](references/sentences.md) |

| 文章の種類、後から読まれる文書（ユーザーガイド、手順書、README など）の最初に書くこと・並べる順・見出し・手順・ほかの節の指し方、既存の文書への書き足し方 | [文書の組み立て](references/documents.md) |

## 見直し

出す前に、次を確かめる。

- 最初の数行で、結論か、読む人にしてほしいことがわかる
- 読む人がすでに知っていること（依頼の言い直し・背景・一般論・用語の説明）を書いていない。
  削っても読む人の判断と作業が変わらない項目が無い
- 日本語の「。」の後が改行になっている（例外の所を除く）。
  書き出し先で、その改行が表示に出る書き方になっている
- 英語を単純に置き換えた語（entry point →「入口」など）や、直訳の言い回しが無い。
  カタカナで定着している語を、無理に日本語にしていない
- 人に確認・判断を求める項目に、確認しないで進めた場合の具体的な懸念がある
- 要求要件・設計で、スコープ（対象と対象外）が最初にある。
  対象外が無いときも「対象外：なし」と書いてある
- 1つの段落が1つの話題になっている
- 箇条書きが 4 階層以上になっていない。
  比べる情報が地の文や箇条書きに埋もれていない
- 理由や因果が、箇条書きで切れ切れになっていない
- 削っても意味が変わらない文が無い（前置き・繰り返し・まとめの言い直し）
- 主語の無い受け身、比喩の動詞、名詞の連続、不要な否定の対比が無い
- 文末がコロンで終わっていない。
  絵文字と飾りの記号が無い
- リポジトリの決まりと食い違っていない

後から読まれる文書では、次も確かめる。

- 最初の数行で、何の文書か・誰のためか・先に要るものがわかる
- 読む人が知らない語を、説明なしに使っていない
- 節が、読む人が進む順に並んでいる。
  節の最初に、その節の要点が書いてある（予告だけになっていない）
- 読む人が順にする操作が番号付きの手順になっていて、結果と確かめ方が書いてある
- 経緯の言い回し（「これまでどおり」「以前は」）と、位置での参照（「下の」「上記の」）が無い

図と画像を使ったときは、次も確かめる。

- 図が、本文を並べ直しただけのものや、1列に並ぶだけの手順になっていない
- 図の中の語が本文と同じで、図の前に何の図かが、本文に図の要点が書いてある
- 画像に代替テキストがあり、参照している画像が実際にある
- スクリーンショットに、秘密の値・個人の情報が写っていない

## 英語の文章

英語で書くときも、日本語と同じ考え方で書く。

- 「。」の後の改行は日本語だけの決まりにする。
  英語ではピリオドの後で改行しない
  - 英語の文は短いので、1文ごとの改行は読みにくくなる
  - 代わりに、1つの段落を 2〜3 文にし、話題が変わったら空行で分ける
  - リポジトリが1文1行（semantic line breaks）を決めていれば、それに従う
- 箇条書きと表、簡潔さの決まりは、日本語と同じ
- 文の組み立ても同じ。
  能動態で行為者を主語にし、比喩の動詞（leverage・streamline・empower など）を具体的な事実に直す
- 日本語と英語の両方の版を書くときは、それぞれの言語の決まりで書く。
  訳すときに日本語の改行を英語に持ち込まない
