# 図と画像

図・スクリーンショット・表・コードの例の使い分けと、作り方。
図と画像は、文章より速く伝わる所だけに使う。
例の「悪い例」は、決まりを破った形をわざと書いている。

## 図にするもの・しないもの

図にするのは、文章で書くと長くなる「関係」。

- 全体の構成：何が何とつながっているか
- 処理やデータの流れ：順序と、分かれ道
- 状態の移り方：何が起きると、どの状態になるか
- 層や入れ子：何が何を含むか、どれがどれに重なるか
- やり取りの順序：誰が誰に、どの順で頼むか

次のものは、図にしない。

- 1列に並ぶだけの手順：番号付きの箇条書きにする
- 複数のものを同じ観点で比べる情報：表にする
- 本文に書いたことを並べ直しただけの図、飾りの図

目安は、要素が3つ以上あり、つながりが1列に並ばないこと。
承認・判断・返信のための文章では、図は、文章では関係を読み取りにくい所だけに使う（多くは1つで足りる）。

悪い例（1列の手順を図にしている）

```text
[設定ファイルを作る] → [コマンドを実行する] → [件数を確かめる]
```

直した例

```text
1. 設定ファイルを作ります。
2. コマンドを実行します。
3. 表示された件数を確かめます。
```

## 図の作り方

1つの図で、1つのことを伝える。

- 要素が 10 個を超えるなら、図を分ける
- 図の中の語は、本文と同じ語にする
- 読む向き（左から右、上から下）と、矢印の意味（データの流れ、呼び出し、状態の移り）を、1つの図の中でそろえる
- 色だけで区別しない。
  形か、文字でも見分けられるようにする
- 図の前に、何の図か・どこを見るかを1文で書く
- 図の要点（何が何とつながるか、どこで分かれるか）は、本文にも1〜2文で書く。
  図が表示されなくても、要点が分かるようにする
- 本文を直したら、図も直す。
  図と本文が食い違うと、読む人はどちらを信じるか決められない

図の形式は、書き出し先で決める。

| 書き出し先 | 形式 |
| --- | --- |
| テキストで書いた図を表示できる所 | テキストで書く |
| 表示できないが、画像を置ける所 | 画像にする |
| どちらもできない所 | 図にしない |

- テキストで書いた図（Mermaid など）は、GitHub の Markdown などが表示する。
  差分が読め、後から直しやすい
- 画像（SVG・PNG）にした図は、後から直せるように、元のファイルを一緒に置くか、元のデータを埋め込んだ画像にする
- 画像にするときに、図を作るためのスキル（`drawio` など）があれば、それに従って作る
- 図にしない所（チャット、コメント、画像を作る道具が無いとき）では、関係を箇条書きか表で書く
- 表示できるか分からないときは、同じ場所にある文書の図の形式に合わせる。
  合わせる図も無ければ、図にせず、関係を箇条書きか表で書く
- リポジトリが図の作り方（道具、置き場所、色）を決めていれば、それに従う
- 画像には、何の図かが分かる代替テキストを付ける

## スクリーンショット

スクリーンショットは、画面のどこを見るか・どこを押すかが、言葉では伝わりにくい所に使う。
手順の節目（最初に開く画面、操作の結果の画面）に置くと、読む人が自分の画面と見比べられる。

次の所には、使わない。

- 文字で書けば足りる所。
  メニューやボタンの名前は、本文に書く（画像の中の文字は、検索も読み上げもできない）
- エラーメッセージ、コマンドの出力、設定の中身。
  コードブロックに、文字で書く

撮り方は、次のとおり。

- 説明に要る範囲だけを写す。
  画面の全体が要らなければ、切り取る
- 架空のデータで撮る。
  秘密の値、個人の情報、実在の組織の名前を写さない
- 1つの文書の中では、画面の大きさと表示の設定（言語、配色）をそろえる
- 見る所が分かりにくいときは、枠などの印を付ける
- 画像の前に、何の画面かを1文で書き、代替テキストを付ける

数は絞る。
画面が変わると、スクリーンショットは古くなる。
手順の1つごとに1枚ずつ貼らない。

画面を撮れないとき・画像を置けないときは、撮ったことにしない。

- 無い画像を参照しない。
  別の画面の画像や、想像で作った画像を、代わりに置かない
- 画面の名前と、見る所を、言葉で書く
- 画像が要る所は、人に確かめることとして、文書の外（報告、PR の本文）に挙げる。
  外に書く場所が無ければ、文書の末尾に分けて書く

## 表とコードの例

比べる情報は表に、写して使うものはコードブロックに書く。

- 複数のものを同じ観点で比べる情報と、調べるための一覧（設定の項目、コマンドのオプション）は、表にする（[改行・段落・箇条書き・表](layout.md)）
- コマンド、設定、出力は、コードブロックに書く。
  読む人が写して使うものは、写してそのまま動く形にする
- 例は、最小で動くものを先に置く。
  すべての項目を使った例は、その後に置く
