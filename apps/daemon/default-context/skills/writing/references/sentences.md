# 文の組み立て

簡潔に書くことと、1つ1つの文の組み立て方。
例の「悪い例」は、決まりを破った形をわざと書いている。

避けたい語を見つけたら、同じ意味の別の語に置き換えて済ませない。
置き換えても、読みにくさの元（主語が無い、事実が無い）は残る。
誰が何をしたか、何が起きたかを確かめて、文を組み直す。

## 簡潔さ

結論を先に書き、次のものを削る。

- 前置き：依頼の言い直し、これから書くことの予告、挨拶
- 繰り返し：同じ事実を、別の言い方でもう一度書くこと
- まとめの言い直し：最後に「以上のように」で本文を繰り返すこと
- 根拠の無いぼかし：「〜と考えられます」「〜かもしれません」を、確かめた事実にまで付けること

悪い例

```text
ご依頼いただいたログインの不具合について調査しましたので、結果をご報告します。
調査の結果、ログインに失敗する原因が判明しました。
原因は、セッションの有効期限が UTC と現地時刻で食い違っていたことと考えられます。
以上のように、時刻の扱いの食い違いが原因でした。
```

直した例

```text
ログインに失敗する原因は、セッションの有効期限が UTC と現地時刻で食い違っていたことです。
期限を UTC にそろえると、再現の手順でも失敗しなくなりました。
```

確かめていないことは、確かめていないと1回だけ書く。
ぼかしの語を文ごとに付けない。

## 行為者を主語にする

誰が・何がしたかを主語にする。
「〜が行われる」「〜される」で行為者が消えると、読む人は誰の動作か推し量ることになる。

悪い例

```text
入力の検証が行われ、不正な値の場合はエラーが返されます。
```

直した例

```text
API は入力を検証し、値が不正ならエラーを返します。
```

行為者がわからないときや、どうでもよいときは、受け身のままでよい。

## 比喩の動詞を事実に直す

「加速する」「支える」「強化する」「担保する」「シームレスに統合する」などは、何が起きるかを言っていない。
数字・動作・状態の変化に直す。

悪い例

```text
この変更により、開発体験が大きく向上し、リリースのサイクルが加速します。
```

直した例

```text
テストの時間が 12 分から 4 分になります。
1日に出せるリリースが2回から4回に増えます。
```

数字が無いときは、何ができるようになるかを書く（「手で直していた設定を、コマンド1つで直せる」）。

## 名詞の連続を、動詞の述語に戻す

名詞を「の」や漢語でつなぐと、何が何をするのかが見えなくなる。
動作は動詞にし、述語のある文に戻す。

悪い例

```text
設定値不整合時の自動復旧処理の実施可否判断基準の明確化
```

直した例

```text
設定値が食い違ったときに、自動で戻してよいかを決める基準をはっきりさせる。
```

見出しや表のセルのように短さが要る所でも、「〜の〜の〜」を3つ以上つなげない。

## 不要な否定の対比

「A ではなく B」「単なる A ではない」は、誰も A と言っていないなら要らない。
B だけを書く。

悪い例

```text
これは単なるリファクタリングではなく、保守性を根本から見直す取り組みです。
```

直した例

```text
重複していた3つの読み込みの関数を1つにまとめました。
```

読む人が A と取り違えそうなとき（よくある誤解を正すとき、2つの案から1つを選んだとき）は、対比を残してよい。

## 装飾

- 太字は、読み落とすと困る所（壊れる操作、期限）だけにする。
  1つの段落に何か所も付けない
- 「重要：」「ポイント：」などの見出しの札を付けない
- 感嘆符、大げさな形容（「画期的な」「非常に強力な」）を使わない
- 「〜することが重要です」「〜することが可能です」は、「〜する」「〜できる」にする

悪い例

```text
**重要：** この機能は**非常に強力**で、設定を一括で書き換えることが可能です！
```

直した例

```text
このコマンドは、すべての環境の設定を一度に書き換えます。
戻すときは、書き換える前に保存した控えを使います。
```

## 文末のコロン

箇条書きや表の前の文を、コロンで終わらせない。
「。」で終わる文にする。

悪い例

```text
変更点は以下の通りです：
```

直した例

```text
変更は次の2つです。
```

「項目：値」のように、1行の中で名前と中身を分けるコロンは使ってよい。

## 絵文字

絵文字と、飾りの記号（✨・🚀・✅ など）を外す。
状態を表すなら、語で書く（「通過」「失敗」「未確認」）。

悪い例

```text
| テスト | 結果 |
| --- | --- |
| 単体 | ✅ |
| 結合 | ❌ |
```

直した例

```text
| テスト | 結果 |
| --- | --- |
| 単体 | 通過 |
| 結合 | 失敗（2件） |
```

リポジトリやテンプレートが決めている記号（PR の本文の末尾の決まった行など）は、そのまま使う。
