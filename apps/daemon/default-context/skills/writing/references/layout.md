# 改行・段落・箇条書き・表

文章の見た目の組み立て方。
例の「悪い例」は、決まりを破った形をわざと書いている。

## 「。」の後の改行

日本語では、「。」の後で必ず改行する。
1行に1文になり、読む人が文の切れ目を探さずに済む。

悪い例

```text
設定ファイルが無いときに起動が止まる不具合を直しました。原因は、読み込みの関数が例外を投げたまま戻っていたことです。既定値で起動するように変え、テストを足しました。
```

直した例

```text
設定ファイルが無いときに起動が止まる不具合を直しました。
原因は、読み込みの関数が例外を投げたまま戻っていたことです。
既定値で起動するように変え、テストを足しました。
```

括弧やかぎ括弧の中の「。」（「保存しました。」と表示する、など）の後では改行しない。

## 書き出し先ごとの改行の書き方

改行の扱いは、書き出し先によって違う。
書く前に書き出し先を確かめ、文ごとの改行が表示にも出る書き方にする。
リポジトリや組織の決まりがあれば、それに従う。

| 書き出し先 | 1つの改行の表示 | 書き方 |
| --- | --- | --- |
| GitHub の PR の本文、Issue、コメント | 改行になる | 「。」の後で改行する |
| リポジトリの Markdown のファイル | 前の行とつながる | 「。」の後で改行し、行末に `\` を置く（下を参照） |
| Confluence のエディタ | Enter は段落になる | 文の区切りは Shift+Enter で改行する |
| Confluence のストレージ形式（API で書くとき） | 表示されない | 改行は `<br />` で書き、段落は `<p>` で分ける |
| チャット（Slack など） | 改行になる | 「。」の後で改行する |

Markdown のファイルでは、1つの改行は表示で前の行とつながる。
表示でも改行されるよう、「。」で終わる行の行末に `\`（強制改行）を置く。

- 段落の最後の文、見出し、表のセル、コードブロックの中には付けない
- 箇条書きの項目の中で文が続くときも、続く行がある文の行末に付ける
- 行末の半角スペース2つは使わない（見えず、エディタやフォーマッターが消すことがある）
- リポジトリが別の書き方（`<br>`、行末の半角スペース2つ、1文1行で表示はつなげる）に決めていれば、それに従う

悪い例（表示では1行につながる）

```text
設定ファイルが無いときに起動が止まる不具合を直しました。
原因は、読み込みの関数が例外を投げたまま戻っていたことです。
```

直した例

```text
設定ファイルが無いときに起動が止まる不具合を直しました。\
原因は、読み込みの関数が例外を投げたまま戻っていたことです。
```

表に無い書き出し先（Jira、Wiki、メールなど）は、記法の仕様か、すでにある文章の表示を見て決める。
Markdown を別の形式に変換して書き出すときは、変換した結果に改行が残るかを確かめる。

## 単純な改行と段落

- 単純な改行：同じ話題の文と文の間
- 段落（空行）：話題が変わるところ

1つの段落には1つの話題だけを書く。
段落が 5 文を超えたら、話題が2つ混ざっていないか確かめる。

悪い例（話題が変わっても段落を分けていない）

```text
一覧の画面で、絞り込みの条件が保存されない不具合を直しました。
条件を URL に持たせ、再読み込みしても残るようにしました。
なお、同じ画面の表示が遅い件は、別の Issue で調べています。
件数が多いときに、全件を一度に描いていることが原因とみています。
```

直した例

```text
一覧の画面で、絞り込みの条件が保存されない不具合を直しました。
条件を URL に持たせ、再読み込みしても残るようにしました。

同じ画面の表示が遅い件は、別の Issue で調べています。
件数が多いときに、全件を一度に描いていることが原因とみています。
```

## 箇条書きの階層

並ぶ項目・手順・条件は箇条書きにする。
順序に意味があれば番号付きにする。

- 1階層：項目が並ぶだけのとき
- 2階層：項目ごとに細目（条件・例・補足）があるとき
- 3階層：細目にさらに細目があるとき。
  4階層以上にはしない。
  深くなるなら、見出しか表に分ける

悪い例（細目を1階層に押し込んでいる）

```text
- 対応する形式は CSV と JSON。CSV は区切り文字を選べ、文字コードは UTF-8 だけ。JSON は配列と、1行1件の形式の両方を読める。
- 上限は 1 ファイル 100 MB。
```

直した例

```text
- 対応する形式
  - CSV
    - 区切り文字を選べる
    - 文字コードは UTF-8 だけ
  - JSON：配列と、1行1件の形式の両方を読める
- 上限：1 ファイル 100 MB
```

1つの項目の中で文が2つ以上になるときは、「。」の後で改行し、続きの行を項目の位置に字下げする。

## 表

複数のものを、同じ観点で比べるときは表にする。
目安は、比べるものが2つ以上、観点が2つ以上。

悪い例

```text
案 A は導入が簡単だが、件数が増えると遅くなる。案 B は導入に手間がかかるが、件数が増えても速さが変わらない。案 C は速いが、有料である。
```

直した例

```text
| 案 | 導入 | 件数が増えたとき | 費用 |
| --- | --- | --- | --- |
| A | 簡単 | 遅くなる | 無料 |
| B | 手間がかかる | 変わらない | 無料 |
| C | 簡単 | 変わらない | 有料 |
```

表のセルには短い語句を書く。
セルの中で改行しない（表が崩れる）。
説明が長くなるなら、表の下に地の文で書く。

## 地の文で書くもの

理由・経緯・判断は地の文で書く。
「〜なので」「その結果」でつながる話を箇条書きに切ると、つながりが消える。

悪い例

```text
- キャッシュを外した
- 古い値が返ることがあった
- 更新の頻度が高い
- 速さはほとんど変わらなかった
```

直した例

```text
キャッシュを外しました。
更新の頻度が高く、キャッシュから古い値が返ることがあったためです。
外した後に測ると、速さはほとんど変わりませんでした。
```

## 改行で表示が崩れる所

「。」の後の改行が、表示を崩したり意味を変えたりする所では、改行しない。
リポジトリの決まり（1行の長さ、段落を1行で書くなど）があれば、それに従う。

- Markdown のファイル
  - 改行の後の行が `-`・`1.`・`#`・`>` で始まると、箇条書きや見出しになる。
    その位置では改行しないか、文を組み直す
  - 「。」の後の改行は、行末の `\` で表示にも出す（上の「書き出し先ごとの改行の書き方」）
- コードブロック・ログ・コマンドの出力の中：書き換えない
- 表のセルの中：改行しない
- 見出し、リンクの文字、インラインコード、1行だけを受け付ける欄（タイトル・件名）：改行しない
- コミットメッセージ
  - 1行目は1行で書く
  - 本文は、リポジトリの既存のコミットの書き方に合わせる
- ソースコードの中の文字列・コメント・設定ファイルの値：言語や形式の決まりに従う
- 改行をそのまま表示する場所（チャット、GitHub の Issue・PR のコメントなど）：決まりどおりに改行する

## 要求要件・設計の並べ方

要求要件・設計は、最初にスコープを書く。
読む人は、範囲が意図どおりかを先に確かめてから、要求や設計の中身を読む。
要求の一覧から範囲を読み取るのは手間がかかり、範囲のずれも見落としやすい。

- 並べる順
  1. スコープ：何を実現するか（1〜3文）と、対象・対象外
  2. 確認したいこと・決めたこと（あれば）
  3. 要求・設計の中身
- 対象外には、読む人が含まれると思いそうだが、今回はやらないことだけを書く。
  当てはまらない観点のための「対象外」（「性能：対象外」など）は書かない
- リポジトリやテンプレートが節の順を決めていれば、それに従う

悪い例（範囲が要求の一覧に埋もれている）

```text
## 要求
- R-1 一覧に作成日の列を足す
- R-2 作成日で並べ替えられる
- R-3 CSV の書き出しにも作成日を入れる
```

直した例

```text
## スコープ
一覧で、タスクを作成日で確かめ、並べ替えられるようにする。

- 対象：一覧の画面、CSV の書き出し
- 対象外：詳細の画面（作成日はすでに表示している）

## 要求
- R-1 一覧に作成日の列を足す
- R-2 作成日で並べ替えられる
- R-3 CSV の書き出しにも作成日を入れる
```
