# 集約

起動した担当の結果を検証し、1つのレビューにまとめる。親はここで初めて指摘の内容を読む（それまでは待つだけ）。

## 結果の検証

1. 起動した全観点の結果を回収する。足りない観点があれば、揃うまで集約しない
2. 各結果が [finding-format.md](finding-format.md) の形式を満たし、依頼した観点と一致することを確かめる。形式が壊れていれば、その担当に出力形式だけを直させる（レビューをやり直させない）
3. `failed` の観点は1回だけ起動し直す。それでも `failed` なら、流れの資料の「完了できないとき」に従う
4. `checked` を見て、観点の「見るもの」が対象の全体にわたって確かめられているかを確かめる。明らかに途中で止まっている（差分の前半しか見ていない等）なら、残りを見させる

## 指摘の統合

- 同じ箇所・同じ問題が複数の観点から出たら1つにまとめる。観点を併記し、`confidence` は高い方にする
- 同じ問題の別の現れ（同じ原因で複数箇所）は、代表の1箇所にまとめて他の箇所を本文に列挙する
- `out_of_scope_notes`（観点外の気づき）は、他の観点の指摘と照らす。どの観点にも拾われていない気づきで、根拠が示せるものは、親が根拠を確かめた上で採用してよい（採用した指摘には「横断で拾った」と記す）。確かめられないものは不採用にする
- 相反する指摘（ある観点は「分けろ」、別の観点は「まとめろ」）は、根拠と影響を比べて1つに決め、決めた理由を記録する

## 不採用

次は不採用にし、理由を `dismissed` に残す（PR には投稿しない。自己レビューでは記録だけ）。

- 観点の外（担当が「見ないもの」を指摘した）
- 範囲の外（PR の変更が持ち込んでいない既存の問題で、`must` に当たらないもの。再レビューで前回以降の差分の外の `should`・`nit`）
- 根拠が無い・`confidence: low` で親が確かめられない
- 好みだけ、意図された振る舞いの変更、同じ問題の言い換え
- 作者が対象外・後続対応を明示した論点（流れの資料の規則）
- PR にすでにある他のレビュアーの指摘と同じ箇所・同じ問題（`pr-review`。言い換えを含む。理由は「既存のレビューで指摘済み」。`must` でも繰り返さない。規則は流れの資料の「既存の指摘との重なり」）

`must` は、過去の指摘の履歴や「前回は出なかった」という理由だけで抑えない（他のレビュアーがすでに同じ指摘をしているときは除く。作者にはすでに届いている）。

## 判定

- `must` が1件以上：修正が必要（`changes_required`）
- `should` のみ：自己レビューでは修正に戻す（主対象が `design-doc` のときの、記述を足す `should` の扱いは [self-review.md](self-review.md)）。PR レビューでは「提案あり（マージは可）」
- 不採用にした指摘（既存のレビューで指摘済みのものを含む）は、判定に数えない
- 指摘なし：合格（`passed`）。ただし、見られなかった観点があれば、判定に「見られなかった観点」を併記する
- 見られなかった観点が1つでもある初回の PR レビューは、合格と書かない
- レビューの対象にした文書（[linked-docs.md](linked-docs.md)）を取得できなかった PR レビューは、初回でも再レビューでも合格と書かない
- 検証のコマンドが失敗しているのに、その原因が指摘になっていない（X-2 が既存の失敗・環境の問題と判断した）ときは、判断の根拠を確かめる。今回の変更が原因でないと確かめられなければ合格と書かない

## 順序

`must` → `should` → `nit`。同じ重要度では、影響（データ破損・セキュリティ・不具合 → 互換性 → 保守性）の大きい順、次にファイルの順。

## 記録

集約の結果として、次を残す（流れの資料が決める場所に）。

```json
{
  "workflow": "self-review | pr-review",
  "round": 1,
  "target_kind": "code | design-doc | user-doc",
  "launched": [{ "viewpoint": "C-1", "tier": "advanced | …| 親と同じ", "status": "passed | changes_required | failed", "findings": { "must": 0, "should": 0, "nit": 0 } }],
  "not_launched": [{ "viewpoint": "C-7", "reason": "並行処理・共有状態の変更が無い" }],
  "linked_docs": [{ "source": "<URL かリポジトリ内のパス>", "role": "target | evidence", "reason": "本文が成果物の設計書として示している", "fetched": true, "copy": "<一時ディレクトリ>/review-linked/design.md", "version": "<版や更新日時。分からなければ空>", "not_fetched_reason": "" }],
  "verification": { "summary": "<一時ディレクトリ>/review-verify/round-1/summary.json", "failed": ["test:pytest"], "not_run": ["build（CI で実行していない）"] },
  "existing_reviews": { "count": 3, "readable": true, "overlapping": 1 },
  "adopted": [],
  "dismissed": [{ "viewpoint": "C-5", "title": "…", "reason": "範囲の外（既存の問題）" }],
  "verdict": "passed | changes_required | incomplete"
}
```

`adopted` は、担当の指摘の形式のまま（併合した観点を `viewpoints` に列挙）。人が読む本文は、この記録から流れの資料の形式に書き起こす。
