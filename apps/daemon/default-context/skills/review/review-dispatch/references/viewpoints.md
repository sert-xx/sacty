# 観点カタログ

親は、主対象の種類の必須観点を全部、条件付き観点を判定して、横断（X-1 は常に、X-2 は検証の結果があれば）を起動する（SKILL.md の「観点の起動の規則」）。
各観点の「見るもの」「見ないもの」は、担当への依頼文にそのまま写す。「見ないもの」は隣の観点との境界で、重複した指摘を防ぐ。
観点ごとの詳しいチェックポイントと NG 例は、担当のスキル `review-execution` の `references/<観点ID>.md` にある（親は読まない。担当が観点 ID から自分で開く）。

観点が足りないと分かったら、このカタログに足す（プロジェクトのコンテキストリポジトリに同じ名前のスキル `review-dispatch` を置いて、このスキルごと差し替えて足すこともできる）。
足すときは、既存の観点の「見ないもの」に新しい観点を書いて境界を保ち、`review-execution/references/<観点ID>.md` に確かめる手順・チェックポイント・NG 例を足す。

## 横断（`X`）

| ID | 観点 | 起動 | 見るもの | 見ないもの |
| --- | --- | --- | --- | --- |
| X-1 | 横断（欠陥探索） | 常に起動する | 観点に縛られず、対象の全体を「作者が知れば直すであろう具体的な問題」の視点で読む。上の観点のどれにも入らない問題、複数の観点にまたがる問題、変更の意図と実際のずれ、変更が触れていないが壊れる周辺、要求に対して足りない・余計な変更 | 上の観点の担当が見るはずのもの（気づいたら `out_of_scope_notes` に1行で残し、指摘にはしない）。検証コマンドの結果の分析（X-2） |
| X-2 | 検証結果の分析 | 検証の結果（ローカルで実行した検証か CI の結果）が1つでもあれば起動する | 親が実行した検証コマンド（フォーマッター・リンター・型チェック・テスト・ビルド）と CI の結果を読み、失敗・警告・実行されなかった検証を変更の原因箇所と結びつける。今回の変更が持ち込んだ失敗か既存の失敗か、不安定なテスト、検証を黙らせる変更（リントの無効化・型エラーの抑止・閾値の緩和）、ローカルと CI の食い違い | テストの設計の良し悪し（C-4）、依存・ビルド・CI の設定の変更そのものの妥当性（C-11）、検証が通っているコードの論理の誤り（C-1 など各観点） |

横断の担当には、起動した他の観点の一覧を依頼文で渡す（何が他で見られるかを知らせ、重複を避ける）。X-2 には、検証の結果（`summary.json` の場所）を必ず渡す。
C-13・C-16 には、画面の記録（`screens.json` の場所。撮っていなければ理由）を渡す（[screen-capture.md](screen-capture.md)）。

## 観点ごとの段階

担当を起動するサブエージェントの段階（モデルの強さ。`lite` < `entry` < `standard` < `advanced` < `ultimate`）。設定のディレクトリの `agents/` に、この名前の定義が置かれている（置く側が段階ごとのモデルを決める）。定義が無い段階は、親と同じモデルで起動する（SKILL.md の「観点の起動の規則」）。

| 段階 | 観点 | 理由 |
| --- | --- | --- |
| `ultimate` | X-1 | 観点に縛られず対象の全体から欠陥を探す。最も推論が要る |
| `advanced` | C-1、C-2、C-3、C-7、C-9、D-2、D-3、D-5 | 正しさ・堅牢性・セキュリティ・並行・データ・設計の整合は、深く読まないと見落とす |
| `standard` | C-4、C-5、C-6、C-8、C-10、C-11、C-12、C-15、C-16、D-1、D-4、D-7、D-8、D-9、D-10、U-1、U-2、U-5、X-2 | 対象を読んで判断する観点の既定 |
| `entry` | C-13、C-14、D-6、U-3、U-6 | 文言・表記・読み手の適合。規則との照合が中心 |
| `lite` | U-4 | 静的な品質（リンク切れ・見出し・表記揺れ）。機械的な確認 |

プロジェクトのコンテキストリポジトリに同じ名前のスキル `review-dispatch` を置いて差し替えれば、この表も変えられる。
