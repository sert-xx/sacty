# U-2 手順の成立

見るもの：前提（環境・権限・インストール）が書かれているか、順序どおりに実行して成立するか、省略された段階、コピーして実行できるか、失敗したときの確認方法と戻し方、成功の確かめ方。
見ないもの：文言の分かりやすさ（U-3）。

## 確かめる手順

1. 手順を「初めての人がまっさらな環境で」上から順に実行するつもりで追う。各段階で「いまの状態でこれは実行できるか」を問う
2. 前提：必要なツール・版・権限・アカウント・ネットワーク・事前の設定が、手順の前に書かれているか。暗黙の前提（すでにログインしている、カレントディレクトリがどこか）
3. 各コマンドが、その時点の状態で成立するか：参照するファイルは前の段階で作られたか、環境変数は設定済みか、ディレクトリは正しいか
4. コピーして実行できるか：プレースホルダー（`<your-token>`）の説明、シェルの違い（bash/zsh/fish/PowerShell）、改行の継続、プロンプト記号の混入
5. 失敗：各段階が失敗したときにどう気づき、どう直し、どこまで戻すか。成功の確かめ方（期待する出力・状態）

## チェックポイント

- 前提の欠落：ツールのインストール、版、OS、権限（sudo・管理者・リポジトリへの書き込み）、認証（ログイン・トークン）、ネットワーク（プロキシ・組織内の DNS）
- 順序：後の段階で使うものを前で作っていない、設定を変える前に起動している、依存の順序
- 省略された段階：「ビルドする」「設定する」とだけあり具体のコマンドが無い、「略」「適宜」
- カレントディレクトリ：`cd` の有無、相対パスの基準がどこか
- 環境変数：設定の方法（export・.env・シェルごとの違い）、永続化、次のシェルで消える
- プレースホルダー：何を入れるか、どこで得るか、形式（引用符の要否）
- シェル・OS の差：bash 固有の構文、Windows のパス、改行の継続（`\`）、クォート
- 権限：ファイルの所有者、実行権限、`sudo` が要る段階と要らない段階の区別
- 成功の確認：各段階の期待する出力・状態（「〜と表示されれば成功」）
- 失敗時：よくある失敗と対処、ログの場所、どこまで戻すか（途中で止めてよいか、やり直せるか）
- 冪等性：手順を 2 回実行しても壊れないか（すでにある・すでに登録済み）
- 時間：長くかかる段階の目安、待ち方
- 後始末：一時的に変えた設定・権限を戻す段階、不要になったファイル
- 破壊的な段階の警告（詳細は U-5。ここでは「警告無しに手順に混ざる」ことを見る）
- 代替の経路：環境によって手順が分岐する所（Docker あり・なし）が整理されているか

## NG 例

### 例1：前提の欠落

```
1. npm run build
2. npm start
```

`npm install` が無い。クローン直後に失敗する。`must`。

### 例2：順序の誤り

```
1. app start
2. config.yaml に API キーを設定する
```

起動後に設定を変えても読み込まれない（再起動が要る）。順序を入れ替えるか、再起動の段階を足す。`must`。

### 例3：省略された段階

```
3. 証明書を設定する
4. サービスを再起動する
```

「証明書を設定する」の具体（どのファイルをどこに、どの形式で）が無い。`must`。

### 例4：コピーして動かない

```
$ export TOKEN=<your token>
```

`$` が混ざる（コピーするとエラー）、トークンの入手先が無い、`<...>` のまま実行する人がいる。`should`、入手先が無いなら `must`。

### 例5：成功の確認が無い

10 段階の手順で、どの段階も「何が出れば成功か」が無い。途中で静かに失敗して後の段階で原因不明のエラーになる。`should`。

### 例6：失敗時の戻し方が無い

DB の移行を含む手順で、失敗したときにどこまで戻し、どう再開するかが無い。`must`。

## 見落としやすい所

- 書いた人の環境には「すでにある」もの（ツール・認証・設定）が前提として抜ける
- 手順を読むだけで「できそう」と判断しない。各段階の入力と出力を追う。self-review では実際に実行できるなら実行する
- 複数の環境（OS・シェル）に対応する文書は、1 つの環境でしか検証されていないことが多い

## 指摘の書き方の例

- title：`セットアップの手順に依存のインストールが無く、クローン直後に失敗する`
- problem：`README 2.1 の手順は npm run build から始まるが、node_modules が無い状態では tsc が見つからず失敗する。npm install の段階が無い`
- evidence：`README.md 2.1。package.json の scripts と、クローン直後の状態を想定して追った`
- suggestion：`1. npm install を足し、必要な Node の版（engines）を前提に書く`
