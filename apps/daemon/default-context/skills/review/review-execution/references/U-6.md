# U-6 多言語・翻訳

見るもの：版の間の内容の一致、更新の漏れ、用語の対応。
見ないもの：原文の正しさ（U-1）。
起動条件：複数の言語の版がある、翻訳を変える。

## 確かめる手順

1. 原文（正とする言語）と翻訳の版を特定する。どちらが正か文書・リポジトリの規約で決まっているか
2. 今回の変更で原文が変わった箇所を列挙し、翻訳の対応箇所が更新されているかを 1 つずつ確かめる（逆も：翻訳だけ変わって原文が古い）
3. 構造の一致：節の数・順序・見出し、箇条書きの項目数、表の行数、コードブロック・リンク・画像の数
4. 用語：用語集・既存の翻訳と一致するか、同じ語が複数の訳になっていないか、固有名詞・コード識別子・コマンドは訳さずそのままか
5. 翻訳の自然さと正確さ：意味が変わっていないか（否定の脱落、数値・単位の変換ミス）、機械翻訳のまま不自然な所、文化的に通じない表現

## チェックポイント

- 更新の漏れ：原文の変更に翻訳が追従していない（新しい節・変わった数値・消えた機能）
- 構造の不一致：節・項目・表の数が違う、順序が違う、片方にだけある注意書き
- 用語の不一致：用語集と違う訳、同じ語の訳の揺れ（文書内・文書間）、UI の文言と文書の訳のずれ（画面は「中止」、文書は「キャンセル」）
- 訳してはいけないもの：コマンド・オプション・設定キー・コード・ファイル名・固有名詞・エラーメッセージの原文（検索のため）
- 意味の変化：否定の脱落・追加、「以上/以下」と「超/未満」、数値・単位（日付の形式、桁区切り、通貨）、主語の取り違え
- リンク：翻訳版からのリンクが原文の版に向いている（翻訳版があるのに）、翻訳版に無いページへのリンク
- 画像・図：画面の画像がその言語の UI になっているか（原文の画像のままなら明示）
- 文字の扱い：全角半角、句読点、引用符、改行位置（CJK の禁則）、右から左の言語の方向
- 自然さ：直訳で意味が取れない、敬体の不統一、長すぎる文（原文の構造をそのまま写した）
- 「翻訳の版は古い可能性があります」の注意書きの有無（規約で決めているなら）、更新日の表示
- 翻訳の仕組み：生成・同期の仕組み（翻訳管理ツール・スクリプト）があるなら、それを通しているか。手で直して仕組みと食い違う
- 片方の言語にだけ存在する文書・節の扱いの明示

## NG 例

### 例1：更新の漏れ

原文 README で「既定の間隔は 60 秒」に変わったが、翻訳版は「30 秒」のまま。利用者が言語で違う情報を得る。`must`（内容の不一致）。

### 例2：節の欠落

原文に「トラブルシューティング」の節が追加されたが、翻訳版に無い。`should`、必須の情報（セキュリティの注意）なら `must`。

### 例3：訳してはいけないものを訳す

```
設定ファイルの「再試行回数」キーを 3 にする。
```

実際のキーは `retry_count`。利用者は訳語で探して見つからない。`must`。

### 例4：意味の変化

原文「Do not run this in production」、翻訳「本番で実行してください」。否定が落ちた。`must`。

### 例5：用語の不一致

UI は「中止」、文書の翻訳は「キャンセル」。利用者が画面で探せない。`should`。

### 例6：画像が原文の言語

日本語版の文書に英語の画面の画像が貼られ、ボタンの名前が本文（日本語）と対応しない。注記か差し替え。`nit`〜`should`。

## 見落としやすい所

- 翻訳版は原文より後に更新されるため、差分の時点では「まだ」追従していないのが普通。追従の予定が無い・仕組みが無いことが問題
- 構造の突き合わせ（節・項目の数）は機械的にできる。先にやると漏れが見つかる
- 翻訳の品質（自然さ）は `nit` に留め、意味の変化・用語・更新漏れを優先する

## 指摘の書き方の例

- title：`英語版 README の既定の間隔の変更（60 秒）が日本語版に反映されていない`
- problem：`README.md 3.2 は今回の差分で "default 60 seconds" に変わったが、README.ja.md 3.2 は「既定は 30 秒」のまま。日本語の利用者が誤った値を前提にする`
- evidence：`差分で README.md の変更を確かめ、README.ja.md の対応箇所を読んだ。翻訳の同期の仕組みは無い（docs/CONTRIBUTING.md）`
- suggestion：`README.ja.md 3.2 を更新する。翻訳の追従を PR のチェックリストに入れる`
