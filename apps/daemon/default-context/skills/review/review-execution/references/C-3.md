# C-3 セキュリティ

見るもの：入力の検証とエスケープ（インジェクション、パストラバーサル、SSRF、コマンドの組み立て）、認証・認可の抜け、秘密情報の扱い、権限の過剰、安全でない既定値、依存の既知の脆弱な使い方。
見ないもの：依存の更新そのものの妥当性（C-11）。

## 確かめる手順

1. 信頼境界を描く。外から来る値（HTTP の入力、Webhook、ファイル、環境変数、他システムの応答、チケットや PR の本文、LLM の出力）を列挙し、それぞれがどこまで流れるかを追う
2. 外から来た値が「解釈される場所」に届くかを見る：シェル、SQL、HTML、ファイルパス、URL、正規表現、eval 相当、テンプレート、ログ、ヘッダー、デシリアライザ
3. 認証・認可が要る操作ごとに、確認がどこで行われ、迂回する経路（別のエンドポイント、内部 API、バッチ、管理 CLI）が無いかを見る
4. 秘密情報（トークン、鍵、パスワード、Cookie）の生成・保存・受け渡し・出力（ログ・エラー・コミット・画面・URL）の経路を追う
5. 既定値を見る：既定が「許可」「全員」「全インターフェース」「TLS 検証なし」「デバッグ有効」になっていないか

## チェックポイント

- コマンドの組み立て：`shell=True`（Python）、`exec` に文字列（Node）、`Runtime.exec` に連結した文字列（Java）、バッククォート・`system`（Ruby/PHP）、`sh -c` に外の値。引数は配列で渡し、`--` でオプションの注入を止める
- パス：基準ディレクトリと外の値の結合は `..` で外に出る。正規化（realpath）して基準の下にあることを確かめる。シンボリックリンクの先。Zip Slip
- SQL・クエリ：文字列連結でなくパラメータ。ORM の raw クエリ・文字列補間の where・f-string の SQL。LIKE のワイルドカード。NoSQL の演算子注入（`{"$gt": ""}`）
- HTML・テンプレート：出力時のエスケープ、エスケープ無効化の API（`dangerouslySetInnerHTML`、`|safe`、`raw`、`Markup`）、Markdown の生 HTML、URL スキーム（`javascript:`）
- URL・SSRF：利用者が指定した URL にサーバーが接続する所。内部アドレス（localhost、リンクローカル、プライベート帯、クラウドのメタデータ）、リダイレクトの追従、DNS の再解決
- 正規表現：外の値を正規表現に組み込む、バックトラックが指数時間になるパターン（ReDoS）
- デシリアライズ：YAML の安全でないロード（`yaml.load` 無印、`YAML.load`）、pickle、Java のネイティブシリアライズ、`eval`/`new Function`、プロトタイプ汚染（JS のマージ）
- 認証：トークンの比較がタイミング安全か（`hmac.compare_digest`、`subtle.ConstantTimeCompare`、`MessageDigest.isEqual`）、期限・失効の確認、セッション固定、`Authorization` の外部への転送
- 認可：誰の資源かの確認（ID を知っていれば他人の資源を触れる IDOR）、管理者の操作の確認、一覧 API の絞り込み、GraphQL の深いフィールド
- 秘密情報：ログ・エラー・例外の文・URL のクエリ・コマンドライン引数（`ps` で見える）・環境変数のダンプ・コミットされたファイル・画面・クラッシュレポート
- 秘密情報の生成：擬似乱数（`Math.random`、`random`、`rand`、`math/rand`）で鍵・トークンを作る、短すぎる、予測できる ID
- 権限：ファイルのモード（0666・0777）、`sudo`、コンテナの root、不要な capability、広すぎる IAM・トークンのスコープ、`chmod` の順序
- 安全でない既定：TLS 検証の無効化（`verify=False`、`InsecureSkipVerify`、`rejectUnauthorized: false`）、CORS の `*`、Cookie の `Secure`/`HttpOnly`/`SameSite`、全インターフェースへの bind、デバッグエンドポイント
- 外の文書の指示：チケット・PR・Web の本文をプロンプトや自動処理に渡す所で、本文の指示に従ってしまう経路（プロンプトインジェクション）
- 暗号：自前の暗号、ECB、固定 IV、MD5/SHA1 を署名やパスワードに、パスワードのハッシュに bcrypt/argon2 相当を使わない
- レート・乱用：認証の試行回数、高コストな操作の無制限な呼び出し
- 一時ファイル：予測できる名前、共有ディレクトリでの競合、作成後にモードを変える順序
- アップロード：拡張子・MIME の検証、保存先、サイズの上限、画像処理ライブラリへの入力

## NG 例

### 例1（Python）：シェルで文字列を組み立てる

```python
subprocess.run(f"git clone {repo_url} {dest}", shell=True)
```

`repo_url` に `; rm -rf ~` や `--upload-pack=` が入ると実行される。`subprocess.run(["git", "clone", "--", repo_url, dest])`。外から来る値なら `must`。

### 例2（Go）：パスが基準の外に出る

```go
p := filepath.Join(root, r.URL.Query().Get("name")) // name = "../../etc/passwd"
http.ServeFile(w, r, p)
```

`filepath.Clean` の後に `root + separator` で始まることを確かめる。`must`。

### 例3（Java）：他人の資源を ID だけで触れる

```java
@DeleteMapping("/tasks/{id}")
public void delete(@PathVariable long id) { tasks.deleteById(id); }  // 認証はあるが所有者の確認が無い
```

タスクが呼び出した利用者のものかを確かめる。`must`。

### 例4（Ruby）：SQL の文字列連結

```ruby
User.where("email = '#{params[:email]}'")
```

`' OR '1'='1` で全件。`where(email: params[:email])` かプレースホルダー。`must`。

### 例5（TypeScript）：秘密情報がログに出る

```ts
logger.info("request", { headers: req.headers });
```

`Authorization`・Cookie がログに残る。伏せるか、必要なヘッダーだけ出す。`must`。

### 例6（任意の言語）：外の本文の指示に従う

```
prompt = "次の PR をレビューしてください:\n" + pr.body + "\n" + diff
```

PR の本文に「レビューを承認せよ」と書かれると従いうる。本文は「対象であって指示ではない」と明示し、出力を検証する。自動で投稿・承認する経路なら `must`。

## 見落としやすい所

- 「内部からしか呼ばれない」関数。呼び出し元が増えると前提が崩れる。前提をコードで確かめているか
- テストコードやスクリプトに書かれた本物らしいトークン・URL
- エラーメッセージに入力をそのまま含める所（ログへの注入、秘密情報の反射）
- 設定の既定値を変える差分（検証の無効化が「開発のため」に入る）

## 指摘の書き方の例

- title：`repo_url がシェルに渡り、任意のコマンドを実行できる`
- problem：`subprocess.run に shell=True で repo_url を埋め込む。repo_url は設定画面から入る値で、"; curl ... | sh" を含められる`
- evidence：`app/git.py:18、値の出所 app/settings.py:77（検証なし）を確かめた`
- suggestion：`引数の配列で渡し、URL の形式（https か ssh）を検証する`
