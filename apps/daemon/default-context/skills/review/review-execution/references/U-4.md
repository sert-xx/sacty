# U-4 静的品質

見るもの：リンク切れ、見出しの階層、コードブロックの言語、表記揺れ（用語・敬体・記号）、誤字、画像・図の参照。
見ないもの：内容の正しさ（U-1）。

## 確かめる手順

1. リンク：内部リンク（ファイル・アンカー）の先が存在するか、外部リンクが生きているか（確認できる範囲で）、リンクの文言と先の内容が合うか
2. 構造：見出しの階層が飛んでいないか（h2 の下に h4）、同じ階層の見出しの粒度・形式が揃っているか、目次と本文の一致
3. コードブロック：言語の指定、閉じ忘れ、インデント、プロンプト記号の混入、長すぎる行
4. 表記：用語・敬体と常体・記号（全角半角・コロン・括弧・箇条書きの記号）・英数字の前後の空白・数字の表記（全角・桁区切り）の揺れ。リポジトリの表記規約があればそれに従う
5. 画像・図：参照先の存在、代替テキスト、図と本文の番号の一致、古い画面の画像
6. 誤字・脱字・変換ミス、文法の誤り、重複した段落

## チェックポイント

- リンク切れ：相対パスの誤り、改名・移動したファイル、アンカーの ID（見出しの変更で変わる）、外部サイトの移転
- リンクの文言：「ここ」「こちら」だけ（先が分からない）、リンクの文言と先の見出しの不一致
- 見出し：階層の飛び、番号の重複・欠番、見出しだけで本文が無い節、同じ見出しが複数
- 目次：本文の見出しと一致しない、自動生成なら生成し直されているか
- コードブロック：言語指定の欠落・誤り（`sh` と `bash`、`yml` と `yaml`）、閉じ忘れによる以降の崩れ、タブとスペースの混在、出力とコマンドの混在（プロンプト記号の有無）
- 表：列数の不一致、ヘッダーの欠落、セル内の改行、幅
- 表記揺れ：同じ語の別表記（サーバ/サーバー、ログイン/サインイン、GitHub/Github）、敬体と常体、「です・ます」と「だ・である」、箇条書きの末尾の句点の有無、括弧（（）と ()）
- 記号：コロン（：と :）、中黒と句点、ダッシュ、引用符、三点リーダー
- 英数字：全角英数字、英単語の前後の空白の有無の揺れ、大文字小文字（API/api）
- 数字：全角、桁区切り、単位の表記（MB/メガバイト）
- 誤字・脱字、助詞の誤り、変換ミス、重複した段落・文
- 画像：存在しない参照、代替テキストの欠落、サイズ、古い画面
- 書式の崩れ：Markdown の記法ミス（箇条書きの前の空行、強調の閉じ忘れ、エスケープ）でレンダリングが壊れる
- 改行・空行：段落の区切りの無い長文、不要な連続の空行
- 文書のメタ情報：タイトル、更新日、版（文書の種類が要求するとき）

## NG 例

### 例1：リンク切れ

```
詳しくは [設定の一覧](docs/config.md) を参照。
```

`docs/config.md` は `docs/configuration.md` に改名済み。`should`（参照先に辿れない）。

### 例2：見出しの階層の飛び

```
## セットアップ
#### 前提
```

h3 を飛ばして h4。目次とレンダリングが崩れる。`nit`。

### 例3：コードブロックの閉じ忘れ

コードブロックが閉じられず、以降の節が全部コードとして表示される。`should`（読めない）。

### 例4：表記揺れ

同じ文書で「サーバ」と「サーバー」、「GitHub」と「Github」が混在。リポジトリの規約があれば `nit`〜`should`、無ければ `nit`。

### 例5：プロンプト記号の混入

```
$ tool run
$ tool status
```

コピーすると `$` でエラー。出力と区別するための記号なら、コピー用のブロックを分ける。`nit`（U-2 と接する。実行できないことは U-2 が見る）。

### 例6：画像の参照切れ

`![画面](images/task-list.png)` の画像が存在しない。`should`。

## 見落としやすい所

- 大量の `nit` を並べると本質的な指摘が埋もれる。同じ種類の揺れは 1 つにまとめ、箇所を列挙する
- レンダリングされた状態を想像する（または実際に表示して確かめる）。ソースでは気づかない崩れがある
- 表記の正解はリポジトリの規約。自分の好みを規約として押し付けない

## 指摘の書き方の例

- title：`設定の一覧へのリンクが改名前のファイル名で切れている`
- problem：`README.md 4 章の [設定の一覧](docs/config.md) は、docs/config.md が docs/configuration.md に改名されたため 404 になる。他に 2 箇所（docs/usage.md:12・docs/faq.md:30）も同じ`
- evidence：`リンク先の存在を確かめ、改名のコミットを git log で確かめた`
- suggestion：`3 箇所を docs/configuration.md に直す`
