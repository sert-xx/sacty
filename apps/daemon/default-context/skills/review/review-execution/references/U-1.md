# U-1 正確性・コードとの同期

見るもの：コマンド・オプション・設定のキー・パス・既定値・出力の例が、コードや設定と一致するか。変更した機能に対応して文書が更新されているか、古くなった記述。
見ないもの：手順の順序（U-2）。

## 確かめる手順

1. 文書の中の「検証できる記述」を全部拾う：コマンドと引数、オプション名、設定キーと既定値、ファイルパス、環境変数、URL、API のエンドポイントと項目、出力の例、エラーメッセージ、版番号
2. それぞれをコード・設定・実際の出力と突き合わせる。引数のパーサー、設定のスキーマ、ルーティング、定数、CLI のヘルプ
3. 今回の変更（差分）で変わった振る舞いを列挙し、文書の該当箇所が更新されているかを見る。新しい機能・設定・コマンドが文書に無い、消えた機能が文書に残る
4. 古さの兆候：存在しないファイル名、改名前の名前、非推奨の方法、「現在は」「将来は」の記述、スクリーンショットの古い画面
5. 複数の文書（README・docs・ヘルプ・コメント・CHANGELOG）の間で食い違いが無いか

## チェックポイント

- コマンド・サブコマンド・オプションの名前と綴り、短縮形、必須か任意か、既定値
- 設定キーの名前・階層・型・既定値・単位。環境変数の名前と優先順位
- ファイルパス・ディレクトリ構成（改名・移動に追従しているか）
- API：エンドポイントのパス・メソッド・項目名・型・必須・応答の例・エラーの形
- 出力の例：実際の出力と形式・項目が一致するか（手で書いた例が古い）
- 版・要件：対応するランタイムの版、OS、依存の版、「以上」「未満」
- 新機能の未記載：差分で足した設定・コマンド・振る舞いが文書に無い
- 消えた機能の残存：削除・非推奨にした機能の説明が残る、非推奨の警告が無い
- 既定の変更：既定値を変えたのに文書が古い既定のまま
- 名前の変更：改名した概念・コマンド・設定が、文書の一部だけ更新されている
- 文書間の矛盾：README と docs、ヘルプと README、コメントと文書
- コードブロックの内容：構文エラー、存在しない関数、古いシグネチャ、言語の指定の誤り
- リンク先の内容：リンクは生きているが内容が変わっている（リンク切れ自体は U-4）
- 画面の説明：ボタン・メニューの名前と位置が実際の画面と一致するか
- 生成される文書（API リファレンス・ヘルプ）と手書きの文書の二重管理

## NG 例

### 例1：オプション名が古い

```
$ tool run --parallel 4
```

コードでは `--jobs` に改名済み（`--parallel` はエラー）。`must`（手順どおりに実行できない）。

### 例2：既定値が違う

README「`timeout` の既定は 30 秒」、コードの既定は 10 秒。利用者の見積もりが外れる。`must`。

### 例3：新しい設定が文書に無い

差分で `retry.max_attempts` を足したが、設定の一覧（README の表）に無い。利用者は存在を知れない。`should`、動作に必須の設定なら `must`。

### 例4：出力の例が古い

```
$ tool status
task-1  running
```

実際の出力は JSON に変わっている。例を機械で読んでいる利用者が壊れる。`should`。

### 例5：消えた機能が残る

「`--legacy` で旧形式を出力できます」が残っているが、コードから削除済み。`should`。

### 例6：コードブロックが動かない

```python
client = Client(api_key="...")
client.tasks.list(status="open")
```

実際の引数名は `state`。写して動かない。`must`。

## 見落としやすい所

- 文書の変更が差分に無いとき、「変更が要らない」のか「忘れた」のか。差分の機能変更から文書側を逆に探す
- 同じ内容が複数の文書にあると、片方だけ更新される
- 「正しそうに読める」記述ほど確かめられない。検証できる記述は 1 つずつコードで確かめる

## 指摘の書き方の例

- title：`README の --parallel は改名済みで、手順どおりに実行するとエラーになる`
- problem：`README 2.3 の例は tool run --parallel 4 だが、cmd/run.go:40 では --jobs に改名され、--parallel は unknown flag になる`
- evidence：`README.md 2.3 と cmd/run.go の flag 定義、CHANGELOG の改名の記述を確かめた`
- suggestion：`--jobs に直し、他の箇所（docs/usage.md）も検索して合わせる`
