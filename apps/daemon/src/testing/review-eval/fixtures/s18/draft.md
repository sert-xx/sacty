# 要求要件：蔵書に出版社を持たせる

蔵書の登録で出版社を入力でき、一覧と詳細の応答で出版社を返し、一覧を出版社で絞り込めるようにする。

## 確認したいこと

### must

- 登録で出版社を必須にするか
  - 推奨：任意にし、未登録は `null` で返す（`isbn` と同じ形）
  - 理由：必須にすると既存の利用者の登録が 400 になり、README の「事前に相談する」変更になる
- 出版社をどう表すか
  - 推奨：蔵書ごとの文字列の名前にする
  - 理由：出版社を別の資源（ID・出版社の登録 API）にすると、要求も設計も別物になる

### should

- 絞り込みの一致の仕方
  - 推奨：`author` と同じ完全一致
  - 理由：既存の絞り込みと揃い、部分一致にすると表記の揺れの扱いを別に決める必要がある
- 出版社の長さの上限と、前後の空白の扱い
  - 推奨：前後の空白を除いて 1〜100 文字（`author` と同じ）
  - 理由：上限を後で変えると、検査と API の定義を直す必要がある

## 既定で決めたこと

- 項目と query の名前は `publisher`（`GET /books?publisher=`）
- 空文字・空白だけの出版社は、未登録として扱わずに 400 にする（`title`・`author` と同じ）

## 受け入れ条件

### 常時

| ID | システム | 応答 |
| --- | --- | --- |
| R-1 | 蔵書 API | 一覧（`GET /books`）と詳細（`GET /books/{bookId}`）の各蔵書に `publisher` を含める |
| R-2 | 蔵書 API | API の定義・生成した型とリファレンスに `publisher` の項目を載せ、版を 1.4.0 にする |

### イベント駆動

| ID | トリガー | システム | 応答 |
| --- | --- | --- | --- |
| R-3 | 出版社を指定して蔵書を登録したとき | 蔵書 API | 前後の空白を除いた出版社を `publisher` に持つ蔵書を 201 で返す |
| R-4 | 出版社を指定せずに蔵書を登録したとき | 蔵書 API | `publisher` が `null` の蔵書を 201 で返す |
| R-5 | `publisher` を指定して一覧を求めたとき | 蔵書 API | 出版社が完全一致する蔵書だけを登録の新しい順で返す |
| R-6 | `publisher` を `author`・`status` と一緒に指定して一覧を求めたとき | 蔵書 API | すべての条件に合う蔵書だけを返す |

### 望まない振る舞い

| ID | トリガー | システム | 応答 |
| --- | --- | --- | --- |
| R-7 | 登録の出版社が前後の空白を除いて 1〜100 文字でない場合 | 蔵書 API | 蔵書を登録せずに 400 `VALIDATION_ERROR` を返す |

## 受け入れの確かめ方

自動のテストで確かめること

- R-1・R-3〜R-7：`src/app.test.ts` で `app.request` を呼び、状態コードと応答の `publisher`・一覧の並びを確かめる
- R-3・R-5：`src/client.test.ts` で、生成した型のクライアントから `publisher` を送り、絞り込めることを確かめる
- R-2：`npm run check:generated` が通り、`info.version` と `package.json` の `version` が 1.4.0 で、CHANGELOG.md に追加の行がある
