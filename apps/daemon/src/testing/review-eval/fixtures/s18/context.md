# 要求要件の書き方の指示（依頼者からの指示の抜粋。根拠として使う）
- 何を実現するかを1〜3文。受け入れ条件は EARS（文型ごとの見出しと表、ID は R-1 から欠番なく、応答列に「しなければならない」を書かない）
- 異常系は、今回の変更で新しく起こりうるものだけを望まない振る舞いで書く
- 実装方法に踏み込まない
- 受け入れの確かめ方は「自動のテストで確かめること」「人が確かめること（無ければ書かない）」に分ける
- 判断できないことは推測で要求にせず「確認したいこと」に挙げる
- 冒頭に「確認したいこと」（must / should。should は最大5件。1件ごとに問い・推奨の答え・理由。依頼の目的に関わる判断と依頼者に不利益が出うる既定はここに置く）と「既定で決めたこと」（最大5件、1件1行、既存のやり方にそのまま従っただけのことは書かない）
- 分量は最小限（小さな変更で20行、大きな変更でも60行ほど）。依頼の言い直し・背景・既存の仕組みの説明・起こりえない異常系・対象外の節・採らなかった案・まとめは書かない
- 本文に作業の経過・指摘への対応の報告・エージェント向けのメモを書かない。別文書の参照だけの項目にしない
