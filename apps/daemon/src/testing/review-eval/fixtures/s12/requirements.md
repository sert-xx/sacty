# 要求要件：予約の変更（API）

`PATCH /api/reservations/:id` で、予約の件名・開始・終了・人数を後から変えられるようにする。
変更後の内容は作成と同じ検査にかけ、予約の状態（開始前・使用中・終了済み・キャンセル済み）で変えられる項目を制限する。

## 確認したいこと

### must

なし

### should

なし

## 既定で決めたこと

- 終了済みは `endsAt <= 現在`、使用中は `startsAt <= 現在 < endsAt`（キャンセルの判定に合わせる）
- 本文の形の誤り（400）を、状態による拒否（422）より先に調べる（作成と同じ）

## 要求

「変更」は `PATCH /api/reservations/:id` の要求を、「4 項目」は `title`・`startsAt`・`endsAt`・`attendees` を指す。

### イベント駆動

| ID | トリガー | システム | 応答 |
| --- | --- | --- | --- |
| R-3 | 開始前の予約に、4 項目の一部を含む正しい本文の変更を受けたとき | API | 200 と、渡した項目だけを変え、ほかの項目を変更前のまま保った予約を返す |
| R-6 | 使用中の予約に、`endsAt` だけを含む正しい本文の変更を受けたとき | API | 200 と、`endsAt` だけを変えた予約を返す |

### 望まない振る舞い

| ID | トリガー | システム | 応答 |
| --- | --- | --- | --- |
| R-8 | 変更後の 4 項目の値（渡さない項目は変更前の値）が作成と同じ形式の検査（15 分単位・終了が開始より後を含む）に反する場合 | API | 400 を返し、予約を変えない |
| R-10 | 使用中の予約への変更が `endsAt` 以外の項目を含む場合 | API | 422 を返し、予約を変えない |
| R-11 | 終了済みかキャンセル済みの予約への変更の場合 | API | 422 を返し、予約を変えない |
| R-12 | 変更後の開始から終了までが 240 分を超える場合 | API | 422 を返し、予約を変えない |
| R-13 | 開始前の予約で、変更後の `startsAt` が現在以前の場合 | API | 422 を返し、予約を変えない |
| R-15 | 変更後の人数が会議室の定員を超える場合 | API | 422 を返し、予約を変えない |

## 受け入れの確かめ方

### 自動のテストで確かめること

- 速いテスト（domain・usecase・HTTP）で、R-3〜R-15 を確かめる。現在の時刻は固定の Clock で模擬する
